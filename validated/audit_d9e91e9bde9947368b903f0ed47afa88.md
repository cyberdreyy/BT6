### Title
Any block proposal that fails to confirm a tenure refreshes that tenure miner's own liveness timer, letting a stalled/malicious miner defeat the inactivity fallback - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` is the function that ultimately decides whether the currently-active sortition's miner is "active" for purposes of `SortitionState::is_timed_out` / `check_miner_inactivity`, the mechanism the signer set uses to detect a stuck or malicious miner and fall back to the prior tenure's miner. This is the same class of bug as the Pyth report: a piece of state that gates a downstream liveness/acceptance decision (there: the accepted price timestamp; here: `last_activity_time`) is refreshed by input that only the "expected" trusted producer is supposed to legitimately advance, but the code accepts *any* signed proposal from that producer — even a proposal that is provably a non-progressing/invalid reorg attempt — as sufficient proof of activity.

### Finding Description
`check_latest_block_in_tenure` is called on every incoming block proposal from the v1/v2 `check_proposal` paths to verify that a proposal confirms as many blocks of the referenced tenure as the signer already knows about. When it does not (`block.header.chain_length <= info.block.header.chain_length`), the function still calls `signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())` for the *current* sortition's tenure before returning `Ok(false)`: [1](#0-0) 

`update_last_activity_time` keys on `block.header.consensus_hash`, i.e., the tenure of the miner who is currently active per `MinerState::ActiveMiner`. That timer is exactly what `SortitionState::is_timed_out` (v1) and its v2 counterpart consult to decide whether the miner has been inactive long enough to be invalidated and replaced with the prior tenure's miner: [2](#0-1) 

and the state-machine driver that actually performs the fallback: [3](#0-2) 

The comment in `chainstate/mod.rs` explicitly acknowledges the design intent — "count this invalid block proposal towards valid miner activity" — but the guard that is supposed to bound this ("if there is no signed_group time... local timeout not yet exceeded") only limits how long a *specific* prior conflicting block can extend activity; it does not stop the current miner from generating a fresh, distinct, always-failing (non-confirming) proposal on every attempt, each one hitting this same branch and re-arming the activity timer with the fresh wall-clock time. Because `NakamotoBlock` proposals are cheap to construct (a miner fully controls `chain_length`, `parent_block_id`, timestamp, etc., and only needs one valid miner signature it already possesses), a currently-active but stalled/malicious miner can indefinitely refresh its own liveness signal without ever producing a block that actually confirms progress or gets signed.

This is the direct analog of the `PythPriceFeedUpdate` bug: there, an untrusted actor could inject a message through an unintended channel and thereby update a timestamp that was meant to reflect legitimate progress from a single trusted producer (the Oracle thread), which then blocked/starved legitimate updates for everyone else. Here, the "trusted producer" is the currently active sortition miner, and the "legitimate progress" signal (`last_activity_time`) is supposed to represent real block production, but it is satisfied by any syntactically valid, signed-by-the-miner proposal — including one deliberately crafted to fail the confirmation check — which blocks the entire signer set's fallback mechanism from ever triggering.

### Impact Explanation
This is a liveness wedge matching the "High" impact category: a signer (indeed, the whole signer set, since `check_latest_block_in_tenure`/`is_timed_out` is evaluated independently but identically by every honest signer against the same `signer_db` state populated by the same proposals) can be kept from ever falling back to a valid miner. `check_miner_inactivity` in `signer_state.rs` is the only path that reverts `current_miner` to a prior, valid tenure when the active miner goes dark; if `is_timed_out` can never return `true` because the miner periodically resends invalid/non-confirming proposals, the tenure can be starved indefinitely (until the next Bitcoin block forces a new sortition), during which no valid block is signed. This directly matches "a signer wedged into never signing valid blocks... acting on a stale ... state" from the impact rubric.

### Likelihood Explanation
The precondition — controlling the currently active sortition's mining key — is exactly the "one-slot miner" actor explicitly permitted by scope. No majority of signers, no other signer's key, and no auth token is needed; only the ordinary ability of the current miner to submit block proposals through the normal StackerDB miner channel, which is the expected and always-available capability of whoever wins a sortition. A miner intending to stall the chain (e.g., to grief a competing chain state, delay finality, or buy time for another action) needs no special resources beyond simply resubmitting cheaply-constructed proposals faster than `reorg_attempts_activity_timeout`/`block_proposal_timeout`.

### Recommendation
`update_last_activity_time` should not be refreshed merely because *a* proposal was received; it should require the proposal to represent genuine, verifiable progress (e.g., only refresh activity when the proposal is forwarded to the node for validation and/or receives a non-trivial validation result, or rate-limit/require increasing `chain_length`/novel `parent_block_id` values across successive non-confirming proposals from the same tenure). At minimum, cap the number of times a single tenure's activity timer can be refreshed by proposals that fail the confirmation check within a `block_proposal_timeout` window, so a miner cannot indefinitely re-arm its own liveness signal without making real progress.

### Proof of Concept
Conceptual reproduction (matches existing test scaffolding in `stacks-signer/src/chainstate/tests/v1.rs`, e.g. `check_block_proposal_timeout` / `reorg_timing_testing`):
1. Become (or simulate) the currently active sortition's miner, referencing the current tenure's `consensus_hash`.
2. Wait until just before `block_proposal_timeout` (or `reorg_attempts_activity_timeout`) would elapse based on `last_activity_time`/`get_burn_block_receive_time_ch`.
3. Submit a new `NakamotoBlock` proposal for the current tenure with `chain_length` no higher than the last known block in that tenure (e.g., an old/duplicate/lower height, always signed with a fresh/adjusted body so it is treated as a new, distinct proposal).
4. Observe that `check_latest_block_in_tenure` returns `Ok(false)` (proposal rejected as non-confirming) but still calls `update_last_activity_time` with the current wall-clock time for that tenure's `consensus_hash`.
5. Repeat step 3 before each successive `block_proposal_timeout` window elapses.
6. Observe via `SortitionState::is_timed_out` (v1.rs `is_timed_out`, and its v2 analog) that `elapsed > block_proposal_timeout` never becomes true, so `check_miner_inactivity` in `signer_state.rs` never falls back to the prior tenure's miner, even though the active miner has produced zero valid/signed blocks.

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };

        let sortition_data = last_sortition.data();
        // If we already reverted to the last sortition miner, don't time it out as it means we have already timed out the current sorititon miner
        // as there is no other miner available.
        if &sortition_data.consensus_hash == tenure_id {
            warn!("Signer State: Last sortition miner has timed out, but no prior valid miner. Allowing last sortition miner to continue");
            return Ok(());
        }

        // Only revert to the prior miner if its tenure is the canonical Stacks tip's
        // tenure. A miner only continues (extends) a tenure it won, so if the canonical
        // tip is in some other tenure due to a Bitcoin reorg orphaning the prior
        // sortition's tenure, the prior miner's node has already stopped mining and
        // will never propose again.
        let stacks_tip_ch = client.get_peer_info()?.stacks_tip_consensus_hash;
        if sortition_data.consensus_hash != stacks_tip_ch {
            warn!(
                "Signer State: Current miner timed out due to inactivity, but the canonical stacks tip is not in the prior miner's tenure, so the prior miner cannot continue it. Allowing current miner to continue";
                "stacks_tip_consensus_hash" => %stacks_tip_ch,
                "prior_sortition_consensus_hash" => %sortition_data.consensus_hash,
            );
            return Ok(());
        }

        if !last_sortition.is_tenure_valid(db, client, proposal_config, eval)? {
            warn!("Signer State: Current miner timed out due to inactivity, but prior miner is not valid. Allowing current miner to continue");
            return Ok(());
        }
        let new_active_tenure_ch = &sortition_data.consensus_hash;
        let inactive_tenure_ch = tenure_id.clone();
        state_machine.current_miner = Self::make_miner_state(
            sortition_data.clone(),
            client,
            db,
            proposal_config.tenure_last_block_proposal_timeout,
        )?;
        info!(
            "Signer State: Current tenure timed out, setting the active miner to the prior tenure";
            "inactive_tenure_ch" => %inactive_tenure_ch,
            "new_active_tenure_ch" => %new_active_tenure_ch
        );

        crate::monitoring::actions::increment_signer_agreement_state_change_reason(
            crate::monitoring::SignerAgreementStateChangeReason::InactiveMiner,
        );

        Ok(())
    }
