### Title
Missing zero-value validation in `IdleCreditVaultWriteOffEscrow.createWriteOffRequest` lets anyone seize escrowed tranche tokens for free — (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` validates that `amount > 0` (tranche tokens deposited) but performs no validation on `underlyingsRequested`. A request with `underlyingsRequested == 0` is accepted: the lender's tranche tokens are escrowed while `currentRequest.underlyings` remains 0. `fullfillWriteOffRequest` only requires `_underlyings >= currentRequest.underlyings`, so any unprivileged caller can fulfill with `_underlyings = 0`, pay nothing (the 0.1% exit fee on 0 is 0), and receive the full escrowed tranche balance. This is the same bug class as `FeeAuction.buy`: a permissionless exchange function transfers value one way while the counter-asset side is unvalidated, letting the payer take assets for zero consideration.

### Finding Description
- `createWriteOffRequest` pulls `amount` tranche tokens via `safeTransferFrom` and stores `underlyings: currentRequest.underlyings + underlyingsRequested` with no `underlyingsRequested > 0` check (`contracts/IdleCreditVaultWriteOffEscrow.sol:86-101`).
- `fullfillWriteOffRequest` is explicitly callable by "any wallet". Its only economic check is `currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings` → `WrongRequest`. With `underlyings == 0` stored, passing `_underlyings = 0` satisfies the check (`lines 123-131`).
- The fulfiller then pays `safeTransferFrom(msg.sender, this, 0)` (a no-op for standard ERC20s), the fee math yields `_totFee = 0`, `safeTransfer(_user, 0)` sends nothing to the lender, and `safeTransfer(msg.sender, _tranches)` delivers the victim's entire escrowed tranche position to the attacker (`lines 137-151`).

Broken invariant: the escrow is meant to guarantee a quid-pro-quo swap (tranches ⇄ underlyings). With a zero-priced request, the "one receipt one payout" / fair-exchange invariant collapses — tokens leave the escrow with zero consideration.

### Impact Explanation
Direct theft. Any tranche tokens sitting in a zero-underlyings request (created by user error, a partially-filled legacy/upgraded request, or a lender who intended a nonzero amount but mis-encoded the call) can be extracted by any EOA at zero cost. Loss equals the full market value of the escrowed tranche tokens; the lender receives 0 underlying. This is permanent, unrecoverable loss of the deposited tranche claim.

### Likelihood Explanation
Requires a zero-`underlyingsRequested` request to exist. Such requests serve no legitimate purpose — a rational lender always wants payment — yet the contract permits them, exactly mirroring the FeeAuction scenario where an empty `_assets` array was accepted. Note also a second-order vector: an attacker monitoring the mempool can front-run `deleteWriteOffRequest`/`createWriteOffRequest` corrections, and since fulfillment is permissionless, no privileged cooperation is needed. Exploitation cost is a single call. Conditional likelihood, high severity.

### Recommendation
- In `createWriteOffRequest`, revert when `underlyingsRequested == 0` (and arguably enforce a minimum ratio / sanity bound vs. `amount`).
- Optionally, in `fullfillWriteOffRequest`, revert when `_underlyings == 0` so a fulfillment can never transfer tranches for zero consideration.
- Both checks mirror the recommended fix for `FeeAuction.buy` (reject empty/zero-value inputs).

### Proof of Concept
Foundry test sketch (fork-free is sufficient — only standard ERC20 mocks needed; vault/strategy/borrower wiring is already satisfied by an initialized escrow):

```solidity
function test_stealZeroPriceRequest() public {
    // lender (victim) deposits 100 tranche tokens asking for 0 underlyings
    vm.startPrank(lender);
    tranche.approve(address(escrow), 100e18);
    escrow.createWriteOffRequest(100e18, 0); // accepted: only amount==0 reverts
    vm.stopPrank();

    // attacker: unprivileged EOA, zero underlying balance
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(lender, 100e18, 0); // pays 0, succeeds

    assertEq(tranche.balanceOf(attacker), 100e18);   // attacker got the tranches
    assertEq(underlying.balanceOf(lender), 0);        // lender got nothing
    assertEq(escrow.userRequests(lender), empty);     // request consumed
}
```
