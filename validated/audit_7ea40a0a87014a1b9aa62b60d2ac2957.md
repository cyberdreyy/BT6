Based on the gateway vault request pipeline in `core/capabilities/vault/`, there is a concrete asymmetry between two structurally identical, unprivileged-client-reachable handlers that both flow through the same shared authorization pipeline (`GatewayVaultRequestProcessor.ProcessRequest` → `authorizeAndStamp` → `AuthorizeRequest`), directly analogous to the reported bug class: a security check present on one path is missing on the sibling path that shares the same entry point.

### Title
Missing owner enforcement in `GatewayHandler.handleSecretsDelete` allows cross-owner secret deletion via IDs not overwritten with the authorized owner - (File: core/capabilities/vault/gw_handler.go)

### Summary
`GatewayHandler.HandleGatewayMessage` dispatches `MethodSecretsList` and `MethodSecretsDelete` through the identical authorization pipeline (`requestProcessor.ProcessRequest`), then calls `handleSecretsList` / `handleSecretsDelete` with the resulting `authResult`. `handleSecretsList` explicitly re-stamps the request's `Owner` field with the value returned by the authorizer (`r.Owner = authResult.AuthorizedOwner()`), refusing to trust the client-submitted owner. `handleSecretsDelete` has no equivalent statement — it uses the `Ids` (each containing its own `Owner` field) exactly as unmarshalled from the client-controlled `req.Params`, without overwriting them with `authResult.AuthorizedOwner()`. [1](#0-0) [2](#0-1) 

### Finding Description
The dispatch logic treats both methods identically at the routing layer: [3](#0-2) 

Both `MethodSecretsDelete` and `MethodSecretsList` are authorized via the same call, `h.requestProcessor.ProcessRequest(ctx, req, nil)`, which returns only an `AuthResult` — it does not itself rewrite `Ids`/`Owner` fields inside the request body for delete requests; it merely stamps the request ID with an owner prefix and calls `p.authorizer.AuthorizeRequest`: [4](#0-3) [5](#0-4) 

Note the `stamp` closure for delete only applies namespace defaults (`ApplySecretIdentifierNamespaceDefaults`) — it never forces each `SecretIdentifier.Owner` to equal the authorized owner. By contrast, `handleSecretsList` defends against this by overwriting `r.Owner` with `authResult.AuthorizedOwner()` right before calling `ListSecretIdentifiers`, i.e., a deliberate design pattern establishing that the client-submitted owner field cannot be trusted and must be replaced with the value derived from authentication. `handleSecretsDelete` does not follow this same pattern, instead passing the raw, client-supplied `Ids` (which each carry an independently client-controlled `Owner` field) straight to `h.secretsService.DeleteSecrets`.

Whether the underlying `AuthorizeRequest` implementation performs a generic cross-owner check for delete/list methods the same way the tests demonstrate for `MethodSecretsCreate` (see `TestGatewayHandler_HandleGatewayMessage`'s "failure - auth layer rejects cross-owner mutation" case) could not be conclusively verified from the code inspected — that test only covers create's encrypted-secret `Owner` field embedded in the digest-signed payload, not the `Ids` owner field used by delete. If `AuthorizeRequest`/the allowlist authorizer does not independently validate that every `Ids[i].Owner` matches the authorized owner for the delete method (the way `handleSecretsList` defensively forces it), then an authenticated-but-unprivileged caller authorized only for their own owner identity could submit a delete request whose `Ids` reference a different owner's secrets and have them deleted. [6](#0-5) 

### Impact Explanation
If the owner check is not otherwise enforced deeper in the authorizer for the delete path, an unprivileged workflow/vault client could delete another owner's secrets by crafting `SecretIdentifier.Owner` values that don't match their own authorized identity, causing data loss / denial of secret availability for other tenants — a cross-user integrity impact analogous in class (missing validation on one path present on a sibling path) to the reported `ExchangeProxy.executeSwapDirect` finding.

### Likelihood Explanation
Likelihood depends entirely on whether `Authorizer.AuthorizeRequest` independently re-validates that all `Ids[i].Owner` in a delete request equal the authorized owner. This could not be fully confirmed with the available index (the `authorizer.go` internals for delete/list owner-matching logic were not retrieved before the iteration limit). Given the explicit defensive owner-overwrite present in `handleSecretsList` but conspicuously absent in `handleSecretsDelete`, this asymmetry is a strong signal of either (a) a genuine gap, or (b) redundant code intentionally removed from delete because authorization already guarantees it — this ambiguity should be resolved by inspecting `core/capabilities/vault/authorizer.go` and `validator.go`'s `ValidateDeleteSecretsRequest`.

### Recommendation
Mirror the `handleSecretsList` pattern in `handleSecretsDelete`: after unmarshalling `DeleteSecretsRequest`, overwrite each `Ids[i].Owner` with `authResult.AuthorizedOwner()` before calling `h.secretsService.DeleteSecrets`, exactly as done for list: [7](#0-6) 

### Proof of Concept
Not independently reproducible from static analysis alone — would require confirming, via a session with the full authorizer/validator source, whether `AuthorizeRequest` for `MethodSecretsDelete` checks `Ids[].Owner` against `AuthResult.AuthorizedOwner()`. The structural evidence is the diff in defensive posture between `handleSecretsList` (owner forcibly overwritten) and `handleSecretsDelete` (owner trusted from client params) despite both sharing the identical gateway authorization entry point.

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
		}
	}

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

func (h *GatewayHandler) handleSecretsList(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage], authResult *AuthResult) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.ListSecretIdentifiersRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}
	r.Owner = authResult.AuthorizedOwner()

	h.lggr.Debugw("Processing authorized list secrets request", "request", r.String())
	resp, err := h.secretsService.ListSecretIdentifiers(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to list secret identifiers: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

func (p *GatewayVaultRequestProcessor) processDeleteSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var deleteReq vaultcommon.DeleteSecretsRequest
	if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		deleteReq.RequestId = req.ID
		if err := marshalVaultParams(req, &deleteReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		deleteReq.RequestId = coalesceRequestID(deleteReq.RequestId, req.ID)
	}

	if err := p.validator.ValidateDeleteSecretsRequest(ctx, &deleteReq); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		deleteReq.RequestId = prefixedRequestID
		vaultutils.ApplySecretIdentifierNamespaceDefaults(deleteReq.Ids)
		return marshalVaultParams(req, &deleteReq)
	})
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}
