### Title
`switch_operator` in `staking_contract.move` can silently reroute the old operator's pending commission to the operator's raw address instead of their configured beneficiary - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` only redirects a distribution-pool payout to `beneficiary_for_operator(operator)` when the shareholder address equals the `operator` parameter that is passed into the call. [1](#0-0)  `switch_operator` reuses the *same* `StakingContract`/`distribution_pool` object but re-keys it in the `Store.staking_contracts` map under `new_operator`, after first calling `request_commission_internal(old_operator, &mut staking_contract)` to record any freshly-unlocked commission owed to `old_operator` in that same pool. [2](#0-1)  Any future `distribute()`/`unlock_stake()` call on this contract is now made with `operator = new_operator`, so the leftover share entry keyed to `old_operator` no longer matches the `operator` parameter checked in `distribute_internal`, and the beneficiary redirect is skipped — the payout goes straight to `old_operator`'s raw account instead of `beneficiary_for_operator(old_operator)`. [3](#0-2) 

### Finding Description
`request_commission_internal` records a share in `distribution_pool` under the `operator` address it is given, to be paid out later, once the amount becomes withdrawable after lockup expiry: `add_distribution(operator, staking_contract, operator, commission_amount)`. [4](#0-3)  The actual redirection to a beneficiary only happens later, in `distribute_internal`, by comparing the stored `recipient` against the `operator` argument passed into that specific `distribute_internal`/`distribute` call:
```
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
``` [5](#0-4) 

`switch_operator` performs, in order: (1) `distribute_internal(staker, old_operator, &mut staking_contract)` to flush already-inactive funds, (2) `request_commission_internal(old_operator, &mut staking_contract)` which can add a *new* share for `old_operator` if any commission accrued since the last principal update, (3) `stake::set_operator_with_cap(new_operator)`, and (4) re-inserts the very same `staking_contract` value into the map under key `new_operator`. [2](#0-1) 

After this, the only way to pay out that pending `old_operator` share is through `distribute(staker, new_operator)` (since the contract is now stored under `new_operator`) or `unlock_stake`, both of which invoke `distribute_internal(staker, new_operator, staking_contract)`. [6](#0-5)  When the loop reaches the leftover shareholder entry equal to `old_operator`, the comparison `recipient == operator` (`old_operator == new_operator`) is false, so `beneficiary_for_operator(old_operator)` is never consulted, and the coins are deposited directly to `old_operator`'s own account via `aptos_account::deposit_coins`. [7](#0-6) 

This means if `old_operator` had called `set_beneficiary_for_operator` to route commission to a custodial/beneficiary address, any commission unlocked exactly at the moment of `switch_operator` (rather than fully drained beforehand via an explicit `distribute` immediately preceding the switch) bypasses that beneficiary and lands in the operator's raw account instead.

### Impact Explanation
This is a share-accounting/beneficiary-routing defect: value that should be credited to the registered beneficiary of `old_operator` is instead credited to a different address (`old_operator`'s own account) without the beneficiary's consent, which matches the "credits the wrong account" impact category for operator commission/beneficiary flows. It does not create out-of-thin-air theft for a third-party attacker, and the staker action (`switch_operator`) is one the staker is authorized to perform on their own staking contract; the harm falls on `old_operator`'s beneficiary configuration being silently ignored for that specific tranche of commission.

### Likelihood Explanation
This requires a specific timing window: commission must accrue (rewards since `last_recorded_principal`) between the last `distribute`/`request_commission` and the `switch_operator` call, and `old_operator` must have a beneficiary configured via `set_beneficiary_for_operator`. Callers performing routine operator switches without first calling `distribute()` immediately beforehand would trigger it. The existing test suite (`test_set_operator_beneficiary_...` style tests observed) exercises the case where `distribute()` is called right before `switch_operator`, which avoids leaving a pending share — so this edge case does not appear to be covered.

### Recommendation
In `distribute_internal`, redirect to a beneficiary based on whether the *shareholder* address itself has a registered beneficiary (`exists<BeneficiaryForOperator>(recipient)` / compare against the operator that was recorded at `add_distribution` time), rather than comparing the shareholder to the currently-active `operator` parameter. Alternatively, `switch_operator` should force full `distribute_internal` + beneficiary-aware payout of any share still recorded for `old_operator` before re-keying the `staking_contract` under `new_operator`, ensuring no lingering `old_operator` share can be paid out under the wrong `operator` context.

### Proof of Concept
Conceptual trace (matching the code paths above, not independently executed):
1. Staker creates a staking contract with `operator1`, and `operator1` calls `set_beneficiary_for_operator(beneficiary1)`. [8](#0-7) 
2. Stake pool earns rewards (`stake::end_epoch()`), so `get_staking_contract_amounts_internal` now shows unpaid commission for `operator1`, but the staker does not call `distribute`/`request_commission` first.
3. Staker calls `switch_operator(staker, operator1, operator2, new_commission)`. Internally: `request_commission_internal(operator1, &mut staking_contract)` records a share for `operator1` in `distribution_pool`; the whole `staking_contract` (with that pending share) is moved to be keyed by `operator2`. [2](#0-1) 
4. After lockup expires, anyone calls `distribute(staker, operator2)`. `distribute_internal` iterates shareholders, reaches the `operator1` entry, and since `operator1 != operator2`, it pays the commission directly to `operator1`'s account instead of `beneficiary1`. [7](#0-6) 

I was not able to run this scenario in a live Move test environment to confirm the exact numeric outcome; this is a static code-path analysis based on the cited logic. A background Devin session with Move unit-test execution could confirm this by writing a variant of `test_set_beneficiary_for_operator`/the "switch operator to operator2" test that leaves an unpaid commission at switch time and asserts `beneficiary1`'s balance versus `operator1`'s balance after `distribute`.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

        if (!exists<Staker>(pool_address)) {

            move_to(pool_signer, Staker { staker });
        };

        let total_potential_withdrawable = inactive + pending_inactive;

            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable

            coin::destroy_zero(coins);
            return

            distribution_amount,
            operator,
