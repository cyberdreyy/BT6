### Title
Unvalidated `underlyingsRequested` lets any fulfiller seize escrowed tranche tokens for free - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` validates `amount != 0` but never validates `underlyingsRequested`. A write-off request stored with `underlyings == 0` can be fulfilled by any wallet with `_underlyings == 0`, because `fullfillWriteOffRequest` only rejects `_underlyings < currentRequest.underlyings`. The fulfiller receives all escrowed tranche tokens while paying nothing.

### Finding Description
The escrow collects tranche tokens from a lender and underlyings from a fulfiller so they can trustlessly exchange debt. In `createWriteOffRequest` (lines 86-102) the only checks are `isEpochRunning()` and `amount != 0`; `underlyingsRequested` is stored verbatim into `userRequests[msg.sender].underlyings` and added to `pendingUnderlyings`. In `fullfillWriteOffRequest` (lines 123-151) the guard is `currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings`. When `currentRequest.underlyings == 0`, passing `_underlyings = 0` satisfies the check, `safeTransferFrom(msg.sender, this, 0)` is a no-op, the fee is zero, and the fulfiller still receives `safeTransfer(msg.sender, _tranches)` — the full escrowed tranche balance, for free. There is also no lower bound, so a lender setting a dust price (e.g. 1 wei of underlying for thousands of tranche tokens) is equally exposed to instant seizure. This mirrors CVE-2020-8866's class: lack of validation of user-supplied data enables an attacker to obtain an asset the protocol holds.

### Impact Explanation
Direct theft. Any unprivileged EOA (the fulfill path is permissionless — tests even confirm non-KYC'd buyers can fulfill) who observes a request with `underlyings == 0` or a negligibly small price can call `fullfillWriteOffRequest(victim, request.tranches, 0)` in the same block the request is created (mempool front-running) and take the entire escrowed tranche position, worth the full `tranchePrice * tranches` in underlying. Loss is bounded only by the size of the victim's escrowed tranche tokens. The lender's only recovery is `deleteWriteOffRequest`, which an attacker can always front-run since fulfillment is atomic.

### Likelihood Explanation
Medium. It requires a lender to create a zero-price or dust-price request — plausible via UI misconfiguration, a UI that prefills 0, a lender intending a free "debt forgiveness" write-off to the borrower only (the design comment suggests borrower fulfillment, but any wallet may fulfill), or a typo in units (e.g. entering price in 18 decimals against 6-decimal USDC). Once such a request exists, exploitation is guaranteed and costless; monitoring bots routinely sweep mispriced escrow orders. No privileged actor is needed.

### Recommendation
In `createWriteOffRequest`, revert when `underlyingsRequested == 0` (e.g. `if (underlyingsRequested == 0) revert NotAllowed();`), and consider enforcing a minimum implied price relative to current tranche NAV. Alternatively/additionally, in `fullfillWriteOffRequest`, restrict fulfillment of under-priced requests or require `_underlyings > 0`.

// Foundry fork PoC — extend test/foundry/IdleCreditVaultWriteOffEscrow.t.sol setup
function testZeroPriceRequestSeized() external {
  // victim LP creates a request with underlyingsRequested = 0 (misconfigured / forgiveness intent)
  uint256 trancheAmt = 10000e18;
  vm.prank(LP);
  escrow.createWriteOffRequest(trancheAmt, 0);

  // any unprivileged attacker fulfills with 0 underlyings in the same block
  address attacker = makeAddr("attacker");
  uint256 pre = tranche.balanceOf(attacker);
  vm.prank(attacker);
  escrow.fullfillWriteOffRequest(LP, trancheAmt, 0); // no approve needed: 0 transfer

  // attacker received all escrowed tranche tokens, paid nothing
  assertEq(tranche.balanceOf(attacker) - pre, trancheAmt);
  assertEq(underlying.balanceOf(attacker), underlyingBalBefore);
  (uint256 t, uint256 u) = escrow.userRequests(LP);
  assertEq(t, 0); assertEq(u, 0);
}
