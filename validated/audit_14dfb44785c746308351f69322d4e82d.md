### Title
Symlink-based path traversal in artifact archiving via `os.Open` following symlinks in `raw.archiver.Archive` - ([File: commands/helpers/archive/raw/raw_archiver.go])

### Summary
`fileArchiver.add()` in `commands/helpers/file_archiver.go` validates and records artifact paths using `os.Lstat`, which correctly identifies symlinks without following them, but only checks that the symlink's own path lies inside the job working directory — it never resolves or validates the symlink's target. When the collected `files` map reaches `raw.archiver.Archive`, `os.Open(pathname)` is called, which does follow symlinks, so a symlink placed by the job script pointing outside the working directory is opened and its target content is streamed into the uploaded artifact.

### Finding Description
The containment check in `fileArchiver.process()` (`commands/helpers/file_archiver.go:65-101`) computes `absolute`/`relative` from the matched path string and rejects anything whose relative path escapes the working directory with `..`. Crucially, this check operates on the *path string itself*, not on the resolved (symlink-followed) location. `fileArchiver.add()` (`file_archiver.go:127-138`) then calls `os.Lstat(path)` — which by design does not follow symlinks — and stores the entry keyed by the symlink's own in-workspace path: [1](#0-0) 

`processPath()` uses `doublestar.FilepathGlob(rel, doublestar.WithNoFollow())` only to avoid symlink cycles while expanding the glob pattern itself, then walks matches with `filepath.Walk`, which also does not descend into symlinked directories but still yields symlinked *files* to the walk callback: [2](#0-1) 

None of this logic ever calls `filepath.EvalSymlinks` or otherwise verifies where the symlink actually points. The resulting `files` map (path -> `os.FileInfo` from `Lstat`) is passed unchanged into `archive.NewArchiver(...).Archive(...)`: [3](#0-2) 

For the raw format, `Archive` iterates the map and calls `os.Open(pathname)`, which — unlike `Lstat` — transparently follows symlinks to whatever target they point to, then streams its content via `io.Copy`: [4](#0-3) 

So a job that runs `ln -s /etc/passwd workdir/leak` and declares `artifacts: paths: [leak]` with `artifact-format: raw` causes the symlink path `leak` (which is legitimately inside the working directory) to pass all containment checks, while `os.Open("leak")` at archive time follows the link and reads `/etc/passwd` (or any file readable by the job process's UID) instead of a file confined to the workspace.

### Impact Explanation
An unprivileged pipeline author can exfiltrate the contents of any file readable by the job's OS user/container process — e.g. runner helper binaries, mounted secrets, SSH keys, or other host-accessible files under the executor's file permission model — by having it delivered back as a normal build artifact through the GitLab artifact channel, which the job's own project already has legitimate access to view/download.

### Likelihood Explanation
The exploit requires only standard job capabilities: create a symlink in the workspace and reference it via the `artifacts:paths` glob, both of which are entirely within an unprivileged pipeline author's control and require no special executor or admin misconfiguration. It is deterministic and repeatable in any executor where the job process has filesystem access to the sensitive target file (shell, docker with volume mounts, etc.).

### Recommendation
When walking/adding entries in `fileArchiver`, resolve the real path with `filepath.EvalSymlinks` (or equivalent) and re-validate that the resolved target is still within `c.wd` before adding it to `c.files`; alternatively, have the raw (and other) archivers refuse to `os.Open` a path whose `Lstat` mode has `os.ModeSymlink` set, or explicitly reject/skip symlinks whose resolved target escapes the working directory during `fileArchiver.process()`.

### Proof of Concept
Go unit test outline for `raw_archiver_test.go` / `file_archiver_test.go`:
```go
func TestRawArchiver_SymlinkEscape(t *testing.T) {
    dir := t.TempDir()
    outside := filepath.Join(t.TempDir(), "secret.txt")
    os.WriteFile(outside, []byte("TOP-SECRET"), 0600)

    link := filepath.Join(dir, "leak")
    os.Symlink(outside, link)

    fa := &fileArchiver{wd: dir}
    fa.files = map[string]os.FileInfo{}
    fa.excluded = map[string]int64{}
    fa.process(link) // simulates glob match inside wd

    var buf bytes.Buffer
    a, _ := raw.NewArchiver(&buf, dir, archive.DefaultCompression)
    err := a.Archive(context.Background(), fa.files)

    // Expected (fixed) behavior: err != nil or buf does not contain "TOP-SECRET"
    require.NotContains(t, buf.String(), "TOP-SECRET")
}
```
Current behavior: the assertion fails because `buf` contains `"TOP-SECRET"`, proving the target file outside `dir` was read and uploaded.

func (a *archiver) Archive(ctx context.Context, files map[string]os.FileInfo) error {
	if len(files) > 1 {
		return ErrTooManyRawFiles
	}

	for pathname := range files {
		f, err := os.Open(pathname)
		if err != nil {
			return err
		}
		defer f.Close()

		_, err = io.Copy(a.w, f)
