Confirmed: `contracts/BaseEscrowFactory.sol::createDstEscrow` (lines 165-185) accepts `dstImmutables` (including `parameters`) directly from `msg.sender` with no length or consistency validation before deployment, and no code anywhere in `contracts/` validates `parameters.length` for a destination escrow before withdrawal time.

## Title
Unvalidated `parameters` length lets an EscrowDst creator permanently brick both `withdraw` and `publicWithdraw`, freezing the maker's payout - (File: contracts/EscrowDst.sol)

### Summary
`EscrowDst._withdraw` decodes protocol/integrator fee amounts and recipients from the attacker-supplied `immutables.parameters` blob using `ImmutablesLib`. The length checks for fee *amounts* (`>= 0x20` / `>= 0x40`) are weaker than the checks for fee *recipients* (`>= 0x60` / `>= 0x80`). A destination-escrow creator who calls `createDstEscrow` fully controls the `parameters` bytes and their length, since the factory performs no validation on this field.

### Finding Description [1](#0-0) 

`createDstEscrow` takes `dstImmutables` verbatim from `msg.sender` and deploys the clone with it — there is no check on `dstImmutables.parameters`' length or content. [2](#0-1) 

`protocolFeeAmountCd`/`integratorFeeAmountCd` only require `parameters.length >= 0x20`/`0x40`, while `protocolFeeRecipientCd`/`integratorFeeRecipientCd` require `>= 0x60`/`0x80`. With a 64-byte (`0x40`) `parameters` blob, both fee-amount reads succeed but both recipient reads revert with `IndexOutOfRange`. [3](#0-2) 

`_withdraw` reads `integratorFeeAmountCd()`/`protocolFeeAmountCd()` first, and only skips the recipient read if the amount is zero. Since the creator fully controls those first 64 bytes, they can set either fee amount to a nonzero value, guaranteeing that any call into `_withdraw` — from `withdraw` (private) or `publicWithdraw` (public) — reverts on the recipient decode. Because `onlyValidImmutables` requires the exact same `immutables` (including this malformed `parameters`) used at deployment, this failure is permanent and cannot be worked around by any future caller, including public-withdrawal participants holding the access token.

### Impact Explanation
This matches the "temporary freezing of funds during the live swap lifecycle" bounty category: the maker's expected destination-chain payout can never be released via `withdraw` or `publicWithdraw` once the escrow is deployed with this malformed `parameters`. The only funds-recovery paths are `cancel()` (only callable by the same `taker` after `DstCancellation`, and it returns the escrow's tokens to the taker, not the maker) or `rescueFunds()` (only callable by `taker` after `RESCUE_DELAY`). The maker who is owed the destination funds has no path to claim them.

### Likelihood Explanation
Any address can call `createDstEscrow` and fully controls `immutables.parameters`, so triggering this requires no privileged role — only crafting a 64-byte parameters blob with a nonzero fee amount. This matches "unprivileged destination-escrow creator" in the Smart Audit Pivots' destination path (`createDstEscrow` -> funding -> withdraw/cancel flow).

### Recommendation
Validate `parameters.length` is either `0` or exactly the full expected size (`0x80`) at `createDstEscrow` time (and/or in `ImmutablesLib`), rejecting any length that would allow non-zero fee amounts to be decoded without their corresponding recipients being decodable.

### Proof of Concept
1. Attacker (any address) calls `createDstEscrow` with `dstImmutables.parameters = abi.encode(uint256(protocolFeeAmount>0), uint256(0))` truncated/crafted to exactly 64 bytes (i.e., only protocol/integrator fee amount words present, no recipient words), funding the escrow normally.
2. Warp past `DstWithdrawal`; call `withdraw(secret, immutables)` — reverts with `ImmutablesLib.IndexOutOfRange`.
3. Warp past `DstPublicWithdrawal`; any access-token holder calls `publicWithdraw(secret, immutables)` — also reverts with `IndexOutOfRange`, confirmed by `_withdraw`'s shared code path: [4](#0-3) 
4. Funds remain locked until the taker calls `cancel()`/`rescueFunds()`, both of which pay the taker, never the maker.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
