### Title
Unfair, instantaneous same-mint emissions distribution allows front-run deposit to steal rewards from long-term depositors - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
`lending_pool_emissions_deposit` is a permissionless instruction that injects extra tokens directly into a bank's liquidity vault and instantly re-prices `asset_share_value` based on the **current** `total_asset_shares` [3](#0-2) . Because the value bump is distributed strictly pro-rata to shares outstanding at that instant — with no consideration of how long a depositor has held those shares — a user can deposit a large amount immediately before this instruction executes, capture a disproportionate fraction of the injected value, and withdraw right afterward, since marginfi deposits/withdrawals have no minimum holding period or cooldown.

### Finding Description
The function computes the updated share value as:
```
total_assets = get_asset_amount(total_asset_shares)
updated_total_assets = total_assets + amount
asset_share_value = updated_total_assets / total_asset_shares
``` [4](#0-3) 

This is a direct structural analog of the Zaros staking-fairness bug: rewards ("emissions") are allocated based only on a snapshot of shares at distribution time, not on staking duration or precedence. The docstring itself confirms the mechanism: "Permissionlessly deposit same-mint emissions directly into the bank liquidity vault, increasing depositor value through asset share value" [5](#0-4) , and the public entrypoint is explicitly documented as `(permissionless)` [6](#0-5) .

The unit tests confirm the exact mechanics of the bug class: depositor share value is boosted purely proportionally to the shares each depositor holds at call time, regardless of how long they have held them [7](#0-6) . There is no lockup, minimum staking duration, or time-weighting anywhere in the deposit/withdraw code paths, both of which execute instantly and permissionlessly [1](#0-0) [2](#0-1) .

This is distinct from marginfi's separate time-weighted `emissions_rate` mechanism (accrued continuously via `emissions_outstanding`/`last_update` per `Balance`) [8](#0-7) , which is fair because it integrates balance over time. The `lending_pool_emissions_deposit` same-mint path bypasses that fairness entirely by directly mutating `asset_share_value` in one shot.

### Impact Explanation
An attacker who can predict or front-run a legitimate emissions/incentive-campaign deposit (a routine, expected, publicly-known event since campaigns are announced and executed on a schedule per the `EMISSIONS.md`/patch-note documentation) can:
1. Deposit a large amount into the target bank just before the `lending_pool_emissions_deposit` transaction lands.
2. Receive a disproportionate share of the value increase relative to depositors who have held their position for the full incentive period.
3. Immediately withdraw, realizing the stolen value with no exposure time and no penalty.

This redirects value from genuine long-term depositors to opportunistic short-term capital, directly undermining the intended incentive design and is a durable, repeatable economic exploit each time same-mint emissions are deposited.

### Likelihood Explanation
Emissions deposits are periodic/announced protocol operations (weekly-style cadence per documentation), and the instruction is permissionless with no anti-sandwich protection, no snapshotting of eligible depositors, and no minimum holding period, making the attack straightforward to execute by any user monitoring for campaign deposits.

### Recommendation
Snapshot eligible depositor shares (or use a Merkle/checkpoint-based distribution) prior to executing `lending_pool_emissions_deposit`, or require a minimum holding/vesting period before newly deposited shares become eligible for a proportional share of same-mint emissions injections — analogous to time-weighted (MasterChef/Synthetix-style) reward accounting already used for the separate `emissions_rate` mechanism.

### Proof of Concept
1. Bank has `total_asset_shares` = 100 (from long-term depositor A holding for weeks).
2. Attacker observes/knows an emissions-campaign operator is about to call `lending_pool_emissions_deposit(amount)`.
3. Attacker calls `lending_account_deposit` with a large amount (e.g., 900), instantly making `total_asset_shares` = 1000, of which attacker holds 900 (90%).
4. Campaign operator's `lending_pool_emissions_deposit` transaction executes, bumping `asset_share_value` uniformly across all 1000 shares [4](#0-3) .
5. Attacker immediately calls `lending_account_withdraw` to redeem their shares at the new higher `asset_share_value`, capturing 90% of the emissions deposit despite 0 duration of exposure, while depositor A — who funded/held the position for the entire campaign — only receives 10%.

/// Permissionlessly deposit same-mint emissions directly into the bank liquidity vault,
/// increasing depositor value through asset share value.
pub fn lending_pool_emissions_deposit(
    ctx: Context<LendingPoolEmissionsDeposit>,
    amount: u64,
) -> MarginfiResult {
    if amount == 0 {
        return Ok(());
    }

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = ctx.accounts.group.load()?;

    utils::validate_bank_state(&bank, utils::InstructionKind::FailsIfPausedOrReduceState)?;

    // Reject mints with non-zero transfer fees or active transfer hooks.
    let mint_ai = ctx.accounts.mint.to_account_info();
    check!(
        !utils::nonzero_fee(mint_ai.clone(), clock.epoch)?,
        MarginfiError::InvalidTransfer
    );
    check!(
        !utils::has_transfer_hook(mint_ai)?,
        MarginfiError::InvalidTransfer
    );

    let total_asset_shares = I80F48::from(bank.total_asset_shares);
    check!(
        total_asset_shares > I80F48::ZERO,
        MarginfiError::EmissionsUpdateError
    );

    bank.accrue_interest(
        clock.unix_timestamp,
        &group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.key(),
            TransferChecked {
                from: ctx.accounts.emissions_funding_account.to_account_info(),
                to: ctx.accounts.liquidity_vault.to_account_info(),
                authority: ctx.accounts.depositor.to_account_info(),
                mint: ctx.accounts.mint.to_account_info(),
            },
        ),
        amount,
        ctx.accounts.mint.decimals,
    )?;

    let total_assets = bank.get_asset_amount(total_asset_shares)?;
    let updated_total_assets = total_assets
        .checked_add(I80F48::from_num(amount))
        .ok_or_else(math_error!())?;

    bank.asset_share_value = updated_total_assets
        .checked_div(total_asset_shares)
        .ok_or_else(math_error!())?
        .into();

async fn emissions_same_bank_deposit_updates_asset_share_value() -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;

    let usdc_bank = test_f.get_bank(&BankMint::Usdc);

    let emissions_funding = test_f.usdc_mint.create_token_account_and_mint_to(50).await;

    let depositor_a = test_f.create_marginfi_account().await;
    let depositor_b = test_f.create_marginfi_account().await;

    let depositor_a_usdc = test_f.usdc_mint.create_token_account_and_mint_to(40).await;
    let depositor_b_usdc = test_f.usdc_mint.create_token_account_and_mint_to(60).await;

    let depositor_a_amount = 40;
    depositor_a
        .try_bank_deposit(
            depositor_a_usdc.key,
            usdc_bank,
            depositor_a_amount as f64,
            None,
        )
        .await?;

    let depositor_b_amount = 60;
    depositor_b
        .try_bank_deposit(
            depositor_b_usdc.key,
            usdc_bank,
            depositor_b_amount as f64,
            None,
        )
        .await?;

    let bank_before = usdc_bank.load().await;
    let shares_before = I80F48::from(bank_before.total_asset_shares);
    let share_value_before = I80F48::from(bank_before.asset_share_value);

    let liquidity_vault_before =
        TokenAccountFixture::fetch(test_f.context.clone(), bank_before.liquidity_vault)
            .await
            .balance()
            .await;

    let emissions_deposit = 50;
    usdc_bank
        .try_emissions_deposit(native!(emissions_deposit, "USDC"), emissions_funding.key)
        .await?;

    let bank_after = usdc_bank.load().await;
    let shares_after = I80F48::from(bank_after.total_asset_shares);
    let share_value_after = I80F48::from(bank_after.asset_share_value);

    let liquidity_vault_after =
        TokenAccountFixture::fetch(test_f.context.clone(), bank_after.liquidity_vault)
            .await
            .balance()
            .await;

    let asset_shares_value_multiplier =
        1.0 + emissions_deposit as f64 / (depositor_a_amount + depositor_b_amount) as f64;

    assert_eq!(shares_after, shares_before);

    // Should be equal, zero liabilities are present
    assert_eq!(
        share_value_before
            .checked_mul(I80F48::from_num(asset_shares_value_multiplier))
            .unwrap(),
        share_value_after
    );
    assert_eq!(
        liquidity_vault_after - liquidity_vault_before,
        native!(emissions_deposit, "USDC")
    );
    assert_eq!(I80F48::from(bank_after.emissions_remaining), I80F48::ZERO);
