### Title
Missing upper-bound (future) validation of `ExecutionPayload`-analog `TriggerRequestPayload.Timestamp` in the Gateway's public Web API trigger handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The `HandleLegacyUserMessage` handler in `core/services/gateway/handlers/capabilities/handler.go` processes JSON-RPC trigger requests submitted by unauthenticated/unprivileged HTTP clients against the Gateway's public Web API trigger surface. It validates the `Timestamp` field of the attacker-controlled `webapicap.TriggerRequestPayload` only for the "too old" (stale) case, but never validates an upper bound (future timestamp), analogous to the reported `ExecutionPayload.Timestamp` bug where only a lower-bound relationship (`> parent`) was checked by the execution client and no upper bound was enforced by the consensus layer.

### Finding Description
`HandleLegacyUserMessage` decodes an unprivileged, network-facing `api.Message` payload into `webapicap.TriggerRequestPayload` and checks: [1](#0-0) 

Specifically, it rejects `Timestamp == 0` and rejects timestamps that are too old: [2](#0-1) 

There is no check that `payload.Timestamp` is not set arbitrarily far in the future (e.g., `math.MaxInt64`). The field is documented in the schema as needing to be "within certain freshness to be processed" implying both bounds should be enforced: [3](#0-2) 

After passing this check, the message (including the unbounded `Timestamp`) is forwarded unmodified to every DON node member: [4](#0-3) 

On the node side, `triggerConnectorHandler.processTrigger` wraps the entire payload (including the attacker-supplied `Timestamp`) into the `capabilities.TriggerEvent.Outputs` that is delivered directly into workflow execution, with no re-validation of `Timestamp`'s upper bound: [5](#0-4) 

This mirrors the report's root cause pattern: a field intended to represent real-world time is accepted from an untrusted request with only partial (one-sided) validation, allowing a malicious/unprivileged sender to inject an artificial, unbounded timestamp value that propagates into downstream logic that assumes it is trustworthy.

### Impact Explanation
Any external, unauthenticated caller able to reach the Gateway's public Web API trigger endpoint can submit a `TriggerRequestPayload` with an arbitrary future `Timestamp` (as long as it is nonzero and not older than `MaxAllowedMessageAgeSec`). This value flows unchecked into the `TriggerEvent.Outputs` delivered to the workflow engine and ultimately to user workflow code, which may treat `Timestamp` as an authoritative representation of "when this event occurred." Downstream workflow logic that uses this value for scheduling, deduplication windows, ordering, or business decisions can be manipulated by a completely unprivileged caller. This is a data-integrity/business-logic manipulation impact, not the chain-halting DoS impact of the original report (there is no consensus/proposer mechanism in this codepath), so severity is lower than "Critical."

### Likelihood Explanation
High likelihood of exploitability for any deployment that exposes the Gateway's legacy Web API trigger method, since `HandleLegacyUserMessage` is reachable from any external HTTP/JSON-RPC caller without additional authorization beyond the trigger's allowlist/topic checks that occur later on the node side, and the vulnerable check happens before those checks (`h.lggr.Errorw("stale message")` gate is the only timestamp gate applied).

### Recommendation
Add an upper-bound check in `HandleLegacyUserMessage` (and any successor handlers processing `webapicap.TriggerRequestPayload`) such that `payload.Timestamp` must not exceed `time.Now().Unix() + <allowed clock-skew tolerance>`, mirroring the existing staleness check pattern already used for `MaxAllowedMessageAgeSec`. Reject requests whose timestamp is unreasonably in the future with the same `"stale message"`/`HandlerError` semantics.

### Proof of Concept
1. An unauthenticated actor with access to the Gateway's Web API trigger endpoint constructs a `TriggerRequestPayload` JSON body with `"timestamp": 9223372036854775807` (max int64) and valid `trigger_id`, `trigger_event_id`, `topics`, `params`.
2. The actor signs and sends this as an `api.Message` to the gateway's legacy user message endpoint invoking `MethodWebAPITrigger`.
3. `HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` (lines 359–383) only checks `Timestamp == 0` and staleness (`now - MaxAllowedMessageAgeSec > Timestamp`); a far-future timestamp passes both checks.
4. The message is forwarded to DON nodes; `processTrigger` in `core/capabilities/webapi/trigger/trigger.go` wraps the payload (with the poisoned `Timestamp`) into `TriggerEvent.Outputs` and delivers it to the workflow engine/user workflow code unmodified.

Note: I could not fully trace whether any specific production workflow currently relies on `payload.Timestamp` for security-relevant decisions (e.g., replay windows) beyond what is shown in `trigger.go`/`handler.go`; the index may not contain all downstream workflow-execution consumers of this field. If a Devin session with full repository access is desired to confirm all consumers of `TriggerRequestPayload.Timestamp` and their trust assumptions, that would need to be done outside this ask-only analysis.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(

				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})

func (h *triggerConnectorHandler) processTrigger(ctx context.Context, gatewayID string, body *api.MessageBody, sender ethCommon.Address, payload webapicap.TriggerRequestPayload) error {
	// Pass on the payload with the expectation that it's in an acceptable format for the executor
	wrappedPayload, err := values.WrapMap(payload)
	if err != nil {
		return fmt.Errorf("error wrapping payload %w", err)
	}
	topics := payload.Topics

	// empty topics is error for V1
	if len(topics) == 0 {
		return errors.New("empty Workflow Topics")
	}

	// workflows that have matched topics
	matchedWorkflows := 0
	// workflows that have matched topic and passed all checks
	fullyMatchedWorkflows := 0
	for _, trigger := range h.registeredWorkflows {
		for _, topic := range topics {
			if trigger.allowedTopics[topic] {
				matchedWorkflows++
				if !trigger.allowedSenders[sender.String()] {
					err = fmt.Errorf("unauthorized Sender %s, messageID %s", sender.String(), body.MessageId)
					h.lggr.Debugw(err.Error())
					continue
				}
				if !trigger.rateLimiter.Allow(body.Sender) {
					err = fmt.Errorf("request rate-limited for sender %s, messageID %s", sender.String(), body.MessageId)
					continue
				}
				fullyMatchedWorkflows++
				TriggerEventID := body.Sender + payload.TriggerEventId

				// Emit trigger execution started event
				workflowExecutionID, genErr := events.GenerateExecutionID(trigger.workflowID, TriggerEventID)
				if genErr != nil {
					h.lggr.Errorw("failed to generate execution ID", "err", genErr)
					workflowExecutionID = ""
				}
				emitErr := events.EmitTriggerExecutionStarted(ctx, map[string]string{}, TriggerEventID, workflowExecutionID)
				if emitErr != nil {
					h.lggr.Errorw("failed to emit trigger execution started event", "err", emitErr)
				}

				tr := capabilities.TriggerResponse{
					Event: capabilities.TriggerEvent{
						TriggerType: TriggerType,
						ID:          TriggerEventID,
						Outputs:     wrappedPayload,
					},
				}
