### Title
Unbounded iteration over vesting contract shareholders in `distribute()` can permanently strand vested funds and commission - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute` (and the functions that depend on it — `vest`, `unlock_rewards`/`vest`/`terminate_vesting_contract`) iterates over **every shareholder** stored in a vesting contract's `grant_pool` in a single transaction, exactly the same gas-scaling bug class as Sherlock M-8 (EMPAM iterating over every bid during settlement). If a vesting contract is created with a large shareholder set, `distribute()` can permanently exceed the block gas limit, and because `terminate_vesting_contract` unconditionally calls `distribute` first, the vested/rewards balance becomes permanently unreachable for every shareholder and for the admin's withdrawal address.

### Finding Description
`distribute` is a public, unprivileged entry function (`public entry fun distribute(contract_address: address)`), callable by anyone, that withdraws all currently-unlocked stake and then loops over the full list of shareholders to pay them their proportional share: [1](#0-0) 

Inside the loop, for every shareholder the code performs a `pool_u64::shares` lookup, a `shares_to_amount_with_total_coins` computation, a `coin::extract`, a `get_beneficiary` map lookup, and an `aptos_account::deposit_coins` call (which can also register a new coin store for the recipient) — several gas-intensive operations per iteration, closely mirroring the per-bid computation in the referenced EMPAM report: [2](#0-1) 

The set of shareholders is fixed at contract-creation time via the `shareholders`/`buy_ins` vectors passed into `create_vesting_contract`. I could not find any upper bound on the number of shareholders in the creation path — only checks for empty vectors and matching vector lengths were found (`test_create_vesting_contract_with_no_shareholders_should_fail`, `test_create_vesting_contract_with_mistmaching_shareholders_should_fail`): [3](#0-2) 

Because `terminate_vesting_contract` unconditionally calls `distribute` before it can proceed: [4](#0-3) 

...and `vest`/`unlock_rewards` funnel new unlocks into the same pool that `distribute` must eventually drain, a vesting contract whose shareholder count is large enough to make `distribute` exceed the gas limit becomes stuck: no shareholder can ever be paid, and the admin can never terminate the contract or reclaim the remaining grant via `admin_withdraw` (which also requires the terminated state).

Note: the batch helpers `distribute_many`/`vest_many`/`unlock_rewards_many` loop over caller-supplied contract address vectors, but that is self-inflicted (caller controls array size); the vulnerability described here is the *inner* per-contract shareholder loop that a caller cannot bound.

### Impact Explanation
This is a "permanent lock or non-recoverable loss of claim rights in ... vesting flows," matching the required impact set:
- All shareholders lose access to their vested stake and accumulated staking rewards forever, since `distribute` cannot complete.
- The admin loses the ability to `terminate_vesting_contract`/`admin_withdraw` the remaining grant, since termination is gated on a successful `distribute` call.
- No unprivileged caller (or even the admin) can work around this once the shareholder count is large enough to exceed the gas limit, since the entire shareholder list is redistributed atomically every time.

This is comparable in class and severity to the EMPAM finding: unbounded per-item loop in a fund-settlement/distribution path causing systemic, non-recoverable fund lock.

### Likelihood Explanation
Likelihood depends on how many shareholders a vesting contract is created with. Real ESOP/staking-reward vesting contracts for large organizations or DAOs plausibly have hundreds to thousands of shareholders (this is the normal, legitimate use case for `vesting.move`, not an artificial attack setup), so the shareholder count does not require any special privilege to grow large — an admin creating a large legitimate vesting pool triggers this without malicious intent. I was not able to confirm from the indexed code whether there is a hard maximum enforced elsewhere (e.g., in a governance-configured constant) that would prevent this; this should be verified directly against the full `vesting.move` source, since the indexer may not have surfaced every constant/assert in the file.

### Recommendation
- Add an explicit maximum shareholder-count check in `create_vesting_contract` (mirroring the EMPAM fix's max-bid-count safeguard) so the contract cannot be instantiated in a state where `distribute` is guaranteed to exceed the gas limit.
- Alternatively, refactor `distribute` to process shareholders in bounded batches (e.g., a `distribute_batch(contract_address, start_index, batch_size)` entry function) so no single transaction is forced to process the entire shareholder list, and decouple `terminate_vesting_contract`'s termination state from requiring a single fully-successful `distribute` call.

### Proof of Concept
1. Call `vesting::create_vesting_contract` with a `shareholders` vector containing N distinct addresses and matching `buy_ins`, where N is large enough that each entry's per-iteration cost (pool lookup + share math + coin extract + beneficiary lookup + deposit) causes cumulative execution to exceed the transaction/block gas limit (analogous to the 580-bid PoC in the referenced report scaled to this loop's per-iteration cost).
2. Let the underlying stake pool accumulate/unlock stake normally (`vest`/`unlock_rewards`/lockup expiration).
3. Call `distribute(contract_address)` — the transaction runs out of gas inside the `shareholders.for_each_ref` loop and reverts.
4. Call `terminate_vesting_contract(admin, contract_address)` — it also reverts because it calls `distribute` first.
5. All future `vest`, `unlock_rewards`, `distribute`, and `terminate_vesting_contract`/`admin_withdraw` calls on this contract permanently fail, locking all vested stake and rewards.

Exact gas thresholds and any un-indexed shareholder-count caps could not be independently verified from the available code index; a background agent with full repository access should confirm the absence of a shareholder cap and measure actual per-iteration gas cost in `distribute` before finalizing severity.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);
