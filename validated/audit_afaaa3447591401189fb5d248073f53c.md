### Title
Dust queued deposit in the prefunded AA queue permanently bricks `stopEpochWithDuration`, freezing all vault funds - ([File: contracts/IdleCDOEpochQueue.sol])

### Summary
The external bug is a malicious-server-induced infinite busy-loop in libcurl (DoS). The strongest in-scope analog is a revert-condition that permanently blocks the epoch state machine: on `IdleCDOEpochVariantPrefunded`, `stopEpochWithDuration` always calls `IdleCDOEpochQueue.prefundedDepositsToProcess()`, which reverts whenever the target epoch still has raw `epochPendingDeposits`. Any KYC-passing lender can deposit 1 wei into the queue in the last block of the open prefunding window, after which neither the manager nor anyone else can clear it, so `stopEpochWithDuration` reverts forever and every tranche holder's funds are permanently frozen in the vault.

### Finding Description
In `IdleCDOEpochVariantPrefunded._afterStopEpochWithDuration`, the queue settlement is unconditional whenever `epochQueue != address(0)`: [1](#0-0) 

`prefundedDepositsToProcess()` reverts if the epoch being settled still holds queue-held deposits: [2](#0-1) 

Deposits enter `epochPendingDeposits[nextEpoch]` via permissionless `requestDeposit`, gated only by `isEpochRunning` and KYC (`_checkAllowed`), plus the prefunded-window cutoff: [3](#0-2) 

The only path that clears `epochPendingDeposits` into `epochPrefundedDeposits` is manager-only `processDepositsToBorrower`, which is itself blocked once `block.timestamp + prefundedDepositWindow >= epochEndDate`: [4](#0-3) 

`deleteRequest` exists, but only the depositor can call it. So an attacker who deposits dust just before the window cutoff leaves a nonzero `epochPendingDeposits[epochNumber + 1]` that no honest actor can remove. At epoch end, `stopEpochWithDuration` → `_afterStopEpochWithDuration` → `prefundedDepositsToProcess` reverts deterministically, in every block, forever — the curl busy-loop analog. The deposit is even refundable to the attacker afterward via `deleteRequest`, making the griefing free.

### Impact Explanation
Permanent freezing of all funds. While `stopEpochWithDuration` reverts, `epochNumber` never advances, `epochEndDate` stays in the past, `requestWithdraw` receipts can never be claimed (`_claimFundedWithdrawRequest` requires `epochNumber > lastWithdrawRequest`), and normal `depositAA/BB` and withdraw flows that depend on epoch transitions are bricked. The entire pool NAV — borrower capital plus all AA/BB tranche principal — is locked indefinitely. Cost to attacker: ~1 wei of underlying plus gas, recoverable via `deleteRequest`.

### Likelihood Explanation
High. Requires only a KYC-passing wallet (an allowed attacker class) and one `requestDeposit` transaction. The guaranteed version lands the dust deposit in the final block where `block.timestamp + prefundedDepositWindow < epochEndDate` still holds; the manager then has zero remaining blocks in which `processDepositsToBorrower` can succeed. Front-running a manager prefund transaction with a dust deposit achieves the same result any time during the window. No privileged misbehavior required — the honest manager cannot prevent it.

### Recommendation
In `stopEpochWithDuration`/`prefundedDepositsToProcess`, don't revert on leftover `epochPendingDeposits`; instead either (a) sweep leftover pending deposits into the prefunded amount at stop time and mint shares for them too, or (b) price leftover queue deposits at `virtualPrice` inside `processPrefundedDeposits` and clear them, mirroring the non-prefunded `processDeposits` path. Alternatively, make `requestDeposit` for prefunded AA queues require that deposits be prefunded atomically (pull-then-forward), so queue-held balances can never straddle the stop boundary.

pragma solidity 0.8.10;
// Foundry fork test: prefunded variant with epochQueue set, prefundedDepositWindow = 5 days

function testDustDepositPermanentlyBricksStopEpoch() external {
    // setup: prefunded CDO, AA queue enabled, manager set prefundedDepositWindow(5 days)
    // epoch running, epochEndDate = block.timestamp + 30 days

    // 1. Attacker (KYC-passing lender) deposits 1 wei in the last open block
    vm.warp(cdo.epochEndDate() - queue.prefundedDepositWindow() - 1);
    underlying.approve(address(queue), 1);
    vm.prank(attacker);
    queue.requestDeposit(1); // epochPendingDeposits[epochNumber + 1] = 1

    // 2. Manager can no longer prefund: cutoff passed
    vm.warp(block.timestamp + 2);
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    queue.processDepositsToBorrower();

    // 3. Epoch ends; every stopEpochWithDuration reverts forever
    vm.warp(cdo.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdo.stopEpochWithDuration(0, expectedFunds);

    // repeat at any later timestamp — still reverts
    vm.warp(block.timestamp + 365 days);
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdo.stopEpochWithDuration(0, expectedFunds);

    // 4. Withdraw receipts can never become claimable: epochNumber frozen
    assertEq(strategy.epochNumber(), epochBefore);

    // 5. Attacker even recovers the dust
    vm.prank(attacker);
    queue.deleteRequest(epochBefore + 1);
}

  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);

      // Once funds are prefunded, or once the subscription window is reached, the next epoch is closed.
