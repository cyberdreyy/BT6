### Title
JWT replay-protection check-then-act race in `WorkflowMetadataHandler.Authorize` allows concurrent replay of a single signed HTTP-trigger JWT - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The Gitcoin report's root cause is a broken invariant caused by state being read/branched-on in one step and written in a separate, non-atomic step, letting an attacker exploit the gap to bypass an accounting/anti-replay guarantee. The same pattern exists in Chainlink's Gateway HTTP-Trigger V2 JWT replay guard: the "used" check and the "mark as used" write are two separate lock acquisitions instead of one atomic check-and-set, so two concurrent requests carrying the identical signed JWT can both pass authorization.

### Finding Description
`WorkflowMetadataHandler.Authorize` is the entry point that authenticates an unprivileged, internet-facing HTTP-trigger request before it is fanned out to workflow nodes to start (or re-trigger) a workflow execution: [1](#0-0) 

The replay guard itself is implemented with two independently-locked operations: [2](#0-1) 

`isReplay` takes an `RLock`, checks map membership, and releases the lock. `recordUsage` is only called afterward (after JWT signature verification and the authorized-key lookup), taking a separate `Lock`. Between the `isReplay` check and the `recordUsage` write there is no held lock and no atomicity — this is structurally identical to the `release()` bug: a value (whether the JWT `jti` has been "consumed") is checked in one step but the corresponding state update happens in another, disconnected step, so the invariant "each `jti` is accepted at most once" is not enforced atomically.

`Authorize` is called from `httpTriggerHandler.authorizeRequest`, which is invoked directly on the request path of `HandleUserTriggerRequest` for every inbound, unauthenticated-until-this-point HTTP trigger request from external callers: [3](#0-2) [4](#0-3) 

Because gateway message handling for distinct request IDs can execute concurrently (the only per-request serialization is on `requestID` via `callbacksMu`/`h.callbacks`, not on JWT `jti`), an attacker who captures/replays a single valid signed JWT and fires two (or more) requests with the same JWT but distinct `id`s at nearly the same time can have both requests pass `Authorize` before either call to `recordUsage` completes, since the check (`isReplay`) for request B can run and return `false` before request A's `recordUsage` executes.

### Impact Explanation
A successful race lets an unprivileged external actor cause an already-consumed (should-be single-use) signed JWT to authorize more than one distinct trigger request, i.e., request impersonation/authorization bypass of the "used-once" invariant. Each successful `Authorize` call leads to `HandleUserTriggerRequest` proceeding to rate-limit checks and then to `sendWithRetries`, which dispatches a `workflows.execute` message to the workflow DON — i.e., an unauthorized/duplicate job (workflow) run triggered from a single signed authorization artifact. This matches the "unauthorized job run" impact class referenced in the rules. The severity is bounded by rate limiting (`userRateLimiter`) and by the fact that the attacker must already possess (or intercept) a legitimately-signed JWT, but the replay guard is explicitly documented and tested as the mechanism meant to prevent exactly this reuse, and that guarantee is not actually atomic.

### Likelihood Explanation
Exploitation requires only network-level concurrency from an unprivileged HTTP-trigger caller (no special privileges, no malicious node/peer, no operator access) — sending the same signed JWT in two simultaneous requests with distinct JSON-RPC `id`s. The race window is small (time between the `RLock`-protected read and the later `Lock`-protected write, which includes an authorized-key map lookup) but is a genuine, deterministically reproducible TOCTOU race under concurrent load, not a purely theoretical one. Likelihood is assessed as low-to-moderate because it needs precise timing and an already-obtained token, but the reachable path is fully unprivileged and internet-facing.

### Recommendation
Make the replay check-and-mark atomic: acquire a single mutex (or use a single `LoadOrStore`-style atomic map operation) that performs the "already used" check and the "mark used" write as one critical section in `jwtReplayCache`, e.g. a `checkAndRecord(jti) (alreadyUsed bool)` method analogous to `RequestReplayGuard.CheckAndRecord` used elsewhere in the vault capability code (`core/capabilities/vault/request_replay_guard.go`), which already implements this pattern correctly and could be reused/mirrored here.

### Proof of Concept
Conceptual PoC (not executed, derived from code reading):
1. Attacker obtains one validly-signed HTTP-trigger JWT for a given `jsonrpc.Request` digest/`jti`.
2. Attacker crafts two `HandleUserTriggerRequest` calls with distinct top-level `id`s (satisfying `setupCallback`'s per-`requestID` uniqueness check) but reuses the same JWT/`Auth` token and same underlying signed digest.
3. Both requests hit `httpTriggerHandler.authorizeRequest` → `WorkflowMetadataHandler.Authorize` concurrently (e.g., via two goroutines/two simultaneous gateway connections).
4. If `isReplay(jti)` for request 2 executes before `recordUsage(jti)` for request 1 completes, both calls return no error, both proceed to `sendWithRetries`, and the workflow DON receives two `workflows.execute` triggers from what should be a single-use signed authorization.

Note: I could not execute this against a live gateway instance in this environment; the analysis is based on static code reading of `jwtReplayCache.isReplay`/`recordUsage` and their call sites. If deeper verification (e.g., a Go race-detector test reproducing the double-authorize) is desired, a Devin session with repo access would be needed to write and run such a test.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
