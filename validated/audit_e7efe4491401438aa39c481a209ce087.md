### Title
Stale confirmations from removed multisig members allow execution below `num_confirmations` live members - (File: `multisig2/src/lib.rs`)

### Summary
`delete_member` only purges the `confirmations` map for requests that the removed member *originated*, not for requests they merely *confirmed* as a co-signer. `confirm` then counts `confirmations.len()` without re-validating that every entry still belongs to a current member, so a stale confirmation from a since-removed member can be combined with fewer live approvals to reach `num_confirmations` and trigger execution.

### Finding Description
The invariant this code is supposed to preserve is:
`num_confirmations == |{ m ∈ confirmations[request_id] : m ∈ members_at_execution_time }|`

In practice the code only guarantees `confirmations[request_id].len() + 1 >= num_confirmations` at the moment `confirm` is called [1](#0-0) , with no check that each existing entry in `confirmations[request_id]` still corresponds to a `MultisigMember` present in `self.members`.

`delete_member` cleans up requests and confirmations only for the subset of requests where the removed member is the *original requester* (`r.member == member`): [2](#0-1) 
It does not scan every entry of every `confirmations` set to strip out the removed member's confirmation string from requests they merely co-confirmed but did not originate. `remove_request`, used both by `confirm` on execution and by `delete_request`, likewise never re-validates confirmer membership [3](#0-2) . `assert_valid_request` only checks that the *caller* is currently a member and that the request/confirmations exist - it does not validate the historical confirmers [4](#0-3) . `current_member` also shows that the same real-world principal can be independently registered as `MultisigMember::Account` (called cross-contract) and `MultisigMember::AccessKey` (called directly with a function-call-permission key on the multisig account itself), producing two distinct string keys in the `confirmations` set for the same actor [5](#0-4) .

Exploit flow:
1. Multisig has members `{A_key (AccessKey), B, C, ...}`, `num_confirmations = N`.
2. Member `B` calls `add_request` for a `Transfer` request `X` (so `X.member == B`).
3. `A_key` calls `confirm(X)`, inserting `"AccessKey:<pk_A>"` into `confirmations[X]` (below threshold).
4. Some unrelated, legitimate `DeleteMember { member: AccessKey{pk_A} }` request executes (e.g., key rotation/incident response). `delete_member` removes `A_key` from `self.members`, but since `X.member != AccessKey{pk_A}` (X was created by `B`), `X`'s confirmation set is left untouched - `A_key`'s stale confirmation for `X` survives.
5. A remaining live member calls `confirm(X)` once more. `confirmations[X].len() + 1 >= num_confirmations` becomes true using the stale `A_key` entry plus this one fresh confirmation, so `execute_request` runs and moves funds - even though only one genuinely live member ever approved `X` after `A_key`'s removal.

None of the existing guards (`assert_valid_request`, `current_member`, the `members.len()-1 >= num_confirmations` check in `delete_member`) validate that confirmers recorded in `confirmations[request_id]` are still members at confirm/execute time.

### Impact Explanation
This lets a request execute (e.g., a `Transfer` moving NEAR out of the multisig account) with fewer than `num_confirmations` *live* member approvals, directly matching the explicitly listed Critical impact: "a multisig request executed below `num_confirmations` live members." Because `delete_member` never sweeps stale entries out of unrelated requests' confirmation sets, this is repeatable for every request pending at the time any member is removed, across any multisig deployed from this contract.

### Likelihood Explanation
This requires no special privilege beyond ordinary multisig operation: any member confirming a request that they did not originate, followed by their own removal (for any unrelated reason) before that request is fully confirmed/executed, leaves an exploitable stale confirmation. No collusion beyond normal multisig activity is needed, and the sequence (confirm → remove member → confirm again) is trivial to trigger and cheap (ordinary contract calls, no deposit requirements beyond gas).

### Recommendation
When a member is deleted, iterate all pending requests' `confirmations` sets (not just requests they originated) and remove the deleted member's confirmation string from each. Additionally, in `confirm`, when counting toward the threshold, filter `confirmations[request_id]` to only those entries that are still present in `self.members` before comparing against `num_confirmations`.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .unwrap_or_else(|| env::panic_str("Failed to remove existing element"));
        // decrement num_requests for original request signer
        let original_member = request_with_signer.member;
        let mut num_requests = self
            .num_requests_pk
            .get(&original_member.to_string())
            .unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_member.to_string(), &num_requests);
        // return request
        request_with_signer.request
    }
