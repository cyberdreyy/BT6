### Title
Zip-slip path traversal in legacy zip extractor allows writing outside build/cache root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFileEntry`, `extractZipSymlinkEntry`, and `extractZipDirectoryEntry` in `helpers/archives/zip_extract.go` use `zip.File.Name` verbatim as the destination path for `os.OpenFile`, `os.Symlink`, and `os.Mkdir`/`os.MkdirAll`, with no containment check against the extraction root. This is unlike `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly validates each resolved path with `filepath.Abs` + `strings.HasPrefix(path, e.dir+separator)` before writing. Note: the file cited in the question, `helpers/docker/options.go`, is unrelated to archive extraction (it only configures the Docker HTTP client/TLS transport) and is not part of this vulnerable path — the actual vulnerable code lives in `helpers/archives/zip_extract.go`, reached via the legacy zip extractor.

### Finding Description
`ExtractZipArchive` iterates `archive.File` entries and calls `extractZipFile(file)` for each: [1](#0-0) 

That function does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on entry type, calls `extractZipDirectoryEntry` (`os.Mkdir(file.Name, ...)`), `extractZipSymlinkEntry` (`os.Symlink(string(data), file.Name)`), or `extractZipFileEntry` (`os.OpenFile(file.Name, ...)`): [2](#0-1) 

None of these validate `file.Name` against the destination root: no `filepath.Abs`/`filepath.Clean` + prefix check is performed anywhere in this file, in contrast to the containment check present in the tar+zstd extractor: [3](#0-2) 

The only path-related check in the zip path is `errorIfGitDirectory`, which only warns about `.git` directory entries and does not stop extraction or enforce containment: [4](#0-3) 

This legacy zip extractor is compiled in and used as a fallback path (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` calls `ExtractZipFile`/`ExtractZipArchive`), which is invoked by `CacheExtractorCommand.Execute` and `ArtifactsDownloaderCommand.Execute` when the archive format resolves to Zip via `archive.NewExtractor`: [5](#0-4) [6](#0-5) 

An attacker (any pipeline author) controls the content of artifacts they upload via `artifacts:paths` or the cache they populate — the Runner archives whatever the job produced. A malicious `.zip` created by job scripts using arbitrary tooling (or crafted directly with Python `zipfile`/manual byte editing before being fed as an "artifact" through non-standard paths, e.g. custom build steps that write a raw zip and register it) can contain entries with `zip.File.Name` values such as `../../../etc/cron.d/x` or an absolute path, or a symlink entry whose target/data is an absolute path or contains `../`. When such an archive later goes through the ziplegacy extractor's `ExtractZipArchive`, `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile`/`os.Symlink` will write outside the intended checkout/cache directory on the Runner host or container filesystem.

### Impact Explanation
On any executor where the ziplegacy fallback extractor path is exercised, a crafted zip artifact/cache archive can escape the build directory and write or overwrite arbitrary files (including symlink targets) at attacker-chosen paths reachable by the Runner process's permissions — violating the invariant that archive extraction stays confined to the destination root. This can lead to file overwrite/persistence outside the job root (e.g., overwriting files in shared paths, or planting files that get picked up elsewhere), scoped to whatever filesystem the extraction runs in (host for shell executor, container filesystem for docker/kubernetes executors).

### Likelihood Explanation
Preconditions: the ziplegacy zip extractor code path must actually be selected (it appears to be a legacy/fallback relative to `fastzip`), and the artifact/cache file must be a zip whose `zip.File.Name` fields were crafted with traversal sequences — trivially achievable since `archive/zip` in Go permits writing arbitrary `Name` values into the central directory without validation at creation time; a job can build such a zip with a short script before uploading it as an artifact, or an attacker who can influence a dependency/tool used during the build can produce one. The bug is fully deterministic and repeatable once the vulnerable extractor path is hit.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: resolve each `file.Name` against the destination root with `filepath.Join(root, file.Name)`, take `filepath.Abs`/`filepath.Clean`, and reject (or skip with a hard error, not just a warning) any entry whose resolved path is not prefixed by the destination root plus separator. Apply this check uniformly to directory, symlink, and regular file entries before any `os.Mkdir`/`os.OpenFile`/`os.Symlink` call, and also validate symlink targets (the `data` written as the link target) to prevent absolute/traversal symlink targets that later extraction steps (`lchmod`, subsequent writes through the link) could exploit.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
