### Title
Unauthenticated access to LOOP plugin Prometheus metrics and pprof endpoints via `/plugins/:name/metrics` - ([File: core/web/router.go])

### Summary
The `loopRoutes` handler group registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level `api` router group with no authentication middleware, unlike every other sensitive route which is wrapped in `auth.Authenticate(...)`. This lets any unauthenticated caller reach `LoopRegistryServer.pluginMetricHandler` and read a registered LOOP plugin's Prometheus metrics.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the `api` group and calls `loopRoutes(app, api)` alongside other route groups [1](#0-0) . Unlike `v2Routes`, which wraps essentially all controllers in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` (see the `authv2` group) [2](#0-1) , `loopRoutes` registers its handlers with no auth wrapper at all: [3](#0-2) 

`pluginMetricHandler` itself performs no authentication or authorization check — it only looks up the plugin name in the registry and proxies the request to the plugin's internal metrics port: [4](#0-3) 

The handler comment even notes "unlike discovery, this endpoint is internal btw the node and plugin" [5](#0-4) , indicating an assumption of restricted network reachability that is not actually enforced by any auth check in the route registration — any client that can reach the node's HTTP API port can hit this route directly.

The same lack-of-auth issue also applies to `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler`, which are registered on the same unauthenticated group and forward to the plugin's `/debug/pprof/*` endpoints [6](#0-5) [7](#0-6) .

### Impact Explanation
This is an information disclosure of internal LOOP plugin telemetry/Prometheus metrics data (and pprof profiling data via the sibling routes) to a fully unauthenticated caller. Metrics/pprof output for chainlink LOOP plugins can reveal internal operational details, resource usage patterns, and potentially sensitive labels (e.g., job/feed identifiers, chain names) that should be gated behind the node's authentication scheme like every other API surface. The pprof routes are more severe since they can be used to trigger CPU/heap profiling with attacker-supplied `seconds`/`debug` parameters, creating an unauthenticated resource-consumption and internal-state-disclosure vector.

### Likelihood Explanation
Trivially reachable: no credentials, tokens, or session cookies are required, only network access to the node's HTTP API port, and the LOOP plugin registry must have at least one registered plugin (true for split/LOOP deployments). This is fully repeatable via a simple unauthenticated `GET /plugins/:name/metrics` request.

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/metrics` and pprof routes) in the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`, or move these onto a separate internal-only listener/port that is not exposed to the public API surface, consistent with the code comment's stated intent that this is meant to be an internal-only endpoint.

### Proof of Concept
1. In `core/web`, add a handler-level integration test using `httptest`:
   - Build a `gin.Engine`, register `loopRoutes(app, engine.Group("/"))` (or use `NewRouter` with a test `chainlink.Application`).
   - Register a fake plugin in `app.GetLoopRegistry()` (via `plugins.NewTestLoopRegistry` or the real registry's `Register`) with a stub HTTP server backing `EnvCfg.PrometheusPort` that returns a fixed metrics body.
   - Send `httptest.NewRequest("GET", "/plugins/fakeplugin/metrics", nil)` with no `Authorization` header and no session cookie.
   - Assert the response status is `200 OK` and the body equals the fake metrics text, and assert no `401 Unauthorized` was ever produced — demonstrating the route bypasses authentication entirely, in contrast to a control test hitting an `authv2` route (e.g. `/v2/jobs`) without credentials, which should return `401`.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
