### Title
Missing role authorization on `/debug/vars` allows any authenticated view-role user to access expvar runtime internals - ([File: core/web/router.go])

### Summary
The `debugRoutes` function wraps `/debug/vars` only with `auth.Authenticate(..., auth.AuthenticateBySession)` and never applies any of the role-gating wrappers (`RequiresAdminRole`, `RequiresEditRole`, `RequiresRunRole`) used elsewhere in the router. As a result, any authenticated user regardless of role, including the lowest-privilege `UserRoleView`, can reach Go's `expvar` handler and read internal runtime/process state.

### Finding Description
`debugRoutes` is registered in `NewRouter`: [1](#0-0) 
It only checks that the request carries a valid session (`auth.AuthenticateBySession`), which succeeds for any user role as long as `AuthorizedUserWithSession` returns a `User` object, populating `SessionUserKey` without any role filtering: [2](#0-1) 
Unlike every admin/edit/run-gated route in `v2Routes` (e.g. `authv2.GET("/keys/csa", csakc.Index)` style groups wrapped with `auth.RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole`), the `/debug` group has no equivalent role wrapper: [3](#0-2) 
`UserRoleView` is the lowest defined role in the system: [4](#0-3) 
and `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` all explicitly reject `UserRoleView`: [5](#0-4) 
Because `debugRoutes` never calls any of these, a `UserRoleView` session (or any role) passes straight through to `expvar.Handler()`, which serves Go runtime internals (`cmdline`, `memstats`, and any custom-registered `expvar.Publish` variables) as JSON.

### Impact Explanation
This is an information-disclosure issue: a low-privilege (`view`-role) authenticated user can retrieve process-level runtime data (GC stats, memory stats, command-line, and any application-registered expvars) that is not intended to be exposed to non-admin users. It does not itself yield secrets/keys, authentication bypass, or fund movement, so it maps to a low-severity "sensitive information disclosure to authenticated low-privilege user" bounty class rather than a critical/high one. There is no evidence in this codebase that private keys, DB credentials, or session secrets are registered as expvars, so the concrete leaked data is limited to Go runtime metrics unless the application publishes something more sensitive via `expvar.Publish`.

### Likelihood Explanation
Highly likely/trivial to exploit: the only precondition is possessing any valid authenticated session cookie (the lowest role, `view`, suffices), which is explicitly allowed per the code path shown above. No additional role elevation, token forgery, or bypass of existing checks is required — the check for a role is simply absent for this route, unlike all comparable routes in the router.

### Recommendation
Wrap the `/debug/vars` route with `auth.RequiresAdminRole` (or at minimum `RequiresEditRole`) in `debugRoutes`, consistent with how other sensitive internal endpoints (e.g., `/log`, key export endpoints) are gated in `v2Routes`.

### Proof of Concept
Go handler-level integration test plan:
1. Build the router via `NewRouter` with a test `chainlink.Application` backed by a mock `Authenticator`/`AuthenticationProvider`.
2. Seed a session for a user with `Role: sessions.UserRoleView` (lowest privilege) and set the session cookie on the test HTTP client (mirroring how `AuthenticateBySession` reads `SessionIDKey` from cookie store).
3. Issue `GET /debug/vars` with only that session cookie attached, no admin/edit role.
4. Assert the response status is `200 OK` and the body contains expected `expvar` keys (e.g., `"cmdline"`, `"memstats"`), proving no role check blocked the view-role user.
5. As a control, assert that a comparable admin-only route (e.g., `GET /v2/keys/eth/export/...`) with the same view-role session returns `401`/`403`, confirming role enforcement works elsewhere but is absent for `/debug/vars`.

```go
func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
```

```go
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```
