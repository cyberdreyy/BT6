### Title
Unauthenticated-role privilege escalation via unguarded pprof debug routes - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` is invoked at [1](#0-0)  inside the `authv2` group, which only requires successful authentication (session or API token) via [2](#0-1) , with no `auth.RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole` wrapper applied to any of the registered pprof handlers. All sibling sensitive routes in the same group (keys export/import/delete, transfers, user management) are explicitly wrapped with role-checking middleware, but `metricRoutes` is not.

### Finding Description
`metricRoutes` registers the standard Go `net/http/pprof` handlers (`/debug/pprof/{,cmdline,profile,symbol,trace,allocs,block,goroutine,heap,mutex,threadcreate}`) directly on the `authv2` router group with no additional wrapper: [3](#0-2) . The `authv2` group's only gate is `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, which merely verifies a valid session cookie or API token exists and sets the authenticated user in context — it performs no role comparison, as seen in `Authenticate` at [4](#0-3) . Role enforcement only happens when a route handler is explicitly wrapped by `RequiresRunRole`, `RequiresEditRole`, or `RequiresAdminRole`, which check `user.Role` against `clsessions.UserRoleView/Run/Edit/Admin` as in [5](#0-4) . Since `metricRoutes(authv2)` at [6](#0-5)  is called with the bare `authv2` group and never wraps its handlers with any `Requires*Role` function, a user authenticated with only the `view` role (the lowest privilege level) satisfies `Authenticate` and reaches the pprof handlers directly, e.g. `GET /v2/debug/pprof/heap`. This contrasts with every other sensitive endpoint in `v2Routes` (e.g. `authv2.DELETE("/keys/eth/:keyID", auth.RequiresAdminRole(ekc.Delete))` at [7](#0-6) ), confirming the omission is inconsistent with the surrounding authorization pattern.

### Impact Explanation
A `view`-role user or a restricted API token holder can retrieve full heap dumps (`/v2/debug/pprof/heap`), goroutine stacks (`/v2/debug/pprof/goroutine`), and CPU/execution traces (`/v2/debug/pprof/profile`, `/v2/debug/pprof/trace`) of the running node process. Chainlink nodes hold private keys (ETH, OCR, P2P, CSA, VRF, etc.) and other secrets in process memory; heap/goroutine dumps can leak these values or other sensitive runtime state (session tokens, DB credentials in memory, pending transaction data) to a low-privileged principal. This matches the "sensitive information disclosure" / authorization-bypass impact class rather than direct fund loss, but is a stepping stone toward key/secret extraction.

### Likelihood Explanation
Minimal precondition: any valid `view`-role session cookie or API token is sufficient — this is the lowest privilege tier the application supports and is often granted broadly (e.g., to monitoring users). No additional exploitation complexity is required; a single authenticated `GET /v2/debug/pprof/heap` request reaches the handler and returns 200 with pprof binary output, since no role check exists anywhere in the call path. This is easily repeatable and does not depend on race conditions, timing, or other node/network preconditions.

### Recommendation
Wrap the pprof routes with an appropriate role requirement — most likely `auth.RequiresAdminRole`, consistent with the sensitivity of memory/goroutine dumps (matching how other privileged debug/config-mutating routes are gated). Modify `metricRoutes` in `core/web/router.go`:
```go
func metricRoutes(r *gin.RouterGroup) {
	pprofGroup := r.Group("/debug/pprof")
	pprofGroup.GET("/", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Index)))
	// ... wrap each handler similarly
}
```
Or apply `pprofGroup.Use(...)`-based middleware that calls the same role check function before dispatching to the underlying pprof handlers.

### Proof of Concept
Go handler-level integration test plan (using the existing router test harness, e.g. patterns from `core/web/*_test.go` that spin up `NewRouter`/`SetupJSONAPIsessionTestApp` fixtures):
1. Create test users with roles `{UserRoleView, UserRoleRun, UserRoleEdit, UserRoleAdmin}`, obtaining a valid session cookie or API token for each.
2. For each role, issue `GET /v2/debug/pprof/heap` (and `/v2/debug/pprof/`, `/goroutine`, `/allocs`) with that role's credentials.
3. Assert: only `UserRoleAdmin` returns `200 OK` with pprof content-type; `UserRoleView`, `UserRoleRun`, and `UserRoleEdit` should return `403 Forbidden` (or `401` if unauthenticated).
4. Current expected/actual result: all four roles (including `view`) return `200 OK`, confirming the unintended access.

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
