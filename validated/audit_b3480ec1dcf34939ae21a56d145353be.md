### Title
Jovian operator-fee calculation omits the decimal-scalar division, overcharging every transaction sender - ([File: crates/common/l1-fees/src/params.rs])

### Summary
`L1FeeParams::operator_fee_charge_inner` computes the Isthmus/Jovian operator fee that is deducted from every non-deposit transaction and routed to `OPERATOR_FEE_VAULT`. In the pre-Jovian branch the fee is correctly normalized by dividing by `OPERATOR_FEE_SCALAR_DECIMAL` (the scalar's fixed-point precision), but the Jovian branch multiplies by `OPERATOR_FEE_JOVIAN_MULTIPLIER` and never divides by the decimal scalar at all, making the fee up to `OPERATOR_FEE_SCALAR_DECIMAL` (1,000,000×) larger than intended for every transaction executed once the Jovian upgrade is active.

### Finding Description
The operator fee is computed as: [1](#0-0) 

```rust
pub fn operator_fee_charge_inner(&self, gas: U256, upgrade: BaseUpgrade) -> U256 {
    let operator_fee_scalar = self.operator_fee_scalar.unwrap_or_default();
    let operator_fee_constant = self.operator_fee_constant.unwrap_or_default();

    let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
        gas.saturating_mul(operator_fee_scalar)
            .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
    } else {
        gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
    };
    product.saturating_add(operator_fee_constant)
}
```

The scalar is documented as fixed-point with 6 decimal places of precision: [2](#0-1) 

For the pre-Jovian (non-Jovian) path, `gas * operator_fee_scalar` is correctly divided by `OPERATOR_FEE_SCALAR_DECIMAL` (`1_000_000`) to normalize the fixed-point scalar back to wei. For the Jovian path, the code multiplies by `OPERATOR_FEE_JOVIAN_MULTIPLIER` (`100`) but performs **no division** by `OPERATOR_FEE_SCALAR_DECIMAL` (or by `OPERATOR_FEE_SCALAR_DECIMAL * OPERATOR_FEE_JOVIAN_MULTIPLIER`, which would be the scaled divisor if the multiplier extends fixed-point precision). The result is a fee that is roughly `1e6`–`1e8` times larger than the value the fixed-point scalar represents.

This is the same bug class as the reported `PayoutManager.payoutDustThreshold` issue: a decimal/fixed-point scaling constant is applied on only one side of the formula (multiplication) while the corresponding normalizing division is dropped, producing a value that is off by a fixed large factor from the intended one.

This function is not test-only code; it is invoked from the production execution path on both EVM engines used by Base:
- `L1BlockInfo::operator_fee_charge_inner` in the primary EVM delegates directly to it: [3](#0-2) 
- It is used to charge the operator fee upfront and settle it after execution in the EVM2 handler: [4](#0-3) , [5](#0-4) 
- It is also used in the EIP-8130 fee settlement path: [6](#0-5) 

### Impact Explanation
Once the Jovian upgrade is active, every ordinary (non-deposit) transaction submitted by any unprivileged sender is charged an operator fee that is orders of magnitude larger than the value the on-chain-configured `operatorFeeScalar` is meant to encode. Funds are pulled from the sender's balance (`charge_upfront`/pre-charge, then settled/credited to `Predeploys::OPERATOR_FEE_VAULT`) far in excess of the intended amount, which is an unauthorized extraction of user funds enforced by the protocol itself — not something the sender can avoid by transaction construction. This can be severe enough to drain a sender's balance or make ordinary transactions economically unusable, and constitutes a de facto theft of funds from every network participant transacting post-Jovian.

### Likelihood Explanation
This code path executes unconditionally for every non-deposit, non-empty transaction once `BaseUpgrade::Jovian` is enabled (checked via `Self::is_enabled(upgrade, BaseUpgrade::Jovian)`), so the bug triggers automatically and deterministically for all traffic — no special crafting, privilege, or race condition is needed. The severity scales with however large `operator_fee_scalar` is configured on L1 (post-Isthmus/Jovian `L1Block` predeploy).

### Recommendation
Restore the fixed-point normalization in the Jovian branch, dividing by the same decimal precision (scaled by the Jovian multiplier if the intent is to extend precision), e.g.:
```rust
let product = if Self::is_enabled(upgrade, BaseUpgrade::Jovian) {
    gas.saturating_mul(operator_fee_scalar)
        .saturating_mul(U256::from(OPERATOR_FEE_JOVIAN_MULTIPLIER))
        / U256::from(OPERATOR_FEE_SCALAR_DECIMAL * OPERATOR_FEE_JOVIAN_MULTIPLIER)
} else {
    gas.saturating_mul(operator_fee_scalar) / U256::from(OPERATOR_FEE_SCALAR_DECIMAL)
};
```
and add a regression test asserting parity/expected scaling between the pre-Jovian and Jovian formulas for a fixed `operator_fee_scalar` and `gas`, mirroring the reference OP-stack specification for the Jovian operator-fee formula.

### Proof of Concept
1. Configure the `L1Block` predeploy's Isthmus operator-fee scalar slot with a small, realistic scalar (e.g., `operator_fee_scalar = 100_000` → intended 10% fee ratio at 6-decimal precision) and activate the Jovian upgrade.
2. Submit any standard transaction with `gas_limit = 1_000_000`.
   - Pre-Jovian formula: `1_000_000 * 100_000 / 1_000_000 = 100_000` wei operator fee (as intended: 10% scalar).
   - Jovian formula as implemented: `1_000_000 * 100_000 * 100 = 10_000_000_000_000` wei — 1e8 times larger than the pre-Jovian-equivalent fee for the same scalar.
3. Observe via `settle_fees`/`settle_transaction` that this inflated amount is charged from the sender and credited to `Predeploys::OPERATOR_FEE_VAULT`, confirming funds are extracted far beyond the configured fee schedule. [7](#0-6)

        // Charge the upfront gas cost, the L1 data fee, and the operator fee (on the gas limit)

    fn settle_transaction(
        host: &mut Evm<'_, BaseEvmTypes>,
        envelope: &BaseTxEnvelope,
        gas: GasSettlement<BaseEvmTypes>,
    ) -> HandlerResult<TxResult<BaseEvmTypes>> {
        let caller = gas.caller;
        let basefee = host.block_env().basefee;
        let l1_fee = host.ext().l1_fee;
        // The operator fee charged upfront (on the gas limit), stashed in before_execution.
        let operator_fee_charged = host.ext().operator_fee;

        // Default settlement refunds the caller's unused gas and pays the coinbase the priority
        // fee. The base fee is credited to its vault below (the OP-stack does not burn it).
        let mut result = default_settle_gas(host, gas)?;
        let gas_used = result.tx_gas_used();

        // Refund the operator fee down from the amount charged (on the gas limit) to the gas
        // actually used; the net is credited to the operator-fee vault below.
        let operator_fee_used = Self::operator_fee(host, envelope, gas_used);
        let operator_fee_refund = operator_fee_charged.saturating_sub(operator_fee_used);
        Self::credit(host, caller, operator_fee_refund)?;

        // Distribute the collected OP-stack fees to their vaults.
        Self::credit(host, Predeploys::L1_FEE_VAULT, l1_fee)?;
        Self::credit(
            host,
            Predeploys::BASE_FEE_VAULT,
            basefee.saturating_mul(U256::from(gas_used)),
        )?;
        Self::credit(host, Predeploys::OPERATOR_FEE_VAULT, operator_fee_used)?;

        result.ext.l1_fee = l1_fee;
        Ok(result)
    }
