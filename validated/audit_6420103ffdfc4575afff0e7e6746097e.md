### Title
Zip artifact extraction path traversal ("Zip Slip") via unsanitized `file.Name` in `extractZipFile` - (File: `helpers/archives/zip_extract.go`)

### Summary
`extractZipFile` (and its helpers `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`) write to the filesystem using the raw `zip.File.Name` value with no path sanitization or confinement check. Unlike the tarzstd extractor, which explicitly verifies `strings.HasPrefix(path, e.dir+string(filepath.Separator))` before writing, the zip legacy path never validates that the resolved path stays inside the extraction directory.

### Finding Description
`ArtifactsDownloaderCommand.Execute` in `commands/helpers/artifacts_downloader.go` downloads the job's own artifacts zip (attacker-controlled contents, since the attacker uploaded them earlier in the pipeline), determines the format via `openArchive` (defaulting to `archive.Zip` unless zstd/gzip magic bytes are present), and calls `archive.NewExtractor(format, f, size, wd)` followed by `extractor.Extract(ctx)`.

For the Zip format this reaches `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`), which stores `dir` (the `wd` passed in) in the extractor struct but **never uses it** — `Extract` only calls `archives.ExtractZipArchive(zr)`, passing no directory context at all: [1](#0-0) 

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry, with the only pre-check being `errorIfGitDirectory` (which only guards against `.git` directory entries, not path traversal): [2](#0-1) 

`extractZipFile` itself does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to `extractZipDirectoryEntry`/`extractZipSymlinkEntry`/`extractZipFileEntry`, all of which pass `file.Name` directly to `os.Mkdir`, `os.Symlink`, or `os.OpenFile` with no `filepath.Clean`, no rejection of absolute paths, and no check that the resolved path remains under `wd`: [3](#0-2) [4](#0-3) 

By contrast, the tarzstd extractor referenced in the question performs an explicit containment check before writing, which this code path entirely lacks. Since Go's `os` file functions resolve relative paths against the process's current working directory, a zip entry named `../../outside.txt` or an absolute path such as `/etc/cron.d/x` will be written outside `wd`.

### Impact Explanation
A malicious job can embed crafted `zip.File.Name` entries (e.g. `../../../../home/gitlab-runner/.gitlab-runner/config.toml`, or paths targeting shared cache/config directories used by other jobs on the same host) in its own `artifacts.zip`. When the next stage/job triggers `artifacts-downloader` to fetch and extract that zip, `extractZipFile` writes attacker-controlled content outside the job's working directory into shared runner state, persisting after the job completes or is cancelled and potentially affecting other projects sharing the host — matching the scoped impact (persistent multi-tenant disruption via file overwrite outside the job root).

### Likelihood Explanation
This is a standard, self-contained, deterministic exploit path fully controllable by an unprivileged user: they only need to control the contents of their own job's uploaded artifacts zip, which is a normal, supported job action. No admin misconfiguration, privileged executor, or third-party compromise is required — it triggers on the default Zip-format code path whenever the zip magic bytes don't match zstd/gzip, which is the default branch in `openArchive`.

### Recommendation
Add path confinement validation identical to the tarzstd extractor: after joining `file.Name` against the destination directory, clean the resulting path (`filepath.Clean`) and reject/skip any entry whose resolved absolute path does not have `dir+string(filepath.Separator)` as a prefix (or is exactly `dir`). Apply this check uniformly in `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and `extractZipFileEntry` (and symlink targets) before performing any filesystem write, and thread the `dir` field stored in `ziplegacy.extractor` through to `ExtractZipArchive`/`extractZipFile` so the check has the correct base directory.

### Proof of Concept
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    wd := t.TempDir()
    outsideMarker := filepath.Join(filepath.Dir(wd), "outside_poc.txt")
    defer os.Remove(outsideMarker)

    // build an in-memory zip with a traversal entry
    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../outside_poc.txt")
    w.Write([]byte("pwned"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    require.NoError(t, os.Chdir(wd))
    err := archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // assert the file landed outside wd
    _, statErr := os.Stat(outsideMarker)
    require.NoError(t, statErr, "expected traversal write outside sandbox to succeed, proving Zip Slip")
}
```
Expected result: the file is created outside `wd`, proving the missing confinement check in `extractZipFile`.

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
