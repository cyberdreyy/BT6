### Title
Stale confirmations from removed multisig members are not purged from other pending requests, letting requests execute below the effective `num_confirmations` threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in [1](#0-0)  only removes confirmations for requests that were *created by* the member being removed. It does not scan `self.confirmations` to strip that member's vote from *other* pending requests they had already confirmed. Because `confirm()` counts membership purely by the size of the stored `HashSet<String>` ( [2](#0-1) ) rather than re-validating that each entry is still a current member, a removed member's stale confirmation continues to count toward the `num_confirmations` threshold on any request they confirmed before being removed.

### Finding Description
The invariant the contract is supposed to enforce is: *a request executes only once `num_confirmations` distinct **current** members have approved it*. The equality that should hold at execution time is:

`len({confirmations that belong to current members}) >= num_confirmations`

Instead, the code checks:

`len(confirmations) >= num_confirmations`

where `confirmations` is never pruned of entries belonging to members deleted after they voted. `delete_member` only cleans up requests *authored* by the removed member (`r.member == member`, [3](#0-2) ); it does not iterate `self.confirmations` to remove that member's string key from confirmation sets of requests authored by *other* members. `confirm()` then blindly trusts the stored set size: [4](#0-3) 

`current_member()` is only used to authorize the *caller* of `confirm`/`add_request`, not to re-validate the *stored* confirmations of a request: [5](#0-4) .

### Impact Explanation
This breaks the K-of-N authorization boundary the multisig is designed to enforce (`Critical` per the given rubric: "a multisig request executed below threshold"). Any `MultiSigRequestAction` — `Transfer`, `DeployContract`, `AddKey`/`FunctionCall`, or another `DeleteMember`/`AddMember` — can be executed with fewer than `num_confirmations` *currently valid* members approving it, because a departed/revoked member's old confirmation is silently retained and counted. This can allow funds to be transferred, keys to be added, or membership to be manipulated with less real authorization than the account's security policy requires.

### Likelihood Explanation
No attacker-controlled deployment, victim key theft, or malicious validator is required — this occurs during ordinary multisig lifecycle events: a member confirms request `R1` (but `R1` doesn't yet reach threshold), and that member is later removed via a separate, properly-confirmed `DeleteMember` request (e.g., an employee offboarding or a compromised-key rotation). The stale vote on `R1` persists indefinitely and can later be combined with fewer newly obtained confirmations to push `R1` past the (unchanged) `num_confirmations` threshold. This is a straightforward sequence of normal operations, not a contrived edge case.

### Recommendation
When a member is deleted, iterate all entries in `self.confirmations` (or maintain a reverse index of member → requests confirmed) and remove the deleted member's key from every confirmation set, not just requests they authored. Alternatively, when `confirm()` checks the threshold, filter `confirmations` to only members present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)` — 4 members, 3 confirmations required.
2. `A` calls `add_request(R1)` (e.g., `Transfer` to some receiver) — `confirmations[R1] = {}`.
3. `B` calls `confirm(R1)` → `0+1 < 3`, so `confirmations[R1] = {B}`.
4. `C` calls `confirm(R1)` → `1+1 < 3`, so `confirmations[R1] = {B, C}`.
5. Separately, members legitimately submit and confirm a `DeleteMember{C}` request (requires 3 confirmations from `A`, `B`, `D` — unrelated to `R1`), executed via `delete_member` at [1](#0-0) . Since `R1.member == A` (not `C`), `R1`'s confirmations are untouched; `self.members = {A, B, D}`.
6. `D` calls `confirm(R1)` → `confirmations[R1].len() == 2`, so `2+1 >= 3` is true, and `R1` executes — even though only `B` and `D` are still current members who approved it (2 live confirmations), one short of the intended 3-of-N threshold. `C`'s stale confirmation was counted despite `C` no longer being a member.     pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()

            }

                account_id: env::predecessor_account_id(),
            }
        };

            Some(member)

            None
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
