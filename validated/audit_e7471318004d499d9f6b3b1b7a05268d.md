### Title
V1 signer protocol accepts a duplicate/conflicting tenure-change block because `validate_tenure_change_payload` checks only globally-accepted state, not locally-accepted/signed state - ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
In the v1 chainstate module, the proposal-time duplicate-tenure-change guard (`validate_tenure_change_payload`) only consults `SignerDb::get_last_globally_accepted_block`, while the equivalent v2 guard was hardened to use `SignerDb::get_last_signed_block` (which also covers `LocallyAccepted` blocks). Because a block a signer has already signed can sit in `LocallyAccepted` state for an arbitrary amount of time before the whole signer set gathers 70% weight and it becomes `GloballyAccepted`, a miner can, during that window, propose a second, conflicting tenure-change block for the same tenure and have it pass the v1 duplicate check that should have rejected it with `DuplicateBlockFound`.

### Finding Description
`SignerDb::get_last_signed_block` explicitly documents that "a block is considered signed if it is locally or globally accepted," while `SignerDb::get_last_globally_accepted_block` (used by v1) only sees blocks that reached the `GloballyAccepted` state. [1](#0-0) 

The v1 tenure-change duplicate check queries only the globally-accepted predicate: [2](#0-1) 

The v2 tenure-change duplicate check was hardened to use the broader "signed" predicate, with the code comment explicitly noting the rationale (a pre-committed block carries no signature, but a locally-accepted one does): [3](#0-2) 

This divergence is called out directly in the repo's own architecture notes, which state that v1 "counts only globally accepted" blocks for this check, and a dedicated regression test exists for v2 (but not v1) proving that a `LocallyAccepted` block used to be missed by the old (v1-style) check: [4](#0-3) [5](#0-4) 

Crucially, `validate_tenure_change_payload`'s `DuplicateBlockFound` check is a proposal-time-only guard; the docs and code confirm it is never re-run at validate-ok or at the moment of signing. The generic "own tenure" re-check that runs later (`check_block_against_signer_db_state`) explicitly checks the block's **parent** tenure for tenure-change blocks, not its own tenure: [6](#0-5) 

The only other backstop is the height-based `get_signed_conflicts` check performed right before signing in `handle_block_pre_commit`. But that check only vetoes a **stale** same-tenure conflict when the node's own view of that tenure has already advanced to or past the conflicting height — precisely the condition that fails when the first (conflicting) block was only locally accepted and never pushed to/adopted by the node: [7](#0-6) 

Combining these: a signer running the v1 protocol who has already signed tenure-start block A (locally accepted, not yet globally accepted because the wider signer set hasn't reached 70%) will (1) pass the v1 `DuplicateBlockFound` proposal check for a conflicting tenure-start block B because that check only looks at `GloballyAccepted` state, (2) skip the parent-tenure recheck at signing time because tenure-change blocks are checked against their *parent* tenure rather than their own, and (3) potentially fall through the `get_signed_conflicts` stale-conflict backstop because the node has not confirmed tenure A at or above B's height. The signer can then sign block B, producing a signature over a block that conflicts with one it already signed in the same tenure.

### Impact Explanation
This breaks the "no signer signs a conflicting/non-canonical block" invariant explicitly called out as Critical impact: a single signer instance running the v1 protocol can be induced by a miner to put its signature over two mutually exclusive tenure-start blocks for the same tenure, without needing a majority of signers or another signer's key. If enough signers hit this same window independently (each having signed a different, not-yet-globally-accepted candidate), aggregated signatures can end up split across conflicting blocks, threatening the "aggregated weight vs. verified accepts" equality that the 70%-threshold consensus mechanism depends on.

### Likelihood Explanation
The vulnerable window (a block sitting in `LocallyAccepted` without yet crossing the global 70% threshold) is a routine and expected state during normal operation, not a rare edge case — it exists on every tenure-start proposal until the last pre-commit/signature crosses the threshold. A miner simply needs to hold back its second tenure-start block proposal until it can observe (via gossip/StackerDB) that the signer already locally accepted the first, then submit block B before global acceptance completes. This requires only the standard miner role and passive observation of public signer gossip — no majority collusion, no key compromise.

### Recommendation
Update `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload` to use `SignerDb::get_last_signed_block` (the same predicate v2 already uses) instead of `SignerDb::get_last_globally_accepted_block`, so that a `LocallyAccepted` block in the tenure is also treated as a duplicate. Additionally, consider re-running the own-tenure duplicate check (not just the parent-tenure check) at pre-commit/signing time for tenure-change blocks in both v1 and v2, so the safety property does not rely solely on a proposal-time-only guard.

### Proof of Concept
1. Miner wins a sortition and proposes tenure-start block A (cause=BlockFound) to the v1 signer set.
2. A quorum of signers validates and pre-commits/signs A; a specific signer S individually signs A and moves it to `LocallyAccepted`, but the wider set has not yet reached 70% weight, so A stays `LocallyAccepted` (not `GloballyAccepted`) in S's `signerdb`.
3. Before A crosses the global threshold, the miner proposes a second, conflicting tenure-start block B for the same tenure (same `consensus_hash`, different content) to signer S.
4. In `check_proposal` → `validate_tenure_change_payload`, S's v1 chainstate calls `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)`, which returns `None` (A is only `LocallyAccepted`), so the `DuplicateBlockFound` rejection is skipped and B is accepted for further validation (`stacks-signer/src/chainstate/v1.rs:505-518`).
5. B proceeds through validation and pre-commit; at the moment S's pre-commit weight crosses threshold, `check_block_against_signer_db_state` checks B's *parent* tenure (not B's own tenure, since B is a tenure-change block) and finds nothing wrong; `get_signed_conflicts` finds A as a same-tenure conflict but, because the node has not adopted A (A was never pushed since it never went globally accepted), the "stale conflict in own tenure" branch does not block signing (`stacks-signer/src/v0/signer.rs:1423-1457`).
6. S signs B, resulting in signer S having produced signatures over two conflicting tenure-start blocks (A and B) for the same tenure.

    /// Return the last signed block in a tenure (identified by its consensus hash).
    /// A block is considered signed if it is locally or globally accepted. Blocks that
    /// have only been pre-committed are excluded, because a pre-commit does not put a
    /// signature over the block and may be safely superseded by a competing proposal.
    ///
    /// This answers "what is the tenure's signed tip?", a different question from
    /// [`SignerDb::has_signed_block_in_tenure`]'s "does a signature bind us to this tenure?",
    /// which is why the predicates deliberately differ on rejected blocks (see there).
    pub fn get_last_signed_block(
        &self,
        tenure: &ConsensusHash,
    ) -> Result<Option<BlockInfo>, DBError> {
        let query = "SELECT block_info FROM blocks WHERE consensus_hash = ?1 AND state IN (?2, ?3) ORDER BY stacks_height DESC LIMIT 1";
        let args = params![
            tenure,
            &BlockState::GloballyAccepted.to_string(),
            &BlockState::LocallyAccepted.to_string(),
        ];
        let result: Option<String> = query_row(&self.db, query, args)?;

        try_deserialize(result)
    }

- `validate_tenure_change_payload` rejects with `DuplicateBlockFound` when we

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
