### Title
Git extra flags passed verbatim to `git clone`/`git fetch` enable argument-injection RCE - (functions/concrete/run/stages/get_sources.go)

### Summary
`GetSources.gitClone` and `GetSources.gitFetch` append user-controlled `GitCloneFlags`/`GitFetchFlags` directly to the git argv without validation. A pipeline author can set `GIT_CLONE_EXTRA_FLAGS` or `GIT_FETCH_EXTRA_FLAGS` to values such as `--upload-pack=touch /tmp/pwned` or `--config-env=core.sshCommand=EVIL`, and git will execute the supplied command during the clone/fetch. No allow-list or deny-list exists in the new concrete stage path.

### Finding Description
The concrete `GetSources` stage in `functions/concrete/run/stages/get_sources.go` builds git command lines as follows:

- `gitClone` appends `s.GitCloneFlags` to `cloneArgs` at line 669 and invokes `git(ctx, e, extraEnv, cloneArgs...)`.
- `gitFetch` appends `s.GitFetchFlags` to `fetchArgs` at line 638 and invokes `git(ctx, e, extraEnv, fetchArgs...)`.

`git()` at line 866–868 forwards the args unchanged to `e.Command`, which uses `exec.Command` with the args slice directly. The flags originate from job variables:

- `GIT_CLONE_EXTRA_FLAGS` and `GIT_FETCH_EXTRA_FLAGS` are parsed by `builder.splitVarFlagsDefault` in `functions/concrete/builder/builder.go` (lines 612–632) using `strings.Fields`, then assigned to `GetSources.GitCloneFlags`/`GitFetchFlags` at lines 141–142.
- `common/build_settings.go` validates the variables into `BuildSettings.GitCloneExtraFlags`/`GitFetchExtraFlags` (lines 167–168) with the same `cmdFlags` parsing, but performs no semantic checks.

There is no allow-list, deny-list, or sanitization of dangerous git options anywhere in the concrete path. Git options such as `--upload-pack=<cmd>` and `--config-env=<key>=<envvar>` are explicitly designed to make git run external commands; when appended to `clone`/`fetch` they are honored by git and can execute arbitrary programs in the helper/host process.

The preconditions are met by a normal pipeline author: these are standard CI job variables documented for user override, and the concrete runner path accepts them without admin gating.

### Impact Explanation
Scoped impact is RCE in the helper/host process running the git binary. The attacker does not need to escape the executor sandbox to achieve this; the malicious command runs as part of the git invocation inside the job’s helper or on the runner host, depending on executor. This violates the core invariant that a normal job must not escape its executor sandbox, because the attacker gains code execution outside the intended git-only operation within the same process context as the runner helper.

### Likelihood Explanation
Preconditions are minimal and feasible:

- The runner uses the concrete `functions/concrete/run/stages` path (the new step-runner based execution).
- The job sets `GIT_CLONE_EXTRA_FLAGS` or `GIT_FETCH_EXTRA_FLAGS` (or `GIT_SUBMODULE_UPDATE_FLAGS` for the analogous submodule path at line 779).
- No admin allow-list is configured; the code has none.

Repeatability is high: any job can set these variables, and the flags are passed verbatim every time `git clone`/`git fetch` runs.

### Recommendation
Introduce an allow-list or a deny-list for git extra flags in `GetSources` (and the legacy shell path). At minimum, reject flags whose names or values can cause command execution, including:

- `--upload-pack`, `--exec`, `--config-env`
- Any flag value containing `core.sshCommand`, `sshCommand`, `ProxyCommand`, or equivalent

Parse flags with a git-option-aware validator rather than `strings.Fields`, and fail closed by returning an error before invoking `git`.

### Proof of Concept
Add an integration test in `functions/concrete/run/stages/get_sources_git_integration_test.go` that asserts dangerous flags are rejected:

```go
func TestGetSourcesGit_RejectDangerousCloneFlags(t *testing.T) {
    repoURL, sha, ref := testRepo(t)
    e := gitEnv(t, "bash")

    gs := stages.GetSources{
        GitStrategy:   "clone",
        Checkout:      true,
        RepoURL:       repoURL,
        SHA:           sha,
        Ref:           ref,
        Refspecs:      []string{"+refs/heads/*:refs/remotes/origin/*"},
        MaxAttempts:   1,
        UseNativeClone: true,
        GitCloneFlags: []string{"--upload-pack=touch /tmp/pwned"},
    }

    err := gs.Run(context.Background(), e)
    require.Error(t, err)
    assert.NotContains(t, e.Stderr.(*bytes.Buffer).String(), "pwned")
    assert.NoFileExists(t, "/tmp/pwned")
}
```

A similar test should be added for `GitFetchFlags` with `--upload-pack` and `--config-env=core.sshCommand=...`, and for `SubmoduleUpdateFlags` with `--upload-pack`. Fuzzing should generate token corpora matching `--upload-pack=`, `--exec=`, and `-o ProxyCommand=` and assert the stage returns an error before `git` is executed.
