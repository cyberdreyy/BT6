The Astaria bug is specifically about a Solidity `unchecked` block combined with a `mulWadDown` fixed-point multiply-then-divide pattern that could overflow a `uint88` field when working with untrusted, arbitrarily-large ERC20 token balances. I searched the in-scope Rust contracts (`staking-pool/src/**`, `lockup/src/**`) for the analogous class of bug — a share-price or vesting/release ratio calculated by multiplying two values before dividing, where the multiplication could overflow before division reduces it.

In `staking-pool/src/internal.rs`, all such ratio calculations (`num_shares_from_staked_amount_rounded_down`, `num_shares_from_staked_amount_rounded_up`, `staked_amount_from_num_shares_rounded_down`, `staked_amount_from_num_shares_rounded_up`) explicitly upcast both operands to `U256` (256-bit) before multiplying, and only convert back to `u128` after dividing [1](#0-0) [2](#0-1) . Since `Balance` is `u128`, the maximum possible product of two `u128` values is bounded well within `U256`'s 256-bit range, so this multiply-before-divide pattern cannot overflow regardless of token amounts.

Similarly, in `lockup/src/getters.rs`, the analogous linear-release and vesting calculations (`get_locked_amount`, `get_unvested_amount`) also multiply using `U256` before dividing [3](#0-2) [4](#0-3) , with comments explicitly noting the result cannot exceed `lockup_amount` — again bounded well within `U256`.

The `RewardFeeFraction.multiply` function referenced in `internal_ping` (`staking-pool/src/internal.rs:215`) also multiplies a `u128` balance by a `u32` numerator/denominator; even without seeing its exact body, the maximum possible intermediate product (`u128 * u32` ≈ 2^160) cannot overflow a native `u128` accumulator in the way the Solidity `uint88` cast could, and NEAR/Rust arithmetic does not silently truncate the way an `unchecked` Solidity block does — release-mode Rust wrapping would require an explicit `unchecked_mul`/`Wrapping` type, which is not used here.

None of the in-scope contracts use an `unchecked`-equivalent pattern (unguarded native multiplication before division against attacker-influenced, unbounded-size values) that would break a custody binding such as claims-vs-holdings, shares-charged-vs-shares-redeemed, or releasable-vs-schedule. The bug class the report describes does not have a reachable analog in this codebase.
