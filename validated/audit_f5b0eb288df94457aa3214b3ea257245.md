### Title
requestCache correctly isolates by composite (sender, id) key, contrasting with capabilities handler.savedCallbacks' single-key regression - ([File: core/services/gateway/handlers/common/requestcache.go], [File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`common.requestCache` binds every pending request to a `globalId{sender, id}` composite key [1](#0-0) , and `ProcessResponse` only resolves entries by `globalId{response.Body.Receiver, response.Body.MessageId}` [2](#0-1) , so a response can only ever match the callback of the sender it was addressed to. By contrast, `capabilities.handler` (the sibling package using the same `handlers.Callback`/DON message model) stores pending callbacks in `savedCallbacks map[string]*savedCallback` keyed only by `msg.Body.MessageId` [3](#0-2) [4](#0-3) , and dispatches the first node response purely by `MessageId` with no sender/receiver binding check [5](#0-4) . This demonstrates that the `requestCache` pattern is the safer, correct design and that `handler.savedCallbacks` is a regression that omits the sender-binding invariant.

### Finding Description
This question asks only to validate/demonstrate the `requestCache` baseline behavior, not to re-report the `handler.savedCallbacks` vulnerability itself (which is a separate, already-identified issue). The `requestCache[T]` type stores requests in `map[globalId]*pendingRequest[T]` where `globalId{sender, id}` is built from `request.Body.Sender` and `request.Body.MessageId` in `NewRequest` [6](#0-5) . When a response arrives, `ProcessResponse` computes the lookup key from `response.Body.Receiver` (the original sender) and `response.Body.MessageId`, so a response addressed to sender A will never match an entry created for sender B even when both share the same `MessageId` [2](#0-1) . Existing tests already exercise concurrent same-`MessageId`, different-sender requests: `TestRequestCache_MultiResponse` creates `nRequests` entries all sharing `MessageId: "abcd"` but with distinct `Sender` values, and asserts each callback only receives the response matching its own sender via `Body.Receiver` [7](#0-6) . This confirms the composite-key design is collision-resistant by construction, and stands in contrast to `capabilities.handler`, where `savedCallbacks[msg.Body.MessageId]` has no sender component at all, meaning two different senders using the same `MessageId` collide and the second overwrites the first's saved callback entry in `HandleLegacyUserMessage` [4](#0-3) , and `handleWebAPITriggerMessage` delivers whichever node response arrives first to whatever callback is currently stored under that `MessageId` [5](#0-4) .

### Impact Explanation
No exploitable node compromise exists in `common.requestCache` itself — this is a comparative/baseline analysis confirming the safe pattern works as intended (correct cross-user isolation, no impact class applies here). The scoped impact is limited to establishing that the `handler.savedCallbacks` design in `core/services/gateway/handlers/capabilities/handler.go` is a regression relative to this safer sibling pattern; that regression (cross-user response confusion / unauthorized delivery of another user's response) is a separate finding outside the scope of this specific question about `requestCache`.

### Likelihood Explanation
Not applicable — `requestCache` demonstrates correct, collision-resistant behavior under the stated preconditions (two distinct senders, identical `MessageId`), as already covered by the existing `TestRequestCache_MultiResponse` test [7](#0-6) . There is no vulnerable path to exploit in this function.

### Recommendation
None needed for `common.requestCache`; it correctly implements composite-key isolation via `globalId{sender, id}` [1](#0-0) . This comparison should be used as the reference implementation when remediating `capabilities.handler.savedCallbacks` (i.e., changing its key to a composite of sender/receiver and MessageId, mirroring `requestCache`'s `globalId`).

### Proof of Concept
Table test plan (extends existing `requestcache_test.go` patterns):
1. Create `cache := common.NewRequestCache[requestState](time.Hour, 1000)`.
2. Call `cache.NewRequest(lggr, &api.Message{Body: api.MessageBody{MessageId: "X", Sender: "A"}}, callbackA, &requestState{})`.
3. Call `cache.NewRequest(lggr, &api.Message{Body: api.MessageBody{MessageId: "X", Sender: "B"}}, callbackB, &requestState{})` — both succeed since keys `{A,X}` and `{B,X}` differ (contrast: in `handler.savedCallbacks`, the second call under the same `MessageId` would silently overwrite the first, per `handler.go:412`).
4. Call `cache.ProcessResponse(&api.Message{Body: api.MessageBody{MessageId: "X", Receiver: "A"}}, processFn)`.
5. Assert `callbackA.Wait(ctx)` returns the aggregated response, and `callbackB` has NOT fired (e.g., use a timeout/select to confirm no delivery, or assert cache still contains entry for `{B, X}` before B's own response arrives).
6. Follow up by sending a response with `Receiver: "B"` and confirm `callbackB` now fires with the correct response, proving strict per-sender isolation as validated by `TestRequestCache_MultiResponse` [7](#0-6) .

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
	codec := api.JsonRPCCodec{}
	timer := time.AfterFunc(c.timeout, func() {
		err := c.deleteAndSendOnce(key, handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(request), ErrorCode: api.RequestTimeoutError})
		if err != nil {
			lggr.Errorw("failed to send timeout response", "error", err)
		}
	})
	c.cache[key] = &pendingRequest[T]{Callback: callback, responseData: responseData, timeoutTimer: timer}
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func TestRequestCache_MultiResponse(t *testing.T) {
	t.Parallel()

	nRequests := 10
	nResponsesPerRequest := 100
	maxDelayMillis := 100

	lggr := logger.Test(t)
	cache := common.NewRequestCache[requestState](time.Hour, 1000)
	cbs := make([]*common.Callback, nRequests)
	reqs := make([]*api.Message, nRequests)
	for i := range nRequests {
		cb := common.NewCallback()
		cbs[i] = cb
		reqs[i] = &api.Message{Body: api.MessageBody{MessageId: "abcd", Sender: fmt.Sprintf("sender_%d", i)}}
		initialState := &requestState{counter: 0}
		require.NoError(t, cache.NewRequest(lggr, reqs[i], cbs[i], initialState))
	}

	for i := range nRequests {
		resp := &api.Message{Body: api.MessageBody{MessageId: "abcd"}}
		resp.Body.Receiver = reqs[i].Body.Sender
		for range nResponsesPerRequest {
			go func() {
				n := rand.Intn(maxDelayMillis) + 1
				time.Sleep(time.Duration(n) * time.Millisecond)
				assert.NoError(t, cache.ProcessResponse(resp, func(response *api.Message, responseData *requestState) (aggregated *handlers.UserCallbackPayload, newResponseData *requestState, err error) {
					responseData.counter++
					if responseData.counter == nResponsesPerRequest {
						var rawResponse json.RawMessage
						rawResponse, err = json.Marshal(response)
						if err != nil {
							return nil, nil, fmt.Errorf("failed to marshal response: %w", err)
						}
						return &handlers.UserCallbackPayload{RawResponse: rawResponse}, nil, nil
					}
					return nil, responseData, nil
				}))
			}()
		}
	}

	for i := range nRequests {
		resp, err := cbs[i].Wait(t.Context())
		require.NoError(t, err)
		var msg api.Message
		require.NoError(t, json.Unmarshal(resp.RawResponse, &msg))
		require.Equal(t, "abcd", msg.Body.MessageId)
		require.Equal(t, reqs[i].Body.Sender, msg.Body.Receiver)
	}
}
