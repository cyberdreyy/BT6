### Title
Zip extraction has no path confinement / Zip Slip in `helpers/archives/zip_extract.go`, reachable via `ziplegacy` extractor - ([File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go])

### Summary
`ziplegacy.extractor.Extract()` stores a `dir` field but never uses it when extracting; it delegates directly to `archives.ExtractZipArchive(zr)`, which writes every `zip.File` using the raw, attacker-controlled `file.Name` with no join-to-root and no traversal/absolute-path check. This is in contrast to the sibling `tarzstd` extractor, which explicitly joins to `e.dir` and rejects paths that escape it.

### Finding Description
- `NewExtractor(r, size, dir)` in `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go` stores `dir` on the `extractor` struct but `Extract()` never references `e.dir`: [1](#0-0) 
- The actual file-write logic lives in `helpers/archives/zip_extract.go`: `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), ...)` and `extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry` operate directly on `file.Name` — a value taken verbatim from the zip's central directory, with no `filepath.Join(root, name)` and no check that the resolved path stays under any root: [2](#0-1) 
- `ExtractZipArchive` only runs a `.git`-directory warning check (`errorIfGitDirectory`) — not a path-confinement check — before extracting each entry: [3](#0-2) 
- By contrast, the `tarzstd` extractor for the same threat model explicitly resolves each entry against `e.dir` and rejects escapes: `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name)); if !strings.HasPrefix(path, e.dir+...) { return fmt.Errorf("cannot be extracted outside of chroot") }` [4](#0-3)  — this protection has no zip counterpart.
- Reachability: both `cache-extractor` and `artifacts-downloader` commands call `os.Getwd()` for `wd`, then `archive.NewExtractor(format, f, size, wd)` and `extractor.Extract(ctx)`, relying on `wd` for confinement, but for the Zip/ZipZstd format this `dir` argument is silently discarded: [5](#0-4) [6](#0-5) 
- Since only "current working directory equals intended root" (no chdir elsewhere before extraction) provides any containment for benign entries, any zip entry name containing `../` sequences or an absolute path (e.g. `/etc/foo`, `../../shared/authorized_keys`) bypasses this entirely because Go's `os.OpenFile`/`os.MkdirAll` honor both relative traversal and absolute paths as given.
- `archive.Register(archive.Zip, NewArchiver, NewExtractor)` in `ziplegacy` package registers this extractor for both `Zip` and `ZipZstd` formats [7](#0-6) , so this is the extractor used whenever cache/artifact archives are in zip format — the primary/default artifact and cache format.

### Impact Explanation
An unprivileged pipeline author who controls the contents of a cache or artifact zip (uploaded via a normal job, then restored in a later job via `cache-extractor` or `artifacts-downloader`) can craft zip entries with `../` traversal or absolute path names. On restore, the `gitlab-runner-helper` process — running inside the job's executor (e.g., Kubernetes helper/build container sharing volumes, shell executor, docker executor) — will write those files to arbitrary writable paths in the container's filesystem, not just the job workspace. This violates the "File operations must stay within intended build/cache/artifact roots" invariant and can overwrite files on shared/mounted volumes reachable by the process's write permissions (subject to actual OS file permissions/mount read-only-ness of specific paths such as service-account token mounts, which are typically read-only and would fail to write, but other writable shared paths, e.g. shared emptyDir volumes, home directory dotfiles, or `.bashrc`/`.profile` executed later, are plausible targets).

### Likelihood Explanation
Highly reachable: any job that creates a cache or artifact and controls the exact file paths written into it (trivial via `cp`/`zip`, or by crafting the artifact zip out-of-band) can produce a zip with malicious entry names; the next job/pipeline stage that restores that cache/artifact triggers extraction through this exact vulnerable code path with no additional privilege required. No masking/allow-list/path-validation currently blocks it for zip format specifically (the equivalent tar defense exists, confirming the gap is not a hardened design decision but an omission for zip).

### Recommendation
Add the same confinement check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: resolve each `file.Name` via `filepath.Join(dir, file.Name)` (and `filepath.Abs`), reject any resulting path that does not have `dir` as a strict prefix (or equals it) before performing `MkdirAll`/`OpenFile`/`Symlink`/`Mkdir`. This requires threading the actual `dir` parameter from `ziplegacy.extractor` (and the fastzip path, which should be checked separately) down into `ExtractZipArchive`/`extractZipFile`, rather than relying on `file.Name` being extracted relative to an implicit and unenforced current working directory.

### Proof of Concept
Go unit test in `helpers/archives`:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    jobDir := filepath.Join(tmpDir, "job")
    require.NoError(t, os.MkdirAll(jobDir, 0o755))

    // build a malicious zip with an entry escaping jobDir
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../../outside.txt")
    w.Write([]byte("pwned"))
    zw.Close()

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    origWd, _ := os.Getwd()
    os.Chdir(jobDir)
    defer os.Chdir(origWd)

    err = ExtractZipArchive(zr)
    require.NoError(t, err) // currently succeeds silently

    _, statErr := os.Stat(filepath.Join(tmpDir, "outside.txt"))
    assert.NoError(t, statErr, "file was written outside of job dir - Zip Slip confirmed")
}
```
Expected (after fix): `ExtractZipArchive`/the ziplegacy extractor should return an error such as `"outside.txt cannot be extracted outside of chroot"` and no file should be created outside `jobDir`.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
