Confirmed: the request id (`msg.Body.MessageId`) used as the key in `handler.savedCallbacks` is taken directly from the JSON-RPC request's `ID` field — an attacker-controlled string — with no derivation from the sender/signer, workflow selector, or payload.

### Title
Request-id collision in `handler.savedCallbacks` allows cross-user response delivery - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The gateway's legacy web-API trigger flow keys pending user callbacks solely by the attacker-supplied `msg.Body.MessageId`, without binding it to the sender's address or any other authorization-relevant field. Two different signed requests from two different EOAs that happen to choose the same `MessageId` will collide in the `savedCallbacks` map, so the DON's response to one request can be delivered to the other requester's callback.

### Finding Description
`ValidatedMessageFromReq` ( [1](#0-0) ) sets `m.Body.MessageId = req.ID` directly from the JSON-RPC request `ID` supplied by the caller — this value is never hashed or combined with the sender address. `Message.Sign` computes the signature over `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload` ( [2](#0-1) ), and `Body.Sender` is derived independently from the signing key — the signature does not bind `MessageId` to `Sender` in a collision-preventing way (it just proves the sender signed *this* MessageId, but two different senders can independently choose to sign the identical `MessageId` string).

In `handler.HandleLegacyUserMessage`, the gateway stores the pending callback keyed only by this attacker-chosen id, with a blind overwrite and no uniqueness check: [3](#0-2) 

Later, in `handleWebAPITriggerMessage`, when a DON node responds, the gateway looks up and deletes the callback purely by `msg.Body.MessageId` and forwards the raw node response to whatever callback is currently stored under that id: [4](#0-3) 

Similarly, `sendHTTPMessageToClient`/`handleWebAPIOutgoingMessage` propagate the same unmodified `MessageId` through the outgoing HTTP action/target/compute flow back to the node ( [5](#0-4) ), so the id is never re-derived to include the sender at any point in this path.

Exploit flow: attacker A submits a signed `web_api_trigger` request with `MessageId = "X"`. The gateway registers `savedCallbacks["X"] = callbackA` and fans the request to DON nodes. Before A's response returns, attacker B submits another signed request (different key/sender, different workflow selector/payload) but reusing `MessageId = "X"`. The map entry becomes `savedCallbacks["X"] = callbackB` (A's is silently overwritten with no error). When the DON node responds to A's original request, the gateway matches on `MessageId = "X"`, finds `callbackB`, deletes it, and delivers A's response to B. If the response could contain sensitive request-specific data (e.g., HTTP action/target results, decrypted secrets, or in vault-adjacent flows, other authorization-relevant payloads gated on the requester's identity), B improperly receives content intended for A. Nothing in this path validates that the message id is unique per sender or globally collision-resistant — the only invariant enforced is JSON-RPC schema validity in `Message.Validate()` and signature verification of the *request itself*, neither of which prevents two independent signers from choosing the same id.

### Impact Explanation
Cross-user response confusion: an unprivileged attacker who can just sign and submit gateway requests can cause another user's asynchronous response (which may contain secrets, decrypted payloads, or execution results tied to a specific workflow/sender) to be delivered to the attacker's own callback instead of the legitimate requester's. This matches "cross-user response confusion" / unauthorized disclosure of another user's request-scoped data, scoped to whatever data this legacy web-API trigger/target/action pipeline carries in its responses.

### Likelihood Explanation
No special privilege is required — only the ability to submit signed gateway `web_api_trigger`/related messages with an attacker-chosen `MessageId`, which is explicitly allowed by the code (`ValidatedMessageFromReq` copies `req.ID` verbatim). The only timing requirement is that the colliding id be submitted while the first request's callback is still pending in `savedCallbacks` (default TTL up to `defaultCallbackMaxAgeSec` = 120s, or configured `CallbackMaxAgeSec`), which is trivially satisfiable by an attacker racing or guessing/observing common/short ids. This is fully repeatable and requires no coordination with node operators.

### Recommendation
Derive the internal lookup key for `savedCallbacks` (and any request id used for routing/matching outgoing DON responses) from a value that binds the client-chosen id to the authenticated sender (e.g., `sha256(sender || messageId)` or `sender + "/" + messageId`), rather than trusting the raw client-supplied `MessageId` alone as the map key. Reject/collision-check duplicate ids from different senders instead of silently overwriting `savedCallbacks[msg.Body.MessageId]`.

### Proof of Concept
Go unit test plan in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct two signed `api.Message`s with `Method = MethodWebAPITrigger`, identical `MessageId = "collide-1"`, but different signer keys (`Body.Sender` differs) and different payloads.
2. Call `handler.HandleLegacyUserMessage` for request A with `callbackA`, then for request B with `callbackB` — assert `savedCallbacks["collide-1"].Callback == callbackB` (A's entry was overwritten).
3. Simulate a DON node response for A's original request (same `MessageId = "collide-1"`, node-signed) via `handler.HandleNodeMessage`/`handleWebAPITriggerMessage`.
4. Assert `callbackB.Wait(ctx)` receives the response instead of `callbackA`, and `callbackA` never receives any response — demonstrating cross-user delivery.
5. Add the invariant-focused table test: generate N distinct `(sender, payload, workflow selector)` tuples and assert the internally used request keys are always distinct (fails currently because the key is `MessageId` alone, independent of sender).

func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageId = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}

func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}

func (h *handler) sendHTTPMessageToClient(ctx context.Context, req network.HTTPRequest, msg *api.Message) (*api.Message, error) {
	var payload Response
	resp, err := h.httpClient.Send(ctx, req)
	if err != nil {
		return nil, err
	}
	payload = Response{
		ExecutionError: false,
		StatusCode:     resp.StatusCode,
		Headers:        resp.Headers,
		Body:           resp.Body,
	}
	payloadBytes, err := json.Marshal(payload)
	if err != nil {
		return nil, err
	}

	return &api.Message{
		Body: api.MessageBody{
			MessageId: msg.Body.MessageId,
			Method:    msg.Body.Method,
			DonId:     msg.Body.DonId,
			Payload:   payloadBytes,
		},
	}, nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
