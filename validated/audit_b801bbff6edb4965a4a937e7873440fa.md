### Title
Unauthenticated per-request goroutine fan-out with no global concurrency cap in confidential relay gateway handler — memory/goroutine exhaustion DoS - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
The `mplex` bug spawned an unbounded number of goroutines per remote peer with no backpressure, exhausting memory. The Chainlink Gateway's confidential-relay handler has an analogous pattern reachable from unprivileged HTTP clients hitting the internet-facing Gateway: every incoming `HandleJSONRPCUserMessage` call creates a new tracked `activeRequest` and immediately fans out to every DON member concurrently via `errgroup.Group`, with no authentication, no per-caller rate limiting, and no cap on the number of concurrently outstanding requests.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) dispatches any external HTTP JSON-RPC request straight to the resolved `Handler.HandleJSONRPCUserMessage` [1](#0-0) . For the confidential-relay handler, `HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 chars — there is no authentication/authorization check before the request is admitted [2](#0-1) .

Each admitted request is stored in an unbounded `activeRequests` map keyed by attacker-supplied `req.ID` [3](#0-2) , and immediately triggers `fanOutToNodes`, which spawns one goroutine per DON member via `errgroup.Group` for every single incoming request [4](#0-3) . There is no global rate limiter or admission-control gate applied to `HandleJSONRPCUserMessage` itself (rate limiters in this handler — `globalNodeRateLimiter`/`perNodeRateLimiters` — are only applied in `HandleNodeMessage`, i.e., to responses coming back from DON nodes, not to inbound user requests) [5](#0-4) .

Each `activeRequest` (and its spawned goroutines/timeout contexts) is retained until `RequestTimeoutSec` (default 30s) elapses, swept only periodically by a background cleanup ticker (`defaultCleanUpPeriod` = 1s) [6](#0-5) [7](#0-6) . Because the only admission gate is the HTTP body-size limiter (`MaxRequestBytesLimiter`, `core/services/gateway/network/httpserver.go:196-209`), an attacker can send a high volume of small, distinct-ID JSON-RPC requests and force the handler to sustain `N_requests × N_don_members` live goroutines plus map entries for up to the full request timeout window, unboundedly scaling with request rate rather than with any fixed concurrency budget.

### Impact Explanation
This is a High-severity resource-exhaustion analog: unauthenticated external HTTP clients can drive unbounded goroutine and memory growth in the Gateway process by submitting many concurrent relay requests with unique IDs, degrading or crashing the Gateway (and by extension availability of the confidential-relay/vault workflow path) for legitimate users — directly mirroring the mplex "goroutine spawning per stream, no bound" DoS class.

### Likelihood Explanation
Likelihood is high: the endpoint is internet-facing (`gateway.ProcessRequest`), requires no authentication for `MethodCapabilityExec`/`MethodSecretsGet` admission (only ID length/uniqueness checks), and the only limiter present bounds request body size, not request rate or concurrency. Generating many unique request IDs is trivial for any client.

### Recommendation
Add a global (and optionally per-caller/IP) admission-control rate limiter or bounded semaphore in front of `HandleJSONRPCUserMessage`/`fanOutToNodes` in `core/services/gateway/handlers/confidentialrelay/handler.go`, capping the number of concurrently active requests (and thus concurrently spawned fan-out goroutines) independent of DON size, consistent with the rate limiters already used for node responses. Consider applying the same admission control pattern used elsewhere in the vault handler's authorization pipeline before `newActiveRequest` is called.

### Proof of Concept
1. Attacker sends a burst of `M` HTTP POST requests to the Gateway's JSON-RPC endpoint, each with method `confidentialrelay.MethodCapabilityExec`/`MethodSecretsGet`, a unique `req.ID`, and minimal valid params.
2. Each request bypasses any per-request-admission rate limiting (`HandleJSONRPCUserMessage` has none), is added to `activeRequests`, and immediately spawns `len(donConfig.Members)` goroutines in `fanOutToNodes`.
3. With `M` large and sustained faster than the 1-second cleanup sweep / 30-second timeout, live goroutines and map entries accumulate as `M × N_don_members`, consuming memory/goroutine stack space proportional to attacker-controlled request volume — verifiable by observing goroutine/memory growth on the Gateway process under load, with no corresponding limiter rejecting excess requests.

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := logger.With(h.lggr, "method", er.req.Method, "requestID", er.req.ID)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()
