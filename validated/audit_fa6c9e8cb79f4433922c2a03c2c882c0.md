### Title
Multisig `confirm` counts stale confirmations from deleted keys, allowing request execution below the effective live-member threshold - ([File: multisig/src/lib.rs])

### Summary
The `AFiBase.withdraw` bug class is "recorded claim vs. actual asset backing it diverges, and the divergence is allowed to be settled on." The nearest reachable analog in this NEAR repo is in the multisig contract: the confirmation count used to authorize execution of a `MultiSigRequest` is not re-validated against the *current* set of live access keys/members at the moment the threshold is reached, so a confirmation recorded by a key that has since been revoked still counts toward `num_confirmations`.

### Finding Description
`confirm()` in [1](#0-0)  checks only `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute the pending request; it never re-checks whether the previously-recorded signer public keys are still valid access keys on the account.

Confirmations are recorded per-`request_id` as a set of public keys in `self.confirmations` (see the insertion at line 262-263). The only place stale confirmations for a *specific* signer are purged is inside `MultiSigRequestAction::DeleteKey` handling in `execute_request` at [2](#0-1) , and that purge is scoped narrowly: it removes only `requests` (and their confirmations) whose *original adding* signer (`r.signer_pk`) matches the deleted key — i.e., requests that key itself created. It does **not** scan `self.confirmations` for *other, unrelated* pending requests that the same now-deleted key had merely confirmed (not created).

Consequence: if key `A` confirms request `X` (bringing it to 1-of-K confirmations), and afterward the multisig executes a separate, unrelated `DeleteKey` request removing `A` from the account's valid keys, request `X` still shows `A`'s confirmation in `self.confirmations`. When the remaining live keys `B`, `C`, ... continue confirming `X`, the stale entry from revoked key `A` is counted toward `self.num_confirmations`, letting execution occur with one fewer *live* confirming key than the configured threshold actually requires. This breaks the equality: `confirmations counted == num_confirmations` should imply `live confirming members == num_confirmations`, but it does not.

The README's own "Gotchas" section at [3](#0-2)  acknowledges that access-key removal is not reconciled against `num_confirmations` when it discusses the contract becoming *locked* — but it does not address the inverse and more dangerous case: a stale confirmation from a *removed* key that lets a request execute with an *effectively lower* threshold of live approvers.

### Impact Explanation
This matches the "multisig request executed below threshold" Critical-impact category: a transfer, `AddKey`, `DeleteKey`, `DeployContract`, or `FunctionCall` request (see `execute_request`, [4](#0-3) ) can be pushed to execution while relying on a confirmation from a party that is no longer an authorized signer, meaning the request was authorized by fewer live/current keyholders than `num_confirmations` requires. Since `MultiSigRequestAction::Transfer` moves NEAR directly out of the multisig account, this can result in funds moved by parties whose authorization was already revoked at execution time.

### Likelihood Explanation
Requires: (1) a pending, not-yet-fully-confirmed request with at least one confirmation from key `A`, and (2) a subsequent, separately-approved `DeleteKey` request that revokes `A`, executed while `X` is still outstanding. This is a realistic operational sequence for any long-lived multisig doing routine key rotation (e.g., removing a departing employee's key) while other requests are mid-flight — it does not require a redeploy, a victim key compromise, or social engineering; it only requires normal governance operations executed in an order the contract fails to reconcile.

### Recommendation
When executing `DeleteKey` (and generally whenever a key/member is removed), scan and purge that public key's confirmation entries from *all* pending requests in `self.confirmations`, not only requests it originally authored. Alternatively/additionally, re-validate at `confirm()` time (or at request-execution time) that every public key present in the request's confirmation set still corresponds to a currently valid access key/member before counting it toward `num_confirmations`.

### Proof of Concept
1. Multisig configured with `num_confirmations = 2`, keys `A`, `B`, `C` valid.
2. `A` calls `add_request_and_confirm` for `Transfer` request `X` → confirmations(`X`) = `{A}` (1/2).
3. Separately, `B` and `C` create+confirm a `DeleteKey{public_key: A}` request; it reaches 2/2 and executes, revoking `A`'s access key. The `DeleteKey` handler purges only requests where `r.signer_pk == A` (requests A itself authored) — `X` was authored by `A` too in this scenario, so to make the PoC clearer: have `A` merely *confirm* (not author) a request `Y` created by `B`. `Y`'s `signer_pk` is `B`, so the `DeleteKey` purge does not touch `Y`'s confirmations even though `A` is now revoked. `Y`'s confirmations(`Y`) still contains `{A}` (1/2).
4. `C` (a still-valid key) confirms `Y` → confirmations(`Y`).len()+1 = 2 ≥ `num_confirmations` (2) → `execute_request(Y)` runs.
5. Result: `Y` executed with only one currently-valid live confirmer (`C`) actually approving it at execution time, plus a stale confirmation from revoked key `A` — i.e., the request executed below the intended live-signer threshold of 2. [1](#0-0) [2](#0-1)

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
