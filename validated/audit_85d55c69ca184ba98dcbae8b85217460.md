### Title
Loss-adjusted withdraw clearing only covers the latest request epoch — earlier pending receipts escape the haircut and are paid at par - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault` records each withdraw receipt under `withdrawsRequestsByEpoch[user][epoch]`, but tracks only a single `lastWithdrawRequest[user]` pointer. When `collectWithdrawFunds` applies a `stopEpochWithDuration` loss, the haircut price is stored under the current `epochNumber` while the haircut itself is computed over the *aggregate* `pendingWithdraws` (all epochs). At claim time, `_claimLossAdjustedWithdrawRequest` clears only the basis stored under `lastWithdrawRequest`'s epoch; a user's earlier-epoch pending receipt basis survives in `withdrawsRequests` and is paid at par via `_claimFundedWithdrawRequest`. This mirrors the Nouns `updateFounders` bug: clearing iterates from the wrong base index, so stale indexed entries retain value they should have lost.

### Finding Description
- `requestWithdraw` writes `withdrawsRequestsByEpoch[_user][currentEpoch] += _amount` and overwrites `lastWithdrawRequest[_user] = currentEpoch` on every request [1](#0-0) .
- `collectWithdrawFunds` haircuts the entire `pendingWithdraws` aggregate but records the price under only `lossRecoveryPriceByEpoch[epochNumber]` [2](#0-1) .
- `_claimLossAdjustedWithdrawRequest` resolves the loss epoch solely from `lastWithdrawRequest[_user]` and `_clearWithdrawClaimForEpoch` zeroes only `withdrawsRequestsByEpoch[user][lossEpoch]`, decrementing `withdrawsRequests[user]` by that epoch's piece only [3](#0-2) [4](#0-3) .
- `claimWithdrawRequest` then calls `_claimFundedWithdrawRequest`, which pays the remaining `withdrawsRequests[_user]` aggregate at par; the `epochNumber <= lastWithdrawRequest` gate passes because clearing reset `lastWithdrawRequest` to 0 [5](#0-4) .
- The `requestWithdraw` guard (revert if the epoch pointed to by `lastWithdrawRequest` already has a loss price) cannot prevent this, because both requests are created *before* the loss price exists [6](#0-5) .

### Impact Explanation
Insolvency / direct overpayment. The borrower funds `(A + B) * lossRecoveryPrice`, but a user holding receipt `A` from an earlier epoch and receipt `B` from the loss epoch is paid `B * price + A` — the full par value of `A`. The excess `A * (1 - price)` is drained from strategy underlyings that belong to other pending claimants, funded receipts, or the default recovery reserve; `_transferFundedClaim` does not check that the remaining basis was ever funded at par, only the recovery-reserve guard [7](#0-6) .

### Likelihood Explanation
Requires a manager-called `stopEpochWithDuration` loss while one user has two unclaimed pending receipts from consecutive epochs — an ordinary, non-privileged sequence: request withdraw in epoch N, wait one epoch, request again in epoch N+1, then the epoch ends with a loss. No malicious privileged role is needed; the attacker is a normal KYC'd tranche holder.

### Recommendation
Track all pending receipt epochs per user (e.g., an enumerable epoch set) and clear/haircut every epoch covered by the aggregated `pendingWithdraws` loss, or store receipts under a single rolling basis so the loss price applies to the full remaining `withdrawsRequests[user]` amount rather than only `withdrawsRequestsByEpoch[user][lastWithdrawRequest[user]]`.

function test_LossEpochClearingMissesEarlierReceipt() public {
    IdleCreditVault cv = IdleCreditVault(address(strategy));
    _depositWithUser(address(this), 20_000 * ONE_SCALE, true);

    // Epoch N buffer: request withdraw #1 (basis A), do NOT claim
    uint256 A = cdoEpoch.requestWithdraw(x, address(AAtranche));
    _startEpochAndCheckPrices(0);
    // epoch N stops fully funded; user still doesn't claim
    ... stopEpoch(0,0) ...

    // Epoch N+1 buffer: request withdraw #2 (basis B) -> lastWithdrawRequest = N+1
    uint256 B = cdoEpoch.requestWithdraw(y, address(AAtranche));
    _startEpochAndCheckPrices(1);

    // Epoch N+1 ends with a loss: pendingBasis = A + B, funded = (A+B)*price
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(..., loss); // collectWithdrawFunds stores lossRecoveryPriceByEpoch[N+1]

    // Claim: B paid at haircut, A paid at PAR -> total > funded (A+B)*price
    uint256 balBefore = underlying.balanceOf(address(this));
    cdoEpoch.claimWithdrawRequest();
    assertGt(underlying.balanceOf(address(this)) - balBefore,
             (A + B) * cv.lossRecoveryPriceByEpoch(Nplus1) / 1e18);
}

  /// @notice Claim a funded non-default withdraw request at par.
  /// @param _user address of the user
  /// @return amount amount claimed
  function _claimFundedWithdrawRequest(address _user) internal returns (uint256 amount) {
    // User should wait at least an epoch before claiming the withdraw. Once the epoch is over user can withdraw 
    // at any time even if a new epoch started. 
    // So if epochNumber is the same as the last withdraw request then we revert. Epoch number is increased at stopEpoch
    // NOTE: If a user does not claim a withdraw request and instead requests another withdraw, he will have to wait
    // for another epoch to claim both requests.
    // NOTE 2: if borrower defaults, old withdraw requests can still be claimed
    if (IIdleCDOEpochVariant(idleCDO).epochEndDate() != 0 && (epochNumber <= lastWithdrawRequest[_user])) {
      revert NotAllowed();
    }
    // settle APR=0 requests once the related epoch has ended
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    // Claim includes:
    // - settled APR0 principal from finalized epochs
    // - still-open APR0 principal: if pool-close mode was used (_interest == 1), IdleCDO sets
    //   epochEndDate = 0 and claims can be immediate, while _settleApr0 can still skip settlement
    //   for the current request epoch (reqEpoch >= epochNumber).
    // - settled APR0 interest
    uint256 normalAmount = withdrawsRequests[_user];
    uint256 apr0PrincipalAmount = _apr0User.settledPrincipal + _apr0User.principal;
    uint256 apr0InterestAmount = _apr0User.settledInterest;
    amount = normalAmount + apr0PrincipalAmount + apr0InterestAmount;
    // burn strategy tokens 1:1 with the principal only (normal amount already includes interest)
    _burn(_user, normalAmount + apr0PrincipalAmount);
    withdrawsRequests[_user] = 0;
    lastWithdrawRequest[_user] = 0;
    if (apr0PrincipalAmount != 0 || apr0InterestAmount != 0) {
      delete apr0Users[_user];
    }
    _transferFundedClaim(_user, amount);

  function _claimLossAdjustedWithdrawRequest(address _user) internal returns (uint256 amount) {
    uint256 lossEpoch = lastWithdrawRequest[_user];
    uint256 lossRecoveryPrice = lossRecoveryPriceByEpoch[lossEpoch];
    if (lossRecoveryPrice == 0) return amount;

    (uint256 claimBasis, uint256 burnAmount) = _clearWithdrawClaimForEpoch(_user, lossEpoch, false);
    if (claimBasis == 0) return amount;

    // pendingWithdraws was already cleared when the borrower funded the loss-adjusted amount.
    _burn(_user, burnAmount);
    amount = (claimBasis * lossRecoveryPrice) / RECOVERY_FULL;
    _transferFundedClaim(_user, amount);

  function _clearWithdrawClaimForEpoch(address _user, uint256 _claimEpoch, bool _isClearingApr0) internal returns (uint256 claimBasis, uint256 burnAmount) {
    (claimBasis, burnAmount) = _withdrawClaimAmountsForEpoch(_user, _claimEpoch);
    if (claimBasis == 0) return (claimBasis, burnAmount);

    uint256 normalAmount = withdrawsRequestsByEpoch[_user][_claimEpoch];
    if (normalAmount != 0) {
      withdrawsRequestsByEpoch[_user][_claimEpoch] = 0;
      // The aggregate may also include older funded receipts; clear only this epoch's piece.
      withdrawsRequests[_user] -= normalAmount;
    }
    Apr0UserData storage apr0User = apr0Users[_user];
    if (apr0User.principal != 0 && apr0User.principalEpoch == _claimEpoch) {
      if (_isClearingApr0) {
        uint256 apr0Principal = apr0User.principal;
        uint256 totalApr0Principal = apr0TotalPrincipal;
        // prepareStopEpochWithApr0 may already close the global APR0 bucket before default finalization.
        apr0TotalPrincipal = apr0Principal >= totalApr0Principal ? 0 : totalApr0Principal - apr0Principal;

      apr0User.principal = 0;
      apr0User.principalEpoch = 0;

      // is older and already funded, so it can continue to the funded-claim path.

  function _transferFundedClaim(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    uint256 reserve = defaultRecoveryReserve;
    if (reserve != 0) {
      uint256 balance = underlyingToken.balanceOf(address(this));
      // This should be unreachable when accounting is consistent. Keep the guard so old funded
      // receipts can never spend underlyings reserved for default recovery claimants.
      if (balance < reserve || balance - reserve < _amount) revert NotAllowed();
    }
    underlyingToken.safeTransfer(_user, _amount);
  }
