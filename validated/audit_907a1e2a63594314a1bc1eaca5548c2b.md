### Title
Unauthenticated Request-ID Squatting Enables Denial of Service on Gateway Confidential Relay / Vault Handlers - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

### Summary
The Vow.flop DoS in the external report is a case where an unprivileged actor perturbs shared, globally-keyed state (`vat.dai(vow)`) that a privileged operation requires to be pristine, blocking that operation until the victim notices and calls `heal`. The Chainlink Gateway's `confidentialrelay` handler (and, to a lesser extent, the `vault` handler) has the same bug class: pending requests are tracked in a single map keyed only by the client-supplied JSON-RPC `req.ID`, with no per-sender namespacing and, in the confidential-relay case, no authentication at all. Any unprivileged caller can pre-occupy an ID that another (possibly authorized) caller is about to use, causing the legitimate request to be rejected with "request ID already exists" until the squatter's entry naturally expires.

### Finding Description
`HandleJSONRPCUserMessage` in `confidentialrelay/handler.go` performs no authorization check whatsoever — it only validates that `req.ID` is non-empty and ≤200 chars, then immediately calls `h.newActiveRequest(req, callback)`: [1](#0-0) 

`newActiveRequest` reserves a slot in a single, global `map[string]*activeRequest` keyed purely by `req.ID`: [2](#0-1) 

Because this map is shared across all callers and DON members with no sender/owner component in the key, any unprivileged client reaching the gateway HTTP endpoint for this handler can submit a JSON-RPC request whose `ID` matches (or is guessed/observed ahead of) another caller's upcoming request. The legitimate caller's subsequent request with the same ID is rejected outright:
```
h.lggr.Errorw("request id already exists", "requestID", req.ID)
return nil, errors.New("request ID already exists: " + req.ID)
```
The squatted entry only clears when it times out (`defaultRequestTimeoutSec = 30`) or is otherwise resolved, exactly mirroring the MakerDAO pattern where an attacker repeatedly re-poisons the precondition to sustain the denial of service: [3](#0-2) [4](#0-3) 

The `vault` handler has the identical global `map[string]*activeRequest` keyed on `req.ID` alone: [5](#0-4) 
For vault write/list methods this is reached only after `requestProcessor.ProcessRequest` authorizes the caller, but `MethodPublicKeyGet` explicitly bypasses authorization ("Public key requests don't require authorization") and also calls `newActiveRequest` on the same shared map, so an unauthenticated request can still squat an ID used elsewhere in that map: [6](#0-5) 

Notably, the codebase already contains the correct pattern elsewhere — `common.RequestCache` deliberately keys pending requests by `globalId{sender, id}` (sender + id), precisely to prevent one caller's ID from colliding with another's: [7](#0-6) 
Both `confidentialrelay` and `vault` handlers deviate from this safe pattern by keying solely on the untrusted `req.ID`.

### Impact Explanation
An unprivileged, unauthenticated actor (for confidential relay) can deny service to legitimate confidential-relay/secrets-retrieval requests by ID-squatting, causing genuine requests to fail with a conflict error for up to the request timeout window, repeatable indefinitely to sustain the outage. This is a direct availability/DoS impact on a gateway capability that brokers access to confidential data relay and vault secrets — analogous in class and mechanism to the MakerDAO Vow/Flop DoS (unprivileged party corrupts shared precondition state to block a legitimate operation).

### Likelihood Explanation
For `confidentialrelay`, likelihood is high: `HandleJSONRPCUserMessage` performs zero authentication before reserving the ID slot, so any party capable of sending an HTTP JSON-RPC request to the gateway can trigger this. Exploitation still requires colliding with (or knowing in advance) the victim's chosen `req.ID`; if IDs are predictable/sequential or observable prior to submission (e.g., via client-side reuse, retries, or workflow conventions), an attacker can race ahead of the legitimate caller, exactly as Eve races `vow.flop` with a higher gas price in the analog. For `vault`, exploitation is restricted to the unauthenticated `MethodPublicKeyGet` path colliding with IDs used by other methods on the same map, which is a narrower but still real cross-method DoS surface.

### Recommendation
- Key `activeRequests` (and any analogous pending-request maps) by a composite of authenticated sender identity plus `req.ID`, mirroring the `globalId{sender, id}` pattern already used in `common.RequestCache`, rather than by `req.ID` alone.
- Require authentication/authorization in `confidentialrelay.HandleJSONRPCUserMessage` before reserving a request-ID slot, consistent with how `vault.HandleJSONRPCUserMessage` gates write/list methods.
- For any handler that must accept unauthenticated methods (e.g., `MethodPublicKeyGet`), route them through a separate keyspace/map so they cannot collide with IDs used by authenticated requests.

### Proof of Concept
1. Attacker sends an unauthenticated JSON-RPC request to the gateway's confidential-relay endpoint with `Method: MethodSecretsGet` (or `MethodCapabilityExec`) and `ID: "victim-request-id"`.
2. `HandleJSONRPCUserMessage` accepts it without authorization and calls `newActiveRequest`, inserting `activeRequests["victim-request-id"]`.
3. Shortly after, the legitimate/authorized caller submits their real request using the same `ID` value (predictable, reused, or observed by the attacker).
4. `newActiveRequest` finds the key already present and returns `"request ID already exists: victim-request-id"`, so the legitimate request is dropped/denied.
5. Attacker repeats step 1 with a fresh request every ~`requestTimeoutSec` (default 30s) to keep the ID permanently squatted, achieving sustained denial of service for that request ID. [2](#0-1)

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := logger.With(h.lggr, "method", er.req.Method, "requestID", er.req.ID)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
