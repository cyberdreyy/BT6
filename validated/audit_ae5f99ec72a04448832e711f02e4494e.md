### Title
Post-default instant withdraw requests reuse the finalized epoch bucket and drain `defaultRecoveryReserve` beyond the finalized claim basis - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
The awk `nvalloc` use-after-free maps to this vault's "write into a ledger after it was finalized/freed" class: once `finalizeDefaultRecovery` crystallizes `defaultRecoveryEpoch`, `defaultRecoveryPrice` and `defaultRecoveryReserve`, the per-epoch receipt ledger is effectively closed. However `requestInstantWithdraw` keeps recording new receipts into `instantWithdrawsRequestsByEpoch[user][epochNumber]`, and because no further `stopEpoch` runs after default, `epochNumber` stays equal to `defaultRecoveryEpoch`. New post-default instant receipts therefore alias the finalized epoch bucket and are paid out of the fixed recovery reserve at `defaultRecoveryPrice` — a claim basis that was never counted in `totalBasis` at finalization. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`finalizeDefaultRecovery` computes `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` where `totalBasis = activeBasis + defaultPendingClaimBasis()` and then freezes `defaultRecoveryEpoch = epochNumber`. [4](#0-3) 

The normal (non-instant) path is protected: after `defaultRecoveryFinalized`, `requestWithdraw` routes to the isolated `postDefaultRequests` bucket and reverts if the user has any open receipts. [5](#0-4) 

`requestInstantWithdraw` has no equivalent post-default branch. It still executes `instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount` and `instantWithdrawClaimsByEpoch[currentEpoch] += _amount` with `currentEpoch == epochNumber == defaultRecoveryEpoch`. [6](#0-5) 

When the user then calls `claimInstantWithdrawRequest`, `defaultInstantWithdrawsFinalized` is true, so `_claimDefaultedInstantWithdrawRequest` reads `instantWithdrawsRequestsByEpoch[_user][defaultEpoch]` — now containing the *new* post-default receipt — and pays `(claimBasis * defaultRecoveryPrice) / RECOVERY_FULL` out of `defaultRecoveryReserve` via `_transferDefaultRecovery`. [7](#0-6) [8](#0-7) [9](#0-8) 

The reserve was sized exactly as `totalBasis * recoveryPrice`, so every extra post-default `claimBasis` unit paid at `defaultRecoveryPrice` is funded by legitimate defaulted-epoch claimants' entitlements. Additionally, the same inflated `instantWithdrawClaimsByEpoch[defaultRecoveryEpoch]` value was already used at finalization through `_defaultPrefundedInstantReserve`/`defaultPendingClaimBasis` semantics only for pre-finalization receipts; post-finalization increments are pure unbacked claims. [10](#0-9) [11](#0-10) 

### Impact Explanation
Direct theft / insolvency of the recovery reserve: an attacker who is a tranche holder (unprivileged, KYC-passed lender) can, after `finalizeDefault`, open an instant withdraw request and immediately claim `X * defaultRecoveryPrice / RECOVERY_FULL` underlying from `defaultRecoveryReserve`, even though their receipt contributed zero to `totalBasis`. Repeating or sizing the request drains the reserve so honest defaulted receipt holders and `DefaultDistributor` claimants are left undercollateralized — the last claimants' `_transferDefaultRecovery` underflows/reverts, permanently freezing their recovery. Quantified loss: up to `attackerReceipt * defaultRecoveryPrice / RECOVERY_FULL` stolen per claim, bounded only by tranche balance; aggregate reserve shortfall equal to total post-default instant claims paid.

### Likelihood Explanation
Requires the vault to be in the `defaulted + defaultRecoveryFinalized` phase and the CDO to route the post-default `requestWithdraw` into the instant path. `claimInstantWithdrawRequest` in the CDO only gates on `allowInstantWithdraw`, which tests show can remain `true` after default (`assertEq(cdoEpoch.allowInstantWithdraw(), true)` at test line 2694/2716). [12](#0-11)  Unverified residual: whether `IdleCDOEpochVariant.requestWithdraw` selects the instant bucket post-default depends on `allowInstantWithdraw`/epoch flags in the CDO (I could not read that function body in the available iterations); if it routes to `requestWithdraw`, the `postDefaultRequests` guard applies and this path is unreachable. The strategy-level hole itself is unconditional — nothing in `requestInstantWithdraw`/`_claimDefaultedInstantWithdrawRequest` distinguishes pre- from post-finalization writes to the same epoch key.

### Recommendation
Mirror the normal-path guard in `requestInstantWithdraw`: after `defaultRecoveryFinalized`, either revert or route the request into `postDefaultRequests` (already haircut-priced), so new receipts can never enter `instantWithdrawsRequestsByEpoch[defaultRecoveryEpoch]` or `instantWithdrawClaimsByEpoch[defaultRecoveryEpoch]` after `recoveryPrice` is frozen. Alternatively, key defaulted-epoch claims to a snapshot taken at `finalizeDefaultRecovery` rather than the live per-epoch ledger.

```solidity
// test/foundry/PocPostDefaultInstantDrain.t.sol
function testPostDefaultInstantReceiptDrainsReserve() external {
    // 1. Deposit as attacker (AA tranche), run epoch, borrower defaults.
    uint256 amt = 10_000 * ONE_SCALE;
    uint256 mintedAA = idleCDO.depositAA(amt);
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr / 2, _expectedFundsEndEpoch() - 1);
    _checkDefault();

    // 2. Manager finalizes default at e.g. 70% recovery.
    IdleCreditVault vault = IdleCreditVault(address(strategy));
    uint256 basis = cdoEpoch.getContractValue() + cdoEpoch.expectedEpochInterest()
        - cdoEpoch.pendingWithdrawFees() + vault.defaultPendingClaimBasis();
    uint256 recovered = basis * 7e17 / ONE_TRANCHE;
    deal(defaultUnderlying, manager, recovered);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), recovered);
    cdoEpoch.finalizeDefault(recovered, manager);
    vm.stopPrank();
    uint256 reservePre = vault.defaultRecoveryReserve();

    // 3. Attacker opens a NEW instant withdraw request post-finalization.
    //    (requires CDO requestWithdraw to take the instant path while
    //    allowInstantWithdraw is still true after default.)
    uint256 req = cdoEpoch.requestWithdraw(AAtranche.balanceOf(address(this)) / 2, address(AAtranche));
    assertGt(vault.instantWithdrawsRequestsByEpoch(address(this), vault.defaultRecoveryEpoch()), 0);

    // 4. Claim pays recovery price from the reserve for a receipt never in totalBasis.
    uint256 balPre = IERC20Detailed(defaultUnderlying).balanceOf(address(this));
    cdoEpoch.claimInstantWithdrawRequest();
    uint256 got = IERC20Detailed(defaultUnderlying).balanceOf(address(this)) - balPre;
    assertEq(got, req * vault.defaultRecoveryPrice() / vault.RECOVERY_FULL());
    // reserve reduced by unbacked claims -> honest claimants' remainder shortfall
    assertLt(vault.defaultRecoveryReserve(), reservePre - got + 1);
}
```

If step 3 is instead routed by the CDO into the guarded normal path, the strategy-level fix in the Recommendation is still required to make the finalized epoch ledger immutable.

```text
  function _defaultPrefundedInstantReserve() internal view returns (uint256 prefundedReserve) {
    uint256 pendingInstant = pendingInstantWithdraws;
    if (pendingInstant == 0) return prefundedReserve;
    uint256 instantBasis = instantWithdrawClaimsByEpoch[epochNumber];
    if (instantBasis > pendingInstant) {
      prefundedReserve = instantBasis - pendingInstant;
    }
  }
```

```text
  function _claimDefaultedInstantWithdrawRequest(address _user) internal returns (uint256 claimBasis) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultEpoch];
    if (claimBasis == 0) return claimBasis;

    instantWithdrawsRequestsByEpoch[_user][defaultEpoch] = 0;
    instantWithdrawsRequests[_user] -= claimBasis;
    uint256 pending = pendingInstantWithdraws;
    // `pendingInstantWithdraws` is only the unfunded remainder. If this user's claim is larger,
    // the extra amount was already counted as prefunded reserve during default finalization.
    pendingInstantWithdraws = claimBasis >= pending ? 0 : pending - claimBasis;
    instantWithdrawClaimsByEpoch[defaultEpoch] -= claimBasis;
    _burn(_user, claimBasis);
    _transferDefaultRecovery(_user, (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL);
  }
```
