Confirmed vulnerability. `FindUserByAPIToken` at [1](#0-0)  only reads the cached `user_role` column from `ldap_user_api_tokens` and checks expiry — it never triggers a live LDAP re-check. The `AuthenticateByToken` middleware calls this function directly on every API-token request with no sync hook: [2](#0-1) . The only place that reconciles cached roles against upstream LDAP group membership is `LDAPServerStateSyncer.Work`, invoked either once at `Start` (if `UpstreamSyncInterval` is `0s`/instant) or on a ticker otherwise [3](#0-2) . With `UpstreamSyncInterval = '0s'` (the documented default), `Work` runs only once at node startup and is never invoked again on a timer, and `AuthenticateByToken` does not call it per-request. This contradicts the package/config doc comments claiming the sync "happens for every auth endpoint hit" [4](#0-3) [5](#0-4) .

### Title
Stale API-token role persists indefinitely when `UpstreamSyncInterval=0s` since `FindUserByAPIToken` never re-validates against upstream LDAP - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`ldapAuthenticator.FindUserByAPIToken` trusts the `user_role` snapshot stored in `ldap_user_api_tokens` at `SetAuthToken` time, and this snapshot is only refreshed by `LDAPServerStateSyncer.Work`. When `UpstreamSyncInterval` is `0s` (the default), `Work` runs a single time at process startup and is never re-triggered by request traffic, so a token minted while the holder briefly had Edit/Admin group membership keeps that privileged role for the full life of the token (`UserAPITokenDuration`, default 240h).

### Finding Description
`SetAuthToken` persists the caller-supplied `user.Role` into `ldap_user_api_tokens.user_role` at token-creation time without any freshness guarantee [6](#0-5) . `FindUserByAPIToken`, invoked from the `AuthenticateByToken` gin middleware on every `X-API-KEY`/`X-API-SECRET` request, only checks token expiry via `created_at + duration >= now()` and returns the stored role, with zero upstream LDAP interaction [1](#0-0) . The only mechanism that reconciles stored roles against the live LDAP directory is `LDAPServerStateSyncer.Work`, called from `Start`: if `UpstreamSyncInterval().IsInstant()` (true for the `0s` default) it runs `Work` once at boot and never schedules a background ticker; only a non-zero interval spawns the recurring `run()` goroutine [7](#0-6) . Since a node typically has long uptime between restarts, an attacker who briefly held (or was granted then had revoked) Edit/Admin LDAP group membership at the moment they called `SetAuthToken`/`CreateAndSetAuthToken` retains that stale privileged role for every subsequent request until token expiry or the next node restart/sync — e.g., `POST /v2/jobs` with the stale token bypasses `RequiresEditRole`/`RequiresAdminRole` checks in [8](#0-7)  because those checks only inspect `user.Role`, which is the unrefreshed cached value.

### Impact Explanation
Concrete impact: unauthorized/privileged REST actions (e.g., job creation/deletion, other Edit/Admin routes) performed by a de-privileged LDAP user using a stale API token — this is a role/authorization bypass leading to unauthorized job run/management, matching the "authorization bypass"/"unauthorized job creation" bounty impact class.

### Likelihood Explanation
Requires only a previously issued, still-unexpired API token from a period when the user was in the Edit/Admin LDAP group (`UserApiTokenEnabled` must be true, LDAP auth mode enabled). No operator/admin/host access needed — purely a credential the attacker already legitimately possesses. With the documented default `UpstreamSyncInterval = '0s'`, this is fully exploitable and reproducible for up to `UserAPITokenDuration` (default 240h) after the group demotion, unless the node happens to restart in between.

### Recommendation
Make `AuthenticateByToken` (or `FindUserByAPIToken`) trigger/await a rate-limited `LDAPServerStateSyncer.Work` pass (or an equivalent per-user live-role check) before trusting the cached role, similar to how the package docs claim sync happens "for every auth endpoint hit." At minimum, always run a recurring background sync regardless of `UpstreamSyncInterval` being zero, or clamp `UpstreamSyncInterval` to a safe non-zero default and document that `0s` is insecure for long-lived deployments.

### Proof of Concept
Go test plan (extending `core/sessions/ldapauth/ldap_test.go` and `sync_test.go`):
1. Instantiate `ldapAuthenticator` with a test datasource; call `SetAuthToken` for `user@example.com` with `Role=UserRoleEdit`, capturing the generated `auth.Token`.
2. Directly assert via SQL that `ldap_user_api_tokens.user_role = 'edit'`.
3. Configure the mock `LDAPClient` so a subsequent group-membership query returns the user only in the `ReadUserGroupCN` group (simulating downgrade), and set `UpstreamSyncInterval` to `0s` in the test config.
4. Do NOT call `LDAPServerStateSyncer.Work` (simulating no restart / no interval-based sync) and instead directly call `l.FindUserByAPIToken(ctx, token.AccessKey)`.
5. Assert the returned `sessions.User.Role` is still `UserRoleEdit` (stale), demonstrating the bypass.
6. As a control, call `syncer.Work(ctx)` once, then re-run `FindUserByAPIToken` and assert the role is now downgraded to `UserRoleView`, proving the fix requires sync to run per-request rather than only at startup/interval.

func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (l *ldapAuthenticator) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	if !l.config.UserApiTokenEnabled() {
		return errors.New("API token is not enabled ")
	}

	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return fmt.Errorf("LDAPAuth SetAuthToken hashed secret error: %w", err)
	}

	err = sqlutil.TransactDataSource(ctx, l.ds, nil, func(tx sqlutil.DataSource) error {
		// Is this user a local CLI Admin or upstream LDAP user?
		// Check presence in local users table. Set localauth_user column true if present.
		// This flag omits the session/token from being purged by the sync daemon/reaper.go
		isLocalCLIAdmin := false
		err = l.ds.QueryRowxContext(ctx, "SELECT EXISTS (SELECT 1 FROM users WHERE email = $1)", user.Email).Scan(&isLocalCLIAdmin)
		if err != nil {
			return fmt.Errorf("error checking user presence in users table: %w", err)
		}

		// Remove any existing API tokens
		if _, err = l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE user_email = $1", user.Email); err != nil {
			return fmt.Errorf("error executing DELETE FROM ldap_user_api_tokens: %w", err)
		}
		// Create new API token for user
		_, err = l.ds.ExecContext(
			ctx,
			"INSERT INTO ldap_user_api_tokens (user_email, user_role, localauth_user, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1, $2, $3, $4, $5, $6, now())",
			user.Email,
			user.Role,
			isLocalCLIAdmin,
			token.AccessKey,
			salt,
			hashedSecret,
		)
		if err != nil {
			return fmt.Errorf("failed insert into ldap_user_api_tokens: %w", err)
		}
		return nil
	})
	if err != nil {
		return errors.New("error creating API token")
	}

	l.auditLogger.Audit(audit.APITokenCreated, map[string]any{"user": user.Email})
	return nil
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) Close() error {
	close(l.stopCh)
	<-l.done
	return nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}
