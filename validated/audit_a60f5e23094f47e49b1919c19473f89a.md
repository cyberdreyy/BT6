### Title
ERC4626 share-price inflation via direct donation inflates `totalInterestDueNow()` and mints uncollateralized epoch interest into tranche NAV - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` measures the epoch PnL of its ERC4626 vault sleeve with `vault.convertToAssets(shares)` in `_currentVaultAssets()` (`ProgrammableBorrower.sol:546-549`). Any unprivileged depositor of that external vault can inflate its exchange rate by donating underlying directly to the vault (or through the classic deposit/borrow rate-inflation loop used in the Edel incident). `_vaultNetInterest()` (`ProgrammableBorrower.sol:337-347`) then reports the phantom delta as vault interest, which flows into `totalInterestDueNow()` (`ProgrammableBorrower.sol:330-334`). `IdleCDOEpochVariant.stopEpoch` consumes this single value to price the epoch; in minted-interest mode (`isInterestMinted`, see `availableToBorrow` comment at `ProgrammableBorrower.sol:352-353`: "Interest is minted (not pulled as cash)") the phantom amount is credited to NAV without any cash being pulled, raising `priceAA`/`priceBB`. An attacker holding tranche tokens redeems at the inflated price and extracts real assets belonging to other lenders, leaving bad debt.

### Finding Description
The Edel exploit manipulated a wrapped token's exchange rate to inflate collateral value ~78x and borrow real assets against it. The analog here is the ERC4626 exchange rate of the programmable borrower's vault:

1. Epoch starts; `onStartEpoch` snapshots `epochStartVaultAssets` and parks all idle underlying into the vault (`ProgrammableBorrower.sol:201-224`).
2. Attacker (a normal ERC4626 vault user) inflates `convertToAssets` — e.g., by transferring underlying directly to a vault whose `totalAssets` counts raw balance, or by flash-loan deposit/redemption loops that move the rate.
3. `_vaultNetInterest()` computes `earnedAssets - principalAssets` where `earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault` (`ProgrammableBorrower.sol:339-341`). The entire donation/manipulation delta is now reported as `interest`.
4. `totalInterestDueNow()` returns `vaultInterest + borrowerInterestAccruedNow() + bufferInterest - loss` (`ProgrammableBorrower.sol:330-334`) — no cap ties vault interest to the contractual `borrowerApr` or any oracle-independent bound.
5. In `isInterestMinted` mode, `stopEpoch` mints strategy tokens for this amount instead of pulling cash, so `_updateAccounting` / NAV bookkeeping treats the phantom interest as real gain and tranche prices (`_virtualPriceAux`, `IdleCDOCreditVault.sol:172-180` → `IdleCDO.sol:359-430`) rise.
6. Attacker, who deposited into AA/BB tranches before the manipulation (or holds previously minted tranche tokens), calls withdraw/`collectWithdrawFunds` at the inflated price and drains real underlying; remaining lenders hold tranches priced above actual NAV — classic bad debt.

The donation is recoverable: the attacker still owns vault shares, so the donated capital is largely returned via their own share redemption, while the minted phantom interest is an unbacked claim on the pool. Cost < profit whenever the attacker holds or can cheaply acquire tranche exposure.

### Impact Explanation
Direct insolvency/theft: phantom vault interest becomes unbacked tranche value. Existing lenders absorb the loss through NAV dilution (BB-first waterfall in `_virtualPriceAux`). Loss is quantified as the inflation amount credited at `stopEpoch`, bounded only by the attacker's donation capital relative to their tranche position — mirroring Edel's leverage between manipulated collateral value and borrowed real assets.

### Likelihood Explanation
Requires (a) a vault configured in `ProgrammableBorrower` whose `convertToAssets` is manipulable by unprivileged users (donation-sensitive ERC4626s, low-liquidity vaults, or rate-inflatable lending vaults — precisely the class hit in Edel), and (b) the attacker holding a tranche position when `stopEpoch` runs. Both attacker roles are explicitly in scope ("a tranche-token holder", "a user of the programmable borrower's ERC4626 vault"); the honest manager calling `stopEpoch`/`startEpoch` is sequenced around, not impersonated. No existing guard stops it: `_skimDonatedAssets`/raw-balance exclusion in `_managedContractValue()` (`IdleCDOCreditVault.sol:133-137`) protects only the CDO's own balance, not the external vault's valuation; `Default`/`skipDefaultCheck` only react to losses, not phantom gains; `onlyOwner/manager` guards do not cover vault deposits/donations by third parties.

### Recommendation
Bound the vault-sleeve valuation inside `ProgrammableBorrower`:
- Track an internal cost-basis asset accrual (e.g., cap `vaultInterest` by a `maxVaultApr * principal * elapsed` bound similar to `_calcInterest`), or require vault interest to be realized by an actual `redeem`/`withdraw` before counting it in `totalInterestDueNow`.
- Use share-amount deltas rather than `convertToAssets` deltas where possible, and treat a positive `convertToAssets` jump unexplained by elapsed time as a loss/limit event rather than free interest.
- Sanity-check `totalInterestDueNow()` against `borrowerInterestOwedNow() + bufferInterest + time-bounded vault yield` in `stopEpoch` and route excess to a reviewable path instead of minting it.

### Proof of Concept
Foundry fork PoC sketch (mainnet fork with a donation-sensitive or low-liquidity ERC4626 as `vault`):

```solidity
// test/foundry/ProgrammableBorrowerDonationInflation.t.sol
function testVaultDonationInflatesEpochInterest() external {
    uint256 amount = 100_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);          // minted-interest mode

    idleCDO.depositAA(amount);                    // attacker or victim LP deposits
    _startEpoch();                                // ProgrammableBorrower parks funds in vault

    // 1. Attacker acquires tranche exposure before manipulation
    deal(USDC, attacker, 10_000 * oneScale);
    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), type(uint256).max);
    cdoEpoch.depositAA(10_000 * oneScale);        // (or holds existing tranche tokens)

    // 2. Attacker inflates vault exchange rate
    deal(USDC, attacker, DONATION);
    underlying.transfer(vaultAddress, DONATION);  // donation -> convertToAssets up

    vm.stopPrank();
    vm.warp(block.timestamp + epochDuration);

    // 3. Phantom interest is now reported
    uint256 phantom = programmableBorrower.totalInterestDueNow();
    assertGt(phantom, DONATION * 9 / 10);

    // 4. Honest manager stops the epoch; phantom interest is minted into NAV
    vm.prank(manager);
    cdoEpoch.stopEpoch(/*apr*/ 0, /*loss*/ 0, /*duration*/ 0);
    assertGt(cdoEpoch.virtualPrice(address(aaTranche)), prePrice);

    // 5. Attacker redeems tranches at inflated price -> drains real underlying,
    //    then redeems own vault shares to recover most of the donation.
    // Post-conditions: attackerProfit > 0, remaining NAV < sum of claims (bad debt).
}
```
