### Title
Stale pre-default tranche price enables over-borrowing against defaulted collateral - ([File: contracts/strategies/morpho/TranchesChainlinkOracle.sol](contracts/strategies/morpho/TranchesChainlinkOracle.sol))

### Summary
`TranchesChainlinkOracle` reports `cdo.virtualPrice(collateralToken)` without checking whether the credit vault has entered hard default. [1](#0-0)  After `_handleBorrowerDefault`, the CDO remains backed on-chain by the same number of strategy tokens even though the borrower failed to return the underlying, so `virtualPrice` continues reporting the pre-default price until recovery is finalized. [2](#0-1) [3](#0-2) 

### Finding Description
`IdleCDOCreditVault.getContractValue()` values the vault as its strategy-token balance plus raw underlying minus fees; it does not check whether the strategy tokens are actually backed by recoverable underlying. [3](#0-2)  During a normal epoch stop, the strategy-token balance therefore remains intact when `getFundsFromBorrower` fails and `_handleBorrowerDefault` marks the pool defaulted. [4](#0-3) [2](#0-1)  The default handler pauses the CDO and disables withdrawal requests, but it does not burn strategy tokens, reduce `lastNAVAA` or `lastNAVBB`, or otherwise reprice tranches. [2](#0-1)  Consequently, `virtualPrice` can continue to report the pre-default NAV per tranche throughout the period between `defaulted = true` and `finalizeDefault`.

The correction only occurs in `finalizeDefault`, which writes recovery-adjusted NAVs and force-updates accounting. [5](#0-4)  Because `IdleCDOTranche` is a normal unrestricted ERC20 once minted, a prior KYC-passing lender or any secondary-market holder can supply those stale-priced tranches as collateral to an external market using this adapter. [6](#0-5) 

### Impact Explanation
An attacker holding defaulted tranche tokens can borrow loan tokens against collateral that the oracle still values at its pre-default price. If the borrower ultimately returns zero, the collateral's finalized tranche price is zero, while a 98%-LLTV market could already have paid out approximately 98% of the stale principal value as borrowed assets. For example, 10,000 tranche tokens priced at 1 loan token each can support a 9,800 loan-token withdrawal even though the collateral's final recovery value is zero. The resulting bad debt is borne by the external market's lenders, while the attacker keeps the borrowed underlying.

This is the same economic bug class as the Moonwell incident: a collateral oracle reports an inflated or stale exchange rate and allows borrowing beyond the collateral's recoverable value. The critical exposure window begins when an honest manager's `stopEpoch` call records the default and ends only when an honest owner or manager calls `finalizeDefault`.

### Likelihood Explanation
No privileged attacker action is required. The attacker only needs to hold freely transferable tranche tokens before or during the default and interact with a lending market that consumes `latestRoundData`. [6](#0-5)  The stale price is produced automatically by the honest default flow: `_handleBorrowerDefault` does not call accounting or recovery finalization. [2](#0-1)  Existing pause, request-withdrawal, and access-control guards prevent normal CDO exits, but they do not prevent transferring tranche tokens or supplying them as external collateral.

### Recommendation
Do not expose a positive pre-default `virtualPrice` after hard default. `latestRoundData` should revert or return zero whenever the underlying CDO is in `defaulted` state and recovery has not been finalized. After finalization, the oracle can resume reporting the recovery-adjusted `virtualPrice`. Equivalently, introduce an explicit oracle-safe valuation that uses the finalized default recovery price rather than raw strategy-token supply.

### Proof of Concept
Add this regression test beside the existing default tests in `test/foundry/IdleCreditVault.t.sol`. It uses the existing deployed-fixture variables and demonstrates that the oracle remains at the pre-default price after `stopEpoch` records a borrower default, then falls to zero only after zero-recovery finalization.

```solidity
// test/foundry/IdleCreditVault.t.sol
function testOracleReportsStalePriceBetweenDefaultAndFinalization() external {
    uint256 amount = 10_000 * ONE_SCALE;
    address attacker = makeAddr("stale-price-attacker");

    // Attacker is an ordinary allowed lender who acquires transferable AA tranches.
    deal(defaultUnderlying, attacker, amount, true);
    vm.startPrank(attacker);
    underlying.approve(address(cdoEpoch), amount);
    uint256 trancheAmount = cdoEpoch.depositAA(amount);
    vm.stopPrank();

    TranchesChainlinkOracle oracle =
        new TranchesChainlinkOracle(address(AAtranche));

    _startEpochAndCheckPrices(0);

    // Honest manager attempts to stop the epoch, but the borrower has no balance/allowance.
    deal(defaultUnderlying, borrower, 0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    assertTrue(cdoEpoch.defaulted());
    assertEq(strategyToken.balanceOf(address(cdoEpoch)), amount);

    // Oracle still reports the old price despite the missing underlying.
    (, int256 stalePrice,,,) = oracle.latestRoundData();
    assertEq(uint256(stalePrice), ONE_SCALE);
    assertEq(cdoEpoch.virtualPrice(address(AAtranche)), ONE_SCALE);

    // A 98% LLTV consumer would lend this much against defaulted collateral.
    uint256 stolenLoan = trancheAmount * uint256(stalePrice) * 98
        / (ONE_TRANCHE * 100);
    assertApproxEqAbs(stolenLoan, amount * 98 / 100, 2);

    vm.prank(manager);
    cdoEpoch.finalizeDefault(0, address(0));

    (, int256 correctedPrice,,,) = oracle.latestRoundData();
    assertEq(uint256(correctedPrice), 0);
}
```

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
