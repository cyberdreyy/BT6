### Title
Unauthenticated flood of `HandleLegacyUserMessage` causes cross-user eviction of pending callbacks via `pruneCallbacks` - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores every incoming legacy request in a single global map `savedCallbacks` keyed only by `MessageId`, with no allowlisting, per-sender quota, or rate limiting applied before insertion. Because `pruneCallbacks` evicts the globally oldest half of entries once the map exceeds `MaxSavedCallbacks`, any unauthenticated client that can produce a self-signed message can flood the map with unique `MessageId`s and force eviction of other users' still-pending callbacks, silently dropping their responses.

### Finding Description
The gateway's HTTP entry point `ProcessRequest` in `core/services/gateway/gateway.go` routes legacy requests (those with a `DonId`) straight to `HandleLegacyUserMessage` after only `msg.Validate()` (a signature well-formedness check, not an identity/allowlist check) [1](#0-0) . Inside `HandleLegacyUserMessage`, the code explicitly documents that allowlisting/rate-limiting is not yet implemented: `// TODO: apply allowlist and rate-limiting here` [2](#0-1) . Any request signed with an arbitrary (attacker-generated) ECDSA key that passes basic structural validation and is not stale is accepted, and immediately inserted into the shared map: `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` [3](#0-2) .

`pruneCallbacks` runs periodically (every `CallbackPruneIntervalSec`, default 30s) and, when the map exceeds `MaxSavedCallbacks` (default 20000), sorts all entries by `createdAt` and deletes the oldest half regardless of which sender/user created them: `entries[:len(entries)-maxSize/2]` [4](#0-3) . There is no per-sender partitioning or fairness in either the storage or the eviction logic — the map and its pruning are entirely global.

Since a legitimate user's callback remains in the map until the node responds (which can take up to the node's processing time), an attacker can continuously submit fresh, uniquely-ID'd legacy messages fast enough to push the total count above `MaxSavedCallbacks`. Because eviction always removes the *oldest* entries first, a victim's still-pending (older) callback that hasn't yet received a node response will be deleted before `handleWebAPITriggerMessage` can look it up and call `SendResponse`, causing that response to be silently dropped (the `found` check in `handleWebAPITriggerMessage` will be false) [5](#0-4) .

### Impact Explanation
This is a denial-of-service / cross-user interference bug: an unprivileged network client can cause legitimate users' in-flight gateway requests to be dropped without any error surfaced to them (the caller just times out per `callback.Wait(ctx)` in `gateway.go`), degrading availability and reliability of the workflow/web-API-trigger capability for arbitrary other tenants sharing the same DON handler. It matches the "quota/allowlist bypass leading to denial of service for other users" impact class.

### Likelihood Explanation
No special privilege, authentication, or allowlist entry is required — the only precondition is the ability to produce a validly-formed, self-signed `api.Message` (any key works, per `msg.Validate()` which only checks structural signature validity, not membership) and network access to the gateway's HTTP endpoint. The attacker needs to sustain enough concurrent requests to exceed `MaxSavedCallbacks` (20000 by default) within roughly a `CallbackPruneIntervalSec` window, which is feasible for a moderately resourced attacker and is explicitly acknowledged as unmitigated in the code (`TODO: apply allowlist and rate-limiting here`).

### Recommendation
Apply per-sender/per-address rate limiting and/or an allowlist check in `HandleLegacyUserMessage` before inserting into `savedCallbacks` (the TODO already present at line 384), and/or make `pruneCallbacks` fairness-aware (e.g., cap the number of pending callbacks per sender, or evict based on per-sender quotas rather than a single global oldest-first cut) so that one sender cannot force eviction of another sender's pending entries.

### Proof of Concept
Go handler-level integration test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Configure `handler` with a small `MaxSavedCallbacks` (e.g., 10) and `CallbackPruneIntervalSec`=short.
2. Submit one legitimate `HandleLegacyUserMessage` call with callback `cbVictim`, do not deliver a node response yet (simulate slow node).
3. Immediately submit `MaxSavedCallbacks` additional `HandleLegacyUserMessage` calls with distinct `MessageId`s (different signing keys) so total entries exceed `MaxSavedCallbacks`.
4. Manually invoke `handler.pruneCallbacks()` (or wait for the ticker).
5. Assert `cbVictim`'s `MessageId` is no longer present in `savedCallbacks` (unexported field access via test in same package) and that subsequently delivering the node's response for the victim message via `HandleNodeMessage` does NOT call `cbVictim.SendResponse` — assert `cb.Wait(ctx)` times out / never resolves, proving the response was silently dropped due to attacker-induced eviction.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.

	}
	return nil

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
