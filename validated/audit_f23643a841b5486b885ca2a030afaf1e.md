### Title
Cache extraction restores symlinks pointing outside the build root without validation - ([File: helpers/archives/zip_extract.go])

### Summary
The zip cache-extraction path used by `commands/helpers/cache_extractor.go` re-creates symlinks from an untrusted cache archive without validating that the symlink target stays inside the extraction root, and without any path/chroot check on the entry name itself. Combined with the archiver, which faithfully stores a workspace symlink's literal target string (e.g. `/etc`) when the *link path* passes the project-root check, a job can plant a symlink such as `cache:paths: [evil]` -> `/etc`, have it pushed into the cache, and have it recreated verbatim on restore in a later job.

### Finding Description
`builder.go` passes `cache.Paths` unmodified into `stages.CacheArchive.Paths`/`stages.CacheExtract.Paths` [1](#0-0) [2](#0-1) , which the actual `cache-archiver`/`cache-extractor` helper commands consume.

On archive creation, `fileArchiver.process`/`findRelativePathInProject` validate that the *symlink's own path* (e.g. `evil`) resolves inside the project working directory, but they never inspect or restrict the symlink's *target* [3](#0-2) . When the legacy zip writer serializes such an entry, it stores the raw `os.Readlink` result (e.g. `/etc`) as the file content with no target validation [4](#0-3) .

On extraction, `ExtractZipArchive`/`extractZipFile` in `helpers/archives/zip_extract.go` iterate the archive entries and call `extractZipSymlinkEntry`, which does `os.Symlink(string(data), file.Name)` — it recreates the symlink pointing to whatever target string is stored in the archive, with **no check** that this target resolves inside the extraction root [5](#0-4) [6](#0-5) . Nor is there any chroot-style check on `file.Name` itself in this package, unlike the parallel guards present in `commands/helpers/archive/tarzstd/tarzstd_extractor.go` (`filepath.Abs`/`HasPrefix(path, e.dir+separator)`) [7](#0-6)  and in the create-side `commands/helpers/archive/tarzstd/tarzstd_archiver.go` [8](#0-7) . The legacy zip extractor wrapper (`ziplegacy.extractor.Extract`) even ignores its own `dir` field entirely and calls `archives.ExtractZipArchive(zr)` with no root parameter at all [9](#0-8) , relying solely on the process's current working directory for containment, which does nothing to stop a symlink target from being an absolute path or a `../`-escaping relative path.

`CacheExtractorCommand.Execute` invokes this extractor with `wd` (job build directory) as the extraction root [10](#0-9) , so the symlink materializes inside the job workspace but can point anywhere on the filesystem the job's runtime user can reach (e.g. `/etc`, a sibling checkout, or another job's temp path in shared-runner/shell-executor deployments).

### Impact Explanation
Once a job pushes a cache containing an out-of-root symlink (`evil -> /etc` or similar), any later job in the same project/cache scope that pulls that cache gets that dangling symlink recreated verbatim in its build directory. Subsequent build-script steps in that job that read or write through the symlinked path (e.g. `cat evil/passwd`, `echo x > evil/cron.d/x`, or a build tool that recursively copies/writes into `cache:paths` directories) read or write files outside the intended build/cache root — violating the "file operations must stay within intended build/cache/artifact roots" invariant. The severity is bounded by what the executor's OS user can already access (this is not a sandbox escape by itself), but it lets a cache-poisoning job affect files outside its own workspace in later jobs sharing that cache/user, which is the scoped impact this question targets.

### Likelihood Explanation
Fully attacker-controlled and repeatable: any pipeline author can define `cache: {paths: [evil]}`, create `ln -s /etc evil` in the job script, and let the cache-push stage run — no special permissions are required beyond normal job authoring. The only precondition is that a later job (attacker's own subsequent pipeline run, or another job sharing the same cache key/scope) pulls the same cache and touches the symlinked path.

### Recommendation
In `helpers/archives/zip_extract.go`:
- Before `os.Symlink(string(data), file.Name)` in `extractZipSymlinkEntry`, resolve the target relative to the entry's directory and reject (or refuse to write) any resulting path that is absolute or escapes the extraction root (mirror the `filepath.Abs` + `HasPrefix(dir+separator)` chroot check already used in `tarzstd_extractor.go`).
- Add the same chroot check on `file.Name` itself in `extractZipFile`/`ExtractZipArchive`, since this package currently performs none.
- Fix `ziplegacy.extractor.Extract` to actually pass and enforce its `dir` field instead of discarding it.

### Proof of Concept
```go
func TestExtractZipArchive_RejectsSymlinkEscapingRoot(t *testing.T) {
    srcDir := t.TempDir()
    // simulate a cache archive created from a workspace containing a symlink
    // "evil" -> "/etc"
    require.NoError(t, os.Symlink("/etc", filepath.Join(srcDir, "evil")))

    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    fh, _ := zip.FileInfoHeader(mustLstat(t, filepath.Join(srcDir, "evil")))
    fh.Name = "evil"
    w, _ := zw.CreateHeader(fh)
    _, _ = w.Write([]byte("/etc")) // attacker/job-controlled symlink target
    require.NoError(t, zw.Close())

    outDir := t.TempDir()
    // simulate extraction into build root outDir
    prev, _ := os.Getwd()
    require.NoError(t, os.Chdir(outDir))
    defer os.Chdir(prev)

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err) // currently succeeds silently

    target, err := os.Readlink(filepath.Join(outDir, "evil"))
    require.NoError(t, err)
    // BUG: assert should be that this is rejected/contained; currently target == "/etc"
    assert.NotEqual(t, "/etc", target, "symlink must not be allowed to point outside the extraction root")
}
```
Expected (fixed) behavior: `ExtractZipArchive` returns an error (or skips the entry with a warning) for any symlink whose target resolves outside `outDir`, rather than silently creating `outDir/evil -> /etc`.

func (c *fileArchiver) findRelativePathInProject(path string) (string, error) {
	slashPath := filepath.ToSlash(path)
	if filepath.Clean(slashPath) == filepath.Clean(c.wd) {
		return ".", nil
	}

	base, patt := slashPath, ""
	// check if path contains a glob pattern
	if strings.ContainsAny(slashPath, "*?[{") {
		base, patt = doublestar.SplitPattern(slashPath)
	}

	abs, err := filepath.Abs(base)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact absolute path %s: %w", path, err)
	}

	rel, err := filepath.Rel(c.wd, abs)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact relative path %s: %w", path, err)
	}

	// If fully resolved relative path begins with ".." it is not a subpath of our working directory
	if strings.HasPrefix(rel, ".."+string(filepath.Separator)) || rel == ".." {
		return "", fmt.Errorf("artifact path is not a subpath of project directory: %s", path)
	}

func createZipSymlinkEntry(archive *zip.Writer, fh *zip.FileHeader) error {
	fw, err := archive.CreateHeader(fh)
	if err != nil {
		return err
	}

	link, err := os.Readlink(fh.Name)
	if err != nil {
		return err
	}

	_, err = io.WriteString(fw, link)
	return err
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
