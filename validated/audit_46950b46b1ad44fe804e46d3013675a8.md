### Title
Attacker-controlled `jsonRequest.ID` collides in `dummyHandler.savedCallbacks` map, enabling cross-user response delivery - (File: core/services/gateway/handlers/handler.dummy.go)

### Summary
`HandleJSONRPCUserMessage` derives `msg.Body.MessageId` directly from the caller-supplied `jsonRequest.ID` with no uniqueness enforcement, and this value is used as the sole key into the shared `savedCallbacks` map in `HandleLegacyUserMessage`. Two concurrent requests (from different users) with the same `ID` collide in the map, so the callback registered by the first request can be overwritten and the eventual node response can be delivered to the wrong caller.

### Finding Description
The request flow is: `gateway.ProcessRequest` (`core/services/gateway/gateway.go`, calling `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` at line 272) → `dummyHandler.HandleJSONRPCUserMessage` [1](#0-0)  → `HandleLegacyUserMessage` which stores the callback keyed by `msg.Body.MessageId`: [2](#0-1) 

`jsonRequest.ID` is fully attacker-controlled input from the HTTP request body (only length-bounded to 200 chars in `gateway.go` line 228), and it is copied verbatim into `msg.Body.MessageId` without any randomization, per-caller namespacing, or nonce binding: [3](#0-2) 

If two different, unrelated callers (either two attackers, or an attacker and a victim whose client happens to reuse an ID such as `"1"`, a common default for JSON-RPC clients) submit requests with the same `ID` concurrently, the second `d.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` assignment overwrites the first entry in the shared map. When the DON node eventually responds (echoing the same `ID` back as `resp.ID`), `HandleNodeMessage` looks up the callback purely by that colliding key: [4](#0-3) 

The `nodeAddr != msg.Body.Sender` check only verifies that the *node* that produced the response is a legitimate signer of that particular response payload — it does nothing to verify that the response corresponds to the specific *user session/request* that originally registered the callback. Because the map key is the sole request-binding mechanism and it is entirely attacker-influenced, whichever caller's registration currently occupies that key slot receives the response, regardless of who actually issued the request that produced it. This is the same class of bug referenced for the capabilities handler (`core/services/gateway/handlers/capabilities/handler.go`), where request IDs are used as map keys for callback routing.

### Impact Explanation
This is a cross-user response confusion / request-binding bypass: an attacker who can send two overlapping requests with a chosen `ID` (or race a victim's naturally-colliding default ID) can receive a response payload intended for another user's request, or cause the legitimate user's callback to be silently dropped/hijacked. Depending on what `dummy`-routed workflows carry (arbitrary JSON-RPC payloads forwarded to DON members), this can leak response data belonging to another user's request to the attacker — matching the "cross-user response confusion" bounty impact class explicitly called out in the prompt.

### Likelihood Explanation
Precondition: the attacker only needs to be an ordinary (even rate-limited) gateway user able to POST JSON-RPC requests through the gateway's public user HTTP endpoint (`gateway.ProcessRequest`), and must be able to cause a request-ID collision — either by controlling both requests, or by racing a victim who uses a colliding default ID (many simple JSON-RPC clients start IDs at `"1"`). No node/operator/admin privileges are required. The race window is the time between the request being forwarded to the DON and the node's response returning, which is realistically exploitable by an attacker who can send requests in a tight loop. This is repeatable and does not depend on any misconfiguration, mock, or test-only code.

### Recommendation
Do not use the raw, user-supplied `jsonRequest.ID` as the sole map key for callback routing. Generate a server-side unique request/message ID (e.g., UUID) per request, keep a strict mapping from the internal unique ID to the caller's own `jsonRequest.ID` for the purpose of formatting the JSON-RPC response back to that caller, and bind/verify caller identity across the round trip so that a colliding attacker-chosen `ID` cannot overwrite another in-flight caller's entry in `savedCallbacks`. Alternatively, key `savedCallbacks` by a composite of the internal unique message ID plus the callback identity, and reject/rename on collision rather than silently overwriting.

### Proof of Concept
Go unit test plan (analogous to the capabilities handler's collision test):
1. Construct a `dummyHandler` with a fake `DON` (mock `SendToNode`) and a `DONConfig` with one member.
2. Simulate "User A": build `jsonrpc.Request[json.RawMessage]{ID: "1", Method: "dummy", Params: <A's params>}`, call `HandleJSONRPCUserMessage` with `callbackA` (a `handlerscommon.NewCallback()`), assert `d.savedCallbacks["1"].Callback == callbackA`.
3. Simulate "User B" concurrently (or immediately after, before A's response arrives): build `jsonrpc.Request[json.RawMessage]{ID: "1", Method: "dummy", Params: <B's params>}`, call `HandleJSONRPCUserMessage` with `callbackB`. Assert `d.savedCallbacks["1"].Callback == callbackB` (i.e., A's entry was overwritten).
4. Simulate the DON node responding with `resp.ID = "1"` and a validly signed `msg.Body.Sender` matching `nodeAddr`, corresponding to the payload that was actually sent for User A's request (or any single response). Call `HandleNodeMessage`.
5. Assert that `callbackB.Wait(ctx)` (User B) receives the response — even though the response was semantically produced for User A's request — proving cross-user delivery, while `callbackA.Wait(ctx)` never resolves (times out), proving A's original request was silently dropped/hijacked.

func (d *dummyHandler) HandleJSONRPCUserMessage(ctx context.Context, jsonRequest jsonrpc.Request[json.RawMessage], callback Callback) error {
	var msg api.Message
	if jsonRequest.Params != nil {
		if err := json.Unmarshal(*jsonRequest.Params, &msg); err != nil {
			return err
		}
	}
	msg.Body.MessageId = jsonRequest.ID
	if msg.Body.Method == "" {
		msg.Body.Method = jsonRequest.Method
	}
	if msg.Body.DonId == "" {
		msg.Body.DonId = d.donConfig.DonId
	}
	return d.HandleLegacyUserMessage(ctx, &msg, callback)
}

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageId]
	delete(d.savedCallbacks, msg.Body.MessageId)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil
