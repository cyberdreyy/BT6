## Title
Unauthenticated Pipeline-Run "Resume" Endpoint Trusts Attacker-Supplied Completion Data Without Verifying the Async Task Actually Ran - (File: core/web/pipeline_runs_controller.go)

### Summary
`PipelineRunsController.Resume` accepts a bare task UUID and an arbitrary JSON body and immediately feeds that body into the pipeline as the "result" of an async external-adapter callback, with no authentication and no verification that the corresponding bridge task was ever contacted or completed. This mirrors the reported `onERC721Received()` pattern: a function meant to confirm that an external action (an NFT transfer / an external-adapter response) actually happened is instead treated as authoritative simply because it was called, letting any caller who knows (or guesses/leaks) the task UUID fabricate the completion of that action.

### Finding Description
Async bridge tasks embed a callback URL of the form `/v2/resume/<taskUUID>` that the external adapter is expected to call once it has finished its work: [1](#0-0) 

That endpoint is served by `PipelineRunsController.Resume`, which parses the `runID` path parameter as a UUID, decodes an arbitrary JSON body into a `pipeline.ResumeRequest`, and calls `App.ResumeJobV2` directly — there is no check of a shared secret, HMAC, signature, or any proof that the request actually originates from the bridge/adapter that was contacted for that task: [2](#0-1) 

`ResumeJobV2` forwards straight into the pipeline runner: [3](#0-2) 

`ResumeRun` then updates the task's stored result and, if it was the last pending task, restarts the pipeline immediately using that attacker-controlled value: [4](#0-3) 

The audit event fired on this path is literally named `UnauthedRunResumed`, confirming this route is intentionally reachable without a logged-in session or any other credential: [5](#0-4) 

The only "authentication" is the unguessability of the `taskID` UUID — there is no cryptographic binding between the resume payload and the original outgoing bridge request (no signature over the response, no verification that the external adapter that received the async request is the one calling back). This is the same root-cause class as the reported bug: a "confirmation" callback (`onERC721Received` / `/v2/resume/:id`) is trusted to prove an external action occurred, when in fact anyone able to invoke the callback can fabricate that confirmation.

### Impact Explanation
If a task UUID is disclosed (e.g., via logs, error messages, a compromised/malicious external adapter endpoint that is passed the `responseURL`, or a UUID leak/timing side channel), an unprivileged remote actor can inject arbitrary pipeline results into a suspended job run. Because pipeline results can feed downstream tasks (e.g., `ethtx`/`vrf`/`ocr` transaction-construction tasks), this can let an attacker steer a job run toward attacker-chosen values or force early completion of a run whose external-adapter action never actually happened — directly analogous to the Lien being marked "repaid" without the NFT being transferred.

### Likelihood Explanation
Exploitation requires knowledge of the specific task UUID, which is not trivial to guess (UUIDv4-style values), so this is not as broadly exploitable as a fully public endpoint. However, the UUID is sent in plaintext to a third-party external adapter/bridge over the `responseURL` field, so any adapter operator, a network intermediary observing that outbound call, or a leak of adapter logs is sufficient to obtain a valid task ID and forge a "resume" call — no additional secret is required.

### Recommendation
Bind the resume callback to the original outgoing request cryptographically (e.g., an HMAC over the task ID using a secret only the node and the intended external adapter possess, or a per-task bearer token generated at dispatch time and validated in `Resume`), rather than relying solely on the UUID's unguessability. Additionally, verify the task is actually in a "pending/awaiting external response" state before accepting the resume payload, and never mark it as a "confirmed" completion when it did not carry a validated authenticator.

### Proof of Concept
1. Configure a webhook/bridge async task; the node sends the external adapter a request whose body includes `responseURL: "http://<node>/v2/resume/<taskUUID>"` [1](#0-0) .
2. Because the URL (and thus `taskUUID`) is transmitted to/through the external adapter's infrastructure, an operator of that adapter (or anyone who intercepts/leaks the URL) obtains the UUID without needing any Chainlink node credentials.
3. That party sends `PATCH /v2/jobs/<jobID>/runs/<taskUUID>` (or the `/v2/resume/<taskUUID>` route) with a forged JSON body of their choosing, before or instead of the legitimate adapter response.
4. `PipelineRunsController.Resume` accepts the request with no authentication check, decodes the body, and calls `ResumeJobV2` → `ResumeRun`, which stores the forged value as the task's result and resumes the pipeline as if the external action had genuinely completed [6](#0-5) [4](#0-3) .

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
