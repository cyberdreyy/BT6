### Title
Fee-on-transfer underlying inflates strategy token supply and tranche NAV, enabling theft from later withdrawers - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The credit vault's tranche-mint path is correctly balance-delta based (`_contractTokenBalance(_token) - _preBal`), so a fee-on-transfer token does not over-mint tranche shares. However, the strategy leg is not: `IdleCDOCreditVault._deposit` forwards the *nominal* `_amount` to `IIdleCDOStrategy(strategy).deposit(_amount)`, and `IdleCreditVault.deposit` mints `_amount` strategy tokens after `safeTransferFrom` without measuring what it actually received. With a fee-on-transfer underlying, the vault receives less than `_amount` while minting `_amount` strategy tokens, permanently inflating `getContractValue` and tranche prices. Any holder (including the depositor) can then withdraw at the inflated price, draining value belonging to remaining LPs.

### Finding Description
`IdleCDOCreditVault._deposit` measures received underlying for share minting but forwards the unadjusted `_amount` to the strategy: [1](#0-0) 

`IdleCreditVault.deposit` then pulls `_amount` from the CDO and mints exactly `_amount` strategy tokens to it, 1:1: [2](#0-1) 

For a token charging fee `f` per transfer, on a user deposit of `A`:
- CDO receives `A·(1−f)`; attacker is minted shares for only `A·(1−f)` (correct).
- Strategy pulls `A` from the CDO (the missing `A·f` comes out of the CDO's unlent buffer) but itself receives only `A·(1−f)` after the second transfer fee, while minting `A` strategy tokens.
- Net real assets entering the system: `A·(1−f)` in the vault, minus `A·f` drained from the CDO buffer. Net accounted assets via `getContractValue` (strategy tokens priced through `_strategyPrice()`): `A` plus a still-intact buffer that is now lower. [3](#0-2) 

The invariant `strategyToken balance ≤ redeemable underlying` is broken on every deposit. Tranche prices computed in `_updateAccounting`/`_virtualPriceAux` are therefore above true NAV, so `withdrawAA`/`withdrawBB`, epoch withdraw claims, and instant withdrawals pay out more underlying per tranche token than was ever deposited.

### Impact Explanation
Broken invariant: fair mint/burn / solvency. Each deposit books `A` of strategy assets against `A·(1−f) − (buffer leakage)` of real assets. Early withdrawers (including the depositing lender, an unprivileged KYC'd user) redeem at the inflated price and extract honest LPs' principal; the deficit socializes onto the last withdrawers, who become unpayable (insolvency). Loss magnitude is `≈ f` per unit deposited, plus the buffer drain `f·A` per deposit, accruing every deposit — unbounded over the vault lifetime.

### Likelihood Explanation
Only requires a KYC-passing lender and a fee-on-transfer token as `token`. The skim/balance checks protect share minting but nothing measures strategy-token backing. No privileged collusion needed; honest owner/manager/borrower actions (startEpoch, borrower funding) simply propagate the inflated accounting.

### Recommendation
Measure actual received amounts at every hop: in `IdleCreditVault.deposit`, snapshot `underlyingToken.balanceOf(address(this))` before/after `safeTransferFrom` and `_mint` only the delta; in `IdleCDOCreditVault._deposit`, pass the measured received amount (not `_amount`) to `strategy.deposit`, and apply the same delta accounting to `mintStrategyTokens`/`depositDuringEpoch` and borrower funding paths. Alternatively, explicitly document/revert that FoT underlyings are unsupported.

### Proof of Concept
Foundry fork sketch:

```solidity
// fork mainnet; vault = deployed IdleCDOCreditVault + IdleCreditVault
// token = FoTToken with 1% burn-on-transfer
uint256 A = 1_000_000e6;
fot.approve(address(cdo), A);

uint256 stratBefore = vault.balanceOf(address(cdo));
uint256 cdoBalBefore = fot.balanceOf(address(cdo));

cdo.depositAA(A);

// Attacker received shares for ~0.99A (correct mint),
// but strategy minted A tokens while receiving ~0.99A (1% transfer fee) —
// and pulled a full A from the CDO, draining the unlent buffer by 0.01A.
assertEq(vault.balanceOf(address(cdo)) - stratBefore, A);
assertLt(fot.balanceOf(address(vault)), A); // < A actually held

// NAV overstatement == redeemable-value shortfall
uint256 nav = cdo.getContractValue();
assertGt(nav, fot.balanceOf(address(cdo)) +
              vault.redeemableValue(vault.balanceOf(address(cdo))));

// Withdraw at inflated price: attacker/honest LPs withdraw tranche tokens,
// payout exceeds fair share; final withdrawer reverts on insufficient balance.
cdo.withdrawAA(attackerShares); // succeeds, overpays
vm.expectRevert();
cdo.withdrawBB(victimShares);   // insolvent — vault lacks backing
```
