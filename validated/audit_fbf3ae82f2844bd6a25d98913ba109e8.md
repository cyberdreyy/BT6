### Title
Operator can permanently DoS a staker's stake/commission withdrawal by setting a coin-transfer-opted-out beneficiary - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` pays out every entry in a single, shared `distribution_pool` (which holds both the staker's pending withdrawals and the operator's pending commission) in one atomic loop, using `aptos_account::deposit_coins` for each recipient. `aptos_account::deposit_coins` aborts if the recipient is unregistered for `AptosCoin` and has opted out of arbitrary coin transfers via `set_allow_direct_coin_transfers(false)`. Because an operator fully controls their own beneficiary address via `set_beneficiary_for_operator` (with no registration check), a malicious operator can set a "poisoned" beneficiary that always aborts on deposit, which permanently reverts every call to `distribute_internal` for that pool — including the staker's own withdrawal that shares the same loop.

### Finding Description
`distribute_internal` iterates the shared `distribution_pool` for the (staker, operator) staking contract: [1](#0-0) 

For each shareholder, if the recipient is the operator, it's redirected to `beneficiary_for_operator(operator)`: [2](#0-1) 

`beneficiary_for_operator` is set by the operator themselves with **no registration/reachability check** on `new_beneficiary`: [3](#0-2) 

`aptos_account::deposit_coins` (invoked here as `deposit_coins`) aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is not registered for the coin type and has opted out via `DirectTransferConfig`: [4](#0-3) [5](#0-4) 

An operator can create an account they control, never register it for `AptosCoin`, and call `set_allow_direct_coin_transfers(false)` on it — a completely permissionless, self-serve action requiring no special role. They then set this address as their beneficiary via `set_beneficiary_for_operator`. From that point on, whenever the pool has any accumulated commission (`commission_amount > 0`), `request_commission_internal` adds the operator as a shareholder in the *same* `distribution_pool` used for staker withdrawals: [6](#0-5) 

Because `unlock_stake`, `unlock_rewards`, and `switch_operator` all call `distribute_internal` before processing the staker's own request (to flush already-inactive stake), and `distribute_internal`'s `while` loop processes all shareholders atomically with no per-recipient error isolation (there is no Move analog of Solidity's `try/catch`), a single failing `deposit_coins` call for the poisoned beneficiary aborts the *entire* transaction — including the staker's legitimate withdrawal in the same call: [7](#0-6) 

This mirrors the H-11 pattern precisely: an external/attacker-controlled payout target that always reverts on receipt, invoked inside a loop with no isolation, blocks legitimate unrelated parties from completing their operation.

### Impact Explanation
Once the operator's beneficiary is poisoned, `distribute`, `unlock_stake`, `unlock_rewards`, and `switch_operator` for that staking contract will **permanently abort** as long as there is any unpaid commission owed to the operator (which recurs any time the pool earns further rewards). This traps the staker's principal and rewards indefinitely, since `distribute_internal` is the only mechanism to release pending_inactive/inactive stake back to the staker and it can never succeed. This is a permanent, non-recoverable loss of claim rights over stake and rewards for the staker — squarely within the required "Permanent lock or non-recoverable loss of claim rights in stake ... beneficiary ... flows" impact category, and reachable by an operator, who is an unprivileged party relative to the staker's funds.

### Likelihood Explanation
High. Setting up a poisoned beneficiary requires only standard, permissionless account operations (`account::create_account`-style account creation and `set_allow_direct_coin_transfers(false)`) that any operator can perform on an address they control, with no cost beyond a small amount of gas, and no cooperation or special privilege needed. The operator role itself is commonly delegated/unprivileged relative to the staker's principal.

### Recommendation
- Isolate payout failures per-recipient in `distribute_internal` (e.g., skip/requeue a failing recipient's distribution instead of aborting the whole loop), or
- Validate that `new_beneficiary` in `set_beneficiary_for_operator` is registered/able to receive `AptosCoin` at set-time (as `vesting::set_beneficiary` already does via `assert_account_is_registered_for_apt`), and additionally guard against later opt-out via `set_allow_direct_coin_transfers` breaking previously-valid recipients, or
- Route commission payouts to a pull-based claim balance instead of a push (`deposit_coins`) inside a loop shared with unrelated stakeholders.

### Proof of Concept
1. Operator `O` creates account `B` (an address they control) without registering it for `AptosCoin`.
2. As `B`, call `aptos_account::set_allow_direct_coin_transfers(false)` — succeeds, no registration required: [8](#0-7) 
3. `O` calls `staking_contract::set_beneficiary_for_operator(O, B)` — succeeds with no reachability validation on `B`: [3](#0-2) 
4. Stake pool accrues rewards (epoch advances), giving `O` a nonzero commission.
5. Staker `S` calls `unlock_stake(S, O, amount)`. Internally this calls `distribute_internal`, which processes `O`'s commission distribution and attempts `aptos_account::deposit_coins(B, commission_coins)`.
6. Because `B` is unregistered for `AptosCoin` and has `allow_arbitrary_coin_transfers = false`, `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
7. The entire `unlock_stake` transaction reverts — `S`'s legitimate withdrawal never completes, and this repeats for every future call to `distribute`/`unlock_stake`/`unlock_rewards`/`switch_operator` on this pool as long as `O` maintains this beneficiary configuration.

Note: I was not able to fully trace `pool_u64::buy_in` behavior for a zero-amount commission edge case (whether a zero-commission buy-in still registers the operator as a shareholder) within the available index; this doesn't affect the core finding since any nonzero commission accrual triggers the described abort.

    /// Staker can call this to request withdrawal of part or all of their staking_contract.
    /// This also triggers paying commission to the operator for accounting simplicity.
    public entry fun unlock_stake(
        staker: &signer, operator: address, amount: u64
    ) acquires Store, BeneficiaryForOperator {
        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

        // Request to unlock the distribution amount from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
