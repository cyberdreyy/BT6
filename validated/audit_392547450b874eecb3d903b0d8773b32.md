### Title
Unsynchronized `savedCallbacks` overwrite allows attacker-chosen MessageId collision to hijack another user's gateway response - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores a `savedCallback` keyed only by the attacker-controlled `MessageId` field with no check for an existing entry, and `pruneCallbacks` only evicts entries after `CallbackMaxAgeSec`/count thresholds. This allows an attacker to submit a message whose `MessageId` collides with a victim's pending request (or vice-versa), silently overwriting the map entry so a legitimate node response gets delivered to the wrong caller's callback.

### Finding Description
`HandleLegacyUserMessage` unconditionally writes to the map without checking for a pre-existing unresolved entry: [1](#0-0) 

`MessageId` is part of `MessageBody`, validated only for length/null-suffix, not uniqueness or ownership, in `Message.Validate()`: [2](#0-1) 

Nothing ties `MessageId` to the sender's signing key — the signature covers `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload`, but any signer (attacker with their own valid keypair) can freely choose the `MessageId` string themselves, since `Sign`/`SignKS` just sign whatever `MessageId` is already set in the body: [3](#0-2) 

Because `HandleLegacyUserMessage` does not check whether `msg.Body.MessageId` is already present in `h.savedCallbacks` before overwriting, a second (attacker or victim) message reusing the same `MessageId` as an earlier still-pending message simply replaces the stored `Callback` for that ID: [4](#0-3) 

When a node eventually responds via `MethodWebAPITrigger`, `handleWebAPITriggerMessage` looks up the callback purely by `MessageId`, deletes it, and delivers the response to whichever `Callback` currently occupies that slot — not necessarily the one that originated the still-in-flight request to the DON: [5](#0-4) 

Exploit flow: an attacker sends `HandleLegacyUserMessage` with `MessageId = X` (any legally-signed message, since the attacker can sign with their own key and choose any `MessageId`). The DON is asked to process it. Before the DON's response for `X` arrives, and before `pruneCallbacks` runs (default interval 30s, default max-age 120s per `defaultCallbackPruneIntervalSec`/`defaultCallbackMaxAgeSec`), a victim's legitimate/independent request happens to reuse (or is made to reuse, e.g. via a caller-suppliable nonce/timestamp-derived ID in the client scripts) the same `MessageId = X`. The map entry for `X` is overwritten with the victim's `Callback`. When the *original* (attacker's) DON response for `X` arrives, it is delivered to the victim's callback (data leak of the node's response body/headers to an unintended callback context) — or, conversely, if the victim's request was saved first and the attacker overwrites it, the victim's DON response is delivered to the attacker's connection, exposing the DON's response payload (which may include the target URL's raw HTTP response body, headers) to the attacker. [6](#0-5) 

No component in this path verifies MessageId ownership/uniqueness before insertion; the only mitigation, `pruneCallbacks`, runs periodically and does not prevent same-window collisions: [7](#0-6) 

### Impact Explanation
This is a cross-user response/data misdelivery: an unauthenticated (or low-privilege, self-authenticated) gateway client can, through simple MessageId collision (accidental or deliberately targeted if IDs are predictable/observable, e.g., timestamp/sequence-based client generation), cause the gateway to route another user's HTTP-callback response — which may contain sensitive computed values or webhook data returned by the DON's HTTP trigger flow — to itself, or vice versa disrupt/misdeliver a victim's request outcome. This falls under the "cross-user response confusion" / unauthorized disclosure-of-response-data class, and also contributes to unbounded memory growth (`defaultMaxSavedCallbacks = 20000`, "could briefly exceed under heavy load") since eviction is best-effort and time/count based rather than immediate.

### Likelihood Explanation
Exploitability requires only reachability to the gateway's legacy user-message endpoint with any valid signature (any attacker-controlled keypair suffices — no special authorization is enforced on `MessageId` selection) and knowledge/guessing of a MessageId that will be reused within the prune window (up to ~150s combined age+interval by default). If client-side MessageId generation is low-entropy or predictable (e.g., timestamp-based, as commonly done in JSON-RPC-style clients), collision is trivially forced by an attacker submitting many candidate MessageIds in that window. This is a self-contained repeatable condition, not dependent on operator misconfiguration.

### Recommendation
In `HandleLegacyUserMessage`, check `h.savedCallbacks` for an existing, non-expired entry under the incoming `MessageId` before inserting; reject (return an error response to the caller) instead of silently overwriting. Additionally, consider deriving/validating uniqueness by binding `MessageId` to `Sender`+`MessageId` composite keys, or rejecting duplicate MessageIds regardless of sender, and shrinking the prune window / doing prune-on-insert checks to close the collision race.

### Proof of Concept
Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct `handler` with mocked `don` and `httpClient`.
2. Call `HandleLegacyUserMessage` with a signed message from "attacker" key, `MessageId = "X"`, capturing the mock `Callback` (`callbackA`) passed to it — do not resolve it (simulate DON never responding).
3. Immediately call `HandleLegacyUserMessage` again with a signed message from "victim" key, same `MessageId = "X"`, with a different mock `Callback` (`callbackB`).
4. Assert: the second call returns an error (expected fix), and `h.savedCallbacks["X"].Callback` still equals `callbackA` (current buggy behavior: assert it was overwritten to `callbackB`, demonstrating the flaw).
5. Simulate a `HandleNodeMessage` response for `MessageId = "X"` (attacker's original outstanding request) and assert it is delivered to `callbackB` (victim's callback) instead of `callbackA`, proving cross-callback misdelivery.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

// Message signatures are over the following data:
//  1. MessageId aligned to 128 bytes
//  2. Method aligned to 64 bytes
//  3. DonId aligned to 64 bytes
//  4. Receiver (in hex) aligned to 42 bytes
//  5. Payload (raw bytes before parsing)
func (m *Message) Sign(privateKey *ecdsa.PrivateKey) error {
	if m == nil {
		return errors.New("nil message")
	}
	rawData := GetRawMessageBody(&m.Body)
	signature, err := gw_common.SignData(privateKey, rawData...)
	if err != nil {
		return err
	}
	m.Signature = utils.StringToHex(string(signature))
	m.Body.Sender = strings.ToLower(crypto.PubkeyToAddress(privateKey.PublicKey).Hex())
	return nil
}
