### Title
Front-running/squatting `LockupFactory::create` lets an unprivileged attacker deploy a victim's lockup with an attacker-controlled `staking_pool_whitelist_account_id` - ([File: lockup-factory/src/lib.rs])

### Summary
`LockupFactory::create` derives the lockup's account id deterministically from `owner_account_id` alone and performs no check that `predecessor_account_id == owner_account_id` or that the caller is the foundation. Any unprivileged account can therefore call `create(owner_account_id = "victim.near", ..., whitelist_account_id = Some("fake_whitelist.near"))`, attach the minimum deposit, and deploy the victim's lockup contract with a whitelist account the attacker owns and controls.

### Finding Description
Binding claimed: `LockupArgs.staking_pool_whitelist_account_id` (deployed) == `self.whitelist_account_id` (factory's own value set at `LockupFactory::new`) for any owner who did not choose their own whitelist. In code:

```
let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
    account_id.into()
} else {
    self.whitelist_account_id.clone()
};
``` [1](#0-0) 

`create` takes `whitelist_account_id: Option<ValidAccountId>` as a plain function argument supplied by whoever calls it — not restricted to the owner or the foundation — and if `Some(...)`, that value is used verbatim as `staking_pool_whitelist_account_id` in the `LockupArgs` sent to the newly-created lockup account: [2](#0-1) 

Critically, the lockup account id is deterministic and depends only on `owner_account_id`, not on the caller:
```
let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
let lockup_account_id = format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());
``` [3](#0-2) 

There is no `assert_called_by_foundation`, no `assert_eq!(env::predecessor_account_id(), owner_account_id)`, and no other access-control check in `create`. The only guard is `assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, ...)` [4](#0-3) , which just requires the attacker to fund the ~3.5 NEAR storage deposit — a cost, not a permission check.

Exploit flow: the attacker deploys/controls `fake_whitelist.near` (a contract that always returns `true` from `is_whitelisted`), then calls `LockupFactory::create(owner_account_id = "victim.near", ..., whitelist_account_id = Some("fake_whitelist.near"))` with the minimum deposit before the legitimate deployer (foundation/victim) does so. Because `Promise::new(lockup_account_id).create_account()` fails if the account already exists, the attacker's call — being first — squats the deterministic lockup address for `victim.near`. The deployed `LockupArgs.staking_pool_whitelist_account_id` field permanently equals `fake_whitelist.near`, not the factory's `whitelist_account_id`. Later, `lockup/src/owner.rs`'s `select_staking_pool` (and related logic) validate a chosen staking pool by cross-contract call to `staking_pool_whitelist_account_id.is_whitelisted(...)` — since the attacker controls that contract, any pool the attacker names will pass the check, and once the lockup (funded, e.g., by the foundation depositing the victim's vested tokens to this deterministic address) delegates there, the attacker's pool can withdraw/drain the delegated NEAR.

Existing guards (`assert_self`, `is_promise_success`, `MIN_ATTACHED_BALANCE` check) do not address caller identity vs. `owner_account_id`, so none of them prevent this.

### Impact Explanation
This is a Critical-severity finding under the stated categories: "a lockup deployed with parameters its rightful creator never chose." The victim's lockup account is created with an attacker-chosen whitelist contract instead of the factory's legitimate whitelist, letting the attacker later get any staking pool whitelisted for that specific victim lockup and potentially divert delegated NEAR that flows into that pool. The attack is repeatable for any `owner_account_id` value the attacker wants to squat, as long as they win the race to create the account first (limited only by attaching ~3.5 NEAR and calling before the legitimate creator).

### Likelihood Explanation
Preconditions: attacker needs only ~3.5 NEAR (`MIN_ATTACHED_BALANCE`) and to call `create` before the legitimate lockup for that `owner_account_id` is deployed — a public, permissionless, low-cost transaction. No special role, key, or foundation access is required. The main practical constraint is winning the race against the legitimate/foundation deployment, which is a front-running/squatting scenario rather than requiring any privilege, so likelihood is high for any owner account whose lockup has not yet been created.

### Recommendation
Restrict `create` so that either (a) only the foundation (`assert_called_by_foundation`-style check against `self.foundation_account_id`) may call it, or (b) require `env::predecessor_account_id() == owner_account_id.as_ref()` when no foundation-level caller is enforced, and/or disallow attacker-supplied `whitelist_account_id` entirely unless the caller is verified to be the owner/foundation.

### Proof of Concept
```rust
// lockup-factory/src/tests (extend existing test module)
#[test]
fn test_attacker_squats_victim_lockup_with_fake_whitelist() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());

    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    let lockup_duration: WrappedTimestamp = 63036000000000000u64.into();

    // Attacker (not victim, not foundation) calls create() naming victim as owner
    // and their own fake whitelist contract.
    context.is_view = false;
    context.predecessor_account_id = String::from("attacker.near"); // unrelated caller
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());

    let promise = contract.create(
        ValidAccountId::try_from("victim.near").unwrap(), // owner_account_id = victim
        lockup_duration,
        None,
        None,
        None,
        Some(ValidAccountId::try_from("fake_whitelist.near").unwrap()), // attacker-controlled whitelist
    );

    // Assert: the serialized LockupArgs function_call in `promise`
    // (inspect via the mocked receipts / VMLogic outcome) has
    // staking_pool_whitelist_account_id == "fake_whitelist.near"
    // and NOT contract.whitelist_account_id (== whitelist_account_id()).
    // This demonstrates staking_pool_whitelist_account_id != self.whitelist_account_id,
    // breaking the claimed binding, for a lockup whose owner ("victim.near")
    // never authorized/chose a custom whitelist.
}
```
Both sides of the binding diverge: `LockupArgs.staking_pool_whitelist_account_id == "fake_whitelist.near"` while `contract.whitelist_account_id == "whitelist_account_id()"` (the factory default), confirming the violation.

```rust
    #[payable]
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }
```
