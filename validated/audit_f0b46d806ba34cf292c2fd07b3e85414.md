### Title
Unprocessed dust queue deposit blocks prefunded epoch settlement - (File: `contracts/IdleCDOEpochVariantPrefunded.sol`)

### Summary
A KYC-passing lender can submit a minimal queued deposit immediately before the prefunding cutoff and deliberately leave it unprocessed. After the cutoff, the deposit can no longer be forwarded to the borrower, while prefunded settlement still reverts on any raw pending deposit for the epoch being stopped. Every `stopEpochWithDuration` call therefore reverts, freezing epoch settlement and withdrawals until the attacker removes the request or the owner disables the queue. [1](#0-0) [2](#0-1) 

### Finding Description
`requestDeposit` records the deposit against `strategy.epochNumber() + 1` and increases `epochPendingDeposits`, while the prefunded AA queue rejects new deposits only after the configured cutoff or after prefunding has already occurred. [1](#0-0) 

`processDepositsToBorrower` is the only path that converts raw queued deposits into prefunded deposits, but it cannot be called once `block.timestamp + prefundedDepositWindow >= epochEndDate`. [3](#0-2) 

The ordinary `processDeposits` path is explicitly disabled when the queue is configured as the prefunded queue. [4](#0-3) 

After a successful or defaulted stop, `IdleCDOEpochVariantPrefunded._afterStopEpochWithDuration` always calls `prefundedDepositsToProcess`, which reverts whenever `epochPendingDeposits` for the just-finished epoch is nonzero. [5](#0-4) [2](#0-1) 

Because `stopEpochWithDuration` executes the hook inside the same transaction, the revert also rolls back the base epoch-settlement changes. A configured queue also blocks the direct `stopEpoch` selector, so the manager cannot bypass the hook through that function. [6](#0-5) [7](#0-6) 

Only the requesting user can remove the stale deposit through `deleteRequest`; a manager cannot clear another user's `userDepositsEpochs` entry. [8](#0-7) 

### Impact Explanation
One unit of underlying can indefinitely prevent the pool from stopping the epoch and settling active NAV, borrower repayments, pending withdrawals, and future deposit/withdrawal requests.

The freeze persists until the attacker voluntarily calls `deleteRequest` or the owner changes `epochQueue` to another value. Disabling the queue is safe in this specific attack path because raw pending deposits and prefunded deposits are mutually exclusive for an epoch, but it is still an emergency configuration action rather than normal settlement. [9](#0-8) [10](#0-9) 

The quantified impact is temporary freezing of the full unsettled pool balance for a cost of one underlying unit plus transaction fees.

### Likelihood Explanation
The attacker needs only a wallet that passes `isWalletAllowed` and one unit of underlying; no privileged role, borrower control, token defect, oracle manipulation, or default is required. [11](#0-10) 

The attack succeeds when the attacker places the dust deposit in the last block that still satisfies the prefunding cutoff and the manager does not include it in `processDepositsToBorrower` in that same block. Transaction ordering makes this practical near the cutoff, although an operator that reliably prefunds every queued deposit before the cutoff prevents the condition.

### Recommendation
Do not let stale, queue-held deposits gate settlement of a separate prefunded deposit bucket.

- Remove the `epochPendingDeposits[_epoch] != 0` revert from `prefundedDepositsToProcess`, or return both prefunded and raw-pending amounts so the stop flow can settle the prefunded bucket while leaving raw deposits refundable.
- Allow a permissionless cleanup of raw pending deposits after the cutoff, while still returning funds only to each depositor.
- Require `block.timestamp < epochEndDate` for `requestDeposit`, even when `prefundedDepositWindow == 0`.
- Treat prefunding as a required settlement checkpoint and monitor the final allowed block so no pending deposit can remain unprocessed.

### Proof of Concept
The following test assumes the existing prefunded-queue Foundry fixture where `cdoEpoch` is `IdleCDOEpochVariantPrefunded`, `queue` is configured through `setEpochQueue`, `manager` controls both contracts, and `attacker` is wallet-allowed:

```solidity
function testDustQueuedDepositBlocksPrefundedStopEpoch() external {
    uint256 window = 1 days;
    vm.prank(manager);
    queue.setPrefundedDepositWindow(window);

    // Current epoch is running and the attacker submits the minimum nonzero deposit.
    assertTrue(cdoEpoch.isEpochRunning());
    uint256 endDate = cdoEpoch.epochEndDate();
    vm.warp(endDate - window - 1);

    uint256 targetEpoch = strategy.epochNumber() + 1;
    deal(address(underlying), attacker, 1, true);

    vm.startPrank(attacker);
    underlying.approve(address(queue), 1);
    queue.requestDeposit(1);
    vm.stopPrank();

    assertEq(queue.epochPendingDeposits(targetEpoch), 1);

    // After the cutoff, neither processDeposits nor processDepositsToBorrower can clear it.
    vm.warp(endDate + 1);

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    queue.processDepositsToBorrower();

    // The hook reverts after the base stop flow, rolling back the entire settlement.
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpochWithDuration(0, 0, cdoEpoch.epochDuration(), 0);

    assertTrue(cdoEpoch.isEpochRunning());
    assertEq(queue.epochPendingDeposits(targetEpoch), 1);

    // The manager cannot delete the attacker's request.
    vm.prank(manager);
    queue.deleteRequest(targetEpoch);
    assertEq(queue.epochPendingDeposits(targetEpoch), 1);

    // Settlement remains blocked on retry.
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpochWithDuration(0, 0, cdoEpoch.epochDuration(), 0);
}
```

  function processDepositsToBorrower() external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    IdleCreditVault _strategy = IdleCreditVault(strategy);
    // only owner or strategy manager can move queued funds to the borrower
    _checkOnlyOwnerOrManager();
    // prefunded flow is supported only for AA queue
    // queue must be explicitly enabled on the prefunded CDO variant
    _checkNotAllowed(tranche != _cdo.AATranche() || !_isPrefundedQueueEnabled());

    // prefunding can be done only while epoch is running
    if (!_cdo.isEpochRunning()) {
      revert EpochNotRunning();
    }
    // Keep prefunding aligned with the same cutoff enforced for new queued deposits.
    uint256 _prefundedWindow = prefundedDepositWindow;
    _checkNotAllowed(_prefundedWindow == 0 || block.timestamp + _prefundedWindow < _cdo.epochEndDate());

    uint256 _epoch = _strategy.epochNumber() + 1;
    // prefunding can happen only once for an epoch
    _checkNotAllowed(epochPrefundedDeposits[_epoch] != 0);
    uint256 _pending = epochPendingDeposits[_epoch];
    if (_pending == 0) {
      return;
    }
    // Recheck after the cutoff because emergency state or the TVL limit can change while queued.
    IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(_pending);

    // Switch the epoch from "queue-held" to "already at borrower" before transferring funds.
    epochPendingDeposits[_epoch] = 0;
    epochPrefundedDeposits[_epoch] = _pending;
    IERC20Detailed(underlying).safeTransfer(_strategy.borrower(), _pending);

  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);

  function _afterStopEpochWithDuration() internal override {
    address _queue = epochQueue;
    if (_queue == address(0)) return;

    IIdleCDOEpochQueuePrefunded _epochQueue = IIdleCDOEpochQueuePrefunded(_queue);
    uint256 _prefunded = _epochQueue.prefundedDepositsToProcess();
    if (_prefunded == 0) return;
    // A zero post-loss AA price cannot safely mint new shares into the same tranche token.
    _checkNotAllowed(priceAA == 0);

    // Prefunded deposits already reached the borrower, so they must join AA even if stop defaulted.
    // Mint tranche shares at the post-stop price and mirror the same amount in strategy tokens,
    // so the queue can later distribute shares to users at the epoch price.
    uint256 _prefundedMinted = _mintSharesAtCurrPrice(_prefunded, _queue, AATranche);
    IdleCreditVault(strategy).mintStrategyTokens(_prefunded);
    // Finalize the prefunded epoch in the queue by storing the epoch price and clearing state.
    _epochQueue.processPrefundedDeposits(_prefundedMinted);
