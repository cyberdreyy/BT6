### Title
Unauthenticated-role pprof debug endpoints reachable by any authenticated low-privilege (view/run) user - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` registers all `net/http/pprof` handlers (`/v2/debug/pprof/*`) inside the `authv2` group, which only requires `auth.Authenticate` (session or API token) with no role check. Unlike every other sensitive endpoint in the same group, these routes are not wrapped in `auth.RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole`, so any valid session or API token — including one with `UserRoleView` — can dump goroutine stacks, heap profiles, and CPU/execution traces of the node process.

### Finding Description
`v2Routes` builds `authv2 := r.Group("/v2", auth.Authenticate(...))` [1](#0-0)  and every route within it that returns sensitive data or performs sensitive actions is explicitly wrapped with a role check, e.g. `auth.RequiresAdminRole(ekc.Delete)` or `auth.RequiresEditRole(jc.Create)` [2](#0-1) . However, at the end of the group, `metricRoutes(authv2)` is called directly with no per-route role wrapper [3](#0-2) , and `metricRoutes` itself registers the raw `net/http/pprof` handlers (`/debug/pprof/`, `/heap`, `/goroutine`, `/profile`, `/trace`, `/allocs`, `/block`, `/mutex`, `/threadcreate`, `/cmdline`, `/symbol`) with only the group's base authentication [4](#0-3) .

`auth.Authenticate` only validates that the requester has a valid session/API token; it does not check role — that check is deliberately delegated to wrapper functions `RequiresRunRole`, `RequiresEditRole`, and `RequiresAdminRole`, which explicitly reject `UserRoleView` (and further restrict `UserRoleRun`) [5](#0-4) . Since `metricRoutes` routes have none of these wrappers, a session/token belonging to a `UserRoleView` user passes `auth.Authenticate` and reaches the pprof handler directly, with no subsequent role gate.

### Impact Explanation
Heap and goroutine dumps from a running Go process can contain in-memory secrets (private keys, session tokens, decrypted config values, DB credentials) captured incidentally in memory, and `/debug/pprof/profile` and `/debug/pprof/trace` can be used to induce sustained CPU sampling load. A low-privilege `UserRoleView` account (the least-trusted operator-created role, or any restricted API token issued with view-only intent) can retrieve this information — an authorization/least-privilege bypass and information-disclosure vector, and a minor availability/DoS vector via repeated profile/trace requests.

### Likelihood Explanation
Exploitation requires only a valid, low-privilege authenticated session or API key — no special credentials or admin access. Any node operator that provisions `UserRoleView` accounts or view-scoped API tokens for read-only dashboards/monitoring unintentionally grants pprof access. The request is trivially reproducible (`GET /v2/debug/pprof/heap` with a view-role session cookie/token).

### Recommendation
Wrap the `metricRoutes` registration with `auth.RequiresAdminRole` (or at minimum `RequiresEditRole`), consistent with the role-based access pattern used for every other sensitive endpoint in `v2Routes`, e.g. change line 446 to register each pprof route through `auth.RequiresAdminRole(...)` or gate the whole `pprofGroup` with an admin-role middleware.

### Proof of Concept
Go handler-level integration test plan (using `httptest` + the app's `gin.Engine` from `NewRouter`):
1. Set up a test `chainlink.Application` with an authentication provider seeded with two users: `admin@example.com` (role `UserRoleAdmin`) and `viewer@example.com` (role `UserRoleView`).
2. Build router via `web.NewRouter(app, nil)`.
3. Create a session for `viewer@example.com` via `POST /sessions`, capture the session cookie.
4. Issue `GET /v2/debug/pprof/heap` (and `/v2/debug/pprof/goroutine`) with the viewer's session cookie.
5. Assert expected: `403 Forbidden` (matching behavior of other admin-protected routes like `GET /v2/keys/eth/import`).
6. Actual (vulnerable) result: `200 OK` with a valid pprof heap dump body, confirming the view-role session bypasses intended role restriction.
7. Repeat with no authentication at all to confirm `401` is still returned (proving only the role check, not the auth check, is missing).

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
