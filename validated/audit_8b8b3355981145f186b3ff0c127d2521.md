### Title
Sponsored EIP-8130 payer can be griefed out of gas fees when the sender invalidates a `calls`-phase precondition after payer signs but before inclusion - (File: `crates/common/evm/src/eip8130.rs`)

### Summary
EIP-8130 lets a `sender` submit a transaction whose `calls` are gas-sponsored by a separate `payer` (a relayer/paymaster analogous to the "bot" in the reported DCA issue). The executor explicitly documents that a reverting call phase does **not** stop the transaction from being included and billed: "the gas already consumed is still charged and the transaction is still included (nonce consumed, fee paid)" [1](#0-0) . Because `sender` — not `payer` — fully controls the on-chain state that any `calls` phase depends on (allowances, balances, policy state, etc.), the sender can unilaterally invalidate a precondition of a sponsored call after the payer has already signed off to fund it, causing the payer to pay real gas for a transaction that does nothing useful, mirroring the `execute_dca_order` frontrunning bug class.

### Finding Description
`Eip8130Executor::execute` runs pre-call authorization/nonce/fee logic, then `prepay`s the worst-case gas fee from the **payer's** balance [2](#0-1) , then dispatches `calls` via `execute_calls`, and finally `settle_fees` bills the payer for whatever gas the calls actually consumed — win or lose: [3](#0-2) 

The phase semantics are explicit: "If any call in a phase reverts (or is blocked by the policy gate), that phase's state changes are discarded and every later phase is skipped, but the gas already consumed is still charged and the transaction is still included" [1](#0-0) .

The mempool does carry a `WatchManifest`/`WatchSet` mechanism intended to drop stale sponsored transactions before they are included, but it only re-checks: the storage slots read during the **authorization** step (actor/policy config slots), the payer's balance, and expiry — not arbitrary state that a `calls` payload (e.g. a B20 `transferFrom` relying on `allowance`) depends on [4](#0-3) [5](#0-4) . The B20 precompile's `transfer_from` — the natural analog of the reported DCA `execute` call — checks `allowance` at call time and reverts with `InsufficientAllowance` if the sender/owner has reduced it [6](#0-5) , which is exactly the class of precondition the manifest's `config_slots` watch does not track (those slots come from `TransactionAuthorizer`'s authorization read-set, not from the payload of `calls`).

Because the `sender` in a sponsored transaction is a normal, unprivileged account, it can at any time — after asking a relayer/paymaster to sponsor a batch of `calls` that includes a delegated transfer, mint-with-approval flow, or any other allowance/state-gated action — submit an ordinary transaction that revokes the allowance or otherwise flips the precondition the sponsored `calls` rely on. If that ordinary transaction lands in an earlier position (front-running the sponsored tx), the sponsored tx's `calls` phase reverts on inclusion, yet the payer is still billed the full gas cost of the executed calls, per the documented "still charged and included" behavior.

### Impact Explanation
This directly disincentivizes third-party payers/relayers (paymasters, sponsors, gas-abstraction services) from sponsoring EIP-8130 transactions whose `calls` depend on sender-controlled resources, because the sender can grief them for free (the sender pays nothing; only the sponsor's gas is burned). Sponsors would either need to duplicate all of a call's runtime preconditions into the `WatchManifest`/predicate mechanism themselves (which the current `manifest.rs` implementation does not do automatically) or eat unbounded gas losses. Repeated griefing is a realistic denial-of-service/fund-loss vector against any payer that sponsors many senders' transactions, similar in kind to the original DCA bot losing gas fees, but here it is enshrined at the protocol/consensus level rather than confined to a single dApp contract.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a payer sponsoring transactions whose `calls` depend on mutable sender-controlled state (a common pattern for gasless UX/relayed ERC-20-like operations), and (b) the sender submitting a cheap ordinary transaction to flip that state before the sponsored transaction is included. Both are within reach of any unprivileged transaction sender and require no special permissions — only ordinary transaction submission and knowledge of pending sponsored transactions (visible via the txpool, same as the original mempool-frontrunning premise in the reported bug).

### Recommendation
Extend the mempool/builder-side revalidation (`WatchManifest`) to also capture and watch storage reads performed by simulating the `calls` payload itself (not just the authorization read-set), and drop/skip transactions whose call-payload preconditions have gone stale before inclusion — mirroring the existing `manifest.rs` approach used for authorization state. Alternatively/additionally, expose a protocol-level mechanism for a payer to bound its exposure per sponsored transaction (e.g., a payer-specified maximum billable gas on revert, or requiring a successful dry-run against latest state immediately before builder inclusion) so a sender-induced revert cannot fully consume the payer's worst-case gas allowance.

### Proof of Concept
1. Payer `P` agrees (off-chain, per EIP-8130 signature) to sponsor sender `S`'s EIP-8130 transaction whose `calls` phase invokes `IB20::transferFrom(from: S, to: X, amount)`, relying on an existing allowance `S -> caller` recorded at signing time.
2. `S` submits (self-paid) `IB20::approveCall { spender: caller, amount: 0 }`, landing in an earlier block/flashblock position than the sponsored EIP-8130 transaction.
3. The B20 `transfer_from` logic re-checks `allowance` at call time and reverts with `InsufficientAllowance` [7](#0-6) .
4. `WatchManifest::revalidate` does not catch this because the allowance slot was never part of the authorization read-set watched by the manifest [5](#0-4) .
5. The EIP-8130 executor still includes the sponsored transaction, charges `P` for the gas consumed by the reverted phase, and settles fees to the fee vaults/beneficiary exactly as documented [8](#0-7) , leaving `P` out of pocket with no recourse.

    /// Pre-charges the payer the worst-case fee and bumps the sender's protocol
    /// nonce, returning the amount debited. The full `gas_limit` (plus payer
    /// authentication) is reserved at the effective price — alongside the L1 and
    /// worst-case operator fee — so the `calls` cannot spend gas money; the
    /// surplus is refunded in [`Self::settle_fees`]. Also overwrites the
    /// placeholder `TxEnv` caller with the resolved sender so `tx.origin`
    /// (the `ORIGIN` opcode) reads correctly during `calls`.
    fn prepay<DB>(
        ctx: &mut BaseContext<DB>,
        outcome: &Eip8130Outcome,
        encoded: &[u8],
        spec: BaseSpecId,
    ) -> Result<U256, EVMError<DB::Error, BaseTransactionError>>
    where
        DB: AlloyDatabase,
        BaseContext<DB>:
            BaseContextTr + ContextTr<Db = DB, Tx = BaseTransaction<TxEnv>, Block = BlockEnv>,
    {
        ctx.tx.base.caller = outcome.sender;

        if outcome.bump_protocol_nonce {
            let mut sender_acc =
                ctx.journal_mut().load_account_mut(outcome.sender).map_err(EVMError::Database)?;
            sender_acc.bump_nonce();
        }

        // Worst-case chargeable gas: the full sender budget plus payer
        // authentication, both billed at the effective price.
        let max_gas = FeeCheck::max_chargeable_gas(outcome.gas_limit, outcome.payer_auth);
        let gas_charge = U256::from(max_gas)
            .checked_mul(U256::from(outcome.effective))
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 gas pre-charge overflow"))?;
        let l1_cost = ctx.chain_mut().calculate_tx_l1_cost(encoded, spec);
        let operator_cost = ctx.chain().operator_fee_charge(encoded, U256::from(max_gas), spec);
        let prepay = gas_charge
            .checked_add(l1_cost)
            .and_then(|v| v.checked_add(operator_cost))
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 pre-charge overflow"))?;

        let mut payer_acc =
            ctx.journal_mut().load_account_mut(outcome.payer).map_err(EVMError::Database)?;
        let debited = payer_acc.balance().checked_sub(prepay).ok_or_else(|| {
            EVMError::Transaction(BaseTransactionError::eip8130(
                "payer balance is below the worst-case fee",
            ))
        })?;
        payer_acc.set_balance(debited);

        Ok(prepay)
    }

    /// Settles the final fee against the pre-charged amount: caps the gas refund,
    /// computes the billable gas, refunds the surplus to the payer, and routes
    /// the base fee, priority tip, L1 cost, and operator fee to their vaults.
    /// Returns the gas used reported in the result.
    #[allow(clippy::too_many_arguments)]
    fn settle_fees<DB>(
        ctx: &mut BaseContext<DB>,
        outcome: &Eip8130Outcome,
        calls: &CallsResult,
        prepay: U256,
        encoded: &[u8],
        spec: BaseSpecId,
        beneficiary: Address,
    ) -> Result<u64, EVMError<DB::Error, BaseTransactionError>>
    where
        DB: AlloyDatabase,
        BaseContext<DB>:
            BaseContextTr + ContextTr<Db = DB, Tx = BaseTransaction<TxEnv>, Block = BlockEnv>,
    {
        // Sender-intrinsic + call gas, less the EIP-3529-capped refund, plus payer
        // authentication. Shared with the estimate path so they cannot diverge.
        let billable_gas = Self::billable_gas(outcome, calls);

        let fee = U256::from(billable_gas)
            .checked_mul(U256::from(outcome.effective))
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 fee overflow"))?;
        let base_fee_amount = U256::from(billable_gas)
            .checked_mul(U256::from(outcome.base_fee))
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 base-fee amount overflow"))?;
        let priority_amount = fee
            .checked_sub(base_fee_amount)
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 priority amount underflow"))?;
        let l1_cost = ctx.chain_mut().calculate_tx_l1_cost(encoded, spec);
        let operator_cost =
            ctx.chain().operator_fee_charge(encoded, U256::from(billable_gas), spec);

        // Refund the surplus of the worst-case pre-charge. The pre-charge bounds
        // every component above (full `gas_limit`/operator at the effective
        // price), so the subtraction never underflows.
        let total_cost = fee
            .checked_add(l1_cost)
            .and_then(|v| v.checked_add(operator_cost))
            .ok_or_else(|| BaseTransactionError::eip8130("EIP-8130 settled cost overflow"))?;
        let refund_amount = prepay.checked_sub(total_cost).ok_or_else(|| {
            BaseTransactionError::eip8130("settled fee exceeds the worst-case pre-charge")
        })?;

        {
            let mut payer_acc =
                ctx.journal_mut().load_account_mut(outcome.payer).map_err(EVMError::Database)?;
            // Consistent with the checked-arithmetic discipline used elsewhere in
            // this file: `refund_amount <= prepay <= original_balance`, so the sum
            // cannot overflow, but surface a violation rather than minting ETH by
            // clamping to `U256::MAX`.
            let balance = payer_acc.balance().checked_add(refund_amount).ok_or_else(|| {
                BaseTransactionError::eip8130("EIP-8130 payer refund balance overflow")
            })?;
            payer_acc.set_balance(balance);
        }

        for (recipient, amount) in [
            (Predeploys::BASE_FEE_VAULT, base_fee_amount),
            (beneficiary, priority_amount),
            (Predeploys::L1_FEE_VAULT, l1_cost),
            (Predeploys::OPERATOR_FEE_VAULT, operator_cost),
        ] {
            ctx.journal_mut().balance_incr(recipient, amount).map_err(EVMError::Database)?;
        }

        Ok(billable_gas)
    }

    pub fn revalidate<DB: Database>(&self, db: &mut DB, now: u64) -> Result<(), ManifestStale> {
        if self.effective_expiry != u64::MAX && now > self.effective_expiry {
            return Err(ManifestStale::Expired { deadline: self.effective_expiry, now });
        }

        for slot in &self.config_slots {
            if let Ok(current) = db.storage(slot.address, slot.slot)
                && current != slot.expected
            {
                return Err(ManifestStale::ConfigSlotChanged {
                    address: slot.address,
                    slot: slot.slot,
                });
            }
        }

        if !self.payer_max_cost.is_zero()
            && let Ok(info) = db.basic(self.payer)
        {
            let available = info.map_or(U256::ZERO, |info| info.balance);
            if available < self.payer_max_cost {
                return Err(ManifestStale::PayerUnderfunded {
                    payer: self.payer,
                    required: self.payer_max_cost,
                    available,
                });
            }
        }

        Ok(())
    }
