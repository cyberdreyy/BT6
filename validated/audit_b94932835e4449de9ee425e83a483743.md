### Title
Zip cache extraction (`extractZipFile`/`ExtractZipArchive`) lacks path-traversal/absolute-path containment check, unlike tarzstd extractor - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive`/`extractZipFile` in `helpers/archives/zip_extract.go` write files using the raw `zip.File.Name` value with no validation that the resolved path stays within the extraction root, unlike `commands/helpers/archive/tarzstd/tarzstd_extractor.go` which explicitly resolves `filepath.Abs(filepath.Join(dir, hdr.Name))` and rejects paths outside `dir`. Because `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`'s `Extract` calls `archives.ExtractZipArchive(zr)` and never uses its own `dir` field, extraction path containment is only implicitly the process's current working directory, and nothing prevents `file.Name` entries like `../../etc/passwd` or absolute paths from writing outside the intended cache/build root.

### Finding Description
`CacheExtractorCommand.Execute` (`commands/helpers/cache_extractor.go:618-664`) resolves `wd` via `os.Getwd()` and calls `archive.NewExtractor(format, f, size, wd)` then `extractor.Extract(ctx)`. For the legacy zip format, `ziplegacy.extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32`) ignores its `dir` field entirely and calls `archives.ExtractZipArchive(zr)`.

Inside `ExtractZipArchive` -> `extractZipFile` (`helpers/archives/zip_extract.go:41-83`), the code does:
- `os.MkdirAll(filepath.Dir(file.Name), 0o777)` 
- `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` for regular files
- `os.Symlink(string(data), file.Name)` for symlink entries

None of these paths are joined against, or validated to remain under, the working directory (`wd`)/cache root. The only existing guard is `errorIfGitDirectory` (`helpers/archives/path_check_helper.go`), which only blocks paths whose first cleaned path component is `.git` — it does not block `..` traversal segments or absolute paths in any other position.

By contrast, `tarzstd_extractor.go:57-64` explicitly computes the absolute joined path and verifies `strings.HasPrefix(path, e.dir+string(filepath.Separator))`, rejecting any entry that would escape `e.dir`. This same protection is absent from the zip path (both `extractZipFile` for the standard-library based `ziplegacy` extractor, and potentially the `fastzip`-based extractor depending on the underlying library's own containment guarantees, which was not verified here).

Attacker-controlled input: a cache archive's internal entry names are attacker-controlled to the extent that whatever produced/uploaded the cache object controls `zip.File.Name`. Under the threat model of this question (poisoned/collided shared cache object retrieved under a guessable/colliding cache key), an attacker who can get a malicious zip written to the shared cache store (e.g., via key collision or writing to a shared cache namespace) can supply entries such as `../../../../etc/passwd` or an absolute path, and when a victim job's runner extracts this cache via `cache-extractor --file ...` -> `CacheExtractorCommand.Execute` -> `openArchive` -> `archive.NewExtractor("zip", ...)` -> `ziplegacy.extractor.Extract` -> `archives.ExtractZipArchive`, the resulting file write lands outside the intended `wd` (cache/build root).

### Impact Explanation
A malicious cache entry extracted via the zip path can write/overwrite arbitrary files reachable by the runner process's filesystem permissions, outside the job's cache/build directory (e.g., relative traversal escaping `wd`, or absolute path writes such as `/etc/...` if permissions allow, or writes into other project directories on a shared runner host/build directory layout). This matches the scoped impact: cross-project cache poisoning leading to file write outside the build root. The severity is bounded by the OS user the runner/helper process runs as, but the confinement invariant that "cache entries must remain confined to the extraction root" is violated for the zip code path, which the tarzstd path explicitly enforces.

### Likelihood Explanation
Requires the stated precondition of a shared/guessable/colliding cache key and the ability to poison a cache object stored under that key — this is an existing precondition accepted by the question. Given that precondition, exploitation is straightforward: craft a zip archive with a malicious `file.Name` and standard zip tooling (Go's `archive/zip` package used for creation, or manual header crafting), no additional runner-side check needs to be bypassed since `extractZipFile`/`ExtractZipArchive` perform no path containment validation at all (only the `.git`-directory check, which is unrelated). This is a real, reachable, existing gap.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to the zip extraction path: in `extractZipFile` (or preferably in `ExtractZipArchive`/`ExtractZipFile`), resolve `path, err := filepath.Abs(filepath.Join(dir, file.Name))` against the intended extraction root, and reject (or skip with a warning, consistent with the existing `tracker.actionable` pattern) any entry whose resolved path does not have `dir+string(filepath.Separator)` as a prefix (and is not equal to `dir`). This requires threading an explicit `dir` parameter through `ExtractZipArchive`/`ExtractZipFile`/`extractZipFile` (currently these functions implicitly rely on `os.Getwd()`/cwd rather than accepting `dir`), and updating `ziplegacy.extractor.Extract` to pass `e.dir` through instead of discarding it. Apply the same fix to symlink target validation (`extractZipSymlinkEntry`) since a symlink itself could point outside the root even if the symlink file's own location is validated.

### Proof of Concept
Go unit test targeting `helpers/archives/zip_extract.go` (analogous to existing `zip_extract_test.go`):
```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpRoot := t.TempDir()
    extractDir := filepath.Join(tmpRoot, "cache")
    require.NoError(t, os.MkdirAll(extractDir, 0o755))

    // Build a malicious zip in-memory with a traversal entry.
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, err := zw.Create("../../../../tmp/pwned.txt")
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    // chdir into extractDir to simulate cache-extractor's wd, then extract
    origWd, _ := os.Getwd()
    defer os.Chdir(origWd)
    require.NoError(t, os.Chdir(extractDir))

    err = ExtractZipArchive(zr)

    // Expected (fixed) behavior: extraction must fail or the traversal file
    // must not exist outside extractDir.
    _, statErr := os.Stat("/tmp/pwned.txt")
    assert.True(t, os.IsNotExist(statErr), "traversal entry must not be written outside extraction root")
    _ = err
}
```
Assertions: after running current code, `/tmp/pwned.txt` (or equivalent path escaping `extractDir`) is created, proving the missing containment check; after applying the recommended fix (path-prefix check as in `tarzstd_extractor.go`), the file must not exist outside the root and `ExtractZipArchive` should return/log an error for that entry instead of writing it. func extractZipFileEntry(file *zip.File) (err error) {
```go
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
```

```go
func (c *CacheExtractorCommand) Execute(cliContext *cli.Context) {
	log.SetRunnerFormatter()

	c.normalizeExtractorArgs()
	if err := validateCacheTransferTuning(c.TransferBufferSize, c.ChunkSize, c.Concurrency); err != nil {
		logrus.Fatalln(err)
	}

	wd, err := os.Getwd()
	if err != nil {
		logrus.Fatalln("Unable to get working directory")
	}

	if c.File == "" {
		warningln("Missing cache file")
	}

	if c.URL != "" || c.GoCloudURL != "" {
		err := c.doRetry(c.download)
		if err != nil {
			warningln(err)
		}
	} else {
		logrus.Infoln(
			"No URL provided, cache will not be downloaded from shared cache server. " +
				"Instead a local version of cache will be extracted.")
	}

	f, size, format, err := openArchive(c.File)
	if os.IsNotExist(err) {
		warningln("Cache file does not exist")
	}
	if err != nil {
		logrus.Fatalln(err)
	}
	defer f.Close()

	extractor, err := archive.NewExtractor(format, f, size, wd)
	if err != nil {
		logrus.Fatalln(err)
	}

	err = extractor.Extract(context.Background())
	if err != nil {
		logrus.Fatalln(err)
	}
}
```
