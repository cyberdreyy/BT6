### Title
Instant-withdraw path in `requestWithdraw` skips `interestForOverUnderPerformance` accounting, corrupting `expectedEpochInterest` - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
`requestWithdraw` has two branches: the normal path calls `_calcInterestWithdrawRequest` and accumulates the tranche over/under-performance `diff` into `interestForOverUnderPerformance` (lines 773–784), while the instant-withdraw path (gated by `disableInstantWithdraw`, which defaults to `true` but can be enabled via `setInstantWithdrawParams`) burns tranches for full principal at lines 761–770 and skips that adjustment entirely. Like the vLLM fix, the vulnerability is only hidden because the feature is off by default — enabling it exposes the missing validation/accounting.

### Finding Description
At `startEpoch` (lines 260–263) the expected epoch interest is computed as `_calcInterest(getContractValue()) + interestForOverUnderPerformance`. Because an instant-withdrawal burns the tranche supply, `getContractValue()` already shrinks, but the blended-rate `_calcInterest` does not reflect the removed tranche's APR share — that correction is exactly what `diff` provides in the normal path. Skipping it means:

- If the instant-withdrawing tranche's interest share exceeds its NAV share (BB in the typical senior-favored config, `diff < 0`), `expectedEpochInterest` is overstated and the borrower is billed excess interest at `stopEpoch`, which is distributed to remaining NAV holders.
- If `diff > 0` (AA withdrawal), `expectedEpochInterest` is understated, borrower underpays, and remaining holders absorb a yield shortfall that the exiting user avoids by leaving at full tranche price.

The instant path also bypasses `_totalWithdrawFees` / `pendingWithdrawFees`, so instant withdrawers pay no upfront management fee (contrast lines 774–778).

### Impact Explanation
A tranche holder can instant-withdraw a large BB position (negative `diff` skipped) while retaining a dust AA position, causing the honest borrower to overpay interest that accrues to remaining NAV — direct theft from the borrower / illicit yield for the attacker, quantifiable as `|diff|` ≈ `amount × (blended − BB rate) × (epochDuration + bufferPeriod) / year`. Symmetrically, a full AA instant exit underpays the epoch and permanently steals unclaimed yield from remaining LPs. Fair mint/burn and solvency invariants are broken whenever instant withdrawals are enabled.

### Likelihood Explanation
Only requires: manager enables instant withdrawals (a supported config path), `lastEpochApr > currentApr + instantWithdrawAprDelta` (any genuine APR reduction), and a KYC'd tranche holder. No privileged misbehavior needed.

### Recommendation
Compute `(interest, diff)` via `_calcInterestWithdrawRequest` on the instant path too, update `interestForOverUnderPerformance += diff`, and apply `_totalWithdrawFees`/`pendingWithdrawFees` consistently (or document and price the fee exemption).
