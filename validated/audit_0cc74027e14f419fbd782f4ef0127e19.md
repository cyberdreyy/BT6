### Title
Missing `mut` on loop counter `i` in `validate_proof` causes all multi-signature Axelar bridge proofs to abort — (File: `crates/sui-axelar-cgp/move/sources/validators.move`)

---

### Summary

`validate_proof` declares the outer loop variable `i` **without `mut`**, so it is never incremented. Every iteration re-reads `signatures[0]` while `operator_index` advances past the already-matched operator. On the second iteration the inner scan exhausts the operator list and `vector::borrow(&weights, operator_index)` aborts with a Move out-of-bounds error. Only proofs where a **single** signer's weight alone meets the threshold can ever succeed; every multi-signature proof always aborts.

---

### Finding Description

In `validate_proof`, line 102:

```move
let (i, mut weight, mut operator_index) = (0, 0, 0);
```

`i` is immutable and is never written inside the loop body. The outer `while (i < total_signatures)` therefore:

1. **Iteration 1** — reads `signatures[0]`, recovers `signed_by`, inner loop finds the matching operator at some `operator_index`, accumulates `weight`. If `weight >= threshold` the function returns `true`. Otherwise `operator_index` is incremented by 1 (line 118).
2. **Iteration 2** — `i` is still `0`, so `signatures[0]` is read again and the same `signed_by` is recovered. The inner loop now starts scanning from the **already-advanced** `operator_index`. Because operators are expected to be sorted and the matched operator was at a lower index, the inner loop runs all the way to `operators_length`. Then line 116 executes `vector::borrow(&weights, operators_length)` — an out-of-bounds access — and the Move runtime **aborts**.

The commented-out guard at line 114 was the intended defence against a non-matching operator, but it was disabled:

```move
// assert!(operator_index == operators_length, 0); // EMalformedSigners
```

Without it, the only thing that terminates the second iteration is the fatal out-of-bounds abort. [1](#0-0) 

The public entry point that reaches this code is `process_commands` in `gateway.move`, which is callable by any unprivileged user:

```move
entry fun process_commands(
    validators: &mut AxelarValidators,
    input: vector<u8>
) {
    ...
    let mut allow_operatorship_transfer = validate_proof(validators, to_sui_signed(*&data), proof);
``` [2](#0-1) 

`AxelarValidators` is a shared object (created in `init` with `transfer::share_object`), so any transaction can pass it. [3](#0-2) 

---

### Impact Explanation

Any operator set where no single member's weight alone reaches the threshold — the standard multi-sig security model — produces a proof that **always aborts** when submitted to `process_commands`. Concretely:

- Cross-chain contract-call approvals (`approveContractCall`) are never written to the `approvals` table.
- Operatorship transfers (`transferOperatorship`) are never executed.
- The bridge is permanently non-functional for multi-sig operator configurations until the package is upgraded.

This matches the "harmful smart-contract behavior reachable from public input" class under the High/Medium gate.

---

### Likelihood Explanation

The trigger is structural: any proof with more than one signature and no single signer meeting the threshold alone will abort. The `process_commands` entry function is publicly callable with arbitrary `input` bytes. No special privilege is required to submit a proof; the attacker model is an ordinary SUI holder.

---

### Recommendation

Declare `i` as mutable and increment it at the end of each outer-loop iteration:

```move
let (mut i, mut weight, mut operator_index) = (0, 0, 0);
// ...
while (i < total_signatures) {
    // ... existing body ...
    operator_index = operator_index + 1;
    i = i + 1;          // ← add this
};
```

Also restore the commented-out guard to reject signatures from non-operators instead of relying on an out-of-bounds abort:

```move
assert!(operator_index < operators_length, EMalformedSigners);
```

---

### Proof of Concept

1. Deploy `AxelarValidators` with two operators `[opA, opB]`, weights `[1, 1]`, threshold `2`.
2. Register the operator set hash via `transfer_operatorship`.
3. Construct a valid BCS-encoded proof containing two valid signatures — one from `opA` and one from `opB` — over the approval hash.
4. Call `process_commands` with this proof.
5. **Observed**: the transaction aborts with a Move vector-index-out-of-bounds error on the second outer-loop iteration (line 116), because `operator_index` equals `operators_length` after the inner scan fails to find `opA` again.
6. **Expected**: `weight` accumulates to `2`, meets the threshold of `2`, and the function returns `true`, allowing the bridge command to be processed.

The root cause is identical in class to the KintoWallet report: a loop that fails to advance its primary counter causes the threshold accumulator to never reach the required value, making every legitimately-signed multi-party proof permanently unprocessable.
