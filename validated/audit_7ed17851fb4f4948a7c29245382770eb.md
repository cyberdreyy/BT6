This confirms the fee model is neutral, not a bypass.

`add_contract_loading_fee` charges `contract_loading_base` + `contract_loading_bytes * code_len` unconditionally, on every `FunctionCall` execution, regardless of whether the code originated from a `DeployContract` action or was referenced via `UseGlobalContract`. This is invoked from `before_loading_executable`/`after_loading_executable` in `runtime/near-vm-runner/src/logic/gas_counter.rs:225-271`, called from `with_compiled_and_loaded` in `runtime/near-vm-runner/src/wasmtime_runner/mod.rs:814,821`. Each executing shard/account pays this load fee independently on its own `FunctionCall` receipt, whether the code is local (`DeployContract`) or a global reference resolved through `UseGlobalContract`.

The `total_send_fees` arms for `DeployContract` and `DeployGlobalContract` (`runtime/runtime/src/config.rs:97-106,168-178`) both charge a *send* fee proportional to `code.len()` — this is the cost of transmitting/dispatching the deploy action itself (bandwidth for the deploy receipt), not a pre-payment for future execution loading costs. It is a separate, orthogonal fee category from `contract_loading_base`/`contract_loading_bytes`, which are `ExtCosts` charged inside `VMLogic`/`GasCounter` at execution time (`core/parameters/src/cost.rs`), not inside `total_send_fees`/`total_exec_fees` action fees at all.

So:
- Deploying account pays once: `deploy_global_contract_base + deploy_global_contract_byte * code.len()` — this only covers dispatching the `DeployGlobalContract` receipt. [1](#0-0) 
- Every account that later executes a `FunctionCall` using that global contract (via `UseGlobalContract`) pays its own `contract_loading_base + contract_loading_bytes * code_len` at execution time in `add_contract_loading_fee`, independent of who deployed it or how many others load it. [2](#0-1) 
- This charge happens on the loading/execution path (`before_loading_executable`/`after_loading_executable`) for every `FunctionCall`, gated only by `fix_contract_loading_cost` for pre- vs post-load timing, not by contract origin.

    /// Add a cost for loading the contract code in the VM.
    ///
    /// This cost does not consider the structure of the contract code, only the
    /// size. This is currently the only loading fee. A fee that takes the code
    /// structure into consideration could be added. But since that would have
    /// to happen after loading, we cannot pre-charge it. This is the main
    /// motivation to (only) have this simple fee.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn add_contract_loading_fee(&mut self, code_len: u64) -> Result<()> {
        self.pay_per(ExtCosts::contract_loading_bytes, code_len)?;
        self.pay_base(ExtCosts::contract_loading_base)
    }
