## Finding: Missing commission-percentage bound check in `staking_contract::switch_operator` permanently bricks stake/vesting funds

### Title
Unbounded `new_commission_percentage` in `switch_operator` permanently locks staker/vesting funds - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`staking_contract::create_staking_contract_with_coins` and `staking_contract::update_commision` both explicitly bound the commission percentage to `[0, 100]` before writing it into `StakingContract.commission_percentage` [1](#0-0) . `switch_operator`, however, writes an attacker/admin-supplied `new_commission_percentage` directly into the struct with no such validation [2](#0-1) .

### Finding Description
`update_commision` enforces the invariant relied on everywhere else in the module: `commission_percentage >= 0 && commission_percentage <= 100` [3](#0-2) . `create_staking_contract_with_coins` is likewise bound-checked, as confirmed by the formal spec (`aborts_if commission_percentage > 100`) [4](#0-3) .

`switch_operator` accepts a caller-supplied `new_commission_percentage`, performs `distribute_internal`/`request_commission_internal` against the *old* contract (using the old, already-validated percentage), then unconditionally assigns the new value with no range check: `staking_contract.commission_percentage = new_commission_percentage;` [5](#0-4) . Unlike `update_commision`, there is no `EINVALID_COMMISSION_PERCENTAGE` assertion here.

Downstream, `request_commission_internal` computes `commission_amount` from `accumulated_rewards` and `commission_percentage`, then does `staking_contract.principal = total_active_stake - commission_amount;` [6](#0-5) . If `commission_percentage` is set above 100 (e.g. 1000), `commission_amount` can exceed `total_active_stake`, and this subtraction (unsigned Move arithmetic) aborts. Because *every* subsequent flow that touches this staking contract — `request_commission`, `distribute` (via `distribute_internal`), `unlock_stake`, and even another `switch_operator` call — routes through `request_commission_internal`/`distribute_internal` first [7](#0-6) , once rewards accrue enough for `commission_amount > total_active_stake`, all of these entry points abort permanently. There is no recovery path once the pool is in this state — this is the stake-and-lockup analog of the fee-rate check described in the external report (SKALE-2157): the same class of "fee rate can exceed 100%" bug, but here it corrupts the whole distribution/commission-accounting flow rather than just a whitelisting gate.

This is directly reachable by vesting flows: `vesting::update_operator` forwards an admin-supplied `commission_percentage` straight into `staking_contract::switch_operator` [8](#0-7)  without its own validation, unlike `vesting::update_commission_percentage`, which correctly routes through `staking_contract::update_commision` (which is bound-checked) [9](#0-8) . Shareholders in a vesting contract have no control over `update_operator` (admin-only) yet bear the consequences if the admin (maliciously or by mistake) sets an out-of-range percentage — their vested/rewards funds become permanently stuck once the invariant is violated.

### Impact Explanation
Once `commission_percentage` is set above 100 through `switch_operator`, the staking contract enters a state where `request_commission_internal`'s principal-subtraction aborts as soon as accumulated rewards make `commission_amount` exceed `total_active_stake`. Since `request_commission`, `distribute`, `unlock_stake`, and `switch_operator` all invoke this internal helper first, the staker's (or vesting shareholders') entire principal + rewards become permanently non-withdrawable — a "permanent lock or non-recoverable loss of claim rights" as defined in the required impact set. There is no admin/staker recovery function to reset `commission_percentage` back into range on a bricked pool (any call that would do so, e.g. `update_commision`, itself calls `request_commission_internal` first, aborting).

### Likelihood Explanation
`switch_operator` is a normal `public entry fun` callable by any staker at will and by vesting admins via `vesting::update_operator`, requiring no elevated privilege beyond controlling one's own staking contract or vesting contract admin role. No governance or privileged action is needed to trigger the missing check — a single malformed/malicious transaction argument suffices.

### Recommendation
Add the same bound check used in `update_commision` to `switch_operator` before assigning `staking_contract.commission_percentage = new_commission_percentage`:
```move
assert!(
    new_commission_percentage <= 100,
    error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
);
```
Also validate `commission_percentage` inside `vesting::update_operator`/`vesting::update_operator_with_same_commission` before calling into `staking_contract::switch_operator`, so admin-supplied values cannot brick shareholder funds even if the framework-level check were ever removed.

### Proof of Concept
1. Staker creates a valid staking contract with `commission_percentage = 10` via `create_staking_contract`.
2. Staker calls `switch_operator(staker, old_operator, new_operator, new_commission_percentage = 100000)` — succeeds because no bound check exists [2](#0-1) .
3. Let an epoch pass so `accumulated_rewards > 0`.
4. Call `request_commission` (or `distribute`, or `unlock_stake`) — `get_staking_contract_amounts_internal` computes `commission_amount` far exceeding `total_active_stake`, and `staking_contract.principal = total_active_stake - commission_amount` aborts on unsigned underflow [6](#0-5) .
5. Every subsequent call to `request_commission`, `distribute`, `unlock_stake`, or `switch_operator` on this contract aborts identically, permanently locking the staker's (or vesting shareholders') funds with no recovery entry point.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);

        // Short-circuit if there's no commission to pay.

            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );
