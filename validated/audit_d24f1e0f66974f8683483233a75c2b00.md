### Title
Settled APR0 withdraw principal is excluded from per-epoch default claim basis yet still paid at par, letting a post-default claim drain funded recovery/funded-claim balances - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault` tracks APR=0 withdraw receipts in a two-stage `Apr0UserData` bucket: open `principal`/`principalEpoch`, and `settledPrincipal`/`settledInterest` after `_settleApr0` moves a matured request. Analogous to the CVE-2024-38440 pattern (a length/bounds field used after parsing without validating the full extent of user-controlled data), the per-epoch defaulted-claim math in `_withdrawClaimAmountsForEpoch` only counts the *open* APR0 bucket that matches `defaultRecoveryEpoch` plus `withdrawsRequestsByEpoch`; the settled bucket has no epoch attribution and is silently dropped from the haircutted `claimBasis` — while `_claimFundedWithdrawRequest` still pays `settledPrincipal + settledInterest` at par in the same `claimWithdrawRequest` call.

### Finding Description
- `_requestWithdrawApr0` calls `_settleApr0`, which (once `principalEpoch < epochNumber`) moves `principal` into `settledPrincipal` and accrues `settledInterest`, zeroing `principal`/`principalEpoch` and thereby erasing which epoch the funds belong to (contracts/strategies/idle/IdleCreditVault.sol:545-577).
- On default, `finalizeDefaultRecovery` computes the global claim basis via `defaultPendingClaimBasis() = pendingWithdraws + current-epoch instant claims` (line 644). `pendingWithdraws` still includes the settled APR0 principal (it was added at request time at line 279 and never removed), so it dilutes `defaultRecoveryPrice` for everyone.
- Per-user payout, however, uses `_withdrawClaimAmountsForEpoch`, which only sums `withdrawsRequestsByEpoch[user][defaultEpoch]` and the *open* `apr0User.principal` whose `principalEpoch == defaultEpoch` (lines 862-881). `settledPrincipal`/`settledInterest` are not in `claimBasis`.
- After `_claimDefaultedWithdrawRequest` clears the epoch and resets `lastWithdrawRequest` to 0 (lines 832-836), `claimWithdrawRequest` unconditionally proceeds to `_claimFundedWithdrawRequest`, whose gate `epochNumber <= lastWithdrawRequest` now passes and which pays `settledPrincipal + settledInterest` at par through `_transferFundedClaim` (lines 319-349, 301-313).

Broken invariant: every unit counted in `totalBasis` (and thus haircutting `defaultRecoveryPrice`) must be paid exclusively through `defaultRecoveryPrice`; the settled bucket is counted in the basis but paid at par from non-reserve balance.

### Impact Explanation
Two outcomes depending on vault balance:
1. If the strategy holds any non-reserve underlying (prefunded instant receipts, previously funded normal receipts, `sendInterestAndDeposits` funds), the attacker's settled APR0 principal is paid at par while other defaulted claimants only receive `defaultRecoveryPrice` per unit — direct theft/solvency loss equal to `settledPrincipal * (1 - defaultRecoveryPrice)` plus full `settledInterest`, funded from balance earmarked for other claimants.
2. If `balanceOf(this) - defaultRecoveryReserve < settledPrincipal + settledInterest`, `_transferFundedClaim` reverts (lines 897-907), rolling back the entire `claimWithdrawRequest` — the user's legitimately defaulted receipt is permanently frozen.

Quantified example: recovery price 0.5e18, attacker settledPrincipal = 100k, others' basis = 100k. Attacker extracts ~150k-equivalent (p2 at 50% + p1 at 100%) from a reserve sized for 200k basis at 50%.

### Likelihood Explanation
- Reachable by any KYC-passed lender (`isWalletAllowed` only), in APR0 / programmable-borrower vaults where `unscaledApr == 0` is the normal mode.
- Requires only: request APR0 withdraw in epoch E; let the epoch stop (honest manager); request again in epoch E+1 (settles bucket 1); borrower then fails to repay at the next stop — an ordinary credit event, not attacker-controlled privilege — followed by honest `finalizeDefaultRecovery`.
- No existing guard stops it: the loss-epoch guard in `requestWithdraw` (lines 263-271) checks `principalEpoch == lossEpoch` but settled buckets have `principalEpoch == 0`, and `_hasWithdrawRequest`/`defaulted` checks do not cover this path.

### Recommendation
Attribute settled APR0 balances to their originating epoch: store a `settledEpoch` (or keep `principalEpoch` after settlement) in `Apr0UserData`, include `settledPrincipal`/`settledInterest` in `_withdrawClaimAmountsForEpoch` when the settled epoch == `defaultRecoveryEpoch`, and subtract them in `_clearWithdrawClaimForEpoch`. Alternatively, pay the settled bucket from `defaultRecoveryReserve` at `defaultRecoveryPrice` during `_claimDefaultedWithdrawRequest` and prevent `_claimFundedWithdrawRequest` from paying APR0 balances after `defaultRecoveryFinalized`.

### Proof of Concept
Foundry fork test (sketch, against `IdleCreditVault` + `IdleCDOEpochVariant` harness as in `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testSettledApr0EscapesDefaultHaircut() external {
    // Programmable borrower vault => unscaledApr == 0
    uint256 amount = 100_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _depositWithUser(attacker, amount, true);   // KYC'd lender

    // Epoch E: attacker requests full APR0 withdraw
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(0, address(AAtranche));
    _startEpochAndCheckPrices(0);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);                    // funded, epochNumber -> 1

    // Buffer of epoch 1: attacker requests again; _settleApr0 moves req1
    // into settledPrincipal/settledInterest (epoch attribution lost)
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(0, address(AAtranche));
    assertGt(strategy.apr0Users(attacker).settledPrincipal, 0);

    _startEpochAndCheckPrices(1);
    // Borrower honestly underpays -> default, then finalize recovery at <1.0
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);                    // defaulted
    finalizeDefaultRecoveryPartial();            // e.g. 50% recovery

    // Claim: p2 haircut from reserve + p1 settled bucket paid at par
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest();
    // assert attacker received more than defaultRecoveryPrice * totalBasis share
    // or that the call reverts in _transferFundedClaim when no excess balance exists
}
```

Key assertion: `underlying.balanceOf(attacker) > (p1 + p2 + settledInterest) * defaultRecoveryPrice / 1e18`, with the excess drawn from non-reserve vault balance belonging to other claimants; in the minimal-balance variant, `vm.expectRevert(NotAllowed.selector)` demonstrates permanent freezing of the defaulted receipt.
