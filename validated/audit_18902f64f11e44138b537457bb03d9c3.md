### Title
Unbounded recursion in `TrieNode::decode` causes stack-exhaustion DoS of the fault-proof program - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` in the MPT crate used by the fault-proof program recursively decodes nested `Extension` and `Branch` nodes with no depth limit, mirroring the `asn1_decode_simple_ber` unbounded-recursion bug in libtasn1 (ALPINE-CVE-2018-6003). A dispute-game participant can craft state-trie preimages with deeply nested inline nodes that exhaust the stack when `op-program` decodes them, crashing the fault-proof program mid-execution.

### Finding Description
`TrieNode::decode` peeks the RLP header and, for list-typed nodes, dispatches on element count: [1](#0-0) 

For a 2-element list it calls `try_decode_leaf_or_extension_payload`, which — when the path prefix marks the node as an `Extension` — recurses back into `Self::decode(buf)` on the embedded child bytes with no depth or size check: [2](#0-1) 

For a 17-element list (`Branch`), it calls `Vec::<Self>::decode(buf)`, which decodes each of the 17 slots by recursively invoking `TrieNode::decode` again: [3](#0-2) 

In a conformant Ethereum MPT, a node is only embedded inline (rather than referenced by a 32-byte keccak commitment) when its own RLP encoding is under 32 bytes — this is enforced on the *encode* path via `blinded_length`: [4](#0-3) 

However, the *decode* path performs no equivalent check: `try_decode_leaf_or_extension_payload` and the branch-list path accept an embedded child of arbitrary size and recurse into it unconditionally. A preimage that violates the size invariant (which no consensus rule prevents an attacker from constructing, since it need only satisfy `keccak256(bytes) == requested_key` for the *specific* node being resolved) can therefore nest thousands of `Extension`/`Branch` frames inside a single, reasonably small RLP blob, each recursive call consuming stack.

This decoder is reached directly from the fault-proof program's preimage-oracle-backed trie providers on both L1 and L2: [5](#0-4) [6](#0-5) 

and from the trie walkers/executor used to build state during proof execution: [7](#0-6) [8](#0-7) 

### Impact Explanation
The fault-proof program (`op-program`) is the arbiter of correctness in the dispute-game: it is executed by challengers to prove an invalid L2 output root wrong. If a dispute-game participant submits/derives state whose trie preimages trigger unbounded recursion in `TrieNode::decode`, the fault-proof program crashes via stack overflow before it can compute the correct output root. This prevents honest participants from disproving an invalid claim, letting a fraudulent output root prevail in the dispute game — a "wrong provable output root" outcome that can enable theft or permanent freezing of bridged funds, matching the CVE's DoS-via-unbounded-recursion bug class.

### Likelihood Explanation
Constructing a legal-looking but oversized inline `Extension`/`Branch` chain only requires producing bytes whose keccak256 hash matches the preimage key being resolved for one step of the trie walk — this is a normal capability of any party supplying preimage data in the dispute-game/derivation pipeline, and the recursive decode has no depth guard, no iterative fallback, and no size assertion mirroring the encoder's `blinded_length` invariant. The recursion is directly and repeatedly reachable on every `trie_node_by_hash` call made throughout state/trie processing.

### Recommendation
Add an explicit recursion-depth (or iterative-decoding) bound in `TrieNode::decode`/`try_decode_leaf_or_extension_payload`, and additionally enforce the encode-side invariant on decode — reject embedded (non-blinded) child nodes whose encoded length is `>= 32` bytes, matching `blinded_length`'s constraint, so malformed/adversarial preimages are rejected rather than recursed into.

### Proof of Concept
Construct an RLP blob representing `Extension(prefix, Extension(prefix, Extension(prefix, ... Leaf)))` nested N times (N in the low thousands), all inline (no blinding/hash indirection) so it decodes in a single call to `TrieNode::decode`. Store this blob under its own keccak256 hash so it satisfies any preimage-oracle lookup for that key, then have a `TrieProvider::trie_node_by_hash` call (e.g., via `OracleL1ChainProvider`/`OracleL2ChainProvider`) resolve it — `TrieNode::decode` recurses N frames deep with no bound, overflowing the stack of the fault-proof program process.

                let mut leaf_values = VecDeque::with_capacity(stack.len());
                for item in stack {
                    match item {
                        TrieNode::Blinded { commitment } => {
                            // If the string is a hash, we need to grab the preimage for it and
                            // continue recursing.
                            let trie_node = Self::get_trie_node(commitment.as_ref(), fetcher)?;
                            leaf_values.append(&mut Self::fetch_leaves(&trie_node, fetcher)?);
                        }
                        TrieNode::Empty => { /* Skip over empty nodes, we're looking for values. */
                        }
                        item => {
                            // If the item is already retrieved, recurse on it.
                            leaf_values.append(&mut Self::fetch_leaves(item, fetcher)?);
                        }
                    }
                }
                Ok(leaf_values)
            }

                Ok(vec![(prefix.to_vec().into(), value.clone())].into())

    /// Fetches the [`TrieAccount`] of an account from the trie DB.
    ///
    /// ## Takes
    /// - `address`: The address of the account.
    ///
    /// ## Returns
    /// - `Ok(Some(TrieAccount))`: The [`TrieAccount`] of the account.
    /// - `Ok(None)`: If the account does not exist in the trie.
    /// - `Err(_)`: If the account could not be fetched.
    pub fn get_trie_account(
        &mut self,
        address: &Address,
        block_number: u64,
    ) -> TrieDBResult<Option<TrieAccount>> {
        // Send a hint to the host to fetch the account proof.
        self.hinter
            .hint_account_proof(*address, block_number)
            .map_err(|e| TrieDBError::Provider(e.to_string()))?;

        // Fetch the account from the trie.
        let hashed_address_nibbles = Nibbles::unpack(keccak256(address.as_slice()));
        let Some(trie_account_rlp) = self.root_node.open(&hashed_address_nibbles, &self.fetcher)?
        else {
            return Ok(None);
        };

        // Decode the trie account from the RLP bytes.
        TrieAccount::decode(&mut trie_account_rlp.as_ref())
            .map_err(TrieNodeError::RLPError)
            .map_err(Into::into)
            .map(Some)
    }
