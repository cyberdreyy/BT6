### Title
`Wrapper.terminateWrapper()` gives up after `terminationTimeout` with no SIGKILL escalation, leaving the wrapped `gitlab-runner run` process (and its unreaped process-group children) alive and holding tokens after the wrapper reports shutdown - ([File: helpers/runner_wrapper/wrapper.go])

### Summary
`terminateWrapper()` sends a single `SIGTERM` to the wrapped process and waits at most `terminationTimeout` (default `DefaultTerminationTimeout` = 10s) for `w.errCh` to receive the `Wait()` result. If the wrapped `gitlab-runner run` process does not exit in time (e.g. because a job/executor cleanup or a hung job process it manages blocks its own shutdown path), `terminateWrapper()` returns `errProcessExitTimeout`, and the caller in `commands/wrapper.go` calls `log.Fatal`, which `os.Exit`s the wrapper immediately without ever attempting `SIGKILL` or reaping the child.

### Finding Description
`terminateWrapper()` in `helpers/runner_wrapper/wrapper.go:146-166` performs exactly one `SIGTERM` (via `terminateWrappedProcess`, line 179: `p.Signal(syscall.SIGTERM)`) and then races `w.errCh` against `time.After(w.terminationTimeout)`. If the timeout wins, it returns `errProcessExitTimeout` and stops waiting — it never retries, never escalates to `SIGKILL`, and there is no equivalent of `forcefulShutdown` (`wrapper_unix.go:13-15`) being invoked here, since that function is likewise only a `SIGTERM` sender, not an actual force-kill.

`commands/wrapper.go:83-86` treats this timeout the same as any other wrapper error: it calls `log.WithError(err).Fatal(...)`, and `logrus.Fatal` calls `os.Exit(1)` internally. This means the wrapper's own process disappears instantly, with no cleanup of the already-`SIGTERM`'d child. Because the child was started via `exec.Command` with only `Setpgid: true` (`commander_unix.go:10-13`) and no `Pdeathsig`, the child is not tied to the wrapper's lifetime at the OS level — it is not killed when the wrapper exits.

Additionally, `setProcessGroup` only puts the child in its own process group; `terminateWrappedProcess` signals the single tracked `os.Process` (`p.Signal(syscall.SIGTERM)`), not the process group (`kill(-pgid, SIGTERM)`). So even in the timeout scenario, any grandchild processes spawned by the wrapped `gitlab-runner run` that ignore or are slow to react to `SIGTERM` are left completely unsignaled by this code path.

The trigger condition — the wrapped `gitlab-runner run` failing to exit within 10 seconds of `SIGTERM` — is plausible whenever job/executor shutdown, cleanup, or a hung script under an executor delays the run process's own graceful-shutdown sequence beyond that window. A pipeline author who can make their job hang uncleanly (e.g. ignore `SIGTERM` inside a shell executor, spawn detached children, or otherwise stall executor cleanup) can extend that shutdown window.

### Impact Explanation
Once the timeout branch is hit, the parent supervisor process (`gitlab-runner wrapper`) exits via `log.Fatal`/`os.Exit`, so from the perspective of any control plane driving this wrapper (gRPC server `srv.Stop()`, line 88, is never even reached), the runner instance appears to have terminated. Meanwhile the wrapped `gitlab-runner run` process — which holds the runner's registration/auth tokens and continues polling GitLab for and executing jobs across whatever projects it's scoped to — is still alive, having only received (at most) one `SIGTERM` it may not have honored in time. This is a real "shutdown does not reliably free resources" scenario: an operator or orchestrator believing the runner was stopped can leave a live, token-holding runner process running and accepting/serving jobs indefinitely, with no forced-kill safety net.

### Likelihood Explanation
This requires the wrapper deployment mode (`gitlab-runner wrapper`) to be in use, which supervises a full `gitlab-runner run` instance via gRPC — this is a real, reachable code path documented in `commands/wrapper.go` and exercised by `helpers/runner_wrapper/wrapper_test.go`'s `"timeout when waiting for wrapped process termination"` test case (lines 107-125), which already demonstrates `errProcessExitTimeout` is returned while the mock process is never confirmed killed. The remaining precondition — an unprivileged job or executor cleanup step causing the inner `gitlab-runner run` to take >10s to shut down after `SIGTERM` — is plausible but not proven trivially reproducible by a single job alone; it depends on how `commands/multi.go`'s graceful shutdown interacts with in-flight jobs, which was not fully traced in this review.

### Recommendation
- In `terminateWrapper()`, on timeout, escalate to `SIGKILL` (and, if using process groups, kill the entire group: `syscall.Kill(-pgid, syscall.SIGKILL)`) before giving up, and wait/confirm the process actually exits (reap it) prior to returning.
- Do not `os.Exit` in `commands/wrapper.go` on `errProcessExitTimeout` until the forced kill has been attempted and confirmed, so no orphaned, token-holding process is left behind.
- Set `Pdeathsig: syscall.SIGKILL` (Linux) in `commander_unix.go`'s `setProcessGroup` as a defense-in-depth measure so an unexpected wrapper exit doesn't orphan the child.

### Proof of Concept
Extend `helpers/runner_wrapper/wrapper_test.go`'s `"timeout when waiting for wrapped process termination"` case: after `w.terminateWrapper()` returns `errProcessExitTimeout`, assert that `p.Signal` was called with `syscall.SIGKILL` in addition to `SIGTERM` (currently the mock only expects `Signal(syscall.SIGTERM)` once and no `SIGKILL` call exists anywhere in `wrapper.go`/`wrapper_unix.go`, so such an assertion should fail against current code, proving the missing escalation). func (w *Wrapper) terminateWrapper() error {
	w.log.Info("Shutting down wrapper process...")

	err := w.terminateWrappedProcess()
	if err != nil {
		if errors.Is(err, api.ErrProcessNotInitialized) {
			return nil
		}
		return err
	}

	select {
	case err := <-w.errCh:
		w.log.WithError(err).Info("Wrapped application exited")

		return nil

	case <-time.After(w.terminationTimeout):
		return errProcessExitTimeout
	}
}

func (w *Wrapper) terminateWrappedProcess() error {
	w.lock.RLock()
	p := w.process
	w.lock.RUnlock()

	if p == nil {
		w.log.Info("No process to shutdown; exiting")

		return api.ErrProcessNotInitialized
	}

	err := p.Signal(syscall.SIGTERM)
	if err != nil {
		return fmt.Errorf("%w: %w", errFailedToTerminateProcess, err)
	}

	return nil
}
