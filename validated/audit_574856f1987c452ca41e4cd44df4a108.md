### Title
Multisig `DeleteMember`/`DeleteKey` does not purge confirmations a removed member cast on other members' pending requests, letting a request execute below the live-member threshold - ([File: multisig2/src/lib.rs])

### Summary
Both `multisig/src/lib.rs` and `multisig2/src/lib.rs` implement a k-of-n confirmation scheme where a request executes once `confirmations.len() + 1 >= num_confirmations`. When a member/key is removed, the contract only deletes **requests that member originated** — it does not scrub that member's confirmation from **other members' pending requests**. A stale confirmation from a since-removed member therefore continues to count toward the execution threshold, analogous to Olympus's "wall stays active on stale data" bug: state that should have been invalidated (a revoked signer's approval) is trusted as if it were still current.

### Finding Description
In `multisig2/src/lib.rs`, `confirm()` tallies membership approval purely by counting entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set: [1](#0-0) 

Removing a member is handled by `delete_member()`, which only cleans up requests whose *originating* member (`r.member == member`) matches the removed member: [2](#0-1) 

Note the filter `if r.member == member` — this is the request *creator*, not the set of accounts that *confirmed* it. If a removed member had previously called `confirm()` on a request created by someone else, that confirmation entry is never removed. The confirming member's identity is validated only at confirmation time via `current_member()`; there is no re-validation of already-recorded confirmers at execution time: [3](#0-2) 

The identical pattern exists in the original `multisig/src/lib.rs`, where `DeleteKey` only purges requests whose `signer_pk == pk` (the originator), leaving confirmations by that key on other requests intact: [4](#0-3) 

This breaks the binding that should hold: `count(confirmations on request R) == count(live members who approved R)`. Instead, after a member is removed, `count(confirmations on request R)` can include revoked, no-longer-authorized identities, so a request can execute with fewer actually-authorized (live) approvals than `num_confirmations` requires.

### Impact Explanation
This falls under the Critical impact bucket explicitly listed in scope: "a multisig request executed below threshold." A multisig is a custody boundary for arbitrary funds/actions on the account (transfers, key/member management, contract deployment/upgrade — see `execute_request` in [5](#0-4) ). If a pending malicious or now-unwanted request already has confirmations from a member later removed (e.g., because their key was compromised or they left the organization), that confirmation is never revoked. Live members only need to supply `num_confirmations - (stale confirmations)` more approvals to push the request through, effectively lowering the real threshold below the configured `num_confirmations` and allowing funds to move (or keys/members to change) without the intended number of currently-trusted approvers.

### Likelihood Explanation
This requires no privileged access beyond being (or having been) a legitimate multisig member at some point, and no protocol-breaking condition — it is a straightforward, always-reachable code path: any member can confirm a request, then later be removed via a separate `DeleteMember`/`DeleteKey` request (a normal, expected multisig lifecycle event, e.g., offboarding or revoking a compromised key), and the stale confirmation persists automatically. No misconfiguration or deployment-specific assumption is needed; the bug is in the shared contract logic itself.

### Recommendation
When removing a member/key (`delete_member` / `DeleteKey`), iterate over *all* pending requests' confirmation sets (not just requests the member originated) and strip that member's identity from every `confirmations` entry, not just requests they authored. Alternatively, re-validate at `confirm()`/execution time that every entry in the stored confirmation set still corresponds to a current member of `self.members`, discarding stale identities before comparing the count against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `num_confirmations = 3` and members `{A, B, C, D, E}`.
2. Member `A` calls `add_request` to create request `R` (e.g., `Transfer` to an attacker-controlled account, or `AddKey` for an attacker's key).
3. Member `E` (whose key is about to be revoked, e.g. suspected compromised) calls `confirm(R)` — `confirmations[R] = {E}`.
4. The remaining trusted members submit and confirm a separate request to `DeleteMember { member: E }`; `delete_member` runs, but since `E` did not *originate* `R`, `R`'s confirmation set is left untouched: `confirmations[R]` still equals `{E}`.
5. Now only **two** additional live members (say `B` and `C`) need to call `confirm(R)`. On `C`'s confirmation, `confirmations.len() + 1 == 3 >= num_confirmations`, and `execute_request(R)` fires — even though the account whose approval satisfied part of the threshold (`E`) is no longer a member and its authorization was supposed to have been revoked.
6. Result: request `R` executes with the contractual "3 confirmations," but only 2 of those confirmers are still live/trusted members — a multisig request executed below the intended, current-live-member threshold.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(

                    args.into(),
                    deposit.into(),

                    active_requests_limit,

                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
