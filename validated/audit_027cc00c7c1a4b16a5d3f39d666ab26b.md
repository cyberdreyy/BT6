### Title
Cross-user callback confusion via attacker-controlled MessageId collision in savedCallbacks map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The gateway's `savedCallbacks` map is keyed only by the client-supplied `MessageId` (JSON-RPC request `ID`), which is fully attacker-controlled and not bound to sender/signer identity. Two unprivileged users submitting `Message`s with the same `MessageId` will cause the second submission to silently overwrite the first's callback entry, so the victim's callback can be resolved with the DON node response intended to answer the attacker's request (or vice versa).

### Finding Description
In `gateway.ProcessRequest` (`core/services/gateway/gateway.go` lines 218-230), the JSON-RPC request `ID` supplied by the caller is decoded and copied directly into `msg.Body.MessageId` via `g.codec.DecodeJSONRequest(jsonRequest)`, with only a length check (`len(jsonRequest.ID) > 200`) and no uniqueness or ownership validation. This value is entirely attacker-chosen. [1](#0-0) 

That message is passed to `h.HandleLegacyUserMessage`, which stores the pending callback keyed purely by `msg.Body.MessageId`:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
``` [2](#0-1) 

There is no association with the message `Sender`/signer, and no check for an existing in-flight entry before overwrite — the write unconditionally replaces any prior entry under the same key. When a DON node later responds, `handleWebAPITriggerMessage` looks up and deletes the callback solely by `msg.Body.MessageId` and forwards the response to whichever callback is currently stored there:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
``` [3](#0-2) 

Exploit flow: Attacker A observes/predicts victim V's `MessageId` X (e.g., sequential/timestamp-based client IDs, or by eavesdropping/timing an HTTP response before it completes). While V's request for X is in flight (nodes have received it but have not yet responded), A submits a second legacy user message with the same `MessageId` X. `HandleLegacyUserMessage` unconditionally overwrites `h.savedCallbacks[X]` with A's own `callback`. When the DON node responds to whichever request (matched only by `MessageId`, not sender), `handleWebAPITriggerMessage` resolves whatever callback is currently stored under X — which is now A's — delivering V's response data to A, or A's fabricated pending entry captures the node reply meant for V, and V's HTTP request in `gateway.ProcessRequest` blocks and eventually times out via `callback.Wait(ctx)`. Neither the auth/signature check on the incoming message (`common.ValidatedRequestFromMessage`) nor `msg.Validate()` binds `MessageId` uniqueness to `Sender`; they validate message structure/signature only, not the callback-map key collision. [4](#0-3) 

### Impact Explanation
This is a cross-user response/callback confusion (ISOLATION violation): an unprivileged attacker who can supply an arbitrary/colliding `MessageId` can hijack another user's in-flight legacy gateway request/response pairing, potentially receiving a victim's node response data intended only for the victim, or causing the victim to receive attacker-influenced data/timeout. This matches the Chainlink bounty impact class of unauthorized disclosure/request impersonation between users of a shared node/gateway.

### Likelihood Explanation
Exploitability requires only: (1) network access to submit a legacy JSON-RPC message to the gateway's user-facing HTTP endpoint (no privileged credentials needed — `ProcessRequest` is reached by any external caller), and (2) knowledge or a lucky guess of the victim's `MessageId` while the victim's request is still pending (a window bounded by node round-trip time, typically sub-second to a few seconds). Since `MessageId` is client-supplied with no enforced randomness/uniqueness and only a max-length check, if client-side ID generation is predictable (sequential counters, timestamps) or observable, the race is straightforward and repeatable.

### Recommendation
Scope `savedCallbacks` keys by `(Sender, MessageId)` rather than `MessageId` alone, and reject/ignore new `HandleLegacyUserMessage` calls that would collide with an existing unexpired entry for a different sender (return an error instead of silently overwriting). Similarly, validate `msg.Body.Sender` against the stored callback's sender when resolving node responses in `handleWebAPITriggerMessage`.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with two `handlers.Callback` instances (`cbVictim`, `cbAttacker`).
2. Call `h.HandleLegacyUserMessage` with `msg.Body.Sender = "victim"`, `msg.Body.MessageId = "X"`, `callback = cbVictim`.
3. Before invoking the node response, call `h.HandleLegacyUserMessage` again with `msg.Body.Sender = "attacker"`, same `msg.Body.MessageId = "X"`, `callback = cbAttacker`.
4. Assert that `h.savedCallbacks["X"].Callback == cbAttacker` (overwrite occurred), proving `cbVictim` is now orphaned/unreachable.
5. Simulate a node response via `handleWebAPITriggerMessage` with `MessageId = "X"` and assert it is delivered to `cbAttacker`, not `cbVictim`, and that `cbVictim.Wait(ctx)` times out — demonstrating cross-user callback confusion.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
