### Title
Zip legacy extractor performs no path-traversal validation on `zip.File.Name`, allowing archive entries to write files outside the extraction directory - ([File: helpers/archives/zip_extract.go])

### Summary
The legacy zip extraction path (`ziplegacy.extractor.Extract` → `archives.ExtractZipArchive` → `extractZipFile`/`extractZipFileEntry`/`extractZipSymlinkEntry`) writes files using the raw, attacker-controlled `zip.File.Name` value with no `..`/absolute-path/chroot check, unlike the sibling `tarzstd` extractor which explicitly validates `filepath.Abs(filepath.Join(e.dir, hdr.Name))` stays within `e.dir`. The `dir` field passed into `ziplegacy.NewExtractor` is stored but never used by `Extract`, so extraction is entirely dependent on the process's current working directory and the unchecked entry name.

### Finding Description
`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`'s `extractor.Extract` (lines 26-32) calls `archives.ExtractZipArchive(zr)` and never references `e.dir` anywhere in the function body — the directory the caller intended to sandbox extraction to is silently discarded. [1](#0-0) 

In `helpers/archives/zip_extract.go`, `ExtractZipArchive` iterates `archive.File` and only checks for a `.git` directory name via `errorIfGitDirectory`; it performs no path traversal or containment check before calling `extractZipFile`. [2](#0-1) 

`extractZipFile` uses `file.Name` directly to `os.MkdirAll(filepath.Dir(file.Name), 0o777)`, and dispatches to `extractZipDirectoryEntry` (`os.Mkdir(file.Name, ...)`), `extractZipSymlinkEntry` (`os.Symlink(data, file.Name)` after `os.Remove(file.Name)`), or `extractZipFileEntry` (`os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` after `os.Remove(file.Name)`) — all operating on the raw, unsanitized `file.Name`. [3](#0-2) [4](#0-3) 

By contrast, the `tarzstd` extractor explicitly resolves the target path against its `dir` and rejects any header whose resolved path escapes that root: `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name)); if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir { return fmt.Errorf(...cannot be extracted outside of chroot...) }`. [5](#0-4) 

The `path_error_tracker.go`/`path_check_helper.go` machinery referenced in the question only implements `errorIfGitDirectory` (suppressing `.git` path warnings) and a repeated-error-suppression tracker — neither performs any containment/traversal validation. [6](#0-5) 

So a zip entry with `Name` such as `../../../some/other/path` (or an absolute path) that reaches `archives.ExtractZipArchive` via the legacy zip codepath is written verbatim relative to the process CWD, with nothing preventing it from escaping the intended extraction root.

### Impact Explanation
If reached, this allows a job that controls the content of a cache/artifact zip archive to write or overwrite arbitrary files reachable from the runner process's working directory/privileges (subject to OS file permissions), which is a classic zip-slip path-traversal bug. That said, I could not confirm from available context that the extraction destination is ever within reach of another job's session/terminal state files on a shared host, nor could I confirm the precise precondition under which the runner "falls back" to the legacy zip codepath for a "corrupt/legacy zip" (I found no fallback-selection logic in the indexed code — `ziplegacy` appears to be a format-registered extractor selected via `archive.NewExtractor(archive.Zip, ...)`, not an automatic fallback triggered on corruption). Without verifying (a) that this codepath is actually reachable for cache/artifact extraction in a normal job flow, and (b) that the runner process's CWD/session files are the same directory tree the zip-slip could reach, the "cross-job session/terminal hijack" portion of the scoped impact is unconfirmed speculation.

### Likelihood Explanation
The code-level weakness (missing path validation in `zip_extract.go`, unused `dir` field in `ziplegacy`) is real and verifiable in the current source, and is inconsistent with the more defensive `tarzstd` extractor in the same package family. However I was unable to locate the actual call site that decides to use `ziplegacy.NewExtractor` for a job's cache/artifact download (only test files reference `ziplegacy.NewExtractor`/`archive.NewExtractor` directly with `Zip` format via `commands/helpers/archiver.go`), so I cannot confirm this is genuinely reachable from an unprivileged job's cache/artifact download without falling back on a corrupted-archive precondition. Given index size limits, I was not able to fully trace `commands/helpers/archiver.go` and `cache_extractor.go` call graphs to confirm the "fallback for corrupt/legacy zip" precondition described in the question, or to confirm what the process CWD is set to at extraction time.

### Recommendation
Add explicit path-containment validation to `helpers/archives/zip_extract.go`'s `extractZipFile` (and callers), mirroring `tarzstd_extractor.go`'s approach: resolve each `file.Name` against the intended extraction root with `filepath.Abs(filepath.Join(dir, file.Name))` and reject entries whose resolved path is not prefixed by `dir` (also rejecting absolute names and symlink targets that would escape the root). Additionally, wire the currently-unused `dir` field in `ziplegacy.extractor.Extract` through to `ExtractZipArchive` so extraction is actually confined to the intended directory rather than relying on process CWD.

### Proof of Concept
Go unit test targeting `helpers/archives/zip_extract.go`:
```go
func TestExtractZipArchive_RejectsPathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    // build an in-memory zip with a malicious entry name
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    f, _ := zw.Create("../../../etc/passwd_overwrite_test")
    f.Write([]byte("pwned"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    wd, _ := os.Getwd()
    os.Chdir(tmpDir)
    defer os.Chdir(wd)

    err := archives.ExtractZipArchive(zr)

    // Expected (secure) behavior: err != nil, and file not created outside tmpDir
    escapedPath := filepath.Join(filepath.Dir(filepath.Dir(filepath.Dir(tmpDir))), "etc/passwd_overwrite_test")
    _, statErr := os.Stat(escapedPath)
    assert.True(t, os.IsNotExist(statErr), "file should not have escaped extraction root")
}
```
This test currently would fail (file gets written outside the intended root) against the current implementation, demonstrating the missing containment check — confirming the code-level flaw described. Full confirmation of the "session/terminal hijack" scoped impact would additionally require an integration test showing (1) the legacy zip codepath is actually selected for job cache/artifact extraction under some condition, and (2) the CWD/extraction root at that time is on a path shared with another job's session state — neither of which I could verify from the available index.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
