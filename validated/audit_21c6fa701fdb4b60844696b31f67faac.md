### Title
`lending_pool_handle_bankruptcy` determines bankruptcy eligibility using stale, non-interest-accrued share values - ([File: programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs])

### Summary
`lending_pool_handle_bankruptcy` calls `check_account_bankrupt` — which values every active balance on the account using each bank's currently-stored `asset_share_value` / `liability_share_value` — *before* calling `bank.accrue_interest()` on the target bank. Because interest accrual only increases share values over time, the bankruptcy determination can be made on stale numbers, exactly the same "decision-before-sync" bug class as `ArmadaWindDown::triggerWindDown` reading `recognizedRevenueUsd` before `syncStablecoinRevenue`.

### Finding Description
`check_account_bankrupt` is invoked at the very start of the handler, before any interest is accrued: [1](#0-0) 

Internally it calls `get_health_components`, which for each active balance computes value via `bank.get_liability_amount()` / `bank.get_asset_amount()` — a straight multiplication of stored shares by the bank's currently cached `liability_share_value` / `asset_share_value`: [2](#0-1) 

`check_account_bankrupt` itself just compares these values against `BANKRUPT_THRESHOLD`, with no interest accrual step: [3](#0-2) 

Only *after* this bankruptcy determination has already passed does the handler accrue interest, and only for the single `bank_loader` bank involved in this specific liability, not for the other banks backing the account's collateral positions that were used inside `check_account_bankrupt`'s asset/liability valuation: [4](#0-3) 

The docs explicitly acknowledge that share values go stale between interactions: "Interest accumulates when any transaction that changes funds occurs... banks without much activity may have stale numbers until someone interacts with them." [5](#0-4) 

Since interest accrual is monotonic (it only ever increases `asset_share_value`/`liability_share_value`, never decreases them — enforced as an invariant in the fuzz suite), using stale, un-accrued values for the collateral side of the health computation understates the account's true asset value at the moment of the check. This can cause the equity-based bankruptcy test (`equity_liabs > equity_assets`, `equity_assets < BANKRUPT_THRESHOLD`) to pass when, after properly accruing interest on the collateral banks, the account would not actually be bankrupt. [6](#0-5) 

### Impact Explanation
When `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set on a bank, this instruction is callable by anyone, without admin/risk-admin authorization: [7](#0-6) 

A permissionless caller could trigger `lending_pool_handle_bankruptcy` against an account whose true (accrued) collateral value would keep it solvent, but whose stale, cached collateral value makes it appear bankrupt. The consequences are irreversible and financially damaging:
- Insurance fund is drawn down to cover the (possibly illusory) bad debt. [8](#0-7) 
- Any shortfall is socialized across all other depositors in the liability bank via `socialize_loss`, permanently reducing their `asset_share_value`. [9](#0-8) 
- In the worst case (super-bankruptcy), the bank is permanently killed, wiping out all other depositors' holdings — a state documented as irrecoverable. [10](#0-9) 
- The account is also flagged `ACCOUNT_DISABLED` and `has_been_bankrupted`, a permanent, non-reversible state change. [11](#0-10) 

### Likelihood Explanation
This requires: (1) a bank with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` enabled (an admin-controlled but intentionally permissionless path, per design — see BANKRUPTCY.md), and (2) an account whose collateral-side bank(s) have accumulated enough un-accrued interest since their last touch that the "true" accrued value would push equity assets above the bankrupt threshold or above liabilities. Given the docs' own admission that "banks without much activity may have stale numbers until someone interacts with them," this condition is plausible for idle collateral banks, and the trigger requires no special privilege once the permissionless flag is set. This is a lower-severity variant of the report (it narrows, rather than eliminates, an admin-gated safety net) since admin/risk-admin-gated banks are unaffected, but it is a concrete, reachable path for permissionless banks.

### Recommendation
In `lending_pool_handle_bankruptcy`, accrue interest on all banks relevant to the account's active balances (or at minimum require/force a fresh `pulse_health`/accrual pass) *before* calling `check_account_bankrupt`, mirroring the order used in `lending_account_liquidate` where interest should be accrued ahead of the pre-liquidation health check. Alternatively, restrict `check_account_bankrupt` to only run against banks whose `last_update` is recent (e.g., require a same-transaction `accrue_interest`/`pulse_health` on every bank contributing to the health computation), so bankruptcy cannot be certified against stale collateral valuations.

### Proof of Concept
Conceptual reproduction (cannot be executed without a live test harness):
1. User deposits collateral into Bank A (a low-activity/low-utilization bank whose `last_update` is old) and borrows from Bank B, which has `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` set.
2. Time passes; Bank A's `asset_share_value` has not been accrued (no deposits/withdrawals/borrows have touched it), so `bank.asset_share_value` under-represents the collateral's true present value versus what it would be if `accrue_interest` were run.
3. Due to a price move or accumulated interest on the Bank B liability, the account's equity computed from `check_account_bankrupt` (using Bank A's stale `asset_share_value`) shows `equity_assets < BANKRUPT_THRESHOLD` and `equity_liabs > equity_assets`.
4. An unprivileged caller invokes `lending_pool_handle_bankruptcy` on Bank B. `check_account_bankrupt` passes (line 80) before `bank.accrue_interest()` is ever called for Bank B (line 102) — and Bank A is never accrued at all in this instruction.
5. The insurance fund is drawn and/or the loss is socialized onto Bank B's other depositors, even though, had Bank A's true accrued collateral value been used, the account might not have met the bankruptcy criteria.

This PoC cannot be fully validated without running the actual test suite/harness; a Devin session with repository access would be needed to instrument `check_account_bankrupt` calls with pre/post accrual to confirm the magnitude of drift achievable in practice.

    /// Socialize a loss of `loss_amount` among depositors, the `total_deposit_shares` stays the
    /// same, but total value of deposits is reduced by `loss_amount`;
    ///
    /// In cases where assets < liabilities, the asset share value will be set to zero, but cannot
    /// go negative. Effectively, depositors forfeit their entire deposit AND all earned interest in
    /// this case.
    fn socialize_loss(&mut self, loss_amount: I80F48) -> MarginfiResult<bool> {
        let mut kill_bank = false;
        let total_asset_shares: I80F48 = self.total_asset_shares.into();
        let old_asset_share_value: I80F48 = self.asset_share_value.into();

        // Compute total "old" value of shares
        let total_value: I80F48 = total_asset_shares
            .checked_mul(old_asset_share_value)
            .ok_or_else(math_error!())?;

        // Subtract loss, clamping at zero (i.e. assets < liabilities, the bank is wiped out)
        if total_value <= loss_amount {
            self.asset_share_value = I80F48::ZERO.into();
            // This state is irrecoverable, the bank is dead.
            kill_bank = true;
        } else {
            // otherwise subtract then redistribute
            let new_share_value: I80F48 = (total_value - loss_amount)
                .checked_div(total_asset_shares)
                .ok_or_else(math_error!())?;
            self.asset_share_value = new_share_value.into();
            // Sanity check: should be unreachable.
            if new_share_value == I80F48::ZERO {
                kill_bank = true;
            }
        }

        Ok(kill_bank)
    }

pub fn check_account_bankrupt<'info>(
    marginfi_account: &MarginfiAccount,
    remaining_ais: &'info [AccountInfo<'info>],
    health_cache: &mut Option<&mut HealthCache>,
) -> MarginfiResult {
    // TODO remove this check here and raise it to the top-level instruction
    check!(
        !marginfi_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    let (equity_assets, equity_liabs) = get_health_components(
        marginfi_account,
        remaining_ais,
        RequirementType::Equity,
        health_cache,
        HealthPriceMode::Live { liq_cache: None },
    )?;

    let has_liabilities = equity_liabs > I80F48::ZERO;
    let below_bankruptcy_threshold = equity_assets < BANKRUPT_THRESHOLD;
    let liabilities_exceed_assets = equity_liabs > equity_assets;
    let is_bankrupt = has_liabilities && below_bankruptcy_threshold && liabilities_exceed_assets;

    if !is_bankrupt {
        return err!(MarginfiError::AccountNotBankrupt);
    }

    Ok(())
}

/// Per-bank directional invariants:
///
/// * `liability_share_value` is strictly monotonic — interest accrual only
///   grows it. No marginfi codepath writes it down.
/// * `asset_share_value` is monotonic *unless* a `handle_bankruptcy` ix
///   has succeeded on this bank (socialised loss reduces it).
/// * All three fee buckets (group / insurance / program) are monotonic
///   until a `withdraw_fees` ix runs — which the harness never invokes,
///   so the buckets must only grow.
pub fn assert_bank_directional_invariants(
    trident: &mut Trident,
    bank_pks: &[Pubkey],
    baselines: &HashMap<Pubkey, BankBaseline>,
    banks_with_bankruptcy: &HashSet<Pubkey>,
) {
    for &pk in bank_pks {
        let bank = trident
            .get_account_with_type::<Bank>(&pk, None)
            .expect("bank must deserialize");
        let base = baselines.get(&pk).expect("baseline missing for bank");

        let asset_share_value = from_wrapped(bank.asset_share_value.value);
        let liability_share_value = from_wrapped(bank.liability_share_value.value);

        invariant!(
            liability_share_value >= base.liability_share_value,
            "bank {pk} liability_share_value regressed: baseline {}, current {}",
            base.liability_share_value,
            liability_share_value
        );
