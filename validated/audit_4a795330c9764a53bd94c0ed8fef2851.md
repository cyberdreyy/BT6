### Title
Stale confirmations from deleted multisig members allow a request to execute below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`multisig2`'s `delete_member` only purges confirmations/requests for which the *removed* member was the original creator, but it never scans the `confirmations` set of *other* requests to remove that member's confirmations recorded via `confirm()`. This lets a phantom confirmation from a no-longer-valid member persist and count toward `num_confirmations`, letting a request execute with fewer live-member approvals than the configured threshold — the same "stale reference to a revoked entity" root cause as the elevation-group mismatch in the report, but here it breaks the confirmations-vs-live-members custody binding instead of causing a DoS.

### Finding Description
`confirm()` tracks approvals in a per-request `HashSet<String>` of member identifiers and executes the request once `confirmations.len() as u32 + 1 >= self.num_confirmations`: [1](#0-0) 

When a member is removed via `MultiSigRequestAction::DeleteMember`, `delete_member` is invoked: [2](#0-1) 

It filters and clears requests where `r.member == member` — i.e., only requests that member *created* — and clears `num_requests_pk` for that member. It does **not** iterate `self.confirmations` to strip that member's confirmation from requests they merely *confirmed* (but did not create). Since `current_member()` derives identity from `members` at call time, once removed the member can no longer be counted as a "live" confirmer for new confirmations — but their prior confirmation entry, stored as a plain string in an unrelated request's `confirmations` set, is never invalidated: [3](#0-2) 

Consequently, the invariant "`confirmations.len()` == number of currently-valid members who approved" silently diverges from reality: a removed member's stale approval keeps counting toward `num_confirmations` for any request they confirmed before being removed but did not create.

### Impact Explanation
This is exactly the Critical impact category "a multisig request executed below threshold": remaining members can push a pending request over the nominal `num_confirmations` count using a phantom approval from someone no longer entitled to approve anything, executing transfers/`DeployContract`/`AddKey`/`FunctionCall` actions with effectively fewer live signers than the contract's stated K-of-N policy guarantees. This directly threatens custody of the multisig account's funds and control, since the threshold is the sole authorization boundary for `Transfer`, `AddKey`, and `DeployContract` actions.

### Likelihood Explanation
The scenario requires only routine multisig lifecycle operations that are common in practice: a member (e.g., an employee leaving, or a rotated signer) confirms one or more pending requests, and is later removed via a normal `DeleteMember` governance action before those requests are otherwise resolved. No victim key theft, no foundation privilege, and no code beyond ordinary member turnover is needed — this is a realistic operational sequence rather than a contrived edge case.

### Recommendation
When executing `DeleteMember`, iterate all pending requests' `confirmations` sets (not just requests created by the removed member) and strip the removed member's identifier from each, so the invariant `confirmations ⊆ current members` is always preserved. Alternatively, re-validate at `confirm()`/execution time that every counted confirmer is still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Multisig initialized with members `{A, B, C, D}` and `num_confirmations = 3`.
2. Member `B` creates request `R` (`add_request`); `B`'s confirmation is recorded automatically via `add_request_and_confirm`, or `A` creates `R` and `B` calls `confirm(R)` — either way `confirmations[R] = {B}` (or `{A, B}`).
3. Governance later removes `B` via a properly-confirmed `DeleteMember { B }` request. `delete_member` only clears requests where `r.member == B` (i.e., requests `B` created) — since `R` was created by `A`, `R`'s `confirmations` entry still contains `B`.
4. Members set is now `{A, C, D}`, `num_confirmations` still `3`. `C` calls `confirm(R)`: `confirmations.len()` is `2` (`A`, `B`), `+1 = 3 >= 3` → `execute_request(R)` fires, even though only two currently-valid members (`A`, `C`) actually authorized it — one fewer than the configured `3`-of-`N` threshold requires.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
