### Title
Zip-slip in legacy zip extractor allows cache-archive path traversal outside job working directory - (File: helpers/archives/zip_extract.go)

### Summary
The legacy Zip extractor (`ziplegacy`), which is registered as the default handler for `archive.Zip`/`archive.ZipZstd` and is reachable from `CacheExtractorCommand.Execute`, extracts every zip entry using the raw, attacker-controlled `zip.File.Name` with no path sanitization, unlike the `tarzstd` extractor which validates each resolved path stays under the target directory. A pipeline author who can poison/control cache archive contents and force use of this extractor (e.g. via the `FF_USE_FASTZIP` feature-flag CI variable) can write files anywhere the runner helper process can reach on the host filesystem.

### Finding Description
`CacheExtractorCommand.Execute` downloads the cache archive and dispatches to `archive.NewExtractor(format, f, size, wd)`, which for `archive.Zip`/`archive.ZipZstd` resolves to whichever extractor is currently registered. [1](#0-0) 

By default `ziplegacy` self-registers both formats: [2](#0-1) 

`fastzip` only overrides this registration when the `FF_USE_FASTZIP` feature flag is enabled: [3](#0-2) 

Runner feature flags such as `FF_USE_FASTZIP` can be toggled per-job via standard `variables:` in `.gitlab-ci.yml`, which is attacker-controlled (pipeline author) input — no admin action required. Setting `FF_USE_FASTZIP: "false"` forces the vulnerable legacy path to be selected for cache extraction.

The `ziplegacy` extractor's `Extract` simply calls `archives.ExtractZipArchive(zr)`, discarding the `dir`/`wd` parameter entirely — it is never used to constrain or join paths: [4](#0-3) 

`ExtractZipArchive` iterates entries and calls `extractZipFile(file)` using `file.Name` verbatim: [5](#0-4) 

`extractZipFile` creates parent directories with `os.MkdirAll(filepath.Dir(file.Name), ...)` and then, depending on entry type, calls `extractZipFileEntry` (which does `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)`) or `extractZipSymlinkEntry` (which does `os.Symlink(target, file.Name)`) — none of these validate that `file.Name` resolves within the working directory: [6](#0-5) 

Compare this to the `tarzstd` extractor, which explicitly computes an absolute path and rejects any entry escaping `e.dir`: [7](#0-6) 

No equivalent check exists anywhere in `helpers/archives/zip_extract.go`. A zip entry named `../../etc/cron.d/x` (or an absolute path such as `/etc/cron.d/x`) will resolve relative to the process's current working directory (the job's `wd`, since `Execute` operates from `wd` obtained via `os.Getwd()`), letting `../../` segments walk out of the workspace onto arbitrary host paths reachable by the runner/helper process.

### Impact Explanation
An unprivileged CI job that can poison the contents of a cache object it (or a colliding/guessable cache key) controls can cause the runner helper process, while extracting that cache, to create/overwrite arbitrary files (or symlinks) outside the job workspace — e.g. `/etc/cron.d/*`, shell profile files, or other paths writable by the process user — leading to potential remote code execution on the runner/helper host, matching the scoped impact.

### Likelihood Explanation
Preconditions are consistent with an unprivileged attacker: (1) ability to place/overwrite the cache object at a resolved cache key (documented precondition of cross-project/shared-cache poisoning, or a race against a legitimate upload), and (2) ability to force selection of the vulnerable legacy extractor by setting the `FF_USE_FASTZIP` CI variable to `false` for the job — a standard, documented feature-flag override mechanism available to any pipeline author. Both actions are fully within normal pipeline-author capability; no admin or infrastructure compromise is required. The bug is deterministic and repeatable — any crafted zip with `../` or absolute-path entry names will reproduce it every time the legacy extractor runs.

### Recommendation
Add path validation identical to the `tarzstd` extractor's check inside `extractZipFile`/`ExtractZipArchive` (or thread the target `dir` through `ziplegacy.extractor.Extract` and validate each resolved `filepath.Join(dir, entry.Name)` stays under `dir` with `filepath.Abs` + `strings.HasPrefix`), rejecting entries with `..` traversal or absolute paths before creating directories, files, or symlinks. Apply the same fix to `extractZipSymlinkEntry`'s target (symlink destination) validation as well.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build a zip archive containing a single entry named `../evil.txt` (or `/tmp/evil.txt` / a deeply nested `"../../etc/cron.d/x"`).
2. In a `t.TempDir()`, `os.Chdir` into a subdirectory `workspace` under the temp dir.
3. Call `archives.ExtractZipFile(archivePath)` (as used transitively by `ziplegacy.extractor.Extract`).
4. Assert `os.Stat(filepath.Join(tempDir, "evil.txt"))` (i.e., outside `workspace`) exists — proving escape — and assert no equivalent file exists solely inside `workspace`.
5. Contrast with an identical test using `tarzstd.NewExtractor`/`fastzip.NewExtractor`, asserting `Extract` returns an error containing `"cannot be extracted outside of chroot"`, confirming the disparity between extractors.

Additionally, add a fuzz test over zip entry names feeding `extractZipFile` with `../`-prefixed and absolute-path names, asserting the resulting file always lies under the configured extraction root.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
