### Title
Vault/HTTP-Trigger JWT replay protection is in-memory-only, allowing duplicate/cross-instance replay of the same signed trigger request - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The reported Beanstalk bug is a replay-attack class issue: a signed authorization message is accepted more than once because its verification does not bind it to a single, unique execution context (there `chainId`; here, the state of the specific service instance that is supposed to consume it exactly once). The Chainlink Gateway's HTTP-trigger authorization path (`WorkflowMetadataHandler.Authorize`) has the analogous root cause: the anti-replay check for a workflow-execution JWT is enforced only via an in-process, unpersisted map (`jwtReplayCache`), so the same valid signed request can be replayed against any other Gateway process instance (or the same instance after a restart) that shares the workflow's authorized keys, causing duplicate unauthorized workflow executions.

### Finding Description
`WorkflowMetadataHandler.Authorize` verifies an incoming HTTP-trigger JWT via `utils.VerifyRequestJWT`, which checks the signature, expiry, and that the JWT's digest claim matches the request body's digest [1](#0-0) . It then checks the JWT ID (`jti`) against a replay cache, and if not seen, records it and authorizes the request based solely on `workflowID` + recovered signer address:

```
if h.jwtCache.isReplay(claims.ID) { ... }
...
h.jwtCache.recordUsage(claims.ID)
``` [2](#0-1) 

The `jwtReplayCache` is a purely in-memory, process-local structure (`sync.RWMutex` + `map[string]time.Time`), constructed once per `WorkflowMetadataHandler` instance with no external/shared persistence (no DB, no distributed cache) [3](#0-2) [4](#0-3) .

Nothing in the signed JWT (digest, `jti`, `iss`, `exp`, `iat`) binds the token to a specific Gateway node instance, DON, or persisted authorization ledger — it only proves "this request+payload was once signed by the workflow owner's key." Just as Beanstalk's `verifySignature` omitted `chainId`, allowing the same signature to be replayed on any deployment of the same contract, here the JWT/replay design omits any binding to a durable, shared record of "already consumed," allowing the exact same signed trigger message to be independently accepted by:
- Any other horizontally-scaled Gateway process (a common HA deployment pattern for the CRE Gateway, evidenced by the multi-shard, multi-DON architecture built into this same handler [5](#0-4) ), or
- The same process after a restart (in-memory cache is wiped).

This differs from the Vault gateway's request authorization, which explicitly separates persisted allowlisting (on-chain, via `workflowRegistrySyncer`) from a dedicated `RequestReplayGuard` [6](#0-5)  — but that guard is *also* only in-process memory, so the same class of gap exists there too, just with a smaller blast radius since Vault authorization is generally additionally scoped to specific request digests that are pre-registered on-chain with an explicit single-use intention.

### Impact Explanation
An unprivileged client that can observe or intercept one valid, signed `workflow.execute`-style HTTP trigger JWT (e.g., from a compromised transport hop, logging, or by simply being the original sender replaying it deliberately) can resubmit the identical request to trigger duplicate, unauthorized execution of the target workflow — because the "already used" check does not survive across Gateway process instances or restarts. In a production Gateway deployment running multiple redundant nodes/pods for availability (which the DON×shard architecture explicitly anticipates), this materially increases the likelihood of successful duplicate submission, since the attacker/duplicate-sender only needs to reach a different instance than the one that first processed the request. This can result in unintended duplicate workflow runs (unauthorized job run), which is especially harmful for workflows with side effects (fund movement, external state mutation).

### Likelihood Explanation
Exploitation requires only network-level access to resend an already-issued, still-unexpired JWT+request pair to the Gateway's public HTTP endpoint — no privileged credentials beyond what the original legitimate submitter already had. The likelihood of the replay window being exploitable scales directly with normal HA deployment practices (multiple Gateway instances) and any Gateway restarts within the JWT's validity window, both of which are expected operational conditions rather than edge cases.

### Recommendation
Move JWT/request replay tracking out of process-local memory into a durable, shared store (e.g., the same database/allowlist backing used for Vault's on-chain allowlisting, or a shared cache like Redis) keyed by `jti` (or request digest) with TTL matching the JWT's `exp`, so that "already consumed" state is consistent across all Gateway instances and survives restarts. Alternatively/additionally, bind the JWT explicitly to a specific `donID`/instance identifier as part of the signed claims (mirroring the Beanstalk fix of adding `chainId`), and reject tokens whose bound identifier doesn't match the serving instance, ensuring a token can only ever be legitimately consumed once in a well-defined trust domain.

### Proof of Concept
1. Client signs and submits a valid HTTP-trigger JWT (`workflow.execute`) with `jti = X` to Gateway instance A; `A.jwtCache` records `X` as used, and the workflow executes once.
2. Attacker (or the original client) resends the exact same JSON-RPC request + JWT to Gateway instance B (a different horizontally-scaled replica of the same Gateway service, or the same instance A after a routine restart).
3. `WorkflowMetadataHandler.Authorize` on instance B calls `h.jwtCache.isReplay(claims.ID)` against its own empty/fresh in-memory cache [7](#0-6) , finds no record of `jti = X`, and authorizes the request again, causing the DON to execute the workflow a second time from a single originally-authorized signature.

		metrics:         metrics,
		jwtCache:        newJWTReplayCache(time.Duration(cfg.JWTReplayPeriodMs) * time.Millisecond),
	}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
```

type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
