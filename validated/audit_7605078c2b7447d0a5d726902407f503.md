### Title
Single-signature `getTransaction` via BigTable path decodes and scans the entire block, making per-request cost proportional to block size - ([File: storage-bigtable/src/lib.rs])

### Finding Description
When `bigtable_ledger_storage` is enabled and a transaction isn't found in the local blockstore, `JsonRpcRequestProcessor::get_transaction` falls back to `bigtable_ledger_storage.get_confirmed_transaction(&signature)`. [1](#0-0) 

`LedgerStorage::get_confirmed_transaction` first reads a small `TransactionInfo{slot, index}` record from the `tx` table, and then calls `self.get_confirmed_block(slot)` to fetch and fully decode the entire block from the `blocks` table before indexing into it with `.nth(index as usize)`: [2](#0-1) 

`get_confirmed_block` fetches the whole block cell and deserializes it as either bincode or protobuf (`generated::ConfirmedBlock` → `ConfirmedBlock`), decoding every transaction, every instruction, and every account key in the block, not just the one requested: [3](#0-2) 

There is no size-based guard, no partial/streaming decode, and no per-transaction extraction path that avoids materializing the full block. The only bound on the amount of work is the on-chain block size itself, which is attacker-influenced: an attacker can construct their own transaction(s) to occupy a maximally sized block (up to the runtime's block size/entry limits), and then issue a single `getTransaction` call to force the validator's JSON-RPC process to decompress and deserialize that entire block just to answer for one signature.

This differs qualitatively from the local blockstore path, which uses `blockstore.get_complete_transaction`/`get_rooted_transaction` to fetch a transaction directly by signature without deserializing full blocks. The BigTable fallback path lacks this precision.

### Impact Explanation
A single low-rate `getTransaction` RPC call (well within the "one call per `CLUSTER_SLOT_TIME_TARGET / 2`" allowance) triggers CPU (protobuf/bincode decode of an entire block) and memory (materializing all transactions of that block) work proportional to total block size rather than the single requested transaction. This is an unbounded-cost-for-a-single-low-rate-call condition against the RPC process (not consensus), matching the "RPC DoS from a single client at ≤1 call per slot-time" bounty category since the cost is attacker-controlled via on-chain data size while remaining a single call.

### Likelihood Explanation
Precondition is that the validator operator has enabled `bigtable_ledger_storage` (a common configuration for RPC nodes serving historical data) and that the requested transaction is not present in the live blockstore (i.e., it is historical). An attacker only needs to have previously landed a transaction inside a maximally-packed block (achievable as an ordinary unprivileged transaction sender) and then issue one `getTransaction` call for that signature. This is fully repeatable for any historical signature in a large block and requires no special privileges beyond normal transaction submission and RPC access.

### Recommendation
Avoid materializing the whole block to satisfy a single-transaction lookup:
- Store transactions individually (or with an index into a partial byte range) so a `getTransaction`-by-signature lookup can fetch/decode just the target transaction bytes.
- Alternatively, when decoding the block protobuf, use a streaming/partial-decode API that stops once the target transaction index has been decoded and released, rather than fully materializing every transaction.
- Add explicit cost accounting/limits in `LedgerStorage::get_confirmed_transaction` (e.g., cap decode CPU/time or block size handled per single-transaction request) so cost is bounded independent of block size.

```rust
// storage-bigtable/tests/get_transaction_cost_scaling.rs
#[tokio::test]
async fn get_transaction_cost_independent_of_block_size() {
    let ledger_storage = LedgerStorage::new_for_test(/* emulator config */).await;

    // 1. Upload a "minimal" block containing exactly one transaction (target_sig_small).
    let small_block = build_confirmed_block_with_n_transactions(1);
    let target_sig_small = small_block.transactions[0].transaction_signature();
    ledger_storage.upload_confirmed_block(100, small_block).await.unwrap();

    // 2. Upload a "maximal" block containing many transactions/instructions
    //    (e.g. thousands of max-size transactions), with the target as one of them.
    let large_block = build_confirmed_block_with_n_transactions(MAX_TXS_PER_BLOCK);
    let target_sig_large = large_block.transactions[0].transaction_signature();
    ledger_storage.upload_confirmed_block(200, large_block).await.unwrap();

    // 3. Measure latency/allocations for get_confirmed_transaction on each signature.
    let t0 = Instant::now();
    ledger_storage.get_confirmed_transaction(&target_sig_small).await.unwrap();
    let small_elapsed = t0.elapsed();

    let t1 = Instant::now();
    ledger_storage.get_confirmed_transaction(&target_sig_large).await.unwrap();
    let large_elapsed = t1.elapsed();

    // Expected (vulnerable) result: large_elapsed >> small_elapsed, scaling with
    // block size rather than being roughly constant, demonstrating unbounded
    // per-single-request cost.
    assert!(
        large_elapsed.as_millis() < small_elapsed.as_millis() * 2,
        "get_confirmed_transaction cost scaled with block size: small={small_elapsed:?} large={large_elapsed:?}"
    );
}
```

```rust
    /// Fetch the confirmed block from the desired slot
    pub async fn get_confirmed_block(&self, slot: Slot) -> Result<ConfirmedBlock> {
        trace!("LedgerStorage::get_confirmed_block request received: {slot:?}");
        self.stats.increment_num_blocks_table_reads();
        let mut bigtable = self.connection.client();

        let block_cell_data = bigtable
            .get_protobuf_or_bincode_cell::<StoredConfirmedBlock, generated::ConfirmedBlock>(
                BLOCKS_TABLE_NAME,
                slot_to_blocks_key(slot),
            )
            .await
            .map_err(|err| match err {
                bigtable::Error::RowNotFound => Error::BlockNotFound(slot),
                _ => err.into(),
            })?;
        Ok(match block_cell_data {
            bigtable::CellData::Bincode(block) => block.into(),
            bigtable::CellData::Protobuf(block) => block.try_into().map_err(|_err| {
                bigtable::Error::ObjectCorrupt(format!("blocks/{}", slot_to_blocks_key(slot)))
            })?,
        })
    }
```

```rust
    /// Fetch a confirmed transaction
    pub async fn get_confirmed_transaction(
        &self,
        signature: &Signature,
    ) -> Result<Option<ConfirmedTransactionWithStatusMeta>> {
        trace!("LedgerStorage::get_confirmed_transaction request received: {signature:?}");
        self.stats.increment_num_tx_table_reads();
        let mut bigtable = self.connection.client();

        // Figure out which block the transaction is located in
        let TransactionInfo { slot, index, .. } = bigtable
            .get_bincode_cell(TX_TABLE_NAME, signature.to_string())
            .await
            .map_err(|err| match err {
                bigtable::Error::RowNotFound => Error::SignatureNotFound(*signature),
                _ => err.into(),
            })?;

        // Load the block and return the transaction
        let block = self.get_confirmed_block(slot).await?;
        match block.transactions.into_iter().nth(index as usize) {
            None => {
                // report this somewhere actionable?
                warn!("Transaction info for {signature} is corrupt");
                Ok(None)
            }
            Some(tx_with_meta) => {
                if tx_with_meta.transaction_signature() != signature {
                    warn!("Transaction info or confirmed block for {signature} is corrupt");
                    Ok(None)
                } else {
                    Ok(Some(ConfirmedTransactionWithStatusMeta {
                        slot,
                        tx_with_meta,
                        block_time: block.block_time,
                        index,
                    }))
                }
            }
        }
    }
```
