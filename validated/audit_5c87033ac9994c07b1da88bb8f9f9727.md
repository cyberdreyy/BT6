### Title
Stale confirmations from removed multisig members are still counted toward `num_confirmations`, allowing a request to execute below the live-member quorum - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` counts entries already present in a request's `confirmations: HashSet<String>` toward the `num_confirmations` threshold without verifying that every recorded confirmer is still a current member. `delete_member` only purges requests and confirmations for requests that the removed member originally *submitted*; it never removes that member's confirmation entries from other pending requests they had merely *confirmed*. This lets a request be executed using a mix of live and stale (removed-member) confirmations, satisfying the numeric threshold with fewer than `num_confirmations` live members actually agreeing.

### Finding Description
`confirm` in `multisig2/src/lib.rs` reads the existing confirmation set for a request and, once the count (including the new confirmer) reaches `num_confirmations`, executes it: [1](#0-0) 

Membership removal is handled by `delete_member`, which only cleans up requests where `r.member == member` (i.e., requests *submitted* by that member) and removes `num_requests_pk` for that member, then deletes the member from `self.members`: [2](#0-1) 

There is no scan of `self.confirmations` for entries where the removed member appears as a *confirmer* on requests submitted by someone else. As a result, if member A confirms a pending request submitted by B, and A is later removed from `self.members` via a separate `DeleteMember` request, the pending request's confirmation set still contains A's stale entry. `confirm`'s quorum check in the snippet above only checks `confirmations.contains(&member.to_string())` to prevent double-confirmation by the *current* caller - it never re-validates that previously recorded confirmers in the `HashSet<String>` are still in `self.members`. So a single live confirmation added afterward can push `confirmations.len() + 1 >= num_confirmations`, executing the request with one live confirmation plus one confirmation from an account that is no longer a member.

This breaks the intended custody binding "confirmations counted == confirmations from live members," letting a request (including `Transfer`, `FunctionCall`, `AddKey`, etc.) execute below the intended live-member threshold.

### Impact Explanation
This matches the Critical impact category "a multisig request executed below threshold." Any sensitive action gated behind `num_confirmations` (NEAR transfers, adding/removing members or keys, arbitrary `FunctionCall`s) can be pushed through with fewer genuinely live confirmations than configured, effectively lowering the security threshold of the account without anyone re-confirming the quorum requirement.

### Likelihood Explanation
Requires no privileged access beyond being (at some point) a legitimate multisig member who confirms a request before being removed - a realistic operational sequence (e.g., member rotation/offboarding) rather than an attack requiring owner/foundation privileges. The remaining members do not need to be aware that the stale confirmation is still counted, since the contract state itself keeps it.

### Recommendation
When executing `delete_member` (and any other member-removal path), iterate `self.confirmations` for all pending requests and strip out entries corresponding to the removed member, not only for requests that member submitted. Alternatively, when checking quorum in `confirm`, validate that every account/key in the stored `confirmations` set is still present in `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with members `{A, B, C}` and `num_confirmations = 2`.
2. `B` calls `add_request` to submit request `X` (e.g., `Transfer`), confirmations for `X` = `{}`.
3. `A` calls `confirm(X)` → confirmations for `X` becomes `{A}` (1 < 2, not yet executed).
4. Separately, `B` and `C` submit and confirm a `DeleteMember { member: A }` request (reaching quorum 2 with two live members), removing `A` from `self.members`. Per `delete_member`, only requests submitted *by* `A` are cleaned up - request `X` (submitted by `B`) is untouched, so its confirmations set still contains `A`.
5. `C` calls `confirm(X)`. `confirmations.len() (1, containing stale "A") + 1 = 2 >= num_confirmations (2)` → request `X` executes, even though only one live member (`C`) actually approved it after `A`'s removal. [3](#0-2) [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
