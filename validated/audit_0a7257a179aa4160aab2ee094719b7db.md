## Title
DeleteBridge bypasses in-use check via case mismatch between raw `args.ID` and job pipeline's `BridgeTask.Name` - ([File: core/web/resolver/mutation.go])

### Summary
`Resolver.DeleteBridge` normalizes the bridge name via `bridges.ParseBridgeName` (which lowercases it) only when looking up the bridge itself, but passes the *raw, unnormalized* `args.ID` string to `FindJobIDsWithBridge`. Because the final in-Go equality check inside `FindJobIDsWithBridge` is case-sensitive against the pipeline's literal `BridgeTask.Name` (which is not normalized to lowercase when a job spec is parsed), an edit-role user can delete a bridge whose name differs only in case from how it's referenced in another user's job DOT source, silently bypassing the "in use" protection.

### Finding Description
In `core/web/resolver/mutation.go`:
```go
taskType, err := bridges.ParseBridgeName(string(args.ID))   // lowercased, e.g. "mybridge"
...
bt, err := orm.FindBridge(ctx, taskType)                     // lookup uses normalized name
...
jobsUsingBridge, err := r.App.JobORM().FindJobIDsWithBridge(ctx, string(args.ID))  // uses RAW args.ID, e.g. "MyBridge"
``` [1](#0-0) 

`bridges.ParseBridgeName` lowercases the name for storage/lookup consistency:
```go
func ParseBridgeName(val string) (BridgeName, error) {
	...
	return BridgeName(strings.ToLower(val)), nil
}
``` [2](#0-1) 

`FindJobIDsWithBridge` first does a broad case-insensitive `ILIKE` substring search, then narrows results via a case-sensitive Go string comparison against the parsed pipeline's `BridgeTask.Name`:
```go
WHERE pipeline_specs.dot_dag_source ILIKE '%' || $1 || '%' ORDER BY id
...
if task.(*pipeline.BridgeTask).Name == name {
    jids = append(jids, id)
}
``` [3](#0-2) 

`BridgeTask.Name` is a plain `string` field populated verbatim from whatever case appears in the job's DOT source (no normalization at parse time), as shown in tests where `Name` is set to arbitrary-case literals directly from spec text. [4](#0-3) 

Exploit flow: An edit-role user creates bridge `MyBridge` (stored/looked-up as `mybridge` due to `ParseBridgeName`). Another user's job references it in DOT source as `type=bridge name="mybridge"` (lowercase, matching normalized storage form but with a case choice independent from what the deleter later types). The attacker calls `deleteBridge(id: "MyBridge")`. `ParseBridgeName` normalizes to `mybridge` for the `FindBridge` lookup (finds the bridge). But `FindJobIDsWithBridge(ctx, "MyBridge")` passes the raw mixed-case string. The SQL `ILIKE` still matches the job's dot_dag_source (case-insensitive), but the Go-level exact-match `task.Name == "MyBridge"` fails against the stored `"mybridge"`, so the job is filtered out of the result set. `len(jobsUsingBridge) > 0` evaluates false, and the bridge is deleted even though a live job depends on it — breaking that job's pipeline execution (its bridge task will start failing with "bridge not found").

### Impact Explanation
This allows an edit-role user to delete a bridge that another user's active job depends on, despite the code's explicit intent to block that action, causing that job's on-chain-triggering pipeline to fail on next run. This matches the "unauthorized interference with pipeline execution / job disruption" impact class — a functional/business-logic bypass of an existing safety check rather than a privilege escalation, but it does let an edit-role actor break another user's running job when the check should have prevented it.

### Likelihood Explanation
Requires only `UserRoleEdit` (a role already permitted to manage bridges) and no special conditions beyond a case mismatch between the string used at delete-time and the case used in an existing job's DOT source — a very plausible, easily reproducible real-world scenario since bridge names are user-typed strings and DOT source case is whatever the job author wrote, with no enforced case-normalization at job-creation time. This is deterministic and repeatable, not a race condition.

### Recommendation
Use the normalized `taskType.String()` (post-`ParseBridgeName`) when calling `FindJobIDsWithBridge`, and additionally normalize/compare `BridgeTask.Name` case-insensitively (or lowercase it at parse time, consistent with `BridgeName`) inside `FindJobIDsWithBridge`'s Go-level filter, so the ILIKE pre-filter and the final match are consistent. Apply the same fix to `BridgeTypesController.Destroy` in `core/web/bridge_types_controller.go`, which has the identical raw-`name` pattern.

### Proof of Concept
Go integration test (extending `core/services/job/runner_integration_test.go` style):
1. Create bridge via `cltest.MustCreateBridge` with name `mybridge` (stored lowercase, matching `ParseBridgeName` normalization).
2. Create an OCR job whose DOT source references `type=bridge name="mybridge"` (lowercase, matching stored bridge name).
3. Call `jobORM.FindJobIDsWithBridge(ctx, "MyBridge")` (mixed-case, as `resolver.DeleteBridge` would pass raw `args.ID`) and assert it incorrectly returns an empty slice (bug) instead of the job's ID.
4. Call `Resolver.DeleteBridge(ctx, args{ID: "MyBridge"})` end-to-end and assert the bridge is deleted (`NewDeleteBridgePayload` succeeds with no "jobs associated" error) despite the referencing job still existing — confirming bypass of the intended `len(jobsUsingBridge) > 0` guard.
5. Contrast with control case using `deleteBridge(id: "mybridge")` (matching case) which correctly blocks deletion, per existing test `Test_DeleteBridgeMutation`'s "bridge with jobs associated" case. [5](#0-4)

func (o *orm) FindJobIDsWithBridge(ctx context.Context, name string) (jids []int32, err error) {
	query := `SELECT
			jobs.id, pipeline_specs.dot_dag_source
		FROM jobs
		    JOIN job_pipeline_specs ON job_pipeline_specs.job_id = jobs.id
		    JOIN pipeline_specs ON pipeline_specs.id = job_pipeline_specs.pipeline_spec_id
		WHERE pipeline_specs.dot_dag_source ILIKE '%' || $1 || '%' ORDER BY id`
	var rows *sqlx.Rows
	rows, err = o.ds.QueryxContext(ctx, query, name)
	if err != nil {
		return
	}
	defer rows.Close()
	var ids []int32
	var sources []string
	for rows.Next() {
		var id int32
		var source string
		if err = rows.Scan(&id, &source); err != nil {
			return
		}
		ids = append(jids, id)
		sources = append(sources, source)
	}
	if err = rows.Err(); err != nil {
		return
	}

	for i, id := range ids {
		var p *pipeline.Pipeline
		p, err = pipeline.Parse(sources[i])
		if err != nil {
			return nil, errors.Wrapf(err, "could not parse dag for job %d", id)
		}
		for _, task := range p.Tasks {
			if task.Type() == pipeline.TaskTypeBridge {
				if task.(*pipeline.BridgeTask).Name == name {
					jids = append(jids, id)
				}
			}
		}
	}
