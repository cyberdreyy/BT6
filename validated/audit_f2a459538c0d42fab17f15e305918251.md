### Title
Cross-Chain Nonce Collision in `isTransferProcessed` Allows Permanent Fund Lock on EVM Bridge - (File: bridge/evm/contracts/SuiBridge.sol)

### Summary

`SuiBridge.transferBridgedTokensWithSignatures` (and its V2 variant) tracks processed token-transfer messages using a mapping keyed **only by nonce**, without including the source chain ID. Because the EVM bridge on ETH Sepolia is configured to accept transfers from both Sui Testnet and Sui Custom — two independent chains each with their own nonce sequences starting at 0 — the first processed transfer from either chain at nonce N permanently blocks the other chain's transfer at the same nonce N. Tokens burned or locked on the source Sui chain can never be claimed on the EVM side.

### Finding Description

`SuiBridge` declares its replay-protection store as:

```solidity
mapping(uint64 nonce => bool isProcessed) public isTransferProcessed;
``` [1](#0-0) 

In `transferBridgedTokensWithSignatures`, the check and write use only `message.nonce` as the key:

```solidity
require(!isTransferProcessed[message.nonce], "SuiBridge: Message already processed");
// ...
isTransferProcessed[message.nonce] = true;
``` [2](#0-1) 

The same pattern is inherited verbatim by `SuiBridgeV2.transferBridgedTokensWithSignaturesV2`: [3](#0-2) 

`message.chainID` is the **source chain** identifier. The `onlySupportedChain` modifier only checks that the source chain is in the supported set — it does not participate in the replay-protection key: [4](#0-3) 

The valid bridge routes include both `SUI_TESTNET → ETH_SEPOLIA` and `SUI_CUSTOM → ETH_SEPOLIA`: [5](#0-4) 

This means the ETH Sepolia bridge is legitimately configured to accept messages from two independent source chains. Each source chain maintains its own nonce sequence starting at 0, managed by `get_current_seq_num_and_increment` on the Move side: [6](#0-5) 

Because the EVM bridge's `isTransferProcessed` mapping does not include the source chain ID in its key, nonce N from Sui Testnet and nonce N from Sui Custom map to the **same slot**. Whichever is processed first marks the slot `true`, and the other is permanently rejected.

**Contrast with the Move side:** The Move bridge correctly namespaces records by `BridgeMessageKey { source_chain, message_type, bridge_seq_num }`: [7](#0-6) [8](#0-7) 

The EVM side lacks this dimension entirely.

### Impact Explanation

Tokens burned or locked on a Sui source chain (Sui Testnet or Sui Custom) cannot be claimed on ETH Sepolia once the corresponding nonce slot has been consumed by the other source chain. The funds are permanently locked: destroyed on Sui, unclaimable on Ethereum. This matches the **permanent fund lock** impact class.

### Likelihood Explanation

This is not a theoretical race condition. Both Sui Testnet and Sui Custom assign nonces sequentially from 0. As soon as both chains have each sent at least one transfer to ETH Sepolia, nonce 0 from both chains exists simultaneously. Every subsequent nonce will collide in the same way. The collision is **systematic and inevitable** — it requires no attacker, only normal bridge usage from both supported source chains.

### Recommendation

Change `isTransferProcessed` to a nested mapping that includes the source chain ID:

```solidity
// Before
mapping(uint64 nonce => bool isProcessed) public isTransferProcessed;

// After
mapping(uint8 chainID => mapping(uint64 nonce => bool isProcessed)) public isTransferProcessed;
```

Update all reads and writes accordingly:

```solidity
require(!isTransferProcessed[message.chainID][message.nonce], "SuiBridge: Message already processed");
// ...
isTransferProcessed[message.chainID][message.nonce] = true;
```

Apply the same fix to `SuiBridgeV2`.

### Proof of Concept

1. ETH Sepolia `SuiBridge` is initialized with `supportedChains = [SUI_TESTNET, SUI_CUSTOM]`.
2. User A sends 1 WETH from Sui Testnet to ETH Sepolia. The Move bridge assigns `seq_num = 0` for the Sui Testnet token-transfer sequence. The bridge node collects signatures and calls `transferBridgedTokensWithSignatures` with `message.chainID = SUI_TESTNET, message.nonce = 0`. The call succeeds; `isTransferProcessed[0] = true`.
3. User B sends 1 WETH from Sui Custom to ETH Sepolia. The Move bridge assigns `seq_num = 0` for the Sui Custom token-transfer sequence (independent counter). The bridge node calls `transferBridgedTokensWithSignatures` with `message.chainID = SUI_CUSTOM, message.nonce = 0`.
4. The check `require(!isTransferProcessed[0])` reverts with `"SuiBridge: Message already processed"`.
5. User B's WETH is burned on Sui Custom and permanently unclaimable on ETH Sepolia. The same collision repeats for every subsequent nonce (1, 2, 3, …) as both chains continue to generate transfers. [9](#0-8) [10](#0-9)

    function transferBridgedTokensWithSignatures(
        bytes[] memory signatures,
        BridgeUtils.Message memory message
    )
        external
        nonReentrant
        verifyMessageAndSignatures(message, signatures, BridgeUtils.TOKEN_TRANSFER)
        onlySupportedChain(message.chainID)
    {
        // verify that message has not been processed
        require(!isTransferProcessed[message.nonce], "SuiBridge: Message already processed");

        IBridgeConfig config = committee.config();

        BridgeUtils.TokenTransferPayload memory tokenTransferPayload =
            BridgeUtils.decodeTokenTransferPayload(message.payload);

        // verify target chain ID is this chain ID
        require(
            tokenTransferPayload.targetChain == config.chainID(), "SuiBridge: Invalid target chain"
        );

        // convert amount to ERC20 token decimals
        uint256 erc20AdjustedAmount = BridgeUtils.convertSuiToERC20Decimal(
            IERC20Metadata(config.tokenAddressOf(tokenTransferPayload.tokenID)).decimals(),
            config.tokenSuiDecimalOf(tokenTransferPayload.tokenID),
            tokenTransferPayload.amount
        );

        _transferTokensFromVault(
            message.chainID,
            tokenTransferPayload.tokenID,
            tokenTransferPayload.recipientAddress,
            erc20AdjustedAmount
        );

        // mark message as processed
        isTransferProcessed[message.nonce] = true;

        emit TokensClaimed(
            message.chainID,
            message.nonce,
            config.chainID(),
            tokenTransferPayload.tokenID,
            erc20AdjustedAmount,
            tokenTransferPayload.senderAddress,
            tokenTransferPayload.recipientAddress
        );
    }

```text
fun get_current_seq_num_and_increment(bridge: &mut BridgeInner, msg_type: u8): u64 {
    if (!bridge.sequence_nums.contains(&msg_type)) {
        bridge.sequence_nums.insert(msg_type, 1);
        return 0
    };

    let entry = &mut bridge.sequence_nums[&msg_type];
    let seq_num = *entry;
    *entry = seq_num + 1;
    seq_num
}
