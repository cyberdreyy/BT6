### Title
Admin/sequencer-control JSON-RPC WebSocket transport lacks Host/Origin validation, enabling cross-site WebSocket hijacking - (File: crates/consensus/service/src/actors/rpc/actor.rs)

### Summary
`launch_rpc_server` builds the jsonrpsee `Server` and applies tower middleware (timeout, concurrency limit, load shed) only to the HTTP transport [1](#0-0) . The code comment itself acknowledges that this HTTP middleware does not see individual JSON-RPC calls streamed over WebSocket, and disables WS unless `config.ws_enabled()` is true [2](#0-1) . When WS is enabled, however, there is no `Host`/`Origin` header check anywhere before jsonrpsee accepts the WebSocket handshake — exactly the CWE-1385/CWE-346 gap described in the MCP advisory.

### Finding Description
The RPC socket defaults to binding on `0.0.0.0` [3](#0-2) , and WebSocket support is toggled purely by the `--rpc.ws-enabled` / `BASE_NODE_RPC_WS_ENABLED` flag, documented as "Enables websocket rpc server to track block production" [4](#0-3) . Once enabled, `ServerConfig::builder()` is not restricted to `http_only()`, so jsonrpsee serves raw WebSocket upgrades on the same socket [5](#0-4) . Because browsers attach an `Origin` header on cross-origin WS upgrades but do not enforce same-origin policy on the response (the same browser behavior underlying GHSA-vj7q-gjh5-988w), any web page can open a WS connection to this port and, once connected, issue arbitrary JSON-RPC calls against every module merged into the RPC module set — including the `AdminApiServer` (`admin_start_sequencer`, `admin_stop_sequencer`, `admin_override_leader`, `admin_set_recover_mode`, `admin_reset_derivation_pipeline`, `admin_post_unsafe_payload`) when `--rpc.enable-admin` is also set [6](#0-5) , and `WsRPC`'s live sync-state subscriptions [7](#0-6) . The code's own comment explicitly frames this as an "unauthenticated control-plane RPC" that "deployments must restrict... to trusted operators on a private network" [8](#0-7) , i.e., the SDK/server layer performs no origin gating itself, mirroring the MCP WebSocket transport's lack of `TransportSecuritySettings`-equivalent enforcement.

### Impact Explanation
If a node operator enables `--rpc.ws-enabled` (and, worse, `--rpc.enable-admin`) without a separate reverse-proxy/firewall Origin gate, a victim who runs the node and visits a malicious webpage can have that page silently open a WS connection to `localhost`/LAN and invoke sequencer-control methods such as `admin_stop_sequencer`, `admin_start_sequencer`, `admin_override_leader`, or `admin_set_recover_mode`. This can halt sequencing, force a conductor leader-override, or push an unsafe payload via `admin_post_unsafe_payload`, causing denial of service or chain-halt/fork-risk on the sequencer — a concrete node-halt / chain-disruption impact reachable purely via an anonymous RPC/browser client, consistent with the "public eth_*/WebSocket query path" scope.

### Likelihood Explanation
Requires the operator to have opted into `--rpc.ws-enabled` (default `false`) and, for the most severe admin methods, `--rpc.enable-admin`. This is a real, documented deployment configuration used to "track block production," and the default bind address is `0.0.0.0`, so it is plausible in production topologies that rely on network-level isolation rather than SDK-level Origin checks. The existing code comment shows the authors were aware WS bypasses the HTTP middleware but did not add any Host/Origin validation layer to close the gap, only a config toggle.

### Recommendation
Add explicit `Host`/`Origin` header validation before accepting WebSocket upgrades on this jsonrpsee server (equivalent to reth's `--ws.origins`/`AllowHosts` mechanism), or wire a `TransportSecuritySettings`-style middleware that runs for both HTTP and WS transports, not just HTTP. At minimum, default-deny WS from any `Origin` other than an explicit allow-list, and document that `--rpc.enable-admin` combined with `--rpc.ws-enabled` should never be exposed on a non-loopback bind without such origin filtering.

### Proof of Concept
1. Run the consensus node with `--rpc.ws-enabled --rpc.enable-admin --rpc.addr=0.0.0.0`.
2. From a browser page hosted on any origin, run: `new WebSocket("ws://<node-ip>:9545")`.
3. On `onopen`, send `{"jsonrpc":"2.0","id":1,"method":"admin_stopSequencer","params":[]}`.
4. Because no Host/Origin check exists on the WS path (only HTTP middleware exists), the request is processed and the sequencer is stopped, despite the socket being intended only for "trusted operators on a private network."

        let sink = sink.accept().await?;

        let mut subscription = self.engine_state_watcher().await?;

        let mut current_safe_head = subscription.borrow().sync_state.safe_head();

        while let Ok(new_state) = subscription
