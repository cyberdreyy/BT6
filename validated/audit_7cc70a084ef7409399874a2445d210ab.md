## Analysis Result

### Title
Griefing via unregistered/opted-out beneficiary or operator address permanently blocks `staking_contract` distribution, locking staker's stake and commission - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` iterates over every pending shareholder in a `StakingContract`'s `distribution_pool` and pays each one via `aptos_account::deposit_coins` in a single atomic loop before returning. Because `deposit_coins` can abort for accounts that are unregistered for `AptosCoin` and have explicitly opted out of direct transfers, a single unpayable recipient in the pool — reachable via the unprivileged `set_beneficiary_for_operator` or `aptos_account::set_allow_direct_coin_transfers` calls — causes every future call to `distribute`, `unlock_stake`, `switch_operator`, `request_commission`, and `update_commission_percentage` to revert, since all of them call `distribute_internal` first.

### Finding Description
`distribute_internal` pays out `distribution_pool` shareholders in a `while` loop: [1](#0-0) 

The payout uses `aptos_account::deposit_coins`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is **not yet registered** for `AptosCoin` **and** has disabled arbitrary direct transfers: [2](#0-1) 

An operator can flip this "reject" flag on their own address at any time via the fully public, unprivileged entry function: [3](#0-2) 

The recipient stored in `distribution_pool` for commission is the operator's own address, dynamically substituted with `beneficiary_for_operator(operator)` right before the deposit call: [4](#0-3) 

Critically, `set_beneficiary_for_operator` — callable unilaterally by the operator, with no staker consent required — does **not** validate that the new beneficiary is registered/able to receive APT: [5](#0-4) 

This is in stark contrast to `vesting::set_beneficiary`, which explicitly guards against exactly this failure mode: [6](#0-5) 

Because `distribute_internal` is invoked at the top of nearly every mutating staker-facing entry point (`unlock_stake`, `switch_operator`, `request_commission`, `update_commission_percentage`, `distribute`), an unpayable recipient anywhere in the `distribution_pool` list causes an unconditional abort in the atomic Move transaction, so the entry is never removed from the pool (Move aborts roll back all state changes) and the failure recurs on every subsequent call: [7](#0-6) [8](#0-7) [9](#0-8) 

### Impact Explanation
Once triggered, the staker permanently loses the ability to `unlock_stake`, `switch_operator`, `request_commission`, `update_commission_percentage`, or `distribute` for that specific `(staker, operator)` `StakingContract`, because all of these paths call `distribute_internal` unconditionally and it will always revert on the stuck recipient. I was unable to find, within `staking_contract.move`, any alternate path that lets the staker access the underlying `owner_cap` directly or otherwise bypass `distribute_internal` (no `owner_cap`/emergency-withdraw accessor was found via search of the module). If that holds, this traps the staker's stake and any pending/unpaid commission indefinitely — a permanent, non-recoverable loss of claim rights over stake and commission funds, matching the "Permanent lock ... of claim rights in stake ... commission ... flows" impact category.

### Likelihood Explanation
The trigger requires only unprivileged, standard-user actions already exposed as public entry functions: an operator (a role obtained through the normal, non-privileged `create_staking_contract`/`switch_operator` flow) calling `set_beneficiary_for_operator` with an address that is unregistered for `AptosCoin`, combined with that address calling `set_allow_direct_coin_transfers(false)`. No admin/governance privilege, no leaked keys, and no assumption of already holding staker/owner authority are needed — only the operator role, which any counterparty can acquire simply by being designated operator by a staker. This is a moderate-likelihood, entirely mainnet-reachable griefing vector (either self-inflicted by a careless operator or maliciously executed by an operator wishing to hold a staker's funds hostage).

### Recommendation
- Require `assert_account_is_registered_for_apt`-style validation (as already done in `vesting::set_beneficiary`) before accepting a new beneficiary in `staking_contract::set_beneficiary_for_operator`.
- Make `distribute_internal`'s payout loop resilient to individual recipient failures — e.g., skip/quarantine an unpayable recipient's shares into a separately claimable balance instead of aborting the whole distribution, or wrap the deposit in a fallback path that credits an internal claimable store when `deposit_coins` would fail.
- Provide a staker-level escape hatch (e.g., an admin/staker-callable rescue function) to force-settle stuck distributions independent of a single non-cooperating recipient.

### Proof of Concept
1. Staker creates a staking contract with `operator` O via `create_staking_contract`, and O joins the validator set and accrues rewards.
2. O calls `staking_contract::set_beneficiary_for_operator(O, B)` where `B` is a fresh address that has never registered for `AptosCoin`.
3. From `B`, call `aptos_account::set_allow_direct_coin_transfers(B_signer, false)` (this only requires `B` to be an existing account/signer — no coin registration needed).
4. Staker calls `staking_contract::request_commission` (or waits for it to be invoked implicitly), which calls `distribute_internal`, which — once `B`'s pending commission share becomes payable — calls `aptos_account::deposit_coins(B, ...)`. Since `B` is unregistered for `AptosCoin` and `can_receive_direct_coin_transfers(B) == false`, this aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
5. Because the abort rolls back the whole transaction, `B`'s entry remains in `distribution_pool` permanently. Every subsequent call to `unlock_stake`, `switch_operator`, `update_commission_percentage`, `request_commission`, or `distribute` on this `StakingContract` will hit the same abort, permanently freezing the staker's stake and commission accounting for that operator relationship.

*Note: I was not able to fully trace whether any other framework-level path (outside `staking_contract.move`) exists that could let the staker recover the underlying `owner_cap`/stake pool funds directly; this should be independently verified by a Devin session with full build/test access before treating this as fully unrecoverable.*

    /// Allows staker to switch operator without going through the lenghthy process to unstake.
    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
