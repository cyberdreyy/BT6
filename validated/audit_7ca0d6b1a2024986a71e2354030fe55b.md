Found a valid analog: the multisig contract's `confirm`/`delete_member` logic breaks the "confirmations counted versus live members" invariant, permitting a request to execute with fewer than `num_confirmations` *currently authorized* signers.

### Title
Stale confirmations from removed multisig members are still counted toward execution threshold, allowing a request to execute below the live-member quorum - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` only checks that the *current* caller is presently a member before adding/counting their confirmation, and simply compares the size of the stored confirmation set against `num_confirmations`. It never re-validates that every confirmation already stored in the set still belongs to a currently authorized member. `DeleteMember`'s cleanup (`delete_member`) only purges pending requests *originated* by the removed member (`r.member == member`), not confirmations the removed member cast on requests originated by someone else.

### Finding Description
- `confirm()` [1](#0-0)  increments/consults a `HashSet<String>` of confirmations for a `request_id`, checking `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute.
- Membership is only checked for the *acting* signer via `assert_valid_request` → `current_member()` [2](#0-1) ; the previously stored confirmations in the set are never re-checked against the live `self.members` set.
- `delete_member()` removes a member and cleans up pending requests, but it filters requests using `r.member == member` — i.e. only requests where the *removed* member was the original requester: [3](#0-2) . It does not scan `self.confirmations` to strip that member's confirmation from *other* pending requests they had merely confirmed (not authored).

Binding that should hold: `confirmations_counted(request) ⊆ live_members` at the moment of execution. After a `DeleteMember` action, this repository allows `confirmations_counted(request) ⊄ live_members` for any request whose original author is not the removed member, since the removed member's earlier `confirm()` call remains in the `confirmations` map.

### Impact Explanation
This breaks the fundamental K-of-N guarantee of the multisig. A member who is removed (e.g. because their access key is suspected compromised, they left the organization, or the group intentionally shrinks trust) retains latent influence: any confirmation they cast on a still-pending request before removal continues to count toward that request's execution threshold. The result is a request executed with fewer than `num_confirmations` distinct *currently authorized* confirmers — matching the Critical impact "a multisig request executed below threshold." Since `MultiSigRequestAction` includes `Transfer`, `FunctionCall`, `AddKey`, and `DeployContract` (i.e. arbitrary self-calls and NEAR transfers) [4](#0-3) , this stale-confirmation path can move NEAR or hijack the multisig account with authorization that has effectively been revoked.

### Likelihood Explanation
No external key compromise, foundation, or owner privilege is required beyond the multisig's own normal, expected operations (members confirming requests, and the group later removing a member — exactly the workflow the contract is designed to support, e.g. revoking a suspected-compromised key). The bug is purely in the accounting logic that fails to invalidate stale confirmations, so it triggers deterministically whenever: (1) a member confirms a pending, not-yet-executed request, and (2) that member is subsequently removed via `DeleteMember` before the request reaches quorum via other members. This is a normal, foreseeable sequence, especially the security-motivated one (removing a member due to suspected key leak) — precisely the scenario where retaining their prior confirmation power is most dangerous.

### Recommendation
When executing `DeleteMember`, iterate over `self.confirmations` for all pending requests (not just ones authored by the removed member) and remove the deleted member's entry from each confirmation set. Alternatively, when checking `confirmations.len() as u32 + 1 >= self.num_confirmations` in `confirm()`, filter the confirmation set to only members currently present in `self.members` before comparing against the threshold.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. Member `A` calls `add_request` to create request `R` (e.g. `Transfer { amount }` to an attacker-controlled or colluding account).
3. Member `B` calls `confirm(R)` → `confirmations(R) = {B}` (only 1/3, not executed).
4. The group, believing `B`'s key may be compromised (or simply rotating membership), submits and confirms a separate request `D_req = DeleteMember { member: B }`. This executes via `delete_member`, which only scans requests where `r.member == B` (i.e., requests B *authored*) — `R` was authored by `A`, so `confirmations(R)` is left untouched, still containing `B`.
5. `B` is now fully removed from `self.members`; `current_member()` for `B` would fail if `B` tried to act again.
6. Members `C` and `D` each call `confirm(R)`. After `C`'s confirm, `confirmations(R) = {B, C}` (2 recorded, but only 1 live member). After `D`'s confirm, `confirmations(R).len() + 1 = 3 >= num_confirmations (3)`, so `execute_request(R)` fires — even though only `C` and `D` (2 of the current 3 live members, well short of the "3 distinct current members" the threshold is meant to enforce) actually authorized it at execution time.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn current_member(&self) -> Option<MultisigMember> {
        let member = if env::current_account_id() == env::predecessor_account_id() {
            MultisigMember::AccessKey {
                public_key: env::signer_account_pk()
                    .try_into()
                    .unwrap_or_else(|_| env::panic_str("Failed to deserialize public key")),
            }
        } else {
            MultisigMember::Account {
                account_id: env::predecessor_account_id(),
            }
        };
        if self.members.contains(&member) {
            Some(member)
        } else {
            None
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
