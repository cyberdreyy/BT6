### Title
Password change/reset does not revoke existing API access tokens, allowing a compromised-credential attacker to retain full API access - ([File: core/web/user_controller.go])

### Summary
Chainlink node's local-auth user-management flow purges browser *sessions* when a user's password is changed, but it never revokes the user's separate API access-key/secret pair (`token_key`/`token_hashed_secret`). This mirrors the reported NEAR bug class: a credential ("full access key") that should become useless when the account's ownership/security state changes is instead left active indefinitely.

### Finding Description
The `UpdatePasswordRequest` flow (`UserController.UpdatePassword` → `updateUserPassword`) is the standard recovery mechanism a user invokes after suspecting account compromise. It calls `ClearNonCurrentSessions` and `SetPassword`, but never `DeleteAuthToken`: [1](#0-0) 

The GraphQL equivalent `UpdateUserPassword` resolver has the identical gap — it clears non-current sessions and sets the password, but does not touch the API token: [2](#0-1) 

Meanwhile, the API token (`token_key` + `token_hashed_secret`) is a completely independent credential from the session cookie or password, created via `CreateAndSetAuthToken`/`SetAuthToken`, and is only removed by an explicit call to `DeleteAuthToken`: [3](#0-2) 

Authentication via this token is handled independently of session/password state in `AuthenticateByToken`, which looks the user up directly by `token_key` and validates the secret — it has no dependency on the current password or session table: [4](#0-3) [5](#0-4) 

By contrast, `UpdateRole` (admin demoting/promoting another user) *does* proactively purge that user's sessions as a security measure: [6](#0-5) 
but even here, the API token is left untouched — only session cookies are invalidated, never the API key/secret pair.

The net effect: once an API access key/secret has been generated for an account (e.g., via `UserController`/`api_token.go` `NewAPIToken` while an attacker had a valid session), that credential remains valid for full API access regardless of subsequent password changes, password resets after suspected compromise, or role changes — exactly the "access key not tied to/revoked on ownership change" pattern from the report.

### Impact Explanation
An attacker who has obtained a user's API access key and secret (via a phished password, an exposed CI/config secret, a compromised session used to mint a new token, etc.) retains full, unrestricted API-level access to the Chainlink node even after the legitimate user changes their password in response to the compromise. Because `AuthenticateByToken` grants access purely based on `token_key`/`token_hashed_secret` match, the attacker can continue creating/deleting jobs, bridges, keys, and other high-privilege actions gated by the user's role, defeating the primary recovery action (password change) that operators believe re-secures the account.

### Likelihood Explanation
This does not require any special access beyond what is needed to obtain an API token in the first place (already-privileged compromise, phishing, leaked credential, or malicious insider with temporary access), and requires no additional exploitation step — the attacker simply keeps using the same, never-revoked API key/secret after the victim "fixes" their account by rotating the password. This is a realistic and commonly expected admin workflow (password rotation as incident response) that silently fails to achieve its security goal.

### Recommendation
- Call `DeleteAuthToken` (or force regeneration) for the affected user as part of both `UserController.UpdatePassword` / `updateUserPassword` and the GraphQL `UpdateUserPassword` resolver, mirroring the session-purging behavior already done for `UpdateRole`.
- Similarly, invalidate/rotate the API token whenever `UpdateRole` changes a user's privileges, not just their sessions.
- Document/alert users that changing a password alone does not revoke API tokens, or better, make token revocation part of the same transactional flow (`sqlutil.TransactDataSource`) used for role updates.

### Proof of Concept
1. Admin user logs in and calls the "create API token" endpoint/resolver, obtaining `accessKey`/`secret` (`CreateAndSetAuthToken`).
2. Attacker obtains this `accessKey`/`secret` pair (e.g., via phishing the admin's session used to create the token, or leaked CI secret).
3. Admin suspects compromise and changes their password via `PATCH /v2/user/password` (`UserController.UpdatePassword`) or the `updateUserPassword` GraphQL mutation.
4. Verify: `ClearNonCurrentSessions` removes session cookies, but `users.token_key`/`token_hashed_secret` are untouched — confirmed by inspecting `updateUserPassword` (`core/web/user_controller.go:341-360`) which never calls `DeleteAuthToken`.
5. Attacker continues to issue authenticated requests using `X-Chainlink-APIKey`/`X-Chainlink-APISecret` headers matching the original token; `AuthenticateByToken` (`core/web/auth/auth.go:78-112`) succeeds and grants full role-based access, unaffected by the password change.

func (u *UserController) updateUserPassword(c *gin.Context, user *clsession.User, newPassword string) error {
	ctx := c.Request.Context()
	sessionID, err := getCurrentSessionID(c)
	if err != nil {
		return err
	}
	orm := u.App.AuthenticationProvider()
	if err := orm.ClearNonCurrentSessions(ctx, sessionID); err != nil {
		u.App.GetLogger().Errorf("failed to clear non current user sessions: %s", err)
		return errors.New("unable to update password")
	}
	if err := orm.SetPassword(ctx, user, newPassword); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			return errUnsupportedForAuth
		}
		u.App.GetLogger().Errorf("failed to update current user password: %s", err)
		return errors.New("unable to update password")
	}
	return nil
}

func (r *Resolver) UpdateUserPassword(ctx context.Context, args struct {
	Input UpdatePasswordInput
}) (*UpdatePasswordPayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	session, ok := webauth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return nil, errors.New("couldn't retrieve user session")
	}

	dbUser, err := r.App.AuthenticationProvider().FindUser(ctx, session.User.Email)
	if err != nil {
		return nil, err
	}

	if !utils.CheckPasswordHash(args.Input.OldPassword, string(dbUser.HashedPassword)) {
		r.App.GetAuditLogger().Audit(audit.PasswordResetAttemptFailedMismatch, map[string]any{"user": dbUser.Email})

		return NewUpdatePasswordPayload(nil, map[string]string{
			"oldPassword": "old password does not match",
		}), nil
	}

	if err = r.App.AuthenticationProvider().ClearNonCurrentSessions(ctx, session.SessionID); err != nil {
		return nil, clearSessionsError{}
	}

	err = r.App.AuthenticationProvider().SetPassword(ctx, &dbUser, args.Input.NewPassword)
	if err != nil {
		return nil, failedPasswordUpdateError{}
	}

	r.App.GetAuditLogger().Audit(audit.PasswordResetSuccess, map[string]any{"user": dbUser.Email})
	return NewUpdatePasswordPayload(session.User, nil), nil
}

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}

func (o *orm) CreateAndSetAuthToken(ctx context.Context, user *sessions.User) (*auth.Token, error) {
	newToken := auth.NewToken()

	err := o.SetAuthToken(ctx, user, newToken)
	if err != nil {
		return nil, err
	}

	return newToken, nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (o *orm) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return pkgerrors.Wrap(err, "user")
	}
	sql := "UPDATE users SET token_salt = $1, token_key = $2, token_hashed_secret = $3, updated_at = now() WHERE email = $4 RETURNING *"
	return o.ds.GetContext(ctx, user, sql, salt, token.AccessKey, hashedSecret, user.Email)
}

// DeleteAuthToken clears and disables the users Authentication Token.
func (o *orm) DeleteAuthToken(ctx context.Context, user *sessions.User) error {
	sql := "UPDATE users SET token_salt = '', token_key = '', token_hashed_secret = '', updated_at = now() WHERE email = $1 RETURNING *"
	return o.ds.GetContext(ctx, user, sql, user.Email)
}

// AuthenticateByToken authenticates a User by their API token.

// Implements authMethod
func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}
