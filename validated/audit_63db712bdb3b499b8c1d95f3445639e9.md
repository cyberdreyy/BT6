## Title
Unauthenticated `/v2/resume/:runID` endpoint allows any unprivileged client to force-transition suspended pipeline runs, bypassing the intended state-machine ownership check - (File: core/web/router.go, core/web/pipeline_runs_controller.go, core/services/pipeline/orm.go)

### Summary
The tbtc report's core theme is that a state machine's transition functions can be invoked out of proper sequence or by parties who shouldn't be racing for a given transition, because the on-chain functions only check the *current* state, not *who* or *when* is calling. The Chainlink node analog is the `PATCH /v2/resume/:runID` route, which drives a suspended `pipeline_run`'s async-task state transition (`suspended → running/completed`) but is mounted with **no authentication middleware at all**, unlike every other write endpoint in the router.

### Finding Description
In `core/web/router.go`, the route table shows the resume endpoint registered on the base unauthenticated `/v2` group, distinct from `authv2` (session/token auth) and `userOrEI` (external-initiator/token/session auth): [1](#0-0) 

```go
func v2Routes(app chainlink.Application, r *gin.RouterGroup) {
	unauthedv2 := r.Group("/v2")

	prc := PipelineRunsController{app}
	psec := PipelineJobSpecErrorsController{app}
	unauthedv2.PATCH("/resume/:runID", prc.Resume)

	authv2 := r.Group("/v2", auth.Authenticate(app.AuthenticationProvider(),
		auth.AuthenticateByToken,
		auth.AuthenticateBySession,
	))
```

The handler itself only validates that `runID` parses as a UUID and that the JSON body decodes; it performs no ownership, secret, or role check before calling `App.ResumeJobV2`: [2](#0-1) 

Downstream, `ResumeRun`/`UpdateTaskRunResult` in the pipeline ORM transitions the run's state directly from the caller-supplied `taskID` and payload, without any secondary secret/token check tied to the specific task run: [3](#0-2) [4](#0-3) 

The design intent (per `task.bridge.go`, which builds the `responseURL` sent to external bridge adapters) is that only the bridge adapter that received the original async request, using the URL containing the task's UUID, is supposed to call back into `/v2/resume/:uuid`: [5](#0-4) 

This mirrors the tbtc pattern precisely: a valid state-transition function (`retrieveSignerPubkey`, `provideBTCFundingProof` in tbtc; `Resume`/`ResumeRun` here) exists to move the state machine forward, but the codebase relies on the assumption that only the "correct" actor will call it, instead of enforcing that at the access-control layer. The audit log even flags this explicitly as `UnauthedRunResumed`: [6](#0-5) 

The only "secret" gating this transition is the unguessability of the `taskID` UUID (a v4 UUID) — there is no rate limiting scoped to this specific endpoint beyond the general authenticated-rate-limit config, and no bridge-specific authentication (e.g., no shared secret between the bridge adapter and the node, unlike the External Initiator's HMAC-style access-key/secret pair used elsewhere in `core/bridges/external_initiator.go`).

### Impact Explanation
Any unprivileged remote client that can guess or otherwise obtain a pending run's task UUID (e.g., via error messages, logs, timing side-channels, or a compromised/curious bridge/EA operator) can:
- Force a suspended run to resume with an attacker-chosen `value`/`error`, effectively completing an oracle/job pipeline run with falsified data (`ResumeRequest.ToResult()` → `Result{Value, Error}`), potentially causing wrong data to be used downstream (e.g., a price feed value, VRF result, or other on-chain-facing task's async leg).
- Race the legitimate bridge adapter's callback with a spoofed early response before the genuine adapter replies, corrupting the job's output.

This is a direct instance of "unauthenticated request impersonation" for a legitimate participant's callback path — exactly the class of bug the analog rules ask for (request impersonation / unauthorized job-run/fund-movement).

### Likelihood Explanation
UUIDv4 task IDs provide 122 bits of entropy, making blind guessing infeasible; the practical risk is bounded by whether the UUID leaks (via bridge adapter logs, network taps of the outbound `responseURL`, or an untrusted/compromised external adapter reusing/publishing the callback URL). Given the endpoint is intentionally unauthenticated to support arbitrary third-party bridge adapters callback flows, this is a known design tradeoff rather than a clear-cut new bug — but it still represents the same "no ownership/timeout/role check baked into the transition" pattern flagged in the tbtc report, and there is no additional layer (HMAC, one-time-use enforcement independent of DB locking, IP allowlisting, etc.) mitigating leakage of the UUID.

### Recommendation
- Bind an unguessable, single-use, per-task secret (not just the pipeline task UUID) to the `/v2/resume/:runID` callback, verified via constant-time comparison, similar to the External Initiator's `AccessKey`/`Secret` pattern in `core/bridges/external_initiator.go`.
- Consider requiring the resume request to include a signed token in the `responseURL` (HMAC over the task ID with a node-held key) so knowledge of the raw UUID is insufficient to trigger the state transition.
- Rate-limit and audit-alert repeated resume attempts against the same or nonexistent task IDs to detect probing.

### Proof of Concept
1. Configure a webhook/bridge-backed async job (`type=bridge async=true`) so the node emits a `responseURL` of the form `http://<node>/v2/resume/<taskUUID>` to the external adapter, per `finalizeAndMarshalBridgeRequestData` in `core/services/pipeline/task.bridge.go`.
2. Obtain the `taskUUID` (e.g., from adapter-side logs, a network intermediary, or a malicious/compromised bridge operator that is only supposed to see this single value).
3. As an unauthenticated third party, send:
   ```
   PATCH /v2/resume/<taskUUID>
   Content-Type: application/json
   {"error": null, "value": "<attacker-controlled result>"}
   ```
   directly to the node with no credentials, since `unauthedv2.PATCH("/resume/:runID", prc.Resume)` requires none.
4. Observe that `PipelineRunsController.Resume` accepts the request and calls `App.ResumeJobV2`, transitioning the pipeline run's state and injecting the attacker's `value`, regardless of whether the legitimate bridge adapter has or hasn't yet responded.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
