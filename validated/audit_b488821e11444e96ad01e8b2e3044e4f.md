### Title
Unauthenticated `PATCH /v2/resume/:runID` allows any unprivileged client to inject arbitrary results into a suspended pipeline (bridge) task run - (File: core/web/pipeline_runs_controller.go)

### Summary
The Convex report describes a bug class where a completion/callback function (`getReward`) that is supposed to be exclusively driven by a controlling contract (the Vault) can instead be called directly by any unprivileged third party, corrupting the state the Vault depends on. Chainlink node has a directly analogous unauthenticated completion callback: `PipelineRunsController.Resume`, mounted with zero authentication, which lets anyone submit arbitrary "task results" for any suspended pipeline task run.

### Finding Description
`PipelineRunsController.Resume` finishes a suspended pipeline task and resumes the run using attacker-supplied JSON body content: [1](#0-0) 

This handler is registered on the router with no authentication middleware at all — it sits in the `unauthedv2` group, separate from every other pipeline/job route which requires session/token auth or `RequiresRunRole`: [2](#0-1) 

Compare this to the sibling `Create` action for triggering runs, which is intentionally gated behind `RequiresRunRole` and `AuthenticateExternalInitiator`/token/session auth: [3](#0-2) 

The `Resume` handler decodes an arbitrary JSON body into a `pipeline.ResumeRequest`, converts it to a `pipeline.Result` (value or error), and immediately calls `app.ResumeJobV2`, which forwards straight into `pipelineRunner.ResumeRun` to unblock and finalize the suspended task with the caller-supplied value/error — the only "authorization" check is that the `runID` (a UUID `taskID`) matches an existing suspended task: [4](#0-3) 

This mirrors the Convex bug precisely: the pipeline task run is meant to be completed exactly once by the legitimate external actor (a bridge adapter performing async work on behalf of the job/task, analogous to the Vault-controlled `getReward` call), but the endpoint imposes no restriction on *who* calls it — only on knowing/guessing the `runID` UUID. Anyone who can obtain or brute an in-flight `taskID` (e.g. it may be embedded in outbound bridge/adapter requests, logs, or webhook URLs handed to external systems as part of the async bridge task flow) can:
- Race the legitimate adapter and resume the task first with attacker-chosen data (`result`/`error`), poisoning the pipeline run's outcome (analogous to "breaking claimRewards" for the legitimate caller).
- Repeatedly probe/guess UUIDs to interfere with in-flight external bridge tasks across all jobs on the node, since the endpoint is entirely unauthenticated and shared across all jobs.

The team-provided audit entry name itself, `audit.UnauthedRunResumed`, at the very call site, documents that this authorization gap is understood as an explicitly "unauthenticated" completion path: [5](#0-4) 

### Impact Explanation
Successful exploitation lets an unprivileged, unauthenticated network client impersonate the legitimate bridge/adapter callback for any pipeline task run whose UUID it can obtain or guess, injecting arbitrary result data (or an arbitrary error) into that job's pipeline run. Depending on the job/task pipeline (e.g., an EA/bridge adapter task feeding downstream `ethtx`/on-chain report tasks), this can corrupt the data ultimately reported on-chain by that job, or deny/short-circuit legitimate completion of async bridge tasks — directly matching the report's confirmed impact category ("loss of/incorrect completion of the intended flow") but here the corrupted flow is off-chain pipeline execution/result data rather than reward accounting.

### Likelihood Explanation
The `runID`/`taskID` is a UUID, so brute-forcing it blindly is impractical; however the endpoint requires **no authentication whatsoever**, unlike every comparable node-triggering/pipeline route, so the security relies entirely on `taskID` secrecy rather than on any access control layer (no rate limiting group is applied to this specific unauthenticated route either, unlike `/sessions`). Any leak of the `taskID` (via bridge adapter logs, network observation of the adapter's outbound webhook call to the node, or a misconfigured/compromised bridge endpoint) is sufficient for full exploitation with no credentials needed.

### Recommendation
Require authentication/authorization on `PATCH /v2/resume/:runID` consistent with the rest of the pipeline-run API surface (e.g., a scoped, per-task bearer secret issued when the async task is created, or requiring the calling bridge to authenticate the same way external initiators authenticate `runs` creation via `auth.AuthenticateExternalInitiator`/token auth), rather than treating knowledge of the UUID as sufficient proof of authorization.

### Proof of Concept
1. Identify or intercept an in-flight pipeline task run UUID for a job containing an async bridge task (obtainable from bridge adapter request logs, network capture of the node's outbound callback registration, or misconfigured EA).
2. Send `PATCH /v2/resume/<taskID>` with an attacker-controlled JSON body (`{"error": null, "value": <attacker-data>}`) directly to the chainlink node, without any authentication headers/cookies.
3. Observe that `PipelineRunsController.Resume` accepts the request, calls `app.ResumeJobV2`, and completes the suspended task with the attacker-supplied result before/instead of the legitimate bridge adapter's callback, corrupting the pipeline run's outcome.

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
```
