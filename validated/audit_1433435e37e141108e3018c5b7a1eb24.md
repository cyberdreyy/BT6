Based on the code I found, the exploit path exists but works differently from how you described it — the misdirection isn't to `beneficiary_for_operator(new_operator)`, but rather it **bypasses beneficiary redirection entirely** for commission that accrued under an old operator, paying it to the old operator's raw address instead of their configured beneficiary.

## Root cause

`distribute` is a fully unprivileged entry function — it takes only plain addresses, no signer authorization against staker/operator: [1](#0-0) 

Inside `distribute_internal`, the beneficiary redirect is only applied if the *recorded distribution-pool key* equals the `operator` parameter that was passed into this specific call: [2](#0-1) 

Commission shares are always recorded in the distribution pool under whatever operator address was active *at the time the share was created* via `add_distribution(operator, ..., operator, commission_amount)`: [3](#0-2) 

`switch_operator` forces a distribution and a `request_commission_internal(old_operator, ...)` call *before* moving the `StakingContract` struct (and its `distribution_pool`) from the `old_operator` key to the `new_operator` key in the `Store` map: [4](#0-3) 

That `request_commission_internal(old_operator, ...)` call adds a *new* pending share keyed under `old_operator`'s raw address for any commission that is still `pending_inactive` (not yet unlocked) at switch time — since the stake pool lockup hasn't elapsed, this amount cannot be paid out immediately.

Once the lockup completes, `assert_staking_contract_exists(staker, old_operator)` will fail because `old_operator` no longer exists as a key in `Store` after the switch — only `new_operator` does. So an unprivileged caller can only call `distribute(staker, new_operator)`. Inside `distribute_internal`, the loop redeems `old_operator`'s recorded share, but the check `recipient == operator` compares `old_operator == new_operator`, which is **false** — so the beneficiary lookup is skipped, and the coins are deposited directly to `old_operator`'s raw address rather than `beneficiary_for_operator(old_operator)`.

This means an unrelated, unprivileged account calling `distribute(staker, new_operator)` after an operator switch can cause commission that had already accrued (and would normally be routed to `old_operator`'s beneficiary) to instead go to `old_operator`'s own address — silently bypassing the beneficiary configuration, rather than routing it to `new_operator`'s beneficiary as your hypothesis suggested.

The existing test suite covers the case where all pending commission is fully distributed and settled *before* the switch happens (so nothing remains keyed under the old operator when `distribute` is later called under the new operator key): [5](#0-4) [6](#0-5) 

It does **not** cover the scenario where commission is still `pending_inactive` (unlocking) at the moment of the switch — that residual share, once it becomes withdrawable, is only reachable via `distribute(staker, new_operator)`, and the beneficiary redirect is skipped for it. ### Title
Unprivileged `distribute` call after `switch_operator` bypasses beneficiary redirection for stale operator's pending commission - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
Commission recorded in a `StakingContract`'s `distribution_pool` under an operator's address survives an operator switch (the pool struct moves keys in `Store` but keeps its internal shareholder records). If that recorded share is still `pending_inactive` at switch time, it can only be later paid out by calling `distribute(staker, new_operator)`, since the old operator key no longer exists in `Store`. `distribute_internal`'s beneficiary redirect logic (`if (recipient == operator) { recipient = beneficiary_for_operator(operator) }`) compares against the *current call's* operator parameter, not the operator that originally owned the share, so the redirect never triggers for the stale share.

### Finding Description
See root cause above — `distribute_internal` at [7](#0-6)  redeems all shares in the pool regardless of which operator they were originally recorded under, but only redirects to `beneficiary_for_operator()` when the share's key happens to equal the operator passed into the current call.

### Impact Explanation
An operator who configured a beneficiary via `set_beneficiary_for_operator` [8](#0-7)  can have already-accrued, still-unlocking commission diverted to their own raw operator address instead of the beneficiary, if the staker switches operators before the lockup completes and any unrelated, unprivileged account then calls `distribute`. This corrupts the beneficiary-controlled payout path.

### Likelihood Explanation
Requires a specific timing window (staker switches operator while operator has unpaid, still-locked commission and a configured beneficiary), but the triggering `distribute` call itself requires no privilege at all.

### Recommendation
Track the *originating* operator address per share (or resolve `beneficiary_for_operator` per-shareholder-key rather than only when it matches the current call's `operator` parameter) in `distribute_internal`, so redirection is applied consistently based on each share's recorded key.

### Proof of Concept
Not independently verified end-to-end because full contents of `staking_contract.move` lines 1771–1800 (part of `test_operator_can_set_beneficiary`) were not retrievable in full due to index limits; recommend a Devin session with full repo access to add/adjust a unit test that: (1) accrues commission under `operator1` with a configured beneficiary, (2) triggers `request_commission` so the share is added but leaves it `pending_inactive`, (3) calls `switch_operator` to `operator2`, (4) fast-forwards past lockup, (5) calls `distribute(staker, operator2)` from an unrelated account, and (6) asserts the payout landed on `operator1`'s raw address rather than `beneficiary_for_operator(operator1)`.

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
