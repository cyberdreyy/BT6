### Title
Cross-user response hijacking via `MessageId` collision in webapi trigger `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The gateway's legacy WebAPI-trigger flow keys pending user callbacks solely by the client-supplied JSON-RPC request `id` (`msg.Body.MessageId`), with no binding to the requester's identity/session, and unconditionally overwrites any existing entry for that key. An attacker who submits a trigger request with the same `MessageId` as a victim's in-flight request can hijack the victim's response when a DON node later replies.

### Finding Description
The JSON-RPC request `id` is fully attacker-controlled: `gateway.ProcessRequest` decodes it from the raw client request and only enforces a 200-character length limit (`core/services/gateway/gateway.go:220-231`). For legacy requests it is copied verbatim into `msg.Body.MessageId` in `common.ValidatedMessageFromReq` [1](#0-0) .

`handler.HandleLegacyUserMessage` stores the caller's callback keyed only by this `MessageId`, with no ownership check and no rejection of a pre-existing key: `h.savedCallbacks[msg.Body.MessageId] = &savedCallback{...}` [2](#0-1) . Notably, the code comment right above explicitly acknowledges missing controls: `// TODO: apply allowlist and rate-limiting here` [3](#0-2) , confirming any unauthenticated sender who can self-sign a message can reach this path.

When a DON node later responds, `handleWebAPITriggerMessage` looks the callback up purely by `MessageId` and delivers the response to whatever callback currently occupies that slot: `savedCb, found := h.savedCallbacks[msg.Body.MessageId]; ...; return savedCb.SendResponse(...)` [4](#0-3) .

Exploit flow:
1. Victim sends a legacy trigger request with `id = X`; `HandleLegacyUserMessage` saves victim's callback at `savedCallbacks[X]` and forwards the request to DON nodes.
2. Before the DON node replies, attacker sends their own self-signed legacy trigger request also using `id = X` (attacker chooses/predicts X per the stated precondition). `HandleLegacyUserMessage` overwrites `savedCallbacks[X]` with the attacker's callback.
3. The DON node's response (echoing `MessageId = X`, since the node just reflects the ID it received) arrives via `HandleNodeMessage` → `handleWebAPITriggerMessage`, which now finds the attacker's callback at `savedCallbacks[X]` and delivers the victim's trigger response payload to the attacker's HTTP connection instead of the victim's.

No mechanism (sender binding, per-request nonce scoped to caller, or reject-on-collision) exists to prevent step 2 from clobbering step 1's entry.

### Impact Explanation
This is a cross-user response disclosure / request impersonation: an unprivileged, unauthenticated caller of the gateway HTTP endpoint can receive the trigger-response payload belonging to another user's in-flight WebAPI trigger request, including any data embedded in that response by DON nodes. This matches the Chainlink bounty class of "unauthorized access to another user's job/response data" / cross-user data confusion.

### Likelihood Explanation
Requires only: (1) ability to call the gateway's legacy trigger endpoint with a self-signed message (no allowlist enforced, per the explicit TODO), and (2) predicting or guessing the victim's `MessageId`, which is fully client-chosen and unauthenticated-client-visible in many integration patterns (sequential counters, timestamps, or fixed values used by some integrators). Timing feasibility is favorable given the round-trip delay to DON nodes provides a real race window. This is repeatable per request pair.

### Recommendation
Scope `savedCallbacks` keys by a value that is not purely attacker-chosen — e.g., combine `MessageId` with the message `Sender`/signer address or a gateway-generated internal correlation ID, and reject (rather than silently overwrite) `HandleLegacyUserMessage` calls whose derived key already exists in `savedCallbacks`.

### Proof of Concept
Go test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCb)` where `victimMsg.Body.MessageId = "collide"`, signed by victim's key, `don.SendToNode` mocked to not immediately trigger a response.
2. Before delivering the node response, call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCb)` with the same `MessageId = "collide"`, signed by attacker's key.
3. Assert `handler.savedCallbacks["collide"]` now equals attacker's callback wrapper (overwritten), i.e., `require.NotEqual` to the originally-saved victim callback pointer.
4. Simulate the DON node responding to the victim's original request (`hc.ValidatedResponseFromMessage(victimMsg)`), call `handler.HandleNodeMessage(ctx, resp, nodes[0].Address)`.
5. Assert `attackerCb.Wait(ctx)` returns the victim's response payload (`codec.EncodeLegacyResponse(victimMsg)`), while `victimCb.Wait(ctx)` times out/never receives a response — proving the response was delivered to the wrong party.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
