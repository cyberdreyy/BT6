### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing execution of a request below the intended `num_confirmations` threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` counts votes stored in `self.confirmations` (a `LookupMap<RequestId, HashSet<String>>`) against `self.num_confirmations` without checking whether each recorded confirmer is still a current member. `delete_member` only purges confirmations/requests that the *removed member itself authored*, not confirmations that the removed member cast on requests authored by others. A confirmation cast by a member who is later removed therefore remains valid "forever" and still counts toward quorum, breaking the binding `confirmations counted == confirmations by live members`.

### Finding Description
`confirm` computes quorum purely from the stored `HashSet<String>` size: [1](#0-0) 

There is no re-validation that every string in `confirmations` corresponds to a member still present in `self.members` at confirmation/execution time.

`delete_member` only cleans up requests *authored by* the removed member; it does not scan `self.confirmations` for other requests where the removed member's identity appears as a voter: [2](#0-1) 

Because `confirmations` is a `HashSet<String>` keyed on `MultisigMember::to_string()` and is never re-validated against the live `members: UnorderedSet<MultisigMember>` set, a confirmation cast before a member's removal continues to be counted as a live confirmation after removal.

### Impact Explanation
This is a "multisig request executed below threshold" scenario, explicitly called out as Critical impact: a pending request can be executed with fewer *currently valid* members having confirmed it than `num_confirmations` requires, because one or more of the counted confirmations belong to a member that has since been removed. This weakens the K-of-N security guarantee of the multisig (e.g. a Transfer, AddKey/AddMember, or FunctionCall request could be pushed through by effectively fewer live signers than the configured threshold), which can directly result in unauthorized movement of NEAR held by the multisig account.

### Likelihood Explanation
This requires no privileged access beyond being (or having been) one of the legitimate members - it is triggerable by ordinary multisig operation sequencing (a member confirms a request, is later removed via a separate `DeleteMember` request executed by the remaining members, and the original request is still pending). No malicious deployment, redeploy, or off-chain compromise is needed; it purely follows from the existing state-machine logic in `confirm`/`delete_member`. Likelihood is moderate-to-high in any long-lived multisig where membership changes while requests are still outstanding.

### Recommendation
When counting confirmations in `confirm` (and anywhere quorum is checked), filter `confirmations` to only members currently present in `self.members` before comparing against `self.num_confirmations`. Additionally, `delete_member` should purge the removed member's entry from every pending request's confirmation set (not just requests it authored), or `confirm`/execution should intersect the stored confirmations with the live `members` set at the time of the quorum check.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `[A, B, C, D]` and `num_confirmations = 3`.
2. Member `B` calls `add_request` to create request `R1` (e.g. `Transfer` to an attacker-controlled account).
3. Member `A` calls `confirm(R1)` → `confirmations[R1] = {A}` (1 of 3, not yet executed): [3](#0-2) 
4. Separately, members `B`, `C`, `D` create and confirm a `DeleteMember { member: A }` request, which executes and calls `delete_member`, removing `A` from `self.members` — but `R1`'s confirmation set still contains `A` because `delete_member` only removes requests authored by `A`, not confirmations `A` cast on other requests: [4](#0-3) 
5. Member `B` calls `confirm(R1)` → `confirmations[R1] = {A, B}` (2 of 3, still pending).
6. Member `C` calls `confirm(R1)` → `confirmations.len() + 1 == 3 >= num_confirmations`, so `R1` executes via `execute_request`: [5](#0-4) 

At execution time, only `B` and `C` are genuinely live members who confirmed `R1` — `A`'s stale confirmation (cast before removal) satisfied the third vote. The Transfer request thus executes with only 2 live confirmations against a nominal threshold of 3, i.e. a multisig request executed below the configured threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
