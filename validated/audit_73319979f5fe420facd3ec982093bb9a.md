## Analysis

The Sherlock bug's core invariant is: **share↔amount rounding must always favor the protocol/counterparty owed value, not the party initiating the operation** — otherwise repeated small operations let an attacker erode debt/commission owed for free.

The closest Aptos-native analog is in `staking_contract.move`'s commission accounting, specifically `get_staking_contract_amounts_internal` and `request_commission_internal`.

### Title
Staker can permanently escape operator commission via rounding-to-zero + unconditional principal roll-up in `request_commission_internal` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`request_commission_internal` computes `commission_amount` with a rounding-down division, then unconditionally rolls the *entire* `accumulated_rewards` into `staking_contract.principal` **before** checking whether any commission was actually paid. When `commission_amount` rounds to zero (small `accumulated_rewards` relative to `commission_percentage`), the whole reward slice is baked into `principal` with zero commission ever assessed on it, permanently exempting it from future commission calculations.

### Finding Description
The commission is computed as: [1](#0-0) 

In `request_commission_internal`, the principal is unconditionally advanced to `total_active_stake - commission_amount` and only afterward does the function short-circuit if `commission_amount == 0`: [2](#0-1) 

Because `commission_amount = accumulated_rewards * commission_percentage / 100` truncates, any `accumulated_rewards` smaller than `100 / commission_percentage` (e.g., under 10 octas at a 10% commission rate) yields `commission_amount == 0`. In that case:
1. `staking_contract.principal` is still set to `total_active_stake` (i.e., the full reward slice is absorbed into principal), and
2. the function returns early, adding **no** distribution to the operator.

This is callable by the staker themself with no special privilege beyond owning the staking contract — `request_commission_internal` is reachable both via `request_commission` (staker or operator per the spec's `aborts_if account_addr != staker && account_addr != operator`) and via `unlock_stake`, which any staker can call on their own contract: [3](#0-2) 

By calling `request_commission`/`unlock_stake` once per epoch (the natural reward-accrual cadence) while their per-epoch `accumulated_rewards` stays below the rounding threshold, the staker converts each epoch's reward slice into commission-exempt principal. This differs qualitatively from an ordinary 1-octa rounding dust loss (as seen elsewhere in the codebase and acknowledged in comments, e.g. the `staking::commission` example module's documented "rob the operator" caveat): here the *entire* reward slice for that epoch escapes commission, not just a fractional octa, because the unconditional principal update happens before the zero-commission short-circuit.

### Impact Explanation
This corrupts operator commission accounting by systematically crediting the wrong (zero) commission for rewards that should be commissioned, and pockets that value into the staker's own principal/withdrawable balance instead of the operator's rightful cut. For staking contracts with modest APY and low principal (or higher `commission_percentage` making the rounding threshold larger), a staker can drive their real commission burden well below the contractually agreed rate, transferring value from operator to staker over many epochs — matching the "operator commission... credits the wrong account or traps value" impact category.

### Likelihood Explanation
Requires only the staker's own signer (no operator/admin privilege) and ordinary epoch-driven reward accrual; exploitability scales with `100 / commission_percentage` versus typical per-epoch reward size, so it's most practical for low-stake/low-reward-rate contracts, similar to the original report's caveat that gas costs bound attacker economics.

### Recommendation
Only advance `staking_contract.principal` by the portion of `accumulated_rewards` *not* commissioned when `commission_amount` is computed, or skip the principal update together with the distribution when `commission_amount == 0`, so unpaid dust rewards remain commissionable at the next call rather than being silently absorbed into principal.

### Proof of Concept
1. Staker creates a staking contract with `commission_percentage = 10` and a validator that earns modest per-epoch rewards such that `accumulated_rewards` per epoch is < 10 octas.
2. Each epoch, staker calls `staking_contract::request_commission(staker, staker_address, operator)` (self is allowed per spec).
3. `get_staking_contract_amounts_internal` computes `commission_amount = accumulated_rewards * 10 / 100 == 0` (truncated).
4. `request_commission_internal` sets `staking_contract.principal = total_active_stake - 0`, absorbing the full reward slice, then returns 0 with no distribution added for the operator.
5. Repeating over many epochs, the operator receives zero commission on those reward slices, while the staker's principal (and thus final payout) reflects the full un-commissioned reward amount. [2](#0-1)

```text
    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );
```

```text
        // Short-circuit if amount is 0.
        if (amount == 0) return;
```
