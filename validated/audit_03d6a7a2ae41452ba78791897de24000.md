## Analysis Result

### Title
Unbounded recursion in `TrieNode::decode`/`TrieNode::open` allows stack-overflow DoS of the fault-proof program via a malicious MPT preimage chain - (File: `crates/proof/mpt/src/node.rs`)

### Summary
`TrieNode::decode` and `TrieNode::open` recurse once per trie level with no maximum-depth check, mirroring the CVE-2020-9861 bug class (unbounded recursion on attacker-controlled nested input causing a stack overflow). In the fault-proof program, both L1 and L2 `TrieProvider` implementations feed attacker-influenced preimage bytes directly into this recursive decoder.

### Finding Description
`TrieNode::decode` recursively calls `Self::decode` for `Extension` nodes and `Vec::<Self>::decode` (which recurses per branch slot) for `Branch` nodes, with no depth counter or maximum-depth guard: [1](#0-0) 

Likewise, `TrieNode::open` recurses through `Branch`, `Extension`, and `Blinded` variants, and every `Blinded` node triggers an `unblind` call that fetches a *new* preimage via the untrusted `TrieProvider` and recurses again: [2](#0-1) 

The preimage fetchers used in the fault-proof program pull data directly from the preimage oracle (populated by the host/challenger during dispute-game execution) with no depth or chain-length limit before invoking `TrieNode::decode`: [3](#0-2) [4](#0-3) 

Because MPT `Extension` nodes can point to another blinded node, and `unblind` fetches and decodes that node before recursing again in `open`, an attacker who controls the set of preimages served to the program (e.g., a malicious/faulty preimage set supplied to a dispute-game participant, or crafted state used to build a claimed root) can construct an arbitrarily long chain of extension/blinded nodes. Walking or decoding this chain drives unbounded native call-stack recursion with no cutoff, analogous to the JSON recursion-depth stack overflow fixed by Swift for CVE-2020-9861.

### Impact Explanation
A stack overflow inside the fault-proof program halts/crashes execution of the dispute-game trace, preventing the honest party from producing a correct execution trace or claim for that step. In the OP Stack/Base fault-proof model, an inability to compute the correct output at a disputed step can let an invalid state root go unchallenged or force a resolution timeout, undermining the correctness guarantee of the dispute-game and risking incorrect settlement of L2 state (a "wrong provable output root" / node-halt class impact per the validation rules).

### Likelihood Explanation
The trie-node decode/open path is on the critical path of every account and storage lookup performed by `TrieDB` (`crates/proof/executor/src/db/mod.rs`) during proof execution, and the preimages walked are sourced from the oracle without independent depth validation, so a state-witness/preimage set that is unusually deep is trivial to construct (just chain extension nodes) and will be processed without any early rejection.

### Recommendation
Add an explicit depth counter (threaded through `decode` and `open`/`unblind`) with a bounded maximum (e.g., matching the theoretical max hexary-trie depth, ~64-65 nibble levels plus a safety margin) and return a decode/open error once exceeded, rather than relying on unbounded native recursion.

### Proof of Concept
1. Construct a chain of N `TrieNode::Extension` nodes, each pointing (via `Blinded{commitment}`) to the next, terminating in a `Leaf`.
2. Populate a preimage store (as used by `OracleL1ChainProvider`/`OracleL2ChainProvider` or `TrieNodeProvider`) with all N preimages keyed by their keccak256 hash.
3. Call `root_node.open(path, &fetcher)` (as done in `TrieDB::get_trie_account`/`storage`) with N large enough (e.g., tens of thousands) that native stack recursion through `open` → `unblind` → `trie_node_by_hash` → `TrieNode::decode` exhausts the fault-proof program's stack, crashing the process before it produces a result.

    pub fn open<'a, F: TrieProvider>(
        &'a mut self,
        path: &Nibbles,
        fetcher: &F,
    ) -> TrieNodeResult<Option<&'a mut Bytes>> {
        match self {
            Self::Branch { stack } => {
                let branch_nibble = path.get(0).ok_or(TrieNodeError::PathTooShort)? as usize;
                stack
                    .get_mut(branch_nibble)
                    .map(|node| node.open(&path.slice(BRANCH_NODE_NIBBLES..), fetcher))
                    .unwrap_or(Ok(None))
            }
            Self::Leaf { prefix, value } => Ok((path == prefix).then_some(value)),
            Self::Extension { prefix, node } => {
                if path.slice(..prefix.len()) == *prefix {
                    // Follow extension branch
                    node.unblind(fetcher)?;
                    node.open(&path.slice(prefix.len()..), fetcher)
                } else {
                    Ok(None)
                }
            }
            Self::Blinded { .. } => {
                self.unblind(fetcher)?;
                self.open(path, fetcher)
            }
            Self::Empty => Ok(None),
        }
    }

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
}

impl<T: CommsClient> TrieProvider for OracleL1ChainProvider<T> {
    type Error = OracleProviderError;

    fn trie_node_by_hash(&self, key: B256) -> Result<TrieNode, Self::Error> {
        // On L1, trie node preimages are stored as keccak preimage types in the oracle. We assume
        // that a hint for these preimages has already been sent, prior to this call.
        crate::block_on(async move {
            TrieNode::decode(
                &mut self
                    .oracle
                    .get(PreimageKey::new(*key, PreimageKeyType::Keccak256))
                    .await
                    .map_err(OracleProviderError::Preimage)?
                    .as_ref(),
            )
            .map_err(OracleProviderError::Rlp)
        })
    }
