### Title
Verbose internal quorum/health metrics leaked verbatim to unprivileged caller via FatalError on quorum-unreachable path - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
When `forwardBundleOrTerminateIfReady` determines that relay quorum cannot be reached, it builds a `FatalError` with a formatted message embedding `summary.Signed()`, `maxPossibleSigned`, `minQuorum`, `summary.Total()`, `nodes`, `remaining`, `summary.Error()`, and `summary.Undecodable()`, and this exact error string is sent verbatim to the requesting caller through `UserCallbackPayload`. This exposes precise DON topology/health counts to any caller who submitted the original signed request.

### Finding Description
In `forwardBundleOrTerminateIfReady`, when `maxPossibleSigned < minQuorum` and the request has not expired, the handler logs and then constructs the error: [1](#0-0) 

This is passed to `constructErrorResponse`, whose switch statement only rewrites the error text for `NodeReponseEncodingError`, `InvalidParamsError`, `UnsupportedMethodError`, and `UserMessageParseError`; `api.FatalError` is not handled, so `err.Error()` (the fully detailed message) is used verbatim as the JSON-RPC error message: [2](#0-1) 

The resulting `UserCallbackPayload` is delivered through `ar.SendResponse(payload)` — the same `Callback` object supplied by the original caller's request handling path (`HandleJSONRPCUserMessage` → `newActiveRequest` stores the caller's `callback`), so the response, including the raw error text, flows directly back to whichever client (authenticated only by request signature, not by any privileged role) submitted the `MethodCapabilityExec`/`MethodSecretsGet` request: [3](#0-2) [4](#0-3) 

There is no role/authorization check between "a request signer" and "someone allowed to see raw node counts" — any caller able to construct a valid signed gateway request for these methods receives the same detail. The identical detailed-message pattern also appears on the `RequestTimeoutError` path just above it (lines 472-474), which returns the same categories of numeric counts.

### Impact Explanation
An unprivileged caller who can submit a `MethodCapabilityExec`/`MethodSecretsGet` request to this DON's gateway handler learns, on quorum failure, the exact `signed`, `maxPossibleSigned`/`collected`/`nodes`/`remaining`/`errors`/`undecodable` counts for that DON at that moment. Repeated over time, or correlated with externally observed node outages, this gives a live, precise fingerprint of DON health/topology (number of live nodes, error rate, undecodable-response rate) to anyone who can send a request — not just to node operators or admins. This matches an information-disclosure / health-endpoint data leakage impact class rather than a direct fund-loss or auth-bypass bug, since the underlying quorum/signature verification by the enclave is unaffected.

### Likelihood Explanation
The precondition is simply that the attacker can submit any valid (correctly signed per the confidential relay handler's message ingestion) `MethodCapabilityExec` or `MethodSecretsGet` request to a DON that is experiencing (or can be induced/waited-into) partial node failures such that `maxPossibleSigned < minQuorum`. No operator, admin, or privileged role is required beyond whatever minimal credential is already needed to reach `HandleJSONRPCUserMessage` for these methods (the same credential any ordinary user of the confidential relay capability has). This is fully reproducible and repeatable — an attacker can simply keep issuing requests and reading the error text whenever quorum health degrades.

### Recommendation
In `constructErrorResponse`, add an explicit case for `api.FatalError` (and similarly sanitize the `RequestTimeoutError` detailed message) that returns a generic, non-parameterized message (e.g., `"relay quorum unreachable"` / `"request timed out waiting for relay quorum"`) to the caller, while keeping the detailed numeric breakdown (`signed`, `maxPossibleSigned`, `minQuorum`, `nodes`, `remaining`, `errors`, `undecodable`) only in the structured log lines (`l.Warnw(...)`), which are already emitted separately and are not part of the response sent to the caller.

### Proof of Concept
Go unit test plan for `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` with a small `donConfig` (e.g., `F=1`, 4 members) and a stub `relayBundler` (or the real `bundler`) that reports `Signed()=0`, `Total()=1`, `Error()=1`, `Undecodable()=0` for a given request.
2. Call `HandleJSONRPCUserMessage` with a `MethodCapabilityExec` request and a `Callback` capturing the payload via `Wait`.
3. Drive `HandleNodeMessage` with enough node error/undecodable responses so that `remaining` computed as `len(donConfig.Members) - summary.Total()` combined with `summary.Signed()` yields `maxPossibleSigned < minQuorum`, forcing the `relay quorum unreachable` branch.
4. Assert on the payload returned to the callback (`UserCallbackPayload.RawResponse` decoded as JSON-RPC error): the error message currently contains the raw substrings `"signed responses"`, `"nodes="`, `"remaining="`, `"errors="`, `"undecodable="` with the exact integers from `summary` — demonstrating the leak. After the fix, assert the message is a fixed generic string with no embedded counts, while a separate assertion on captured log output confirms the detailed counts are still logged for operators via `l.Warnw`.

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
```

func (h *handler) constructErrorResponse(req jsonrpc.Request[json.RawMessage], errorCode api.ErrorCode, err error) gwhandlers.UserCallbackPayload {
	//nolint:exhaustive // do not modify other error codes
	switch errorCode {
	case api.NodeReponseEncodingError:
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		err = fmt.Errorf("invalid params error: %w", err)
	case api.UnsupportedMethodError:
		err = fmt.Errorf("unsupported method(%s): %w", req.Method, err)
	case api.UserMessageParseError:
		err = fmt.Errorf("user message parse error: %w", err)
	}
	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			nil,
		),
		ErrorCode: errorCode,
	}
```

func (c *Callback) SendResponse(payload handlers.UserCallbackPayload) error {
	if !c.sent.CompareAndSwap(false, true) {
		return errors.New("response already sent: each callback can only be used once")
	}
	// The channel is initialized with a buffer size of 1,
	// so this send will not block.
	c.ch <- payload
	return nil
}
