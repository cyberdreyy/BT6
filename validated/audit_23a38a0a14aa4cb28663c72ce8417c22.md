### Title
Stale confirmations from a removed member let a multisig request execute below the live-member confirmation threshold - (File: `multisig2/src/lib.rs`)

### Summary
In `MultiSigContract::delete_member`, when a member is removed only the *requests that member created* are purged; confirmations that removed member previously cast on *other* requests (created by different members) are left untouched. `confirm()` counts entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set purely by size, without checking whether each entry still belongs to a current member. This lets a request execute (e.g. a `Transfer`) once the stale confirmation plus fewer live-member confirmations than `num_confirmations` reach the threshold.

### Finding Description
`delete_member` only cleans requests keyed by the removed member as the *creator* (`r.member == member`): [1](#0-0) 

It never scans the `confirmations` map to strip the removed member's `to_string()` entry from confirmation sets belonging to requests created by *other* members. The `confirm` method, however, treats the size of that stored set as proof of live consent: [2](#0-1) 

Because `MultisigMember` is compared/stored by its serialized string via `HashSet<String>`, once a member is deleted, any confirmation string they previously added to another request's `HashSet` is never removed, and continues to count toward `confirmations.len() as u32 + 1 >= self.num_confirmations`.

Concretely, with members `{A,B,C,D}` and `num_confirmations = 3`:
1. `A` calls `add_request` to create `R1` (e.g. `Transfer`), unconfirmed.
2. `D` calls `confirm(R1)` → `confirmations[R1] = {D}` (len 1, below threshold, request stays open).
3. The group later removes `D` (e.g. compromised key) via a separate, correctly-threshold-met request executed by `A, B, C`. `delete_member` only purges requests where `D` was the *creator*; `R1` was created by `A`, so its confirmation set `{D}` is left in place, and `D` is removed from `self.members`.
4. `A` then calls `confirm(R1)` → `{D, A}` (len 2).
5. `C` then calls `confirm(R1)` → `{D, A, C}` (len 3) → `3 >= num_confirmations(3)` is true, and `execute_request` runs the `Transfer`.

Only two currently-live members (`A`, `C`) actually authorized the transfer, yet the contract executed it as if three live members had signed off, because the removed member `D`'s stale confirmation was silently retained and counted.

### Impact Explanation
This breaks the multisig's core custody guarantee: a request (including fund `Transfer`, `AddKey`/`DeleteMember`, or `FunctionCall`) can be executed with fewer genuinely live/authorized confirmations than the configured `num_confirmations` threshold. Per the rubric this is Critical: "a multisig request executed below threshold." Funds controlled by the multisig account can move (or governance actions like adding a new full-access key) without the intended K-of-N live approval.

### Likelihood Explanation
Likelihood is not purely theoretical but requires a specific but realistic sequence: an outstanding unconfirmed/partially-confirmed request exists at the time a member is removed. Given that member removal (e.g., due to key rotation/compromise) is an expected operational action, and requests can legitimately remain pending for a while (subject only to the 15-minute deletion cooldown, not an upper bound on how long they may stay open), this scenario is plausible in normal multisig operation, not merely a contrived edge case.

### Recommendation
When deleting a member in `delete_member`, also scan all `confirmations` entries and remove the deleted member's `to_string()` key from every request's confirmation `HashSet`, not just requests the member created:

### Proof of Concept
Using the existing test harness in `multisig2/src/lib.rs`:
1. `MultiSigContract::new([A,B,C,D], 3)`.
2. `A` (as predecessor) calls `add_request(Transfer{...})` → `request_id = R1`.
3. `D` calls `confirm(R1)` → `confirmations[R1].len() == 1`.
4. Execute a separate `DeleteMember{D}` request confirmed by `A,B,C` (3 confirmations) → `D` removed from `members`, but `confirmations[R1]` still equals `{D}` since `R1.member == A`, not `D`.
5. `A` calls `confirm(R1)` → len 2; `C` calls `confirm(R1)` → len 3 → `3 >= 3` → `execute_request` runs, transferring funds, even though only `A` and `C` (two live members) actually consented in real time. [3](#0-2) [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
