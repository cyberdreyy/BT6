### Title
`BlockInfo::mark_pre_committed` mutates `valid` before the state transition succeeds, letting a validation-ok response overwrite the outcome of an already-consensus-reached (globally rejected) block — analog of the "no rollback on failed operation" bug class ([File: stacks-signer/src/signerdb.rs])

### Summary
`BlockInfo::mark_pre_committed` sets `self.valid = Some(true)` unconditionally, before attempting the state transition via `move_to`, and does not roll this back if `move_to` fails: [1](#0-0) 

The only caller, `handle_block_validate_ok`, only bails out of persisting this corrupted `valid` field when the block has *not* reached consensus and is not `LocallyAccepted`; if the block has already reached consensus (e.g. it is `GloballyRejected`), the corrupted `valid = Some(true)` is persisted anyway, and the code unconditionally proceeds to broadcast a pre-commit and count its own pre-commit: [2](#0-1) 

### Finding Description
`mark_pre_committed()` writes to `self.valid` first and only afterward calls `self.move_to(BlockState::PreCommitted)`, which can fail (returns `Err`) for any state other than `Unprocessed` per `check_state`: [3](#0-2) 

Because the mutation to `valid` happens unconditionally regardless of whether `move_to` succeeds, a late-arriving `BlockValidateOk` response for a block whose `BlockInfo` has already moved past `Unprocessed` (e.g. it was independently pushed to `GloballyRejected` via peer rejection signatures, per `store_and_process_block_rejection`) will silently set `valid = Some(true)` on that `BlockInfo` while its `state` remains untouched. The caller's guard (`!block_info.has_reached_consensus() && block_info.state != BlockState::LocallyAccepted`) is meant to prevent acting on this corrupted flag, but it only prevents the *early return*; when the guard's condition is false (block has reached consensus, i.e., `GloballyAccepted`/`GloballyRejected`), the code does **not** return — it falls through to persist the block (with `valid = Some(true)` now incorrectly set on a `GloballyRejected` record) and then unconditionally calls `send_block_pre_commit` and `handle_block_pre_commit` for that block hash.

This breaks the "rejection recounted as an accept" equality class: the persisted `valid` field for a block that the signer set (via consensus) already rejected is flipped to `true`, and the signer actively re-broadcasts/re-processes a pre-commit for a block it should treat as terminally rejected.

### Impact Explanation
This falls in the "rejection recounted as acceptance" impact bucket described by the scan rules: a signer's on-disk state for an already `GloballyRejected` block gets its `valid` flag flipped to `true`, and the signer emits a `BlockPreCommit` for a block that has already reached a rejected consensus outcome. Depending on downstream consumers of `valid` (e.g., `handle_block_pre_commit`'s `if !block_info.valid.unwrap_or(false)` gate at line 1323 of signer.rs), this could let the signer's own subsequent pre-commit/signature logic treat the block as viable again, contrary to the already-finalized rejection, undermining the signed-vs-validated equality invariant that the state machine is designed to preserve.

### Likelihood Explanation
The likelihood is intrinsically low-to-moderate: it requires a race where a stacks-node validation response for a block arrives late enough that the block's `BlockInfo` has already reached `GloballyRejected` via peer signatures (a plausible network condition, not requiring a majority of signers to be malicious — just normal timing/latency between node validation and peer gossip). A single miner (or even normal network jitter) proposing/timing block validation could trigger this without any attacker collusion. However, because `move_to` failing is the triggering condition and the surrounding code only partially guards against it, I could not fully verify (due to session limits) whether `has_reached_consensus()`'s exact definition (not found via available tools) covers `GloballyRejected`, nor could I trace every downstream consumer of the `valid` field to confirm full exploitability of this state corruption into an actual signature. This should be treated as a probable but not fully proven finding.

### Recommendation
Make `mark_pre_committed` (and analogous `mark_*` methods) transactional: only mutate `self.valid` / timestamps after `move_to` succeeds, or roll back `self.valid` if `move_to` returns `Err`. Additionally, in `handle_block_validate_ok`, treat any `mark_pre_committed` failure as a hard stop regardless of `has_reached_consensus()`/`LocallyAccepted` state, ensuring a late validation response can never mutate the persisted `valid` field of a block whose consensus state machine has already moved on.

### Proof of Concept
1. Signer submits block B for stacks-node validation (`submit_block_for_validation`), tracked as `submitted_block_proposal`.
2. Before the node's validation response returns, enough peer `BlockResponse::Rejected` messages arrive to push B's `BlockInfo.state` to `GloballyRejected` via `store_and_process_block_rejection` (`mark_globally_rejected`).
3. The delayed `BlockValidateOk` for B finally arrives; `handle_block_validate_ok` fetches the (now `GloballyRejected`) `BlockInfo`, whose `valid` is still `None` (rejection signatures set `state` but the local `mark_locally_rejected`/`valid` flag was never necessarily set locally for this signer if it never rejected itself — e.g. its own vote was still pending).
4. `check_block_against_signer_db_state` returns `None` (no rejection reason applies), so the code calls `block_info.mark_pre_committed()`, which sets `valid = Some(true)` but `move_to(PreCommitted)` fails (`GloballyRejected` isn't `Unprocessed`).
5. Since `block_info.has_reached_consensus()` is presumably `true` for `GloballyRejected`, the early-return guard is skipped, so `insert_block` persists `valid = Some(true)` against the `GloballyRejected` record, and `send_block_pre_commit` / `handle_block_pre_commit` execute for a block the signer set has already rejected.     /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
