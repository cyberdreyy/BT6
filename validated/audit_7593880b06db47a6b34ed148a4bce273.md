### Title
External Initiator credential can trigger runs of ANY int-ID job, not just the job it was registered for - ([File: core/web/pipeline_runs_controller.go])

### Summary
The `/v2/jobs/:ID/runs` route is guarded by `Authenticate(..., AuthenticateExternalInitiator, AuthenticateByToken, AuthenticateBySession)` [1](#0-0) , and `AuthenticateExternalInitiator` unconditionally grants any valid EI credential a synthetic `UserRoleRun` identity in the same `SessionUserKey` slot used for real users [2](#0-1) . `PipelineRunsController.Create` then only checks `isUser` (i.e. "is *any* identity present in `SessionUserKey`") before running the job by an arbitrary attacker-supplied int32 job ID, with no check that the authenticated EI is bound to that specific job or bridge [3](#0-2) .

### Finding Description
`AuthenticateExternalInitiator` finds the EI record by access key/secret and, on success, sets `c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})` [4](#0-3) . This makes `auth.GetAuthenticatedUser(c)` return `ok == true` for an EI exactly as it would for a real logged-in user, and `auth.RequiresRunRole` (used to wrap `prc.Create` in the router) passes because `UserRoleRun` satisfies the "at least run" check [5](#0-4) [6](#0-5) .

Inside `PipelineRunsController.Create`, the only gate for running a job by integer ID is:
```go
_, isUser := auth.GetAuthenticatedUser(c)
// only users are allowed to run jobs using int IDs - EIs not allowed
if isUser {
    ...
    jobRunID, err := prc.App.RunJobV2(ctx, jobID, nil)
``` [7](#0-6) 

The comment claims "EIs not allowed," but that is factually incorrect for the current code: since `AuthenticateExternalInitiator` populates `SessionUserKey` identically to a real user, `isUser` is `true` for an EI-authenticated request too. There is no lookup of `auth.GetAuthenticatedExternalInitiator(c)` in this handler to verify the EI's identity is associated with the target job ID, and `app.RunJobV2` (in `core/services/chainlink/application.go`) takes an arbitrary `jobID int32` and executes the pipeline for whatever job is found, again with no ownership/binding check [8](#0-7) .

Historically, EI-triggered runs were scoped through webhook jobs referenced by UUID (`ExternalJobID`), where the specific job's webhook/bridge spec bound it to a specific EI. That code path is now dead — any UUID-looking ID immediately errors with `job.ErrJobTypeRemoved` because Webhook job type support was removed [9](#0-8) . The only remaining path is the "int ID" branch, which has no such binding, so any authenticated EI holder can run any job by its integer database ID.

### Impact Explanation
An attacker who registers/holds only external-initiator credentials scoped to one bridge/job can trigger pipeline runs of unrelated jobs belonging to the same node, matching the Chainlink bounty impact class of "unauthorized job run" / authorization bypass via request-binding violation. Depending on the target job's task graph, this could cause unwanted on-chain transactions, spurious external HTTP calls with the node's credentials, VRF fulfillment simulation, or resource exhaustion — actions the EI was never authorized to perform.

### Likelihood Explanation
Exploitation requires only possession of any valid EI access key/secret pair (the lowest-privilege credential type in the system, obtainable by any EI owner and often distributed to third-party integrations) and knowledge/guessing of a target job's small integer ID, which is not treated as a secret and is often sequential/enumerable via other public-facing behavior. No admin or extra role is needed since `RequiresRunRole` already accepts EI-derived `UserRoleRun`. This is fully repeatable via HTTP.

### Recommendation
In `PipelineRunsController.Create`, distinguish between a real user session/token (`AuthenticateBySession`/`AuthenticateByToken`) and an EI-derived identity. For EI-authenticated requests, resolve `auth.GetAuthenticatedExternalInitiator(c)` and verify the target job (via its bridge/webhook spec or explicit EI-to-job mapping) is actually registered to that EI before calling `RunJobV2`; reject with 401/403 otherwise. Do not rely on the synthetic `UserRoleRun` user object to imply general run permission for EIs.

### Proof of Concept
Handler-level Go test (extend `core/web/pipeline_runs_controller_test.go`):
1. Start `cltest.NewApplicationEVMDisabled(t)`, create EI `eiA` via `bridges.NewExternalInitiator` + `app.BridgeORM().CreateExternalInitiator`, and register it against `bridgeA`/`jobA`'s pipeline spec.
2. Create a second, unrelated job `jobB` (int-ID job type, e.g. `cltest.MustInsertV2JobSpec` or similar non-webhook spec) that has no relation to `eiA`.
3. Send `POST /v2/jobs/{jobB.ID}/runs` with headers `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` set to `eiA`'s credentials.
4. Assert response is `200 OK` and a `pipelineRun` resource for `jobB` is returned (confirms `app.RunJobV2` executed for `jobB` despite `eiA` only being registered for `jobA`).
5. Add assertion that this should instead return `401/403` once the binding check from the Recommendation is implemented, to demonstrate the fix.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (app *ChainlinkApplication) RunJobV2(
	ctx context.Context,
	jobID int32,
	meta map[string]any,
) (int64, error) {
	if build.IsProd() {
		return 0, errors.New("manual job runs not supported on secure builds")
	}
	jb, err := app.jobORM.FindJob(ctx, jobID)
	if err != nil {
		return 0, errors.Wrapf(err, "job ID %v", jobID)
	}
	var runID int64

	// Some jobs are special in that they do not have a task graph.
	isBootstrap := jb.Type == job.OffchainReporting && jb.OCROracleSpec != nil && jb.OCROracleSpec.IsBootstrapPeer
	if jb.Type.RequiresPipelineSpec() || !isBootstrap {
		var vars map[string]any
		var saveTasks bool
		if jb.Type == job.VRF {
			saveTasks = true
			// Create a dummy log to trigger a run
			testLog := types.Log{
				Data: bytes.Join([][]byte{
					jb.VRFSpec.PublicKey.MustHash().Bytes(),  // key hash
					common.BigToHash(big.NewInt(42)).Bytes(), // seed
					evmutils.NewHash().Bytes(),               // sender
					evmutils.NewHash().Bytes(),               // fee
					evmutils.NewHash().Bytes(),
				}, // requestID
					[]byte{}),
				Topics:      []common.Hash{{}, jb.ExternalIDEncodeBytesToTopic()}, // jobID BYTES
				TxHash:      evmutils.NewHash(),
				BlockNumber: 10,
				BlockHash:   evmutils.NewHash(),
			}
			vars = map[string]any{
				"jobSpec": map[string]any{
					"databaseID":    jb.ID,
					"externalJobID": jb.ExternalJobID,
					"name":          jb.Name.ValueOrZero(),
					"publicKey":     jb.VRFSpec.PublicKey[:],
					"evmChainID":    jb.VRFSpec.EVMChainID.String(),
				},
				"jobRun": map[string]any{
					"meta":           meta,
					"logBlockHash":   testLog.BlockHash[:],
					"logBlockNumber": testLog.BlockNumber,
					"logTxHash":      testLog.TxHash,
					"logTopics":      testLog.Topics,
					"logData":        testLog.Data,
				},
			}
		} else {
			vars = map[string]any{
				"jobRun": map[string]any{
					"meta": meta,
				},
			}
		}
		runID, _, err = app.pipelineRunner.ExecuteAndInsertFinishedRun(ctx, *jb.PipelineSpec, pipeline.NewVarsFrom(vars), saveTasks)
	}
	return runID, err
}
