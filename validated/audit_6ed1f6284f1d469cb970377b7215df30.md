### Title
Unauthenticated resource-exhaustion via unbounded concurrent pprof profile proxy requests - (File: core/web/loop_registry.go)

### Summary
The `/plugins/:name/debug/pprof/*` routes are registered without any authentication middleware, and `LoopRegistryServer.doRequest` uses `http.DefaultClient` (not the 1-second-timeout `l.promClient`) to proxy pprof requests to internal LOOP plugin ports, with a timeout equal to `seconds+30`. An unauthenticated attacker can issue many concurrent `GET /plugins/{name}/debug/pprof/profile?seconds=<large>` requests to hold open long-lived internal connections and goroutines with no authentication barrier.

### Finding Description
`loopRoutes` wires `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler` on the bare `api` group [1](#0-0) , whereas comparable sensitive endpoints (`/debug/vars`, `/debug/pprof/*` under `metricRoutes`, `/v2/*`) are always wrapped with `auth.Authenticate(...)` [2](#0-1) [3](#0-2) . `pluginPPROFHandler` computes a `timeout` from the `seconds` query parameter via `pprofURLVals`, which is `PPROFOverheadSeconds + seconds` (default 30s cap-free — no maximum enforced on `seconds`) [4](#0-3) . This timeout and request are then passed to `doRequest`, which explicitly performs the outbound proxy call using `http.DefaultClient.Do(req)` rather than `l.promClient` (the client with a hardcoded 1-second timeout used for `/metrics`) [5](#0-4) . Because there's no authentication gate on this route and no upper bound on `seconds`, any unauthenticated client can open many concurrent requests, each holding a server-side goroutine, an internal HTTP connection to the plugin's pprof endpoint, and a `context.WithTimeout` for `seconds+30` seconds (attacker-controlled and unbounded), tying up node-side network sockets/goroutines with zero credentials required.

### Impact Explanation
This maps to Chainlink's Denial-of-Service / resource-exhaustion impact class reachable without authentication. Repeated unauthenticated large-`seconds` profile requests can exhaust available goroutines/file descriptors/internal connections on the node's web server, potentially degrading or blocking legitimate authenticated node operations (job execution, monitoring, admin API access), which is a materially different and more severe condition than the bounded 1-second-timeout metrics path.

### Likelihood Explanation
No credential, session, or API token is required — the routes are reachable by any network client that can reach the node's HTTP port and know (or guess) a registered plugin name via `l.registry.List()`/`/discovery` (also unauthenticated) [6](#0-5) . The attack is trivially repeatable and scriptable (fire N concurrent GETs with large `seconds`), making this a low-effort, high-repeatability condition assuming the node runs LOOP plugins with reachable prometheus/pprof ports.

### Recommendation
Wrap the `loopRoutes` pprof and metric endpoints (or at minimum the pprof ones) with `auth.Authenticate(...)` middleware consistent with `metricRoutes`/`debugRoutes`; enforce a hard maximum on the `seconds` query parameter server-side before computing `timeout`; and use a bounded/shared `http.Client` (e.g., reuse `l.promClient` semantics or a dedicated client with connection limits and a sane max timeout) instead of `http.DefaultClient` in `doRequest`.

### Proof of Concept
Handler-level integration test plan:
1. Spin up `NewRouter` (or directly construct the gin engine with `loopRoutes`) against a test `chainlink.Application` with a mocked `plugins.LoopRegistry` containing a fake plugin pointing to a local test pprof server that sleeps for `seconds` duration.
2. Without any `Authorization` header or session cookie, issue N (e.g., 50) concurrent `GET /plugins/testplugin/debug/pprof/profile?seconds=60` requests.
3. Assert: (a) all requests are accepted with HTTP 200/without any 401/403, confirming no auth gate; (b) `runtime.NumGoroutine()` grows by ~N during the test window, remaining elevated for close to `seconds+PPROFOverheadSeconds`; (c) contrast with an authenticated-only route (e.g., `/v2/build_info` or `metricRoutes` pprof under `authv2`) which returns 401 when unauthenticated, demonstrating the asymmetry.
4. Optionally assert `doRequest`'s outbound request uses a client without the 1s timeout by verifying requests with `seconds` values exceeding 1 second still succeed (proving `l.promClient`'s 1s timeout is not applied to this path), unlike `pluginMetricHandler`, which would fail for any backend response slower than 1s.

```go
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
```

```go
const PPROFOverheadSeconds = 30

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}
```

```go
func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
```
