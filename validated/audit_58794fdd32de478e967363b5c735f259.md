### Title
Stale confirmations from removed multisig members/keys can be counted toward the confirmation threshold, allowing request execution below the live-member quorum - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
When a multisig key (`multisig`) or member (`multisig2`) is removed via `DeleteKey`/`DeleteMember`, the contract only deletes requests that the removed key/member *created*. It never scrubs that key/member's prior *confirmations* recorded on other pending requests created by other members. Those stale confirmations remain in the `confirmations: UnorderedMap/LookupMap<RequestId, HashSet<..>>` and continue to count toward `num_confirmations` in `confirm()`, so a request can later execute with fewer live, currently-authorized confirmations than the configured threshold.

### Finding Description
In `multisig/src/lib.rs`, `execute_request`'s `DeleteKey` branch (lines 198-216) computes `request_ids` as requests whose `signer_pk` (the original requester) equals the deleted key, and removes only those requests/confirmations: [1](#0-0) 

It never inspects other requests' `confirmations` HashSet to strip the deleted key's prior confirmation entries. `confirm()` (lines 246-266) simply counts `confirmations.len() + 1 >= self.num_confirmations` without validating that each recorded confirming key is still an active key of the contract account: [2](#0-1) 

The same pattern exists in `multisig2/src/lib.rs`. `delete_member` filters `self.requests` by `r.member == member` (lines 361-374) — again only requests *created* by the removed member — and leaves that member's confirmation string in `confirmations` sets of requests created by other members: [3](#0-2) 

`confirm()` in `multisig2` (lines 292-315) likewise trusts the raw count of stored confirmation strings, without checking `self.members.contains(...)` for each entry: [4](#0-3) 

Binding broken: the intended invariant is `live confirmations recorded >= num_confirmations` (i.e., only confirmations from *currently authorized* keys/members should count toward the threshold). After a `DeleteKey`/`DeleteMember` action, the actual state is `confirmations.len()` includes confirmations from keys/members no longer in `members`/no longer valid access keys, so the equality `authorized confirmers == recorded confirmers` breaks.

### Impact Explanation
This is a "multisig request executed below threshold" scenario (Critical per the given impact categories): a `Transfer`, `FunctionCall`, `AddKey`/`AddMember`, or other high-value action can be executed by combining confirmations from members who currently number fewer than `num_confirmations`, because one or more of the counted confirmations belongs to a key/member that has since been revoked. This directly undermines the authorization threshold the multisig is meant to enforce, and can lead to unauthorized movement of NEAR held by the multisig account.

### Likelihood Explanation
This requires no special privilege beyond being (or having been) a legitimate multisig member/key at some point, and requires a normal governance action (removing a member/key) to occur afterward — a routine operational event for any multisig (e.g. rotating a compromised or departing signer). Any pending request that received a confirmation from the since-removed member before removal remains exploitable by the remaining members without any additional confirmation from the removed party.

### Recommendation
When executing `DeleteKey`/`DeleteMember`, iterate over **all** `confirmations` entries (not just requests created by the removed key/member) and remove the removed key's/member's entry from every confirmation set; alternatively, validate membership of each recorded confirmer at `confirm()` time (filtering out/discarding stale confirmations from accounts no longer in `members`, or recomputing effective confirmation count against currently valid keys/members) before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C]`, `num_confirmations = 2`.
2. Member `A` calls `add_request` with a `Transfer` action to an attacker-controlled receiver (creates request `R`, `signer/member = A`, not yet confirmed).
3. Member `B` calls `confirm(R)` → `confirmations(R) = {B}` (1 < 2, so it stays pending) — see `confirm()` at `multisig2/src/lib.rs:294-315`.
4. Separately, members confirm and execute a `DeleteMember { member: B }` request (e.g. because `B`'s key is believed compromised). `delete_member` (`multisig2/src/lib.rs:356-379`) removes `B` from `self.members` and deletes `B`'s access key on-chain, but request `R`'s `confirmations` set still contains `B`'s entry because `R` was created by `A`, not `B`.
5. Member `C` calls `confirm(R)`. `confirmations(R).len() + 1 == 2 >= num_confirmations (2)`, so `execute_request` runs the `Transfer` — even though only `A` (creator) and `C` are current live members confirming, and `B`'s stale, revoked confirmation was needed to reach the threshold that should require 2 *live* confirmers acting after `B`'s removal.
6. Funds are transferred out of the multisig account despite the removed member's authority having been revoked, demonstrating execution below the intended live-member threshold.

        self.assert_valid_request(request_id);

        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {

        } else {

            self.confirmations.insert(&request_id, &confirmations);

        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
