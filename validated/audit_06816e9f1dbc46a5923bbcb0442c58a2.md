### Title
Client-supplied `requestID` reuse allows cross-workflow response misdelivery in `httpTriggerHandler` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The gateway's HTTP trigger callback table (`h.callbacks`) is keyed solely by the client-supplied `requestID` with no binding to the requester's identity, workflow, or a per-registration generation token. `setupCallback` only rejects a `requestID` that is *currently* in-flight; once `cleanupCallback` deletes the entry (on quorum success or reap), the same ID can be immediately reused by any other caller, and `HandleNodeTriggerResponse` will blindly route any subsequent node response bearing that `requestID` to whichever caller currently owns the map entry.

### Finding Description
`setupCallback` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:398-435`) only guards against a currently in-flight collision: [1](#0-0) 
Once that request's callback is removed via `cleanupCallback` (called either on quorum success in `HandleNodeTriggerResponse` line 491, or by the reaper `reapExpiredCallbacks`), the same `requestID` string is free to be reused by a completely different, unrelated caller's request, because `h.callbacks` is a single global `map[string]savedCallback` with no owner/workflow binding baked into the key or a generation counter distinguishing successive registrations under the same ID: [2](#0-1) 

`HandleNodeTriggerResponse` then looks the response up purely by `resp.ID` and forwards it to whatever `savedCallback` currently occupies that slot, with no check that the response actually corresponds to the workflow/owner that registered that slot — only a shard-membership check is performed: [3](#0-2) 

Because a workflow can be assigned multiple shards, and cleanup happens as soon as the *first* shard reaches quorum (`// First shard to reach quorum wins`), responses from the *other*, still-in-flight shard(s) of the original request may straggle in after cleanup. If, in that window, another caller submits a new request reusing the same `requestID` and that caller's workflow happens to share a shard/DON with the victim's workflow, the straggling genuine node responses for the victim's execution will be collected by the new `IdenticalNodeResponseAggregator` created for the attacker's request and, if they reach threshold, delivered via `saved.SendResponse` to the attacker's callback — i.e., the victim's execution output is delivered to the attacker.

### Impact Explanation
This is a cross-user response confusion: an unprivileged caller can, with correct timing, receive another user's workflow execution result payload through their own HTTP trigger callback, violating the invariant that a gateway request/response pair is bound to exactly one sender. This maps to unauthorized disclosure of another user's job/execution data.

### Likelihood Explanation
Exploitation requires: (1) the attacker knows or can guess a `requestID` currently in flight for a target workflow (feasible if IDs are predictable, sequential, or otherwise observable — e.g., logs, timing side channels, or if the attacker is the intended recipient of a public webhook style requestID); (2) the attacker races to re-register the same `requestID` in the narrow window between the victim's quorum-triggering shard completing and cleanup, and any straggling shard's late responses arriving; (3) the attacker's own workflow must be assigned to the same shard as the victim's straggling shard so the responses aggregate and reach quorum. This is a non-trivial race with several preconditions, but it requires no elevated privileges — only the ability to submit HTTP trigger requests with an attacker-chosen `requestID`, satisfying the "unprivileged caller" threat model.

### Recommendation
Do not key the callback table purely on the raw client-supplied `requestID`. Bind each registration to the authenticated caller/workflow (e.g., derive the internal map key from `(workflowID, workflowOwner, requestID)` or attach a per-registration generation/nonce that must match on response delivery). Additionally, `HandleNodeTriggerResponse` should validate that the responding node's shard/workflow assignment matches the *same* registration generation that sent the outbound request, not merely whichever entry currently occupies `h.callbacks[requestID]`, and should reject or discard responses for a request ID after cleanup rather than allowing new registrations to silently absorb stale node responses.

### Proof of Concept
Go handler-level integration test (extending `http_trigger_handler_test.go`):
1. Register two workflows, `wfVictim` and `wfAttacker`, both assigned to the same shard (`donID: "shardA"`) plus `wfVictim` additionally assigned to a second shard `shardB`.
2. Call `HandleUserTriggerRequest` for `wfVictim` with `requestID = "dup-1"`.
3. Simulate `shardA` reaching quorum by calling `HandleNodeTriggerResponse` with matching responses from `shardA`'s nodes for `resp.ID = "dup-1"`; assert `cleanupCallback` removes the entry (verify via a subsequent lookup or exported test hook) and the victim callback receives its correct response.
4. Immediately call `HandleUserTriggerRequest` for `wfAttacker` with the same `requestID = "dup-1"`; assert it succeeds (no `ErrConflict`), creating a new `savedCallback` with a fresh aggregator for `shardA`.
5. Deliver the previously-pending `shardB` node responses for the original victim execution (still carrying `resp.ID = "dup-1"`) via `HandleNodeTriggerResponse`, using node addresses mapped to `shardA` instead (representing overlap) reaching quorum for `wfAttacker`'s aggregator.
6. Assert that the attacker's callback (`callback.SendResponse`) receives the victim's original response payload — demonstrating cross-user response delivery — and that this should instead be rejected (expected fix: response rejected because it does not match the current registration's workflow/generation).

```go
func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
```

```go
// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}
```

```go
func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}
	aggResp, err := agg.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
	if aggResp == nil {
		h.lggr.Debugw("Not enough responses to aggregate", "requestID", resp.ID, "nodeAddress", nodeAddr, "shard", shard.donID)
		return nil
	}
	rawResp, err := json.Marshal(aggResp)
	if err != nil {
		return errors.New("failed to marshal response: " + err.Error())
	}

	err = saved.SendResponse(handlers.UserCallbackPayload{
		RawResponse: rawResp,
		ErrorCode:   api.NoError,
	})
	if err != nil {
		return err
	}

	// First shard to reach quorum wins: only after successfully sending the
	// response, clean up the callback (closes doneCh, stopping all shard sends).
	h.cleanupCallback(resp.ID)
```
