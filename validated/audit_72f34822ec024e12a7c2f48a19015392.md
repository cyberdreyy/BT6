### Title
Deleted multisig signer's stale confirmation is still counted toward `num_confirmations`, allowing a request to execute below the live-signer threshold - (File: `multisig/src/lib.rs`)

### Summary
The `MultiSigContract::confirm` function counts confirmations stored in the `confirmations: UnorderedMap<RequestId, HashSet<PublicKey>>` map without verifying that each recorded public key is still a valid access key on the account. When a key is removed via the `DeleteKey` action, `execute_request` only purges requests *created* by that key and the `num_requests_pk` counter for it; it does not scan and remove that key's confirmation entries from `self.confirmations` on other, still-pending requests it had previously confirmed. As a result, a stale confirmation from a since-revoked key remains counted, and a request can reach `num_confirmations` and execute with fewer currently-live signers than the threshold requires.

### Finding Description
`confirm()` compares `confirmations.len() as u32 + 1 >= self.num_confirmations` and executes the request once that condition holds [1](#0-0) . The only place confirmations are purged due to key removal is inside the `DeleteKey` action handler, and it filters strictly by `r.signer_pk == pk`, i.e., requests the deleted key itself *created*, not confirmations it cast on other requests: [2](#0-1) 

Nothing else in the contract removes a deleted key's `PublicKey` entries from other requests' `HashSet<PublicKey>` in `self.confirmations`. Consequently the invariant the contract is supposed to maintain — "confirmations counted == confirmations from currently live/authorized signer keys" — can be broken: a confirmation from a key that is no longer an authorized signer on the account still counts toward `num_confirmations`.

This is the same class of bug as the external report: a trust binding (there, `_smartWallet` address vs. an actually-valid wallet; here, a counted confirmation vs. an actually-live signer key) is never re-validated at the point where funds/authority are committed.

### Impact Explanation
This falls under the explicitly listed Critical impact: "a multisig request executed below threshold." A transfer or other privileged action (`Transfer`, `AddKey`, `FunctionCall`, etc.) can be executed by `execute_request` with effective authorization from fewer live signers than `num_confirmations` mandates, because one or more of the counted confirmations belong to a key that was already revoked. This directly weakens the multisig's custody guarantee over NEAR held by the account.

### Likelihood Explanation
Requires no attacker-side privilege beyond having previously held a multisig key that was later revoked (a normal, expected lifecycle event for any multisig, e.g. member rotation/offboarding). Any request that receives a confirmation and is left pending across a subsequent `DeleteKey` action against that confirmer is affected — this is a realistic, not contrived, sequence of operations that a legitimate deployment would perform.

### Recommendation
When executing a `DeleteKey` action, iterate over all entries in `self.confirmations` (not only requests where `signer_pk == pk`) and remove the deleted `pk` from every `HashSet<PublicKey>` found. Alternatively, validate at `confirm()`/`execute_request()` time that every public key in the stored confirmation set is currently a valid access key on `env::current_account_id()` before counting it toward `num_confirmations`.

### Proof of Concept
1. Multisig initialized with `num_confirmations = 3` and signer keys `A, B, C, D`.
2. Key `A` calls `add_request` to create request `R` (`Transfer`), then key `B` calls `confirm(R)` → `confirmations[R] = {B}` (len 1) [1](#0-0) .
3. Separately, a fully-confirmed request executes `DeleteKey { public_key: B }`. `execute_request` removes requests created by `B` and `num_requests_pk[B]`, but leaves `confirmations[R] = {B}` untouched [2](#0-1) . Key `B` is now removed from the account and is no longer a valid signer.
4. Key `C` calls `confirm(R)` → `confirmations[R] = {B, C}` (len 2, still below 3).
5. Key `D` calls `confirm(R)` → `confirmations.len() + 1 = 3 >= num_confirmations(3)` → `execute_request(R)` runs the `Transfer`, even though only `C` and `D` are currently live, authorized signers who actually confirmed post-revocation; `B`'s stale confirmation supplied the missing vote. [3](#0-2)

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
