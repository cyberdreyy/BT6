### Title
Unauthenticated `InitForcefulShutdown` gRPC RPC on loopback lets any local job kill the shared multi-tenant wrapped runner process - (File: helpers/runner_wrapper/api/server/server.go)

### Summary
`RunnerWrapperCommand.Execute` starts an unauthenticated gRPC server on `tcp://localhost:7777` by default (`defaultWrapperGRPCListen`) that forwards `InitForcefulShutdown` directly to `Wrapper.InitiateForcefulShutdown`, which force-kills the single wrapped `gitlab-runner run` process backing the whole "wrapper" instance. Any local process able to reach loopback on that host/VM can invoke this RPC with zero authentication and terminate every concurrently running job on that instance, not just its own.

### Finding Description
`commands/wrapper.go` sets the default listen address to `tcp://localhost:7777` [1](#0-0)  and `RunnerWrapperCommand.Execute` wires a plain `net.Listener` into `server.New(grpcLog, w)` / `srv.Listen(l)` with no TLS or auth options [2](#0-1) .

`server.New` builds the gRPC server with `grpc.NewServer()` — no interceptor, no credentials, no per-RPC auth check of any kind [3](#0-2) . `Server.InitForcefulShutdown` unconditionally calls `s.wrapper.InitiateForcefulShutdown()` for any caller [4](#0-3) . `ProcessWrapper_ServiceDesc` exposes this method with no auth metadata requirement [5](#0-4) .

`Wrapper.InitiateForcefulShutdown` operates on `w.process`, which is the single child process started via `w.commanderFactory(w.path, w.args)` where `path` is the `gitlab-runner` binary and `args` is whatever was passed to `gitlab-runner wrapper <args>` (typically `run`) [6](#0-5) [7](#0-6) . That single wrapped process is the entire multi-runner manager (`gitlab-runner run`), which per its own documentation and `commands/multi.go` handles all configured runners/projects concurrently, not one job [8](#0-7) .

This is most concretely reachable on the **instance executor with autoscaling**: `capacity_per_instance > 1` runs multiple jobs concurrently on the same VM without process/user isolation, and jobs execute directly on that VM's OS (not inside a container network namespace) [9](#0-8) . If that instance's runner-manager process is started via `gitlab-runner wrapper run ...` (the wrapper's stated purpose: "start multi runner service wrapped with gRPC manager server", used for fleeting/taskscaler graceful/forceful shutdown orchestration), the wrapper's gRPC port is reachable on `localhost:7777` from any process running directly on that VM — including an unprivileged job's own shell commands, since instance-executor jobs are not containerized and share the host loopback. A job simply issuing `grpcurl -plaintext localhost:7777 gitlab_com.gitlab_runner.runner_wrapper.ProcessWrapper/InitForcefulShutdown` (or an equivalent raw gRPC call) reaches the unauthenticated handler and forces the entire wrapped `gitlab-runner run` process to be killed, aborting all other jobs concurrently scheduled on that instance/VM — potentially from different projects, since `capacity_per_instance` slots are not project-scoped.

No allowed-image, path-validation, or auth check anywhere in `Server` or in `grpc.NewServer()` mitigates this; the RPC is deliberately unauthenticated by design as an internal control channel, but is bound to a plain TCP loopback socket reachable by anything on the same host/VM.

### Impact Explanation
A single unprivileged job — without any admin misconfiguration of containers, privileged mode, or host networking (the instance executor inherently runs jobs directly on the VM) — can force-kill the shared runner-manager process. This aborts every other concurrently running job/project scheduled on that instance, a persistent, multi-tenant disruption that outlives the attacker's own job and is not confined to the attacker's workspace/session, directly matching the tested invariant.

### Likelihood Explanation
Preconditions: the deployment must use `gitlab-runner wrapper run` (rather than plain `run`) to front the `run` command with the gRPC control API, and `--grpc-listen` left at its default (`tcp://localhost:7777`) or otherwise bound to a TCP/loopback address reachable from job workloads. This applies specifically to the instance/docker-autoscaler executor pattern where `capacity_per_instance > 1` and jobs run directly on the same VM as the wrapper (no network namespace isolation from loopback). Given that pattern, exploitation is trivial and 100% repeatable: one gRPC unary call with an empty request body, no credentials, no retries needed.

### Recommendation
- Require authentication/authorization for the wrapper gRPC API (e.g., a per-instance shared secret injected out-of-band, mTLS, or Unix domain socket restricted by filesystem permissions to a specific trusted user/group not shared with the job execution user).
- Default `--grpc-listen` to a Unix socket with restrictive permissions instead of a TCP loopback listener, and document that TCP listeners must never be reachable from job execution contexts.
- At minimum, add a `grpc.UnaryInterceptor` enforcing a token check before dispatching to `InitForcefulShutdown`/`InitGracefulShutdown`.

### Proof of Concept
Go integration test in `helpers/runner_wrapper/api/server`:
```go
func TestServer_InitForcefulShutdown_NoAuth(t *testing.T) {
    mockWrapper := new(mocks.wrapper) // generated mock implementing the `wrapper` interface
    mockWrapper.On("InitiateForcefulShutdown").Return(nil)
    mockWrapper.On("Status").Return(api.StatusStopped)
    mockWrapper.On("FailureReason").Return("")

    lis, _ := net.Listen("tcp", "127.0.0.1:0")
    srv := server.New(logrus.NewEntry(logrus.New()), mockWrapper)
    go srv.Listen(lis)
    defer srv.Stop()

    // Unrelated, unauthenticated client - simulating a job process on the same host
    conn, _ := grpc.NewClient(lis.Addr().String(), grpc.WithTransportCredentials(insecure.NewCredentials()))
    client := pb.NewProcessWrapperClient(conn)

    _, err := client.InitForcefulShutdown(context.Background(), &pb.InitForcefulShutdownRequest{})
    require.NoError(t, err)

    // Assert the call succeeded with no identity/authorization check
    mockWrapper.AssertCalled(t, "InitiateForcefulShutdown")
}
```
Expected assertion: the unauthenticated RPC succeeds and `InitiateForcefulShutdown` is invoked, proving there is no caller-identity check anywhere in the request path, confirming that any co-located process (e.g., an instance-executor job script) can force-kill the shared wrapped runner process.

```go
		}
```

```go
		Status:        api.Statuses.Map(s.wrapper.Status()),
		FailureReason: s.wrapper.FailureReason(),
```

```go
func (w *Wrapper) start() {
	cmd := w.commanderFactory(w.path, w.args)

	w.log.
		WithField("path", w.path).
		WithField("args", w.args).
		Debug("Starting process")

	err := cmd.Start()
	if err != nil {
		w.errCh <- fmt.Errorf("%w: %w", errFailedToStartProcess, err)
		return
	}

	w.setProcess(cmd.Process())
	w.setStatus(api.StatusRunning)

	w.errCh <- cmd.Wait()
}
```

```go
func (w *Wrapper) InitiateForcefulShutdown() error {
	w.lock.RLock()
	p := w.process
	w.lock.RUnlock()

	if p == nil {
		return api.ErrProcessNotInitialized
	}

	w.log.Info("Initiating forceful shutdown of the process")

	err := w.forcefulShutdown(p)
	if err != nil {
		return fmt.Errorf("could not send forceful shutdown signal: %w", err)
	}

	w.setStatus(api.StatusInShutdown)

	return nil
}
```
