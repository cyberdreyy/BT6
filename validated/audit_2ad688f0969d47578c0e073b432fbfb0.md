### Title
`setApr`/`setAprs`/`setAprsWithBuffer` skip the caller check entirely while `idleCDO == address(0)`, letting any EOA set `lastApr` and `unscaledApr` before CDO whitelisting - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
The closest analog to "authentication check evaluated but execution continues anyway" is `setApr` in `IdleCreditVault`. Like the elFinder connector that sends a redirect but keeps executing, `setApr` contains an authorization check that is conditionally bypassed: when `idleCDO` is not yet set, the `msg.sender` check is skipped and any caller can write `lastApr` (and, via `setAprs`/`setAprsWithBuffer`, `unscaledApr`) at will.

### Finding Description [1](#0-0) 

```solidity
function setApr(uint256 _apr) public {
  address _cdo = idleCDO;
  // if cdo is not yet set we skip the check (this can happen only during the setup)
  if (_cdo != address(0)) {
    if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
  }
  uint256 _maxApr = maxApr;
  if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
  lastApr = _apr;
}
```

Between `initialize` (line 124) and `setWhitelistedCDO` (line 954), `idleCDO == address(0)`, so the only caller restriction is absent. `setAprs` (line 206) and `setAprsWithBuffer` (line 217) write `unscaledApr` before delegating to `setApr`, inheriting the same bypass. `maxApr` defaults to `DEFAULT_MAX_APR = 20e18` (line 143), so an attacker can pin `lastApr`/`unscaledApr` to 20% scaled. `lastApr` is the value the CDO uses to compute `expectedEpochInterest` for the epoch (it is only overwritten when the CDO/manager later calls `setAprsWithBuffer` during `startEpoch`; in flows where the CDO does not push a fresh APR each epoch, the attacker-set value persists into interest accounting). Inflated `expectedEpochInterest` inflates the borrower repayment demanded at `stopEpoch`; a shortfall pushes the vault toward `defaulted` handling, socializing the shortfall across AA/BB LPs via the default-recovery waterfall (`finalizeDefaultRecovery`, line 661). Setting `unscaledApr = 0` also flips `requestWithdraw` into the APR0 accounting branch (`_requestWithdrawApr0`, line 285), corrupting `apr0TotalPrincipal`/`apr0RateByEpoch` interest settlement.

### Impact Explanation
Unauthorized control over the vault's APR parameter. Depending on whether the CDO overwrites APRs at each `startEpoch`, this ranges from forcing an inflated borrower obligation (driving an otherwise unnecessary default and LP haircut through `defaultRecoveryPrice`) to corrupting APR0 withdraw settlement. Loss is bounded by what the manipulated interest demand induces; a forced default crystallizes losses across all tranche holders.

### Likelihood Explanation
Exploitability depends on deployment ordering: `initialize` sets `maxApr` and leaves `idleCDO` unset, and the window closes only when `setWhitelistedCDO` is called. If `IdleCreditVaultFactory` (or the deployer) does not call `setWhitelistedCDO` atomically in the same transaction as `initialize`, any EOA can front-run the whitelisting. If deployment is atomic, there is no reachable window and this is a hardening issue only — this precondition could not be fully verified against the factory deployment flow in this pass and should be confirmed.

### Recommendation
Apply the caller check unconditionally: require `msg.sender == idleCDO || msg.sender == manager` regardless of whether `idleCDO` is set, or gate the pre-whitelisting path behind `onlyOwner`/manager. Equivalently, allow `unscaledApr`/`lastApr` writes only after `idleCDO != address(0)` and set the CDO atomically during deployment.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
import "forge-std/Test.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";

contract SetAprMissingAuthPoC is Test {
  IdleCreditVault vault;
  address attacker = address(0xBEEF);

  function setUp() public {
    // Deploy implementation + proxy equivalent: initialize WITHOUT setWhitelistedCDO
    vault = new IdleCreditVault();
    // (behind a proxy in production; direct call ok since constructor sets token=address(1) on impl only)
  }

  function testAnyoneCanSetAprBeforeWhitelist() public {
    // On a freshly initialized (not-yet-whitelisted) vault:
    //   idleCDO == address(0) -> auth check in setApr is skipped entirely
    vm.prank(attacker);
    vault.setAprsWithBuffer(0, 30 days, 2 days); // sets unscaledApr=0 AND lastApr=0 -> APR0 mode hijack
    assertEq(vault.unscaledApr(), 0);

    vm.prank(attacker);
    vault.setApr(20e18); // maxApr cap, arbitrary attacker-controlled APR
    assertEq(vault.lastApr(), 20e18);
  }
}
```
The PoC shows a non-privileged EOA writing both `lastApr` and `unscaledApr` while `idleCDO == address(0)`; a full fork PoC should deploy via `IdleCreditVaultFactory`/proxy and confirm whether the whitelist step is atomic with `initialize`.
