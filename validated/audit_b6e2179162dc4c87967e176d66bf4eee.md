### Title
Bridge Transfer Limit Bypass via Stale Notional Price in `TransferRecord.total_amount` — (`crates/sui-framework/packages/bridge/sources/limiter.move`)

---

### Summary

The Sui bridge's `TransferLimiter` enforces a rolling 24-hour USD-denominated transfer cap per route. When `update_asset_notional_price` changes a token's USD price, the existing `TransferRecord.total_amount` — which was computed using the **old** price — is never retroactively adjusted. New transfers are valued at the new price, but the accumulated window total still reflects the old price. When the price rises, past transfers are systematically undervalued in the window, allowing an ordinary user to push the actual USD outflow well above the configured limit.

---

### Finding Description

**Configurable parameter:** `BridgeTokenMetadata.notional_value` (the per-token USD price used to convert raw token amounts into the USD notional stored in `TransferRecord.total_amount`).

**How the limit is enforced** (`limiter.move`, `check_and_record_sending_transfer`):

```move
let route_limit_adjusted =
    (route_limit as u128) * (treasury.decimal_multiplier<T>() as u128);

let notional_amount_with_token_multiplier =
    (treasury.notional_value<T>() as u128) * (amount as u128);   // uses CURRENT price

if (
    (record.total_amount as u128)                                 // uses OLD price
        * (treasury.decimal_multiplier<T>() as u128)
        + notional_amount_with_token_multiplier > route_limit_adjusted
) { return false };

let notional_amount =
    notional_amount_with_token_multiplier / (treasury.decimal_multiplier<T>() as u128);
record.total_amount = record.total_amount + notional_amount;      // stored at CURRENT price
``` [1](#0-0) 

**How the price is updated** (`treasury.move`, `update_asset_notional_price`):

`TransferRecord.total_amount` is **never recalculated** after a price change. The `adjust_transfer_records` helper only evicts hours older than 24 hours; it does not revalue any stored amounts. [3](#0-2) 

---

### Impact Explanation

**Concrete bypass scenario (price increase):**

| Step | Action | `total_amount` (stored) | Actual USD at new price |
|------|--------|------------------------|------------------------|
| 1 | ETH price = $1 000; limit = $5 M; user transfers 1 000 ETH | $1 M | $1 M |
| 2 | Bridge committee updates ETH price to $3 000 | $1 M (stale) | $3 M |
| 3 | Ordinary user transfers 1 000 ETH | check sees $1 M + $3 M = $4 M < $5 M → **accepted** | $3 M + $3 M = **$6 M > $5 M** |

The limit check passes ($4 M < $5 M) but the real USD outflow is $6 M — 20 % above the $5 M cap. With a 3× price jump the bypass factor grows proportionally.

The 24-hour rolling window means the inconsistency persists for up to 24 hours after each price update, during which any ordinary bridge user can exploit it.

**Reverse direction (price decrease):** old transfers are overvalued, causing the limit to be over-enforced and legitimate transfers to be incorrectly rejected — a temporary fund-lock for users.

---

### Likelihood Explanation

- A legitimate bridge-committee price update (the normal operational path) is the only prerequisite.
- After the update, **any** ordinary user holding bridged tokens can send transfers that collectively exceed the intended USD cap.
- Price updates are expected to occur regularly as market prices move; the window of exposure is up to 24 hours per update.
- No special permissions, keys, or exploits are required beyond submitting a normal bridge transfer transaction.

---

### Recommendation

When `update_asset_notional_price` is called, revalue all in-window `TransferRecord` entries for the affected token type, or reset `total_amount` to zero (accepting a brief under-enforcement window rather than an over-bypass window). Alternatively, store raw token amounts per hour instead of pre-converted USD amounts, and compute the USD total on-the-fly using the current price at check time — eliminating the stale-price problem entirely.

---

### Proof of Concept

```
Setup
-----
route_limit          = $5 000 000 (5_000_000 * 1e8)
ETH decimal_mult     = 1e8
ETH notional_value   = $1 000 (1_000 * 1e8 = 1e11)

Step 1 – Transfer 1 000 ETH at old price
  amount                              = 1 000 * 1e8 = 1e11
  notional_amount_with_token_mult     = 1e11 * 1e11 = 1e22
  route_limit_adjusted                = 5e14 * 1e8  = 5e22
  check: (0 * 1e8) + 1e22 = 1e22 < 5e22  → ACCEPTED
  notional_amount stored              = 1e22 / 1e8  = 1e14  ($1 M)
  total_amount                        = 1e14

Step 2 – Governance updates ETH price to $3 000 (3e11)
  total_amount unchanged              = 1e14  (stale $1 M)

Step 3 – Transfer another 1 000 ETH at new price
  notional_amount_with_token_mult     = 3e11 * 1e11 = 3e22
  check: (1e14 * 1e8) + 3e22 = 1e22 + 3e22 = 4e22 < 5e22  → ACCEPTED ✓

Actual USD outflow at new price
  Step 1: 1 000 ETH × $3 000 = $3 M
  Step 3: 1 000 ETH × $3 000 = $3 M
  Total:  $6 M  >  $5 M limit  ← limit bypassed
```

```text
fun adjust_transfer_records(self: &mut TransferRecord, current_hour_since_epoch: u64) {
    if (self.hour_head == current_hour_since_epoch) {
        return // nothing to backfill
    };

    let target_tail = current_hour_since_epoch - 23;

    // If `hour_head` is even older than 24 hours ago, it means all items in
    // `per_hour_amounts` are to be evicted.
    if (self.hour_head < target_tail) {
        self.per_hour_amounts = vector[];
        self.total_amount = 0;
        self.hour_tail = target_tail;
        self.hour_head = target_tail;
        // Don't forget to insert this hour's record
        self.per_hour_amounts.push_back(0);
    } else {
        // self.hour_head is within 24 hour range.
        // some items in `per_hour_amounts` are still valid, we remove stale hours.
        while (self.hour_tail < target_tail) {
            self.total_amount = self.total_amount - self.per_hour_amounts.remove(0);
            self.hour_tail = self.hour_tail + 1;
        }
    };

    // Backfill from hour_head to current hour
    while (self.hour_head < current_hour_since_epoch) {
        self.per_hour_amounts.push_back(0);
        self.hour_head = self.hour_head + 1;
    }
}

```text
public(package) fun update_asset_notional_price(
    self: &mut BridgeTreasury,
    token_id: u8,
    new_usd_price: u64,
) {
    let type_name = self.id_token_type_map.try_get(&token_id);
    assert!(type_name.is_some(), EUnsupportedTokenType);
    assert!(new_usd_price > 0, EInvalidNotionalValue);
    let type_name = type_name.destroy_some();
    let metadata = self.supported_tokens.get_mut(&type_name);
    metadata.notional_value = new_usd_price;

    event::emit(UpdateTokenPriceEvent {
        token_id,
        new_price: new_usd_price,
    })
}
