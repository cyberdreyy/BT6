Confirmed: `delete_member` in `multisig2/src/lib.rs` only purges confirmations/requests that were *authored* by the deleted member (`r.member == member`), never confirmations that member *cast* on other members' requests. This lets a request execute with a confirmation from a member no longer in the multisig, breaking the "confirmations counted vs. live members" custody binding — analogous in class to the Size `compensate()` bug (an action's authorization/pricing is computed from data that can go stale between separate calls).

### Title
Confirmations from removed multisig members remain counted toward the execution threshold - (File: multisig2/src/lib.rs)

### Summary
`confirm()` decides whether to execute a request purely by comparing `confirmations.len()+1` against `self.num_confirmations` [1](#0-0) . `delete_member()` removes a departing member from `self.members` and cleans up requests/confirmations *they authored*, but does not scan other requests' `confirmations` sets to strip entries where that member had already confirmed [2](#0-1) . Consequently a stale confirmation cast by a since-removed member still counts toward the K-of-N threshold on any request they confirmed before being deleted.

### Finding Description
The binding that should hold is: `count(confirmations for request R) == count(confirmations cast by accounts/keys that are currently in self.members)`. The contract instead maintains `confirmations: LookupMap<RequestId, HashSet<String>>` as an append-only-until-removed set keyed by the confirming member's string identity, with no invalidation hook on membership change [3](#0-2) . `delete_member` only filters `self.requests` for entries whose `MultiSigRequestWithSigner.member` equals the deleted member (i.e., requests *they created*), and removes confirmations only for those [4](#0-3) . It never iterates `self.confirmations` to remove the deleted member's entries from requests created by *other* members. When `confirm()` is later called by a remaining member on such a request, it reads the untouched `HashSet` (which still contains the removed member's confirmation) and compares its size to `num_confirmations`, potentially reaching the threshold using one fewer *live* confirming member than `num_confirmations` requires [5](#0-4) .

### Impact Explanation
This falls under "a multisig request executed below threshold," a Critical-severity category by the rules: the contract can transfer funds, deploy code, add/delete members, or add access keys via `execute_request` after collecting fewer genuinely-current-member confirmations than `num_confirmations` mandates [6](#0-5) . E.g., with `num_confirmations = 3`: member A confirms request R1 (created by B) — 1/3. A is then removed via `DeleteMember` (a separate, already-confirmed action). Members C and D now confirm R1; the set already contains A (stale) + C + D = 3, meeting the threshold and executing a `Transfer`/`AddKey`/`DeleteMember` action with only 2 currently-live confirmations instead of 3.

### Likelihood Explanation
No privileged action by the victim is required beyond ordinary multisig operation: any member can be removed for any legitimate reason (key rotation, offboarding) between the time they confirm a pending request and the time that request reaches quorum via other members' confirmations. Given `REQUEST_COOLDOWN`/`active_requests_limit` allow requests to remain open, and membership changes are a normal admin action, this race is easily triggered without collusion or any nearcore/off-chain dependency — it's purely a same-repo logic gap.

### Recommendation
On `delete_member`, iterate all active `requests`/`confirmations` (not just those authored by the removed member) and remove the removed member's string key from every confirmation `HashSet`. Alternatively, validate at `confirm()`-time that every entry in the stored confirmation set still belongs to `self.members` before comparing against `num_confirmations`, discarding stale entries lazily.

### Proof of Concept
1. `MultiSigContract::new(members=[A,B,C,D], num_confirmations=3)`.
2. B calls `add_request(R1)` (Transfer action) → `confirmations[R1] = {}`.
3. A calls `confirm(R1)` → `confirmations[R1] = {A}` (1 < 3, not executed) [7](#0-6) .
4. Members execute a separate fully-confirmed `DeleteMember{member: A}` request → `self.members` no longer contains A; `confirmations[R1]` is untouched because R1 was authored by B, not A [4](#0-3) .
5. C calls `confirm(R1)` → `{A, C}` (2 < 3).
6. D calls `confirm(R1)` → `{A, C, D}`, size 3 ≥ `num_confirmations` (3) → `execute_request(R1)` fires the Transfer, even though only C and D are current members confirming (A is gone) — 2 live confirmations executed a 3-of-N request. [2](#0-1) [8](#0-7)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
