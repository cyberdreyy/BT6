### Title
Path traversal in artifact metadata filename via unsanitized `--name` (`opts.artifactName`) - (File: commands/helpers/artifact_metadata.go)

### Summary
`ArtifactsUploaderCommand.generateStatementToFile` builds the metadata JSON file path with `filepath.Join(opts.artifactsWd, fmt.Sprintf(artifactsStatementFormat, opts.artifactName))`, where `opts.artifactName` is `c.Name` — the pipeline-controlled `artifacts:name` value only passed through `shell.Expand` (variable expansion, no path sanitization). Unlike `artifactFilename()` which explicitly calls `filepath.Base(name)` before using the name for the actual archive file, no equivalent sanitization is applied to the metadata filename, allowing traversal sequences to escape `opts.artifactsWd`.

### Finding Description
`ArtifactsUploaderCommand.Execute` calls `c.normalizeArgs()`, which only expands shell/environment variables in `c.Name` via `mvdan.cc/sh/v3/shell.Expand` and does not strip or validate path-traversal sequences: [1](#0-0) 

That unsanitized `c.Name` is passed straight into `generateStatementOptions.artifactName` when `GenerateArtifactsMetadata` is enabled: [2](#0-1) 

In `generateStatementToFile`, this value is joined with `opts.artifactsWd` (the job's artifacts working directory) using `filepath.Join` and `fmt.Sprintf`, with no `filepath.Clean` + prefix check to confine the result to `artifactsWd`: [3](#0-2) 

Note the contrast: for the actual archive filename, the code deliberately calls `filepath.Base(name)` to strip any directory components before use: [4](#0-3) 

No such sanitization exists for the metadata-file path. Since `filepath.Join` calls `filepath.Clean` on the combined path, a value like `../../../../tmp/pwn` in `c.Name` will legitimately walk `opts.artifactsWd` upward and land outside it, e.g., `/builds/proj/../../../../tmp/pwn-metadata.json` → `/tmp/pwn-metadata.json`. `os.WriteFile` will then create (or truncate/overwrite, if the target already exists and is writable by the job's user) an arbitrary file with a `.json` extension appended by the format string, at that path, with content controlled by the runner (SLSA provenance JSON, not fully attacker-controlled content, but the *location* is attacker-controlled).

### Impact Explanation
An unprivileged pipeline author who sets `artifacts:name: "../../../../some/path/pwn"` in `.gitlab-ci.yml` (with `--generate-artifacts-metadata` enabled, e.g. via provenance/SLSA generation settings) can cause the `gitlab-runner-helper`/uploader process to write a JSON file at an arbitrary filesystem path reachable by the job's execution user, instead of confined to the artifacts working directory. This can overwrite any file the job process has write permission to (e.g., other files in the build's parent directories, shared caches, or other locations under the runner's build root depending on executor), which violates the "file operations must stay within intended build/cache/artifact roots" invariant. The write is not attacker-arbitrary-content (it's always the metadata/provenance JSON), which limits impact to overwrite/DoS/corruption of files rather than arbitrary code injection, but it is still a genuine sandbox/path-confinement violation.

### Likelihood Explanation
This requires: (1) the runner configured to generate artifact provenance metadata (`--generate-artifacts-metadata`, i.e. `RUNNER_GENERATE_ARTIFACTS_METADATA`/`generate_artifacts_metadata` enabled), and (2) the job to set a crafted `artifacts:name`. Both are fully within a normal pipeline author's control (`.gitlab-ci.yml` `artifacts:name` field is standard, user-editable CI config), so this is easily reproducible whenever metadata generation is turned on — no special privileges are needed beyond authoring a `.gitlab-ci.yml`.

### Recommendation
Sanitize `opts.artifactName` in `generateStatementToFile` the same way `artifactFilename` does — call `filepath.Base(opts.artifactName)` (and reject `.`/empty results) before formatting into the filename, or explicitly validate that `filepath.Clean(file)` still has `opts.artifactsWd` as a prefix before calling `os.WriteFile`, returning an error otherwise.

### Proof of Concept

```go
func TestGenerateMetadataToFile_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir() // simulates "outside artifactsWd"

    g := &artifactStatementGenerator{
        SLSAProvenanceVersion: slsaProvenanceVersion1,
        StartedAtRFC3339:      time.Now().Format(time.RFC3339),
        EndedAtRFC3339:        time.Now().Add(time.Minute).Format(time.RFC3339),
    }

    traversal := filepath.Join("..", filepath.Base(outsideDir), "pwn")
    opts := generateStatementOptions{
        artifactName: traversal,
        files:        map[string]os.FileInfo{},
        artifactsWd:  tmpDir,
        jobID:        1,
    }

    file, err := g.generateStatementToFile(opts)
    require.NoError(t, err)

    // Assert the resulting file escaped artifactsWd
    cleanWd, _ := filepath.Abs(tmpDir)
    cleanFile, _ := filepath.Abs(file)
    assert.False(t, strings.HasPrefix(cleanFile, cleanWd),
        "expected traversal to escape artifactsWd, got %s under %s", cleanFile, cleanWd)

    // Fix verification: after patch, this should instead assert an error
    // or that cleanFile always has cleanWd as prefix.
}
```
Expected (pre-fix): the assertion demonstrating escape passes (bug reproduced) — file is written under `outsideDir` instead of `tmpDir`. Post-fix: `generateStatementToFile` should either error out or always produce a path with `opts.artifactsWd` as a strict prefix.

func (c *ArtifactsUploaderCommand) artifactFilename(name string, format spec.ArtifactFormat) string {
	name = filepath.Base(name)
	if name == "" || name == "." {
		name = DefaultUploadName
	}

	switch format {
	case spec.ArtifactFormatZip, spec.ArtifactFormatZipZstd:
		return name + ".zip"

	case spec.ArtifactFormatGzip:
		return name + ".gz"

	case spec.ArtifactFormatTarZstd:
		return name + ".tar.zst"
	}
	return name
}
