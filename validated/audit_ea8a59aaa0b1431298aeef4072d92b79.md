### Title
Missing role check on `GET /v2/external_initiators` allows any authenticated (view-role) user to enumerate External Initiator names, URLs, `AccessKey`, and `OutgoingToken` - ([File: core/web/router.go])

### Summary
`GET /v2/external_initiators` is registered under the `authv2` group with only `auth.AuthenticateByToken`/`auth.AuthenticateBySession`, with no `auth.RequiresEditRole` or `auth.RequiresRunRole` wrapper, unlike the sibling `POST` and `DELETE` routes for the same resource. This allows any authenticated principal, including a minimal view-role session/API-token user, to list all configured External Initiators and their `AccessKey`/`OutgoingToken` values.

### Finding Description
In `v2Routes` in `core/web/router.go`, the External Initiator routes are defined as: [1](#0-0) 

`POST` and `DELETE` are wrapped with `auth.RequiresEditRole`, but `GET /v2/external_initiators` is bound directly to `eia.Index` with no role wrapper, so it is reachable by any principal that passes the outer `authv2` group's `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware — i.e., any valid session or API token regardless of role (view, run, edit, admin).

`ExternalInitiatorsController.Index` fetches all external initiators and returns them via `presenters.NewExternalInitiatorResource`: [2](#0-1) 

The presenter serializes `Name`, `URL`, `AccessKey`, and `OutgoingToken` for every EI record: [3](#0-2) 

Comparing to the underlying model, `HashedSecret`/`Salt` (used to verify the EI's incoming secret) and `OutgoingSecret` are not included in the list presenter — only in the one-time `Create` response via `NewExternalInitiatorAuthentication`: [4](#0-3) [5](#0-4) 

So the exposed fields on the `Index` (list) endpoint are `AccessKey` and `OutgoingToken` — not the full incoming secret or `OutgoingSecret`. Still, this is inconsistent with the edit-role gating applied to `Create`/`Destroy`, and it discloses the `AccessKey` (part of the incoming-EI credential pair) and `OutgoingToken` (a secret used when the node calls out to the external initiator) to any authenticated user, not just edit/admin-role operators.

### Impact Explanation
A view-role (read-only) authenticated user or restricted API-token holder can call `GET /v2/external_initiators` and receive, for every configured EI, its `Name`, `URL`, `AccessKey`, and `OutgoingToken` — data that its sibling mutating endpoints correctly restrict to edit-role users. This is a role/authorization-scope violation (privilege boundary bypass) and a partial credential-disclosure issue: `AccessKey` is half of the credential pair used to authenticate inbound EI job-run requests, and `OutgoingToken` is a secret the node uses to authenticate itself to the external initiator. Full compromise (spoofing an EI to trigger job runs) also requires the corresponding `Secret`/`HashedSecret`, which is not exposed by this endpoint, limiting severity to unauthorized information disclosure / broken access-control rather than full impersonation.

### Likelihood Explanation
Any user who possesses only view-role credentials (session cookie or API token) — the minimal principal contemplated by the bounty's "restricted API token holder" threat model — can trivially and repeatably call this GET endpoint with no additional preconditions once at least one External Initiator has been registered on the node.

### Recommendation
Wrap `authv2.GET("/external_initiators", ...)` with the same role check intended for this resource (at minimum `auth.RequiresEditRole`, consistent with `POST`/`DELETE`), or, if view access is intentional, strip `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource` for non-edit roles.

### Proof of Concept
Go handler-level integration test (pattern matching `core/web/external_initiators_controller_test.go`):
1. Create an app/test client via `cltest.NewApplicationWithConfig` and register an External Initiator as an edit/admin user (`POST /v2/external_initiators`).
2. Create a second user/session with `sessions.UserRoleView` (minimal view-role) using existing test helpers (e.g. `cltest.CreateUserWithRole` or `client.NewTestClient` with a view-role user), analogous to role checks elsewhere in `core/web/router_test.go` / `jobs_controller_test.go` for `RequiresEditRole`.
3. Using the view-role session/token, call `GET /v2/external_initiators`.
4. Assert response status `200 OK` (not `401`/`403`), and that the JSON body contains the `accessKey` and `outgoingToken` fields for the EI created in step 1 — demonstrating that a view-role principal obtained data intended to require edit-role access, unlike a parallel `POST /v2/external_initiators` or `DELETE /v2/external_initiators/:Name` call with the same view-role credential, which should return `401 Unauthorized`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

type ExternalInitiatorAuthentication struct {
	Name           string        `json:"name,omitempty"`
	URL            models.WebURL `json:"url"`
	AccessKey      string        `json:"incomingAccessKey,omitempty"`
	Secret         string        `json:"incomingSecret,omitempty"`
	OutgoingToken  string        `json:"outgoingToken,omitempty"`
	OutgoingSecret string        `json:"outgoingSecret,omitempty"`
}

// NewExternalInitiatorAuthentication creates an instance of ExternalInitiatorAuthentication.
func NewExternalInitiatorAuthentication(
	ei bridges.ExternalInitiator,
	eia auth.Token,
) *ExternalInitiatorAuthentication {
	var result = &ExternalInitiatorAuthentication{
		Name:           ei.Name,
		AccessKey:      ei.AccessKey,
		Secret:         eia.Secret,
		OutgoingToken:  ei.OutgoingToken,
		OutgoingSecret: ei.OutgoingSecret,
	}
	if ei.URL != nil {
		result.URL = *ei.URL
	}
	return result
}
