## Analysis

The core bug pattern in the report is: **a single actor can multiply the effective weight of one identity by repeating an action, because the code caps a fixed value (deposit amount / stream quota / stake weight) per-action or per-connection rather than aggregating it across all actions taken by the same identity, letting the global fairness invariant be defeated.**

The closest reachable, unprivileged analog in Agave is in the QUIC stake-weighted QoS ingest path (`streamer` crate), which is explicitly in the allowed "TPU ingest limits" scope.

### How stake-weighted stream quota is computed
Each QUIC connection is assigned a `ConnectionPeerType::Staked(stake)` based on a lookup of the identity's total stake, and its per-throttle-interval stream budget is computed as a fraction of that stake relative to total network stake: [1](#0-0) 

The budget is enforced per-connection via a `ConnectionStreamCounter` that resets every `STREAM_THROTTLING_INTERVAL`: [2](#0-1) 

### How connections/counters are keyed
When a connection is added, the connection table entry — and thus the `ConnectionStreamCounter` used for throttling — is keyed by `(remote_addr.ip(), remote_pubkey)`, and the connection's per-peer cap (`max_connections_per_staked_peer`) is enforced only against the number of existing entries under that exact key: [3](#0-2) 

Because the stream counter is only shared among connections sharing the *same* `(ip, pubkey)` key, and each connection's allowed quota (`available_load_capacity_in_throttling_duration`) is computed purely from the identity's fixed stake value (not from how many connections/IPs that identity currently has open), a single staked identity that opens connections from multiple distinct source IP addresses obtains a *separate, independent* `ConnectionStreamCounter` and full per-stake stream quota for each IP — as long as the connection is admitted into the global staked connection table: [4](#0-3) 

The only ceiling is the global `max_staked_connections` table size, enforced via random-sample pruning keyed on stake (`prune_random`), not via any accounting of "total streams already granted to this pubkey across all its connections": [5](#0-4) 

This mirrors the Wheel-contract bug: the intended invariant ("total stream throughput available to a given staked identity should be bounded by its stake") is enforced only at the level of a single connection/action rather than aggregated per identity, so repeating the action (opening additional connections from additional source IPs) lets one identity accumulate multiples of its entitled quota, up to the size of the global staked-connection table.

## Assessment and confidence caveat

I was not able to fully read the `ConnectionTableKey` struct definition (only its usage sites) before running out of tool iterations, so I cannot 100% confirm whether its `Hash`/`Eq` implementation might normalize or otherwise deduplicate by pubkey alone in some code path I did not see — that would negate this finding. Given what was observed (`ConnectionTableKey::new(ip, pubkey)` used directly as the per-entry key for both the connection cap and the shared stream-counter lookup), the analog appears structurally real, but I flag this as the one unverified assumption underlying the finding. If a Devin session is used to confirm this, it should specifically dump `ConnectionTableKey`'s definition and confirm that entries with the same pubkey but different IPs are treated as distinct keys (not merged) in `ConnectionTable::try_add_connection`.

### Title
Stake-weighted QUIC stream quota is granted per-(IP, pubkey) connection instead of per-identity, allowing multi-IP quota multiplication - (File: streamer/src/nonblocking/swqos.rs)

### Summary
The stake-weighted QoS system grants each QUIC connection a stream quota proportional to the connecting identity's total stake, but the quota counter and per-peer connection cap are keyed by `(remote_addr.ip(), remote_pubkey)` rather than by `remote_pubkey` alone. An identity that opens connections from multiple distinct source IPs receives one independent quota per IP rather than one aggregate quota for its stake.

### Finding Description
`available_load_capacity_in_throttling_duration` computes the number of streams a staked peer may send per throttling interval as a function of the peer's stake and the network's total stake [1](#0-0) . This quota is tracked via a `ConnectionStreamCounter` that is created (or reused) per connection-table entry, and the table entry is keyed by `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)` [6](#0-5) . Because the key includes the IP address, the same staked pubkey connecting from N different source addresses is treated as N unrelated peers, each independently entitled to the full per-stake quota, and each admitted so long as the shared, global `max_staked_connections` table has room (with room reclaimed via stake-based random pruning rather than per-identity accounting) [4](#0-3) [5](#0-4) .

### Impact Explanation
A moderately staked validator identity can obtain a disproportionate share of leader/forwarding-node QUIC ingest bandwidth by opening connections from many source addresses (multiple hosts, NAT egress points, or IP rotation), each contributing its own independent stream quota. This subverts the intended fairness invariant that ingest bandwidth is proportional to stake, and — because slots in the shared staked-connection table are finite and evicted by random low-stake pruning — can also degrade or starve legitimately low/moderately staked single-connection peers as the attacker consumes more table slots.

### Likelihood Explanation
Any staked validator (an ordinary, non-privileged network participant with a valid identity keypair and nonzero stake) can trigger this by simply establishing additional TPU QUIC connections from different source IP addresses — no special network position, leaked keys, or protocol violation is required.

### Recommendation
Track and enforce the stream quota (`ConnectionStreamCounter`) and the per-peer connection cap at the identity (`pubkey`) level, aggregating usage across all IPs/connections belonging to that identity, rather than keying enforcement on `(ip, pubkey)`.

### Proof of Concept
Conceptually:
1. Attacker has a staked identity with stake `S`, giving quota `Q(S)` per `STREAM_THROTTLING_INTERVAL_MS`.
2. Attacker opens a QUIC connection to the leader/TPU from source IP `A`, receiving quota `Q(S)`.
3. Attacker opens additional QUIC connections using the same identity but from IPs `B`, `C`, ... (e.g. via multiple hosts or address rotation), each independently admitted into the staked connection table (subject only to the global `max_staked_connections` cap and stake-based pruning) and each receiving its own fresh `ConnectionStreamCounter` with quota `Q(S)`.
4. Aggregate throughput achieved by the attacker's single identity approaches `k * Q(S)` for `k` simultaneous IP-distinct connections, exceeding the stake-proportional allocation intended by the design.

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
