### Title
Attacker-controlled entrypoint stdout can forge `StageCommandStatus` markers to desync log pause/resume state - (File: executors/kubernetes/container_entrypoint_forwarder.go)

### Summary
`entrypointLogForwarder.writeLine`/`commandStatus` treats any line from the container's entrypoint stdout matching a timestamp + JSON payload as an authoritative build-stage control marker, with no source authentication. A CI job whose image entrypoint (or any process writing to the container's stdout stream forwarded through this logger) prints a crafted `"<timestamp> {\"command_exit_code\":N,\"script\":\"...\"}"` line can toggle `lf.paused`, suppressing subsequent job log lines from being forwarded to the trace/Sink.

### Finding Description
`commandStatus` (executors/kubernetes/container_entrypoint_forwarder.go:91-113) validates only that the first `len(containerLoggerTimeStampFormat)` bytes parse as an RFC3339-like timestamp followed by a space, then hands the remainder to `shells.StageCommandStatus.TryUnmarshal` (shells/trap_command_exit_status.go:47-61), which just does `json.Unmarshal` and checks that at least one of `command_exit_code`/`script` is non-nil. There is no signature, sequence number, or channel separation distinguishing "genuine trap-injected status markers written by Runner's own generated script" from arbitrary stdout produced by the job's container image/entrypoint.

`writeLine` (container_entrypoint_forwarder.go:22-38) uses the parsed result to toggle forwarding state: `IsExited()` unpauses, a non-empty `BuildStage()` pauses, and in both matching cases the line itself is swallowed (`return nil`) rather than forwarded to the Sink. Since the timestamp format and JSON shape are fully documented/derivable from `shells/trap_command_exit_status.go` and the constant `containerLoggerTimeStampFormat`, a job that controls what its container prints to stdout (custom image, custom entrypoint/CMD invoked via `image:`/`services:` job config, or a script that pipes through fabricated timestamps) can synthesize matching lines.

Existing checks reviewed: only timestamp format + JSON required-field validation; there is no verification that the line actually originated from the internal stage/trap tracking wrapper versus job/container-produced stdout, so this check does not stop spoofing.

### Impact Explanation
Impact is confined to the job's own log stream: by injecting a spoofed `BuildStage()` marker, a job can pause forwarding of its own subsequent legitimate output to the trace/Sink (hiding it from the pipeline log), or inject a spoofed exit marker to resume/desync pause state, potentially causing later genuine command-status lines to be misinterpreted or its own step output to be selectively hidden/omitted from the job trace. This does not cross job/project boundaries, does not leak other jobs' secrets, and does not break sandbox isolation — the forwarder only affects the log forwarding of the same job/container the attacker already controls. This falls into "a job hiding/altering its own trace output," a self-inflicted, low-severity log-integrity issue rather than the excluded categories (privileged containers, docker.sock, admin trust).

### Likelihood Explanation
Trivial to trigger: any pipeline author who can set a custom `image:`/`services:` with a controllable entrypoint, or otherwise cause arbitrary bytes to reach the container's stdout that the forwarder reads, can emit a line of the exact form `time.Now().Format(containerLoggerTimeStampFormat) + " " + {"command_exit_code":0}` (or with a `"script"` field). No special privileges beyond normal job authoring are required, and the format/logic is fully visible in-repo.

### Recommendation
Do not treat container/entrypoint stdout as a trusted control channel indistinguishable from Runner's own internal step-status markers. Use a dedicated, non-stdout channel (e.g., separate file descriptor/pipe, prefixed sentinel with a runner-generated per-job random token, or a distinct stream) for the trap/exit-status protocol so job-produced stdout cannot be confused with it, or clearly document/scope this as an accepted limitation only if entrypoint output is already assumed fully trusted equivalent to job script output (which should be explicitly confirmed against the security model).

### Proof of Concept
Go unit test added to `executors/kubernetes/container_entrypoint_forwarder_test.go`:
1. Construct an `entrypointLogForwarder` with a fake `Sink` (e.g., `bytes.Buffer`-backed `io.WriteCloser`).
2. Write a line: `fmt.Sprintf("%s %s\n", time.Now().Format(containerLoggerTimeStampFormat), `{"script":"build"}`)` — assert `lf.paused == true` and the line is NOT present in Sink output.
3. Write a normal log line afterward (e.g., `"hello\n"`) — assert it is also NOT forwarded to Sink (proving suppression persists due to attacker-forged pause).
4. Write a forged unpause line `{"command_exit_code":0}` with valid timestamp — assert `lf.paused == false` again, demonstrating full attacker control over the pause state machine from spoofed "entrypoint" stdout content. [1](#0-0) [2](#0-1) [3](#0-2)

func (lf *entrypointLogForwarder) writeLine(p []byte) error {
	cmdStatus, ok := lf.commandStatus(p)
	if ok {
		if cmdStatus.IsExited() {
			lf.paused = false
		} else if cmdStatus.BuildStage() != "" {
			lf.paused = true
		}
	}

	if lf.paused || ok {
		return nil
	}

	_, err := lf.Sink.Write(p)
	return err
}

func (lf *entrypointLogForwarder) commandStatus(p []byte) (shells.StageCommandStatus, bool) {
	cmdStatus := shells.StageCommandStatus{}

	// check if the first part resembles a timestamp
	if len(p) < len(containerLoggerTimeStampFormat) ||
		p[len(containerLoggerTimeStampFormat)] != ' ' {
		return cmdStatus, false
	}

	line := string(p)
	ts := line[:len(containerLoggerTimeStampFormat)]
	_, err := time.Parse(containerLoggerTimeStampFormat, ts)

	if err != nil {
		return cmdStatus, false
	}

	// the actual log line starts after the timestamp + a space
	line = line[len(containerLoggerTimeStampFormat)+1:]

	ok := cmdStatus.TryUnmarshal(line)
	return cmdStatus, ok
}

// TryUnmarshal tries to unmarshal a json string into its pointer receiver.
// It wil return true only if the unmarshalled struct has all of its required fields be non-nil.
// It's safe to use the struct only if this method returns true.
func (c *StageCommandStatus) TryUnmarshal(line string) bool {
	var status stageCommandExitStatusImpl
	err := status.tryUnmarshal(line)
	if err != nil {
		return false
	}

	if status.isEmpty() {
		return false
	}

	status.applyTo(c)

	return true
}
