### Title
Replay protection for one-time allowlisted Vault requests (e.g. `MethodSecretsDelete`) is lost on node restart - ([File: core/capabilities/vault/authorizer.go])

### Summary
`(*authorizer).AuthorizeRequest` relies exclusively on `RequestReplayGuard`, an in-memory map created fresh via `NewRequestReplayGuard()` at process start, to prevent reuse of a one-time allowlisted request digest. Because the allowlist entries themselves are read live from the on-chain workflow registry (via `workflowRegistrySyncer.GetAllowlistedRequests`) rather than consumed/removed at authorization time, restarting the node clears the `seen` map and allows a previously-used allowlisted digest to be authorized again as long as the on-chain entry has not expired or been separately removed.

### Finding Description
`NewAuthorizer` constructs `replayGuard: NewRequestReplayGuard()` [1](#0-0)  which backs a purely in-memory `map[string]int64` [2](#0-1) . `AuthorizeRequest` calls `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` after allowlist authorization succeeds, and this is the *only* mechanism preventing reuse of the same digest [3](#0-2) . Meanwhile, `allowListBasedAuth.AuthorizeRequest` re-derives the allowlisted item independently on every call by querying `r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)` and checking whether the digest and expiry are still valid — it never marks or removes the on-chain/synced allowlist entry as "consumed" [4](#0-3) . Consequently, the sole gate against reuse of a still-unexpired allowlisted digest is the process-local `seen` map, which is discarded on restart, so a previously-authorized `MethodSecretsDelete` request (or any other allowlisted request) with the same digest will pass both allowlist lookup and replay-guard checks again after a restart, up until the allowlist entry's `ExpiryTimestamp` naturally elapses or is revoked on-chain.

### Impact Explanation
For `MethodSecretsDelete` the practical impact is limited because delete is idempotent (repeating it produces the same end state), but the finding confirms an architectural gap: the "single-use" authorization guarantee for allowlist-based requests is not durable across restarts. For non-idempotent one-time-allowlisted actions (e.g., `MethodSecretsCreate`/`MethodSecretsUpdate` using the same allowlist+replay-guard flow), the same gap could allow a previously-consumed authorization to be replayed and reapplied after a restart, within the request's remaining allowlist expiry window — this corresponds to a "replay/no-replay invariant violation" rather than a direct authentication bypass, since the attacker still needs a digest that was legitimately allowlisted on-chain and not yet expired.

### Likelihood Explanation
Preconditions: (1) attacker possesses a request whose digest was legitimately allowlisted on-chain (an unprivileged network client can already submit any allowlisted digest — no node credential needed beyond the gateway/API access already assumed), (2) the allowlist entry has not yet expired on-chain, and (3) the node process restarts between the original authorized use and the replay attempt. Node restarts are a normal operational event (upgrades, crashes, redeploys), making this a realistically triggerable window rather than a purely theoretical one, though it depends on restart timing and the remaining validity window of the allowlist entry, which the attacker does not control.

### Recommendation
Persist replay-guard state (e.g., in the node's database) instead of only in-memory, or have `allowListBasedAuth` mark/remove the on-chain allowlist entry as consumed after first successful use so a fresh in-memory guard cannot re-authorize it after restart.

### Proof of Concept
Go unit test in `core/capabilities/vault/request_replay_guard_test.go`:
1. Create `guard1 := NewRequestReplayGuard()`.
2. Call `guard1.CheckAndRecord("digest-A", futureExpiry)` and assert `nil` error (first use succeeds).
3. Call `guard1.CheckAndRecord("digest-A", futureExpiry)` again and assert `ErrRequestAlreadySeen` (replay blocked pre-restart).
4. Simulate a node restart by discarding `guard1` and creating `guard2 := NewRequestReplayGuard()` (fresh `seen` map, as happens via `NewAuthorizer` on process start).
5. Call `guard2.CheckAndRecord("digest-A", futureExpiry)` and assert it returns `nil` (no error) — demonstrating the same digest that was already consumed pre-restart is accepted again post-restart, confirming the replay guard provides no protection across restarts.

	mu      sync.Mutex

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {

		seen:    make(map[string]int64),

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}
