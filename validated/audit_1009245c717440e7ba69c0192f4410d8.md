### Title
Denial of Service via unbounded owned-ABI-decode diagnostic construction in the B20Asset `announce` precompile's frozen V1 fast-path fallthrough - (File: `crates/common/precompiles/src/b20_asset/dispatch.rs`)

### Summary
The B20Asset precompile's `announce` selector has a fast, borrowed-slice decode path (`DecodedAnnounce::decode_if_announce`) that was added specifically to avoid an O(aliases · tail_bytes) blow-up when a caller supplies ABI calldata whose `bytes[]` offset table aliases the same tail blob many times. For the frozen `AssetVersion::V1` surface, however, a malformed payload (one that fails `valid_token`, e.g. non-UTF-8 `id`/`description`/`uri`) is *not* rejected on the cheap path — it deliberately falls through to the legacy, expensive owned `abi_decode_validate` diagnostic construction, in order to preserve byte-identical, consensus-frozen revert data.

### Finding Description
`DecodedAnnounce::decode_if_announce` in [1](#0-0)  runs the cheap `decode_sequence`/`valid_token` check on borrowed slices. When `valid_token` fails, the code branches on `version`: [2](#0-1) 

- `AssetVersion::V2` returns a bounded rejection immediately.
- `AssetVersion::V1` returns `None`, explicitly falling through to "the owned decoder's diagnostic, however expensive, unchanged" — this is stated directly in the code comment.

This fallthrough routes into `version.abi().decode(calldata)` in `route` ( [3](#0-2) ), which for `V1` invokes `IB20AssetV1::IB20AssetCalls::abi_decode_validate` ( [4](#0-3) ). This owned decode materializes every aliased `bytes[]` element as an independent owned copy before it can even report the validation failure.

The repo's own test suite documents and reproduces the amplification primitive: `aliased_announce_calldata(n, tail)` builds calldata where `n` `bytes[]` element offsets all point at one shared `tail` blob, so wire size stays `O(calldata)` while the naive owned decode would materialize `O(n · tail_bytes)` — this is exactly the "Cantina #16" DoS class the fast path was built to close [5](#0-4) . The companion golden test `golden_announce_malformed_id_stays_on_owned_diagnostic_at_v1` pins that V1 must keep taking this expensive path unchanged [6](#0-5) , while `golden_announce_malformed_id_short_circuits_at_v2` shows the same input is bounded on V2 [7](#0-6) .

Crucially, this expensive decode happens during **call decoding**, before any role/authorization check runs (`handle_asset_call`, which enforces `operator`/mint/etc. roles, is only reached after a successful decode) — so no privileged role is required to trigger the expensive path; any address able to submit an L2 transaction (or an `eth_call`) that reaches the B20Asset precompile with `announce` calldata can hit it.

### Impact Explanation
This is the same bug class as the referenced advisory: a computation whose cost is far larger than the "authorization"/payment gate protecting it, reachable by an unprivileged caller, causing the node to spend disproportionate CPU/memory on a single request/transaction. Here the disproportion is between the wire-level calldata gas charged by `deduct_calldata_gas`/`CALLDATA_WORD_GAS` (linear in raw calldata bytes) and the actual work performed by the owned ABI decoder (linear in `aliases × tail_bytes`, which can be many multiples of the wire size via offset aliasing). Because every full node must execute (or attempt to execute) this call during block validation/building, a single crafted transaction can impose amplified CPU/memory cost network-wide, which is a resource-exhaustion/DoS vector rather than a localized single-node issue — matching the "node halt"/no-longer-serviceable-RPC-or-block-processing bar in scope.

### Likelihood Explanation
Likelihood depends on whether `AssetVersion::V1` (Beryl) is still reachable on a live network. The repository's own comment states this explicitly: "V2 (Cobalt, not live on any network) returns the bounded rejection directly" — implying V1/Beryl is (or was) the live surface on at least one network, meaning this fallthrough is exploitable today via any ordinary account submitting calldata to the B20Asset precompile, needing no special role, no signature beyond a normal transaction, and no privileged position. Exact confirmation of which chain/fork is currently active for V1 vs V2, and the exact wall-clock magnification achievable given DA/calldata size caps, would require checking chain activation state directly (e.g. `crates/common/genesis/src/chain/upgrade.rs`), which I was not able to fully trace before the iteration limit was reached — this is the primary remaining uncertainty.

### Recommendation
Consider whether the V1 fast-path fallthrough can be made bounded without touching the *accepted* revert byte content — e.g., by capping the total aliased `bytes[]` materialization (a size guard before invoking the owned decoder) even for V1, since a revert path does not require byte-identical intermediate computation, only byte-identical *output*. Alternatively, gate the announce fast path check earlier by capping `tail_bytes × alias_count` and charging proportional gas for calldata-word expansion before falling through to the owned decode, so cost tracks work done rather than raw wire size.

### Proof of Concept
The repository already contains a proof-of-concept generator for this exact primitive: `aliased_announce_calldata(n, tail)` in [8](#0-7) . Concretely:
1. Build a large `tail` blob (an arbitrary calldata blob, e.g. tens of KB).
2. Use `aliased_announce_calldata(n, tail)` with `n` in the thousands to build `announce` calldata whose wire size is `O(calldata)` but whose `bytes[]` offset table aliases `tail` `n` times.
3. Corrupt one of the UTF-8 string fields (`id`/`description`/`uri`) so `valid_token` fails (as done in `golden_announce_malformed_id_stays_on_owned_diagnostic_at_v1`, [9](#0-8) ).
4. Submit this calldata as a transaction to the B20Asset precompile address while `AssetVersion::V1` is the active surface. `decode_if_announce` returns `None` (falls through), and `version.abi().decode(calldata)` invokes the owned `abi_decode_validate`, materializing `O(n · tail_bytes)` of data purely to build the rejection diagnostic — with calldata gas charged only for the much smaller wire-level bytes.

    fn decode_if_announce(
        calldata: &'a [u8],
        version: AssetVersion,
    ) -> Option<Result<Self, BasePrecompileError>> {
        let selector = calldata.first_chunk::<4>().copied()?;
        if selector != IB20Asset::announceCall::SELECTOR {
            return None;
        }
        if !version.abi().asset.valid_selector(selector) {
            return None;
        }
        let rest = &calldata[4..];
        let token =
            abi::decode_sequence::<<IB20Asset::announceCall as SolCall>::Token<'a>>(rest).ok()?;
        if !<<IB20Asset::announceCall as SolCall>::Parameters<'a> as SolType>::valid_token(&token) {
            return match version {
                // V1/Beryl: revert bytes are already consensus-frozen — keep falling through to
                // the owned decoder's diagnostic, however expensive, unchanged.
                AssetVersion::V1 => None,
                // V2/Cobalt: not scheduled on any network yet, so this can short-circuit cheaply
                // without touching any live consensus bytes.
                AssetVersion::V2 => Some(Err(BasePrecompileError::AbiDecodeFailed {
                    selector,
                    error: String::from("announce: malformed bytes[] payload"),
                })),
            };
        }
        // Field `.0` of `PackedSeqToken<'a>` is `&'a [u8]`, so each iter yields a slice with the
        // full calldata lifetime. `as_slice()` would tie borrows to `token` (a local) instead.
        Some(Ok(Self {
            id: Self::string_from_utf8(token.1.0),
            description: Self::string_from_utf8(token.2.0),
            uri: Self::string_from_utf8(token.3.0),
            internal_calls: token.0.0.iter().map(|call| call.0).collect(),
        }))
    }

    // --- Cantina #16: aliased-`bytes[]` announce borrowed decode -------------------------------

    /// Builds `announce` calldata where `n` `bytes[]` element offsets all alias one shared `tail`.
    ///
    /// The helper starts from a valid one-element alloy encoding, widens the array offset table so
    /// every element offset points at the same tail blob, and shifts the trailing string offsets to
    /// match. The resulting wire is smaller than an `n`-copy owned-style encoding. That size gap is
    /// the heap amplification a naive owned decode would materialize and the borrowed decode avoids.
    fn aliased_announce_calldata(n: usize, tail: &[u8]) -> Vec<u8> {
        assert!(n >= 1, "need at least one aliased entry");
        let base = IB20Asset::announceCall {
            internalCalls: alloc::vec![Bytes::copy_from_slice(tail)],
            id: String::from("aliased-id"),
            description: String::from("desc"),
            uri: String::new(),
        }
        .abi_encode();

        let args = &base[4..];
        let read_off = |at: usize| -> usize {
            let mut buf = [0u8; 8];
            buf.copy_from_slice(&args[at + 24..at + 32]);
            u64::from_be_bytes(buf) as usize
        };
        let write_off = |out: &mut [u8], at: usize, v: usize| {
            out[at..at + 32].fill(0);
            out[at + 24..at + 32].copy_from_slice(&(v as u64).to_be_bytes());
        };

        let off_calls = read_off(0);
        let off_id = read_off(32);
        let off_desc = read_off(64);
        let off_uri = read_off(96);
        assert_eq!(read_off(off_calls), 1, "base encoding must be one element");

        // Base array section (n == 1): [len=1][off0][blob..]; the three strings begin at off_id.
        let blob = &args[off_calls + 64..off_id];
        let strings = &args[off_id..];

        let extra = (n - 1) * 32; // widening the offset table shifts everything after it
        let shared_elem_off = n * 32; // offset (from after the length word) of the shared blob

        let mut out = base[..4].to_vec();
        out.resize(4 + off_calls + 32 + n * 32 + blob.len() + strings.len(), 0);
        let a = &mut out[4..];
        write_off(a, 0, off_calls);
        write_off(a, 32, off_id + extra);
        write_off(a, 64, off_desc + extra);
        write_off(a, 96, off_uri + extra);
        write_off(a, off_calls, n); // array length
        for i in 0..n {
            write_off(a, off_calls + 32 + i * 32, shared_elem_off);
        }
        let blob_at = off_calls + 32 + n * 32;
        a[blob_at..blob_at + blob.len()].copy_from_slice(blob);
        let strings_at = off_id + extra;
        a[strings_at..strings_at + strings.len()].copy_from_slice(strings);
        out
    }

/// consensus-frozen and must never take the new V2-only bounded-rejection path.
#[test]
fn golden_announce_malformed_id_stays_on_owned_diagnostic_at_v1() {
    let mut s = fresh();
    let marker = "malformed-id-marker";
    let mut calldata = IB20Asset::announceCall {
        internalCalls: vec![],
        id: marker.into(),
        description: String::new(),
        uri: String::new(),
    }
    .abi_encode();
    let at = calldata.windows(marker.len()).position(|w| w == marker.as_bytes()).unwrap();
    calldata[at..at + marker.len()].fill(0xff);

    let err = op(&mut s, ALICE, FakePolicyAccounting::new(), calldata.clone()).unwrap_err();
    let oracle_error = IB20Asset::IB20AssetCalls::abi_decode_validate(&calldata).unwrap_err();
    assert_eq!(
        err,
        BasePrecompileError::AbiDecodeFailed {
            selector: IB20Asset::announceCall::SELECTOR,
            error: oracle_error.to_string(),
        },
        "V1 must keep falling through to the owned decoder's diagnostic, unchanged",
    );
}
