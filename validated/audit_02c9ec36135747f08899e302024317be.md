### Title
Stale confirmations from removed multisig members allow a request to execute below the configured confirmation threshold - (`multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
`MultiSigContract::confirm()` counts raw confirmation-set size against `num_confirmations` without verifying that every prior confirmer is still a live member. `delete_member` / `DeleteKey` only purge requests *created* by the removed member, leaving that member's confirmations on requests created by *other* members intact. A member who confirms a pending request and is later removed still counts toward that request's threshold, letting it execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` decides whether to execute a request purely from the size of the stored confirmation set: [1](#0-0) 

`delete_member()` removes the deleted member from `self.members`, and purges only the requests whose *creator* (`r.member`) equals the removed member — it never scans other requests' `confirmations` entries to strip the removed member's vote: [2](#0-1) 

The same pattern exists in the older `multisig` contract, where `DeleteKey` removes requests signed by the deleted key but does not clean that key out of confirmation sets belonging to requests created by other keys: [3](#0-2) [4](#0-3) 

The binding that should hold is:
`confirmations_counted_for(request) == confirmations_from_currently_live_members(request)`

After a member is removed while they still have a live (unexecuted, unconfirmed-through) confirmation on someone else's request, this becomes:
`confirmations_counted_for(request) > confirmations_from_currently_live_members(request)`

so the request can reach `num_confirmations` with strictly fewer *live* member approvals than the configured threshold.

### Impact Explanation
This breaks the "K of N" custody guarantee of the multisig: a request (transfer, `AddKey`/`AddMember`, `FunctionCall`, etc.) can be executed with fewer than `num_confirmations` currently-authorized approvals, i.e. "a multisig request executed below threshold." Depending on the request contents this can move funds or grant access keys that were never actually approved by the required number of live signers — a Critical-severity outcome per the custody-binding rules (authorization threshold crossed).

### Likelihood Explanation
No special privilege is required beyond being a multisig member at some point — a normal, expected lifecycle event (member/key rotation, offboarding, compromised-key removal) triggers the bug. Any member (malicious or otherwise) can confirm a pending request created by another member and then be removed later (for any reason); their stale confirmation persists indefinitely because `delete_member`/`DeleteKey` don't scan unrelated `confirmations` entries. Given member turnover in multisig setups is routine, this is readily reachable, not a contrived edge case.

### Recommendation
When removing a member/key (`DeleteMember`/`DeleteKey`), iterate over all `confirmations` entries (not just requests created by that member) and remove the member's/key's confirmation from each. Alternatively, when tallying confirmations in `confirm()`, filter the stored confirmation set against currently-live `members` before comparing against `num_confirmations`, so stale entries never count toward the threshold.

### Proof of Concept
1. Deploy `MultiSigContract::new(members = {A, B, M}, num_confirmations = 2)`.
2. Member `B` calls `add_request` to create request `R` (e.g., `Transfer` to some account) — not confirmed yet, `confirmations[R] = {}`.
3. Member `M` calls `confirm(R)` → `confirmations[R] = {M}` (1 confirmation, below threshold of 2, so it doesn't execute).
4. Members `A` and `B` later submit and confirm a `DeleteMember { member: M }` request (2/2 confirmations, e.g. because `M`'s key was suspected compromised or `M` left the org). `delete_member` removes `M` from `self.members`, but `R` was created by `B`, not `M`, so `R` is not in the purge list — `confirmations[R]` still equals `{M}`.
5. Now only `A` and `B` are valid members (`num_confirmations` still 2). Member `A` calls `confirm(R)` → `confirmations[R].len() + 1 == 2 >= num_confirmations` → `R` executes, having been approved by only one live member (`A`) plus the stale, no-longer-authorized confirmation from removed member `M`, instead of the required two live-member approvals.

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
