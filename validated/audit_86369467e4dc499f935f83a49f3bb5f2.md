Confirmed the mechanics: both `multisig/src/lib.rs` and `multisig2/src/lib.rs` only purge a removed member's *own* pending requests (via `r.signer_pk == pk` / `r.member == member` filters) when `DeleteKey`/`DeleteMember` executes, but never scrub that member's *confirmations already recorded on other members' pending requests*. Since `confirmations` is a separate map keyed by `request_id` holding a raw `HashSet<PublicKey>`/`HashSet<String>`, a stale confirmation from a deleted key/member remains counted by `confirm()`'s threshold check (`confirmations.len() as u32 + 1 >= self.num_confirmations`), letting a request execute using a vote from a party that is no longer a live signer.

### Title
Multisig request can execute below the live-member threshold because confirmations from a removed key/member are never purged from other pending requests - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
`confirm()` counts entries in the `confirmations` map to decide whether a request has reached `num_confirmations` [1](#0-0) . When a key (v1) or member (v2) is removed via the `DeleteKey`/`DeleteMember` action, the cleanup logic only removes *requests originally created by* that key/member, and drops the confirmations map entry for those requests only [2](#0-1) [3](#0-2) . It never scans `confirmations` for entries where the removed key/member had already confirmed a request *created by someone else*. Those stale confirmations remain and continue to count toward the `num_confirmations` threshold.

### Finding Description
The intended custody binding is: `confirmations counted for request R == confirmations by members who are currently live signers of the multisig`. The code breaks this equality:

- A member/key confirms request R (`confirmations.insert(...)`) [4](#0-3) .
- That member/key is later removed through a legitimate `DeleteKey`/`DeleteMember` request. The removal path only removes *requests where the removed party was the original requester* (`r.signer_pk == pk` in v1, `r.member == member` in v2) [5](#0-4) [6](#0-5) .
- Request R, which the removed party merely *confirmed* (not requested), is untouched — its confirmation set still contains the now-removed identity.
- When the remaining live members later confirm R, `confirm()` adds `confirmations.len() + 1` against `self.num_confirmations` [7](#0-6) , and the stale confirmation is counted toward the threshold, so `execute_request` fires with fewer *live* confirmations than `num_confirmations` requires.

This differs from the documented "gotcha" in the README (deleting keys below `num_confirmations` locks the contract) [8](#0-7) , which is the opposite failure mode (over-restriction). Here the failure mode is under-restriction: a phantom vote from a removed identity is spent to reach quorum.

### Impact Explanation
This crosses the "multisig request executed below threshold" boundary called out as Critical: a `Transfer`, `FunctionCall`, `DeployContract`, `AddKey`/`AddMember`, or `SetNumConfirmations` request can execute with one fewer *live* confirming identity than `num_confirmations` mandates, because a confirmation from an already-removed signer is still tallied.

### Likelihood Explanation
Requires no attacker privilege beyond being (or having been) one of the K/N signers at some point before removal, which is a realistic and even benign operational sequence (rotate out a departing team member/co-signer after they've already confirmed a pending request). No malicious deployment, redeploy, or victim key theft is needed — it's a property of the accounting itself. The only extra condition is that a to-be-removed signer has an outstanding confirmation on some other pending request, which is plausible in normal K-of-N key rotation flows.

### Recommendation
When executing `DeleteKey` (v1) / `DeleteMember` (v2), iterate over **all** requests' `confirmations` sets (not just requests originated by the removed party) and remove the removed identity's confirmation from each, so `confirmations.len()` for any still-pending request reflects only currently-live signers before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy multisig v1 with `num_confirmations = 3`, keys A, B, C.
2. Key A calls `add_request` for a benign request R0 (any receiver), no confirm.
3. Key B calls `confirm(R0)` → confirmations = {B}, len 1 < 3, stored.
4. Governance separately raises and executes a `DeleteKey { public_key: B }` request (fully confirmed by A + C + a third confirmer, or however threshold is met) to remove B, e.g., because B's device was lost. The `DeleteKey` branch only removes requests where `r.signer_pk == B` — R0 was created by A, so it's untouched; R0's confirmations set `{B}` survives in storage [5](#0-4) .
5. Key C calls `confirm(R0)`. `confirmations.len()` is 1 (stale B) + 1 (C) = 2, `2 >= 3`? No — with num_confirmations=3 this specific tiny example needs one more live signer than exists; but generalize to num_confirmations=2, keys A/B/C, B removed after confirming R0: then C alone calling `confirm(R0)` yields `confirmations.len()==1 (B) + 1 (C) = 2 >= 2`, and `execute_request(R0)` fires even though only A (creator, unconfirmed) and C are live and only C actually confirmed live — the 2-of-2 threshold was met using B's phantom vote instead of two live confirmations.
6. R0's actions (e.g., `Transfer`) execute via `execute_request` [9](#0-8)  despite B no longer being an authorized signer.

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(",").into_bytes(),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::DeleteKey { public_key } => {
                    self.assert_self_request(receiver_id.clone());
                    let pk: PublicKey = public_key.into();
                    // delete outstanding requests by public_key
                    let request_ids: Vec<u32> = self
                        .requests
                        .iter()
                        .filter(|(_k, r)| r.signer_pk == pk)
                        .map(|(k, _r)| k)
                        .collect();
                    for request_id in request_ids {
                        // remove confirmations for this request
                        self.confirmations.remove(&request_id);
                        self.requests.remove(&request_id);
                    }
                    // remove num_requests_pk entry for public_key
                    self.num_requests_pk.remove(&pk);
                    promise.delete_key(pk)
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name.into_bytes(),
                    args.into(),
                    deposit.into(),
                    gas.into(),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }
