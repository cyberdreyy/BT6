## Analog Found

### Title
Malicious sortition winner can indefinitely reset `last_activity_time` via repeated losing/duplicate proposals, permanently suppressing the miner-inactivity fallback - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`check_latest_block_in_tenure` treats *any* competing or non-advancing block proposal from the current tenure's miner as "miner activity" and refreshes `last_activity_time`, as long as the conflicting tip is within a freshness window. Because a still-valid sortition winner can keep generating fresh, uniquely-hashed losing proposals (or re-pre-committed near-duplicates) faster than that window expires, it can indefinitely delay the exact timeout (`is_timed_out`) that is supposed to let the signer set fall back to the prior miner when the current one goes unresponsive — mirroring the Noya bug class where a legitimate-looking, frequently-triggered action (`recordProfitForFee`) kept resetting a timestamp gate (`profitStoredTime`) that another critical action (`collectPerformanceFees`) depended on, permanently starving it.

### Finding Description
`SortitionData::check_latest_block_in_tenure` in [1](#0-0)  is invoked at proposal arrival, validate-ok, and signing time. When a proposed block does not advance past the tenure's already-signed tip, it is rejected, but the code still calls `update_last_activity_time` for the tenure whenever the existing tip's `signed_group` freshness (`reorg_attempts_activity_timeout`) has not lapsed — explicitly commented as "count this invalid block proposal towards valid miner activity."

A second path does the same for the *pre-committed* (not-yet-signed) tip: [2](#0-1)  refreshes activity whenever a competing, non-advancing proposal arrives while the existing pre-commit is still fresh (`approved_time + tenure_last_block_proposal_timeout > now`). A pre-committed block's `approved_time` is only set once via `mark_pre_committed`, but a miner can simply issue a *new*, uniquely-hashed competing proposal (e.g., bump the block timestamp, as the test harness itself does at [3](#0-2) ) to obtain a brand-new pre-commit round and a brand-new `approved_time`, resetting the freshness clock again.

This `last_activity_time` is the sole input (besides `has_signed_block_in_tenure`) to the liveness check `is_timed_out`: [4](#0-3)  and its v2 counterpart [5](#0-4) . This is exactly the gate that `check_miner_inactivity` relies on to decide whether the signer set should abandon a stalled current miner and revert to the prior tenure's miner: [6](#0-5) .

So a sortition winner that never intends to produce (or never can produce) a legitimately-advancing, signable block can nonetheless keep pushing fresh, cheap, losing proposals (below/equal height, or re-pre-committed variants) at a cadence tighter than `reorg_attempts_activity_timeout` / `tenure_last_block_proposal_timeout`, perpetually refreshing `last_activity_time` and preventing `elapsed > block_proposal_timeout` from ever becoming true — exactly analogous to how `recordProfitForFee` kept resetting `profitStoredTime` on every call, so `collectPerformanceFees`'s `block.timestamp - profitStoredTime >= 12 hours` gate could never be satisfied.

### Impact Explanation
This is a liveness wedge: the signer set is designed to fall back to the prior tenure's miner once the current miner is judged inactive (`check_miner_inactivity` → `make_miner_state(prior sortition)`, documented in [7](#0-6) ). By weaponizing the "count invalid proposal as miner activity" carve-outs, a single miner (no majority of signers required — only its own gossiped proposals) can suppress that fallback indefinitely, stalling the tenure and denying the network the recovery path the inactivity timeout exists to provide.

### Likelihood Explanation
The mechanism requires only actions available to the current sortition winner (broadcasting cheap, uniquely-hashed proposals) and no cooperation from other signers or the node beyond normal proposal/pre-commit handling — the same "single winning miner, plus gossip" actor class the analog rules target. The `reorg_attempts_activity_timeout` and `tenure_last_block_proposal_timeout` windows (configurable, e.g. seconds-to-minutes range per `sample/conf/signer/mainnet-signer-conf.toml`) are the only cost of re-arming the reset, well within reach of an automated miner.

### Recommendation
Do not let repeated non-advancing/losing proposals from the *same* miner in the *same* tenure indefinitely refresh `last_activity_time`; cap the total extension per tenure (e.g., bound it relative to the burn-block-received time, not purely to the latest reset), or require genuine chain progress (a newly *signed* block) rather than mere proposal/pre-commit churn to keep the tenure "active."

### Proof of Concept
1. Miner M wins the sortition and proposes block B0 (height h) which the signer set pre-commits to but does not sign (e.g., M controls enough weight to avoid the 70% pre-commit-to-signature threshold, or deliberately withholds the last needed pre-commits from cooperating peers).
2. Before `tenure_last_block_proposal_timeout` elapses on B0's `approved_time`, M proposes B1 at the same height h with a bumped timestamp (new `signer_signature_hash`), which the signer's `check_latest_block_in_tenure` treats as a same/lower-height competing proposal against the fresh pre-commit and calls `update_last_activity_time` (path at `stacks-signer/src/chainstate/mod.rs:427-447`).
3. M repeats step 2 indefinitely, each time before the freshness window closes.
4. `SortitionState::is_timed_out` (`chainstate/v1.rs:55-94` / `chainstate/v2.rs:48-89`) never observes `elapsed > block_proposal_timeout` because `last_activity_time` keeps advancing, so `check_miner_inactivity` (`v0/signer_state.rs:284-354`) never falls back to the prior miner, and the tenure never advances or recovers.

            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()

                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);

impl SortitionState {
    /// Check if the given sortition identified by its ConsensusHash has timed out based on current signed blocks
    /// and the time at which the burn block for it was first recorded in the provided signerdb
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };

        let sortition_data = last_sortition.data();
        // If we already reverted to the last sortition miner, don't time it out as it means we have already timed out the current sorititon miner
        // as there is no other miner available.
        if &sortition_data.consensus_hash == tenure_id {
            warn!("Signer State: Last sortition miner has timed out, but no prior valid miner. Allowing last sortition miner to continue");
            return Ok(());
        }

        // Only revert to the prior miner if its tenure is the canonical Stacks tip's
        // tenure. A miner only continues (extends) a tenure it won, so if the canonical
        // tip is in some other tenure due to a Bitcoin reorg orphaning the prior
        // sortition's tenure, the prior miner's node has already stopped mining and
        // will never propose again.
        let stacks_tip_ch = client.get_peer_info()?.stacks_tip_consensus_hash;
        if sortition_data.consensus_hash != stacks_tip_ch {
            warn!(
                "Signer State: Current miner timed out due to inactivity, but the canonical stacks tip is not in the prior miner's tenure, so the prior miner cannot continue it. Allowing current miner to continue";
                "stacks_tip_consensus_hash" => %stacks_tip_ch,
                "prior_sortition_consensus_hash" => %sortition_data.consensus_hash,
            );
            return Ok(());
        }

        if !last_sortition.is_tenure_valid(db, client, proposal_config, eval)? {
            warn!("Signer State: Current miner timed out due to inactivity, but prior miner is not valid. Allowing current miner to continue");
            return Ok(());
