### Title
Masker resynchronization logic only checks a 1-byte overlap on partial-match failure, allowing self-overlapping masked phrases to leak fully unmasked when split across `Write()` calls - (File: `common/buildlogger/internal/masker/masker.go`)

### Summary
The `masker.Write` failure-recovery path (lines 113–131) restarts phrase matching by testing only a single byte (`m.phrase[0] == p[n]`) instead of computing the actual longest self-overlap of the phrase. For phrases whose prefix reappears with an overlap longer than one byte, this causes the masker to both flush already-buffered matched bytes as plaintext and fail to detect a genuine full-phrase match that spans a `Write()` boundary, so the entire phrase reaches the trace unmasked.

### Finding Description
`masker.New` builds a chain of per-phrase `masker` writers via `Logger.wrap` -> `masker.New(w, l.maskPhrases)` [1](#0-0) , where `l.maskPhrases` comes directly from `Options.MaskPhrases` set in `New` [2](#0-1) . Each `masker.Write` call carries persistent state (`m.matching`) across calls, exactly to survive phrase splits at `Write()` boundaries, as documented at the top of the file [3](#0-2) .

The bug is in the mismatch-recovery branch:
```
if m.matching > 0 {
    _, err = m.next.Write(m.phrase[:m.matching])
    ...
    if m.phrase[0] == p[n] {
        m.matching = 1
        last++
        n++
        continue
    }
}
m.matching = 0
``` [4](#0-3) 

When a partial match fails, the code (1) immediately flushes the already-buffered `m.phrase[:m.matching]` bytes to the next writer as plaintext, and (2) only checks whether the *single* current byte equals `phrase[0]` to decide whether to keep tracking at `matching=1`. This is not a correct restart (unlike a proper KMP failure function), so it cannot detect a valid overlap longer than one byte between the already-matched prefix and a new potential match starting mid-buffer.

Concretely, for `phrase = "aab"` split into two `Write()` calls as `"aa"` then `"ab"` (concatenated stream = `"aaab"`, which contains the phrase `"aab"` as a substring at offset 1):
- `Write("aa")` matches 2 bytes (`m.matching = 2`), buffers state, emits nothing.
- `Write("ab")` fails to extend the match (`phrase[2]='b'` vs `p[0]='a'`), flushes the buffered `"aa"` as plaintext, then restarts at `matching=1` (since `phrase[0]=='a'==p[0]`), fails again at the next byte, flushes `"a"`, and finally flushes `"b"` unmodified.
- Net output: `"aaab"` — the phrase `"aab"` is never masked, even though it is present in the reassembled stream, and a single, unchunked `Write("aaab")` call correctly masks it to `"a[MASKED]"`.

This shows the recovery logic loses information whenever the failed byte belongs to a re-alignment window wider than one character, which is a real state-management bug, not a theoretical one — it is fully deterministic given the phrase content and the chunk boundaries of the underlying `Write()` calls feeding the wrap chain (`Logger.wrap` -> `internal.NewSync` -> `masker.New` -> `urlsanitizer.New` -> `tokensanitizer.New` -> `timestamper.New`) [1](#0-0) .

### Impact Explanation
Any masked phrase (project/job/protected CI/CD variable value passed into `Options.MaskPhrases`) that has an internal self-overlapping byte pattern longer than one character can leak fully unmasked into the job trace if its bytes happen to be split across pipe/PTY reads at an unlucky boundary. Since job output chunk boundaries are influenced by executor buffering (pipe/PTY read sizes, timing of writes/flushes from the job's own script), a job author can increase the likelihood of, or in controlled environments (e.g. local shell executor testing, custom scripts pacing output) reliably trigger, such a split for a phrase they know the value of, resulting in disclosure of that secret/token in the trace — directly violating the "masked values must not leak... in traces... regardless of write chunking" invariant.

### Likelihood Explanation
Preconditions are realistic: any job with masked variables enables `MaskPhrases`, and the split point depends only on how the executor happens to chunk stdout/stderr into `Write()` calls feeding the wrap chain — something a job can nudge via output timing/size (e.g. writing partial output, then sleeping, then writing the rest) since executor writers typically forward each PTY/pipe read as one `Write()` call. Exploitability requires the masked phrase to contain a self-overlap of length ≥2 with an offset that lines up with an achievable chunk boundary; this is not guaranteed for arbitrary secrets but is fully deterministic and reproducible via a fuzz/unit test, and there exist realistic secret formats (e.g., tokens/strings with repeated substrings) where this condition holds.

### Recommendation
Replace the 1-byte lookback in the mismatch-recovery branch with a proper failure-function (KMP-style) restart: on a failed extension at `m.matching`, compute the longest proper suffix of `m.phrase[:m.matching]` (extended by the current byte) that is also a prefix of `m.phrase`, and only flush the bytes that are provably *not* part of any possible future match, not `m.phrase[:m.matching]` in full. Precompute this failure table once when the `masker` is constructed and use it in `Write` to update `m.matching` correctly, and add regression tests for self-overlapping phrases split at every possible byte boundary.

### Proof of Concept
Go unit test in `common/buildlogger/internal/masker/masker_test.go`:
```go
func TestMasking_SelfOverlappingPhraseSplitAcrossWrites(t *testing.T) {
    var buf bytes.Buffer
    w := masker.New(internal.NewNopCloser(&buf), [][]byte{[]byte("aab")})

    n1, err := w.Write([]byte("aa"))
    require.NoError(t, err)
    require.Equal(t, 2, n1)

    n2, err := w.Write([]byte("ab"))
    require.NoError(t, err)
    require.Equal(t, 2, n2)

    require.NoError(t, w.Close())

    // The concatenated input "aa"+"ab" == "aaab" contains "aab" at offset 1,
    // which a single unchunked Write("aaab") correctly masks to "a[MASKED]".
    assert.NotContains(t, buf.String(), "aab", "phrase leaked unmasked across Write() boundary: %q", buf.String())
}
```
Expected (current buggy) result: assertion fails because `buf.String() == "aaab"`. Additionally, extend the existing fuzz harness `common/buildlogger/internal/build_logger_fuzz.go` `Fuzz` function's `phrases` list with self-overlapping strings (e.g. `"aab"`, `"abab"`, `"aaba"`) to catch this class of split systematically; running it will surface `panic("mask %q present in %q")` for such phrases.

func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {

// Package masker implements a masking Writer, where specified phrases are
// replaced with the word "[MASKED]".
//
// To achieve masking over Write() boundaries, each phrase has its own writer.
// These writers are stacked, with each one calling the next, in length order,

// in-turn, filtering data down to the next writer as required.

// Each mask writer tracks when its phrase is being written, and counts until
