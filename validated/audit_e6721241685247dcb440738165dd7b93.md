### Title
Floor-division rounding mismatch between `GlobalStateEvaluator::reached_agreement` (libsigner) and `NakamotoBlockHeader::compute_voting_weight_threshold` (stackslib) lets a below-threshold weight be treated as "agreement reached" - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The report's bug class is a rounding error in a percentage/threshold check using flooring division (`x - x/100` vs. `x*99/100`), which lets a value that should fail the check pass it. The stacks-core analog is a divergence between two implementations of the *same* 70% (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`) supermajority threshold: the authoritative, chain-validated version in `stackslib` uses ceiling division, while the signer-local `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` used for state-machine consensus in `libsigner` uses floor division.

### Finding Description
The canonical/on-chain threshold used to accept a Nakamoto block's aggregate signer signature weight is computed with an explicit ceiling: [1](#0-0) 

This is exercised directly in `verify_signer_signatures`, which is the ground truth for whether a block has enough weight to be canonical: [2](#0-1) 

By contrast, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` — used by every signer to decide when the network has reached agreement on global state (active protocol version, global burn view, current miner, and the transaction replay set) — perform the identical 7/10 threshold arithmetic but with plain integer (floor) division and no ceiling adjustment: [3](#0-2) 

For any `total_weight` where `total_weight * 7` is not a multiple of 10, `compute_voting_weight_threshold` rounds *up* (stricter, requires more weight) while `reached_agreement` rounds *down* (laxer, requires less weight). Example: `total_weight = 11` → chain-authoritative threshold `= ceil(77/10) = 8` (72.7%), but `reached_agreement` accepts any `vote_weight >= floor(77/10) = 7` (63.6%). This is exactly the `x - x/100` vs `x*99/100` class of bug: a floor-based check accepts inputs a ceiling-based check would reject.

This mismatch is reachable by a normal signer/miner interaction: `reached_agreement` is invoked while folding in per-signer state-machine-update weights (which arrive over StackerDB/gossip as ordinary `StateMachineUpdate` messages) inside `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state`: [4](#0-3) [5](#0-4) 

`determine_global_state`'s output (the agreed `current_miner`, burn view, and replay set) feeds `SortitionState::is_timed_out` / `is_tenure_valid` for the V2 (global-state) chainstate path, which gates whether a signer treats a tenure/miner as valid and times it out: [6](#0-5) 

### Impact Explanation
This does not require a majority of signers to trigger — any subset of signers whose combined reported weight lands strictly between the floor and ceiling thresholds for the current `total_weight` (i.e., a "fractional" total-weight distribution, which is common since weights are integers derived from stacked-STX proportions) is sufficient to make `reached_agreement` claim consensus that does not actually meet the protocol-mandated 70% supermajority. Signers can then act on a "global state" (active protocol version, current miner/tenure view, or transaction replay set) that a strict reading of the protocol's approval rule would not have sanctioned, and different signer processes could disagree with the node-side/authoritative ceiling-based threshold used for actual block-signature acceptance (`verify_signer_signatures`). This is a genuine equality break between "signer-perceived aggregated weight crossing the supermajority" and "chain-verified threshold," matching the High-impact criterion of a signer acting on a stale/incorrectly-thresholded view of the reward set. It is a rounding/consistency defect rather than requiring collusion or a majority — a minority can produce a total whose 70% floor differs from its ceiling.

### Likelihood Explanation
Likelihood is high in practice: because signer weights are integer values that rarely divide evenly by 10 relative to `total_weight`, floor vs. ceil disagreement occurs for the majority of possible `total_weight` values (any `total_weight` where `total_weight*7 mod 10 != 0`), and this code path executes on every routine `StateMachineUpdate` gossip round, not just adversarial input.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same ceiling-based arithmetic as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have `libsigner` call/reuse that exact function) so the signer-local "supermajority reached" check is never laxer than the chain-authoritative one. Add a shared, single source-of-truth threshold helper used by both `stackslib` and `libsigner` to prevent this class of divergence from recurring.

### Proof of Concept
1. Configure a signer set with weights summing to `total_weight = 11` (e.g., weights `4, 4, 3`).
2. Have signers with combined weight `7` submit matching `StateMachineUpdate`s (any of protocol-version, burn view, or state-machine content).
3. `GlobalStateEvaluator::reached_agreement(7)` evaluates `7 >= 11*7/10 = 77/10 = 7` (integer floor) → `true`, so `determine_global_state`/`determine_latest_supported_signer_protocol_version` reports consensus reached at 63.6% of weight.
4. Meanwhile `NakamotoBlockHeader::compute_voting_weight_threshold(11)` returns `8` (ceil(77/10)) — the value actually required for a block/committee decision to be treated as having crossed the protocol's 70% supermajority — showing the 63.6%-weight "agreement" from step 3 does not meet the authoritative bar.     pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// check if the tenure defined by sortition state:
    ///  (1) chose an appropriate parent tenure
    ///  (2) has not "timed out"
    pub fn is_tenure_valid(
        &self,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<bool, SignerChainstateError> {
        let data = self.data();
        let chose_good_parent = data.check_parent_tenure_choice(
            signer_db,
            client,
            &proposal_config.first_proposal_burn_block_timing,
        )?;
        if !chose_good_parent {
            return Ok(false);
        }
        Self::is_timed_out(
            &self.version(),
            &data.consensus_hash,
            signer_db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )
        .map(|timed_out| !timed_out)
    }
