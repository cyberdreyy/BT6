### Title
Unvalidated `parameters` bytes length in `createDstEscrow` allows a malicious taker to permanently block destination withdrawals and steal the maker's source funds - (File: `contracts/BaseEscrowFactory.sol`)

### Summary
`createDstEscrow` accepts an arbitrary, caller-supplied `Immutables` struct (including the opaque `parameters` field that encodes protocol/integrator fee amounts and recipients) with no validation of its length or content before using it to deploy and fund an `EscrowDst` clone. `EscrowDst._withdraw` later blindly decodes fee amount/recipient values out of that same `parameters` field via `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd`, which revert with `IndexOutOfRange` if the bytes are too short. This is the same root-cause class as the external report: a value that is structurally "required" for downstream logic is never checked for validity at the point of intake, so a malicious/malformed input later crashes (reverts) the code path that depends on it.

### Finding Description
`BaseEscrowFactory.createDstEscrow` is a permissionless, `external payable` function — any address can call it and act as `taker`, supplying the full `dstImmutables` calldata that becomes the salt/state for a newly deployed `EscrowDst` clone: [1](#0-0) 

Only `token`, `amount`/`safetyDeposit` balance and `srcCancellationTimestamp` are checked. The `parameters` bytes field — which is later relied upon to extract `integratorFeeAmount`, `protocolFeeAmount` and their recipients — is never checked for length or consistency: [2](#0-1) 

`EscrowDst._withdraw` (invoked by both the private `withdraw` and the public `publicWithdraw` paths) unconditionally decodes these fields: [3](#0-2) 

If `dstImmutables.parameters` is shorter than `0x40` bytes (e.g., empty, as it deliberately is on the source-side `Immutables` — see the comment "Must skip params due only EscrowDst.withdraw() using it" in `_postInteraction`), every call to `_withdraw` — whether from the taker (`withdraw`) or any public-withdrawal access-token holder (`publicWithdraw`) — reverts with `IndexOutOfRange`, forever. `cancel()`, however, does not touch `parameters` and works normally once the cancellation timelock is reached, refunding `immutables.amount` to `immutables.taker` (the malicious caller who created the escrow), not to the maker: [4](#0-3) 

### Impact Explanation
A malicious taker can call `createDstEscrow` with an otherwise-plausible `Immutables` (correct `hashlock`, `amount`, `token`, `timelocks`, matching what the maker expects for the swap) but with a corrupted/too-short `parameters` field. Nothing on-chain forces `parameters` to encode a consistent, decodable fee tuple. Once the maker is convinced the destination escrow is properly funded (balance checks pass) and reveals the secret off-chain, the malicious taker uses that secret to call `EscrowSrc.withdraw`, claiming the maker's source-chain tokens. On the destination side, `withdraw`/`publicWithdraw` can never succeed (always reverts with `IndexOutOfRange`), so the maker can never claim the destination tokens. After the `DstCancellation` timelock elapses, the same malicious taker calls `EscrowDst.cancel()` and recovers the destination funds back into their own hands. Net effect: the maker's source tokens are taken, and the destination tokens are returned to the attacker — direct theft of user funds, meeting the Critical bounty bar. At minimum (if the secret is never actually consumed on the source chain), this is a temporary freeze of funds during the live swap lifecycle, meeting the High bar.

### Likelihood Explanation
`createDstEscrow` is fully permissionless and reachable by any unprivileged actor acting as taker in the normal swap flow — no owner/governance/relayer trust is required to trigger it. The only prerequisite is that the maker's off-chain client does not deeply validate the byte-length/content of the encoded `parameters` field (which is not a "visible" swap parameter like amount/token/timelocks), making this practically exploitable against unsuspecting makers.

### Recommendation
In `createDstEscrow` (and generally before persisting/using any `Immutables.parameters`), validate that `parameters.length` matches the exact expected size for the fee-encoding scheme (`>= 0x80` for protocol fee amount + integrator fee amount + both recipients), and/or enforce `protocolFeeAmount + integratorFeeAmount < amount` at creation time, mirroring the check already done in `_postInteraction` (`InvalidFeeAmounts`). This prevents malformed/insufficient `parameters` from ever making a legitimately-funded destination escrow unwithdrawable.

### Proof of Concept
1. Attacker (as taker) calls `escrowFactory.createDstEscrow{value: safetyDeposit + amount}(dstImmutables, srcCancellationTimestamp)` where `dstImmutables.parameters = ""` (or any bytes shorter than `0x40`), but `hashlock`, `amount`, `token`, `maker`, `timelocks` all match what the maker expects for the swap.
2. `DstEscrowCreated` is emitted; escrow balance checks (amount + safety deposit) pass normally, so a maker checking on-chain balances sees a "correctly funded" escrow.
3. Maker reveals the secret (off-chain) believing the swap is safe.
4. Attacker calls `EscrowSrc.withdraw(secret, srcImmutables)` and receives the maker's source tokens.
5. Maker (or any access-token holder) attempts `EscrowDst.withdraw`/`publicWithdraw(secret, dstImmutables)` — this reverts every time with `ImmutablesLib.IndexOutOfRange` because `immutables.integratorFeeAmountCd()` requires `parameters.length >= 0x40`.
6. After `DstCancellation` timelock, attacker (as `taker`) calls `EscrowDst.cancel(dstImmutables)`, receiving back the full `amount` and `safetyDeposit` that were deposited into the destination escrow.
7. Result: attacker keeps the maker's source tokens and reclaims their own destination-chain deposit; maker receives nothing.

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**
     * @notice Returns the integrator fee amount from the immutables (calldata version).
     * @param immutables The immutables to extract the fee from.
     * @return ret The integrator fee amount.
     */
    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x40) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(add(parameters.offset, 0x20))
        }
    }

    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
