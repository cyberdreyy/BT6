### Title
Default-recovery basis reads only the current-epoch instant bucket, stranding older instant receipts — ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`defaultPendingClaimBasis()` adds `instantWithdrawClaimsByEpoch[epochNumber]` whenever `pendingInstantWithdraws != 0`, but `pendingInstantWithdraws` is an aggregate counter that can carry partially-funded instant receipts from earlier epochs. Instant receipts requested in any epoch other than the default epoch are silently excluded from the recovery basis, which both inflates `defaultRecoveryPrice` for included claimants and permanently freezes the excluded receipts behind the `_transferFundedClaim` reserve guard. This mirrors the CVE-2017-14501 bug class: an out-of-bounds/stale index read — the code reads a per-epoch mapping at the wrong epoch index and treats the result as the full claim set.

### Finding Description
- `pendingInstantWithdraws` is incremented on every `requestInstantWithdraw` and decremented only by `collectInstantWithdrawFunds` (partial funding) and by claims (`claimInstantWithdrawRequest`). If `startEpoch` funding is partial, a nonzero remainder persists across `epochNumber` increments while `instantWithdrawClaimsByEpoch[oldEpoch]` still holds the basis. [1](#0-0) [2](#0-1) 
- On default finalization, `defaultPendingClaimBasis()` conditions on the aggregate `pendingInstantWithdraws != 0` but only adds `instantWithdrawClaimsByEpoch[epochNumber]` — the current epoch's bucket. Prior-epoch instant receipts contribute nothing to `basis`. [3](#0-2) 
- `finalizeDefaultRecovery` then computes `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` over the understated basis, so defaulted-epoch claimants (normal receipts, APR0, current-epoch instant) each recover an inflated share and drain `defaultRecoveryReserve`. [4](#0-3) 
- After finalization, an excluded user calling `claimInstantWithdrawRequest` skips `_claimDefaultedInstantWithdrawRequest` (`instantWithdrawsRequestsByEpoch[user][defaultEpoch] == 0`) and falls through to the par claim path `_transferFundedClaim`. [5](#0-4) 
- `_transferFundedClaim` reverts whenever `balance - defaultRecoveryReserve < amount`; since the reserve was sized to consume the whole balance for the included basis, the old instant receipt can never be paid — permanent freeze. [6](#0-5) 

### Impact Explanation
Direct theft plus permanent freezing: included defaulted-epoch claimants receive recovery above their fair share (recovery price computed over an understated basis), while holders of prior-epoch instant receipts lose 100% of their claim — their strategy-token receipts can neither be haircut-claimed nor paid at par. Loss is bounded by the stale instant bucket size but is total for that bucket.

### Likelihood Explanation
Requires a specific but legitimate sequence reachable by an unprivileged lender: (1) request an instant withdraw during a running epoch via `requestWithdraw` when APR drops (`requestInstantWithdraw`), (2) the borrower only partially funds the instant queue at the next `startEpoch` so `pendingInstantWithdraws` stays nonzero while `epochNumber` advances, (3) a borrower default and `finalizeDefaultRecovery` in a later epoch. No privileged misbehavior needed; partial prefunding is an explicitly handled state (`_defaultPrefundedInstantReserve`).

### Recommendation
In `defaultPendingClaimBasis`/`finalizeDefaultRecovery`, include the full outstanding instant claim basis — e.g., track a global `instantWithdrawClaims` aggregate (sum over all epochs, decremented on claim and funding) and add it rather than `instantWithdrawClaimsByEpoch[epochNumber]`, or iterate/settle all unfunded instant epochs before fixing `recoveryPrice`. Correspondingly, let `_claimDefaultedInstantWithdrawRequest` clear a user's entire stale instant basis at `defaultRecoveryPrice`, not only `defaultEpoch`.

  function _transferFundedClaim(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    uint256 reserve = defaultRecoveryReserve;
    if (reserve != 0) {
      uint256 balance = underlyingToken.balanceOf(address(this));
      // This should be unreachable when accounting is consistent. Keep the guard so old funded
      // receipts can never spend underlyings reserved for default recovery claimants.
