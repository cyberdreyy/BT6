Based on the investigation, I found a valid analog vulnerability in the `websocket-proxy` crate's message filtering logic, which mirrors the Nova CVE-2014-3708 pattern: an authenticated (or public, when enabled) remote client supplies an unbounded filter list which is then evaluated with an inefficient linear/substring-scan algorithm on every single broadcast message, for the entire lifetime of the connection, causing sustained CPU consumption.

### Title
Unbounded attacker-controlled address/topic filter list causes per-message CPU-exhaustion DoS in WebSocket proxy - (File: crates/infra/websocket-proxy/src/filter.rs)

### Summary
The `websocket-proxy`'s `/ws/{api_key}/filter` (and, if `public_access_enabled`, unauthenticated `/ws`) endpoint lets a remote client supply comma-separated `addresses`/`topics` query parameters that are parsed into a `HashSet<String>` with **no cap on the number of entries**. That filter is then evaluated against **every** broadcast flashblocks payload for the lifetime of the connection via `Registry::subscribe`, and the address-matching fallback path performs an `O(addresses × transactions × tx_length)` substring scan (`tx_lower.contains(address)`), analogous to Nova's unbounded IP-filter evaluation in the "list active servers" API that caused CVE-2014-3708.

### Finding Description
The query parsing has no length/count limit on the filter values: [1](#0-0) 

This builds a `HashSet<String>` of attacker-controlled size, wrapped in a `FilterType::Addresses`/`Combined` variant and attached to the client connection: [2](#0-1) 

For every message broadcast to that client, `Registry::subscribe` invokes `filter.matches(msg_bytes, compressed)` synchronously inside the per-client async task, before deciding whether to forward the message: [3](#0-2) 

Inside `contains_any_address`, once the cheaper direct-lookup checks (`new_account_balances`, log addresses) fail to match, the code falls back to a nested loop that does a substring `contains` check for **every attacker-supplied address** against **every transaction string** in the payload: [4](#0-3) 

Because this filter evaluation runs on every broadcast message (flashblocks payloads arrive frequently, e.g., sub-second intervals) for as long as the WebSocket connection is open, and the number of addresses supplied is unbounded by the parsing code (only implicitly bounded by whatever HTTP request-line/header size limit the underlying `axum`/`hyper` stack enforces), an attacker can inflate the per-message CPU cost substantially, and sustain it indefinitely via a single long-lived connection.

### Impact Explanation
This causes sustained CPU consumption in the `websocket-proxy` process, directly analogous to the Nova DoS. Because Tokio multiplexes many client tasks on a shared thread pool, a single (or a handful of) attacker connections doing expensive `O(addresses × transactions × tx_length)` work on every broadcast tick can starve CPU available to other legitimate client tasks on the same worker threads, degrading or denying the RPC/WebSocket broadcast service ("an RPC the node can no longer serve") for other subscribers, and increasing broadcast latency/backpressure that can also trigger the "client is lagging" disconnect path for well-behaved clients.

### Likelihood Explanation
Reachable by any external, low-privilege caller that can complete the HTTP-to-WebSocket upgrade — an authenticated API-key holder via `/ws/{api_key}/filter`, or any anonymous client if `public_access_enabled` is set. No special permissions beyond obtaining/holding a valid API key (or none, in public mode) are needed. The existing per-IP/global rate limiter only throttles *connection establishment*, not the CPU cost sustained *within* an already-open connection, so it does not mitigate this specific vector.

### Recommendation
- Cap the number of `addresses`/`topics` entries accepted in `create_filter_from_query` (e.g., reject or truncate lists beyond a small fixed limit).
- Replace the substring-based transaction fallback scan in `contains_any_address` with a bounded/indexed lookup (e.g., only match well-formed 20-byte hex addresses via structured parsing rather than raw substring search across the whole transaction hex blob), or drop the transaction-body fallback entirely in favor of the already-indexed `new_account_balances`/log-address checks.
- Consider moving expensive filter evaluation off the async task's inline hot path (e.g., a bounded worker pool with a per-connection CPU-time budget) so a single connection cannot starve the shared Tokio runtime.

### Proof of Concept
1. Obtain (or use a public, unauthenticated if enabled) WebSocket proxy endpoint.
2. Connect with a maximally long query string of many comma-separated bogus 40-hex-char "addresses", e.g.:
   `wss://<host>/ws/<api_key>/filter?addresses=0x1111...1,0x2222...2,...,0xNNNN...N` (as many as fit under the HTTP request-line/header size limit).
3. Keep the connection open while the upstream flashblocks feed broadcasts payloads containing transaction lists.
4. Observe elevated CPU usage in the proxy process on every broadcast tick, scaling with the number of supplied addresses times the number/size of transactions in each payload, sustained for the life of the connection; repeat with multiple such connections to amplify the effect. // Parse comma-separated values into Vec<String>
fn parse_comma_separated(input: Option<String>) -> Vec<String> {
    input
        .map(|s| {
            s.split(',')
                .map(|item| item.trim().to_string())
                .filter(|item| !item.is_empty())
                .collect()
        })
        .unwrap_or_default()
}

fn create_filter_from_query(query: FilterQuery) -> FilterType {
    let addresses = parse_comma_separated(query.addresses);
    let topics = parse_comma_separated(query.topics);

    // Parse match mode, default to "any" if not specified
    let match_mode = match query.r#match.as_deref() {
        Some("all") => MatchMode::All,
        Some("any") | None => MatchMode::Any,
        Some(other) => {
            warn!(param = %other, "Invalid match parameter, defaulting to 'any'");
            MatchMode::Any
        }
    };

    let filter = FilterType::new_combined_with_mode(addresses.clone(), topics.clone(), match_mode);
    debug!(
        "Created filter: {:?} from addresses: {:?}, topics: {:?}, match_mode: {:?}",
        filter, addresses, topics, match_mode
    );
    filter
}

    fn contains_any_address(&self, json: &Value, addresses: &HashSet<String>) -> bool {
        // Optimized search: early return on first match

        // Check new_account_balances first (most direct lookup)
        if let Some(found) = json
            .get("metadata")
            .and_then(|m| m.get("new_account_balances"))
            .and_then(|b| b.as_object())
        {
            for account in found.keys() {
                if addresses.contains(&account.to_lowercase()) {
                    debug!(account = %account, "Found address in new_account_balances");
                    return true;
                }
            }
        }

        // Check logs in receipts (most common case for filtering)
        if let Some(receipts) =
            json.get("metadata").and_then(|m| m.get("receipts")).and_then(|r| r.as_object())
        {
            for receipt_value in receipts.values() {
                if let Some(receipt_obj) = receipt_value.as_object() {
                    for receipt_data in receipt_obj.values() {
                        if let Some(logs) =
                            receipt_data.get("logs").and_then(|logs| logs.as_array())
                        {
                            for log in logs {
                                if let Some(addr_str) =
                                    log.get("address").and_then(|addr| addr.as_str())
                                    && addresses.contains(&addr_str.to_lowercase())
                                {
                                    debug!(addr = %addr_str, "Found address in logs");
                                    return true;
                                }
                            }
                        }
                    }
                }
            }
        }

        // Check transactions (least efficient, check last)
        if let Some(transactions) =
            json.get("diff").and_then(|d| d.get("transactions")).and_then(|t| t.as_array())
        {
            for tx in transactions {
                if let Some(tx_str) = tx.as_str() {
                    let tx_lower = tx_str.to_lowercase();
                    for address in addresses {
                        if tx_lower.contains(address) {
                            debug!(tx = %tx_str, "Found address in transaction");
                            return true;
                        }
                    }
                }
            }
        }

        false
    }
