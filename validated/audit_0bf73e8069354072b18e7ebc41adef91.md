### Title
Zip Slip in `extractZipFileEntry` allows attacker archive entries to write outside the intended cache/artifact extraction directory - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFileEntry`, `extractZipDirectoryEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` use `file.Name` from the zip entry verbatim when calling `os.OpenFile`, `os.Mkdir`, and `os.Symlink`, with no check for `..` traversal segments, absolute paths, or symlink targets escaping the extraction root. This is the classic "Zip Slip" pattern and is reachable from the default zip decompression path used by both cache and artifact extraction (`ExtractZipFile` → `ExtractZipArchive` → `extractZipFile` → `extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry`).

### Finding Description
`extractZipFileEntry` performs no path sanitation at all: [1](#0-0) 

The same is true of `extractZipDirectoryEntry` (`os.Mkdir(file.Name, ...)`) and `extractZipSymlinkEntry` (`os.Symlink(string(data), file.Name)`): [2](#0-1) 

The only per-entry check performed before extraction in `ExtractZipArchive` is a warning-only `.git` directory heuristic (`errorIfGitDirectory`) — it never blocks extraction, and there is no validation of `..` segments, drive-absolute paths, or symlink target confinement: [3](#0-2) 

This contrasts sharply with the sibling tar/zstd extractor used for cache/artifact tar archives, which explicitly resolves each entry to an absolute path and rejects anything that escapes the target directory (`chroot`): [4](#0-3) 

The legacy zip extractor that wires this vulnerable code into the CLI (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) does not even reference its own `dir` field for confinement — it just calls `archives.ExtractZipArchive(zr)` and relies entirely on the process's current working directory, with zero path validation: [5](#0-4) 

This legacy zip extractor is the *default* decompressor for zip/zip+zstd cache and artifact archives — it is only overridden when the `FF_USE_FASTZIP` feature flag is explicitly enabled by the operator: [6](#0-5) 

The reachable call chain for cache extraction is `CacheExtractorCommand.Execute` → `archive.NewExtractor(format, f, size, wd)` → `ziplegacy.NewExtractor.Extract` → `archives.ExtractZipArchive`, with `wd` being the job's build/cache directory: [7](#0-6) 

If a zip entry name contains `../../` sequences (or, on Windows, a drive-absolute path such as `C:\...`), or a symlink entry whose target is `../../` combined with a later file entry using that same relative name, `os.OpenFile`/`os.Mkdir`/`os.Symlink` will happily create/overwrite files outside of the intended build/cache root, anywhere the runner process has filesystem permission (e.g., other job workspaces on the same host for shell/SSH executors, or shared paths mounted into the container for Docker executors with bind mounts).

### Impact Explanation
An attacker who can get the runner to decompress an attacker-influenced zip archive (i.e., the "attacker-produced archive content" scenario stated as the entrypoint precondition for this question) can write files to arbitrary paths reachable by the runner process/container user. This can be used to overwrite helper-consumed files (env files, temp scripts, SSH keys, `.bashrc`/profile files sourced by later shell stages, or other jobs' workspace files on shared-host shell executors), leading to secret exposure or code execution in a stronger context on the runner host, matching the "secret exposure or stronger-context execution" impact class described in the question.

### Likelihood Explanation
Precondition: the runner must decompress a zip whose entry names were not produced/sanitized by GitLab Runner's own trusted archiver (i.e., raw archive bytes attacker fully controls end up as the object retrieved for cache/artifact extraction). Given that precondition — which the question explicitly frames as in-scope ("artifact or cache extraction for a job consuming attacker-produced archive content") — exploitation is fully deterministic and repeatable: any zip with `../` in an entry name, or absolute paths, will be extracted verbatim with no error and no path check, every time, on any executor type. The bug is a straightforward missing-check (unlike the tar/zstd extractor, no confinement logic exists at all in this file), so it is not probabilistic or environment-dependent.

### Recommendation
Add the same confinement logic used in `commands/helpers/archive/tarzstd/tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: resolve each entry's target path via `filepath.Join(dir, file.Name)` + `filepath.Abs`, verify the result stays within the extraction root (`strings.HasPrefix(path, dir+string(filepath.Separator))`), and reject/skip entries (and symlink targets) that escape it. Wire the target directory through `ziplegacy.extractor.dir` (currently unused) into `ExtractZipArchive`/`extractZipFile` instead of relying implicitly on `os.Getwd()`.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
1. Build an in-memory `zip.Writer` with a single file entry named `../../evil.txt` (or `..\\..\\evil.txt` on Windows) containing marker bytes.
2. Call `archives.ExtractZipArchive` (or `ExtractZipFile`) with `dir` set to a fresh `t.TempDir()/sub/dir`, mirroring `TestExtractZipFile`'s harness (`testOnArchive`).
3. Assert: `os.Stat(filepath.Join(tempRoot, "evil.txt"))` (i.e., two levels above the intended extraction directory) exists and contains the marker bytes — proving the file escaped the intended root.
4. Add a second case with a symlink entry (`os.ModeSymlink`) whose target is `../../../etc/passwd`-style content, followed by a regular-file entry with the same name, and assert the write followed the escaping symlink.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
