### Title
`minContextSlot` guarantee silently ignored in `accountSubscribe`/`programSubscribe` pubsub handlers - (File: rpc/src/rpc_pubsub.rs)

### Summary
`RpcAccountInfoConfig::min_context_slot` is a client-supplied parameter meant to guarantee that the RPC node has observed at least a given slot before answering. In every stateless JSON-RPC handler (e.g. `get_account_info`, `get_multiple_accounts`) this field is enforced through `get_bank_with_config`, which rejects the request with `MinContextSlotNotReached` if the node's bank slot is behind. In the WebSocket pubsub handlers, however, the same field is explicitly discarded.

### Finding Description
`RpcSolPubSubImpl::account_subscribe` destructures the config and drops the field with an explicit comment marking it dead: [1](#0-0) 

```rust
fn account_subscribe(
    &self,
    pubkey_str: String,
    config: Option<RpcAccountInfoConfig>,
) -> Result<SubscriptionId> {
    let RpcAccountInfoConfig {
        encoding,
        data_slice,
        commitment,
        min_context_slot: _, // ignored
    } = config.unwrap_or_default();
    ...
```

`program_subscribe` exhibits the same behavior — it only reads `encoding`, `data_slice`, and `commitment` out of `config.account_config`, never checking `min_context_slot`: [2](#0-1) 

By contrast, the equivalent stateless calls resolve and enforce this exact field via `get_bank_with_config`: [3](#0-2) [4](#0-3) 

This creates the same class of conflict described in the analog report: a parameter that is supposed to provide a caller-facing guarantee (here, "don't answer from a stale bank/slot") behaves completely differently depending on which code path (stateless RPC vs. pubsub subscribe) is taken, and the pubsub path silently nullifies the check rather than rejecting or honoring it.

### Impact Explanation
A caller who sets `minContextSlot` on `accountSubscribe`/`programSubscribe` — expecting the subscription setup/initial read to be based on state at or after that slot, consistent with how the same config field behaves on `getAccountInfo`/`getProgramAccounts` — instead gets a subscription silently established against whatever bank state is currently available, with no error and no wait. This is a wrong-state-returned analog: the caller can be handed data from a bank slot behind the one they explicitly required, without any signal that the guarantee wasn't honored, which is misleading for consumers building consistency guarantees on top of RPC (e.g., read-your-writes patterns across `sendTransaction` + `accountSubscribe`).

### Likelihood Explanation
Any unprivileged client can trigger this simply by calling `accountSubscribe` or `programSubscribe` with a `minContextSlot` set to a value ahead of the node's current bank slot; no special access or race condition is required, and the field is unconditionally dropped every time.

### Recommendation
Either enforce `min_context_slot` in `account_subscribe`/`program_subscribe` (returning `MinContextSlotNotReached`, consistent with the stateless handlers) or explicitly reject requests that set the field, documenting that it is not supported for pubsub subscriptions so that clients aren't silently misled about the guarantee they requested.

### Proof of Concept
1. Start a node whose current bank slot is `S`.
2. Send `accountSubscribe` (or `programSubscribe`) with `config.minContextSlot = S + 1000000`.
3. Observe that the subscription succeeds immediately and begins delivering notifications based on the current (stale relative to the request) bank state, with no `MinContextSlotNotReached` error — contrasted with calling `getAccountInfo` with the same `minContextSlot`, which correctly errors via `get_bank_with_config` in `rpc/src/rpc.rs`.

impl JsonRpcRequestProcessor {
    fn get_bank_with_config(&self, config: RpcContextConfig) -> Result<Arc<Bank>> {
        let RpcContextConfig {
            commitment,
            min_context_slot,
        } = config;
        let bank = self.bank(commitment);
        if let Some(min_context_slot) = min_context_slot
            && bank.slot() < min_context_slot
        {
            return Err(RpcCustomError::MinContextSlotNotReached {
                context_slot: bank.slot(),
            }
            .into());
        }
        Ok(bank)
    }
