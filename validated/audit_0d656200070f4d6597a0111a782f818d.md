## Analog Found

### Title
Missing allowlist and rate-limiting check on the legacy WebAPI trigger path - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The Rubicon report describes two sibling `offer` functions where one enforces a minimum-amount (`_dust`) check and the other, reachable via `make`, omits it — allowing an unprivileged caller to bypass a validation gate that exists on a parallel code path. The Chainlink Gateway `capabilities` handler exhibits the same class of defect: the legacy web-API trigger path (`HandleLegacyUserMessage`) forwards a user-originated request to every DON node without performing the allowlist/authorization and rate-limit checks that the newer, parallel v2 HTTP trigger path (`httpTriggerHandler.HandleUserTriggerRequest`) explicitly performs before dispatching to nodes.

### Finding Description
`handler.HandleLegacyUserMessage` decodes and validates only structural/timing properties of the incoming request (payload decodability, non-zero/non-stale timestamp, supported method), then immediately fans the request out to every DON member: [1](#0-0) [2](#0-1) 

The code contains an explicit acknowledgment of the missing control: `// TODO: apply allowlist and rate-limiting here`, immediately preceding the method-name check and node fan-out.

By contrast, the parallel v2 HTTP trigger handler — which serves the same conceptual purpose (relaying a user trigger request from the gateway to DON nodes) — performs both a per-workflow authorization step and a rate-limit check before ever contacting a node: [3](#0-2) [4](#0-3) 

This mirrors the Rubicon pattern exactly: one of two structurally-equivalent code paths (`offer` called directly vs. `offer` called via `make`; here, legacy trigger handling vs. v2 trigger handling) enforces the security-relevant check while the other omits it, even though both are reachable from the same class of caller (an unprivileged/unauthenticated gateway client) via `gateway.ProcessRequest`, which selects the legacy path whenever the message carries a non-empty DON ID: [5](#0-4) 

### Impact Explanation
Because `HandleLegacyUserMessage` has no allowlist/authorization gate, any caller able to reach the gateway's legacy JSON message endpoint for a `web_api_trigger` message can cause every member of a DON to receive and process the trigger, without proof that the caller is an authorized workflow owner. This is functionally equivalent to an authorization bypass on the write/trigger path exposed to unprivileged clients, and the missing rate limit additionally removes the throttling protection the newer trigger path relies on to bound resource consumption per workflow/owner — a request-impersonation/quota-bypass concern in gateway terms.

### Likelihood Explanation
Likelihood is high for any deployment still routing `web_api_trigger` messages through the legacy DON-ID-addressed path (the `isLegacyRequest` branch in `gateway.ProcessRequest`), since reaching `HandleLegacyUserMessage` requires nothing more than a well-formed legacy `api.Message` with a valid timestamp and supported method — no per-caller authorization token or allowlist membership is verified in this code path, unlike its v2 counterpart.

### Recommendation
Add the same authorization/allowlist and rate-limiting checks used by `httpTriggerHandler.authorizeRequest`/`checkRateLimit` to `handler.HandleLegacyUserMessage` before forwarding requests to DON members, removing the outstanding TODO, or explicitly deprecate/disable the legacy path in favor of the v2 handler if the gap is intentional and no longer relied upon in production.

### Proof of Concept
1. Send a legacy-format gateway message (`api.Message`) with `Body.Method == "web_api_trigger"`, a valid (non-zero, non-stale) `Timestamp`, and a `DonId` routing it to the `capabilities.handler` instance.
2. Because `gateway.ProcessRequest` routes DON-ID-addressed messages to `HandleLegacyUserMessage` (`core/services/gateway/gateway.go:250-262`), and that method performs no allowlist/authorization or rate-limit check (`core/services/gateway/handlers/capabilities/handler.go:372-420`), the request is forwarded to every DON member (`don.SendToNode`) regardless of caller identity or request volume.
3. Compare with the v2 path (`http_trigger_handler.go:88-106, 361-396`), where an equivalent request is rejected unless `workflowMetadataHandler.Authorize` succeeds and `userRateLimiter.AllowErr` passes — demonstrating the check exists in the codebase for the same conceptual operation but is absent on the legacy path.

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
