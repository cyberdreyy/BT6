## Finding: Valid

### Title
Combined shareholder key causes staker principal to be misrouted to operator's beneficiary in self-operated staking contracts - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`distribute_internal` iterates the `distribution_pool` (a `pool_u64::Pool`, `aptos-move/framework/aptos-stdlib/sources/pool_u64.move`) which tracks shares keyed only by `address` (`shares: SimpleMap<address, u64>`), and unconditionally treats any shareholder entry whose key equals `operator` as commission, rerouting it to `beneficiary_for_operator(operator)`. When a staker creates a self-operated staking contract (`staker == operator`, which is not blocked anywhere in `create_staking_contract`/`create_staking_contract_with_coins`), the staker's principal-withdrawal shares (bought in via `add_distribution` with `recipient = staker_address`, `staking_contract.move:938-957`) and the operator's commission shares (bought in via `update_distribution_pool` with `recipient = operator`, `staking_contract.move:880-886`) get bought into the **same shareholder slot**, because `pool_u64::add_shares` merges shares for an address that already exists in the map: [1](#0-0) 

### Finding Description
In `distribute_internal`: [2](#0-1) 

`recipients[0]` and `current_shares` are read per address. If `staker_address == operator`, the single shareholder entry at that address contains the *sum* of the staker's principal-withdrawal shares (added via `add_distribution(operator, staking_contract, staker_address, amount)`) and the operator's commission shares (added via `update_distribution_pool(...)`): [3](#0-2) 

`amount_to_distribute = distribution_pool.redeem_shares(recipient, current_shares)` therefore returns the combined principal + commission value. The subsequent check `if (recipient == operator) { recipient = beneficiary_for_operator(operator) }` is then true (since `recipient == staker_address == operator`), so the **entire combined amount, including the staker's principal**, is deposited to the operator's beneficiary rather than the staker.

This breaks the documented invariant that `beneficiary_for_operator` should only ever receive the operator's commission share, not staker principal, as stated in the module's own accounting model docstring at the top of the file: [4](#0-3) 

### Impact Explanation
An operator who is also the staker of their own staking contract (a legitimate, unprivileged configuration — nothing in `create_staking_contract`/`create_staking_contract_with_coins` prevents `staker == operator`) and who sets a distinct `beneficiary_for_operator` will have their own unlocked principal misrouted to the beneficiary address instead of themselves whenever `distribute`/`distribute_internal` runs with commingled principal and commission owed in the same epoch's unlock batch. This is a self-inflicted misrouting (the staker/operator controls the beneficiary setting), so it does not let a third-party attacker steal funds from someone else's pool, but it does corrupt the accounting invariant that beneficiary redirection applies only to commission, silently sending principal to an unintended (though self-chosen) address, and could also affect commission accounting reasoning for auditors/tools that assume commission-only redirection.

### Likelihood Explanation
Requires: (1) a self-operated staking contract (`staker == operator`), and (2) `set_beneficiary_for_operator` used to point commission elsewhere, and (3) a `distribute`/`unlock_stake`/`request_commission`/`switch_operator` call while both an unredeemed staker-principal distribution and unredeemed operator-commission distribution coexist in the pool for the same address. All of these are reachable via normal unprivileged entry functions (`create_staking_contract`, `set_beneficiary_for_operator`, `unlock_stake`, `distribute`), so the path is fully unprivileged, though the scenario (self-operated pool + separate beneficiary) is a narrow, non-default configuration.

### Recommendation
Prevent principal and commission shares for the same staking contract from being merged into a single `pool_u64` shareholder slot when `staker == operator`. Options: (a) disallow `staker == operator` in `create_staking_contract`, or (b) track commission and principal distributions in logically separate ledgers keyed independently of raw address collisions (e.g., tag entries with a role rather than relying solely on `address == operator` equality), or (c) explicitly special-case and split out the principal portion before rerouting only the commission portion to the beneficiary during `distribute_internal`.

### Proof of Concept
Move test sketch, extending the existing test module in `staking_contract.move`:
1. `create_staking_contract_with_coins(staker, staker /* same address */, voter, 100_coins, 10 /* commission % */, seed)`.
2. `set_beneficiary_for_operator(staker, beneficiary)` with `beneficiary != staker`.
3. Generate rewards via `stake::end_epoch()` so accumulated rewards exist.
4. Call `unlock_stake(staker, staker, principal_amount)` to buy the staker into `distribution_pool` under `recipient = staker_address` (== operator).
5. Call `request_commission(staker, staker, staker)` or otherwise cause commission shares to also be bought in under the same operator address before the pool is drained (e.g., trigger both paths within the same `distribute_internal` call so `update_distribution_pool` and `add_distribution` both touch the same address before shares are redeemed).
6. Advance epochs to make inactive/pending_inactive funds withdrawable, then call `distribute(staker, staker)`.
7. Assert that `beneficiary`'s balance equals only the expected commission (`unpaid_commission`), not `unpaid_commission + principal_amount`; the bug manifests as `beneficiary`'s balance including the principal. [5](#0-4)

    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
