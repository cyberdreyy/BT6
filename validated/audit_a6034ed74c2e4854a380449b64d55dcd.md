### Title
Floor-division threshold check in `GlobalStateEvaluator::reached_agreement` lets sub-70% weight finalize global state - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` computes the approval threshold as `total_weight * NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD / 10` using integer (floor) division and then compares `vote_weight >= threshold`. Because the division floors instead of producing the mathematically exact comparison, a coalition holding strictly less than 70% of `total_weight` can satisfy the check whenever `7 * total_weight` is not evenly divisible by 10. [1](#0-0) 

### Finding Description
The correct predicate for "vote_weight is at least 70% of total_weight" is the exact cross-multiplied inequality `vote_weight * 10 >= total_weight * 7`, which requires no rounding at all. Instead, the implementation pre-computes `total_weight * 7 / 10` (floor) as a threshold constant and then checks `vote_weight >= threshold`. For any `total_weight` where `7 * total_weight` is not a multiple of 10 (e.g. `total_weight = 3`: `7*3/10 = 2` via floor division, while the exact requirement is `vote_weight*10 >= 21`, i.e. `vote_weight >= 3`), a `vote_weight` one unit below the true requirement (`vote_weight = 2`, i.e. 66.7%) is incorrectly accepted as having "reached agreement." This function is invoked from `determine_global_state`/`determine_global_burn_view` to decide when accumulated per-key vote weight is sufficient to finalize a `SignerStateMachine`/burn view. No attacker privilege beyond normal participation in gossip/StackerDB signer traffic is needed to benefit from this arithmetic error - it is a latent logic bug triggered purely by the reward-set weight distribution, not by any crafted message content.

### Impact Explanation
This breaks the intended fail-closed 70%-weight safety margin for state-machine convergence: a minority coalition (as low as ~66.7% depending on weight distribution) can cause the evaluator to treat global agreement as reached on a `MinerState`/burn view. Signers that finalize on this under-quorum state then act on that view (e.g., which miner/tenure/burn block is canonical) for gating block-signing eligibility, which can cause participants to sign or refuse based on a view that did not actually have real 70% support - a stale/incorrect threshold-driven state acceptance.

### Likelihood Explanation
The bug triggers automatically whenever the reward-set weight distribution produces a `total_weight` such that `7 * total_weight mod 10 != 0`, which is common for arbitrary weight distributions (most values of `total_weight` are not multiples of 10). No special attacker action is needed beyond normal proposal/vote traffic; it is a deterministic arithmetic property of the reward set, so it is reliably reproducible whenever such weight distributions occur.

### Recommendation
Replace the floor-divided threshold constant with the exact cross-multiplied comparison to eliminate rounding entirely:
```rust
u64::from(vote_weight).strict_mul(10) >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
```
This avoids any floor/ceiling ambiguity by keeping both sides as exact integers.

### Proof of Concept
```rust
#[test]
fn reached_agreement_floor_division_bug() {
    // total_weight = 3, threshold = 70% (NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7)
    let mut evaluator = GlobalStateEvaluator::new(/* weights */ HashMap::new(), 3);

    // Exact requirement: vote_weight * 10 >= total_weight * 7  =>  vote_weight >= 2.1  =>  vote_weight >= 3
    // Buggy floor-division threshold: total_weight * 7 / 10 = 21 / 10 = 2 (floor)

    // vote_weight = 2 represents 66.7% of total_weight, below the 70% requirement.
    assert!(
        !exact_reached_agreement(2, 3, 7),
        "2/3 = 66.7% must NOT satisfy a 70% threshold"
    );

    // Current buggy implementation incorrectly accepts it:
    assert!(
        evaluator.reached_agreement(2),
        "bug: floor-division threshold accepts vote_weight=2 as reaching 70% agreement"
    );
}

fn exact_reached_agreement(vote_weight: u64, total_weight: u64, threshold_pct: u64) -> bool {
    vote_weight * 10 >= total_weight * threshold_pct
}
```
This test demonstrates the divergence: the exact ceiling-based inequality rejects `vote_weight = 2` out of `total_weight = 3`, while the floor-divided threshold in `reached_agreement` accepts it, confirming the sub-quorum finalization vulnerability. [1](#0-0)
