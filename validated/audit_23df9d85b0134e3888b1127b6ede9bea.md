### Title
Hardcoded 24h staleness window equal to the USD0++/USD feed heartbeat DoSes `stopEpoch`/`startEpoch` and freezes tranche withdrawals — (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice` enforces a single hardcoded staleness threshold (`updatedAt > block.timestamp - 24 hours`) that is exactly equal to the USD0pp oracle's 24‑hour heartbeat. Because the revert margin is zero (strict `>` with no buffer beyond the heartbeat), any update that lands at or slightly past the heartbeat boundary — a routine occurrence for a deviation-threshold feed — makes `getChainlinkPrice` revert. Both `IdleCDOUsualVariant.startEpoch` and `stopEpoch` call it, so a stale round blocks epoch transitions and keeps `allowAAWithdraw`/`allowBBWithdraw` disabled, temporarily freezing all senior and junior tranche funds until the feed next updates. ### Finding Description
The external report's bug class — a single staleness period mismatched with a feed's actual update cadence — maps directly onto `IdleUsualStrategy`. `getChainlinkPrice` reads `updatedAt` from the fixed `USD0ppOracle` feed and reverts unless the round is strictly newer than 24 hours old:

```solidity
(,int256 answer,,uint256 updatedAt,) = IOracle(USD0ppOracle).latestRoundData();
require(updatedAt > block.timestamp - 24 hours, "Stale price");
``` [3](#0-2) 

The comment states the feed has a 24h heartbeat plus a 0.5% deviation trigger, so the staleness allowance equals the maximum expected gap between rounds — there is no slack at all. In `stopEpoch`, the fetched price is what decides whether juniors must socialize a loss to seniors (`_oraclePrice >= oneToken` early-return vs. `lastNAVAA` bump + `_updateAccounting`), so the epoch cannot safely conclude without it; a stale round therefore halts the entire epoch state machine. [4](#0-3) 

### Impact Explanation
Temporary freezing of all tranche funds. While `isEpochRunning == true`, `allowAAWithdraw` and `allowBBWithdraw` are `false`, so no senior or junior holder can redeem. If the USD0pp feed's last update is ≥24h old when the owner calls `stopEpoch` (keeper delay, low-volatility period where deviation threshold isn't hit and the heartbeat update propagates late, or a round landing exactly at the boundary failing the strict `>`), the call reverts. Every retry reverts until Chainlink posts a new round, extending the freeze by up to a full heartbeat (~24h) per occurrence, repeatedly. The same applies to `startEpoch` (deposited underlying sits idle, epoch can't start) and `initialize` (revert at deployment if the feed happens to be at the boundary). Honest privileged roles cannot mitigate this — there is no fallback price path; `setOraclePrice` is only reachable after `getChainlinkPrice` already succeeded inside `stopEpoch`. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
No attacker action is required — this is a liveness/availability failure triggered by normal feed behavior. A feed whose heartbeat equals the staleness window will periodically sit right at the boundary: heartbeat updates are scheduled "at" 24h but propagate with nonzero delay, and the strict inequality offers zero tolerance. Each epoch transition (owner-initiated, so timing is not controllable by the protocol relative to the feed's clock) has a material chance of hitting a stale round; over many epochs the probability compounds to near-certainty. Quantified impact: per occurrence, 100% of AA and BB tranche NAV is unredeemable for up to ~24 hours (until the next USD0pp round).

### Recommendation
Add a buffer to the staleness window (e.g., `updatedAt > block.timestamp - 25 hours` or `24 hours + grace`), and/or allow a fallback path: let `stopEpoch` proceed using the floor price via `IUSD0pp.getFloorPrice()` when the Chainlink round is stale, or let the owner call `setOraclePrice` directly to conclude the epoch. Also record `answeredInRound`/roundId validation alongside the relaxed staleness bound.

    require(epochEndDate == 0, "9");

  function stopEpoch() external {
    _checkOnlyOwner();
    // if the epoch is not running we revert
    require(isEpochRunning && block.timestamp >= epochEndDate, "9");

    IdleUsualStrategy _strategy = IdleUsualStrategy(strategy);
    // we fetch and set oracle price for reference
    uint256 _oraclePrice = _strategy.getChainlinkPrice();
    _strategy.setOraclePrice(_oraclePrice);

    // we unpause redeems only
    allowAAWithdraw = true;
    allowBBWithdraw = true;
    // set epoch as not running
    isEpochRunning = false;

    // if usd0++ price is 1$ or more then junior doesn't owe anything to senior
    if (_oraclePrice >= oneToken) {
      return;
    }
    // if price is less than 1$ we calculate how much junior should give to senior considering 1 usd0++ = 1$
    // eg price is 0.9$, lastNAVAA is 100 usd0++ (ie 90$) and targetAATVL should be 100$ so 100 / 0.9 = 111.11 usd0++
    // so we do lastNAVAA * (1 / oraclePrice) = 100 * (1 / 0.9) = 111.11
    uint256 targetAATVL = lastNAVAA * oneToken / _oraclePrice;

    // we increase the lastNAVAA so that the senior tranche is at par with 1$
    lastNAVAA += targetAATVL - lastNAVAA;

    // this will cause the next updateAccounting call to account a loss which will be absorbed by the junior tranche
    _updateAccounting();    
```
