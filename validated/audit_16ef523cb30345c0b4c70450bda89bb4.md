### Title
Cache/artifact extraction only warns (does not block) `.git/hooks/*` entries, allowing hook-based command execution later in the same job - (File: `helpers/archives/path_check_helper.go`, `helpers/archives/zip_extract.go`)

### Summary
`errorIfGitDirectory` only classifies a zip entry as `.git`-rooted; it never aborts extraction, and `ExtractZipArchive` treats the returned error as "actionable" only for a warning log, always proceeding to `extractZipFile`. This lets a cache or artifact zip plant arbitrary files (including executable hook scripts) into `<project>/.git/hooks/`, which can be triggered by any git command the job script runs afterward, in the same job, before the runner's post-clone hook cleanup has any chance to remove them.

### Finding Description
`isPathAGitDirectory`/`errorIfGitDirectory` in `helpers/archives/path_check_helper.go:13-31` only detect the `.git` first path segment and return a `*os.PathError` describing the problem — they never prevent extraction. `ExtractZipArchive` in `helpers/archives/zip_extract.go:85-96` calls `errorIfGitDirectory(file.Name)`, and if `tracker.actionable(err)` is true it only calls `printGitArchiveWarning("extract")` and continues straight to `extractZipFile(file)` on the very next line — the entry is written to disk regardless. `extractZipFile`/`extractZipFileEntry` (`helpers/archives/zip_extract.go:41-83`) writes the file with the mode stored in the zip header (`file.Mode().Perm()`), so an attacker fully controls both content and the executable bit of the planted file. This is confirmed by the existing test `TestExtractZipFileWithGitPath` (`helpers/archives/zip_extract_test.go:69-92`), which asserts extraction succeeds (`require.NoError`) and the `.git/test_file` is actually created — the only enforcement is a log line.

In the job execution flow (`functions/concrete/run/runner.go:172-207`, `prepare`), `get_sources` (clone/checkout + git hook/config cleanup via `cleanupGitState`/`writeGitCleanupAllConfigs`) runs first, and `restore_cache` / `download_artifacts` run afterward, in the same job, extracting attacker-influenced cache/artifact zip content directly into the project's working tree — including `.git/hooks/` — with no re-run of the cleanup logic after extraction. The runner's dedicated hook-cleanup mechanism (`shells/abstract.go:1112-1139`, `functions/concrete/run/stages/get_sources.go:557-592`) only removes a hardcoded `hooks/post-checkout` file and (if `clean_git_config` is enabled) wipes the whole `hooks/` directory, but this cleanup executes before cache/artifact extraction in the same job, not after. Consequently, any hook planted by cache/artifact extraction (`pre-commit`, `post-merge`, `pre-push`, `post-checkout` from a subsequent manual checkout, etc.) remains live for the rest of the job and will fire the next time the job script invokes a git operation that triggers it.

### Impact Explanation
An attacker who controls the contents of a cache or artifact zip (e.g., a prior stage/job in the same pipeline/project that legitimately or maliciously stores `.git/hooks/*` as a cache path, or a cache-key collision/poisoning scenario) can achieve command execution in the runner's job context during a later stage of the same job, outside of the explicitly authored job script — satisfying the scoped impact of "runner-side command execution outside the authored job script." This is a genuine gap: the code explicitly attempts to detect `.git`-rooted archive entries (`errorIfGitDirectory` exists specifically for this reason) but deliberately downgrades the block to a warning, defeating the protection's purpose.

### Likelihood Explanation
The precondition ("job pipeline runs `git` commands against the extraction directory after cache/artifact restore") is common — jobs frequently run `git checkout`, `git submodule update`, `git commit`, or `git merge` after `cache:`/`artifacts:` restoration, and GIT_STRATEGY `fetch`/`clone` reuse the same working tree. Producing a zip with a `.git/hooks/<name>` entry and desired file mode is trivial and fully attacker-controlled at zip-creation time (e.g. crafted during an earlier job stage that uploads it as a cache/artifact). The bug is deterministically reproducible since the extraction code path unconditionally proceeds after only logging a warning, as already demonstrated by the existing `TestExtractZipFileWithGitPath` test.

### Recommendation
Change `ExtractZipArchive` (and the equivalent tar/tar.zst/tar.gz extractors) to actually reject `.git`-rooted entries from cache/artifact archives instead of merely warning — return an error (or skip the entry entirely) when `errorIfGitDirectory` detects a `.git` path, at minimum disallowing writes under `.git/hooks/`. If some legitimate use case requires caching `.git` metadata, strip the executable bit from anything under `.git/hooks/` on extraction and/or re-run the existing `writeGitCleanupAllConfigs`/`cleanupGitState` hook-removal logic after cache/artifact extraction completes, not only before `get_sources`.

func TestExtractZipFilePlantsExecutableGitHook(t *testing.T) {
    testOnArchive(t, func(t *testing.T, archive *zip.Writer) {
        hdr := &zip.FileHeader{Name: ".git/hooks/post-checkout"}
        hdr.SetMode(0o755)
        w, err := archive.CreateHeader(hdr)
        require.NoError(t, err)
        _, err = w.Write([]byte("#!/bin/sh\ntouch /tmp/pwned\n"))
        require.NoError(t, err)
    }, func(t *testing.T, fileName string) {
        err := ExtractZipFile(fileName)
        require.NoError(t, err) // extraction "succeeds" despite malicious .git path

        info, statErr := os.Stat(".git/hooks/post-checkout")
        require.NoError(t, statErr)
        assert.NotZero(t, info.Mode()&0o111, "hook file is executable")
        defer os.RemoveAll(".git")
    })
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

//nolint:gocognit
func (r *Runner) prepare(ctx context.Context) error {
	if err := r.section(ctx, "get_sources", r.config.GetSources.Run); err != nil {
		return fmt.Errorf("fetching sources: %w", err)
	}

	// Reload so KEY=VALUE entries appended by pre_clone_script / post_clone_script flow into downstream stages.
	if hasCacheSources(r.config.CacheExtract) {
		r.loadGitlabEnv()
		_ = r.section(ctx, "restore_cache", func(ctx context.Context, e *env.Env) error {
			for _, cache := range r.config.CacheExtract {
				if len(cache.Sources) == 0 {
					continue
				}
				if err := cache.Run(ctx, e); err != nil {
					r.logWarningf("Failed to restore cache %q: %v", cache.Sources[0].Key, err)
				}
			}
			return nil
		})
	}

	if len(r.config.ArtifactExtract) > 0 {
		r.loadGitlabEnv()
		_ = r.section(ctx, "download_artifacts", func(ctx context.Context, e *env.Env) error {
			for _, artifact := range r.config.ArtifactExtract {
				if err := artifact.Run(ctx, e); err != nil {
					r.logWarningf("Failed to download artifact %q: %v", artifact.ArtifactName, err)
				}
			}
			return nil
		})
	}

	return nil
}

// cleanupGitState removes stale lock files and (when CleanGitConfig is set)
// potentially-malicious git configs and hooks from prior jobs.
func (s GetSources) cleanupGitState(e *env.Env) {
	dotGitDir := filepath.Join(e.WorkingDir, ".git")

	// Remove lock files and stale post-checkout hook.
	lockFiles := []string{"index.lock", "shallow.lock", "HEAD.lock", "config.lock"}
	for _, f := range lockFiles {
		_ = os.Remove(filepath.Join(dotGitDir, f))
	}
	_ = os.Remove(filepath.Join(dotGitDir, "hooks", "post-checkout"))

	if s.hasSubmodules() {
		modulesDir := filepath.Join(dotGitDir, "modules")
		for _, f := range lockFiles {
			walkRemove(modulesDir, f, false)
		}
		// The old shell code also removed post-checkout recursively in modules.
		walkRemove(modulesDir, "post-checkout", false)
	}

	walkRemove(filepath.Join(dotGitDir, "refs"), ".lock", true)

	// Clean configs and hooks if requested.
	if !s.CleanGitConfig {
		return
	}

	for _, dir := range []string{filepath.Join(e.WorkingDir+".tmp", templateDirName), dotGitDir} {
		_ = os.Remove(filepath.Join(dir, "config"))
		_ = os.RemoveAll(filepath.Join(dir, "hooks"))
	}
	if s.hasSubmodules() {
		modulesDir := filepath.Join(dotGitDir, "modules")
		walkRemove(modulesDir, "config", false)
		walkRemove(modulesDir, "hooks", false)
	}
}

func (b *AbstractShell) writeGitCleanup(w ShellWriter, build *common.Build) {
	projectDir := build.FullProjectDir()
	submoduleStrategy := build.GetSubmoduleStrategy()
	cleanForSubmodules := submoduleStrategy == common.SubmoduleNormal || submoduleStrategy == common.SubmoduleRecursive

	// Remove .git/{index,shallow,HEAD,config}.lock files from .git, which can fail the fetch command
	// The file can be left if previous build was terminated during git operation.
	// If the git submodule strategy is defined as normal or recursive, also remove these files
	// inside .git/modules/**/
	files := []string{
		"index.lock",
		"shallow.lock",
		"HEAD.lock",
		"hooks/post-checkout",
		"config.lock",
	}

	for _, f := range files {
		w.RmFile(path.Join(projectDir, gitDir, f))
		if cleanForSubmodules {
			w.RmFilesRecursive(path.Join(projectDir, gitDir, "modules"), path.Base(f))
		}
	}

	w.RmFilesRecursive(path.Join(projectDir, gitDir, "refs"), "*.lock")

	b.writeGitCleanupAllConfigs(w, build, cleanForSubmodules)
}
