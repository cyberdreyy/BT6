**Rationale:** The receipt's action list is built directly from the same `Transaction` object that `verify_function_call_permission` validates — there is no divergent serialization/reconstruction path.

In `runtime/runtime/src/lib.rs`, on `TxVerdict::Success`, the receipt is created with `tx.transaction.actions().to_vec()` [1](#0-0)  — this is the exact in-memory `Transaction::actions()` slice that `verify_function_call_permission` read moments earlier during `verify_and_charge_tx_ephemeral` (or the gas-key equivalent) [2](#0-1) [3](#0-2) . There is no re-parsing, re-deserialization, or alternate construction of the action list between verification and receipt creation — `.to_vec()` simply clones the `Vec<Action>` already borrowed by `tx.actions()`.

Later, `execute_function_call` populates `VMContext::signer_account_id` from `action_receipt.signer_id()` [4](#0-3) , and the `action_receipt.actions` used to drive execution is this same cloned vector (via `VersionedActionReceipt`), so the action executed is guaranteed to be the identical `FunctionCall` action checked by `verify_function_call_permission`.

The only other place actions get rebuilt from a receipt's action list is for *new* receipts spawned by a function call (`ActionReceiptV2` construction in `action_function_call`), which is unrelated to the original transaction's access-key check and does not re-derive from `tx.actions()` at all [5](#0-4) .

Since the premised "divergent code path" reconstructing `ActionReceipt.actions` from a separate serialization of `SignedTransaction.transaction.actions` does not exist in this codebase — the receipt is built from the exact same `Transaction` struct/slice used for verification — the described authorization-widening scenario is not reachable.

fn verify_function_call_permission(
    function_call_permission: &FunctionCallPermission,
    tx: &Transaction,
) -> Result<(), InvalidTxError> {
    if tx.actions().len() != 1 {
        return Err(InvalidTxError::InvalidAccessKeyError(
            InvalidAccessKeyError::RequiresFullAccess,
        ));
    }
    let Some(Action::FunctionCall(function_call)) = tx.actions().get(0) else {
        return Err(InvalidTxError::InvalidAccessKeyError(
            InvalidAccessKeyError::RequiresFullAccess,
        ));
    };
    if function_call.deposit > Balance::ZERO {
        return Err(InvalidTxError::InvalidAccessKeyError(
            InvalidAccessKeyError::DepositWithFunctionCall,
        ));
    }
    let tx_receiver = tx.receiver_id();
    let ak_receiver = &function_call_permission.receiver_id;
    if tx_receiver != ak_receiver {
        return Err(InvalidTxError::InvalidAccessKeyError(
            InvalidAccessKeyError::ReceiverMismatch {
                tx_receiver: tx_receiver.clone(),
                ak_receiver: ak_receiver.clone(),
            },
        ));
    }
    if !function_call_permission.method_names.is_empty()
        && function_call_permission
            .method_names
            .iter()
            .all(|method_name| &function_call.method_name != method_name)
    {
        return Err(InvalidTxError::InvalidAccessKeyError(
            InvalidAccessKeyError::MethodNameMismatch {
                method_name: function_call.method_name.clone(),
            },
        ));
    }
    Ok(())
}
