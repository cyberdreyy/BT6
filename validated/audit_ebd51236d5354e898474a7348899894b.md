## Title
Single-use Vault request-digest authorization consumed without fallback enables front-run DoS of `AllowListBasedAuth` gateway requests - (File: core/capabilities/vault/authorizer.go, core/capabilities/vault/allow_list_based_auth.go)

### Summary
The Vault gateway authorization pipeline (`AllowListBasedAuth` + `RequestReplayGuard`) mirrors the RouterV2 permit-frontrunning bug class: a request is authorized purely by matching a single-use `requestDigest` against an on-chain-published allowlist entry, and the digest is unconditionally marked "seen" on first successful match with no fallback path. Because the on-chain allowlist entry (owner, digest, expiry) published via `workflow_registry_wrapper_v2` is public before the corresponding gateway request is submitted, any unprivileged actor who reconstructs or observes the exact request body can submit it to the gateway ahead of the legitimate owner, consuming the digest and permanently causing the legitimate request to fail with `ErrRequestAlreadySeen`.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` computes a `requestDigest` from the raw JSON-RPC request and checks it against the on-chain allowlist (`workflowRegistrySyncer.GetAllowlistedRequests`), returning an `AuthResult` bound to that digest if a match is found: [1](#0-0) 

Critically, this authorization path performs **no signature check on the caller** — any party who can produce a JSON-RPC request whose digest matches a pre-published on-chain allowlist entry is authorized as that owner, exactly analogous to RouterV2's unconditional `permit()` call that trusts the raw signature without a fallback if it's already been consumed.

`authorizer.AuthorizeRequest` then immediately and unconditionally records the digest as used via `replayGuard.CheckAndRecord`, with no error handling or fallback if that digest was already consumed by someone else: [2](#0-1) 

The `RequestReplayGuard` is a simple map: once a digest is recorded, any subsequent request bearing that same digest is rejected with `ErrRequestAlreadySeen`, with no distinction between "attacker replay" and "legitimate owner's real submission": [3](#0-2) 

This exactly matches the reported bug class: "any function call that unconditionally performs a single-use authorization check can be forced to fail this way" — here, instead of `permit()` reverting on reuse, the gateway's replay guard rejects the legitimate owner's follow-up call once the digest has already been recorded by someone else who got there first.

### Impact Explanation
If an unprivileged party obtains or reconstructs the plaintext JSON-RPC body corresponding to a digest that a workflow owner has pre-published on-chain (e.g., via network observation of the gateway-bound HTTP request, a leaked/forwarded request body, or a predictable/low-entropy request), that party can submit it to the Vault gateway before the legitimate owner does. Their submission is authorized (digest matches the allowlist) and immediately consumes the digest in `RequestReplayGuard`. The legitimate owner's subsequent, otherwise-valid submission of the same allowlisted request is then rejected outright with `ErrRequestAlreadySeen`, permanently denying the owner's Vault operation (secret create/update/delete/list) tied to that pre-authorized digest, since allowlist entries are single-use and time-boxed by `ExpiryTimestamp`. This is a request-level DoS with no recovery short of re-allowlisting on-chain, directly mirroring the loss of liquidity-removal functionality described in the RouterV2 report.

### Likelihood Explanation
Exploitation requires the attacker to know the exact plaintext request body (not just its digest) that hashes to a public on-chain allowlist entry, since only the digest — not the plaintext — is published on-chain. This is a materially harder precondition than the RouterV2 case, where the permit signature itself is fully visible in the mempool. The likelihood is therefore contingent on some channel exposing the plaintext request ahead of the owner's real submission (e.g., logging, a shared/observable transport, or an untrusted intermediary constructing and forwarding the request on the owner's behalf). I was not able to verify from the indexed code whether such an exposure channel exists in this codebase (e.g., whether workflow-side tooling broadcasts the plaintext body prior to gateway submission), so likelihood is assessed as **possible but unconfirmed** given available context.

### Recommendation
- Do not treat "digest already seen" as an unconditional terminal rejection when the caller is the legitimate allowlisted owner; consider binding the replay-guard record to a caller-provided nonce/signature so only the genuine owner (or someone possessing owner authority) can consume the entry, not merely anyone who reproduces the plaintext.
- Consider requiring a lightweight caller-bound proof (e.g., an ECDSA signature over the digest by the owner's key, similar to the JWT-based path already present in `authorizer.go`) rather than pure digest matching for `AllowListBasedAuth`, closing the impersonation/DoS gap.
- If digest-only authorization must be retained for backwards compatibility, add a fallback (e.g., grace window keyed by requester identity) analogous to the try/catch mitigation recommended for RouterV2, rather than a hard, permanent single-use rejection.

### Proof of Concept
Conceptual (not verified end-to-end due to inability to confirm plaintext-exposure precondition):
1. Workflow owner allowlists a specific Vault request on-chain: `(owner, requestDigest = H(method, params, id), expiryTimestamp)` via the workflow registry contract.
2. Owner (or their client tooling) prepares to submit the exact JSON-RPC body to the Vault gateway.
3. An unprivileged party who obtains that plaintext body ahead of time (e.g., via a compromised/observable transport) submits it to the gateway first.
4. `allowListBasedAuth.AuthorizeRequest` matches the digest against the allowlist and returns a valid `AuthResult`. [4](#0-3) 
5. `authorizer.AuthorizeRequest` records the digest via `replayGuard.CheckAndRecord`, marking it consumed. [5](#0-4) 
6. The legitimate owner submits the identical request; `CheckAndRecord` now returns `ErrRequestAlreadySeen`, and the owner's Vault operation is permanently rejected — a request-level DoS analogous to the front-run permit() failure in RouterV2. [3](#0-2)

```go
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
```

```go
func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
```

```go
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
```
