### Title
EI-authenticated requests bypass "no int-ID job runs for EIs" restriction in `PipelineRunsController.Create` via synthetic run-role user - ([File: core/web/pipeline_runs_controller.go])

### Summary
`AuthenticateExternalInitiator` injects a synthetic `clsessions.User{Role: UserRoleRun}` into the gin context under `SessionUserKey` for any successfully authenticated external initiator. `RequiresRunRole` and `GetAuthenticatedUser` cannot distinguish this synthetic user from a genuine session/API-token user, so `PipelineRunsController.Create`'s `isUser` check passes and lets EIs trigger `RunJobV2` on arbitrary int32 job IDs, directly contradicting the code's own "EIs not allowed" comment.

### Finding Description
`AuthenticateExternalInitiator` (core/web/auth/auth.go:119-151), after validating the EI access key/secret, sets both `SessionExternalInitiatorKey` and `SessionUserKey`: [1](#0-0) 

`GetAuthenticatedUser` simply reads back whatever object is stored at `SessionUserKey` with no way to tell whether it originated from a real session/API-token authentication or from this synthetic EI injection: [2](#0-1) 

`RequiresRunRole` only checks that `user.Role != UserRoleView`, so the synthetic `UserRoleRun` user passes: [3](#0-2) 

Inside `PipelineRunsController.Create`, the `isUser` boolean is derived purely from `GetAuthenticatedUser`'s second return value (`ok`), not from whether the caller authenticated via session/token vs. EI: [4](#0-3) 

Because the synthetic EI user satisfies `ok == true`, `isUser` is `true`, and the branch intended to be reserved for real users (per the comment "only users are allowed to run jobs using int IDs - EIs not allowed") executes `prc.App.RunJobV2(ctx, jobID, nil)` for any parseable int32 job ID — including jobs of a type unrelated to the EI's binding (e.g., an OCR job), since `RunJobV2` performs no ownership/type check tying the run to the EI.

### Impact Explanation
An external-initiator credential holder — a lower-trust credential intended only to trigger webhook-bound job runs — can manually trigger arbitrary job runs (`unauthorized job run`) on any job by integer ID, bypassing the webhook/job-UUID binding model entirely. This matches the "unauthorized job run" bounty impact class: an EI is meant to only be able to invoke the specific webhook job it's bound to, not arbitrary jobs (e.g., OCR jobs) by ID.

### Likelihood Explanation
Exploitation requires only a valid, already-provisioned EI credential (access key + secret) — no session cookie or API token. It's a single unauthenticated (from the node's session perspective) HTTP POST to `/v2/jobs/<int32-job-id>/runs` with the EI headers set, fully repeatable, and requires no race conditions or timing dependencies.

### Recommendation
Do not overload `SessionUserKey`/`GetAuthenticatedUser` for external initiators. Track EI authentication via a distinct context flag (e.g., check `GetAuthenticatedExternalInitiator` presence) and explicitly exclude that case from the `isUser` branch in `Create`, e.g.: `_, isEI := auth.GetAuthenticatedExternalInitiator(c); if isUser && !isEI { ... }`, or have `RequiresRunRole`/`Create` reject requests where both the EI and synthetic-user keys are set.

### Proof of Concept
1. Set up a test app with `build.IsProd() == false`.
2. Create an OCR (non-webhook) job with a known int32 job ID.
3. Register a valid `ExternalInitiator` credential unrelated to that job.
4. Send `POST /v2/jobs/<ocr-job-id>/runs` with only `X-Chainlink-EA-AccessKey` / `X-Chainlink-EA-Secret` headers set (no session cookie, no `X-API-KEY`/`X-API-SECRET`).
5. Assert current (vulnerable) behavior: HTTP 200/201 with a created `pipelineRun` resource, and that `App.RunJobV2` was invoked with `nil` — expected/fixed behavior should be `422` or `401`, with `RunJobV2` never called for EI-only requests.

// GetAuthenticatedUser extracts the authentication user from the context.
func GetAuthenticatedUser(c *gin.Context) (*clsessions.User, bool) {
	obj, ok := c.Get(SessionUserKey)
	if !ok {
		return nil, false
	}

	user, ok := obj.(*clsessions.User)

	return user, ok
}
```

func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```
