### Title
Kubernetes autoscaler `Provider` keys pause-pod managers by runner token, causing orphaned managers/pods on token rotation - (File: `executors/kubernetes/autoscaler/provider.go`)

### Summary
`executors/kubernetes/autoscaler/provider.go` tracks per-runner `PausePodManager` state in `Provider.managers`, keyed solely by `config.GetToken()`. GitLab Runner automatically rotates runner authentication tokens in place (`commands/multi.go` `resetOneRunnerToken`/`reloadConfig`), which changes the value returned by `GetToken()` for a runner whose `RunnerConfig` identity (URL/ID) is otherwise unchanged. When this happens, `ensureManager` creates a brand-new map entry under the new token instead of reusing/updating the existing manager, leaving the previous entry (and its running goroutine/managed pods) orphaned in the map, never stopped or migrated.

### Finding Description
`Provider.managers` is declared as `map[string]*autoscalingManager // keyed by runner token`. [1](#0-0) 

`ensureManager` looks the manager up (and creates a new one) using `token := config.GetToken()`: [2](#0-1) 

`GetManager` performs the same token-keyed lookup: [3](#0-2) 

Runner tokens are rotated automatically and in place by the runner process, exactly like the "manager address changes" scenario in the analog report: `resetOneRunnerToken` mutates `runnerCfg.Token` via `common.ResetToken` and persists the new config. [4](#0-3) 

This is precisely the scenario the sibling `executors/internal/autoscaler/provider.go` was fixed for (issue #39380): it deliberately stopped keying its scaler map by token and instead uses a stable `URL|ID` key so that a rotated token continues to resolve to the *same* scaler/manager instance, explicitly to avoid re-discovering "pre-existing" resources and pruning them mid-job: [5](#0-4) 

The regression test for that fix explicitly documents the failure mode being guarded against: [6](#0-5) 

The Kubernetes autoscaler `Provider`, however, still uses the vulnerable token-only key (`executors/kubernetes/autoscaler/provider.go:24,121,227`) and has no `runnerScalerKey`-style ID fallback and no equivalent regression test. This is the direct structural analog of `OmoAgent.setPositionManager`: the "key"/"manager reference" (token) can change out from under previously-created state (pause pod manager + its pods), and the old state becomes orphaned/inaccessible via the current lookup path.

### Impact Explanation
When a runner's token rotates:
- The old `autoscalingManager` entry (with its running `manager.Start(ctx)` goroutine) is never stopped via the normal path — `Shutdown` only stops managers that are still present under `p.managers`, but a *new* manager is created under the new token key rather than replacing the old one, so both goroutines can coexist indefinitely.
- `GetManager(config)` calls made with the post-rotation config resolve to the *new* manager, losing continuity of `ActiveJobs` accounting that had accumulated on the old manager for jobs still in flight.
- The old manager's pause pods become effectively "orphaned" from the perspective of the current config-derived manager, relying only on the best-effort `CleanupOrphanedDeployments` call that runs when the *new* manager is created — this is opportunistic cleanup, not a synchronous/guaranteed reconciliation of the specific old-token entry.
This causes resource leakage (duplicate managers/goroutines, potentially duplicate pause pods incurring cost) and desynchronized job accounting, i.e., a persistent-DoS/resource-leak class impact, analogous to "loss of deposited positions" in the original report (loss of tracking/access to previously created state after a key identity change).

### Likelihood Explanation
Token rotation is a normal, automatic, non-privileged operational event in GitLab Runner (`resetOneRunnerToken` runs continuously in the background per `commands/multi.go` `resetRunnerTokens`), not an attacker-chosen or admin-misconfiguration action, so it triggers routinely for any runner using the Kubernetes autoscaler executor with `ManagedExecutorProvider` semantics. This makes the likelihood high for any long-lived Kubernetes-autoscaler-enabled runner, not a theoretical edge case.

### Recommendation
Key `Provider.managers` (and the corresponding lookups in `ensureManager`/`GetManager`) by a stable runner identity that survives token rotation, mirroring the fix already applied in `executors/internal/autoscaler/provider.go`'s `runnerScalerKey` (e.g., `URL|ID` with a token fallback for legacy configs with `ID == 0`). Add a regression test analogous to `TestProviderTokenRotationDoesNotPruneInstance` / `TestInitReusesScalerOnTokenRotation` that rotates `config.Token` in place and asserts the same `*autoscalingManager` (and its pods) are reused rather than orphaned.

### Proof of Concept
1. Start a runner configured with the Kubernetes executor and `Autoscaler` policy enabled; `Provider.Acquire` creates a `PausePodManager` keyed by `config.GetToken()` (`ensureManager`, `executors/kubernetes/autoscaler/provider.go:108-149`).
2. Let `commands/multi.go`'s `resetOneRunnerToken` rotate the runner's token in place, as it does automatically before `TokenExpiresAt` (`commands/multi.go:351-406`).
3. On the next job, `Provider.Acquire`/`ensureManager` runs again with the new token; since `p.managers[newToken]` does not exist, a new `PausePodManager` and Kubernetes client are created and started, while `p.managers[oldToken]` (with its running goroutine and pods) remains in the map, untouched, unless `Shutdown` (full process shutdown) is invoked.
4. Verify via `TestProvider_ConfigReload_ReplacesManager`-style instrumentation that both the old- and new-token-keyed `autoscalingManager` entries coexist in `p.managers`, confirming the leak/orphaning (contrast with `executors/internal/autoscaler/provider_test.go`'s `TestInitReusesScalerOnTokenRotation`, which proves the sibling provider does *not* exhibit this behavior). func (p *Provider) ensureManager(config *common.RunnerConfig) error {
	if config.Kubernetes == nil || config.Kubernetes.Autoscaler == nil {
		return nil
	}

	if len(config.Kubernetes.Autoscaler.Policy) == 0 {
		return nil
	}

	p.mu.Lock()
	defer p.mu.Unlock()

	token := config.GetToken()
	rm, exists := p.managers[token]

	// Check if config changed
	configKey := configLoadedKey(config)
	if exists && rm.configLoadedAt == configKey {
		return nil
	}

	// Stop existing manager if config changed
	if exists {
		rm.manager.Stop(context.Background())
		rm.cancel()
		delete(p.managers, token)
	}

	// Create new manager
	manager, cancel, err := p.createManager(config)
	if err != nil {
		return err
	}

	p.managers[token] = &autoscalingManager{
		manager:        manager,
		cancel:         cancel,
		configLoadedAt: configKey,
	}

	return nil
}

// GetManager returns the pause pod manager for a runner, if one exists.
// This is used by the executor to update active job counts.
func (p *Provider) GetManager(config *common.RunnerConfig) *PausePodManager {
	p.mu.Lock()
	defer p.mu.Unlock()

	rm, exists := p.managers[config.GetToken()]
	if !exists {
		return nil
	}
	return rm.manager
}

// runnerScalerKey returns a stable key for the scalers map. The runner ID
// survives token rotation, so keying by URL+ID keeps a rotated token pointing at
// the existing scaler instead of spinning up a second one that prunes the
// still-running instances.
func runnerScalerKey(config *common.RunnerConfig) string {
	if config.ID == 0 {
		// Legacy/pre-v15.3.0 configs have no ID; URL+0 would collide distinct
		// runners onto one scaler, so fallback to the token.
		return config.GetToken()
	}

	return fmt.Sprintf("%s|%d", config.URL, config.ID)
}

func TestProvider_ConfigReload_ReplacesManager(t *testing.T) {
	mockProvider := common.NewMockExecutorProvider(t)
	mockProvider.EXPECT().Acquire(mock.Anything).Return(nil, nil)

	provider := NewProvider(mockProvider)

	provider.newKubeClient = func(*restclient.Config) (kubernetes.Interface, error) {
		return fake.NewClientset(), nil
	}
	provider.getKubeConfig = func(*common.KubernetesConfig) (*restclient.Config, error) {
		return &restclient.Config{}, nil
	}

	configTime1 := time.Now()
	config := &common.RunnerConfig{
		RunnerCredentials: common.RunnerCredentials{
			Token: "test-token",
		},
		RunnerSettings: common.RunnerSettings{
			Kubernetes: &common.KubernetesConfig{
				Namespace: "default",
				Autoscaler: &common.KubernetesAutoscalerConfig{
					Policy: []common.AutoscalerPolicyConfig{
						{
							IdleCount: 2,
							Periods:   []string{"* * * * *"},
						},
					},
				},
			},
		},
		ConfigLoadedAt: configTime1,
	}

	// First acquire creates a manager
	_, err := provider.Acquire(config)
	require.NoError(t, err)

	manager1 := provider.GetManager(config)
	require.NotNil(t, manager1)

	// Same config timestamp - should reuse same manager
	_, err = provider.Acquire(config)
	require.NoError(t, err)

	manager1Again := provider.GetManager(config)
	assert.Same(t, manager1, manager1Again, "same config should reuse manager")

	// Simulate config reload with new timestamp
	config2 := &common.RunnerConfig{
		RunnerCredentials: common.RunnerCredentials{
			Token: "test-token",
		},
		RunnerSettings: common.RunnerSettings{
			Kubernetes: &common.KubernetesConfig{
				Namespace: "default",
				Autoscaler: &common.KubernetesAutoscalerConfig{
					Policy: []common.AutoscalerPolicyConfig{
						{
							IdleCount: 5,
							Periods:   []string{"* * * * *"},
						},
					},
				},
			},
		},
		ConfigLoadedAt: configTime1.Add(1 * time.Second),
	}

	_, err = provider.Acquire(config2)
	require.NoError(t, err)

	manager2 := provider.GetManager(config2)
	require.NotNil(t, manager2)
	assert.NotSame(t, manager1, manager2, "config reload should create new manager")
}
