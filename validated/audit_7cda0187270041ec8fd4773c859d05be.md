### Title
Unauthenticated disclosure of internal LOOP plugin Prometheus metrics via `/plugins/:name/metrics` - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `GET /plugins/:name/metrics`, `GET /discovery`, and the plugin pprof routes directly on the base `api` router group without any `auth.Authenticate` middleware, unlike every other sensitive endpoint in the router. Any unauthenticated network client that can reach the node's HTTP API can retrieve raw Prometheus metrics text proxied from an internal LOOP plugin's metrics port.

### Finding Description
`NewRouter` builds an `api` group with only rate limiting and session middleware attached (no auth), then calls `debugRoutes`, `healthRoutes`, `sessionRoutes`, `v2Routes`, and `loopRoutes` on it. [4](#0-3)  Every other handler group that exposes sensitive data explicitly wraps itself with `auth.Authenticate(...)` (e.g. `debugRoutes` at line 181, `sessionRoutes` at line 216, `authv2` at lines 245-248). `loopRoutes`, however, registers its routes directly on `r` (the unauthenticated `api` group) with no auth middleware at all: [2](#0-1) 

The handler `pluginMetricHandler` looks up the plugin by name from `LoopRegistry`, then makes an outbound HTTP GET to the plugin's internal Prometheus endpoint (`http://<loopHostName>:<PrometheusPort>/metrics`) and streams the response body back to the caller as-is: [3](#0-2) . There is no role check (`auth.RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole`) and no `auth.Authenticate` gate anywhere in this path, so a plain unauthenticated GET request reaches the handler and its response is returned with a 200 status.

### Impact Explanation
This allows unauthenticated disclosure of internal metrics/labels from LOOP plugins (e.g., relayer/plugin internal counters, potentially job/chain-identifying labels) to any network client that can reach the node's HTTP port, matching Chainlink's "information disclosure of internal node metrics/monitoring data" bounty impact class. It does not directly expose secrets/keys but does leak internal operational telemetry that should be gated behind authentication, consistent with the rest of the router's design intent (all comparable debug/metrics endpoints such as `/debug/vars` and `authv2`'s `metricRoutes` are auth-gated).

### Likelihood Explanation
No credentials or special role are required — an unauthenticated GET is sufficient. The only precondition is that a plugin be registered in the `LoopRegistry` and that the caller can reach the node's HTTP listener (which is the same reachability needed for any other unauthenticated route already in the router, e.g. `/health`), making this trivially and repeatably exploitable.

### Recommendation
Wrap `loopRoutes` registrations with the same `auth.Authenticate` middleware used elsewhere (e.g. `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), and consider requiring at minimum a view/run role, consistent with how `metricRoutes(authv2)` and `debugRoutes` are gated.

### Proof of Concept
Go handler-level integration test plan:
1. Build a `chainlink.Application` mock/test app with a `LoopRegistry` containing one registered plugin (`plugins.RegisteredLoop{Name: "test-plugin", EnvCfg: {PrometheusPort: <port of a local httptest server serving fake metrics text>}}`).
2. Call `web.NewRouter(app, nil)` to construct the full `gin.Engine` exactly as production does (do not manually inject the loop registry route in isolation, to prove the true unauthenticated router path).
3. Issue `httptest.NewRequest("GET", "/plugins/test-plugin/metrics", nil)` with **no** `Authorization` header, **no** session cookie.
4. Serve via `engine.ServeHTTP(w, req)` and assert `w.Code == http.StatusOK` and `w.Body.String()` contains the fake metrics text served by the internal stub, proving the response is returned without any authentication check.
5. As a control, repeat the same request against `/v2/jobs` (an `authv2` route) and assert it returns `401 Unauthorized`, confirming the router's normal behavior and highlighting that `loopRoutes` is the outlier lacking auth.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
