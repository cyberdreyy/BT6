### Title
Unbounded per-request linear scan and unconditional debug-string allocation over the on-chain allowlist causes CPU/latency DoS in Vault Gateway request authorization - (File: core/capabilities/vault/allow_list_based_auth.go)

### Summary
Every Vault Gateway JSON-RPC request that does not carry `req.Auth` (JWT) is authorized via `allowListBasedAuth.AuthorizeRequest`, which retries up to 11 times, and on every attempt copies the *entire* in-memory allowlist, unconditionally builds a formatted debug string for *every* entry in it, and then linearly scans it looking for a match. The allowlist is populated by unprivileged workflow owners calling `AllowlistRequest` on the on-chain `WorkflowRegistry` contract and is only pruned when entries *expire* — it is never bounded in size. This mirrors the reported bug class ("for loop over `_approvedBorrowers` in `_pendingInterests`, used in nearly every important function, causing DoS as the array grows") but here the unbounded array is the Vault node's allowlisted-requests cache and the hot path is the authorization step invoked on every incoming Vault Gateway request.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` calls `findAllowlistedItemWithRetry`: [1](#0-0) 

For each of up to `allowListBasedAuthRetryCount + 1` (11) attempts, it:
1. Calls `r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)`, which copies the full in-memory slice under a read lock: [2](#0-1) 
2. **Unconditionally** (regardless of whether debug logging is enabled) builds a formatted string for every single entry via `fmt.Sprintf` inside a loop, purely to pass to `Debugw`: [3](#0-2) 
3. Performs an O(n) linear scan via `fetchAllowlistedItem` looking for a digest match: [4](#0-3) 
4. If no match is found and it isn't the last attempt, sleeps `allowListBasedAuthRetryInterval` (3s) and retries: [5](#0-4) 

The allowlist (`w.allowListedRequests`) that backs `GetAllowlistedRequests` grows from on-chain `AllowlistRequest` calls made by workflow owners (an unprivileged, external-facing role relative to the Vault node) and is periodically refreshed and pruned **only by expiry timestamp**, not by any cap on total size: [6](#0-5) . There is no maximum-length enforcement anywhere in this path (the only length limit found, `MaxResultsPerQuery = 1_000`, only bounds the page size of a single contract read call, not the total accumulated in-memory list): [7](#0-6) 

Because any request digest that doesn't match anything in the allowlist (e.g., a request sent by an unlinked/unauthorized workflow, or simply garbage) triggers the *full* 11-iteration retry loop before failing with "request not allowlisted" — each iteration paying the O(n) copy + O(n) unconditional string-formatting + O(n) scan cost — a single unauthorized request's processing cost scales linearly with the number of currently-active allowlist entries, multiplied by 11, and additionally blocks the handling goroutine for up to ~30 seconds of sleep time.

### Impact Explanation
As the allowlist grows (which any workflow owner can contribute to simply by calling `AllowlistRequest` on-chain, at their own gas cost, with no per-owner or global cap enforced in the node), the per-request authorization cost for the entire Vault Gateway path grows unbounded. Since `AuthorizeRequest` sits directly in the request-handling flow invoked from `GatewayHandler.HandleGatewayMessage` for essentially all Vault operations (`create/update/delete/list secrets`, `get public key`) that don't use JWT auth, an attacker capable of sending unauthorized (non-matching-digest) requests to the gateway can force repeated worst-case (11×O(n)) CPU and allocation cost per request. At scale (many concurrent unauthorized requests, or as the legitimate allowlist naturally grows large over time), this can degrade or exhaust node resources handling all Vault traffic — an availability impact on the Vault DON's node-side request processing, analogous to the reported unbounded-loop DoS class.

### Likelihood Explanation
Medium. Triggering the expensive path only requires sending a syntactically valid Vault Gateway JSON-RPC request without `req.Auth` and with a digest that is not currently allowlisted — no privileged access or successful authentication is required to *invoke* the costly loop; the cost is paid before the "not allowlisted" rejection is returned. Growing the underlying allowlist further requires on-chain `AllowlistRequest` calls (gas-bounded, but the node enforces no in-memory cap regardless of how the list was populated), so the severity compounds as usage of the CRE Vault system increases over time. This is consistent with the report's classification of "Medium" severity for the analogous unbounded-array class.

### Recommendation
- Enforce a maximum size on the in-memory `allowListedRequests` collection (reject/evict oldest or reject new on-chain entries beyond a cap, as recommended in the original report for `_approvedBorrowers`).
- Replace the linear scan with an O(1) lookup structure (e.g., a `map[digest]entry`) built once per sync interval instead of scanning a slice on every authorization attempt.
- Gate the `allowedRequestsStrs` debug-string construction behind an actual debug-log-level check so it is not unconditionally computed on every request/attempt.
- Consider bounding/removing the 11-attempt retry-with-sleep loop for requests that are clearly not going to become allowlisted soon, or apply rate limiting ahead of the allowlist-auth path for unauthenticated requests.

### Proof of Concept
1. Populate the Vault node's synced allowlist with a large number of active (non-expired) entries — achievable simply through normal/heavy use of the CRE Vault allowlist feature (each entry costs the workflow owner one `AllowlistRequest` on-chain call, no cap enforced by the node): [8](#0-7) 
2. Send a Vault Gateway JSON-RPC request (any of `secrets/create`, `secrets/update`, `secrets/delete`, `secrets/list`, `public_key/get`) without `Auth` set, and with a payload whose digest does not match any allowlisted entry.
3. Observe that `allowListBasedAuth.AuthorizeRequest` → `findAllowlistedItemWithRetry` performs 11 iterations of: full-list copy, full-list debug-string formatting, and full-list linear scan (each O(n) where n = allowlist size), separated by 3-second sleeps, before finally returning "request not allowlisted": [1](#0-0) 
4. Repeating such requests concurrently multiplies this O(n) cost across many goroutines, consuming CPU/memory proportional to allowlist size × request rate × 11.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, digest [32]byte) *workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	for _, item := range allowListedRequests {
		if item.RequestDigest == digest {
			return &item
		}
	}
	return nil
}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}
	}
}

func (w *workflowRegistry) GetAllowlistedRequests(_ context.Context) []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	w.allowListedMu.RLock()
	defer w.allowListedMu.RUnlock()
	allowListedRequests := make([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, len(w.allowListedRequests))
	copy(allowListedRequests, w.allowListedRequests)
	return allowListedRequests
}
