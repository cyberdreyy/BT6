### Title
Dust APR0 withdrawal request permanently bricks `stopEpoch` once APR is non-zero - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
Analogous to the AuraLocker dust-lock DoS on `withdrawToVault`, an unprivileged KYC'd tranche holder can leave a 1-wei-class `apr0TotalPrincipal` residue in `IdleCreditVault` by calling `IdleCDOEpochVariant.requestWithdraw` while `unscaledApr == 0`. If the (honest) manager/owner subsequently raises the APR above zero — the normal way to start an interest-bearing epoch — every `stopEpoch`/`stopEpochWithDuration` call reverts at the `unscaledApr != 0` guard in `prepareStopEpochWithApr0`, and there is no non-default path that clears `apr0TotalPrincipal`. The result is permanent freezing of all vault funds absent a borrower default.

### Finding Description
`IdleCDOEpochVariant.requestWithdraw` forwards to `IdleCreditVault.requestWithdraw`, which — when `unscaledApr == 0` and the pool is not closed — records the request in the APR0 bucket via `_requestWithdrawApr0`, incrementing the global `apr0TotalPrincipal` (IdleCreditVault.sol L285–L286, L567–L577). Any KYC-passing lender holding a dust amount of tranche tokens can do this during a buffer period; the receipt is minted to the user and there is no cancel path.

At epoch end, `IdleCDOEpochVariant.stopEpoch` calls `IdleCreditVault.prepareStopEpochWithApr0` (IdleCDOEpochVariant.sol L362). That function fast-paths only when `apr0TotalPrincipal == 0`; otherwise it requires `unscaledApr == 0` and reverts otherwise:

```solidity
uint256 _principal = apr0TotalPrincipal;
if (_principal == 0) { return ...; }
if (unscaledApr != 0) {
  revert NotAllowed();   // L506-L508
}
```

`apr0TotalPrincipal` is reset only (a) inside `prepareStopEpochWithApr0` itself (L540 — unreachable while reverting), or (b) inside `_clearWithdrawClaimForEpoch` during post-default claims (L822–L828), which requires the borrower to actually default and `finalizeDefault` to run. `setApr`/`setAprs`/`setAprsWithBuffer` are freely callable by manager or the CDO (L206–L235) and `stopEpochWithDuration` passes through the same `prepareStopEpochWithApr0`, so lowering APR back to 0 at stop time does not help: the check reads live `unscaledApr`, and even setting it back to 0 only restores the pre-change state — the freeze persists for any epoch run at APR > 0.

This mirrors the reported bug's structure exactly: a dust-sized, unprivileged state write (`LOCKER.lock(strategy, 1)` ↔ `requestWithdraw` dust) trips a permanent invariant check in the privileged settlement path (`_withdrawAll`'s `LOCKER.balanceOf == 0` ↔ `stopEpoch`'s APR0 guard), with no permissionless recovery.

### Impact Explanation
Permanent freezing of all user funds in the CDO/strategy for any deployment that ever operates at `unscaledApr == 0` and later raises APR — a routine configuration change (e.g., APR0 promotional epochs, or APR reductions to 0 then restoration). Once triggered, `stopEpoch`, `stopEpochWithDuration`, and pool closing (`_interest == 1`) all revert, so borrower repayments can never be settled into the strategy, `epochNumber` never increments, and no withdraw request can ever become claimable (`_claimFundedWithdrawRequest` requires `epochNumber > lastWithdrawRequest`). The only escape is the borrower defaulting plus `finalizeDefault`, i.e., socializing the freeze into a loss event. Cost to the attacker is a dust tranche position (sub-1-USDC for 6-decimal underlyings).

### Likelihood Explanation
Requires two conditions: (1) the vault operates at `unscaledApr == 0` for at least one buffer window with withdraw requests enabled (`allowAAWithdrawRequest`/`allowBBWithdrawRequest`), and (2) APR is later set non-zero, by the manager or by the CDO itself at `stopEpoch`/`startEpoch` via `setAprs`/`setAprsWithBuffer`. Both are ordinary, honest operations — no malicious privileged action needed. The attacker only needs KYC clearance and dust tranche tokens, and can leave the poison request indefinitely since it can only be claimed one epoch after a successful `stopEpoch`, which is exactly what it bricks. No existing guard prevents it: `_skimDonatedAssets` only handles raw underlying donations, the request path is legitimate, and `pendingWithdraws`/receipt accounting treats the dust request as valid.

### Recommendation
Make the APR0 bucket survivable across APR changes. Options:
- In `prepareStopEpochWithApr0`, when `unscaledApr != 0` treat the residual `apr0TotalPrincipal` as a normal pending receipt: settle it with zero APR0 interest (or at the current `lastApr`) instead of reverting, then clear `apr0TotalPrincipal`.
- Alternatively, let `setAprs`/`setApr` revert (or force-settle) when `apr0TotalPrincipal != 0` and the new APR is non-zero, so operators must resolve outstanding APR0 requests before changing rate regime.
- Or add a manager function to refund/cancel open APR0 requests before an APR transition.

### Proof of Concept
Foundry fork sketch against `test/foundry/IdleCreditVault.t.sol` harness:

```solidity
function test_Apr0DustBlocksStopEpoch() external {
    // Config: owner sets unscaledApr = 0 while pool is in buffer
    vm.prank(manager); // honest manager
    IdleCreditVault(address(strategy)).setAprs(0, 0);

    // Attacker: KYC'd lender with dust tranche position
    address attacker = vm.addr(0xA77);
    _whitelist(attacker);
    deal(defaultUnderlying, attacker, 1e6);
    vm.startPrank(attacker);
    underlying.approve(address(idleCDO), type(uint256).max);
    idleCDO.depositAA(1e6);                     // dust position
    uint256 req = cdoEpoch.requestWithdraw(0, cdoEpoch.AATranche()); // APR0 request
    vm.stopPrank();
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    // Honest manager raises APR and runs a normal epoch
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprsWithBuffer(5e18, epochDur, bufferDur);
    _startEpochAndCheckPrices(0);

    // Warp past epoch end; borrower funded
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);

    // stopEpoch permanently reverts: apr0TotalPrincipal != 0 && unscaledApr != 0
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);

    // Every subsequent attempt reverts; funds frozen (no non-default clearing path)
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 1);
}
```
