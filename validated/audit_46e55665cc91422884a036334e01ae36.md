This clarifies the picture decisively: `approved_time` is a **new field introduced in schema V19** alongside `mark_pre_committed` — it did not exist under any name in schema V18. `BlockInfo::mark_pre_committed` (`stacks-signer/src/signerdb.rs:272-277`) stamps `approved_time` and `mark_locally_accepted`/`mark_globally_accepted` also fill it in as a fallback, but under V18 the persisted `blocks` table only had `signed_over`, `signed_self`, `signed_group`, etc. — there was no legacy pre-commit-timestamp column anywhere (the `block_pre_commits` table added in `SCHEMA_17` via `CREATE_BLOCK_PRE_COMMITS_TABLE`, `stacks-signer/src/signerdb.rs:740-750`, only records `(signer_signature_hash, signer_addr)` pairs with **no timestamp column at all**). [1](#0-0) [2](#0-1) 

So the premise "a block that was only ever pre-committed (never signed) under V18 has a differently-named legacy column mapped incorrectly during backfill" has no basis: no such column exists to be mis-mapped. Under V18, a pre-commit-only block simply has `signed_self = NULL`, and `MIGRATE_BLOCKS_DROP_SIGNED_OVER_ADD_APPROVED_TIME` (`stacks-signer/src/signerdb.rs:884-943`) backfills `approved_time` as `SELECT ... signed_self ... FROM blocks`, which correctly yields `NULL` for that block. This is exactly what `test_all_schema_migrations` verifies: `hash_unsigned` (signed_self = None) → `approved_time` is `None` after V19 migration. [3](#0-2) 

The claimed equality break — "the freshness/activity view a signer holds after migration == the actual pre-commit timestamp recorded before migration, not a backfilled proxy value" — never diverges, because pre-V19 there was no persisted pre-commit timestamp to lose in the first place. The migration cannot fabricate a timestamp for a never-signed block; it only ever copies `signed_self`, which is `NULL` for such blocks.

Additionally, even hypothetically, `check_latest_block_in_tenure`'s CARVE branch (`stacks-signer/src/chainstate/mod.rs:422-448`) only treats a pre-commit as "fresh" while `approved_time.saturating_add(tenure_last_block_proposal_timeout) > now`; it explicitly cannot "block a legitimate carve-out indefinitely" since it is bounded by `tenure_last_block_proposal_timeout` and, per the `is_fresh_pre_commit` check, it only suppresses the *height-check bypass counting as activity*, never actually vetoes (`is_fresh_pre_commit && ... <= ...` only triggers `update_last_activity_time`, and the function still proceeds to consult the node's tenure tip afterward, per lines 450-477). This is confirmed by the `pre_committed_block_does_not_veto_replacement` test. [4](#0-3) [5](#0-4)

#[test]
fn pre_committed_block_does_not_veto_replacement() {
    let (stacks_client, mut signer_db, _block_sk, mut block, cur_sortition, _, _) =
        setup_test_environment(function_name!());

    let tenure_id = cur_sortition.data.consensus_hash.clone();
    block.header.consensus_hash = tenure_id.clone();

    // The originally-proposed block, which we pre-committed to but never signed.
    let existing_block_proposal = BlockProposal {
        block: block.clone(),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_pre_committed().unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // The pre-committed block must not be reported as the tenure's last (signed) block.
    assert!(SortitionData::get_tenure_last_block_info(
        &tenure_id,
        &signer_db,
        Duration::from_secs(30),
    )
    .unwrap()
    .is_none());

    // A replacement block at the same height.
    let mut replacement = block.clone();
    replacement.header.timestamp += 1;
    assert_ne!(
        replacement.header.signer_signature_hash(),
        block.header.signer_signature_hash()
    );

    assert!(signer_db
        .get_last_activity_time(&tenure_id)
        .unwrap()
        .is_none());

    // The replacement passes the height check. (The stacks-node call inside fails since nothing
    // is listening, which makes the check fall back to assuming the proposal is higher; the
    // point here is that the pre-committed block does not early-reject it.)
    assert!(SortitionData::check_latest_block_in_tenure(
        &tenure_id,
        &replacement,
        &mut signer_db,
        &stacks_client,
        Duration::from_secs(30),
        Duration::from_secs(3),
    )
    .unwrap());

    // But conflicting with a fresh pre-commit still counts as miner activity.
    assert!(signer_db
        .get_last_activity_time(&tenure_id)
        .unwrap()
        .is_some());

    // Once we actually sign the original block, it becomes the tenure's tip and the replacement
    // at the same height must be rejected.
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    assert!(SortitionData::get_tenure_last_block_info(
        &tenure_id,
        &signer_db,
        Duration::from_secs(30),
    )
    .unwrap()
    .is_some());

    assert!(!SortitionData::check_latest_block_in_tenure(
        &tenure_id,
        &replacement,
        &mut signer_db,
        &stacks_client,
        Duration::from_secs(30),
        Duration::from_secs(3),
    )
    .unwrap());
