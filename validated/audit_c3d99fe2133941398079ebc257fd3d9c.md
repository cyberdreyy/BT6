### Title
Unbounded EIP-8130 `calls`/`account_changes` allocation in `eth_call`/`eth_estimateGas` bypasses the mempool's CWE-770 phase-count bound - ([File: crates/common/rpc-types/src/eip8130.rs])

### Summary
`BaseTransactionRequest::to_eip8130_simulation_tx`, the function that turns a JSON-RPC `eth_call`/`eth_estimateGas` request into a simulated EIP-8130 transaction, clones the caller-supplied `account_changes: Vec<AccountChange>` and `calls: Vec<Vec<Call>>` fields directly into a `TxEip8130` with no length or size bound. [1](#0-0) 

### Finding Description
The codebase already treats "unbounded allocation from an attacker-controlled count/length before validation runs" as CWE-770 and has hardened multiple paths against it: the RLP transaction decoder caps call phases at `Eip8130Constants::MAX_CALL_PHASES_PER_TX` (1,024) specifically to stop "a sequence of single-byte empty RLP lists from amplifying into unbounded allocations before transaction-pool admission limits run" [2](#0-1) 
and the RLP decoder enforces that bound while decoding [3](#0-2) .

The JSON-RPC `eth_call`/`eth_estimateGas` path for the same transaction type does not reuse this guard. `Eip8130RequestFields` deserializes `account_changes: Option<Vec<AccountChange>>` and `calls: Option<Vec<Vec<Call>>>` from the JSON body with no `#[serde]` length limit or custom bounded visitor (contrast with `SendRawTransactionValidityOptions.validity`, which explicitly uses `deserialize_with = "deserialize_bounded_predicates"` to abort decoding once a batch exceeds a cap, precisely to prevent this DoS shape) [4](#0-3) [5](#0-4) .

`to_eip8130_simulation_tx` then unconditionally clones these unbounded vectors into the transaction it will execute:
```rust
account_changes: aa.account_changes.clone().unwrap_or_default(),
calls: aa.calls.clone().unwrap_or_default(),
``` [1](#0-0) 

The function only bounds the `sender_auth`/`payer_auth` blob lengths via `check_auth_len` (capped at `MAX_AUTH_SIZE = 8_192`) [6](#0-5) [7](#0-6) 
— it never checks the length of `calls` (outer or inner `Vec`) or `account_changes`, nor the size of each `Call.data` payload. Every RPC entry point that serves `eth_call`/`eth_estimateGas` (the standalone EIP-8130 override and the flashblocks override) routes into this same unguarded conversion before any gas metering or execution begins: [8](#0-7) [9](#0-8) 

Because these RPC methods are public, unauthenticated `eth_*` endpoints reachable by any anonymous RPC client, a single JSON body containing a `calls` array with an extremely large number of empty phases (or `account_changes` entries) forces the node to materialize a correspondingly large `Vec<Vec<Call>>`/`Vec<AccountChange>` in memory before `to_eip8130_simulation_tx` returns — the exact allocation-amplification shape the mempool/RLP path and the `decode_allocation_bound.rs` regression test were built to prevent, just via the JSON-RPC ingress instead of the RLP/gossip ingress.

### Impact Explanation
An unauthenticated RPC client can send a single crafted `eth_call`/`eth_estimateGas` request with a very large `calls`/`account_changes` array and force excessive heap allocation per request, without spending any gas or paying any fee (this path never enters the EVM's per-tx gas metering before the vectors are materialized). Repeated requests can exhaust node memory, causing a denial of service on the affected node's public JSON-RPC service — matching the "Excessive Allocation (CAPEC-130)" / CWE-770 pattern in the reported advisory, but reachable at "PR:N" (no privilege) rather than requiring snapshot-restore privileges as in the Elasticsearch report.

### Likelihood Explanation
High: `eth_call` and `eth_estimateGas` are core, publicly exposed, unauthenticated JSON-RPC methods with no special permission requirement. Constructing an oversized JSON array of empty/near-empty `Call`/`AccountChange` objects requires no on-chain state, no signature, and no fee, only body-size headroom on the RPC server's max-request-body configuration (which is generic and much larger than the mempool's per-phase bound).

### Recommendation
Enforce the same phase/entry bound used by the RLP/mempool path (`Eip8130Constants::MAX_CALL_PHASES_PER_TX`) — and an analogous cap for `account_changes` — inside `Eip8130RequestFields` deserialization (e.g., a bounded `Vec` visitor mirroring `deserialize_bounded_predicates`) or at the start of `to_eip8130_simulation_tx`, before cloning `aa.account_changes`/`aa.calls`, so an oversized JSON request is rejected with `INVALID_PARAMS` prior to allocation.

### Proof of Concept
Send an unauthenticated JSON-RPC request such as:
```json
{
  "jsonrpc": "2.0",
  "method": "eth_estimateGas",
  "params": [
    {
      "from": "0x00000000000000000000000000000000000001",
      "calls": [[], [], [], ... /* millions of empty phase arrays */]
    },
    "latest"
  ],
  "id": 1
}
```
`to_eip8130_simulation_tx` clones the entire `calls: Vec<Vec<Call>>` into the constructed `TxEip8130` with no bound check (unlike the RLP decode path, which caps this at 1,024 phases), causing the node to allocate memory proportional to the attacker-declared array length before any execution or gas accounting occurs.     pub fn to_eip8130_simulation_tx(
        &self,
        chain_id: u64,
        gas_limit_cap: u64,
    ) -> Option<BaseRevm<TxEnv>> {
        let aa = self.as_eip8130()?;
        let req = self.as_ref();

        let account = match (aa.sender, req.from) {
            (Some(sender), Some(from)) if sender != from => return None,
            (Some(sender), _) => sender,
            (None, Some(from)) => from,
            (None, None) => return None,
        };
        let sender_declared = aa.sender.is_some();

        let (sender, sender_auth) = match &aa.sender_auth {
            Some(blob) => {
                let prefixed = Self::is_prefixed_auth(blob);
                Self::check_auth_len(blob, prefixed)?;
                (prefixed.then_some(account), blob.clone())
            }
            None if sender_declared => (
                Some(account),
                Self::stub_prefixed_auth(
                    Eip8130AuthScheme::Secp256k1,
                    Eip8130AuthScheme::Secp256k1.default_data_len(),
                ),
            ),
            None => (None, Self::default_bare_auth()),
        };

        let (payer, payer_auth) = match aa.payer {
            None => (None, Bytes::new()),
            Some(payer) => {
                let blob = match &aa.payer_auth {
                    Some(blob) => {
                        if !Self::is_prefixed_auth(blob) {
                            return None;
                        }
                        Self::check_auth_len(blob, true)?;
                        blob.clone()
                    }
                    None => Self::stub_prefixed_auth(
                        Eip8130AuthScheme::Secp256k1,
                        Eip8130AuthScheme::Secp256k1.default_data_len(),
                    ),
                };
                (Some(payer), blob)
            }
        };

        let tx = TxEip8130 {
            chain_id,
            sender,
            nonce_key: aa.nonce_key.unwrap_or(U256::ZERO),
            nonce_sequence: 0,
            valid_after: aa.valid_after.unwrap_or_default(),
            valid_before: aa.valid_before.unwrap_or_default(),
            max_priority_fee_per_gas: req.max_priority_fee_per_gas.unwrap_or_default(),
            max_fee_per_gas: req.max_fee_per_gas.unwrap_or_default(),
            gas_limit: req.gas.unwrap_or(gas_limit_cap),
            account_changes: aa.account_changes.clone().unwrap_or_default(),
            calls: aa.calls.clone().unwrap_or_default(),
            metadata: aa.metadata.clone().unwrap_or_default(),
            payer,
        };

    async fn estimate_gas(
        &self,
        transaction: BaseTransactionRequest,
        block_number: Option<BlockId>,
        overrides: Option<StateOverride>,
    ) -> RpcResult<U256> {
        debug!(
            message = "rpc::estimate_gas",
            transaction = ?transaction,
            block_number = ?block_number,
            overrides = ?overrides,
        );

        let mut block_id = block_number.unwrap_or_default();
        let mut pending_overrides = EvmOverrides::default();
        // If the call is to pending block use cached override (if it exists)
        if block_id.is_pending() {
            Metrics::rpc_estimate_gas().increment(1);
            let pending_blocks = self.flashblocks_state.get_pending_blocks();
            block_id = pending_blocks.get_canonical_block_number().into();
            pending_overrides.state = pending_blocks.get_state_overrides();
        }

        let mut state_overrides_builder =
            StateOverridesBuilder::new(pending_overrides.state.unwrap_or_default());
        state_overrides_builder = state_overrides_builder.extend(overrides.unwrap_or_default());
        let final_overrides = state_overrides_builder.build();

        // EIP-8130 request: estimate via a single read-only simulation against
        // the (pending-merged) block state, gated on the Zenith fork. The
        // deterministic, signature-independent EIP-8130 gas charge means no
        // gas-limit binary search is needed.
        if transaction.as_eip8130().is_some() {
            Eip8130ZenithGate::check(&self.eth_api, block_id)?;
            return Eip8130GasEstimator::estimate(
                &self.eth_api,
                transaction,
                block_id,
                EvmOverrides::new(Some(final_overrides), pending_overrides.block),
            )
            .await;
        }
