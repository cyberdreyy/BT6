### Title
APR0 withdraw receipts permanently block `stopEpoch` once APR is raised — unprivileged lender can freeze the epoch - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
Analogous to CVE-2023-26923 — a "misconfigured input" (an APR0-tagged withdraw receipt) is later processed by `prepareStopEpochWithApr0`, which reverts instead of safely handling the state when the vault's APR is no longer zero. Any KYC-passing lender can plant this poisoned state by calling `requestWithdraw` during a zero-APR buffer period; the moment the honest borrower/manager configures a positive APR for the next epoch, `stopEpoch` becomes un-callable and the entire epoch state machine halts.

### Finding Description
- `requestWithdraw` routes into `_requestWithdrawApr0` whenever `unscaledApr == 0` and the pool is not closed, accumulating `apr0TotalPrincipal` and minting the user a strategy-token receipt (`IdleCreditVault.sol:285-286`, `:567-577`). Any allowed lender triggers this with a normal withdraw request — no privilege needed.
- At `stopEpoch`, the CDO calls `prepareStopEpochWithApr0`. If `apr0TotalPrincipal != 0` the function enforces `if (unscaledApr != 0) revert NotAllowed()` (`IdleCreditVault.sol:506-508`). The revert propagates and aborts the whole `stopEpoch`/`stopEpochWithDuration` transaction, including loss paths.
- `apr0TotalPrincipal` is only cleared inside `prepareStopEpochWithApr0` (`:540`) or in the default-claim path `_clearWithdrawClaimForEpoch` (`:822-827`). There is no user- or manager-facing escape: the requester's own `claimWithdrawRequest` reverts because `epochNumber <= lastWithdrawRequest[_user]` while the epoch is still running (`:326-328`), so the poisoned bucket cannot be drained before `stopEpoch`.
- Broken invariant: epoch state machine liveness. A single lender's ordinary request makes `stopEpoch` revert under a configuration (APR > 0) that the honest manager legitimately chooses, freezing all deposits, pending withdraws and the borrower's repayment.

### Impact Explanation
- All pool funds (active NAV + `pendingWithdraws`) are frozen for as long as `unscaledApr != 0`. The only recovery is for the manager to set APR back to 0, which concedes the attacker a zero-interest epoch; if the borrower is repaying or the pool should move to a positive rate, the epoch cannot settle. Loss amount: time-value of the entire TVL plus inability to realize a default through `stopEpochWithDuration` while APR is nonzero — a permanent freeze in any configuration where management refuses a 0-APR epoch.

### Likelihood Explanation
- Requires only that an epoch is configured with `unscaledApr == 0` (a supported first-class mode — see `testApr0WithdrawGetsInterestAtStopEpoch`), that an attacker deposits and requests withdraw during the buffer, and that the APR is later raised. All attacker steps are unprivileged. The guard at `:506` is unconditional once the bucket is non-empty, so the freeze is deterministic, not rounding-dependent.

### Recommendation
- When `unscaledApr != 0`, do not revert: either settle the APR0 bucket at zero rate (`apr0RateByEpoch[epochNumber] = 0`, zero `apr0TotalPrincipal`) and let receipts claim principal at par, or convert open APR0 requests to normal `withdrawsRequests` priced at the new APR. Alternatively, block `setAprs`/`setAprsWithBuffer` from raising the APR while `apr0TotalPrincipal != 0` so the inconsistency can never be entered.

### Proof of Concept
```solidity
// Foundry fork PoC (scaffold against test/foundry/IdleCreditVault.t.sol setup)
function testApr0PoisonBlocksStopEpoch() external {
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0); // epoch APR = 0

    // Attacker: KYC-passing lender deposits and requests withdraw during buffer
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);
    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);            // ends epoch 0, apr still 0
    _forceLastEpochAprToZero();
    cdoEpoch.requestWithdraw(IERC20(AAtranche).balanceOf(address(this)) / 2, address(AAtranche));

    // Honest manager starts epoch 1 and sets a positive APR (legit action)
    _startEpochAndCheckPrices(1);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(5e17, 5e17); // unscaledApr != 0

    // stopEpoch now always reverts -> epoch frozen
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, type(uint120).max);
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);
}
```
