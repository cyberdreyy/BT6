### Title
`GlobalStateEvaluator::reached_agreement` uses floor division instead of the ceiling rule used for block-approval, letting sub-70% weight be treated as global consensus - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The consensus-critical 70% supermajority threshold for Nakamoto block approval is computed with a strict ceiling in `NakamotoBlockHeader::compute_voting_weight_threshold` [1](#0-0) , which rounds any fractional 70% requirement *up*. The signer-side `GlobalStateEvaluator::reached_agreement` (and its sibling `reached_disagreement`), which every signer uses to decide the "global state" (active miner, burn view, active signer protocol version, tx replay set) that drives block validation, instead performs a plain floor division with no ceiling adjustment: [2](#0-1) .

### Finding Description
`compute_voting_weight_threshold` intentionally ceils: `(total_weight * 7 + remainder-adjust) / 10`, guaranteeing that the minimum accepted signing weight is always `>= 70%` of `total_weight`, even when `total_weight * 7` is not a multiple of 10 [3](#0-2) .

`GlobalStateEvaluator::reached_agreement`, used purely on the signer side to decide when a quorum of signers agree on state (which miner is active, current burn view, protocol version, replay set), computes `total_weight * 7 / 10` with no ceiling: `u64::from(vote_weight) >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10` [4](#0-3) . This is a floor, not a ceiling: e.g. for `total_weight = 13`, the strict/ceiling threshold is `ceil(13*7/10) = ceil(9.1) = 10`, but `reached_agreement` accepts any `vote_weight >= 9` (`13*7/10 = 9` via integer floor). `9/13 ≈ 69.2%`, which is below the 70% supermajority that the rest of the system (block-header signature verification, pre-commit/rejection tallies in `stacks-signer/src/v0/signer.rs`) enforces via `NakamotoBlockHeader::compute_voting_weight_threshold` [5](#0-4) [6](#0-5) [7](#0-6) .

This creates exactly the analog to the reported bug class: two places compute "the same" 70% ratio with different rounding, so a value that legitimately should fail the strict/ceiling threshold check can pass the looser floor-division check. Here, `determine_global_state`/`determine_latest_supported_signer_protocol_version`/`determine_global_burn_view` (all gated by `reached_agreement`) can conclude "global agreement" exists on a current-miner/tenure/burn-view/protocol-version state machine with weight that is provably below the true 70% supermajority required for block signing elsewhere in the same codebase.

### Impact Explanation
Because `determine_global_state()` feeds the signer's belief about the active miner/tenure and the negotiated tx-replay set (used to decide what is "canonical" locally), accepting agreement at <70% weight means a signer can lock in a `current_miner`/tenure view (and thus validate/sign block proposals against that view as if it were the canonically-supermajority-endorsed state) using less real support than the protocol's actual security margin assumes. This weakens the guarantee that "acting on global state" implies real supermajority backing — the exact "aggregated-weight vs verified-accepts" equality break the scope calls out: the aggregated weight computed via floor division is treated as equivalent to the verified (ceiling-based) 70% acceptance used for block signature verification, when it is not. In edge cases near the rounding boundary this can let a coalition just under 70% dictate the signer's view of the active miner/tenure, which downstream informs block-validation decisions.

### Likelihood Explanation
This requires no majority and no protocol violation by other signers — it is triggered purely by ordinary weight distributions where `total_weight * 7` is not a multiple of 10 (i.e., most reward-cycle weight totals), combined with a set of updates whose combined weight lands in the `[floor, ceiling)` gap (as narrow as 1 unit of weight for many `total_weight` values, per the worked example above). A one-slot signer (plus ordinary gossip of `StateMachineUpdate` messages) can be part of the coalition whose vote_weight sits in that gap.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the same ceiling semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (widen to u64 and add the ceiling remainder adjustment, or simply call `compute_voting_weight_threshold` and compare against it) so that "global agreement" as tracked by `GlobalStateEvaluator` can never be satisfied by less than the true 70% supermajority weight used for actual block approval.

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 13` (e.g., 13 signers of weight 1 each, or any weight distribution summing to 13).
2. Compute the "official" 70% supermajority via `NakamotoBlockHeader::compute_voting_weight_threshold(13)` → `ceil(13*7/10) = 10`.
3. Call `evaluator.reached_agreement(9)` — per [4](#0-3)  this returns `true` (`9 >= 13*7/10 = 9`), even though `9/13 ≈ 69.2% < 70%` and is below the `10` required by the canonical block-approval threshold.
4. Feed enough `StateMachineUpdate` gossip messages from addresses summing to weight 9 (out of 13) supporting the same `current_miner`/burn view; `determine_global_state()` will report agreement on that state despite lacking the true 70% supermajority that the rest of the protocol (e.g. `store_and_process_block_signature`, `handle_block_pre_commit`) requires for block-level decisions.

```rust
    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
```

```rust
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
```
