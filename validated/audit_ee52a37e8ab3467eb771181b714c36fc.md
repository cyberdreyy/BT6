## Analysis

The bug class in the report is a **formula/type mismatch that silently defeats a safety bound**, causing either false rejections (DoS) or false acceptances (bypass) depending on which quantity flows into the calculation with the wrong sign/units. The reachable analog in this codebase is the staleness check in the gateway's `web_api_trigger` legacy user-message handler, which mixes a `uint` age bound with an attacker-supplied `int64` timestamp before subtracting/casting, exactly the "different units/magnitudes feeding one formula" failure mode from the report. ### Title
Unsigned/signed integer mismatch in gateway staleness check allows bypass of message-age validation - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` validates that an inbound `web_api_trigger` payload is not stale by comparing `uint(time.Now().Unix()) - h.config.MaxAllowedMessageAgeSec` against `uint(payload.Timestamp)`. `payload.Timestamp` is an `int64` field taken directly from the unprivileged client's JSON-RPC request body, while `MaxAllowedMessageAgeSec` and the current time are cast to `uint`. Mixing a signed, attacker-controlled value with unsigned arithmetic lets an attacker defeat the entire staleness check by supplying a negative or otherwise crafted timestamp.

### Finding Description
The relevant code is: [2](#0-1) 

`payload.Timestamp` comes from `webapicap.TriggerRequestPayload`, which is unmarshalled straight from the message body supplied by the caller (an unprivileged HTTP/gateway client) with no range validation beyond `payload.Timestamp == 0`: [3](#0-2) 

`payload.Timestamp` is declared as a signed integer (`int64`) type, populated e.g. via `strconv.ParseInt` in tests, so it can legally be negative: [4](#0-3) 

When `payload.Timestamp` is negative (e.g. `-1`), `uint(payload.Timestamp)` wraps around to a huge value (≈2^64−1 on 64-bit platforms). The staleness comparison `now - maxAge > uint(payload.Timestamp)` then always evaluates false, so the "stale message" branch is never taken — regardless of how old, forged, or nonsensical the timestamp actually is. This defeats the intended freshness/anti-replay guard entirely for crafted inputs, the same class of error as the zkSync report: a bound-checking formula built from mismatched signed/unsigned quantities of very different magnitudes, silently neutering the safety check instead of failing safe.

Notably, the same function still carries an explicit TODO acknowledging missing authorization controls on this path: [5](#0-4) 
which means the staleness check is one of the only gating mechanisms currently protecting this internet-facing handler from replay/flooding of `web_api_trigger` messages.

### Impact Explanation
This handler sits on the gateway's user-facing (internet-facing) message path and fans a validated request out to every node in the DON: [6](#0-5) 
Bypassing the staleness check lets an unprivileged remote caller submit requests with arbitrary/forged timestamps that should have been rejected as stale, enabling replay of old signed payloads and unrestricted flooding of DON member nodes with trigger traffic — a denial-of-service vector against gateway/DON nodes, consistent with the "DoS via miscalculated bound" impact described in the reference report. Given the adjacent TODO indicating allowlist/rate-limiting is not yet applied on this path, the staleness check is one of few available mitigations, amplifying the impact of its bypass.

### Likelihood Explanation
Likelihood is high for any deployment still using this legacy path: the caller fully controls `payload.Timestamp` in the JSON body and only needs to set it to a negative number (or otherwise craft it) to always short-circuit the staleness comparison to "not stale." No special privileges, secrets, or race conditions are required — only a syntactically valid signed message, which is otherwise the normal way to invoke this handler.

### Recommendation
- Validate `payload.Timestamp` is non-negative (and within a sane forward/backward bound) before using it in any arithmetic, rejecting the message otherwise.
- Perform the staleness comparison entirely in a signed integer domain (e.g., `int64` or `time.Duration`) instead of mixing `uint` and `int64` via casts, e.g.: `if time.Now().Unix()-payload.Timestamp > int64(h.config.MaxAllowedMessageAgeSec) { ... }`, guarding against both directions (too old and too far in the future).
- Add unit tests covering negative, zero, and future timestamps to lock in the corrected behavior, mirroring the report's recommendation to add concrete test cases for boundary/formula correctness.
- Prioritize implementing the allowlist/rate-limiting noted in the TODO on this same code path, since the staleness check alone is insufficient authorization.

### Proof of Concept
1. Craft a `TriggerRequestPayload` JSON body with `"timestamp": -1` (or any negative `int64`), sign it with any valid ECDSA key as done in the handler's own test helper (`msg.Sign(key)`).
2. Submit it to the gateway as a `web_api_trigger` message calling `HandleLegacyUserMessage`.
3. Because `uint(-1)` wraps to `18446744073709551615`, the condition `uint(time.Now().Unix()) - h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp)` evaluates to `false`, so the "stale message" rejection branch at [7](#0-6) 
is skipped, and the forged/stale message is forwarded to all DON members despite the freshness check that was supposed to block it.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
