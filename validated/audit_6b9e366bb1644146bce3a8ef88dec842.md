### Title
Unauthenticated `/v2/resume/:runID` endpoint allows forging async bridge task results and prematurely completing/poisoning pending job runs - (File: core/web/pipeline_runs_controller.go)

### Summary
The `Resume` handler on `PATCH /v2/resume/:runID` is mounted in the unauthenticated route group (`unauthedv2`), not the authenticated `authv2` group, so any external, unprivileged caller can invoke it with a task-run UUID and an arbitrary JSON result body.

### Finding Description
`v2Routes` registers `unauthedv2.PATCH("/resume/:runID", prc.Resume)` with no auth middleware, while every other job-run-mutating route lives under `authv2` (protected by `auth.Authenticate`). [1](#0-0) 

`PipelineRunsController.Resume` parses `runID` as the `taskID` directly from the URL, decodes an attacker-controlled JSON body into a `pipeline.ResumeRequest`, and forwards it unchanged to `App.ResumeJobV2`. [2](#0-1) 

`ResumeJobV2` calls `pipelineRunner.ResumeRun`, which calls `orm.UpdateTaskRunResult(taskID, result)`. This only checks that the run identified by `taskID` is in `running`/`suspended` state — it does not verify that the caller is the legitimate external adapter/bridge that was originally sent the resume URL. [3](#0-2) [4](#0-3) 

The task-run UUID (`t.uuid`) is embedded in the bridge's async `responseURL` (`.../v2/resume/<uuid>`) and sent to the external adapter as the sole "credential" for completing the run — there is no additional shared secret or signature check. [5](#0-4) 

This is the same bug class as the Lombard report: a value that should only be trusted once confirmed by the legitimate authority (the real external adapter) is instead accepted permissionlessly from any caller who can obtain or guess the UUID, and is immediately used to finalize state (`UpdateTaskRunResult` marks the task finished and un-suspends/finishes the run) before the genuine response arrives.

### Impact Explanation
An attacker who learns or brute-forces/guesses a pending run's UUID (e.g., via logs, error messages, monitoring exposure, or a leaked/observed resume URL) can inject a forged result into a suspended async pipeline run. This can poison job outputs (e.g., falsified price data feeding into an `ethtx` submission task) or prematurely finish a run so the genuine external adapter's later legitimate callback is rejected/ignored (the run is no longer `running`/`suspended`), functionally griefing the job the same way forged unstake receipts blocked legitimate Lombard unstake processing.

### Likelihood Explanation
Exploitation requires knowledge of a specific pending run's UUID (v4, effectively unguessable at scale), so this is not trivially mass-exploitable, but it is a real design weakness: the endpoint is intentionally unauthenticated (relying purely on UUID secrecy) and any leak of the UUID (logging, error responses, network capture of the outbound request to the external adapter, a compromised or malicious external adapter, SSRF, etc.) fully compromises the run's integrity with no additional authentication layer.

### Recommendation
Require the resume request to prove it originates from the intended external adapter (e.g., HMAC-signed callback token, per-run shared secret separate from the UUID used for lookup, or restricting acceptance to the specific IP/host the bridge was configured with), and/or re-validate that a resume is only accepted once and audited independent of network exposure of the UUID.

### Proof of Concept
1. Configure a bridge with `async=true` and observe the `responseURL` sent to the external adapter, e.g. `http://<node>:6688/v2/resume/<task-uuid>` (visible in bridge task request logs/telemetry or via a compromised/observing network path).
2. Without any Chainlink Node authentication, send:
   `PATCH /v2/resume/<task-uuid>` with body `{"data":{"result":"<attacker-controlled value>"}}`.
3. `PipelineRunsController.Resume` accepts it, calls `ResumeJobV2` → `ResumeRun` → `UpdateTaskRunResult`, which finalizes the task run and resumes/finishes the pipeline with the attacker's forged value, regardless of what the real external adapter later sends.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
