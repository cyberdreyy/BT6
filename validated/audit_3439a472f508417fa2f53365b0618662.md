### Title
Miner can indefinitely spam stale/losing block proposals to permanently suppress the tenure-inactivity timeout, wedging signers onto a non-productive miner - (`stacks-signer/src/chainstate/mod.rs`)

### Summary
`SortitionData::check_latest_block_in_tenure` treats any block proposal that fails the height/tip check as "miner activity" and refreshes `tenure_activity.last_activity_time` whenever the tenure's last *signed* block has not yet reached `signed_group` (global acceptance). Because that guard is an unconditional `is_none_or` on `signed_group`, a miner who gets one block locally signed (70% pre-commit) but never lets it become globally accepted can keep this condition true forever, and can refresh the activity clock at will by resubmitting trivially-modified (different-timestamp) losing proposals. This defeats `SortitionState::is_timed_out` (v1/v2), which exists specifically to let signers abandon a non-productive miner and fall back to the prior tenure. No signer majority is needed — a single one-slot miner, acting for free over gossip/StackerDB, can wedge block production for the tenure.

### Finding Description
`check_latest_block_in_tenure` in `stacks-signer/src/chainstate/mod.rs` is invoked at proposal arrival (via `check_proposal`), at validate-ok, and at signing time to check whether a new proposal confirms the tenure's expected tip: [1](#0-0) 

When the proposal fails the height check (`block.header.chain_length <= info.block.header.chain_length`), the code decides whether to still count it as miner activity:
```
if info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
}) {
    // ... update_last_activity_time ...
}
return Ok(false);
``` [2](#0-1) 

The intent (per the surrounding comments) is to give a slow miner a bounded grace window (`reorg_attempts_activity_timeout`) after a block is confirmed on-chain (`signed_group` set) before further reorg attempts stop counting as activity. But if the tenure's last locally-signed block (`signed_self`) never actually reaches `signed_group` (global acceptance) — which the miner can arrange simply by never successfully broadcasting/mining that block onward, or by it losing the race to be confirmed — then `info.signed_group` stays `None` forever, and `is_none_or` is unconditionally `true`. Every subsequent losing/duplicate proposal from that miner therefore refreshes `last_activity_time`, with no time bound at all.

This activity timestamp is exactly what feeds `SortitionState::is_timed_out` in both protocol versions, whose entire purpose is to declare the current miner inactive and fall back to the prior tenure once nothing productive has happened for `block_proposal_timeout`: [3](#0-2) [4](#0-3) 
and the doc flow confirms `is_timed_out` is the sole liveness recovery path when no block has been signed in the tenure: [5](#0-4) 

The signer's proposal-dedup logic (`should_reevaluate_block`) only shortcuts re-evaluation of the *exact same* proposal (same `signer_signature_hash`); a proposal with a changed header field (e.g. `timestamp`) is a "new" block and goes through the full fresh-evaluation path, re-running `check_proposal` → `check_latest_block_in_tenure` every time: [6](#0-5) 
Tests elsewhere in the codebase demonstrate exactly this technique (bumping `header.timestamp` by 1 to produce a distinct `signer_signature_hash` while keeping the same tenure/height), confirming it is trivial for a miner (who signs the header) to mint an unlimited stream of distinct-but-losing proposals for the same tenure: [7](#0-6) 

Reaching this vulnerable branch requires only that the proposal passes the earlier, cheap `check_proposal` gates (correct tenure id/consensus hash, matching miner pubkey hash, all-1s bitvec) — checks that the legitimately elected, one-slot miner for that sortition trivially satisfies with their own signing key: [8](#0-7) 

### Impact Explanation
This is a liveness wedge matching the "High" category: "a signer wedged into never signing valid blocks." A single miner who once achieves local (70% pre-commit) signature on a block, but ensures that block never becomes globally accepted (e.g. it never gets pushed/adopted, or the node never observes it), gains an unbounded ability to refresh `last_activity_time` for that tenure at zero cost by resubmitting stale/losing block-header variants. `is_timed_out` (`stacks-signer/src/chainstate/v1.rs` / `v2.rs`) never returns true, so signers never invoke the `FALL["fall back to prior tenure"]` recovery path, and the tenure/miner can never be abandoned by the honest signer set even though it is not producing a chain-extending block. This stalls chain progress for the reward cycle without requiring control of a majority of signer weight — exactly the "for free, anytime, no external condition" griefing pattern called out as High in the source report (H-7), mapped here onto the signer's inactivity/fallback safety mechanism instead of a token balance-diff.

### Likelihood Explanation
Likelihood is high given how the mechanism must be triggered:
- Only the legitimately elected miner for the current sortition can satisfy the pubkey/tenure checks in `check_proposal`, so the attacker is exactly the "one-slot miner" contemplated by scope — no majority-signer collusion or external cost is required.
- The miner already controls block header contents (timestamp, etc.), so producing distinct `signer_signature_hash` values that dodge `should_reevaluate_block`'s dedup and force a fresh evaluation each time is trivial and requires no extra infrastructure beyond normal mining/signing.
- The precondition (`signed_group` never getting set for the tenure's last signed block) is naturally achievable by a miner that intentionally withholds or otherwise prevents the locally-signed block from being confirmed by the node — a decision fully within the miner's control.

### Recommendation
Bound the "activity" credit independent of whether `signed_group` was ever observed — e.g., measure freshness from when the *tenure* itself (or its burn block) arrived rather than from `signed_group`, or cap the number/rate of reorg-attempt-driven activity refreshes per tenure so a miner cannot indefinitely reset the inactivity clock. Concretely, replace the unconditional `is_none_or(...)` (which is vacuously true when `signed_group` is `None`) with a check anchored to a monotonic, attacker-uncontrolled origin (e.g., first-seen time of the tenure, or `received_ts`/`get_burn_block_receive_time_ch`), so that `reorg_attempts_activity_timeout` always eventually elapses regardless of whether the miner's block reaches global acceptance.

### Proof of Concept
1. Miner M wins a sortition and starts tenure T.
2. M proposes block B1 at height h; signers validate it and enough of them pre-commit that this signer signs B1 locally (`signed_self` set), but M prevents B1 from ever reaching the node/broadcast to become globally accepted (`signed_group` stays `None` — e.g., M simply never uploads it, or lets a race lose).
3. `get_tenure_last_block_info(T, ...)` now returns `Some(B1_info)` with `signed_group == None`.
4. M repeatedly crafts trivially-modified proposals B2, B3, … at height ≤ h (e.g., re-timestamped copies of B1, or copies of an earlier/losing sibling), each producing a new `signer_signature_hash` and thus bypassing `should_reevaluate_block`'s "already decided" shortcut.
5. For each Bi, `check_proposal` → `check_latest_block_in_tenure(T, Bi, ...)` finds `Bi.chain_length <= B1.chain_length`, evaluates `info.signed_group.is_none_or(...)` → `true` (since `signed_group` is `None`), and calls `update_last_activity_time(T, now)`.
6. As long as M sends at least one such proposal before `block_proposal_timeout` elapses since the last refresh, `SortitionState::is_timed_out(T, ...)` in `chainstate/v1.rs`/`v2.rs` keeps returning `false`.
7. Signers therefore never execute `FALL["fall back to prior tenure"]`, and the tenure is wedged: M controls block production indefinitely without producing a single further globally-accepted block, and without needing any signer-weight majority.

            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout

                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.

                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
