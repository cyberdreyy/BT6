### Title
Unguarded `new_currency<T>` Allows Any Caller to Steal `TreasuryCap<T>` and Permanently DoS Coin Registration — (File: `crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

---

### Summary

`coin_registry::new_currency<T>` is a fully `public` function that accepts any type `T: key` with no check that the caller owns or published type `T`. Any unprivileged caller can front-run a coin publisher by calling `new_currency<T>` with the victim's coin type, receiving the `TreasuryCap<T>` for that type and permanently blocking the legitimate owner from ever registering their coin in the `CoinRegistry`.

---

### Finding Description

The function signature is:

```move
public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    decimals: u8,
    symbol: String,
    name: String,
    description: String,
    icon_url: String,
    ctx: &mut TxContext,
): (CurrencyInitializer<T>, TreasuryCap<T>)
``` [1](#0-0) 

The `/* internal */` annotation is a **comment only** — it imposes no runtime or compile-time constraint. The actual ability bound is just `key`. The function is unconditionally `public`.

Inside `new_currency`, two irreversible actions occur:

1. **Derived address permanently claimed** — `derived_object::claim(&mut registry.id, CurrencyKey<T>())` marks the deterministic slot for type `T` in the singleton `CoinRegistry` as `Reserved`. Any subsequent call with the same `T` aborts with `EObjectAlreadyExists`. [2](#0-1) 

2. **`TreasuryCap<T>` minted for the caller** — `coin::new_treasury_cap(ctx)` creates a fresh `TreasuryCap<T>` (backed by `balance::create_supply_internal()`, which bypasses the one-time-witness uniqueness guard used by the legacy `coin::create_currency`). [3](#0-2) 

The only guard present is:

```move
assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
``` [4](#0-3) 

This check protects against double-registration but does **not** verify that the caller is the publisher of `T`.

**Contrast with `display_registry::new_with_publisher`**, which correctly gates creation on a `Publisher` proof-of-package-ownership:

```move
public fun new_with_publisher<T>(
    registry: &mut DisplayRegistry,
    publisher: &mut Publisher,   // ← proof of ownership
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    assert!(publisher.from_package<T>(), ENotValidPublisher);
    ...
}
``` [5](#0-4) 

`new_currency` has no equivalent guard.

The `derived_object::claim` function itself is safe — it requires `&mut UID` of the parent, which is only reachable through `coin_registry` module functions. The vulnerability is that `new_currency` exposes this path to any caller without authorization. [6](#0-5) 

---

### Impact Explanation

An attacker who calls `new_currency<VictimCoin>(registry, ...)` followed by `finalize(init, ctx)` in a single PTB:

- Receives `TreasuryCap<VictimCoin>` — full minting authority over the victim's coin type, enabling unlimited coin creation.
- Receives `MetadataCap<VictimCoin>` — authority to set the coin's name, symbol, and icon.
- Permanently occupies the `CurrencyKey<VictimCoin>` derived slot in the `CoinRegistry`; the victim's own `new_currency<VictimCoin>` call will always abort with `ECurrencyAlreadyExists`.

The `TreasuryCap<T>` is the canonical minting capability. Holding it for a type the attacker does not own constitutes unauthorized object creation enabling direct fund theft (minting). The DoS is permanent — the derived address cannot be reclaimed.

This matches the Critical impact class: *"direct fund theft or state corruption from unauthorized object creation"*.

---

### Likelihood Explanation

- The `CoinRegistry` is a well-known shared object at `0xc`. Any PTB can pass it as a mutable shared-object argument.
- Type parameters in PTBs are arbitrary `TypeTag` values; an attacker can reference any published type from any package.
- The attack window opens the moment a package containing a `T: key` coin type is published on-chain and before the legitimate owner submits their `new_currency` transaction. On Sui's sub-second finality, this is a narrow but real window exploitable by a mempool-watching bot.
- No special privileges, keys, or governance access are required — only a funded address.

---

### Recommendation

Add a `Publisher` (or `internal::Permit<T>`) parameter to `new_currency` to enforce that only the package that defines `T` can register it, mirroring the pattern already used in `display_registry::new_with_publisher`:

```move
public fun new_currency<T: key>(
    registry: &mut CoinRegistry,
    publisher: &Publisher,   // add this
    decimals: u8,
    ...
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(publisher.from_package<T>(), ENotAuthorized);
    assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
    ...
}
```

Alternatively, require an `internal::Permit<T>` (as `display_registry::new` does) which can only be produced by the defining module. [7](#0-6) 

---

### Proof of Concept

1. Victim publishes a package containing:
   ```move
   public struct MYCOIN has key { id: UID }
   ```
   The package is assigned address `<victim_pkg>`.

2. Attacker observes the published package on-chain and submits a PTB before the victim:
   ```
   sui client ptb \
     --move-call 0x2::coin_registry::new_currency \
       "<victim_pkg>::mycoin::MYCOIN" \
       @0xc 6 "FAKE" "Fake Coin" "Attacker-controlled" "" \
     --assign init_result \
     --move-call 0x2::coin_registry::finalize \
       "<victim_pkg>::mycoin::MYCOIN" \
       init_result.0
   ```

3. The attacker's transaction executes:
   - `derived_object::claim(&mut registry.id, CurrencyKey<MYCOIN>())` marks the slot as `Reserved`.
   - `coin::new_treasury_cap(ctx)` creates `TreasuryCap<MYCOIN>` owned by the attacker.
   - `Currency<MYCOIN>` is shared with attacker-controlled metadata.

4. Victim submits `new_currency<MYCOIN>(registry, ...)` — aborts with `ECurrencyAlreadyExists`.

5. Attacker holds `TreasuryCap<MYCOIN>` and can mint unlimited `MYCOIN` tokens. The victim's coin type is permanently locked out of the registry. [8](#0-7) [9](#0-8)

public fun new_currency<T: /* internal */ key>(

    decimals: u8,
    symbol: String,
    name: String,
    description: String,
    icon_url: String,
    ctx: &mut TxContext,
