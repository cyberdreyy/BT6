### Title
Unauthenticated `MethodPublicKeyGet` requests bypass all rate limiting/quota checks and can trigger unbounded DON-wide fan-out before the public key cache is warm - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`HandleJSONRPCUserMessage` explicitly skips `requestProcessor.ProcessRequest` (the only place quotas/authorization/rate limiting are enforced) for `vaulttypes.MethodPublicKeyGet`, relying solely on an in-memory public key cache to bound cost. Until that cache is populated (gateway startup, restart, or after any fetch failure), each request with a unique `req.ID` unconditionally creates a new `activeRequest` and fans out to every vault DON node via `fanOutToVaultNodes`, with no per-sender or global rate limit applied to this inbound path.

### Finding Description
In `HandleJSONRPCUserMessage` [1](#0-0) , the `MethodPublicKeyGet` branch is handled "right away" without calling `h.requestProcessor.ProcessRequest`, which is the code path that performs authorization and (implicitly) quota-based throttling for `MethodSecretsCreate/Update/Delete/List` [2](#0-1) . The comment justifies this by asserting the response is "cache[d] quite aggressively" so "don't need to worry about DoS."

That assumption only holds once `h.cachedPublicKeyGetResponse` is non-nil. `getCachedPublicKey` returns `nil, nil` until a node quorum response has been received and cached via `tryCachePublicKeyResponse` [3](#0-2) [4](#0-3) . While the cache is cold (startup, restart, or after any failed fetch), every `MethodPublicKeyGet` request with a distinct `req.ID` calls `newActiveRequest` and `handlePublicKeyGet`, which calls `fanOutToVaultNodes` to send the request to every configured DON member [5](#0-4) . The only dedup control is rejecting a *repeated* `req.ID` [6](#0-5) , which an unauthenticated caller trivially bypasses by using a fresh ID (up to 200 chars) per request [7](#0-6) . `gateway.ProcessRequest`, the HTTP entry point, performs no global/per-sender rate limiting before invoking `HandleJSONRPCUserMessage` [8](#0-7) .

This means an unauthenticated client can repeatedly amplify one HTTP request into N outbound node requests (N = DON member count) and grow the in-memory `activeRequests` map, bounded only by request-timeout-based cleanup rather than any concurrency/rate cap, specifically because this method is the one path in the handler that is designed to skip the quota/authorization pipeline entirely.

I could not find any evidence in the code that the aggregated response leaks individual node addresses or per-node timing to the caller — `fanOutToVaultNodes`/`sendSuccessResponse` return a single aggregated JSON-RPC response, so the "topology fingerprinting" portion of the question is not supported by the code and should be treated as unconfirmed.

### Impact Explanation
This maps to an unauthenticated quota/rate-limit bypass on a legitimately-public endpoint, allowing amplification of a single unauthenticated HTTP request into fan-out traffic to every vault DON node, and unbounded growth of the gateway's `activeRequests` map during the cold-cache window. This is a resource-exhaustion vector against the gateway/DON, not a secret- or key-disclosure issue (the master public key returned is intentionally public), and not a topology-disclosure issue (no node identity is returned to the caller).

### Likelihood Explanation
Exploitability is limited to the window before the public key cache is warm: gateway startup/restart, or transient failure of `fetchVaultPublicKey`/quorum aggregation. Chainlink code implicitly acknowledges the general risk (the "don't need to worry about DoS" comment) but only accounts for the steady-state cached case, not the cold-start/failure window, which has no independent rate limit.

### Recommendation
Apply a per-sender/global rate limiter (or reuse `nodeRateLimiter`/a similar `limits.RateLimiter`) to `MethodPublicKeyGet` requests before creating `activeRequest`s and fanning out to nodes, independent of cache state, and/or coalesce concurrent in-flight `MethodPublicKeyGet` fan-outs into a single outbound round of node requests instead of one per unique request ID.

### Proof of Concept
Go test plan (in `core/services/gateway/handlers/vault/handler_test.go`):
1. Construct a `handler` with an empty public-key cache (`cachedPublicKeyGetResponse == nil`).
2. Mock `don.SendToNode` and assert call count.
3. Loop N times (e.g., 100) calling `h.HandleJSONRPCUserMessage(ctx, req, callback)` with `Method: vaulttypes.MethodPublicKeyGet` and a unique `req.ID` each iteration, without ever populating the cache (never invoking `HandleNodeMessage` to complete quorum).
4. Assert that `don.SendToNode` is called `N * len(donConfig.Members)` times and that `len(h.activeRequests)` grows unbounded/proportionally to N, with no error returned and no rate-limit rejection — demonstrating the lack of any throttling on this path.
5. Expected (fixed) behavior: after adding a rate limiter, assert that beyond a configured threshold, `HandleJSONRPCUserMessage` returns a rate-limit error/response instead of fanning out.

```go
func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
```

```go
func (h *handler) tryCachePublicKeyResponse(resp *jsonrpc.Response[json.RawMessage], l logger.Logger) {
	if resp.Result == nil {
		l.Debugw("no result in public key response, not caching")
		return
	}

	r := &vaultcommon.GetPublicKeyResponse{}
	err := h.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		l.Debugw("failed to unmarshal public key response, not caching", "error", err)
		return
	}

	if r.PublicKey == "" {
		l.Debugw("no public key in unmarshaled response, not caching", "response", resp, "result", r)
		return
	}
	masterPublicKey := tdh2easy.PublicKey{}
	masterPublicKeyBytes, err := hex.DecodeString(r.PublicKey)
	if err != nil {
		l.Debugw("failed to decode master public key string", "error", err)
		return
	}
	err = masterPublicKey.Unmarshal(masterPublicKeyBytes)
	if err != nil {
		l.Debugw("failed to unmarshal master public key", "error", err)
		return
	}

	h.mu.Lock()
	h.cachedPublicKeyGetResponse = *resp.Result
	h.cachedPublicKeyObject = &masterPublicKey
	h.mu.Unlock()
	l.Debugw("successfully cached public key response")
```

```go
func (h *handler) getCachedPublicKey() ([]byte, *tdh2easy.PublicKey) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	if h.cachedPublicKeyGetResponse == nil {
		return nil, nil
	}
	copied := make([]byte, len(h.cachedPublicKeyGetResponse))
	copy(copied, h.cachedPublicKeyGetResponse)
	cachedPublicKeyCopy := *h.cachedPublicKeyObject
	return copied, &cachedPublicKeyCopy
}
```

```go
func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}
```
