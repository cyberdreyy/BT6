### Title
Missing Authorization in `migrate_v1_to_v2` Allows Any V1 Display Holder to Claim `DisplayCap<T>` — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`migrate_v1_to_v2` performs no publisher or ownership check. Because V1 `Display<T>` carries `key + store` and is freely transferable, any address that holds a V1 `Display<T>` can call this function to receive a freshly minted `DisplayCap<T>` for the V2 registry — permanently locking the legitimate package publisher out of V2 display management for type `T`.

---

### Finding Description

**V1 `Display<T>` is freely transferable.** [1](#0-0) 

The `store` ability means any holder can call `public_transfer` to send the object to an arbitrary address.

**`migrate_v1_to_v2` has no authorization check.** [2](#0-1) 

The function accepts `legacy: LegacyDisplay<T>` by value and immediately delegates to `new_display<T>`, which mints a fresh `DisplayCap<T>` and sets `cap_id` to the new cap's ID. There is no `Publisher` argument, no `ctx.sender()` check, and no proof of package ownership of any kind.

**`new_display` only guards against duplicate V2 Displays — not against unauthorized callers.** [3](#0-2) 

The sole guard is `EDisplayAlreadyExists`. Once the attacker migrates first, the legitimate publisher is permanently blocked by this same assertion.

**Contrast with the authorized paths**, which all require a `Publisher` argument: [4](#0-3) [5](#0-4) 

`migrate_v1_to_v2` is the only path that creates a `DisplayCap<T>` without any such proof.

---

### Impact Explanation

An attacker who obtains a V1 `Display<T>` (possible because it has `key + store`) can:

1. Call `migrate_v1_to_v2(registry, legacy_display, ctx)` and receive `(Display<T>, DisplayCap<T>)`.
2. Use the `DisplayCap<T>` to call `set`, `unset`, and `clear` on the V2 `Display<T>`, corrupting display fields for every object of type `T` across all wallets and explorers.
3. Permanently prevent the legitimate publisher from ever creating or managing a V2 `Display<T>` for type `T` (`EDisplayAlreadyExists` fires on all subsequent attempts).

The `cap_id` field of the V2 `Display<T>` is set to an attacker-controlled object ID — this is unauthorized object creation and state corruption under the bounty scope.

---

### Likelihood Explanation

The prerequisite is that the attacker must hold a V1 `Display<T>`. This requires the publisher to have transferred it (intentionally, by mistake, or through an escrow/marketplace contract). This is a meaningful prerequisite that limits exploitability to scenarios where the V1 Display leaves the publisher's address. It is not a zero-trust attack, but it is a realistic one given that `key + store` objects are routinely transferred in Sui protocols.

---

### Recommendation

Add a `Publisher` argument to `migrate_v1_to_v2` and assert package ownership before proceeding:

```move
public fun migrate_v1_to_v2<T: key>(
    registry: &mut DisplayRegistry,
    publisher: &Publisher,          // <-- add this
    legacy: LegacyDisplay<T>,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    assert!(publisher.from_package<T>(), ENotValidPublisher);  // <-- add this
    let (mut display, cap) = new_display<T>(registry, ctx);
    display.fields = *legacy.fields();
    legacy.destroy();
    (display, cap)
}
```

This mirrors the pattern already used in `new_with_publisher` and `claim_with_publisher`.

### Proof of Concept

```

2. Publisher: call display::new<T>(publisher, ctx) → Display<T> (V1).
3. Publisher: transfer::public_transfer(display_v1, attacker_address).
4. Attacker: call display_registry::migrate_v1_to_v2(registry, display_v1, ctx)

5. Assert: attacker holds a valid DisplayCap<T>.
```

```text
fun new_display<T>(
    registry: &mut DisplayRegistry,
    ctx: &mut TxContext,
): (Display<T>, DisplayCap<T>) {
    let key = DisplayKey<T>();
    assert!(!derived_object::exists(&registry.id, key), EDisplayAlreadyExists);
    let cap = DisplayCap<T> { id: object::new(ctx) };
    let display = Display<T> {
        id: derived_object::claim(&mut registry.id, key),
        fields: vec_map::empty(),
        cap_id: option::some(cap.id.to_inner()),
    };
    (display, cap)
}
```
