### Title
Instant-withdraw receipts from epochs before the default epoch escape the recovery haircut and are paid at par, stealing post-finalization recoveries - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault` tracks instant-withdraw receipt ownership per epoch (`instantWithdrawsRequestsByEpoch[user][epoch]`) but aggregates liabilities in `instantWithdrawsRequests[user]` and `pendingInstantWithdraws`. When a borrower defaults, `defaultPendingClaimBasis()` and `_claimDefaultedInstantWithdrawRequest()` only look at the *current/default* epoch bucket, so an instant receipt requested in an earlier epoch and never funded is neither haircutted nor cleared — yet `claimInstantWithdrawRequest` still pays the full aggregate `instantWithdrawsRequests[_user]` through `_transferFundedClaim` at 100 cents on the dollar. This mirrors CVE-2018-19854: stale, unaccounted structures keyed by an outdated index leak value that the new accounting path assumes is covered.

### Finding Description
In `requestInstantWithdraw`, basis is recorded both per-user-per-epoch (`instantWithdrawsRequestsByEpoch[_user][currentEpoch]`) and in the aggregate `pendingInstantWithdraws`. [1](#0-0)  There is no expiry: if `getInstantWithdrawFunds` is never able to pull enough from the borrower during the running epoch (partial funding or none), `pendingInstantWithdraws` and the user's `instantWithdrawsRequestsByEpoch[E]` entry carry over while `epochNumber` is incremented at each `stopEpoch`. [2](#0-1) 

At default finalization:
- `defaultPendingClaimBasis()` adds only `instantWithdrawClaimsByEpoch[epochNumber]` — claims tagged to the *default* epoch F. Stale receipts tagged to E < F are excluded from the recovery basis, so `defaultRecoveryPrice` and `defaultRecoveryReserve` are computed as if they didn't exist. [3](#0-2) 
- `defaultInstantWithdrawsFinalized` is still set to `true` because `pendingInstantWithdraws != 0`. [4](#0-3) 
- On `claimInstantWithdrawRequest`, `_claimDefaultedInstantWithdrawRequest` checks `instantWithdrawsRequestsByEpoch[_user][defaultEpoch]` — the stale user's entry at epoch F is zero, so nothing is cleared or haircutted. [5](#0-4) 
- Execution then falls through to the par path: `amount = instantWithdrawsRequests[_user]` is burned and paid via `_transferFundedClaim`, which only requires `balance - defaultRecoveryReserve >= amount`. [6](#0-5) [7](#0-6) 

Any underlying that lands in the strategy after finalization outside `defaultRecoveryReserve` — e.g., late borrower repayments routed through `restoreOperations`/write-off recovery, ERC-20 donations not yet skimmed, or residual prefunded balances — is claimable at par by the stale-receipt holder, ahead of and independent of the haircutted recovery schedule applied to every other claimant.

### Impact Explanation
Direct theft of unclaimed recovery yield: the stale-epoch instant claimant receives 100% of their receipt from post-finalization inflows, while all other defaulted-epoch claimants (and active tranche holders) are capped at `defaultRecoveryPrice`. Quantified loss is up to the full stale receipt amount, bounded by post-finalization non-reserve inflows — in a credit vault, late recoveries are precisely the funds expected to flow in after a default, so the theft surface coincides with real money movement.

### Likelihood Explanation
Requires: (1) an instant-withdraw request that survives an epoch boundary unfunded — possible whenever `getInstantWithdrawFunds` pulls less than `pendingInstantWithdraws` from the borrower (the try/catch and `collectInstantWithdrawFunds(_instantWithdraws)` partial path allow this), and (2) a later borrower default that is finalized. Both are reachable with honest privileged roles; the attacker is just a KYC-passing lender who filed an instant request early and waits. The guard in `_transferFundedClaim` only protects the reserve, not par payout ordering, and `_claimDefaultedInstantWithdrawRequest`'s epoch-scoped lookup silently skips the stale bucket instead of reverting.

### Recommendation
Track per-epoch ownership for *all* outstanding instant receipts in the default basis: either iterate/accumulate `instantWithdrawsRequestsByEpoch` across epochs when computing `defaultPendingClaimBasis` (e.g., maintain a global `instantWithdrawClaims` aggregate and haircut every unfunded instant claim via a stored price), or force settlement/cancellation of unfunded instant receipts at `stopEpoch` before `epochNumber` advances so no bucket can be tagged to a superseded epoch. At minimum, `_claimDefaultedInstantWithdrawRequest` and the par path in `claimInstantWithdrawRequest` should verify that the user's entire `instantWithdrawsRequests` balance is attributable to the finalized default epoch before paying at par.

```solidity
// SPDX-License-Identifier: MIT
// Foundry fork test sketch against test/foundry/IdleCreditVault.t.sol harness

function testStaleEpochInstantClaimPaidAtParAfterDefault() external {
    uint256 amount = 10_000 * ONE_SCALE;
    _depositWithUser(user1, amount, true);           // KYC'd lender

    // Epoch 0: user files an instant withdraw request in buffer phase.
    vm.prank(user1);
    cdoEpoch.requestInstantWithdraw(trancheAmount, address(tranche));

    // Epoch runs; borrower never sends instant funds (pendingInstantWithdraws stays > 0).
    _startEpochAndCheckPrices(0);
    _stopCurrentEpochWithApr(10e18);                 // epochNumber -> 1, receipt still tagged epoch 0
    assertGt(strategy.pendingInstantWithdraws(), 0);
    assertEq(strategy.instantWithdrawsRequestsByEpoch(user1, 0), trancheAmount);
    assertEq(strategy.instantWithdrawsRequestsByEpoch(user1, 1), 0);

    // Epoch 1: borrower defaults; manager finalizes recovery.
    _startEpochAndCheckPrices(1);
    _stopEpochAndCheckPrices(1, initialProvidedApr, 0);   // defaulted
    _checkDefault();
    uint256 recovered = computedRecovery;
    deal(defaultUnderlying, manager, recovered);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), recovered);
    cdoEpoch.finalizeDefault(recovered, manager);
    vm.stopPrank();

    // Post-finalization: late recovery inflow lands in the strategy, outside defaultRecoveryReserve.
    uint256 late = trancheAmount;
    deal(defaultUnderlying, borrower, late);
    vm.prank(borrower);
    IERC20Detailed(defaultUnderlying).transfer(address(strategy), late);

    // Stale receipt claims at par even though defaultEpoch bucket for user1 is zero.
    uint256 balPre = IERC20Detailed(defaultUnderlying).balanceOf(user1);
    vm.prank(user1);
    cdoEpoch.claimInstantWithdrawRequest();
    // BUG: receives 100% of stale receipt while all other claimants are haircutted at defaultRecoveryPrice.
    assertEq(
        IERC20Detailed(defaultUnderlying).balanceOf(user1) - balPre,
        trancheAmount,
        'stale instant receipt paid at par from post-default inflows'
    );
}
```

```text
  function _claimDefaultedInstantWithdrawRequest(address _user) internal returns (uint256 claimBasis) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultEpoch];
    if (claimBasis == 0) return claimBasis;

    instantWithdrawsRequestsByEpoch[_user][defaultEpoch] = 0;
    instantWithdrawsRequests[_user] -= claimBasis;
    uint256 pending = pendingInstantWithdraws;
    // `pendingInstantWithdraws` is only the unfunded remainder. If this user's claim is larger,
    // the extra amount was already counted as prefunded reserve during default finalization.
    pendingInstantWithdraws = claimBasis >= pending ? 0 : pending - claimBasis;
    instantWithdrawClaimsByEpoch[defaultEpoch] -= claimBasis;
    _burn(_user, claimBasis);
    _transferDefaultRecovery(_user, (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL);
  }
```

```text
  function _transferFundedClaim(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    uint256 reserve = defaultRecoveryReserve;
    if (reserve != 0) {
      uint256 balance = underlyingToken.balanceOf(address(this));
      // This should be unreachable when accounting is consistent. Keep the guard so old funded
      // receipts can never spend underlyings reserved for default recovery claimants.
      if (balance < reserve || balance - reserve < _amount) revert NotAllowed();
    }
    underlyingToken.safeTransfer(_user, _amount);
  }
```
