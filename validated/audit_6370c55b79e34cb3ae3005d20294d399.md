### Title
Permanent `stopEpoch` freeze when an APR0 withdraw request exists and APR is raised — ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` reverts with `NotAllowed` whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`, *before* it closes the APR0 bucket. An unprivileged KYC-passed lender can open a normal withdraw request while `unscaledApr == 0`, which records principal into `apr0TotalPrincipal` via `_requestWithdrawApr0`. If the manager later sets a non-zero APR for the next epoch, every subsequent `stopEpoch` call reverts, permanently freezing all user funds in the vault. This is the analog of CVE-2019-2436's repeatable-crash DoS bug class: a low-privileged action leaves the system in a state that causes an unconditional hang of a critical operation.

### Finding Description
In `IdleCreditVault.requestWithdraw`, a normal withdraw request made while `unscaledApr == 0` routes into `_requestWithdrawApr0`, which increments `apr0TotalPrincipal` and stores the user's `principalEpoch` [1](#0-0) [2](#0-1) .

`apr0TotalPrincipal` is only reset inside `prepareStopEpochWithApr0`, the hook the CDO invokes during `stopEpoch`. But the guard ordering is wrong:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol:502-508
if (_principal == 0) {
  return (_expInterest, _adjPendingWithdrawFees);
}
// APR0 principal is only valid while APR is 0 for that request lifecycle.
if (unscaledApr != 0) {
  revert NotAllowed();
}
```

The revert happens **before** `apr0TotalPrincipal = 0` at line 540 [3](#0-2) . There is no other code path that clears `apr0TotalPrincipal` — `_clearWithdrawClaimForEpoch` only reduces it during *default* finalization, and `_settleApr0` only touches per-user data [4](#0-3) . The user also cannot withdraw-claim the bucket away: `_settleApr0` only moves `principal` to `settledPrincipal`, never touching `apr0TotalPrincipal` [5](#0-4) .

Attack sequence (buffer phase, APR=0 configuration):

1. Manager configures the vault at `unscaledApr == 0` (a supported mode; tests exercise APR0 withdraw flows at `IdleCreditVault.t.sol:2979-3028`).
2. Attacker (KYC-passed lender) deposits AA, then calls `IdleCDOEpochVariant.requestWithdraw` during the buffer. `IdleCDOEpochVariant.requestWithdraw` calls `creditVault.requestWithdraw(...)` [6](#0-5) , which lands in `_requestWithdrawApr0`, setting `apr0TotalPrincipal > 0`.
3. Manager (honest) calls `setAprs`/`setAprsWithBuffer` to raise APR for the next epoch — a routine configuration change.
4. Any `stopEpoch` call now reaches `prepareStopEpochWithApr0`, hits `unscaledApr != 0 && apr0TotalPrincipal != 0`, and reverts. This is permanent: the bucket is never cleared, so every future `stopEpoch` reverts identically.

### Impact Explanation
Permanent freezing of funds. With `stopEpoch` bricked, the epoch never ends: `epochNumber` never increments, so `_claimFundedWithdrawRequest`'s `epochNumber <= lastWithdrawRequest` check never passes for pending receipts [7](#0-6) , deposits cannot be claimed at a priced epoch, and borrower repayments cannot be booked. All LP principal is locked in the vault indefinitely. The cost to the attacker is a single dust-sized withdraw request.

### Likelihood Explanation
Medium-low. It requires an APR=0 epoch configuration (a documented supported mode) followed by a benign APR raise by the honest manager — a normal operational action, not an adversarial one. The attacker only needs the KYC-passed-lender role that `requestWithdraw` already requires via `isWalletAllowed` [8](#0-7) . No existing guard prevents it: the revert is unconditional once both state variables hold, and no escape path clears `apr0TotalPrincipal` while APR is non-zero.

*Caveat:* index size limits prevented fully confirming the exact call site/conditions under which `IdleCDOEpochVariant.stopEpoch` invokes `prepareStopEpochWithApr0` (e.g., whether it is skipped when APR is non-zero). If the CDO only calls it when `unscaledApr == 0`, this finding collapses; that should be verified against the full file before reporting.

### Recommendation
In `prepareStopEpochWithApr0`, do not revert on `unscaledApr != 0` when APR0 principal is outstanding. Either:

- settle/close the APR0 bucket at pro-rata rate zero (or the last recorded `apr0RateByEpoch`) instead of reverting — i.e., move `apr0TotalPrincipal = 0` before the revert, or replace the revert with a settlement path; or
- allow the manager/CDO to forcibly clear `apr0TotalPrincipal` so the epoch machine is never permanently blocked.

At minimum, ensure no state transition exists where `apr0TotalPrincipal > 0` can survive an APR change without a clearing path.

### Proof of Concept
```solidity
// test/foundry/Apr0StopEpochDos.t.sol — Foundry fork PoC (sketch)
function test_Apr0RequestThenAprRaise_BlocksStopEpoch() external {
  // Setup: vault configured with unscaledApr == 0 (APR0 mode)
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setAprs(0, 0);

  // 1. Attacker (KYC'd lender) deposits and requests withdraw during buffer
  uint256 mintedAA = idleCDO.depositAA(1e6);
  _transferBurnedTrancheTokens(attacker, true);
  vm.prank(attacker);
  cdoEpoch.requestWithdraw(mintedAA, address(AAtranche));
  assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

  // 2. Manager honestly raises APR for next epoch
  vm.prank(manager);
  IdleCreditVault(address(strategy)).setAprs(5e18, 5e18);

  // 3. Run epoch, then try to stop it — reverts forever
  _startEpoch();
  vm.warp(cdoEpoch.epochEndDate() + 1);
  deal(defaultUnderlying, borrower, type(uint96).max);
  vm.prank(manager);
  vm.expectRevert(NotAllowed.selector);
  cdoEpoch.stopEpoch(5e18, 0);

  // Repeatable: every subsequent stopEpoch reverts identically → funds frozen
}
```

    Apr0UserData storage _apr0User = apr0Users[_user];

      return;

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {

    }
