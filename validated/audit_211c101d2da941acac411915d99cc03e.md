### Title
LOOP plugin registry/debug routes and `/debug/vars` are missing `auth.RequiresAdminRole` (and even authentication) - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the base `api` router group with **no auth middleware at all**, and `debugRoutes` registers `/debug/vars` behind only `auth.Authenticate(...)` with **no role gate**. Neither route group calls `auth.RequiresAdminRole`, unlike every other admin-sensitive route in `v2Routes`.

### Finding Description
In `core/web/router.go`, `NewRouter` wires up route groups in this order: [1](#0-0) 

`debugRoutes` wraps `/debug/vars` only with session authentication, not any role check: [2](#0-1) 

`loopRoutes` is registered on `r` (the plain `api` group, which only has rate-limiting and session-store middleware attached at `NewRouter`, no auth call) with zero authentication middleware: [3](#0-2) [4](#0-3) 

Contrast this with every admin-sensitive handler in `v2Routes`, which is explicitly wrapped with `auth.RequiresAdminRole`, e.g. user management and key export/import/delete: [5](#0-4) [6](#0-5) 

The `loopRoutes` handlers (`discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) proxy to internal LOOP plugin processes and forward pprof/metrics data, and contain no internal auth check of their own: [7](#0-6) [8](#0-7) 

Because `loopRoutes` has no `auth.Authenticate` wrapper at all, an unauthenticated attacker (not just an edit-role user) can reach the plugin registry discovery endpoint and pprof proxy for any registered LOOP plugin. `debug/vars` similarly requires only a valid session (any role — view/run/edit) rather than an admin session, so a non-admin authenticated user can read process-wide `expvar` state (memory stats, custom exported vars) that should be admin-only.

### Impact Explanation
- `loopRoutes`: full unauthenticated disclosure of the LOOP plugin registry (plugin names via `/discovery`), plugin metrics, and pprof profiling data (goroutine dumps, heap profiles, CPU traces) proxied from internal plugin processes — matching the "sensitive data disclosure / debug endpoint exposure" impact class named in the question.
- `debugRoutes` (`/debug/vars`): expvar data exposed to any authenticated user regardless of role (view/run/edit), a lesser but still real authorization-exactness violation versus admin-only intent implied elsewhere in the router.

Neither of these routes allows privilege escalation into `UpdateRole`/user management themselves — those routes are correctly wrapped with `auth.RequiresAdminRole` (`/users`, `/user` PATCH is missing role check but is self-scoped to the acting user). The impact is limited to information disclosure of internal metrics/pprof/plugin-registry data, not direct account takeover.

### Likelihood Explanation
High for `loopRoutes`: no credentials at all are required, only network access to the node's API port and knowledge of registered plugin names (discoverable via `/discovery`), making this trivially and repeatably exploitable by any unauthenticated client. Moderate for `/debug/vars`: requires any valid session (lowest-privilege view-role credential suffices), which is easy to obtain in multi-tenant/shared-node deployments.

### Recommendation
- Wrap `loopRoutes` in `core/web/router.go` with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` and gate each handler with `auth.RequiresAdminRole`, consistent with other operational/debug routes.
- Gate `/debug/vars` in `debugRoutes` with `auth.RequiresAdminRole` in addition to the existing `auth.Authenticate` session check.

### Proof of Concept
1. Handler-level integration test using `httptest`: build the router via `NewRouter` with a test `chainlink.Application` that has a `LoopRegistry` containing at least one registered plugin.
2. Issue `GET /discovery`, `GET /plugins/testplugin/metrics`, `GET /plugins/testplugin/debug/pprof/heap` with **no** `Authorization` header and **no** session cookie; assert response status is `200` (currently) rather than the expected `401`.
3. Issue `GET /debug/vars` with a valid session cookie for a user with `sessions.UserRoleView` (lowest role); assert response is `200` rather than expected `403` if admin-only intent applies.
4. Add a table-driven test enumerating all routes registered in `router.go` (`debugRoutes`, `healthRoutes` excluded as intentionally public, `loopRoutes`) and assert each non-public route's middleware chain includes `auth.RequiresAdminRole` or equivalent, failing the build if a new route is added without it.

func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
