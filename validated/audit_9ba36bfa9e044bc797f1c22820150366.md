### Title
Unauthenticated `opp2p_connectPeer` RPC triggers attacker-controlled synchronous DNS resolution, stalling the consensus node's P2P event loop - ([File: crates/consensus/gossip/src/gater.rs])

### Summary
The consensus node exposes `opp2p_connectPeer` on the public, non-admin-gated `opp2p` RPC namespace. It accepts an arbitrary libp2p `Multiaddr` string from any RPC caller and forwards it to `GossipDriver::dial_multiaddr`, which calls `ConnectionGater::can_connect_outbound`. That path resolves DNS-based multiaddr components (`/dns/`, `/dns4/`, `/dns6/`, `/dnsaddr/`) synchronously via `std::net::ToSocketAddrs::to_socket_addrs` in `ConnectionGater::try_resolve_dns`, blocking on OS-level `getaddrinfo` for an attacker-chosen hostname before the connection gate decision (and therefore the RPC's effect) completes.

### Finding Description
`BaseP2PApi::opp2p_connect_peer` is registered unconditionally whenever a P2P network handle exists — it is not behind the `--rpc.enable-admin` admin gate that protects `AdminApi`: [1](#0-0) [2](#0-1) 

Its handler accepts a raw string, parses it into a `Multiaddr`, and only checks for a `p2p` peer-id component — it performs no restriction on the address portion (IP, DNS, private range, etc.): [3](#0-2) 

The request is forwarded through the gossip actor to `dial_multiaddr`, whose own comment acknowledges DNS resolution occurs off the RPC caller's direct control but still happens on the node's behalf: [4](#0-3) 

Before libp2p's transport-layer DNS resolution even runs, the connection gate itself performs a **blocking, synchronous** DNS lookup to enforce IP/subnet blocklists, using `format!("{hostname}:0").to_socket_addrs()` — a direct OS resolver call with no timeout, no `spawn_blocking`, and no async cooperation: [5](#0-4) 

This is invoked from `can_connect_outbound` → `can_connect` → `blocklist_ip_from_addr` → `try_resolve_dns`, all on the calling task's thread: [6](#0-5) 

An attacker who controls a domain (or simply points a DNS name at a non-responsive/black-holed nameserver) can call `opp2p_connectPeer` with `/dns4/attacker-controlled-host/tcp/1/p2p/<any-generated-peer-id>`. This forces the node to perform a synchronous `getaddrinfo` call against an attacker-controlled or unresponsive DNS server. Because the call is synchronous and un-timed, it will block for the OS resolver's full timeout/retry window (which, depending on `resolv.conf`, can be tens of seconds per call), stalling whatever task/thread is executing the gossip driver's connection-gate logic for that duration. This is the same bug class as the reported Apache Wicket CVE-2021-23937: an unauthenticated network input (there, `X-Forwarded-For`; here, an RPC multiaddr parameter) forces the server to perform DNS lookups to attacker-chosen hostnames, enabling a DNS-proxy/amplification-style denial-of-service against the node's own resolver and processing pipeline.

### Impact Explanation
Repeated or sustained calls to `opp2p_connectPeer` with hostnames pointing at slow/unresponsive/attacker-controlled DNS infrastructure can serially block the gossip driver's connection-gating logic, delaying legitimate peer dial/connect/disconnect/block/unblock operations processed through the same request channel. Because `P2pRpcRequest` handling is centralized (`handle_peers`, `disconnect_peer`, `block_peer`, etc. all funnel through the same dispatcher as `ConnectPeer`), a stalled DNS resolution effectively serializes and delays all other pending P2P admin operations, degrading peer management responsiveness and, if abused repeatedly/concurrently, can meaningfully degrade the node's consensus-layer P2P health — a node-level denial-of-service condition under the "resource exhaustion via unauthenticated attacker-controlled DNS lookups" bug class of the referenced CVE. It does not by itself cause fund loss, unbacked supply, or wrong provable output, but it does constitute a node health/availability impact reachable from an anonymous RPC client with no privileged access required.

### Likelihood Explanation
The `opp2p` namespace is exposed without admin gating whenever P2P is enabled, and `opp2p_connectPeer` takes a free-form string with no hostname/private-range restriction beyond requiring a `/p2p/<peer-id>` suffix, which is trivial for an attacker to satisfy with any freshly generated libp2p `PeerId`. No special privileges, funds, or preconditions are needed — a single unauthenticated JSON-RPC call is sufficient to trigger the blocking DNS resolution path.

### Recommendation
- Restrict DNS-address multiaddr components in `AddTarget`/`opp2p_connectPeer` inputs, or resolve DNS asynchronously with a bounded timeout (e.g., `tokio::time::timeout` combined with `tokio::net::lookup_host` or `spawn_blocking`) instead of the blocking `std::net::ToSocketAddrs::to_socket_addrs` call in `ConnectionGater::try_resolve_dns`.
- Consider gating `opp2p_connectPeer` (and other mutating P2P RPCs) behind the same admin/authenticated surface as `AdminApi`, or apply per-caller rate limiting, since it currently allows any anonymous RPC client to direct outbound network activity (including DNS lookups) from the node.
- Add an explicit timeout around the whole `can_connect`/`try_resolve_dns` call path so a single slow resolution cannot stall the shared P2P request-handling loop.

### Proof of Concept
1. Reach the consensus node's public RPC endpoint (no authentication required for the `opp2p` namespace).
2. Generate an arbitrary libp2p keypair/peer ID (no cost, done client-side).
3. Register or control a DNS name whose authoritative server never responds (or is deliberately slow), e.g. `dns-blackhole.attacker.tld`.
4. Call:
   ```
   opp2p_connectPeer("/dns4/dns-blackhole.attacker.tld/tcp/1/p2p/<generated-peer-id>")
   ```
5. Observe that `ConnectionGater::try_resolve_dns` (via `can_connect_outbound`) performs a blocking `to_socket_addrs()` call against the attacker's DNS name, stalling the gossip actor's processing of the `P2pRpcRequest` queue (delaying subsequent `Peers`, `BlockPeer`, `DisconnectPeer`, etc. requests) for the duration of the OS resolver timeout.
6. Repeat with several concurrent calls / different unresolvable hostnames to amplify the effect on node responsiveness.

Note: I was unable to fully verify, within the given tool budget, whether the gossip actor's main loop runs on a dedicated OS thread (in which case only P2P admin operations stall) or is scheduled on a shared tokio worker (in which case unrelated async tasks on that worker could also be delayed by the blocking syscall) — this affects the precise blast radius but not the existence of the blocking, attacker-triggerable DNS lookup itself.

    /// Attempts to resolve a DNS-based [`Multiaddr`] to an [`IpAddr`].
    ///
    /// Returns:
    /// - `None` if the multiaddr does not contain a DNS component (use [`Self::ip_from_addr`])
    /// - `Some(Err(()))` if DNS resolution failed
    /// - `Some(Ok(ip))` if DNS resolution succeeded
    ///
    /// Respects the DNS protocol type: `dns4` only returns `IPv4`, `dns6` only returns `IPv6`.
    pub fn try_resolve_dns(addr: &Multiaddr) -> Option<Result<IpAddr, ()>> {
        // Track which DNS protocol type was used
        let (hostname, ipv4_only, ipv6_only) =
            addr.iter().find_map(|component| match component {
                libp2p::multiaddr::Protocol::Dns(h) | libp2p::multiaddr::Protocol::Dnsaddr(h) => {
                    Some((h.to_string(), false, false))
                }
                libp2p::multiaddr::Protocol::Dns4(h) => Some((h.to_string(), true, false)),
                libp2p::multiaddr::Protocol::Dns6(h) => Some((h.to_string(), false, true)),
                _ => None,
            })?;

        debug!(target: "p2p", %hostname, ipv4_only, ipv6_only, "Resolving DNS hostname");

        let ip = match format!("{hostname}:0").to_socket_addrs() {
            Ok(addrs) => {
                // Filter addresses based on DNS protocol type
                addrs.map(|socket_addr| socket_addr.ip()).find(|ip| {
                    if ipv4_only {
                        ip.is_ipv4()
                    } else if ipv6_only {
                        ip.is_ipv6()
                    } else {
                        true
                    }
                })
            }
            Err(e) => {
                warn!(target: "p2p", %hostname, error = %e, "DNS resolution failed");
                return Some(Err(()));
            }
        };

        ip.map_or_else(
            || {
                warn!(target: "p2p", %hostname, "DNS resolution returned no matching addresses");
                Some(Err(()))
            },
            |resolved_ip| {
                debug!(target: "p2p", %hostname, %resolved_ip, "DNS resolution successful");
                Some(Ok(resolved_ip))
            },
        )
    }

    pub fn blocklist_ip_from_addr(addr: &Multiaddr) -> Result<Option<IpAddr>, ConnectionError> {
        match Self::try_resolve_dns(addr) {
            Some(Ok(ip)) => Ok(Some(ip)),
            Some(Err(())) => Ok(None),
            None => Self::ip_from_addr(addr)
                .map(Some)
                .ok_or_else(|| ConnectionError::InvalidIpAddress { addr: addr.clone() }),
        }
    }

    /// Checks shared peer, address, and subnet blocklists for the given peer and address.
    ///
    /// Outbound checks allow unresolved DNS addresses so libp2p can handle resolution at the
    /// transport layer. Inbound checks reject unresolved DNS addresses because listener endpoints
    /// should have IP-based remote addresses.
    pub fn can_connect(
        &self,
        peer_id: &PeerId,
        addr: &Multiaddr,
        dns_resolution_failure: DnsResolutionFailure,
    ) -> Result<(), ConnectionError> {
        if self.blocked_peers.contains(peer_id) {
            return Err(ConnectionError::PeerBlocked { peer_id: *peer_id });
        }

        let Some(ip_addr) = Self::blocklist_ip_from_addr(addr)? else {
            return match dns_resolution_failure {
                DnsResolutionFailure::Allow => {
                    debug!(target: "gossip", addr = ?addr, "DNS resolution failed, allowing connection");
                    Ok(())
                }
                DnsResolutionFailure::Reject => {
                    warn!(target: "gossip", addr = ?addr, "DNS resolution failed, rejecting connection");
                    Err(ConnectionError::InvalidIpAddress { addr: addr.clone() })
                }
            };
        };

        if self.blocked_addrs.contains(&ip_addr) {
            return Err(ConnectionError::AddressBlocked { ip: ip_addr });
        }

        if self.check_ip_in_blocked_subnets(&ip_addr) {
            return Err(ConnectionError::SubnetBlocked { ip: ip_addr });
        }

        Ok(())
    }
