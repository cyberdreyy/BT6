## Title
`lending_pool_configure_bank_interest_only` / `lending_pool_configure_bank` update the interest-rate config without first accruing interest, causing rate changes to be retroactively applied - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank_lite.rs`, `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
Both the `delegate_curve_admin`-gated `lending_pool_configure_bank_interest_only` instruction and the group-admin-gated `lending_pool_configure_bank` instruction mutate `bank.config.interest_rate_config` directly, without first calling `bank.accrue_interest()`. Because `accrue_interest` always applies the *current* interest-rate config over the *entire* elapsed `time_delta` since `last_update` (whenever it is next invoked), any config change made while interest is stale gets retroactively applied to the whole unaccrued period, distorting the interest actually earned/owed by depositors and borrowers for that period. This is the same root cause as the Revert Lend `setReserveFactor` finding: reserve/rate parameters are changed before global interest is settled at the old rate.

### Finding Description
`lending_pool_configure_bank_interest_only` updates the interest-rate config in place: [1](#0-0) 

`lending_pool_configure_bank` (full admin config path) similarly calls `bank.configure()`, which updates `interest_rate_config` directly, again with no accrual step beforehand: [2](#0-1) [3](#0-2) 

Neither instruction calls `Bank::accrue_interest`, unlike other bank-mutating flows (e.g. `lending_pool_emissions_deposit`, deposit/borrow/repay/withdraw, and the dedicated permissionless `lending_pool_accrue_bank_interest`) which always accrue first: [4](#0-3) 

The accrual logic itself computes the new share values using the *current* `interest_rate_config` applied over the full elapsed `time_delta` since `last_update`, with no memory of what rate applied historically: [5](#0-4) [6](#0-5) 

Because `last_update` is only advanced when `accrue_interest` actually runs, if the admin (or delegate curve admin) changes `zero_util_rate`, `hundred_util_rate`, `points`, or the fee parameters while a bank has gone unaccrued for some time, the next accrual event (triggered permissionlessly or by any depositor/borrower interacting with the bank) will apply the *new* rate/fee schedule across the *entire* stale interval rather than just from the moment of the config change onward. This retroactively and unfairly shifts value between lenders and borrowers for a period during which the old rate should have applied.

### Impact Explanation
This breaks the fairness/accuracy of the interest accounting: depositors and borrowers who interacted with (or held positions in) the bank during the stale interval receive a share-value update computed with a rate that never actually applied during most of that interval. Depending on the direction of the config change, this can transfer value between lenders and borrowers (and affect protocol/insurance/group fee accrual amounts) beyond what any party should have owed or earned. Although each mispricing may be modest per config change, it is a durable and repeatable accounting inconsistency with direct financial effect on ordinary (unprivileged) depositors' and borrowers' share values — the same class of impact judged as "breaks the math" and confirmed in the source report.

### Likelihood Explanation
Bank interest-rate configs are changed periodically by the `delegate_curve_admin` or group `admin` as part of normal risk-parameter management (per `guides/ADMIN/PERMISSIONS_AND_ROLES.md`), and there is no requirement or built-in mechanism forcing interest accrual immediately before such a change. Any bank that has gone even a short time without a triggering deposit/borrow/repay/withdraw (which is common for less active banks, as also noted in `guides/ADMIN/COLLECTING_FEES.md`: "banks without much activity may have stale numbers until someone interacts with them") is exposed whenever its config is updated. This makes the issue realistically and repeatedly reachable in normal operation, not merely theoretical.

### Recommendation
Call `bank.accrue_interest(...)` (and ideally `bank.update_bank_cache(...)`) at the start of both `lending_pool_configure_bank_interest_only` and `lending_pool_configure_bank` (and `configure_unfrozen_fields_only`'s frozen-bank branch if it can affect rate-relevant fields), before applying the new configuration. This ensures `last_update` and share values are settled under the old config prior to any parameter change, so new rates only apply prospectively.

### Proof of Concept
1. Deposit and borrow in a bank to create nonzero `total_asset_shares`/`total_liability_shares`.
2. Let a significant amount of time pass (e.g. via `warp`) without any bank interaction, so `last_update` becomes stale while `interest_rate_config` is unchanged (as in `programs/marginfi/tests/admin_actions/interest_accrual.rs`, which demonstrates the accrual math over elapsed `time_delta`).
3. As `delegate_curve_admin`, call `lending_pool_configure_bank_interest_only` (or as `admin`, call `lending_pool_configure_bank`) to substantially change `zero_util_rate`/`hundred_util_rate`/fee parameters — this succeeds with no accrual having occurred, per `configure_bank_lite.rs` lines 12-35.
4. Trigger accrual (e.g., via a deposit, or the permissionless `lending_pool_accrue_bank_interest`) and observe that `asset_share_value`/`liability_share_value` are updated using the *new* rate config across the *entire* stale `time_delta`, not just the time since the config change — reproducing the same retroactive-rate distortion demonstrated in the source report's forge tests for `V3Vault.setReserveFactor`.

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())
}

pub fn lending_pool_configure_bank(
    ctx: Context<LendingPoolConfigureBank>,
    bank_config: BankConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;

    // If settings are frozen, you can only update the deposit and borrow limits, everything else is ignored.
    if bank.get_flag(FREEZE_SETTINGS) {
        bank.configure_unfrozen_fields_only(&bank_config)?;

        msg!("WARN: Only deposit+borrow limits updated. Other settings IGNORED for frozen banks!");

        emit!(LendingPoolBankConfigureFrozenEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            deposit_limit: bank.config.deposit_limit,
            borrow_limit: bank.config.borrow_limit,
        });
    } else {
        // Settings are not frozen, everything updates
        bank.configure(&bank_config)?;
        msg!("Bank configured!");

        let group = ctx.accounts.group.load()?;
        bank.emode.validate_entries_with_liability_weights(
            &bank.config,
            group.emode_max_init_leverage,
            group.emode_max_maint_leverage,
        )?;

        emit!(LendingPoolBankConfigureEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            config: bank_config,
        });
    }

    Ok(())
}

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

pub fn calc_interest_rate_accrual_state_changes(
    time_delta: u64,
    total_assets_amount: I80F48,
    total_liabilities_amount: I80F48,
    interest_rate_calc: &InterestRateCalc,
    asset_share_value: I80F48,
    liability_share_value: I80F48,
) -> MarginfiResult<InterestRateStateChanges> {
    // If the cache is empty, we need to calculate the interest rates
    let utilization_rate: I80F48 = total_liabilities_amount
        .checked_div(total_assets_amount)
        .ok_or_else(math_error!())?;
    debug!(
        "Utilization rate: {}, time delta {}s",
        utilization_rate, time_delta
    );
    let interest_rates = interest_rate_calc.calc_interest_rate(utilization_rate)?;

    debug!("{:#?}", interest_rates);

    let ComputedInterestRates {
        lending_rate_apr,
        borrowing_rate_apr,
        group_fee_apr,
        insurance_fee_apr,
        protocol_fee_apr,
        ..
    } = interest_rates;

    Ok(InterestRateStateChanges {
        new_asset_share_value: calc_accrued_interest_payment_per_period(
            lending_rate_apr,
            time_delta,
            asset_share_value,
        )
        .ok_or_else(math_error!())?,
        new_liability_share_value: calc_accrued_interest_payment_per_period(
            borrowing_rate_apr,
            time_delta,
            liability_share_value,
        )
        .ok_or_else(math_error!())?,
        insurance_fees_collected: calc_interest_payment_for_period(
            insurance_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        group_fees_collected: calc_interest_payment_for_period(
            group_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        protocol_fees_collected: calc_interest_payment_for_period(
            protocol_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
    })
}
