### Title
Recovery claim rate can be recomputed after first claim, breaking pro-rata distribution - (File: contracts/DefaultDistributor.sol)

### Summary
`DefaultDistributor` distributes underlying tokens to defaulted tranche holders at a fixed `rate` computed when `setIsActive(true)` is called. However, `setIsActive` can be invoked again after claims have already occurred — toggled off and back on by the owner. On re-activation, `rate` is recomputed as `balanceOf(this) * 1e18 / trancheToken.totalSupply()`, but the tranche tokens of users who already claimed were transferred into the distributor rather than burned, so `totalSupply` is unchanged while the underlying balance has shrunk. Later claimers therefore receive a strictly lower rate than earlier claimers, and the residual underlying is permanently stranded in the contract.

### Finding Description
The external report describes distribution parameters being mutable after the first claim, producing unequal payouts to holders of identical claim rights. The idle-tranches analog is the redemption `rate` in `DefaultDistributor.claim` / `setIsActive`:

- `claim` transfers the caller's entire `trancheToken` balance into the distributor and pays `trancheBal * rate / ONE_TRANCHE` of underlying (lines 35–41).
- `setIsActive(true)` sets `rate = IERC20(token).balanceOf(address(this)) * ONE_TRANCHE / IERC20(trancheToken).totalSupply()` (lines 45–51).

There is no "first claim already happened" guard and no check that the distributor's `trancheToken` balance is zero when recomputing `rate`. Sequence:

1. Default is finalized; the distributor holds `U` underlying and `isActive` is set, giving `rate = U / S` where `S` is the (now frozen) tranche total supply.
2. Some holders claim. Their tranche tokens are pulled into the distributor (not burned), so `S` is unchanged but the underlying balance drops to `U' < U`.
3. `setIsActive(false)` then `setIsActive(true)` (both callable by the honest owner, e.g., to pause/restart claims) recomputes `rate' = U' / S < rate`, because claimed tranche tokens still count in `totalSupply`.
4. All subsequent claimers receive `rate'` — less than pro-rata — and `rate * claimedTranches - rate' * claimedTranches` worth of underlying can never be claimed, since every later claim only pays `rate'` and the contract only releases the rest via the owner-only `transferToken` escape hatch.

### Impact Explanation
Broken invariant: fair burn / one unit of tranche, one fixed redemption share. Unclaimed yield is permanently frozen: after any re-activation, `sum(all payouts at rate') < U`, so a portion of the default-recovery fund is locked in `DefaultDistributor` with no user-facing withdrawal path. With, e.g., 50% of supply already claimed, the recomputed rate is roughly half the intended rate, and half the remaining recovery funds are stranded. `transferToken` can rescue funds only to an owner-chosen address; it does not restore pro-rata payouts.

### Likelihood Explanation
Triggering requires only the privileged-but-honest owner calling `setIsActive` twice after claims began — a plausible operational action (pausing claims during a pause/emergency, then resuming). No attacker transaction is needed; per the threat model, privileged calls are honest but their sequencing is in scope. Note the analogous in-scope IdleCreditVault default-recovery claim path (`_claimDefaulted*` / `_transferDefaultRecovery`) could not be fully verified within this analysis, but the `DefaultDistributor` surface alone exhibits the bug class.

### Recommendation
- Disallow changing `isActive` from `true` back to `false` and back to `true` once `rate` has been set and at least one claim occurred — e.g., record `claimStarted` on the first `claim` and `require(!claimStarted)` in `setIsActive`, or compute `rate` only once and make it immutable.
- Alternatively, burn claimed tranche tokens (or track `claimedSupply`) and keep `rate` fixed so re-activation cannot dilute remaining claimers.

### Proof of Concept
```solidity
// SPDX-License-Identifier: Apache-2.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {DefaultDistributor} from "../contracts/DefaultDistributor.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract T is ERC20 { constructor() ERC20("T","T") { _mint(msg.sender, 1000e18);} }
contract U is ERC20 { constructor() ERC20("U","U") { _mint(msg.sender, 1000e18);} }

contract RateRecomputeTest is Test {
  function test_rateDilution() public {
    T tranche = new T();
    U und = new U();
    DefaultDistributor d = new DefaultDistributor(address(und), address(tranche), address(this));

    // 2 holders, 500 tranche each
    address a = address(0xA); address b = address(0xB);
    tranche.transfer(a, 500e18); tranche.transfer(b, 500e18);

    und.transfer(address(d), 1000e18);
    d.setIsActive(true); // rate = 1.0
    uint256 r0 = d.rate();

    // A claims at full rate
    vm.startPrank(a); tranche.approve(address(d), type(uint256).max); d.claim(a); vm.stopPrank();
    assertEq(und.balanceOf(a), 500e18);

    // Owner toggles claims off/on (honest sequencing) after first claim
    d.setIsActive(false);
    d.setIsActive(true);
    uint256 r1 = d.rate();
    assertLt(r1, r0); // rate recomputed lower: balance halved, totalSupply unchanged

    // B claims, gets less than pro-rata
    vm.startPrank(b); tranche.approve(address(d), type(uint256).max); d.claim(b); vm.stopPrank();
    assertEq(und.balanceOf(b), 250e18); // 500 tranche * 0.5 rate
    // 250e18 underlying permanently stranded; no claim can ever withdraw it
    assertEq(und.balanceOf(address(d)), 250e18);
  }
}
```
