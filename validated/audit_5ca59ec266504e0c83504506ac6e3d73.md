### Title
Unauthenticated `vault.publicKey.get` requests bypass all authorization and rate limiting, allowing DoS amplification against vault DON nodes via `fanOutToVaultNodes` - (File: core/services/gateway/handlers/vault/handler.go)

### Summary
`handler.HandleJSONRPCUserMessage` explicitly skips `h.requestProcessor.ProcessRequest` for `vaulttypes.MethodPublicKeyGet`, relying solely on an aggressive response cache to bound the resulting load. When the cache is empty (cold start, eviction, or before the first quorum-validated response is received), every unique-ID request from an unauthenticated caller triggers `handlePublicKeyGet` → `fanOutToVaultNodes`, which sends a message to every DON member via `h.don.SendToNode` with no per-sender or global rate limiting on this path.

### Finding Description
In `core/services/gateway/handlers/vault/handler.go`, `HandleJSONRPCUserMessage` handles `MethodPublicKeyGet` before any authorization check: [1](#0-0) 

If `h.getCachedPublicKey()` returns nil, the request is turned into an `activeRequest` and passed to `handlePublicKeyGet`, which forwards it to every DON node: [2](#0-1) [3](#0-2) 

The only guard against duplicate work is `newActiveRequest`'s rejection of an already-in-flight `req.ID`: [4](#0-3) 

This is trivially bypassed by using a unique `req.ID` per call (the only constraint is non-empty and ≤200 chars, checked earlier in the same function): [5](#0-4) 

Unlike the confidentialrelay handler (which has a `nodeRateLimiter`/`globalNodeRateLimiter` gating node responses) or the HTTP-trigger handler (which enforces `h.userRateLimiter.AllowErr` per workflow before any node interaction), the vault handler's `nodeRateLimiter` (seen in `HandleNodeMessage`, line 493) only throttles inbound node **responses**, not the fan-out of unauthenticated user **requests**: [6](#0-5) 

The upstream call chain (`gateway.ProcessRequest` in `core/services/gateway/gateway.go`) performs no rate limiting either — it decodes the request and directly invokes `h.HandleJSONRPCUserMessage`: [7](#0-6) 

The cache-population path (`tryCachePublicKeyResponse`, triggered from `HandleNodeMessage` on `MethodPublicKeyGet`) mitigates steady-state load once a full quorum response has been cached, but there is no rate limiting protecting the window before that first successful cache fill (e.g., at gateway startup, after cache eviction, or if the DON is temporarily unable to reach quorum) — during that window each attacker request multiplies into `len(h.donConfig.Members)` `SendToNode` calls with zero cost to the caller.

### Impact Explanation
This maps to a DoS amplification impact against the vault DON: an unauthenticated caller can repeatedly trigger fan-out to all DON node members with unbounded request volume (bounded only by network/HTTP throughput, not by any application-level quota), since the method explicitly skips the authorization pipeline that would otherwise apply owner/session-based checks, and no substitute rate limiter is applied to this code path.

### Likelihood Explanation
No preconditions are required — any HTTP/gateway client can reach `vault.publicKey.get` with zero credentials. The attack is trivially repeatable (unique `req.ID` per call defeats the only existing dedup mechanism), and is fully effective during any window where the public-key cache is not yet populated (startup, restart, cache eviction). Feasibility is high; the code path and lack of a limiter are directly confirmed in the source.

### Recommendation
Apply an unauthenticated-request rate limiter (per source IP/connection or per gateway session, similar to `nodeRateLimiter`/`userRateLimiter` patterns used elsewhere in the gateway handlers) to the `MethodPublicKeyGet` branch of `HandleJSONRPCUserMessage`, specifically guarding calls to `fanOutToVaultNodes` when the cache is empty, so that cache-miss fan-out cannot be triggered at unbounded volume by an unauthenticated caller.

### Proof of Concept
Go unit test plan (extend `core/services/gateway/handlers/vault/handler_test.go`):
1. Build a `handler` via `setupHandler`/`newHandlerWithAuthorizer` with a mocked `don` whose `SendToNode` is instrumented with a call counter.
2. Ensure the public-key cache is empty (no prior successful `HandleNodeMessage` for `MethodPublicKeyGet`).
3. Loop N times (e.g., N=1000), calling `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request{ID: uuid.New().String(), Method: vaulttypes.MethodPublicKeyGet}, callback)` with a fresh `callback` each iteration, without ever populating the cache (do not call `HandleNodeMessage`).
4. Assert that `don.SendToNode` is called exactly `N * len(donConfig.Members)` times — i.e., unbounded, growing linearly with attacker requests — and that no equivalent of `h.nodeRateLimiter.Allow` (or similar) is invoked to cap this before reaching `fanOutToVaultNodes`.
5. To demonstrate the fix, add a rate limiter to the cache-miss branch and re-run the same test expecting `SendToNode` call count to plateau at a configured cap regardless of N.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
