### Title
Global unbounded `savedCallbacks` map allows a single low-privileged sender to trigger eviction of other users' pending trigger callbacks - (core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` stores every valid `web_api_trigger` request from any signer into a single shared `h.savedCallbacks` map keyed only by `MessageId`, with no per-sender partitioning or quota. `pruneCallbacks` evicts purely by global count/age (`entries[:len(entries)-maxSize/2]`), so a burst of requests from one attacker can evict other users' un-expired, still-pending callbacks from the map before their node responses arrive.

### Finding Description
`HandleLegacyUserMessage` (line 341) validates the signed message (signature, timestamp, method) and then unconditionally inserts a `savedCallback` into the shared map: [1](#0-0) 
There is no per-sender allowlist or rate-limit check at this point — the code explicitly marks this as unimplemented: `// TODO: apply allowlist and rate-limiting here` [2](#0-1) . The `nodeRateLimiter` field exists in the handler but is never invoked from `HandleLegacyUserMessage` or anywhere that gates user message insertion into `savedCallbacks` (confirmed by searching all `nodeRateLimiter.*` call sites in this file — none appear in the ingestion path).

`pruneCallbacks` (line 299) periodically removes expired entries, then, if the map exceeds `MaxSavedCallbacks`, sorts *all* remaining entries by creation time and deletes the oldest half regardless of whose message it is: [3](#0-2) 

Since the map is shared across the entire DON handler (not partitioned by sender/user), any signer permitted to call `MethodWebAPITrigger` (any authorized signer for that DON per `msg.Validate()`/signature check) can insert enough entries to push the total above `MaxSavedCallbacks`, causing older-but-still-live entries belonging to other users to be deleted. Once a victim's entry is deleted, when the legitimate `HandleNodeMessage` response for that request eventually arrives, the lookup in `savedCallbacks` will miss it (analogous to the dummy handler's `found` check pattern in `core/services/gateway/handlers/handler.dummy.go` lines 98-108), so the victim's callback is never resolved and the gateway `ProcessRequest` caller times out via `callback.Wait(ctx)`, returning `RequestTimeoutError` — i.e., their response is dropped/misrouted-as-lost.

### Impact Explanation
This is a cross-user denial of service against workflow trigger responses: a single misbehaving but otherwise authorized sender for the DON can cause other users' `web_api_trigger` requests to silently time out by flooding the shared, unpartitioned `savedCallbacks` map, violating the intended per-request isolation. This maps to a "Denial of Service" / availability-impact bounty class rather than a fund-loss or auth-bypass class, since no unauthorized data access or fund movement occurs — only loss/delay of a legitimate response.

### Likelihood Explanation
Exploitability requires only that the attacker be a signer authorized to send `MethodWebAPITrigger` messages to the same DON handler (a low-privileged but valid signer per the existing signature-verification gate) — no operator or host access is needed. However, the default `MaxSavedCallbacks` is 20000 and prune runs every `CallbackPruneIntervalSec` (default 30s), so an attacker must sustain roughly >10,000 in-flight (unresolved) requests within a single prune interval to force eviction, which is a substantial but plausible burst for an automated/scripted attacker with no request-rate gating in front of this code path (the `// TODO: apply allowlist and rate-limiting here` comment confirms no rate limiting currently occurs before insertion). The comment `// could briefly exceed under heavy load` at line 44 indicates this behavior is a known, accepted limitation of the current design rather than a guarded invariant.

### Recommendation
Partition `savedCallbacks` (or apply eviction/quota) per sender/signer rather than using a single global LRU-by-age map, and/or enforce a per-sender in-flight request cap before insertion (implementing the still-outstanding rate-limiting/allowlist TODO) so that one sender's volume cannot affect another sender's callback lifecycle. At minimum, prioritize eviction of the *requesting* sender's own oldest entries when a quota is hit, instead of a purely global oldest-first eviction.

### Proof of Concept
Go unit test extending `TestPruneCallbacks` in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Set `handler.config.MaxSavedCallbacks = N` (small, e.g. 4).
2. Seed `handler.savedCallbacks` with one "victim" entry with `createdAt = now` (fresh, unexpired, simulating a legitimate pending trigger from user A).
3. Seed `N` "attacker" entries with `createdAt` timestamps between `now-ε` and `now` (simulating a burst from a single attacker sender, all newer than the victim would be if attacker floods right after victim's request).
4. Actually to demonstrate cross-user impact, make the victim's entry the *oldest* live (non-expired) entry, and add attacker entries that are newer, all within `CallbackMaxAgeSec`.
5. Call `handler.pruneCallbacks()`.
6. Assert the victim's entry (`"victim"`) has been deleted from `handler.savedCallbacks` even though it had not expired, solely because the attacker inflated total count above `MaxSavedCallbacks`, demonstrating `require.NotContains(t, handler.savedCallbacks, "victim")`.
7. Optionally extend to a handler-level integration test: call `HandleLegacyUserMessage` for a victim message, then loop calling `HandleLegacyUserMessage` with attacker-signed messages until `len(handler.savedCallbacks) > MaxSavedCallbacks`, invoke `pruneCallbacks`, then simulate the victim's `HandleNodeMessage` response arriving and assert `cb.Wait(ctx)` times out/returns no result because the map entry was evicted.

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
