### Title
Missing subscriber/allowlist check in `HandleLegacyUserMessage` allows unauthorized `MethodWebAPITrigger` requests to be forwarded to all DON nodes - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` only validates payload decoding, timestamp presence, message staleness, and the method name before broadcasting the incoming request to every member of `h.donConfig.Members` via `don.SendToNode`. There is no check that the message sender is an authorized subscriber/allowlisted user for the target DON, and the code even contains a `// TODO: apply allowlist and rate-limiting here` comment acknowledging the gap.

### Finding Description
The gateway HTTP endpoint accepts a JSON-RPC-wrapped `api.Message`, which is parsed and cryptographically validated via `msg.Validate()` (called in `common.ValidatedMessageFromReq`) — this only confirms the signature matches the claimed `msg.Body.Sender` address, i.e., that the sender holds *some* valid ECDSA key, not that the sender is authorized for the target DON/workflow.

The message is then routed by method name to `handler.HandleLegacyUserMessage` [1](#0-0) . Inside this function, the only checks performed are:
1. JSON payload decoding into `webapicap.TriggerRequestPayload` [2](#0-1) 
2. Presence of a non-zero `Timestamp` [3](#0-2) 
3. Message staleness against `h.config.MaxAllowedMessageAgeSec` [4](#0-3) 
4. Method equals `MethodWebAPITrigger` [5](#0-4) 

Immediately after these checks, the code converts the message to a request and unconditionally broadcasts it to every DON member: [6](#0-5) . There is no lookup of `msg.Body.Sender` against a per-DON/per-workflow allowlist or subscription table anywhere in this path, and the code explicitly flags this as a `TODO`.

Any attacker who can produce a validly-signed `api.Message` (any ECDSA keypair, no registration required) with `Method = "web_api_trigger"`, a fresh `Timestamp`, and the target `DonId` will have that message accepted and relayed to `don.SendToNode` for all `h.donConfig.Members`, triggering workflow capability execution resources on nodes for a DON/workflow the attacker has no relationship with.

### Impact Explanation
This breaks the authorization-exactness invariant that a trigger request must be bound to an authorized subscription/allowlisted sender for the target DON. Concretely it enables unauthorized triggering of `web_api_trigger` workflow capability executions on arbitrary DONs, causing unauthorized job/workflow runs and unbounded resource consumption (a node-level DoS/unauthorized-execution vector) — this matches the "unauthorized job run" / authorization bypass impact class.

### Likelihood Explanation
Feasibility is high: the only precondition is possessing an arbitrary ECDSA keypair (self-generated, free) and knowledge of a target `DonId` (not secret — DON IDs are generally discoverable/public configuration). No registration, subscription, or prior interaction with the DON is required. The request is a single signed HTTP call to the gateway; it is trivially repeatable and scriptable against any configured DON.

### Recommendation
Add an authorization step in `HandleLegacyUserMessage` (or upstream in message validation) that checks `msg.Body.Sender` against a configured per-DON/per-workflow allowlist or active subscription registry before forwarding to `don.SendToNode`; reject with an authorization error (e.g., a new `api.UnauthorizedError` JSON-RPC error code) if the sender is not authorized. Implement the currently-noted `TODO: apply allowlist and rate-limiting here`.

### Proof of Concept
Go handler-level test plan (extending `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct a `handler` via `NewHandler` with a `donConfig` containing known DON members and a mock `handlers.DON`.
2. Generate a fresh ECDSA key not present in any DON/user allowlist config.
3. Build an `api.Message` with `Method: MethodWebAPITrigger`, a valid recent `Timestamp` in the `webapicap.TriggerRequestPayload`, target `DonId` set to the handler's DON, and sign it with the unregistered key so `msg.Validate()`/signature checks pass.
4. Call `h.HandleLegacyUserMessage(ctx, msg, mockCallback)`.
5. Assert (current behavior, demonstrating the bug): `don.SendToNode` mock is invoked once per `donConfig.Members` entry and `callback.SendResponse` is not called with an authorization error — i.e., the request is *not* rejected.
6. Expected behavior post-fix: assert `SendToNode` is never called and `callback.SendResponse` returns an authorization/allowlist error code (e.g. via `codec.EncodeNewErrorResponse` with a new unauthorized-sender error code).

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}
