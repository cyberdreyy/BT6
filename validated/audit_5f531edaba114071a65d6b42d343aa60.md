### Title
Unauthenticated `/health` and `/readyz` (non-public) endpoints leak internal service/check names and raw error output - ([File: core/web/router.go])

### Summary
`healthRoutes` registers `/readyz`, `/health`, and `/health.txt` directly on the unauthenticated `api` route group with no `auth.Authenticate` middleware, unlike almost every other informational endpoint in the router. `Readyz` and `Health` return per-check names and raw `err.Error()` strings from the node's `HealthChecker`, which can include internal service/subsystem identifiers and underlying error text (e.g., dial/connection errors that can embed RPC endpoint hosts) to any anonymous caller.

### Finding Description
In `core/web/router.go`, `healthRoutes` is called with the bare `api` group and adds no authentication middleware: [1](#0-0) 
Compare this to every other sensitive group in the same file (`v2Routes`, `debugRoutes`), which is wrapped with `auth.Authenticate(...)`.

`HealthController.Readyz` (invoked via `?full` query param) and `HealthController.Health` iterate over `checker.IsReady()` / `checker.IsHealthy()` results and build a `presenters.Check` list containing the check `Name` and `Output` (which is `err.Error()` for any failing subsystem): [2](#0-1) [3](#0-2) 

The code even acknowledges this exact risk with `PublicReadyz`, whose doc comment explicitly states its purpose is to avoid "leaking internal service state on publicly reachable endpoints" by never returning per-check details: [4](#0-3) 
However, `PublicReadyz` is registered as an *additional* route (`/public-readyz`) alongside the verbose `/readyz` and `/health` — it does not replace or gate them. The verbose endpoints remain reachable by anyone without credentials, and `checker.IsReady()`/`IsHealthy()` error strings originate from underlying service health checks (e.g., chain clients, head trackers, relayers), whose `Error()` text can include connection/dial failure details that may reference configured RPC endpoints or subsystem names, along with the full list of registered check names (revealing which chains, relayers, or plugins are configured on the node).

No auth middleware, role wrapper, or presenter redaction filters this response before it is returned to the caller.

### Impact Explanation
An unauthenticated network client can enumerate the node's internal check/service topology (chain IDs, subsystem names, plugin/LOOP names) and any failing-check error text via `GET /health` or `GET /readyz?full=1`. This is an information-disclosure issue (internal topology/config leak) rather than direct fund loss or key exposure, but it aids reconnaissance for further targeted attacks and violates the intended "minimal disclosure" design that the codebase itself documents via `PublicReadyz`.

### Likelihood Explanation
Trivial and fully unauthenticated: any anonymous HTTP client can send `GET /health` or `GET /readyz?full=1` with no credentials, no rate-limit bypass needed (only the generic authenticated-tier rate limiter applies), and repeat indefinitely.

### Recommendation
Restrict `/readyz` (with `full`) and `/health` to authenticated/admin sessions, or strip per-check `Output`/`Name` details for anonymous requests (mirroring the `PublicReadyz` behavior), reserving verbose output for an authenticated route.

### Proof of Concept
Handler-level integration test:
1. Build the router via `NewRouter` with a mock `chainlink.Application` whose `HealthChecker` reports one failing check with `Output` containing a string resembling an internal RPC host (e.g., `"dial tcp 10.0.0.5:8545: connect: connection refused"`).
2. Issue `GET /health` and `GET /readyz?full=1` with no `Authorization`/session cookie.
3. Assert response status is not 401/403 (currently 207/200/503) and response body contains the check `Name` and `Output` fields verbatim — demonstrating disclosure to an anonymous caller.
4. Contrast with `GET /public-readyz`, asserting it returns only a bare status code with no body, confirming the discrepancy between the two endpoints.

// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {
	case gin.MIMEJSON:
		break // default

	case gin.MIMEHTML:
		if err := newCheckTree(checks).WriteHTMLTo(c.Writer); err != nil {
			hc.App.GetLogger().Errorw("Failed to write HTML health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return

	case gin.MIMEPlain:
		if err := writeTextTo(c.Writer, checks); err != nil {
			hc.App.GetLogger().Errorw("Failed to write plaintext health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return
	}

	slices.SortFunc(checks, presenters.CmpCheckName)
	jsonAPIResponseWithStatus(c, checks, "checks", status)
}
