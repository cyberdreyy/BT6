### Title
Missing authentication/role gate on LOOP registry routes (discovery, plugin metrics, plugin pprof) - ([File: core/web/router.go])

### Summary
The LOOP plugin registry routes registered by `loopRoutes` (`/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`) are mounted directly on the bare `api` router group, which carries no authentication middleware at all — not even the weakest 'view' role check applied elsewhere in the router. Any unauthenticated client can therefore invoke `NewLoopRegistryServer`'s handlers to enumerate registered LOOP plugins and proxy requests into each plugin's internal `/metrics` and `/debug/pprof/*` HTTP endpoints.

### Finding Description
In `core/web/router.go`, `NewRouter` builds an `api` group with only rate-limiting and session-cookie middleware (no `auth.Authenticate*`): [1](#0-0) 
`loopRoutes(app, api)` registers the LOOP registry endpoints straight on this unauthenticated group: [2](#0-1) 
Contrast this with every other sensitive route in the same file, which is nested under `authv2` (requiring token/session auth) and frequently wrapped with `auth.RequiresEditRole`/`auth.RequiresAdminRole`/`auth.RequiresRunRole` (e.g. `debugRoutes` requires `auth.Authenticate` at minimum, `metricRoutes(authv2)` for the node's own pprof is nested inside the authenticated `authv2` block). The LOOP registry routes have no such wrapper at all.

`NewLoopRegistryServer` (`core/web/loop_registry.go`) builds handlers that take the attacker-controlled `:name` path parameter, look it up in the plugin registry, and forward the request to the plugin's internal Prometheus/pprof HTTP port on `loopHostName`: [3](#0-2) [4](#0-3) 
Because the route itself has zero role/authentication gate, any network client that can reach the node's web server — including a completely unauthenticated caller, which is strictly weaker than the 'view' role assumed by the question — can invoke these handlers.

### Impact Explanation
This is a genuine authorization/authentication gap: the side effect (proxying into internal plugin debug/metrics/pprof interfaces and returning their output to the caller) requires no credential whatsoever, whereas comparable functionality elsewhere in the router (the node's own `/debug/pprof/*`) is gated behind `auth.Authenticate`. Exposed data includes plugin metrics and pprof profiles/goroutine dumps/heap dumps, which can leak internal state, memory contents, and service topology of LOOP plugins, and gives an unauthenticated attacker a reconnaissance/DoS primitive (e.g. triggering long-running CPU profiles via `seconds` query param) against internal plugin processes. This does not, however, directly demonstrate key export or transaction submission — the handlers only proxy to the plugin's own metrics/pprof HTTP server, not to admin/key-management endpoints — so the "node takeover" characterization in the prompt is not substantiated by the code; the concretely provable impact is unauthenticated information disclosure / internal service exposure, which is still a valid missing-authorization bug matching "route gate weaker than the side effect."

### Likelihood Explanation
Trivial and fully repeatable: no credentials, tokens, or sessions of any kind are required — a bare unauthenticated HTTP GET/POST to `/discovery`, `/plugins/<name>/metrics`, `/plugins/<name>/debug/pprof/<profile>`, or `/plugins/<name>/debug/pprof/symbol` succeeds against any node running LOOP plugins.

### Recommendation
Move `loopRoutes(app, api)` (or at minimum the plugin-metrics/pprof/discovery handlers) under an authenticated group with an explicit role wrapper consistent with the sensitivity of exposing internal plugin debug/pprof data (e.g. `auth.RequiresAdminRole` or at least `auth.Authenticate` + `auth.RequiresEditRole`), mirroring how `debugRoutes`/`metricRoutes` are gated for the node's own pprof endpoints.

### Proof of Concept
Go handler-level integration test plan (using `httptest` against the router returned by `web.NewRouter`):
1. Build a test `chainlink.Application` mock with a `LoopRegistry` containing one registered plugin (`p.EnvCfg.PrometheusPort` pointed at a local `httptest.Server` stub implementing `/metrics` and `/debug/pprof/*`).
2. Construct the router via `NewRouter(app, nil)` without performing any login/session/token setup.
3. Send `GET /discovery` with no `Authorization` header and no session cookie; assert `200 OK` and that JSON target groups for the registered plugin are returned (proving zero-auth read access).
4. Send `GET /plugins/<name>/metrics` unauthenticated; assert `200 OK` with body from the stub plugin metrics server.
5. Send `GET /plugins/<name>/debug/pprof/goroutine` and `POST /plugins/<name>/debug/pprof/symbol` unauthenticated; assert both succeed (`200 OK`) and return the stub pprof body.
6. Repeat step 3-5 using a session authenticated only with `view` role (`sessions.User{Role: RoleView}`) to show identical (unrestricted) access, confirming no role differentiation exists.
7. Compare against `/v2/debug/pprof/*` (the node's own pprof, `metricRoutes(authv2)`), showing that same-class endpoint correctly returns `401 Unauthorized` when unauthenticated — demonstrating the inconsistency/gap for the LOOP registry routes.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
