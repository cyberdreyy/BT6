### Title
Unauthenticated flood of `MethodPublicKeyGet` bypasses per-sender rate limiting and forces unbounded DON fan-out — ([File: core/services/gateway/handlers/vault/handler.go])

### Finding Description
`handler.HandleJSONRPCUserMessage` explicitly skips authorization for `vaulttypes.MethodPublicKeyGet` because the method is intentionally public: [1](#0-0) 

The only mitigation the code relies on is an in-memory cache (`h.cachedPublicKeyGetResponse`/`h.cachedPublicKeyObject`), with the comment "we cache this value quite aggressively so don't need to worry about DoS." On a cache miss, every request calls `h.newActiveRequest` and `h.handlePublicKeyGet`, which calls `h.fanOutToVaultNodes` and sends a JSON-RPC request to **every DON member** via `h.don.SendToNode`: [2](#0-1) [3](#0-2) 

`h.nodeRateLimiter` (built from `Config.NodeRateLimiter`, containing `PerSenderRPS`/`PerSenderBurst`) is only invoked in `HandleNodeMessage`, keyed by `nodeAddr` — i.e. the identity of the responding DON node, not the identity of the original unauthenticated caller: [4](#0-3) 

There is no `UserRateLimiter`/per-sender limiter field in the vault handler's `Config` struct at all (compare to `core/services/gateway/handlers/capabilities/v2/http_handler.go`, which has a distinct `userRateLimiter` for its public-facing trigger path): [5](#0-4) 

The request path from the wire is: `httpserver.go` `handleRequest` → `gateway.go` `ProcessRequest` → `handler.HandleJSONRPCUserMessage`. The HTTP layer only enforces a body-size limiter, not a per-sender/per-IP request-rate limiter: [6](#0-5) [7](#0-6) 

`newActiveRequest` only rejects duplicate request IDs, so an attacker trivially avoids that check by using a fresh UUID per request: [8](#0-7) 

The public-key cache is populated only after a successful periodic refresh, which first fires one minute after `Start()` (via `tickerVaultPublicKeyRefresh := h.clock.NewTicker(1 * time.Minute)`), or after a user-triggered cache-miss fetch succeeds: [9](#0-8) 

During that startup window (and any period where the cache is unset, e.g. before the first successful fetch), an unauthenticated attacker sending many concurrent `MethodPublicKeyGet` requests will trigger one `fanOutToVaultNodes` call (to all DON members) per request, entirely unthrottled by caller identity.

### Impact Explanation
This is a resource-exhaustion / quota-bypass issue: an unauthenticated caller can generate unbounded fan-out traffic to every vault DON member and unbounded `activeRequest` map growth in the gateway, without any per-sender throttle applying to the request-issuing side. This matches the "resource exhaustion / DoS" and "allowlist/quota bypass" impact classes referenced in the prompt, since the code's only documented DoS mitigation (aggressive caching) is not actually a rate limit and does not cover the pre-cache window.

### Likelihood Explanation
No credentials, allowlist entry, or authorization are required — `MethodPublicKeyGet` is explicitly exempted from `h.requestProcessor.ProcessRequest` authorization. The attack is trivially repeatable by any HTTP client that can reach the gateway's user-facing port, requires only varying the JSON-RPC `id` field to bypass the duplicate-ID check, and is most impactful right after gateway (re)start or whenever the cache is unpopulated.

### Recommendation
Add an explicit per-sender (e.g., per source IP or per connection identity) rate limiter that gates the `MethodPublicKeyGet` cache-miss path (and ideally all incoming user requests) before calling `h.newActiveRequest`/`h.fanOutToVaultNodes`, similar to the `userRateLimiter` pattern used in `core/services/gateway/handlers/capabilities/v2/http_handler.go`. Additionally, consider proactively populating the cache synchronously at `Start()` (rather than waiting for the first 1-minute tick) to minimize the exposure window.

### Proof of Concept
Go unit test plan (extends `core/services/gateway/handlers/vault/handler_test.go`):
1. Construct a `handler` via `newHandlerWithAuthorizer` with a DON of N mock members and no pre-populated cache (`cachedPublicKeyGetResponse == nil`).
2. Mock `don.On("SendToNode", ...)` to count invocations per call, and never respond (simulating cold DON / slow response), keeping `cachedPublicKeyObject` nil.
3. Issue, from a single unauthenticated "identity" (no `req.Auth`), M concurrent `HandleJSONRPCUserMessage` calls with method `vaulttypes.MethodPublicKeyGet` and distinct `req.ID` values, well above any reasonable `PerSenderBurst`/`PerSenderRPS` (e.g., M=1000).
4. Assert `don.SendToNode` was called `M * N` times (no reduction from any rate limiter) and that `len(h.activeRequests)` grew to M, demonstrating there is no per-sender throttle applied to the anonymous caller before fan-out — i.e., the test should fail an expected assertion like "`SendToNode` call count does not exceed configured `PerSenderBurst`" because no such check exists in the code path.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
