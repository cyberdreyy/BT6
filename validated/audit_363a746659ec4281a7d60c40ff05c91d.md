### Title
Masking store silently resets when its file is deleted mid-job, letting a job's own script permanently disable secret masking for the rest of the job - (File: commands/helpers/internal/store/store.go)

### Summary
`store.Open` treats a missing `masking.db` as "first run" and silently regenerates a fresh, empty store with a new key instead of failing [1](#0-0) . Because `NewProxy`/`store.Open` is invoked fresh for every `proxy-exec`-wrapped command in the job rather than once for the whole job [2](#0-1) , and the file lives in the job's own build/temp directory that the job itself controls, a job step that deletes `masking.db` between two wrapped commands causes all previously-registered masked phrases to be forgotten with no error, and later trace output containing those phrases is no longer masked.

### Finding Description
`Store.Add` appends an encrypted phrase to `masking.db` and `Store.List` decrypts and returns every entry currently in that file [3](#0-2) . `openFile` on Windows deliberately opens the handle with `FILE_SHARE_DELETE` so the path can be removed while a handle is open, per its own comment [4](#0-3) , and this is exercised/confirmed by `TestDeleteOpenFile`, which shows `os.Remove(pathname)` succeeds with no error while the store handle is open [5](#0-4) . On the *same* open handle, Windows delete-on-close semantics mean the existing data is still reachable until the handle is closed — the acute risk isn't that a live `List()` call on the same handle instantly returns nothing.

The real, reachable path is architectural: each `proxy-exec` invocation (one per wrapped shell command in the job script) calls `store.Open(dir)` anew, and `Close()`s it when that command finishes [6](#0-5) [7](#0-6) . `Open()` decides whether the store is "new" purely by `os.Stat(pathname)`, and if the file doesn't exist it regenerates the key and lets `openFile`'s `OPEN_ALWAYS` create a brand-new, empty file [8](#0-7) . This exact "recreate on missing file" behavior is documented and asserted by `TestOpen/recreates_key_when_db_missing`, which shows that after removing `masking.db`, a fresh `Open()` + `List()` returns an empty slice with no error, even though a secret was previously `Add`ed [9](#0-8) .

Since `masking.db` sits inside the job's own build directory (writable/deletable by the job's own commands — that's the entire reason `FILE_SHARE_DELETE` was added), an unprivileged job script can simply delete that file between two wrapped command invocations. The next `proxy-exec` invocation's `store.Open` silently fabricates a new, empty store instead of erroring, and the `addmask` masking layer built on top of `store.List` (via `addmask.New(db, ...)` [10](#0-9) ) then has no knowledge of previously-registered phrases. There is no check anywhere in `Open`/`List`/`Add` that distinguishes "legitimately empty new store" from "store that existed and was deleted mid-job," and no error surfaces to the pipeline or to Runner's own diagnostics.

### Impact Explanation
Previously-masked secret phrases (e.g. masked CI/CD variables or values explicitly registered for masking earlier in the job) stop being redacted in subsequent trace/log lines for the remainder of the job, once the underlying `masking.db` is removed. This is a direct violation of the "masked values must never leak through traces once registered" invariant, exposing secret material in the persisted job log to anyone with log-view access.

### Likelihood Explanation
Preconditions are trivially met: `masking.db` lives in the job's own writable build/temp directory (`RUNNER_TEMP_PROJECT_DIR`), so any job script step has delete access by design [11](#0-10) . All that's required is a job step (e.g. `del` on Windows, `rm` on Unix — the same "recreate on missing" logic lives in the cross-platform `store.go`, not just the Windows file) that removes the store file before a later step that would emit the secret. This is fully repeatable and requires no elevated privileges, race conditions, or timing tricks.

### Recommendation
Make `store.Open` fail loudly instead of silently recreating the store when `masking.db` unexpectedly disappears mid-job (e.g., track store existence/identity via a job-scoped in-memory sentinel or an inode/creation-time check, and treat re-creation after the job has started as a hard error). Alternatively, hold a single long-lived `Store`/file handle for the entire job (instead of reopening per `proxy-exec` invocation) so that deletion of the path cannot silently swap in a fresh empty file, and have Runner treat a missing masking store as a job-failing condition rather than a quiet reinitialization.

### Proof of Concept
Go unit test extending `store_test.go`:
```go
func TestStoreResetOnMidJobDeletion(t *testing.T) {
    dir := t.TempDir()

    db, err := Open(dir)
    require.NoError(t, err)
    require.NoError(t, db.Add("super-secret"))
    db.Close() // simulates end of one proxy-exec invocation

    // attacker-controlled job step deletes the store file
    require.NoError(t, os.Remove(filepath.Join(dir, "masking.db")))

    // next proxy-exec invocation for a later job step
    db2, err := Open(dir)
    require.NoError(t, err) // no error surfaced

    items, err := db2.List()
    require.NoError(t, err)
    require.Empty(t, items) // "super-secret" is gone; addmask will no longer mask it
}
```
Expected assertion failure/behavior to fix: `Open` after mid-job deletion should either return an error or otherwise prevent silent loss of previously-registered phrases, rather than returning `nil` error with an empty list.

```go
func (s *Store) List() ([]string, error) {
	buf := bufio.NewReader(io.NewSectionReader(s.f, 32, math.MaxInt64))

	var results []string
	for {
		line, err := buf.ReadString('\n')
		if err != nil {
			if errors.Is(err, io.EOF) {
				return results, nil
			}
			return results, err
		}

		msg, err := base64.StdEncoding.DecodeString(line)
		if err != nil {
			return results, fmt.Errorf("decoding msg: %w", err)
		}

		if len(line) < s.c.NonceSize() {
			return results, fmt.Errorf("encrypted message length too small")
		}

		nonce, ciphertext := msg[:s.c.NonceSize()], msg[s.c.NonceSize():]
		plaintext, err := s.c.Open(nil, nonce, ciphertext, nil)
		if err != nil {
			return results, fmt.Errorf("opening encrypted message: %w", err)
		}

		results = append(results, string(plaintext))
	}
}

func (s *Store) Add(phrase string) error {
	s.mu.Lock()
	defer s.mu.Unlock()

	if s.closed {
		return os.ErrClosed
	}

	input := []byte(phrase)
	nonce := make([]byte, s.c.NonceSize(), s.c.NonceSize()+len(input)+s.c.Overhead())
	if _, err := rand.Read(nonce); err != nil {
		return err
	}

	line := base64.StdEncoding.EncodeToString(s.c.Seal(nonce, nonce, input, nil)) + "\n"
	if _, err := s.f.Write([]byte(line)); err != nil {
		return err
	}

	if err := s.f.Sync(); err != nil {
		return err
	}

	return nil
}
```

```go
func NewProxy(dir string, stdout, stderr io.Writer) (*Proxy, error) {
	db, err := store.Open(dir)
	if err != nil {
		return nil, err
	}

	pe := &Proxy{store: db}

	pe.addmask, err = addmask.New(db, stdout, stderr)
	if err != nil {
		return nil, err
	}

	return pe, nil
}

func (p *Proxy) Stdout() io.Writer {
	return p.addmask.Get(0)
}

func (p *Proxy) Stderr() io.Writer {
	return p.addmask.Get(1)
}

func (p *Proxy) Close() error {
	p.store.Close()
	return p.addmask.Close()
}
```

```go
// openFile is like os.OpenFile, but adds FILE_SHARE_DELETE, allowing the file
// to be deleted, even when open, on Windows.
func openFile(pathname string) (*os.File, error) {
	p, err := windows.UTF16PtrFromString(pathname)
	if err != nil {
		return nil, fmt.Errorf("converting pathname to UTF16: %w", err)
	}

	h, err := windows.CreateFile(
		p,
		windows.GENERIC_READ|windows.FILE_APPEND_DATA,
		windows.FILE_SHARE_READ|windows.FILE_SHARE_WRITE|windows.FILE_SHARE_DELETE,
		nil,
		windows.OPEN_ALWAYS,
		windows.FILE_ATTRIBUTE_NORMAL,
		0,
	)
	if err != nil {
		return nil, fmt.Errorf("creating file share file: %w", err)
	}

	return os.NewFile(uintptr(h), pathname), nil
```
