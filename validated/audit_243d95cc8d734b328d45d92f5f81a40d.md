### Title
Stale confirmations from removed multisig members still count toward quorum - (File: multisig2/src/lib.rs)

### Summary
`confirm()` tallies quorum from the raw size of the `confirmations: LookupMap<RequestId, HashSet<String>>` set for a request, but a member's earlier confirmation on an *unrelated* still-pending request is never invalidated when that member is later removed via `DeleteMember`/`DeleteKey`. The stored confirmation count diverges from the set of currently authorized (live) members, letting a request execute with fewer than `num_confirmations` genuine, currently-trusted approvals.

### Finding Description
`delete_member` at `multisig2/src/lib.rs:355-379` removes the departing member from `self.members` and cleans up requests/confirmations only for requests *that member itself created* (`self.requests.iter().filter_map(|(k, r)| if r.member == member { Some(k) } else { None })`). It never inspects `self.confirmations` entries belonging to *other* pending requests where that member had already cast a confirmation.

`confirm()` at `multisig2/src/lib.rs:292-315` decides execution purely by `confirmations.len() as u32 + 1 >= self.num_confirmations` — it re-validates only the *new* confirmer via `current_member()`/`assert_valid_request`, but does not re-check that every previously stored confirmer string in the `HashSet<String>` is still an entry in `self.members`.

Consequently: if member A confirms request X (partial confirmation, below quorum), and A is subsequently removed from the multisig by an unrelated `DeleteMember` request (which only checks `self.members.len() - 1 >= self.num_confirmations`, not whether A has outstanding confirmations elsewhere), A's confirmation on X is never purged. When the remaining live members later confirm X, A's stale vote is still counted, so X executes with one fewer *live* approval than `num_confirmations` actually requires. The same gap exists in the older `multisig/src/lib.rs` via `MultiSigRequestAction::DeleteKey` (lines 198-216), which purges only requests created by the deleted key, not its confirmations on other requests.

This breaks the authorization binding the contract is meant to guarantee: "K live members must confirm before receiver_id executes an action," which for `Transfer`, `AddKey`/`AddMember`/`DeleteMember`, `FunctionCall`, and `DeployContract` actions gates control of the account and its funds.

### Impact Explanation
A request (including a `Transfer` of the account's NEAR balance, or an `AddKey`/`AddMember` action that seizes full control of the multisig account) can be executed with confirmations from only `num_confirmations - 1` genuinely current members plus one stale vote from a removed/ousted member. This is an authorized-party threshold being crossed with fewer than the required live signers — funds can move, or the account's key/member set can be altered, without true quorum consent. This matches the Critical impact category: "a multisig request executed below threshold."

### Likelihood Explanation
Requires only ordinary multisig operation, not a bug in access-control: any member proposes and partially confirms a request, is later removed for a legitimate/unrelated reason (compromised key, offboarding, malicious behavior discovered), and the remaining members are unaware their subsequent confirmations combine with a no-longer-trusted vote to reach quorum. No privileged bypass or redeploy is needed — it is a natural sequence of member churn combined with a long-lived pending request (requests persist until confirmed or explicitly deleted after the 15-minute cooldown).

### Recommendation
When removing a member in `delete_member` (and `DeleteKey` in the legacy `multisig` contract), iterate all entries in `self.confirmations` and strip the departing member's identifier from every request's confirmation set, not just requests they created. Alternatively, re-validate every entry in a request's confirmation `HashSet` against `self.members` at `confirm()` time before counting quorum, discarding stale votes from members who are no longer current.

### Proof of Concept
1. Initialize a `multisig2` contract with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request` then `confirm` on request `X = Transfer{amount}` — `confirmations[X] = {A}` (1/3).
3. Separately, members confirm a `DeleteMember{member: A}` request (requires 3 confirmations from B, C, D — none of whom need to touch X). `delete_member` removes `A` from `self.members`, but `self.confirmations[X]` still contains `A` because `X.member != A` (X was not created by A in this scenario, or even if created by A, only requests *created by* A get purged — a confirmation A gave on a request created by someone else survives).
4. `B` calls `confirm(X)` → `confirmations[X] = {A, B}` (2/3, still below quorum, allowed since only the confirming party is validated).
5. `C` calls `confirm(X)` → `confirmations.len() + 1 = 3 >= num_confirmations(3)` → `execute_request` fires the `Transfer`, even though only 2 of the 3 confirmations (`B`, `C`) came from members currently in `self.members`; `A`'s vote is stale but still counted.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
