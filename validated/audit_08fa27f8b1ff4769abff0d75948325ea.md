### Title
Reward distributed to shares present at ping time, not shares held throughout the rewarded epoch, enabling one-block "flash-stake" reward capture - ([File: staking-pool/src/internal.rs])

### Summary
`StakingContract::internal_stake` lets any account buy "stake" shares instantly, at the price fixed by `total_staked_balance / total_stake_shares` calculated by the *last* `internal_ping`. Because `internal_ping` only recomputes rewards when the epoch height changes, and the price/points don't discriminate on *when during the previous epoch* a share was bought, an attacker who stakes in the last block of epoch N and unstakes in the first block of epoch N+1 (right after the first `internal_ping` of the new epoch fires) receives a pro-rata cut of the *entire* epoch N reward despite having zero actual validation exposure during epoch N.

### Finding Description
The broken binding: for delegator `i`, `reward_i` should equal `shares_i(t) * reward_rate` integrated only over the time `shares_i(t)` were actually staked *during the rewarded epoch* — i.e. `reward_i ∝ shares_i` held across epoch N. What the code actually implements is `reward_i ∝ shares_i` **at the moment `internal_ping` executes**, regardless of when those shares were minted.

Code path:
1. `stake` / `stake_all` / `deposit_and_stake` all call `internal_ping()` first [1](#0-0) , and while `last_epoch_height == epoch_height` this is a no-op [2](#0-1) . So an attacker can call `deposit_and_stake` at the tail end of epoch N, and `internal_stake` mints shares at the current (pre-reward) price with no reward distribution happening yet [3](#0-2) .
2. Once the epoch height changes (protocol-level, requires no special action), the very next call to any pool method (`ping`, `unstake`, `withdraw`, etc.) triggers `internal_ping`, which now computes `total_reward = total_balance - last_total_balance` — the entire epoch N validation reward that materialized atomically at the epoch boundary — and distributes it by adding `remaining_reward` directly to `self.total_staked_balance`, without reference to how long any given share existed [4](#0-3) . Since price = `total_staked_balance / total_stake_shares`, and the attacker's shares are already counted in `total_stake_shares` at this point, the attacker's balance jumps up proportionally to their share of the pool, exactly as if they had been staked the whole epoch.
3. The attacker then calls `unstake`/`unstake_all`, which calls `internal_ping()` again (no-op, same epoch) and then `inner_unstake`, converting the inflated share value into `account.unstaked` immediately [5](#0-4) . No minimum staking duration or epoch-based lock exists on the `stake` path — only `unstake` imposes a 4-epoch delay before the actual token *transfer*, via `unstaked_available_epoch_height` [6](#0-5) . That delay only postpones withdrawal, not the accounting theft: by the time `withdraw` executes, the reward has already been misappropriated from the accounts that were actually staked throughout epoch N.

Existing guards checked and found insufficient:
- `internal_ping`'s only assertion is `total_balance >= last_total_balance` — it does not gate on when shares were acquired [7](#0-6) .
- The U256 rounding pairs (`num_shares_from_staked_amount_rounded_down/up`, `staked_amount_from_num_shares_rounded_down/up`) only guard against price manipulation via rounding, not against time-of-stake dilution [8](#0-7) .
- No `assert_owner`, `assert_self`, or minimum-holding-period check exists on `stake`, `stake_all`, or `deposit_and_stake`.

### Impact Explanation
Long-term delegators who were staked throughout epoch N have their rightful reward diluted; the attacker walks away with a slice of `remaining_reward` proportional to `X/(T+X)` (where `X` is the attacker's flash-staked amount and `T` is the pre-existing total staked balance), despite contributing zero actual stake-weight to the validator during that epoch. This is an accounting value (`account.unstaked`/`stake_shares`) diverging from the economic reality that other delegators rely on to settle their claims, and after the 4-epoch unstaking delay the attacker withdraws real NEAR that was never theirs — NEAR leaving the pool account to a party never entitled to it. This matches "High: rewards ... attributed to the wrong party." The attack is fully repeatable every epoch, against any pool, by any account with enough capital to move the needle on `X/(T+X)`.

### Likelihood Explanation
No privileged role is required — any account can call `deposit_and_stake`, then `unstake_all`/`withdraw_all`. The only precondition is timing a stake near an epoch boundary and an unstake right after, both fully attacker-controlled and observable via `env::epoch_height()`/on-chain epoch data. Capital cost is temporary (funds are only "at risk" for roughly one block plus the mandatory 4-epoch unstake delay before final withdrawal, during which the attacker's principal is safely recoverable). The larger the attacker's stake relative to the pool's existing `total_staked_balance`, the larger their share of the stolen reward, making this attractive to well-capitalized actors and trivially repeatable every epoch.

### Recommendation
Reward accrual should not depend on the shareholder snapshot at ping time. Options: (1) require a minimum holding period between `stake` and reward eligibility (e.g., snapshot `total_stake_shares` at the start of the epoch, and only apply reward proportionally to shares that existed since the epoch began — new shares purchased mid/late-epoch shouldn't participate until the next epoch's reward is computed); (2) force `internal_ping` to run and settle rewards before allowing `internal_stake` to mint shares in the same block, and additionally introduce an epoch-delay before newly minted shares become reward-eligible, mirroring the delay already applied to unstaking.

```rust
// staking-pool/src/lib.rs test module (near-sdk testing_env! / Emulator harness already present)
#[test]
fn test_flash_stake_reward_capture() {
    let mut emulator = Emulator::new(owner(), "KuTCtARNzxZQ3YvXDeLjx83FDqxv2SdQTSbiq876zR7".to_string(), zero_fee());

    // Long-term delegator "alice" stakes for the whole epoch.
    emulator.update_context(alice(), ntoy(1_000_000));
    emulator.contract.deposit();
    emulator.amount += ntoy(1_000_000);
    emulator.update_context(alice(), 0);
    emulator.contract.stake(ntoy(1_000_000).into());
    emulator.simulate_stake_call();

    // Simulate the epoch about to earn a reward, but epoch has NOT switched yet.
    let locked_amount = emulator.locked_amount;

    // Attacker "bob" flash-stakes right before epoch switch (internal_ping is a no-op here).
    emulator.update_context(bob(), ntoy(1_000_000));
    emulator.contract.deposit();
    emulator.amount += ntoy(1_000_000);
    emulator.update_context(bob(), 0);
    emulator.contract.stake(ntoy(1_000_000).into());
    emulator.simulate_stake_call();

    // Epoch switches; reward materializes atomically (as env::account_locked_balance jump).
    emulator.skip_epochs(1);
    emulator.locked_amount = locked_amount + ntoy(100_000); // full-epoch reward earned only by alice's real stake

    // Bob immediately unstakes right after the reward-triggering ping.
    emulator.update_context(bob(), 0);
    emulator.contract.unstake_all(); // internal_ping fires here, distributing reward pro-rata to CURRENT shares

    // Assert: bob captured a share of the reward despite 1-block exposure.
    let bob_balance = emulator.contract.get_account_total_balance(bob()).0;
    assert!(bob_balance > ntoy(1_000_000), "bob should not have earned any of alice's epoch reward");

    // Assert: alice's share of the reward is correspondingly diluted below the "held full epoch" expectation.
    let alice_balance = emulator.contract.get_account_staked_balance(alice()).0;
    assert!(alice_balance < ntoy(1_000_000) + ntoy(100_000), "alice's reward diluted by bob's flash stake");
}
```

```rust
    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

        env::log(
            format!(
                "@{} staking {}. Received {} new staking shares. Total {} unstaked balance and {} staking shares",
                account_id, charge_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }
```

```rust
    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true
    }
```

```rust
    pub(crate) fn num_shares_from_staked_amount_rounded_down(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        (U256::from(self.total_stake_shares) * U256::from(amount)
            / U256::from(self.total_staked_balance))
        .as_u128()
    }

    /// Returns the number of "stake" shares rounded up corresponding to the given staked balance
    /// amount.
    ///
    /// Rounding up division of `a / b` is done using `(a + b - 1) / b`.
    pub(crate) fn num_shares_from_staked_amount_rounded_up(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        ((U256::from(self.total_stake_shares) * U256::from(amount)
            + U256::from(self.total_staked_balance - 1))
            / U256::from(self.total_staked_balance))
        .as_u128()
    }

    /// Returns the staked amount rounded down corresponding to the given number of "stake" shares.
    pub(crate) fn staked_amount_from_num_shares_rounded_down(
        &self,
        num_shares: NumStakeShares,
    ) -> Balance {
        assert!(
            self.total_stake_shares > 0,
            "The total number of stake shares can't be 0"
        );
        (U256::from(self.total_staked_balance) * U256::from(num_shares)
            / U256::from(self.total_stake_shares))
        .as_u128()
    }

    /// Returns the staked amount rounded up corresponding to the given number of "stake" shares.
    ///
    /// Rounding up division of `a / b` is done using `(a + b - 1) / b`.
    pub(crate) fn staked_amount_from_num_shares_rounded_up(

        num_shares: NumStakeShares,
    ) -> Balance {
        assert!(
            self.total_stake_shares > 0,
            "The total number of stake shares can't be 0"

            + U256::from(self.total_stake_shares - 1))
```
