### Title
Off-by-one threshold miscalculation in `GlobalStateEvaluator::reached_agreement()` diverges from the canonical block-approval threshold formula — ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement()` computes the signer-set agreement threshold using floor (truncating) integer division, while the canonical, consensus-critical threshold used to actually validate/verify block signatures — `NakamotoBlockHeader::compute_voting_weight_threshold()` — uses ceiling division. For any `total_weight` where `total_weight * NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` is not evenly divisible by 10 (i.e., most real-world reward sets), the two formulas disagree by exactly one weight unit. This is structurally analogous to the reported `revBp()` bug: a percentage/threshold helper that is reused for a purpose whose base/denominator/rounding rule differs from the one it was originally designed for, silently producing a wrong number.

### Finding Description
The canonical threshold used to gate real block-signature acceptance is: [1](#0-0) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```
This is a **ceiling** division: `ceil(total_weight * threshold / 10)`.

The signer-side `GlobalStateEvaluator`, used to determine the local signer's view of "global state" (active miner, burn view, protocol version, tx-replay set), instead computes: [2](#0-1) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```
This is a **floor** division: `floor(total_weight * threshold / 10)`. Whenever `total_weight * threshold` is not a multiple of 10 (e.g. `total_weight = 99`, `threshold = 7` → canonical threshold = `ceil(693/10) = 70`, but `reached_agreement` accepts at `floor(693/10) = 69`), `reached_agreement` will report "agreement reached" one weight-unit *before* the amount that the canonical, consensus-critical `compute_voting_weight_threshold()` requires for a block to actually be signed/broadcast.

`reached_agreement`/`reached_disagreement` gate every piece of the signer's local "global state machine" determination:
- `determine_latest_supported_signer_protocol_version()` [3](#0-2) 
- `determine_global_burn_view()` [4](#0-3) 
- `determine_global_state()` (current miner, tx replay set) [5](#0-4) 
- `capitulate_miner_view()`, which decides when a signer should switch its local "current miner" viewpoint to match what it believes is the majority view, using both `reached_disagreement` (blocking-minority check) and `reached_agreement` (majority check) [6](#0-5) 

Because this evaluator is fed purely from gossiped `StateMachineUpdate` messages from other signers (no majority key or auth needed — a signer just needs to see the update messages that any subset of signers legitimately broadcasts), a single observing signer can independently be misled into believing the state-machine supermajority (70%) has been reached for miner viewpoint / burn view / protocol version / replay-set, when in fact the weight is one unit below what the canonical, block-verification-grade threshold formula (`compute_voting_weight_threshold`) would require.

### Impact Explanation
This causes a signer to act on a threshold value that is inconsistent with — and weaker than — the canonical, consensus-critical threshold formula used elsewhere in the same codebase for verifying that a block has actually received a supermajority of signatures. Concretely, `capitulate_miner_view()` can flip a signer's local view of the "current miner" (and hence which miner's proposals/pre-commits it will act on) based on a floor-rounded 1-weight-unit-short majority, rather than the true ceiling-rounded supermajority. This is the "signer acting on a stale/wrong threshold" class of High-impact bug: the signer's coordination state (which miner is canonical, which burn view is canonical, which protocol version is active) is derived from a threshold check that silently disagrees with the one used to actually accept blocks, for any total signer weight not evenly divisible by 10 relative to the 70% cutoff.

### Likelihood Explanation
High. `total_weight` is the sum of all signers' reward-cycle weights and, absent special engineering, will not be a multiple of 10/threshold in most reward cycles — this is not a crafted edge case but the common case. No majority collusion, node/consensus flaw, or key compromise is required: any observing signer independently runs this arithmetic on ordinary gossiped `StateMachineUpdate` messages every time it evaluates global state (every bitcoin/stacks block arrival, every capitulation check).

### Recommendation
Make `GlobalStateEvaluator::reached_agreement()` use the same ceiling-division formula as `NakamotoBlockHeader::compute_voting_weight_threshold()` (or better, call that function directly) so that the signer-local notion of "supermajority agreement" is always consistent with the canonical, consensus-critical block-approval threshold:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    // use the same ceil(total_weight * threshold / 10) formula as
    // NakamotoBlockHeader::compute_voting_weight_threshold
    vote_weight >= NakamotoBlockHeader::compute_voting_weight_threshold(self.total_weight)
        .unwrap_or(u32::MAX)
}
```
And adjust `reached_disagreement` analogously (using the complementary ceil/floor pairing that correctly represents "blocking minority" = `total_weight - threshold + 1`).

### Proof of Concept
1. Construct a reward cycle where the sum of signer weights, `total_weight = 99` (easily reachable — weights are derived per-signer from stacked amounts and are not artificially constrained to multiples of 10).
2. `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (70%).
3. Canonical threshold via `compute_voting_weight_threshold(99)`: `(99*7)=693`, `693 % 10 = 3` → `ceil = 1` → threshold `= 69 + 1 = 70`.
4. `GlobalStateEvaluator::reached_agreement(69)`: `69 >= 693/10 (=69)` → `true`.
5. Thus a coalition of signers totaling weight `69` (69.7% of `99`) is treated by every observing signer's `GlobalStateEvaluator` as having reached the 70% agreement threshold for current-miner/burn-view/protocol-version/tx-replay-set, one weight unit short of the `70` that the canonical `compute_voting_weight_threshold` (used to actually accept a block's signatures) would require for the equivalent decision.     /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
