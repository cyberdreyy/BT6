### Title
Job-controlled cache `key` bypasses path sanitization and escapes `CacheDir`/`BuildDir` when `FF_HASH_CACHE_KEYS` is enabled - ([File: shells/abstract.go])

### Summary
`newCacheConfig` in `shells/abstract.go` disables `cachekey.Sanitize` for the human-readable cache key whenever `FF_HASH_CACHE_KEYS` is on, yet still uses that unsanitized key to build a local filesystem path (`AlternateArchiveFile`) via `path.Join`/`filepath.Rel`. Because a pipeline author fully controls `cache: key:` (and `ExpandValue` further expands job variables into it), a crafted key containing `../` sequences resolves to a path outside the intended cache/build root, which is then passed to `cache-archiver --alternate-file` and used in an `os.Rename` in `commands/helpers/cache_archiver.go`.

### Finding Description
In `newCacheConfig` [1](#0-0) , when `featureflags.HashCacheKeys` is on, `sanitizer` is replaced with a no-op (`func(s string) string { return s }`-equivalent), so `humanKey` is the raw, only-variable-expanded `rawKey` derived from the job-controlled `userKey` (the `cache: key:`/`fallback_keys` value). `cacheAlternateKey` then returns this unsanitized `humanKey` directly as `alternateKey` when hashing is enabled [2](#0-1) .

`getArchivePath` builds the local archive path with `path.Join(build.CacheDir, key, "cache.zip")` and then makes it relative to `build.BuildDir` via `filepath.Rel` [3](#0-2) . `path.Join` calls `path.Clean`, which collapses `..` segments lexically; if `key` contains enough `../` components to cancel out `CacheDir`'s own path segments, the resulting absolute path (and thus the relative path resolved later against `BuildDir` by the shell script) points outside the cache directory entirely (e.g., to `/etc/cron.d/...`).

This unsanitized path becomes `cacheConfig.AlternateArchiveFile`, which is passed unconditionally as `--alternate-file` to the `cache-archiver` helper in `addCacheUploadCommand` [4](#0-3)  (the same pattern exists in `functions/concrete/run/stages/cache_archive.go` line 53-54). The helper's `tryRenameAlternateFile` then performs `os.Stat(c.AlternateFile)` and `os.Rename(c.AlternateFile, c.File)` [5](#0-4) , i.e. it moves whatever file exists at the attacker-influenced path into the safe (hashed) cache location, deleting the source. If a subsequent `isFileChanged` check treats the primary file as unchanged, `uploadExistingArchiveIfNeeded` uploads that moved content as the project's cache archive [6](#0-5) .

No path-containment check exists on this local path the way `cache.GetAdapter` enforces for remote object paths (`strings.HasPrefix(fullPath, basePath+"/")` in `cache/cache.go`); that check only guards the remote bucket key, not the local `AlternateArchiveFile`. `cachekey.Sanitize`, which normally strips `../` and backslashes, is explicitly skipped for this code path per the FF's own design/documentation.

### Impact Explanation
An unprivileged pipeline author who can set a job's `cache: key:` (or `CACHE_FALLBACK_KEY`/`fallback_keys`, which reach the same `newCacheConfig`) can, once `FF_HASH_CACHE_KEYS` is enabled, cause the runner helper to:
- Delete/move an arbitrary file reachable from the executor's filesystem view (outside `build.CacheDir`/`build.BuildDir`) via `os.Rename`, and
- Potentially have that file's content re-uploaded as the project's cache archive, exposing it to whoever can pull that cache key.

This is a violation of the "File operations must stay within intended build/cache/artifact roots" invariant, and depending on executor type (e.g., shell executor sharing a host filesystem) it can affect files outside the job's own intended sandboxed area.

### Likelihood Explanation
Requires the admin-controlled, opt-in `FF_HASH_CACHE_KEYS` feature flag to be enabled — once that precondition holds, exploitation only requires a normal pipeline author setting a `.gitlab-ci.yml` `cache: key:` value with `../` segments; no special privileges are needed, and the flow is deterministic and repeatable on every job run.

### Recommendation
Always sanitize/normalize the human-readable key before using it to construct any local filesystem path, regardless of `FF_HASH_CACHE_KEYS`. At minimum, apply `cachekey.Sanitize` (or an equivalent traversal-safe check like the `strings.HasPrefix(fullPath, basePath+"/")` guard already used in `cache/cache.go`) to the key used in `getArchivePath`'s `path.Join` call for both `ArchiveFile` and `AlternateArchiveFile`, independent of whether the key is also used unsanitized for hashing/URL/metadata purposes.

### Proof of Concept
Go unit test to add near `TestNewCacheConfig` in `shells/abstract_test.go`:
```go
func TestNewCacheConfig_PathTraversalWithHashCacheKeysFF(t *testing.T) {
    build := &common.Build{
        CacheDir: "/builds/group/project/cache",
        BuildDir: "/builds/group/project",
        Runner: &common.RunnerConfig{
            RunnerSettings: common.RunnerSettings{
                FeatureFlags: map[string]bool{featureflags.HashCacheKeys: true},
            },
        },
    }
    cfg, _, err := newCacheConfig(build, "../../../../etc/cron.d/evil")
    require.NoError(t, err)
    // AlternateArchiveFile must not resolve outside CacheDir once
    // re-joined with BuildDir at script runtime.
    resolved := filepath.Clean(filepath.Join(build.BuildDir, cfg.AlternateArchiveFile))
    assert.True(t, strings.HasPrefix(resolved, build.CacheDir),
        "AlternateArchiveFile escaped CacheDir: %s", resolved)
}
```
Expected current (buggy) behavior: `resolved` equals `/etc/cron.d/evil/cache.zip`, failing the `HasPrefix` assertion, demonstrating the traversal. A full integration PoC would additionally run `cache-archiver --file <safe> --alternate-file /etc/cron.d/evil/cache.zip` and assert that `/etc/cron.d/evil` is renamed/removed from its original location.

func newCacheConfig(build *common.Build, userKey string, keyChecks ...func(string) bool) (*cacheConfig, string, error) {
	if build.CacheDir == "" {
		return nil, "", fmt.Errorf("unset cache directory")
	}

	rawKey := path.Join("/", build.JobInfo.Name, build.GitInfo.Ref)[1:]
	if userKey != "" {
		rawKey = build.GetAllVariables().ExpandValue(userKey)
	}

	hasher := func(s string) string { return s }
	sanitizer := cachekey.Sanitize
	// if hash key support is enabled, we don't need to sanitize keys anymore
	if build.IsFeatureFlagOn(featureflags.HashCacheKeys) {
		hasher = func(s string) string { return fmt.Sprintf("%x", sha256.Sum256([]byte(s))) }
		sanitizer = func(s string) (string, error) { return s, nil }
	}

func (c *CacheArchiverCommand) tryRenameAlternateFile() {
	if c.AlternateFile == "" || c.AlternateFile == c.File {
		return
	}

	_, err := os.Stat(c.File)
	if err == nil {
		logrus.Debugln("Primary cache file already exists locally, skipping rename from alternate")
		return
	}
	if !errors.Is(err, fs.ErrNotExist) {
		logrus.WithError(err).Warningln("Failed to stat primary cache file")
		return
	}

	if _, err := os.Stat(c.AlternateFile); err != nil {
		logrus.Debugln("Alternate cache file not found locally, nothing to rename")
		return
	}

	if err := os.MkdirAll(filepath.Dir(c.File), 0o700); err != nil {
		logrus.WithError(err).Warningln("Failed to create directory for cache file rename")
		return
	}

	if err := os.Rename(c.AlternateFile, c.File); err != nil {
		logrus.WithError(err).Warningln("Failed to rename alternate cache file to primary")
		return
	}

	logrus.Infoln("Renamed alternate cache file to primary")
}

func (c *CacheArchiverCommand) Execute(*cli.Context) {
	log.SetRunnerFormatter()

	c.normalizeArgs()
	c.tryRenameAlternateFile()
	if err := validateCacheTransferTuning(c.TransferBufferSize, c.ChunkSize, c.Concurrency); err != nil {
		logrus.Fatalln(err)
	}

	// Enumerate files
	err := c.enumerate()
	if err != nil {
		logrus.Fatalln(err)
	}

	// Skip upload if no files were found
	if len(c.files) == 0 {
		logrus.Warningln("No files to cache.")
		return
	}

	// Check if list of files changed
	if !c.isFileChanged(c.File) {
		if c.AlternateFile != c.File {
			// AlternateFile is set (FF_HASH_CACHE_KEYS compatibility mode): the primary
			// archive may have been downloaded from the alternate URL by the extractor,
			// meaning the primary remote URL does not yet have an object. Upload the
			// existing archive to ensure the primary URL is populated.
			// This handles both transition directions:
			//   FF false→true: primary=hashed, alternate=unhashed
			//   FF true→false: primary=unhashed, alternate=hashed
			c.uploadExistingArchiveIfNeeded()
			return
		}
		logrus.Infoln("Archive is up to date!")
		return
	}
