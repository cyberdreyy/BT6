### Title
A gossiped BlockAccepted signature silently deletes an already-broadcast block rejection, letting a signer's "no" be overwritten and re-tallied as "yes" without re-validation - ([File: stacks-signer/src/signerdb.rs])

### Summary
`SignerDb::add_block_signature` unconditionally deletes any existing row for `(block_sighash, signer_addr)` in `block_rejection_signer_addrs` before inserting the new signature, with no check that the incoming signature is fresh, self-originated, or that the underlying block/consensus view is unchanged. `add_block_rejection_signer_addr`, by contrast, explicitly refuses to record a rejection once a signature already exists for that signer/block pair. This is a one-directional guard: acceptance is allowed to erase a prior rejection, but rejection cannot erase a prior acceptance.

### Finding Description
`add_block_rejection_signer_addr` guards against a signer's rejection overwriting a signature: [1](#0-0) 

But `add_block_signature`, called from `store_and_process_block_signature` whenever a `BlockAccepted` gossip message is processed for *any* signer address (not just self), unconditionally deletes any rejection row for that signer/block before inserting the signature: [2](#0-1) 

`handle_block_response`/`store_and_process_block_signature` treat a `BlockAccepted` message from any signer (recovered from its own signature, so it's a valid gossip signature, not the receiving signer's own decision) as authoritative, storing the signature and immediately recomputing `total_signature_weight` toward the accept threshold: [3](#0-2) 

Meanwhile `store_and_process_block_rejection` computes the *reject* tally from `get_block_rejection_signer_addrs`, which now silently lost that signer's row the moment any (correctly-signed, valid) `BlockAccepted` for the same signer/block arrived later — even one that is stale, out-of-order, or delivered after this local signer already tallied the rejection weight from that signer toward `GloballyRejected`: [4](#0-3) 

Because the delete in `add_block_signature` has no ordering/freshness check (no timestamp, no epoch/nonce, nothing tying it to which message a given signer actually intended as final), a signer's rejection can be erased retroactively by any later-arriving accept signature for the same signer/block, even if that accept message was gossip-relayed after the reject and even if the local node already used the rejection to reach `GloballyRejected`. This breaks the equality between "the rejection weight this node counted towards consensus" and "the rejection weight actually still on record," and it lets a stale/replayed acceptance retroactively flip what is counted as that signer's vote — i.e., a rejection recounted as an accept.

### Impact Explanation
This matches the "Critical: a rejection recounted as an accept" impact class from the rules. If block state has already moved past a threshold decision (e.g. `GloballyRejected` via `mark_globally_rejected`), a subsequently-processed accept signature for the same signer/block deletes the reject-address row that justified that decision, corrupting the audit trail (`get_block_rejection_signer_addrs`) used elsewhere (e.g. `RT` check in `store_and_process_block_rejection`, and other call sites re-deriving reject weight) and permanently masking that a signer ever rejected the block. Combined with no ordering constraint on delivery of `BlockAccepted` gossip (which can be resent/replayed by the network or an adversarial relay), this can make a stale/duplicate acceptance from an honest signer erase evidence of rejection after the fact, silently changing the recomputed weight in later re-tallies.

### Likelihood Explanation
Any signer or gossip relay can trigger this by delivering a `BlockAccepted` message (a legitimately-signed message from some signer, potentially replayed/delayed) for a signer/block pair that already has a stored rejection — no majority or key compromise is required; this is triggerable by a single miner/gossip actor re-broadcasting or delaying delivery of a signer's own earlier `BlockAccepted` message, or by network reordering that this codebase's own comments show it explicitly anticipates elsewhere (e.g. the "outdated-peer fallback" logic in `handle_block_response`) but does not apply symmetrically here.

### Recommendation
Make `add_block_signature`'s deletion of a prior rejection row conditional and symmetric with the check in `add_block_rejection_signer_addr`: refuse (or at least log/guard) overwriting a rejection with a signature once a rejection has already contributed to a terminal (`GloballyRejected`) decision, or require that acceptance/rejection updates carry monotonic ordering (e.g., a per-signer sequence/timestamp) before allowing one to erase the other.

### Proof of Concept
1. Signer S sends `BlockRejection` for block B; local db stores `(B, S) -> reject_reason` via `add_block_rejection_signer_addr`.
2. Enough rejection weight accumulates and `store_and_process_block_rejection` calls `block_info.mark_globally_rejected()`, persisting `GloballyRejected`.
3. Later, a replayed/delayed `BlockAccepted(B, S)` (still validly signed by S, e.g. resent by the network or a relay) arrives and is processed by `handle_block_response` → `store_and_process_block_signature` → `add_block_signature`, which deletes the `(B,S)` row from `block_rejection_signer_addrs` unconditionally.
4. `get_block_rejection_signer_addrs(B)` no longer returns S's rejection, even though the local `BlockInfo.state` is already `GloballyRejected` based on it — the recorded justification for the decision is now inconsistent with the persisted decision, and any later re-tally of the same block (e.g. after a `should_reevaluate_block` re-evaluation) would compute a different (lower) rejection weight for the same historical event.     /// Record an observed block signature
    pub fn add_block_signature(
        &self,
        block_sighash: &Sha512Trunc256Sum,
        signer_addr: &StacksAddress,
        signature: &MessageSignature,
    ) -> Result<bool, DBError> {
        // Remove any block rejection entry for this signer and block hash
        let del_qry = "DELETE FROM block_rejection_signer_addrs WHERE signer_signature_hash = ?1 AND signer_addr = ?2";
        let del_args = params![block_sighash, signer_addr.to_string()];
        self.db.execute(del_qry, del_args)?;

        // Insert the block signature
        let qry = "INSERT OR IGNORE INTO block_signatures (signer_signature_hash, signer_addr, signature) VALUES (?1, ?2, ?3);";
        let args = params![
            block_sighash,
            signer_addr.to_string(),
            serde_json::to_string(signature).map_err(DBError::SerializationError)?
        ];
        let rows_added = self.db.execute(qry, args)?;

        let is_new_signature = rows_added > 0;
        if is_new_signature {
            debug!("Added block signature.";
                "signer_signature_hash" => %block_sighash,
                "signer_address" => %signer_addr,
                "signature" => %signature
            );
        } else {
            debug!("Duplicate block signature.";
                "signer_signature_hash" => %block_sighash,
                "signer_address" => %signer_addr,
                "signature" => %signature
            );
        }
        Ok(is_new_signature)
    }

        &self,
        block_sighash: &Sha512Trunc256Sum,

                "signer_address" => %addr,

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();
