Based on my investigation, `VmSlice::end()` is never used anywhere in the security-critical translation or bounds-checking path in this codebase. The only call sites of `.end()` found by grep are unrelated (`snapshot_bank_utils.rs`, `serde_stakes.rs`, `cli/src/program.rs`, `ledger-tool/src/output.rs`, `deploy.rs`, `bank_hash_details.rs`, `transaction-status-client-types/src/lib.rs`) — none of which touch `VmSlice`.

The actual security-relevant translation function, `translate_vm_slice` in `program-runtime/src/memory.rs`, does **not** call `end()` at all. It calls `translate_slice::<T>(memory_mapping, slice.ptr(), slice.len(), check_aligned)`, which independently recomputes `total_size = len.saturating_mul(size_of::<T>())` and explicitly validates it via `isize::try_from(total_size).is_err()` before ever calling `memory_mapping.map(...)`: [1](#0-0) [2](#0-1) 

`VmSlice::end()` itself is defined purely with `saturating_add`/`saturating_mul` and has no consumers that treat it as a security boundary or bounds-diagnostic value: [3](#0-2) 

So the premise of the question — that some downstream consumer trusts `end()` while `translate_slice`/`translate_vm_slice` independently trusts `ptr()`/`len()`, causing a divergence exploitable for OOB read — does not hold in this codebase. `translate_vm_slice` is the sole authoritative gate for CPI slice-of-slices/account-info style translations (used e.g. in `translate_signers` and `SyscallHash` in `syscalls/src/lib.rs`), and it never consults `end()`; every length is independently re-validated against `isize` range and then against actual `MemoryMapping` region bounds via `MemoryMapping::map`, regardless of what `saturating_add`/`saturating_mul` produced in `end()`. There is no code path where `end()`'s saturated value informs a bounds decision that `translate_slice`'s separately-computed `total_size` does not also independently check. [4](#0-3) [5](#0-4)

macro_rules! translate_slice_inner {
    ($memory_mapping:expr, AccessType::Store, $vm_addr:expr, $len:expr, $T:ty, $check_aligned:expr $(,)?) => {{
        if $len == 0 {
            Ok(std::ptr::slice_from_raw_parts_mut(
                std::ptr::dangling_mut::<$T>(),
                0,
            ))
        } else {
            let total_size = $len.saturating_mul(size_of::<$T>() as u64);
            if isize::try_from(total_size).is_err() {
                Err($crate::memory::MemoryTranslationError::InvalidLength.into())
            } else {
                match $crate::translate_inner!(
                    $memory_mapping,
                    map,
                    $crate::solana_sbpf::memory_region::AccessType::Store,
                    $vm_addr,
                    total_size
                ) {
                    Err(e) => Err(e),
                    Ok(host_buf) if $check_aligned && !host_buf.ptr().cast::<$T>().is_aligned() => {
                        Err($crate::memory::MemoryTranslationError::UnalignedPointer.into())
                    }
                    Ok(host_buf) => Ok(std::ptr::slice_from_raw_parts_mut(
                        host_buf.ptr_mut().cast(),
                        $len as usize,
                    )),
                }
            }
        }
    }};
