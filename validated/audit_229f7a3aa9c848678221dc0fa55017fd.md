### Title
Pre-genesis withdraw requests skip the one-epoch wait and can be claimed instantly, stealing unaccrued interest - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
The analog of CVE-2017-15698 — an edge-case input that silently bypasses a mandatory validation (there: a >127-byte AIA field skipping OCSP; here: `epochEndDate() == 0` skipping the "wait one epoch" check). `IdleCreditVault._claimFundedWithdrawRequest` gates claims with `if (epochEndDate() != 0 && epochNumber <= lastWithdrawRequest[_user]) revert NotAllowed()`. That condition is meant for pool-close (`epochEndDate` reset to 0 after funds are recalled), but it is also `0` before the first `startEpoch`. During the initial buffer period a KYC-passed lender can deposit, call `requestWithdraw`, and immediately `claimWithdrawRequest`, receiving principal plus a full epoch of expected interest that was never accrued, paid out of other depositors' principal.

### Finding Description
- `IdleCDOEpochVariant.requestWithdraw` (`contracts/IdleCDOEpochVariant.sol:739-791`) only checks the `allowAA/BBWithdrawRequest` flags and `isWalletAllowed`; it does not require the epoch to be running or the pool to have started. It books `_underlyings = principal + interest - fees` where `interest` comes from `_calcInterestWithdrawRequest` for the upcoming full epoch (per tests: request returns "amount + net interest for next epoch").
- `IdleCreditVault.requestWithdraw` (`contracts/strategies/idle/IdleCreditVault.sol:243-295`) computes `isClosed = epochEndDate() == 0`. Pre-genesis this is `true`, so it mints the receipt to the user, burns the CDO's principal, records `withdrawsRequests`, and — critically — does not add to `pendingWithdraws` (so the borrower will never be billed for it at `stopEpoch`).
- `IdleCreditVault._claimFundedWithdrawRequest` (`contracts/strategies/idle/IdleCreditVault.sol:319-350`) skips the `epochNumber <= lastWithdrawRequest` wait entirely when `epochEndDate() == 0`, so the same transaction/next transaction pays out `amount = withdrawsRequests[_user]` (principal + unaccrued interest) via `_transferFundedClaim` from underlying held by the strategy.

During the initial buffer, deposits sit in the strategy (funds reach the borrower only at `startEpoch`), so the payout is backed 1:1 by other LPs' deposits. The attacker withdraws `deposit + epochInterest` while having supplied only `deposit`.

### Impact Explanation
Broken invariant: fair mint/burn — the claim pays a full epoch of interest that was never earned and never sourced from the borrower (it bypasses `pendingWithdraws`, so `stopEpoch` never collects it). The excess over the attacker's deposit is taken directly from underlying belonging to other depositors. Quantified loss per attack: approximately `attackerPrincipal * apr * epochDuration / 365 days` (net of fees), repeatable on both AA and BB tranches, bounded by the pool's initial buffer TVL. Direct theft of LP principal by an unprivileged KYC-passing lender.

### Likelihood Explanation
Requires: `allowAAWithdrawRequest`/`allowBBWithdrawRequest` enabled (the normal operating mode), Keyring-passed wallet, and acting before the first `startEpoch` — i.e., during the pool's initial buffer period, which is precisely when deposits are being onboarded. After the first epoch runs, `epochEndDate != 0` until pool close, and on a properly closed pool all funds are already recalled so the same skip is benign. The vulnerability window is therefore genesis-only, which lowers likelihood but requires no privileged misbehavior.

### Recommendation
Distinguish "never started" from "closed" in `_claimFundedWithdrawRequest` and `requestWithdraw`. E.g., treat `epochEndDate() == 0` as `isClosed` only when `epochNumber > 0` (or a dedicated `poolClosed` flag), so pre-genesis receipts still respect `epochNumber <= lastWithdrawRequest` and contribute to `pendingWithdraws`. Alternatively, have `IdleCDOEpochVariant.requestWithdraw` revert while `epochEndDate == 0 && epochNumber == 0`.

### Proof of Concept
Foundry fork test (repo harness style, see `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testPreGenesisInstantClaimStealsInterest() external {
    // Pool freshly deployed: epochEndDate() == 0, epochNumber == 0, funds sit in strategy.
    uint256 amountWei = 10_000 * ONE_SCALE; // USDC-scale

    // Victim deposits during initial buffer
    address victim = makeAddr('victim');
    _depositWithUser(victim, amountWei, true);          // AA deposit

    // Attacker (KYC-passed lender) deposits the same
    uint256 mintedAA = idleCDO.depositAA(amountWei);

    // Attacker requests withdraw; receipt = principal + full-epoch net interest
    uint256 requested = cdoEpoch.requestWithdraw(0, address(AAtranche));
    assertGt(requested, amountWei, 'receipt includes unaccrued interest');

    // The one-epoch wait is skipped because epochEndDate() == 0
    uint256 balPre = underlying.balanceOf(address(this));
    cdoEpoch.claimWithdrawRequest();                    // must NOT succeed pre-genesis
    uint256 claimed = underlying.balanceOf(address(this)) - balPre;

    assertEq(claimed, requested, 'instant payout of principal + unearned interest');
    assertGt(claimed, amountWei, 'attacker drains more than deposited');

    // The stolen interest was never added to pendingWithdraws, so the borrower is
    // never billed for it: the shortfall hits the victim's principal.
    assertEq(strategy.pendingWithdraws(), 0, 'payout bypassed borrower billing');
}
```

Expected result on current code: the claim succeeds pre-genesis and `claimed > amountWei`, with the delta taken from strategy-held underlying belonging to the victim.
