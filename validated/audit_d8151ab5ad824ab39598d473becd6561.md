### Title
Unsanitized ERC4626 `convertToAssets` read lets a vault user inflate `totalInterestDueNow`, minting unbacked epoch interest and breaking solvency - ([File: contracts/strategies/idle/ProgrammableBorrower.sol])

### Summary
In programmable-borrower mode, `stopEpoch` treats `IProgrammableBorrower.totalInterestDueNow()` as the sole source of truth for epoch interest. That value is derived from `vault.convertToAssets(shares)`, an unsanitized read-back of the external ERC4626 vault's share price — the same bug class as ALPINE-CVE-2020-25595, where Xen acted on unsanitized values read back from device registers. A vault depositor (an allowed attacker class) can inflate `convertToAssets` with a direct donation to the vault; in minted-interest mode the inflated interest is credited to tranche NAV without any cash ever being pulled, producing unbacked tranche value and eventual insolvency.

### Finding Description
The chain of unsanitized reads:

1. `IdleCDOEpochVariant._resolveStopEpochInterest` returns `IProgrammableBorrower(_borrower()).totalInterestDueNow()` verbatim when `isProgrammableBorrower` is set, and `_checkNotAllowed(_interest > 1)` forbids any override [1](#0-0) .
2. `totalInterestDueNow` adds `_vaultNetInterest()` interest on top of borrower interest, where `earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault` and `_currentVaultAssets()` is a raw `vault.convertToAssets(vaultSharesBalance)` [2](#0-1) .
3. In minted mode `_amountToPullFromBorrower = 0`, so the entire resolved interest is booked into `expectedEpochInterest`/`lastEpochInterest` and folded into tranche `virtualPrice` via `_updateAccounting` without a single underlying token entering the contract [3](#0-2) .
4. `settleBorrowerInterest` only moves `borrowerInterestAccrued` into `borrowerInterestDebt`; the inflated vault-interest component creates no debt and no obligation — it is pure phantom NAV [4](#0-3) .

The only sanity bound on interest, the `maxApr` check at `IdleCDOEpochVariant.sol:377-379`, is gated on `_interest > 1`, which is unreachable in programmable mode, so the inflated value is completely uncapped [5](#0-4) . `_skimDonatedAssets` only sweeps tokens donated to the CDO contract itself, not donations into the ERC4626 vault [6](#0-5) .

### Impact Explanation
Insolvency / unfair mint: donated vault appreciation is minted as tranche value with zero backing. Tranche holders (and pending-withdraw receipt holders at the earlier, lower price basis) are diluted in real terms — the minted price claims assets that don't exist. First claimers/`requestWithdraw` fillers are paid real underlying; later claimers face permanently unfulfillable requests — direct theft of redeemable value and permanent freezing of residual claims. Quantified: a donation of `D` into the vault raises `totalInterestDueNow` by roughly `D * pbSharesFraction`; an attacker controlling a large fraction of tranche supply and vault supply (donate as deposit-then-price-manipulation, or donate while holding vault shares to recover part) can convert most of `D` into withdrawable tranche NAV, extracting honest lenders' principal.

### Likelihood Explanation
Requires programmable-borrower mode with `isInterestMinted` (the tested operating mode — `setIsInterestMinted(true)` is the test default) and a vault whose `convertToAssets` is donation-sensitive (standard ERC4626/MetaMorpho). The attacker is any vault user — explicitly in scope. Profitability needs the attacker to hold a dominant share of tranche supply and vault supply, which is realistic for a young pool; no privileged role is needed since `stopEpoch` itself only reads the tainted value.

### Recommendation
Bound the vault-derived component: cap `totalInterestDueNow` at borrower contractual interest plus a time-bounded vault APR (e.g., reuse `maxApr`), or in `stopEpoch` require minted-mode interest to be covered by actually-pulled cash (`_amountToPullFromBorrower > 0`) before crediting NAV. Alternatively measure vault PnL against a cost-basis snapshot that excludes unsolicited balance increases (per-share tracking instead of `convertToAssets` deltas).

### Proof of Concept
Foundry fork (mainnet, real MetaMorpho vault, mirroring `test/foundry/ProgrammableBorrowerCreditVault.t.sol`):

```solidity
function testDonationInflatesMintedEpochInterest() external {
    uint256 amount = 10_000 * oneScale;
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    // Attacker deposits into AA tranche, then epoch starts
    idleCDO.depositAA(amount);          // attacker controls large tranche share
    _startEpochAndCheckPrices(0);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    // Attacker (as ERC4626 vault user) donates directly into the MetaMorpho vault,
    // inflating convertToAssets for the programmable borrower's shares.
    uint256 donation = 1_000 * oneScale;
    deal(USDC, attacker, donation, true);
    vm.startPrank(attacker);
    IERC20(USDC).transfer(address(morphoVault), donation); // donation, no shares minted
    vm.stopPrank();

    uint256 inflated = programmableBorrower.totalInterestDueNow();
    assertGt(inflated, 0, "phantom vault interest recognized");

    uint256 navBefore = cdoEpoch.getContractValue();
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // Interest credited to NAV/tranche price but zero cash pulled (_amountToPullFromBorrower == 0)
    assertApproxEqAbs(cdoEpoch.lastEpochInterest(), inflated, 10);
    assertEq(underlying.balanceOf(address(cdoEpoch)) , navBeforeCashBefore, "no backing received");
    // Attacker withdraws AA at inflated price, draining honest depositors' backing.
}
```

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
