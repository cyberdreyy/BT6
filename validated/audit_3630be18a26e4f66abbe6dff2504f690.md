### Title
Rewards streamed while tranche-token staking supply is zero are permanently undistributed - ([File: contracts/StakingRewards.sol](contracts/StakingRewards.sol))

### Summary
`depositReward` in `StakingRewards.sol` starts a reward period that streams `rewardRate` per second over `rewardsDuration` regardless of whether any tranche tokens are staked. Because `rewardPerToken()` short-circuits when `_totalSupply == 0`, all rewards that vest during a zero-supply window are never credited to anyone and remain locked as undistributable balance. The same pattern exists in `DelegateStakingRewardsIDLE.sol`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
`depositReward` is called by `rewardsDistribution` (the `IdleCDO`, via `_depositFees`/incentive flows) and sets `lastUpdateTime = block.timestamp` and `periodFinish = block.timestamp + rewardsDuration`. From that point, `lastTimeRewardApplicable()` advances with `block.timestamp` up to `periodFinish`, but `rewardPerToken()` returns `rewardPerTokenStored` unchanged whenever `_totalSupply == 0`. Every `updateReward` modifier call also sets `lastUpdateTime = lastTimeRewardApplicable()`, so once time passes with zero stakers, that elapsed window is consumed without ever increasing `rewardPerTokenStored`. When a user later stakes, their `userRewardPerTokenPaid` is set to the current stored value, so the rewards vested during the empty period can never be claimed by anyone. On the next `depositReward`, only `remaining * rewardRate` (the not-yet-vested portion) is rolled into the new rate; the already-vested-but-undistributed amount is not accounted for. [5](#0-4) [6](#0-5) [7](#0-6) 

Concrete scenario: `depositReward` sets `rewardRate = 50` with `rewardsDuration = 100` seconds. No one stakes for the first 40 seconds. A staker then deposits; over the remaining 60 seconds they accrue only `50 * 60 * share`. The `50 * 40 = 2000` rewards vested during the empty window can never be claimed by any staker.

### Impact Explanation
Permanent loss of distributable yield: rewards paid into the contract by the IdleCDO incentive stream during zero-supply windows are carved out of `rewardRate` but never reach any `rewards[account]` entry. The entire deposited reward amount is committed via `require(rewardRate <= balance / rewardsDuration)`, so the tokens are part of the scheduled distribution yet no staker can ever withdraw them. This is a permanent freezing of yield that was intended for tranche-token stakers (the same bug class as the external report). The only escape is `recoverERC20` by the owner, which rescues the tokens to governance rather than to the stakers they were meant for — the yield is still permanently lost to its intended recipients. [8](#0-7) 

### Likelihood Explanation
High for tranche-reward staking contracts: incentive staking for `IdleCDOTranche` tokens routinely has zero or near-zero supply right after deployment, after an epoch transition, or whenever all stakers exit. `depositReward` is called automatically by the IdleCDO on harvests (`rewardsDistribution`), so the timing of reward deposits is decoupled from staking activity — the honest owner/CDO calls it on schedule with no way to know supply is zero. Any gap with `_totalSupply == 0` leaks `rewardRate * gap` permanently. No attacker action is needed; it is triggered entirely by honest sequencing. [2](#0-1) 

### Recommendation
Do not let vesting time elapse while `_totalSupply == 0`. Either:
- defer the start of the period until the first stake: keep `lastUpdateTime` pinned (i.e., set `lastUpdateTime`/`periodFinish` to begin at the first `stake` after `depositReward` when supply is zero), or
- carry the undistributed vested amount into the next period: in `depositReward`, compute `undistributed = (lastTimeRewardApplicable() - lastUpdateTime) * rewardRate` for the zero-supply window and add it to the new `reward`, or
- revert in `depositReward` when `_totalSupply == 0` so rewards are only scheduled once a staker exists.

### Proof of Concept
Foundry sketch against `contracts/StakingRewards.sol` (initialize with `rewardsDuration = 1 days`, any ERC20 as reward/staking token):

```solidity
// contracts/StakingRewards.sol — PoC
function test_RewardsStuckDuringZeroSupply() public {
    // staking = new StakingRewards(); initialized with owner, rewardsDistribution = address(this)
    uint256 reward = 1000e18;
    rewardToken.mint(address(this), reward);
    rewardToken.approve(address(staking), reward);

    // 1. Reward deposited while _totalSupply == 0
    staking.depositReward(address(0), reward);   // sets rewardRate, periodFinish = now + 1 day

    // 2. Half the period passes with nobody staked
    vm.warp(block.timestamp + 12 hours);

    // 3. Alice stakes and stays for the rest of the period
    stakingToken.mint(alice, 100e18);
    vm.startPrank(alice);
    stakingToken.approve(address(staking), 100e18);
    staking.stake(100e18);
    vm.warp(block.timestamp + 12 hours + 1);
    uint256 aliceEarned = staking.earned(alice);

    // Alice can never claim the ~500e18 vested during the zero-supply window
    assertApproxEqAbs(aliceEarned, reward / 2, 1);
    uint256 stuck = rewardToken.balanceOf(address(staking)) - aliceEarned;
    assertGt(stuck, 0); // ~500e18 permanently undistributable to any staker
}
```

  function lastTimeRewardApplicable() public view returns (uint256) {
    return block.timestamp < periodFinish ? block.timestamp : periodFinish;
  }

  function rewardPerToken() public view returns (uint256) {
    if (_totalSupply == 0) {
      return rewardPerTokenStored;
    }
    return rewardPerTokenStored + ((lastTimeRewardApplicable() - lastUpdateTime) * rewardRate * 1e18 / _totalSupply);
  }

  function earned(address account) public view returns (uint256) {
    return (_balances[account] * (rewardPerToken() - userRewardPerTokenPaid[account]) / 1e18) + rewards[account];
  }

  function getRewardForDuration() external view returns (uint256) {

  }

  function depositReward(address, uint256 reward) external onlyRewardsDistribution updateReward(address(0)) {
    if (shouldTransfer) {
      rewardsToken.safeTransferFrom(msg.sender, address(this), reward);
    }

    if (block.timestamp >= periodFinish) {
      rewardRate = reward / rewardsDuration;
    } else {
      uint256 remaining = periodFinish - block.timestamp;
      uint256 leftover = remaining * rewardRate;
      rewardRate = (reward + leftover) / rewardsDuration;
    }

    // Ensure the provided reward amount is not more than the balance in the contract.
    // This keeps the reward rate in the right range, preventing overflows due to
    // very high values of rewardRate in the earned and rewardsPerToken functions;
    // Reward + leftover must be less than 2^256 / 10^18 to avoid overflow.
    uint balance = rewardsToken.balanceOf(address(this));
    require(rewardRate <= balance / rewardsDuration, "Provided reward too high");

    lastUpdateTime = block.timestamp;
    periodFinish = block.timestamp + rewardsDuration;

    emit RewardAdded(reward);
  }
