### Title
Instant withdrawal requests skip the upfront management fee charged to identical normal withdrawal requests - ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
Analogous to the GMX report where ADL orders set `uiFeeReceiver` to `address(0)` while referral fees were still assessed, `requestWithdraw` in `IdleCDOEpochVariant` takes an early-return branch for instant withdrawals that never calls `_totalWithdrawFees` and never increments `pendingWithdrawFees`. A lender whose request is routed to the instant path pays zero management/performance fees, while a lender submitting the same request one block later (or whenever `instantWithdrawAprDelta` is not triggered) pays an upfront management fee on principal plus a performance fee on projected interest. The skipped fee is a direct loss to `feeReceiver`/`owner` and a direct gain to the withdrawer.

### Finding Description
`requestWithdraw` computes `_underlyings = _trancheToUnderlyings(_amount, _tranche)` and then branches:

- Instant path (lines 761-769): `creditVault.requestInstantWithdraw(_underlyings, msg.sender); _withdrawOps(_amount, _underlyings, _tranche); return _underlyings;` — full principal is queued for claim, no fee deducted.
- Normal path (lines 772-779): `totalFees = _totalWithdrawFees(principal, interest)` where `_totalWithdrawFees` (lines 900-906) always charges `_calculateManagementFee(_principal, _withdrawRequestManagementFeeDuration())` on principal — even when interest is zero or below the fee — plus the performance fee on the remaining gain. `pendingWithdrawFees += totalFees` books the fee so `stopEpoch` later pays it to `feeReceiver`/`owner` via `_transferFeeUnderlyings`/`_mintSharesAtCurrPrice` (lines 418-457).

The management fee is explicitly justified in the code as compensation for the time a receipt "waits outside live NAV" (comment at lines 786-787, `_withdrawRequestManagementFeeDuration` at lines 925-931). Instant receipts are equally outside live NAV — they wait for `instantWithdrawDeadline`/`instantWithdrawDelay` and are funded by `collectInstantWithdrawFunds` — yet are exempted. Like the ADL/`uiFeeReceiver` case, the fee infrastructure exists and is honored on the sibling path but the receiver is effectively set to zero on this path.

### Impact Explanation
Unprivileged KYC-passed lenders recover `principal * managementFee * (epochDuration + remainingBuffer) / (FULL_ALLOC * 365 days)` more than an equivalent normal withdrawer. With `managementFee = 10_000` (10% APR, the max), a 35-day epoch+30-day buffer cycle and a large withdrawal, the avoided fee is on the order of ~1.8% of principal per withdrawal, permanently diverted from `feeReceiver`/`owner` to the withdrawer. During a sustained APR cut — precisely when instant withdrawals are enabled and mass exit is most likely — the fee leakage scales with total exiting TVL.

### Likelihood Explanation
Requires `disableInstantWithdraw == false` and `lastEpochApr > unscaledApr + instantWithdrawAprDelta`, i.e., the manager must have enabled instant withdrawals and lowered APR — a routine, expected configuration change, not an edge case. Once active, every lender qualifies by calling `requestWithdraw`; no privileged or malicious setup is needed. Note the possibility this exemption is intentional (instant withdrawers receive no interest), which mirrors the report's own uncertainty about the liquidation-order exclusion; the management-fee-on-idle-principal rationale in the code, however, applies equally to instant receipts.

### Recommendation
Apply the same fee accounting in the instant branch: compute `_totalWithdrawFees` (or a duration-adjusted variant covering `instantWithdrawDelay` plus remaining buffer) against the principal, subtract it from `_underlyings`, and add it to `pendingWithdrawFees` before calling `requestInstantWithdraw`, so `stopEpoch`/`getInstantWithdrawFunds` settles it to `feeReceiver`/`owner` like normal-request fees.

### Proof of Concept
Foundry fork sketch (extend `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testInstantWithdrawSkipsManagementFee() external {
    uint256 amount = 100_000 * ONE_SCALE;
    // 1% management fee, all fees to feeReceiver
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    _setManagementFee(1_000);

    idleCDO.depositAA(amount);
    _transferBurnedTrancheTokens(address(this), true);

    // epoch 1 at 10% apr
    vm.startPrank(manager);
    cdoEpoch.setEpochParams(30 days, 5 days);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);
    cdoEpoch.startEpoch();
    vm.stopPrank();

    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest());
    vm.warp(cdoEpoch.epochEndDate() + 1);
    // stop epoch, set next apr to 0 -> instant withdraw enabled
    vm.prank(manager);
    cdoEpoch.stopEpochWithDuration(0, 0, 30 days, 0);
    vm.prank(manager);
    cdoEpoch.setInstantWithdrawParams(3 days, 1e18, false);

    uint256 trancheBal = AAtranche.balanceOf(address(this));
    uint256 expectedMgmtFee = _calcManagementFee(
        trancheBal * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN,
        1_000,
        cdoEpoch.epochDuration() // or remaining-buffer-adjusted duration
    );

    // normal-path preview would charge the fee:
    // maxWithdrawable subtracts _totalWithdrawFees; the instant path does not.
    uint256 requested = cdoEpoch.requestWithdraw(trancheBal, address(AAtranche));
    assertEq(cdoEpoch.pendingWithdrawFees(), 0, "instant path booked no fee");
    assertEq(
        requested,
        trancheBal * cdoEpoch.tranchePrice(address(AAtranche)) / ONE_TRANCHE_TOKEN,
        "full principal returned, management fee skipped"
    );
    // feeReceiver never receives `expectedMgmtFee` at stopEpoch for this request.
}
```

Key assertion: `pendingWithdrawFees == 0` after an instant-mode `requestWithdraw`, while the same-sized normal request (run with `instantWithdrawAprDelta` unmet) books `expectedMgmtFee` into `pendingWithdrawFees` — the identical `feeReceiver` accounting gap as `uiFeeReceiver = address(0)` for ADL orders.
