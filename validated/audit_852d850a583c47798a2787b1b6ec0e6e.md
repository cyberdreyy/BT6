### Title
Kamino `harvest_reward` lacks the mint/market isolation checks that Drift's analog enforces, allowing reward-harvesting to be pointed at the bank's own collateral farm - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
The external report flags `ShyftStaking`'s failure to check that reward payouts never dip into the tracked staked-funds balance (`totalSupply`). Marginfi has an analogous "reward vs. staked funds" boundary problem in its Kamino integration: `KaminoHarvestReward` provides no on-chain check that the reward-harvesting `farm_state`/`reward_mint` are distinct from the bank's own collateral/reserve, whereas the parallel Drift implementation (`DriftHarvestReward`) explicitly enforces this separation.

### Finding Description
`DriftHarvestReward` (`programs/marginfi/src/instructions/drift/harvest_reward.rs`) contains explicit constraints to prevent the "harvest" path from touching the bank's actual collateral/market: [1](#0-0) 

These constraints assert `harvest_drift_spot_market.mint != bank.mint` and `harvest_drift_spot_market.key() != bank.integration_acc_1`, i.e., the market being drained for "rewards" cannot be the bank's own collateral market or use the bank's own mint.

The Kamino counterpart, `KaminoHarvestReward`, has no equivalent constraints. `reward_mint`, `farm_state`, and `user_state` are all `UncheckedAccount`/plain `InterfaceAccount` with no relationship asserted against the bank's `integration_acc_1` (Kamino reserve) or `integration_acc_2` (Kamino obligation), and no check that `reward_mint != bank.mint`: [2](#0-1) 

The instruction logic simply harvests whatever the provided `farm_state`/`user_state`/`reward_mint` combination yields and sweeps the entire delta to the global fee wallet: [3](#0-2) 

Because the bank's Kamino obligation (`integration_acc_2`) can itself be enrolled in a Kamino Farm tied to the reserve (see the obligation-farm registration flow used in tests, `initObligationFarmsForReserve`), and because nothing here validates that the `user_state`/`farm_state` passed in is a farm exclusively used for admin-seeded/extra rewards (as opposed to the reserve's own deposit-tracking farm), a caller can supply the bank's actual reserve/obligation farm accounts instead of a genuine "rewards-only" farm. This mirrors the `ShyftStaking` root cause: there is no invariant enforced on-chain that separates the pool that represents user-staked principal/yield entitlement from the pool being swept as "rewards."

### Impact Explanation
If the reserve's own obligation-farm (which accrues yield attributable to bank depositors via the reserve's normal interest/points/rewards mechanism) is passed as the harvest target, legitimate depositor-earned value that should accrue to `asset_share_value` (or otherwise remain attributable to depositors) is instead swept in full to the `global_fee_wallet`, permanently diverting value away from depositors. This is a durable, financially-impactful misappropriation of funds that rightfully belong to the bank's users, distinguishing it from a purely theoretical issue.

### Likelihood Explanation
The instruction's account validation is comparatively weak versus its sibling (`DriftHarvestReward`), which was clearly hardened against exactly this class of confusion (reward market == bank market). The absence of the analogous check in the Kamino path is a concrete, reachable gap rather than a hypothetical one, though exploitability further depends on whether callers can freely choose arbitrary `farm_state`/`user_state`/`reward_mint` combinations at the transaction-building layer (which the account structure does not prevent on-chain) and on Kamino's actual obligation-farm semantics for the specific reserve/bank in question.

### Recommendation
Add the same class of guard to `KaminoHarvestReward` that `DriftHarvestReward` already has for Drift: require that `reward_mint != bank.mint`, and that the `farm_state`/`user_state` being harvested is not the farm/obligation-farm associated with the bank's own reserve/obligation (`integration_acc_1`/`integration_acc_2`). Concretely, derive/verify that `user_state` is *not* the PDA derived from `(farm_state, bank_obligation)` for the bank's own collateral farm, mirroring the `harvest_drift_spot_market.key() != bank.integration_acc_1` check.

### Proof of Concept
Not independently reproducible from static review alone — a full PoC would require confirming (a) whether Kamino enrolls the bank's own obligation in a reward-bearing Farm for the specific reserve/market in production configuration, and (b) whether the off-chain/admin tooling that constructs `kamino_harvest_reward` transactions restricts `farm_state`/`user_state` selection. This could not be fully verified with the available tools within the index; a Devin session with full repo/CPI-target access would be needed to confirm exploitability end-to-end.

pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}
