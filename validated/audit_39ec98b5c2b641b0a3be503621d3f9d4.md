Found the key candidate: `drift_claim_bad_debt` — a permissionless, credit-side instruction (analogous to `_credit` in the OFT adapter report) that pulls funds into the bank's vault/fee wallet, and unlike every other credit/debit flow in this codebase, it has **no** `is_protocol_paused()` check.### Title
Missing pause enforcement in `drift_claim_bad_debt` breaks the emergency panic-pause invariant - ([File: programs/marginfi/src/instructions/drift/claim_bad_debt.rs])

### Summary
Marginfi enforces a protocol-wide `panic_pause` invariant: every instruction that moves value into or out of a bank's vaults checks `!group.load()?.is_protocol_paused()` (deposit, withdraw, borrow, repay, and every Kamino/Drift/Juplend/Solend equivalent, plus `lending_pool_emissions_deposit`, `lending_pool_collect_bank_fees`, `lending_pool_withdraw_fees(_permissionless)`, and `TransferToNewAccount(Pda)`) [1](#0-0) [2](#0-1) [3](#0-2) . `drift_claim_bad_debt`, however, is a permissionless instruction that moves external funds through the bank's `liquidity_vault_authority` and into the global fee wallet via CPI to Drift's merkle-distributor program, and its `Accounts` struct has no `group` account and no `is_protocol_paused()` constraint at all [4](#0-3) . This is the same bug class as the reported `_credit` issue: a value-crediting/receiving code path that was left out of an otherwise-consistent pause gate.

### Finding Description
Every fund-moving instruction in marginfi conditions on the group's panic-pause state, e.g. `LendingAccountDeposit`/`LendingAccountBorrow`/`LendingAccountRepay`/`LendingAccountWithdraw` and the Kamino/Drift/Juplend/Solend deposit/withdraw variants all carry a `group` account with `constraint = (!group.load()?.is_protocol_paused()) @ MarginfiError::ProtocolPaused` (deposit/withdraw sides also allow the `ACCOUNT_IN_DELEVERAGE` bypass) [5](#0-4) [6](#0-5) [7](#0-6) . Permissionless value-moving instructions such as `lending_pool_emissions_deposit`, `lending_pool_collect_bank_fees`, and `lending_pool_withdraw_fees_permissionless` are likewise gated on the same constraint [8](#0-7) [9](#0-8) , and the project's own documentation explicitly states "Permissionless bank-fee collection" is blocked while paused [10](#0-9) .

`drift_claim_bad_debt` is architecturally the same class of instruction — permissionless, bank-scoped, and it moves tokens through the bank's `liquidity_vault_authority` signer PDA via CPI (claiming from Drift's `MerkleDistributor`, then sweeping to the global fee wallet's ATA) — but its `DriftClaimBadDebt` accounts struct contains no `group: AccountLoader<'info, MarginfiGroup>` field and thus no possible `is_protocol_paused()` check [11](#0-10) . The handler signs with the bank's `liquidity_vault_authority` PDA bump (`bank_signer!(BankVaultType::Liquidity, ...)`) to both claim from the distributor and transfer the claimed balance out [12](#0-11) , meaning it fully operates on protocol-controlled vault-authority signing power exactly like the other pause-gated flows, yet is reachable during an active `panic_pause`.

### Impact Explanation
The panic-pause mechanism exists to give admins a hard stop for "extreme emergencies" — every other value-moving code path (deposits, withdrawals, borrows, repays, integration flows, emissions deposits, fee collection/withdrawal, account transfers) is deliberately frozen so that admins can diagnose an incident with a known, static state of all banks' vaults and share values [13](#0-12) . Because `drift_claim_bad_debt` bypasses this gate, an incident responder cannot guarantee that Drift-bank vault authorities are inert during a pause: this instruction can still be invoked to claim/CPI/sweep funds through the vault authority PDA and to the global fee wallet while the protocol believes all such flows are halted. This breaks the documented "all financial operations on all Groups and Banks are suspended" guarantee during a global pause and creates the same kind of inconsistent-state condition the reported OFT `_credit` bug represents (some operations frozen, others silently continuing).

### Likelihood Explanation
The instruction is explicitly permissionless (any signer can call it, only requiring a valid merkle proof and the bank's fixed PDA accounts), and it requires no special account or authority privileges beyond what is publicly derivable from a bank pubkey [14](#0-13) . It can be called at any time, including while `panic_pause` is active, with no additional preconditions related to pause state. This makes exploitation trivial to trigger for anyone monitoring the Drift bad-debt merkle distributor for a claimable allocation.

### Recommendation
Add a `group: AccountLoader<'info, MarginfiGroup>` account to `DriftClaimBadDebt` (validated via `has_one = group` on `bank`) with the same pause constraint used elsewhere in the codebase:
```rust
#[account(
    constraint = (!group.load()?.is_protocol_paused()) @ MarginfiError::ProtocolPaused
)]
pub group: AccountLoader<'info, MarginfiGroup>,
```
This mirrors the pattern already used consistently for `LendingPoolEmissionsDeposit`, `LendingPoolCollectBankFees`, and every deposit/withdraw variant, restoring the invariant that no bank-vault-authority-signed value movement can occur during an active panic-pause.

### Proof of Concept
1. Admin or `pause_delegate_admin` calls `panic_pause`, entering an emergency-paused state; `group.panic_state_cache.is_paused_flag()` becomes true and every other bank operation (deposit/withdraw/borrow/repay/Kamino/Drift/Juplend/Solend flows/emissions deposit/fee collection) now reverts with `MarginfiError::ProtocolPaused` as verified by the project's own pause test suite [15](#0-14) .
2. An attacker or arbitrary permissionless caller who holds a valid Drift bad-debt merkle proof for a Drift-integration bank calls `drift_claim_bad_debt(amount, proof)` with the bank's `liquidity_vault_authority`, `distributor`, `claim_status`, and ATAs supplied.
3. Because `DriftClaimBadDebt` has no `group` account/pause constraint, the instruction succeeds: the bank's `liquidity_vault_authority` PDA claims tokens from Drift's `MerkleDistributor` via CPI and immediately sweeps them to the global fee wallet's ATA [16](#0-15) , despite the protocol being in an active emergency pause — violating the documented "all financial operations ... are suspended" guarantee that every comparable instruction upholds.

pub fn drift_claim_bad_debt<'info>(
    ctx: Context<'info, DriftClaimBadDebt<'info>>,
    amount: u64,
    proof: Vec<[u8; 32]>,
) -> MarginfiResult {
    ctx.accounts.create_claimant_token_account()?;
    ctx.accounts.create_destination_token_account()?;
    ctx.accounts.prefund_claim_status()?;
    let pre_claim_balance = ctx.accounts.claimant_token_balance()?;
    ctx.accounts.cpi_new_claim(amount, proof)?;
    let post_claim_balance = ctx.accounts.claimant_token_balance()?;
    let received_amount = post_claim_balance
        .checked_sub(pre_claim_balance)
        .ok_or_else(|| error!(MarginfiError::InternalLogicError))?;
    let swept_amount = ctx.accounts.cpi_transfer_to_destination()?;
    ctx.accounts
        .emit_claim_event(amount, received_amount, swept_amount)?;
    Ok(())
}

    fn cpi_new_claim(&self, amount: u64, proof: Vec<[u8; 32]>) -> MarginfiResult {
        let mut data = get_discrim_hash("global", "new_claim").to_vec();
        NewClaimIxArgs {
            amount_unlocked: amount,
            amount_locked: 0,
            proof,
        }
        .serialize(&mut data)?;

        let ix = Instruction {
            program_id: self.merkle_distributor_program.key(),
            accounts: vec![
                AccountMeta::new(self.distributor.key(), false),
                AccountMeta::new(self.claim_status.key(), false),
                AccountMeta::new(self.from.key(), false),
                AccountMeta::new(self.claimant_token_account.key(), false),
                AccountMeta::new(self.liquidity_vault_authority.key(), true),
                AccountMeta::new_readonly(self.token_program.key(), false),
                AccountMeta::new_readonly(self.system_program.key(), false),
            ],
            data,
        };

        let account_infos = [
            self.distributor.to_account_info(),
            self.claim_status.to_account_info(),
            self.from.to_account_info(),
            self.claimant_token_account.to_account_info(),
            self.liquidity_vault_authority.to_account_info(),
            self.token_program.to_account_info(),
            self.system_program.to_account_info(),
        ];

        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);

        invoke_signed(&ix, &account_infos, signer_seeds)?;
        Ok(())
    }

    fn cpi_transfer_to_destination(&self) -> MarginfiResult<u64> {
        let amount = accessor::amount(&self.claimant_token_account.to_account_info())?;
        if amount == 0 {
            return Ok(0);
        }

        let accounts = Transfer {
            from: self.claimant_token_account.to_account_info(),
            to: self.destination_token_account.to_account_info(),
            authority: self.liquidity_vault_authority.to_account_info(),
        };
        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(self.token_program.key(), accounts, signer_seeds);

        token::transfer(cpi_ctx, amount)?;
        Ok(amount)
    }

### Blocked while paused

All normal user flows are disabled:

- Deposit, Borrow, Withdraw, Repay (both native banks and integration banks — Kamino, Drift,
  Juplend, Solend)
- Order placement / order flows
- Account transfer
- Classic liquidation (`LendingAccountLiquidate`)
- Permissionless bank-fee collection
- Permissionless bad-debt settlement (`HandleBankruptcy` when called by a non-admin, even on banks
  with the `PERMISSIONLESS_BAD_DEBT_SETTLEMENT` flag)
- Admin bank configuration changes that route through `LendingPoolConfigureBank`
