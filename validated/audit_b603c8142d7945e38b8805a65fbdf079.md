### Title
Signed-to-unsigned integer wraparound in gateway trigger timestamp check silently bypasses staleness/replay validation - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` validates the freshness of an attacker-supplied `TriggerRequestPayload.Timestamp` (an `int64`) by comparing it against `time.Now()` using unsigned (`uint`) arithmetic. Because the comparison mixes a signed, attacker-controlled `int64` with `uint` types without range validation, a crafted negative timestamp silently wraps to a huge unsigned value when cast, causing the staleness check to always evaluate as "not stale," analogous to the referenced silent-overflow-on-downcast bug where an out-of-range value bypasses an intended bound check.

### Finding Description
The staleness check is:
```go
if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
``` [1](#0-0) 

`payload.Timestamp` is defined as `int64` and is fully attacker-controlled JSON input decoded straight from the message body: [2](#0-1) 

`uint(payload.Timestamp)` performs a signed-to-unsigned conversion with no bounds check (no `_safeUint88`-style guard). If an attacker sets `Timestamp` to a negative value (e.g. `-1`), `uint(payload.Timestamp)` wraps around to a value near `math.MaxUint64`. The comparison `smallNumber > hugeNumber` is then always false, so the "stale message" branch is never taken regardless of the real age of the message, and the message proceeds to be dispatched to all DON members: [3](#0-2) 

This mirrors the report's root cause exactly: a value from outside the expected range is silently coerced/truncated during an unchecked type conversion, defeating a safety/bounds check that the code relies on (`_fCashAmount` overflowing `uint88` vs. `payload.Timestamp` overflowing `uint` when cast from a negative `int64`).

The path is reachable pre-authorization: `HandleLegacyUserMessage` runs before any allowlist enforcement — the code explicitly notes `// TODO: apply allowlist and rate-limiting here` — and the sender identity is derived only from an arbitrary self-generated ECDSA key used to produce a valid signature, not from a pre-registered/permissioned key: [4](#0-3) [5](#0-4) 

### Impact Explanation
The freshness/staleness check exists specifically to prevent replay of stale (or forged out-of-sequence) messages being forwarded from the gateway to DON nodes. By supplying a negative `Timestamp`, an unprivileged, unauthenticated (any-keypair) sender can defeat this check entirely and have crafted `web_api_trigger` messages accepted as "fresh" and broadcast to every member of the DON, regardless of downstream allowlist/quota assumptions built on the freshness property. This is a concrete bypass of an intended validation gate on an internet-facing message handler, though the direct exploitability further depends on what other checks (allowlist by sender, per-topic authorization) still gate the ultimate workflow trigger.

### Likelihood Explanation
High. No special privileges or registered credentials are needed — the only requirement is generating an EC keypair and signing the message body, which any external client can do. The vulnerable comparison is reachable on every incoming legacy user message before any allowlist is applied.

### Recommendation
Reject non-positive or out-of-range timestamps before doing unsigned arithmetic, and avoid mixing signed and unsigned types:
```go
if payload.Timestamp <= 0 {
    // reject as invalid
}
now := time.Now().Unix()
if now - int64(h.config.MaxAllowedMessageAgeSec) > payload.Timestamp {
    // stale
}
```
Perform all comparisons in `int64` space (or explicitly validate `payload.Timestamp >= 0` and `<= math.MaxInt64` bounds) before any cast to `uint`, mirroring the recommended `_safeUint88`-style guarded downcast pattern from the referenced report.

### Proof of Concept
1. Generate an arbitrary ECDSA key (no registration needed).
2. Construct a `TriggerRequestPayload` with `Timestamp: -1` (or any negative int64) and a valid `trigger_id`/`topics`/`params`.
3. Sign the enclosing `api.Message` with the arbitrary key per `Message.Sign` and submit it as a `web_api_trigger` JSON-RPC request to the gateway's `HandleLegacyUserMessage` path (test harness pattern shown in [6](#0-5) , replacing the timestamp with a negative value).
4. Observe that `uint(payload.Timestamp)` wraps to a near-`MaxUint64` value, the staleness comparison `uint(time.Now().Unix())-MaxAllowedMessageAgeSec > uint(payload.Timestamp)` evaluates false, and the message is forwarded to `don.SendToNode` for every DON member instead of being rejected as stale.

	}

		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))

func triggerRequest(t *testing.T, key *ecdsa.PrivateKey, topics []string, methodName, timestamp, payload string) *api.Message {
	messageID := "12345"
	if methodName == "" {
		methodName = MethodWebAPITrigger
	}
	if timestamp == "" {
		timestamp = strconv.FormatInt(time.Now().Unix(), 10)

	donID := "workflow_don_1"

		ts, err := strconv.ParseInt(timestamp, 10, 64)
		require.NoError(t, err)
		reqPayload := webapicap.TriggerRequestPayload{
			TriggerId:      "web-api-trigger@1.0.0",
			TriggerEventId: "action_1234567890",
			Timestamp:      ts,
			Topics:         topics,
			Params: webapicap.TriggerRequestPayloadParams(map[string]any{
				"bid": "101",
				"ask": "102",
			}),
		}
		payloadJSON, err = json.Marshal(reqPayload)
		require.NoError(t, err)
	} else {
		payloadJSON = []byte(payload)
	}
	msg := &api.Message{
		Body: api.MessageBody{

			Method:    methodName,
			DonId:     donID,

		},
	}
	err := msg.Sign(key)
	require.NoError(t, err)
	err = msg.Validate()
	require.NoError(t, err)
	return msg
