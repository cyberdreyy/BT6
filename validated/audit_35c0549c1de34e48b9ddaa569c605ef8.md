### Title
Stale-epoch instant withdraw receipts are excluded from default recovery basis via unvalidated epoch index - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault` keys instant-withdraw receipts by the `epochNumber` at request time (`instantWithdrawsRequestsByEpoch[user][epoch]`, `instantWithdrawClaimsByEpoch[epoch]`), but the default-recovery path looks the bucket up with the *current* `epochNumber` at finalization time without validating that pending instant claims actually belong to that epoch. Any instant receipt that survives an epoch boundary unfunded is silently dropped from `defaultPendingClaimBasis`, inflating `defaultRecoveryPrice` for all other claimants and permanently freezing the stranded instant receipt holders. This is the direct analog of the ext4 bug: an epoch index that is never validated against the range of epochs that actually hold claims is dereferenced as if it were always the correct bucket.

### Finding Description
- `requestInstantWithdraw` records receipts under `currentEpoch = epochNumber`: `instantWithdrawsRequestsByEpoch[_user][currentEpoch] += _amount` and `instantWithdrawClaimsByEpoch[currentEpoch] += _amount` (lines 367-372).
- `epochNumber` is incremented inside `deposit()` during every successful `stopEpoch` (lines 607-610).
- `pendingInstantWithdraws` is only decremented by `collectInstantWithdrawFunds` (lines 398-403), which the manager triggers via `getInstantWithdrawFunds`. Nothing in `stopEpoch` settles or re-keys unfunded instant receipts, so they can persist across arbitrarily many successful epochs.
- At default finalization, `defaultPendingClaimBasis()` does `basis = pendingWithdraws; if (pendingInstantWithdraws != 0) basis += instantWithdrawClaimsByEpoch[epochNumber]` (lines 644-649), using the *current* epoch as the lookup key with no check that claims were actually recorded there.
- `finalizeDefaultRecovery` then computes `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` with the undercounted basis (line 688) and stores `defaultRecoveryEpoch = epochNumber` (line 693).
- `_claimDefaultedInstantWithdrawRequest` repeats the same stale-index read: `claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultRecoveryEpoch]` (line 844), so the stranded user finds zero basis and falls through to `_transferFundedClaim`, which reverts whenever the (now inflated) recovery reserve must be protected (lines 900-905).

Concrete sequence (running epoch, non-programmable borrower, instant withdraws enabled):

1. Pool running in epoch `N`. Alice calls `requestInstantWithdraw` via the CDO; her receipt is keyed at `instantWithdrawClaimsByEpoch[N]` and `pendingInstantWithdraws = A`.
2. Manager never calls `getInstantWithdrawFunds` (it is optional and gated on `instantWithdrawDeadline`), so `pendingInstantWithdraws` stays `A`.
3. `stopEpoch` succeeds: `epochNumber` becomes `N+1`. Alice's basis is still keyed at `N`.
4. During epoch `N+1` the borrower fails to fund the stop → `_handleBorrowerDefault` → `defaulted = true`; `epochNumber` remains `N+1` because `deposit()` inside the `try` never ran.
5. `finalizeDefault(recovered, src)`: `defaultPendingClaimBasis()` adds `instantWithdrawClaimsByEpoch[N+1] == 0`, so Alice's `A` is missing from `totalBasis`. `recoveryPrice` is inflated by a factor of `realBasis / (realBasis - A)`.
6. `defaultRecoveryEpoch = N+1`. Every normal-receipt and active claim is paid `claimBasis * recoveryPrice`, over-drawing `defaultRecoveryReserve`. Alice's `_claimDefaultedInstantWithdrawRequest` reads `instantWithdrawsRequestsByEpoch[alice][N+1] == 0`, pays nothing from the reserve, and her fallback `_transferFundedClaim` reverts once the reserve protection check applies.

### Impact Explanation
Two fund-impacting effects from the same missing index validation:

- **Theft/overpayment from the recovery reserve**: `defaultRecoveryPrice` is computed against a basis that excludes Alice's `A`, so all other defaulted claimants and active tranche holders recover at an inflated ratio and drain `defaultRecoveryReserve` beyond their pro-rata share. With `A` equal to a large fraction of the default-epoch claim basis, the overpayment approaches the full reserve.
- **Permanent freezing of unclaimed yield/principal**: Alice's instant receipt is real (`instantWithdrawsRequests[alice] == A`, receipt tokens minted), but `instantWithdrawsRequestsByEpoch[alice][defaultRecoveryEpoch]` is zero, so she receives nothing from the reserve; her `_transferFundedClaim` fallback is capped by `balance - reserve`, which is zero or insufficient after the overpayment. Her claim is permanently unrecoverable.

Broken invariant: one receipt one payout, and fair pro-rata loss socialization over the true claim basis.

### Likelihood Explanation
- Attacker profile: any tranche-token holder can also be the stranded victim/instigator by requesting an instant withdraw while the epoch is running and the manager simply doesn't fulfill it; no privileged collusion is needed for the trigger (manager failing to call `getInstantWithdrawFunds` is an honest omission path — the function is gated on a deadline, not mandatory).
- Requires: instant withdraws enabled (non-programmable borrower), an unfunded instant receipt surviving at least one successful `stopEpoch`, and a later borrower default — all normal protocol states.
- Existing guards do not stop it: `_ensureDefaultRecoveryInitialized` only gates legacy upgrades; `_onlyIdleCDO`/`_transferFundedClaim` reserve checks actually enforce the freeze on the victim rather than prevent the mispricing.

### Recommendation
Apply the same "validate the index before dereferencing" fix as the ext4 patch: before `defaultPendingClaimBasis()` adds `instantWithdrawClaimsByEpoch[epochNumber]` and before `_claimDefaultedInstantWithdrawRequest` reads `instantWithdrawsRequestsByEpoch[_user][defaultRecoveryEpoch]`, validate that the epoch bucket actually covers the pending claims — e.g. track the min/max epoch with outstanding instant claims, iterate all epochs `<= epochNumber` with nonzero `instantWithdrawClaimsByEpoch`, or store a cumulative `totalInstantClaims` counter alongside the per-epoch map and include that in the basis. Similarly, `_claimDefaultedInstantWithdrawRequest` should settle a user's claim across all request epochs `<= defaultRecoveryEpoch`, not only the finalization epoch.

### Proof of Concept
Foundry fork test sketch (in the style of `test/foundry/IdleCreditVault.t.sol`):

```solidity
function testDefaultRecoveryMissesStaleEpochInstantReceipt() external {
    // epoch N running with instant withdraws enabled
    idleCDO.depositAA(10_000 * ONE_SCALE);
    idleCDO.depositBB(10_000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);

    // alice requests instant withdraw while epoch N runs
    address alice = makeAddr("alice");
    _depositWithUser(alice, 5_000 * ONE_SCALE, true); // AA tranches
    uint256 aliceShares = AAtranche.balanceOf(alice);
    vm.prank(alice);
    cdoEpoch.requestInstantWithdraw(aliceShares / 2, address(AAtranche)); // keyed at epoch N
    // manager never calls getInstantWithdrawFunds -> pendingInstantWithdraws stays > 0

    // stop epoch N successfully -> epochNumber becomes N+1
    uint256 totFunds = _expectedFundsEndEpoch();
    deal(defaultUnderlying, borrower, totFunds);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
    assertEq(creditVault.epochNumber(), 1);

    // epoch N+1: borrower defaults at stop
    _startEpochAndCheckPrices(1);
    deal(defaultUnderlying, borrower, 0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    _checkDefault(); // defaulted == true, epochNumber still 1

    // alice's receipt is keyed at epoch 0; basis lookup reads epoch 1 -> excluded
    uint256 basis = creditVault.defaultPendingClaimBasis();
    assertLt(basis, pendingExpectedBasis + instantExpectedBasis, "instant basis dropped");

    // finalize with a recovery amount sized for the *true* basis
    uint256 recovered = trueBasis * 7e17 / 1e18;
    deal(defaultUnderlying, manager, recovered);
    vm.startPrank(manager);
    IERC20Detailed(defaultUnderlying).approve(address(strategy), recovered);
    cdoEpoch.finalizeDefault(recovered, manager);
    vm.stopPrank();

    // alice's defaulted-epoch instant claim reads epoch-1 bucket -> 0
    vm.prank(alice);
    cdoEpoch.claimInstantWithdrawRequest(); // pays ~0; reserve overpaid to others
    assertEq(creditVault.instantWithdrawsRequestsByEpoch(alice, 0), aliceShares / 2);
    // defaultRecoveryReserve is drained below pro-rata / alice permanently unpaid
}
```
