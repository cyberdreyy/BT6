### Title
Missing sender allowlist check allows unauthenticated forwarding of `web_api_trigger` messages to all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` accepts any signed `api.Message` with `Method: MethodWebAPITrigger` and a known `DonId`, and forwards it to every member of that DON via `don.SendToNode`, with only signature/timestamp validation and no sender allowlist check, exactly as flagged by the `TODO: apply allowlist and rate-limiting here` comment. Any attacker holding a throwaway ECDSA key can reach this fan-out with no prior registration.

### Finding Description
The request path is: HTTP → `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) → since `msg.Body.DonId != ""`, treated as legacy request, `msg.Validate()` is called [1](#0-0)  → handler lookup by `DonId` → `h.HandleLegacyUserMessage(ctx, msg, callback)` [2](#0-1) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON decoding, a non-zero `Timestamp`, and a staleness check against `MaxAllowedMessageAgeSec` [3](#0-2) . Immediately after these checks, the code has the comment `// TODO: apply allowlist and rate-limiting here`, followed only by a method-type check (`MethodWebAPITrigger`) and message-to-request transformation — no lookup against any per-workflow/per-DON sender allowlist [4](#0-3) . The function then saves a callback and iterates over `h.donConfig.Members`, calling `don.SendToNode` for every DON member unconditionally [5](#0-4) .

`msg.Validate()` (called in `gateway.go`) and `ValidatedRequestFromMessage` only enforce structural/signature validity of the message body — they do not verify that the message's signer/sender is a member of any allowlist tied to a specific trigger/workflow. The rate limiter (`h.nodeRateLimiter`) that exists in this handler is only invoked in `handleWebAPIOutgoingMessage`, which handles node-originated (outgoing) messages, not the user-originated `HandleLegacyUserMessage` path — so no rate limiting applies here either [6](#0-5) .

Consequently, any address that can produce a validly-signed `api.Message{Method: MethodWebAPITrigger, DonId: <known-don>, Payload: {timestamp: now}}` — regardless of whether that key belongs to any registered workflow's `allowedSenders` — will have the message forwarded to every node in the target DON.

### Impact Explanation
This matches the Chainlink bounty impact class of unauthorized triggering of capability workflows / DoS on a DON's node set: an unregistered, unprivileged sender can force fan-out of a `web_api_trigger` message to all DON members, consuming node processing/bandwidth and potentially invoking trigger-capability logic on the node side without belonging to any registered workflow's `allowedSenders`. This is a spam/DoS vector against the DON member set at the gateway layer, not RCE or fund theft, but it does violate the intended "authorization is exact" invariant for message forwarding.

### Likelihood Explanation
Preconditions are minimal: knowledge of a valid `don_id` (typically discoverable/public via gateway configuration) and any keypair to sign the message (per `msg.Validate()`, which only checks signature well-formedness, not allowlist membership). No prior registration or credential is required. The attack is trivially repeatable and automatable — each request only needs a fresh timestamp to pass the staleness check.

### Recommendation
Implement the allowlist check called out by the TODO in `HandleLegacyUserMessage` before forwarding: verify `msg.Body.Sender` against a per-DON (and ideally per-workflow) allowlist configured in `donConfig`/`HandlerConfig`, and add a user-facing rate limiter (analogous to `nodeRateLimiter`) keyed by sender address, rejecting unauthorized/excessive requests with `api.HandlerError` before reaching the `don.SendToNode` fan-out loop.

### Proof of Concept
Go handler-level test (extends existing `core/services/gateway/handlers/capabilities/handler_test.go` style):
1. Construct a `handler` via `NewHandler` with a `donConfig.Members` list and a mock `handlers.DON`.
2. Sign an `api.Message{Body: {Method: MethodWebAPITrigger, DonId: <donConfig.DonId>, Payload: {"timestamp": <now>}}}` using a throwaway key never referenced anywhere in the DON/workflow configuration.
3. Call `handler.HandleLegacyUserMessage(ctx, msg, callback)`.
4. Assert (expected to fail on current code, demonstrating the bug): `mockDON.SendToNode` is called zero times / handler returns an authorization error, instead of being invoked once per `donConfig.Members` entry as currently happens.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
