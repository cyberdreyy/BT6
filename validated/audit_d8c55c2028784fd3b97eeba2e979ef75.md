### Title
Cross-user response hijacking via unauthenticated MessageId collision in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.savedCallbacks` in the legacy webAPI-trigger flow is keyed solely by `msg.Body.MessageId`, a value fully controlled by the unauthenticated gateway HTTP client (it is the raw JSON-RPC request `ID`). Because `HandleLegacyUserMessage` inserts into the map with no existence check and no binding to the sender's identity, an unprivileged attacker can submit a request whose `MessageId` collides with another user's still-pending request, overwriting the map entry so that the honest DON node's later response (intended for the victim) is delivered to the attacker's callback instead.

### Finding Description
`HandleLegacyUserMessage` unconditionally stores the caller-supplied callback under the caller-supplied ID: [1](#0-0) 

`msg.Body.MessageId` originates directly from the JSON-RPC request `ID` supplied by the (unauthenticated) gateway HTTP client in `gateway.ProcessRequest`, which only enforces a 200-character length cap — no uniqueness or per-user namespacing: [2](#0-1) 

When a node later responds, `handleWebAPITriggerMessage` looks the callback up purely by `msg.Body.MessageId` and, on the "first response wins" basis, invokes whichever callback is currently stored for that ID — with no sender/session check tying the response back to the original requester: [3](#0-2) 

Exploit flow: Victim sends a legitimate `web_api_trigger` request with `MessageId = "X"`; this creates `savedCallbacks["X"] -> victimCallback` and the request is fanned out to the DON. Before the DON responds, the attacker (any unauthenticated/unprivileged client of the gateway user-facing HTTP endpoint) sends its own `web_api_trigger` request also using `MessageId = "X"`. This overwrites `savedCallbacks["X"] -> attackerCallback` with no error, since the store has no "already exists" guard (contrast with `common.requestCache`, which does key on the composite `{sender, id}` and rejects duplicates — see `NewRequest`): [4](#0-3) 

When the honest DON node responds to the victim's original message (echoing `MessageId = "X"`), `handleWebAPITriggerMessage` finds `savedCallbacks["X"]` — now the attacker's entry — and delivers the victim's `RawResponse` content to the attacker's HTTP callback, closing the victim's pending request with no response (or a timeout) while the attacker receives data belonging to the victim's request. No node compromise, signature forgery, or DON-level trust is required; the attacker only needs to guess/observe a colliding `MessageId` for a request routed to the same DON, which is fully feasible since IDs are attacker-chosen client-side values with no server-enforced entropy or namespacing.

### Impact Explanation
This is cross-user response confusion / unauthorized disclosure: an unprivileged attacker can receive another user's node response payload (`RawResponse`, which may contain sensitive workflow/computation output) simply by racing a colliding request ID, and can simultaneously deny/disrupt the victim's request (denial of service for that request). This matches the Chainlink bounty impact class of unauthorized access to another user's request/response data.

### Likelihood Explanation
Exploitability requires only unauthenticated/unprivileged access to the gateway's user-facing HTTP endpoint for the same DON, knowledge or prediction of the victim's `MessageId` (or coordinated ID choice, e.g., the attacker simply reuses IDs deterministically and races many requests to increase collision probability against concurrent legitimate traffic), and timing the attacker's request between the victim's request submission and the node's response. No cryptographic bypass is needed. This is straightforwardly repeatable in a unit test.

### Recommendation
Key `savedCallbacks` by a composite identifier that binds the callback to the original request's session/sender context (similar to `common.requestCache`'s `globalId{sender, id}`), reject/queue duplicate `MessageId` insertions instead of silently overwriting, and/or generate the map key server-side (e.g., append a gateway-generated nonce) rather than trusting the client-supplied JSON-RPC ID as the sole map key.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with a fake `don.SendToNode` that records but does not immediately reply.
2. Call `HandleLegacyUserMessage` for "victim" with `msg.Body.MessageId = "X"` and callback `victimCb` (captured via a fake `handlers.Callback` that records `SendResponse` calls).
3. Call `HandleLegacyUserMessage` again for "attacker" with the same `MessageId = "X"` and a different callback `attackerCb`.
4. Assert `h.savedCallbacks["X"].Callback == attackerCb` (overwrite occurred, no error returned).
5. Simulate the DON node responding with `msg.Body.MessageId = "X"` and a distinctive `RawResponse` payload representing the victim's real answer; call `handleWebAPITriggerMessage`.
6. Assert `attackerCb.SendResponse` was invoked with the victim's response payload, and `victimCb.SendResponse` was never called — demonstrating cross-user response delivery caused purely by an unprivileged client choosing a colliding `MessageId`.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

type globalId struct {
	sender string
	id     string
}

type pendingRequest[T any] struct {
	handlers.Callback
	responseData *T
	timeoutTimer *time.Timer
	mu           sync.Mutex
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
