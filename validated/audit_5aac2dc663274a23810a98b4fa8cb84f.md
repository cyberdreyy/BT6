## Finding [1](#0-0) , the `confirm()` function schedules execution of a `MultiSigRequest` once `confirmations.len() + 1 >= self.num_confirmations`, treating every entry recorded in the request's `confirmations` set as a live, currently-authorized member's approval.

### Root cause

`delete_member()` only purges pending requests that were **created by** the member being removed, and only clears that member's `num_requests_pk` entry — it never scans the `confirmations` sets of other outstanding requests to strip out confirmations the removed member already cast on requests created by someone else: [2](#0-1) 

So if member `B` confirms a pending `request_id` (adding their `MultisigMember::to_string()` to `self.confirmations[request_id]`), and is subsequently removed via a separate `DeleteMember{B}` request (which itself reaches the legitimate `num_confirmations` threshold from other members), `B`'s stale confirmation on the *first* request is never removed. The equality the threshold check depends on —

```
confirmations_recorded_for(request_id) == confirmations_from_currently_live_members(request_id)
```

— is broken: `confirmations.len()` can include confirmations from accounts/keys that are no longer members.

### Proof of Concept

1. `MultiSigContract::new([A, B, C, D], 3)` — 4 members, threshold 3.
2. `A.add_request_and_confirm(R1)` (e.g. a `Transfer`) → `confirmations[R1] = {A}` (1/3).
3. `B.confirm(R1)` → `confirmations[R1] = {A, B}` (2/3, not yet executed).
4. Separately, `A, C, D` create+confirm `R2 = DeleteMember{B}` (this legitimately reaches 3/3) → executes, removing `B` from `self.members`. Per `delete_member` at [3](#0-2) , only requests *authored by* `B` are cleaned up; `R1`'s confirmations set is untouched.
5. `C.confirm(R1)`: `confirmations[R1].len() == 2`, `2 + 1 >= 3` → `execute_request(R1)` runs at [4](#0-3) .

`R1` (e.g. a `Transfer` of funds) executes with confirmations from only `A` and `C` — two currently-live members plus one stale, removed member (`B`) — even though the contract requires 3-of-N *live* member approval. The same code pattern (requests filtered only by signer, not by confirmer) exists in the legacy contract's `DeleteKey` handling at [5](#0-4) .

### Impact

A multisig request (e.g. a `Transfer` of NEAR, an `AddKey`, or a `FunctionCall`) can be executed with fewer than `num_confirmations` confirmations from members who are actually authorized at execution time, effectively lowering the approval threshold below what was configured. This matches the Critical impact criterion "a multisig request executed below threshold."

### Likelihood

Requires: (a) a request that collects some but not all needed confirmations, (b) one of the confirming parties subsequently being removed via a normal `DeleteMember`/`DeleteKey` action (a routine governance event — key rotation, offboarding, compromise response), and (c) the original request still being open (no expiry mechanism exists) so remaining members can push it past the threshold later. This is a realistic sequence for any multisig that rotates members while it has stale pending requests.

### Recommendation

When removing a member (`delete_member` in `multisig2/src/lib.rs`, `DeleteKey` in `multisig/src/lib.rs`), iterate all outstanding requests' `confirmations` sets and strip the removed member/key from each, not just requests they authored. Alternatively, revalidate at `confirm()`/execution time that every entry in `confirmations` still corresponds to a current member of `self.members` before counting it toward the threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
