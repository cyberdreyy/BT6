### Title
Cross-user response hijacking via attacker-controlled `MessageId` collision in `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` stores each incoming user callback in `h.savedCallbacks` keyed solely by `msg.Body.MessageId`, a value fully controlled by the unauthenticated sender (it becomes the JSON-RPC request `ID`). Two different senders can submit `MethodWebAPITrigger` requests with the same `MessageId`, causing the second sender's callback to silently overwrite the first's, so the DON node's response meant for one user is delivered to the other.

### Finding Description
`HandleLegacyUserMessage` at [1](#0-0)  stores the callback with:
```go
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
```
without checking whether an entry already exists or whether it belongs to the same sender. `msg.Body.MessageId` is populated from `req.ID` in `ValidatedMessageFromReq` ( [2](#0-1) ), i.e. it is the JSON-RPC request ID an unauthenticated client fully controls. The signature (`m.Validate()` in [3](#0-2) ) authenticates the sender's address but places no constraint that `MessageId` be unique per sender.

When a node later responds, `HandleNodeMessage` dispatches to `handleWebAPITriggerMessage` ( [4](#0-3) ), which looks up and deletes the callback purely by `msg.Body.MessageId`:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
return savedCb.SendResponse(...)
```
It only verifies `msg.Body.Sender == nodeAddr` (the node identity), never which original user submitted the request that this `MessageId` corresponds to. Because the map key is shared, if Attacker A submits a trigger with `MessageId="X"` and Attacker B later submits a different trigger also with `MessageId="X"`, B's entry overwrites A's in the map. Both requests were independently forwarded to all DON nodes with `ID="X"` (via `ValidatedRequestFromMessage`, [5](#0-4) ). Whichever node response for ID "X" arrives first (which could be the answer to A's original request) is delivered to whatever callback is currently stored — potentially B's callback — leaking A's execution result to B, while A's own callback silently receives nothing.

### Impact Explanation
This is a cross-user isolation violation: gateway/capability response data intended for one unauthenticated user's HTTP trigger request can be delivered to a different, unrelated user who merely guessed or reused the same `MessageId`. This maps to Chainlink's "unauthorized disclosure of another user's request/response data" / cross-user response confusion impact class, and can also be used as a griefing/DoS primitive (the original submitter's job result is dropped).

### Likelihood Explanation
No special privilege is required — any unauthenticated client capable of sending a signed gateway message (a normal legitimate capability of this API) can choose an arbitrary `MessageId` string. Since `MessageId` is just an attacker-chosen JSON-RPC ID with no per-sender namespacing or uniqueness enforcement, an attacker only needs to predict or brute-force a value used concurrently by another user (or intentionally coordinate timing) to trigger the collision. This is straightforward and repeatable via automated requests.

### Recommendation
Scope `savedCallbacks` keys by `(Sender, MessageId)` (or another composite/opaque server-generated identifier) instead of `MessageId` alone, so callbacks from different senders can never collide. Additionally consider rejecting/overwrite-protecting duplicate in-flight `MessageId`s from the same sender, and validate on the node-response path that the responding message's target matches the original sender before dispatching the callback.

### Proof of Concept
1. In `core/services/gateway/handlers/capabilities/handler_test.go`, construct two `api.Message` values with distinct ECDSA private keys (different `Sender`), identical `Body.MessageId = "X"`, method `MethodWebAPITrigger`, and valid `TriggerRequestPayload`.
2. Create two mock `handlers.Callback` implementations (`callbackA`, `callbackB`) recording calls to `SendResponse`.
3. Call `h.HandleLegacyUserMessage(ctx, msgA, callbackA)` then `h.HandleLegacyUserMessage(ctx, msgB, callbackB)`.
4. Assert `h.savedCallbacks["X"].Callback == callbackB` (A's callback was overwritten).
5. Construct a node response `jsonrpc.Response` with `ID="X"`, `Body.Sender = nodeAddr` matching a DON member, and call `h.HandleNodeMessage(ctx, resp, nodeAddr)`.
6. Assert `callbackB.SendResponse` was invoked (receiving a response that was actually correlated with A's original request context/payload), and `callbackA.SendResponse` was never called — demonstrating cross-user response delivery.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {

	savedCb, found := h.savedCallbacks[msg.Body.MessageId]

}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
