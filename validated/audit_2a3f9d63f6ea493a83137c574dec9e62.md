### Title
`PosixShellEscape` fails to quote strings containing bare `;`, newline, `\r`, `\t`, `]`, `{`, `}`, `~`, or `^` — shell command injection when `FF_POSIXLY_CORRECT_ESCAPES` is enabled - (File: helpers/shell_escape.go)

### Summary
`helpers.PosixShellEscape`, used by `BashWriter.escape` when the `FF_POSIXLY_CORRECT_ESCAPES` feature flag is on, only wraps output in double quotes if the input contains one of a small explicit set of trigger characters (`` ` " \ $ `` plus a short quo-list: space `!#%&()*<=>?[|`). Any byte not in that table (notably `;`, `\n`, `\r`, `\t`, `]`, `{`, `}`, `~`, `^`) is written through **literally with no escaping and does not set the `escape` flag**, so a string made up solely of "safe-looking" characters plus one of these omitted metacharacters is returned completely unquoted from `PosixShellEscape`.

### Finding Description
`PosixShellEscape` (helpers/shell_escape.go, `posixModeTable` at lines 90-95 and function body at lines 98-126) builds the escaped string byte-by-byte: [1](#0-0) 

- Case `quo` (space, `!#%&()*<=>?[|`): byte is written as-is and `escape=true` is set, causing the whole string to be wrapped in double quotes.
- Case `""` (the zero value, meaning the byte is **not present** in `posixModeTable`): the byte is written as-is and `escape` is left untouched.
- `default` case (`` ` " \ $ ``): a backslash-escaped literal is written and `escape=true` is set.

The bug is that the comparable set of trigger characters used by the non-POSIX `ShellEscape` (`modeTable`, lines 26-48) includes `;` and `:` in its `quo` set, but `posixModeTable` omits `;` entirely, along with `\n`, `\r`, `\t`, `]`, `{`, `}`, `~`, `^`. These bytes fall into the `case ""` branch: they get written literally, and — critically — **do not force the surrounding double-quote wrap**. If a value contains only these omitted characters combined with otherwise ordinary letters/digits (i.e. no space, `!`, `#`, `%`, `&`, `(`, `)`, `*`, `<`, `=`, `>`, `?`, `[`, `|`, `` ` ``, `"`, `\`, or `$`), `escape` never becomes `true` and the function returns the raw, completely unquoted attacker string.

This function feeds `BashWriter.escape` (shells/bash.go, lines 447-453), which is used as the `stringQuoter` for `BashWriter.Command`, `CommandWithStdin`, `IfCmd`, `IfCmdWithOutput`, `Variable`, `Printf`/`Noticef`/`Warningf`/`Errorf`, `SectionStart`, and the `SetupGitCredHelper` section/helper-command arguments: [2](#0-1) [3](#0-2) 

Any of these values ends up embedded directly in the generated bash script body, which is later executed via `eval` inside `Finish()`: [4](#0-3) 

Because `Finish()` also escapes the whole script body with `b.escape(b.String())` before the outer `eval`, and that outer escaping is subject to the exact same `PosixShellEscape` weakness, an unescaped `;`/newline embedded by an inner call can break out of the intended single statement once the outer `eval` unwraps it, injecting an arbitrary additional shell statement that executes with the job's privileges.

Existing protections that fail here: the only existing check is the `escape` boolean gating whether the string gets quote-wrapped; it is a purely character-driven heuristic with an incomplete character set, so no additional validation (e.g. allow-listing, secondary escaping, or output verification) exists to catch the gap.

Note: `SetupGitCredHelper`'s final `git config -f %[1]s %[5]s %[6]s` line passes the `user` argument completely raw with no call to `b.escape` or `doubleQuote` at all (shells/bash.go, lines 165-184) — a related but distinct unescaped-injection point, contingent on where `user` originates (this call chain's caller was not fully traced in the available index, so its exploitability is not confirmed and is called out only as an adjacent risk, not part of this finding's proof).

### Impact Explanation
An attacker who controls any value later passed through `b.escape` in POSIX-escape mode (job variable value, `CI_JOB_TOKEN`-adjacent config values, git remote/URL-derived strings, or other project/pipeline-controlled strings written via `Variable`, `Command`, `Printf`, etc.) and can craft that value to contain `;` or a raw newline without any of the trigger characters, can inject additional shell statements into the generated build script. Those statements execute with the job's own execution identity inside the same script that exports credential-helper tokens and other stage-scoped secrets, allowing the injected command to read/exfiltrate exported auth variables (e.g. `CI_JOB_TOKEN`, git credential helper output) or otherwise manipulate subsequent commands in the same script — a real "escape the intended single command" bug matching the audited invariant.

### Likelihood Explanation
Requires `FF_POSIXLY_CORRECT_ESCAPES` to be enabled (feature-flag gated in `NewBashWriter`, shells/bash.go line 121) and an attacker-influenced value flowing into any `b.escape`-quoted context without also containing one of the trigger characters. This is a realistic condition for a pipeline author supplying custom variable values, since values like `foo;touch pwned` or values containing a bare newline contain no quo/default-triggering byte. The bug is deterministic and fully reproducible without race conditions or timing — a simple crafted string triggers it every time the flag is on.

### Recommendation
Add `;`, `\n`, `\r`, `\t`, `]`, `{`, `}`, `~`, `^`, and any other POSIX shell special characters (word/command separators, glob/brace/tilde-expansion triggers) to `posixModeTable` as `quo` entries so that their mere presence forces the double-quote wrap, mirroring the more complete `modeTable` used by `ShellEscape`. Also audit and fix the unescaped `user` argument passed directly (without quoting) in `SetupGitCredHelper`'s final `git config` invocation.

var posixModeTable = [256]mode{
	'`': "\\`", '"': `\"`, '\\': `\\`, '$': `\$`,

	' ': quo, '!': quo, '#': quo, '%': quo, '&': quo, '(': quo, ')': quo,
	'*': quo, '<': quo, '=': quo, '>': quo, '?': quo, '[': quo, '|': quo,
}

// PosixShellEscape double quotes strings and escapes a string where necessary.
func PosixShellEscape(input string) string {
	if input == "" {
		return "''"
	}

	var sb strings.Builder
	sb.Grow(len(input) * 2)

	escape := false
	for _, c := range []byte(input) {
		mode := posixModeTable[c]
		switch mode {
		case quo:
			sb.WriteByte(c)
			escape = true
		case "":
			sb.WriteByte(c)
		default:
			sb.WriteString(string(mode))
			escape = true
		}
	}

	if escape {
		return `"` + sb.String() + `"`
	}

	return sb.String()
}
