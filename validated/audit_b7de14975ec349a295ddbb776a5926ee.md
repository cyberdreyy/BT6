### Title
Stale confirmations from removed multisig members are still counted toward the execution threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges confirmations for requests that were *originated* by the removed member; it does not purge that member's *confirmations* on other still-pending requests. Since `confirm` counts entries in the per-request `confirmations: HashSet<String>` without validating that each entry still corresponds to a current member of `self.members`, a request can reach `num_confirmations` and execute even though one or more of the counted "votes" belong to an account/key that has since been removed from the multisig.

### Finding Description
`confirm` accepts or executes a request purely by counting strings in the `confirmations` set for that `request_id`: [1](#0-0) 

The set is populated with `member.to_string()` when a live member confirms: [2](#0-1) 

`delete_member` is the only code path that removes a member and cleans up confirmation state, but it filters exclusively on requests where the removed member was the *original requester* (`r.member == member`), then wipes those confirmations. It does **not** scan or clean the `confirmations` entries of other pending requests that the removed member may have separately confirmed: [3](#0-2) 

So the binding that should hold — "number of confirmations counted for a request == number of *currently authorized* members who approved it" — is broken: `confirmations.len()` can include ghost votes from accounts/keys no longer in `self.members`. `execute_request`'s `Transfer` action (and other privileged actions like `AddKey`/`FunctionCall`) will then run once the (partially stale) count reaches `num_confirmations`: [4](#0-3) 

### Impact Explanation
This maps directly to the "multisig request executed below threshold" Critical-impact category: a K-of-N approval can be satisfied with fewer than K *live* member approvals. Concretely, if a member's key is compromised and that member confirmed a malicious `Transfer` request before being detected and removed via `DeleteMember`, their stale confirmation continues to count. Removing the compromised member does not retroactively invalidate the vote already cast, so the malicious transfer can still execute with one fewer live confirmer than the configured threshold, moving NEAR out of the account without the intended K distinct current authorizations.

### Likelihood Explanation
Requires two conditions that are realistic operational events for this contract: (1) an existing pending, partially-confirmed request, and (2) a subsequent `DeleteMember` of one of that request's confirmers (e.g. as an incident-response action after key compromise, or normal membership rotation). Both are ordinary multisig operations already supported by the contract, so no privileged bypass or redeploy is needed beyond using the multisig's own existing member-management feature as designed.

### Recommendation
When a member is deleted, iterate all pending requests and strip that member's entry from every `confirmations` set (not only requests they authored), and re-evaluate whether any request should be dropped/re-opened for confirmation. Alternatively, validate at confirm/execute time that every string in a request's `confirmations` set corresponds to an entry still present in `self.members`, and only count still-valid confirmations toward `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `B` calls `add_request` to create malicious `Transfer` request `R` to an attacker-controlled account.
3. `A` calls `confirm(R)` → `confirmations = {A}` (1/3).
4. The multisig detects `A`'s key is compromised and, via a separate confirmed `DeleteMember{A}` request, removes `A`. `delete_member` only cleans confirmations for requests *authored* by `A`; `R` was authored by `B`, so `confirmations = {A}` on `R` is untouched. Members are now `{B, C, D}`, still satisfying `members.len() - 1 >= num_confirmations` check. [5](#0-4) 
5. `B` calls `confirm(R)` → `confirmations = {A, B}` (2/3, but only `B` is currently live).
6. `C` calls `confirm(R)` → count reaches `3 >= num_confirmations`, so `execute_request` fires the `Transfer`, even though only `B` and `C` are still authorized members — the removed member `A`'s stale vote supplied the third confirmation. [6](#0-5)

    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }

        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);

            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),

        }
