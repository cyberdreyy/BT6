### Title
Zip-slip path traversal via unsanitized `zip.File.Name` in symlink/file extraction - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile`, `extractZipSymlinkEntry`, and `extractZipFileEntry` use `file.Name` (and the symlink target payload) directly as filesystem paths with no `..`/absolute-path sanitization or containment check against the extraction root. This is the classic "zip-slip" bug: a crafted cache/artifact zip entry named e.g. `../../etc/cron.d/x` is written or symlinked outside the intended extraction directory.

### Finding Description
`ExtractZipFile` opens a zip and calls `ExtractZipArchive`, which iterates `archive.File` and calls `extractZipFile(file)` for each entry. [1](#0-0) 
That function only checks the `.git` directory case (`errorIfGitDirectory`) and creates parent directories via `os.MkdirAll(filepath.Dir(file.Name), ...)`, then dispatches based on entry mode:
- Regular files go to `extractZipFileEntry`, which does `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` directly on the raw, attacker-controlled `file.Name`. [2](#0-1) 
- Symlink entries go to `extractZipSymlinkEntry`, which reads the link target from the entry's data and calls `os.Symlink(string(data), file.Name)` — again using the raw `file.Name` with no validation of either the link path or the link target. [3](#0-2) 

None of `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, or `extractZipFile` clean/normalize `file.Name`, reject `..` segments, reject absolute paths, or verify the resolved path stays under the extraction root. The only sanitization present in `helpers/archives/path_check_helper.go` (`errorIfGitDirectory`/`isPathAGitDirectory`) is specific to blocking `.git` paths, not path traversal. [4](#0-3) 

This is notably inconsistent with the sibling tar/zstd extractor in the codebase, `commands/helpers/archive/tarzstd/tarzstd_extractor.go`, which explicitly resolves each entry with `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if it doesn't have the extraction directory as a prefix ("cannot be extracted outside of chroot"). The zip path (`helpers/archives/zip_extract.go`, used via `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) has no equivalent guard — `ziplegacy`'s `Extract` simply forwards to `archives.ExtractZipArchive(zr)` with no chroot check of its own. [5](#0-4) 

Because ordinary regular-file entries already write through the raw `file.Name` without containment checks, an attacker does not even need the symlink indirection described in the question — a single crafted entry named `../../etc/cron.d/x` (or an absolute path) in a zip is enough to write outside the extraction root when the archive is restored via `ExtractZipFile`/`ExtractZipArchive` (reached from cache/artifact restoration code paths such as `commands/helpers/cache_extractor.go` and `commands/helpers/artifacts_downloader.go`). The symlink variant described in the question (`ModeSymlink` entry with a traversal `Name`, followed by a regular entry that writes through the resulting dangling symlink) works identically since `os.Symlink(data, file.Name)` also has no path validation.

### Impact Explanation
A job author who controls the content of their own cache or artifact zip can cause the runner (or helper binary, e.g. `gitlab-runner-helper` running the `extract` subcommand) to create/overwrite files and symlinks outside the intended cache/artifact/build root, anywhere the runner process has filesystem write permission. This can lead to arbitrary file write/overwrite on the runner or helper filesystem (e.g., overwriting scripts run by later jobs, planted cron files, or corrupting other build directories), which matches the scoped impact ("unauthorized file write outside build/cache/artifact roots").

### Likelihood Explanation
This is highly reachable: a normal, unprivileged pipeline author can build a cache/artifact zip with arbitrary entry names as part of their own job (e.g., by generating the zip manually and pushing it as artifact/cache content, or by crafting a `.zip` file directly since GitLab Runner accepts arbitrary artifact/cache archives). When that cache/artifact is later restored (same job re-run, subsequent job/pipeline sharing the cache key, or artifact download), `ExtractZipFile` runs the vulnerable code unconditionally on every job that restores it. No special permissions or race conditions are required — this is a straightforward, deterministically reproducible zip-slip.

### Recommendation
In `helpers/archives/zip_extract.go`, before extracting each entry, resolve `file.Name` against the extraction root (`filepath.Join(root, file.Name)`), `filepath.Clean` it, and verify (like `tarzstd_extractor.go` does) that the resolved absolute path has the extraction root as a prefix, rejecting the entry otherwise. Additionally, for symlink entries, validate the resolved link target (or at minimum keep the link target confined, or drop the ability to write absolute/`..`-escaping symlink targets) before calling `os.Symlink`. Reuse or generalize the containment check already implemented in `tarzstd_extractor.go` for both `ziplegacy` and `zip_extract.go`.

### Proof of Concept
Go unit test to add to `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir() // simulate "outside extraction root"

    // Build a zip whose entry name escapes tmpDir via ../
    zipPath := filepath.Join(tmpDir, "evil.zip")
    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)
    traversalName := filepath.Join("..", filepath.Base(outsideDir), "pwned.txt")
    w, _ := zw.Create(traversalName)
    _, _ = w.Write([]byte("owned"))
    _ = zw.Close()
    _ = f.Close()

    wd, _ := os.Getwd()
    _ = os.Chdir(tmpDir)
    defer os.Chdir(wd)

    err := archives.ExtractZipFile(zipPath)
    require.NoError(t, err)

    // Assertion: file must NOT exist outside tmpDir
    _, statErr := os.Stat(filepath.Join(outsideDir, "pwned.txt"))
    assert.True(t, os.IsNotExist(statErr), "zip-slip: file was written outside extraction root")
}
```
Expected current (buggy) behavior: the assertion fails because `pwned.txt` is created in `outsideDir`, proving the containment invariant is violated. A fuzz variant (`FuzzExtractZipArchive`) can generate random `Name`/`Linkname` values containing `../` and absolute paths and assert no writes occur outside a temp root, per the question's proof idea.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```
