Based on my investigation, I found a real analog worth flagging in the vault gateway's `DeleteSecrets` and `CreateSecrets`/`UpdateSecrets` flows: the write/delete paths never re-stamp the payload's `Owner` field to the caller's `AuthorizedOwner()`, unlike `handleSecretsList`, which does.

### Title
Missing enforcement that vault `DeleteSecrets` / `CreateSecrets` / `UpdateSecrets` secret `Owner` fields match the authorized caller - ([File: core/capabilities/vault/validator.go])

### Summary
The report describes `arbitraryCall()` trusting a caller-controlled `who` parameter without checking that it doesn't reference a protected resource (an incentive token), letting a privileged caller act on behalf of unrelated users. The closest unprivileged-client analog in Chainlink is the Vault capability's gateway request pipeline, where `Owner` is an attacker-controlled field embedded inside JSON-RPC params for `secrets/delete`, `secrets/create`, and `secrets/update`, and is validated only for format (`ValidateSecretIdentifier`) — never checked for equality against the authenticated caller's `AuthorizedOwner()`.

### Finding Description
`GatewayVaultRequestProcessor.authorizeAndStamp` [1](#0-0)  authorizes the *envelope* (`req.ID`/digest) via `AuthorizeRequest`, and only rewrites `req.ID` with `authorizedOwner + separator + originalRequestID`. It does **not** rewrite or verify the `Owner` field(s) embedded inside `CreateSecretsRequest.EncryptedSecrets[i].Id.Owner`, `UpdateSecretsRequest.EncryptedSecrets[i].Id.Owner`, or `DeleteSecretsRequest.Ids[i].Owner`.

`RequestValidator.ValidateDeleteSecretsRequest` and `validateWriteRequest` only validate that `Owner` is present and well-formed (`ValidateSecretIdentifier`) [2](#0-1) [3](#0-2)  — there is no comparison against the digest-authorized owner from `AuthResult`.

By contrast, `handleSecretsList` explicitly overrides the caller-supplied `Owner` with the authorized owner before calling the service: `r.Owner = authResult.AuthorizedOwner()` [4](#0-3) . No equivalent override/verification exists in `handleSecretsCreate`, `handleSecretsUpdate`, or `handleSecretsDelete` [5](#0-4) .

For write requests (`create`/`update`), there is a mitigating control: `EnsureRightLabelOnSecret` checks that the TDH2 ciphertext's cryptographic label matches `vaultutils.WorkflowOwnerToLabel(owner)` [6](#0-5) , which ties the encrypted payload to a specific owner label — this appears to prevent a caller from writing secrets under an arbitrary `Owner` unless they also produced/possess a ciphertext correctly labeled for that owner. However, for `DeleteSecrets`, no such cryptographic binding exists — deletion is a metadata-only operation (identifying `Key`/`Owner`/`Namespace`), so if the workflow-registry allowlist digest check (`AllowListBasedAuth`) does not itself bind the request digest to a specific owner value inside the params (it binds only to the request's outer digest/ID, per `allow_list_based_auth.go`), an authenticated request whose *envelope* was allowlisted for owner A but whose *inner* `DeleteSecretsRequest.Ids[i].Owner` field is set to victim owner B would not be rejected by validation, since `ValidateSecretIdentifier` only checks format, not identity match to `AuthResult.AuthorizedOwner()`.

I was not able to fully verify from the index whether `AllowListBasedAuth.AuthorizeRequest`'s digest (computed over the full raw request bytes, per `req.Digest()`) transitively covers and thus effectively pins the inner `Owner` fields—if the digest is computed over the entire request body including params, then any tampering with `Owner` inside `Ids[]` would change the digest and fail allowlist lookup, closing this gap. This is the key uncertainty limiting confidence in this finding.

### Impact Explanation
If the digest does not cover per-item `Owner` fields (e.g., only covers method/ID, or if `Owner` is normalized/canonicalized in a way that a byte-different-but-logically-different payload still produces a matching digest is not the case, but there could be other multi-secret batch scenarios), a caller who is allowlisted only for their own owner could delete secrets belonging to another owner in the same batch, since batch items are validated individually for format only, and `secretsService.DeleteSecrets` is invoked with the unmodified, unstamped `Owner` values. This would constitute unauthorized destruction of another user's Vault secrets — a cross-user integrity impact analogous to the "steal another user's assets via unchecked target/owner parameter" pattern in the source report.

### Likelihood Explanation
Likelihood is **uncertain/low-to-moderate** and could not be conclusively confirmed with the tools available: `jsonrpc.Request.Digest()`'s exact implementation (whether it hashes the full params bytes, and whether allowlisting is granted per full-payload digest, meaning any change to `Owner` breaks the digest match) lives outside the currently indexed files, so I could not verify whether the digest binding closes this gap. The asymmetry between `handleSecretsList` (explicit re-stamping of `Owner`) and `handleSecretsDelete`/`Create`/`Update` (no re-stamping) is a real, concrete code-pattern inconsistency worth a defense-in-depth fix regardless.

### Recommendation
For defense-in-depth (independent of whether `Digest()` already prevents this), explicitly enforce that every `Owner` field inside `CreateSecretsRequest`, `UpdateSecretsRequest`, and `DeleteSecretsRequest` batches equals `authResult.AuthorizedOwner()` before invoking `secretsService.*`, mirroring the pattern already used in `handleSecretsList` (`r.Owner = authResult.AuthorizedOwner()`). This should be done in `GatewayVaultRequestProcessor.authorizeAndStamp` or immediately after authorization in `gw_handler.go`, rejecting the request if any item's `Owner` does not match the authorized owner, rather than trusting the caller-provided value.

### Proof of Concept
Not constructible from the indexed code alone — a live/dynamic Vault gateway test harness (e.g., extending `gw_handler_test.go`'s `TestGatewayHandler_HandleGatewayMessage`) would be needed to determine whether `jsonrpc.Request.Digest()` and the allowlist check reject a `DeleteSecretsRequest` batch where an allowlisted owner-A request ID is paired with `Ids[].Owner = "B"`. I recommend a Devin session with full repo/test access to (1) inspect `jsonrpc.Request.Digest()` in the `chainlink-common` dependency, (2) write a unit test submitting a `secrets/delete` request allowlisted for owner A with an item owner field set to B, and (3) confirm whether `handleSecretsDelete` calls `DeleteSecrets` with the unmodified (unauthorized) owner value.

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

func (r *RequestValidator) validateWriteRequest(ctx context.Context, publicKey *tdh2easy.PublicKey, id string, encryptedSecrets []*vaultcommon.EncryptedSecret, skipLabelValidation bool) error {
	if id == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(encryptedSecrets)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(encryptedSecrets) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, req := range encryptedSecrets {
		if req == nil {
			return errors.New("encrypted secret must not be nil at index " + strconv.Itoa(idx))
		}
		if req.Id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}

		if req.EncryptedValue == "" {
			return errors.New("secret must have encrypted value set at index " + strconv.Itoa(idx) + ":" + req.Id.String())
		}

		if err := r.ValidateSecretIdentifier(ctx, req.Id.Key, req.Id.Owner, req.Id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}
		if err := r.ValidateCiphertextSize(ctx, req.Id.Owner, req.EncryptedValue); err != nil {
			return fmt.Errorf("secret encrypted value at index %d is invalid: %w", idx, err)
		}
		if skipLabelValidation {
			if _, err := verifyEncryptedSecret(publicKey, req.EncryptedValue); err != nil {
				return errors.New("Encrypted Secret at index [" + strconv.Itoa(idx) + "] is invalid. Error: " + err.Error())
			}
		} else {
			err := EnsureRightLabelOnSecret(publicKey, req.EncryptedValue, req.Id.Owner)
			if err != nil {
				return errors.New("Encrypted Secret at index [" + strconv.Itoa(idx) + "] doesn't have owner as the label. Error: " + err.Error())
			}
		}
		_, ok := uniqueIDs[vaulttypes.KeyFor(req.Id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + req.Id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(req.Id)] = true
	}

	return nil
}

// EnsureRightLabelOnSecret verifies that the TDH2 ciphertext label matches the workflow
// owner label (Ethereum address, left-padded to 32 bytes). owner must be non-empty;
// when the public key is nil, verification is skipped for the same reasons as
// verifyEncryptedSecret.
func EnsureRightLabelOnSecret(publicKey *tdh2easy.PublicKey, secret, owner string) error {
	cipherText, err := verifyEncryptedSecret(publicKey, secret)
	if err != nil {
		return err
	}
	if cipherText == nil {
		return nil
	}
	if owner == "" {
		return errors.New("owner must not be empty for secret label verification")
	}

	expected := vaultutils.WorkflowOwnerToLabel(owner)
	secretLabel := cipherText.Label()
	if secretLabel == expected {
		return nil
	}

	return fmt.Errorf("secret label [%s] does not match workflow owner label [%s]",
		hex.EncodeToString(secretLabel[:]), hex.EncodeToString(expected[:]))
}

func (h *GatewayHandler) handleSecretsCreate(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	vaultCapRequest := vaultcommon.CreateSecretsRequest{}
	if err := json.Unmarshal(*req.Params, &vaultCapRequest); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized create secrets request", "request", vaultCapRequest.String())
	vaultCapResponse, err := h.secretsService.CreateSecrets(ctx, &vaultCapRequest)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.FatalError, err)
	}

	jsonResponse, err := toJSONResponse(vaultCapResponse, req.Method)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}
	return jsonResponse
}

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}
