### Title
Attacker-chosen MessageId collision in `savedCallbacks` map allows cross-user response hijacking - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores each user's response callback keyed only by the attacker-supplied `msg.Body.MessageId`, with no uniqueness/collision check and no binding to the requester's signer/sender address. A second, unrelated attacker can submit a signed message with the same `MessageId` as an in-flight legitimate request, silently overwriting the first callback so the eventual DON response is delivered to the second attacker instead of the original requester.

### Finding Description
`HandleLegacyUserMessage` validates payload shape, timestamp freshness, and method, and calls `common.ValidatedRequestFromMessage(msg)`, which enforces a valid ECDSA signature over the message body — but signature validity only proves *who signed*, not that the `MessageId` is unique or owned by that signer [1](#0-0) . `MessageId` itself is a free-form attacker-chosen string (bounded only by length/null-byte checks in `Message.Validate()`) [2](#0-1) .

After validation, the handler does an unconditional map write:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [3](#0-2) 

There is no `found`/collision check before this assignment, unlike the read side in `handleWebAPITriggerMessage`, which looks up and deletes by `MessageId` alone and delivers the response to whichever callback is currently stored:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
...
if found {
    return savedCb.SendResponse(...)
}
``` [4](#0-3) 

Exploit flow: Attacker A submits a legitimate signed `web_api_trigger` request with `MessageId = X`. Before the DON responds, Attacker B (a different, unrelated key holder) submits their own signed request also using `MessageId = X`. Both pass `Validate()`/`ValidatedRequestFromMessage` independently since signature checks are per-message, not per-ID. B's call to `HandleLegacyUserMessage` overwrites `h.savedCallbacks[X]` with B's own `callback`. A's original request has already been forwarded to DON nodes with `MessageId = X` (from A's own signed body) [5](#0-4) . When a node responds with `MessageId = X`, `handleWebAPITriggerMessage` finds B's callback in the map and delivers A's response data to B — silently, with no error and no indication to A that its response was hijacked (A's connection instead just times out/never resolves).

### Impact Explanation
This breaks request-to-response isolation between two unprivileged users of the gateway: an unrelated attacker can receive response data (trigger event payload) generated for another user's request, matching the "cross-user response confusion / attacker-controlled data returned to another user" bounty impact class. It also causes denial of delivery for the legitimate requester (their callback is orphaned and never invoked). No node/operator/DON compromise or misconfiguration is required.

### Likelihood Explanation
Exploitability requires only two things the attacker fully controls: (1) any valid ECDSA key (self-generated, free), and (2) the ability to predict or race for the same `MessageId` string as another in-flight request. Since `MessageId` is fully client-chosen with no server-side randomness/entropy requirement enforced (see `Message.Validate()`, which only bounds length and forbids trailing NUL) [2](#0-1) , collisions are trivial if IDs are ever predictable/sequential/short (e.g., counters, timestamps, or simply guessed common values), and always possible by brute-force racing many IDs against the ~120s callback TTL window (`defaultCallbackMaxAgeSec`) [6](#0-5) . This is fully repeatable and requires no special role, credential, or timing precision beyond submitting two HTTP requests to the gateway's user-facing endpoint in quick succession.

### Recommendation
Scope `savedCallbacks` keys by both `MessageId` and the validated `Sender` (signer address), or reject/return an error when a `MessageId` already has a pending callback instead of overwriting it. E.g., change the key to `sender + ":" + MessageId`, or add an explicit `if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists { return error }` check under the lock before insertion, and correspondingly key/verify sender on the response-delivery path in `handleWebAPITriggerMessage`.

### Proof of Concept
Go handler-level test plan (in `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Set up `handler` via `setupHandler(t)`.
2. Generate two distinct ECDSA keys, `keyA` and `keyB` (e.g., via `crypto.GenerateKey()`).
3. Build `msgA := triggerRequest(t, keyA, ..., "" /*timestamp*/, "")` and `msgB` with the same helper but force `msgB.Body.MessageId = msgA.Body.MessageId` (re-sign with `keyB` after setting the ID so the signature is valid for B).
4. Create `cbA := hc.NewCallback()` and call `err := handler.HandleLegacyUserMessage(ctx, msgA, cbA)`; expect `require.NoError(t, err)`.
5. Create `cbB := hc.NewCallback()` and call `err = handler.HandleLegacyUserMessage(ctx, msgB, cbB)`; expect current (vulnerable) behavior: `require.NoError(t, err)` with **no collision error**, demonstrating the overwrite. Assert `handler.savedCallbacks[msgA.Body.MessageId].Callback == cbB` (not `cbA`), proving overwrite.
6. Simulate the DON node response for `MessageId = msgA.Body.MessageId` via `handler.HandleNodeMessage(ctx, resp, nodeAddr)`, and assert that `cbB.Wait(ctx)` receives the response (intended for A) while `cbA.Wait(ctx)` times out/never resolves — proving cross-user response hijacking.
7. Expected fix behavior: step 5 should instead return an error (e.g., "duplicate message id") and `cbB` should never receive A's response.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
```
