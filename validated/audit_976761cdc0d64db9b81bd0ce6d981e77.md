## Title
Multisig requests can execute below the required confirmation threshold because confirmations from removed members are never purged - (`File: multisig2/src/lib.rs`)

## Summary
The `GovernanceProxy` report describes state (`pendingChanges`) that persists indefinitely and can later be executed even though it has become stale/invalid. The same bug class exists in the `multisig`/`multisig2` contracts: a `confirm()` recorded by a member is stored keyed only by `RequestId`, and when that member is later removed from the multisig, only requests that member *originally created* are purged — their confirmations on *other* pending requests are never scrubbed. Those stale confirmations remain forever eligible to count toward `num_confirmations`, letting a request execute with fewer genuinely live approvals than the threshold requires.

## Finding Description
In `multisig2/src/lib.rs`, confirmations are stored in `confirmations: LookupMap<RequestId, HashSet<String>>` keyed by `RequestId` only [1](#0-0) . When a member is removed via `DeleteMember`, `delete_member()` only removes requests where the removed member was the *original requester* (`r.member == member`) — it does not scan or purge the `confirmations` set of any other outstanding request that the removed member had confirmed: [2](#0-1) 

`confirm()` then evaluates the threshold purely by counting entries already present in that `HashSet<String>`, regardless of whether those members are still in `self.members`: [3](#0-2) 

So the binding that should hold is:
```
confirmations_counted(request) == confirmations_from_live_members(request)
```
But after a `DeleteMember` action, a stale confirmation from a now-removed member remains counted, breaking this equality: `confirmations_counted(request) > confirmations_from_live_members(request)`.

The same pattern exists in the older `multisig/src/lib.rs` contract: `DeleteKey` only removes requests whose original signer (`r.signer_pk`) is the deleted key, not confirmations by that key on other requests [4](#0-3) , and `confirm()` there similarly just counts whatever is in the `confirmations` `HashSet<PublicKey>` [5](#0-4) .

## Impact Explanation
This lets a multisig request be executed with a real live-approval count below `num_confirmations` — i.e. "a multisig request executed below threshold," explicitly listed as a Critical impact. Because `MultiSigRequestAction` includes `Transfer`, `FunctionCall`, `AddKey`, etc., an attacker who can arrange for one confirming member to be later removed (a routine multisig operation, not requiring foundation/owner privilege beyond normal membership changes) can get a fund-transfer or key-addition request executed while only one genuinely live member actually endorsed it at execution time.

## Likelihood Explanation
This requires normal multisig activity: some member confirms a pending request, then that same member is removed from the multisig for unrelated reasons (turnover, compromise response, rotation) before the request reaches full confirmation, and a remaining member later pushes the confirmation count over the threshold. Membership rotation among N-of-K governance/treasury multisigs is a routine, foreseeable event, making this more than a theoretical edge case.

## Recommendation
When a member/key is deleted, scan `confirmations` for all outstanding requests and remove the entry corresponding to the removed member (not just requests they originated), or re-validate at `confirm()`/execution time that every entry in a request's confirmation set still corresponds to a current member of `self.members`.

## Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C]`, `num_confirmations = 2`.
2. `A` calls `add_request(R)` where `R` is e.g. a `Transfer` to an attacker-controlled account — `R` is stored with `member = A`, `confirmations = {}` [6](#0-5) .
3. `B` calls `confirm(R)` → `confirmations(R) = {B}` (1 < 2, not yet executed) [3](#0-2) .
4. Via a separate, properly-confirmed request, the multisig executes `DeleteMember{member: B}`. `delete_member()` removes `B` from `self.members` but leaves `R` and its `confirmations = {B}` untouched because `R.member == A`, not `B` [7](#0-6) .
5. `A` calls `confirm(R)` again. `confirmations(R).len() (1, from removed B) + 1 = 2 >= num_confirmations (2)` → `R` executes the `Transfer`, even though only one currently-live member (`A`) actually authorized it at execution time [8](#0-7) .

                "Predecessor must be a member or transaction signed with key of given account",

            .unwrap_or(0)

            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
