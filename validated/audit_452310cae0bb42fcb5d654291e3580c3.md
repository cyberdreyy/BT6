### Title
`end_receivership` clears `ACCOUNT_IN_RECEIVERSHIP` using account health computed from stale (non-accrued) bank interest - (File: `programs/marginfi/src/instructions/marginfi_account/liquidate_end.rs`)

### Summary
`end_receivership` (shared by `end_liquidation` and `end_deleverage`) computes the liquidatee's post-action health and, if it is not worse than the pre-liquidation snapshot, immediately clears the `ACCOUNT_IN_RECEIVERSHIP` flag. Unlike `lending_account_liquidate`, which explicitly calls `bank.accrue_interest(...)` on both the asset and liability banks before computing pre/post health [1](#0-0) , neither `start_receivership` nor `end_receivership` accrue interest on the account's banks themselves [2](#0-1) [3](#0-2) .

### Finding Description
This mirrors the reported Ditto bug: a function that is capable of resetting an unhealthy/flagged state (there, `combineShorts` resetting the short's flag; here, `end_receivership` clearing `ACCOUNT_IN_RECEIVERSHIP`) does not force a fresh accrual of debt before evaluating whether the position is now healthy enough to have its flag cleared.

In marginfi, interest accrual is per-bank and is only triggered by instructions that directly touch that bank (deposit, withdraw, borrow, repay, close_balance, or the atomic `lending_account_liquidate` path) [4](#0-3) [5](#0-4) . During receivership (the "start liquidation ... withdraw/repay ... end liquidation" flow), `end_receivership` calls `check_pre_liquidation_condition_and_get_account_health` and `get_health_components` with `HealthPriceMode::Cached` to compute `post_health`, using whatever share-value/exchange-rate state each bank currently has — it does not itself call `accrue_interest` on any bank in the account's `lending_account` [6](#0-5) . It then unconditionally clears `ACCOUNT_IN_RECEIVERSHIP` as long as `pre_health <= post_health` (or `ignore_healthy` is set) [7](#0-6) .

If the receivership transaction's remedial actions (withdraw/repay) do not touch every bank the liquidatee holds a position in (e.g., collateral is seized from one bank while a liability sits in a different bank that the receiver never issues a repay/withdraw against during that tx, or interest for that liability bank simply hasn't been refreshed in a while and no other instruction in the batch touches it), that liability bank's `liability_share_value` remains stale/understated. The post-health computed in `end_receivership` would then understate the true liability, allowing the health comparison to pass and `ACCOUNT_IN_RECEIVERSHIP` to be cleared even though the account is still actually unhealthy once interest is properly accrued.

### Impact Explanation
Clearing `ACCOUNT_IN_RECEIVERSHIP` prematurely returns full control to the original account authority and ends the liquidation attempt, even though the underlying account remains under-collateralized once debt is accrued correctly. The account would then need to be re-flagged via `StartLiquidation` again, delaying resolution of bad debt and extending the window during which the protocol carries unhealthy/underwater exposure — directly analogous to the impact described in the source report (flag incorrectly reset, timer/flow must restart, unhealthy position persists longer).

### Likelihood Explanation
This requires a receiver to structure the liquidation/deleverage transaction such that a liability-bearing bank is not touched by an interest-accruing instruction (deposit/withdraw/borrow/repay) within the same transaction, while another position in the account is remediated enough that overall `post_health >= pre_health` under the stale exchange rate. This is a plausible, permissionless-liquidator-controlled sequencing rather than a purely theoretical scenario, since `end_receivership` is reachable by any permissionless liquidator via `end_liquidation` and by the risk admin via `end_deleverage`.

### Recommendation
Before computing `post_health` in `end_receivership`, iterate the liquidatee's active balances and call `bank.accrue_interest(...)` on every bank referenced by an active balance (similar to what `lending_account_liquidate` does for the two banks it directly operates on), so that the health check used to decide whether to clear `ACCOUNT_IN_RECEIVERSHIP` is always computed against freshly accrued debt values.

### Proof of Concept
1. Liquidatee account has Balance A (collateral, Bank_A) and Balance B (liability, Bank_B); Bank_B has not accrued interest recently, so `liability_share_value` understates true debt.
2. Attacker/receiver calls `StartLiquidation`, then within the same tx only interacts with Bank_A (e.g., `withdraw` some collateral, which calls `accrue_interest` only on Bank_A per `programs/marginfi/src/instructions/marginfi_account/withdraw.rs`), never touching Bank_B.
3. Receiver calls `EndLiquidation`. `end_receivership` computes `post_health` using `HealthPriceMode::Cached`, which reads Bank_B's stale (understated) liability share value.
4. Because the stale debt figure makes the account look no worse (or even healthier) than the pre-liquidation snapshot, the `pre_health > post_health` check in `end_receivership` passes and `ACCOUNT_IN_RECEIVERSHIP` is cleared [7](#0-6) , even though accruing Bank_B's real interest would show the account still unhealthy.

pub fn start_receivership<'info>(
    marginfi_account: &mut MarginfiAccount,
    liq_record: &mut LiquidationRecord,
    remaining_ais: &'info [AccountInfo<'info>],
    ignore_healthy: bool,
) -> MarginfiResult {
    // Note: the receiver can use the health cache state after this ix concludes to plan their
    // liquidation/deleverage strategy.
    let mut health_cache = HealthCache::zeroed();
    let mut liq_price_cache = LiquidationPriceCache::default();
    let (_pre_health, assets, liabs) = check_pre_liquidation_condition_and_get_account_health(
        marginfi_account,
        remaining_ais,
        None,
        &mut Some(&mut health_cache),
        HealthPriceMode::Live {
            liq_cache: Some(&mut liq_price_cache),
        },
        ignore_healthy,
    )?;

    // Use heap-efficient equity calculation
    let (assets_equity, liabs_equity) = get_health_components(
        marginfi_account,
        remaining_ais,
        RequirementType::Equity,
        &mut Some(&mut health_cache),
        HealthPriceMode::Live {
            liq_cache: Some(&mut liq_price_cache),
        },
    )?;

    write_liquidation_price_cache_from(marginfi_account, remaining_ais, &liq_price_cache)?;
    marginfi_account.health_cache = health_cache;
    marginfi_account.set_flag(ACCOUNT_IN_RECEIVERSHIP, false);
    marginfi_account.indexer_flags.has_ever_been_liquidated = 1;

pub fn end_receivership<'info>(
    marginfi_account: &mut MarginfiAccount,
    liq_record: &mut LiquidationRecord,
    remaining_ais: &'info [AccountInfo<'info>],
    ignore_healthy: bool,
) -> Result<(I80F48, f64, I80F48, f64)> {
    let pre_assets: I80F48 = liq_record.cache.asset_value_maint.into();
    let pre_liabs: I80F48 = liq_record.cache.liability_value_maint.into();
    let pre_assets_equity: I80F48 = liq_record.cache.asset_value_equity.into();
    let pre_liabs_equity: I80F48 = liq_record.cache.liability_value_equity.into();
    let pre_health: I80F48 = pre_assets - pre_liabs;

    let mut post_hc = HealthCache::zeroed();
    let (post_health, _post_assets, _post_liabs) =
        check_pre_liquidation_condition_and_get_account_health(
            marginfi_account,
            remaining_ais,
            None,
            &mut Some(&mut post_hc),
            HealthPriceMode::Cached,
            ignore_healthy,
        )?;
    let (post_assets_equity, post_liabilities_equity) = get_health_components(
        marginfi_account,
        remaining_ais,
        RequirementType::Equity,
        &mut Some(&mut post_hc),
        HealthPriceMode::Cached,
    )?;

    clear_liquidation_price_cache_locks(marginfi_account, remaining_ais)?;
    marginfi_account.health_cache = post_hc;

    // health must not get worse
    if pre_health > post_health {
        msg!(
            "pre_health > post_health: {} >= {}",
            pre_health,
            post_health
        );
        return err!(MarginfiError::WorseHealthPostLiquidation);
    }

    let seized: I80F48 = pre_assets_equity - post_assets_equity;
    let repaid: I80F48 = pre_liabs_equity - post_liabilities_equity;

    // clear receivership
    marginfi_account.unset_flag(ACCOUNT_IN_RECEIVERSHIP, false);
