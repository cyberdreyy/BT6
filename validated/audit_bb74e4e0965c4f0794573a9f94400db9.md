### Title
Carried `unclaimedFees` become permanently stranded and permanently haircut LP NAV when the pool is closed via `stopEpoch(0, 1)` - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
When `stopEpoch` is called with the close-pool sentinel `_interest == 1`, cash-funded fees are capped at the epoch's residual gross interest (`_availableForFees = _grossInterest - _pendingWithdrawFees`) and only the payable portion is deducted from `unclaimedFees` (`unclaimedFees -= _fees`). Any accrued fee balance that exceeds this cap stays in `unclaimedFees`. Because closing the pool sets `epochDuration = 0` and `epochEndDate = 0`, and both `setEpochParams` and `startEpoch` permanently revert once `epochDuration == 0`, no subsequent `stopEpoch` can ever run — so the carried `unclaimedFees` can never be paid to `feeReceiver`/`owner`, while `getContractValue()` keeps subtracting them from LP NAV forever. This is the idle-tranches analog of "unclaimed yield stranded by an irreversible state transition."

### Finding Description
- `getContractValue()` computes NAV as `strategyToken balance + token balance - unclaimedFees`, so every unit of `unclaimedFees` is a real claim senior to tranche holders [1](#0-0) .
- During `_stopEpoch`, the non-minted path only pays out `min(unclaimedFees, _grossInterest - _pendingWithdrawFees)` in cash and leaves the remainder accrued: `unclaimedFees -= _fees` with the comment "Any fee that cannot be paid in cash remains accrued and continues reducing NAV" [2](#0-1) .
- In close-pool mode (`_interest == 1`), `_grossInterest` is only the final epoch's interest (principal is added to `_expectedInterest` but excluded from `_grossInterest`), so any `unclaimedFees` carried from prior underperforming epochs — or a management fee accrued over a long epoch that exceeds the final gross interest — survives the payout [3](#0-2) .
- After closing, `disableInstantWithdraw = true; epochDuration = 0; epochEndDate = 0;` [4](#0-3) .
- The pool is then irreversibly closed: `setEpochParams` reverts when `epochDuration == 0` [5](#0-4) , and `startEpoch` reverts when `epochDuration == 0` [6](#0-5) . No code path other than `_stopEpoch`/harvest-style fee deposit ever clears or pays `unclaimedFees`, and `_depositFees` does not exist in the credit-vault variant — there is no `harvest`.
- The residual `unclaimedFees` therefore sits in a state exactly like the Aloe courier's unclaimed rewards: an accrued, NAV-reducing entitlement that no function can ever disburse. LPs redeem at a permanently depressed `virtualPrice`/`tranchePrice`, and the fee beneficiaries never receive the tokens — the backing underlying simply stays inside the strategy/CDO as dead value.

The only other clearing path, `finalizeDefault`, explicitly zeroes `unclaimedFees` (waiving fees on hard default) [7](#0-6) , proving the codebase recognizes stranded fee claims must be resolved on terminal transitions — but the close-pool transition omits the same handling.

### Impact Explanation
Permanent freezing of unclaimed yield plus a permanent LP NAV haircut. Quantified: the stuck amount equals `unclaimedFees - paidFees` at close time. With a 2% management fee on a 10,000-underlying pool and a final-epoch gross interest of 100, the carried fee is ~100 underlyings (per the existing test `testStopEpochCarriesManagementFeesAboveGrossInterest`, which asserts the carry). If the manager then closes the pool, that ~100 underlyings of fee entitlement can never be claimed and ~100 underlyings of LP redemption value is destroyed — the underlying tokens remain locked in the strategy backing a fee claim nobody can exercise.

### Likelihood Explanation
Requires no attacker action — only the honest manager calling `stopEpoch(0, 1)` while `unclaimedFees > _grossInterest - _pendingWithdrawFees`. This occurs whenever carried fees exist (a prior underperforming epoch) or a long epoch accrues management fees exceeding its final interest. Closing a pool is a designed, reachable state.

### Recommendation
On the close-pool path (`_isRequestingAllFunds`), settle the full `unclaimedFees` balance from the recalled principal (the gross principal recall already includes fee backing, per the `testClosePoolRecallsGrossPrincipalBackingCarriedFees` invariant), or explicitly waive it as `finalizeDefault` does by zeroing `unclaimedFees` before crystallizing final prices, so LPs are not charged for a fee that is never paid.

### Proof of Concept
```solidity
// Foundry fork test against the credit-vault CDO (mirrors test/foundry/IdleCreditVault.t.sol setup)
function testClosePoolStrandsCarriedFees() external {
    uint256 amount = 10_000 * ONE_SCALE;
    _setManagementFee(2_000); // 2% annualized
    idleCDO.depositAA(amount);
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());

    // epoch 1: low gross interest so management fee carries into unclaimedFees
    vm.startPrank(manager);
    cdoEpoch.setEpochParams(365 days, 0);
    IdleCreditVault(address(strategy)).setApr(initialProvidedApr);
    cdoEpoch.startEpoch();
    vm.stopPrank();

    deal(defaultUnderlying, borrower, 100 * ONE_SCALE); // low gross interest
    vm.warp(cdoEpoch.epochEndDate());
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 100 * ONE_SCALE);
    uint256 carried = cdoEpoch.unclaimedFees();
    assertGt(carried, 0); // fee carry exists

    // epoch 2: close pool via _interest == 1 sentinel, zero interest
    vm.prank(manager);
    cdoEpoch.startEpoch();
    deal(defaultUnderlying, borrower, strategyToken.balanceOf(address(cdoEpoch)));
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 1); // close pool

    // carried fees survive but can never be paid: epochDuration == 0 permanently
    assertEq(cdoEpoch.epochDuration(), 0);
    assertGt(cdoEpoch.unclaimedFees(), 0); // stranded
    vm.expectRevert(); // startEpoch blocked forever
    vm.prank(manager);
    cdoEpoch.startEpoch();
    // LP NAV permanently reduced by the stranded fee claim
    assertLt(cdoEpoch.getContractValue(), strategyToken.balanceOf(address(cdoEpoch)));
}
```
