The external bug is a "size grew past the tracked basis, so the revert/payout spends more than was funded" class. The closest credit-vault analog lives in the post-default withdraw path of `IdleCreditVault`, where post-default receipts are paid 1:1 from a recovery reserve that was sized only for default-epoch claimants.

### Title
Post-default withdraw requests pay par from the recovery reserve, stealing recovery funds from defaulted claimants - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`finalizeDefaultRecovery` sizes `defaultRecoveryReserve` to exactly cover the default-epoch claim basis (`totalBasis * defaultRecoveryPrice`). After finalization, `requestWithdraw` lets any tranche holder open a `postDefaultRequests` receipt that is paid 1:1 out of that same reserve via `_transferDefaultRecovery`, without adding any backing or haircut. Because post-default claims were never included in `totalBasis`, each post-default claim consumes reserve that belongs to defaulted-epoch receipt holders; once the reserve is drained, their claims revert permanently.

### Finding Description
In `requestWithdraw`, when `defaultRecoveryFinalized` is true, the CDO's strategy tokens are burned, an equal amount is minted to the user, and `postDefaultRequests[_user] = _amount` is recorded [1](#0-0) . No underlying moves into the reserve: `defaultRecoveryReserve` is untouched.

`finalizeDefaultRecovery` sets `reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve` and `defaultRecoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` [2](#0-1) . By construction, the reserve equals the sum of all default-epoch entitlements (`claimBasis * price / RECOVERY_FULL`), modulo dust. Active-side value was settled separately by rebasing the CDO's strategy-token balance to `activeFinalNAV` — it was not earmarked in the reserve [3](#0-2) .

`_claimPostDefaultWithdrawRequest` then pays `postDefaultRequests` at par via `_transferDefaultRecovery`, which decrements `defaultRecoveryReserve` [4](#0-3) [5](#0-4) . This is the analog of `iov_iter_revert(&msg->msg_iter, msg_pl->sg.size - orig_size)`: the payout iterator was sized against a larger "sg.size" (post-default receipts minted on top) than the funded "msg_iter" basis (only default-epoch `totalBasis`).

Concretely: a defaulted receipt holder entitled to `basis * price` can be front-run. An attacker holding tranche tokens worth `price * X` post-haircut calls `requestWithdraw` (through `IdleCDOEpochVariant`), then `claimWithdrawRequest` in the same or next transaction, receiving `X` underlying at par. Each such claim removes `X` from a reserve that owed only `price * X` worth of capacity to attacker-equivalent claims. When the reserve is exhausted, `_transferDefaultRecovery` underflows (`defaultRecoveryReserve -= _amount`) and honest defaulted claimants' claims revert permanently — their ledger entries are never cleared but can never be paid.

### Impact Explanation
Direct theft plus permanent freezing of unclaimed recovery. With `defaultRecoveryPrice = p < 1e18`, every underlying paid to a post-default claim removes `1/p` more than its fair recovery share from the reserve. An attacker can cycle cheap defaulted tranche tokens (or deposit post-default through the prefunded/queue path) into full-par payouts until the reserve is drained, after which all remaining defaulted-epoch receipt claims are unpayable forever — the accounting entries remain but `defaultRecoveryReserve` cannot be replenished. Loss is bounded by the reserve size and scales with post-default request volume.

### Likelihood Explanation
Requires a borrower default that is finalized via `finalizeDefaultRecovery` — a real, manager-driven flow, not an exotic state. After finalization, the attacker needs only tranche tokens (any holder qualifies) and two permissionless calls (`cdo.requestWithdraw`, `cdo.claimWithdrawRequest`). Guards do not stop it: the `requestWithdraw` post-default guard only blocks users who still hold unclaimed receipts [6](#0-5) , and the reserve guard in `_transferFundedClaim` protects the reserve only from funded-claim spending, not from `_transferDefaultRecovery` oversubscription [7](#0-6) . The ordering in `claimWithdrawRequest` even prioritizes the post-default claim first [8](#0-7) .

### Recommendation
Do not pay post-default requests from `defaultRecoveryReserve` at par without backing. Options:
- Fund post-default receipts at request time by pulling the corresponding underlying into the reserve (e.g., have the CDO transfer `_amount` of underlying, or account them in a separate reserve bucket), so `postDefaultRequests` are self-collateralized.
- Alternatively apply the same `defaultRecoveryPrice` haircut and account post-default claims in a strictly last-priority bucket paid only from reserve surplus (`recoveryPrice > 1e18`) or dust.
- At minimum, cap post-default payouts to `reserve - sum(outstanding default-epoch entitlements)` rather than the raw reserve balance.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
// uses the repo's existing IdleCreditVault.t.sol harness conventions

contract PostDefaultReserveDrainTest is Test {
    // Assume fixtures from IdleCreditVault.t.sol:
    //   cdoEpoch (IdleCDOEpochVariant), creditVault (IdleCreditVault),
    //   underlying, borrower, manager, AAtranche

    function testPostDefaultClaimDrainsRecoveryReserve() external {
        uint256 amount = 10_000 * 1e6; // USDC-scale

        // 1. Alice deposits and requests a normal withdraw during epoch 0.
        address alice = makeAddr("alice");
        _depositAA(alice, amount);
        _startEpoch();
        vm.prank(alice);
        cdoEpoch.requestWithdraw(0, address(AAtranche));
        // bob stays an active LP / receipt holder
        address bob = makeAddr("bob");
        _depositAA(bob, amount);
        vm.prank(bob);
        cdoEpoch.requestWithdraw(0, address(AAtranche));

        // 2. Epoch ends with borrower default -> finalizeDefaultRecovery
        //    sets recoveryPrice p < 1e18 and reserve == totalBasis * p.
        _stopEpochWithDefault();
        cdoEpoch.finalizeDefault(); // pulls recovered funds, sets defaultRecoveryPrice
        uint256 price = creditVault.defaultRecoveryPrice();
        assertLt(price, 1e18);
        uint256 reservePre = creditVault.defaultRecoveryReserve();

        // 3. Attacker holds defaulted tranche tokens worth p per unit.
        address attacker = makeAddr("attacker");
        _depositAAPostDefault(attacker, amount); // or buys tranches
        vm.startPrank(attacker);
        cdoEpoch.requestWithdraw(0, address(AAtranche)); // postDefaultRequests path
        cdoEpoch.claimWithdrawRequest();                 // paid 1:1 from reserve
        vm.stopPrank();

        // 4. Reserve decreased by `amount`, but attacker's tranche basis was
        //    only worth amount * p. Honest claimants are now short.
        uint256 reservePost = creditVault.defaultRecoveryReserve();
        assertEq(reservePre - reservePost, amount);

        // 5. Repeat (or single large request) until reserve drained, then:
        vm.expectRevert(); // underflow in _transferDefaultRecovery
        vm.prank(bob);
        cdoEpoch.claimWithdrawRequest(); // permanent freeze of bob's recovery
    }
}
```

```text
  function _claimPostDefaultWithdrawRequest(address _user) internal returns (uint256 amount) {

    postDefaultRequests[_user] = 0;
```
