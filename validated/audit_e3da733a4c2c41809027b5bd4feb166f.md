### Title
Unvalidated `parameters` length in `createDstEscrow` permanently bricks `withdraw`/`publicWithdraw` on `EscrowDst`, freezing the maker's payout - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`, `contracts/libraries/ImmutablesLib.sol`)

### Summary
`BaseEscrowFactory.createDstEscrow` accepts an attacker-supplied `IBaseEscrow.Immutables` struct with **no validation of the `parameters` field's length or content**. `EscrowDst._withdraw` unconditionally calls `ImmutablesLib.integratorFeeAmountCd()`/`protocolFeeAmountCd()`, which revert with `IndexOutOfRange()` if `parameters.length` is shorter than the fixed offsets they read (0x40 and 0x20 bytes respectively). An unprivileged caller can therefore fund a destination escrow with a `parameters` blob shorter than 64 bytes (e.g. 63 bytes) and permanently disable both the private `withdraw` and the public `publicWithdraw` paths, since both funnel into `_withdraw`.

### Finding Description
- `createDstEscrow` performs only balance/timing checks and copies `dstImmutables` verbatim into `immutables`, with no check on `parameters` length/shape: [1](#0-0) 
- `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` require `parameters.length >= 0x40`/`0x20` and revert `IndexOutOfRange()` otherwise, regardless of the actual fee values encoded: [2](#0-1) 
- `EscrowDst._withdraw` calls `integratorFeeAmountCd()` before any other logic, and both `withdraw()` and `publicWithdraw()` route through `_withdraw`: [3](#0-2) 
- `onlyValidImmutables` only checks that the immutables hash matches the one committed at CREATE2 deployment time — it does not validate that `parameters` is well-formed: [4](#0-3) 
- `cancel()` and `rescueFunds()` never touch the fee-decoding functions, so they remain callable by the taker (the original creator) after the relevant timelocks: [5](#0-4) [6](#0-5) 

The intended `parameters` encoding is `abi.encode(protocolFeeAmount, integratorFeeAmount, protocolFeeRecipient, integratorFeeRecipient)` (128 bytes), as constructed by the factory itself during `_postInteraction`: [7](#0-6) . However, this canonical encoding is only produced for the `immutablesComplement` object emitted in the `SrcEscrowCreated` event on the source chain; the destination-chain `createDstEscrow` function has no on-chain mechanism to enforce that the caller reproduces this encoding faithfully — it is fully attacker-controlled calldata.

### Impact Explanation
Because `withdraw`/`publicWithdraw` both revert unconditionally once `parameters.length < 0x40`, the destination escrow can never pay out to the maker via the secret-based path — neither the private taker-only window nor the public access-token-holder window. Only `cancel` (after `DstCancellation`) and `rescueFunds` (after the rescue delay) remain usable, and both return funds to the **taker**, not the maker. This means the maker's intended destination payout is frozen indefinitely by an action fully controlled by an unprivileged destination-escrow creator, matching "temporary/permanent freezing of funds" impact criteria. It also creates an asymmetric risk in the broader swap flow: if a secret is later revealed/used on the source chain (e.g., because off-chain systems believed the destination escrow was correctly funded), the malicious taker could still claim the maker's source-side assets while ultimately reclaiming their own destination-side deposit via `cancel`, though that broader chained scenario depends on off-chain secret-release assumptions outside this contract's guarantees.

### Likelihood Explanation
High. `createDstEscrow` is a fully public, unprivileged entrypoint with no schema/length enforcement on `parameters`. No special timing, race condition, or privileged role is required — any account with the required native/ERC20 balance can trigger this by simply supplying a short `parameters` byte string.

### Recommendation
Validate `dstImmutables.parameters` in `createDstEscrow` (e.g., require `parameters.length == 0x80` matching the canonical 4-word fee encoding, or otherwise bound/verify it before deployment) so that fee-decoding in `EscrowDst._withdraw` can never be starved of the required bytes. Alternatively, make `ImmutablesLib`'s Cd fee accessors fail safe (e.g., treat under-length parameters as zero fees) instead of reverting, so a malformed/short `parameters` cannot brick withdrawal entirely.

### Proof of Concept
1. Attacker (as an ordinary caller, no privileges) prepares `dstImmutables` with a valid `hashlock`, `maker`, `taker=attacker`, `token`, `amount`, `safetyDeposit`, `timelocks`, but sets `parameters` to a 63-byte blob (e.g., a truncated `abi.encode` of the fee tuple).
2. Attacker calls `createDstEscrow{value: nativeAmount}(dstImmutables, srcCancellationTimestamp)`; the factory deploys and funds the clone with no validation of `parameters`. [1](#0-0) 
3. Time advances into `DstWithdrawal`; attacker (as taker) calls `withdraw(secret, dstImmutables)` — reverts with `IndexOutOfRange()` inside `integratorFeeAmountCd()` before any transfer occurs. [8](#0-7) 
4. Time advances into `DstPublicWithdrawal`; any access-token holder calls `publicWithdraw(secret, dstImmutables)` — reverts identically, confirming the public path is equally bricked. [9](#0-8) 
5. After `DstCancellation`, only the attacker (as taker) can call `cancel()` to reclaim the deposited destination amount + safety deposit — the maker never receives the destination payout. [5](#0-4)

```text
    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }
```

```text
    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**
     * @notice Returns the integrator fee amount from the immutables (calldata version).
     * @param immutables The immutables to extract the fee from.
     * @return ret The integrator fee amount.

    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
```

```text
    function _withdraw(bytes32 secret, Immutables calldata immutables)
        internal
        onlyValidImmutables(immutables.hash())
        onlyValidSecret(secret, immutables.hashlock)
    {
        uint256 integratorFeeAmount = immutables.integratorFeeAmountCd();
        uint256 protocolFeeAmount = immutables.protocolFeeAmountCd();
        if (integratorFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);
        }
        if (protocolFeeAmount > 0) {
            _uniTransfer(immutables.token.get(), immutables.protocolFeeRecipientCd().get(), protocolFeeAmount);
        }
        uint256 amount = immutables.amount - integratorFeeAmount - protocolFeeAmount;
        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);
        _ethTransfer(msg.sender, immutables.safetyDeposit);
        emit EscrowWithdrawal(secret);
    }
```
