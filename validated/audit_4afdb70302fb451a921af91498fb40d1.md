### Title
Stale confirmations from removed multisig members/keys are still counted toward `num_confirmations`, allowing request execution below the live threshold - (File: `multisig2/src/lib.rs`, `multisig/src/lib.rs`)

### Summary
The Hats `_removeSigner` bug class ("count updated without reflecting the current live set") has a direct analog here: NEAR's multisig contracts track confirmations as a raw `HashSet` of member/key identifiers per request, and count-vs-threshold comparisons never validate that each recorded confirmation still corresponds to a currently valid (live) member. When a member is removed via `DeleteMember` (`multisig2`) or a key is removed via `DeleteKey` (`multisig`), cleanup only strips pending requests *originated* by that member/key — it does not strip that member's/key's confirmations on *other* pending requests they had previously confirmed but did not originate.

### Finding Description
In `multisig2/src/lib.rs`, `confirm()` decides whether to execute a request purely by counting set entries: `if confirmations.len() as u32 + 1 >= self.num_confirmations` [5](#0-4) . The `confirmations` map is keyed by `request_id -> HashSet<String>` where each string is `MultisigMember::to_string()` [6](#0-5) .

`delete_member()` is the only cleanup path invoked when a member is removed, and it explicitly filters requests by `r.member == member` (i.e., requests *originated* by the removed member) before clearing their confirmations: `self.requests.iter().filter_map(|(k, r)| if r.member == member { Some(k) } else { None })` [7](#0-6) . It never iterates over all `self.confirmations` entries to remove the deleted member's string from confirmation sets of requests originated by *other* members. The `members: UnorderedSet<MultisigMember>` set itself is updated (`self.members.remove(&member)` [8](#0-7) ), but `confirmations` entries are never cross-checked against `self.members` at confirm-time.

Consequently, the binding the contract is supposed to maintain — `live confirming members recorded == live confirming members counted toward the threshold` — is broken: a stale entry from a now-removed member remains in a pending request's confirmation set and is still counted by `confirm()`'s length check, letting that request execute with fewer *live* member confirmations than `num_confirmations` requires.

The legacy `multisig/src/lib.rs` has the same defect: `DeleteKey` only purges requests where `r.signer_pk == pk` (the deleted key's *own* requests) [9](#0-8) , leaving that key's confirmation entries intact in the `confirmations: UnorderedMap<RequestId, HashSet<PublicKey>>` [10](#0-9)  for requests it confirmed but did not originate, and `confirm()` counts purely by `confirmations.len()` [11](#0-10) .

### Impact Explanation
This crosses the "a multisig request executed below threshold" boundary called out as Critical impact: a pending `Transfer`, `FunctionCall`, `AddKey`/`AddMember`, or `DeployContract` request can be pushed to execution using one confirmation from a member/key that has already been removed from the live member/key set, combined with fewer live confirmations than `num_confirmations` mandates. This directly undermines the K-of-N custody guarantee the multisig is meant to enforce, potentially moving NEAR or granting access below the configured threshold of live signers.

### Likelihood Explanation
Requires a realistic sequence: (1) member/key B confirms request R (originated by A, not B) without pushing it over threshold; (2) a separate `DeleteMember`/`DeleteKey` request removes B from the live set; (3) request R is later confirmed by enough *additional* remaining members to reach `num_confirmations` in raw count, but B's stale confirmation is one of the counted entries even though B is no longer live — meaning fewer than `num_confirmations` live signers actually authorized execution. This does not require any privileged action beyond normal multisig usage (members legitimately confirming and later being legitimately removed as part of normal key/membership rotation), so it is reachable without a compromised key or social engineering.

### Recommendation
When removing a member (`delete_member`) or key (`DeleteKey`), iterate all entries in `confirmations` (not just requests originated by that member/key) and strip the removed member's/key's entry from every confirmation set. Alternatively, at `confirm()` time, filter `confirmations` against the current live `members`/valid keys before comparing the count to `num_confirmations`, i.e., count only confirmations from entries still present in the live set.

### Proof of Concept
1. Initialize `multisig2` with members `{A, B, C}` and `num_confirmations = 2`.
2. `A` calls `add_request` to create request `R1` (e.g., a `Transfer`).
3. `B` calls `confirm(R1)` — `confirmations[R1] = {B}`, count 1 < 2, request stays pending.
4. Separately, `A` and `C` create and confirm a `DeleteMember{member: B}` request, which executes `delete_member(B)`; since `R1` was originated by `A`, not `B`, the filter `r.member == member` in `delete_member` does not touch `R1`'s confirmations — `confirmations[R1]` still contains `B`.
5. `C` calls `confirm(R1)` — `confirmations[R1].len() + 1 = 2 >= num_confirmations (2)`, so `R1` executes, even though only `A` (originator, uncounted) and `C` are live members who actually acted, and `B`'s stale confirmation was needed to reach the count of 2.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);

        );

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
