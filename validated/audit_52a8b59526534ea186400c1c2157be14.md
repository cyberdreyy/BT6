### Title
Unauthenticated flooding of `h.savedCallbacks` causes `pruneCallbacks` to evict a victim's pending callback before its DON response arrives - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` inserts an entry into the shared `h.savedCallbacks` map for every unique `MessageId` without any allowlisting or per-sender quota, as the code explicitly marks with `// TODO: apply allowlist and rate-limiting here`. Because `pruneCallbacks` evicts strictly by `createdAt` (oldest first) once `len(savedCallbacks) > MaxSavedCallbacks`, an attacker who cheaply signs many distinct messages can force eviction of an older, still-valid victim callback before the DON's legitimate response is delivered.

### Finding Description
The gateway `ProcessRequest` routes any legacy request (message with a `DonId`) after only `msg.Validate()` (signature well-formedness / structural checks) directly to `h.HandleLegacyUserMessage` [1](#0-0) . Inside `HandleLegacyUserMessage`, before any allowlist or rate-limit check (explicitly deferred by a TODO), the handler unconditionally stores the callback keyed by the attacker-chosen `msg.Body.MessageId`: [2](#0-1) 

Because `MessageId` is attacker-controlled and each request only needs a fresh ECDSA-signed message (no subscription/allowlist gate exists at this point), an attacker can generate an arbitrary number of distinct `savedCallbacks` entries cheaply and quickly.

`pruneCallbacks` runs on a timer (`CallbackPruneIntervalSec`) and, after removing expired entries, if `len(savedCallbacks) > MaxSavedCallbacks`, sorts all remaining entries purely by `createdAt` and deletes the oldest half regardless of which "user"/session created them: [3](#0-2) 

There is no per-sender isolation, quota, or precedence protecting a victim's earlier, not-yet-expired entry from eviction — the map is fully attacker-reachable and eviction has no notion of the requester's identity. If a victim's request was saved before the attacker starts flooding, and the flood pushes the map size above `MaxSavedCallbacks` before the DON responds and calls `handleWebAPITriggerMessage` (which does the lookup/delete on `msg.Body.MessageId`) [4](#0-3) , the victim's entry can be deleted, causing the eventual DON response for that message ID to find nothing in the map and silently drop (`found` is false, function returns `nil` — no response is ever delivered to the caller, whose `callback.Wait(ctx)` will time out) [5](#0-4) .

### Impact Explanation
This is a Denial-of-Service against legitimate users of the capabilities gateway: a victim's in-flight request can be silently dropped, appearing to the caller as a handler timeout (`api.RequestTimeoutError`), even though the request was valid and the DON eventually processed and responded to it. This matches Chainlink's "Denial of Service" bounty impact class for the Gateway/Capabilities pathway, since it breaks isolation between users' pending requests using only cheap, unauthenticated traffic.

### Likelihood Explanation
The attack requires no privileges beyond the ability to sign a JSON-RPC message with any ECDSA key (no registered node identity or DON allowlist membership is needed to reach `HandleLegacyUserMessage`, since the allowlist/rate-limit check is explicitly a TODO not yet implemented). The attacker needs to generate more than `MaxSavedCallbacks - len(existing)` distinct-MessageId requests within one `CallbackPruneIntervalSec` window (default `defaultMaxSavedCallbacks = 20000`, `defaultCallbackPruneIntervalSec = 30`), which is feasible for a scripted flood, and the attack is fully repeatable.

### Recommendation
Implement per-sender rate-limiting/allowlisting before inserting into `savedCallbacks` (the TODO at handler.go:384), and/or change `pruneCallbacks` eviction to be sender-aware/fair (e.g., cap entries per sender, or refuse new inserts once `MaxSavedCallbacks` is reached rather than evicting arbitrary older entries), so a single sender cannot force eviction of another sender's pending callback.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with `MaxSavedCallbacks` set to a small value (e.g., 10) and `CallbackMaxAgeSec` large enough that nothing expires by age.
2. Insert one "victim" `savedCallback` directly into `h.savedCallbacks` with an early `createdAt` and a mock `Callback` whose `SendResponse` is tracked/asserted never called improperly.
3. Insert `MaxSavedCallbacks` additional "attacker" entries with `createdAt` set to `time.Now()` (simulating a flood via repeated `HandleLegacyUserMessage` calls with unique `MessageId`s, or directly populating the map for test speed).
4. Call `h.pruneCallbacks()`.
5. Assert the victim's `MessageId` is no longer present in `h.savedCallbacks` (`_, found := h.savedCallbacks[victimID]; assert.False(t, found)`), demonstrating eviction of a valid, non-expired victim entry purely due to attacker-driven volume.
6. Optionally simulate the late-arriving DON response via `handleWebAPITriggerMessage` for the victim's `MessageId` and assert it returns `nil` without invoking the victim's `SendResponse`, confirming the response is silently dropped.

	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}
