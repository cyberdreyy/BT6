Confirmed: `assert_valid_request` only checks that the *caller* is currently a member and that the request exists; it never re-validates that previously-recorded confirmers in `self.confirmations.get(&request_id)` are still in `self.members`. The `confirm()` threshold check (`confirmations.len() as u32 + 1 >= self.num_confirmations`) at [1](#0-0)  is purely a cardinality check on stale strings, with no membership re-validation.

### Title
Stale confirmations from removed members allow execution of a multisig request with fewer than `num_confirmations` live approvals - (File: multisig2/src/lib.rs)

### Summary
`delete_member` only purges requests that a removed member originally *created* (`r.member == member`), and only clears `num_requests_pk` for that member; it never scans `self.confirmations` to strip the removed member's string from confirmation sets of *other* requests they had merely confirmed. `confirm()` then counts `confirmations.len()` (including stale entries) without re-verifying each confirmer is still in `self.members`, so a request can execute once the confirmation-set cardinality reaches `num_confirmations` even though fewer distinct live members actually approved it.

### Finding Description
The broken binding: `{ m in self.members : m.to_string() ∈ confirmations.get(&R) } == num_confirmations` is claimed true at execution time but is actually `2 == 3` (false).

Code path:
1. Member A creates/confirms request `R{receiver_id: attacker, actions:[Transfer{amount}]}` via `add_request_and_confirm`, and member B calls `confirm(R)`. This inserts `A` and `B`'s `member.to_string()` into `self.confirmations[R]`, per [2](#0-1) . `confirmations[R].len() == 2 < num_confirmations(3)`, so it stays pending.
2. A separate request `R2{receiver_id: current_account_id, actions:[DeleteMember{A}]}` is created and confirmed by B and C, reaching `num_confirmations`. This routes through `execute_request` → `delete_member`, shown at [3](#0-2) .
3. `delete_member` only removes requests where `r.member == member` (i.e., requests A *originated*) and removes `num_requests_pk[A]`, then removes A from `self.members`. It does **not** iterate `self.confirmations` to strip A's string from `R`'s confirmation set, since `R` was originated by A but A only appears as a *confirmer* in other requests — or even if `R` was originated by A itself, if A is only a confirmer (not originator) of some other pending request, that request's confirmation entry for A is never cleaned. In the scenario described, A originated `R` (so R would actually be caught by the `r.member == member` filter and deleted) — but the more general and still-valid variant is: A confirms (not originates) some request `R` created by another member; `delete_member(A)` leaves A's stale entry in `confirmations[R]` untouched because the filter only matches on `r.member` (the *creator*), not on entries inside `confirmations`.
4. Member C then calls `confirm(R)`. `assert_valid_request` at [4](#0-3)  only checks that C is currently a member and that `R`/`confirmations[R]` exist — it does not filter out A's stale entry.
5. `confirmations.len() as u32 + 1 >= self.num_confirmations` evaluates `2 + 1 >= 3` → true, so `execute_request` runs the `Transfer{amount}` to the attacker-controlled `receiver_id`, even though only B and C (2 live members) actually approved.

Root cause: confirmation cleanup on membership removal is scoped only to requests *authored* by the removed member (`r.member == member`), not to the removed member's *confirmation entries* recorded on requests authored by others. `confirm()`'s threshold check trusts stale string counts in the `HashSet<String>` without cross-checking `self.members`.

### Impact Explanation
NEAR is transferred out of the multisig account to an attacker-chosen `receiver_id` with only 2 of 3 required live member approvals, i.e., a multisig request executed below `num_confirmations` live members — explicitly listed as a Critical impact category. This is repeatable any time a member is removed while they hold outstanding confirmations on other pending requests, and scales to arbitrarily large transfers.

### Likelihood Explanation
Preconditions: a live multisig (`num_confirmations` k-of-n) where a member later gets removed via `DeleteMember` while having previously confirmed (but not authored) another pending request. This requires cooperation among the remaining legitimate members to eventually remove a member and to confirm the malicious/stale request — the "attacker" here would need at least colluding members B and C already at 2 live confirmations, which is a plausible operational sequence (member turnover) rather than a pure external-attacker scenario, but it still breaks the security invariant of the contract with no additional guard from `assert_valid_request`, `assert_self_request`, or `current_member` to catch it.

### Recommendation
When removing a member in `delete_member`, iterate all entries in `self.confirmations` (not just requests authored by the removed member) and remove the member's `to_string()` key from every confirmation set; alternatively, have `confirm()` recompute the live-confirmer count by intersecting `confirmations.get(&request_id)` with `self.members` before comparing against `num_confirmations`.

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
