### Title
Unbounded per-request cost in secondary-index lookups: `SecondaryIndex::get`/`get_index_key_pubkeys` fully materialize all inner keys and `index_scan_accounts` `do_load`s each one before any size limit is enforced - ([File: accounts-db/src/accounts_index/secondary.rs, accounts-db/src/accounts_index.rs, accounts-db/src/accounts_db.rs])

### Summary
`AccountsIndex::get_index_key_pubkeys` (which backs `getTokenAccountsByOwner`, `getTokenAccountsByMint`, and secondary-indexed `getProgramAccounts`) calls `SecondaryIndex::get()`, which clones the *entire* `HashSet<Pubkey>` of inner keys under an outer key into a `Vec<Pubkey>` before any scan/size-limit logic runs. `AccountsDb::index_scan_accounts` then iterates that fully-materialized vector, calling `do_load` for every pubkey, checking `config.is_aborted()` only between iterations. An attacker who cheaply creates many SPL-token accounts sharing one owner/mint pubkey can make a single low-rate RPC call force O(N) allocation and O(N) `do_load` calls, where N is fully attacker-controlled on-chain data volume, not a server-enforced constant.

### Finding Description
The relevant code path is:
- `rpc/src/rpc.rs::get_filtered_spl_token_accounts_by_owner`/`_by_mint`/`get_filtered_program_accounts` → `get_filtered_indexed_accounts` (`rpc/src/rpc.rs:309-347`) → `Bank::get_filtered_indexed_accounts` (`runtime/src/bank.rs:5134-5147`) → `Accounts::load_by_index_key_with_filter` (`accounts-db/src/accounts.rs:396-433`) → `AccountsDb::index_scan_accounts` (`accounts-db/src/accounts_db.rs:3358-3421`).
- Inside `index_scan_accounts`, line `for pubkey in self.accounts_index.get_index_key_pubkeys(&index_key)` (`accounts-db/src/accounts_db.rs:3398`) calls `AccountsIndex::get_index_key_pubkeys` (`accounts-db/src/accounts_index.rs:377-383`), which dispatches to `SecondaryIndex::get()` (`accounts-db/src/accounts_index/secondary.rs:252-258`):
```rust
pub fn get(&self, key: &Pubkey) -> Vec<Pubkey> {
    if let Some(inner_keys_map) = self.index.get(key) {
        inner_keys_map.keys()
    } else {
        vec![]
    }
}
```
`inner_keys_map.keys()` is `RwLockSecondaryIndexEntry::keys()` (`accounts-db/src/accounts_index/secondary.rs:104-106`), which does `self.account_keys.read().unwrap().iter().cloned().collect()` — an unconditional full clone of every inner key (every account pubkey indexed under that owner/mint/program).
- This entire `Vec<Pubkey>` is built and returned **before** the `for` loop in `index_scan_accounts` starts, so the `config.is_aborted()` check at line 3399 and the byte-size abort logic in `accumulate_and_check_scan_result_size` (`accounts-db/src/accounts.rs:367-381`, wired via `ScanConfig::abort()`) cannot prevent this initial O(N) allocation — they only stop further `do_load` calls in the loop *after* the vector already exists.
- The optional `byte_limit_for_scan` (`scan_results_limit_bytes`, config flag `--accounts-index-scan-results-limit-mb`) has **no default value** — `validator/src/commands/run/args/json_rpc_config.rs:58-64` uses `value_t!(...).ok()` with no `.default_value()` on the arg, so by default `byte_limit_for_scan` is `None` and `accumulate_and_check_scan_result_size` always returns `false` (`accounts-db/src/accounts.rs:373-379`), meaning the scan is never aborted early by default at all.
- There is no per-key cap on the number of inner keys `SecondaryIndex::insert` will accept (`accounts-db/src/accounts_index/secondary.rs:132-171`) — any number of accounts can be indexed under one owner/mint/program pubkey via ordinary on-chain writes (creating SPL-token accounts), which requires no special privilege.

Thus a single unprivileged, low-rate RPC call (`getTokenAccountsByOwner`, `getTokenAccountsByMint`, or `getProgramAccounts` with `AccountIndex::ProgramId` enabled) against a key with N indexed accounts costs at least O(N) in vector allocation/cloning, and — absent an explicit, non-default byte limit — O(N) `do_load` calls as well.

### Impact Explanation
This matches the "RPC DoS from a single low-rate call" bounty category: node CPU/memory cost for one request scales with attacker-controlled on-chain data volume (number of accounts under one owner/mint/program key) rather than any fixed, server-enforced bound. With secondary indexes enabled (a supported, non-default-but-common validator configuration for RPC nodes serving `getTokenAccountsByOwner`/`getTokenAccountsByMint`), an attacker can grow N to millions cheaply (rent-exempt minimum SPL token account creation, no special privilege), then issue one call to degrade or exhaust RPC node memory/CPU.

### Likelihood Explanation
- Requires the validator to run with `--account-index=spl-token-owner` (or `spl-token-mint`/`program-id`) enabled — a documented, supported RPC configuration, not a misconfiguration outside scope.
- Requires no special privilege: creating N SPL-token accounts under one owner is ordinary permissionless on-chain activity (rent + transaction fees only), reachable at any rate by any client over time.
- The subsequent RPC call is a single, un-paginated `getTokenAccountsByOwner`/`getTokenAccountsByMint`/`getProgramAccounts` call — well within the "one call per `CLUSTER_SLOT_TIME_TARGET / 2`" constraint.
- By default `scan_results_limit_bytes` is `None`, so no built-in cap exists unless the operator explicitly opts in to `--accounts-index-scan-results-limit-mb`.

### Recommendation
- Change `SecondaryIndex::get`/`get_index_key_pubkeys` to support bounded/streaming iteration (e.g., an iterator or chunked cursor) instead of eagerly cloning the full inner-key set into a `Vec`.
- Enforce a hard, non-optional cap (independent of operator opt-in) on the number of pubkeys/bytes returned by `get_index_key_pubkeys`/`index_scan_accounts` per RPC request, or make `scan_results_limit_bytes` default to a safe non-`None` value.
- Check the abort/size condition incrementally while iterating inner keys (e.g., a bounded `Iterator` from `RwLockSecondaryIndexEntry`), rather than after fully materializing them, so the cost of a single request is capped independent of on-chain state size.

    /// Return true iff sum > 'byte_limit_for_scan'
    fn accumulate_and_check_scan_result_size(
        sum: &AtomicUsize,
        account: &AccountSharedData,
        byte_limit_for_scan: &Option<usize>,
    ) -> bool {
        if let Some(byte_limit_for_scan) = byte_limit_for_scan.as_ref() {
            let added = Self::calc_scan_result_size(account);
            sum.fetch_add(added, Ordering::Relaxed)
                .saturating_add(added)
                > *byte_limit_for_scan
        } else {
            false
        }
    }

            result
        }
    }

    }

    pub async fn get_filtered_indexed_accounts(
        &self,
        bank: &Arc<Bank>,
        index_key: &IndexKey,
        program_id: &Pubkey,
        filters: Vec<RpcFilterType>,
        sort_results: bool,
    ) -> ScanResult<Vec<KeyedAccountSharedData>> {
        let bank = Arc::clone(bank);
        let index_key = index_key.to_owned();
        let program_id = program_id.to_owned();
        let byte_limit_for_scans = self.config.scan_results_limit_bytes;
        let mut accounts = self
            .runtime
            .spawn_blocking(move || {
                bank.get_filtered_indexed_accounts(
                    &index_key,
                    |account| {
                        // The program-id account index checks for Account owner on inclusion.
                        // However, due to the current AccountsDb implementation, an account may
                        // remain in storage as a zero-lamport AccountSharedData::Default() after
                        // being wiped and reinitialized in later updates. We include the redundant
                        // filters here to avoid returning these accounts.
                        account.owner().eq(&program_id)
                            && filters
                                .iter()
                                .all(|filter_type| filter_allows(filter_type, account))
                    },
                    byte_limit_for_scans,
                )
            })
            .await
            .expect("Failed to spawn blocking task")?;
        if sort_results {
            // Avoid copying pubkeys (using Ord::cmp(a, b) silences clippy::unnecessary_sort_by).
            accounts.sort_unstable_by(|(addr_a, _), (addr_b, _)| Ord::cmp(addr_a, addr_b));
        }
        Ok(accounts)
    }
