**Analysis:**

The premise mischaracterizes how `synchronize_delegation_pool` and `total_coins_inactive` interact. `total_coins_inactive` is intentionally allowed to go "stale" between synchronizations — this is documented and tested behavior, not a bug [1](#0-0) . The key facts that defeat the exploit theory:

1. **Every stake-management entrypoint re-synchronizes before touching state.** `withdraw`, `unlock`, `reactivate_stake`, and `add_stake` all call `synchronize_delegation_pool(pool_address)` as their first action [2](#0-1) [3](#0-2) . So by the time `withdraw_internal` evaluates eligibility, `total_coins_inactive` has just been recomputed from the ground-truth `stake::get_stake` value.

2. **`total_coins_inactive` is always set to the exact current `inactive` from `stake::get_stake`, not an incremental delta.** In `synchronize_delegation_pool`, when `lockup_cycle_ended` is detected, `pool.total_coins_inactive = inactive` is a direct read of `stake::get_stake(pool_address)` at that moment — regardless of how many epochs elapsed without a sync call [4](#0-3) . There is no accumulation of error across skipped epochs because the update is absolute, not relative.

3. **`calculate_stake_pool_drift` enforces the invariant `inactive >= pool.total_coins_inactive`** on every call, and computes `lockup_cycle_ended` and the correct `pending_inactive` split purely from the current snapshot vs. the last-known `total_coins_inactive`, correctly capturing however many lockup cycles/epochs passed in aggregate [5](#0-4) .

4. **The scenario "no delegator ever calls unlock" produces no divergence at all**, since `pending_inactive` and `inactive` on the stake pool remain 0 in the absence of any unlock activity; there is nothing for `stake::get_stake`'s inactive value to drift ahead of. This matches the module's own documented invariant that "only a real lockup with 'activity' (which inactivated some unlocking stake) triggers the creation of a new OLC" [1](#0-0) .

5. The existing test `test_total_coins_inactive` explicitly exercises multiple epochs/lockup cycles passing without synchronization and asserts that once `synchronize_delegation_pool` is invoked, `total_coins_inactive` exactly equals `inactive + pending_inactive + rewards` from `stake::get_stake` — i.e., synchronization is exact catch-up, not stale/corrupted [6](#0-5) .

Since any legitimate `withdraw` call is preceded by a fresh, exact synchronization against `stake::get_stake`, an unprivileged caller invoking `synchronize_delegation_pool` repeatedly across epochs (or not at all) cannot cause `total_coins_inactive` to be incorrect at the point a withdrawal eligibility check is performed. The claimed staleness is real between calls but is provably harmless because it's always corrected before use, and no delta-based accumulation exists to be exploited.

    fun calculate_stake_pool_drift(pool: &DelegationPool): (bool, u64, u64, u64, u64) {
        let (active, inactive, pending_active, pending_inactive) = stake::get_stake(get_pool_address(pool));
        assert!(
            inactive >= pool.total_coins_inactive,
            error::invalid_state(ESLASHED_INACTIVE_STAKE_ON_PAST_OLC)
        );
        // determine whether a new lockup cycle has been ended on the stake pool and
        // inactivated SOME `pending_inactive` stake which should stop earning rewards now,
        // thus requiring separation of the `pending_inactive` stake on current observed lockup
        // and the future one on the newly started lockup
        let lockup_cycle_ended = inactive > pool.total_coins_inactive;

        // actual coins on stake pool belonging to the active shares pool
        active += pending_active;
        // actual coins on stake pool belonging to the shares pool hosting `pending_inactive` stake
        // at current observed lockup cycle, either pending: `pending_inactive` or already inactivated:
        if (lockup_cycle_ended) {
            // `inactive` on stake pool = any previous `inactive` stake +
            // any previous `pending_inactive` stake and its rewards (both inactivated)
            pending_inactive = inactive - pool.total_coins_inactive
        };
