### Title
Sync deposit/mint/redeem in ProvisionerV2 use stale anchor price immediately after `unpauseVault` - ([File: v3/src/core/ProvisionerV2.sol], [File: v3/src/core/PriceAndFeeCalculatorV2.sol])

### Summary
When `PriceAndFeeCalculatorV2` unpauses a vault via `unpauseVault`, it deliberately restores the exact anchor price/timestamp tuple that existed at pause time rather than accepting a fresh price [1](#0-0) . The synchronous `deposit`/`mint`/redeem paths in `ProvisionerV2` convert tokens⇄units via `convertTokenToUnitsIfActive`/`convertUnitsToTokenIfActive`, which only check `!paused` and apply no price-age/staleness guard [2](#0-1) , unlike the async solve path which explicitly checks `_guardPriceAge` against a user-specified `maxPriceAge` [3](#0-2) . This mirrors the referenced report's root cause: a vault toggled "on" again resumes user deposits/withdrawals using an exchange rate that is not refreshed for the toggle event itself.

### Finding Description
`setAnchorPrice` is the only path that updates `vaultPriceState.anchorPrice`, and it accrues fees / advances the price only when not paused; while paused, calls to `setAnchorPrice` merely accumulate `accrualLag` and do **not** update `anchorPrice`/`anchorTimestamp` [4](#0-3) . `setDriftPrice` explicitly reverts while paused [5](#0-4) . `unpauseVault` requires the caller to supply exactly the stored `anchorPrice`/`anchorTimestamp` (i.e., it cannot inject a fresh price), then flips `paused` back to `false` [6](#0-5) .

Immediately after this call returns, `ProvisionerV2.deposit`/`mint` (and the sync redeem path) become callable again by any ordinary user because they are only gated by `solvingNotPaused`/`anyoneButVault`, not by the PFC pause flag being freshly re-priced [7](#0-6) . These paths call `_tokensToUnitsFloorIfActive`/`_unitsToTokensCeilIfActive`, which forward straight to `convertTokenToUnitsIfActive`/`convertUnitsToTokenIfActive` [8](#0-7) . Those PFC functions only assert `!paused`; they contain no check that the anchor price/timestamp is recent [2](#0-1) . Consequently there is a window — from the moment `unpauseVault` executes until the next `setAnchorPrice` call updates the anchor — during which sync deposits/mints/redeems execute at the pre-pause (possibly stale/outdated) exchange rate, with no on-chain guard preventing it. This is the same broken invariant as the referenced report: "vault re-activated without a fresh exchange rate, and ordinary depositors/withdrawers transact at the stale rate."

### Impact Explanation
If the true market/vault value moved during the pause (which is realistically why an anchor-policy pause would occur, per the `pauseOnBadAnchorUpdate` design intent noted in the contract's own NatSpec: "Anchor-policy violations can either pause or revert... unpause against the current anchor tuple") [9](#0-8) , ordinary users can mint units at an undervalued price (diluting existing holders) or redeem at an overvalued price (extracting more tokens than fair value) during this window — concrete theft/dilution of user/vault funds via `deposit`/`mint`/sync redeem, matching the "incorrect shares calculation" impact category of the referenced report.

### Likelihood Explanation
The trigger (pause → unpause) is a normal, expected admin/accountant operation, not a malicious privileged action — the referenced report was rated valid precisely because the on/off switch is routine operation and ordinary depositors/withdrawers are the ones exploiting the resulting stale-rate window. Exploitation requires only that (1) a vault is paused and later unpaused (both intended, documented flows), and (2) the operator does not call `setAnchorPrice` in the same transaction/atomically with `unpauseVault`. Given `unpauseVault` and `setAnchorPrice` are separate external calls with no atomicity enforced by the contract, this window is trivially observable by any onlooker who can then call `deposit`/`mint`/redeem before the follow-up price update lands.

### Recommendation
Either (a) require `unpauseVault` to accept and set a fresh `price`/`timestamp` pair (rather than only validating a match to the stale stored tuple) before clearing `paused`, or (b) add a price-age check (analogous to `_guardPriceAge` used in async solves) inside `convertTokenToUnitsIfActive`/`convertUnitsToTokenIfActive`/`ProvisionerV2.deposit`/`mint`/sync-redeem so stale-priced sync conversions revert until a fresh anchor update occurs after unpause.

### Proof of Concept
1. Fork mainnet at a block after `PriceAndFeeCalculatorV2`/`ProvisionerV2`/`MultiDepositorVault` deployment; register/impersonate an in-scope vault with sync deposits/mints enabled.
2. As `vaultAccountant`, call `setAnchorPrice(vault, P0, T0)` to establish a baseline price.
3. Have the vault's true value increase (e.g., simulate profitable strategy return) so a later `setAnchorPrice(vault, P1, T1)` with `P1 >> P0` would trigger `_shouldPauseAnchor` → pause (`pauseOnBadAnchorUpdate = true`), per `setAnchorPrice` logic [4](#0-3) .
4. Confirm `isVaultPaused(vault) == true` and `deposit`/`mint` revert (`Aera__VaultPaused`) via `convertTokenToUnitsIfActive`.
5. Vault owner calls `unpauseVault(vault, P0, T0)` (must match the pre-pause stored tuple) — this succeeds and sets `paused = false`, without updating `anchorPrice` to `P1`.
6. Before the accountant calls `setAnchorPrice(vault, P1, T1)`, an ordinary user calls `ProvisionerV2.mint(token, unitsOut, maxTokensIn, receiver)`; assert the tokensIn charged is computed off `P0` (stale, lower than true `P1`) — i.e., `_unitsToTokensCeilIfActive` returns a token amount understating true fair value, letting the user mint units below the up-to-date valuation.
7. Assert this trade would not have been possible (or would cost strictly more tokens) had the price already been updated to `P1`, demonstrating the value extraction enabled purely by the stale post-unpause window.

    function setAnchorPrice(address vault, uint128 price, uint32 timestamp) external onlyVaultAccountant(vault) {
        VaultPriceStateV2 storage vaultPriceState = _vaultPriceStates[vault];
        uint256 latestPriceTimestamp = _getLastTimestamp(vaultPriceState);

        // Requirements: validate the anchor update
        _validatePriceUpdate(vaultPriceState, price, timestamp, latestPriceTimestamp);

        uint32 oldAnchorTimestamp = vaultPriceState.anchorTimestamp;
        if (!vaultPriceState.paused) {
            bool shouldPause = _shouldPauseAnchor(vaultPriceState, price, timestamp, oldAnchorTimestamp);

            if (shouldPause) {
                // Requirements: revert if pause-on-bad-anchor is disabled
                require(vaultPriceState.pauseOnBadAnchorUpdate, Aera__BadAnchorPriceUpdate());
                // Effects + Log: pause the vault
                _setVaultPaused(vaultPriceState, vault, true);
                // Effects: write the accrual lag
                unchecked {
                    // Cant overflow because _validatePriceUpdate requires timestamp > anchorTimestamp
                    vaultPriceState.accrualLag = timestamp - oldAnchorTimestamp;
                }
            } else {
                // Effects: accrue fees
                _accrueFees(vault, price, timestamp);
            }
        } else {
            // Effects: set the accrual lag
            unchecked {
                // Cant overflow because _validatePriceUpdate requires timestamp > anchorTimestamp
                vaultPriceState.accrualLag += timestamp - oldAnchorTimestamp;
            }
        }

        // Effects: set anchor state
        vaultPriceState.anchorPrice = price;
        vaultPriceState.anchorTimestamp = timestamp;

        // Log anchor price update
        emit AnchorPriceUpdated(vault, price, timestamp);
    }

    /// @inheritdoc IPriceAndFeeCalculatorV2
    function unpauseVault(address vault, uint128 price, uint32 timestamp) external requiresVaultAuth(vault) {
        VaultPriceStateV2 storage vaultPriceState = _vaultPriceStates[vault];

        // Requirements: check that the vault is paused, and the anchor price and timestamp match what is expected
        require(vaultPriceState.paused, Aera__VaultNotPaused());
        require(vaultPriceState.anchorPrice == price, Aera__UnitPriceMismatch());
        require(vaultPriceState.anchorTimestamp == timestamp, Aera__TimestampMismatch());

        // Effects: accrue fees
        _accrueFees(vault, price, timestamp);

        // Effects + Log: unpause the vault
        _setVaultPaused(vaultPriceState, vault, false);
    }

    {
