### Title
Signer permanently wedged rejecting a since-valid re-proposed block due to non-reevaluable `SortitionViewMismatch` from `check_block_against_signer_db_state` - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`check_block_against_signer_db_state` can reject a block with `RejectReason::SortitionViewMismatch` for a **transient**, time-bounded reason (a signed sibling at the same tenure height that has not yet timed out per `tenure_last_block_proposal_timeout`), but `should_reevaluate_reject_reason` classifies `SortitionViewMismatch` as never re-evaluable. Because `determine_response` only reads the cached `block_info.valid` and `block_info.reject_reason` on any later re-proposal of the identical block, the signer will resend the stale rejection forever even after the sibling conflict has become stale and the block would now pass.

### Finding Description
`check_block_against_signer_db_state` at [1](#0-0)  is invoked both at validate-ok ( [2](#0-1) ) and at pre-commit threshold time ( [3](#0-2) ) to re-check a block against `check_latest_block_in_tenure` / `check_tenure_change_confirms_parent`. Both wrap `check_latest_block_in_tenure`, whose "does a fresh signed sibling block this?" gate is explicitly time-based via `get_tenure_last_block_info`'s freshness window (`signed_over_time + tenure_last_block_proposal_timeout`): [4](#0-3)  and [5](#0-4) . Once that window elapses, the very same check can return a different result for the identical proposal.

The attack sequence for an unprivileged single-slot miner:
1. Miner proposes block X (tenure Z, chain_length N). It passes proposal-time `check_proposal` and is submitted to the node for validation (stored via `insert_block`), per `handle_block_proposal` at [6](#0-5) .
2. Before X's node validation returns, the signer signs a competing sibling Y at the same height (either from this or another proposer/race).
3. X's `BlockValidateOk` arrives; `handle_block_validate_response` re-checks state via `check_block_against_signer_db_state`, finds Y as the tenure's fresh signed tip, and marks X `LocallyRejected` with `RejectReason::SortitionViewMismatch`, `valid=Some(false)` — [2](#0-1) .
4. Time passes beyond `tenure_last_block_proposal_timeout` (default 30s) and Y's signature times out with the node's tenure tip not having advanced to Y (e.g. Y never got confirmed).
5. Miner re-gossips the byte-identical proposal X (same `signer_signature_hash`). `handle_block_proposal` finds it already tracked and calls `should_reevaluate_block` at [7](#0-6) . `should_reevaluate_reject_reason` returns `false` for `SortitionViewMismatch` ( [8](#0-7) ), and since `block_info.state` is `LocallyRejected` (not `PreCommitted`), the pre-commit re-evaluation branch is skipped and `determine_response` simply resends the cached rejection using the stale `valid` flag ( [9](#0-8) ) without ever calling `check_block_against_signer_db_state` again.

This is not a hypothetical misclassification — `check_block_against_signer_db_state`'s own docstring acknowledges the race: "This is required in case a block has been approved since the initial checks of the block validation endpoint" ( [10](#0-9) ), and the design doc confirms `SortitionViewMismatch` is overloaded between a permanent proposal-time cause and this transient signerdb-state cause (`docs/signer-flows.md` lines 420-423). Note that the analogous re-check that DOES happen for `PreCommitted` blocks (`handle_block_pre_commit`, re-run on every re-proposal) explicitly relies on staleness self-correcting "on the next pre-commit or re-proposal" — but that self-correction path is unreachable once the block has already moved to `LocallyRejected`, because `should_reevaluate_block`'s `PC` branch only fires for `state == PreCommitted`.

### Impact Explanation
This breaks the bounded-liveness guarantee for one specific block hash: a legitimately-valid re-proposal of the same bytes can never be reconsidered by this signer once tagged `SortitionViewMismatch` via `check_block_against_signer_db_state`, since neither a new proposal event nor a new pre-commit event will trigger re-validation for a `LocallyRejected` block. This matches the "High — signer wedged into never signing valid blocks (liveness)" category. It is a per-block, per-signer DoS: the miner can still recover network liveness by proposing a syntactically different block (different hash), so it does not stall the whole chain, but it deterministically and repeatably denies this signer's vote on that exact block forever.

### Likelihood Explanation
The preconditions are all reachable by a single unprivileged miner slot plus normal StackerDB gossip: (1) win one sortition, (2) have two competing blocks at the same tenure height reach different processing states within the node's validation round-trip window (a naturally occurring race the code's own comments acknowledge), (3) wait past `tenure_last_block_proposal_timeout` (default 30s, configurable), (4) re-broadcast the identical original `BlockProposal` — an action miners already legitimately perform (see `signers_consider_consensus_blocks.rs` "Resend the same block proposal" and the config comment about resending prior decisions). No signer majority, node compromise, or auth token is required, and the sequence is fully repeatable per block.

### Recommendation
Do not treat `RejectReason::SortitionViewMismatch` as universally non-reevaluable. Either (a) split it into a permanent variant (proposal-time tenure-choice violations) and a distinct transient variant emitted specifically by `check_block_against_signer_db_state`'s `check_latest_block_in_tenure`/`check_tenure_change_confirms_parent` failures, marking only the transient variant re-evaluable in `should_reevaluate_reject_reason`; or (b) always re-run `check_block_against_signer_db_state` in `should_reevaluate_block` before falling back to `determine_response`'s cached `valid`, mirroring the re-check already performed for `PreCommitted` blocks in the `PC` branch.

### Proof of Concept
Rust unit test in `stacks-signer/src/v0/tests.rs` (extending the existing `run_sibling_scenario` harness at [11](#0-10) ):
1. Construct siblings A (signed) and B (same tenure/height, different hash) as in `run_sibling_scenario`.
2. Drive B through `handle_block_validate_response`'s Ok path after A is already signed and fresh, so `check_block_against_signer_db_state` returns `SortitionViewMismatch` and B becomes `LocallyRejected` with `valid=Some(false)`.
3. Advance mock time past `tenure_last_block_proposal_timeout` so A's signature is stale per `get_tenure_last_block_info`, and configure the mock node's tenure tip to remain below B's chain_length (so a fresh `check_latest_block_in_tenure` call for B would now return `true`).
4. Re-submit the byte-identical B proposal via `handle_block_proposal`.
5. Assert: `should_reevaluate_reject_reason(&block_info_b)` is `false`; `check_block_against_signer_db_state` is never invoked again for B (e.g. via a call counter or by asserting the mock endpoint for the tenure tip is not hit a second time); and the resulting `BlockResponse` is still `Rejected` (`RejectedInPriorRound`) even though a direct call to `check_block_against_signer_db_state(B)` at this point independently returns `None` (would pass).

fn should_reevaluate_reject_reason(block_info: &BlockInfo) -> bool {
    if let Some(reject_reason) = &block_info.reject_reason {
        match reject_reason {
            RejectReason::ValidationFailed(ValidateRejectCode::UnknownParent)
            | RejectReason::ValidationFailed(ValidateRejectCode::NotFoundError)
            | RejectReason::NoSortitionView
            | RejectReason::ConnectivityIssues(_)
            | RejectReason::TestingDirective
            | RejectReason::InvalidTenureExtend
            | RejectReason::ConsensusHashMismatch { .. }
            | RejectReason::NoSignerConsensus
            | RejectReason::NotRejected
            | RejectReason::Unknown(_) => true,
            RejectReason::ValidationFailed(_)
            | RejectReason::RejectedInPriorRound
            | RejectReason::SortitionViewMismatch
            | RejectReason::ReorgNotAllowed
            | RejectReason::InvalidBitvec
            | RejectReason::PubkeyHashMismatch
            | RejectReason::InvalidMiner
            | RejectReason::NotLatestSortitionWinner
            | RejectReason::InvalidParentBlock
            | RejectReason::DuplicateBlockFound
            | RejectReason::IrrecoverablePubkeyHash
            | RejectReason::ProblematicTransactions
            | RejectReason::ProposalTooOld => {
                // No need to re-validate these types of rejections.
                false
            }
        }

    /// Get the last signed block from the given tenure if it has not timed out.
    /// Even globally accepted blocks are allowed to be timed out, as that
    /// triggers the signer to consult the Stacks node for the latest globally
    /// accepted block. This is needed to handle Bitcoin reorgs correctly.
    ///
    /// The timeout window is measured from the last time a signature actually covered the
    /// block: our own (`signed_self`) or the observed group/global acceptance
    /// (`signed_group`), whichever is later, matching how `get_signed_conflicts` measures
    /// endorsement freshness. `approved_time` is deliberately not used: it is stamped at
    /// pre-commit, which carries no signature, so it would close the window early. This also
    /// means a globally accepted block we never signed ourselves gets a full window from the
    /// time its acceptance was observed, rather than timing out instantly for lack of a
    /// timestamp.
    pub fn get_tenure_last_block_info(
        consensus_hash: &ConsensusHash,
        signer_db: &SignerDb,
        tenure_last_block_proposal_timeout: Duration,
    ) -> Result<Option<BlockInfo>, ClientError> {
        // Get the last signed block in the tenure
        let last_signed_block = signer_db
            .get_last_signed_block(consensus_hash)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;

        let Some(block_info) = last_signed_block else {
            return Ok(None);
        };

        // `approved_time` may hold the pre-commit time; use the actual signature time.
        let Some(signed_over_time) = block_info.signed_self.max(block_info.signed_group) else {
            return Ok(None);
        };

        if signed_over_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
            > get_epoch_time_secs()
        {
            // The last accepted block is not timed out, return it
            Ok(Some(block_info))
        } else {
            // The last accepted block is timed out
            info!(
                "Last accepted block has timed out";
                "signer_signature_hash" => %block_info.block.header.signer_signature_hash(),
                "signed_over_time" => signed_over_time,
                "state" => %block_info.state,
            );
            Ok(None)
        }
    }

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout

                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
