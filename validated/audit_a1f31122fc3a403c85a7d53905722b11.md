### Title
Griefer can permanently DoS `staking_contract::distribute` for an entire operator pool by opting out of direct coin transfers — (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` iterates over *all* shareholders of a single shared `distribution_pool` and pays every one of them out in one atomic transaction via `aptos_account::deposit_coins`. Any account can call the unprivileged, self-only function `aptos_account::set_allow_direct_coin_transfers(account, false)` to opt out of receiving un-registered coin deposits. If that account is (or later becomes) a shareholder in a `staking_contract`'s `distribution_pool` (e.g., a delegated staker or operator who is owed a distribution but has not yet registered a `CoinStore<AptosCoin>`), the `deposit_coins` call for that single recipient aborts the whole transaction, which reverts commission/stake payouts to *every other* shareholder in that same pool — mirroring the Ion Protocol M‑01 pattern where a single "unhealthy" queue entry (paused pool) blocks withdrawals for everyone behind it in the same call. [1](#0-0) 

### Finding Description
`distribute_internal` withdraws all inactive/pending_inactive coins from the stake pool and redistributes them to shareholders of `staking_contract.distribution_pool` in a `while` loop: [2](#0-1) 

For each shareholder it calls `aptos_account::deposit_coins(recipient, ...)`. That function aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient does not already have a registered coin store for the type being sent and has explicitly opted out via `DirectTransferConfig.allow_arbitrary_coin_transfers = false`: [3](#0-2) 

`set_allow_direct_coin_transfers` is a fully unprivileged entry function callable by any account on itself, with no restriction preventing an address from disabling transfers before it is ever added as a `distribution_pool` shareholder: [4](#0-3) 

`distribute_internal` is invoked from `distribute`, `request_commission`, and `unlock_stake` — all of which affect every shareholder sharing the same `distribution_pool` for a given (staker, operator) pair: [5](#0-4) [6](#0-5) 

Because Move transactions are atomic, if the deposit to any single recipient aborts, the entire `distribute()`/`unlock_stake()`/`request_commission()` call reverts — no partial payout occurs, and the withdrawal request that triggered `distribute_internal` (e.g., a staker's `unlock_stake`) is rolled back along with it. This exactly parallels the reported bug class: iterating through a shared queue where a single bad/blocked entry causes the whole withdrawal operation to fail for unrelated parties.

### Impact Explanation
- Any delegator, staker, or operator who is a shareholder of a `distribution_pool` can grief the shared pool by opting out of direct coin transfers before or during their entitlement to a distribution.
- This blocks `distribute`, `request_commission`, and `unlock_stake` for **every other shareholder in the same staking contract** (typically staker + operator, but principal accounting is shared), producing a temporary-to-persistent DoS on operator commission payouts and staker stake withdrawals.
- Because `distribute_internal` is also invoked as a side effect at the start of `unlock_stake`/`request_commission` (to flush pending distributions first), a griefer can block legitimate stakers from ever unlocking or withdrawing stake through that contract, and can block operators from ever collecting commission, until the griefer re-enables `allow_arbitrary_coin_transfers` — which the griefer controls and may refuse to do.
- Since `distribution_pool` shares are only cleared by successfully looping through and redeeming every shareholder in a single atomic call, there is no mechanism to skip an unpayable recipient, so the value becomes stranded (their share, plus the shares of all still-unpaid co-shareholders in the pool) until the poison condition is fixed.

This matches the required impact class ("permanent lock or non-recoverable loss of claim rights in stake, delegation, commission, beneficiary, or vesting flows") because commission and stake withdrawal claim rights become non-executable for parties who are not the griefer.

### Likelihood Explanation
Likelihood is high: `set_allow_direct_coin_transfers` is a normal unprivileged entry function usable by any account with no cost beyond gas, and a new/unregistered address (one that has never received AptosCoin directly, e.g., freshly generated operator or delegator address) is a completely realistic and common state to be added to a `distribution_pool` for.

### Recommendation
In `distribute_internal`, don't let one recipient's payout abort the whole distribution: catch/skip recipients that fail `can_receive_direct_coin_transfers` (or otherwise cannot receive the deposit), and either (a) leave their shares in the pool until they opt back in, continuing to process the remaining shareholders, or (b) force-register the recipient for `AptosCoin` regardless of their opt-out flag when the transfer originates from stake distribution logic (similar rationale to the Ion team's proposed fix of "return zero rather than revert" for a single bad participant instead of failing the entire batch).

### Proof of Concept
1. Staker creates a `staking_contract` with operator O and adds a distribution entry for delegator D (D is a valid but never-before-funded address, so it has no `CoinStore<AptosCoin>`/registration).
2. D calls `aptos_account::set_allow_direct_coin_transfers(D_signer, false)` — an entirely unprivileged self-call. [4](#0-3) 
3. Time passes, rewards accrue, and D becomes entitled to a distribution share in `staking_contract.distribution_pool` (e.g., via `unlock_stake` or reward accrual flows that add D as a recipient).
4. Operator O calls `staking_contract::request_commission` (or staker calls `unlock_stake`/`distribute`), which invokes `distribute_internal`. [7](#0-6) 
5. The `while` loop reaches D and calls `aptos_account::deposit_coins(D, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because D has no CoinStore and has opted out. [8](#0-7) [9](#0-8) 
6. The entire transaction reverts, so the operator's commission and the staker's withdrawal both fail — repeatable indefinitely as long as D keeps `allow_arbitrary_coin_transfers = false`.

*Caveat*: I could not fully confirm within available context whether `coin::is_account_registered<AptosCoin>`/`coin::deposit<AptosCoin>` in this codebase's current fungible-asset migration state (`coin.move`) still routes through the `can_receive_direct_coin_transfers` gate identically for `AptosCoin` versus a generic `CoinType`, since the relevant `coin.move` deposit/registration implementation could not be retrieved in this session (file returned empty in my last read). The `aptos_account.move` `deposit_coins` generic-path logic and spec (`RegistCoinAbortsIf`/`DepositAbortsIf`) strongly indicate the gate applies, but confirming this against the exact current fungible-asset-migrated `coin::deposit`/`register` implementation would require a follow-up read of `coin.move`'s `deposit`, `register`, and `is_account_registered` functions, which a Devin session with full file access should verify before treating this as conclusively exploitable in production.

        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

        // Request to unlock the distribution amount from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
