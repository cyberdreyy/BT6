This confirms the vulnerability: `main.go` creates exactly **one shared `router.Client`** (`rc := router.NewClient(mainClient, certDir, common.AppVersion.UserAgent())`) which is passed to `commands.NewRunCommand` and used for all runner configurations configured in that `gitlab-runner` process [1](#0-0) . The single `*router.Client` is shared across every `RunnerConfig` the process polls, and `RequestJob` is called concurrently per-runner by the runner manager.

### Title
Router discovery cache is keyed globally instead of per-`RunnerConfig`, causing cross-runner TLS/ServerURL bleed - (File: router/client.go)

### Summary
`Client.getRouterDiscovery` caches `c.disco`/`c.discoExpiresAt` as single fields on the shared `*router.Client` instance, with no keying by `RunnerConfig` (e.g. token, URL, or ID) [2](#0-1) . Because `main.go` constructs exactly one `router.Client` shared by all configured runners [3](#0-2) , and `parseJobResponse` unconditionally sets `response.TLSData = disco.TLSData` [4](#0-3) , a job response for one `RunnerConfig` can be stamped with another runner/project's router `ServerURL`/`TLSData` for up to `discoveryTTL` (1 hour).

### Finding Description
`getRouterDiscovery` (router/client.go:239-253) locks `c.mu`, checks `c.discoExpiresAt`, and if not expired, returns the cached `c.disco` regardless of which `config` was passed in:
```go
func (c *Client) getRouterDiscovery(ctx context.Context, config common.RunnerConfig) *common.RouterDiscovery {
	c.mu.Lock()
	defer c.mu.Unlock()
	if c.discoExpiresAt.After(time.Now()) {
		return c.disco
	}
	c.disco = c.delegate.GetRouterDiscovery(ctx, config)
	c.discoExpiresAt = time.Now().Add(discoveryTTL)
	return c.disco
}
```
`RequestJob` calls this per invocation and then uses `disco.ServerURL` to dial the router and `disco.TLSData` to populate the returned `spec.Job.TLSData` via `parseJobResponse` [5](#0-4) . Since the process wires a single shared `*router.Client` for all runner sections in `config.toml` (confirmed in `main.go`), the cache has no dimension for runner identity — whichever `RunnerConfig` happens to trigger the first `GetRouterDiscovery` call (a cache miss) populates `c.disco` for up to one hour, and every other `RunnerConfig`'s concurrent/subsequent `RequestJob` call reads that same cached `ServerURL`/`TLSData` and dials that router with its own token/config, then stamps its own job response with the first runner's `TLSData`.

The delegate's `GetRouterDiscovery(ctx, config)` presumably returns config/project-specific discovery (router endpoint + TLS material for that runner's GitLab instance/project), since it's called with `config` as an argument and is meant to vary per runner — otherwise passing `config` would be pointless. Nothing in `RequestJob` or `getRouterDiscovery` validates that the cached `disco` corresponds to the `config` of the current call.

### Impact Explanation
A runner process configured with multiple `[[runners]]` entries pointing at different GitLab instances/projects (a supported, common multi-runner deployment) can have job responses for runner B stamped with router `ServerURL`/`TLSData` that were discovered for runner A. This is routing/TLS identity bleed across runner configs sharing one process — the runner may attempt to route runner B's job traffic through a router endpoint and TLS material belonging to runner A's discovery, which matches the described scoped impact of cross-project routing/TLS identity confusion.

### Likelihood Explanation
This requires no attacker action within a job — it's a structural bug triggered purely by normal multi-runner operation: any `gitlab-runner` process configured with 2+ runner entries (common in production fleets) using the job-router feature flag (`UseJobRouter`) will hit this path. The race is deterministic in effect once the cache is warm (not merely a narrow timing race): every call within the 1-hour TTL after the first discovery reuses the stale/foreign `disco`, so it is highly likely to manifest whenever multiple distinct runner configs share a process and the router feature flag is enabled.

### Recommendation
Key the discovery cache by a per-`RunnerConfig` identity (e.g. a cache map from `config.GetToken()`/`config.ShortDescription()`/unique runner ID to `(disco, expiresAt)`), or move the cache into a per-`RunnerConfig` wrapper instead of a single field on the shared `*router.Client`. At minimum, `getRouterDiscovery` should not serve `c.disco` to a `config` different from the one that produced it.

### Proof of Concept
Go unit test in `router/client_test.go`:
1. Create one `*Client` with a fake `Delegate` whose `GetRouterDiscovery` returns `&common.RouterDiscovery{ServerURL: "runnerA-url", TLSData: "runnerA-tls"}` for `config == runnerA` and `&common.RouterDiscovery{ServerURL: "runnerB-url", TLSData: "runnerB-tls"}` for `config == runnerB`.
2. Call `client.RequestJob(ctx, runnerA, nil)` first (cache miss, populates `c.disco` with runner A's discovery).
3. Immediately call `client.RequestJob(ctx, runnerB, nil)` before TTL expiry.
4. Assert that the second call's resulting `spec.Job.TLSData` equals `"runnerA-tls"` (not `"runnerB-tls"`) and that the dial target used `ServerURL == "runnerA-url"`, proving runner B's job request/response was routed and TLS-stamped using runner A's discovery — confirming the bug.

func (c *Client) RequestJob(ctx context.Context, config common.RunnerConfig, sessionInfo *common.SessionInfo) (*spec.Job, bool) {
	if !config.IsFeatureFlagOn(featureflags.UseJobRouter) {
		return c.delegate.RequestJob(ctx, config, sessionInfo)
	}

	// Resolve discovery before the breaker gate so a "no router" result can't
	// strand a half-open trial. Every path past Allow() must then resolve the
	// trial: record an outcome once the router is reached, or Abort if we bail.
	disco := c.getRouterDiscovery(ctx, config)
	if disco == nil {
		return c.fallback(ctx, config, sessionInfo, fallbackNoDiscovery)
	}

	if !c.breaker.Allow() {
		return c.fallback(ctx, config, sessionInfo, fallbackBreakerOpen)
	}

	jobRequest := c.delegate.PrepareJobRequest(config, sessionInfo)
	jobRequestJSON, err := json.Marshal(jobRequest)
	if err != nil {
		// The router was never contacted, so there's no success/failure to record;
		// Abort releases the half-open trial Allow() may have granted.
		c.breaker.Abort()
		config.Log().WithError(err).Error("json.Marshal()")
		return nil, false
	}

	client, err := c.factory.Dial(DialTarget{
		URL:         disco.ServerURL,
		Token:       config.Token,
		TLSCAFile:   config.TLSCAFile, // use the same TLS bits as for the main GitLab URL
		TLSCertFile: config.TLSCertFile,
		TLSKeyFile:  config.TLSKeyFile,
	})
	if err != nil {
		if c.breaker.RecordFailure() {
			config.Log().WithError(err).WithField("job_router_url", disco.ServerURL).
				Warn("Job router circuit breaker tripped on dial failure, falling back to direct job requests")
		} else {
			config.Log().WithError(err).WithField("job_router_url", disco.ServerURL).
				Warn("Job router dial failed, falling back to direct job requests")
		}
		return c.fallback(ctx, config, sessionInfo, fallbackDialFailed)
	}
	defer client.Done()

	var responseMD metadata.MD
	requestCorrelationID := network.NewCorrelationID()
	getJobStart := time.Now()
	job, err := rpc.NewJobRouterClient(client).GetJob(
		metadata.NewOutgoingContext(ctx, metadata.Pairs(
			requestIDMetadataKey, requestCorrelationID,
		)),
		&rpc.GetJobRequest{
			JobRequest: jobRequestJSON,
		},
		grpc.Header(&responseMD),
	)
	c.metrics.observeGetJob(time.Since(getJobStart).Seconds())
	if err != nil {
		healthy, reason := c.handleRouterError(err, disco, config)
		if reason != fallbackNone {
			return c.fallback(ctx, config, sessionInfo, reason)
		}
		return nil, healthy
	}

	if c.breaker.RecordSuccess() {
		config.Log().WithField("job_router_url", disco.ServerURL).
			Info("Job router recovered, resuming routing")
	}

	return parseJobResponse(job, responseMD, disco, requestCorrelationID, config)
}
