## Analysis

The report's bug class — a low-level transfer that can fail without the caller verifying the result, leaving accounting mutated as if the transfer succeeded — has a direct analog in `staking-pool/src/internal.rs`.

### Binding broken

`account.unstaked` (and the contract-wide `self.last_total_balance`) must equal the NEAR actually delivered to the withdrawing delegator: `sum(account.unstaked after withdraw) == NEAR received by delegator`. `internal_withdraw` breaks this by debiting the ledger unconditionally while firing an unchecked, uncallback'd `Promise::new(account_id).transfer(amount)`. [1](#0-0) 

Contrast this with every other cross-contract action in the same contract and its sibling contracts, which attach an `ext_self`/callback and use `is_promise_success()`/`PromiseResult` to verify the outcome and roll back state on failure (e.g. `internal_restake`/`on_stake_action`, `deposit_to_staking_pool`/`on_staking_pool_deposit`, `termination_withdraw`/`on_withdraw_unvested_amount`, `on_staking_pool_withdraw`): [2](#0-1) [3](#0-2) [4](#0-3) 

`internal_withdraw` is the *only* balance-moving path in this codebase that mutates the persistent ledger (`account.unstaked -= amount; self.internal_save_account(...); self.last_total_balance -= amount;`) around a bare `Promise::new(...).transfer(amount)` with no `.then(...)` callback at all, so a failed transfer is never observed or reconciled.

### Why the transfer can fail and where the funds go

The project's own documentation confirms transfers can fail and describes what happens to the funds when they do — they are **not** returned to the intended recipient, they are absorbed into the pool's own balance and later redistributed to other delegators as a reward: [5](#0-4) 

Since `internal_withdraw` already decremented `account.unstaked` and `self.last_total_balance` before the promise executes, and there is no callback to detect failure and re-credit the withdrawing account, a delegator whose transfer fails (e.g. their own account gets deleted in the window between submitting the withdraw transaction and receipt execution) permanently loses the withdrawn balance: the ledger says it was paid out, the actual NEAR lands back in the pool contract and is subsequently distributed to the *other* delegators via `internal_ping`'s reward mechanism. [6](#0-5) 

### Title
Unchecked withdraw transfer in `internal_withdraw` permanently debits delegator ledger while funds can be misdirected to other delegators - (File: `staking-pool/src/internal.rs`)

### Summary
`internal_withdraw` in the staking-pool contract decrements the delegator's `account.unstaked` and the contract-wide `last_total_balance` and then fires `Promise::new(account_id).transfer(amount)` with no `.then(...)` callback and no check of the promise result, unlike every other balance-moving code path in this repository.

### Finding Description
`withdraw`/`withdraw_all` call `internal_withdraw`, which does:
```
account.unstaked -= amount;
self.internal_save_account(&account_id, &account);
Promise::new(account_id).transfer(amount);
self.last_total_balance -= amount;
```
There is no callback attached to the `transfer` promise, so the contract never learns whether the transfer succeeded. The contract's own README documents that a failed transfer receipt does not return the NEAR to the intended recipient — it lands back on the staking-pool contract's own balance and is later swept up as a "reward" and redistributed to the remaining delegators by `internal_ping`.

### Impact Explanation
If the withdrawing account no longer exists by the time the transfer receipt executes, the withdrawing delegator's `unstaked` balance claim has already been erased from the ledger, yet they receive no NEAR — the value is captured by the contract and effectively redistributed to other delegators. This is a permanent, unauthorized loss of the withdrawing delegator's funds and a divergence between the recorded ledger and the NEAR actually held/delivered, matching the "funds permanently frozen"/"accounting value diverging from reality" impact class.

### Likelihood Explanation
Triggering requires only that the delegator's own account be deleted (or otherwise become unable to receive a plain transfer) in the window between submitting `withdraw`/`withdraw_all` and the transfer receipt executing — no special privilege, no cooperation from the staking pool owner, and no malicious validator/node is needed; it is entirely under the withdrawing account holder's own control (e.g. self-deleting the account, or an attacker front-running/deleting a compromised low-value throwaway account they control after issuing the withdraw call) or can occur incidentally in normal account-lifecycle operations.

### Recommendation
Attach a `.then(ext_self::on_withdraw(...))` callback to the transfer in `internal_withdraw`, mirroring the pattern already used elsewhere in this codebase (`on_staking_pool_withdraw`, `on_withdraw_unvested_amount`), and only finalize the ledger debit (or re-credit `account.unstaked`/`last_total_balance` on failure) after confirming `is_promise_success()`.

### Proof of Concept
1. Delegator deposits and later unstakes, then after the unstaking delay calls `withdraw`/`withdraw_all`.
2. `internal_withdraw` immediately debits `account.unstaked` and `self.last_total_balance` and fires `Promise::new(account_id).transfer(amount)` with no callback.
3. Before the transfer receipt executes, the delegator's account is deleted (self-delete or account-lifecycle race).
4. The transfer action fails; per the contract's documented behavior the NEAR is retained by the staking pool contract instead of reaching the delegator.
5. On the next `ping`, `internal_ping` computes `total_reward = total_balance - last_total_balance` using the now-inflated actual `total_balance` (holding the failed-transfer NEAR) against the already-decremented `last_total_balance`, distributing that amount as reward to the *other* delegators — the original withdrawing delegator's balance is unrecoverably gone from the ledger with no compensating credit anywhere.

                account_id, amount, account.unstaked
            )

        );

        Promise::new(account_id).transfer(amount);

    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true

        assert_self();
