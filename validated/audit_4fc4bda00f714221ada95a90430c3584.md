### Title
Non-deterministic tie-break in `SignerDb::get_last_signed_block` corrupts the `parent_tenure_last_block` equality key used for global state-machine agreement - (File: `stacks-signer/src/signerdb.rs`)

### Summary
The reported Alchemix bug is that a binary search returning "the first exact match" instead of "the canonical (most recent) exact match" lets duplicate timestamp entries produce a value that varies depending on incidental state (epoch count), breaking an equality check that governance relies on. The same structural flaw exists in `stacks-signer`'s "last block in tenure" getters: they select a single row with `ORDER BY stacks_height DESC LIMIT 1` and no tie-breaker, even though the schema and the signer's own conflict-recovery logic can legitimately produce two different rows (two different `signer_signature_hash`es) sharing the same `consensus_hash`/`stacks_height`. Because the `blocks` table's primary key is `(reward_cycle, signer_signature_hash)` [1](#0-0) , siblings at the same height coexist as separate rows, and the tests confirm the signer can genuinely sign two conflicting siblings in the same tenure once the first signature goes stale [2](#0-1) .

### Finding Description
`get_last_signed_block`, `get_last_accepted_block`, and `get_last_globally_accepted_block` all pick a single row by height with no secondary ordering key: [3](#0-2) [4](#0-3) [5](#0-4) 

Compare this to `get_canonical_tip`, which deliberately adds a tie-breaker (`signed_group DESC`) precisely because ties on `stacks_height` are expected across the whole DB: [6](#0-5) 

The `get_last_signed_block`/tenure-scoped getters omit this tie-breaker. This is reachable in-scope by a single miner (no signer majority needed): the signer's own pre-commit/signing flow can place a signature over a sibling block B at the same height as an already-signed block A in the *same* tenure, once A's signature goes stale and the node has not yet confirmed A — this is an intentional recovery path, proven by test `stale_sibling_replaced_when_canonical_tip_below` [2](#0-1) . After this, the `blocks` table holds two rows (A, B) with identical `consensus_hash` and `stacks_height`, both in a "signed" state (`LocallyAccepted`/`GloballyAccepted`).

`get_last_signed_block` feeds `SortitionData::get_tenure_last_block_info`, whose result is combined with the node's view in `get_parent_tenure_last_block`: [7](#0-6) [8](#0-7) 

The tuple returned — `(chain_length, block_id())` — is not just a height; it carries the specific sibling's block hash. Because A and B tie on `chain_length`, *which* sibling's `block_id()` is returned by the untie-broken SQL query is implementation-defined (SQLite gives no ordering guarantee among tied rows, and the physical row order can differ between independent signer processes depending on the order pre-commits/signatures were received and inserted, or across restarts/VACUUMs). This value becomes part of `parent_tenure_last_block` in the signer's `StateMachineUpdate`, which the docs explicitly identify as "the equality key for global agreement" that is "consensus-visible": [9](#0-8) 

Two honest signers that both correctly followed the sibling-replacement rules can therefore end up broadcasting `StateMachineUpdate`s that disagree on `parent_tenure_last_block` — not because they disagree about the real chain, but because their local SQLite instances happened to break an unresolved tie differently. This is precisely the Alchemix bug pattern: a value meant to be a canonical, comparable fact (there, `totalSupplyAtT`; here, "the tenure's last signed block") is instead one of several equally-valid rows chosen non-deterministically.

### Impact Explanation
`parent_tenure_last_block` is aggregated across signers by weight to determine global agreement on the miner's state (`GlobalStateEvaluator::reached_agreement`, `capitulate_miner_view`). If honest signers' locally-derived `parent_tenure_last_block` values diverge because of this tie-break gap, no single value can reach the agreement threshold even though every signer acted correctly per protocol — this can wedge the miner-view state machine so that a valid new tenure's parent choice can never be confirmed by a threshold of signers, stalling block production (a liveness wedge, matching "a signer wedged into never signing valid blocks / acting on a stale...view"). It does not itself directly cause the signature of an invalid block, since the height comparison in `check_latest_block_in_tenure` is unaffected by which tied sibling is chosen (both have equal `chain_length`), but it corrupts the one piece of state explicitly documented as a cross-signer equality key.

### Likelihood Explanation
The precondition — two signed siblings coexisting in one tenure — is not a hypothetical edge case; it is a deliberately supported recovery path in the codebase's own test suite (`stale_sibling_replaced_when_canonical_tip_below`), reachable by ordinary miner/network conditions (a stale conflict plus an unconfirmed canonical tip), requiring no signer majority and no cryptographic break — only ordinary timing between a re-proposed sibling and staleness of the earlier signature.

### Recommendation
Add a deterministic tie-breaker to `get_last_signed_block`, `get_last_accepted_block`, and `get_last_globally_accepted_block` (e.g., `ORDER BY stacks_height DESC, COALESCE(signed_group, signed_self) DESC` or `ORDER BY stacks_height DESC, rowid DESC`), consistent with what `get_canonical_tip` already does, so that all signers derive the same "last signed block" fact from the same underlying data whenever a height tie exists.

### Proof of Concept
1. Run the existing test scenario `stale_sibling_replaced_when_canonical_tip_below` (`stacks-signer/src/v0/tests.rs:809-826`) to produce two rows, A and B, in the `blocks` table with identical `consensus_hash`/`stacks_height`, both signed.
2. Call `SignerDb::get_last_signed_block(&consensus_hash)` repeatedly against databases populated by inserting A then B, versus B then A (simulating two different signer instances receiving the pre-commits/signatures in different orders).
3. Observe that the returned `BlockInfo.block.block_id()` differs between the two insertion orders despite both databases representing an equally "correct" local view — demonstrating the non-deterministic selection that then propagates into `get_parent_tenure_last_block`'s equality key.

    /// Get the last signed block from the given tenure if it has not timed out.
    /// Even globally accepted blocks are allowed to be timed out, as that
    /// triggers the signer to consult the Stacks node for the latest globally
    /// accepted block. This is needed to handle Bitcoin reorgs correctly.
    ///
    /// The timeout window is measured from the last time a signature actually covered the
    /// block: our own (`signed_self`) or the observed group/global acceptance
    /// (`signed_group`), whichever is later, matching how `get_signed_conflicts` measures
    /// endorsement freshness. `approved_time` is deliberately not used: it is stamped at
    /// pre-commit, which carries no signature, so it would close the window early. This also
    /// means a globally accepted block we never signed ourselves gets a full window from the
    /// time its acceptance was observed, rather than timing out instantly for lack of a
    /// timestamp.
    pub fn get_tenure_last_block_info(
        consensus_hash: &ConsensusHash,
        signer_db: &SignerDb,
        tenure_last_block_proposal_timeout: Duration,
    ) -> Result<Option<BlockInfo>, ClientError> {
        // Get the last signed block in the tenure
        let last_signed_block = signer_db
            .get_last_signed_block(consensus_hash)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;

        let Some(block_info) = last_signed_block else {
            return Ok(None);
        };

        // `approved_time` may hold the pre-commit time; use the actual signature time.
        let Some(signed_over_time) = block_info.signed_self.max(block_info.signed_group) else {
            return Ok(None);
        };

        if signed_over_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
            > get_epoch_time_secs()
        {
            // The last accepted block is not timed out, return it
            Ok(Some(block_info))
        } else {
            // The last accepted block is timed out
            info!(
                "Last accepted block has timed out";
                "signer_signature_hash" => %block_info.block.header.signer_signature_hash(),
                "signed_over_time" => signed_over_time,
                "state" => %block_info.state,
            );
            Ok(None)
        }
    }

    /// Retrieves the last known block height and ID for a given parent tenure, querying
    /// both the connected stacks-node and local signer database to determine the most
    /// recent block associated with the specified `parent_tenure_id`.
    pub fn get_parent_tenure_last_block(
        client: &StacksClient,
        db: &SignerDb,
        tenure_last_block_proposal_timeout: Duration,
        parent_tenure_id: &ConsensusHash,
    ) -> Result<(u64, StacksBlockId), SignerChainstateError> {
        let stacks_node_last_block = client
            .get_tenure_tip(parent_tenure_id)
            .inspect_err(|e| {
                warn!(
                    "Signer State: Failed to fetch last block in parent tenure from stacks-node";
                    "parent_tenure_id" => %parent_tenure_id,
                    "err" => ?e,
                )
            })
            .ok()
            .map(|header| {
                (
                    header.anchored_header.height(),
                    StacksBlockId::new(parent_tenure_id, &header.anchored_header.block_hash()),
                )
            });
        let signerdb_last_block = SortitionData::get_tenure_last_block_info(
            parent_tenure_id,
            db,
            tenure_last_block_proposal_timeout,
        )?
        .map(|info| (info.block.header.chain_length, info.block.block_id()));

        let (parent_tenure_last_block_height, parent_tenure_last_block) =
            match (stacks_node_last_block, signerdb_last_block) {
                (Some(stacks_node_info), Some(signerdb_info)) => {
                    std::cmp::max_by_key(stacks_node_info, signerdb_info, |(chain_length, _)| {
                        *chain_length
                    })
                }
                (None, Some(signerdb_info)) => signerdb_info,
                (Some(stacks_node_info), None) => stacks_node_info,
                (None, None) => {
                    return Err(SignerChainstateError::NoParentTenureInfo(
                        parent_tenure_id.clone(),
                    ))
                }
            };
        Ok((parent_tenure_last_block_height, parent_tenure_last_block))
    }
