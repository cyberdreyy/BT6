### Title
Missing subscriber/allowlist authorization check in HandleLegacyUserMessage allows any signed message to trigger DON capability execution - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` validates message structure, timestamp freshness, and method name, but never checks whether `msg.Body.Sender` (the recovered signer address) is an authorized/allowlisted subscriber for the target DON before saving the callback and fanning the request out to every DON member via `don.SendToNode`. The code even contains a `TODO: apply allowlist and rate-limiting here` comment marking the gap explicitly.

### Finding Description
`HandleLegacyUserMessage` ( [1](#0-0) ) performs these checks in order: (1) unmarshal `body.Payload` into `webapicap.TriggerRequestPayload`, (2) verify `payload.Timestamp != 0`, (3) verify message is not stale relative to `MaxAllowedMessageAgeSec`, (4) verify `msg.Body.Method == MethodWebAPITrigger`, and (5) build a request via `common.ValidatedRequestFromMessage(msg)`. None of these steps check `msg.Body.Sender` against `h.donConfig.Members` or any subscriber/allowlist structure. The explicit comment at line 384, `// TODO: apply allowlist and rate-limiting here`, confirms the check is not implemented in this reviewed path [2](#0-1) .

After passing these checks, the handler unconditionally stores the callback keyed by `msg.Body.MessageId` and iterates `h.donConfig.Members`, calling `don.SendToNode(ctx, member.Address, req)` for every DON node [3](#0-2) . `ValidatedRequestFromMessage` only transforms the message into a JSON-RPC request format for the DON transport layer — it does not perform subscriber authorization; it validates message construction, not the identity/permission of the sender relative to the DON.

Because `msg.Body.Sender` is not cross-checked against a per-DON or per-method allowlist, any holder of a valid ECDSA key who can produce a correctly-signed `MessageBody` (with a `DonId`/`Method` matching a configured handler) can reach this code path and cause `don.SendToNode` to fan a compute-triggering request out to every member node of the DON, consuming DON-side compute resources meant to be reserved for authorized subscribers.

### Impact Explanation
This matches the Chainlink bounty class of "unauthorized job run" / access to gated compute: an unauthenticated (relative to the DON's subscriber list) actor can force DON capability execution (`MethodWebAPITrigger`) across the entire DON. This can be leveraged for resource-exhaustion/DoS against a capability DON, and represents unauthorized consumption of gated compute meant to be limited to allowlisted subscribers.

### Likelihood Explanation
The only precondition stated is possession of any valid ECDSA keypair (no DON membership needed) and knowledge of the target `DonId`/`Method`, both of which are not secret (Don IDs and method names are part of routine, non-secret protocol/config data). The check gap is explicit in the code with a `TODO` comment, and the reachable path (gateway receiving `MessageBody`, JSON-RPC decode, signature recovery to populate `Sender`, then `HandleLegacyUserMessage`) does not perform an allowlist/subscription check anywhere before `don.SendToNode`. This makes the issue highly likely to be exploitable and repeatable as long as no allowlist enforcement exists elsewhere in the invocation chain that this scoped review could confirm (upstream gateway signature-verification code in `gateway.go` was not fully retrievable due to tool constraints, but based on all located code, only signature validity — not subscription membership — is checked before dispatch).

### Recommendation
Before storing the callback and calling `don.SendToNode`, verify that `msg.Body.Sender` is present in an authorized allowlist/subscription registry scoped to `h.donConfig.DonId` and `msg.Body.Method` (e.g., per-DON subscriber list configured alongside `donConfig.Members`), and reject with an authorization error (e.g., `api.UnauthorizedError`) if the sender is not a subscribed/allowlisted principal. Implement the `TODO: apply allowlist and rate-limiting here` item as a blocking check rather than a comment.

### Proof of Concept
Go unit test plan (extends `handler_test.go`):
1. Construct a `donConfig.Members` list that does not include the attacker's address.
2. Generate a fresh ECDSA keypair for the "attacker" (never registered anywhere in `donConfig` or any allowlist config).
3. Build a `webapicap.TriggerRequestPayload` with a valid, current `Timestamp`, marshal it into `MessageBody.Payload`, set `Method = MethodWebAPITrigger` and `DonId` to the handler's configured DON id.
4. Sign the message body with the attacker's private key, recover/set `msg.Body.Sender` to the attacker's address (mirroring how the gateway populates `Sender` after signature verification).
5. Provide a mock `handlers.DON` (e.g., via `handlers/mocks/handler.go`'s `DON` mock) with `SendToNode` instrumented to record calls.
6. Call `handler.HandleLegacyUserMessage(ctx, msg, callback)` directly.
7. Assert: `don.SendToNode` was called once per DON member (proving fan-out occurred) despite the attacker's address never appearing in `donConfig.Members`/any allowlist, and no authorization error was returned via `callback.SendResponse`. This demonstrates the missing allowlist check.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
