### Title
Freshness check in `HandleLegacyUserMessage` has no upper bound on `payload.Timestamp`, allowing attacker-forged future timestamps to permanently bypass staleness/anti-replay protection - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` only rejects messages that are too old, computed as `uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp)`, but never checks that `payload.Timestamp` is not unreasonably far in the future. An attacker who controls the payload they sign (as any legitimate requester does) can set `Timestamp = now + N` for a large `N`, causing the staleness check to never trip until real wall-clock time catches up to that forged value — effectively making a captured/older request appear perpetually "fresh" well past the intended `MaxAllowedMessageAgeSec` window.

### Finding Description
In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` decodes the `webapicap.TriggerRequestPayload` from `msg.Body.Payload` and performs this freshness check: [1](#0-0) 

The check only computes a lower bound (`now - MaxAllowedMessageAgeSec > payload.Timestamp` ⇒ stale). There is no corresponding upper-bound check (e.g., `payload.Timestamp > now + allowedClockSkew` ⇒ reject as "in the future"). The rest of message validation (`common.ValidatedMessageFromResp` / `msg.Validate()` and `common.ValidatedRequestFromMessage`) authenticates the sender's identity and message structure but does not constrain the value of `payload.Timestamp` itself — it only checks presence of `MessageId`/`Method`. [2](#0-1) [3](#0-2) 

Since `Timestamp` is a field inside the signed `webapicap.TriggerRequestPayload` that the requester constructs and signs themselves, any unprivileged caller submitting a `web_api_trigger` message can set `Timestamp` to an inflated future value (e.g., `time.Now().Unix()+1e9`). Because the check only compares against `now - MaxAllowedMessageAgeSec`, an inflated `Timestamp` will satisfy `payload.Timestamp >= now - MaxAllowedMessageAgeSec` for as long as real time hasn't caught up to the forged value — i.e., essentially indefinitely for realistic values of `N`. A captured copy of such a message (with a valid signature, since the signature was produced honestly at submission time over the forged payload) can then be replayed by anyone who obtains it, well beyond the intended freshness window, and the "stale message" branch will never trigger.

### Impact Explanation
This defeats the intended anti-replay/staleness protection (`MaxAllowedMessageAgeSec`) for `web_api_trigger` requests processed via `HandleLegacyUserMessage`. Impact is scoped to replay of previously captured/valid trigger request messages remaining "fresh" indefinitely, which can cause the DON nodes to re-execute a workflow trigger that was intended to expire, potentially causing duplicate or unauthorized workflow runs if such a message is intercepted or reused. This falls under bypass of a request freshness/anti-replay control, matching a "request impersonation via replay" class issue rather than key/secret disclosure or fund movement directly, though downstream effects depend on what actions the triggered workflow performs.

### Likelihood Explanation
Exploitation requires only the ability to submit a `web_api_trigger` message through the gateway with a self-chosen `Timestamp` field, which is available to any unprivileged, unauthenticated-to-this-check external client capable of sending gateway trigger requests (the same population described in the threat model). No signature forgery or elevated privilege is needed — the attacker simply picks their own `Timestamp` value when constructing the message they legitimately sign. This makes the issue highly feasible and fully repeatable.

### Recommendation
Add an upper-bound check on `payload.Timestamp` in `HandleLegacyUserMessage`, e.g.:
```go
now := uint(time.Now().Unix())
if now-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) || uint(payload.Timestamp) > now+allowedClockSkewSec {
    // reject as stale/invalid
}
```
Reject messages whose `Timestamp` is further in the future than a small configurable clock-skew tolerance, so forged future timestamps cannot be used to bypass staleness checks.

### Proof of Concept
Go unit test plan (extending `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct a `handler` with `HandlerConfig.MaxAllowedMessageAgeSec = 5`.
2. Build a `webapicap.TriggerRequestPayload` with `Timestamp = time.Now().Unix() + 1_000_000_000` (far future) and marshal it into `api.Message.Body.Payload` with `Method = MethodWebAPITrigger`.
3. Call `h.HandleLegacyUserMessage(ctx, msg, callback)` immediately, and again after `time.Sleep(6 * time.Second)` (past `MaxAllowedMessageAgeSec`).
4. Assert that in both calls the callback does **not** receive an error response with message `"stale message"` (i.e., the staleness branch is never triggered), demonstrating the message remains "fresh" indefinitely despite exceeding the configured age window.
5. As a control, repeat with a normal `Timestamp = time.Now().Unix()` and confirm the "stale message" error **is** returned after sleeping past `MaxAllowedMessageAgeSec`, confirming the check works correctly for non-forged timestamps and only fails for forged future ones.

// ValidatedMessageFromResp validates and extracts legacy Gateway Message
// from JSON-RPC results field in the response
func ValidatedMessageFromResp(resp *jsonrpc.Response[json.RawMessage]) (*api.Message, error) {
	if resp.Error != nil {
		return nil, fmt.Errorf("received error, ID: %s", resp.ID)
	}
	if resp.Result == nil {
		return nil, fmt.Errorf("response result is nil, ID: %s", resp.ID)
	}
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return nil, err
	}
	msg.Body.MessageId = resp.ID
	err = msg.Validate()
	if err != nil {
		return nil, err
	}
	return &msg, nil
}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
