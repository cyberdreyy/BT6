### Title
JWT replay cache TOCTOU race allows single-use trigger JWT to be executed twice via concurrent Authorize calls - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` checks `jwtCache.isReplay(claims.ID)` and later calls `jwtCache.recordUsage(claims.ID)` as two separate, independently-locked operations rather than one atomic check-and-set. A holder of a single valid JWT can send two concurrent requests with the same token so that both goroutines pass the replay check before either records usage, causing the same signed authorization to be accepted twice.

### Finding Description
`Authorize` first verifies the JWT and extracts `claims.ID` (jti), then calls `h.jwtCache.isReplay(claims.ID)` which only takes an `RLock` to read `cache.cache[jti]` [1](#0-0) . Only after signer/authorized-key validation succeeds does it call `h.jwtCache.recordUsage(claims.ID)`, which takes a separate `Lock` to write the timestamp [2](#0-1) . These two locked critical sections are not combined into a single atomic "test-and-set," so the full sequence in `Authorize` is: verify → isReplay → lookup authorized keys → check signer → recordUsage [3](#0-2) .

If an attacker who holds one valid, unexpired JWT (jti=X) issues two requests with identical `req.Auth` concurrently, both goroutines can execute `isReplay(X)` before either executes `recordUsage(X)`, since there is a window between the read and the write with no held lock across the whole function. Both calls will see `exists == false`, both will pass the authorized-key check, and both will call `recordUsage`, resulting in the single signed authorization being accepted and acted upon twice. The existing replay-cache design assumes serialized check-then-record, but the code does not enforce mutual exclusion across the full authorize sequence, so it does not actually prevent this race.

### Impact Explanation
This maps to the Chainlink bounty impact class of "authorization/quota bypass leading to unauthorized action from a single signed credential" — i.e., replay/duplication of a legitimately-obtained, single-use JWT-authorized workflow trigger. Concretely, a single signed HTTP trigger request could cause the underlying workflow to run twice (double execution of trigger logic, potential duplicate state changes, double consumption of quota/rate-limit budget, or duplicate fund-moving actions if the triggered workflow performs any state-changing effect), even though the JWT is designed to be single-use.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs one valid, unexpired JWT that they are otherwise entitled to use once (an unprivileged, legitimate holder of a signed trigger credential — no operator/admin access required). The race window is a normal Go concurrency race requiring no special network timing tricks beyond firing two requests in parallel (e.g., via goroutines or near-simultaneous HTTP requests), so it is practically reproducible and repeatable in a unit/integration test that invokes `Authorize` from two goroutines with the same token.

### Recommendation
Combine the isReplay check and recordUsage into a single atomic operation guarded by one lock acquisition for the whole check-and-set sequence, e.g., add a `checkAndRecord(jti string) bool` method that takes the write lock once, checks existence, and inserts atomically, returning false if already present. Call this single atomic method from `Authorize` immediately after JWT verification (before doing authorized-key lookups), so a duplicate jti is rejected regardless of concurrent timing, and only proceed to authorized-key checks if the atomic reservation succeeded (rolling back / not needed since insertion just needs to happen once up front).

### Proof of Concept
Go unit test in `workflow_metadata_handler_test.go`:
1. Construct a `WorkflowMetadataHandler` with a valid workflow ID registered with one authorized key, matching a test ECDSA signer.
2. Generate one valid JWT (`jti = "X"`) signed by that authorized key for a given `req`.
3. Launch two goroutines that both call `h.Authorize(workflowID, token, req)` concurrently using a `sync.WaitGroup` and a barrier (e.g., a channel or `sync.WaitGroup` released simultaneously) to maximize race probability; run with `-race` and repeat in a loop (e.g., 100–1000 iterations) to reliably trigger the race window.
4. Collect both results; assert that exactly one call returns success (`nil` error) and the other returns the "JWT token has already been used" error.
5. Expected current (buggy) behavior: under race conditions, both calls return success (no error), demonstrating double-authorization from a single JWT. After the fix (atomic check-and-set), exactly one call succeeds deterministically even under concurrent execution.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
