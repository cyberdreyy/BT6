### Title
Verbose FatalError on unreachable relay quorum leaks DON topology/health counters to any gateway caller - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`forwardBundleOrTerminateIfReady`'s "relay quorum unreachable" branch builds a `FatalError` whose message directly interpolates `summary.Signed()`, `maxPossibleSigned`, `minQuorum`, `summary.Total()`, `nodes`, `remaining`, `summary.Error()`, and `summary.Undecodable()`, and `constructErrorResponse` passes this string through unmodified via `err.Error()` into the JSON-RPC error sent back to the requester. Any caller of `HandleJSONRPCUserMessage` (e.g. `MethodSecretsGet`/`MethodCapabilityExec`) who can trigger enough node non-responses to make quorum unreachable receives this fully detailed error text, exposing DON size and health as an oracle.

### Finding Description
In `forwardBundleOrTerminateIfReady` [1](#0-0) , when `maxPossibleSigned < minQuorum` and the request has not expired, the handler logs the warning and then builds the externally sent error:

```go
return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError,
    fmt.Errorf("relay quorum unreachable: %d signed responses, at most %d possible, need %d (collected=%d nodes=%d remaining=%d errors=%d undecodable=%d)",
        summary.Signed(), maxPossibleSigned, minQuorum, summary.Total(), nodes, remaining, summary.Error(), summary.Undecodable())))
```

`constructErrorResponse` [2](#0-1)  only rewrites the error text for `NodeReponseEncodingError`, `InvalidParamsError`, `UnsupportedMethodError`, and `UserMessageParseError`; `api.FatalError` falls through untouched, so `err.Error()` — containing the raw counts above — is placed verbatim into `h.codec.EncodeNewErrorResponse(req.ID, ..., err.Error(), nil)`. That payload is delivered through `sendResponseAndClearRequest` → `ar.SendResponse` (the `gwhandlers.Callback`) [3](#0-2) , which is the same callback mechanism the gateway uses to synchronously return the HTTP response body to `ProcessRequest`'s caller, as shown by handler test patterns that echo `SendResponse` payload straight back as the returned response body [4](#0-3) . There is no role check, redaction, or generic-message substitution anywhere in this branch or in `constructErrorResponse` gating verbosity by caller privilege — the handler and `Callback` interface [5](#0-4)  carry no notion of caller role at all.

This is reachable because `nodes` (total DON member count), `remaining` (nodes expected to still respond), `summary.Total()` (nodes that have responded so far), and `summary.Error()`/`summary.Undecodable()` (node failure/decoding-error counts) are DON-internal topology/health signals normally only visible to operators, not something a request signer needs to see to interpret a business failure.

### Impact Explanation
An unprivileged caller who can force the DON into a state where quorum is provably unreachable (e.g., by targeting a DON/method when they know some subset of nodes are offline or misbehaving, or simply retrying and observing which requests degrade) receives exact counters for total DON size, remaining nodes, currently-collected responses, node error counts, and undecodable counts. This matches the SECRET_CONFINEMENT concern in scope: DON topology and per-node health become an oracle usable to fingerprint DON size/liveness without any operator credential, which is a legitimate (though limited-severity) information-disclosure class — it does not by itself expose keys, secrets, or allow unauthorized actions, but it does leak internal infrastructure state cross-privilege-boundary to any signer of a gateway request.

### Likelihood Explanation
Feasibility is moderate: the caller only needs to be a valid signer of gateway JSON-RPC requests (no operator role) and needs the DON to be in a state where fewer than `minQuorum` further signed responses are possible (e.g., several nodes down/unreachable, which can happen during routine node maintenance or failures, or be induced by a caller who has some ability to affect the fan-out, such as sending malformed params many nodes reject). This is fully repeatable — every time the condition recurs, the same detailed counters are re-disclosed, letting an attacker sample DON health over time.

### Recommendation
In `constructErrorResponse`, treat `api.FatalError` like the other sanitized cases: replace the detailed `err` with a generic, caller-safe message (e.g., `"relay quorum unreachable"`) before encoding it into the JSON-RPC response, while keeping the full counts only in the `l.Warnw(...)` structured log line (already present) for operator visibility. Apply the same treatment to the `RequestTimeoutError` branch that builds an equally detailed message at [6](#0-5) .

### Proof of Concept
Go unit test plan for `confidentialrelay` package:
1. Construct a `handler` with `donConfig.Members` of size N and `F` such that `minQuorum = F+1`.
2. Provide a `relayBundler` mock returning a `BundleSummary` where `Signed()` plus `remaining` is less than `minQuorum` (simulate several nodes already failed/undecodable).
3. Call `h.forwardBundleOrTerminateIfReady(ctx, l, ar, summary, remaining, false)` directly (or drive it via `HandleNodeMessage`).
4. Capture the payload passed to `ar.SendResponse` (mock `gwhandlers.Callback`).
5. Assert: the decoded JSON-RPC error `Message` field does NOT contain the literals `"collected="`, `"nodes="`, `"remaining="`, `"errors="`, or `"undecodable="`, and instead equals a fixed generic string such as `"relay quorum unreachable"`.
6. Current code will fail this assertion, confirming the raw counters are present in the caller-visible message today.

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}

func (h *handler) constructErrorResponse(req jsonrpc.Request[json.RawMessage], errorCode api.ErrorCode, err error) gwhandlers.UserCallbackPayload {
	//nolint:exhaustive // do not modify other error codes
	switch errorCode {
	case api.NodeReponseEncodingError:
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		err = fmt.Errorf("invalid params error: %w", err)
	case api.UnsupportedMethodError:
		err = fmt.Errorf("unsupported method(%s): %w", req.Method, err)
	case api.UserMessageParseError:
		err = fmt.Errorf("user message parse error: %w", err)
	}
	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			nil,
		),
		ErrorCode: errorCode,
	}
}

	gw, handler := newGatewayWithMockHandler(t)

		request := args.Get(1).(jsonrpc.Request[json.RawMessage])
		callback := args.Get(2).(handlers.Callback)
		// echo back to sender with attached payload
		rawResult := json.RawMessage(`{"result":"OK"}`)
		response := jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      request.ID,
			Result:  &rawResult,
			Method:  request.Method,
		}
		rawMsg, err := json.Marshal(&response)

		require.NoError(t, err)

	requireJSONRPCResult(t, "testDON", response, "abcd", `{"result":"OK"}`)

// UserCallbackPayload is a response to user request sent to HandleLegacyUserMessage()/HandleJSONRPCUserMessage().
// Each message needs to receive at most one response on the provided channel.
type UserCallbackPayload struct {
	RawResponse []byte
	ErrorCode   api.ErrorCode
}

type Callback interface {
	SendResponse(cb UserCallbackPayload) error
}
