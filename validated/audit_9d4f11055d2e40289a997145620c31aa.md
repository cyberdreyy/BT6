### Title
`GlobalStateEvaluator::reached_agreement()` truncates instead of rounding up the 70% threshold, letting signer state machines converge on a stale/under-quorum view - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The Lido report is about a fixed numeric floor (100 wei) that the code fails to respect when splitting an amount, causing a permanent failure once the remainder falls under that floor. The analogous class in this repo is a threshold/rounding inconsistency: two different implementations of the "70% signer weight" supermajority check use different rounding rules, so one of them silently accepts less than the true 70% as "enough."

### Finding Description
The canonical, safety-critical threshold computation for Nakamoto block signing rounds *up*: [1](#0-0) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```

This is deliberately ceiling division: whenever `total_weight * 7` is not an exact multiple of 10, the threshold is bumped up by one unit of weight so that a signer/miner can never treat *less than* 70% of the weight as sufficient. This function is used everywhere a block signature/pre-commit/rejection quorum is checked (`verify_signer_signatures`, `store_and_process_block_signature`, `handle_block_pre_commit`, `store_and_process_block_rejection`) — see e.g. [2](#0-1)  and [3](#0-2) .

However, `GlobalStateEvaluator::reached_agreement()` — the function used to decide agreement on the **global signer state machine** (current miner, burn-block view, active protocol version, and tx-replay set) — uses plain floor division with no ceiling adjustment: [4](#0-3) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```

Because there is no `+1`/ceiling term, whenever `total_weight * 7` is not divisible by 10 the effective bar is one unit of weight *lower* than the intended 70% supermajority (e.g. `total_weight = 15` → true 70% requires weight `11`, but `reached_agreement` accepts weight `10`, i.e. 66.7%). In the degenerate case `total_weight = 1`, the floor becomes `0`, so `reached_agreement(0)` is `true` unconditionally.

`reached_agreement` is the sole gate used throughout `GlobalStateEvaluator` to decide:
- the active signer protocol version (`determine_latest_supported_signer_protocol_version`) — [5](#0-4) 
- the global burn-block view (`determine_global_burn_view`) — [6](#0-5) 
- the global state view / current miner / tx-replay set (`determine_global_state`) — [7](#0-6) 

and it feeds `capitulate_miner_view`/`capitulate_viewpoint` in `stacks-signer/src/v0/signer_state.rs`, which is what causes a signer to switch its local view of the active miner/tenure and its tx-replay set: [8](#0-7) .

So the exact same 70%-threshold constant (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`) is enforced with two different rounding conventions in the same codebase: one that is intentionally conservative (rounds up, used for signatures) and one that is not (rounds down, used for state-machine agreement). This is the "aggregated-weight vs verified-accepts" equality mismatch called out in scope — the weight the state machine treats as "agreement" is not the same weight the signature/rejection path treats as "threshold reached."

### Impact Explanation
This falls under the High-impact category "acting on a stale reward set/threshold." A coalition of signers whose combined weight is strictly between `floor(0.7*W)` and `ceil(0.7*W)` — i.e., below the true supermajority required to actually sign/reject a block — is nonetheless sufficient to flip the *global state machine's* view of: the active protocol version, the canonical burn-block view, the current miner, and the tx-replay set. A signer capitulating to this under-quorum "agreement" changes which miner/tenure it treats as authoritative (`capitulate_viewpoint`) even though the true 70% bar used for actual block signing was never met. This can desynchronize a signer's local state machine from the properly-thresholded block-signing view, and in the degenerate `total_weight == 1` case makes `reached_agreement` trivially true for zero votes.

### Likelihood Explanation
Medium. The bug is deterministic and triggers any time `total_weight * 7 mod 10 != 0`, which is the common case for arbitrary signer-weight distributions (not a rare edge value like the Lido "last chunk < 100 wei" case, but structurally identical: an integer-division remainder that the code fails to round up for a fixed threshold). It requires only that a set of signers close to — but numerically under — the true 70% bar broadcast `StateMachineUpdate` messages agreeing on a value; it does not require compromising a majority of signers, only exploiting the built-in one-unit rounding gap.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` use the same ceiling-division logic as `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g. by calling that shared function (or duplicating its `+1` remainder adjustment) instead of performing raw floor division, so that "reaching agreement" in the global state machine always requires the same true ≥70% weight that block signing requires.

### Proof of Concept
Not independently executed (ask-only mode); the discrepancy is demonstrable purely by arithmetic:
- `total_weight = 15`, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`:
  - `compute_voting_weight_threshold(15)` → `(15*7)/10 = 10`, remainder ≠ 0 → `+1` → **11** required for signing.
  - `reached_agreement(10)` on a `GlobalStateEvaluator` with `total_weight = 15` → `10 >= (15*7)/10 = 10` → **true**, despite only carrying 66.7% of the weight, one unit short of the actual 70% bar used for signatures.
- `total_weight = 1`: `reached_agreement(0)` → `0 >= (1*7)/10 = 0` → **true** unconditionally.

Note: due to index size limits, I could not fully trace every downstream consumer of `capitulate_miner_view`'s output across the node-side coordinator to quantify the exact end-to-end consequence chain; a Devin session with full repo access would be needed to trace all call sites and confirm whether any additional guard rails elsewhere compensate for this rounding gap.

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
