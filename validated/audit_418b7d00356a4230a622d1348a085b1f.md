### Title
Division-before-multiplication precision loss in Jovian DA-footprint gas estimation - (File: crates/common/l1-fees/src/params.rs, crates/execution/flashblocks/src/state_builder.rs)

### Summary
`L1FeeParams::jovian_da_footprint` and the equivalent inline logic in `StateProcessor::jovian_da_footprint_estimation` (flashblocks state builder) compute the Jovian DA-footprint gas charge by dividing the FastLZ-scaled estimated size by `1e6` *before* multiplying by the DA-footprint gas scalar, instead of multiplying first and dividing last. This is the same "division before multiplication" precision-loss pattern reported in the external USSD audit finding, reproduced here in Base's consensus-relevant DA-footprint gas metering used on the Jovian upgrade.

### Finding Description
`tx_estimated_size_fjord` returns the FastLZ compressed-size estimate pre-scaled by `1e6` [1](#0-0) .

`L1FeeParams::jovian_da_footprint` is documented as computing `estimated_size(scaled by 1e6) / 1e6 * scalar`, and that is exactly the order of operations implemented — divide by `1e6` first, then multiply by `scalar`: [2](#0-1) 

Contrast this with the sibling `calculate_tx_l1_cost_fjord`, which correctly multiplies the estimated size by the fee-scaled value *before* dividing: [3](#0-2) 

The same divide-then-multiply order is duplicated in the flashblocks pending-state builder's own copy of this computation: [4](#0-3) 

Because `tx_estimated_size_fjord` values are frequently not exact multiples of `1e6` (e.g. `100 * 1_000_000` floor, or `intercept + fastlzCoef*fastlzSize` for larger transactions, whose remainder mod `1e6` is essentially arbitrary), performing `size / 1e6` first truncates the sub-`1e6` remainder before it is scaled up again by `scalar`. Multiplying first (`size * scalar / 1e6`) would retain that remainder's contribution, scaled by `scalar`, in the final integer result. For any `scalar > 1`, the "divide-then-multiply" order systematically loses up to `(scalar - 1) * (1e6 - 1) / 1e6` units of gas per transaction relative to the mathematically correct multiply-then-divide order — an on-chain analog of the exact bug class in the reported audit finding.

### Impact Explanation
`jovian_da_footprint` (and its duplicate in `jovian_da_footprint_estimation`) feeds the Jovian DA-footprint block-limit accounting, which is a resource-metering mechanism gating how much L1 data-availability footprint a block may consume [5](#0-4) . Systematically undercharging DA-footprint gas for every transaction (because the truncated remainder from `/1e6` is silently dropped before scaling) causes blocks to under-report their true DA footprint, letting more calldata-heavy transactions fit under the DA-footprint gas limit than the protocol intends. This is a resource-metering integrity issue on a consensus-critical path (block building / gas metering for the Jovian upgrade), not merely a rounding cosmetics issue, since the DA-footprint limit exists specifically to bound L1 data posting cost/availability per block.

### Likelihood Explanation
This code runs unconditionally for every non-deposit transaction once Jovian is active, on every block-building and flashblocks-pending-state path, so the precision loss is triggered on essentially all Jovian-era transactions whenever `tx_estimated_size_fjord(input) % 1_000_000 != 0` and `da_footprint_gas_scalar > 1`. This is a near-certain condition for real transactions (FastLZ-estimated size is rarely an exact multiple of a million), so the bug is continuously triggered without any attacker action — any transaction sender's normal transaction reaches this path.

### Recommendation
Reorder the arithmetic to multiply before dividing, mirroring `calculate_tx_l1_cost_fjord`:
```rust
pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
    let Some(scalar) = self.da_footprint_gas_scalar else {
        return 0;
    };
    U256::from(tx_estimated_size_fjord(input))
        .saturating_mul(scalar)
        .wrapping_div(U256::from(1_000_000u64))
        .saturating_to::<u64>()
}
```
Apply the same reordering to the duplicated logic in `StateProcessor::jovian_da_footprint_estimation` in `crates/execution/flashblocks/src/state_builder.rs`, and add a regression test asserting parity between the two implementations (and against a multiply-first reference) for inputs whose FastLZ-estimated size is not an exact multiple of `1e6`.

### Proof of Concept
Using the existing `L1FeeParams::jovian_da_footprint` implementation:
```rust
// tx_estimated_size_fjord returns e.g. 100_500_000 (not a multiple of 1e6)
// scalar = 7
let p = L1FeeParams { da_footprint_gas_scalar: Some(U256::from(7)), ..Default::default() };

// Current (buggy) order: divide first, then multiply
// 100_500_000 / 1_000_000 = 100  → 100 * 7 = 700

// Correct order: multiply first, then divide
// 100_500_000 * 7 = 703_500_000 → / 1_000_000 = 703

// 700 != 703 — 3 gas units of DA-footprint undercharge per such transaction,
// scaling with scalar and the truncated remainder.
```
This mirrors the reproduction methodology in the original report (comparing `/2 * 1e12` vs `* 1e12 / 2` on the same inputs), applied to `jovian_da_footprint`'s `/1e6` then `*scalar` ordering.

/// This value is computed based on the following formula:

        .saturating_mul(L1_COST_FASTLZ_COEF)

    /// Post-Fjord L1 cost:
    /// `estimatedSize * (baseFeeScalar*l1BaseFee*16 + blobFeeScalar*l1BlobBaseFee) / 1e12`.
    pub fn calculate_tx_l1_cost_fjord(&self, input: &[u8]) -> U256 {
        if Self::is_fee_exempt(input) {
            return U256::ZERO;

        let l1_fee_scaled = self.calculate_l1_fee_scaled_ecotone();

            .saturating_mul(l1_fee_scaled)
            .wrapping_div(U256::from(1_000_000_000_000u64))
    }

    fn jovian_da_footprint_estimation(
        &mut self,
        tx_env: &Recovered<BaseTxEnvelope>,
    ) -> Result<u64, StateProcessorError> {
        // Try to use the enveloped tx if it exists, otherwise use the encoded 2718 bytes
        let encoded = estimate_tx_compressed_size(tx_env.into_encoded().encoded_bytes())
            .saturating_div(1_000_000);

        // Load the L1 block contract into the cache. If the L1 block contract is not pre-loaded the
        // database will panic when trying to fetch the DA footprint gas scalar.
        self.evm.db_mut().basic(Predeploys::L1_BLOCK_INFO).map_err(|err| {
            StateProcessorError::Execution(ExecutionError::DaFootprintEstimation(err.to_string()))
        })?;

        let da_footprint_gas_scalar = L1BlockInfo::fetch_da_footprint_gas_scalar(self.evm.db_mut())
            .map_err(|err| {
                StateProcessorError::Execution(ExecutionError::DaFootprintEstimation(
                    err.to_string(),
                ))
            })?
            .into();

        Ok(encoded.saturating_mul(da_footprint_gas_scalar))
    }
