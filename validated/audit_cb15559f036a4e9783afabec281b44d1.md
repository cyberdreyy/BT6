### Title
Legacy WebAPI trigger messages accepted by the DON gateway lack replay protection, allowing signature/message reuse to trigger duplicate workflow executions - (File: core/capabilities/webapi/trigger/trigger.go, core/services/gateway/handlers/capabilities/handler.go)

### Summary
The `DelegationMetaSwapAdapter` report flags that a validly-signed payload (checked only for signature correctness and expiration) can be replayed because no nonce/"already used" tracking exists. The Chainlink gateway's legacy WebAPI trigger path (`core/services/gateway/handlers/capabilities/handler.go` `HandleLegacyUserMessage`, forwarded to `core/capabilities/webapi/trigger/trigger.go` `processTrigger`) has an analogous gap for user-submitted, signed `Message`s: validation only checks the ECDSA signature (`api.Message.Validate()` / `ExtractSigner()`) and a coarse timestamp-staleness window (`MaxAllowedMessageAgeSec`), but never records a used message ID/signature to reject resubmission.

### Finding Description
An unprivileged client authenticates a WebAPI trigger request purely via an ECDSA signature over the message body [1](#0-0) . `HandleLegacyUserMessage` rejects a message only if it fails to unmarshal, has a zero timestamp, or its `payload.Timestamp` is older than `MaxAllowedMessageAgeSec` seconds — there is no check for "have I already processed this exact `MessageId`/signature" [2](#0-1) . The `savedCallbacks` map is keyed by `msg.Body.MessageId` purely to route the eventual node response back to the original caller and is deleted as soon as it's consumed, not to detect duplicate submissions [3](#0-2) [4](#0-3) .

The message is forwarded unchanged to all DON nodes, where `triggerConnectorHandler.processTrigger` re-checks only sender allow-listing and per-sender rate limiting before firing the trigger channel that starts a workflow execution [5](#0-4) . As long as the signed message is resubmitted within the `MaxAllowedMessageAgeSec` window and under the sender's rate limit, the identical signed payload will be accepted again and will trigger the workflow again — there is no nonce/message-ID dedup analogous to the `RequestReplayGuard`/JWT-`jti` replay caches used elsewhere in the gateway for the Vault flow and HTTP trigger v2 flow [6](#0-5) [7](#0-6) . Those newer flows (Vault JSON-RPC, v2 HTTP trigger with JWT) were explicitly hardened against this exact class of bug (see `ErrRequestAlreadySeen` and "token has already been used" tests) [8](#0-7) [9](#0-8) , but the legacy `MethodWebAPITrigger` message path was not.

### Impact Explanation
Replay of a captured/legitimately-observed signed trigger message causes duplicate, unauthorized workflow executions on the DON — an unprivileged actor (or anyone who observes network traffic / logs containing the signed message before its expiry) can re-trigger workflow logic multiple times using a single valid signature, without needing the sender's private key. Depending on what the triggered workflow does (on-chain writes, external calls, state changes), this can cause duplicate financial/on-chain actions, similar in class to the "unauthorized job run" acceptance criterion.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to obtain a copy of an already-signed, unexpired `Message` (e.g., via network observation, log access, or a cooperating/compromised gateway relay) since they cannot forge the ECDSA signature themselves. Given `MaxAllowedMessageAgeSec` provides a window (not instantaneous single-use enforcement) and the only other gate is a per-sender rate limiter (not a duplicate-ID check), replay is straightforward once a signed message is captured.

### Recommendation
Add a replay guard for legacy `MethodWebAPITrigger` messages analogous to `RequestReplayGuard`/JWT `jti` cache already used in the Vault and v2 HTTP trigger flows: track seen `MessageId` (or signature) values with an expiry equal to `MaxAllowedMessageAgeSec` at the gateway (`handler.go`) and/or at the DON trigger handler (`trigger.go`), rejecting any message whose ID/signature has already been accepted within that window.

### Proof of Concept
1. A legitimate sender signs and submits a `MethodWebAPITrigger` message with a valid `MessageId`, timestamp, and topics that match a registered workflow's `allowedTopics`/`allowedSenders`.
2. `HandleLegacyUserMessage` accepts it (timestamp is fresh) and forwards it to all DON members [10](#0-9) .
3. An observer captures the exact same signed JSON-RPC request bytes before `MaxAllowedMessageAgeSec` elapses and resubmits it to the gateway.
4. `HandleLegacyUserMessage` re-validates it identically (no dedup check) and forwards it again; `processTrigger` on each DON node passes the sender/rate-limit checks again (as long as the rate limiter has capacity) and fires `trigger.ch <- tr` again, starting a second workflow execution from the same signed payload [11](#0-10) .

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here

// RequestReplayGuard prevents replay of already-processed requests by tracking
// request digests with expiry timestamps. It is safe for concurrent use.
//
// Used by both the AllowListBasedAuth flow and the JWTBasedAuth flow to ensure
// that a given request digest is only accepted once.
type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
