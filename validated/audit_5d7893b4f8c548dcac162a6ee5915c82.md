## Title
Stale confirmations from removed multisig members are not purged, allowing requests to execute below the true live-member threshold — (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only removes requests that were *authored* by the member being deleted; it does not scrub confirmations that member previously cast on *other* members' pending requests. Because `confirm()` counts entries in the `confirmations: LookupMap<RequestId, HashSet<String>>` set toward `num_confirmations` without re-validating that each entry still corresponds to a current member, a request can later execute using a confirmation from an account that has already been removed from the multisig. This breaks the K-of-N invariant: the number of *recorded* confirmations no longer equals the number of confirmations from *live* members.

### Finding Description
`confirm()` adds the caller's identity to the request's confirmation set and executes the request once the set size (plus the new confirmation) reaches `num_confirmations`: [1](#0-0) 

`assert_valid_request()` only checks that the *current caller* is a member; it never re-validates the members recorded in an existing `confirmations` set: [2](#0-1) 

`delete_member()` removes the departing member from `self.members`, deletes any *requests they authored*, and removes their `num_requests_pk` entry — but it never scans `self.confirmations` to strip that member's `to_string()` entry from confirmation sets of requests authored by *other* members: [3](#0-2) 

Binding that should hold: `confirmations.len() at execution time == number of confirmations from accounts that are still members at execution time`. After a member is removed, this equality is violated — a stale confirmation from a now-removed member remains counted forever, since nothing ever revisits or invalidates confirmation sets outside of the deleted member's own authored requests.

### Impact Explanation
This is a Critical-impact issue per the multisig request-execution binding: a request can be executed with fewer than `num_confirmations` *live* signatures, because one "confirmation" belongs to an account that is no longer part of the multisig set. This defeats the K-of-N security assumption the contract advertises (e.g., `Transfer`, `DeployContract`, `AddKey`/`FunctionCall` actions in `execute_request`, `multisig2/src/lib.rs:224-290`), since privileged actions can be authorized with less real consensus than configured.

### Likelihood Explanation
This requires no attacker exploit beyond ordinary multisig lifecycle usage: (1) a member confirms a pending request that does not yet reach threshold, (2) that member is later removed via a normal `DeleteMember` governance action (a routine operation, not requiring any special privilege beyond normal multisig governance), and (3) the original request is later brought to threshold by other members and executes, silently counting the removed member's stale confirmation. No malicious actor input is required — any accidental sequencing of "confirm then get removed" reproduces it, similar to how the Midas bug is triggered by a routine admin action (`rejectRequest`) leaving stale state that is later misused/mis-accounted.

### Recommendation
When removing a member in `delete_member`, iterate over all entries in `self.confirmations` and strip the departing member's `to_string()` key from every confirmation set (not just requests they authored). Alternatively, when counting confirmations in `confirm()`, filter the confirmation set against `self.members` at execution time so that any confirmation from a no-longer-current member does not count toward `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `{A, B, C, D}` and `num_confirmations = 3`.
2. Member `B` calls `add_request_and_confirm(request)` → confirmations = `{B}`.
3. Member `A` calls `confirm(request_id)` → confirmations = `{B, A}` (2 of 3, request not yet executed).
4. Separately, members execute a `DeleteMember { member: A }` request (a normal governance action reaching its own threshold) → `delete_member` removes `A` from `self.members`, deletes only requests *authored by* `A`, but leaves `A`'s entry inside the confirmation set of the request from step 2 untouched (`multisig2/src/lib.rs:356-379`).
5. Member `D` calls `confirm(request_id)` → confirmations = `{B, A, D}`, size 3 ≥ `num_confirmations` (3) → `execute_request` runs the privileged action (e.g. `Transfer`), even though only `B` and `D` are actual live members who confirmed; `A`'s vote is stale. [1](#0-0) [3](#0-2)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
