### Title
V1 duplicate-tenure-block check trusts only "globally accepted" state, missing locally-accepted/pre-committed blocks — a miner can get two conflicting tenure-start blocks signed in the same tenure - ([File: stacks-signer/src/chainstate/v1.rs])

### Summary
`SortitionsView::validate_tenure_change_payload` in the v1 chainstate path guards against duplicate tenure-start blocks by checking `signer_db.get_last_globally_accepted_block(&block.header.consensus_hash)` only [1](#0-0) . This is the same "check the wrong copy of the truth" bug class as CVE-2018-1000073: RubyGems' `install_location` validated a path without resolving it through the actual (possibly symlinked) filesystem location, so an attacker-controlled indirection let files be written outside the intended root. Here, the signer validates "have I already signed a block in this tenure?" against a narrower state (`GloballyAccepted`) than the true set of states that represent "already signed" (`LocallyAccepted`, `PreCommitted`), so a miner can drive a divergence between what the signer *believes* is safe and what has *actually* happened.

### Finding Description
The codebase's own regression test confirms this exact defect was fixed in the v2 chainstate path: v2's `validate_tenure_change_payload` was changed to query `signer_db.get_last_signed_block(&block.header.consensus_hash)` [2](#0-1) , and the test explicitly documents the prior bug: *"previously, the check used `get_last_globally_accepted_block`, which would miss blocks in `LocallyAccepted` or `PreCommitted` state and incorrectly allow a duplicate tenure change"* [3](#0-2) .

The v1 file, however, still performs the check with the narrower query: [1](#0-0) 

`get_last_globally_accepted_block` only returns a block once the network-wide 70% signature threshold has been reached and the node has adopted it as canonical (`GloballyAccepted` state), while `get_last_signed_block`/`get_last_accepted_block` also cover `LocallyAccepted` and `PreCommitted` states that individual signers reach well before global acceptance (per the state machine order documented in `docs/signer-flows.md` and `BlockInfo::check_state`) [4](#0-3) .

Attack path (one-slot miner, no majority of signers required):
1. Miner proposes tenure-start block A for tenure T. This signer instance validates it via the v1 path, finds no prior block in T, and eventually locally accepts / signs A (`mark_locally_accepted`) — but A does not reach the 70% threshold quickly (e.g. some signers are slow, offline, or the miner deliberately withholds broadcasting to enough peers to cross the global 70% pre-commit/signature threshold).
2. Before A becomes `GloballyAccepted`, the same miner proposes a second, different tenure-start block B for the same tenure T (different transactions/coinbase).
3. `validate_tenure_change_payload` (v1) calls `get_last_globally_accepted_block(consensus_hash)`, which returns `None` because A is still only `LocallyAccepted`, so the duplicate check passes.
4. The signer proceeds to validate B against the node and can go on to sign B as well.

This breaks the "one signed tenure-start block per tenure" invariant — the same equality-class of guarantee that `DuplicateBlockFound` is meant to enforce (analogous to "signed vs validated" / "one-per-height/tenure" equality mentioned in scope). The per-height conflict guard at pre-commit/signature time (`get_signed_conflicts`, section 5 of `docs/signer-flows.md`) is a *different* height-based check and does not substitute for the tenure-scoped duplicate-block check that only runs at proposal time [5](#0-4) , as the flow doc itself notes: *"Because the duplicate check never runs again, a block that crosses the pre-commit threshold long after it was proposed relies on section 5's own-tenure conflict guard to cover the same ground."* — but that guard is at the block-height level and depends on `get_signed_conflicts`, not on this consensus-hash/tenure duplicate detection which this specific signer instance skips at proposal time due to using the wrong accessor.

### Impact Explanation
If this signer (running the v1/pre-global-state protocol path) signs two distinct tenure-start blocks for the same tenure because its local state was `LocallyAccepted`/`PreCommitted` rather than `GloballyAccepted` when the second proposal arrived, it contributes a valid signature toward two conflicting blocks at the same tenure. This is exactly the "signer signing a conflicting block" class called out as Critical impact: a rejection/duplicate check that should force a hard reject instead passes because it checks the wrong (stale/narrower) state predicate — the equality being broken is "have I already committed to a block in this tenure" (should include all committed states) vs. "have I globally-accepted a block in this tenure" (only the final state).

### Likelihood Explanation
Reachable by a single miner with no majority-of-signers requirement: it only requires that a signer's own local database has the first tenure-start block in `LocallyAccepted` or `PreCommitted` state (which happens by design during normal operation before 70% threshold is reached) at the moment the miner proposes a competing tenure-start block. This is easily reproducible with normal network latency/timing, or intentionally by a miner withholding block B's competing broadcast until it can time the resend. No cryptographic material beyond the miner's own key is required.

### Recommendation
Change `SortitionsView::validate_tenure_change_payload` in `stacks-signer/src/chainstate/v1.rs` to use `signer_db.get_last_signed_block(&block.header.consensus_hash)` (or the equivalent inclusive query covering `LocallyAccepted`, `PreCommitted`, and `GloballyAccepted`) instead of `get_last_globally_accepted_block`, mirroring the fix already applied in `stacks-signer/src/chainstate/v2.rs`.

### Proof of Concept
1. Configure a signer to use the v1 (pre-global-state) chainstate path (`check_block_against_local_state` → `SortitionsView::check_proposal`) [6](#0-5) .
2. Submit tenure-start block A for tenure T; allow it to reach `LocallyAccepted` (signed by this signer) but prevent it from reaching `GloballyAccepted` (e.g., delay other signers' pre-commits/signatures).
3. Submit tenure-start block B for the same tenure T with different transactions.
4. Observe `validate_tenure_change_payload` calls `get_last_globally_accepted_block`, which returns `None` since A is not yet globally accepted, so the `DuplicateBlockFound` rejection is not raised, and the signer proceeds to sign B — reproducing the exact bug the analogous v2 regression test (`check_tenure_change_rejects_when_locally_accepted_block_exists`) was written to catch [7](#0-6) , but for the still-unpatched v1 path.

fn check_tenure_change_rejects_when_locally_accepted_block_exists() {

    let rand_int = server.local_addr().unwrap().port();

        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure

                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),

        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(

            response.as_bytes(),
            moved_exit_flag,
        );
    });

    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}

    fn check_block_against_local_state(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block: &NakamotoBlock,
    ) -> Option<BlockRejection> {
        let signer_signature_hash = block.header.signer_signature_hash();
        let block_id = block.block_id();
        // Get sortition view if we don't have it
        if sortition_state.is_none() {
            *sortition_state =
                SortitionsView::fetch_view(self.proposal_config.clone(), stacks_client)
                    .inspect_err(|e| {
                        warn!(
                            "{self}: Failed to update sortition view: {e:?}";
                            "signer_signature_hash" => %signer_signature_hash,
                            "block_id" => %block_id,
                        )
                    })
                    .ok();
        }

        // Check if proposal can be rejected now if not valid against sortition view
        if let Some(sortition_state) = sortition_state {
            match sortition_state.check_proposal(
                stacks_client,
                &mut self.signer_db,
                block,
                true,
                self.global_state_evaluator
                    .get_global_tx_replay_set()
                    .unwrap_or_default(),
            ) {
                // Error validating block
                Err(RejectReason::ConnectivityIssues(e)) => {
                    warn!(
                        "{self}: Error checking block proposal: {e}";
                        "signer_signature_hash" => %signer_signature_hash,
                        "block_id" => %block_id,
                    );
                    Some(self.create_block_rejection(RejectReason::ConnectivityIssues(e), block))
                }
                // Block proposal is bad
                Err(reject_code) => {
                    warn!(
                        "{self}: Block proposal invalid";
                        "signer_signature_hash" => %signer_signature_hash,
                        "block_id" => %block_id,
                        "reject_reason" => %reject_code,
                        "reject_code" => ?reject_code,
                    );
                    Some(self.create_block_rejection(reject_code, block))
                }
                // Block proposal passed check, still don't know if valid
                Ok(_) => None,
            }
        } else {
            warn!(
                "{self}: Cannot validate block, no sortition view";
                "signer_signature_hash" => %signer_signature_hash,
                "block_id" => %block_id,
            );
            Some(self.create_block_rejection(RejectReason::NoSortitionView, block))
        }
    }
