### Title
Unauthenticated auth-failure path leaks raw internal error strings via `errors.Join`/`err.Error()` concatenation into user-visible JSON-RPC error - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`httpTriggerHandler.authorizeRequest` is the only error path in this file that concatenates the raw underlying `err.Error()` string from `workflowMetadataHandler.Authorize` directly into the client-visible JSON-RPC error message, rather than using a fixed/generic message like every other validation error in the file. This happens before `setupCallback` is reached, so it is reachable by any unauthenticated caller who can send arbitrary JWT/auth material.

### Finding Description
In `authorizeRequest`: [1](#0-0) 
the code does:
```go
key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
if err != nil {
    h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
    return nil, errors.Join(errors.New("auth failure"), err)
}
```
`handleUserError` marshals `message` directly into the `jsonrpc.WireError.Message` field and sends it back to the caller through `callback.SendResponse`: [2](#0-1) 
and the `Callback.SendResponse` implementation simply forwards the payload to the channel that the HTTP handler reads to build the response for the same requester who sent the malformed/unauthenticated request: [3](#0-2) 

Every other validation failure in this file (missing params, invalid method, invalid workflow ID format, workflow not found, rate limit exceeded, etc.) uses a fixed, hand-written message string that only echoes back values the caller itself supplied (e.g., the `workflowID` they submitted). `authorizeRequest` is the sole exception where the literal `Authorize()` error value — which is produced deep inside `workflowMetadataHandler`'s internal authorization/signature-verification logic — is appended verbatim to the outbound message. This is a deviation from the pattern used everywhere else in the file and is a code smell that risks leaking implementation details (e.g., specific reason for signature mismatch, internal lookup failure text, or other authorization internals) that a generic "invalid auth" message would otherwise withhold.

### Impact Explanation
This falls into the information-disclosure impact class: an unauthenticated caller could receive verbose internal error text describing why a JWT/signature check failed, potentially revealing implementation details about the authorization mechanism (error text shape, presence/absence of internal lookups, etc.) beyond a generic failure notice. This aids reconnaissance/fingerprinting of the authorization logic but the disclosed data is returned only to the same requester who triggered the failure (not to a different, victim user), and I could not confirm the exact contents of `workflowMetadataHandler.Authorize`'s error strings (e.g., whether they include signer addresses or only generic phrases) since that function's body was not available for inspection in this review.

### Likelihood Explanation
Trivial to trigger: any unauthenticated client can send a JSON-RPC trigger request with a malformed or invalid auth token and observe the returned message text. No credentials or prior access are required, and the path executes before `setupCallback`, i.e., pre-authentication.

### Recommendation
Replace `"Auth failure: "+err.Error()` in `authorizeRequest` with a fixed, generic message (e.g., `"Auth failure"` or a small enum of safe categories), consistent with the rest of the handlers in this file, and log the detailed `err` server-side only (as is already done via `h.lggr` inside `handleUserError`).

### Proof of Concept
Go handler-level test plan:
1. Construct an `httpTriggerHandler` with a `workflowMetadataHandler` mock whose `Authorize` returns an error containing a distinguishing internal string (e.g., `"signer 0xABC... does not match owner 0xDEF..."`).
2. Call `HandleUserTriggerRequest` with a valid-looking request but invalid `req.Auth` so that `authorizeRequest` fails.
3. Capture the payload sent to `callback.SendResponse` (via a fake `handlers.Callback`) and assert on `jsonrpc.Response.Error.Message`.
4. Expected (failing) assertion: message should equal a fixed generic string (e.g., `"Auth failure"`), not contain the substring from the underlying `Authorize` error (e.g., not contain `"0xABC"` / `"0xDEF"`).

Note: full confirmation of the actual leaked content requires reviewing `workflowMetadataHandler.Authorize`'s error construction in `workflow_metadata_handler.go`, which could not be completed in this session; a Devin session with full repository access should inspect that function to determine the precise strings that would be exposed.

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)

	if err != nil {

		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) handleUserError(ctx context.Context, requestID string, code int64, message string, callback handlers.Callback) {
	switch code {
	case jsonrpc.ErrInternal, jsonrpc.ErrServerOverloaded, jsonrpc.ErrUnknown, jsonrpc.ErrLimitExceeded, jsonrpc.ErrConflict:
		h.lggr.Errorw("returning error to user", "code", code, "message", message, "requestID", requestID)
	default:
		h.lggr.Warnw("returning error to user", "code", code, "message", message, "requestID", requestID)
	}
	resp := &jsonrpc.Response[json.RawMessage]{
		Version: "2.0",
		ID:      requestID,
		Error: &jsonrpc.WireError{
			Code:    code,
			Message: message,
		},
	}
	rawResp, err := json.Marshal(resp)
	if err != nil {
		h.lggr.Errorw("failed to marshal error response", "err", err, "requestID", requestID)
		return
	}
	errorCode := api.FromJSONRPCErrorCode(code)
	h.metrics.IncrementRequestErrors(ctx, code, h.lggr)
	err = callback.SendResponse(handlers.UserCallbackPayload{
		RawResponse: rawResp,
		ErrorCode:   errorCode,
	})
	if err != nil {
		h.lggr.Errorw("failed to send user callback", "err", err, "requestID", requestID)
		return
	}
}

func (c *Callback) SendResponse(payload handlers.UserCallbackPayload) error {
	if !c.sent.CompareAndSwap(false, true) {
		return errors.New("response already sent: each callback can only be used once")
	}
	// The channel is initialized with a buffer size of 1,
	// so this send will not block.
	c.ch <- payload
	return nil
}
