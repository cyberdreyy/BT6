### Title
Distinguishable error messages in `HandleUserTriggerRequest` allow unauthenticated workflow-ID enumeration - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Finding Description
`HandleUserTriggerRequest` performs workflow resolution (`resolveWorkflowID`) strictly before authorization (`authorizeRequest`), and each failure path calls `handleUserError` with a distinct, information-revealing message that is sent straight back to the caller via `callback.SendResponse`:

- Unknown `workflowID`: `"Workflow not found. 'workflowID' %s is not a valid workflow ID"` [1](#0-0) 
- Unknown owner/name/tag combo: the generic `"Workflow not found. Provide either a valid 'workflowID'..."` [2](#0-1) 
- Known `workflowID` but unauthorized signer: `"Auth failure: " + err.Error()`, where the underlying error from `WorkflowMetadataHandler.Authorize` is `"signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition"` [3](#0-2) [4](#0-3) 

Because `resolveWorkflowID` runs before `authorizeRequest`, and `Authorize()` (`utils.VerifyRequestJWT`) accepts any syntactically valid, self-signed JWT (the signer does not need to be pre-registered — it is merely ECDSA-recovered from the signature), an attacker with no credentials can craft a trivial self-signed JWT and only needs to vary `WorkflowID` to distinguish "workflow does not exist" from "workflow exists but this key is unauthorized," purely by comparing the returned `ErrorMessage` text. This provides an oracle to enumerate active/valid `workflowID` values on the gateway before any authorization succeeds.

### Impact Explanation
This is a pre-authorization information-disclosure/enumeration issue: an unauthenticated caller can determine which `workflowID` values are currently registered and assigned to shards on the gateway, without needing to be an authorized signer for any of them. It does not by itself expose secrets, keys, or allow execution, and it does not enable unauthorized job execution or fund movement — the impact is limited to confirming the existence of tenant workflow identifiers (which are also opaque hashes derived from owner/name/tag, so this at most confirms a specific ID/owner/name/tag combination is live, not that it exposes execution results or private data).

### Likelihood Explanation
Trivially reachable and repeatable: any caller able to reach the gateway JSON-RPC HTTP-trigger endpoint can send `workflows.execute` requests with an `Auth` field containing any self-signed JWT and vary `WorkflowID`/`WorkflowOwner`/`WorkflowName`/`WorkflowTag`, then diff the `ErrorMessage` strings returned. No special role, registered key, or prior authorization is required — only a syntactically valid JWT signature (self-generated).

### Recommendation
Return a single, generic, indistinguishable error (same code and message, e.g., `"workflow not found or not authorized"`) for both the "workflow not found" and "unauthorized signer" cases in `resolveWorkflowID`/`authorizeRequest`, and avoid echoing the caller-supplied `workflowID` or the underlying `Authorize()` error text back to the client. Perform authorization/lookup in constant-message form so no branch reveals whether the identifier exists.

### Proof of Concept
Table-driven test in `http_trigger_handler_test.go`:
1. Case A: `WorkflowID` = random unregistered hex → expect `handleUserError`/`callback.SendResponse` invoked with message containing `"Workflow not found"`.
2. Case B: `WorkflowID` = a real, registered workflow ID (seeded into `workflowMetadataHandler`), `Auth` = self-signed JWT from an arbitrary, non-registered EOA key → expect message containing `"Auth failure: signer ... is not authorized"`.
3. Assert the two `ErrorMessage` strings (and any code/format differences) are distinguishable, proving the oracle: `require.NotEqual(t, respA.Error.Message, respB.Error.Message)` and specifically that case B message differs from "not found" wording, confirming existence can be inferred purely from error text without ever supplying an authorized key.

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
