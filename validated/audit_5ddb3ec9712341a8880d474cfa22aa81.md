### Title
`lending_pool_handle_bankruptcy` performs an unconditional zero-amount SPL transfer, permanently blocking bankruptcy resolution for banks with revert-on-zero-transfer tokens - ([File: programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs])

### Summary
`lending_pool_handle_bankruptcy` computes `covered_by_insurance` as `min(bad_debt, available_insurance_fund)` and then unconditionally calls `bank.withdraw_spl_transfer(...)` with that (rounded) amount from the insurance vault to the liquidity vault, without ever checking that the amount is non-zero. Whenever the insurance vault has no funds (a very common precondition for bankruptcy — bankruptcy typically fires precisely because a bank was under-insured), `covered_by_insurance_rounded_up` is `0`, and the transfer call is still executed with `amount = 0`. This is structurally the same defect as the reported Cozy `Backstop.claim()` issue: a `safeTransfer`/token-transfer call that is not gated by `amount > 0`.

### Finding Description [1](#0-0) 
computes the insurance coverage as `min(bad_debt, available_insurance_fund)`, which is `0` whenever the insurance vault balance is `0`. [2](#0-1) 
then calls `bank.withdraw_spl_transfer(insurance_coverage_deposit_pre_fee, ...)` unconditionally — there is no `if insurance_coverage_deposit_pre_fee > 0` guard, unlike the fix requested for the analogous `Backstop.claim()` report.

`withdraw_spl_transfer` itself performs no zero-amount short-circuit either; it always invokes either `invoke_client_token_transfer` or `spl_token_2022::onchain::invoke_transfer_checked`/`transfer`: [3](#0-2) 

marginfi explicitly supports Token-2022 mints with transfer-hook extensions elsewhere in the codebase — the presence of a bundled `test_transfer_hook` program and the explicit `has_transfer_hook` check in `lending_pool_emissions_deposit` demonstrate that the protocol is aware that transfer-hook-bearing mints can be bank mints and that such hooks can impose arbitrary transfer-time constraints: [4](#0-3) 

Unlike `lending_pool_emissions_deposit`, which defensively rejects mints with active transfer hooks before transferring, `lending_pool_handle_bankruptcy` (and other unconditional `withdraw_spl_transfer` call sites such as `lending_pool_collect_bank_fees` and `lending_account_liquidate`'s insurance-fee transfer) has no equivalent protection. If the bank's mint uses a Token-2022 transfer hook (or any transfer-fee/extension logic) that reverts on a zero-amount transfer, the `handle_bankruptcy` instruction will always fail whenever the insurance vault is empty for that bank — which is the ordinary, expected condition under which bankruptcy resolution is invoked.

### Impact Explanation
`handle_bankruptcy` is the only mechanism to resolve bad debt on a bankrupt account (per `guides/RISK_AND_LIQUIDATORS/BANKRUPTCY.md`): if it doesn't run, "remaining depositors can never withdraw the whole balance in the bank." If a bank's mint reverts on zero-value transfers, bankruptcy resolution becomes permanently unavailable whenever the insurance fund balance is zero (the common case that triggers bankruptcy in the first place), because the instruction will always attempt and fail on a zero-amount transfer. This creates a durable freeze: bad debt can never be socialized or written off, and the bank's remaining depositors permanently cannot withdraw their full balances, exactly analogous to the reported inability to call `Set.updateMarketState(MarketState.TRIGGERED)`.

### Likelihood Explanation
Reaching this state requires only that (a) the bank's mint is a token type whose transfer path reverts on `amount == 0` (a documented Token-2022 extension behavior category the marginfi codebase itself accounts for elsewhere), and (b) the insurance vault has zero balance at the time bankruptcy is called — which is the default/likely condition for any pool that has not been pre-funded with insurance, or one where insurance has already been drained by an earlier bankruptcy event. `handle_bankruptcy` can be called permissionlessly when `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set, and is otherwise called by admin/risk_admin as ordinary operational maintenance, not a privileged/unusual action — so this is a realistic operational deadlock rather than a purely theoretical scenario.

### Recommendation
Guard every `withdraw_spl_transfer` invocation (in `handle_bankruptcy.rs`, `collect_bank_fees.rs`, and the insurance-fee transfer in `liquidate.rs`) with an `if amount > 0 { ... }` check, mirroring the fix pattern from the referenced Cozy `Backstop.claim()` remediation, so that zero-value transfers are skipped rather than attempted.

### Proof of Concept
1. Create a bank whose mint is a Token-2022 mint with a transfer-hook program that reverts when the transfer `amount` is `0` (this is exactly the class of token supported per `has_transfer_hook`/`test_transfer_hook` in the repo).
2. Do not fund (or fully drain) that bank's insurance vault.
3. Cause a user to go bankrupt (borrow, then liquidate down to zero collateral) as in the existing `bankruptcy.rs` test flow.
4. Call `lending_pool_handle_bankruptcy`: `available_insurance_fund` is `0`, so `covered_by_insurance_rounded_up == 0`, and `bank.withdraw_spl_transfer(0, insurance_vault, liquidity_vault, ...)` is invoked at [5](#0-4) 
which triggers the mint's transfer hook with `amount = 0`, causing the hook program to revert and the entire `handle_bankruptcy` transaction to fail every time it is retried, permanently blocking bad-debt resolution for that account/bank.

    fn withdraw_spl_transfer<'info>(
        &self,
        amount: u64,
        from: AccountInfo<'info>,
        to: AccountInfo<'info>,
        authority: AccountInfo<'info>,
        maybe_mint: Option<&InterfaceAccount<'info, Mint>>,
        program: AccountInfo<'info>,
        signer_seeds: &[&[&[u8]]],
        remaining_accounts: &[AccountInfo<'info>],
    ) -> MarginfiResult {
        debug!(
            "withdraw_spl_transfer: amount: {} from {} to {}, auth {}",
            amount, from.key, to.key, authority.key
        );

        #[cfg(feature = "client")]
        if let Some(mint) = maybe_mint {
            invoke_client_token_transfer(
                program.key,
                amount,
                from,
                Some(mint.to_account_info()),
                to,
                authority,
                Some(mint.decimals),
                remaining_accounts,
                signer_seeds,
            )?;
        } else {
            // `transfer_checked` and `transfer` does the same thing, the additional `_checked` logic
            // is only to assert the expected attributes by the user (mint, decimal scaling),
            //
            // Security of `transfer` is equal to `transfer_checked`.
            invoke_client_token_transfer(
                program.key,
                amount,
                from,
                None,
                to,
                authority,
                None,
                remaining_accounts,
                signer_seeds,
            )?;
        }

        #[cfg(not(feature = "client"))]
        if let Some(mint) = maybe_mint {
            spl_token_2022::onchain::invoke_transfer_checked(
                program.key,
                from,
                mint.to_account_info(),
                to,
                authority,
                remaining_accounts,
                amount,
                mint.decimals,
                signer_seeds,
            )?;
        } else {
            // `transfer_checked` and `transfer` does the same thing, the additional `_checked` logic
            // is only to assert the expected attributes by the user (mint, decimal scaling),
            //
            // Security of `transfer` is equal to `transfer_checked`.
            #[allow(deprecated)]
            transfer(
                CpiContext::new_with_signer(
                    program.key(),
                    Transfer {
                        from,
                        to,
                        authority,
                    },
                    signer_seeds,
                ),
                amount,
            )?;
        }

        Ok(())
    }
