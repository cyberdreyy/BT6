### Title
Reward-cycle slot collision in `stacks_signers` can silently destroy a stale-but-still-live `Signer` instance before it finishes a pending validation/pre-commit - ([File: stacks-signer/src/runloop.rs])

### Summary
`RunLoop` keeps only two live `Signer` instances at a time, indexed by `reward_cycle % 2` [1](#0-0) . When the burn chain advances into a new reward cycle, `refresh_signer_config` unconditionally overwrites whatever `ConfiguredSigner` currently occupies that parity slot with a brand-new `Signer::new(...)` [2](#0-1) , and `cleanup_stale_signers` is only supposed to remove a signer whose cycle has ended once it has no unprocessed blocks left [3](#0-2) . Because the slot key is `reward_cycle % 2`, a signer for cycle `N` and a signer for cycle `N+2` collide on the same slot. If cycle `N`'s signer still has an outstanding, unresolved block (e.g. still waiting on a `BlockValidationResponse`, or `PreCommitted` and waiting for the 70% threshold) when cycle `N+2` starts, `refresh_signer_config` will replace it anyway, because the overwrite check (`is_configured_for_cycle`) only asks "is the slot's signer at the current cycle," not "does the stale slot still have unfinished work." This mirrors the `[M-08]` "updating boost periods" bug class: mutating a piece of retained/index-keyed state that a not-yet-finished claim/vote depends on causes that in-flight work to be discarded.

### Finding Description
`stacks_signers: HashMap<u64, ConfiguredSigner<Signer, T>>` is keyed by `reward_cycle % 2`, giving only two slots for the entire history of reward cycles [1](#0-0) .

On every burn-block refresh, `refresh_runloop`:
1. Refreshes `current_reward_cycle_info` for the new burn height.
2. Calls `refresh_signer_config(current_reward_cycle)` if the slot for that cycle isn't already configured for exactly that cycle.
3. Only afterward calls `cleanup_stale_signers(current_reward_cycle)` to prune anything whose cycle is now behind `current_reward_cycle` **and** has no unprocessed blocks left [4](#0-3) .

`refresh_signer_config` performs an unconditional `self.stacks_signers.insert(reward_index, new_signer_config)` [5](#0-4) , which drops the previous `ConfiguredSigner` value (and the live `Signer` object inside it) regardless of whether that prior signer still has unresolved blocks. The guard used to decide *whether* to call `refresh_signer_config` — `is_configured_for_cycle` — only checks that the slot's stored `reward_cycle()` equals the *target* reward cycle [6](#0-5) ; it has no notion of "is the occupant of this slot still doing important work for an older cycle."

Two reward cycles have the same parity (`N` and `N+2`). If, when cycle `N+2` starts, the signer for cycle `N` is still sitting in the `N % 2` slot because `cleanup_stale_signers` correctly refused to evict it (its `has_unprocessed_blocks()` was still `true` when cycle `N+1` began, so cleanup at that point left it alone — `cleanup_stale_signers` only fires when `reward_cycle < current_reward_cycle`, i.e., is a no-op at cycle `N+1` for a signer that is `N+1`'s predecessor but had residual work; the slot for `N` is preserved because it isn't the one being written at cycle `N+1`), then the subsequent `refresh_signer_config(N+2)` call will `insert` at the same slot index (`N % 2 == (N+2) % 2`) and silently replace that `Signer` — including its in-memory `submitted_block_proposal` (an in-flight validation request to the node) and any queued/pending proposals — with a fresh `Signer::new()` for cycle `N+2`.

Because the runloop's event dispatch only iterates `self.stacks_signers.values_mut()` [7](#0-6) , once the old `Signer` for cycle `N` is gone there is no longer any object registered to receive a delayed `BlockValidationResponse` for that block, nor to re-broadcast a pre-commit, nor to eventually sign once the pre-commit threshold is reached. The block's fate (in signer terms) is orphaned mid-flight — the exact "in-progress claim discarded by an index/state update" pattern the external report describes for boost-period updates.

### Impact Explanation
This is a liveness wedge, not a value-loss bug: a signer that had already validated and pre-committed to a block (or was waiting on the node's validation verdict) for a stale reward cycle can be dropped from memory before its participation in that block's threshold is resolved. If that signer's vote/signature was needed to reach 70% weight (or to correctly apply the own-tenure/height conflict checks in `handle_block_pre_commit`), the signer is wedged into never completing that action, which the scan rules explicitly classify as High severity ("a signer wedged into never signing valid blocks").

### Likelihood Explanation
Low. It requires an unusually long-lived unresolved block (one that survives an entire extra reward cycle transition without being globally accepted/rejected and without `has_unprocessed_blocks()` becoming false), which is an edge case dependent on a stalling miner/tenure rather than something trivially triggered by a single proposal. It does not require a signer majority, another signer's key, or any privileged access — only sustained non-finalization of a block across cycle boundaries, which a misbehaving or unlucky miner/tenure could produce over time.

### Recommendation
`refresh_signer_config`/`cleanup_stale_signers` should not allow a slot overwrite to destroy a `ConfiguredSigner::RegisteredSigner` that still reports `has_unprocessed_blocks() == true`. Before inserting a new signer into a `reward_cycle % 2` slot, check whether the occupant still has unresolved work; if so, either delay activation of the new cycle's signer in that slot (analogous to the report's "grace period" suggestion) or track/migrate the stale signer's outstanding validation/pre-commit state independently so it can still be completed after the overwrite (analogous to the report's "track old boost periods independently" suggestion).

### Proof of Concept
1. Signer is configured and registered for reward cycle `N`, occupying slot `N % 2`.
2. A block proposal for cycle `N` is validated and reaches `PreCommitted` (or is still awaiting `BlockValidationResponse`), but never crosses the 70% pre-commit threshold and is never globally rejected (e.g., a stalling miner keeps proposing rival blocks at the same height so no side reaches quorum) — `has_unprocessed_blocks()` remains `true`.
3. The burn chain advances through cycle `N+1`; `cleanup_stale_signers(N+1)` runs but the cycle-`N` signer is not evicted because it still has unprocessed blocks (`stacks-signer/src/runloop.rs:480-490`).
4. The burn chain advances into cycle `N+2`. `refresh_signer_config(N+2)` computes `reward_index = (N+2) % 2 == N % 2` and unconditionally `insert`s a fresh `Signer::new()` at that slot (`stacks-signer/src/runloop.rs:342-362`), discarding the cycle-`N` `Signer` object and its outstanding `submitted_block_proposal`/pending proposal state.
5. Any subsequent `BlockValidationResponse` or `BlockPreCommit` gossip for the orphaned cycle-`N` block is no longer routed to any live `Signer` instance in `self.stacks_signers` (`stacks-signer/src/runloop.rs:596-609`), so that signer can never complete signing the block it had already committed to.

                warn!("Signer is not registered for reward cycle {reward_cycle}");
                ConfiguredSigner::not_registered(reward_cycle)

                return;
            }
        };

    fn cleanup_stale_signers(&mut self, current_reward_cycle: u64) {
        #[cfg(any(test, feature = "testing"))]
        if TEST_SKIP_SIGNER_CLEANUP.get() {
            warn!("Skipping signer cleanup due to testing directive.");
            return;
        }
        let mut to_delete = Vec::new();
        for (idx, signer) in &mut self.stacks_signers {
            let reward_cycle = signer.reward_cycle();
            if reward_cycle >= current_reward_cycle {
                // We are either the current or a future reward cycle, so we are not stale.
                continue;
            }
            match signer {
                ConfiguredSigner::RegisteredSigner(signer) => {
                    if !signer.has_unprocessed_blocks() {
                        debug!("{signer}: Signer's tenure has completed.");
                        to_delete.push(*idx);
                    }
                }
                ConfiguredSigner::NotRegistered { .. } => {
                    debug!("{signer}: Unregistered signer's tenure has completed.");
                    to_delete.push(*idx);
                }
            }
        }
        for idx in to_delete {
            self.stacks_signers.remove(&idx);
        }
    }
