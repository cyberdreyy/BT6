### Title
Unauthenticated pprof profile/heap/goroutine dump exposure of internal LOOP plugin processes via `pluginPPROFHandler` - (core/web/loop_registry.go, core/web/router.go)

### Summary
`loopRoutes` registers `GET /plugins/:name/debug/pprof/*profile` directly on the unauthenticated `api` router group, with no `auth.Authenticate` wrapper, unlike every other sensitive route (sessions, v2 API, and even the node's own pprof `metricRoutes`, which is explicitly gated behind `authv2`). This lets any unauthenticated network client reach `LoopRegistryServer.pluginPPROFHandler`, which proxies the request straight through to the named LOOP plugin's internal `/debug/pprof/*` endpoint and returns the raw response.

### Finding Description
`loopRoutes` is registered on `api` in `NewRouter` without any auth middleware: [1](#0-0) 
compared to `metricRoutes(authv2)`, which is intentionally placed inside the authenticated `v2Routes` group with the comment "Debug routes accessible via authentication": [2](#0-1) 

The route itself is defined with no auth group wrapper at all: [3](#0-2) 

`pluginPPROFHandler` takes the `:name` and `*profile` path params directly from the unauthenticated request, resolves the plugin from the registry, builds a URL to the plugin's internal prometheus/pprof port, and forwards the client's query params (`debug`, `gc`, `seconds`) before relaying the response body and a `StatusOK` back to the caller: [4](#0-3) [5](#0-4) 

No authentication, session, token, or role check occurs anywhere on this path — `sessionRoutes`, `debugRoutes`, and the sensitive parts of `v2Routes` all explicitly wrap their groups with `auth.Authenticate(...)` or `auth.RequiresXRole(...)`, but `loopRoutes` does not.

### Impact Explanation
An unauthenticated network client that can reach the node's main HTTP API port can pull live heap/goroutine/CPU/allocs profiles from any registered LOOP plugin process (e.g. a median/mercury/OCR plugin) by hitting `GET /plugins/<name>/debug/pprof/heap` etc. This is an information disclosure vulnerability: pprof heap/goroutine dumps can leak in-process memory contents, potentially including sensitive material handled by the plugin (config values, buffers, in-flight report data), and goroutine/CPU profiles reveal internal state, code paths, and possibly stack traces useful for further attacks. This matches the "sensitive data exposure" / unauthenticated information disclosure impact class.

### Likelihood Explanation
No credentials, session, token, or role of any kind are required — a fully unauthenticated attacker who can send an HTTP GET to the node's API endpoint can trigger this repeatedly and at will. The only precondition is that the target node has one or more LOOP plugins registered (`app.GetLoopRegistry()`), which is standard for LOOP-based OCR2/Mercury/etc. plugin deployments. This is trivially and repeatably exploitable.

### Recommendation
Wrap `loopRoutes`'s pprof-related endpoints (`/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol`) — and ideally the `/plugins/:name/metrics` and `/discovery` endpoints as well — with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or admin-role) middleware used for `debugRoutes` and `metricRoutes`, so they require an authenticated admin session/token like the node's own pprof endpoints do.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/loop_registry_test.go`):
1. Start `cltest.NewApplicationWithConfigAndKey` as in `TestLoopRegistry`, register a mock LOOP plugin via `app.GetLoopRegistry().Register(...)`, and start a mock pprof-serving HTTP listener on the plugin's `EnvCfg.PrometheusPort` (reusing the `mockLoopImpl` pattern).
2. Build a raw `http.Client` (not `app.NewHTTPClient`, which attaches a session) and issue `GET /plugins/mockLoopImpl/debug/pprof/heap` with no `Authorization` header/cookie.
3. Assert the response status is `http.StatusOK` (or matches the mock's response) rather than `http.StatusUnauthorized`/`http.StatusForbidden`, proving the endpoint is reachable without authentication.
4. As a control, assert that hitting an equivalent authenticated endpoint (e.g. `/v2/debug/pprof/heap` under `metricRoutes(authv2)`) without credentials correctly returns `401`, demonstrating the inconsistency between the two pprof exposure paths.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
