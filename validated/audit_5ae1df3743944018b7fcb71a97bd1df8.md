### Title
Unauthenticated access to LOOP plugin pprof symbol proxy endpoint - ([File: core/web/loop_registry.go])

### Summary
The route `POST /plugins/:name/debug/pprof/symbol` is registered directly on the top-level `api` group without any authentication middleware, unlike the analogous `/debug/pprof/*` routes which are wrapped in `authv2` (requiring session/token auth). Its handler, `LoopRegistryServer.pluginPPROFPOSTSymbolHandler`, performs no auth check itself and simply forwards attacker-supplied request bytes to the internal LOOP plugin's `/debug/pprof/symbol` endpoint, returning the proxied response verbatim.

### Finding Description
In `core/web/router.go`, `loopRoutes` registers the LOOP-related endpoints on the bare `api` group: [1](#0-0) 
Unlike `debugRoutes` (`/debug/vars`, wrapped with `auth.Authenticate(...)`) and `metricRoutes` (`/debug/pprof/*`, only mounted inside the authenticated `authv2` group at line 446), the `loopRoutes` group has no `auth.Authenticate` middleware attached at all — only the outer `api` group's session-cookie middleware (`sessions.Sessions`) and rate limiter, neither of which reject unauthenticated requests.

`pluginPPROFPOSTSymbolHandler` itself contains no authentication or authorization check: [2](#0-1) 
It reads the raw POST body from `gc.Request.Body`, forwards it via `doRequest` to `http://<loopHostName>:<PrometheusPort>/debug/pprof/symbol`, and writes the plugin's response back with `gc.Data(http.StatusOK, "text/plain", b)`. There is no session/token validation anywhere in this call chain, so any network client that can reach the node's HTTP API can hit this route.

This is corroborated by `core/web/loop_registry_test.go`, where `/plugins/mockLoopImpl/metrics` (a sibling route on the same unauthenticated group) is successfully requested with a plain `app.NewHTTPClient(nil)` (no credentials), confirming the group is reachable without authentication.

### Impact Explanation
An unauthenticated remote attacker can invoke an internal debug/profiling proxy (`pprof symbol` resolution) against the node's LOOP plugin processes, and, more broadly, all loop-registry endpoints (`/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*`, `/plugins/:name/debug/pprof/symbol`) are exposed without authentication. This maps to Chainlink's "authentication bypass on non-public HTTP endpoint" bounty class: it discloses internal service topology/symbol data and provides an unauthenticated pivot into an internal-only surface (pprof `debug/pprof/symbol`, `debug/pprof/profile`, etc.) that was clearly intended to be behind node authentication, consistent with how the equivalent core node pprof endpoints (`metricRoutes`) are locked behind `authv2`.

### Likelihood Explanation
No credentials, session, or API token are required — only network reachability to the node's web server port. The endpoint is reachable as long as at least one LOOP plugin is registered (`l.registry.Get(pluginName)` must succeed), which is standard for OCR2/median/other LOOPp deployments. This is trivially and repeatably exploitable with a single unauthenticated HTTP POST.

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`/`metricRoutes`, so pprof/debug data can only be retrieved by authenticated node users, consistent with how core pprof endpoints are protected.

### Proof of Concept
Go handler-level integration test plan (extending `core/web/loop_registry_test.go`):
1. Start the app as in `TestLoopRegistry`, register a mock LOOP plugin (`mockLoopImpl`) exposing a pprof-compatible endpoint on `loop.EnvCfg.PrometheusPort`.
2. Using an **unauthenticated** raw `http.Client` (not `app.NewHTTPClient` with session, but a bare client with no cookie jar and no `Authorization` header) issue:
   `POST /plugins/mockLoopImpl/debug/pprof/symbol` with body `"0x1234\n"`.
3. Assert:
   - Response status is `200 OK` (not `401 Unauthorized` / `403 Forbidden`).
   - Response body contains data proxied from the mock plugin's pprof symbol handler (e.g., expected `num_symbols: ...` or resolved symbol text), proving the request reached and returned data from the internal plugin without any credential.
4. Repeat for `GET /plugins/mockLoopImpl/debug/pprof/heap` to show the sibling route is equally unauthenticated, confirming the whole `loopRoutes` group lacks auth middleware.

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
