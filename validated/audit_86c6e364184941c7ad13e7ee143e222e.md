### Title
Incorrect rounding direction in `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` allows a signer to declare false "70%" global-state consensus below the true supermajority threshold - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority threshold using floor division, while the canonical on-chain block-approval threshold `NakamotoBlockHeader::compute_voting_weight_threshold` explicitly rounds the same 70% threshold **up** (ceiling). The two computations are meant to represent the identical "NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7/10" supermajority, but the local state-machine agreement check uses the weaker (lower) bound.

### Finding Description
The canonical, consensus-critical threshold used when actually counting signatures on a Nakamoto block is: [1](#0-0) 

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil).map_err(...)
}
```
This rounds `total_weight * 7 / 10` **up** whenever it isn't exact, i.e. it always requires *at least* 70% of weight — the strict, "safe" direction.

`GlobalStateEvaluator::reached_agreement`, used by the signer's local/global state machine to decide when signers have reached global agreement on the active protocol version, the burn view, the active miner, and the tx-replay set, computes the *same nominal 70% threshold* with plain floor division and no ceiling correction: [2](#0-1) 

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}

pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
            / 10
}
```
For any `total_weight` where `total_weight * 7` is not a multiple of 10 (the common case), `reached_agreement`'s floor-divided threshold is strictly *lower* than `compute_voting_weight_threshold`'s ceiling-divided threshold. For example, with `total_weight = 15`: `compute_voting_weight_threshold(15) = ceil(105/10) = 11` (73.3%), while `reached_agreement` accepts any `vote_weight >= floor(105/10) = 10` (66.7%) as having "reached agreement." This is the exact same bug class as the audited DEX flaw: two code paths compute what should be the same rounding boundary, but one path silently rounds in the direction that makes the threshold easier to satisfy, benefiting whichever side profits from a looser bar.

`reached_agreement` gates `determine_global_state`, which fixes the signer's view of the canonical `current_miner`, `burn_block`/`burn_block_height`, and `tx_replay_set`: [3](#0-2) 

That state feeds directly into block-proposal validation in `GlobalStateView::check_proposal`, which trusts `signer_state.current_miner`/`tenure_id` as authoritative when deciding whether a proposed block's miner/tenure is legitimate: [4](#0-3) 

Because `reached_agreement` can lock in a "global" miner/burn-view/tx-replay state with only ~66.7%–70% weight (below the real 70% supermajority the chain itself requires for a block to be accepted), a signer's local state machine can settle on a state that does not actually reflect the reward set's true supermajority. This can cause the signer to treat a given tenure/miner as the consensus-approved active miner and validate/pre-commit/sign a proposal from it, even though the equivalent weight would fail the strict `compute_voting_weight_threshold` check used for real block-signature counting elsewhere in the same codebase (e.g. `verify_signer_signatures`, `store_and_process_block_signature`, `handle_block_pre_commit` all use the ceiling-based threshold consistently): [5](#0-4) [6](#0-5) 

This mirrors the report's root cause precisely: an internal computation that is supposed to mirror a strict, protocol-defined supermajority instead rounds toward the weaker outcome, creating an exploitable equality mismatch between "true 70% consensus" (used to actually sign/accept blocks) and "declared agreement" (used to steer the signer's own state machine).

### Impact Explanation
A minority coalition holding between `floor(0.7*W)` and `ceil(0.7*W)` weight — strictly less than the true 70% supermajority — can push their `StateMachineUpdate` broadcasts (miner/tenure view, burn view, tx replay set, protocol version) to be accepted by `GlobalStateEvaluator::determine_global_state` on every other signer as the "global" consensus state. Signers then use this understated-threshold state to validate/accept block proposals in `GlobalStateView::check_proposal`, effectively basing chain-safety decisions (which miner/tenure is canonical, what tx-replay set is in force) on a weaker-than-required threshold. This matches the "acting on a stale/under-verified threshold" and, via cascading effects into `check_proposal`, "signing a non-canonical block" impact classes.

### Likelihood Explanation
No majority of signers, no key compromise, and no auth-token access are required — only a normal minority weight distribution such that `total_weight * 7` is not an exact multiple of 10 (the typical case for real reward-set weight totals) and that minority broadcasting a `StateMachineUpdate` consistent with its own view. This is directly reachable via ordinary gossip/StackerDB traffic that any signer set participant can produce.

### Recommendation
Make `reached_agreement`/`reached_disagreement` use the exact same ceiling semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (or call that function directly) so the "70% global agreement" bound used by the signer state machine never falls below the true on-chain supermajority threshold.

### Proof of Concept
For `total_weight = 15` (e.g. weights `[8,7]`):
- `compute_voting_weight_threshold(15)` → `ceil(15*7/10) = ceil(10.5) = 11` (true 73.3% threshold).
- `GlobalStateEvaluator::reached_agreement(10)` → `10 >= floor(15*7/10) = 10` → `true`.

A weight-10 minority (66.7% of total) is accepted by `reached_agreement` as having reached global consensus on `current_miner`/burn view/tx-replay-set, even though the same weight would fail the real 70%-supermajority check (`10 < 11`) used everywhere else in the codebase for actual block-signature acceptance.
