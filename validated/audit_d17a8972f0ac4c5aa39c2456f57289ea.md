### Title
`SystemInstruction::InitializeNonceAccount` performs no signer/ownership check, letting any transaction seize authority over — and drain — a pre-funded, uninitialized nonce account - ([File: programs/system/src/system_instruction.rs])

### Summary
The reported bug (`BasePool.mint()` frontrunning) is a class of vulnerability where a permissionless "claim"/"finalize" instruction assigns control of previously deposited value to whoever calls it first, instead of to the party that actually deposited the value. The system program's `initialize_nonce_account` handler exhibits the same root cause: it sets the nonce authority to an arbitrary attacker-supplied pubkey without requiring any signature from the nonce account itself or from the intended owner, allowing an attacker to front-run the legitimate initialization of a funded nonce account and later drain it.

### Finding Description
`initialize_nonce_account` only checks that the target account is writable and that it is in `State::Uninitialized` with sufficient rent-exempt lamports; it never checks that the caller or the nonce account key is present in the transaction's signer set, and it never checks any relationship between the caller and the `nonce_authority` value supplied in the instruction data: [1](#0-0) 

The dispatcher in `system_processor.rs` likewise only verifies the number of accounts and the presence/format of the recent-blockhashes and rent sysvars before calling into `initialize_nonce_account` — it performs no signer check for account index 0 (the nonce account): [2](#0-1) 

Contrast this with sibling nonce instructions in the same file, which do require signer verification: `withdraw_nonce_account` calls `check_signer(&data.authority)` / `check_signer(from.get_key())` before moving lamports, and `authorize_nonce_account` requires the current authority (or account key) to be a transaction signer: [3](#0-2) [4](#0-3) 

`InitializeNonceAccount` is the odd one out: it is the instruction that first assigns the "owner" (authority) of value already held in the account, exactly analogous to `BasePool.mint()` assigning the NFT (and the underlying deposited assets) to whoever calls `mint()`, regardless of who actually deposited the assets.

An attacker who observes (via mempool/gossip or simply by scanning committed slots) any system-owned account that:
1. is in `Uninitialized` nonce state (freshly `CreateAccount`'d with `space` equal to the nonce account size, owner = system program), and
2. holds at least the rent-exempt minimum lamports for that size,

can submit a transaction naming that account as the writable "nonce account" and their own pubkey as `nonce_authority`. Because no signature tied to that account or to the original funder is required, the attacker's transaction — if it lands first — permanently sets them as the nonce authority.

### Impact Explanation
Once the attacker becomes the nonce authority, they can subsequently call `WithdrawNonceAccount`, which only requires `check_signer(&data.authority)` to move the full account balance to a destination of their choosing: [5](#0-4) 

This results in concrete, unsigned fund movement: lamports funded by the legitimate account creator (who intended to become the nonce authority) are seized and can be fully withdrawn by an unrelated attacker, with no signature from the original depositor ever required for the authority assignment step. This matches the "concrete unsigned fund movement" bar for a valid finding.

### Likelihood Explanation
Exploitability depends on there being a real-world gap between the `CreateAccount` transaction (which does require the new account's private key to sign, per `allocate`'s `address.is_signer` check) and a separate, later `InitializeNonceAccount` transaction. Any workflow, wallet, or program that creates a nonce account and initializes it in two separate transactions (e.g., pre-provisioning nonce accounts, funding-then-initializing flows, relayer/faucet patterns, or simple client bugs/multi-step UIs) creates this window. Even where the common client helper bundles both instructions atomically in one transaction, the protocol-level check is still missing entirely — the vulnerability is a property of the instruction handler itself, not of any particular client's usage pattern, so any code path that produces a funded, uninitialized, system-owned account of the correct size is at risk.

### Recommendation
Require that `InitializeNonceAccount` (and by extension `create_account`/`initialize_nonce_account` combos generally) verify a signer bound to the account or an explicit "initializer" authorization, mirroring the signer checks already present in `withdraw_nonce_account` and `authorize_nonce_account`. At minimum, require `signers.contains(account.get_key())` (i.e., the nonce account's own key must sign the initialize instruction), consistent with how `allocate`/`assign` already require `address.is_signer(signers)` for account creation in `system_processor.rs`.

### Proof of Concept
1. Victim submits transaction A: `SystemInstruction::CreateAccount { lamports: rent_exempt_min, space: NonceState::size(), owner: system_program::id() }` creating account `N` (signed by `N`'s keypair and the funder), intending to send a follow-up `InitializeNonceAccount` transaction.
2. Before the victim's follow-up transaction lands, attacker observes account `N` on-chain in `State::Uninitialized` with sufficient lamports and submits transaction B: `SystemInstruction::InitializeNonceAccount(attacker_pubkey)` with account `N` as the sole writable account (attacker does not need to sign as `N`, only needs `N` listed as writable) — see the accepted call path in `initialize_nonce_account`: [6](#0-5) 
3. Transaction B lands first; `N`'s nonce authority is now `attacker_pubkey`.
4. The victim's original `InitializeNonceAccount` transaction now fails (`State::Initialized(_)` branch returns `InstructionError::InvalidAccountData`), so the victim cannot recover.
5. Attacker submits `SystemInstruction::WithdrawNonceAccount(full_balance)` signed as `attacker_pubkey`, draining all lamports from `N` to an address they control, per the `check_signer(&data.authority)` path in `withdraw_nonce_account`.

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
}

pub(crate) fn initialize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    rent: &Rent,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Initialize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    match account.get_state::<Versions>()?.state() {
        State::Uninitialized => {
            let min_balance = rent.minimum_balance(account.get_data().len());
            if account.get_lamports() < min_balance {
                ic_msg!(
                    invoke_context,
                    "Initialize nonce account: insufficient lamports {}, need {}",
                    account.get_lamports(),
                    min_balance
                );
                return Err(InstructionError::InsufficientFunds);
            }
            let durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            let data = nonce::state::Data::new(
                *nonce_authority,
                durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            let state = State::Initialized(data);
            account.set_state(&Versions::new(state))
        }
        State::Initialized(_) => {
            ic_msg!(
                invoke_context,
                "Initialize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
    }
}

pub(crate) fn authorize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Authorize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }
    match account
        .get_state::<Versions>()?
        .authorize(signers, *nonce_authority)
    {
        Ok(versions) => account.set_state(&versions),
        Err(AuthorizeNonceError::Uninitialized) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
        Err(AuthorizeNonceError::MissingRequiredSignature(account_authority)) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} must sign",
                account_authority
            );
            Err(InstructionError::MissingRequiredSignature)
        }
    }
}
