### Title
Zip extraction allows symlink-then-write TOCTOU escaping the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFile` processes zip entries in archive order and dispatches symlink entries to `extractZipSymlinkEntry`, which creates a symlink at `file.Name` pointing to arbitrary, attacker-controlled link-target data with no validation. `extractZipFileEntry` then opens/writes subsequent entries via `os.OpenFile(file.Name, O_WRONLY|O_CREATE|O_TRUNC, ...)`, which follows any existing symlink at that path, allowing writes to be redirected outside the extraction root.

### Finding Description
`extractZipSymlinkEntry` reads the symlink target directly from the zip entry's file content and calls `os.Symlink(string(data), file.Name)` with no check that the target is within the extraction directory: [1](#0-0) 

`extractZipFile` dispatches each entry, including symlinks, in the order they appear in `archive.File` (preserving archive order, as noted in the question), and `ExtractZipArchive` iterates entries sequentially without reordering symlinks to be processed last: [2](#0-1) 

`extractZipFileEntry` removes any existing file/symlink at `file.Name` via `os.Remove` and then opens it with `O_WRONLY|O_CREATE|O_TRUNC`: [3](#0-2) 

Critically, `os.Remove(file.Name)` at line 50 removes the symlink itself (not its target) before `os.OpenFile` is called for a path where the parent directory component is itself a symlink. The described attack scenario is: entry `link` (type symlink, content `/tmp/outside` or `../../../secrets`) is extracted first, creating a symlink named `link`. Then entry `link/payload` is extracted — `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` for `link` (a no-op/error avoided because `link` already exists as a symlink to a directory), and `extractZipFileEntry` calls `os.OpenFile("link/payload", O_WRONLY|O_CREATE|O_TRUNC, ...)`. Since `link` is a symlink to `/tmp/outside`, the OS resolves `link/payload` to `/tmp/outside/payload`, and the write occurs outside the intended extraction root.

The only existing protections are `errorIfGitDirectory` (blocks `.git` paths only) and the `pathErrorTracker` (only suppresses repeated warning logs, not a security control): [4](#0-3) 
Neither checks symlink target values nor validates that `file.Name` combined with a preceding symlink stays within the extraction root. There is no code in `zip_extract.go` that resolves/validates `file.Name` against the destination directory (no `filepath.Clean`+prefix check, no `os.Lstat` check on parent components, no `filepath.EvalSymlinks` guard).

### Impact Explanation
An attacker who controls artifact ZIP content (e.g., a pipeline job producing artifacts uploaded to GitLab and later downloaded by `ArtifactsDownloaderCommand`, or a similarly-extracted cache/archive) can write arbitrary content to arbitrary paths on the runner host/executor filesystem outside the intended artifact/build extraction root, limited only by the permissions of the runner process. This matches the scoped impact: unauthorized file write outside artifact/build root via symlink-then-write TOCTOU.

### Likelihood Explanation
The attacker only needs to control the contents of an artifact/cache ZIP archive that GitLab Runner extracts — this is entirely within an unprivileged pipeline author's control (e.g., crafting a job that produces a malicious artifact ZIP, or if artifacts/caches from one job are consumed and extracted by another job/stage). The extraction path (`archive/zip` → `ExtractZipArchive` → `extractZipFile` → `extractZipSymlinkEntry`/`extractZipFileEntry`) is reached via `commands/helpers/artifacts_downloader.go`'s `Execute` → `archive.NewExtractor(format, ...)` → `Extract`, which is a standard, always-executed part of artifact download handling. It is reliably reproducible: crafting the exact order (`link` then `link/payload`) is deterministic since zip entry order is preserved.

### Recommendation
Before creating a symlink in `extractZipSymlinkEntry`, validate that the resolved absolute target stays within the destination root, and reject/skip symlink entries whose target escapes the extraction directory. Additionally, before extracting any entry (file, dir, or symlink) in `extractZipFile`/`extractZipFileEntry`, verify that no path component of `file.Name` is (or resolves through) a symlink pointing outside the extraction root — e.g., using `filepath.EvalSymlinks` on `filepath.Dir(file.Name)` and confirming the result has the destination root as a prefix, or by extracting into a temp location and validating before renaming into place. Symlink entries should also be deferred to the end of extraction (as already done for tarzstd) as a defense-in-depth measure, though the primary fix must be target-path validation.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipFileSymlinkEscape(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        outsideDir := t.TempDir() // simulate a directory outside the extraction root
        f, err := os.Create(fileName)
        require.NoError(t, err)
        defer f.Close()

        archive := zip.NewWriter(f)
        // Create a symlink entry named "link" pointing outside the workspace
        symHeader := &zip.FileHeader{Name: "link"}
        symHeader.SetMode(os.ModeSymlink | 0o777)
        w, err := archive.CreateHeader(symHeader)
        require.NoError(t, err)
        _, err = w.Write([]byte(outsideDir))
        require.NoError(t, err)

        // Create a regular file entry "link/payload" that will follow the symlink
        payload, err := archive.Create("link/payload")
        require.NoError(t, err)
        _, err = payload.Write([]byte("PWNED"))
        require.NoError(t, err)
        require.NoError(t, archive.Close())
        f.Close()

        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Assert the payload did NOT escape into outsideDir
        _, err = os.Stat(filepath.Join(outsideDir, "payload"))
        assert.True(t, os.IsNotExist(err), "payload should not have been written outside the extraction root via symlink")
    })
}
```
Expected result on the current code: the assertion fails (payload is found in `outsideDir`), proving the escape; after applying the recommended fix, the assertion passes.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
