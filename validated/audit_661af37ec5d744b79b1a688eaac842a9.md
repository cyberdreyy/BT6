### Title
Path traversal in artifact metadata filename allows writing files outside the job working directory - ([File: commands/helpers/artifact_metadata.go])

### Summary
`(g *artifactStatementGenerator).generateStatementToFile` builds the metadata output path with `filepath.Join(opts.artifactsWd, fmt.Sprintf(artifactsStatementFormat, opts.artifactName))` using the raw, unsanitized `opts.artifactName`, which is populated directly from `ArtifactsUploaderCommand.Name` (the `--name`/`artifacts:name` job value, shell-expanded in `normalizeArgs`). Unlike the actual archive filename construction in `artifactFilename` (which calls `filepath.Base(name)`), this code path performs no `filepath.Base`/containment check before `os.WriteFile`, so a crafted name containing `../` sequences causes the JSON file to be written outside the job's working directory before any later validation occurs.

### Finding Description
The flow is: `.gitlab-ci.yml` `artifacts.name` → `ArtifactsUploaderCommand.Name` → `normalizeArgs()` expands it via `shell.Expand` [1](#0-0)  → `Execute()` passes `c.Name` unmodified as `artifactName` into `generateStatementOptions` [2](#0-1)  → `generateStatementToFile` joins it into a path and writes it with `os.WriteFile` [3](#0-2) .

Critically, the sibling code path that builds the actual uploaded archive filename sanitizes the name with `filepath.Base` first: [4](#0-3) . The metadata-file path does not apply this or any other containment check, so `filepath.Join` will happily resolve and clean a name like `../../other-job/x` to a path outside `opts.artifactsWd` (which is the job's actual OS working directory captured via `os.Getwd()` in `fileArchiver.enumerate` [5](#0-4) ).

After the write, `Execute()` calls `c.process(metadataFile)` to add the generated file to the archive's file list [6](#0-5) , and `fileArchiver.process` does reject paths outside the working directory ("not supported: outside build directory") [7](#0-6) . However, this check runs strictly *after* `os.WriteFile` has already executed in `generateStatementToFile`. The write-to-disk side effect happens unconditionally regardless of whether the file will later be accepted into the archive — so the guard in `process()` only prevents the traversal file from being uploaded to GitLab, it does not prevent the file from being written to an attacker-chosen path on the runner host/container filesystem.

### Impact Explanation
An unprivileged pipeline author who can set `artifacts:name` (and who has `--generate-artifacts-metadata` enabled, e.g. via provenance/SLSA attestation feature) can cause the runner's `artifacts-uploader` helper process to write an arbitrary-content JSON file (the SLSA provenance statement, whose contents are largely runner/job metadata, not further attacker-controlled) to any path reachable by relative traversal from the job's working directory, within the permissions of the job process. On shared/shell executors where multiple concurrent jobs' working directories are siblings on the same host, this can overwrite files in another job's checkout or cache directory (e.g. `../../other-project-id/somefile`), corrupting or tampering with another job's build/cache state. On containerized executors the blast radius is limited to the helper container's filesystem, reducing but not eliminating impact (e.g. overwriting build tooling paths mounted into that container).

### Likelihood Explanation
Preconditions: `--generate-artifacts-metadata` must be enabled for the job (an increasingly common feature for SLSA provenance), and the attacker needs to know/guess a target relative path (feasible on shared runners with predictable build directory layouts by project/job ID). The attacker action is trivial — simply setting `artifacts: name: "../../<target>/x"` in `.gitlab-ci.yml`, fully within a normal user's control, then triggering a pipeline. This is reliably repeatable since `shell.Expand` and `filepath.Join` behave deterministically.

### Recommendation
Sanitize `opts.artifactName` the same way `artifactFilename` does (e.g., `filepath.Base`) before constructing the metadata file path in `generateStatementToFile`, and additionally verify the resulting cleaned path is still prefixed by `filepath.Clean(opts.artifactsWd)` before calling `os.WriteFile`, returning an error otherwise instead of relying on the later `process()` containment check which runs too late.

### Proof of Concept
Go unit test to add to `commands/helpers/artifact_metadata_test.go`:
```go
func TestGenerateMetadataToFile_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    artifactsWd := filepath.Join(tmpDir, "job-wd")
    require.NoError(t, os.MkdirAll(artifactsWd, 0o755))

    g := &artifactStatementGenerator{
        RunnerID: 1, RepoURL: "u", RepoDigest: "d", JobName: "j",
        ExecutorName: "e", RunnerName: "r",
        StartedAtRFC3339: time.Now().Format(time.RFC3339),
        EndedAtRFC3339:   time.Now().Add(time.Minute).Format(time.RFC3339),
        SLSAProvenanceVersion: slsaProvenanceVersion1,
    }

    opts := generateStatementOptions{
        artifactName: "../../escaped",
        files:        map[string]os.FileInfo{},
        artifactsWd:  artifactsWd,
        jobID:        1,
    }

    f, err := g.generateStatementToFile(opts)
    require.NoError(t, err)

    // Assert the invariant that the write must stay under artifactsWd.
    cleanWd := filepath.Clean(artifactsWd)
    cleanFile := filepath.Clean(f)
    assert.Truef(t, strings.HasPrefix(cleanFile, cleanWd+string(filepath.Separator)),
        "metadata file %q escaped artifactsWd %q", cleanFile, cleanWd)

    // Confirm the file actually exists outside the intended directory (demonstrates the bug today).
    _, statErr := os.Stat(cleanFile)
    require.NoError(t, statErr)
}
```
Expected result on current code: the test fails the `assert.Truef` containment check (and the file is found written at `tmpDir/escaped-metadata.json`, outside `artifactsWd`), proving the traversal. After applying the recommended fix, the containment assertion should pass or `generateStatementToFile` should return an error.

func (c *ArtifactsUploaderCommand) artifactFilename(name string, format spec.ArtifactFormat) string {
	name = filepath.Base(name)
	if name == "" || name == "." {
		name = DefaultUploadName
	}

	switch format {
	case spec.ArtifactFormatZip, spec.ArtifactFormatZipZstd:
		return name + ".zip"

	case spec.ArtifactFormatGzip:
		return name + ".gz"

	case spec.ArtifactFormatTarZstd:
		return name + ".tar.zst"
	}
	return name
}

func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

	if err == nil {
		// Process path only if it lives in our build directory
		if !strings.HasPrefix(relative, ".."+string(filepath.Separator)) {
			excluded, rule := c.isExcluded(relative)
			if excluded {
				c.exclude(rule)
				return false
			}

			err = c.add(relative)
		} else {
			err = errors.New("not supported: outside build directory")
		}
	}
