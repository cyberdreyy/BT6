### Title
Message.Validate() lacks nonce/timestamp/expiry checks, permitting unlimited replay of a captured signed gateway Message once evicted from RequestCache - ([File: core/services/gateway/api/message.go])

### Summary
`Message.Validate()` only checks field lengths, null-byte suffixes, and cryptographic signature validity; it never inspects any freshness field, because `MessageBody` contains no nonce, timestamp, or expiry field at all. Combined with `handlers/common.RequestCache`, which keys pending requests by `{Sender, MessageId}` and deletes the entry once a response is delivered or the timeout fires, an attacker who possesses one previously valid `Signature+Body` pair can resend the exact same bytes indefinitely after the original entry is evicted, and `Validate()`/`NewRequest()` will accept it as a brand-new request every time.

### Finding Description
`Message.Validate()` at [1](#0-0)  validates signature length, `MessageId`/`Method`/`DonId`/`Receiver` length/format, and recovers the signer via `ExtractSigner()`. Nowhere does it check a timestamp, nonce, or expiry — and `MessageBody` itself has no such field [2](#0-1) . The signature covers only `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload` [3](#0-2) , none of which are guaranteed to change between replays.

`handlers/common.RequestCache.NewRequest` uses `globalId{Sender, MessageId}` as the sole dedup key and only rejects it while the key is still present in the map [4](#0-3) . Once a response is aggregated or the timer fires, `deleteAndSendOnce` removes the key from `c.cache` [5](#0-4) , after which an identical `NewRequest` call with the same `Sender`/`MessageId` succeeds again — this is exactly what `TestRequestCache_Timeout` and `TestRequestCache_MaxSize` demonstrate the mechanics of (no anti-replay check exists in either `NewRequest` or `Validate`) [6](#0-5) .

I checked whether any calling handler compensates for this gap. `handlers/capabilities/handler.go`'s `HandleLegacyUserMessage` does enforce a staleness window, but only for the `web_api_trigger` method, and only via an application-specific `payload.Timestamp` field inside the trigger's own JSON payload (`webapicap.TriggerRequestPayload`), not via `Message.Validate()` or `RequestCache`: [7](#0-6) . That check only bounds staleness to `MaxAllowedMessageAgeSec`; it does not prevent replay within that window, and it is not present generically for other handlers/methods (e.g. `handlers/vault/handler.go` has no `Timestamp`/`MessageId` freshness references at all). So the core `api.Message`/`RequestCache` primitives that other handlers (vault, confidentialrelay, workflowsyncer, capabilities v2) rely on provide no baseline replay protection.

### Impact Explanation
Because signature verification alone does not bind a request to a single use, any handler that trusts `Validate()` + `RequestCache` for freshness/uniqueness can be made to process the same signed request multiple times after the first exchange completes or times out. This falls under Chainlink's "unauthorized job run" / request-integrity impact class: duplicate execution of the same action (e.g., re-triggering a workflow, re-issuing a target/action call, or re-submitting a vault/confidential-relay request) attributed to the original signer, without requiring a new signature or any additional secret. If a captured/leaked signed message belongs to another party (e.g., extracted from a gateway log or network capture), the attacker can impersonate that sender's request indefinitely with no time bound, which is the more severe cross-user variant of this issue.

### Likelihood Explanation
Exploitability requires only possession of one previously valid `Signature+Body` byte sequence — no private key, no additional credential, and no elevated role. This is trivially satisfiable by an unprivileged attacker who is the legitimate sender of a single request (self-replay) or who obtained someone else's signed request via network capture or a leaked log. The replay is reproducible indefinitely as long as the original entry has been evicted from `RequestCache` (post-response or post-timeout), which happens routinely in normal operation.

### Recommendation
Add an explicit freshness/anti-replay mechanism to the wire protocol rather than relying solely on `MessageId` uniqueness in a transient in-memory cache:
- Add a signed `Timestamp` (and optionally a monotonic nonce) field to `MessageBody`, include it in the signed payload (`GetRawMessageBody`), and reject messages outside an allowed clock skew window in `Message.Validate()`.
- Maintain a durable (or sufficiently long-lived, e.g. TTL beyond max allowed clock skew) "seen message" set per sender (similar in spirit to `core/capabilities/vault/request_replay_guard.go`'s `RequestReplayGuard`) so that a `MessageId` cannot be reused by the same sender even after `RequestCache` eviction.
- Apply this check generically at the point where `Message.Validate()` is called, not per-handler, so all handlers built on `api.Message`/`RequestCache` inherit the protection.

### Proof of Concept
Go test plan (`core/services/gateway/handlers/common/requestcache_test.go`):
1. Create `cache := common.NewRequestCache[requestState](time.Millisecond*10, 10)`.
2. Build `req := &api.Message{Body: api.MessageBody{MessageId: "aa", Sender: "0xabc"}}`; call `req.Validate()`-equivalent path is bypassed here since only signature/format matter — assert `Validate()` returns `nil` for this message with no timestamp field present, confirming no freshness check exists.
3. Call `cache.NewRequest(lggr, req, callback, &requestState{})`; assert `NoError`.
4. Wait for the timeout to fire (as in `TestRequestCache_Timeout`), confirming the entry is evicted via `deleteAndSendOnce`.
5. Call `cache.NewRequest(lggr, req, callback2, &requestState{})` again with the identical `req` (same `Signature`/`Body` bytes) and assert `NoError` — proving the identical message is accepted a second time with no nonce/timestamp barrier.
6. Extend the PoC to a handler using `RequestCache` (e.g. vault or confidentialrelay handler) to show the duplicate `NewRequest` results in a second downstream dispatch/action for the same original request bytes.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
```

func (c *requestCache[T]) deleteAndSendOnce(key globalId, callbackResponse handlers.UserCallbackPayload) error {
	c.mu.Lock()
	entry, deleted := c.cache[key]
	delete(c.cache, key)
	c.mu.Unlock()
	if deleted {
		entry.timeoutTimer.Stop()
		return entry.SendResponse(callbackResponse)
	}

	return nil
}
```

func TestRequestCache_Timeout(t *testing.T) {
	t.Parallel()

	cache := common.NewRequestCache[requestState](time.Millisecond*10, 1000)
	callback := common.NewCallback()
	lggr := logger.Test(t)

	req := &api.Message{Body: api.MessageBody{MessageId: "aa", Sender: "0x1234"}}
	initialState := &requestState{}
	require.NoError(t, cache.NewRequest(lggr, req, callback, initialState))

	finalResp, err := callback.Wait(t.Context())
	require.NoError(t, err)
	codec := api.JsonRPCCodec{}
	rawResp, err := codec.DecodeLegacyResponse(finalResp.RawResponse)
	require.NoError(t, err)
	require.Equal(t, "aa", rawResp.Body.MessageId)
	require.Equal(t, api.RequestTimeoutError, finalResp.ErrorCode)
}
