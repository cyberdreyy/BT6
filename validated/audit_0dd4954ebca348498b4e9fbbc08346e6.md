### Title
GraphQL `Node`/`Nodes` queries expose full RPC URLs (including embedded API keys) to any authenticated view-role user - ([File: core/web/resolver/node.go])

### Summary
The GraphQL `Node` type schema exposes `wsURL` and `httpURL` as plain `String!` fields, and `NodeResolver.WSURL()`/`HTTPURL()` return the raw configured URL verbatim with no redaction of embedded credentials (e.g., Infura/Alchemy API keys). Any authenticated user who can execute the `node`/`nodes` GraphQL query (no elevated role check beyond authentication is present in the resolver) receives these secrets in the response.

### Finding Description
`core/web/schema/type/node.graphql` declares:
```
type Node {
    ...
    wsURL: String!
    httpURL: String!
    ...
}
``` [1](#0-0) 

The resolver backing these fields, `NodeResolver.WSURL()` and `NodeResolver.HTTPURL()`, directly calls `.String()` on the parsed `url.URL` from the node's TOML config and returns it unmodified: [2](#0-1) 

This config is populated from `types.NodeStatus.Config` (the raw TOML node config, which for EVM nodes includes `WSURL`/`HTTPURL` as configured by the operator, potentially containing embedded API keys such as `https://mainnet.infura.io/v3/<secret>`), via `NewNode`: [3](#0-2) 

`NewNodePayloadResolver` and `NewNodesPayload` wrap these `NodeResolver` instances with no additional filtering or redaction of URL fields: [4](#0-3) 

Regarding access control: `AuthenticateGQL` middleware only checks for a valid session cookie and attaches the user to context — it explicitly states "It is the responsibility of each resolver to validate whether it requires an authenticated user": [5](#0-4) 

The `Node`/`Nodes`/`Chains` query resolvers in `core/web/resolver/query.go` do not perform any additional role-elevation check restricting these fields beyond baseline session authentication, so a low-privilege "view" role user with a valid session can query `nodes{results{httpURL wsURL}}` and receive the raw provider URL, including any embedded API key, in the plaintext GraphQL response.

### Impact Explanation
This matches Chainlink's key/secret disclosure impact class: leakage of third-party RPC provider API keys embedded in node RPC URLs to the lowest-privilege authenticated session. An attacker who compromises or is granted a view-only account can exfiltrate the operator's Infura/Alchemy/QuickNode API key, enabling quota theft, billing abuse, or denial-of-service against the node operator's RPC provider account — without needing any operator or admin capability.

### Likelihood Explanation
Preconditions are minimal: an authenticated session with the lowest role ("view") and at least one EVM node configured with a credential-bearing HTTP/WS URL (a very common operational pattern, e.g., Infura/Alchemy URLs with the API key embedded in the path). The exploit requires a single GraphQL query (`nodes { results { httpURL wsURL } }`) and is fully repeatable and deterministic — no race conditions, no special network positioning, and no reliance on misconfiguration beyond the standard practice of embedding API keys in RPC URLs.

### Recommendation
Redact or mask credential-bearing portions of `wsURL`/`httpURL` before returning them from `NodeResolver.WSURL()`/`HTTPURL()` (e.g., strip path segments/query params matching known API-key patterns, or require an elevated "admin" role to view raw URLs while showing only the host to lower-privileged roles). At minimum, gate exposure of full URLs behind a role check equivalent to admin/keystore-access rather than the general view role.

### Proof of Concept
Go unit test plan in `core/web/resolver/node_test.go`:
1. Construct a `types.NodeStatus` with `Config` TOML containing `WSURL = "wss://mainnet.infura.io/ws/v3/SECRET_API_KEY"` and `HTTPURL = "https://mainnet.infura.io/v3/SECRET_API_KEY"`.
2. Call `resolver.NewNodePayloadResolver(&status, nil)` and resolve `ToNode()`.
3. Assert that `NodeResolver.HTTPURL()` and `WSURL()` currently return the string containing `"SECRET_API_KEY"` (proving disclosure).
4. Handler-level integration test: authenticate a session with role `view`, POST `/query` with body `{"query":"{ nodes(offset:0, limit:10){ results{ name httpURL wsURL } } }"}`, and assert the JSON response body contains `SECRET_API_KEY` — confirming the secret reaches a low-privilege authenticated client.
5. After remediation, assert the same test expects the raw secret to be absent/masked from the response.

func NewNodePayloadResolver(node *types.NodeStatus, err error) (npr *NodePayloadResolver, warn error) {
	e := NotFoundErrorUnionType{err: err, message: "node not found", isExpectedErrorFn: nil}
	npr = &NodePayloadResolver{NotFoundErrorUnionType: e}
	if node != nil {
		npr.nr, warn = NewNode(*node)
	}
	return
}

// ToNode resolves the Node object to be returned if it is found
func (r *NodePayloadResolver) ToNode() (*NodeResolver, bool) {
	return r.nr, r.nr != nil
}

// AuthenticateGQL middleware checks the session cookie for a user and sets it
// on the request context if it exists. It is the responsibility of each resolver
// to validate whether it requires an authenticated user.
//
// We currently only support GQL authentication by session cookie.
func AuthenticateGQL(authenticator Authenticator, lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		ctx := c.Request.Context()
		session := sessions.Default(c)
		sessionID, ok := session.Get(SessionIDKey).(string)
		if !ok {
			return
		}

		user, err := authenticator.AuthorizedUserWithSession(ctx, sessionID)
		if err != nil {
			if errors.Is(err, clsessions.ErrUserSessionExpired) {
				lggr.Warnw("Failed to authenticate session", "err", err)
			} else {
				lggr.Errorw("Failed call to AuthorizedUserWithSession, unable to get user", "err", err)
			}
			return
		}

		ctx = WithGQLAuthenticatedSession(c.Request.Context(), user, sessionID)

		c.Request = c.Request.WithContext(ctx)
	}
}
