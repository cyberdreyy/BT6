I found a valid analog in `multisig2/src/lib.rs`: removing a multisig member does not purge that member's confirmation entries from *other* members' pending requests, allowing a request to later execute with fewer live confirming members than `num_confirmations` requires.

### Title
Multisig member removal leaves stale confirmations, allowing requests to execute below the confirmation threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` in the NEAR multisig2 contract only clears requests and `num_requests_pk` entries where the *removed member is the request owner*. It never scans `self.confirmations` to strip that member's prior confirmations from requests owned by *other* members. Because `confirm()` counts entries in the stored `HashSet<String>` without checking whether each entry still corresponds to a live member, a stale confirmation from a since-removed member is counted toward the threshold, letting a request execute with fewer currently-valid confirming members than `num_confirmations`.

### Finding Description
`delete_member` (multisig2/src/lib.rs:355-379) does: [1](#0-0) 
It filters `self.requests` for entries whose `r.member == member` and removes those requests/confirmations, and removes `num_requests_pk` for that member — but it never iterates `self.confirmations` values to drop the removed member's string key from confirmation sets belonging to *other* members' requests.

`confirm()` (multisig2/src/lib.rs:294-315) computes readiness purely from set cardinality: [2](#0-1) 
`confirmations.len() as u32 + 1 >= self.num_confirmations` does not verify that every string already in the `HashSet<String>` still names a current member (`self.members.contains(...)`). So a confirmation recorded by a member who is later removed remains counted forever.

This mirrors the Palmera pattern cited in the external report: state tied to an entity (here, a multisig member) is not fully purged on removal, and that residual state (a confirmation) is later inherited/counted by unrelated operations, in this case inflating the live-confirmation count used to authorize fund transfers, key additions, or contract deployments.

### Impact Explanation
This breaks the custody binding "confirmations counted versus live members": the contract can execute a `MultiSigRequest` (including `Transfer`, `AddKey`, `DeployContract`, `FunctionCall`) with fewer genuinely live confirming members than `num_confirmations` mandates. That is a multisig request executed below threshold, which per the rules is a Critical-severity outcome (NEAR/wNEAR could be moved, or a full-access key added, by fewer real approvers than the contract's own guarantee requires).

### Likelihood Explanation
No privileged action or foundation/owner cooperation is required beyond the multisig's own normal governance flow: any member can create a request, any member can confirm it without immediate execution, and any legitimate `DeleteMember` action (itself confirmed by the threshold, as is normal governance) leaves the exploitable residue behind. No malicious validator, redeploy, or out-of-repo dependency is needed — only ordinary use of `add_request`, `confirm`, and `DeleteMember` in a specific but realistic order.

### Proof of Concept
1. Contract initialized with `members = {A, B, C}`, `num_confirmations = 2`.
2. `A` calls `add_request` for `Transfer{amount}` (request `R`, owned by `A`).
3. `B` calls `confirm(R)` → `confirmations[R] = {B}`, `1 < 2`, so it is not yet executed.
4. `A` and `C` submit and confirm a `DeleteMember{member: B}` request (reaching the 2-of-3 threshold normally) → `B` is removed from `self.members`; `delete_member` clears only requests owned by `B` (none here) and `num_requests_pk[B]`; it does **not** touch `confirmations[R]`, which still contains `"B"`.
5. `C` (a legitimate current member) now calls `confirm(R)`. `confirmations[R].len() + 1 == 2 >= num_confirmations(2)`, so the request executes — even though the only currently valid, live confirmer is `C`; `B`'s confirmation is stale and `B` is no longer a member.
6. Result: a `Transfer` (or `AddKey`/`DeployContract`) executes with only one live member's real approval against a nominal 2-of-3 policy. [3](#0-2) [4](#0-3)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
