## Finding: Any single vesting shareholder can permanently block `distribute()` for the entire vesting pool by opting out of direct coin transfers

### Title
Unprivileged shareholder can permanently trap all other shareholders' vested rewards by disabling direct coin transfers on their own account - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute()` is a permissionless entry function that iterates over *all* shareholders of a vesting contract in a single loop and calls `aptos_account::deposit_coins` for each one [1](#0-0) . `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has opted out of unsolicited transfers via `set_allow_direct_coin_transfers(false)` [2](#0-1) . Since Move transactions are atomic and there is no try/catch or per-recipient isolation in the loop, a single shareholder opting out permanently DoSes distribution for every other shareholder in that vesting contract — directly analogous to the external report where a single failing oracle call reverts the entire aggregate `getData()` call.

### Finding Description
`set_allow_direct_coin_transfers` is a completely unprivileged, self-service function any account holder can call on their own address [3](#0-2) . Once set to `false`, `can_receive_direct_coin_transfers` returns `false` for that address [4](#0-3) , and any subsequent `deposit_coins` call to that address aborts [5](#0-4) .

`vesting::distribute` withdraws all currently-withdrawable stake from the underlying stake pool, then iterates over *every* shareholder of the vesting contract's `grant_pool`, computing each one's share and calling `aptos_account::deposit_coins(recipient_address, ...)` for the shareholder's beneficiary (which defaults to the shareholder's own address) [6](#0-5) . There is no skip-on-failure, no removal of a "stuck" shareholder, and no isolation between shareholders — a single abort anywhere in the loop reverts the whole transaction, including the `withdraw_stake` call that already pulled funds out of the stake pool.

Since any shareholder can unilaterally flip their own `DirectTransferConfig.allow_arbitrary_coin_transfers` to `false` at any time (no admin or operator permission required), and there is no mechanism forcing them back to `true` before `distribute()` succeeds, this permanently blocks `distribute()` (and `distribute_many`) for the entire vesting contract, not just for the opted-out shareholder.

The exact same pattern also exists in `staking_contract::distribute_internal`, which loops over `distribution_pool` shareholders (staker + operator/beneficiary) and calls `aptos_account::deposit_coins` per recipient inside a `while` loop with no isolation [7](#0-6) ; if the staker opts out, the operator's already-unlocked commission can never be paid out via `distribute()` either, since both recipients share the same atomic loop.

### Impact Explanation
This traps value permanently for parties who did nothing wrong: any other shareholder in the same vesting contract (there can be up to 30 shareholders per contract) loses the ability to ever receive their vested grant or accumulated staking rewards via `distribute()`, because one co-shareholder's self-inflicted (or intentionally griefing) opt-out permanently reverts every future distribution attempt. This matches the required impact category "Operator commission, beneficiary payout, or share-accounting corruption that credits the wrong account or traps value" and "Permanent lock or non-recoverable loss of claim rights in stake, delegation, commission, beneficiary, or vesting flows." Funds already unlocked and withdrawn from the stake pool inside the same transaction are never delivered since the whole call reverts, and they remain locked in the vesting contract's resource account indefinitely (each new `distribute()` attempt re-withdraws and re-fails the same way).

### Likelihood Explanation
The action required — calling `set_allow_direct_coin_transfers(false)` on one's own account — is a completely normal, publicly documented user operation with no cost or restriction beyond gas, and it can be invoked by any of the (potentially many) unprivileged shareholders of a vesting contract. No admin, operator, or governance privilege is needed. This makes the likelihood high once any shareholder does this (deliberately or even accidentally, e.g., to avoid unsolicited token spam, unaware of the side effect).

### Recommendation
In `vesting::distribute` (and `staking_contract::distribute_internal`), avoid letting a single recipient's failed deposit abort payouts to all other shareholders. Options: wrap each `aptos_account::deposit_coins` call so a failure only skips/re-queues that specific shareholder's share (e.g., keep it as pending, or fall back to storing the amount for later withdrawal) instead of reverting the whole loop; or require accounts opting out of direct transfers to still allow "owed" distributions from contracts they voluntarily joined, e.g., by checking for registration/opt-out only at buy-in time, not at each distribution.

### Proof of Concept
1. Admin creates a vesting contract with two shareholders, A and B, via `create_vesting_contract`.
2. Shareholder A calls `aptos_account::set_allow_direct_coin_transfers(A_signer, false)` on their own account — a normal, permissionless action.
3. Time passes; rewards/vesting periods elapse; `vest` or `unlock_rewards` is called, moving stake into `pending_inactive`/`inactive`.
4. Once funds are withdrawable, anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches shareholder A and calls `aptos_account::deposit_coins(A, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` because A opted out.
6. The entire transaction reverts — shareholder B (and the admin's withdrawal address for dust) never receive their share, and this failure repeats on every future `distribute()` call for this vesting contract until A manually re-enables direct transfers, which A has no incentive to do.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to

    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
    }
