### Title
Zip-slip path traversal in `ExtractZipArchive`/`extractZipFile` allows writing and chmod'ing files outside job workspace - (File: `helpers/archives/zip_extract.go`)

### Summary
`ExtractZipArchive` (and the Windows/Unix `lchmod` helpers it calls) use `zip.File.Name` verbatim as a filesystem path with no path-traversal or absolute-path validation and no confinement to a base extraction directory. The only guard, `errorIfGitDirectory`, only rejects paths whose first segment is `.git`; it does nothing to stop `../` segments or absolute paths. Because the `ziplegacy` extractor never joins/chroots to the `dir` passed to `NewExtractor`, a crafted cache/artifact zip entry such as `../../victim/token` (or an absolute path) is extracted and chmod'ed outside the job's working directory.

### Finding Description
- `CacheExtractorCommand.Execute` computes `wd` via `os.Getwd()` and calls `archive.NewExtractor(format, f, size, wd)`, which for zip resolves to `ziplegacy.NewExtractor(r, size, wd)`. [1](#0-0) 
- `ziplegacy.extractor` stores `dir` but its `Extract` method never uses it — it calls `archives.ExtractZipArchive(zr)` directly, passing no base directory at all. [2](#0-1) 
- `ExtractZipArchive` iterates `archive.File` and, for each entry, only runs `errorIfGitDirectory(file.Name)` (which is a non-fatal warning, not an extraction abort) before calling `extractZipFile(file)` with the raw `file.Name`. [3](#0-2) 
- `errorIfGitDirectory`/`isPathAGitDirectory` only clean the path and check if the first path segment equals `.git`; it does not reject `..` segments, absolute paths, or paths that escape any root. [4](#0-3) 
- `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on the entry type, `extractZipFileEntry`/`extractZipSymlinkEntry` perform `os.Remove(file.Name)` + `os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, ...)` or `os.Symlink`, all using the attacker-controlled `file.Name` directly with no `filepath.Clean`/prefix check against any root directory. [5](#0-4) 
- After all files are written, a second pass calls `lchmod(file.Name, file.Mode())` for every entry, again using the raw, unvalidated name — this is exactly the `os_windows.go`/`os_unix.go` `lchmod` referenced in the question, and it operates on whatever path the traversal resolved to. [6](#0-5) [7](#0-6) 

Attacker-controlled input: the cache/artifact archive contents themselves are attacker-controlled — a pipeline author can produce a `cache:` (or artifacts) zip whose entries include `..`-relative or absolute path names, then have it stored as a project cache/artifact and later downloaded/extracted by `CacheExtractorCommand`/`ExtractZipArchive`. There is no server-side or client-side validation of the zip member names before or during extraction that would block traversal, since `errorIfGitDirectory` is the only existing check and it targets an unrelated invariant (protecting `.git`), not path containment. The `dir`/`wd` value that could have served as a confinement root is computed but discarded (never joined against member names), so the invariant "archive extraction stays within the job working directory" is not enforced anywhere in this path.

### Impact Explanation
On a shared runner host (or any host where multiple jobs/projects execute as the same OS user, e.g. shell executor or executors sharing a filesystem), a crafted archive can write/overwrite arbitrary files reachable by the runner process's permissions outside of the job's working directory, and additionally have their permission bits altered via the `lchmod` second pass. Concrete scoped impact: unauthorized modification of files belonging to another job/project (e.g. altering permissions/content of files in a sibling job workspace or shared paths), which is a workspace-isolation violation as scoped by this audit.

### Likelihood Explanation
Fully attacker-reachable from an unprivileged CI job: any pipeline author can produce cache/artifact content (e.g. via a `before_script` that fabricates a zip with crafted `zip.File.Name` values, or by directly uploading a crafted cache archive if the flow allows influencing raw bytes) and have GitLab Runner's `cache-extractor` helper extract it via `ExtractZipArchive`. No special privileges, admin action, or infrastructure compromise is required — the only precondition is that the target and victim jobs execute on a filesystem-sharing runner (e.g., shell executor, or any executor configuration where multiple jobs' working directories are reachable from the same OS user), which is a common, unprivileged, in-scope scenario (not an "admin-only" precondition since it doesn't rely on privileged containers/host PID/docker.sock).

### Recommendation
Enforce path containment in `helpers/archives/zip_extract.go` before any filesystem operation: for each `zip.File`, compute `target := filepath.Join(baseDir, file.Name)` and reject the entry (rather than silently proceeding) if `!strings.HasPrefix(filepath.Clean(target), filepath.Clean(baseDir)+string(filepath.Separator))`, or use `filepath.Rel` and check the result does not start with `..`/isn't absolute. Thread the destination `baseDir` (the `dir` already passed into `ziplegacy.NewExtractor`) through to `ExtractZipArchive`, `extractZipFile`, and the `lchmod` pass so all path operations (`MkdirAll`, `OpenFile`, `Symlink`, `lchmod`) operate on the canonicalized, confined path rather than the raw `file.Name`. Apply the same containment check to symlink targets (`extractZipSymlinkEntry`) to prevent symlink-based escapes as well.

### Proof of Concept

```go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpRoot := t.TempDir()
    victimDir := t.TempDir() // simulates a sibling job's directory
    victimFile := filepath.Join(victimDir, "token")
    require.NoError(t, os.WriteFile(victimFile, []byte("orig"), 0o600))

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    // relative path escapes tmpRoot via ".."
    rel, _ := filepath.Rel(tmpRoot, victimFile)
    w, _ := zw.CreateHeader(&zip.FileHeader{Name: rel, Method: zip.Deflate})
    w.Write([]byte("owned"))
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    // change CWD to tmpRoot to simulate job working directory
    oldWd, _ := os.Getwd()
    defer os.Chdir(oldWd)
    os.Chdir(tmpRoot)

    err = archives.ExtractZipArchive(zr)

    // Expected (fixed) behavior: extraction must be rejected/confined
    contents, _ := os.ReadFile(victimFile)
    assert.Equal(t, "orig", string(contents), "victim file outside root must not be modified")
    assert.Error(t, err, "extraction of path-traversal entry should fail")
}
```
Expected current (vulnerable) result: `victimFile` content becomes `"owned"` and its permission bits are altered by the subsequent `lchmod` pass, proving the escape; after the fix, the test should assert the entry is rejected (or the write is confined under `tmpRoot`) and `victimFile` remains unmodified.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
