### Title
Confirmations from deleted members remain counted toward the confirmation threshold on other requests - ([File: multisig2/src/lib.rs])

### Summary
`delete_member` in `multisig2/src/lib.rs` removes a departing member's own outstanding requests and their `num_requests_pk` entry, but never scans and strips that member's existing *confirmations* on other, still-live requests. `confirm` later counts `confirmations.len() as u32 + 1 >= self.num_confirmations` without verifying every counted confirmation still belongs to a current member, so a confirmation cast before removal continues to count toward execution afterward.

### Finding Description
`confirm` treats the size of the `confirmations` set for a request as the count of valid approvals: `if confirmations.len() as u32 + 1 >= self.num_confirmations { ... execute_request ... }` [1](#0-0) . This binding assumes every entry in `confirmations` corresponds to a currently live member.

`delete_member`, however, only cleans up requests *authored* by the deleted member and their `num_requests_pk` counter — it never inspects or purges the deleted member's public-key/account string from `confirmations` sets belonging to *other* requests that member had already confirmed: [2](#0-1) 

So if member A confirms a request created by member B (adding A's identity string to that request's `confirmations` set) and is subsequently removed via a `DeleteMember` request, A's stale confirmation string remains stored under that unrelated request. When later members confirm the same request, `confirm` only checks the raw count of stored confirmation strings against `num_confirmations`, still incorporating A's now-invalid confirmation, effectively lowering the number of *live* members whose approval is truly required to reach the configured threshold.

This breaks the equality that should hold: `live confirmations counted == live confirmations needed`. Instead the code allows `stale confirmations + live confirmations >= num_confirmations`, letting a request execute (including `Transfer`, `AddMember`, `AddKey`, `FunctionCall`, etc.) with fewer than `num_confirmations` currently-authorized signers.

### Impact Explanation
This is a request executed below the configured confirmation threshold once a member departs — directly matching the "Critical: a multisig request executed below threshold" impact bucket. Because `MultiSigRequestAction::Transfer` and `FunctionCall` can move NEAR or invoke arbitrary calls, an attacker who was previously a member (and confirmed a pending request before being removed) effectively retains one vote after removal, letting the remaining `num_confirmations - 1` live members (or fewer, if multiple confirmations become stale) push a transfer or privileged action through without reaching the intended threshold of *currently authorized* approvers.

### Likelihood Explanation
This requires an ordinary sequence achievable without any privileged bypass: (1) a request is created and partially confirmed, (2) before it is finalized, a `DeleteMember` request removes one of the confirming members, (3) the original request is later confirmed by the remaining members to reach the nominal count. No foundation/owner-only action, redeploy, or external key compromise is needed beyond the multisig's own normal member-management flow, which any subset of members with delete privileges can trigger.

### Recommendation
When deleting a member in `delete_member`, iterate all active requests' `confirmations` sets and remove the departing member's identity string from each (not only from requests the member authored). Alternatively, on `confirm`, revalidate that every string in the stored `confirmations` set still corresponds to a member in `self.members` before comparing against `num_confirmations`, discarding stale entries.

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)`.
2. `A` calls `add_request_and_confirm(transfer_request)` → confirmations = `{A}`.
3. `B` calls `confirm(request_id)` → confirmations = `{A, B}` (2 of 3 needed).
4. Members create and confirm a `DeleteMember { member: B }` request (reaching 3-of-4 threshold on that separate request) → `B` is removed from `self.members`, but `B`'s confirmation on `transfer_request` (in step 3) is never purged from `confirmations`.
5. `C` calls `confirm(transfer_request_id)`. `confirmations.len()` is still 2 (`A`, `B`), `+1` for `C` = 3 ≥ `num_confirmations` (3) → `execute_request` runs and transfers funds, even though only `A` and `C` are still live members casting valid approvals (2 live confirmations, not 3).     pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
