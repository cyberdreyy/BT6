### Title
Missing allowlist enforcement on legacy `web_api_trigger` messages allows unauthorized DON dispatch - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` validates message format, timestamp freshness, and method name, then forwards the request to every DON member via `don.SendToNode`, but it never checks that `msg.Body.Sender` is an allowlisted/registered sender for the target workflow/DON. The `// TODO: apply allowlist and rate-limiting here` comment marks exactly the gap where this check is missing.

### Finding Description
The request path is: `gateway.ProcessRequest` decodes the JSON-RPC request, and for legacy requests (those with a non-empty `msg.Body.DonId`) calls `msg.Validate()` and then dispatches to `h.HandleLegacyUserMessage` [1](#0-0) . `msg.Validate()` is a structural/signature-format validation on the message, not an authorization/allowlist check — nothing in `gateway.go` or `HandleLegacyUserMessage` cross-references the sender against a per-workflow/DON allowlist before dispatch.

Inside `HandleLegacyUserMessage`, the checks performed are: JSON payload decoding, presence of `Timestamp`, and staleness relative to `MaxAllowedMessageAgeSec` [2](#0-1) . Immediately after these checks, the code contains the comment `// TODO: apply allowlist and rate-limiting here`, followed only by a method-name check (`msg.Body.Method != MethodWebAPITrigger`) before constructing the outbound request and saving the callback [3](#0-2) . The function then dispatches the request to every DON member unconditionally:

```go
for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [4](#0-3) 

There is no lookup of `msg.Body.Sender` against any allowlist structure (e.g., a per-workflow or per-DON sender allowlist) anywhere in this function or in `gateway.ProcessRequest`. The only prerequisite for reaching `don.SendToNode` for all DON members is that the message parses, has a non-zero, non-stale timestamp, and has method `web_api_trigger` — none of which require the sender to be registered or authorized for that workflow/DON.

### Impact Explanation
Any caller who can produce a message satisfying `msg.Validate()` (well-formed signature over an arbitrary/unregistered key pair) and craft a `TriggerRequestPayload` with a fresh timestamp can force every node in the target DON to receive and act on a `web_api_trigger` message, without being a registered/allowlisted sender for that workflow. This matches the "unauthorized action/allowlist bypass causing resource consumption at other subscribers' expense" impact class: unauthorized DON-wide compute/resource consumption, and a mechanism to trigger workflow execution attempts on behalf of an unregistered principal.

### Likelihood Explanation
The only precondition is possession of any ECDSA keypair to sign the message body — no registration, allowlist entry, or prior relationship with the DON/workflow is required. The attacker sends the request through the gateway's public user-facing HTTP endpoint (`gateway.ProcessRequest`), a normal unauthenticated entry point. This is trivially repeatable and scriptable.

### Recommendation
Implement the allowlist check at the marked TODO location in `HandleLegacyUserMessage`: before saving the callback and dispatching to DON members, look up `msg.Body.Sender` against the DON's/workflow's configured allowlist (and apply the intended rate-limiting), rejecting with an appropriate `api.ErrorCode` (e.g., an authorization/forbidden error) if the sender is not present, mirroring the enforcement pattern already used elsewhere in the gateway (e.g., node-side rate limiting via `h.nodeRateLimiter` in `handleWebAPIOutgoingMessage`).

### Proof of Concept
Go handler-level test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a `donConfig` whose `Members` do NOT include the attacker's address, and with no allowlist entry for the attacker's signing key (since no allowlist support currently exists to configure).
2. Sign a `MessageBody` with method `MethodWebAPITrigger`, a valid `TriggerRequestPayload` (fresh `Timestamp`), using an arbitrary/freshly generated ECDSA key not associated with any registered workflow owner.
3. Use a mock `handlers.DON` (via `mocks.DON`) with `SendToNode` mocked to assert it is called once per `h.donConfig.Members`.
4. Call `h.HandleLegacyUserMessage(ctx, msg, callback)`.
5. Assert: `don.SendToNode` was invoked for every DON member despite the sender never being registered/allowlisted, and that no error/rejection response indicating "unauthorized sender" was returned via `callback.SendResponse` — demonstrating the missing enforcement at this call site.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()
