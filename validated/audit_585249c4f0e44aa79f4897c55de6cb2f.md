### Title
`send_transaction_with_context` panics on unwrap of `None` from `get_blockhash_last_valid_block_height` for an unknown/expired blockhash - ([File: banks-server/src/banks_server.rs])

### Summary
`BanksServer::send_transaction_with_context` calls `.unwrap()` directly on the `Option<u64>` returned by `root_bank().get_blockhash_last_valid_block_height(blockhash)` without first validating that the client-supplied `recent_blockhash` is actually a known/recent blockhash. Any client can submit a `VersionedTransaction` with an arbitrary 32-byte hash as `recent_blockhash` to trigger this `None` case and panic the serving task.

### Finding Description
The vulnerable code path is: [1](#0-0) 

`send_transaction_with_context` takes an attacker-supplied `VersionedTransaction` directly off the wire, with no `SanitizedTransaction`/`RuntimeTransaction` verification step preceding the blockhash lookup (unlike `process_transaction_with_commitment_and_context`, which at least runs `SanitizedTransaction::try_create` and `.verify()` before reaching the same pattern). It extracts `blockhash = transaction.message.recent_blockhash()` directly from the untrusted message and immediately calls:

```rust
let last_valid_block_height = self
    .bank_forks
    .read()
    .unwrap()
    .root_bank()
    .get_blockhash_last_valid_block_height(blockhash)
    .unwrap();
```

`get_blockhash_last_valid_block_height` returns `Option<u64>`, returning `None` when the given hash is not present in the bank's recent blockhash cache (e.g., an arbitrary/garbage hash, or an expired blockhash that has aged out). Since there is no check on `blockhash` before this call, and no fallback/graceful error path, calling `.unwrap()` on `None` panics the tarpc-served async task calling into this handler. This function is directly exposed to any client connecting via `start_local_server` (in-process, unbounded channel served via `tokio::spawn`) and `start_tcp_server` (network-exposed, one channel per client IP, up to 10 concurrently): [2](#0-1) [3](#0-2) 

Because each incoming connection is served on its own spawned task/thread but shares `bank_forks`, `block_commitment_cache`, and `transaction_sender` state, a panicking task terminates that client's request-serving future; in a single-threaded or `catch_unwind`-less executor configuration this can abort the process, and at minimum denies that connection's read/writes for good since the executing future is destroyed mid-flight. No existing guard (parameter validation, commitment check, or length check) intercepts an unrecognized blockhash before the `.unwrap()`.

### Impact Explanation
A single unprivileged client can panic a `BanksServer`-serving task/thread by sending a `VersionedTransaction` whose `recent_blockhash` doesn't correspond to any blockhash tracked in `root_bank`'s recent-blockhash queue (e.g. `Hash::new_unique()`). This falls under the crash-from-a-single-request bounty category, denying subsequent request processing on that connection/process.

### Likelihood Explanation
Trivially reachable: connect through `start_local_server` or `start_tcp_server`, build any `VersionedTransaction` with a random/garbage `recent_blockhash`, and call `send_transaction_with_context`. No signature verification, blockhash validation, or sanitization occurs before the `.unwrap()`, so this is 100% reproducible with a single call.

### Recommendation
Replace the `.unwrap()` with proper error handling — e.g., have `send_transaction_with_context` validate the blockhash via `SanitizedTransaction`/`RuntimeTransaction::try_create` first (mirroring `process_transaction_with_commitment_and_context`), and return an explicit error/rejection (or default to a max-height / drop the transaction) when `get_blockhash_last_valid_block_height` returns `None`, instead of panicking.

### Proof of Concept
```rust
// banks-server/src/banks_server.rs (test module)
#[tokio::test]
async fn test_send_transaction_with_invalid_blockhash_does_not_panic() {
    let (bank_forks, block_commitment_cache) = /* set up as in existing tests, e.g. test_banks_client_new */;
    let client_transport = start_local_server(
        bank_forks,
        block_commitment_cache,
        Duration::from_millis(1),
    ).await;
    let mut banks_client = start_client(client_transport).await.unwrap();

    let payer = Keypair::new();
    let bogus_blockhash = Hash::new_unique(); // not in root_bank's recent blockhashes
    let mut tx = Transaction::new_unsigned(Message::new(&[], Some(&payer.pubkey())));
    tx.message.recent_blockhash = bogus_blockhash;
    tx.sign(&[&payer], bogus_blockhash);

    // Expect a graceful error, not a panic that kills the serving task
    let result = banks_client
        .send_transaction_with_context(VersionedTransaction::from(tx))
        .await;
    assert!(result.is_err() || matches!(result, Ok(Err(_))));
}
```
Currently, this test causes the `solBankForksCli`-adjacent tarpc-serving task to panic at the `.unwrap()` in `send_transaction_with_context` instead of returning an error.

#[tarpc::server]
impl Banks for BanksServer {
    async fn send_transaction_with_context(self, _: Context, transaction: VersionedTransaction) {
        let message_hash = transaction.message.hash();
        let blockhash = transaction.message.recent_blockhash();
        let last_valid_block_height = self
            .bank_forks
            .read()
            .unwrap()
            .root_bank()
            .get_blockhash_last_valid_block_height(blockhash)
            .unwrap();
        let signature = transaction.signatures.first().cloned().unwrap_or_default();
        let info = TransactionInfo::new(
            message_hash,
            signature,
            *blockhash,
            serialize(&transaction).unwrap(),
            last_valid_block_height,
            None,
            None,
            None,
        );
        self.transaction_sender.send(info).unwrap();
    }

pub async fn start_tcp_server(
    listen_addr: SocketAddr,
    tpu_addr: SocketAddr,
    bank_forks: Arc<RwLock<BankForks>>,
    block_commitment_cache: Arc<RwLock<BlockCommitmentCache>>,
    exit: Arc<AtomicBool>,
) -> io::Result<()> {
    // Note: These settings are copied straight from the tarpc example.
    let server = tcp::listen(listen_addr, Bincode::default)
        .await?
        // Ignore accept errors.
        .filter_map(|r| future::ready(r.ok()))
        .map(server::BaseChannel::with_defaults)
        // Limit channels to 1 per IP.
        .max_channels_per_key(1, |t| {
            t.as_ref()
                .peer_addr()
                .map(|x| x.ip())
                .unwrap_or_else(|_| Ipv4Addr::UNSPECIFIED.into())
        })
        // serve is generated by the service attribute. It takes as input any type implementing
        // the generated Banks trait.
        .map(move |chan| {
            let (sender, receiver) = unbounded();

            let client = create_client(None, tpu_addr, exit.clone());

            SendTransactionService::new(
                bank_forks.clone(),
                receiver,
                client,
                Config {
                    retry_rate_ms: 5_000,
                    ..Config::default()
                },
                exit.clone(),
            );

            let server = BanksServer::new(
                bank_forks.clone(),
                block_commitment_cache.clone(),
                sender,
                Duration::from_millis(200),
            );
            chan.execute(server.serve())
        })
        // Max 10 channels.
        .buffer_unordered(10)
        .for_each(|_| async {});

    server.await;
    Ok(())
}
