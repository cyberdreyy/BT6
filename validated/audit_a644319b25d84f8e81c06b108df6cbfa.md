### Title
Zip Slip: unsanitized `zip.File.Name` in `extractZipFile`/`extractZipFileEntry` allows path traversal outside the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` iterates zip entries and calls `extractZipFile`, which uses `file.Name` directly (relative to the process's current working directory) to `os.MkdirAll` parent directories and to `os.OpenFile`/`os.Symlink`/`os.Mkdir` the entry, with no `..`/absolute-path validation. The only path check present, `errorIfGitDirectory`, only rejects paths beginning with `.git` and does nothing to prevent traversal.

### Finding Description
`extractZipFile` (helpers/archives/zip_extract.go:61-83) does:
```
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
extractZipFileEntry / extractZipSymlinkEntry / extractZipDirectoryEntry
```
and each of these (`extractZipFileEntry` at lines 41-59, `extractZipSymlinkEntry` at 22-39, `extractZipDirectoryEntry` at 12-20) uses `file.Name` verbatim as the destination path passed to `os.OpenFile`, `os.Symlink`, and `os.Mkdir` respectively. `ExtractZipArchive` (lines 85-110) only guards against `.git` directory entries via `errorIfGitDirectory`/`isPathAGitDirectory` (helpers/archives/path_check_helper.go:13-31), which simply checks whether the first path segment (after `filepath.Clean`) equals `.git`. There is no check that the cleaned/joined path stays under the extraction root, no `filepath.Rel` containment check, and no rejection of absolute paths or `..` segments.

Since `zip.File.Name` is fully attacker-controlled cache/artifact-archive content, an unprivileged job (which controls both the artifacts it uploads and, on cache restore, the cache archive contents fed back through GitLab's cache/artifact download path) can construct a zip whose entries are named e.g. `../../shared-vol/payload` or use a leading `/` combined with `filepath.Clean` behavior to attempt writing outside the extraction directory. `os.MkdirAll(filepath.Dir(file.Name), ...)` will create the necessary parent directories anywhere the process has write permission, and `os.OpenFile`/`os.Symlink` will then write/symlink the file there — entirely relative to the extractor process's current working directory, with no root confinement enforced.

Note also that `extractZipSymlinkEntry` allows creating a symlink whose target is arbitrary attacker-supplied data (`data` read from the zip entry contents), which combined with unrestrained `file.Name` traversal compounds the risk (symlink planted outside the workspace pointing anywhere on the filesystem visible to the helper/service container).

### Impact Explanation
If the working directory at extraction time is the job's build/cache directory (as is normal for `gitlab-runner artifacts-downloader`/`cache-extractor` helpers), a crafted artifact or cache zip can write or symlink files to any path reachable via relative traversal from that directory that the runner/helper process has permission to write — including paths that back onto volumes mounted into the helper or a service container (e.g., a shared cache volume, `/builds/.../..` style traversal into sibling project directories, or into a bind-mounted host/shared path). This breaks the workspace-confinement invariant: file operations during artifact/cache extraction must stay within the intended extraction root, and a job should not be able to place files in locations later read/executed by a helper or another job/service with a different, more privileged identity.

### Likelihood Explanation
This is highly reachable and repeatable: any pipeline author can control artifact and cache zip contents directly (via `zip`-crafted uploads or by controlling files placed into a cache/artifact prior to upload with crafted names, e.g. via untar/rename tricks, or by directly crafting the archive bytes if uploading raw artifact archives is possible). Extraction occurs automatically whenever the runner restores a cache or downloads dependent-job artifacts, with no interactive step and no existing validation beyond the `.git` check. No special runner/executor privilege escalation is required to trigger the write — only the ability to supply an artifact/cache archive, which is a normal, unprivileged CI capability.

### Recommendation
In `extractZipFile` (and the analogous entry helpers), sanitize every `file.Name` before use: reject entries whose `filepath.Clean` result is absolute or begins with `..`/contains a `..` segment that escapes the extraction root, or resolve `filepath.Join(root, file.Name)` and verify (e.g., via `filepath.Rel` or a prefix check post-`Clean`) that the result stays under `root` before calling `MkdirAll`/`OpenFile`/`Symlink`/`Mkdir`. Apply the same containment check to symlink targets to prevent planting symlinks that point outside the workspace.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go` style:
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmpRoot := t.TempDir()
    extractDir := filepath.Join(tmpRoot, "workspace")
    require.NoError(t, os.MkdirAll(extractDir, 0o755))

    // build malicious zip with traversal entry
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../../outside/payload.txt")
    _, _ = w.Write([]byte("evil"))
    require.NoError(t, zw.Close())

    origWD, _ := os.Getwd()
    require.NoError(t, os.Chdir(extractDir))
    defer os.Chdir(origWD)

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    err = archives.ExtractZipArchive(zr)
    require.NoError(t, err)

    // Assert the file was NOT written outside extractDir
    escaped := filepath.Join(tmpRoot, "outside", "payload.txt")
    _, statErr := os.Stat(escaped)
    assert.True(t, os.IsNotExist(statErr), "zip slip: file escaped extraction root: %s", escaped)
}
```
Expected current (vulnerable) behavior: the assertion fails because `payload.txt` is created at `tmpRoot/outside/payload.txt`, outside `extractDir`. After adding root-containment validation, the test should pass (file rejected or extracted only within `extractDir`). [1](#0-0) [2](#0-1) [3](#0-2)

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
