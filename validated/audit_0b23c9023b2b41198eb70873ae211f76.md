### Title
Path-traversal bypass in `fileArchiver.findRelativePathInProject` via `..` segments embedded after a glob wildcard in `cache.paths`/`--exclude` - ([File: commands/helpers/file_archiver.go])

### Summary
`findRelativePathInProject` only validates that the *literal, non-wildcard* prefix (`base`) of a `cache.paths`/`cache.exclude` entry stays inside the project working directory. The wildcard suffix (`patt`) returned by `doublestar.SplitPattern` is re-attached to the validated `rel` via `filepath.Join`/`filepath.Clean` *after* the containment check runs, so `..` segments placed inside the wildcard portion (e.g. `sub/**/../../../etc/*`) are lexically collapsed by `filepath.Join`, letting the resulting path escape the project directory even though the check appeared to pass.

### Finding Description
In `commands/helpers/file_archiver.go`:
```
191: func (c *fileArchiver) findRelativePathInProject(path string) (string, error) {
...
199:	if strings.ContainsAny(slashPath, "*?[{") {
200:		base, patt = doublestar.SplitPattern(slashPath)
201:	}
203:	abs, err := filepath.Abs(base)
208:	rel, err := filepath.Rel(c.wd, abs)
214:	if strings.HasPrefix(rel, ".."+string(filepath.Separator)) || rel == ".." {
215:		return "", fmt.Errorf(...)
216:	}
219:	rel = filepath.Join(rel, patt)
220:	rel = filepath.FromSlash(rel)
221:	return rel, nil
222: }
```
`doublestar.SplitPattern` splits the input only at the first path segment containing a wildcard metacharacter (`*`, `?`, `[`, `{`). Everything from that segment onward — including any literal `..` components that appear *after* the first wildcard segment — is returned as `patt`, not `base`. The containment check at line 214 is performed only on `rel` (derived from `base`), before `patt` is joined back in. Because `filepath.Join` internally calls `filepath.Clean`, which lexically resolves `..` regardless of whether the preceding component was a real directory or a glob token like `**`, a pattern such as:

```
sub/**/../../../../etc/*
```//
splits into `base = "sub"`, `patt = "**/../../../../etc/*"`. `base` resolves safely inside the working directory and passes the check. Then `filepath.Join(rel, patt)` cleans the whole string lexically, canceling `sub`, `**`, and further `..` segments, producing a final `rel` such as `../../etc/*` that lies outside `c.wd`. This value is returned as if validated, and `processPath` (`commands/helpers/file_archiver.go:152-164`) hands it directly to `doublestar.FilepathGlob(rel, ...)` without any further containment check — the only defensive check in the whole call chain already ran and passed on the pre-join value.

This is reachable from the `cache-archiver` command (`commands/helpers/cache_archiver.go:296` `c.enumerate()`) whenever a job defines `cache.paths` (or `cache.exclude` via `isExcluded`, `commands/helpers/file_archiver.go:103-121`) with attacker-controlled glob strings — a standard, unprivileged `.gitlab-ci.yml` field fully controlled by the pipeline author.

### Impact Explanation
A job author can cause the cache archiver to read and package files from outside the project's working/build directory into the uploaded cache archive (which the job's own project can later download), or use the same crafted exclude pattern to bypass exclusion logic. Concretely this breaks the "file operations must stay within intended build/cache/artifact roots" invariant: an unprivileged pipeline can exfiltrate files elsewhere on the runner's filesystem (subject to OS file permissions of the job process) into the cache/artifact stream, which is a real sandbox-escape-adjacent bug rather than a documented trust boundary.

### Likelihood Explanation
No special privileges are required beyond authoring/editing a `.gitlab-ci.yml` `cache.paths` (or `cache.exclude`) entry — something any project maintainer/developer with pipeline-editing rights can do. The crafted pattern (`something/**/../../../etc/*` style) is easy to construct and deterministic; `filepath.Join`'s lexical `..` collapsing behavior is stable across Go versions, making the bypass reliably reproducible.

### Recommendation
Validate containment on the **final** joined path, not just the pre-join `base`. After computing `rel = filepath.Join(rel, patt)`, re-run the `strings.HasPrefix(rel, ".."+sep) || rel == ".."` check (or better, reject any `patt` containing literal `..` path segments before joining, since a legitimate glob into the project tree never needs to escape via `..`). Alternatively, resolve/clean the full pattern first and confirm the cleaned literal directory components lie under `c.wd` before invoking `doublestar.FilepathGlob`.

### Proof of Concept
Go unit test to add to `commands/helpers/file_archiver_test.go`:
```go
func TestFindRelativePathInProject_TraversalViaGlobSuffix(t *testing.T) {
    wd, _ := os.Getwd()
    build := filepath.Join(wd, "build_root")
    require.NoError(t, os.MkdirAll(filepath.Join(build, "sub"), 0o755))
    defer os.RemoveAll(build)

    c := &fileArchiver{wd: build}

    // crafted pattern: literal base is inside build dir, but the
    // pattern segment smuggles ".." to climb back out.
    rel, err := c.findRelativePathInProject("sub/**/../../../etc/*")
    require.NoError(t, err)

    // Assert the bug: rel escapes build dir despite no top-level error
    absRel, _ := filepath.Abs(filepath.Join(build, rel))
    relToBuild, _ := filepath.Rel(build, absRel)
    assert.True(t, strings.HasPrefix(relToBuild, ".."),
        "expected escaped path, got %q (rel=%q)", relToBuild, rel)
}
```
Expected result on the vulnerable code: the assertion passes (i.e., `rel` resolves outside `build`), demonstrating that the containment check is bypassed. A companion integration test can point `cache-archiver --path` at such a pattern and confirm the produced archive contains files from outside the job's working directory.
