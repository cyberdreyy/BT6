### Title
Termination unstake trusts the staking pool's self-reported balance, letting an attacker-controlled pool under-report the deficit - ([File: lockup/src/foundation_callbacks.rs])

### Summary
The termination state machine advances to `EverythingUnstaked` based solely on the value returned by an external staking pool's `get_account_staked_balance` view call, with no cross-check against the lockup's own `staking_information.deposit_amount`. Since a lockup owner freely chooses both the `staking_pool_whitelist_account_id` and the staking pool at `select_staking_pool`, an attacker can deploy a malicious "pool" that under-reports the staked balance so the unstake covers less than the true deficit, letting the attacker retain unvested tokens the Foundation should have clawed back.

### Finding Description
The broken binding is: `amount_unstaked_for_termination == true_staked_balance_for_this_account_in_the_pool`. The code instead enforces `amount_unstaked_for_termination == staked_balance` where `staked_balance` is whatever value the (attacker-controlled) pool contract chooses to return.

Path:
1. `LockupFactory::create` is payable/open to anyone, and `LockupContract::new` takes `staking_pool_whitelist_account_id` and (later) `foundation_account_id`/`vesting_schedule` directly from the caller [1](#0-0) .
2. `select_staking_pool` only checks whitelisting against whatever whitelist contract the owner supplied at creation - an attacker deploys their own "whitelist" that always returns `true`, and their own "pool" contract [2](#0-1) .
3. Owner (attacker) deposits/stakes real NEAR into that self-controlled pool via `deposit_and_stake`/`stake`, physically moving locked/unvested NEAR into an account the attacker fully controls [3](#0-2) .
4. When the Foundation later calls `terminate_vesting` and `termination_prepare_to_withdraw`, the contract queries `get_account_staked_balance` from the attacker's pool and unconditionally trusts the returned value as the amount to unstake [4](#0-3) .
5. `on_get_account_staked_balance_to_unstake` issues `unstake(staked_balance)` for exactly that (possibly under-reported) amount and, on success, unconditionally transitions to `TerminationStatus::EverythingUnstaked` - there is no check that `staked_balance` matches the previously tracked `deposit_amount` or actual pool holdings [5](#0-4) .
6. `on_staking_pool_unstake_for_termination` only checks `is_promise_success()` (i.e., that the unstake call didn't fail), not that the unstaked amount actually equals the deficit, before marking the account `EverythingUnstaked` [6](#0-5) .
7. The subsequent withdrawal step (`termination_withdraw`) then only transfers `min(get_terminated_unvested_balance(), get_account_balance())` to the Foundation-designated receiver [7](#0-6) . Because the pool under-reported, `get_account_balance()` never reflects the true deficit, so the Foundation is paid less than the unvested amount, while the remainder stays parked in the attacker's own malicious pool contract - money the attacker already fully controls.

None of `assert_self`, `is_promise_success`, or `assert_called_by_foundation` protect against this, because they validate call authorization/promise success, not the semantic correctness of the externally-reported balance. There is no assertion anywhere in this callback chain comparing the reported `staked_balance`/`unstaked_balance` against `self.staking_information.deposit_amount` (the lockup's own bookkeeping of what it deposited), which is the only internal reference value that could have caught the discrepancy.

The `release_duration = Some(0)` detail from the question is orthogonal reinforcement: it merely ensures that once `lockup_timestamp`/`lockup_duration` passes, the full "vested-but-locked" concept collapses immediately to available balance so that any recovered amount is materially the deficit, making the shortfall directly quantifiable/exploitable rather than being masked by an additional gradual release schedule.

### Impact Explanation
Unvested/locked NEAR that should be clawed back and transferred to the NEAR Foundation upon `terminate_vesting` is instead permanently retained inside a pool contract the attacker (the terminated lockup's own owner) deployed and controls. This is locked/unvested lockup tokens effectively released to (or rather, never taken away from) a party not entitled to them - the terminated employee/owner - matching the Critical impact category. It is repeatable per malicious pool/lockup instance the attacker deploys, and the blast radius is limited to lockups where the owner picked a malicious whitelist+pool pair before termination (which is exactly the scenario this repo's design allows an unprivileged owner to set up).

### Likelihood Explanation
Preconditions are fully within an unprivileged actor's control: deploy a lockup via the open `LockupFactory::create`, deploy a "whitelist" contract that always returns `true`, deploy a "pool" contract that under-reports `get_account_staked_balance`/`get_account_unstaked_balance`, select that pool as owner, stake real funds into it, and wait for a vesting schedule + Foundation-initiated termination to occur. No foundation, multisig, or owner-of-victim-account privileges are required - the attacker is the owner of their own lockup contract, which is a legitimate unprivileged position obtainable by anyone. The attack cost is only gas/deployment cost and is fully repeatable across any number of self-created lockups.

### Recommendation
Before transitioning to `TerminationStatus::EverythingUnstaked` in `on_staking_pool_unstake_for_termination`, and before accepting the queried `staked_balance` in `on_get_account_staked_balance_to_unstake`, cross-validate the externally reported balance against `self.staking_information.deposit_amount` (and/or require unstaking the full known deposited balance, not just the pool-reported staked amount). Consider requiring the termination flow to call `unstake_all` semantics driven by internally tracked deposit accounting rather than blindly trusting an external view call, and/or track a running total across staking operations that is reconciled independently of what the pool self-reports.

### Proof of Concept
```
cargo test -p lockup termination_under_reporting_pool
```
Test plan (near-sdk `testing_env!` unit test mirroring existing patterns in `lockup/src/lib.rs` tests):
1. Create a lockup with `vesting_schedule = Some(...)`, `foundation_account_id = Some(account_foundation())`, `release_duration = Some(0)`.
2. As owner, `select_staking_pool("malicious_pool")`, then `deposit_and_stake(amount)` for the full lockup amount (simulate via `on_staking_pool_deposit_and_stake` callback with `PromiseResult::Successful`).
3. As foundation, call `terminate_vesting(None)`; assert `unvested_amount.0 > 0` and status becomes `VestingTerminatedWithDeficit`.
4. Call `termination_prepare_to_withdraw()`; then simulate the pool's malicious response by calling `on_get_account_staked_balance_to_unstake` with `staked_balance` set to e.g. half of the real staked `deposit_amount`.
5. Simulate `on_staking_pool_unstake_for_termination(half_amount)` with `PromiseResult::Successful`; assert status becomes `EverythingUnstaked` even though `half_amount < deposit_amount`.
6. Continue the withdrawal steps (`on_get_account_unstaked_balance_to_withdraw` / `on_staking_pool_withdraw_for_termination`) with the same half amount, then call `termination_withdraw(receiver)`.
7. Assert on both sides of the invariant: `amount_paid_to_receiver == half_amount < true_unvested_amount` (i.e., `get_terminated_unvested_balance().0 > 0` remains after `on_withdraw_unvested_amount` completes, or `self.foundation_account_id` remains `Some` indicating incomplete recovery) - proving the Foundation never recovers the full deficit while the other half stays in the attacker's "malicious_pool" account, which the attacker already controls.

    pub fn termination_withdraw(&mut self, receiver_id: AccountId) -> Promise {
        self.assert_called_by_foundation();
        assert!(
            env::is_valid_account_id(receiver_id.as_bytes()),
            "The receiver account ID is invalid"
        );
        assert_eq!(
            self.get_termination_status(),
            Some(TerminationStatus::ReadyToWithdraw),
            "Termination status is not ready to withdraw"
        );

        let amount = std::cmp::min(
            self.get_terminated_unvested_balance().0,
            self.get_account_balance().0,
        );
        assert!(
            amount > 0,
            "The account doesn't have enough liquid balance to withdraw any amount"
        );

        env::log(
            format!(
                "Termination Step: Withdrawing {} of terminated unvested balance to account @{}",
                amount, receiver_id
            )
            .as_bytes(),
        );

        self.set_termination_status(TerminationStatus::WithdrawingFromAccountInProgress);

        Promise::new(receiver_id.clone()).transfer(amount).then(
            ext_self_foundation::on_withdraw_unvested_amount(
                amount.into(),
                receiver_id,
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::foundation_callbacks::ON_WITHDRAW_UNVESTED_AMOUNT,
            ),
        )
    }

    pub fn on_get_account_staked_balance_to_unstake(
        &mut self,
        #[callback] staked_balance: WrappedBalance,
    ) -> PromiseOrValue<bool> {
        assert_self();
        if staked_balance.0 > 0 {
            // Need to unstake
            env::log(
                format!(
                    "Termination Step: Unstaking {} from the staking pool @{}",
                    staked_balance.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );

            ext_staking_pool::unstake(
                staked_balance,
                &self
                    .staking_information
                    .as_ref()
                    .unwrap()
                    .staking_pool_account_id,
                NO_DEPOSIT,
                gas::staking_pool::UNSTAKE,
            )
            .then(
                ext_self_foundation::on_staking_pool_unstake_for_termination(
                    staked_balance,
                    &env::current_account_id(),
                    NO_DEPOSIT,
                    gas::foundation_callbacks::ON_STAKING_POOL_UNSTAKE_FOR_TERMINATION,
                ),
            )
            .into()
        } else {
            env::log(b"Termination Step: Nothing to unstake. Moving to the next status.");
            self.set_staking_pool_status(TransactionStatus::Idle);
            self.set_termination_status(TerminationStatus::EverythingUnstaked);
            PromiseOrValue::Value(true)
        }
    }

    pub fn on_staking_pool_unstake_for_termination(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let unstake_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if unstake_succeeded {
            self.set_termination_status(TerminationStatus::EverythingUnstaked);
            env::log(
                format!(
                    "Termination Step: Unstaking of {} at @{} succeeded",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        } else {
            self.set_termination_status(TerminationStatus::VestingTerminatedWithDeficit);
            env::log(
                format!(
                    "Termination Step: Unstaking {} at @{} has failed",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        }
        unstake_succeeded
    }
