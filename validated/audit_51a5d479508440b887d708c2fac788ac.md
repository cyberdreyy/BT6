Based on my investigation, the strongest analog to the reported bug class ("state-changing entrypoint reachable by anyone, with no validation of who the legitimate caller should be") is in the Chainlink Gateway's legacy WebAPI capabilities handler.

### Title
Gateway `WebAPIHandler.HandleLegacyUserMessage` forwards unauthenticated trigger requests to the DON without an allowlist check - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The external report's root cause is a privileged/state-changing entrypoint (`onTokenTransfer`) that accepts calls from any unprivileged caller because it never validates that the caller is the entity it was designed to trust (the DATA token contract). The same bug class is present in Chainlink's internet-facing Gateway: `handler.HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` accepts and forwards any structurally-valid, self-signed message from the public gateway HTTP endpoint to every member of the DON, with an explicit `// TODO: apply allowlist and rate-limiting here` marking the missing sender authorization check.

### Finding Description
The gateway's public entrypoint `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) decodes and calls `msg.Validate()` [1](#0-0) , which only checks structural constraints (ID/method/DonId lengths, receiver length) and that the ECDSA signature is self-consistent — it recovers the signer from the signature and sets `Body.Sender` to whatever address signed the payload [2](#0-1) . Anyone can generate an arbitrary keypair, sign a message with it, and pass validation — `Validate()` never checks the sender against any allowlist of authorized workflow owners/DONs.

The message is then routed to `handler.HandleLegacyUserMessage` [3](#0-2) . This function checks payload decodability, a `Timestamp` field, and staleness, then hits the explicit comment:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger {
``` [4](#0-3) 

No check is performed to confirm the sender is a party authorized to trigger workflows for this DON. The handler then stores a callback keyed by `MessageId` and forwards the request to every DON member: [5](#0-4) .

### Impact Explanation
Because the sender is never checked against an allowlist, an unprivileged internet client can:
- Cause the gateway to forward arbitrary `web_api_trigger` messages to every node in a DON, consuming node/gateway resources.
- Fill the bounded `savedCallbacks` map (capacity `defaultMaxSavedCallbacks = 20000`, pruned periodically) with attacker-controlled entries [6](#0-5) , which is the same DoS pattern as the `OperatorFactory::onTokenTransfer` case in the external report (attacker abuses an unauthenticated entrypoint to exhaust a resource / block legitimate use).
- Trigger downstream workflow execution paths on DON nodes with attacker-supplied payloads if node-side capability trigger logic (e.g. `webapicap`) does not independently re-verify the sender is authorized — this needs further confirmation on the node side.

### Likelihood Explanation
The gateway HTTP endpoint is explicitly internet-facing and designed to accept external, unauthenticated client requests (that is its purpose), so this path is trivially reachable by any external actor with no credentials. The missing check is also self-documented by the author via the `TODO` comment, indicating this is a known gap rather than a redundant control implemented elsewhere.

### Recommendation
Add sender allowlist validation in `HandleLegacyUserMessage` (and equivalently in the JSON-RPC path if applicable) before forwarding to the DON — verifying `msg.Body.Sender` against the DON's configured/authorized caller list — and add rate-limiting per sender, consistent with the `// TODO` already present in the code.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (no relationship to any legitimate/authorized workflow owner).
2. Construct a legacy gateway `Message` with `DonId` set to a known DON, `Method = "web_api_trigger"`, and a `TriggerRequestPayload` with a fresh `Timestamp`.
3. Sign the message with the arbitrary key so `Message.Validate()` succeeds (it only verifies self-consistency of signature and sender, not whether the sender is authorized).
4. Submit the message via the gateway's public request endpoint (`gateway.ProcessRequest`); observe `HandleLegacyUserMessage` accepts it (no allowlist check per the `TODO`), stores a callback, and forwards the request to all DON members.
5. Repeat to fill `savedCallbacks` and burden the DON with unauthorized trigger traffic.

**Caveat:** I could not fully verify within tool budget whether an allowlist check exists further downstream on the DON/node side (e.g., inside `webapicap` trigger processing) that would mitigate impact, nor whether this legacy `handler.go` path is still actively wired into production DON configs versus superseded by `capabilities/v2/http_handler.go`. This should be confirmed by an engineer with full repository access before treating this as fully validated.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}
