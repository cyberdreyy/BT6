## Analysis

The external report describes CSRF/DNS-rebinding against an **unauthenticated local HTTP server** that blindly trusts any POST it receives. The `stacks-signer` binary runs exactly such a server: `SignerEventReceiver` in `libsigner/src/events.rs` opens a `tiny_http::Server` and, on `next_event()`, dispatches any POST to `/proposal_response`, `/stackerdb_chunks`, `/new_burn_block`, `/new_block`, or `/shutdown` straight into `process_event()` — with **no Authorization header, no auth token, and no peer/source check whatsoever**. [1](#0-0) [2](#0-1) 

Contrast this with the node-side `/v3/block_proposal` RPC endpoint, which explicitly documents `auth_token`/basic-auth requirements, and the sample configs which bind the signer's listener to `0.0.0.0:30000` by default. [3](#0-2) 

A forged `/proposal_response` POST containing a `BlockValidateResponse::Ok` for a `signer_signature_hash` the signer already knows about (from public StackerDB gossip of the miner's `BlockProposal`) is deserialized and forwarded as `SignerEvent::BlockValidationResponse`, which the runloop dispatches to `handle_block_validate_ok` — the same path used for genuine, node-verified validation results — advancing the block straight to pre-commit/signature without any real chainstate validation ever having occurred. [4](#0-3) 

### Title
Unauthenticated Signer Event-Receiver HTTP Endpoint Allows Forged Block-Validation Verdicts to Bypass Real Chainstate Validation - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` accepts and processes POST requests on `/proposal_response`, `/stackerdb_chunks`, `/new_burn_block`, `/new_block`, and `/shutdown` with zero authentication, source validation, or even a shared-secret check comparable to the node's `auth_token`. Any network peer able to reach the bound port (`0.0.0.0:<port>` per the shipped sample configs) can submit a forged `BlockValidateResponse::Ok` body that is indistinguishable, from the signer runloop's perspective, from a genuine verdict returned by the trusted `stacks-node` after real chainstate/transaction validation.

### Finding Description
The signer's block-signing state machine is supposed to enforce: propose → submit to node's `/v3/block_proposal` → node validates chainstate/txs → node POSTs verdict back to signer's listener → signer acts on verdict. The equality being relied upon is "validated (by the node) implies acted-upon (by the signer)". `next_event` routes `/proposal_response` bodies straight into `process_event::<T, BlockValidateResponse>`, which JSON-deserializes the attacker-controlled body into `BlockValidateResponse` and converts it via `TryFrom<BlockValidateResponse> for SignerEvent<T>` with no provenance check at all: [5](#0-4) 

This event is forwarded unmodified to the signer runloop, which calls `handle_block_validate_response` → `handle_block_validate_ok`. That handler only requires that the referenced `signer_signature_hash` already correspond to a `block_info` the signer is tracking (`block_lookup_by_reward_cycle`) and that `block_info.valid` is still `None` — i.e., that a genuine node response for this exact block is still outstanding: [6](#0-5) 

If those two conditions hold, the forged "Ok" verdict is accepted exactly as if it came from the node: `submitted_block_proposal` is cleared, `check_block_against_signer_db_state` is (re-)run against the signer's own local DB state (not against a freshly executed chainstate), and on success the block is marked pre-committed and `send_block_pre_commit`/`handle_block_pre_commit` is invoked — pushing the block toward the pre-commit/signature threshold: [7](#0-6) 

The `signer_signature_hash` needed to target a specific pending proposal is not a secret — it is the hash of a `NakamotoBlockHeader` that the miner already gossiped to all signers over the public `.miners` StackerDB contract as a `BlockProposal`, so any observer of that gossip (which requires no signer key or auth token) knows the exact hash to forge a response for.

### Impact Explanation
This breaks the "signed vs. validated" equality that the whole node/signer split is built on: a signer can be induced to sign a pre-commit/signature for a block that the trusted node never actually validated (e.g. one still queued or timed-out in real validation), because the forged verdict short-circuits `submit_block_for_validation`'s real chainstate check. Depending on timing, this can help push an invalid/never-actually-validated block toward the 70% weight threshold needed for a full block signature, i.e. exactly the "signer signing an invalid/non-canonical/conflicting block" critical-impact class in scope. It also functions as a liveness/DoS primitive: a forged `/shutdown` POST unconditionally terminates the event receiver thread (`event_receiver.stop_signal.store(true, ...)` then `Err(EventError::Terminated)`), wedging that signer out of the protocol entirely, since nothing checks who sent the shutdown request: [8](#0-7) 

### Likelihood Explanation
Requires only network/local reachability to the signer's listener port (bound `0.0.0.0` in the shipped reference configs) and knowledge of a currently-pending `signer_signature_hash`, both obtainable without any signer key, auth token, or majority collusion — a single miner or any network-adjacent host can attempt this against a signer whose event-receiver port is exposed.

### Recommendation
Require the event receiver to authenticate incoming POSTs from the node (e.g. a shared secret/HMAC analogous to the node's `connection_options.auth_token`, checked on every request in `next_event`/`process_event`), and default-bind the listener to `127.0.0.1` rather than `0.0.0.0` unless explicitly configured otherwise. At minimum, `/shutdown` and `/proposal_response` should require proof the request originated from the paired, configured `stacks-node`.

### Proof of Concept
1. Observe a miner's `BlockProposal` gossiped via the public `.miners` StackerDB contract; compute/read its `signer_signature_hash`.
2. While the signer's own `submitted_block_proposal` for that hash is still outstanding (i.e. before the real node response arrives), send `POST /proposal_response` to the signer's bound endpoint (e.g. `0.0.0.0:30000`) with a JSON body matching `BlockValidateResponse::Ok { signer_signature_hash, cost: zero, size, validation_time_ms, replay_tx_hash: None, replay_tx_exhausted: false }` and no Authorization header.
3. Observe `next_event` accept it via `process_event::<T, BlockValidateResponse>` with no auth check, and the runloop invoke `handle_block_validate_ok`, marking the block pre-committed and issuing `send_block_pre_commit`/signature progression without the real node ever validating the block's chainstate/transactions.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)

                    url

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
