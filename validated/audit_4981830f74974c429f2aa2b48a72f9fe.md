### Title
Password rotation does not invalidate the acting session, allowing a pre-stolen session cookie to survive credential rotation - ([File: core/web/user_controller.go])

### Summary
`(*UserController).updateUserPassword` calls `orm.ClearNonCurrentSessions(ctx, sessionID)` which deletes every session row for the user *except* the one identified by the current `sessionID`, and never calls `DeleteUserSession` or rotates the session ID for that current session. If an attacker obtained the victim's session cookie before the victim performs `PATCH /user/password`, and that cookie is the one used to submit the password-change request (the "current" session), the attacker's copy of the same cookie continues to authenticate indefinitely after the password rotation.

### Finding Description
`UpdatePassword` (route handler for `PATCH /user/password`) validates the old password and complexity of the new one, then calls `u.updateUserPassword(c, &user, request.NewPassword)` [4](#0-3) . That helper reads the current session ID from the gin session cookie via `getCurrentSessionID`, then calls `orm.ClearNonCurrentSessions(ctx, sessionID)` before `orm.SetPassword` [3](#0-2) .

`ClearNonCurrentSessions` explicitly preserves the row matching `sessionID`: `DELETE FROM sessions WHERE lower(email) = lower($1) AND id != $2` [2](#0-1) . There is no companion call to `DeleteUserSession` (which does exist and issues `DELETE FROM sessions WHERE id = $1`) [5](#0-4)  for the acting session, and no session-ID regeneration.

Every subsequent request is authenticated purely by looking up the `sessions` table row for the cookie's session ID via `AuthorizedUserWithSession`, which re-fetches the user and refreshes `last_used`, but performs no independent check that the session was created before the last password change [1](#0-0) ; `AuthenticateBySession` simply trusts the stored cookie's `clsession_id` value [6](#0-5) .

Given the precondition that an attacker already possesses the victim's session cookie prior to the password change, and the victim performs the password change using that same still-live browser session (the common real-world flow — a user proactively rotates credentials from their currently logged-in session after suspecting compromise), the session ID used for the `PATCH /user/password` request is exactly the one the attacker also holds. Because that ID is excluded from `ClearNonCurrentSessions`, the attacker's copy of the cookie remains valid in the `sessions` table and continues to authenticate as the victim after the rotation, defeating the security purpose of the password change.

### Impact Explanation
This is a session/credential-rotation bypass: an already-hijacked session survives a legitimate password change, so the intended remediation action (changing the password to lock out an attacker) fails for the specific session the attacker is using. Depending on the victim's role, the attacker retains authenticated access to the node's admin API (job management, keys, bridges, etc.) — this maps to an authentication-bypass / broken session-invalidation impact class, with actions performed by the attacker still attributable to the victim's session.

### Likelihood Explanation
The only precondition is that the attacker already holds a valid session cookie for the victim (assumed given per the audit scope) and that the victim changes their password using that same still-active session — a realistic and common flow (e.g., a user changing password from an open browser tab). No additional privilege or exploitation technique is required beyond replaying the stolen cookie after the victim's `PATCH /user/password` call; the gap is deterministic and repeatable every time.

### Recommendation
On password change, invalidate/rotate the acting session as well: either call `DeleteUserSession` for the current `sessionID` in addition to `ClearNonCurrentSessions` (forcing re-authentication and re-establishing a fresh session in the response), or issue a new session ID for the just-authenticated request after the password update and delete the old one. This ensures no stale session ID — attacker-held or otherwise — can outlive a credential rotation.

### Proof of Concept
Handler-level integration test plan (Go):
1. Create a user and call `CreateSession` to obtain `sessionID_A`; store it as the "victim" cookie and duplicate it as the "attacker" cookie (simulating theft).
2. Using cookie `sessionID_A`, call `PATCH /user/password` (`UserController.UpdatePassword`) with valid `oldPassword`/`newPassword`; assert `200 OK`.
3. Replay the request `GET /v2/user` (or any authenticated route) using the identical `sessionID_A` cookie ("attacker" copy).
4. Current expected (vulnerable) result: request succeeds (`200`), proving the attacker's stolen session still authenticates post-rotation.
5. Desired assertion after fix: replaying `sessionID_A` after the password change should return `401 Unauthorized`, and only a freshly issued session ID (returned/set at password-change time) should authenticate.

func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

// ClearNonCurrentSessions removes other sessions for the user tied to sessionID.
func (o *orm) ClearNonCurrentSessions(ctx context.Context, sessionID string) error {
	var email string
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1", sessionID); err != nil {
		return err
	}
	_, err := o.ds.ExecContext(ctx, "DELETE FROM sessions WHERE lower(email) = lower($1) AND id != $2", email, sessionID)
	return err
}

func (u *UserController) UpdatePassword(c *gin.Context) {
	ctx := c.Request.Context()
	var request UpdatePasswordRequest
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	user, err := u.App.AuthenticationProvider().FindUser(ctx, sessionUser.Email)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		u.App.GetLogger().Errorf("failed to obtain current user record: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to update password"))
		return
	}
	if !utils.CheckPasswordHash(request.OldPassword, string(user.HashedPassword)) {
		u.App.GetAuditLogger().Audit(audit.PasswordResetAttemptFailedMismatch, map[string]any{"user": user.Email})
		jsonAPIError(c, http.StatusConflict, errors.New("old password does not match"))
		return
	}
	if err := utils.VerifyPasswordComplexity(request.NewPassword, user.Email); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if err := u.updateUserPassword(c, &user, request.NewPassword); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	u.App.GetAuditLogger().Audit(audit.PasswordResetSuccess, map[string]any{"user": user.Email})
	jsonAPIResponse(c, presenters.NewUserResource(user), "user")
}

func (u *UserController) updateUserPassword(c *gin.Context, user *clsession.User, newPassword string) error {
	ctx := c.Request.Context()
	sessionID, err := getCurrentSessionID(c)
	if err != nil {
		return err
	}
	orm := u.App.AuthenticationProvider()
	if err := orm.ClearNonCurrentSessions(ctx, sessionID); err != nil {
		u.App.GetLogger().Errorf("failed to clear non current user sessions: %s", err)
		return errors.New("unable to update password")
	}
	if err := orm.SetPassword(ctx, user, newPassword); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			return errUnsupportedForAuth
		}
		u.App.GetLogger().Errorf("failed to update current user password: %s", err)
		return errors.New("unable to update password")
	}
	return nil
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
