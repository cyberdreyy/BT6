### Title
Truncation of masked-token prefix list in `tokensanitizer.New` allows attacker-controlled prefixes to push out default `glpat-` masking - (File: common/buildlogger/internal/tokensanitizer/token_masker.go)

### Summary
`tokensanitizer.New` hard-caps the number of active masking prefixes at 15 (`count := min(len(prefixes), 15)`), and the full prefix list is built in `buildlogger.New` (`common/buildlogger/build_logger.go`) by appending `opts.MaskTokenPrefixes` (sourced from `b.Job.Features.TokenMaskPrefixes`, `common/build.go:1643`) before the default prefixes and then sorting with `internal.Unique`. Because `internal.Unique` sorts primarily by string length (shortest first), an attacker who supplies enough short bogus prefixes can force the legitimate `glpat-` (6 chars) default prefix past index 15, causing it to be silently dropped from masking.

### Finding Description
The masking prefix list is constructed in `New` (`common/buildlogger/build_logger.go:68-74`):
```go
l.maskTokenPrefixes = internal.Unique(
    append(opts.MaskTokenPrefixes, tokensanitizer.DefaultTokenPrefixes(opts.MaskAllDefaultTokens)...),
)
``` [1](#0-0) 

`opts.MaskTokenPrefixes` is populated directly from `b.Job.Features.TokenMaskPrefixes` at `common/build.go:1643` with no length or content validation: [2](#0-1) 

`internal.Unique` trims, then sorts tokens by length ascending (ties broken alphabetically), and de-duplicates — it does not preserve caller-supplied ordering or prioritize the "default" entries: [3](#0-2) 

Finally, `tokensanitizer.New` only instantiates masking writers for the first 15 entries of whatever list it receives, silently discarding the rest: [4](#0-3) 

Because sorting is by length first, an attacker who supplies ≥15 short prefixes (e.g. single/double-character strings shorter than `"glpat-"`, which is 6 bytes) guarantees those bogus prefixes occupy the first 15 slots after sorting, pushing `glpat-` (and any other longer default prefix) beyond the truncation cutoff. The result: `tokensanitizer.New` never creates a masking writer for `glpat-`, so any real `glpat-`-prefixed token echoed later in the job's log output will not be masked.

### Impact Explanation
If a job can control `Job.Features.TokenMaskPrefixes` and supply crafted short values, the default masking guarantee for GitLab Personal/Project Access Tokens (`glpat-`) can be defeated. Any real `glpat-` token that ends up in job output (e.g. via a misconfigured variable, an accidentally printed secret, or a token embedded in a URL/log line) would then be exposed in plaintext in the job trace, which may be visible to other users/projects with access to that trace (e.g. shared traces, artifacts, or trace export), constituting token exfiltration.

### Likelihood Explanation
The exploit requires only that the attacker's job payload sets `Job.Features.TokenMaskPrefixes` with ≥15 entries shorter than `"glpat-"`. Whether a pipeline author can directly influence this field depends on how `Job.Features` is populated by the GitLab backend when dispatching a job to the Runner — this repository does not show the full backend/API-side logic that decides the contents of `Features.TokenMaskPrefixes`, so it can't be fully confirmed from this codebase alone whether it is a raw pass-through of user input or backend-curated. Assuming the stated precondition holds (attacker can set the value via job payload), the mechanism in `tokensanitizer.New`/`internal.Unique`/`build_logger.New` is deterministic and 100% reproducible — no timing or race conditions involved.

### Recommendation
- Always guarantee that default prefixes (`tokensanitizer.DefaultTokenPrefixes`) are included in the active masking set regardless of how many attacker-supplied prefixes are present — e.g., reserve slots for defaults and truncate only the caller-supplied prefixes, not the combined+sorted list.
- Change `internal.Unique`/`tokensanitizer.New` so truncation happens only on the untrusted portion of the list (`opts.MaskTokenPrefixes`), before appending the trusted defaults, instead of sorting/truncating the merged list.
- Add a unit/fuzz test asserting that regardless of the number or length of caller-supplied prefixes, `glpat-` masking is always active.

### Proof of Concept
```go
func TestTokenSanitizer_DefaultPrefixSurvivesTruncation(t *testing.T) {
    // simulate attacker-supplied prefixes: 20 short bogus prefixes
    var attacker []string
    for i := 0; i < 20; i++ {
        attacker = append(attacker, fmt.Sprintf("a%d-", i)) // all shorter than "glpat-"
    }

    opts := buildlogger.Options{
        MaskTokenPrefixes: attacker,
    }

    var buf bytes.Buffer
    logger := buildlogger.New(nopTrace{&buf}, logrus.NewEntry(logrus.New()), opts)
    w := logger.Stream(buildlogger.StreamWorkLevel, buildlogger.Stdout)

    token := "glpat-AAAAAAAAAAAAAAAAAAAA"
    fmt.Fprint(w, token)
    w.Close()

    // Expected: token masked
    assert.NotContains(t, buf.String(), token)
    assert.Contains(t, buf.String(), "[MASKED]")
}
```
Expected result if bug is present: the assertion fails because `glpat-...` appears unmasked in `buf.String()`, confirming that the 20 bogus short prefixes displaced the default `glpat-` prefix out of the first-15 cutoff in `tokensanitizer.New`.

func Unique(tokens []string) [][]byte {
	for idx, token := range tokens {
		tokens[idx] = strings.TrimSpace(token)
	}

	slices.SortFunc(tokens, func(a, b string) int {
		switch {
		case len(a) < len(b):
			return -1
		case len(a) > len(b):
			return 1
		}

		return cmp.Compare(a, b)
	})

	compact := slices.Compact(tokens)
	unique := make([][]byte, 0, len(compact))
	for _, token := range compact {
		if token == "" {
			continue
		}
		unique = append(unique, []byte(token))
	}

	return unique
}

// New returns a new TokenSanitizer.
// We only allow 10 token prefixes at the moment. Everything else is being silently ignored
func New(w io.WriteCloser, prefixes [][]byte) *TokenSanitizer {
	m := &TokenSanitizer{}
	m.next = w

	count := min(len(prefixes), 15)

	for i := 0; i < count; i++ {
		m.next = &tokenSanitizer{next: m.next, prefix: prefixes[i]}
	}

	return m
}
