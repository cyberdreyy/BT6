### Title
Bridge creation lacks SSRF/allowlist validation on `url` field, allowing bridges pointed at internal-only hosts - ([File: core/web/bridge_types_controller.go])

### Summary
`ValidateBridgeType` in `core/web/bridge_types_controller.go` only checks that the bridge `Name` is non-empty/valid and that the `URL` string is non-empty after trimming whitespace; it performs no scheme, hostname, or IP-range validation. An edit-role-authenticated user can therefore register a bridge whose `url` points at an internal/link-local address (e.g. `http://169.254.169.254/`), and every job that later references this bridge will cause the node to make outbound HTTP requests to that internal target via the bridge task runner. [1](#0-0) 

### Finding Description
The `Create` and `Update` handlers on `BridgeTypesController` bind the request body into a `bridges.BridgeTypeRequest` and call `ValidateBridgeType(btr)` before persisting the bridge via `orm.CreateBridgeType`/`orm.UpdateBridgeType`. [2](#0-1) [3](#0-2) 

`ValidateBridgeType` itself does the following checks on the URL:
```go
u := bt.URL.String()
if len(strings.TrimSpace(u)) == 0 {
    fe.Add("URL must be present")
}
```
There is no allowlist, scheme restriction (e.g., blocking `file://`), hostname resolution check, or link-local/private IP range rejection. Any syntactically-present URL string, including `http://169.254.169.254/` (cloud metadata endpoint) or other RFC1918/loopback targets, passes validation and is stored as the bridge's `URL`. [4](#0-3) 

Once created, this bridge can be referenced by any job (bridge task), and the node's HTTP client will issue outbound requests to the stored URL whenever the job runs — attributing the request to the bridge/job rather than exposing it as a discretionary action by the creator at request time.

I was unable to fully confirm within this session which minimum role (`UserRoleView`/`UserRoleEdit`/`UserRoleAdmin`) or auth guard is required by the router for `POST /v2/bridge_types`, since my last route/role lookups did not return conclusive results before the session ended. This is a gap in my verification — it should be confirmed that an edit-role token (not just admin) is sufficient to hit this endpoint before treating this as fully "unprivileged" relative to admin-only bridge management. If bridge creation is restricted to admin-only tokens, the severity assessment below should be revisited (lower likelihood, still a real gap but requiring higher privilege).

### Impact Explanation
This matches Chainlink's SSRF impact class: an attacker with only edit-level bridge-creation credentials (not necessarily full admin/node access) can weaponize the node into an internal request proxy, targeting cloud metadata services (AWS/GCP credential theft), internal-only management APIs, or other services not intended to be externally reachable, with requests originating from the node's own network position and reused persistently by any job wired to the bridge.

### Likelihood Explanation
The bridge-creation code path performs no allowlist or private-IP/link-local checks, so exploitation requires only a single POST to `/v2/bridge_types` (or `PATCH` for update) with an internal URL, with the credential/token issue noted above as the main open question on preconditions. It is trivially repeatable and does not depend on any race condition or timing.

### Recommendation
Add SSRF-hardening in `ValidateBridgeType`: parse the URL, reject non-`http(s)` schemes, resolve the hostname, and reject responses that resolve to loopback, link-local (169.254.0.0/16, fe80::/10), private (RFC1918), or other disallowed ranges unless explicitly allowlisted by node configuration; re-validate at request time (not just DNS-pinning at creation) to prevent DNS-rebinding bypass.

### Proof of Concept
Add a Go unit test in `core/web/bridge_types_controller_test.go` (or a new `_test.go` calling `ValidateBridgeType` directly):
```go
func TestValidateBridgeType_RejectsInternalURL(t *testing.T) {
    btr := &bridges.BridgeTypeRequest{
        Name: bridges.BridgeName("test"),
        URL:  models.WebURL(*mustParseURL("http://169.254.169.254/")),
    }
    err := ValidateBridgeType(btr)
    assert.Error(t, err) // currently fails: err is nil
}
```
Expected: today this assertion fails because `err` is `nil` (only "URL must be present" triggers on empty string), demonstrating the missing allowlist check. After the fix, the test should assert a rejection error for link-local/private targets while still allowing legitimate external HTTPS URLs.

// ValidateBridgeType checks that the bridge type has the required field with valid values.
func ValidateBridgeType(bt *bridges.BridgeTypeRequest) error {
	fe := models.NewJSONAPIErrors()
	if len(bt.Name.String()) < 1 {
		fe.Add("No name specified")
	}
	if _, err := bridges.ParseBridgeName(bt.Name.String()); err != nil {
		fe.Merge(err)
	}
	u := bt.URL.String()
	if len(strings.TrimSpace(u)) == 0 {
		fe.Add("URL must be present")
	}
	if bt.MinimumContractPayment != nil &&
		bt.MinimumContractPayment.Cmp(assets.NewLinkFromJuels(0)) < 0 {
		fe.Add("MinimumContractPayment must be positive")
	}
	return fe.CoerceEmptyToNil()
}

func (btc *BridgeTypesController) Update(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")
	btr := &bridges.BridgeTypeRequest{}

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	orm := btc.App.BridgeORM()
	bt, err := orm.FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := c.ShouldBindJSON(btr); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if err := ValidateBridgeType(btr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := orm.UpdateBridgeType(ctx, &bt, btr); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	btc.App.GetAuditLogger().Audit(audit.BridgeUpdated, map[string]any{
		"bridgeName":                   bt.Name,
		"bridgeConfirmations":          bt.Confirmations,
		"bridgeMinimumContractPayment": bt.MinimumContractPayment,
		"bridgeURL":                    bt.URL,
	})

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
