### Title
SLSA provenance digest can diverge from actual uploaded artifact content due to TOCTOU between metadata hashing and archiving - (File: commands/helpers/artifact_metadata.go / commands/helpers/artifacts_uploader.go)

### Summary
`ArtifactsUploaderCommand.Execute` computes the SLSA in-toto statement (including SHA-256 subject digests) via `generateStatementToFile` -> `generateSubjects`, which opens and hashes each enumerated file, and only afterwards invokes `c.Run()` which triggers the actual archive creation (`archiver.Archive`) that re-reads the same files from disk a second time. Any file content change between these two independent reads produces a provenance statement whose subject digest does not match the bytes that end up in the uploaded artifact archive.

### Finding Description
The call sequence in `commands/helpers/artifacts_uploader.go` `Execute` is:
1. `c.enumerate()` populates `c.files` (a `map[string]os.FileInfo]`) with metadata snapshots only, not content. [1](#0-0) 
2. If `GenerateArtifactsMetadata` is set, `generateStatementToFile` is called, which calls `generateSubjects(opts.files)`. This function opens each file and streams it through `io.Copy` into a SHA-256 hash, producing the `Digest` map embedded in the `ita_v1.ResourceDescriptor` subjects of the SLSA statement. [2](#0-1) 
3. Only after the metadata file is written and processed does `Execute` call `retry.WithFn(c, c.Run).Run()`, which calls `c.createBodyProvider()`. [3](#0-2) 
4. `createBodyProvider` spins up a goroutine that calls `archiver.Archive(context.Background(), c.files)`, passing the *same* `c.files` map of `os.FileInfo` (not content) — the archiver (e.g. `fastzip.archiver.Archive`) opens and reads each file's bytes fresh from disk to build the zip/tar stream that is actually uploaded. [4](#0-3) [5](#0-4) 

There is no re-stat, mtime/size comparison, or content re-verification between the hash computed in step 2 and the bytes archived in step 4. The `os.FileInfo` snapshot from `enumerate()` is reused purely for archive metadata (mode, mtime entries in the zip), not to detect tampering of file contents. Because the artifacts-uploader helper runs as a distinct process after the job script completes, any process still able to write into the job workspace (e.g., a backgrounded/detached process spawned by the job script itself, or another container/service sharing the workspace volume) can modify a file's content in the window between the two disk reads, causing the emitted SLSA digest to describe content that differs from what is actually uploaded.

### Impact Explanation
This breaks the core invariant that the SLSA/in-toto subject digest must reflect the actual bytes of the artifact being attested. A job author (unprivileged, controls their own job's shell script) can arrange for a background process to swap file content after enumeration/hashing but before archiving, producing a cryptographically "clean" attestation while uploading different (e.g., malicious or backdoored) artifact content. Any downstream consumer or verification pipeline that trusts the runner-generated provenance digest without independently re-hashing the archived artifact can be misled — a supply-chain integrity bypass via forged/stale attestation.

### Likelihood Explanation
Feasible and repeatable: an unprivileged job author fully controls the job script and can trivially launch a detached/background process (e.g., `nohup sh -c 'sleep N; overwrite file' &`) before the job script exits, timed to fire during the enumerate→hash→archive window of the separate `artifacts-uploader` helper process. No special runner configuration, privileged container, or admin action is required — only a workspace that both the job and the helper process share, which is the standard case for shell/docker executors running artifacts-uploader against the job's own build directory.

### Recommendation
Compute the artifact archive first (or compute the digest from the same read used to build the archive) so that hashing and archiving operate on a single consistent read of file content. Concretely: refactor `generateSubjects`/`generateStatementToFile` to hash files as they are streamed into the archive (e.g., a `TeeReader` inside `archiver.Archive`) instead of performing a separate, temporally-disjoint `os.Open`+`io.Copy` pass, or re-verify file `os.FileInfo` (size/mtime/inode) immediately before archiving and fail/warn if it differs from the snapshot used for hashing.

### Proof of Concept
Go test sketch in `commands/helpers`:
```go
func TestArtifactMetadata_TOCTOU(t *testing.T) {
    dir := t.TempDir()
    path := filepath.Join(dir, "artifact.txt")
    require.NoError(t, os.WriteFile(path, []byte("original-content"), 0o644))

    fi, err := os.Stat(path)
    require.NoError(t, err)
    files := map[string]os.FileInfo{path: fi}

    g := &artifactStatementGenerator{ /* ... required fields ... */ }

    // Simulate concurrent tamper between enumerate and archive by mutating
    // content right after generateSubjects has computed its digest but
    // before "archiving" reads it again.
    subjects, err := g.generateSubjects(files)
    require.NoError(t, err)
    staleDigest := subjects[0].Digest["sha256"]

    require.NoError(t, os.WriteFile(path, []byte("tampered-content"), 0o644))

    // Simulate the later archive step re-reading the file.
    actual, _ := os.ReadFile(path)
    h := sha256.Sum256(actual)
    actualDigest := hex.EncodeToString(h[:])

    require.NotEqual(t, staleDigest, actualDigest,
        "SLSA subject digest does not match actual archived content - TOCTOU confirmed")
}
```
Expected assertion: `staleDigest != actualDigest`, demonstrating that the SLSA statement's embedded digest can silently diverge from the content that is later archived/uploaded, with no detection or failure in the current code path.

```go
func (g *artifactStatementGenerator) generateSubjects(files map[string]os.FileInfo) ([]*ita_v1.ResourceDescriptor, error) {
	subjects := make([]*ita_v1.ResourceDescriptor, 0, len(files))

	h := sha256.New()
	br := bufio.NewReader(nil)
	subjectGeneratorFunc := func(file string) (*ita_v1.ResourceDescriptor, error) {
		f, err := os.Open(file)
		if err != nil {
			return &ita_v1.ResourceDescriptor{}, err
		}
		defer f.Close()

		br.Reset(f)
		h.Reset()
		if _, err := io.Copy(h, br); err != nil {
			return &ita_v1.ResourceDescriptor{}, err
		}

		return &ita_v1.ResourceDescriptor{
			Name:   file,
			Digest: map[string]string{"sha256": hex.EncodeToString(h.Sum(nil))},
		}, nil
	}

	for file, fi := range files {
		if !fi.Mode().IsRegular() {
			continue
		}

		subject, err := subjectGeneratorFunc(file)
		if err != nil {
			return nil, err
		}

		subjects = append(subjects, subject)
	}

	return subjects, nil
```

```go
func (a *archiver) Archive(ctx context.Context, files map[string]os.FileInfo) error {
	tmpDir, err := os.MkdirTemp(os.Getenv(archiverStagingDir), "fastzip")
	if err != nil {
		return fmt.Errorf("fastzip archiver unable to create temporary directory: %w", err)
	}
	defer os.RemoveAll(tmpDir)

	opts, err := getArchiverOptionsFromEnvironment()
	if err != nil {
		return err
	}

	opts = append(opts, fastzip.WithStageDirectory(tmpDir))
	if a.level == archive.FastestCompression {
		opts = append(opts, fastzip.WithArchiverMethod(zip.Store))
	}

	if a.zstd {
		opts = append(opts, fastzip.WithArchiverMethod(zstd.ZipMethodWinZip))
	}

	fa, err := fastzip.NewArchiver(a.w, a.dir, opts...)
	if err != nil {
		return err
	}

	if a.level != archive.FastestCompression {
		if a.zstd {
			fa.RegisterCompressor(zstd.ZipMethodWinZip, fastzip.ZstdCompressor(zstdLevels[a.level]))
		} else {
			fa.RegisterCompressor(zip.Deflate, fastzip.FlateCompressor(flateLevels[a.level]))
		}
	}

	err = fa.Archive(ctx, files)

	if cerr := fa.Close(); err == nil && cerr != nil {
		return cerr
	}

	return err
}
```
