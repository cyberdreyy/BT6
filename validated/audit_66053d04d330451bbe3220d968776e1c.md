### Title
Legacy gateway messages reach a DON handler with no sender-authorization/allowlist check, only structural signature validation - ([File: core/services/gateway/gateway.go])

### Summary
In `gateway.ProcessRequest`, the legacy branch calls `msg.Validate()` before resolving `handlerKey = msg.Body.DonId` and dispatching to `g.handlers[handlerKey]`, but `Validate()` only checks field lengths/format and recovers a valid ECDSA signer — it performs no check that the recovered signer is authorized/allowlisted for the target DON. The downstream handler (`capabilities.handler.HandleLegacyUserMessage`) also does not perform this check, as confirmed by an explicit `// TODO: apply allowlist and rate-limiting here` comment, and instead forwards the message to every member of the DON.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:250-262`) takes the legacy path when `msg.Body.DonId != ""`:
```go
isLegacyRequest = true
if err = msg.Validate(); err != nil {
    return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
}
handlerKey = msg.Body.DonId
h, ok = g.handlers[handlerKey]
```
`Message.Validate()` (`core/services/gateway/api/message.go:54-88`) only validates field lengths/null-byte suffixes and calls `ExtractSigner()` to recover *any* valid ECDSA signer from the self-supplied signature, storing it in `m.Body.Sender`. It never checks that this signer is a member of, or otherwise authorized for, the DON identified by `m.Body.DonId`. The lookup `g.handlers[handlerKey]` only checks that a handler was *configured* for that DON name — a purely structural/config lookup, not an authorization decision about the caller.

The message is then dispatched to `h.HandleLegacyUserMessage` (`core/services/gateway/handlers/capabilities/handler.go:341-421`). That function decodes the payload, checks timestamp freshness and method name, but explicitly notes at line 384: `// TODO: apply allowlist and rate-limiting here`, and unconditionally forwards the message to all `h.donConfig.Members` via `don.SendToNode`. There is no code path in either `gateway.go` or the `capabilities` handler that checks `msg.Body.Sender` against any per-DON allowlist before forwarding.

Any holder of an ECDSA key can self-sign a `MessageBody` with `DonId` set to any DON name present in `g.handlers`, and the message will pass `Validate()` (since signature recovery always succeeds for a message the attacker signed themselves) and be forwarded to that DON's nodes.

### Impact Explanation
This allows an unauthenticated/unprivileged attacker to send arbitrary Web API trigger requests to any configured DON's nodes without ever being registered or allowlisted for that DON, i.e., cross-tenant DON access using self-signed, unauthorized messages. This matches Chainlink's "unauthorized job run" / "allowlist bypass" bounty impact class, since DON nodes will process/relay attacker-forged triggers as if from a legitimate client.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only an ECDSA keypair (no registration, no credentials) and knowledge of a configured `DonId` string (these are often predictable/public service names). The exploit is fully reproducible and repeatable — sign any `MessageBody`/`Message` with `Sign()`, submit via the gateway's user HTTP endpoint, and the request is processed identically to a legitimate one, limited only by generic rate limiting on the node side (`nodeRateLimiter`), not by sender authorization.

### Recommendation
Add explicit sender-authorization/allowlist enforcement before dispatch: after `msg.Validate()` populates `m.Body.Sender`, check that the recovered sender address is present in the DON/service's configured allowlist for that `DonId` (mirroring the intended check called out by the `// TODO: apply allowlist and rate-limiting here` comment in `HandleLegacyUserMessage`), and reject with an authorization error otherwise. This check should happen either in `gateway.ProcessRequest` right after `msg.Validate()`, or unconditionally at the start of `HandleLegacyUserMessage`, before any message is forwarded to DON nodes.

### Proof of Concept
Go handler-level integration test plan:
1. Configure a `gateway` instance with `g.handlers["donA"]` pointing to a `capabilities.handler` backed by a `donConfig` whose `Members`/allowlist contains only known operator addresses (e.g., `0xAAA...`).
2. Generate a fresh, unregistered ECDSA keypair for "attacker" (`0xBBB...`), not present in `donConfig`/any allowlist.
3. Construct an `api.Message` with `Body.DonId = "donA"`, a valid `Method` (`web_api_trigger`), valid `MessageId`, and a well-formed payload; call `msg.Sign(attackerPrivKey)`.
4. Encode via `api.JsonRPCCodec` into a raw JSON-RPC request and call `gateway.ProcessRequest(ctx, rawRequest, "")`.
5. Assert current (vulnerable) behavior: `ProcessRequest` returns success (no `UnsupportedDONIdError`/`UserMessageParseError`), and `HandleLegacyUserMessage` calls `don.SendToNode` for DON members — i.e., the forged, unauthorized message is forwarded to the DON despite the attacker never being registered.
6. Assert the desired (fixed) behavior: the handler must independently reject the message because `msg.Body.Sender` (`0xBBB...`) is not in the DON's allowlist, returning an authorization error and never calling `don.SendToNode`. [1](#0-0) [2](#0-1) [3](#0-2)

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
