### Title
Locally-computed tenure-extend timestamps let a single miner cause honest signers to reach divergent valid/invalid verdicts for the same block - ([File: stacks-signer/src/signerdb.rs])

### Summary
The DODO/MagicLP report shows that letting a single privileged actor mutate a price-relevant parameter mid-flight lets that actor pick the exact moment of the mutation to exploit the resulting inconsistency window. In `stacks-signer`, the analogous "parameter" is the *tenure-extend timestamp* used to decide whether a miner's `TenureChangeCause::Extended` / `ExtendedReadCount` proposal is legitimate. That timestamp is derived purely from each signer's own local database and local wall clock rather than from any value agreed upon across the signer set, so a miner can time a tenure-extend block to straddle the boundary and get divergent accept/reject verdicts from otherwise-honest signers for the identical block.

### Finding Description
The tenure-extend validity check lives in `SortitionsView::check_proposal` (v1) and `SortitionState::check_proposal` (v2): [1](#0-0) [2](#0-1) 

For a full extend, the block is accepted if `changed_burn_view || enough_time_passed || is_in_replay`. `enough_time_passed` is computed as `get_epoch_time_secs() >= extend_timestamp`, where `extend_timestamp` comes from `SignerDb::calculate_full_extend_timestamp` / `calculate_read_count_extend_timestamp`: [3](#0-2) [4](#0-3) 

`get_tenure_times` walks the *signer's own* `blocks` table, summing each block's locally-recorded `validation_time_ms` (recorded by the node when that particular signer validated the block, see `handle_block_validate_ok` writing `block_info.validation_time_ms`) plus that signer's own `proposed_time`: [5](#0-4) 

Both operands of the check — `epoch_time` (the signer's own wall clock) and `extend_timestamp` (built from that signer's own historical validation timings and its own record of `proposed_time` for earlier blocks in the tenure) — are purely local. Nothing forces two signers to compute the same `extend_timestamp` for the same tenure, and nothing forces two signers' local clocks to agree to sub-second precision. The `tenure_idle_timeout_buffer` config option exists specifically because the authors know clock skew is a live concern: [6](#0-5) 

Because the check is a `>=` comparison against a threshold that both the miner and any signer can predict approximately, a single miner (the "one-slot" actor here — it alone decides when to broadcast the extend block) can choose to propose the tenure-extend block exactly at the moment when it expects the aggregate signer set to be near the threshold. Signers whose local `validation_time_ms` history was smaller (faster block processing) or whose clock runs slightly fast will independently compute `enough_time_passed = true` and accept the extend as valid; signers with slower validation histories or slower clocks will compute `false` and reject it with `RejectReason::InvalidTenureExtend`, given `!changed_burn_view` and `!is_in_replay` are otherwise identical for all signers on the same proposal. This is exactly the DODO-style bug class: a single controlling actor's power to choose *when* to trigger a comparison against a parameter that is not held equal (consensus-wide) across all evaluators, engineered to land in the ambiguous window and produce a profitable split of outcomes.

### Impact Explanation
This breaks the required equality that identical block proposals must be evaluated identically by every signer. If enough of the honestly-diverging signers land on the "accept" side purely because of clock/processing-history skew (no collusion or majority control needed — natural skew across a real deployment plus a miner picking the timing is sufficient), the tenure-extend block accumulates enough weight to be signed and become canonical, even though it would legitimately be rejected under any single consistent evaluation of the same rule. This is a signer-set-wide equality break of exactly the class called out in scope: some signers end up signing/pre-committing a block that other correctly-behaving signers correctly reject as `InvalidTenureExtend` for the very same block, i.e., "a signer signing an invalid/non-canonical/conflicting block" relative to what the deterministic rule should produce. The stacks-node's own `NakamotoBlockProposal::validate` in `postblock_proposal.rs` performs no independent enforcement of the tenure-idle-timeout policy — that judgment is delegated entirely to the signer set's local, non-synchronized state, so there is no backstop.

### Likelihood Explanation
No special privileges, majority control, or key compromise are required — only the block proposer (the tenure's current miner, a normal single actor able to choose exactly when to broadcast a tenure-extend block) needs to time its proposal near the idle-timeout boundary. Real-world clock skew between independently operated signer nodes, and natural variance in `validation_time_ms` recorded per node (dependent on each node's own load / connectivity to its own stacks-node), makes landing in the ambiguous window plausible without any adversarial signer behavior at all.

### Recommendation
Do not derive `enough_time_passed` from each signer's private wall clock and private validation-time bookkeping. Instead, tie the tenure-idle-timeout decision to a value that is either: (a) computed identically from consensus-visible chain data (e.g., burn block height/time rather than local `get_epoch_time_secs()`), or (b) agreed upon via the `GlobalStateEvaluator`/`StateMachineUpdate` gossip mechanism the same way `burn_block`/`current_miner` are reconciled, so that all signers necessarily compute the same `extend_timestamp` and the same `enough_time_passed` boolean for a given tenure/block. At minimum, widen `tenure_idle_timeout_buffer` deterministically and require exact agreement (not just "close enough") before treating a tenure-extend as valid on this basis alone.

### Proof of Concept
1. Two honest signers, S1 and S2, are both tracking the same tenure. S1's stacks-node happens to validate the tenure's earlier blocks slightly faster (lower recorded `validation_time_ms`) than S2's, or S1's system clock is a couple of seconds ahead of S2's — both plausible in any real deployment.
2. The tenure's miner (single proposer) waits until it estimates the group is near, but not universally past, the idle-timeout threshold, then proposes a `TenureChangeCause::Extended` block with an unchanged burn view and no active tx replay.
3. S1's `calculate_full_extend_timestamp` (via `get_tenure_times`) yields a smaller `extend_timestamp`; combined with S1's slightly-ahead clock, `check_proposal` in `chainstate/v1.rs`/`v2.rs` evaluates `enough_time_passed = true` → S1 treats the extend as valid and pre-commits/signs.
4. S2, using its own slower processing history and/or slightly-behind clock, evaluates `enough_time_passed = false` → S2 returns `RejectReason::InvalidTenureExtend` for the identical block.
5. If enough signers land on S1's side of the boundary purely by timing/clock variance (no collusion required), the block reaches the ≥70% signature threshold and becomes canonical, despite a strictly consistent, single evaluation of the extend-timestamp rule having rejected it for a meaningful fraction of the signer set — demonstrating the cross-signer equality break.

    fn get_tenure_times<F>(
        &self,
        tenure: &ConsensusHash,
        cause_match: F,
    ) -> Result<(u64, u64), DBError>
    where
        F: Fn(TenureChangeCause) -> bool,
    {
        let query = "SELECT tenure_change_cause, proposed_time, validation_time_ms FROM blocks WHERE consensus_hash = ?1 AND state = ?2 ORDER BY stacks_height DESC";
        let args = params![tenure, BlockState::GloballyAccepted.to_string()];
        let mut stmt = self.db.prepare(query)?;
        let rows = stmt.query_map(args, |row| {
            let tenure_change_cause: Option<u8> = row.get(0)?;
            let tenure_change_cause = tenure_change_cause
                .and_then(|cause_byte| TenureChangeCause::try_from(cause_byte).ok());
            let proposed_time: u64 = row.get(1)?;
            let validation_time_ms: Option<u64> = row.get(2)?;
            Ok((tenure_change_cause, proposed_time, validation_time_ms))
        })?;
        let mut tenure_processing_time_ms = 0_u64;
        let mut tenure_start_time = None;
        let mut nmb_rows = 0;
        for (i, row) in rows.enumerate() {
            nmb_rows += 1;
            let (tenure_change_cause, proposed_time, validation_time_ms) = row?;
            tenure_processing_time_ms =
                tenure_processing_time_ms.saturating_add(validation_time_ms.unwrap_or(0));
            tenure_start_time = Some(proposed_time);
            if let Some(tenure_change_cause) = tenure_change_cause {
                if cause_match(tenure_change_cause) {
                    debug!("Found matching tenure change block {i} blocks ago in tenure {tenure}");
                    break;
                }
            }
        }
        debug!("Calculated tenure extend timestamp from {nmb_rows} blocks in tenure {tenure}");
        Ok((
            tenure_start_time.unwrap_or(get_epoch_time_secs()),
            tenure_processing_time_ms,
        ))
    }

    fn calculate_tenure_extend_timestamp<F>(
        &self,
        tenure_idle_timeout: Duration,
        block: &NakamotoBlock,
        check_tenure_extend: bool,
        tenure_change_match: F,
    ) -> u64
    where
        F: Fn(TenureChangeCause) -> bool,
    {
        if check_tenure_extend {
            if let Some(tenure_change) = block.get_tenure_change_tx_payload() {
                if tenure_change_match(tenure_change.cause) {
                    let tenure_extend_timestamp =
                        get_epoch_time_secs().wrapping_add(tenure_idle_timeout.as_secs());
                    debug!("Calculated tenure extend timestamp for a tenure extend block. Rolling over timestamp: {tenure_extend_timestamp}");
                    return tenure_extend_timestamp;
                }
            }
        }
        let tenure_idle_timeout_secs = tenure_idle_timeout.as_secs();
        let (tenure_start_time, tenure_process_time_ms) = self.get_tenure_times(
            &block.header.consensus_hash,
            tenure_change_match,
        ).unwrap_or_else(|e| {
            error!("Error occurred calculating tenure extend timestamp: {e:?}. Defaulting to {tenure_idle_timeout_secs} from now.");
            (get_epoch_time_secs(), 0)
        });
        // Plus (ms + 999)/1000 to round up to the nearest second
        let tenure_extend_timestamp = tenure_start_time
            .saturating_add(tenure_idle_timeout_secs)
            .saturating_add(tenure_process_time_ms.div_ceil(1000));
        debug!("Calculated tenure extend timestamp";
            "tenure_extend_timestamp" => tenure_extend_timestamp,
            "tenure_start_time" => tenure_start_time,
            "tenure_process_time_ms" => tenure_process_time_ms,
            "tenure_idle_timeout_secs" => tenure_idle_timeout_secs,
            "tenure_extend_in" => tenure_extend_timestamp.saturating_sub(get_epoch_time_secs()),
            "consensus_hash" => %block.header.consensus_hash,
        );
        tenure_extend_timestamp
    }
