### Title
Zip-slip path traversal via unvalidated `zip.File.Name` in legacy zip extractor - ([File: helpers/archives/zip_extract.go], [File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go])

### Summary
`ExtractZipArchive` writes every zip entry using the raw, attacker-controlled `file.Name` with no check for absolute paths, drive letters, or `../` traversal sequences, and the `ziplegacy.extractor.dir` field that is supposed to scope extraction is never actually used to join or validate paths. A crafted artifact/cache zip can therefore write files outside the intended extraction directory.

### Finding Description
`extractor.Extract` (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-33`) stores `dir` in the struct [1](#0-0)  but simply calls `archives.ExtractZipArchive(zr)` without ever using `e.dir` to `chdir`, `filepath.Join`, or validate entry names [2](#0-1) .

Inside `ExtractZipArchive` (`helpers/archives/zip_extract.go:85-110`), each `file.Name` is passed straight to `extractZipFile`, which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on entry type, `os.Mkdir`, `os.Symlink`, or `os.OpenFile`/`io.Copy` — all using the unmodified `file.Name` [3](#0-2) . The only path-related validation performed is `errorIfGitDirectory`, which merely detects a leading `.git` path component and does not reject absolute paths or `..` segments [4](#0-3) . `pathErrorTracker` only deduplicates warning logs and performs no path enforcement [5](#0-4) .

Because Go's `os.OpenFile`/`os.Mkdir`/`os.Symlink` honor absolute paths and `..` traversal verbatim, a zip entry named `/etc/cron.d/x` (or, on Windows, `C:\Windows\...` or `..\..\..\Windows\...`) will be written outside any confinement directory, provided the runner process has filesystem permission to do so.

### Impact Explanation
Any job that can supply an artifact/cache zip consumed via this legacy zip extractor path (e.g., `ArtifactsDownloaderCommand` restoring artifacts, or cache restore using the zip format) can write to arbitrary filesystem locations reachable by the runner process's OS user — not just outside the job's own build directory, but outside the intended shared job root, if the runner process has write permission there (e.g., host-installed runner, shell executor, or any executor where the extraction happens in a shared filesystem namespace). This breaks the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
The bug is reachable purely through pipeline-author-controlled input: an attacker only needs to produce/upload a job artifact or cache zip file with crafted entry names (trivial with the standard `archive/zip` package, bypassing GitLab's own archive creation since the file only needs to be a valid zip when downloaded and extracted by the runner). No special runner configuration or admin misconfiguration is required beyond the runner extracting an untrusted zip on a filesystem where such paths are writable, which is the default behavior for the extractor. This is a straightforward, repeatable, deterministic exploit path.

### Recommendation
In `extractZipFile` (and the directory/symlink/file entry helpers), reject or `filepath.Clean`-and-check every `file.Name`: require it to be a relative path with no leading `/`, no drive letter, and (after `filepath.Join(dir, cleaned)`) result must have `dir` as a strict prefix. Thread the actual extraction root (`e.dir` from `ziplegacy.extractor`) through `ExtractZipArchive`/`extractZipFile` so writes are always joined against and validated relative to that root, rather than relying on process CWD or raw entry names.

### Proof of Concept
```go
func TestExtractZipArchive_RejectsPathTraversal(t *testing.T) {
    dir := t.TempDir()
    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("../../../../tmp/evil_zip_slip")
    _, _ = w.Write([]byte("pwned"))
    _ = zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    old, _ := os.Getwd()
    _ = os.Chdir(dir)
    defer os.Chdir(old)

    err := archives.ExtractZipArchive(zr)
    require.Error(t, err, "expected traversal entry to be rejected")
    _, statErr := os.Stat("/tmp/evil_zip_slip")
    require.True(t, os.IsNotExist(statErr), "file must not be written outside dir")
}
```
Expected today: `err` is `nil` and `/tmp/evil_zip_slip` exists, demonstrating the escape. A fuzz test iterating over `/etc/...`, `C:\...`, and `..\..\` variants against `extractZipFile`/`ExtractZipArchive`, asserting all writes stay under a fixed temp `dir`, would similarly fail with current code.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func (p *pathErrorTracker) actionable(e error) bool {
	pathErr, isPathErr := e.(*os.PathError)
	if e == nil || isPathErr && pathErr == nil {
		return false
	}

	if !isPathErr {
		return true
	}

	p.lock.Lock()
	defer p.lock.Unlock()

	seen := p.seenOps[pathErr.Op]
	p.seenOps[pathErr.Op] = true

	// actionable if *not* seen before
	return !seen
}
