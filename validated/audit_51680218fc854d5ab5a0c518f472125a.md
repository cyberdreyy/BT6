## Title
Stale confirmations from removed multisig members are still counted toward `num_confirmations`, allowing request execution below threshold - (File: `multisig2/src/lib.rs`)

### Summary
The Karak finding centers on a queued state (a pending slash) that is finalized without re-validating that the underlying authorization (operator registration) still holds at finalization time. The direct analog in this repo is `multisig2/src/lib.rs`: a request's recorded `confirmations` set can contain a member that is later removed via `DeleteMember`, but `delete_member` never scrubs that member's confirmations from requests they didn't themselves create. `confirm()` then counts that stale confirmation toward `self.num_confirmations` without re-checking that every confirming party is still a live member, letting a request execute with fewer *currently valid* confirmations than the configured threshold.

### Finding Description
`confirm()` decides whether to execute a request purely by the size of the stored `confirmations` set: [1](#0-0) 

`delete_member()` only cleans up requests **created (`r.member == member`)** by the removed member, and removes that member from `self.members` — it does **not** scan other requests to strip confirmations previously cast by that member: [2](#0-1) 

Because of this, the equality the contract is supposed to preserve —

`live confirming members counted in confirmations == self.num_confirmations` (i.e. every accepted confirmation belongs to a currently active member)

— can be violated: a confirmation entry can remain in `confirmations` for a `request_id` after the member who cast it is deleted from `self.members`, yet `confirm()` still adds it to the tally that gates execution.

### Impact Explanation
This is a Critical-class issue per the custody-binding rules: "a multisig request executed below threshold." A K-of-N multisig can be made to execute an action (e.g. `Transfer`, `AddKey`, `FunctionCall`) with fewer than K currently authorized signers, because one of the counted confirmations belongs to a member who has since been removed (e.g. because their key was known/suspected to be compromised, or they left the organization). This directly breaks the authorization/threshold boundary the multisig is meant to enforce over any funds or privileged calls it controls.

### Likelihood Explanation
This requires only ordinary, unprivileged-relative-to-the-bug interaction: any current or former member confirming a request before their removal, and a normal governance action to remove them later (`DeleteMember` requires reaching the existing threshold once, which is routine operational behavior, not an attacker exploiting a special privilege). No malicious insider collusion beyond an ordinary member confirming and later being removed is required for the invariant to already be broken; an attacker among the remaining members can then simply finish confirming the still-pending request to execute it under-threshold.

### Recommendation
When executing `DeleteMember`, iterate all outstanding `requests` (not just those created by the removed member) and drop the removed member's entry from each `confirmations` set, or re-validate at `confirm()`/execution time that every account/key present in `confirmations` is still contained in `self.members` before comparing against `self.num_confirmations`.

### Proof of Concept
1. Initialize with `members = {A, B, C, D}` and `num_confirmations = 3`.
2. `A` calls `add_request(X)` (some `Transfer` request) — `confirmations[X] = {}` (`add_request`, `multisig2/src/lib.rs:170-200`).
3. `B` calls `confirm(X)` → `confirmations[X] = {B}` (size 1 < 3).
4. `D` calls `confirm(X)` → `confirmations[X] = {B, D}` (size 2 < 3), not yet executed.
5. Separately, members reach 3-of-4 on a `DeleteMember{D}` request; it executes `delete_member` — this only removes requests where `r.member == D` (i.e., requests *D* created), so request `X` (created by `A`) is untouched; `confirmations[X]` still contains `D`, but `D` is removed from `self.members`.
6. `C` calls `confirm(X)`: `confirmations[X].len() + 1 == 3 >= self.num_confirmations` → `execute_request` runs the `Transfer`.
7. Result: request `X` executed with confirmations from `{B, D, C}` where `D` was no longer a member at execution time — only 2 currently-valid members (`B`, `C`) actually authorized it, below the configured 3-of-4 threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
