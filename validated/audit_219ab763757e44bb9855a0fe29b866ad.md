## Finding: `switch_operator` leaves stale operator-commission shares in a shared `distribution_pool` that get re-taxed under the new operator's commission rate

### Summary
`switch_operator` correctly settles the outgoing operator's commission *at the moment of the switch* by calling `request_commission_internal(old_operator, ...)` before reassigning the `StakingContract` to `new_operator` [1](#0-0) . However, the settled commission is not paid out immediately — it is recorded as shares owed to `old_operator` inside the same `distribution_pool: Pool` that stays attached to the (now reused) `StakingContract` struct. Because `distribution_pool` is a shared `pool_u64` structure and `update_distribution_pool` re-taxes *any* growth in the pool's total value to the *current* operator address regardless of whose balance grew, `old_operator`'s already-earned, unpaid commission balance can later be partially redirected to `new_operator`.

### Finding Description
When `switch_operator` runs, it:
1. Force-distributes any already-inactive funds via `distribute_internal`.
2. Calls `request_commission_internal(old_operator, &mut staking_contract)`, which locks in `old_operator`'s commission as new shares in `staking_contract.distribution_pool` via `add_distribution`, keyed to `old_operator`'s address [2](#0-1) .
3. Re-keys the same `StakingContract` (including the same `distribution_pool`) under `new_operator` and updates `commission_percentage` [3](#0-2) .

If `old_operator`'s commission shares haven't been redeemed yet (i.e., no one has called `distribute` to pay them out — funds are still `pending_inactive` and the lockup hasn't expired), those shares remain as a "shareholder" entry in the pool, tagged to `old_operator`'s address.

Any subsequent growth of the pool (which happens naturally, since `pending_inactive` stake continues to earn epoch rewards until the lockup fully expires, or because further calls to `add_distribution`/`distribute_internal` recompute `total_distribution_amount` from the live stake pool) triggers `update_distribution_pool` [4](#0-3) . This function iterates every shareholder that is **not** the `operator` argument passed in (which, after the switch, is `new_operator`) and transfers a `commission_percentage`-sized cut of that shareholder's balance growth to `operator`:
```
if (shareholder != operator) {
    ...
    let unpaid_commission = (current_worth - previous_worth) * commission_percentage / 100;
    ...
    pool_u64::transfer_shares(distribution_pool, shareholder, operator, shares_to_transfer);
};
``` [5](#0-4) 

`old_operator` is not distinguished from an ordinary staker in this loop — it is simply "a shareholder that isn't the current operator." So `old_operator`'s previously-earned, already-settled commission balance gets taxed again, this time at `new_operator`'s commission rate, and the skimmed amount is transferred to `new_operator`. This can be triggered by any unprivileged account, since `distribute` is a public entry function with no caller restriction [6](#0-5) , and `request_commission`/`unlock_stake` (callable by staker/operator/beneficiary) also route through `distribute_internal` and `add_distribution`.

### Impact Explanation
Value that was already earned and legitimately owed to `old_operator` (or its beneficiary) is silently redirected, in part, to `new_operator`, corrupting the beneficiary payout for the prior operator's tenure — matching the "Operator commission ... share-accounting corruption that credits the wrong account" impact category.

### Likelihood Explanation
This requires only ordinary usage: a staker switching operators while the prior operator has an unredeemed commission balance sitting as `pending_inactive` (which is the common case, since `distribute` must be separately called after lockup expiry). Reward compounding on `pending_inactive` stake across at least one more epoch, or another `add_distribution`/`unlock_stake` call, is enough to trigger the mistaxation. No special privileges are needed to trigger the retax — `distribute` is fully permissionless.

### Recommendation
`update_distribution_pool` should not recharge commission on a shareholder's balance if that shareholder is a *former* operator whose balance represents already-settled commission rather than an ordinary staker/withdrawal claim. Options include: paying out (or fully redeeming) `old_operator`'s distribution-pool shares as part of `switch_operator` instead of leaving them in the shared pool, or tracking a separate "commission owed" balance per operator that is excluded from future `update_distribution_pool` re-taxation.

### Proof of Concept
1. Staker creates a staking contract with `operator_1` at 10% commission; stake earns rewards for an epoch.
2. Staker calls `switch_operator(staker, operator_1, operator_2, new_commission=20)`. This settles `operator_1`'s commission as shares in `distribution_pool` (via `request_commission_internal`) and reassigns the contract to `operator_2` at 20% [1](#0-0) .
3. Before `operator_1`'s pending commission is distributed (lockup not yet expired), let another epoch pass so the pending-inactive stake (including `operator_1`'s locked-in commission shares) compounds rewards.
4. Any account calls `unlock_stake`/`request_commission`/`distribute` against `(staker, operator_2)`, triggering `update_distribution_pool` with `operator = operator_2` and `commission_percentage = 20`.
5. Assert: `operator_1`'s balance in `distribution_pool` (queryable via `pending_attribution_snapshot(staker, operator_2, operator_1)`) grows by less than its full reward-compounded amount, while `operator_2`'s balance increases by the skimmed 20% cut — demonstrating `operator_2` captured commission on `operator_1`'s already-earned, pre-switch balance.

```text
    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
