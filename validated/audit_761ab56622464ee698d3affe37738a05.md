### Title
View-role user can read node RPC endpoint URLs (potentially containing API keys) via GET /v2/nodes with no role gate - ([File: core/web/router.go])

### Summary
The `/v2/nodes` route only requires generic authentication (`auth.Authenticate` with `AuthenticateByToken`/`AuthenticateBySession`), with no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, unlike most other sensitive routes in the same file. `NodesController.Index` returns `presenters.NodeResource` which embeds the node's raw TOML `Config` field verbatim, including `WSURL`/`HTTPURL` values that operators commonly set to provider RPC endpoints with embedded API keys in the URL.

### Finding Description
`v2Routes` registers `nodes.GET("", paginatedRequest(nodesController.Index))` and `nodes.GET("/:network", ...)` under `authv2` only, i.e., protected solely by `auth.Authenticate(..., AuthenticateByToken, AuthenticateBySession)` at line 245-248 [1](#0-0) . Compare with adjacent routes like `/keys/eth/import` or `/transfers` that are explicitly wrapped with `auth.RequiresAdminRole`/`auth.RequiresEditRole` [2](#0-1)  — nodes Index has no such wrapper, meaning any authenticated session/API token regardless of role (view, run, edit, admin) can call it.

`nodesController.Index` calls `relayers.NodeStatuses(...)` and converts each `types.NodeStatus` into a `presenters.NodeResource` via `n.newResource(node)` [3](#0-2) . `presenters.NewNodeResource` copies `node.Config` (the TOML-serialized node config) directly into the `Config` field with no filtering: [4](#0-3) . That TOML config, as built in `nodeStatus()` (test helper mirroring production `ListNodeStatuses`/relayer implementations), is a `toml.Marshal(n)` of the node struct including `WSURL`/`HTTPURL` [5](#0-4) , and `resolver/node.go`'s GraphQL analog confirms these same URL fields are parsed straight out of `status.Config` [6](#0-5) . Operators frequently configure paid RPC providers (Alchemy, Infura, QuickNode, etc.) using URLs of the form `https://provider.com/v2/<API_KEY>` or with an API key as a query parameter — this credential is not redacted anywhere in the presenter or controller path.

The generic authenticate middleware validates only that the caller has *some* valid session or API token; it does not check role. Because `Index` is not wrapped in `auth.RequiresEditRole`/`RequiresAdminRole`, a minimally-privileged "view" role account (which Chainlink node's role model treats as read-only, low-trust) can retrieve this data.

### Impact Explanation
This matches the Chainlink bounty "sensitive credential/secret disclosure" impact class: a low-privileged, authenticated user (view role) can exfiltrate the node operator's RPC provider API keys embedded in `WSURL`/`HTTPURL`, which could then be used to: (a) incur cost/quota abuse against the operator's RPC provider account, (b) pivot to further reconnaissance of the operator's chain infrastructure. It does not grant direct fund movement or job/key compromise, but it is a genuine secret-disclosure vulnerability scoped to the node's RPC credentials.

### Likelihood Explanation
Preconditions are minimal: any account with a "view" role API token or web session (the lowest privilege tier that still allows API access) can call `GET /v2/nodes` and immediately receive full node configs for all configured chains (EVM, Solana, Cosmos, etc., per the loop-relayer node status listing) with no additional permission check. This is trivially and repeatably exploitable — a single unauthenticated-role-elevation-free HTTP GET.

### Recommendation
Add role enforcement consistent with other configuration/credential-adjacent endpoints — wrap `nodesController.Index` (and `chainController.Index`/`Show`, which have the same issue) with at least `auth.RequiresEditRole` or `auth.RequiresAdminRole` in `v2Routes`. Additionally, redact credentials from `NodeResource.Config`/`ChainResource.Config` before serialization (e.g., strip query-string/userinfo credentials from `WSURL`/`HTTPURL` when building the presenter), independent of role, since TOML config strings should never carry raw secrets to any HTTP response.

### Proof of Concept
Go handler-level integration test plan (in `core/web/nodes_controller_test.go` style, using existing test harness `cltest.NewApplicationEVMDisabled`/`setupNodesControllerTests`):
1. Seed a `RelayerChainInteroperators` mock/test config (`evmtest.TestConfigs`) with an EVM node whose `HTTPURL` is `https://rpc.example.com/v2/SECRET_API_KEY_123`.
2. Create a client authenticated with a session/API token whose `sessions.User.Role` is `user.RoleView` (the minimal role, per `auth.go`'s `RequiresEditRole`/`RequiresAdminRole` role-checks referenced at `core/web/auth/auth.go`).
3. Issue `client.Get("/v2/nodes")`.
4. Assert HTTP 200 (not 401/403) — proving no role gate blocks access.
5. Decode the JSON:API response into `[]presenters.NodeResource` and assert `resource.Config` contains the substring `SECRET_API_KEY_123`, proving the credential is disclosed verbatim to the view-role caller.
6. As a control, verify the currently-missing expected behavior would be either (a) a 403 rejecting the view-role caller, or (b) the returned `Config` string having the credential portion of the URL redacted/masked.

func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
