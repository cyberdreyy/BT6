## Title
Path traversal in ziplegacy zip extraction allows writing files outside job workspace via crafted artifact zip entry names - (File: `helpers/archives/zip_extract.go`)

## Summary
`archive.Zip` is registered by default (`FF_USE_FASTZIP=false`) to `ziplegacy.NewExtractor`, which calls `archives.ExtractZipArchive()` in `helpers/archives/zip_extract.go`. That code path uses `file.Name` verbatim in `os.Mkdir`, `os.OpenFile`, and `os.Symlink` calls with no `filepath.Join(dir, ...)`, no `filepath.Abs`, and no `strings.HasPrefix` chroot check — unlike `tarzstd_extractor.go`, which explicitly validates each entry stays inside the destination directory.

## Finding Description
`ArtifactsDownloaderCommand.Execute` (`commands/helpers/artifacts_downloader.go:88-141`) determines the archive format via `openArchive()`, which only checks for zstd/gzip magic bytes and **defaults to `archive.Zip`** for anything else (`commands/helpers/artifacts_downloader.go:148-164`). It then calls `archive.NewExtractor(format, f, size, wd)` and `extractor.Extract(ctx)`.

By default (`FF_USE_FASTZIP` off), `archive.Zip` is registered to `ziplegacy.NewExtractor` in `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:19-32`. Notably, `ziplegacy.extractor.Extract()` receives `dir` (the job's `wd`) in its struct but **never uses it**:

```go
func (e *extractor) Extract(ctx context.Context) error {
	zr, err := zip.NewReader(e.r, e.size)
	...
	return archives.ExtractZipArchive(zr)
}
``` [1](#0-0) 

`ExtractZipArchive`/`extractZipFile` in `helpers/archives/zip_extract.go` then writes each entry using `file.Name` directly:
```go
err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
...
out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
``` [2](#0-1) 

There is no path validation anywhere in this file — no `filepath.Join` against a base directory, no `filepath.Abs`/prefix check like the one present in `tarzstd_extractor.go`:
```go
path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))
if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir {
	return fmt.Errorf("%s cannot be extracted outside of chroot (%s)", path, e.dir)
}
``` [3](#0-2) 

Only a `.git` directory warning check exists (`errorIfGitDirectory`) — no traversal guard. Because `extractZipFile` operates purely on relative-to-CWD paths, and `Execute()` never changes CWD (it only reads it via `os.Getwd()`), an entry named `../../etc/cron.d/evil` will resolve relative to the process's actual current working directory. In a real GitLab Runner build, the process's CWD at the time `artifacts-downloader` (a subcommand launched by the build shell script) runs is the job's `wd` (build directory), so a `..`-prefixed name written by `extractZipFile` escapes that directory exactly as intended by the attack (e.g., writing outside the build root to whatever the traversal targets, subject only to OS file permissions of the job's user).

The `errorIfGitDirectory`/`pathErrorTracker` logic only suppresses repeated warnings and detects `.git`; it performs no rejection of `..` path segments. The symlink handler (`extractZipSymlinkEntry`) is equally unguarded, allowing a malicious symlink target combined with traversal for further escapes.

## Impact Explanation
An unprivileged pipeline author can upload/control a job artifact zip with entries containing `../` path segments. When a downstream job (or any job that triggers `artifacts-downloader` with the default `FF_USE_FASTZIP=false` extractor) downloads and extracts that artifact, `ziplegacy`'s extractor writes files outside the job's working directory, anywhere the runner process's file permissions allow — a concrete build/artifact-root escape via arbitrary file write, limited to the OS-level permissions of the runner/build user.

## Likelihood Explanation
- Preconditions are minimal and fully attacker-controlled: any user who can define a CI job that produces artifacts (`artifacts:` config) can control the zip's entry names, since GitLab Runner's uploader packages whatever files/paths the job script produces without renaming entries beyond what `zip.Writer.Create(name)` receives.
- This is the **default** code path — `FF_USE_FASTZIP` defaults to `false` per `docs/configuration/feature-flags.md`, so the vulnerable `ziplegacy` extractor is used unless an operator explicitly enables fastzip.
- Repeatable: any job with a `../`-crafted artifact triggers this every time a dependent job downloads that artifact.
- Whether `fastzip`'s underlying `github.com/saracen/fastzip` library independently sanitizes paths was not verified in this codebase (it's a third-party library only wrapped by `zip_fastzip_extractor.go`), so this finding is scoped specifically to the default/`ziplegacy` path, which is definitively unguarded by first-party code.

## Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: before performing any filesystem operation on `file.Name`, compute `filepath.Join(dir, file.Name)`, take `filepath.Abs`, and verify it has `dir` as prefix (or reject `..`/absolute entries outright), rejecting or skipping non-conforming entries. Since `ExtractZipArchive`/`extractZipFile` currently have no notion of a destination directory at all, thread the `dir` parameter through `ziplegacy.extractor.Extract()` → `ExtractZipArchive(zr, dir)` → `extractZipFile(file, dir)` so extraction is anchored to the intended workspace root, matching tarzstd's invariant.

## Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
package archives

import (
	"archive/zip"
	"os"
	"path/filepath"
	"testing"

	"github.com/stretchr/testify/require"
)

func TestExtractZipFile_PathTraversalEscapesWorkdir(t *testing.T) {
	// Set up: workdir/victim area
	base := t.TempDir()
	workdir := filepath.Join(base, "wd")
	require.NoError(t, os.Mkdir(workdir, 0o755))

	// Build malicious zip with a traversal entry
	zipPath := filepath.Join(base, "artifacts.zip")
	zf, err := os.Create(zipPath)
	require.NoError(t, err)
	zw := zip.NewWriter(zf)
	w, err := zw.Create("../evil.txt")
	require.NoError(t, err)
	_, err = w.Write([]byte("pwned"))
	require.NoError(t, err)
	require.NoError(t, zw.Close())
	require.NoError(t, zf.Close())

	// Simulate artifacts-downloader: chdir into workdir, then extract
	origWd, _ := os.Getwd()
	defer os.Chdir(origWd)
	require.NoError(t, os.Chdir(workdir))

	err = ExtractZipFile(zipPath)
	require.NoError(t, err)

	// Assertion: file must NOT exist outside workdir (base dir), but current
	// (buggy) behavior writes it to base/evil.txt, escaping workdir.
	escaped := filepath.Join(base, "evil.txt")
	_, statErr := os.Stat(escaped)
	require.True(t, os.IsNotExist(statErr),
		"expected traversal to be blocked; found file escaped to %s", escaped)
}
```
Expected result today: the test **fails** (file is created at `base/evil.txt`, outside `workdir`), proving the traversal. After adding the recommended containment check, the test should pass (extraction rejects or confines the entry, keeping `evil.txt` from escaping `workdir`).

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}
