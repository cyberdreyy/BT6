### Title
Stale member confirmations are not purged on removal, allowing a multisig request to execute below the live K-of-N threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only removes requests *created by* the member being deleted and clears their `num_requests_pk` entry; it never scans the `confirmations` map to strip that member's confirmation entries from *other*, still-pending requests. `confirm()` later counts `confirmations.len()` toward `num_confirmations` without re-validating that every entry in the set still corresponds to a current member of `self.members`. This lets a request execute using a confirmation from an account that is no longer a member, effectively lowering the real K-of-N threshold that is satisfied by currently authorized members.

### Finding Description
- `delete_member` ( [1](#0-0) ) removes the member from `self.members` and deletes only the requests where `r.member == member` (i.e., requests the removed member itself created), clearing their confirmations. It does not touch `self.confirmations` entries for requests created by other members that the removed member had already confirmed.
- `confirm()` ( [2](#0-1) ) computes `confirmations.len() as u32 + 1 >= self.num_confirmations` to decide whether to execute the request. It only validates the *current caller* via `current_member()` ( [3](#0-2) ); it never re-checks that the pre-existing entries already stored in the `confirmations: HashSet<String>` are still members of `self.members`.
- Binding broken: `confirmations counted == live members who approved` should hold, but the code allows `confirmations counted > live members who approved`, i.e. a request can reach `num_confirmations` while strictly fewer than `num_confirmations` *current* members actually approved it.

### Impact Explanation
This crosses an authorization/threshold boundary explicitly called out as Critical impact: "a multisig request executed below threshold." A `Transfer`, `FunctionCall`, `AddKey` (full access key), or `AddMember` request can be pushed to execution using a stale confirmation from a since-removed member, meaning NEAR funds, contract upgrades, or key/membership changes can be authorized by fewer live, currently-trusted parties than the configured `num_confirmations` requires.

### Likelihood Explanation
Reaching this state requires only ordinary, in-scope multisig activity (member confirms a request, then, before that request is finalized, the confirming member is removed via a normal `DeleteMember` governance action) — no foundation, redeploy, or victim key compromise is needed. Any member of the multisig (an "unprivileged" party relative to the others, since it is one of N key holders each entitled only to their own vote) benefits by keeping a pending request open across a membership change and getting it finished with one fewer *live* approval than intended.

### Recommendation
When removing a member in `delete_member`, iterate over all entries in `self.confirmations` (not just requests created by that member) and remove the deleted member's string key from every confirmation set. Alternatively, in `confirm()`, recompute the confirmation count by filtering out entries that are no longer present in `self.members` before comparing to `num_confirmations`.

### Proof of Concept
1. Deploy `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. `A.add_request(R)` creates request `R` (e.g., `Transfer` to an attacker-controlled `receiver_id`). `confirmations[R] = {}`.
3. `A.confirm(R)` → `confirmations[R] = {A}` (len 1 < 3).
4. `B.confirm(R)` → `confirmations[R] = {A, B}` (len 2 < 3, not yet executed).
5. Separately, members legitimately vote to remove `B` via a `DeleteMember{member: B}` request (`request_id = R2`), reaching 3 confirmations from `A, C, D` and executing `delete_member`. This clears `R2`'s own confirmations and any requests *created by* `B`, but `confirmations[R] = {A, B}` is untouched because `R` was created by `A`, not `B`. `B` is now removed from `self.members`.
6. `C.confirm(R)` → `confirmations[R].len() + 1 == 3 >= num_confirmations(3)` → `execute_request(R)` fires the `Transfer`.
7. Result: request `R` executed with confirmations nominally satisfying "3 of 4," but the *live* member set at execution time is `{A, C, D}`, and only `A` and `C` (2 live members) actually approved it after `B`'s removal — the threshold was bypassed using `B`'s stale, no-longer-valid confirmation.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
