### Title
Path-traversal via glob pattern `..` segments bypasses `findRelativePathInProject`'s directory-escape check - (File: commands/helpers/file_archiver.go)

### Summary
`fileArchiver.findRelativePathInProject` validates only the non-glob "base" portion of a `--path`/`artifacts:paths` value against `c.wd`, then joins the glob "pattern" portion back on afterward without re-checking the result. Because `filepath.Join` performs `Clean`, a pattern containing `..` segments *after* the first glob metacharacter can reintroduce path components that escape `c.wd` after the security check has already passed, and the resulting string is fed directly into `doublestar.FilepathGlob` and `filepath.Walk`.

### Finding Description
The function first splits the input on the first occurrence of a glob metacharacter (`*?[{`) using `doublestar.SplitPattern`: [1](#0-0) 

Only the literal `base` component is resolved to an absolute path and checked against `c.wd`: [2](#0-1) 

The check at line 214 passes because it only sees `rel` derived from `base`, not the full path. The glob `patt` (which may legitimately contain `../` segments occurring after the first metachar, e.g. `"*/../../../etc/passwd"`) is then joined onto the already-validated `rel` **after** the check, with no subsequent re-validation: [3](#0-2) 

`filepath.Join` calls `Clean`, which collapses `foo/*/../../../etc/passwd` down to `../etc/passwd` — a path that once again escapes `c.wd`, but is returned as-is with no error. This value is then used directly as a glob pattern in `processPath`: [4](#0-3) 

`doublestar.FilepathGlob` and `filepath.Walk` then operate on the real filesystem relative to the process's actual working directory (`c.wd`), so `"../etc/passwd"` (or any other traversal target reachable by the number of embedded `..` segments) is walked and matched, and matched files/dirs are added to `c.files` via `c.add` for inclusion in the artifacts/cache archive. The `--path`/`artifacts:paths` values are attacker-controlled (job author defines `artifacts:paths` or cache paths in `.gitlab-ci.yml`), making this directly reachable without any special executor configuration.

### Impact Explanation
An unprivileged pipeline author can cause the Runner's artifact/cache archiver to read and package files located outside the job's build directory (`c.wd`) — e.g., other directories on the build host/container filesystem reachable via `..` traversal — into the job's artifact or cache archive. This violates the invariant that "file operations must stay within intended build/cache/artifact roots" and can leak host-side files (subject to file permissions of the job process) into artifacts/cache retrievable by the job's uploader, i.e., exfiltration of files outside the intended sandboxed directory.

### Likelihood Explanation
This requires no privileged executor misconfiguration, symlinks, or bind mounts — a plain `artifacts:paths` or cache `paths` entry with a crafted glob such as `foo/*/../../../etc/passwd` (adjusting the number of `..` levels to match `c.wd` depth, which is discoverable via `pwd`/`echo $CI_PROJECT_DIR` in an earlier script step) is sufficient. It is fully repeatable and deterministic, since `filepath.Join`'s `Clean` behavior is well-defined Go standard library behavior. The only "difficulty" is knowing the depth of `c.wd` to craft the right number of `..` segments, which is trivially discoverable from within the job itself.

### Recommendation
Re-validate the fully joined path (`filepath.Join(rel, patt)`) against the `..`-prefix check *after* the join, not just the `base` portion before it. E.g., after line 219, re-run the same `strings.HasPrefix(cleaned, ".."+separator) || cleaned == ".."` check on the final `rel` and return an error if it still escapes, mirroring the check already applied to the base-only case.

### Proof of Concept
Go unit test to add to `commands/helpers/file_archiver_test.go`, exercising `findRelativePathInProject` directly (as `TestFileArchiver_pathIsInProject` already does), asserting that a glob pattern with post-metachar `..` segments is rejected:

```go
func TestFileArchiver_globWithTraversalSegments(t *testing.T) {
    wd, err := os.Getwd()
    require.NoError(t, err)

    c := &fileArchiver{wd: wd}

    // "sub" is a literal prefix (no meta chars), but the glob segment "*/../../.."
    // walks back out past wd after the base-only check has already passed.
    path := "sub/*/../../../etc/passwd"

    rel, err := c.findRelativePathInProject(path)

    // Currently: err == nil and rel == "../etc/passwd" (escapes wd) — BUG.
    // Expected (fixed behavior):
    assert.Error(t, err, "expected traversal via glob pattern to be rejected, got rel=%q", rel)
}
```

Running this against the current code shows `err == nil` and `rel` resolving to a path starting with `../`, i.e. outside `c.wd`, confirming the bypass. An end-to-end PoC job would set `artifacts:paths: ["sub/*/../../../etc/passwd"]` (adjusting `..` depth to `$CI_PROJECT_DIR`), then inspect the resulting artifact archive to confirm `/etc/passwd` was included.
