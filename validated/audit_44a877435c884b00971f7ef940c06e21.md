### Title
Per-IP QUIC connection rate limiting is trivially bypassed by IPv6 /64 sybil to exhaust the shared global connection-rate budget - ([File: streamer/src/nonblocking/connection_rate_limiter.rs])

### Summary
`ConnectionRateLimiter` in `streamer/src/nonblocking/connection_rate_limiter.rs` keys its `KeyedRateLimiter<IpAddr>` on the exact source `IpAddr` returned from the completed QUIC handshake, with no aggregation by IPv6 prefix. Because a single IPv6 allocation (a /64 or larger, trivially obtainable and free for any unprivileged internet user) contains ~1.8×10^19 distinct addresses, an attacker can complete one handshake per distinct address, each getting a fresh `TokenBucket`, and thereby consume the shared `overall_connection_rate_limiter` budget in `streamer/src/nonblocking/quic.rs` without ever tripping the per-IP limiter.

### Finding Description
`ConnectionRateLimiter::new` builds a `KeyedRateLimiter<IpAddr>` keyed strictly by `std::net::IpAddr` [1](#0-0) . `is_allowed`/`register_connection` look up state purely by exact IP equality; if the IP has never been seen, `is_allowed` returns `true` and `register_connection` creates a brand-new `TokenBucket` for it via `consume_tokens` [2](#0-1) . There is no /56 or /64 prefix normalization for IPv6 addresses anywhere in this path.

In `run_server`, both the per-IP limiter and a single shared `overall_connection_rate_limiter` (`TokenBucket::new(MAX_CONNECTION_BURST, MAX_CONNECTION_BURST, TOTAL_CONNECTIONS_PER_SECOND)`) gate every accepted QUIC handshake [3](#0-2) . After the QUIC handshake completes, `setup_connection` calls `rate_limiter.register_connection(&from.ip())` and then `overall_connection_rate_limiter.consume_tokens(1)` [4](#0-3) . The per-IP limiter can only ever reject connections from the *same* address exceeding `max_connections_per_ipaddr_per_min`; it provides no defense once the attacker rotates addresses. Since the global limiter is a single shared token bucket (`TOTAL_CONNECTIONS_PER_SECOND` / `MAX_CONNECTION_BURST`), an attacker who completes handshakes from many distinct IPv6 addresses within a single /64 can monopolize this shared budget while staying under the per-IP cap on each address, causing legitimate clients' handshakes to be rejected via the `overall_connection_rate_limiter.consume_tokens(1).is_err()` branch (`stats.connection_rate_limited_across_all`) rather than the per-IP path.

The code comment in `run_server` acknowledges the intended defense-in-depth design ("rate-limit abusive peers by (control-asserted) ip", "cap total connections per-peer/ip") but does not account for the attacker asserting control over an effectively unlimited number of distinct, individually-valid IPv6 addresses from one allocation [5](#0-4) .

### Impact Explanation
This is a non-RPC ingest resource-exhaustion issue on the TPU QUIC front door: the shared, IP-agnostic `overall_connection_rate_limiter` budget (`MAX_CONNECTION_BURST`/`TOTAL_CONNECTIONS_PER_SECOND`) can be consumed almost entirely by a sybil attacker rotating through IPv6 addresses in a single /64, each staying comfortably under `max_connections_per_ipaddr_per_min`. This degrades or starves legitimate unstaked/low-priority client connection admission at the QUIC ingest layer, matching the "non-RPC remote resource exhaustion / ingest starvation" impact category called out in scope.

### Likelihood Explanation
The precondition is only "attacker controls an IPv6 /64 (or larger) allocation," which is a default, free, and common capability for essentially any residential or cloud internet connection today — no privileged access, staked identity, or non-default validator configuration is required. Completing a real QUIC handshake per source address is the only cost, and the per-IP limiter's design explicitly permits fresh buckets per unseen IP by design, so this is fully reachable with default configuration and repeatable indefinitely (bounded only by `CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD = 100_000` map entries, which is itself easily exceeded by a /64 sybil, at which point older entries are evicted and can be reused).

### Recommendation
Aggregate per-IP rate limiting keys for IPv6 by network prefix (e.g., truncate to a /56 or /64 boundary, configurable) rather than the full 128-bit address, so `ConnectionRateLimiter` treats an entire attacker-controlled allocation as one rate-limited entity, analogous to common QUIC/DDoS mitigation practice (e.g., quiche/QUIC-LB and many CDNs rate-limit by IPv6 /56 or /64 rather than full address).

#[tokio::test]
async fn test_ipv6_sybil_bypasses_per_ip_limiter() {
    use std::net::{IpAddr, Ipv6Addr};
    let limiter = ConnectionRateLimiter::new(/*limit_per_minute=*/2, /*max_burst=*/2, 4);

    // Attacker owns 2001:db8::/64 -- generate N distinct addresses within it.
    let base: u128 = 0x2001_0db8_0000_0000_0000_0000_0000_0000;
    let mut allowed_count = 0;
    for i in 0..10_000u128 {
        let ip = IpAddr::V6(Ipv6Addr::from(base | i));
        // Each distinct IPv6 address gets a fresh TokenBucket, so registration
        // succeeds even though the attacker vastly exceeds the intended
        // per-source rate when viewed as one /64 owner.
        assert!(limiter.is_allowed(&ip));
        if limiter.register_connection(&ip) {
            allowed_count += 1;
        }
    }
    // Expect ~10,000 successful registrations despite limit_per_minute=2,
    // demonstrating the per-IP limiter provides no aggregate protection
    // for a single /64 owner.
    assert_eq!(allowed_count, 10_000);
}

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
