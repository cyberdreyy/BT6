### Title
TOCTOU race between reading `highest_super_majority_root()` and `BankForks::get(slot)` causes silent loss of `accountSubscribe` initial notification for `finalized` commitment - ([File: rpc/src/rpc_subscriptions.rs])

### Summary
`initial_last_notified_slot` reads `block_commitment_cache.highest_super_majority_root()` and then, without holding any lock across the gap, calls `bank_forks.read().unwrap().get(slot)?`. Between these two unsynchronized reads, `AggregateCommitmentService`/`root_utils::set_bank_forks_root` can advance the commitment cache's `highest_super_majority_root` and call `BankForks::set_root`, whose `prune_non_rooted`/`get_non_rooted` logic prunes banks with `slot < new_highest_super_majority_root`, which can include the just-read (older) root slot. This causes `bank_forks.read().unwrap().get(slot)` to return `None`, and the `?` operator silently drops the initial notification for a `finalized`-commitment `accountSubscribe`.

### Finding Description
In `initial_last_notified_slot`:
```rust
let slot = if params.commitment.is_finalized() {
    block_commitment_cache.read().unwrap().highest_super_majority_root()
} ...
let bank = bank_forks.read().unwrap().get(slot)?;
Some(bank.get_account_modified_slot(&params.pubkey)?.1)
``` [1](#0-0) 

The two reads acquire and release two separate `RwLock`s (`block_commitment_cache` then `bank_forks`) with no atomicity between them. Concurrently, `AggregateCommitmentService::update_commitment_cache` computes a new, larger `highest_super_majority_root` and writes it into the cache [2](#0-1) , and then the replay/root path calls `root_utils::set_bank_forks_root` → `BankForks::set_root` → `prune_non_rooted` → `get_non_rooted` with that new `highest_super_majority_root` value [3](#0-2) .

`get_non_rooted`'s keep condition explicitly requires `*slot >= highest_super_majority_root` for non-root ancestors to survive pruning:
```rust
let keep = *slot == root
    || self.descendants[&root].contains(slot)
    || (*slot < root
        && *slot >= highest_super_majority_root
        && self.descendants[slot].contains(&root));
!keep
``` [4](#0-3) 

If the RPC thread's earlier-read `slot` (the old `highest_super_majority_root` value) is now `< new_highest_super_majority_root` (a normal, expected progression as consensus advances), that bank is removed by `prune_non_rooted`/`self.remove(slot)` in the same `set_root` call [5](#0-4) . When the RPC thread then calls `bank_forks.read().unwrap().get(slot)`, it gets `None`, and the `?` operator in `initial_last_notified_slot` returns `None` for the whole function rather than panicking or retrying. This silently causes no initial notification to be sent for a legitimately requested `finalized` `accountSubscribe`, i.e., a wrong (empty) initial account-subscription state rather than a crash.

### Impact Explanation
Scoped impact: a single, valid `accountSubscribe` request with `CommitmentConfig::finalized()` can have its initial notification silently dropped due to this internal race, producing incorrect/incomplete pubsub behavior (client believes it is subscribed and awaits updates, but never receives the initial finalized state, potentially leading to desync until the next account-modifying slot triggers a subsequent notification). This matches the "wrong-slot/fork/account data returned" / notification-completeness category rather than a crash or DoS.

### Likelihood Explanation
This requires no attacker privilege beyond issuing one ordinary `accountSubscribe` call; the race trigger (root advancing and pruning while the RPC read is in flight) happens naturally on every validator due to the normal root/commitment-update cadence, so it's a narrow but repeatable timing window that occurs during ordinary cluster operation, not something the client can control precisely. It is a genuine TOCTOU rather than a deliberately triggerable exploit, so likelihood is opportunistic/low-probability-per-call but non-zero and naturally recurring across many subscriptions over time.

### Recommendation
Take a single consistent snapshot: while holding `bank_forks.read()` (or a snapshot of both bank_forks and the specific bank `Arc`), re-derive/validate the `slot` under one critical section, or retry `get(slot)` against `bank_forks.root()` if the originally-selected slot is no longer present (falling back to the current root bank rather than dropping the notification). Alternatively, have `BlockCommitmentCache` return the corresponding `Arc<Bank>` atomically together with the slot number under a single lock acquisition, eliminating the gap between reading `highest_super_majority_root()` and calling `bank_forks.get()`.

    fn prune_non_rooted(
        &mut self,
        root: Slot,
        highest_super_majority_root: Option<Slot>,
    ) -> (Vec<BankWithScheduler>, u64, u64) {
        // We want to collect timing separately, and the 2nd collect requires
        // a unique borrow to self which is already borrowed by self.banks
        let mut prune_slots_time = Measure::start("prune_slots");
        let prune_slots: Vec<_> = self
            .get_non_rooted(root, highest_super_majority_root)
            .collect();
        prune_slots_time.stop();

        let mut prune_remove_time = Measure::start("prune_slots");
        let removed_banks = prune_slots
            .into_iter()
            .filter_map(|slot| self.remove(slot))
            .collect();
        prune_remove_time.stop();

        (
            removed_banks,
            prune_slots_time.as_ms(),
            prune_remove_time.as_ms(),
        )
    }

    pub fn get_non_rooted(
        &self,
        root: Slot,
        highest_super_majority_root: Option<Slot>,
    ) -> impl Iterator<Item = Slot> + '_ {
        let highest_super_majority_root = highest_super_majority_root.unwrap_or(root);
        self.banks.keys().copied().filter(move |slot| {
            let keep = *slot == root
                || self.descendants[&root].contains(slot)
                || (*slot < root
                    && *slot >= highest_super_majority_root
                    && self.descendants[slot].contains(&root));
            !keep
        })
