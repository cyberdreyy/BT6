### Title
Stale confirmations from removed multisig members are still counted toward the confirmation threshold, allowing requests to execute below the live-member quorum - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::confirm` decides whether to execute a request purely by comparing the *size* of the stored `confirmations: HashSet<String>` against `self.num_confirmations`, without ever re-validating that every entry in that set still corresponds to a currently active member. `delete_member` only purges confirmations/requests that the removed member itself *created* (`r.member == member`), but never scans other members' pending requests to strip confirmations the removed member had *given*. A confirmation cast by a member who is later removed therefore remains permanently counted, letting a request execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
The relevant logic: [1](#0-0) 

`confirm` never checks that each `String` already stored in `confirmations` still belongs to `self.members` — it only checks `confirmations.len() as u32 + 1 >= self.num_confirmations`.

`delete_member` is the only place confirmations get cleaned up on removal, and it is scoped incorrectly: [2](#0-1) 

It filters `self.requests` for entries where `r.member == member` (i.e., requests *authored* by the removed member) and clears confirmations only for *those* requests. It does **not** iterate over `self.confirmations` to strip the removed member's entry from requests authored by *other* members. Consequently, if member `A` confirmed a request `R` created by `B`, and `A` is later removed via `DeleteMember`, `R`'s confirmation set still contains `A`'s entry indefinitely.

This breaks the intended custody/authorization binding:
```
confirmations counted for a request == confirmations from currently live members
```
Instead, after a member removal, `confirmations counted for a request >= confirmations from currently live members`, because stale entries persist and are never revalidated against `self.members`.

### Impact Explanation
This is a threshold/authorization bypass on a NEAR account controlled by the multisig contract. A request (e.g., a `Transfer` of NEAR, an `AddKey`, or a `FunctionCall`) can execute after receiving fewer *live* member confirmations than `num_confirmations` mandates, because one or more of the counted confirmations belong to members that have since been removed (e.g., a compromised key that was intentionally revoked). This falls under the Critical impact category: "a multisig request executed below threshold."

### Likelihood Explanation
This requires no privileged action beyond normal multisig operation: a member confirms a pending request, then later that member is removed for any reason (compromise, rotation, offboarding) via the standard `DeleteMember` flow which is a first-class, documented feature of the contract [3](#0-2) . Because `DeleteMember` is a normal governance action expected to be exercised over the contract's lifetime (key rotation, revoking a compromised signer), the stale-confirmation condition is readily reachable without any deployment misconfiguration or victim key requirement beyond the ordinary use of "confirm then later be removed."

### Recommendation
When executing `delete_member`, iterate over all entries in `self.confirmations` (not just requests authored by the removed member) and remove the removed member's entry from every confirmation set. Alternatively, revalidate every confirming identity against `self.members` inside `confirm` before counting it toward `num_confirmations`, discarding stale entries either lazily on read or eagerly on member removal.

### Proof of Concept
1. Deploy `MultiSigContract::new([A, B, C, D], 3)`.
2. `B` calls `add_request` to create request `R` (e.g., `Transfer` of a large amount to an attacker-controlled `receiver_id`). `R`'s confirmations set = `{}`.
3. `A` calls `confirm(R)` → `confirmations.len() == 1` (`{A}`), below threshold (3), request stays pending.
4. The multisig subsequently removes `A` (e.g., due to key compromise) by confirming and executing a `DeleteMember{A}}` request via `B`, `C`, `D`. Per `delete_member` at [4](#0-3) , only requests *authored by* `A` are purged; `R` (authored by `B`) is untouched, and its confirmation set still contains `A`.
5. Members are now `{B, C, D}` (3 members, matching `num_confirmations == 3`).
6. `C` calls `confirm(R)` → set becomes `{A, C}`, size 2, still below 3.
7. `D` calls `confirm(R)` → `confirmations.len() as u32 + 1 == 3 >= self.num_confirmations` at [5](#0-4)  → `execute_request(R)` fires, transferring funds to the attacker's `receiver_id`.
8. Only `C` and `D` — two *live* members — actually authorized this execution; the third counted "confirmation" came from `A`, who had already been removed from the multisig at the time of execution. The Transfer action executed below the intended live-member threshold.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
