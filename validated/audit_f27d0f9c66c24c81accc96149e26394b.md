### Title
Stale confirmations from removed multisig members still count toward `num_confirmations` threshold - ([File: multisig2/src/lib.rs], [File: multisig/src/lib.rs])

### Summary
When a member is removed from the multisig via `DeleteMember` (in `multisig2`) or a key is removed via `DeleteKey` (in `multisig`), the contract only purges requests that were *originated* by the removed member/key. It does not purge that member's/key's *confirmations* recorded on requests originated by other members. Because `confirm()` counts confirmations purely by set size without re-validating that every entry in the set still belongs to a current member, a request can later execute using a confirmation from an account/key that is no longer part of the multisig, effectively executing with fewer than `num_confirmations` live-member approvals.

### Finding Description
The custody binding the multisig is supposed to guarantee is: `confirmations counted == confirmations from currently live members`. This binding is broken.

In `multisig2/src/lib.rs`, `delete_member` only cleans up requests where the request's own `member` field equals the member being deleted: [1](#0-0) 

It never scans `self.confirmations` for entries where the removed member had confirmed *someone else's* request. Those stale confirmation strings remain stored under other, still-active `request_id`s.

`confirm()` then counts confirmations purely by length of the stored `HashSet<String>`, without re-checking that each entry corresponds to a member still present in `self.members`: [2](#0-1) 

The same defect exists in the original `multisig/src/lib.rs`: the `DeleteKey` action filters and removes only requests whose `signer_pk` equals the deleted key... [3](#0-2) 

...but does not scrub that key's confirmations from other requests' `confirmations` sets, and confirmation counting elsewhere is likewise based purely on set cardinality.

### Impact Explanation
This is a **Critical** impact per the custody-boundary definition: "a multisig request executed below threshold." A request (e.g., `Transfer`, `FunctionCall`, `AddKey`) can be executed with the approval of fewer *currently authorized* members than `num_confirmations` requires, because a stale confirmation from a removed member/key is silently counted as valid. This directly moves NEAR (or triggers arbitrary function calls/key changes) under insufficient live authorization — an authorization-threshold bypass.

### Likelihood Explanation
Medium/High. It requires only the ordinary sequence of multisig operations that legitimate multisig operators regularly perform:
1. A member confirms (but does not complete) a pending request.
2. The multisig later removes that member (e.g., because a key was compromised, an employee left, or membership was rotated) via the standard `DeleteMember`/`DeleteKey` flow.
3. Because the removed member's confirmation is never purged from the earlier, still-pending request, the remaining members complete confirmation and the request executes with the stale vote counted, even though the vote came from an entity no longer trusted.

No malicious insider action is needed beyond normal member-rotation hygiene — this is a logic gap in `delete_member`/`DeleteKey` cleanup, not abuse of a granted privilege.

### Recommendation
When removing a member/key, also scan all active `requests`/`confirmations` entries and strip that member's/key's confirmation string from every request's confirmation set (not only requests they originated), or alternatively re-validate at `confirm()`-time that every stored confirmation still corresponds to a current member of `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
Using `multisig2` with members `{A, B, C}` and `num_confirmations = 2`:
1. `A` calls `add_request(X)` — creates request `X` with empty confirmations, `member = A`.
2. `B` calls `confirm(X)` — `confirmations[X] = {B}` (len 1 < 2, not executed): [4](#0-3) 
3. Members submit and confirm a separate `DeleteMember { member: B }` request (2 confirmations from A and C), removing `B`. `delete_member` only removes requests where `r.member == B`; since `X.member == A`, request `X` and its confirmation set `{B}` are untouched: [5](#0-4) 
4. Now the live members are `{A, C}`, yet `num_confirmations` is still `2`.
5. `A` calls `confirm(X)`. `confirmations[X].len() (1) + 1 >= num_confirmations (2)` → request `X` executes, counting `B`'s stale confirmation even though `B` is no longer a member — the request executed with only one live-member (`A`) approval instead of the required two.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
