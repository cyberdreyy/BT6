### Title
Stale confirmations from deleted multisig members remain counted toward the execution threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::confirm` decides whether a request has reached quorum purely by counting entries in the per-request `confirmations` set, without checking whether the accounts/keys in that set are still current members. `delete_member` only purges requests *authored* by the removed member, not confirmations that member left on requests authored by someone else. A member can therefore be removed from the multisig, yet their earlier confirmation continues to count toward `num_confirmations`, letting a request execute with fewer *live* signers than the configured threshold.

### Finding Description
Confirmations are tracked in `self.confirmations: LookupMap<RequestId, HashSet<String>>`, keyed by `member.to_string()`: [1](#0-0) 

`confirm()` checks quorum with `confirmations.len() as u32 + 1 >= self.num_confirmations` and, on reaching it, executes the request — it never re-validates that the accounts already present in `confirmations` are still in `self.members`.

`delete_member()` only cleans up requests where `r.member == member`, i.e. requests the removed member *created*. It never scans `self.confirmations` for other requests where the removed member appears as a confirming party: [2](#0-1) 

So the binding that should hold — *confirmations counted == confirmations from currently live members* — is broken: a stale confirmation entry from a removed member persists and is still counted by `confirm()`.

### Impact Explanation
This is a Critical-class impact per the rubric: "a multisig request executed below threshold." An attacker (or a member who is later removed, maliciously or otherwise) can leave a confirmation on a pending request; even after being deleted as a member (e.g., due to key compromise, offboarding, or a governance decision), their stale confirmation still contributes to quorum. This allows execution of arbitrary `MultiSigRequest` actions (transfers, `AddKey`, `DeployContract`, `AddMember`/`DeleteMember`, etc.) with fewer than `num_confirmations` *live* signers, undermining the entire threshold security guarantee of the multisig.

### Likelihood Explanation
Requires no attacker-only capability beyond normal usage: any member can confirm a request they don't own, then later be removed (a routine multisig operation) while the request they confirmed remains pending (up to `active_requests_limit` requests can be pending, with only a 15-minute `REQUEST_COOLDOWN` before deletion is even possible). No special privilege, victim key, or foundation/owner cooperation is required beyond the normal `DeleteMember` action that any quorum would eventually perform for legitimate operational reasons (e.g. offboarding a signer).

### Recommendation
When executing `DeleteMember`, iterate over `self.requests`/`self.confirmations` and strip the removed member's entry from every pending request's confirmation set (not only requests they authored), or re-validate at `confirm()` time that every entry in the stored confirmation set still corresponds to a current member before counting it toward `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. `A` calls `add_request(...)` creating `request_id = 0` (member field = `A`); `A` auto-confirms via `add_request_and_confirm`, so `confirmations[0] = {A}`.
3. `B` calls `confirm(0)` → `confirmations[0] = {A, B}` (len 2, threshold 3, not yet executed) — see `confirm()` at [3](#0-2) .
4. Separately, quorum executes a `DeleteMember { member: B }` request. `delete_member` removes `B` from `self.members` and any of `B`'s own key/access, but only deletes requests where `r.member == B` — request `0` (authored by `A`) is untouched, so `confirmations[0]` still contains `B`.
5. `C` calls `confirm(0)` → `confirmations.len() + 1 == 3 >= num_confirmations`, so `execute_request` runs, even though only `A` and `C` are still live members — the request executed with only 2 live confirmations against a threshold of 3.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
