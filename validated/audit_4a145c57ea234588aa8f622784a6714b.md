### Title
`extractZipFileEntry` writes zip entries using raw, unsanitized `file.Name`, allowing absolute/traversal paths to escape the extraction root - (File: helpers/archives/zip_extract.go)

### Summary
`extractZipFileEntry`, `extractZipDirectoryEntry`, and `extractZipSymlinkEntry` in `helpers/archives/zip_extract.go` write to `file.Name` directly with no path cleaning, no absolute-path rejection, and no confinement check against an extraction root, unlike the sibling `tarzstd` extractor which explicitly joins against a root directory and verifies the resolved path stays under it.

### Finding Description
`ExtractZipArchive` iterates `archive.File` entries and calls `extractZipFile(file)` for each, which dispatches to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry` based on file mode [1](#0-0) . All three of these functions use `file.Name` verbatim as the destination path for `os.Mkdir`, `os.Symlink`, and `os.OpenFile`/`os.Remove` respectively, with zero validation that the name is relative or confined to any root [2](#0-1) . The only check performed before writing is `errorIfGitDirectory`, which only rejects `.git`-prefixed entries and is purely a warning-and-continue check (via `tracker.actionable`), not a path-confinement control [3](#0-2) .

This contrasts directly with the `tarzstd` extractor in the same codebase, which explicitly computes `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any resolved path that does not have `e.dir` as a prefix, returning `"%s cannot be extracted outside of chroot (%s)"` [4](#0-3) . No equivalent root-join/prefix-check exists anywhere in `zip_extract.go`.

`ExtractZipFile`/`ExtractZipArchive` is wired up as the zip extraction implementation via `ziplegacy.extractor.Extract`, which calls `archives.ExtractZipArchive(zr)` directly on a `zip.Reader` built from attacker-supplied bytes, with no root-confinement wrapper of its own [5](#0-4) . This `ziplegacy` extractor is registered as the default zip extractor (used unless `FF_USE_FASTZIP` is enabled, in which case `fastzip.NewExtractor` — which delegates to the third-party `fastzip` library — is used instead) [6](#0-5) . Cache/artifact extraction commands (`cache_extractor.go`, `artifacts_downloader.go`) consume archive bytes originating from job-produced or user-supplied artifact/cache content and route them through this registered extractor.

Because `file.Name` in a `zip.File` is fully attacker-controlled archive metadata, an attacker who can produce the archive content consumed by an artifact/cache "restore" operation can craft entries with absolute paths (e.g. `/etc/foo`, `C:\Windows\...`, UNC paths) or `../../` traversal sequences. Since `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry` pass these names straight to OS file APIs without `filepath.Clean`, `filepath.IsAbs` rejection, or root-prefix verification, the write target is not confined to the intended restore directory.

### Impact Explanation
An unprivileged pipeline author who controls the bytes of a cache/artifact zip archive consumed via the `ziplegacy` extraction path can cause file writes (including directory creation, regular file overwrite, and symlink creation) outside the intended restore root — anywhere the Runner process has filesystem permissions to write. This enables cross-job state tampering (files planted for a later job/build to consume) or overwrite of files that carry higher trust than the sandboxed job workspace, matching the scoped "cross-job state tampering or stronger-context file overwrite" impact.

### Likelihood Explanation
Preconditions: the target Runner/executor must be using the legacy zip extraction path (`FF_USE_FASTZIP` not enabled, or the `ZipZstd` decompression path, which always uses `ziplegacy` regardless of the feature flag per the comment in `archiver.go`) [7](#0-6) . Given that, the exploit only requires the attacker to control the artifact/cache zip content (trivially achievable by any pipeline author producing job artifacts/cache), making it highly feasible and fully repeatable — no race conditions or timing dependencies are involved.

### Recommendation
Add root confinement in `extractZipFile`/`extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, mirroring the `tarzstd` extractor: resolve each entry's destination as `filepath.Abs(filepath.Join(destRoot, file.Name))`, reject any entry whose resolved path is not prefixed by `destRoot` (or equal to it), and reject symlink targets that escape the root as well. This requires threading an explicit destination-root parameter through `ExtractZipArchive`/`ExtractZipFile` (currently they operate on the current working directory implicitly), since today there is no root parameter at all to enforce confinement against.

### Proof of Concept
```go
func TestExtractZipFileEntry_RejectsAbsolutePath(t *testing.T) {
    tmpDir := t.TempDir()
    archivePath := filepath.Join(tmpDir, "evil.zip")

    f, err := os.Create(archivePath)
    require.NoError(t, err)
    zw := zip.NewWriter(f)
    // Attacker-controlled entry name is an absolute path outside tmpDir.
    evilTarget := filepath.Join(t.TempDir(), "pwned.txt")
    w, err := zw.Create(evilTarget)
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())
    require.NoError(t, f.Close())

    err = archives.ExtractZipFile(archivePath)
    // Expected (fixed) behavior: extraction is rejected or confined, and the
    // absolute-path target must NOT be created.
    _, statErr := os.Stat(evilTarget)
    assert.True(t, os.IsNotExist(statErr), "absolute-path entry escaped extraction root")
}
```
Current behavior (unpatched): `os.Stat(evilTarget)` succeeds because `extractZipFileEntry` writes directly to the attacker-supplied absolute `file.Name`, demonstrating the escape. A fixed implementation with root-confinement checks (as in `tarzstd_extractor.go`) would either return an error or write the file only under the intended destination root, causing the assertion to hold.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
