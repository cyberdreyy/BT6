## Analysis Result [1](#0-0) 

### Title
Unbounded task spawning per WebSocket subscription in flashblocks `eth_subscribe` handler enables WS-based DoS - (File: crates/execution/flashblocks/src/rpc/pubsub.rs)

### Summary
The flashblocks `EthPubSub::subscribe` handler, exposed as the public `eth_subscribe` JSON-RPC method over WebSocket, spawns a new `tokio::spawn` task and a fresh `BroadcastStream`-backed generator for every accepted subscription of kind `NewFlashblocks`, `PendingLogs`, or `NewFlashblockTransactions`, with no additional application-level cap on the number of concurrently active subscriptions per connection or per client. [2](#0-1) 

### Finding Description
`EthPubSubApiServer::subscribe` is the trait implementation backing the public `eth_subscribe` RPC method for the Base execution node's flashblocks feature. [3](#0-2)  For standard Ethereum subscription kinds it delegates to reth's own implementation, but for the Base-specific kinds (`NewFlashblocks`, `PendingLogs`, `NewFlashblockTransactions`) it accepts the pending sink and unconditionally spawns a new task that streams from a fresh `BroadcastStream` derived from `subscribe_to_flashblocks()`: [4](#0-3) 

```
let sink = pending.accept().await?;
match base_kind {
    BaseSubscriptionKind::NewFlashblocks => {
        let stream = Self::new_flashblocks_stream(...);
        tokio::spawn(async move { pipe_from_stream(sink, stream).await; });
    }
    ...
}
```

Nothing in this method checks how many subscriptions are already active for the connection before spawning another task; each subscribe request accepted by the sink immediately produces one more long-lived task plus a `BroadcastStream` receiver, regardless of how many are already outstanding. This is registered into the RPC module at node startup via `hooks.add_rpc_module`, using `ctx.registry.eth_api()` and the node's task executor: [5](#0-4) 

The execution node's WebSocket RPC transport is enabled by default in deployment configs with permissive settings (`--ws --ws.origins="*"` and public `eth,web3,net,txpool,debug` APIs), making `eth_subscribe` reachable by any anonymous WS client. [6](#0-5) [7](#0-6) 

This mirrors the reported bug class: WebSocket subscription handlers that allocate a task/generator per subscribe message without enforcing a limit on active subscriptions per connection, allowing an attacker to flood subscribe messages and cause unbounded resource growth.

### Impact Explanation
Repeated `eth_subscribe` calls with `newFlashblocks`, `pendingLogs`, or `newFlashblockTransactions` from a single (or few) connections cause linear growth in the number of live `tokio::spawn` tasks and `BroadcastStream` receivers held by the node's async runtime, each of which competes for the shared flashblocks broadcast channel and executor scheduling. Sustained flooding can exhaust memory/CPU on the RPC-serving node and degrade or crash the process, denying legitimate `eth_*` and WebSocket service — i.e., "an RPC the node can no longer serve," one of the accepted impact categories.

### Likelihood Explanation
`eth_subscribe` is a standard, publicly documented JSON-RPC method reachable by any anonymous WebSocket client with no authentication, and the flashblocks-specific kinds are handled by exactly this vulnerable code path. An attacker only needs to open one or a few WS connections and repeatedly send `eth_subscribe` requests with unique/absent IDs to trigger the unbounded task growth — no special privileges, funds, or protocol knowledge beyond the public JSON-RPC subscribe format are required.

Note: I could not confirm from the indexed code whether jsonrpsee's own built-in default per-connection subscription cap (a library-level default, not something explicitly configured in this repo) is present and would partially bound this on a single connection; I found no explicit override or removal of that default in the flashblocks-node RPC server setup, nor any application-level connection/subscription-count limiting comparable to the `InMemoryRateLimit` used by the separate `websocket-proxy` service (which is a distinct downstream fan-out proxy, not the execution node's own JSON-RPC endpoint). Even if a per-connection library default exists, an attacker can still open many WebSocket connections to multiply the effect, since I found no per-IP/global connection-count limiting on the execution node's own WS RPC endpoint in the codebase (unlike the standalone `websocket-proxy` binary, which does rate-limit connections but is a different service).

### Recommendation
Enforce an explicit, low, configurable maximum on the number of concurrently active flashblocks subscriptions per WebSocket connection (and ideally per client IP) inside `EthPubSub::subscribe` in `crates/execution/flashblocks/src/rpc/pubsub.rs`, rejecting or closing the sink when the limit is exceeded before spawning the task. Additionally, ensure the execution node's JSON-RPC/WebSocket server explicitly configures (rather than relies on library defaults for) `max_subscriptions_per_connection` and overall connection limits, consistent with the protections already implemented in `crates/infra/websocket-proxy/src/rate_limit.rs`.

### Proof of Concept
1. Connect to the Base execution node's public WebSocket RPC endpoint (`--ws.origins="*"`, `eth` namespace enabled per `etc/docker/docker-compose.yml`).
2. Repeatedly send JSON-RPC requests: `{"jsonrpc":"2.0","id":<n>,"method":"eth_subscribe","params":["newFlashblocks"]}` (or `"pendingLogs"` / `"newFlashblockTransactions"`) with incrementing `id` values and never unsubscribing, as demonstrated by the existing test harness pattern in `crates/execution/flashblocks-node/tests/flashblocks_rpc.rs`. [8](#0-7) 
3. Each accepted request causes `EthPubSub::subscribe` to `tokio::spawn` a new task and `BroadcastStream` subscriber with no bound. [9](#0-8) 
4. Repeat across one or more connections until node memory/CPU is exhausted, degrading or crashing the RPC service.

    async fn subscribe(
        &self,
        pending: PendingSubscriptionSink,
        kind: ExtendedSubscriptionKind,
        params: Option<Params>,
    ) -> SubscriptionResult {
        // For standard subscription types, delegate to reth's implementation
        if let Some(standard_kind) = kind.as_standard() {
            return RethEthPubSubApiServer::subscribe(&self.inner, pending, standard_kind, params)
                .await;
        }

        // Handle flashblocks-specific subscriptions
        let ExtendedSubscriptionKind::Base(base_kind) = kind else {
            unreachable!("Standard subscription types should be delegated to inner");
        };

        let sink = pending.accept().await?;

        match base_kind {
            BaseSubscriptionKind::NewFlashblocks => {
                let stream = Self::new_flashblocks_stream(Arc::clone(&self.flashblocks_state));

                tokio::spawn(async move {
                    pipe_from_stream(sink, stream).await;
                });
            }
            BaseSubscriptionKind::PendingLogs => {
                // Extract filter from params, default to empty filter (match all)
                let filter = match params {
                    Some(Params::Logs(filter)) => *filter,
                    _ => Filter::default(),
                };

                let stream = Self::pending_logs_stream(Arc::clone(&self.flashblocks_state), filter);

                tokio::spawn(async move {
                    pipe_from_stream(sink, stream).await;
                });
            }
            BaseSubscriptionKind::NewFlashblockTransactions => match params {
                Some(Params::Logs(filter)) => {
                    let stream = Self::new_flashblock_transactions_filtered_stream(
                        Arc::clone(&self.flashblocks_state),
                        *filter,
                    );
                    tokio::spawn(async move {
                        pipe_from_stream(sink, stream).await;
                    });
                }
                Some(Params::Bool(true)) => {
                    let stream = Self::new_flashblock_transactions_full_stream(Arc::clone(
                        &self.flashblocks_state,
                    ));
                    tokio::spawn(async move {
                        pipe_from_stream(sink, stream).await;
                    });
                }
                _ => {
                    let stream = Self::new_flashblock_transactions_hash_stream(Arc::clone(
                        &self.flashblocks_state,
                    ));
                    tokio::spawn(async move {
                        pipe_from_stream(sink, stream).await;
                    });
                }
            },
        }

        Ok(())
    }
}

#[tokio::test]
async fn test_eth_subscribe_new_flashblocks() -> eyre::Result<()> {
    let setup = TestSetup::new().await?;
    let _provider = setup.harness.provider();
    let ws_url = setup.harness.ws_url();
    let (mut ws_stream, _) = connect_async(&ws_url).await?;

    ws_stream
        .send(Message::Text(
            json!({
                "jsonrpc": "2.0",
                "id": 1,
                "method": "eth_subscribe",
                "params": ["newFlashblocks"]
            })
            .to_string()
            .into(),
        ))
        .await?;

    let response = ws_stream.next().await.unwrap()?;
    let sub: serde_json::Value = serde_json::from_str(response.to_text()?)?;
    assert_eq!(sub["jsonrpc"], "2.0");
    assert_eq!(sub["id"], 1);
    let subscription_id = sub["result"].as_str().expect("subscription id expected");

    setup.send_flashblock(setup.create_first_payload()).await?;

    let notification = ws_stream.next().await.unwrap()?;
    let notif: serde_json::Value = serde_json::from_str(notification.to_text()?)?;
    assert_eq!(notif["method"], "eth_subscription");
    assert_eq!(notif["params"]["subscription"], subscription_id);

    let block = &notif["params"]["result"];
    assert_eq!(block["number"], "0x1");
    assert!(block["hash"].is_string());
    assert!(block["parentHash"].is_string());
    assert!(block["transactions"].is_array());
    assert_eq!(block["transactions"].as_array().unwrap().len(), 1);

    Ok(())
}
