The relative path stored via `c.add(relative)` is what ends up as a key in `c.files`, and this is what gets passed to `Archive`. Since `Archive` does `os.Open(pathname)` directly with these relative paths without resolving against `a.dir` or checking symlink targets, the actual behavior depends entirely on the current working directory being `c.wd` at the time of opening.

## Analysis

**Path validation happens before `Archive`, not inside it.** The `raw.archiver.Archive` function in `commands/helpers/archive/raw/raw_archiver.go:35-52` takes whatever paths are in the `files` map and calls `os.Open(pathname)` directly — it never checks the path against `a.dir` (the `dir` field is stored but unused), unlike `tarzstd_archiver.go:68-74` which explicitly validates `filepath.Abs(path)` has the `a.dir` prefix before archiving. [1](#0-0) [2](#0-1) 

However, the `files` map fed into any archiver (including raw) is populated exclusively by `fileArchiver` in `commands/helpers/file_archiver.go`, which enforces root-containment **before** any path reaches `Archive`:

- `processPath`/`findRelativePathInProject` (`commands/helpers/file_archiver.go:191-222`) resolves the path to absolute, computes `filepath.Rel(c.wd, abs)`, and rejects it if the relative path starts with `".."`.
- `process` (`commands/helpers/file_archiver.go:65-101`) repeats this same containment check (`strings.HasPrefix(relative, ".."+separator)`) for every path discovered by `filepath.Walk`/glob, before calling `c.add(relative)`. [3](#0-2) [4](#0-3) 

Only these validated, `c.wd`-relative paths are stored via `c.add()` and later handed to `archiver.Archive(ctx, c.files)` from `commands/helpers/artifacts_uploader.go:116-126` and `commands/helpers/cache_archiver.go`. The raw archiver's `Archive` is only invoked with at most one file (`ErrTooManyRawFiles` otherwise) and that file has already passed the same containment gate as every other archive format. [5](#0-4) 

Regarding the symlink concern: since `filepath.Abs`/`filepath.Rel` operate lexically (no symlink resolution), a symlink placed *inside* the workspace whose target points *outside* the workspace (e.g., `wd/evil -> /etc/passwd`) would pass the lexical containment check, because the symlink's own path (`wd/evil`) is lexically inside `wd`. `os.Open`/`os.Lstat` on that path would then follow the symlink target when opened (though `add()` uses `Lstat`, and the archiver's `os.Open` in raw and `os.Open` in tarzstd would follow the symlink for regular file reads). This is a real, generic risk for symlink-based content substitution, but it is a property of the whole file-selection pipeline (shared by all archive formats), not something specific to `raw_archiver.go`'s missing `a.dir` check — and it requires the attacker to already have write access to the job's own workspace to plant such a symlink, which is the normal, expected attacker capability for a pipeline author (their own job's workspace). The question's stated invariant ("archive must remain inside the assigned workspace root") is enforced at the `fileArchiver` layer for all paths that reach any `archive.Archiver`, including raw, so `raw_archiver.go`'s lack of an internal check does not create a reachable path-escape given the current call graph. [6](#0-5)

func (c *fileArchiver) process(match string) bool {
	var absolute, relative string
	var err error

	absolute, err = filepath.Abs(match)
	if err == nil {
		// Let's try to find a real relative path to an absolute from working directory
		relative, err = filepath.Rel(c.wd, absolute)
	}

		// Process path only if it lives in our build directory

				return false
			}

func (c *fileArchiver) findRelativePathInProject(path string) (string, error) {
	slashPath := filepath.ToSlash(path)
	if filepath.Clean(slashPath) == filepath.Clean(c.wd) {
		return ".", nil
	}

	base, patt := slashPath, ""
	// check if path contains a glob pattern
	if strings.ContainsAny(slashPath, "*?[{") {
		base, patt = doublestar.SplitPattern(slashPath)
	}

	abs, err := filepath.Abs(base)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact absolute path %s: %w", path, err)
	}

	rel, err := filepath.Rel(c.wd, abs)
	if err != nil {
		return "", fmt.Errorf("could not resolve artifact relative path %s: %w", path, err)
	}

	// If fully resolved relative path begins with ".." it is not a subpath of our working directory
	if strings.HasPrefix(rel, ".."+string(filepath.Separator)) || rel == ".." {
		return "", fmt.Errorf("artifact path is not a subpath of project directory: %s", path)
	}

	// Relative path is needed now that our fsys "root" is at the working directory
	rel = filepath.Join(rel, patt)
	rel = filepath.FromSlash(rel)
	return rel, nil
}
