### Title
`ExternalInitiatorResource` presenter leaks the node's `OutgoingToken` webhook credential on `GET /v2/external_initiators` - ([File: core/web/presenters/external_initiators.go])

### Summary
The JSON presenter used to serve `GET /v2/external_initiators` (`ExternalInitiatorsController.Index`) returns `ExternalInitiatorResource`, which includes the `OutgoingToken` field — the credential the node uses when it calls back into the external initiator's own webhook. `OutgoingSecret`, `HashedSecret`, and `Salt` are correctly excluded from this struct, but `OutgoingToken` is not, so any caller permitted to hit this read endpoint receives a live outbound-authentication token for every registered external initiator.

### Finding Description
`core/web/external_initiators_controller.go`'s `Index` handler builds the response purely from `presenters.NewExternalInitiatorResource(initiator)` for each row returned by `BridgeORM().ExternalInitiators`: [1](#0-0) 

`ExternalInitiatorResource` and its constructor copy `OutgoingToken` directly from the `bridges.ExternalInitiator` model into the JSON-serialized resource: [2](#0-1) 

The underlying `bridges.ExternalInitiator` struct stores both `OutgoingSecret` and `OutgoingToken` as the credentials used for the node's outbound calls to the external initiator: [3](#0-2) 

While `OutgoingSecret`, `Salt`, and `HashedSecret` are correctly omitted from `ExternalInitiatorResource` (only `Name`, `URL`, `AccessKey`, `OutgoingToken`, `CreatedAt`, `UpdatedAt` are exposed), `OutgoingToken` itself is not redacted. There is no dedicated `GET /v2/external_initiators/:id` "Show" handler in this controller — only `Index` (list), `Create`, and `Destroy` exist — so the exposure occurs via the paginated list endpoint rather than a single-resource fetch, but the effect is identical: the presenter returns a real outbound credential to any caller authorized to invoke a read-only list endpoint.

### Impact Explanation
Disclosure of `OutgoingToken` lets an attacker with only read access construct requests that impersonate the node when calling the external initiator's webhook infrastructure, matching the "credential/key disclosure enabling request impersonation" bounty class. It does not expose `OutgoingSecret`, so full credential-pair impersonation (if the EI verifies both token and secret) is only partially achievable from this endpoint alone.

### Likelihood Explanation
Exploitability is high once a caller has any authenticated access to the read endpoint: no additional interaction, timing, or race conditions are required, and the leak is deterministic and repeatable for every external initiator in the list. I was unable to fully verify from the available router configuration exactly which RBAC role (`view` vs. higher) is enforced on `GET /v2/external_initiators` in `core/web/router.go` — the routing/role-guard registration for this specific endpoint was not resolved in this investigation, so the precondition that a low-privilege "view" role suffices could not be conclusively confirmed from code alone.

### Recommendation
Remove `OutgoingToken` from `ExternalInitiatorResource` (and any other read/list presenter), consistent with `OutgoingSecret`/`Salt`/`HashedSecret` already being excluded. Outbound credentials should only ever be returned once, at creation time, via `ExternalInitiatorAuthentication` (`core/web/presenters/external_initiators.go`, `NewExternalInitiatorAuthentication`), never again on subsequent list/get calls.

### Proof of Concept
Go handler-level test plan:
1. In `core/web/external_initiators_controller_test.go`, create an external initiator via `POST /v2/external_initiators` and capture its `OutgoingToken`.
2. Call `GET /v2/external_initiators` with a client scoped to a low-privilege ("view") role.
3. Parse the JSON-API response into `presenters.ExternalInitiatorResource`.
4. Assert `resp.OutgoingToken == ""` (expected to currently fail, proving the leak) and additionally assert `OutgoingSecret`, `HashedSecret`, `Salt` are absent from the raw JSON body (expected to currently pass).
5. Add a schema-level test asserting `ExternalInitiatorResource`'s JSON tags never include `outgoingToken`, `outgoingSecret`, `hashedSecret`, or `salt`, regardless of caller role.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
