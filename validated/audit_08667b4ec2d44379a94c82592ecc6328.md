### Title
Global unbounded `savedCallbacks` map with no per-sender isolation allows cross-user eviction DoS - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`handler.savedCallbacks` is a single shared map keyed only by `MessageId`, pruned globally by age/oldest-first without any per-sender quota. Because `HandleLegacyUserMessage` accepts any self-signed message with an unused `MessageId` (no allowlist/quota enforced at this call site), an attacker can flood the map with garbage entries to force premature eviction of another user's still-pending legitimate callback.

### Finding Description
`HandleLegacyUserMessage` unmarshals payload, validates timestamp/method, and unconditionally inserts a `savedCallback{createdAt: time.Now(), Callback: callback}` into `h.savedCallbacks[msg.Body.MessageId]` before fan-out to DON nodes: [4](#0-3) . The explicit `// TODO: apply allowlist and rate-limiting here` confirms no sender check or per-sender quota exists before this insertion [3](#0-2) .

`pruneCallbacks`, run on a periodic ticker via `Start`, first removes age-expired entries, then — if the map still exceeds `MaxSavedCallbacks` — sorts **all** entries globally by `createdAt` and deletes everything except the newest `maxSize/2`, with no notion of sender/owner: [5](#0-4) . `savedCallback` and the map itself carry no sender/owner field for isolation: [6](#0-5) .

Reachability: the gateway's public `ProcessRequest` routes any structurally valid, self-signed legacy message (`msg.Validate()` only checks lengths/null-suffix/signature recoverability, not sender membership) straight into `HandleLegacyUserMessage`: [7](#0-6) . Any attacker holding an arbitrary ECDSA key can therefore submit `MaxSavedCallbacks` (default 20000, `defaultMaxSavedCallbacks`) distinct `MessageId`s cheaply: [8](#0-7) . When the ticker (`CallbackPruneIntervalSec`, default 30s) fires `pruneCallbacks`, the victim's earlier-created legitimate entry — being globally the oldest — is evicted along with other old entries, dropping its channel/callback reference before the DON node's response (`handleWebAPITriggerMessage`, which does `savedCb, found := h.savedCallbacks[...]`) arrives: [9](#0-8) . Once evicted, the node's genuine response is silently dropped (`found` is false), and the victim's original HTTP request blocks until the gateway's callback timeout expires and returns a timeout error, denying the on-chain follow-up for that pipeline run/trigger.

Existing unit tests (`TestPruneCallbacks`) confirm the eviction logic is purely time-order based with no sender partitioning, evicting oldest entries regardless of who created them: [10](#0-9) .

### Impact Explanation
This is a Denial-of-Service against a specific, targeted victim's pending WebAPI trigger callback (used to route pipeline-run/target results back to the requester). It does not compromise keys, cause unauthorized fund movement, or bypass authentication — it is a scoped availability impact: the attacker can starve a targeted victim's response path, causing the gateway to time out that request instead of forwarding the correct DON response. Under the Chainlink bounty impact classes this falls into "Denial of service" for a specific service function, not a critical/high-severity fund-loss or key-disclosure class.

### Likelihood Explanation
- No credential beyond any arbitrary ECDSA keypair is required — `Sign`/`Validate` accept any self-generated key, no membership/allowlist check occurs before insertion into `savedCallbacks`. [11](#0-10) 
- The attacker needs to generate/submit on the order of `MaxSavedCallbacks/2 + 1` (≥10001 for default config) distinct valid-looking trigger messages before the prune ticker fires — feasible for a scripted attacker with modest throughput, and repeatable indefinitely.
- Timing precision to guarantee eviction of one *specific* known victim message requires the attacker to know the approximate timing of the victim's request and flood shortly after it, which adds some difficulty but is achievable given messages sort strictly by `createdAt`.

### Recommendation
- Add per-sender/per-address quotas on `savedCallbacks` (e.g., limit each `msg.Body.Sender` to N pending callbacks) and reject/rate-limit new trigger submissions from a sender once their quota is exhausted, rather than a purely global oldest-first eviction.
- Implement the allowlist/rate-limiting TODO already flagged in `HandleLegacyUserMessage` before accepting and storing a callback. [3](#0-2) 
- Consider keying eviction priority by (sender, createdAt) so that a flood from one sender only evicts that sender's own oldest entries, not the entire cache.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]

	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
