### Title
`RunLoop::get_parsed_reward_set` panics on `SignerEntries::parse` failure, wedging the signer on a malformed reward-set entry - (File: `stacks-signer/src/runloop.rs`)

### Summary
`RunLoop::get_parsed_reward_set` calls `SignerEntries::parse(self.config.network.is_mainnet(), &signers).unwrap()` on the reward set returned by the node, converting any `Error::BadSignerPublicKey` into a thread panic instead of a recoverable error. [1](#0-0)  This is a real fail-open-to-crash pattern, but I could not confirm within the available context that an unprivileged attacker can actually cause the on-chain reward set to contain a `NakamotoSignerEntry` whose `signing_key` fails `StacksPublicKey::from_slice`.

### Finding Description
`SignerEntries::parse` iterates every entry in the reward set and calls `StacksPublicKey::from_slice(entry.signing_key.as_slice())`, returning `Error::BadSignerPublicKey` if any entry's 33-byte buffer is not a valid compressed secp256k1 point. [2](#0-1)  `get_parsed_reward_set` unwraps this result unconditionally, so a single bad entry panics the whole runloop thread rather than returning `Err`. [3](#0-2)  This function is invoked from `get_signer_config`, which is on the hot path for provisioning a signer for a reward cycle. [4](#0-3) 

The entries in the reward set originate from `RawRewardSetEntry::from_pox_4_tuple`, which reads the `signer` field as `expect_buff(SIGNERS_PK_LEN)` and only length-checks it (33 bytes), padding with zero bytes on mismatch — it does **not** validate that the bytes decode to a valid secp256k1 curve point. [5](#0-4)  `make_signer_set` then builds `NakamotoSignerEntry` directly from this unchecked `signing_key` buffer with no additional validation. [6](#0-5) 

However, whether an attacker can actually get such an invalid 33-byte value accepted as their `signer-key` in a `stack-stx`/`stack-extend` transaction depends on the pox-4/pox-5 Clarity contract's validation of the `signer-key` parameter (typically enforced via a `verify-signer-key-sig` / `secp256k1-verify` check requiring the caller to produce a valid signature under that key, which would implicitly require the key to be a well-formed point). I was not able to locate or confirm the exact validation logic for `signer-key` in the `stack-stx`/`stack-extend`/`stack-aggregation-commit` Clarity functions within my available tool budget — searches for `verify-signer-key-sig` inside `pox-4.clar` did not return the surrounding logic, and I could not confirm whether `secp256k1-verify`/`Secp256k1PublicKey::from_slice` in the Clarity native function rejects malformed keys at the contract level (which would close this path) or merely returns `(ok false)` while still allowing the raw signer-key buffer to be stored regardless of verification outcome.

Because this precondition is unverified, I cannot confirm the attacker-reachable path required by the audit's rules (single unprivileged party, no special access, reaching the node's consensus-level reward-set computation with a malformed key). Without confirming that the Clarity contract path allows an arbitrary/malformed 33-byte buffer to reach `make_signer_set` as a `signing_key` for a real, active signer of a reward cycle, this cannot be validated as an attacker-reachable liveness break under the stated threat model.

### Recommendation
Independent of exploitability, `get_parsed_reward_set` should not `.unwrap()` the result of `SignerEntries::parse`; it should propagate `Error::BadSignerPublicKey` as a `ClientError`/`ConfigurationError` so the runloop can log and either retry, skip the cycle, or fail closed rather than crashing the process. This defensive fix is low-cost regardless of whether the on-chain path to a malformed key is exploitable.

    /// Get the registered signers for a specific reward cycle
    /// Returns None if no signers are registered or its not Nakamoto cycle
    pub fn get_parsed_reward_set(
        &self,
        reward_cycle: u64,
    ) -> Result<Option<SignerEntries>, ClientError> {
        debug!("Getting registered signers for reward cycle {reward_cycle}...");
        let Some(signers) = self.stacks_client.get_reward_set_signers(reward_cycle)? else {
            warn!("No reward set signers found for reward cycle {reward_cycle}.");
            return Ok(None);
        };
        if signers.is_empty() {
            warn!("No registered signers found for reward cycle {reward_cycle}.");
            return Ok(None);
        }
        let entries = SignerEntries::parse(self.config.network.is_mainnet(), &signers).unwrap();
        Ok(Some(entries))
    }
