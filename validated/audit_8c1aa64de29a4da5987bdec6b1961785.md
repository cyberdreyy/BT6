### Title
Legacy ZIP extractor writes files using unsanitized `zip.File.Name`, allowing path traversal outside the build/cache root - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipFile`/`extractZipFileEntry` in `helpers/archives/zip_extract.go` call `os.MkdirAll(filepath.Dir(file.Name), ...)` and `os.OpenFile(file.Name, ...)` directly on the archive-supplied name, with no join against, or validation against, a target directory. This is the extractor actually wired up as the default ZIP extractor (`ziplegacy`) used by `ArtifactsDownloaderCommand.Execute` and the cache extractor, and it stands in contrast to `tarzstd`'s extractor, which explicitly enforces a chroot-style prefix check.

### Finding Description
`commands/helpers/artifacts_downloader.go`'s `Execute` gets the working directory (`wd`) and calls `archive.NewExtractor(format, f, size, wd)` [1](#0-0) . For the `Zip` format, unless `FF_USE_FASTZIP` is enabled, the registered extractor is `ziplegacy.NewExtractor`, which is auto-registered in `commands/helpers/archiver.go`'s imports and is only overridden with `fastzip.NewExtractor` when the feature flag is explicitly turned on [2](#0-1) .

`ziplegacy.extractor.Extract` completely ignores the `dir` field it was constructed with and delegates straight to `archives.ExtractZipArchive(zr)`: [3](#0-2) 

`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry, which in turn calls `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, all of which use `file.Name` verbatim with `os.OpenFile`, `os.Mkdir`, or `os.Symlink`, and `os.MkdirAll(filepath.Dir(file.Name), 0o777)` to create parent directories: [4](#0-3) 

No path is ever joined to a base/confinement directory, and no check exists to reject `..` segments or absolute paths. This is functionally identical to a classic "zip slip" vulnerability. It is inconsistent with `tarzstd`'s extractor, which computes `path = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and explicitly rejects any path that doesn't have `e.dir` as a prefix: [5](#0-4) 

Confinement in the legacy zip path relies entirely on the operating system process's current working directory being the intended build directory when extraction runs, with zero defense-in-depth if any `zip.File.Name` entry contains `../` segments or an absolute path.

### Impact Explanation
If a ZIP archive with crafted entry names (e.g. `../../tmp/pwned` or an absolute path) reaches `ExtractZipArchive`/`ExtractZipFile` via the artifacts-downloader or cache-extractor commands, files can be written or symlinked outside the intended build/cache root on the runner host's filesystem, for whichever user account the `gitlab-runner-helper`/extractor process runs as. This is a violation of the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
The extraction-side bug itself is unconditionally present and trivially demonstrable with a synthetic ZIP archive, independent of how such an archive is produced. What is not confirmed with the available context is whether GitLab Runner's own archive-creation path (the ZIP archiver used to build artifacts/cache from `artifacts:paths`/`cache:paths`) already prevents `../`-style entry names from being written into archives it creates itself; I could not fully verify the archiver's path-sanitization logic in the code retrieved. If the archiver's own confinement checks already block traversal entries at creation time, then the exploit requires an attacker able to supply a hand-crafted zip through some other means (e.g., a cache/artifact byte stream not produced by the runner's own archiver), which narrows real-world exploitability. Regardless, this is a genuine missing safety check that should not rely solely on the assumption that inputs were only ever produced by a trusted, correctly-sanitizing archiver, especially since `ziplegacy` remains the default extractor absent the `FF_USE_FASTZIP` flag.

### Recommendation
Add the same chroot-style confinement check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: compute `path := filepath.Join(dir, file.Name)`, resolve it with `filepath.Abs`, and reject any entry whose resolved path does not have `dir` (plus separator) as a prefix, before performing any `os.Mkdir`, `os.OpenFile`, or `os.Symlink` calls. Also thread the actual extraction directory (`e.dir`) through `ziplegacy.extractor.Extract` into `ExtractZipArchive`/`extractZipFile` instead of relying implicitly on process CWD.

### Proof of Concept
```go
// helpers/archives/zip_extract_traversal_test.go
func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpDir := t.TempDir()
    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(origWd)

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    f, err := zw.Create("../../tmp/pwned")
    require.NoError(t, err)
    _, _ = f.Write([]byte("pwned"))
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = ExtractZipArchive(zr)
    // Expected (secure) behavior: extraction should fail or be confined.
    require.Error(t, err, "expected traversal entry to be rejected")

    _, statErr := os.Stat(filepath.Join(filepath.Dir(filepath.Dir(tmpDir)), "tmp", "pwned"))
    assert.True(t, os.IsNotExist(statErr), "file must not be written outside working directory")
}
```
Current behavior: `ExtractZipArchive` returns `nil` and the file is written outside `tmpDir` (confirming the vulnerability), contrasting with `tarzstd`'s extractor, which would return an explicit `"... cannot be extracted outside of chroot ..."` error for the equivalent tar entry.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}
