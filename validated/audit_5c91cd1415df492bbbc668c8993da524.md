## Title
Stale Confirmations From Deleted Members Are Not Purged, Allowing Multisig Requests To Execute Below The Live-Member Threshold - (File: multisig2/src/lib.rs)

### Summary
`delete_member` in `multisig2/src/lib.rs` only removes confirmations for requests that the *removed member itself created* (`r.member == member`), but never scrubs that member's confirmation from requests **created by other members that the removed member had already confirmed**. Because `confirm()` counts entries in the `confirmations` set directly against `num_confirmations`, a stale confirmation left behind by a deleted member can be combined with confirmations from fewer live members to reach the threshold and trigger execution.

### Finding Description
`confirm()` decides whether to execute a request purely by counting set membership: [1](#0-0) 

`delete_member()` removes the member from `self.members` and cleans up requests **authored by** that member, but does not scan `self.confirmations` for entries where the deleted member appears as a confirmer on requests authored by someone else: [2](#0-1) 

Sequence:
1. Multisig has `num_confirmations = 2` and members `A, B, C`.
2. `B` calls `add_request` to create request `R` (`R.member == B`).
3. `A` calls `confirm(R)`. Since `confirmations.len() (0) + 1 < 2`, it doesn't execute; `confirmations[R]` becomes `{A}`.
4. A separate, properly-confirmed multisig request executes `DeleteMember { member: A }`. Inside `delete_member`, the filter `r.member == member` only matches requests **created by** `A`; request `R` was created by `B`, so it is skipped. `A`'s stale confirmation entry `{A}` in `confirmations[R]` is never removed. `A` is removed from `self.members`.
5. Live members are now `{B, C}`, and the multisig still requires 2 confirmations.
6. `C` calls `confirm(R)`. `confirmations.len() (1, still containing stale "A") + 1 == 2 >= num_confirmations`, so `execute_request` fires.

The request executes with only one live member (`C`) actually confirming — `A`'s confirmation is a ghost from a member who no longer has any authority over the contract. The binding "confirmations counted == confirmations from live members" is broken: 2 confirmations are counted, but only 1 came from a currently valid member.

### Impact Explanation
This lets a multisig request execute below the intended live-member threshold, which directly matches the Critical impact category "a multisig request executed below threshold." Any action reachable via `MultiSigRequestAction` (fund transfer, `AddKey`/`AddMember`/`AddFullAccessKey`, `FunctionCall`, `DeployContract`, etc.) can be pushed through with insufficient real approval, effectively lowering the multisig's security threshold without any of the current members' knowledge. Because `AddKey`/`AddMember` are also gated this way, an attacker who arranges for a stale confirmation (e.g., by being removed right after confirming something) can help push through a request that grants extra access with only 1 live confirmer instead of 2.

### Likelihood Explanation
This requires no privileged access beyond being (temporarily) a member of the multisig — i.e., it's reachable by any of the multisig's own members through the standard `add_request` / `confirm` / `DeleteMember` action flow, with no owner or foundation intervention needed. The sequence (create request, confirm as a member, remove that member via a normal governance action, have another member push the same request over threshold) is a normal usage pattern and easy to trigger, especially since member removal and rotation is an expected multisig operation.

### Recommendation
When deleting a member in `delete_member`, iterate over `self.confirmations` for **all** outstanding requests (not just ones authored by the deleted member) and remove the deleted member's entry from each confirmation set. Alternatively, change `confirm()` to validate, at confirmation-counting time, that every account/key in the stored confirmation set is still a current member (filtering out stale ones) before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy multisig with `members = [A, B, C]`, `num_confirmations = 2`.
2. `B` calls `add_request(R)` (e.g. `Transfer` action to attacker-controlled account).
3. `A` calls `confirm(R)` → not yet executed, `confirmations[R] = {A}`.
4. Through a separate correctly-confirmed request, execute `DeleteMember { member: A }`.
5. `C` calls `confirm(R)` → `confirmations[R].len() (1) + 1 >= 2` → `execute_request(R)` fires with only `C` as a genuinely live confirming member, despite the contract requiring 2 confirmations from current members. [1](#0-0) [3](#0-2)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
