### Title
Dust queued withdrawal permanently/temporarily bricks `processWithdrawRequests` via `Is0` revert, freezing all queued claims - (File: contracts/IdleCDOEpochQueue.sol)

### Summary
`IdleCDOEpochQueue.processWithdrawRequests()` computes the per-epoch withdrawal price as `_underlyingsRequested * ONE_TRANCHE / _pending` and reverts with `Is0()` when the result is 0. Any KYC-passing tranche holder can queue a 1-wei withdrawal request for the next epoch. When the tranche `virtualPrice` has fallen below `1e18` (any prior loss epoch), the CDO-side `requestWithdraw` truncates the underlyings owed for that dust request to 0, the price computation returns 0, and the whole call reverts — leaving `epochPendingWithdrawals[_epoch]` nonzero forever, because only the attacker can remove their own dust request via `deleteWithdrawRequest`. Every other user's queued withdrawal for that epoch is frozen.

### Finding Description
Withdrawal requests are queued in `requestWithdraw(uint256 amount)` with no minimum amount; a user transferring 1 wei of tranche registers `userWithdrawalsEpochs[user][nextEpoch] = 1` and `epochPendingWithdrawals[nextEpoch] = 1` (`contracts/IdleCDOEpochQueue.sol:131-143`).

In `processWithdrawRequests()` (`contracts/IdleCDOEpochQueue.sol:298-329`):

- `_cdo.requestWithdraw(_pending, tranche)` returns `_underlyingsRequested`, computed inside the CDO as roughly `_pending * virtualPrice(tranche) / ONE_TRANCHE`.
- `uint256 _epochPrice = _underlyingsRequested * ONE_TRANCHE / _pending;` followed by `if (_epochPrice == 0) revert Is0();` (`lines 318-321`).

For `_epochPrice` to be 0 it suffices that `_underlyingsRequested == 0`, which happens whenever `virtualPrice < ONE_TRANCHE` (i.e., after any loss epoch / haircut, the common state where claims matter most) and `_pending` is small enough that the product truncates to 0 — e.g. `_pending = 1` wei of tranche.

Because the revert occurs before `epochPendingWithdrawals[_epoch]` is cleared, the state is untouched: honest users cannot delete the attacker's request (`deleteWithdrawRequest` only operates on `msg.sender`'s entry, `lines 203-218`), and `epochWithdrawPrice[_epoch]` remains 0 so `claimWithdrawRequest` also cannot proceed. The owner/manager cannot force-remove the request. The attacker can repeat the dust request every epoch at negligible cost, turning a per-epoch DoS into an effectively permanent freeze of all queued withdrawals.

### Impact Explanation
Temporary-to-permanent freezing of funds: all users who queued withdrawals in the poisoned epoch have their tranche tokens locked in the queue and cannot claim underlyings. The broken invariant is liveness of the withdrawal queue — a single unprivileged dust request blocks the privileged `processWithdrawRequests` settlement path for everyone. Loss magnitude equals the entire `epochPendingWithdrawals` of that epoch while the condition persists (per-epoch, repeatable).

### Likelihood Explanation
Requires: (a) a KYC-passed wallet (same requirement as any depositor), (b) 1 wei of the tranche token, and (c) `virtualPrice(tranche) < 1e18`, which holds after any loss-bearing `stopEpoch` — precisely when withdrawal demand spikes. The attacker spends only gas plus dust to keep the queue bricked each epoch. Uncertainty: if `virtualPrice >= 1e18` and the CDO's `requestWithdraw` rounds the dust request to a nonzero underlying amount, the revert path is unreachable; the attack is therefore conditional on a depressed tranche price, and on the CDO not reverting internally on a 0-underlying request (it does not — the `Is0` guard in the queue exists specifically because 0 is reachable).

### Recommendation
Enforce a minimum withdrawal request size (e.g. revert in `requestWithdraw` if `amount` is below a dust threshold such that `amount * virtualPrice` cannot truncate to 0), or make `processWithdrawRequests` skip/zero-price dust requests instead of reverting (mirror the `isEpochWithdrawZero` handling already added for claims), or allow owner/manager to cancel dust-sized requests.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCDOEpochQueue, Is0} from "../contracts/IdleCDOEpochQueue.sol";
import {IdleCDOEpochVariant} from "../contracts/IdleCDOEpochVariant.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";
import {IERC20Detailed} from "../contracts/interfaces/IERC20Detailed.sol";

// Fork test: run against a deployed epoch-variant CDO whose tranche
// virtualPrice < 1e18 (post-loss epoch), or recreate via stopEpochWithDuration loss.
contract QueueDustDoSTest is Test {
    IdleCDOEpochQueue queue;
    IdleCDOEpochVariant cdo;
    IdleCreditVault strategy;
    IERC20Detailed tranche;
    address manager;
    address honestUser;
    address attacker; // KYC-passed EOA

    function testDustRequestBlocksProcessWithdrawRequests() public {
        uint256 epoch = strategy.epochNumber() + 1;

        // honest user queues a real withdrawal during the running epoch
        uint256 honestAmt = 100e18;
        deal(address(tranche), honestUser, honestAmt);
        vm.startPrank(honestUser);
        tranche.approve(address(queue), honestAmt);
        queue.requestWithdraw(honestAmt);
        vm.stopPrank();

        // attacker queues 1 wei of tranche in the same epoch
        deal(address(tranche), attacker, 1);
        vm.startPrank(attacker);
        tranche.approve(address(queue), 1);
        queue.requestWithdraw(1);
        vm.stopPrank();

        assertEq(queue.epochPendingWithdrawals(epoch), honestAmt + 1);

        // buffer period: manager tries to settle withdrawal requests
        vm.prank(manager);
        vm.expectRevert(Is0.selector); // _underlyingsRequested == 0 -> _epochPrice == 0
        queue.processWithdrawRequests();

        // state unchanged; attacker refuses to delete -> honest claim frozen
        assertEq(queue.epochPendingWithdrawals(epoch), honestAmt + 1);
        assertEq(queue.epochWithdrawPrice(epoch), 0);
    }
}
```

Preconditions for the PoC: tranche `virtualPrice < 1e18` (simulate by stopping an epoch with a loss via `stopEpochWithDuration`), a KYC-approved attacker wallet, and the epoch in its buffer phase when `processWithdrawRequests` is invoked.
