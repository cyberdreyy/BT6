## Analog Found: Premature replay-guard commit in Chainlink's Vault gateway authorizer

The Furnace bug is a "checkpoint advances even though the guarded action never completed" pattern: `lastPayout`/`lastPayoutBal` are updated to reflect a melt that didn't happen, permanently depriving token holders of value they were owed for that period. The same premature-commit pattern exists in the unprivileged-reachable Vault gateway request authorizer.

### Title
Replay guard records request digest before owner-binding validation completes, permanently locking out legitimate retries - (File: core/capabilities/vault/authorizer.go)

### Summary
`authorizer.AuthorizeRequest` commits a request's digest to the `RequestReplayGuard` *before* it finishes validating that the request is actually authorized to touch the claimed secret owner. If that later `validateSecretOwnersMatchAuthorized` check fails, the request is rejected — but the digest has already been permanently recorded as "seen," so any subsequent, otherwise-valid resubmission with the same digest is rejected forever with `ErrRequestAlreadySeen`.

### Finding Description
In `AuthorizeRequest`: [1](#0-0) 

the sequence is:
1. Authenticate (allowlist or JWT) and obtain `authResult` (digest + expiry).
2. `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` — this **records** the digest as seen as a side effect, even on the very first (successful) call.
3. Only afterward does it call `validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner())`, which can still fail (e.g., owner mismatch in the encrypted secret payload).

The replay guard itself is a simple "seen" map keyed by digest with no rollback path: [2](#0-1) 

Because `CheckAndRecord` unconditionally inserts the digest into `seen` on the first sighting (step 2), there is no mechanism to "un-record" the digest if the subsequent owner-binding check (step 3) fails. The digest — which is derived from the request's method/params/ID via `req.Digest()` — is now permanently blacklisted for its `expiresAt` window, exactly like `lastPayout` in Furnace being advanced even though the melt for that period never actually occurred. The requester is deprived of the ability to ever successfully process that exact request, even though the failed attempt was never actually authorized/completed.

### Impact Explanation
Any unprivileged client hitting the Vault gateway endpoint (`vault.secrets.create/update/delete/list`) whose request momentarily fails the owner-binding check (e.g., a benign client bug producing a params/owner mismatch, or a malicious third party crafting a lookalike request that reproduces the same digest) causes that specific request digest to be permanently rejected as a replay, even though the underlying action was never actually authorized or executed. This is a denial-of-service against a specific, otherwise legitimate request — the same "premature checkpoint / lost intended action" defect class as the Furnace finding, just manifesting as permanent request lockout rather than lost melt value.

### Likelihood Explanation
Reachable by any client calling the gateway's Vault JSON-RPC methods without any special privilege — only a valid (possibly self-crafted) JWT/allowlist entry is needed, which unprivileged workflow owners already possess to interact with Vault. Triggering the owner-mismatch failure path is trivial (malformed or mismatched `owner` field in `CreateSecretsRequest`/`UpdateSecretsRequest`/`DeleteSecretsRequest`/`ListSecretIdentifiersRequest`), as shown by the existing validation tests in `validateSecretOwnersMatchAuthorized`.

### Recommendation
Move the `replayGuard.CheckAndRecord` call to after `validateSecretOwnersMatchAuthorized` succeeds, so the digest is only committed once the request is fully authorized (mirroring how `WorkflowMetadataHandler.Authorize` correctly calls `h.jwtCache.recordUsage(claims.ID)` only after all authorization checks pass): [3](#0-2) 

### Proof of Concept
1. Craft a `vault.secrets.create` request with a valid JWT/allowlist auth for owner `A`, but with `EncryptedSecrets[0].Id.Owner = "B"` (owner mismatch).
2. Send it to the gateway; `CheckAndRecord` records the digest as seen, then `validateSecretOwnersMatchAuthorized` rejects it with an owner-mismatch error (request never processed).
3. Correct the payload (owner `A`) and resend the identical request (same digest, e.g., resubmitted by the legitimate client's retry logic).
4. The second, fully valid request is rejected with `ErrRequestAlreadySeen` — as demonstrated by the existing replay tests confirming a second call with the same digest always fails regardless of whether the first attempt succeeded: [4](#0-3)

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestAuthorizer_RejectsJWTReplay(t *testing.T) {
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "1",
		Method: vaulttypes.MethodPublicKeyGet,
		Auth:   "jwt-token",
	}
	digest, err := req.Digest()
	require.NoError(t, err)

	jwtBasedAuth := vaultmocks.NewAuthorizer(t)
	jwtBasedAuth.EXPECT().AuthorizeRequest(mock.Anything, req).Return(vault.NewAuthResult("org-1", "", digest, time.Now().Add(time.Minute).Unix()), nil).Twice()

	a := vault.NewAuthorizer(nil, jwtBasedAuth, logger.TestLogger(t))

	authResult, err := a.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Empty(t, authResult.AuthorizedOwner())

	authResult, err = a.AuthorizeRequest(t.Context(), req)
	require.Nil(t, authResult)
	require.ErrorIs(t, err, vault.ErrRequestAlreadySeen)
}
