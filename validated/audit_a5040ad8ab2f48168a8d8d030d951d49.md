### Title
JWT Replay Protection Race Condition Allows Duplicate Workflow Trigger Execution — ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `WorkflowMetadataHandler.Authorize` function checks JWT replay status via a separate `isReplay` read-lock call and later records usage via a separate `recordUsage` write-lock call, with no atomicity between the check and the record. Concurrent HTTP trigger requests using the same signed JWT can both pass the replay check before either records usage, defeating the intended single-use protection — the same failure pattern as the report's root cause, where a decision-making check (`canStartDraw`) is evaluated independently from, and inconsistently with, the state-mutating action (`startDraw`), leaving a window where stale/duplicated state is acted upon.

### Finding Description
`Authorize` is the entry point used to validate a workflow-trigger JWT before allowing an HTTP-triggered workflow execution to proceed: [1](#0-0) 

It calls `h.jwtCache.isReplay(claims.ID)` to check whether the JWT ID (`jti`) has already been used, and only after passing all other authorization checks does it call `h.jwtCache.recordUsage(claims.ID)` to mark the JWT as spent: [2](#0-1) 

`isReplay` acquires `cache.mu.RLock()` and returns immediately, and `recordUsage` acquires `cache.mu.Lock()` separately — these are two independent, non-atomic critical sections. Between the `isReplay` check and the `recordUsage` write, there is no lock held over the whole `Authorize` call. If two requests carrying the exact same signed JWT (same `jti`) arrive concurrently — which an external, unprivileged client fully controls since it possesses the JWT — both goroutines can call `isReplay` and see `exists == false` before either has called `recordUsage`, so both requests pass the replay check and are treated as authorized, identical to the report's flaw where `canStartDraw`'s check and `startDraw`'s actual state-transition condition diverge under concurrent/retried conditions.

This differs structurally from a plain "duplicate request ID" collision that `setupCallback` already guards against (`h.callbacks[requestID]` uniqueness check), because the replay guard here is specifically meant to prevent **JWT reuse** as an authentication control, independent of the caller-supplied `requestID`. An attacker can use two different `requestID`s with the same JWT/signature to bypass the "used once" invariant, since `validateRequestID`/`setupCallback` dedupe on `requestID`, not on `jti`.

### Impact Explanation
A captured/observed signed JWT trigger request (e.g., replayed by a proxy, buggy retry logic in a client, or a malicious relay sitting between an unprivileged client and the gateway) can be submitted twice concurrently with two different `requestID`s and both will pass authorization, resulting in the same authorized workflow execution being triggered more than once. This is a concrete authentication/replay-protection bypass leading to unauthorized duplicate job execution for a caller who should only get a single execution per JWT.

### Likelihood Explanation
Exploitation requires only network-level concurrency of two requests bearing the same JWT and different `requestID` values — no privileged access is required, and the race window (RLock read + subsequent separate Lock write) is realistically hittable under load or intentional concurrent submission by an unprivileged client.

### Recommendation
Make the replay check-and-record atomic: combine `isReplay` and `recordUsage` into a single method that acquires `cache.mu.Lock()` once, checks for existence, and if absent, inserts within the same critical section (analogous to `RequestReplayGuard.CheckAndRecord` in `core/capabilities/vault/request_replay_guard.go`, which already does this correctly). Update `Authorize` in `workflow_metadata_handler.go` to call this single atomic method instead of the separate `isReplay`/`recordUsage` calls.

### Proof of Concept
1. Obtain a validly signed JWT for a workflow trigger request (as any unprivileged client capable of signing requests for their own workflow).
2. Submit two HTTP trigger requests concurrently to the gateway with the same JWT (`Auth` header) but two different `requestID` values (`req.ID`), e.g. via two simultaneous goroutines/curl processes.
3. Both requests reach `Authorize`; both call `jwtCache.isReplay(claims.ID)` before either calls `recordUsage(claims.ID)`, since there is no shared lock across the full check-then-record sequence.
4. Both requests pass authorization and proceed through `checkRateLimit`/`setupCallback`/`sendWithRetries`, causing the workflow to be triggered twice from a single JWT that was intended to be single-use.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
