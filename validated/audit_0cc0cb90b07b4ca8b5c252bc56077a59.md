### Title
Unrestricted role grants via `initCalls` privileged bypass in B-20 factory `createB20` - (File: `crates/common/precompiles/src/b20_factory/logic/v1.rs`)

### Summary
The external report describes a mass-assignment bug: an untrusted client supplies extra fields (`role: admin`) that get bound directly into a privileged account record without an allowlist/authorization check. The closest reachable analog on Base is in the B-20 token factory: `createB20` accepts an attacker-supplied `initCalls: Vec<Bytes>` array of arbitrary token calldata that is executed against the freshly created token with a `privileged=true` flag [1](#0-0) . When `privileged=true`, `grant_role` for any non-`DefaultAdmin` role skips **every** authorization check entirely.

### Finding Description
`createB20` decodes `call.initCalls` and routes each entry through the token's `route()` with `privileged: true`, running with the factory's own caller context [2](#0-1) . The `route()` dispatcher forwards this `privileged` flag unchanged into `handle_asset_call`/`handle_b20_call`, which reaches `grant_role` [3](#0-2) .

`grant_role`'s authorization logic is:
```
if role == DefaultAdmin.id() || !privileged { ensure_role_admin_mutations_available(...)?; }
if !privileged { ensure_role(caller, role_admin)?; }
grant_role_unchecked(...)
``` [4](#0-3) 

For any role **other than** `DefaultAdmin` (e.g. `MINT_ROLE`, `BURN_ROLE`, `SEIZE_ROLE`, `PAUSE_ROLE`, `METADATA_ROLE`), when `privileged=true` **both** guard branches are skipped — there is no caller-authorization check whatsoever. This is confirmed by the existing unit test `grant_role_privileged_grants_and_emits`, which grants `MINT_ROLE` to an arbitrary account purely because `privileged=true`, without any caller-role check [5](#0-4) .

The `privileged` flag is intended only for the factory's own bootstrap sequence (granting `initialAdmin` before any admin exists) [6](#0-5) , but the *same* privileged context is reused to execute the caller-supplied `initCalls` array during `createB20`, as shown by the golden test that mints tokens via an init call executed atomically at creation [7](#0-6) . Nothing in `init_asset_token`/`init_stablecoin` restricts which functions an `initCalls` entry may target, or requires them to only run before an admin exists — the loop just executes each attacker-supplied calldata blob with `privileged=true` unconditionally [8](#0-7) .

This is the mass-assignment analog: the `initCalls` field is meant only to let a token creator perform ordinary launch configuration (mint, set cap, pause), but it also transparently grants access to a hidden "trusted/privileged" execution mode that removes admin-role checks — exactly like the anything-llm bug where an unvalidated `role` property let a client silently opt into an admin-privileged code path.

### Impact Explanation
Any caller of the public `createB20` precompile function (any unprivileged transaction sender/contract deployer) can pass `initCalls` entries that grant themselves (or any address) `MINT_ROLE`, `SEIZE_ROLE`, `BURN_ROLE`, `PAUSE_ROLE`, etc. on the newly created token, bypassing the intended requirement of holding the corresponding role-admin. Since `grantRole` for non-default roles is dispatched through the exact same `route`/`grant_role` code path used for normal post-creation calls, and `privileged=true` is not otherwise scoped to a "no admin yet" bootstrap invariant for non-`DefaultAdmin` roles, an attacker can mint unlimited token supply (`MINT_ROLE`), seize arbitrary balances (`SEIZE_ROLE`), or otherwise fully control the token's supply/security policy immediately at creation, regardless of the `initialAdmin` parameter they declared. This directly satisfies "unauthorized operation" / "unbacked supply" impact criteria for a B-20 token created through this factory.

### Likelihood Explanation
Trivial and fully attacker-controlled: `createB20` is a public precompile entry point callable by any signed transaction, `initCalls` is plain user-supplied `bytes[]` calldata with no validation on which selectors it may contain, and the vulnerable `grant_role` logic with the missing check is exercised by the codebase's own tests, confirming the code path is live and reachable in the current implementation.

### Recommendation
In `grant_role` (both `b20_asset` and `b20_stablecoin`, v1 and v2), require the `ensure_role_admin_mutations_available`/`ensure_role` authorization checks for privileged calls unless the role is exactly the bootstrap `DefaultAdmin` grant performed directly by the factory (not through arbitrary `initCalls`). Concretely, either: (a) restrict `initCalls` privilege so it can only invoke a fixed allowlist of launch-configuration functions (mint/pause/setCap/metadata) that intentionally require creator trust, explicitly excluding `grantRole`/`revokeRole`/`setRoleAdmin`; or (b) scope `privileged=true` role grants strictly to `role == DefaultAdmin.id()` and route all other role mutations back through the normal caller-authorization path even when invoked from `initCalls`.

### Proof of Concept
```rust
// Attacker calls createB20 with initCalls containing a grantRole to themselves.
let attacker = Address::repeat_byte(0x41);
let params = IB20Factory::B20AssetCreateParams {
    version: B20Variant::Asset.supported_version(),
    name: "Evil".into(),
    symbol: "EVL".into(),
    initialAdmin: Address::ZERO, // no admin declared
    decimals: 6,
};
let grant_mint = IB20::grantRoleCall {
    role: B20TokenRole::Mint.id(),
    account: attacker,
}.abi_encode();

let call = IB20Factory::createB20Call {
    variant: IB20Factory::B20Variant::ASSET,
    salt: B256::repeat_byte(0x01),
    params: params.abi_encode().into(),
    initCalls: vec![Bytes::from(grant_mint)], // executed with privileged=true, no auth check
};
// factory.create_b20(attacker, call, upgrade) — attacker now holds MINT_ROLE
// on the token despite declaring no initialAdmin and never holding role-admin.
```
This mirrors `golden_create_with_init_calls`, which already demonstrates that arbitrary `initCalls` entries execute atomically with elevated (`privileged=true`) trust during token creation [7](#0-6) , combined with the unchecked-grant behavior shown in `grant_role_privileged_grants_and_emits` [5](#0-4) .

    /// factory-init privilege.
    pub fn route<O>(
        &mut self,
        ctx: StorageCtx<'_>,
        calldata: &[u8],
        version: AssetVersion,
        privileged: bool,
        observer: O,
    ) -> base_precompile_storage::Result<Bytes>
    where
        O: PrecompileCallObserver,
    {
        // Fast-path `announce` before the generic decode; `announce` is the only B-20 selector an
        // aliased payload can amplify. `DecodedAnnounce::decode_if_announce` runs
        // `decode_sequence` and `valid_token` and keeps the `bytes[]` entries as slices into
        // `calldata`, never owned copies. A call this version doesn't recognize as `announce`
        // falls through to the generic decode below, unchanged. A recognized but malformed
        // `announce` returns `Some(Err(..))` when the rejection can be cheap without changing
        // frozen revert bytes (Cantina #16 follow-up). V1/Beryl can't take that path, so it falls
        // through too, with today's error bytes.
        match DecodedAnnounce::decode_if_announce(calldata, version) {
            Some(Ok(announce)) => {
                return observer.observe("precompile-b20-asset-announce", || {
                    self.run_announce(ctx, version, privileged, &observer, announce)?;
                    Ok(Bytes::new())
                });
            }
            Some(Err(error)) => return Err(error),
            None => {}
        }

        let call = version.abi().decode(calldata)?;
        let label = call.as_label();
        match call {
            AssetCall::Asset(call) => {
                let asset_observer = observer.clone();
                observer.observe(label, move || {
                    self.handle_asset_call(ctx, call, version, privileged, asset_observer)
                })
            }
            AssetCall::Common(call) => {
                observer.observe(label, || self.handle_b20_call(ctx, call, version, privileged))
            }
        }
