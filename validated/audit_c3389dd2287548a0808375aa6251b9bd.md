### Title
Local Signer State Machine Wedges to `Uninitialized` on Any Error Mid-`bitcoin_block_arrival` - (File: `stacks-signer/src/v0/signer_state.rs`)

### Summary
`LocalStateMachine::bitcoin_block_arrival` unconditionally swaps `self` to `Uninitialized` at the start of the call via `std::mem::replace`, then only restores it to `Initialized(...)` at the very end of the function, after several fallible operations chained with `?`. Any error raised in between (including one deterministically reachable through gossiped `StateMachineUpdate` content) leaves the signer's local state machine permanently `Uninitialized` instead of restoring the prior state — the same "clear-context-on-error" anti-pattern described in the external report.

### Finding Description
At function entry the code takes ownership of the current state and marks `self` as `Uninitialized` "just in case": [1](#0-0) 

It then performs several operations that can return early via `?` or explicit `return Err(...)`, all of which occur **before** `self` is ever restored: [2](#0-1) [3](#0-2) 

`self` is only reset back to `Initialized` at the tail of the function, and the surrounding comment explicitly flags this as a known fragility: [4](#0-3) 

The `ReplayState::infer_state` branch is the most directly gossip-triggerable path: `tx_replay_set` is populated from other signers' `StateMachineUpdate` messages (via `handle_state_machine_update`/`capitulate_viewpoint`, which insert peer updates into the `GlobalStateEvaluator` and can be adopted into the local `tx_replay_set`), while `tx_replay_scope` is a separately-maintained local field set only by this signer's own fork-handling logic (`handle_possible_bitcoin_fork`). A malicious or simply out-of-order signer update can therefore desynchronize `tx_replay_set` from `tx_replay_scope`, causing `ReplayState::infer_state` to return `None` on the next burn-block tick — at which point `self` is already `Uninitialized` and the function returns `Err(SignerChainstateError::LocalStateMachineNotReady)` without restoring the prior state: [5](#0-4) 

This is structurally identical to `handleJobReply`'s `h.Clear()` on any `HandleReply` error in the external report: an error that should be recoverable (a stale/out-of-sync replay scope, a transient node-RPC failure inside `get_current_and_last_sortition`/`is_tenure_valid`/`make_miner_state`) instead wipes the entire state object rather than leaving it untouched or restoring the pre-call value.

### Impact Explanation
Once wedged, the signer's `local_state_machine` reports `Uninitialized` for every subsequent tick until a full, error-free re-derivation succeeds. This state machine is what the signer gossips to peers (`send_signer_update_message`) and what drives capitulation/miner-tracking logic (`capitulate_viewpoint`, `update_parent_tenure_last_block`, `update_protocol_version`). A signer stuck `Uninitialized` broadcasts a degraded view to the rest of the network and stops correctly tracking the active miner/tenure/protocol version, which can affect global state evaluation and capitulation decisions network-wide — a liveness wedge in the state-machine layer that persists until the next call happens to complete without error (which, if triggered repeatedly by peer gossip desync, may not reliably self-heal).

### Likelihood Explanation
The `ReplayState::infer_state` branch requires only that this signer be in "replay pending" mode with `tx_replay_set` set from gossip while `tx_replay_scope` lags behind — reachable by any peer signer sending replay-related `StateMachineUpdate` gossip, no majority required. The RPC-error branches (`get_current_and_last_sortition`, `is_tenure_valid`, `make_miner_state`) additionally trigger on ordinary transient node errors, making the wedge easy to hit even without adversarial input, though those are not attacker-controlled paths.

### Recommendation
Do not perform `std::mem::replace(self, Self::Uninitialized)` before the fallible computation completes. Compute the new state into a local variable and only assign it to `*self` once the entire function has succeeded, or on any early error restore `*self` to the captured `prior_state_machine` instead of leaving it `Uninitialized`.

### Proof of Concept
1. Signer A is `Initialized` with `tx_replay_set = None`, `tx_replay_scope = None`.
2. A peer signer sends a `StateMachineUpdate` gossip message with replay txids set; via `handle_state_machine_update`/`capitulate_viewpoint` this updates Signer A's `tx_replay_set` to `Some(...)` without updating `tx_replay_scope` (owned separately by A).
3. On the next Bitcoin block tick, `bitcoin_block_arrival` runs: `self` is replaced with `Uninitialized` (line 575), reaches `ReplayState::infer_state(&tx_replay_set, tx_replay_scope)` with mismatched state (line 630), returns `None`, and the function returns `Err(SignerChainstateError::LocalStateMachineNotReady)` (line 636) without restoring `self`.
4. `local_state_machine` is now permanently `Uninitialized`; every subsequent processing cycle in `Signer::process_event` (`stacks-signer/src/v0/signer.rs:346-351`) logs the error and leaves the state degraded until a lucky error-free re-derivation occurs.
