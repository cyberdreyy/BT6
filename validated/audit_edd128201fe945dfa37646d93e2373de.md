### Title
Unchecked `mark_locally_accepted` failure lets a signer's `signed_group` timestamp and block re-broadcast survive an already-terminal `GloballyRejected` state - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` mirrors the classic "unchecked return value" bug class from the ERC-20 report: it calls `block_info.mark_locally_accepted(true)`, ignores the `Err` result in all but a log line, and then unconditionally continues to persist the block and broadcast it to the node, exactly as if the state transition had succeeded.

### Finding Description
`BlockInfo::mark_locally_accepted` first mutates state (`signed_group.get_or_insert(...)`) and only afterwards calls `self.move_to(BlockState::LocallyAccepted)`, returning whatever `Err` that produces: [1](#0-0) 

`move_to`/`check_state` make `GloballyRejected` and `GloballyAccepted` mutually terminal — a block already `GloballyRejected` can never legally move to `LocallyAccepted`: [2](#0-1) 

In `store_and_process_block_signature`, the `Err` from `mark_locally_accepted` is swallowed (only logged, and only if `!has_reached_consensus()`), and execution falls through unconditionally to `insert_block` and `broadcast_signed_block`: [3](#0-2) 

The same "check-then-ignore-and-proceed" pattern recurs at every other call site of `mark_locally_accepted`/`mark_locally_rejected`/`mark_pre_committed` in `signer.rs` (e.g. lines 1467-1478, 1946-1970), so the side effect (timestamp mutation) is never gated on the transition actually succeeding, and the caller never aborts the subsequent persistence/broadcast on failure.

Consequently, if a signer's local view of a block has already reached `GloballyRejected` (its own model's terminal, safety-relevant decision) and a subsequent `BlockResponse::Accepted` message pushes the recomputed weight over `min_weight` (e.g., due to a single equivocating signer's earlier rejection and later acceptance both being additively tallied in the separate, non-exclusive `get_block_rejection_signer_addrs` / `get_block_signatures` stores, since no code deduplicates a signer's weight across the two mutually-exclusive buckets), `store_and_process_block_signature` will still call `broadcast_signed_block` → `handle_post_block` → `stacks_client.post_block`, pushing the very block this signer had already finalized as rejected to the node.

### Impact Explanation
This breaks the documented invariant that `GloballyRejected`/`GloballyAccepted` are terminal against one another (see `docs/signer-flows.md` state diagram, section 2) and that a signer's own finalized rejection should never be undone by further tallying. A signer's process pushing a block onward after it has locally decided the block is rejected is precisely the "rejection recounted as an accept" / conflicting-signature class called out as Critical in scope: it corrupts the signer's own accept/reject accounting and can cause the node to receive and consider a block the signer set had already sunk.

### Likelihood Explanation
Reachable purely through message ordering/gossip and a single equivocating signer's two genuine, differently-signed messages (a `Rejected` then later an `Accepted` for the same block hash) — no majority, no key compromise, and no auth-token access are required. This lies squarely in-scope (`stacks-signer/src/v0/signer.rs`, `signerdb.rs`).

### Recommendation
- Make `move_to` idempotent/atomic with its side effects: only stamp `signed_group`/`signed_self`/`approved_time` after `move_to` succeeds, not before.
- In `store_and_process_block_signature` (and all sibling call sites), `return` immediately when `mark_locally_accepted` fails instead of falling through to `insert_block`/`broadcast_signed_block`.
- Ensure accept-weight and reject-weight tallies are mutually exclusive per signer address (a signer's weight should count toward only its most recent decision), so a single equivocating signer cannot inflate both buckets independently.

### Proof of Concept
1. Signer S1 receives a `BlockPreCommit`/validation flow that results in enough `Rejected` weight (>30% blocking minority) from a set of honest signers, and S1 calls `mark_globally_rejected()`, moving `block_info.state` to `GloballyRejected`. [4](#0-3) 
2. A subsequent, legitimately-signed `BlockResponse::Accepted` from a signer that previously also sent a `Rejected` for the same block (a genuine equivocation, requiring only that one signer's own key) arrives at S1 and is routed to `store_and_process_block_signature`.
3. `compute_signature_signing_weight` recomputes total accept weight purely from `get_block_signatures` (independent of the reject table), and if it reaches `min_weight`, `mark_locally_accepted(true)` is called on the `GloballyRejected` `block_info`.
4. `move_to` returns `Err("Invalid state transition from GloballyRejected to LocallyAccepted")`, but because `block_info.has_reached_consensus()` is `true`, even the warning is suppressed, and the code falls through to `insert_block` and `broadcast_signed_block`, pushing the rejected block to the node. [5](#0-4)

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }
