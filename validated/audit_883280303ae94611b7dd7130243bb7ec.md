### Title
Stale-conflict exemption in the pre-commit signing guard lets a signer equivocate on a conflicting block in a different tenure at the same height - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`handle_block_pre_commit`'s conflict guard, which is supposed to stop a signer from signing two blocks that could both end up in the chain at the same height, only asks the stacks-node whether a conflicting, previously-signed block is still live (`conflict_still_blocks`) when that conflict is *fresh*. Once a previously-signed conflicting block's endorsement timestamp falls outside `tenure_last_block_proposal_timeout`, the guard drops it from consideration entirely — with no node round-trip and no re-derivation of whether it is actually still canonical. A signer can therefore end up putting a valid signature over two conflicting blocks (different tenures, same or higher height), because the chainstate re-check (`check_block_against_signer_db_state`) that runs earlier in the same function only ever examines the proposal's own tenure (or its parent, for a tenure-change block) — never a sibling tenure — so this "freshness" gate is the only thing standing between the signer and a cross-tenure double-sign.

### Finding Description
`handle_block_pre_commit` (`stacks-signer/src/v0/signer.rs`, around lines 1383-1421) queries `get_signed_conflicts` for every block the signer has ever put a signature over (own or observed-group) at or above the proposed height, in *any* tenure: [1](#0-0) 

It then computes a `freshness_cutoff` from `tenure_last_block_proposal_timeout` and only treats a conflict as blocking if it is fresh (`last_endorsed > freshness_cutoff`) **and** no reorg permit covers it **and** `conflict_still_blocks` (a node round-trip) says the conflicting block is still reachable: [2](#0-1) 

`conflict_still_blocks` is the only place that actually asks the node whether a conflict is dead (burnchain fork orphaned the tenure, or the Stacks chain has moved past it): [3](#0-2) 

But that function is never invoked for a conflict whose `last_endorsed` timestamp is older than `freshness_cutoff` — the `.iter().find(...)` short-circuits on the `last_endorsed > freshness_cutoff` condition before `conflict_still_blocks` is ever called. A stale-but-still-perfectly-live block (e.g. it was globally accepted by every other signer and is sitting at the real chain tip) is dismissed with a purely local timestamp comparison, no query to the node at all.

The only other safety net, `check_block_against_signer_db_state`, is explicitly scoped to a single tenure — the proposal's own tenure, or its parent for a tenure-change block — and never considers a sibling block in a third, unrelated tenure: [4](#0-3) 

So for a cross-tenure conflict at the same height, the *only* protection is the freshness+`conflict_still_blocks` pair, and that pair is bypassed precisely when the earlier signature is old enough to be "stale" — regardless of whether the block it covers is still canonical.

The design note in `get_tenure_last_block_info` also documents that the same timeout window is what "closes" a tenure's last-signed-block visibility, but that only governs *same*-tenure freshness for `check_latest_block_in_tenure`, not the cross-tenure sibling check performed here: [5](#0-4) 

### Impact Explanation
This breaks the "one-per-height, no double-sign" equality the pre-commit→signature flow is built to guarantee (`docs/signer-flows.md` explicitly frames the conflict guard as existing "to stop us endorsing two blocks that could both end up in the chain"). A single signer contributing weight to two mutually exclusive blocks at the same height, once independently reproduced across enough of the signer set (each signer's local clock crossing `tenure_last_block_proposal_timeout` at different times relative to a competing proposal surfacing), can let two different tenures each accumulate the 70% aggregate signature threshold at the same Stacks height — a signer-level equivocation. This matches the Critical bucket: "a signer signing an invalid, non-canonical, or conflicting block."

### Likelihood Explanation
Triggering it needs only: (1) a signer to have previously signed/accepted a block B in tenure T1 at height H, (2) `tenure_last_block_proposal_timeout` (config, default order of minutes) to elapse without that signer's local pre-commit re-evaluation refreshing `last_endorsed`/being retried, and (3) a competing proposal at the same height H in a different tenure T2 crossing the pre-commit threshold at that point. Miners routinely retry proposals and tenure changes happen naturally around sortition boundaries, so a modestly slow miner/tenure-switch scenario combined with the timeout window is plausible without requiring a majority of colluding signers — only the timing condition on this one signer's local state.

### Recommendation
Do not let staleness alone exempt a conflict from `conflict_still_blocks`. Either always ask the node whether a same-or-higher-height conflict in another tenure is still canonical/reachable before excluding it, or replace the local timestamp heuristic with a definitive, node-derived staleness signal (e.g., only drop a conflict once `conflict_still_blocks` itself returns `false`, never on locally-measured elapsed time alone).

### Proof of Concept
1. Signer S signs block B (tenure T1, height H) — `signed_self`/`signed_group` recorded with today's timestamp.
2. Wait longer than `tenure_last_block_proposal_timeout` without B being superseded (e.g. a stalled miner, or S simply misses gossip refreshing the endorsement).
3. A new tenure T2's tenure-change block B' at height H (or higher) is proposed and, independently, reaches the 70% pre-commit threshold among some signers.
4. In `handle_block_pre_commit` for B', `get_signed_conflicts` returns B, but `last_endorsed <= freshness_cutoff`, so the `.find(...)` predicate short-circuits false without ever calling `conflict_still_blocks` — even though B is still fully live/canonical.
5. S signs B' (`mark_locally_accepted`), while B was never invalidated on-chain — S has now signed two conflicting blocks at height H in different tenures.

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)

    fn conflict_still_blocks(
        &self,
        stacks_client: &StacksClient,
        conflict: &SignedConflictInfo,
        proposed_height: u64,
    ) -> bool {
        if let Ok(burn_block) = self
            .signer_db
            .get_burn_block_by_ch(&conflict.consensus_hash)
        {
            match stacks_client.get_sortition_by_burn_hash(&burn_block.block_hash) {
                Ok(_) => {
                    // The tenure's sortition is still canonical: the conflict is live at the
                    // burn chain level, so fall through to the block-level questions.
                }
                Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => {
                    // A 404 only proves the sortition was orphaned if the node's burnchain
                    // view actually covers the burn block's height: a node still catching up
                    // 404s canonical burn blocks it hasn't processed yet (and the
                    // endpoint also 404s on internal data misses). Only trust it once the
                    // node's burnchain tip is at or past the stored burn block.
                    match stacks_client.get_peer_info() {
                        Ok(peer_info) if peer_info.burn_block_height >= burn_block.block_height => {
                            info!("{self}: A conflicting block's tenure was orphaned by a burnchain fork. The conflict no longer blocks.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "conflicting_block_height" => conflict.stacks_height,
                                "burn_block_hash" => %burn_block.block_hash,
                            );
                            return false;
                        }
                        Ok(peer_info) => {
                            info!("{self}: The node does not know a conflicting block's burn block, but its burnchain tip has not reached that height, so this does not prove the tenure was orphaned. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "burn_block_hash" => %burn_block.block_hash,
                                "burn_block_height" => burn_block.block_height,
                                "node_burn_block_height" => peer_info.burn_block_height,
                            );
                            return true;
                        }
                        Err(e) => {
                            warn!("{self}: Failed to fetch the node's burnchain tip while checking a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                            );
                            return true;
                        }
                    }
                }
                Err(e) => {
                    warn!("{self}: Failed to check whether a conflicting block's tenure is still canonical: {e:?}. Leaving the conflict in place.";
                        "conflicting_consensus_hash" => %conflict.consensus_hash,
                    );
                    return true;
                }
            }
        }
        let node_reaches_conflict = match stacks_client.get_tenure_tip(&conflict.consensus_hash) {
            Ok(tip) => tip.anchored_header.height() >= conflict.stacks_height,
            // A 404 is an answer, not a failure: the node has no blocks in that tenure at all.
            Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => false,
            Err(e) => {
                warn!("{self}: Failed to fetch the canonical tip of a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                    "conflicting_consensus_hash" => %conflict.consensus_hash,
                    "conflicting_block_height" => conflict.stacks_height,
                );
                return true;
            }
        };
        node_reaches_conflict
            || (!conflict.globally_accepted && conflict.stacks_height <= proposed_height)
    }

    /// Get the last signed block from the given tenure if it has not timed out.
    /// Even globally accepted blocks are allowed to be timed out, as that
    /// triggers the signer to consult the Stacks node for the latest globally
    /// accepted block. This is needed to handle Bitcoin reorgs correctly.
    ///
    /// The timeout window is measured from the last time a signature actually covered the
    /// block: our own (`signed_self`) or the observed group/global acceptance
    /// (`signed_group`), whichever is later, matching how `get_signed_conflicts` measures
    /// endorsement freshness. `approved_time` is deliberately not used: it is stamped at
    /// pre-commit, which carries no signature, so it would close the window early. This also
    /// means a globally accepted block we never signed ourselves gets a full window from the
    /// time its acceptance was observed, rather than timing out instantly for lack of a
    /// timestamp.
    pub fn get_tenure_last_block_info(
        consensus_hash: &ConsensusHash,
        signer_db: &SignerDb,
        tenure_last_block_proposal_timeout: Duration,
    ) -> Result<Option<BlockInfo>, ClientError> {
        // Get the last signed block in the tenure
        let last_signed_block = signer_db
            .get_last_signed_block(consensus_hash)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;

        let Some(block_info) = last_signed_block else {
            return Ok(None);
        };

        // `approved_time` may hold the pre-commit time; use the actual signature time.
        let Some(signed_over_time) = block_info.signed_self.max(block_info.signed_group) else {
            return Ok(None);
        };
