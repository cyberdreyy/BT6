### Title
Zip cache extraction path/symlink traversal (zip-slip) in legacy zip extractor lacks confinement to working directory - ([File: helpers/archives/zip_extract.go])

### Summary
The default (`FF_USE_FASTZIP` off) zip cache extractor path — `CacheExtractorCommand.Execute` → `archive.NewExtractor(archive.Zip, ...)` → `ziplegacy.extractor.Extract` → `archives.ExtractZipArchive` → `extractZipFile` → `extractZipSymlinkEntry`/`extractZipFileEntry` — uses the raw `zip.File.Name` from the archive with no confinement check against the extraction root `wd`. This is unlike the sibling `tarzstd` extractor, which explicitly resolves `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects paths outside `e.dir`.

### Finding Description
`archive.NewExtractor` dispatches by format via a registry populated in `commands/helpers/archiver.go`'s `init()`. The `ziplegacy` package is always registered for `archive.Zip`/`archive.ZipZstd`, and is the extractor actually used unless `FF_USE_FASTZIP` is enabled — in which case `fastzip.NewExtractor` (which uses the external `saracen/fastzip` library, believed to include its own zip-slip protections) is registered instead: [1](#0-0) .

`ziplegacy.extractor.Extract` calls `archives.ExtractZipArchive(zr)`, which iterates `zip.File` entries with no path validation: [2](#0-1) [3](#0-2) .

`extractZipFile` builds the destination purely from `file.Name` (attacker-controlled, from the archive entry) with `filepath.Dir(file.Name)` used for `MkdirAll`, and no `filepath.Abs`/prefix check against `wd`: [4](#0-3) . For symlink entries, `extractZipSymlinkEntry` reads the link target from the entry's *content* and calls `os.Remove(file.Name)` + `os.Symlink(string(data), file.Name)` — both the symlink's own path (`file.Name`) and its target (`data`) are fully attacker-controlled and unchecked: [5](#0-4) . Regular-file entries have the identical unchecked-path problem via `extractZipFileEntry`: [6](#0-5) .

Contrast with `tarzstd_extractor.go`, which is the only extractor in the repo enforcing containment: [7](#0-6) .

`CacheExtractorCommand.Execute` passes the process's current working directory (the job's build directory) as `wd`/`dir` to the extractor with no further sandboxing: [8](#0-7) .

Exploit flow: an attacker (a normal pipeline author) controls the content of a job that populates the shared cache for a given cache key (a normal, legitimate CI/CD capability). They craft a zip archive containing an entry with `Name` such as `../../../../home/user/.bashrc` (or, for the symlink variant, a symlink entry whose `Name` is a relative path like `escape` but whose target — read from entry content — is `../../etc/something`, or whose `Name` itself contains `../` traversal). When a later job (potentially their own, or — if cache keys are shared across the pipeline/project as intended by GitLab CI cache scoping — another job in the same protected pipeline context) restores this cache, `CacheExtractorCommand` runs the vulnerable `ziplegacy` path and writes/symlinks files outside the job's working directory, anywhere the runner process has filesystem permission to write.

### Impact Explanation
This is a file write/symlink-creation primitive outside the intended cache/build root, scoped to whatever the runner process (helper binary, running inside the job's executor context) can write to. On shell/executor setups where the job process shares a filesystem with the runner host or with a persistent build directory reused across job invocations, this allows planting files (e.g. shell rc files, cron entries, or overwriting files picked up by subsequent job runs) outside the sandboxed workspace — violating the "file operations must stay within intended build/cache/artifact roots" invariant. The severity is bounded by the executor's own isolation (e.g., a fully ephemeral container executor limits blast radius to that container's filesystem, but that still breaks the workspace confinement guarantee and can affect anything mounted or persisted across job runs, e.g. shared cache/build volumes).

### Likelihood Explanation
Feasible and repeatable: the only precondition is control over the content of one's own cache-producing job (a completely standard, unprivileged CI capability), plus use of the legacy zip cache path, which is the *default* unless `FF_USE_FASTZIP` is enabled. No auth bypass or admin compromise is required. The bug is deterministic — any subsequent extraction of the crafted archive reproduces the traversal.

### Recommendation
Add the same containment check used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`'s extraction routines: resolve `filepath.Abs(filepath.Join(dir, file.Name))` for every entry (regular files, directories, and symlinks) and reject/skip entries whose resolved path is not equal to or a descendant of `dir`; additionally validate/reject symlink targets (`data` in `extractZipSymlinkEntry`) that would resolve outside `dir` when combined with the symlink's own location. Since `ExtractZipArchive`/`extractZipFile` currently take only a `*zip.File` without the destination root, thread the extraction root (`dir`) through `ExtractZipArchive` → `extractZipFile` → `extractZipSymlinkEntry`/`extractZipFileEntry`/`extractZipDirectoryEntry` so the confinement check can be applied consistently, mirroring `tarzstd_extractor.go:58-64`.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go` style:
```go
func TestExtractZipFile_PathTraversalSymlink(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        // Build a zip in-memory with a symlink entry whose Name traverses out of dir
        var buf bytes.Buffer
        zw := zip.NewWriter(&buf)
        fh := &zip.FileHeader{Name: "../outside_link"}
        fh.SetMode(os.ModeSymlink | 0o777)
        fw, _ := zw.CreateHeader(fh)
        _, _ = fw.Write([]byte("/etc/passwd")) // attacker-controlled symlink target
        _ = zw.Close()

        f, _ := os.Create(fileName)
        _, _ = f.Write(buf.Bytes())
        f.Close()

        err := ExtractZipFile(fileName)
        require.NoError(t, err) // current behavior: no error, symlink is created outside wd

        // Assertion for the fix: entry should be rejected or confined
        _, statErr := os.Lstat("../outside_link")
        assert.True(t, os.IsNotExist(statErr), "symlink must not be created outside the extraction root")
        _ = os.Remove("../outside_link")
    })
}
```
Expected pre-fix result: the symlink `../outside_link` → `/etc/passwd` is created outside the working directory, proving the escape. Expected post-fix result: extraction rejects the entry (or confines the resulting path under the extraction root), matching `tarzstd_extractor.go`'s behavior verified by an equivalent differential test against `TestExtract` in `tarzstd_extractor_test.go`.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
