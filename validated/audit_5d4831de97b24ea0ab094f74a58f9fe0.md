### Title
Signer can be induced to sign and broadcast a signature for a block it has already recorded as `GloballyRejected` - ([File: stacks-signer/src/v0/signer.rs], [File: stacks-signer/src/signerdb.rs])

### Summary
`handle_block_pre_commit` calls `BlockInfo::mark_locally_accepted(false)` and then unconditionally proceeds to sign and broadcast the block, ignoring the `Result` returned by that call. `mark_locally_accepted` mutates `signed_self`/`valid`/`approved_time` *before* it validates the state transition via `move_to`, so those side-effect fields are poisoned even when the transition is illegal (e.g. the block is already `GloballyRejected`). Because the caller discards the error (and specifically suppresses even the warning when `has_reached_consensus()` is true — exactly the case that should have blocked the action), the signer proceeds to call `create_block_acceptance`, which unconditionally produces a valid ECDSA signature over the block header, and then broadcasts it via `send_block_response`. This mirrors the reported bug class: an internal "action" function is invoked without the flag/state-guard that the caller assumes was enforced, allowing the guarded action (execute / sign) to occur anyway.

### Finding Description
`BlockInfo::mark_locally_accepted` sets `valid`, `approved_time`, and `signed_self` before checking whether the transition to `LocallyAccepted` is legal: [1](#0-0) 

`check_state`/`move_to` correctly forbid moving out of a terminal state such as `GloballyRejected`: [2](#0-1) 

But the only caller in the signing path, `handle_block_pre_commit`, ignores that `Err` result and continues regardless: [3](#0-2) 

None of the preceding guards in `handle_block_pre_commit` (checked in order: `signed_self.is_some()`, `valid` flag, pre-commit weight threshold, `check_block_against_signer_db_state`, and the signed-conflict checks) inspect `block_info.state` for a terminal value: [4](#0-3) [5](#0-4) 

A block's local `BlockInfo` can legitimately reach `GloballyRejected` while `valid` is still `Some(true)` and `signed_self` is still `None`: `store_and_process_block_rejection` calls `mark_globally_rejected()`, which only checks/updates `state` (not `valid`), whenever enough other signers' rejections make 70% acceptance mathematically impossible — independent of this signer's own validity assessment: [6](#0-5) 

If a pre-commit message for that same block (e.g. from a peer whose pre-commit was delayed by ordinary network/gossip jitter, or resent) is processed by this signer *after* rejection consensus was already reached locally, `handle_block_pre_commit` will still tally the pre-commit weight, pass every existing guard (since none check `state`), call `mark_locally_accepted(false)` (which sets `signed_self`/`valid`/`approved_time` even though `move_to` fails and `state` stays `GloballyRejected`), and then unconditionally call `create_block_acceptance` — which signs the block header hash with the signer's private key with no state check at all — and broadcast it with `send_block_response`: [7](#0-6) 

This breaks the intended terminal-state invariant documented for `BlockState` ("Global states are terminal against each other") and produces a genuine, valid signature endorsing a block the signer has already locally decided is globally rejected.

### Impact Explanation
This is a Critical-class issue: a signer emits a cryptographically valid acceptance signature for a block already recorded as `GloballyRejected` on that same node. Because the 70%-reject/70%-accept thresholds are designed to be mutually exclusive once one side is reached, any additional accept signature produced after rejection consensus undermines that safety property; if the same race affects multiple signer nodes (a plausible, non-malicious, purely timing-based scenario since ordinary message delivery order is not guaranteed), it can contribute stray weight toward reversing a decision that was supposed to be final, and at minimum produces an internally inconsistent, non-canonical signature that other peers may store and act on.

### Likelihood Explanation
No majority of colluding signers, stolen keys, or local access is needed — a single delayed/gossiped pre-commit message arriving after this node's own rejection consensus is reached is sufficient to hit the code path. This is realistic in an asynchronous signer network where StackerDB message delivery/processing order across events is not strictly serialized with rejection-vs-pre-commit races.

### Recommendation
In `handle_block_pre_commit` (and any other call site of `mark_locally_accepted`/`mark_globally_accepted`/`mark_locally_rejected`), treat a returned `Err` as fatal to the operation: return immediately without calling `insert_block`, `create_block_acceptance`, or `send_block_response` when the state transition is rejected. Additionally, harden `BlockInfo::mark_locally_accepted` (and its sibling `mark_*` methods) to validate the transition via `check_state` *before* mutating `valid`/`approved_time`/`signed_self`, so the side-effect fields are never poisoned when the transition itself is illegal.

### Proof of Concept
1. Signer S receives and validates block B (`valid = Some(true)`, `state = PreCommitted`, `signed_self = None`).
2. Enough other signers reject B for a reason S has not yet observed (e.g. a conflict check S hasn't re-run yet); their rejection messages reach S and, via `store_and_process_block_rejection`, push rejection weight past the "70% acceptance impossible" bar, causing S to call `mark_globally_rejected()` on its local `BlockInfo` for B (`state` becomes `GloballyRejected`; `valid` remains `Some(true)`, `signed_self` remains `None`).
3. A pre-commit message for B from another (or the same, resent) signer, delayed by ordinary network/gossip timing, is now processed by `handle_block_pre_commit`.
4. None of the checks (`signed_self.is_some()`, `valid`, weight threshold, chainstate re-check, conflict checks) inspect `state`, so execution reaches `block_info.mark_locally_accepted(false)`.
5. `mark_locally_accepted` sets `signed_self`/`valid`/`approved_time`, then `move_to(LocallyAccepted)` fails (previous state `GloballyRejected`) and returns `Err`; the caller only logs (and even that is suppressed since `has_reached_consensus()` is `true`), and execution continues.
6. `create_block_acceptance(&block_info.block)` signs B's header hash with S's private key, and `send_block_response` broadcasts this acceptance to StackerDB — S has now signed and broadcast an acceptance for a block it had already recorded as `GloballyRejected`.

    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }

    /// Attempt to transition the block state
    pub fn move_to(&mut self, state: BlockState) -> Result<(), String> {
        if !self.check_state(state) {
            return Err(format!(
                "Invalid state transition from {} to {state}",
                self.state
            ));
        }
        self.state = state;
        Ok(())
    }

    pub fn create_block_acceptance(&self, block: &NakamotoBlock) -> BlockAccepted {
        let signature = self
            .private_key
            .sign(block.header.signer_signature_hash().bits())
            .expect("Failed to sign block");
        BlockAccepted::new(
            block.header.signer_signature_hash(),
            signature,
            self.signer_db.calculate_full_extend_timestamp(

                block,
                true,
            ),

                self.proposal_config
                    .read_count_idle_timeout
                    .saturating_add(self.proposal_config.tenure_idle_timeout_buffer),
                block,
                true,
            ),
        )
    }
