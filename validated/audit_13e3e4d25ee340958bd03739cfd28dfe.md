### Title
Unrestricted pprof debug endpoints exposed to any authenticated user regardless of role - ([File: core/web/router.go])

### Summary
`v2Routes` mounts `metricRoutes(authv2)` at line 446 of `core/web/router.go`, exposing full `net/http/pprof` handlers (`/v2/debug/pprof/heap`, `/goroutine`, `/profile`, `/trace`, `/cmdline`, etc.) under the `authv2` group, which is guarded only by base authentication (`auth.Authenticate` with `AuthenticateByToken`/`AuthenticateBySession`). Unlike every other sensitive route in the same group, none of these pprof routes are wrapped with `auth.RequiresEditRole`/`auth.RequiresAdminRole`/`auth.RequiresRunRole`, so any authenticated principal — including the lowest-privilege `view` role or a restricted API token — can pull full heap and goroutine dumps of the running node process.

### Finding Description
In `core/web/router.go`:

```go

    auth.AuthenticateByToken,
    auth.AuthenticateBySession,
))
{
    ...
    // Debug routes accessible via authentication
    metricRoutes(authv2)
}

`metricRoutes` registers the standard Go `net/http/pprof` handlers directly with no additional role check:

```go

	pprofGroup.GET("/cmdline", ginHandlerFromHTTP(pprof.Cmdline))

	pprofGroup.GET("/goroutine", ginHandlerFromHTTP(pprof.Handler("goroutine").ServeHTTP))
	pprofGroup.GET("/heap", ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP))
	...
}
``` [3](#0-2) 

Contrast this with every other endpoint in the same `authv2` block, all of which are explicitly wrapped in a role check, e.g. `auth.RequiresRunRole(rc.ReplayFromBlock)`, `auth.RequiresEditRole(jc.Create)`, `auth.RequiresAdminRole(uc.Index)`. [4](#0-3) [5](#0-4) [6](#0-5) 

`auth.Authenticate` only verifies identity (valid session or API token) and sets the authenticated `User` in context; it performs no role comparison itself — role gating is exclusively done via the `RequiresXRole` wrapper functions in `core/web/auth/auth.go`:

```go
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		...
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
``` [7](#0-6) 

Because `metricRoutes(authv2)` never calls into any of `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole`, a `view`-role user (or a restricted API token belonging to a `view`-role account) that successfully authenticates can `GET /v2/debug/pprof/heap`, `/goroutine`, `/profile`, `/trace`, `/allocs`, etc. and pull a full in-process memory/goroutine/CPU dump. This is confirmed by the project's own CHANGELOG entry noting "Allow dumping pprof even when not in dev mode, useful for debugging (go to /v2/debug/pprof as a logged in user)" — i.e. any logged-in user, with no role distinction, by design. [8](#0-7) 

### Impact Explanation
A heap dump (`/v2/debug/pprof/heap`) or full memory profile (`/v2/debug/pprof/profile`, `/goroutine?debug=2`) of a running Chainlink node process can contain decrypted private key material staged in memory during signing operations, session tokens/cookies, database connection strings, and other secrets held in live goroutine stacks and heap objects. This matches Chainlink's bounty impact class for sensitive information disclosure / key material exposure, reachable by the lowest-privilege authenticated role (`view`), constituting a broken authorization boundary (privilege escalation from `view` to effectively node-internals access).

### Likelihood Explanation
Exploitation requires only a valid `view`-role session or API token — the lowest privilege tier a Chainlink node operator can grant, commonly issued to monitoring/read-only integrations. No special conditions, timing, or additional bypass is needed: a single authenticated `GET` request to `/v2/debug/pprof/heap` (or any of the other pprof sub-routes) succeeds. This is trivially repeatable and requires no race conditions or environment-specific quirks.

### Recommendation
Wrap `metricRoutes(authv2)` (or the individual pprof handlers) with `auth.RequiresAdminRole` (or at minimum `auth.RequiresEditRole`) so that only privileged operators can access process-level debug/profiling data, consistent with the role gating applied to every other sensitive endpoint in `v2Routes`.

### Proof of Concept
Go handler-level integration test plan (in `core/web` test package, following existing patterns in `router_test.go`/`auth_test.go`):
1. Set up a test `chainlink.Application` and router via `NewRouter`, seed a user with `clsessions.UserRoleView`.
2. Authenticate as that view-role user (session cookie or API token via `AuthenticateByToken`).
3. Issue `GET /v2/debug/pprof/heap` and `GET /v2/debug/pprof/goroutine?debug=2` with the view-role credentials.
4. Assert the response status is `200 OK` (not `401`/`403`), and that the body is non-empty pprof/text profile data (e.g., contains goroutine stack traces or heap profile magic bytes) — proving a low-privilege caller obtained a raw process memory dump.
5. As a control, repeat against `POST /v2/replay_from_block/:number` (wrapped with `RequiresRunRole`) with the same view-role credentials and assert `401 Unauthorized`, demonstrating the inconsistency between pprof routes and properly role-gated routes.

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// GetAuthenticatedUser extracts the authentication user from the context.
func GetAuthenticatedUser(c *gin.Context) (*clsessions.User, bool) {
	obj, ok := c.Get(SessionUserKey)
	if !ok {
		return nil, false
	}

	user, ok := obj.(*clsessions.User)

	return user, ok
}

// GetAuthenticatedExternalInitiator extracts the external initiator from the
// context.
func GetAuthenticatedExternalInitiator(c *gin.Context) (*bridges.ExternalInitiator, bool) {
	obj, ok := c.Get(SessionExternalInitiatorKey)
	if !ok {
		return nil, false
	}

	return obj.(*bridges.ExternalInitiator), ok
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
