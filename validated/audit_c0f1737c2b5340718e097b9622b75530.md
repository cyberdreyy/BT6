### Title
Missing role restriction on `GET /v2/external_initiators` discloses `AccessKey`/`OutgoingToken` for all External Initiators to any authenticated user regardless of role - ([File: core/web/router.go], [File: core/web/external_initiators_controller.go], [File: core/web/presenters/external_initiators.go])

### Summary
`GET /v2/external_initiators` is registered without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, unlike `POST`/`DELETE` on the same resource, so any session/API-token authenticated user — including a bare `view` or `run` role user — can list every configured External Initiator and read its `AccessKey` and `OutgoingToken`. `OutgoingSecret`, `HashedSecret`, and `Salt` are correctly excluded from the response, so full credential-pair disclosure does not occur, but the `OutgoingToken` half of the outbound-authentication credential is exposed system‑wide to unprivileged authenticated users.

### Finding Description
The route is wired as: [1](#0-0) 
`authv2.GET("/external_initiators", paginatedRequest(eia.Index))` has no role guard, while `Create`/`Destroy` on the same resource are wrapped in `auth.RequiresEditRole`. `Index` iterates over **all** stored initiators and serializes them via `presenters.NewExternalInitiatorResource`: [2](#0-1) [3](#0-2) 
The resource includes `AccessKey` and `OutgoingToken` for every EI in the system (confirmed by the existing test asserting equality with the DB values), but omits `OutgoingSecret`, `HashedSecret`, and `Salt`: [4](#0-3) 

Regarding the specific premise in the question — that a holder of *inbound* EI `AccessKey`/`Secret` could call this endpoint — that path does not exist: `AuthenticateExternalInitiator` middleware is only applied to `/v2/ping` and `POST /v2/jobs/:ID/runs`, not to `authv2` (which requires `AuthenticateByToken`/`AuthenticateBySession`, i.e. a real user identity): [5](#0-4) [6](#0-5) 
So EI credentials alone cannot reach `Index`. However, per the rules a `view`/`run`-role authenticated user is an accepted attacker, and such a user *can* reach `Index` because it has no role check, unlike its sibling mutating endpoints.

### Impact Explanation
A low-privileged (`view` or `run` role) authenticated user can enumerate every External Initiator's `AccessKey` and `OutgoingToken` across the whole node, not just ones they created. `OutgoingToken` is part of the credential pair the node uses when calling back into external initiator systems; its disclosure to users who should have no edit-level visibility is a scoped secret-confinement/authorization defect (cross-tenant secret exposure within a single node's EI registry). `OutgoingSecret` itself, `HashedSecret`, and `Salt` are correctly redacted, so this does not amount to full node impersonation of arbitrary EIs — only partial callback-credential disclosure.

### Likelihood Explanation
Trivial and fully reproducible: any authenticated user with the lowest role (`view`) can call `GET /v2/external_initiators` since no `RequiresEditRole`/`RequiresAdminRole` wrapper guards it, in contrast to `Create`/`Destroy` on the same controller.

### Recommendation
Wrap the `Index` route with `auth.RequiresEditRole` (matching `Create`/`Destroy`) in `core/web/router.go`, and/or drop `OutgoingToken` from `presenters.ExternalInitiatorResource` so it is never returned outside the one-time `Create` response.

### Proof of Concept
Extend `TestExternalInitiatorsController_Index` in `core/web/external_initiators_controller_test.go`:
1. Create a user session/API token with `clsessions.UserRoleView`.
2. Call `GET /v2/external_initiators` as that view-role client.
3. Assert the request succeeds (HTTP 200) and the response body contains non-empty `AccessKey`/`OutgoingToken` fields for initiators the view-role user did not create — demonstrating that a role check is missing compared to `POST`/`DELETE` which return 401 for the same user.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
