### Title
Dust APR0 withdraw request permanently blocks `stopEpoch` once APR is moved off zero, freezing all pool funds - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary
An unprivileged tranche holder can poison the global `apr0TotalPrincipal` bucket by calling `requestWithdraw` with an arbitrarily small (dust) amount while `unscaledApr == 0`. Later, when the honest manager/borrower sets a non-zero APR (a normal operation between epochs), every subsequent `stopEpoch`/`stopEpochWithDuration` reverts in `prepareStopEpochWithApr0` at the `unscaledApr != 0` check, because the poisoned bucket is non-zero. There is no user-level or privileged path that clears `apr0TotalPrincipal` while APR is non-zero, so the epoch state machine is stuck and all lender funds remain locked at the borrower until the APR is driven back to exactly 0.

### Finding Description
`IdleCreditVault.requestWithdraw` routes requests to `_requestWithdrawApr0` whenever `unscaledApr == 0`, unconditionally incrementing the global `apr0TotalPrincipal` by `_amount` (IdleCreditVault.sol:285-286, 567-577). `prepareStopEpochWithApr0`, called by `IdleCDOEpochVariant` inside `stopEpoch`, returns early only when `apr0TotalPrincipal == 0`; otherwise it hard-reverts with `NotAllowed()` if `unscaledApr != 0` (IdleCreditVault.sol:502-508). The bucket is only cleared in two places: line 540 (`apr0TotalPrincipal = 0`) after the revert check, i.e. unreachable while APR != 0, and line 827 during default-claim clearing, which only decrements by the claiming user's own principal and requires a default to have occurred. `_settleApr0` (545-565) moves a user's `principal` to `settledPrincipal` but never touches `apr0TotalPrincipal`, so even after every legitimate user's request settles, the attacker's dust keeps the global bucket non-zero. An attacker deposits a minimal amount, waits for (or causes) an APR0 epoch, calls `requestWithdraw(dust)`, and the pool becomes unable to stop any epoch in any subsequent non-zero-APR configuration.

### Impact Explanation
Temporary freezing of all pool funds at pool scale. While `stopEpoch` reverts, the epoch never ends: `epochNumber` cannot advance, so `claimWithdrawRequest` reverts for every user (`epochNumber <= lastWithdrawRequest[_user]` gate at IdleCreditVault.sol:326), `startEpoch`/`getInstantWithdrawFunds` cannot run, deposits in the buffer cannot be deployed, and interest accounting halts. Recovery requires the manager to set `unscaledApr` back to 0 and successfully stop an epoch before raising APR again — but if the attacker holds a tranche balance, they can submit a fresh dust APR0 request during that forced APR0 epoch, re-poisoning the bucket and repeating the freeze indefinitely at near-zero cost (only the upfront management fee on dust). Loss is bounded by pool illiquidity duration and forfeited yield; quantified as: every block the freeze persists, `expectedEpochInterest` accrual and all withdrawals are suspended for the entire `getContractValue()` TVL.

### Likelihood Explanation
Requirements are all unprivileged: attacker needs only a KYC-passed lender position (any tranche-token holder qualifies per scope). The trigger condition — an epoch with `unscaledApr == 0` followed by a later non-zero APR — is a normal configuration transition (APR0 vaults exist explicitly; manager `setAprs` changes APR between epochs). No privileged cooperation is needed; the manager's honest APR change is what arms the trap. Cost to attacker is one dust deposit plus the management fee on dust. Existing guards do not help: the KYC/`isWalletAllowed` check only gates deposits, not `requestWithdraw` for existing holders, and there is no minimum request amount.

### Recommendation
In `prepareStopEpochWithApr0`, do not revert on `unscaledApr != 0` with a lingering bucket. Options: (a) treat a non-zero APR as an APR0 bucket termination — settle `apr0TotalPrincipal` to 0 and forfeit or pro-rata the pending APR0 interest rather than bricking the epoch; (b) enforce a minimum `requestWithdraw` amount; (c) per-epoch bucket keyed like `withdrawsRequestsByEpoch` so stale principal from a prior APR0 epoch cannot block later APR regimes. Any fix must ensure `apr0TotalPrincipal` cannot survive into an epoch where `unscaledApr != 0`.

### Proof of Concept
```solidity
// Foundry fork PoC against IdleCreditVault + IdleCDOEpochVariant
function testApr0DustBlocksStopEpoch() external {
    // vault in APR0 mode: strategy.setAprs(0,0) already configured
    address attacker = makeAddr('attacker');
    _depositWithUser(attacker, 1e6);               // minimal deposit, mint AA tranches

    vm.prank(manager);
    cdoEpoch.startEpoch();                          // epoch N running, unscaledApr == 0

    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1, address(AAtranche)); // dust request -> apr0TotalPrincipal = ~1
    assertGt(strategy.apr0TotalPrincipal(), 0);

    _stopCurrentEpochWithApr(0);                    // epoch N stops fine (apr still 0)

    // honest manager raises APR for the next epoch
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(10e18, 10e18);

    vm.prank(manager);
    cdoEpoch.startEpoch();                          // epoch N+1 running
    vm.warp(cdoEpoch.epochEndDate() + 1);

    // every stopEpoch now reverts: apr0TotalPrincipal != 0 && unscaledApr != 0
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // attacker claim does NOT clear apr0TotalPrincipal (settledPrincipal path),
    // so the freeze persists; only forcing APR back to 0 unsticks it.
}

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
