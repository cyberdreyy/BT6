### Title
Signature-weight tally bypasses the conflict/staleness re-check that gates a signer's own signing decision, letting a node broadcast a block it has already `LocallyRejected` - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` tallies peer `BlockAccepted` signatures purely by weight and, once the 70% threshold is crossed, calls `mark_locally_accepted` and `broadcast_signed_block` unconditionally. Unlike the signer's own signing path (`handle_block_pre_commit`), this tally never re-runs `check_block_against_signer_db_state` or the sibling/conflict guard (`get_signed_conflicts` / `conflict_still_blocks` / `reorg_permit_stands`) before assembling and pushing the block. A block this node has already marked `LocallyRejected` because it conflicts with a fresher/canonical signature can still be pushed to the node once enough previously-stored peer signatures accumulate weight, because the aggregate-weight path and the verified-accept path are not kept in sync.

### Finding Description
Two different code paths in `stacks-signer/src/v0/signer.rs` decide whether a block is safe to endorse, and only one of them enforces the safety checks:

- The signer's own decision to sign, in `handle_block_pre_commit`, re-runs `check_block_against_signer_db_state` and the conflict/staleness guard (`get_signed_conflicts`, `reorg_permit_stands`, freshness cutoff) immediately before calling `mark_locally_accepted`: [1](#0-0) 

- The aggregate-weight broadcast decision, in `store_and_process_block_signature`, only checks `block_info.signed_group.is_some()` and the raw signature weight before calling `mark_locally_accepted(true)` and `broadcast_signed_block` — it never re-checks `block_info.state` or re-runs any conflict/staleness guard: [2](#0-1) 

Crucially, `add_block_signature` stores an incoming peer signature into `block_signatures` unconditionally, before any conflict re-check runs: [3](#0-2) 

And when the sender never sent a pre-commit, the same call redirects into `handle_block_pre_commit` for tallying/validation purposes and `return`s — but the raw signature already written to `block_signatures` is never retracted even if that redirect ends in `mark_locally_rejected`: [4](#0-3) [5](#0-4) 

Because `get_block_signatures` (used to build `addrs_to_sigs` and compute `total_signature_weight`) reads every signature ever stored for the hash regardless of the block's current `BlockState`, and `mark_locally_accepted` is a permitted transition from `LocallyRejected` per `BlockInfo::check_state`: [6](#0-5) 

a block that this node's own `check_block_against_signer_db_state`/conflict logic has already rejected as conflicting with a fresher signed sibling can still cross the 70% signature-weight threshold in a later call to `store_and_process_block_signature` (triggered by any subsequent, possibly late-arriving or re-delivered, peer `BlockAccepted` message) and be pushed to the node via `broadcast_signed_block` → `handle_post_block`: [7](#0-6) [8](#0-7) 

This is the direct analog of the ENS finding: the "canonical" state-mutating path (`handle_block_pre_commit`, gating the signer's own signature) performs the safety re-check, while a second path that reaches the same effect (assembling and broadcasting a fully-signed block) omits it — exactly as ENS's `ETHRegistrarController.renew` mutated registrar state through a path that bypassed `NameWrapper`'s fuse-setting logic that the "real" renewal path enforced.

### Impact Explanation
This breaks the aggregated-weight-vs-verified-accepts equality: the 70%-weight threshold is meant to represent signatures the local node currently believes are safe to endorse, but the tally can include a signature the node's own logic has already deemed conflicting/invalid (block marked `LocallyRejected`). The result is the local signer instance assembling and pushing a block to its own node that it had itself flagged as conflicting with a signed sibling — a signer acting on/propagating a conflicting block, which the task's Critical-impact bucket ("a rejection recounted as an accept") directly covers, since a locally-rejected verdict is silently overridden by stale weight accounting rather than a fresh, re-validated acceptance.

### Likelihood Explanation
Triggering the stale-signature buildup requires only ordinary gossip: any peer (honest, slow, or simply reordered) sending a `BlockAccepted` for a block that later becomes conflicting, or a signer sending an acceptance without a prior pre-commit (the documented "outdated peer" fallback), is sufficient to place a signature into `block_signatures` without a state check ever being retried against it. No majority-malicious coordination is required — only enough independently valid peer signatures (which can legitimately occur before a conflict becomes visible, e.g. during a burnchain fork/reorg race) to push `total_signature_weight` over threshold after this node has already locally rejected the block.

### Recommendation
`store_and_process_block_signature` should re-verify the block against the same guards used by `handle_block_pre_commit` (`check_block_against_signer_db_state` and the conflict/staleness/reorg-permit checks) before calling `mark_locally_accepted`/`broadcast_signed_block`, and/or should refuse to tally weight for a block whose `BlockState` is `LocallyRejected` unless it is freshly re-validated. Signatures stored via `add_block_signature` for a block that a subsequent conflict check rejects should be excluded from the aggregate weight computation, not merely ignored at the point of rejection.

### Proof of Concept
1. Peer signers P1..Pn send `BlockAccepted` for block B (chain_length h) before block A (a conflicting sibling at height h in another/own tenure) is observed as canonical; each triggers `store_and_process_block_signature`, storing signatures via `add_block_signature` [9](#0-8) , but weight stays below threshold.
2. This node signs A (or observes A's group signature) and, via the normal flow, later re-evaluates B through `handle_block_pre_commit`'s conflict re-check, calling `mark_locally_rejected` on B [5](#0-4) . The previously stored signatures for B in `block_signatures` are not purged.
3. One more `BlockAccepted` for B arrives (e.g. replay, late peer, or the "outdated peer" pre-commit fallback) and triggers `store_and_process_block_signature` again; `get_block_signatures(block_hash)` returns all previously accumulated signatures for B, `total_signature_weight` now clears `min_weight`, and the code calls `mark_locally_accepted(true)` (a state-machine-legal `LocallyRejected → LocallyAccepted` transition per `BlockInfo::check_state`) [10](#0-9)  followed by `broadcast_signed_block`, pushing B to the node despite this signer having already determined B conflicts with signed block A [7](#0-6) .

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
