### Title
Stale queued deposits can be committed to a later credit epoch without expiry - ([File: contracts/IdleCDOEpochQueue.sol](contracts/IdleCDOEpochQueue.sol))

### Summary
`requestDeposit` does not let a lender specify an expiry or intended epoch. A delayed transaction can therefore enter a later epoch than the lender intended and can be immediately prefunded to the borrower, permanently removing the lender’s ability to cancel that request.

### Finding Description
`requestDeposit` binds the deposit to `epochNumber() + 1` at execution time, rather than to an epoch selected when the transaction was signed. It also has no deadline parameter. [1](#0-0) 

If a lender broadcasts the transaction while epoch `N` is running, the intended target is epoch `N + 1`. A validator can withhold the transaction through the end of epoch `N`, buffer period, and start of epoch `N + 1`; when included, the same transaction targets epoch `N + 2`. A subsequent honest manager call to `processDepositsToBorrower` can move the funds to the borrower in the same block. [2](#0-1) 

Once prefunded, `epochPrefundedDeposits[_epoch]` is non-zero and `deleteRequest` reverts, so the lender cannot recover the deposited underlying before the epoch settles. [3](#0-2) 

### Impact Explanation
The lender’s full deposited amount can be temporarily frozen in an unintended future credit epoch and exposed to that epoch’s borrower risk. If the borrower defaults before prefunded settlement, the delayed deposit can suffer a loss even though the lender would have been able to cancel had the transaction executed in the intended epoch.

For a deposit of `X` underlying, the frozen amount is `X`; the loss under a subsequent default is up to `X`, according to the applicable recovery price.

### Likelihood Explanation
The attack requires transaction censorship or delayed inclusion across an epoch boundary. This is possible on chains where validators or block builders can hold profitable or useful transactions.

No privileged role needs to be malicious. The validator only needs to include the stale `requestDeposit` immediately before a routine owner or manager `processDepositsToBorrower` call while the prefunded window remains open.

### Recommendation
Add an expiry to `requestDeposit`, for example `requestDeposit(uint256 amount, uint256 deadline)`, and revert when `block.timestamp > deadline`.

For stronger protection, also add an explicit `targetEpoch` parameter and require `targetEpoch == epochNumber() + 1`. This prevents a valid but delayed transaction from silently changing the subscribed epoch.

### Proof of Concept
This test can be added to `test/foundry/IdleCDOEpochQueue.t.sol`, using the existing fork fixture and helpers.

```solidity
function testStaleRequestDepositCanBePrefundedInLaterEpoch() external {
    uint256 amount = 100e6;
    uint256 intendedEpoch = strategy.epochNumber() + 1;

    // Simulate the user's requestDeposit transaction being withheld while
    // epoch N stops and epoch N + 1 starts.
    _stopCurrentEpoch();
    vm.prank(manager);
    cdoEpoch.startEpoch();

    // The same call now binds to epoch N + 2, not N + 1.
    deal(defaultUnderlying, FASA, amount);
    vm.startPrank(FASA);
    IERC20Detailed(defaultUnderlying).approve(address(queue), amount);
    queue.requestDeposit(amount);
    vm.stopPrank();

    assertEq(queue.userDepositsEpochs(FASA, intendedEpoch), 0);
    assertEq(queue.userDepositsEpochs(FASA, intendedEpoch + 1), amount);
    assertEq(queue.epochPendingDeposits(intendedEpoch + 1), amount);

    uint256 borrowerBalanceBefore =
        IERC20Detailed(defaultUnderlying).balanceOf(strategy.borrower());

    // A routine manager prefunding call commits the stale request.
    vm.prank(manager);
    queue.processDepositsToBorrower();

    assertEq(queue.epochPendingDeposits(intendedEpoch + 1), 0);
    assertEq(queue.epochPrefundedDeposits(intendedEpoch + 1), amount);
    assertEq(
        IERC20Detailed(defaultUnderlying).balanceOf(strategy.borrower()) -
            borrowerBalanceBefore,
        amount
    );

    // The user can no longer cancel because the request was prefunded.
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(FASA);
    queue.deleteRequest(intendedEpoch + 1);
}
```

  function requestDeposit(uint256 amount) external nonReentrant {
    // check if the wallet is allowed to deposit (ie epoch is running and keyring KYC completed)
    _checkAllowed(msg.sender);

    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    uint256 nextEpoch = IdleCreditVault(strategy).epochNumber() + 1;
    uint256 _prefundedWindow = prefundedDepositWindow;
    // Only the AA prefunded queue enforces a deposit cutoff for the next epoch.
    if (tranche == _cdo.AATranche() && _isPrefundedQueueEnabled()) {
      IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(epochPendingDeposits[nextEpoch] + amount);
      // Once funds are prefunded, or once the subscription window is reached, the next epoch is closed.
      _checkNotAllowed(
        epochPrefundedDeposits[nextEpoch] != 0 || (
        _prefundedWindow != 0 && block.timestamp + _prefundedWindow >= _cdo.epochEndDate()
      ));
    }

    // get underlying tokens from user
    IERC20Detailed(underlying).safeTransferFrom(msg.sender, address(this), amount);
    // deposit will be made in the next buffer period (ie next epoch)
    // updated user queued amount for the next epoch
    userDepositsEpochs[msg.sender][nextEpoch] += amount;
    // update pending deposits
    epochPendingDeposits[nextEpoch] += amount;
  }

  function processDepositsToBorrower() external {
    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    IdleCreditVault _strategy = IdleCreditVault(strategy);
    // only owner or strategy manager can move queued funds to the borrower
    _checkOnlyOwnerOrManager();
    // prefunded flow is supported only for AA queue
    // queue must be explicitly enabled on the prefunded CDO variant
    _checkNotAllowed(tranche != _cdo.AATranche() || !_isPrefundedQueueEnabled());

    // prefunding can be done only while epoch is running
    if (!_cdo.isEpochRunning()) {
      revert EpochNotRunning();
    }
    // Keep prefunding aligned with the same cutoff enforced for new queued deposits.
    uint256 _prefundedWindow = prefundedDepositWindow;
    _checkNotAllowed(_prefundedWindow == 0 || block.timestamp + _prefundedWindow < _cdo.epochEndDate());

    uint256 _epoch = _strategy.epochNumber() + 1;
    // prefunding can happen only once for an epoch
    _checkNotAllowed(epochPrefundedDeposits[_epoch] != 0);
    uint256 _pending = epochPendingDeposits[_epoch];
    if (_pending == 0) {
      return;
    }
    // Recheck after the cutoff because emergency state or the TVL limit can change while queued.
    IdleCDOEpochVariantPrefunded(idleCDOEpoch).checkPrefunding(_pending);

    // Switch the epoch from "queue-held" to "already at borrower" before transferring funds.
    epochPendingDeposits[_epoch] = 0;
    epochPrefundedDeposits[_epoch] = _pending;
    IERC20Detailed(underlying).safeTransfer(_strategy.borrower(), _pending);
  }

  function deleteRequest(uint256 _requestEpoch) external {
    // if the epoch price is already set, deposits were already processed so
    // the deposit request can't be deleted.
    _checkNotAllowed(epochPrice[_requestEpoch] != 0 || epochPrefundedDeposits[_requestEpoch] != 0);

    uint256 amount = userDepositsEpochs[msg.sender][_requestEpoch];
    if (amount == 0) {
      return;
    }
    // reset user deposit for the epoch
    userDepositsEpochs[msg.sender][_requestEpoch] = 0;
    // update pending deposits
    epochPendingDeposits[_requestEpoch] -= amount;
    // transfer underlyings back to the user
    IERC20Detailed(underlying).safeTransfer(msg.sender, amount);
  }
