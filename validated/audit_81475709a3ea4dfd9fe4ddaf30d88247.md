### Title
Unauthenticated repeated resumption of pipeline task runs via `PATCH /v2/resume/:runID` - (File: `core/web/router.go`, `core/services/pipeline/orm.go`)

### Summary
The `/v2/resume/:runID` endpoint, intended for external adapters to deliver async task results, is registered without any authentication middleware and its backing `UpdateTaskRunResult` query does not guard against a given `taskID` being resumed more than once with different values, mirroring the "repeatedly resolve proposals" bug class where a completion action lacks a check/flag preventing re-execution.

### Finding Description
`v2Routes` mounts the resume route on the unauthenticated group: `unauthedv2.PATCH("/resume/:runID", prc.Resume)` [1](#0-0) . `PipelineRunsController.Resume` parses the task UUID from the URL and the result body, then calls `App.ResumeJobV2` with no caller identity check, logging only an `UnauthedRunResumed` audit entry [2](#0-1) . The `runner.ResumeRun` implementation simply forwards `taskID`, `value`, and `err` into `orm.UpdateTaskRunResult` [3](#0-2) . `UpdateTaskRunResult` selects the parent run by `pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running','suspended')` and then unconditionally overwrites `output`/`error`/`finished_at` on that task run without checking whether the specific task run has already been finished: `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1` [4](#0-3) . Because the guard is only on the parent run's overall state (which flips back to `running` once resumed) rather than on whether this individual task's result has already been recorded, an unauthenticated caller who learns/guesses a valid `runID` (task UUID) can resend the PATCH request while the run is still `running`/`suspended` for a subsequent async task, and repeatedly overwrite the same task's result, or interleave malicious resume calls to inject attacker-controlled values into a task result the run has not yet consumed — the same "no completion-flag check" root cause as the `Proposer.resolveProposal` bug (validated the terminal condition but not that the individual work item had already been settled).

### Impact Explanation
An unprivileged, unauthenticated network client can inject or repeatedly overwrite async task results for any job run whose task ID (a UUID, not secret by construction) it can obtain — e.g. from job-run-related identifiers surfaced elsewhere, logs, or brute predictable schemes in some deployments — causing incorrect pipeline outputs, corrupted ETH transaction task parameters, or repeated/duplicated downstream actions (e.g., re-triggering an ETHTx task path) once the run state cycles back to `running`. This can lead to fund-affecting on-chain transactions being built from attacker-supplied data or duplicate execution of the resumed leg of a pipeline.

### Likelihood Explanation
Likelihood is moderate: exploitation requires knowledge of a valid, in-flight task UUID and the run being in `running`/`suspended` state, but the endpoint itself is completely unauthenticated by design (documented via the `UnauthedRunResumed` audit label), so no credentials, tokens, or external-initiator secrets are required to reach it — only the pipeline-level check (parent run state) gates the request, not per-task idempotency.

### Recommendation
Add a per-task-run guard in `UpdateTaskRunResult` (e.g., `AND finished_at IS NULL` on the target `pipeline_task_runs` row, checked and enforced transactionally) so a task result can only be set once; consider additionally requiring the resume payload to prove knowledge of a per-run resume token instead of relying solely on task-run UUID secrecy, consistent with how the vault/gateway handlers in this codebase already implement replay guards (`RequestReplayGuard`, `activeRequest` ID checks) for similar unauthenticated flows.

### Proof of Concept
1. Create/observe a job with an async task (e.g., a bridge task) and capture its `pipeline_task_runs.id` while the run is suspended awaiting external adapter callback.
2. Send `PATCH /v2/resume/<taskID>` with a body resolving via `pipeline.ResumeRequest` to a first result value; the run transitions and resumes execution to the next async task.
3. Before that next task resolves, or while the run is again `running`, resend `PATCH /v2/resume/<taskID>` (same taskID) with a different value/error; because `UpdateTaskRunResult`'s `WHERE` clause only checks `pipeline_runs.state`, not whether the specific task run already has `finished_at` set, the row is unconditionally overwritten again, and if `start` evaluates true it re-triggers `r.Run` for the pipeline a second time from that resumed state — with no authentication ever required.

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
