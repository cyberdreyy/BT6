## Title
Operator/beneficiary opting out of direct coin transfers permanently blocks `staking_contract` distribution, freezing staker's unlock/withdraw path - (File: aptos-move/framework/aptos-framework/sources/staking_contract.move)

## Summary
`distribute_internal` in `staking_contract.move` pays out every recipient in `distribution_pool` — the staker and the operator's beneficiary — via `aptos_account::deposit_coins`, inside a `while` loop that aborts the entire transaction if any single payout fails. [1](#0-0)  `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the destination has not registered a `CoinStore<CoinType>` and has explicitly opted out of unsolicited transfers via `set_allow_direct_coin_transfers(false)`. [2](#0-1) [3](#0-2) 

## Finding Description
`distribute_internal` is the shared payout routine invoked by `distribute`, `unlock_stake`, `request_commission`, and `switch_operator`. [4](#0-3)  It iterates every shareholder in `distribution_pool` (staker and operator-beneficiary) and calls `aptos_account::deposit_coins(recipient, coin::extract(&mut coins, amount_to_distribute))` for each one, with no error handling. [5](#0-4) 

`deposit_coins` only succeeds unconditionally for accounts that either (a) already have a `CoinStore<CoinType>` registered, or (b) still allow unsolicited direct coin transfers (`can_receive_direct_coin_transfers`). An operator (or their beneficiary, set via `set_beneficiary_for_operator`) can call the standard, unprivileged `aptos_account::set_allow_direct_coin_transfers(false)` on their own account without ever registering `CoinStore<AptosCoin>` for that coin type. Any subsequent commission distribution attempt to that address then aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. [6](#0-5) 

Because `distribute_internal` is called at the *start* of `unlock_stake` ("Force distribution of any already inactive stake") before the staker's own unlock logic runs, a single failing payout to the operator/beneficiary aborts the whole `unlock_stake` transaction — meaning the staker cannot unlock or withdraw their own principal either, since every entry point that touches this staking contract funnels through `distribute_internal` first. [7](#0-6) 

This is the same bug class as the external report: a legitimate payout path (`deposit_coins`/refund) is not robust to the destination account's valid, unprivileged configuration state (an EOA that hasn't registered the coin store / has opted out), causing funds that are rightfully due to be permanently stuck rather than delivered or safely escrowed.

## Impact Explanation
Once the operator or their beneficiary opts out of direct transfers and never registers a `CoinStore<AptosCoin>`, `distribute`, `unlock_stake`, `unlock_rewards`, `request_commission`, and `switch_operator`/`switch_operator_with_same_commission` all revert for that `(staker, operator)` staking contract, because they each call `distribute_internal` (directly or via `request_commission_internal`'s pending distribution flush) before performing their own logic. [4](#0-3) [8](#0-7)  This traps the staker's principal and rewards indefinitely and also blocks the operator from ever collecting their own already-earned commission, since the abort happens mid-distribution regardless of whose payout triggered it. This satisfies "permanent lock or non-recoverable loss of claim rights in stake, ... commission, beneficiary" per the impact gate, and it is triggerable by an unprivileged operator/beneficiary account against a staker who has no control over the operator's account configuration.

## Likelihood Explanation
The precondition is a single unprivileged, permissionless call: `aptos_account::set_allow_direct_coin_transfers(false)` on the operator's or beneficiary's own account, combined with never registering `CoinStore<AptosCoin>` (the default post-migration state for many accounts that only hold APT via the FungibleAsset primary store rather than the legacy `CoinStore`). No governance or admin privilege is needed, and the affected operator does not need to hold any special role beyond being a normal, already-configured operator/beneficiary on the staking contract. This makes the likelihood high for any staker paired with an adversarial or even a merely "coin-transfer-hardened" operator.

Caveat: this analysis could not fully confirm within the available index whether `coin::is_account_registered<AptosCoin>` treats accounts backed only by the migrated FungibleAsset primary store as "registered" (which would suppress the `can_receive_direct_coin_transfers` check for such accounts). The `coin.move` migration logic (`primary_fungible_store`/pairing) was only partially inspected, so the exact registration semantics for post-migration AptosCoin accounts are not fully verified from the retrieved snippets.

## Recommendation
- In `distribute_internal`, do not let a single failed payout abort the entire distribution loop; wrap each `aptos_account::deposit_coins` call so failures for one recipient re-queue/skip that recipient's shares (leaving them redeemable later) rather than reverting payouts already due to other shareholders.
- Alternatively, pre-validate (as `vesting::set_beneficiary` does via `assert_account_is_registered_for_apt`) that both the staker and the operator/beneficiary remain able to receive direct APT transfers, and re-check this whenever `set_beneficiary_for_operator` is called, rejecting configurations that would deadlock the staking contract.
- Provide a governance/staker-callable emergency path (e.g., permit the staker to force-withdraw independent of operator payout success) so one uncooperative operator cannot indefinitely freeze the staker's own principal.

## Proof of Concept
Conceptual PoC (Move test, not run against the live framework due to sandbox limitations):
1. `staker` creates a staking contract with `operator` via `staking_contract::create_staking_contract`.
2. `operator` calls `set_beneficiary_for_operator(operator, beneficiary)`.
3. `beneficiary` (a plain EOA, never registers `CoinStore<AptosCoin>`) calls `aptos_account::set_allow_direct_coin_transfers(beneficiary_signer, false)`.
4. Time passes; the pool accrues rewards and commission becomes due.
5. `staker` calls `staking_contract::unlock_stake(staker, operator, amount)`.
6. Expected: transaction aborts inside `distribute_internal` -> `aptos_account::deposit_coins` with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, and this abort recurs on every future call to `unlock_stake`, `unlock_rewards`, `distribute`, `request_commission`, and `switch_operator` for this `(staker, operator)` pair, permanently freezing the staker's stake.

This exact runtime behavior (registration/config-dependent revert in `deposit_coins`, and the unconditional loop over all shareholders in `distribute_internal`) is directly supported by the cited code; the end-to-end PoC could not be executed in this environment, so the precise abort code path should be confirmed by running the scenario in a local Move test harness.

    /// Staker can call this to request withdrawal of part or all of their staking_contract.
    /// This also triggers paying commission to the operator for accounting simplicity.
    public entry fun unlock_stake(
        staker: &signer, operator: address, amount: u64
    ) acquires Store, BeneficiaryForOperator {
        // Short-circuit if amount is 0.
        if (amount == 0) return;

        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, operator);

        let store = borrow_global_mut<Store>(staker_address);
        let staking_contract = store.staking_contracts.borrow_mut(&operator);

        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            operator,
            staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        let commission_paid =
            request_commission_internal(
                operator,
                staking_contract,
            );

        // If there's less active stake remaining than the amount requested (potentially due to commission),
        // only withdraw up to the active amount.
        let (active, _, _, _) = stake::get_stake(staking_contract.pool_address);
        if (active < amount) {
            amount = active;
        };
        staking_contract.principal -= amount;

        // Record a distribution for the staker.
        add_distribution(
            operator,
            staking_contract,
            staker_address,
            amount,
        );

        // Request to unlock the distribution amount from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            UnlockStake { pool_address, operator, amount, commission_paid }
        );
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
    /// receive.
    ///
    /// By default, this returns true if an account has not explicitly set whether the can receive direct transfers.
    public fun can_receive_direct_coin_transfers(
        account: address
    ): bool acquires DirectTransferConfig {
        !exists<DirectTransferConfig>(account)
            || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
    }
