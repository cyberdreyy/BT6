### Title
APR0 withdraw receipts permanently brick `stopEpoch` once APR turns non-zero, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
The external report (OpenVPN memory leak reachable by any holder of a valid client credential, degrading the service into an unusable state) maps to a **state leak in the APR0 withdraw path**: `apr0TotalPrincipal` is only ever cleared inside `prepareStopEpochWithApr0`, *after* a guard that reverts when `unscaledApr != 0`. Once the manager sets a non-zero APR while an APR0 receipt is outstanding, `stopEpoch` reverts permanently and the epoch state machine is bricked — a permanent freezing of all lender funds. Attacker needs only to be a KYC-passed tranche holder.

### Finding Description
`requestWithdraw` routes to `_requestWithdrawApr0` whenever `unscaledApr == 0 && !isClosed` ( [1](#0-0) ). Each request adds the receipt to the global bucket `apr0TotalPrincipal += _amount` ( [2](#0-1) ).

At `stopEpoch`, `IdleCDOEpochVariant` calls `prepareStopEpochWithApr0`, which enforces:
```solidity
if (unscaledApr != 0) {
  revert NotAllowed();
}
```
whenever `_principal = apr0TotalPrincipal != 0` ( [3](#0-2) ).

The only write that clears the bucket, `apr0TotalPrincipal = 0`, sits at the end of the same function — unreachable once the revert path is armed ( [4](#0-3) ). Critically, `_settleApr0` and `claimWithdrawRequest` only delete per-user `apr0Users[_user]` data; neither decrements `apr0TotalPrincipal` ( [5](#0-4) [6](#0-5) ). So even if the attacker claims their receipt before the APR change, the stale global bucket still forces the revert — this is the "leaked" state that can never be reclaimed.

The normal operational sequence arms the trap: the manager/orchestrator sets the next-epoch APR via `setApr` (as in `test/foundry/IdleCreditVault.t.sol:1236`, `setApr` → `startEpoch`/`stopEpoch` flow). The moment `unscaledApr` becomes non-zero while `apr0TotalPrincipal > 0`, every subsequent `stopEpoch` reverts.

### Impact Explanation
Permanent freezing of funds. With `stopEpoch` uncallable, the epoch never ends: lenders cannot claim withdraw requests (gated on `epochNumber` advancing at [7](#0-6) ), `startEpoch`/buffer flows stall, and borrower repayment can never be accounted. The frozen amount is the full vault TVL plus any borrower-held principal earmarked for repayment — bounded only by total deposits. No admin escape exists in the code paths reviewed (`Default revert` path doesn't apply since the borrower isn't in default; `apr0TotalPrincipal` has no setter/clearance function other than the reverting one).

### Likelihood Explanation
Low-to-moderate. Requires a conjunction: (1) `unscaledApr == 0` epoch configuration, which is a supported mode with dedicated accounting; (2) any single unprivileged lender calling `requestWithdraw` during that phase — even a dust amount arms the bucket; (3) the manager subsequently configuring a non-zero APR, which is the standard way to resume interest-bearing epochs. The attacker cannot force step (3), but cannot be stopped from performing step (2), and the freeze persists even if the attacker fully exits, making it a persistent booby-trap rather than an active hold. There is no loss to the attacker (their claim is either already paid or equally frozen).

### Recommendation
- In `prepareStopEpochWithApr0`, instead of reverting when `unscaledApr != 0` while `apr0TotalPrincipal > 0`, settle the APR0 bucket at a zero rate (or last recorded `apr0RateByEpoch`) and clear it, mirroring the normal `apr0TotalPrincipal = 0` path.
- Alternatively (defense in depth), decrement `apr0TotalPrincipal` in `_settleApr0`/`claimWithdrawRequest` when APR0 principal is paid out, so the global counter reflects only unsettled receipts.
- Add a revert-free admin path (e.g., guardian or borrower-triggered) to clear `apr0TotalPrincipal` if the invariant is ever violated by migration.

// test/foundry/Apr0StopEpochBrick.t.sol
// Fork test against the existing IdleCreditVault.t.sol harness.
function testApr0ReceiptBricksStopEpochAfterAprChange() external {
    uint256 amount = 10_000 * ONE_SCALE;

    // 1. Pool in APR0 mode: manager sets apr = 0, epoch runs.
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setApr(0);
    idleCDO.depositAA(amount);                 // honest TVL present
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, 0, _expectedFundsEndEpoch()); // epoch ends at apr 0

    // 2. Attacker (KYC'd AA holder) requests a withdraw while unscaledApr == 0.
    uint256 trancheBal = AAtranche.balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(trancheBal, address(AAtranche));
    assertGt(IdleCreditVault(address(strategy)).apr0TotalPrincipal(), 0);

    // 3. (Optional hardening) attacker even claims their funded receipt —
    //    apr0TotalPrincipal is NOT decremented by the claim path.
    //    ... fund via borrower repayment, then cdoEpoch.claimWithdrawRequest() ...

    // 4. Manager configures a non-zero APR for the next epoch (normal ops).
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setApr(initialProvidedApr);

    // 5. stopEpoch now reverts forever -> epoch permanently stuck.
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest()
        + IdleCreditVault(address(strategy)).pendingWithdraws());
    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    vm.expectRevert(); // NotAllowed
    cdoEpoch.stopEpoch(initialProvidedApr, 0);

    // Repeat: still reverts. All lender funds remain frozen.
    vm.prank(manager);
    vm.expectRevert();
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
}
```

  function _settleApr0(address _user) internal {
    Apr0UserData storage _apr0User = apr0Users[_user];
    uint256 _principal = _apr0User.principal;
    if (_principal == 0) {
      return;
    }
    uint256 _reqEpoch = _apr0User.principalEpoch;
    // Settle only after stopEpoch bumped epochNumber (ie after one full wait epoch).
    if (_reqEpoch >= epochNumber) {
      return;
    }
    // Move principal from "open APR0 bucket" to "settled bucket" (same principal, not duplicated).
    _apr0User.settledPrincipal += _principal;
    uint256 _rate = apr0RateByEpoch[_reqEpoch];
    if (_rate != 0) {
      // Convert per-epoch rate to claimable underlying interest.
      _apr0User.settledInterest += (_principal * _rate) / 1e18;
    }
    _apr0User.principal = 0;
    _apr0User.principalEpoch = 0;
  }
```

  function _requestWithdrawApr0(uint256 _amount, address _user) internal {
    // Settle any previous APR0 request first, then start/update current epoch bucket.
    _settleApr0(_user);
    Apr0UserData storage _apr0User = apr0Users[_user];
    if (_apr0User.principal == 0) {
      _apr0User.principalEpoch = epochNumber;
    }
    _apr0User.principal += _amount;
    // Epoch-level APR0 principal used only to compute stopEpoch APR0 pro-rata interest.
    apr0TotalPrincipal += _amount;
  }
