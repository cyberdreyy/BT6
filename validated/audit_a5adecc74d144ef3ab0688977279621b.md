### Title
Griefing via opted-out coin-transfer recipient permanently blocks `staking_contract`/`vesting` commission and reward distribution - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
The external USDT report is fundamentally about an unchecked external-interface assumption (`approve` always succeeds) causing an unrecoverable revert that blocks a fund-management flow. The Aptos analog is `aptos_account::deposit_coins`, which assumes every recipient in a distribution loop accepts direct coin transfers. Any unprivileged account can opt out of that assumption via the `DirectTransferConfig`/`can_receive_direct_coin_transfers` gate. `staking_contract::distribute_internal` (used by `staking_contract::distribute`, `request_commission`, `unlock_stake`, `switch_operator`, and transitively by `vesting::distribute`, `vest`, `unlock_rewards`, `terminate_vesting_contract`, and `admin_withdraw`) iterates unconditionally over every recipient ever added to the pool's `distribution_pool` and calls `aptos_account::deposit_coins` for each one. If any single recipient (staker, current operator/beneficiary, or a *past* operator/beneficiary retained from a prior `switch_operator`) has disabled direct transfers, the loop aborts on that recipient and the entire transaction reverts — permanently blocking distribution for every other shareholder in the same staking/vesting pool.

### Finding Description
`distribute_internal` withdraws all currently inactive/pending_inactive stake, then loops over `distribution_pool.shareholders()` and pays each one with `aptos_account::deposit_coins`: [1](#0-0) 

`aptos_account::deposit_coins` will only auto-register an unregistered recipient if `can_receive_direct_coin_transfers(to)` is true; otherwise it aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`: [2](#0-1) 

`can_receive_direct_coin_transfers` reads the caller-controlled `DirectTransferConfig.allow_arbitrary_coin_transfers` flag, which any account (unprivileged) can flip off on itself: [3](#0-2) 

Critically, the `distribution_pool` accumulates recipients over the life of the staking contract and is never pruned: `switch_operator` adds a distribution for the old operator (paid to its beneficiary) and then re-adds the contract under the new operator, while the old operator's beneficiary entry can remain a pending shareholder in the same `distribution_pool` if their payout wasn't cleared: [4](#0-3) 

Operators can also redirect their commission recipient at will via `set_beneficiary_for_operator`, which is entirely self-service and unprivileged with respect to the staking pool: [5](#0-4) 

This same `distribute`/`distribute_internal` path is the *only* mechanism vesting contracts use to move funds out of the underlying stake pool. `vesting::withdraw_stake`, `vesting::distribute`, `vest`, `unlock_rewards`, `terminate_vesting_contract`, and `admin_withdraw` all funnel through it: [6](#0-5) [7](#0-6) 

Because Move transactions are atomic, a single non-accepting recipient anywhere in the historical `distribution_pool` causes every subsequent call to `distribute`/`request_commission`/`unlock_stake`/`switch_operator`/`vest`/`terminate_vesting_contract`/`admin_withdraw` to revert. There is no code path that skips, times out, or force-registers a non-consenting recipient, and no privileged actor (not even the staker/admin) can remove a stale distribution entry from `distribution_pool`.

### Impact Explanation
Any single unprivileged party who at some point becomes a distribution recipient (an operator, an operator's chosen beneficiary via self-service `set_beneficiary_for_operator`, or a staker) can permanently freeze:
- commission payouts to the current operator,
- reward/principal withdrawals for the staker,
- and, for vesting contracts, vesting distributions, reward unlocks, and even the terminal `admin_withdraw` that returns the entire remaining grant to the withdrawal address after contract termination,

by simply disabling direct coin transfers on their own account before/after being added as a distribution recipient. This traps value belonging to other, unrelated parties (the staker, other shareholders, the withdrawal address) with no on-chain recovery path, satisfying the "permanent lock or non-recoverable loss of claim rights" and "traps value" impact criteria.

### Likelihood Explanation
Likelihood is Medium-High: no special permission is required — any account can call the standard opt-out entry function for direct coin transfers on itself, and becoming a distribution-pool recipient happens automatically as a side effect of ordinary operator/beneficiary actions (`switch_operator`, `set_beneficiary_for_operator`, `unlock_stake`) that are already part of normal contract lifecycle, not adversarial by themselves. The bug can be triggered accidentally by a legitimate user who toggles this preference for unrelated reasons, or maliciously by an operator/beneficiary who wants to grief a staker or block their own liability window.

### Recommendation
- In `distribute_internal` (and the vesting `distribute` loop), do not let one recipient's inability to receive funds abort the whole distribution. Either: (1) skip/queue the failing recipient's share into a separate claimable balance instead of pushing it via `deposit_coins`, or (2) wrap each `deposit_coins` call so a failure only forfeits/re-escrows that one recipient's share rather than reverting the entire loop.
- Prune stale entries from `distribution_pool` once a recipient's balance has been fully paid or their prior role (operator/beneficiary) is no longer active, so a single retired beneficiary/operator cannot indefinitely block future distributions.
- Alternatively, require distribution recipients to be validated as coin-transfer acceptors at the time they are ADDED to the pool, and re-validate/queue rather than hard-abort during payout.

### Proof of Concept
1. Staker S creates a `staking_contract` with operator O1 via `staking_contract::create_staking_contract`.
2. O1 calls `set_beneficiary_for_operator(O1, B1)` to route commission to beneficiary B1 (self-service, unprivileged): [8](#0-7) 
3. B1, at any point, disables direct coin transfers on its own account (standard `aptos_account` self-service toggle backing `DirectTransferConfig`).
4. Stake pool accrues rewards; someone calls `staking_contract::request_commission` or `unlock_stake`, which calls `distribute_internal`, which iterates the `distribution_pool` and hits B1's entry, calling `aptos_account::deposit_coins(B1, ...)`.
5. Because B1's `CoinStore<AptosCoin>` is not yet registered and `can_receive_direct_coin_transfers(B1)` is false, `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`: [9](#0-8) 
6. The entire `distribute_internal` transaction reverts, meaning staker S can never again call `unlock_stake`, `distribute`, `switch_operator`, or `request_commission` on this contract (all of them force-call `distribute_internal` first), permanently trapping S's stake and any other shareholder's commission in the pool as long as B1 keeps direct transfers disabled.
7. The identical mechanism applies to `vesting::admin_withdraw` after `terminate_vesting_contract`, permanently trapping the vesting contract's entire remaining grant if any historical operator/beneficiary in its underlying `staking_contract` distribution pool has opted out.

    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    fun withdraw_stake(vesting_contract: &VestingContract, contract_address: address): Coin<AptosCoin> {

        // the vesting contract's account.
        staking_contract::distribute(contract_address, vesting_contract.staking.operator);
