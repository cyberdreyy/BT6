### Title
JWT replay-guard check-then-act race allows a single-use trigger token to authorize duplicate workflow executions - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The HTTP Trigger gateway handler authorizes inbound, unprivileged HTTP-trigger requests using a per-JWT single-use replay guard (`jwtReplayCache`). The guard's "check" (`isReplay`) and "record" (`recordUsage`) operations are two separate, independently-locked calls rather than one atomic check-and-set, so concurrent requests carrying the same JWT can both pass the replay check before either records usage — mirroring the Paladin-style class of bug where a stateful, time/identity-scoped value is read and updated non-atomically, letting stale/duplicate state slip through and corrupt subsequent processing.

### Finding Description
`WorkflowMetadataHandler.Authorize` is the authorization entrypoint for inbound HTTP Trigger requests coming from external, unauthenticated (pre-JWT-verification) callers through the internet-facing gateway [1](#0-0) . It calls `h.jwtCache.isReplay(claims.ID)` to reject already-used JWT IDs (`jti`), performs the workflow/signer authorization lookups, and only afterwards calls `h.jwtCache.recordUsage(claims.ID)` to mark the token as used [2](#0-1) .

The underlying `jwtReplayCache` implements `isReplay` and `recordUsage` as two independent, separately-locked operations rather than a single atomic check-and-set: [3](#0-2) 

Because `isReplay` (RLock) and `recordUsage` (Lock) are not combined under one critical section guarding the whole "check, then use, then record" sequence in `Authorize`, two (or more) concurrent HTTP trigger requests presenting the identical signed JWT can each observe `isReplay == false` before either has called `recordUsage`. Both requests then pass authorization and are dispatched to the workflow DON as independent trigger executions, defeating the single-use (`jti`) replay protection that this cache is specifically designed to enforce. This is directly analogous to the reported bug class: a security-relevant piece of per-identity state (a "slope"/usage marker) is read and later written non-atomically, so overlapping requests around the same instant see and act on stale state, corrupting the intended invariant (each JWT authorizes exactly one execution).

### Impact Explanation
An external, unprivileged caller of the HTTP Trigger capability can send the same signed, single-use JWT concurrently (e.g., two parallel HTTP requests) and get the associated workflow execution triggered more than once, even though the JWT's `jti` was intended to bound authorization to a single use. Depending on the workflow, this can cause unintended duplicate job/workflow runs (e.g., duplicate on-chain actions, duplicate payouts, or resource exhaustion via repeated execution), which falls under "unauthorized job run" impact.

### Likelihood Explanation
The race window is small but requires no special privileges — any caller who already possesses one valid, correctly-signed trigger JWT (the normal, expected caller of this API) can trigger the race deterministically by firing multiple concurrent requests with the same token before the first `recordUsage` completes. No cryptographic bypass is needed; it purely relies on request timing, which is trivial to engineer from a client.

### Recommendation
Merge `isReplay` and `recordUsage` into a single atomic check-and-set method (e.g., `CheckAndRecord(jti string) bool`) protected by one mutex acquisition, similar to the correctly-implemented `RequestReplayGuard.CheckAndRecord` pattern used elsewhere in the vault authorizer [4](#0-3) , and call it from `Authorize` before performing authorization work, so that only one of the concurrent requests can ever proceed past the replay check for a given `jti`.

### Proof of Concept
1. Obtain one valid signed trigger JWT (`jti = X`) for a workflow authorized via `WorkflowMetadataHandler`.
2. Fire two concurrent HTTP requests to the gateway's HTTP Trigger endpoint using the identical token.
3. Both requests reach `Authorize`; both call `h.jwtCache.isReplay(X)` before either calls `h.jwtCache.recordUsage(X)`, so both see `exists == false`.
4. Both requests pass authorization checks in `Authorize` (workflow lookup and signer check succeed for both), and both are forwarded as separate trigger executions to the DON, i.e. the single JWT authorized two executions instead of one.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
