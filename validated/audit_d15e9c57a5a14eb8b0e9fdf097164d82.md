### Title
Missing `DisplayCap<T>` Witness in `delete_legacy` Allows Any Actor to Destroy Arbitrary `LegacyDisplay<T>` Objects — (`crates/sui-framework/packages/sui-framework/sources/registries/display_registry.move`)

---

### Summary

`delete_legacy` guards destruction of `LegacyDisplay<T>` objects with only a boolean check (`cap_id.is_some()`) on a shared `Display<T>` object. Because `Display<T>` is a shared object accessible to every caller, and because the function never demands that the caller present the matching `DisplayCap<T>`, any unprivileged actor can irreversibly destroy any `LegacyDisplay<T>` for any type `T` once the canonical display's cap has been set — without owning or ever touching the cap.

---

### Finding Description

`delete_legacy` is defined as:

```move
public fun delete_legacy<T: key>(display: &Display<T>, legacy: LegacyDisplay<T>) {
    assert!(display.cap_id.is_some(), ECapNotClaimed);
    legacy.destroy();
}
``` [1](#0-0) 

The only guard is `display.cap_id.is_some()`. This checks a field on the shared `Display<T>` object — it does **not** require the transaction sender to hold the `DisplayCap<T>` whose ID is stored in `cap_id`.

`Display<T>` is always published as a shared object:

```move
transfer::share_object(Display<T> { ... });
``` [2](#0-1) 

and via `share`:

```move
public fun share<T>(display: Display<T>) {
    transfer::share_object(display)
}
``` [3](#0-2) 

Once the legitimate publisher calls `claim`, `claim_with_publisher`, `new_with_publisher`, or `migrate_v1_to_v2`, the shared `Display<T>` transitions to `cap_id = Some(...)`. From that moment, the boolean check in `delete_legacy` is permanently satisfied for every caller.

Compare with every other cap-gated function in the same module, which correctly demands the capability object as a witness parameter:

```move
public fun set<T>(display: &mut Display<T>, _: &DisplayCap<T>, ...)
public fun unset<T>(display: &mut Display<T>, _: &DisplayCap<T>, ...)
public fun clear<T>(display: &mut Display<T>, _: &DisplayCap<T>)
``` [4](#0-3) 

`delete_legacy` is the only mutating function that omits this witness.

---

### Impact Explanation

An attacker can permanently and irreversibly destroy any `LegacyDisplay<T>` object owned by any address, for any type `T` whose canonical `Display<T>` already has `cap_id = Some(...)`. The destruction is performed via `legacy.destroy()` which deletes the UID:

```move
legacy.destroy();
``` [5](#0-4) 

This is unauthorized, permanent object destruction — state corruption — with no recovery path. The victim's `LegacyDisplay<T>` object ceases to exist on-chain without the owner's consent or any capability proof from the attacker.

---

### Likelihood Explanation

- The precondition (a `Display<T>` with `cap_id = Some(...)` existing as a shared object) is the normal post-migration state for every type that has been migrated.
- The attack requires no special privilege: any address can submit a transaction referencing the shared `Display<T>` and any `LegacyDisplay<T>` they can obtain or that is passed to them.
- The attack is a single public transaction with no setup beyond knowing the object IDs.

---

### Recommendation

Add `DisplayCap<T>` as a required witness parameter, matching the pattern used by every other cap-gated function:

```move
public fun delete_legacy<T: key>(
    display: &Display<T>,
    _cap: &DisplayCap<T>,
    legacy: LegacyDisplay<T>,
) {
    assert!(display.cap_id.is_some(), ECapNotClaimed);
    legacy.destroy();
}
```

This ensures only the holder of the canonical `DisplayCap<T>` can authorize destruction of legacy display objects.

---

### Proof of Concept

1. Legitimate publisher calls `claim_with_publisher` on the shared `Display<MyNFT>` (created by `system_migration`). This sets `cap_id = Some(cap_id_value)` on the shared object. Publisher keeps the `DisplayCap<MyNFT>`.

2. Victim holds a `LegacyDisplay<MyNFT>` (a `sui::display::Display<MyNFT>` object at address `0xVICTIM_LEGACY`).

3. Attacker (any address, no cap, no publisher) submits:
   ```
   delete_legacy<MyNFT>(
       shared_display_object_id,   // Display<MyNFT> with cap_id = Some(...)
       victim_legacy_object_id     // LegacyDisplay<MyNFT> owned by victim
   )
   ```

4. `display.cap_id.is_some()` → `true`. `legacy.destroy()` executes. The victim's `LegacyDisplay<MyNFT>` is permanently deleted.

5. Assert: the attacker never held `DisplayCap<MyNFT>`. The victim's object is gone. The invariant — that only the cap holder may authorize legacy display destruction — is violated. [1](#0-0)
