### Title
`ConvexStrategyETH` permanently locks ETH sent by arbitrary callers - (File: `contracts/strategies/convex/ConvexStrategyETH.sol`)

### Summary

`ConvexStrategyETH` accepts ETH through an unrestricted `receive()` function. The function is needed to accept ETH when `_depositInCurve()` unwraps WETH, but it does not verify that `msg.sender` is the WETH contract. ETH sent directly by any user remains locked because the contract has no ETH withdrawal or recovery path.

### Finding Description

`_depositInCurve()` unwraps the strategy’s WETH balance and supplies that amount of ETH to a Curve pool. The WETH withdrawal sends ETH to the strategy, which explains the presence of a `receive()` function. However, the implementation accepts ETH from any sender rather than only accepting the WETH contract. [1](#0-0) 

If ETH is already present before the next Curve deposit, `_depositInCurve()` still supplies only the newly unwrapped WETH amount, `_balance`; it does not consume the preexisting ETH balance. Consequently, accidentally transferred ETH remains in the contract indefinitely. [2](#0-1) 

The comparable Lido gateway already implements the missing guard by accepting ETH only when `msg.sender == wethToken`. [3](#0-2) 

### Impact Explanation

An arbitrary caller can permanently lose any ETH sent directly to the strategy. For example, transferring 1 ETH to the contract succeeds through `receive()`, but neither users nor privileged roles have a code path that returns that ETH. The impact is permanent freezing of the sender’s funds, with the loss equal to the transferred amount.

### Likelihood Explanation

Exploitation does not affect other vault users or existing strategy assets; it depends on an ETH transfer being sent directly to the strategy by mistake or due to a mistaken integration. That makes the likelihood lower than an externally triggerable theft, but the resulting loss is permanent once the transfer succeeds.

### Recommendation

Restrict the receiver to the WETH contract:

```solidity
receive() external payable {
    require(msg.sender == WETH, "only-weth");
}
```

This preserves the WETH unwrap flow while rejecting direct ETH transfers.

### Proof of Concept

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/strategies/convex/ConvexStrategyETH.sol";

contract ConvexStrategyETHReceiveTest is Test {
    function testDirectEthTransferIsAcceptedAndLocked() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        ConvexStrategyETH strategy = new ConvexStrategyETH();
        address user = makeAddr("user");
        uint256 amount = 1 ether;

        vm.deal(user, amount);
        vm.prank(user);

        // The unrestricted receive() accepts the direct ETH transfer.
        (bool success,) = address(strategy).call{value: amount}("");
        assertTrue(success);

        // The strategy now owns the ETH, but exposes no ETH recovery path.
        assertEq(address(strategy).balance, amount);
        assertEq(user.balance, 0);
    }
}
```
