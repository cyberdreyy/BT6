### Title
Unresolved operator distribution shares are mistaxed as staker rewards after `switch_operator`, misdirecting commission to the new operator - ([File: aptos-move/framework/aptos-framework/sources/staking_contract.move])

### Summary
`switch_operator` moves the entire `StakingContract` struct — including its `distribution_pool` — from the `old_operator` key to the `new_operator` key in the `Store.staking_contracts` map [1](#0-0) . If `old_operator` has an unresolved commission distribution recorded in that pool (i.e. commission that has been requested via `request_commission_internal` but not yet paid out because the stake pool's lockup hasn't expired), `old_operator` remains a shareholder in the very same `distribution_pool` object even though the map key is now `new_operator`. Any subsequent call to `add_distribution` (e.g. via `new_operator`'s `request_commission`, or a staker's `unlock_stake`) invokes `update_distribution_pool`, which treats every shareholder that is not equal to the current `operator` parameter identically — including the old operator — as if their existing share balance were untaxed principal/rewards subject to a fresh commission cut [2](#0-1) .

### Finding Description
`request_commission_internal` computes commission and calls `add_distribution(operator, staking_contract, operator, commission_amount)` [3](#0-2) . `add_distribution` recomputes `total_distribution_amount` from `stake::get_stake` and calls `update_distribution_pool(distribution_pool, total_distribution_amount, operator, commission_percentage)` before doing the `buy_in` for the new recipient [4](#0-3) .

`update_distribution_pool` iterates over *every* shareholder in the pool, and for any shareholder that is not the `operator` argument passed in, it computes the shareholder's value growth relative to the pool's previous `total_coins`, taxes that growth at `commission_percentage`, and transfers the equivalent shares to `operator` [5](#0-4) . This logic is designed to let the operator earn commission on the staker's unrealized/unpaid balance growth in the pool — it implicitly assumes the only non-operator shareholder type is the staker (or a still-current operator).

When `switch_operator` is invoked with a pending, unpaid commission for `old_operator` still sitting in the pool's shares (created by the `request_commission_internal(old_operator, ...)` call inside `switch_operator` itself, right before the map key swap) [6](#0-5) , this pending amount is not distinguishable from staker principal in `update_distribution_pool`'s view. If, later in the same epoch/lockup window, `new_operator` calls `request_commission` (or the staker calls `unlock_stake`, which also calls `add_distribution`), the growth in `distribution_pool.total_coins` caused by the new unlock request is used to tax `old_operator`'s already-settled, unpaid share, and the resulting shares are transferred to `new_operator`. This breaks the invariant that distribution shares map to the entity currently entitled to them — the old operator's already-earned commission gets partially reassigned to the new operator.

### Impact Explanation
This corrupts operator commission accounting between two distinct operator addresses: `new_operator` receives commission it did not earn, at the expense of `old_operator`, whose already-computed and locked-in commission share is silently reduced. This is a direct, unprivileged loss/misdirection of value between two operator identities on a real staking-contract instance — matching the "Stake And Lockup" impact criteria (accounting across commission state must preserve value and payout rights across operator/role boundaries).

### Likelihood Explanation
The precondition is realistic and requires no privileged assumptions beyond being either the staker (who owns/controls `switch_operator` and `request_commission` calls on their own staking contract) or simply triggering a second `add_distribution`-invoking action after a switch within the same lockup cycle. Since Aptos lockup cycles can span up to 30 days on mainnet, an operator switch followed by any further commission request or unlock action before the prior operator's commission is fully distributed is a routine, easily reachable operational sequence — not a contrived edge case.

### Recommendation
`update_distribution_pool` should not apply commission taxation to shareholders that are former operators with pending, already-taxed distributions. One approach: track “operator” shareholders explicitly (e.g., a small set of historical operator addresses associated with the pool) and exclude them from the re-taxation loop, only taxing genuine staker-type shareholders. Alternatively, force a full `distribute_internal` (or otherwise zero out old operator shares) as part of `switch_operator` before the key swap, ensuring no shareholder other than the staker persists in the pool across an operator change, or refuse to let a new operator's `request_commission`/`add_distribution` proceed while a prior operator still holds unresolved shares.

### Proof of Concept
1. Staker creates a staking contract with `operator_1`, stake earns rewards over an epoch.
2. Staker calls `switch_operator(staker, operator_1, operator_2, commission_pct)`. Internally this calls `distribute_internal` (which may or may not fully clear inactive funds depending on lockup timing) then `request_commission_internal(operator_1, ...)`, which adds a new distribution entry crediting `operator_1` with the just-computed commission and calls `stake::unlock_with_cap` — this amount sits in `pending_inactive`, not yet withdrawable since lockup has not expired. The `StakingContract` (including its `distribution_pool` with `operator_1`'s pending share) is now keyed under `operator_2`.
3. Still within the same lockup cycle, stake earns further rewards; `operator_2` calls `request_commission`. This calls `add_distribution(operator_2, staking_contract, operator_2, new_commission)` → `update_distribution_pool(pool, updated_total_coins, operator_2, commission_pct)`.
4. Inside `update_distribution_pool`, `operator_1` (shareholder != operator_2) has its share's `current_worth` computed against the increased `updated_total_coins`, is taxed `commission_pct` on the apparent "growth", and the corresponding shares are transferred from `operator_1` to `operator_2`.
5. When both operators eventually call `distribute`, `operator_1` receives less than the commission amount recorded in the original `RequestCommission` event at switch time, and `operator_2` receives more than the commission amount actually accrued while they were operator — the sum equals total commission earned, but attribution between the two operators is wrong (`operator_1` underpaid, `operator_2` overpaid), demonstrating misdirected commission across the operator switch boundary.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
