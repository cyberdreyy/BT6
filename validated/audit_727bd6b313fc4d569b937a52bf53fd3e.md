### Title
Stale-conflict guard lets a signer double-sign at the same height across an unrelated tenure - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`handle_block_pre_commit`'s conflict guard, which is the only barrier preventing a signer from putting a second signature over a same-height block once the pre-commit threshold is crossed, checks liveness of a cross-tenure conflict **only while it is "fresh"**. Once the conflict's `last_endorsed` timestamp ages past `tenure_last_block_proposal_timeout`, the guard silently drops it from consideration — even if the conflicting block is still fully live/canonical per the node — because the fallback check that runs afterward only re-examines conflicts in the proposal's *own* tenure, not third-party tenures. This lets the same signer sign two conflicting blocks at the same Stacks height in unrelated tenures.

### Finding Description
In `handle_block_pre_commit` [1](#0-0) , after the chainstate re-check passes, the signer fetches every signed conflict at or above the proposed height, in ANY tenure, via `get_signed_conflicts` [2](#0-1) . It then looks for a conflict that is simultaneously:

1. fresh (`last_endorsed > freshness_cutoff`),
2. not covered by a standing reorg permit, and
3. still live per `conflict_still_blocks` (a node round-trip that checks whether the conflicting tenure's sortition and block are still canonical) [3](#0-2) .

Crucially, the `&&` short-circuits on freshness first [4](#0-3) : a conflict that has merely gone stale by the local clock is **never asked whether it is actually still live**. The code's own comment acknowledges the design intent — stale conflicts are assumed to be "settled by the chainstate checks above" [5](#0-4)  — but the chainstate re-check (`check_block_against_signer_db_state` → `check_latest_block_in_tenure`) only ever inspects the proposed block's *own* tenure, or its *parent* tenure for a tenure-change block [6](#0-5) [7](#0-6) . It never examines an unrelated third tenure.

The only remaining fallback, the second `conflicts.iter().any(...)` block, is explicitly restricted to conflicts sharing the *same* `consensus_hash` as the proposal [8](#0-7) . It does nothing for a conflict in a different tenure.

Net effect: if a signer has already signed block **Y** at height **H** in tenure **B**, and later a miner proposes block **X** at the same height **H** in an unrelated tenure **C** (not B's child and not B's parent), the guard that is documented as spanning "ANY tenure" for exactly this scenario stops functioning as soon as Y's `last_endorsed` timestamp ages past `tenure_last_block_proposal_timeout` — regardless of whether Y is still genuinely live/canonical. The signer proceeds to sign X, breaking the one-signature-per-height invariant this whole subsystem (`docs/signer-flows.md` section 5, `get_signed_conflicts`) is built to enforce. This mirrors the ouroboros bug class: a soundness assumption ("stale implies safe to ignore, because another layer already covers it") that is not actually true in all reachable states, silently producing an unsound result (a second signature over a conflicting block) rather than an explicit failure.

### Impact Explanation
This breaks the "signed vs. one-per-height" equality the whole conflict-guard subsystem exists to protect: the same signer can put its signature over two mutually exclusive blocks at the same height in different tenures. If both blocks separately accumulate the 70% signer weight (a realistic scenario during a contested tenure transition, since this signer's weight now counts toward both), the network could end up with two competing, both-signed candidate blocks at the same height — a direct equivocation. This falls under the Critical impact bucket: "a signer signing an invalid, non-canonical, or conflicting block."

### Likelihood Explanation
This requires no majority of signers, no other signer's key, and no StackerDB/transport trickery — only ordinary timing that a single miner (plus normal gossip delay) controls:
1. Get this signer to sign block Y at height H in tenure B (normal operation).
2. Let more than `tenure_last_block_proposal_timeout` elapse without Y reaching global (node-adopted) acceptance — plausible whenever the rest of the signer set is slow, partitioned, or contested, which is exactly when conflicting proposals at the same height are most likely to occur.
3. Propose block X at height H in an unrelated tenure C to the same signer.

Because step 2 only requires the passage of a configurable, but not adversary-proof, timeout (`tenure_last_block_proposal_timeout`), and because it is the *sole* determinant of whether `conflict_still_blocks` even gets invoked, this is readily reachable by a lone miner racing two tenures/proposals without any collusion.

### Recommendation
Do not gate the liveness check (`conflict_still_blocks`) on freshness for cross-tenure conflicts. Either:
- Always call `conflict_still_blocks` (and `reorg_permit_stands`) for every returned conflict regardless of `last_endorsed` age, using the freshness comparison only as an optimization to skip the node round-trip when the conflict is *both* stale *and* the chainstate re-check already covers that tenure (i.e., own/parent tenure only); or
- Extend the second (`any`) fallback block to also re-verify liveness via `conflict_still_blocks` for conflicts in tenures other than the proposal's own tenure, rather than unconditionally treating them as "settled."

### Proof of Concept
1. Signer S validates and signs block **Y** (tenure B, height H) via the normal validate-ok → pre-commit → `handle_block_pre_commit` path, reaching `LocallyAccepted` with `signed_self` set [9](#0-8) .
2. Y never reaches global acceptance (e.g., the rest of the signer set stalls or is slow), and time advances past `tenure_last_block_proposal_timeout` from Y's `signed_self`/`signed_group` timestamp, so `last_endorsed <= freshness_cutoff` for Y when evaluated against a later proposal.
3. Miner proposes block **X** at the same height H, but in tenure C, where C is neither the parent nor child of B (e.g., a new tenure following a different, unrelated sortition history). X passes validation and the chainstate re-check (which only inspects C's own tenure/parent, never B).
4. In `handle_block_pre_commit` for X: `get_signed_conflicts` returns Y (height ≥ H, all tenures). The first `find` predicate evaluates `last_endorsed > freshness_cutoff` → false for Y, so `conflict_still_blocks` is never called; the predicate is false, so no conflict is found to refuse on.
5. The second `any` block only matches conflicts where `consensus_hash == C`; Y's consensus hash is B, so it does not match either.
6. Signer S proceeds to `mark_locally_accepted` and sign X — now holding signatures over two same-height, mutually exclusive blocks Y and X in different tenures, even though Y may still be perfectly live/canonical (this is never re-checked in step 4). [10](#0-9)

    fn conflict_still_blocks(
        &self,
        stacks_client: &StacksClient,
        conflict: &SignedConflictInfo,
        proposed_height: u64,
    ) -> bool {
        if let Ok(burn_block) = self
            .signer_db
            .get_burn_block_by_ch(&conflict.consensus_hash)
        {
            match stacks_client.get_sortition_by_burn_hash(&burn_block.block_hash) {
                Ok(_) => {
                    // The tenure's sortition is still canonical: the conflict is live at the
                    // burn chain level, so fall through to the block-level questions.
                }
                Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => {
                    // A 404 only proves the sortition was orphaned if the node's burnchain
                    // view actually covers the burn block's height: a node still catching up
                    // 404s canonical burn blocks it hasn't processed yet (and the
                    // endpoint also 404s on internal data misses). Only trust it once the
                    // node's burnchain tip is at or past the stored burn block.
                    match stacks_client.get_peer_info() {
                        Ok(peer_info) if peer_info.burn_block_height >= burn_block.block_height => {
                            info!("{self}: A conflicting block's tenure was orphaned by a burnchain fork. The conflict no longer blocks.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "conflicting_block_height" => conflict.stacks_height,
                                "burn_block_hash" => %burn_block.block_hash,
                            );
                            return false;
                        }
                        Ok(peer_info) => {
                            info!("{self}: The node does not know a conflicting block's burn block, but its burnchain tip has not reached that height, so this does not prove the tenure was orphaned. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                                "burn_block_hash" => %burn_block.block_hash,
                                "burn_block_height" => burn_block.block_height,
                                "node_burn_block_height" => peer_info.burn_block_height,
                            );
                            return true;
                        }
                        Err(e) => {
                            warn!("{self}: Failed to fetch the node's burnchain tip while checking a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                                "conflicting_consensus_hash" => %conflict.consensus_hash,
                            );
                            return true;
                        }
                    }
                }
                Err(e) => {
                    warn!("{self}: Failed to check whether a conflicting block's tenure is still canonical: {e:?}. Leaving the conflict in place.";
                        "conflicting_consensus_hash" => %conflict.consensus_hash,
                    );
                    return true;
                }
            }
        }
        let node_reaches_conflict = match stacks_client.get_tenure_tip(&conflict.consensus_hash) {
            Ok(tip) => tip.anchored_header.height() >= conflict.stacks_height,
            // A 404 is an answer, not a failure: the node has no blocks in that tenure at all.
            Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => false,
            Err(e) => {
                warn!("{self}: Failed to fetch the canonical tip of a conflicting block's tenure: {e:?}. Leaving the conflict in place.";
                    "conflicting_consensus_hash" => %conflict.consensus_hash,
                    "conflicting_block_height" => conflict.stacks_height,
                );
                return true;
            }
        };
        node_reaches_conflict
            || (!conflict.globally_accepted && conflict.stacks_height <= proposed_height)
    }

    pub fn get_signed_conflicts(
        &self,
        height: u64,
        excluded_signer_signature_hash: &Sha512Trunc256Sum,
    ) -> Result<Vec<SignedConflictInfo>, DBError> {
        let query = "SELECT b.consensus_hash, b.signer_signature_hash, b.stacks_height, b.state,
                MAX(COALESCE(b.signed_self, 0), COALESCE(b.signed_group, 0)) AS last_endorsed,
                st.superseded_by_consensus_hash, st.superseded_by_burn_block_hash
            FROM blocks b
            LEFT JOIN superseded_tenures st ON st.consensus_hash = b.consensus_hash
            WHERE (b.signed_self IS NOT NULL OR b.signed_group IS NOT NULL)
                AND b.stacks_height >= ?1
                AND b.signer_signature_hash != ?2
            ORDER BY b.stacks_height DESC";
        let args = params![
            u64_to_sql(height)?,
            excluded_signer_signature_hash.to_string(),
        ];
        query_rows(&self.db, query, args)
    }

## 7. The chainstate checks (shared)

`check_latest_block_in_tenure` answers "does this block confirm the tip we
expect?" and it runs in three places: at proposal arrival (inside
`check_proposal`), at validate-ok, and at the moment of signing. _Which_ tenure
it is asked about depends on the block: a tenure-change block is checked against
its **parent** tenure, every other block against its **own**. Never both. The
pivotal helper is `get_tenure_last_block_info`, which considers only blocks that
carry a signature (`get_last_signed_block`): a pre-commit never vetoes anything,
it only counts as miner activity.
