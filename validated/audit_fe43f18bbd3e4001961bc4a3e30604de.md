### Title
Internal Database Error Messages Leaked to Unauthenticated Callers via External Initiator Auth Error Path - ([File: core/web/auth/auth.go])

### Summary
In `AuthenticateExternalInitiator`, when `store.FindExternalInitiator` returns any error other than `sql.ErrNoRows`, the raw wrapped error (`errors.Wrap(err, "finding external initiator")`) is propagated up through the `Authenticate` middleware and rendered directly to the unauthenticated HTTP client via `jsonAPIError`. This can leak internal database/driver error text to an unauthenticated attacker.

### Finding Description
`AuthenticateExternalInitiator` reads the `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers into an `auth.Token` and calls `store.FindExternalInitiator(ctx, eia)`: [1](#0-0) 

If the returned error is `sql.ErrNoRows`, it is converted to the generic `auth.ErrorAuthFailed`. For any other error (DB timeouts, connection errors, malformed-token-triggered driver errors, context cancellations, etc.), the function returns `errors.Wrap(err, "finding external initiator")` — preserving the original driver/db error text in the wrapped error's message.

This error bubbles up through `Authenticate`: [2](#0-1) 

Since the error is not `auth.ErrorAuthFailed`, the loop breaks immediately and the raw error is passed to `jsonAPIError(c, http.StatusUnauthorized, err)`.

`jsonAPIError` renders `err.Error()` directly into the JSON response body when the error is not a `*models.JSONAPIErrors`: [3](#0-2) 

Because `errors.Wrap` is not a `*models.JSONAPIErrors`, the fallback path executes and the full wrapped message (`"finding external initiator: <underlying db driver error>"`) is sent back to the caller — an entirely unauthenticated client, since this code runs on the external-initiator auth middleware before any identity is established.

### Impact Explanation
This is an information-disclosure issue, not an authentication bypass: the `!ok` / role checks after `FindExternalInitiator` still require a valid matching key/secret before granting the `run` role, so no privilege escalation occurs via this path itself. The concrete impact is limited to internal error/DB detail exposure (e.g., driver error strings, potentially schema/query fragments) to an unauthenticated caller, which falls under Chainlink's "information disclosure" bounty class rather than a critical/high authentication-bypass class. It does not by itself expose secrets, keys, or another user's data.

### Likelihood Explanation
Triggering a non-`ErrNoRows` error from `FindExternalInitiator` typically requires an underlying database condition (e.g., connection pool exhaustion, timeout, or a malformed query due to unusual header content) rather than attacker-controlled input alone in the common case, since the ORM implementation was not confirmed to perform any error-prone parsing of the access key before querying. Without visibility into `core/bridges/orm.go`'s `FindExternalInitiator` implementation (not fully retrieved), it is uncertain whether attacker-supplied header values can deterministically force a specific driver error (as opposed to only transient/environmental errors like timeouts). This uncertainty reduces confidence in reliable, repeatable exploitability from a purely unprivileged remote attacker.

### Recommendation
In `AuthenticateExternalInitiator` (and similarly in `AuthenticateByToken`), do not propagate the raw wrapped error to the HTTP response. Log the detailed error server-side and return a generic `auth.ErrorAuthFailed` (or another opaque error) to the client for any error case, mirroring the `sql.ErrNoRows` branch, e.g.:
```go
if err != nil {
    logger.Errorw("error finding external initiator", "err", err)
    return auth.ErrorAuthFailed
}
```

### Proof of Concept
1. Handler-level integration test: stand up the external-initiator-authenticated route with a mock `Authenticator` (`core/bridges/mocks/orm.go` style) whose `FindExternalInitiator` returns a non-`sql.ErrNoRows` error containing a distinctive string (e.g., `errors.New("pq: connection reset by peer, db=chainlink_prod")`).
2. Send an HTTP request to the protected route with arbitrary `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers, without any valid session/API token.
3. Assert response status is `401 Unauthorized` and assert the JSON body's error message contains the distinctive underlying string (e.g., `"finding external initiator: pq: connection reset by peer, db=chainlink_prod"`), confirming the internal error detail is disclosed to the unauthenticated caller.
4. Expected fix assertion: after remediation, the same test should assert the response body only contains a generic message (e.g., matching `auth.ErrorAuthFailed`'s text) with no trace of the underlying driver error string.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}
```

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
```

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
