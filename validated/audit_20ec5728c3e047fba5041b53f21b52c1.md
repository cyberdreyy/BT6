### Title
Unauthenticated flood of legacy trigger messages causes LRU eviction of a victim's pending `savedCallbacks` entry, silently dropping the victim's node response - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores every valid legacy trigger request in the shared `h.savedCallbacks` map keyed by `MessageId`, and `pruneCallbacks()` evicts the oldest entries purely by `createdAt` once the map exceeds `MaxSavedCallbacks`, with no per-sender quota, priority, or allowlist check. Because message signing only requires an arbitrary ECDSA keypair (not a privileged credential) and there is an explicit `// TODO: apply allowlist and rate-limiting here` marking the missing control, any external caller can generate enough distinct signed messages to exceed `MaxSavedCallbacks` and evict a victim's still-pending callback, causing the victim's later-arriving node response to be silently dropped (`found=false` in `handleWebAPITriggerMessage`).

### Finding Description
The relevant code path is: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218) decodes the JSON-RPC request, validates the message signature via `msg.Validate()` (core/services/gateway/api/message.go:54), and routes legacy requests to `handler.HandleLegacyUserMessage` [1](#0-0) . `Validate()` only checks field lengths and that a valid ECDSA signature exists over the message; it derives `Body.Sender` from `ExtractSigner()` but does not check the sender against any allowlist [2](#0-1) . Any party holding an arbitrary private key can sign a well-formed message and reach `HandleLegacyUserMessage` — this is explicitly acknowledged by the `// TODO: apply allowlist and rate-limiting here` comment right before method validation [3](#0-2) .

Once past minimal checks, every message is stored keyed by attacker-chosen `MessageId`: [4](#0-3) 

`pruneCallbacks()` runs periodically (or could be forced via natural growth) and, when `len(savedCallbacks) > MaxSavedCallbacks`, sorts all entries strictly by `createdAt` and deletes the oldest half regardless of sender identity: [5](#0-4) 

If a victim's entry is evicted before the corresponding node response arrives, `handleWebAPITriggerMessage` will find no entry in the map (`found=false`) and silently drop the response instead of delivering it to the victim's callback: [6](#0-5) 

The existing test suite (`TestPruneCallbacks`) already demonstrates the pure LRU-by-time eviction behavior with no sender-based protection: [7](#0-6) 

### Impact Explanation
This is a resource-exhaustion / availability issue: an unauthenticated (or minimally-authenticated, since only a valid signature over attacker-controlled data is required) actor can flood the shared `savedCallbacks` map to evict a legitimate victim's pending trigger callback, causing the victim's subsequent, valid capability response to be dropped. This maps to a DoS/availability impact class rather than authentication bypass, fund movement, or secret disclosure — it does not grant the attacker access to the victim's data or credentials, only denies/delays delivery of the victim's response.

### Likelihood Explanation
Feasibility is high: the attacker only needs to be able to generate distinct ECDSA keypairs (or reuse one key with distinct `MessageId`s) and submit `MaxSavedCallbacks`+1 well-formed legacy trigger requests in quick succession before pruning runs (`CallbackPruneIntervalSec`, default 30s) or before the map naturally exceeds size. No operator/admin credentials or DON membership are required — this is reachable purely via the gateway's public user-facing HTTP endpoint. The default `MaxSavedCallbacks` is 20000, which raises the practical cost of the attack but is still an unbounded, purely time/volume-based race with no per-sender rate limiting in this code path (rate limiting exists only for `nodeRateLimiter`, applied to node-originated outgoing messages, not to inbound user legacy triggers).

### Recommendation
Add per-sender rate limiting / quotas for `HandleLegacyUserMessage` (the TODO already flags this gap), and change `pruneCallbacks()` eviction policy to avoid pure global time-based LRU — e.g., cap the number of pending callbacks per sender/address, or weight eviction by sender fairness rather than only global age, so a single high-volume caller cannot starve other callers' pending entries.

### Proof of Concept
Extend `TestPruneCallbacks` in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Set `handler.config.MaxSavedCallbacks = N` (small value for test speed, e.g. 4).
2. Insert one "victim" entry with an early `createdAt` timestamp and a callback that has not yet been resolved.
3. Insert `N` "attacker" entries with `createdAt` timestamps later than the victim's, simulating rapid flooding.
4. Call `handler.pruneCallbacks()`.
5. Assert `handler.savedCallbacks` no longer contains the victim's `MessageId` (`require.NotContains`), demonstrating eviction.
6. Simulate the victim's node response arriving afterward by calling `handler.handleWebAPITriggerMessage` (or `HandleNodeMessage`) with the victim's `MessageId` and assert that no response is delivered to the victim's callback (i.e., `found=false` path taken, callback never receives `SendResponse`), confirming silent response loss.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
