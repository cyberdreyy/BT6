### Title
Session lifetime is bounded only by idle time, never by absolute age, allowing indefinite session renewal - ([File: core/sessions/localauth/orm.go](core/sessions/localauth/orm.go))

### Summary
`AuthorizedUserWithSession` in the local-auth `AuthenticationProvider` implementation (which backs `sessions.BasicAdminUsersORM`/`AuthenticationProvider`) validates a session solely on `last_used + SessionTimeout >= now()` and refreshes `last_used = now()` on every successful call. Neither this check, the `POST /sessions` login flow, nor the background reaper ever compare against the session's `created_at`, so a session ID that is used at least once per `SessionTimeout` interval (default 15m) never expires, contradicting the documented "session lasts before expiring" guarantee.

### Finding Description
`findValidSession` only checks idle time: [1](#0-0) 
and every successful `AuthorizedUserWithSession` call (invoked on every `/v2` request authenticated via `AuthenticateBySession`) bumps `last_used` forward again: [2](#0-1) 
The middleware that drives this on each request is `AuthenticateBySession`: [3](#0-2) 
The background `sessionReaper` (the only other place session lifetime is enforced) also computes its stale threshold purely from `last_used`, using `SessionReaperExpiration` only to delay cleanup of idle sessions, not to cap total session age: [4](#0-3) 
Nowhere in the codebase is `created_at` compared against a maximum lifetime for the purpose of rejecting a session. The docs describe `SessionReaperExpiration` as "how long an API session lasts before expiring and requiring a new login," but the implementation never enforces that as an absolute cap — it is only a grace period added on top of the idle timeout before the reaper deletes rows.

Consequently, if an attacker obtains a valid session ID (e.g., a stolen/shared browser session cookie, since `AuthenticateBySession` reads the session cookie value directly), they can keep it alive forever by sending any authenticated `/v2` request (or repeating `POST /sessions`-adjacent authenticated calls) at an interval shorter than `SessionTimeout`, well under the reaper's `SessionReaperExpiration` window. Each such request refreshes `last_used`, so `findValidSession`'s idle-time check always passes and the reaper's stale threshold is never reached.

### Impact Explanation
A hijacked or shared session that should eventually require re-authentication instead persists indefinitely as long as it is periodically used, giving an attacker permanent access at whatever role that session holds. If the compromised session belongs to an admin user, this enables indefinite admin-level access (key export, job/bridge management, unauthorized transaction submission) — matching the "node takeover" impact class, though the actual likelihood/severity depends on how the session credential was first obtained (see below).

### Likelihood Explanation
This does not grant privilege escalation from zero access: the attacker must first possess a valid session ID/cookie (via theft, sharing, XSS, endpoint exposure, etc.) — the finding assumes a "stolen or shared session" as stated in the question. Given that starting condition, exploitation is trivial and fully repeatable: a simple periodic HTTP GET/POST to any authenticated endpoint using the stolen cookie keeps the session alive forever with no further credentials, password, or MFA needed, and no additional detection barrier beyond normal request logging.

### Recommendation
Enforce an absolute session lifetime independent of activity: store and check `created_at` in `findValidSession` (e.g., reject if `created_at + MaxSessionAge < now()`, regardless of `last_used`), add a corresponding `MaxSessionAge`/`AbsoluteSessionTimeout` config, and have the reaper delete sessions whose `created_at` exceeds that same absolute bound, not just idle-based ones.

### Proof of Concept
Go integration test plan (extends existing `core/web/sessions_controller_test.go` patterns):
1. Create a user and log in via `POST /sessions` to obtain a valid session cookie; record `created_at`.
2. Using an advanceable clock, simulate repeated authenticated requests (e.g., `GET /v2/config` or any `/v2` route protected by `AuthenticateBySession`) every `SessionTimeout - 1s` for a duration well beyond `SessionReaperExpiration + SessionTimeout` (e.g., 300h with defaults of `SessionTimeout=15m`, `SessionReaperExpiration=240h`).
3. Assert that after this simulated absolute age is exceeded, the request is still accepted (HTTP 200) instead of being rejected with `ErrUserSessionExpired`/401 — demonstrating no absolute cap.
4. As a regression test for the fix, add a unit test on `findValidSession`/`AuthorizedUserWithSession` directly manipulating `created_at` in the `sessions` table to be older than the intended `MaxSessionAge` while keeping `last_used` fresh, and assert the call now returns `sessions.ErrUserSessionExpired`.

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

// AuthorizedUserWithSession will return the API user associated with the Session ID if it

func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM sessions WHERE last_used < $1", before)
	return err
}
