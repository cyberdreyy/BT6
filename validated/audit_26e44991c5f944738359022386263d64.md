### Title
Unbounded zstd compression of attacker-sized account data in `encode_ui_account` with no per-request byte cap - ([File: account-decoder/src/lib.rs])

### Summary
`JsonRpcRequestProcessor::get_account_info` fetches an account and calls `encode_ui_account`, which for `UiAccountEncoding::Base64Zstd` runs `zstd::stream::write::Encoder` over the account's entire on-chain data with no size guard. An attacker who has previously written a large account (up to `MAX_PERMITTED_DATA_LENGTH`, i.e. 10MB) can force a single `getAccountInfo` call to allocate and zstd-compress the full buffer.

### Finding Description
`encode_ui_account` in [1](#0-0)  for `Base64Zstd` encoding constructs a `zstd::stream::write::Encoder` and writes the full `slice_data(account.data(), data_slice_config)` output into it, with no length check before compressing. This is reached from `JsonRpcRequestProcessor::get_account_info`, which loads the account and dispatches to `get_encoded_account`/`encode_account` for encoding [2](#0-1) . The only existing size guard, `MAX_BASE58_BYTES` (128 bytes), is checked exclusively for `Binary`/`Base58` encodings in `encode_account`, and is bypassed entirely for `Base64` and `Base64Zstd` [3](#0-2) . Since `data_slice` is optional and defaults to the whole account, an attacker who has written an account up to the runtime-enforced `MAX_PERMITTED_DATA_LENGTH` can request that account with `encoding: "base64+zstd"` and no `dataSlice`, forcing a single-request zstd compression pass sized purely by the attacker-controlled account size, with no explicit RPC-level cap.

### Impact Explanation
This matches the "unbounded cost for a single low-rate call" category in scope: CPU time and heap allocation for one `getAccountInfo` request scale with attacker-controlled on-chain account size rather than an explicit RPC parameter limit, unlike the base58 path which is explicitly capped at `MAX_BASE58_BYTES`.

### Likelihood Explanation
Fully attacker-reachable with a single unprivileged RPC call once the attacker has written one large account on-chain (a prerequisite achievable via ordinary transactions, e.g. system program allocate/extend up to `MAX_PERMITTED_DATA_LENGTH`). No special privileges, staking, or multiple calls are required — one `getAccountInfo` call with `encoding: base64+zstd` triggers the full-size compression, and it can be repeated at the permitted rate.

### Recommendation
Apply an explicit byte-size cap (analogous to `MAX_BASE58_BYTES`) before performing `Base64`/`Base64Zstd` encoding in `encode_account`/`encode_ui_account`, or require/enforce a `dataSlice` for large accounts, returning an `InvalidRequest` error when the (post-slice) account length exceeds a configured maximum instead of unconditionally allocating and compressing the full account.

fn test_base64_zstd_scales_unbounded_with_account_size() {
    use std::time::Instant;
    let sizes = [1_000usize, 1_000_000, 10_000_000]; // up to MAX_PERMITTED_DATA_LENGTH
    let mut timings = vec![];
    for size in sizes {
        let account = AccountSharedData::from(Account {
            data: vec![0u8; size],
            ..Account::default()

        let _ = encode_ui_account(
            &Pubkey::default(),
            &account,
            UiAccountEncoding::Base64Zstd,
            None,
            None,
        );
        timings.push(start.elapsed());
    }
    // Expect: no cap present, so cost tracks account size directly.
    // A fix should assert an early InvalidRequest-style rejection above
    // a fixed threshold instead of unbounded growth in timings/allocation.
    println!("{:?}", timings);
}

fn encode_account<T: ReadableAccount>(
    account: &T,
    pubkey: &Pubkey,
    encoding: UiAccountEncoding,
    data_slice: Option<UiDataSliceConfig>,
) -> Result<UiAccount> {
    if (encoding == UiAccountEncoding::Binary || encoding == UiAccountEncoding::Base58)
        && data_slice
            .map(|s| min(s.length, account.data().len().saturating_sub(s.offset)))
            .unwrap_or(account.data().len())
            > MAX_BASE58_BYTES
    {
        let message = format!(
            "Encoded binary (base 58) data should be less than {MAX_BASE58_BYTES} bytes, please \
             use Base64 encoding."
        );
        Err(error::Error {
            code: error::ErrorCode::InvalidRequest,
            message,
            data: None,
        })
    } else {
        Ok(encode_ui_account(
            pubkey, account, encoding, None, data_slice,
        ))
    }
}
