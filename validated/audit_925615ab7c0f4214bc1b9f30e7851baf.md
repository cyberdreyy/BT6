### Title
Node-wide log replay/rewind endpoints require only the low-privilege "Run" role instead of "Admin" - (File: core/web/router.go)

### Summary
The Yaxis finding flagged that `setHalted()`, a function capable of shutting down the entire protocol, was gated by `onlyStrategist` (a lower-trust role) instead of `onlyGovernance` (the highest-trust role), letting a lesser-privileged actor cause node/protocol-wide disruption. The chainlink node exhibits the same class of issue: node-wide, chain-affecting operations that reprocess/rewind on-chain data for *all* jobs on a chain are gated by the lowest authenticated role ("Run") rather than "Admin".

### Finding Description
In `core/web/router.go`, the routes that trigger full-chain log/broadcaster/log-poller rewinds are wrapped with `auth.RequiresRunRole` rather than `auth.RequiresAdminRole`: [1](#0-0) 

`RequiresRunRole` only rejects the lowest role, `UserRoleView`; any user holding `Run`, `Edit`, or `Admin` passes: [2](#0-1) 

`ReplayController.ReplayFromBlock` and `LPSkipController.LPSkipToBlock` both invoke chain-wide operations — replaying the `LogBroadcaster`/`LogPoller` from an arbitrary block for an entire chain, or forcibly repositioning the LogPoller's cursor — which affect every job/subscriber consuming that chain's logs, not just resources owned by the caller: [3](#0-2) [4](#0-3) [5](#0-4) 

The role hierarchy defined for the operator UI/API is Admin > Edit > Run > View, and virtually every other operation that can disrupt shared/global node state (key management, ETH transfers, log level) is restricted to `RequiresAdminRole`: [6](#0-5) [7](#0-6) 

By contrast, `replay_from_block` and `lp_skip_to_block` — which can force reprocessing of already-consumed logs (`force`/`forceBroadcast=true`) or reposition the log poller's cursor for an entire chain shared by all jobs — are left at the `Run` role tier, the same tier automatically assigned to unattended/external-initiator-style callers elsewhere in the codebase (e.g., `auth.AuthenticateExternalInitiator` auto-assigns `UserRoleRun`): [8](#0-7) 

While these two specific routes are not reachable via the external-initiator auth path (only `/ping` and `/jobs/:ID/runs` are exposed to that group), a "Run"-role API user — the minimal role intended for scripted, single-purpose automation of job runs — can nonetheless trigger a node-wide chain rewind affecting all jobs, mirroring the "Strategist could halt the whole protocol" pattern: a role meant for narrow, low-impact operations is empowered to perform an action with blast radius far beyond the caller's own resources.

### Impact Explanation
A "Run" role credential is meant to be scoped to invoking individual job runs (e.g. `POST /v2/jobs/:ID/runs`), the lowest meaningful authenticated privilege above read-only "View". Because `replay_from_block` and `lp_skip_to_block` are also gated at that same tier, any account provisioned only with "Run" access — which operators may issue to automation/scripts with the expectation of minimal blast radius — can:
- Force the `LogBroadcaster`/`LogPoller` to reprocess a large range of historical blocks/logs for an entire chain (`force=true`), potentially causing duplicate job executions, resource exhaustion (CPU/DB/RPC load), and delayed processing of new logs for every job on that chain.
- Reposition the `LogPoller`'s cursor (`lp_skip_to_block`), altering what log range is considered processed for the whole chain, which can desynchronize or disrupt OCR/keeper/automation jobs relying on log-based state for all users of that node — not just the caller's own jobs.

This is a node-wide (not scoped to the caller) disruptive/DoS-class capability exposed to a role explicitly documented and designed for the narrowest scope of authority, directly analogous to a "Strategist"-level actor being able to halt/shutdown protocol-wide state that should require "Governance"-level trust.

### Likelihood Explanation
Exploitation requires possession of valid API credentials with only the "Run" role (via `AuthenticateByToken` or `AuthenticateBySession`), which is plausible in operational settings where automation accounts or delegated lower-trust users are issued "Run" tokens intentionally scoped for narrow job-triggering purposes. No further privilege escalation is needed since the RBAC middleware itself permits it.

### Recommendation
Change the access-control middleware on the chain-rewind endpoints from `auth.RequiresRunRole` to `auth.RequiresAdminRole`, consistent with other node-wide/shared-state-impacting operations (key management, ETH transfers, log level changes): [1](#0-0) 

### Proof of Concept
1. Provision (or compromise) an API user/token with only `UserRoleRun`.
2. Authenticate and call `POST /v2/replay_from_block/1?family=evm&ChainID=<chainID>&force=true`.
3. Observe that `auth.RequiresRunRole` (core/web/auth/auth.go:202-217) allows the request through since the caller's role is not `View`.
4. `ChainlinkApplication.ReplayFromBlock` triggers `LogBroadcaster.ReplayFromBlock` and, if LogPoller feature is enabled, `LogPoller.ReplayAsync`, forcing chain-wide reprocessing of logs for all jobs on that chain — an action with blast radius exceeding what a "Run"-scoped credential should be trusted with.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// ReplayFromBlock causes the node to process blocks again from the given block number
// Example:
//
//	"<application>/v2/replay_from_block/:number"
func (bdc *ReplayController) ReplayFromBlock(c *gin.Context) {
	if c.Param("number") == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("missing 'number' parameter"))
		return
	}

	// check if "force" query string parameter provided
	var force bool
	var err error
	if fb := c.Query("force"); fb != "" {
		force, err = strconv.ParseBool(fb)
		if err != nil {
			jsonAPIError(c, http.StatusUnprocessableEntity, errors.Wrap(err, "boolean value required for 'force' query string param"))
			return
		}
	}

	blockNumber, err := strconv.ParseInt(c.Param("number"), 10, 0)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if blockNumber < 0 {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.Errorf("block number cannot be negative: %v", blockNumber))
		return
	}

	chainFamily := c.Query("family")
	if chainFamily == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("chain family was not provided"))
		return
	}

	chainID := c.Query("ChainID")
	if strings.TrimSpace(chainID) == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("chain-id was not provided"))
		return
	}

	ctx := c.Request.Context()
	if err := bdc.App.ReplayFromBlock(ctx, chainFamily, chainID, uint64(blockNumber), force); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	response := ReplayResponse{
		Message: "Replay started",
		ChainID: chainID,
	}
	jsonAPIResponse(c, &response, "response")

// LPSkipToBlock repositions the LogPoller to start processing from the given block number.
// Example:
//
//	"<application>/v2/lp_skip_to_block"
func (c *LPSkipController) LPSkipToBlock(gctx *gin.Context) {
	var request LPSkipToBlockRequest
	if err := gctx.ShouldBindJSON(&request); err != nil {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, err)
		return
	}
	if request.BlockNumber < 2 {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("block number must be >= 2: %v", request.BlockNumber))
		return
	}

	if request.Family == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain family was not provided"))
		return
	}
	if request.Family != relay.NetworkEVM {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("unsupported chain family %q, only %s is supported", request.Family, relay.NetworkEVM))
		return
	}

	if strings.TrimSpace(request.ChainID) == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain-id was not provided"))
		return
	}

	ctx := gctx.Request.Context()
	if err := c.App.LPSkipToBlock(ctx, request.Family, request.ChainID, request.BlockNumber); err != nil {
		if errors.Is(err, chainlink.ErrNoSuchRelayer) {
			jsonAPIError(gctx, http.StatusBadRequest, err)
			return
		}
		jsonAPIError(gctx, http.StatusInternalServerError, err)
		return
	}

	response := LPSkipToBlockResponse{
		Message:     "Log poller will start processing from the new block on next tick",
		ChainID:     request.ChainID,
		BlockNumber: request.BlockNumber,
	}
	jsonAPIResponse(gctx, &response, "response")
}

// ReplayFromBlock implements the Application interface.
func (app *ChainlinkApplication) ReplayFromBlock(ctx context.Context, chainFamily string, chainID string, number uint64, forceBroadcast bool) error {
	if chainFamily == relay.NetworkEVM {
		// TODO: Implement EVM Replay on Relayer instead of using LegacyChains - BCFR-1160
		chain, err := app.GetRelayers().LegacyEVMChains().Get(chainID)
		if err != nil {
			return err
		}
		//nolint:gosec // this won't overflow
		fromBlock := int64(number)

		if legacyChain, ok := chain.(legacyevm.Chain); ok {
			legacyChain.LogBroadcaster().ReplayFromBlock(fromBlock, forceBroadcast)
			if app.Config.Feature().LogPoller() {
				legacyChain.LogPoller().ReplayAsync(fromBlock)
			}
			return nil
		}
		// else LOOPP mode, so fall back to default
	}
	relayer, err := app.GetRelayers().Get(commontypes.RelayID{
		Network: chainFamily,
		ChainID: chainID,
	})
	if err != nil {
		return err
	}
	return relayer.Replay(ctx, strconv.FormatUint(number, 10), map[string]any{})
}
