### Title
Floor-rounded 70% threshold in `GlobalStateEvaluator::reached_agreement` allows sub-70% weight to be treated as global consensus - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` compute the 70%/30% supermajority thresholds with integer (floor) division instead of the ceiling that the consensus-critical, node-verified threshold uses. This is the exact rounding-direction bug class from the report: a division that should round in the "stricter" direction is rounded the "looser" way, letting a vote weight strictly below the true 70% supermajority be accepted as having "reached agreement."

### Finding Description
The consensus-critical, node-enforced signer approval threshold is implemented with an explicit ceiling in `NakamotoBlockHeader::compute_voting_weight_threshold`: [1](#0-0) 

That function is used both by the node (`verify_signer_signatures`) and by the signer's own pre-commit/acceptance counting logic (`compute_voting_weight_threshold` calls in `handle_block_pre_commit` and `store_and_process_block_signature`): [2](#0-1) [3](#0-2) 

However, the signer's *global state machine* agreement logic in `libsigner/src/v0/signer_state.rs` uses a different, floor-rounded computation: [4](#0-3) 

`u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10` performs a floor division of `total_weight * 7 / 10`. Whenever `total_weight * 7` is not a multiple of 10, this floors down to a strictly smaller integer than the true 70% cutoff, so a `vote_weight` that is *below* 70% of `total_weight` can still satisfy `vote_weight >= threshold`. Existing regression tests in `libsigner/src/tests/signer_state.rs` only pin the *overflow* fix (u64 widening) and use `total_weight` values evenly divisible to avoid exposing the rounding-direction issue itself: [5](#0-4) 

`reached_agreement`/`reached_disagreement` gate `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which resolves the agreed active miner, burn view, and transaction-replay set): [6](#0-5) [7](#0-6) [8](#0-7) 

This breaks the intended equality "aggregated-weight >= verified 70% supermajority" for the signer's view of global state (active miner / canonical burn view / tx replay set), even though the actual block-signature threshold (`compute_voting_weight_threshold`) is computed correctly elsewhere.

### Impact Explanation
This matches the High-impact category: the signer can act on an incorrect ("stale"/miscomputed) threshold. Because `reached_agreement`/`reached_disagreement` under-count the true 70% bar, a signer can conclude that the network-wide signer set has agreed on a burn view, active miner, protocol version, or transaction-replay set when, in fact, strictly less than 70% (or more than 30% for disagreement) truly support it. Since this feeds `determine_global_state`, which establishes the signer's belief about the currently active miner/tenure and permitted replay set, a signer could commit to acting on a global view (e.g., accepting a miner as the agreed active miner, or adopting a shorter/incorrect tx replay set) without the specified supermajority genuinely backing it — a violation of the state-machine's designed safety margin, distinct from (and not covered by) the separately-correct block-signature threshold check.

### Likelihood Explanation
The bug triggers deterministically whenever `total_weight * 7` is not a multiple of 10 — i.e., for the vast majority of possible signer weight distributions (only totals that are multiples of 10 avoid it). No majority collusion or privileged access is required; it is a pure arithmetic defect reachable by ordinary signer-set weight distributions during normal operation, exactly matching the "reachable by a one-slot miner / any signer set, not requiring majority collusion" bar, since it is triggered purely by the natural, adversary-independent weight totals of the reward set.

### Recommendation
Change `reached_agreement` and `reached_disagreement` to use ceiling division consistent with `NakamotoBlockHeader::compute_voting_weight_threshold`, e.g.:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total = u64::from(self.total_weight);
    let num = total.strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let threshold = num.div_ceil(10);
    u64::from(vote_weight) >= threshold
}
```
and apply the analogous ceiling fix to `reached_disagreement`'s complementary threshold, so the two helper functions match the rounding semantics already used for the on-chain/consensus threshold.

### Proof of Concept
Let `total_weight = 11` (e.g., signer weights summing to 11 across the reward set).
- True 70% cutoff: `ceil(11 * 7 / 10) = ceil(7.7) = 8` (72.7% of total).
- `reached_agreement`'s floor computation: `11 * 7 / 10 = 77 / 10 = 7` (using integer division on the `u64` result), so `reached_agreement(7)` returns `true`.
- `7 / 11 ≈ 63.6%`, strictly below the intended 70% supermajority, yet `GlobalStateEvaluator::determine_global_state`/`determine_global_burn_view`/`determine_latest_supported_signer_protocol_version` (all gated by `reached_agreement`) will accept this as a resolved global-state consensus value.         let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view

/// Regression: u32 multiplication in `reached_agreement` wrapped silently in
/// release builds for `total_weight > u32::MAX / 7 ≈ 613_566_756`. With
/// `total_weight = 1_000_000_000` the buggy expression `total_weight * 7 / 10`
/// wrapped to ~270_503_270, allowing roughly 27% of total weight to satisfy
/// the 70% supermajority check. The fix widens to u64 first.
fn reached_agreement_no_u32_overflow() {
    let evaluator = evaluator_with_total_weight(1_000_000_000);

    // Pre-fix wrap landed at 270_503_270; assert that vote_weight at the wrapped
    // value is correctly rejected — i.e., 27% does not satisfy 70%.
    assert!(
        !evaluator.reached_agreement(270_503_270),
        "27% of total_weight must not satisfy the 70% threshold"
    );
    // Boundary: exactly 70% must pass.
    assert!(
        evaluator.reached_agreement(700_000_000),
        "70% of total_weight must satisfy the 70% threshold"
    );
    // Just below 70% must fail.
    assert!(
        !evaluator.reached_agreement(699_999_999),
        "below 70% must not satisfy the threshold"
    );
}
