### Title
Unauthenticated pre-link APR manipulation inflates borrower settlement or forces default - ([File: contracts/strategies/idle/IdleCreditVault.sol](contracts/strategies/idle/IdleCreditVault.sol))

### Summary

`IdleCreditVault.setApr()` skips its CDO/manager authorization check whenever `idleCDO` is unset, allowing any EOA or contract to overwrite the vault’s fixed APR during deployment setup. [1](#0-0) 

### Finding Description

`initialize()` configures the initial APR and `maxApr`, but it does not configure `idleCDO`. [2](#0-1)  The CDO address is only installed later through the owner-only `setWhitelistedCDO()` function. [3](#0-2) 

Before that call, an unprivileged attacker can invoke `setApr(20e18)` or `setAprsWithBuffer(...)` because `setAprsWithBuffer()` has no authorization check and `setApr()` explicitly bypasses authorization while `idleCDO == address(0)`. [4](#0-3) 

A concrete sequence is:

1. Owner initializes `IdleCreditVault` with a legitimate 5% APR.
2. Owner initializes `IdleCDOEpochVariant`; its initialization reads and rescales the strategy APR. [5](#0-4) 
3. Before `setWhitelistedCDO()` links the CDO, the attacker calls `setApr(20e18)`, the maximum accepted value.
4. Owner links the CDO.
5. A KYC-passing attacker deposits as the sole lender, and the manager starts the epoch in fixed-APR cash-interest mode.
6. `startEpoch()` computes `expectedEpochInterest` using the strategy APR. [6](#0-5) 
7. At `stopEpoch()`, the CDO pulls the inflated interest amount from the honest borrower. [7](#0-6) 

For a 1,000,000-underlying pool, replacing an approximately 5.83% scaled APR with 20% produces approximately 16,438 units of borrower-paid interest rather than approximately 4,795 units for a 30-day epoch, an unauthorized excess of approximately 11,643 units.

### Impact Explanation

If the honest borrower has sufficient balance and allowance, the manipulated APR causes a direct excess transfer from the borrower into the CDO, where it becomes distributable vault yield to lenders; an attacker who is the sole KYC-passing lender receives the excess. [8](#0-7) 

If the borrower funded or approved only the legitimate quote, the oversized `transferFrom` fails and the catch path invokes `_handleBorrowerDefault()`. [9](#0-8)  That sets `defaulted`, stops the epoch, pauses deposits, and disables withdrawal requests, freezing ordinary lender exits until the default-recovery flow completes. [10](#0-9) 

The existing `_onlyIdleCDO()` guards on deposits, withdrawals, minting, burning, and recovery functions do not protect `setApr()` because that function uses a separate conditional authorization path. [11](#0-10) 

### Likelihood Explanation

Likelihood depends on deployment sequencing: the attack requires a transaction or mempool-visible gap between strategy/CDO initialization and `setWhitelistedCDO()`. [3](#0-2)  Nothing in `setApr()` itself prevents that gap from being exploited, so atomic deployment would reduce exposure but does not remove the broken authorization assumption. [1](#0-0) 

### Recommendation

Remove the unauthenticated `idleCDO == address(0)` bypass from `setApr()` and require `msg.sender` to be the CDO, manager, or owner during initialization. Deployments should link the strategy to the already-deployed CDO proxy before calling the CDO initializer, or the factory/orchestrator should initialize and link the pair atomically so no unprivileged setup window exists.

  /// @notice Handle borrower default
  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    emit BorrowerDefault(funds);
