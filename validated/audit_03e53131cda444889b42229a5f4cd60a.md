### Title
Missing "0x" prefix enforcement in `validateHexInput` allows negative-length `strings.Repeat` panic in `normalizeHex`, crashing the gateway HTTP trigger request handler - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` only checks that the total input length is `<=` the expected length and that the string (after an optional `"0x"` trim) decodes as valid hex; it never requires the `"0x"` prefix to actually be present. [1](#0-0)  An unauthenticated attacker can therefore submit a `workflowID` (or `workflowOwner`) as a raw hex string of exactly `workflowIDLength` (66) or `workflowOwnerLength` (42) characters with no `"0x"` prefix. This passes `validateWorkflowID`/`validateWorkflowOwner`, but when `resolveWorkflowID` subsequently calls `normalizeHex`, the `TrimPrefix` becomes a no-op (nothing to trim), leaving `len(hexStr)` equal to the full input length while `expectedHexLength = length - 2`, producing a negative count for `strings.Repeat`, which panics. [2](#0-1) 

### Finding Description
Request flow: `HandleUserTriggerRequest` → `validatedTriggerRequest` → `validateTriggerParams` → `validateWorkflowFields` → `validateWorkflowID`/`validateWorkflowOwner` (via `validateHexInput`) → then back in `HandleUserTriggerRequest`, `resolveWorkflowID` is called, which invokes `normalizeHex`. [3](#0-2) 

`validateHexInput` logic:
```go
hexStr := strings.TrimPrefix(input, "0x")
_, err := hex.DecodeString(hexStr)
```
If the attacker sends a `workflowID` of exactly 66 lowercase hex characters with **no** `0x` prefix (e.g., `"1234...ef"` × 66 chars), it satisfies `len(input) <= 66` and decodes as valid hex (66 is even), so `validateHexInput` returns no error. [4](#0-3) 

Then `resolveWorkflowID` calls `normalizeHex(workflowID, workflowIDLength)` where `workflowIDLength = 66`:
```go
hexStr := strings.TrimPrefix(input, "0x")     // no-op, len(hexStr) = 66
expectedHexLength := length - 2               // 64
paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr))  // Repeat("0", -2) -> panic
```
`strings.Repeat` panics with `"strings: negative Repeat count"` for any negative count. [5](#0-4)  The same is true for `workflowOwner` when passed as a raw 42-char hex string with no `0x` prefix, reached via the same `resolveWorkflowID` function. [6](#0-5) 

Crucially, no earlier check enforces that the string must actually start with `"0x"` — it is only "trimmed if present." There is no length floor check (only an upper bound `len(input) > expectedLength`), so equal-length inputs without the prefix slip through. There is no `recover()` anywhere in the call chain (`HandleUserTriggerRequest`, `resolveWorkflowID`, `normalizeHex`), so the panic propagates unhandled. [7](#0-6) 

### Impact Explanation
An unrecovered panic in Go crashes the entire process (not merely the invoking goroutine), unless the code path is wrapped by a `recover()` — none was found in this call chain. This means a single crafted, unauthenticated gateway trigger request (any user reachable to `HandleUserTriggerRequest`, prior to authorization via `authorizeRequest`) can crash the whole Chainlink gateway process, denying service to every user of that gateway/DON, not just callers of one handler instance. This matches Chainlink's "Denial of Service" bounty impact class caused by unauthenticated/pre-auth crafted input.

### Likelihood Explanation
No authentication or authorization is required to reach this code — the panic occurs in `resolveWorkflowID`, which runs before `authorizeRequest`/signature verification in `HandleUserTriggerRequest`. [8](#0-7)  The malicious payload is a simple JSON body with `workflowID` set to a 66-character lowercase hex string without the `0x` prefix (or `workflowOwner` at 42 chars). This is trivially repeatable and requires no special credentials, only network access to the gateway's trigger endpoint.

### Recommendation
In `validateHexInput` (and/or `normalizeHex`), require the `"0x"` prefix to actually be present (reject if `!strings.HasPrefix(input, "0x")`), and additionally guard `normalizeHex` to reject/error instead of panicking when `expectedHexLength - len(hexStr) < 0` (i.e., when the un-prefixed hex payload is already too long). Defensive fix: 
```go
func normalizeHex(input string, length int) (string, error) {
    hexStr := strings.TrimPrefix(input, "0x")
    expectedHexLength := length - 2
    if len(hexStr) > expectedHexLength {
        return "", fmt.Errorf("hex string too long")
    }
    return "0x" + strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr, nil
}
```
and propagate/handle the error at both call sites in `resolveWorkflowID`.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func (h *httpTriggerHandler) validateWorkflowID(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	if err := validateHexInput(workflowID, workflowIDLength); err != nil {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflowID "+err.Error(), callback)
		return errors.New("workflowID " + err.Error())
	}

	return nil
}

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}
