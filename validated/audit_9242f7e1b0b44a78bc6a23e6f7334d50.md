### Title
Account enumeration via non-uniform error content and timing in login flow - (File: core/sessions/localauth/orm.go)

### Summary
`CreateSession` (called from `POST /sessions` via `SessionsController.Create`) returns distinct error strings for "user not found", "wrong password", and "MFA required" cases, and these raw error messages are serialized verbatim into the JSON response body. Combined with the fact that password hashing (`utils.CheckPasswordHash`) is only performed for existing accounts, an unauthenticated caller can enumerate valid operator emails by content and by timing. The other two authentication surfaces named in the question — API-token headers (`AuthenticateByToken`) and session-cookie lookup (`AuthorizedUserWithSession`/`AuthenticateBySession`) — already normalize failures to generic errors and do not leak this information.

### Finding Description
`orm.CreateSession` in [1](#0-0)  first calls `o.FindUser(ctx, sr.Email)`. If the email doesn't exist, the raw DB error (e.g. `sql: no rows in result set`) is returned unmodified. If the email exists but the password is wrong, the distinct string `"Invalid password"` is returned. If the email exists, password is correct, and MFA is enrolled, a distinct WebAuthn challenge JSON payload is returned instead of an error, as seen in [2](#0-1) .

These errors propagate up to `SessionsController.Create` in [3](#0-2) , which passes them to `jsonAPIError(c, http.StatusUnauthorized, err)`. That helper serializes `err.Error()` directly into the JSON body without normalization: [4](#0-3) . All three cases return the same HTTP status (401), but the body content differs deterministically per case, giving an unauthenticated client a reliable oracle to distinguish "no such account" from "account exists, wrong password" from "account exists, MFA-enabled."

In addition, the password check `utils.CheckPasswordHash(sr.Password, ...)` in [5](#0-4)  — a bcrypt comparison — is only executed when the email lookup succeeds, so requests for non-existent accounts return faster than requests for existing accounts with wrong passwords, providing a secondary timing oracle.

By contrast, the other two auth surfaces referenced in the question already avoid this class of leak:
- `AuthorizedUserWithSession` (session cookie lookup) always maps failures to the single generic `sessions.ErrUserSessionExpired` regardless of whether the session/email is unknown: [6](#0-5) .
- `AuthenticateByToken` (API-token headers) maps `sql.ErrNoRows`/expired-token cases uniformly to `auth.ErrorAuthFailed`: [7](#0-6) .

So the exploitable oracle is confined to the `POST /sessions` login endpoint, not `FindUser`/`FindUserByAPIToken`/session-cookie validation as generically implied by the question.

### Impact Explanation
This is an information-disclosure/user-enumeration issue, not a direct authentication bypass or privilege escalation. It lets an unauthenticated network client build a list of valid operator emails on the node's API port, which is a precondition/force-multiplier for subsequent targeted credential attacks (password guessing, credential stuffing) — but does not itself grant session creation, key export, or fund movement. It does not meet the "Critical - node takeover" bar claimed in the question; the concrete, provable impact here is account enumeration (typically Low/Informational under most bounty frameworks) rather than direct compromise.

### Likelihood Explanation
Trivially exploitable and fully repeatable: no privileges are required, no rate limiting distinguishes content-based probing (only volumetric limiting exists via `rl.UnauthenticatedPeriod()` in [8](#0-7) , which slows but does not prevent enumeration), and the differing response bodies/timings are deterministic per request.

### Recommendation
In `orm.CreateSession`, normalize all pre-authentication failure paths (unknown email, wrong password, MFA errors) to a single generic error (e.g., `"invalid credentials"`) and status code before returning from `SessionsController.Create`. Additionally, always perform a dummy/constant-cost password hash comparison (e.g., against a static reference hash) when the email lookup fails, so response timing does not vary between known/unknown accounts. The WebAuthn challenge path should also be gated so its distinguishable response shape doesn't leak MFA enrollment status pre-authentication.

### Proof of Concept
Table-driven handler test against `POST /sessions`:
1. Create one known user (`user.Email`/`cltest.Password`) via `AuthenticationProvider().CreateUser`.
2. Issue three requests: (a) unknown email + any password, (b) known email + wrong password, (c) known email (with WebAuthn registered) + correct password/no `WebAuthnData`.
3. Assert all three return `http.StatusUnauthorized` (confirming status alone doesn't leak), similar to the pattern in [9](#0-8) .
4. Additionally assert the response bodies differ (`"sql: no rows..."` vs `"Invalid password"` vs webauthn challenge JSON), proving the content-based oracle.
5. Optionally measure wall-clock time for (a) vs (b) over many iterations to confirm the bcrypt timing gap.

```go
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
```

```go
func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}
```

```go
func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```

```go
func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
```

```go
	}

	for _, test := range tests {

			t.Parallel()
```
