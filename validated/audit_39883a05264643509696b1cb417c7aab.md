### Title
Missing mint-owner validation in `get_token_account_balance` allows attacker-controlled decimals from a forged, non-Mint account - (File: rpc/src/parsed_token_accounts.rs, rpc/src/rpc.rs)

### Summary
`Bank::get_token_account_balance` resolves the `mint` field of an attacker-supplied token account via `get_mint_owner_and_additional_data`, but discards the returned mint owner and never validates that the referenced "mint" account is actually owned by a known SPL Token program. Any account whose raw bytes happen to satisfy `StateWithExtensions::<Mint>::unpack`'s structural checks (82-byte length, valid `COption` tags, boolean `is_initialized`) is accepted as a genuine Mint, letting an attacker report arbitrary, fabricated `decimals` for a token balance query.

### Finding Description
`get_token_account_balance` reads the target account, checks only that *the token account itself* is owned by a known SPL token id, unpacks it as `TokenAccount`, and extracts the embedded `mint` pubkey directly from attacker-controlled data: [1](#0-0) 

It then calls `get_mint_owner_and_additional_data(&bank, mint)`, but binds the returned owner to `_`, discarding it entirely:
```rust
let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;
```

`get_mint_owner_and_additional_data` fetches whatever account exists at `mint` — with **no ownership check** — and hands its raw bytes to `get_additional_mint_data`, which only checks that the bytes structurally unpack as `Mint`: [2](#0-1) 

By contrast, other call sites that use the same helper *do* validate the returned owner before trusting the parsed data, e.g. `get_token_largest_accounts` and `get_token_program_id_and_mint`: [3](#0-2) [4](#0-3) 

and `get_token_supply` independently checks `is_known_spl_token_id(mint_account.owner())` before unpacking: [5](#0-4) 

`get_token_account_balance` is the outlier: it never performs this check. Since an unprivileged attacker fully controls both:
1. the "token account" content (mint field, amount) — via the write-then-`system_instruction::assign` pattern (write arbitrary bytes to an account owned by an attacker-controlled program, then reassign ownership to a known SPL token id so `is_known_spl_token_id(account.owner())` passes), and
2. the "mint" account content — likewise crafted to be exactly 82 bytes with valid `COption`/`bool` encodings, with **no requirement that its owner be a token program at all** (the owner is discarded),

`StateWithExtensions::<Mint>::unpack` will happily succeed on this forged mint account and return an attacker-chosen `decimals` value that has never been validated by, or associated with, any real SPL Token/Token-2022 `InitializeMint` invocation.

### Impact Explanation
This is a decoder/RPC data-integrity issue: `getTokenAccountBalance` can return a balance whose `decimals` (and thus `uiAmount`/`uiAmountString`) is entirely attacker-fabricated rather than derived from a genuine on-chain Mint, misreporting token data to downstream integrators (wallets, exchanges, indexers) that trust this RPC response. This matches the "misreporting program, authority, amount, decimals, or token owner to downstream integrators" bounty category — an RPC/decoder correctness bug, not a consensus or crash issue.

### Likelihood Explanation
Fully reachable by a single unprivileged client: deploy a small on-chain program, allocate two accounts, write the crafted `Account`- and `Mint`-shaped byte layouts while still owned by that program, reassign the "token account" to a real SPL Token program id via `system_instruction::assign` (the "mint" account's owner need not even be a token program, since it's never checked), then call `getTokenAccountBalance` on the fake token account. No commitment/length/quota guard blocks this, and the exploit is deterministic and repeatable on any single call.

### Recommendation
In `get_token_account_balance`, validate the mint owner returned from `get_mint_owner_and_additional_data` (mirroring `get_token_largest_accounts`/`get_token_program_id_and_mint`):
```rust
let (mint_owner, data) = get_mint_owner_and_additional_data(&bank, mint)?;
if !is_known_spl_token_id(&mint_owner) {
    return Err(Error::invalid_params("Invalid param: not a Token mint".to_string()));
}
```
More robustly, move this owner check inside `get_mint_owner_and_additional_data` itself so all call sites (including `get_parsed_token_account`/`get_parsed_token_accounts` in `parsed_token_accounts.rs`, which have the same gap via `get_additional_mint_data`) are protected uniformly.

### Proof of Concept
```rust
// rpc/src/rpc.rs test module
#[test]
fn test_get_token_account_balance_with_forged_mint() {
    let rpc = RpcHandler::start();
    let bank = rpc.working_bank();
    let RpcHandler { meta, .. } = rpc;

    // Forged "mint" account: 82-byte Mint layout, owner is NOT a token program,
    // decimals is attacker-chosen (e.g. 255) with no on-chain InitializeMint ever run.
    let fake_mint_pubkey = solana_pubkey::new_rand();
    let mut mint_data = vec![0u8; Mint::get_packed_len()];
    let fake_mint = Mint {
        mint_authority: COption::None,
        supply: 0,
        decimals: 255, // attacker-controlled, never validated on-chain
        is_initialized: true,
        freeze_authority: COption::None,
    };
    Mint::pack(fake_mint, &mut mint_data).unwrap();
    let fake_mint_account = AccountSharedData::from(Account {
        lamports: 111,
        data: mint_data,
        owner: solana_pubkey::new_rand(), // arbitrary, NOT spl_token/spl_token_2022 id
        ..Account::default()
    });
    bank.store_account(&fake_mint_pubkey, &fake_mint_account);

    // Forged token account owned by a real SPL Token program, pointing at fake mint.
    let token_account_pubkey = solana_pubkey::new_rand();
    let mut account_data = vec![0u8; TokenAccount::get_packed_len()];
    let token_account = TokenAccount {
        mint: fake_mint_pubkey,
        owner: solana_pubkey::new_rand(),
        delegate: COption::None,
        amount: 1_000,
        state: TokenAccountState::Initialized,
        is_native: COption::None,
        delegated_amount: 0,
        close_authority: COption::None,
    };
    TokenAccount::pack(token_account, &mut account_data).unwrap();
    let token_account = AccountSharedData::from(Account {
        lamports: 111,
        data: account_data,
        owner: spl_token_interface::id(), // passes is_known_spl_token_id check
        ..Account::default()
    });
    bank.store_account(&token_account_pubkey, &token_account);

    let result = meta.get_token_account_balance(&token_account_pubkey, None);
    // BUG: currently succeeds with attacker-chosen decimals=255 despite fake_mint
    // never being owned by/initialized through any real SPL Token program.
    // Expected (fixed) behavior: Err(Error::invalid_params("... not a Token mint"))
    assert!(result.is_err(), "expected rejection of forged, non-token-owned mint account");
}
```

```rust
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}
```
