### Title
Missing sender allowlist validation in Gateway `HandleLegacyUserMessage` broadcasts unauthenticated user requests to entire DON - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The Chainlink Gateway's internet-facing `web_api_trigger` capability handler accepts incoming user (client) messages via `handler.HandleLegacyUserMessage` and forwards them to every node in the DON without any sender allowlist check or gateway-side rate-limiting, despite an explicit TODO acknowledging this gap. This mirrors the CCIP report's bug class: a message-processing entry point that trusts message content/signature validity but omits verification that the *sender* is an authorized/trusted party before triggering downstream state changes (here, dispatching work to all DON nodes and creating a persisted callback).

### Finding Description
`handler.HandleLegacyUserMessage` in [1](#0-0)  processes a `api.Message` originating from an external HTTP client (per the `Handler` interface doc: "processed by a separate goroutine ... calls HandleUserMessage"), validates only:
- payload decodability,
- a non-zero timestamp,
- message staleness,
- that the method equals `MethodWebAPITrigger`.

It then explicitly skips authorization with the comment `// TODO: apply allowlist and rate-limiting here` at [2](#0-1)  and proceeds to save a callback and broadcast the request to **every member of the DON**: [3](#0-2) 

The only signature check performed earlier is `Message.Validate()` (in `core/services/gateway/api/message.go`), which verifies the message is well-formed and recovers a signer address into `Body.Sender` — but nothing in `HandleLegacyUserMessage` checks that this recovered sender is a member of any `allowedSenders` set. Contrast this with the trigger's own node-side re-validation in `webapiTrigger.allowedSenders` (`core/capabilities/webapi/trigger/trigger.go:101`), which is a *separate, second* check performed later, per-workflow, on the node side after the Gateway has already fanned the message out to all DON nodes.

This means the Gateway layer itself — the component directly reachable by unprivileged internet clients — performs no source/sender validation before forwarding a signed-but-unauthorized message to the whole DON, exactly analogous to `BridgeCCIP::_ccipReceive` processing any well-formed cross-chain message without checking that the sender/source is on an allowed-peer list.

### Impact Explanation
Any client capable of producing a validly-signed `api.Message` (signature validity only requires a recoverable ECDSA signature, not membership in any allowlist) can:
- Force the Gateway to persist entries in `h.savedCallbacks` (resource consumption / DoS vector against `MaxSavedCallbacks`),
- Force `don.SendToNode` calls to every DON member for an unauthorized workflow trigger, consuming node-side compute/network resources and rate-limit budget (`nodeRateLimiter`, `trigger.rateLimiter`) that should be reserved for legitimate senders,
- Rely entirely on individual workflow registrations' own `allowedSenders` check to reject the request as a last line of defense; if that per-workflow check is absent, misconfigured, or bypassed, unauthorized trigger execution results.

While the second-layer `allowedSenders` check in `trigger.go` does mitigate the worst outcome (arbitrary unauthorized workflow execution) for correctly configured triggers, the Gateway itself provides no equivalent protection and openly documents the omission via the TODO, meaning defense-in-depth at the ingress point is absent.

### Likelihood Explanation
High reachability: `HandleLegacyUserMessage` is invoked directly from unauthenticated HTTP/user-facing Gateway request handling (per the `Handler` interface contract), requiring no privileged credentials — only a validly signed message (any keypair can sign it). No source/sender allowlist gate exists before DON-wide fanout.

### Recommendation
Implement sender/source allowlist validation directly inside `HandleLegacyUserMessage` (or a shared pre-check invoked before persisting callbacks and calling `don.SendToNode`), rejecting requests from senders not present in a DON/gateway-level allowlist, and apply Gateway-level rate-limiting per the existing TODO, rather than relying solely on the downstream per-workflow `allowedSenders` check in the trigger capability.

### Proof of Concept
1. Construct a valid `api.Message` with `Body.Method = "web_api_trigger"`, a non-zero `Timestamp` payload field, and a valid signature from an arbitrary (non-allowlisted) private key so `Message.Validate()` succeeds and populates `Body.Sender`.
2. Submit it to the Gateway's HTTP endpoint, invoking `HandleLegacyUserMessage`.
3. Observe that `handler.go` skips any sender-allowlist check (the TODO at line 384) and calls `don.SendToNode` for every DON member (`core/services/gateway/handlers/capabilities/handler.go:411-420`), regardless of whether the sender is authorized — the request is only rejected later, per-workflow, if `trigger.go`'s own `allowedSenders` map does not contain the sender. func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
