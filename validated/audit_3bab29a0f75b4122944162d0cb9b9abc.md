### Title
Provenance attestation omits symlink subjects while archive faithfully embeds symlink content, allowing artifact content to be delivered without a matching attested subject - (File: commands/helpers/artifact_metadata.go)

### Summary
`generateSubjects` in `commands/helpers/artifact_metadata.go` explicitly skips any file whose `fi.Mode().IsRegular()` is false, which includes symlinks collected by `fileArchiver.enumerate`/`c.add` (`os.Lstat`) into the same `files` map that is later passed to the archiver. The actual archiver (`helpers/archives/zip_create.go`'s `createZipEntry`) does archive symlinks as real entries (writing the link target as content via `createZipSymlinkEntry`), so the resulting artifact archive can contain entries that have no corresponding subject in the generated in-toto/SLSA provenance statement.

### Finding Description
The reachable path is: job defines `artifacts:paths` in `.gitlab-ci.yml` → `fileArchiver.processPath`/`add` (`commands/helpers/file_archiver.go:127-138`) calls `os.Lstat` and stores every matched path (including symlinks, since `Lstat` does not follow them) into `c.files map[string]os.FileInfo` → `ArtifactsUploaderCommand.Execute` (`commands/helpers/artifacts_uploader.go:213-243`) calls `c.enumerate()` then, if `GenerateArtifactsMetadata` is set, calls `generateStatementToFile(generateStatementOptions{files: c.files, ...})` → `generateStatementToFile` calls `generateSubjects(opts.files)` (`commands/helpers/artifact_metadata.go:68,191-228`).

In `generateSubjects`, the loop `for file, fi := range files { if !fi.Mode().IsRegular() { continue } ... }` (lines 215-218) silently drops any non-regular file, including symlinks (`fi.Mode()&os.ModeSymlink != 0`), from the subject list — no warning, no error, no count reconciliation against the actual archived set.

Separately, the actual archive creation (invoked later through `c.Archive`/the registered archiver, e.g. `fastzip` or the fallback `helpers/archives/zip_create.go:CreateZipArchive`) does **not** apply the same filter: `createZipEntry` (lines 52-83) switches on `fi.Mode() & os.ModeType` and for `os.ModeSymlink` calls `createZipSymlinkEntry`, which creates a real zip entry and writes the symlink target string as its content (lines 17-30). Thus a symlink present in `c.files` is written into the artifact archive as a legitimate entry, but it is never represented in the generated provenance `Subject` list because `generateSubjects` filtered it out.

The existing "checks" that might be expected to prevent this — path-in-project validation (`findRelativePathInProject`), exclude-pattern matching, and the `IsRegular()` filter itself — do not address this gap: the `IsRegular()` filter was seemingly intended to skip directories (which have no meaningful content digest) but it also (perhaps unintentionally) sweeps up symlinks, which do have meaningful archived content and should be represented, and there is no fallback path that resolves the symlink target and computes/attests its content digest, nor a diff between the subject count and the archived file count to catch such mismatches.

### Impact Explanation
An attacker (a normal pipeline author) can commit a symlink to a build path within their own job and cause it to be listed under `artifacts:paths`. When `--generate-artifacts-metadata` is enabled, the generated SLSA/in-toto provenance statement omits the symlink's content from `Subject`, yet the actual artifact archive downloaded/verified by any downstream consumer (e.g., a deploy job, a security scanner, or a consumer that trusts the provenance attestation to represent "everything in the archive") will contain that symlink entry with attacker-controlled target content, unaccounted for in the attestation. This breaks the invariant "every archived artifact file must be faithfully represented as a subject; no silent omission," undermining any integrity check that relies on the SLSA provenance subject list matching the delivered artifact exactly (attestation/archive mismatch, i.e., a form of artifact/provenance integrity-check bypass).

### Likelihood Explanation
This is straightforwardly reproducible by any unprivileged pipeline author: add a symlink file to the repo/build directory, reference it (directly or via glob) in `artifacts:paths`, and enable artifact metadata generation via runner config (`GenerateArtifactsMetadata`/`generate-artifacts-metadata`) — a standard, documented, non-privileged feature. No special executor privileges or admin action are required; only the existence of a symlink in the workspace and the metadata-generation feature being turned on by the project/runner configuration.

### Recommendation
In `generateSubjects` (`commands/helpers/artifact_metadata.go`), do not unconditionally skip non-regular files. Distinguish directories (which should be skipped, since they have no content) from symlinks (which are archived with real content by `createZipSymlinkEntry`/tar equivalents): either (a) resolve the symlink and hash its target content/hash the link string exactly as `createZipSymlinkEntry` writes it, and add a corresponding `ResourceDescriptor`, or (b) if symlinks intentionally must not be archived, filter them out consistently in `fileArchiver`/`createZipEntry` too so the archive and the provenance statement stay in sync. Additionally, add a post-generation invariant check that asserts `len(subjects)` plus any explicitly-skipped-and-logged category equals the number of entries actually written to the archive, failing (or at least loudly warning) the job on mismatch.

### Proof of Concept
```go
// commands/helpers/artifact_metadata_test.go (extension)
func TestGenerateSubjects_SymlinkOmittedButArchived(t *testing.T) {
    tmpDir := t.TempDir()
    target := filepath.Join(tmpDir, "real.txt")
    require.NoError(t, os.WriteFile(target, []byte("secret-payload"), 0644))

    link := filepath.Join(tmpDir, "link")
    require.NoError(t, os.Symlink(target, link))

    fi, err := os.Lstat(link)
    require.NoError(t, err)
    require.True(t, fi.Mode()&os.ModeSymlink != 0)

    g := &artifactStatementGenerator{SLSAProvenanceVersion: "v1"}
    subjects, err := g.generateSubjects(map[string]os.FileInfo{link: fi})
    require.NoError(t, err)

    // BUG: subjects is empty even though the symlink will be archived as a real entry.
    assert.Empty(t, subjects, "symlink silently dropped from provenance subjects")

    // Now show the archiver DOES include it:
    var buf bytes.Buffer
    err = archives.CreateZipArchive(&buf, []string{link})
    require.NoError(t, err)

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    require.Len(t, zr.File, 1, "archive contains the symlink entry")
    // Assertion proving the mismatch: 1 archived entry vs 0 attested subjects.
}
```
Expected assertions: `len(subjects) == 0` while `len(zr.File) == 1`, proving the archived artifact contains an entry with no corresponding attested subject.
