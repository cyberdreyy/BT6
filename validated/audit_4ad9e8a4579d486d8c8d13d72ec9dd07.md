### Title
Legacy zip extractor ignores extraction directory and performs no path traversal validation, enabling zip-slip - ([File: commands/helpers/archive/ziplegacy/zip_legacy_extractor.go], [File: helpers/archives/zip_extract.go])

### Summary
The legacy zip extractor (`ziplegacy.extractor.Extract`) discards the `dir` parameter it is given by `archive.NewExtractor` and delegates directly to `archives.ExtractZipArchive`, which writes each zip entry to `file.Name` with no validation against `../` traversal, absolute paths, or symlink targets escaping the extraction root. This is in stark contrast to the `tarzstd` extractor, which explicitly resolves and checks that each entry path stays within `e.dir` before writing.

### Finding Description
`CacheExtractorCommand.Execute` and `ArtifactsDownloaderCommand.Execute` both call `archive.NewExtractor(format, f, size, wd)` and then `extractor.Extract(ctx)` [1](#0-0) , expecting the extraction to be confined to `wd`.

For the `Zip`/`ZipZstd` formats, when the `ziplegacy` package's extractor is selected, `NewExtractor` stores `dir` but `Extract` never uses it: [2](#0-1) 

It instead calls `archives.ExtractZipArchive(zr)`, which iterates zip entries and writes each using the raw `file.Name` from the archive, with no join against a base directory, no path-cleaning, and no rejection of `..` segments or absolute paths: [3](#0-2) 

This contrasts with `tarzstd`'s extractor, which explicitly computes `filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects any resulting path that doesn't have `e.dir` as prefix: [4](#0-3) 

`extractZipSymlinkEntry` is similarly unguarded — it creates a symlink at `file.Name` pointing to arbitrary attacker-controlled link target data read from the archive, again with no confinement check: [5](#0-4) 

Because confinement in the legacy path relies purely on the process's current working directory happening to equal `wd` (as acknowledged in a test comment: "legacy archiver require being in the correct working dir" [6](#0-5) ), an entry named e.g. `../../../etc/cron.d/x` or an absolute path, or a symlink entry pointing outside `wd` followed by a file write through it, escapes the intended extraction root entirely. `errorIfGitDirectory` only warns about `.git` directories and does not perform any path confinement [7](#0-6) .

An attacker who can poison a cache archive (cross-project cache key collision, malicious `fallback_keys`, or a project artifact) supplies a crafted zip whose entries use traversal names or symlinks, which is then extracted by `CacheExtractorCommand.Execute` / `ArtifactsDownloaderCommand.Execute` via this unguarded code path.

### Impact Explanation
Arbitrary file write outside the job's build/cache root is possible when the vulnerable legacy zip extraction path is used, matching the scoped zip-slip impact (writing files to attacker-chosen paths reachable via `../` traversal or symlink redirection from a poisoned cache/artifact zip archive).

### Likelihood Explanation
Exploitability depends entirely on whether the `ziplegacy` implementation (rather than the path-safe `fastzip`/`tarzstd` implementations) is the one actually registered/selected for `Zip`/`ZipZstd` formats at runtime — this is controlled through `archive.Register` calls, and GitLab Runner has historically gated zip archiver/extractor selection behind a feature flag (e.g. `FF_USE_FASTZIP`), which can be set as a job-level CI/CD variable by a pipeline author. I was not able to fully confirm, within available tool budget, the current default value of that flag or the exact final registration order in `commands/helpers/archiver.go` (only partial matches were retrieved), so whether this code path is reachable by default or only when a pipeline author explicitly disables the fast/safe zip implementation is uncertain and should be verified directly in that file.

### Recommendation
Add the same path-confinement logic used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`/`ExtractZipArchive`: resolve each `file.Name` against the target extraction directory with `filepath.Join`/`filepath.Abs`, reject any entry whose resolved path escapes that directory, and reject symlink entries whose link target would resolve outside the directory. Additionally, make `ziplegacy.extractor.Extract` actually pass and use `e.dir` instead of relying on the process's working directory.

### Proof of Concept
Go unit test in `helpers/archives` (or `commands/helpers/archive/ziplegacy`):
1. Build an in-memory zip (`archive/zip`) containing an entry named `../evil.txt` and a symlink entry named `link` pointing to `/tmp/outside`.
2. Call `ExtractZipArchive` (or `ziplegacy.NewExtractor(...).Extract(ctx)`) with `dir` set to a fresh `t.TempDir()`.
3. Assert that `../evil.txt` is NOT created outside `dir` (e.g., assert `os.Stat(filepath.Join(filepath.Dir(dir), "evil.txt"))` returns `os.ErrNotExist`), and that extraction either fails with an explicit "cannot be extracted outside" error (matching `tarzstd`'s behavior) or the entry is skipped — currently the test would show the file being written outside `dir`, proving the bug.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
