## Analog Found: Fee-rate changes are applied retroactively over unaccrued time in Aera v3 fee calculators

### Title
Fee rate changes in `setVaultFees` are applied retroactively over the entire un-checkpointed accrual period instead of being split at the rate-change timestamp - ([File: v3/src/core/BaseFeeCalculator.sol], [File: v3/src/core/PriceAndFeeCalculatorV2.sol], [File: v3/src/core/DelayedFeeCalculator.sol])

### Summary
`BaseFeeCalculator.setVaultFees` overwrites `vaultAccruals.fees` (TVL/performance rates) in place without first checkpointing (accruing) fees at the old rate. The next accrual pass — `PriceAndFeeCalculatorV2._accrueFees` or `DelayedFeeCalculator._accrueFees` — then multiplies the *entire* elapsed time since the last checkpoint (`anchorTimestamp`/`lastFeeAccrual`) by whatever fee rate is stored *at accrual time*, i.e. the new rate, rather than splitting the interval at the moment the rate changed. This is structurally identical to the disclosed LoopFi `ChefIncentivesController.setScheduledRewardsPerSecond` bug: a rate change is not checkpointed before the new rate is written, so the whole elapsed duration is later billed/rewarded at the wrong (post-change) rate.

### Finding Description
`setVaultFees` directly mutates the stored `Fee` struct with no accrual step: [1](#0-0) 

When the next fee-triggering event occurs (an accountant calling `setAnchorPrice`, which calls `_accrueFees`, or `submitSnapshot`/`accrueFees` in the delayed variant), the fee calculation uses the *current* (post-change) rate applied over the *entire* time delta since the last checkpoint: [2](#0-1) 

and equivalently in the delayed path: [3](#0-2) [4](#0-3) 

The correct formula would split the interval: `oldFee * (rateChangeTimestamp - lastCheckpoint) + newFee * (currentTimestamp - rateChangeTimestamp)`, exactly as recommended in the original disclosed report. Instead, `_calculateTvlFee` applies a single rate over the full `timeDelta`/`totalDuration`: [5](#0-4) 

No guard in `setVaultFees`, `_accrueFees`, or `_calculateTvlFee` checkpoints accrued fees before switching the rate, so the broken invariant "fees for a given second are charged at the rate in effect during that second" does not hold across a rate change.

### Impact Explanation
This misallocates TVL/performance fees between the vault fee recipient, the protocol fee recipient, and vault depositors:
- If a fee rate is raised, depositors are retroactively overcharged for a period when the lower rate applied — funds are diverted from vault share value to fee recipients that they should not have received.
- If a fee rate is lowered, the vault/protocol fee recipient loses fees earned during the higher-rate period that had not yet been checkpointed — a freezing/loss of already-earned yield.

Because `accruedFees`/`accruedProtocolFees` are directly transferred out via `claimFees`/`claimProtocolFees`, this is a real, quantifiable misallocation of vault-holder yield, matching a live Medium-severity "incorrect allocation of rewards/fees" impact as accepted in the analogous disclosed finding.

### Likelihood Explanation
No attacker privilege is required beyond normal, expected protocol operation: any vault owner (or an authorized entity per `requiresVaultAuth`) changing fee rates via `setVaultFees` — a routine, documented governance action — combined with the accountant's normal periodic `setAnchorPrice`/`submitSnapshot` calls, triggers the bug automatically. No malicious collusion, oracle manipulation, or MEV is needed; it occurs whenever a fee-rate change happens between two accrual checkpoints, which is an expected and periodic occurrence in vault operation.

### Recommendation
In `setVaultFees` (and `setProtocolFees`), force a fee checkpoint/accrual at the currently-stored rate for every affected vault before writing the new `Fee` struct — i.e., call the vault's `_accrueFees` (or an equivalent checkpoint that updates `lastFeeAccrual`/`anchorTimestamp` and flushes `accruedFees`/`accruedProtocolFees`) prior to overwriting `vaultAccruals.fees`. This ensures each rate is only ever applied to the time interval during which it was actually in effect.

### Proof of Concept
Foundry fork/unit test outline against `PriceAndFeeCalculatorV2`:
1. Deploy `PriceAndFeeCalculatorV2`, register a mock vault (`registerVault`), `setThresholds`, and `setInitialPrice` to establish `anchorTimestamp = t0`.
2. As vault auth, call `setVaultFees(vault, tvl = 100 /*1%*/, performance = 0)`.
3. `vm.warp(t0 + 30 days)`.
4. As vault auth, call `setVaultFees(vault, tvl = 1000 /*10%*/, performance = 0)` — note no accrual occurs; `anchorTimestamp` is still `t0`.
5. `vm.warp(t0 + 60 days)`.
6. As the registered accountant, call `setAnchorPrice(vault, price, uint32(block.timestamp))`, which internally calls `_accrueFees`, computing `timeDelta = 60 days` entirely at the 10% rate.
7. Assert `vaultAccruals.accruedFees` (read via `vaultFeeState`/`previewFees`) equals `tvl(10%) * avgValue * 60 days / SECONDS_PER_YEAR`, and is strictly greater than the correct split value `tvl(1%) * avgValue * 30 days / SECONDS_PER_YEAR + tvl(10%) * avgValue * 30 days / SECONDS_PER_YEAR` — demonstrating depositors were overcharged for the first 30 days at the wrong (higher) rate, confirming the misallocation.     /// @notice Calculates the TVL fee for a given period
    /// @dev Fee is annualized and prorated for the time period
    /// @param averageValue The average value during the period
    /// @param tvlFee The TVL fee rate in basis points
    /// @param timeDelta The duration of the fee period in seconds
    /// @return The earned TVL fee
    function _calculateTvlFee(uint256 averageValue, uint256 tvlFee, uint256 timeDelta)
        internal
        pure
        returns (uint256)
    {
        unchecked {
            // safe because averageValue is uint160, tvlFee is uint16, timeDelta is uint32
            return averageValue * tvlFee * timeDelta / ONE_IN_BPS / SECONDS_PER_YEAR;
        }
    }

    function _accrueFees(address vault, uint256 price, uint256 timestamp) internal {
        VaultPriceStateV2 storage vaultPriceState = _vaultPriceStates[vault];

        uint256 timeDelta;
        unchecked {
            timeDelta = timestamp - vaultPriceState.anchorTimestamp + vaultPriceState.accrualLag;
        }

        // Interactions: get the current total supply
        uint256 currentTotalSupply = IERC20(vault).totalSupply();

```text
    function _accrueFees(
        VaultSnapshot storage vaultSnapshot,
        VaultAccruals storage vaultAccruals,
        uint256 lastFeeAccrualCached
    ) internal returns (uint256 protocolFeesEarned, uint256 vaultFeesEarned) {
        uint256 snapshotTimestamp = vaultSnapshot.timestamp;
        if (lastFeeAccrualCached >= snapshotTimestamp || vaultSnapshot.finalizedAt > block.timestamp) {
            // nothing to accrue
            return (0, 0);
        }

        // pending snapshot has become active, accrue fees
        (uint256 vaultPerformanceFeeEarned, uint256 protocolPerformanceFeeEarned) = _calculatePerformanceFees(
            vaultAccruals.fees.performance, vaultSnapshot.highestProfit, vaultSnapshot.lastHighestProfit
        );

        (uint256 vaultTvlFeeEarned, uint256 protocolTvlFeeEarned) = _calculateTvlFees(
            vaultAccruals.fees.tvl, vaultSnapshot.averageValue, snapshotTimestamp, lastFeeAccrualCached
        );

        // Effects: update the vault's state
        vaultSnapshot.lastHighestProfit = vaultSnapshot.highestProfit;
        vaultSnapshot.lastFeeAccrual = uint32(snapshotTimestamp);
        vaultAccruals.accruedFees += (vaultPerformanceFeeEarned + vaultTvlFeeEarned).toUint112();
        vaultAccruals.accruedProtocolFees += (protocolPerformanceFeeEarned + protocolTvlFeeEarned).toUint112();

        // Effects: delete the pending snapshot
        vaultSnapshot.averageValue = 0;
        vaultSnapshot.highestProfit = 0;
        vaultSnapshot.timestamp = 0;
        vaultSnapshot.finalizedAt = 0;

        protocolFeesEarned = protocolPerformanceFeeEarned + protocolTvlFeeEarned;
        vaultFeesEarned = vaultPerformanceFeeEarned + vaultTvlFeeEarned;
    }
```

    function _calculateTvlFees(
        uint256 vaultTvlFeeRate,
        uint256 averageValue,
        uint256 snapshotTimestamp,
        uint256 lastFeeAccrual
    ) internal view returns (uint256, uint256) {
        uint256 totalDuration;
        unchecked {
            totalDuration = snapshotTimestamp - lastFeeAccrual;
        }

        return (
            _calculateTvlFee(averageValue, vaultTvlFeeRate, totalDuration),
            _calculateTvlFee(averageValue, protocolFees.tvl, totalDuration)
        );
    }
