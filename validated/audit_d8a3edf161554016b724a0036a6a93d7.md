### Title
Unauthenticated APR configuration before `idleCDO` initialization allows malicious credit terms - (`contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`IdleCreditVault.setAprs()` and `setApr()` are callable by any address while `idleCDO == address(0)`, because the authorization check is explicitly skipped during setup. [1](#0-0)  An unprivileged attacker can therefore front-run the CDO linkage and set both `unscaledApr` and `lastApr`, subject only to `maxApr`. [2](#0-1) 

### Finding Description
`setAprs()` writes attacker-controlled `unscaledApr` before delegating authorization to `setApr()`. [3](#0-2)  When `idleCDO` has not yet been assigned, `setApr()` does not require the caller to be the owner, manager, or CDO. [4](#0-3)  The attacker can persist a malicious APR by supplying a value below `maxApr`. [5](#0-4) 

The privileged owner later associates the strategy with the credit vault through `setWhitelistedCDO()`. [6](#0-5)  `IdleCDOEpochVariant.initialize()` then reads the strategy APR and scales it for epoch accounting. [7](#0-6)  After that point, normal APR updates are restricted to the CDO or manager. [8](#0-7) 

### Impact Explanation
An attacker who participates as an eligible lender can set an excessive borrower APR during deployment and receive yield caused by terms never approved by the owner or manager. [1](#0-0)  Conversely, setting the APR to an artificially low value can permanently suppress the yield owed for the configured epoch until privileged intervention corrects it. [1](#0-0)  The affected amount is the difference between expected borrower interest and interest produced by the attacker-selected APR; the upper bound is controlled by `maxApr`, whose default is `20e18`. [9](#0-8) 

### Likelihood Explanation
The exploit requires a deployment or upgrade window in which the strategy is initialized but `idleCDO` remains unset. [4](#0-3)  That window is explicitly supported by the code comment and therefore does not require privileged misconduct. [10](#0-9)  Any EOA can execute the state change atomically in that window, after which the CDO linkage preserves the poisoned APR. [6](#0-5) 

### Recommendation
Remove the `idleCDO == address(0)` authorization bypass and require `msg.sender == owner() || msg.sender == manager` until the CDO is configured. [4](#0-3)  Apply the same authorization check to `setAprs()` and `setAprsWithBuffer()` before writing `unscaledApr`, rather than relying on a nested call for access control. [11](#0-10) 

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVault} from "../contracts/strategies/idle/IdleCreditVault.sol";

contract UnauthorizedAprSetupTest is Test {
    IdleCreditVault internal vault;
    address internal attacker = makeAddr("attacker");
    address internal cdo = makeAddr("cdo");

    function testAnyoneCanSetAprBeforeIdleCDO() external {
        // Deploy/initialize the strategy through the production fixture so that
        // idleCDO remains unset during the setup window.
        vault = _deployInitializedCreditVault();

        assertEq(vault.idleCDO(), address(0));

        uint256 maliciousApr = vault.maxApr();

        vm.prank(attacker);
        vault.setAprs(maliciousApr, maliciousApr);

        assertEq(vault.unscaledApr(), maliciousApr);
        assertEq(vault.getApr(), maliciousApr);

        // Once ownership/configuration links the CDO, the attacker-supplied
        // value remains the strategy APR while future changes are restricted.
        vm.prank(vault.owner());
        vault.setWhitelistedCDO(cdo);

        assertEq(vault.idleCDO(), cdo);
        assertEq(vault.getApr(), maliciousApr);

        vm.prank(attacker);
        vm.expectRevert(NotAllowed.selector);
        vault.setApr(0);
    }

    function _deployInitializedCreditVault() internal returns (IdleCreditVault) {
        // Use the repository's deployment fixture / proxy initialization path.
        // The prerequisite state is simply an initialized vault whose
        // `idleCDO` storage variable is still address(0).
    }
}
```

```text
    unscaledApr = _unscaledApr;
    // here we also check that msg.sender is allowed
    setApr(_apr);
  }

  /// @notice set both the unscaled APR and APR scaled by epoch plus buffer duration.
  /// @dev only CDO and manager can set the APR through `setApr`.
  /// @param _unscaledApr unscaled APR
  /// @param _duration epoch duration
  /// @param _buffer buffer duration
  function setAprsWithBuffer(uint256 _unscaledApr, uint256 _duration, uint256 _buffer) external {
    unscaledApr = _unscaledApr;
    setApr(_duration == 0 ? _unscaledApr : _unscaledApr * (_duration + _buffer) / _duration);
  }

  /// @notice set the fixed apr
  /// @dev only cdo and manager can set the apr. If manager manually set apr from 
  /// here it will not be scaled to include the buffer period
  function setApr(uint256 _apr) public {
    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
```
