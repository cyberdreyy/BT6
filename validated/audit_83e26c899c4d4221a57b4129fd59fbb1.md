### Title
Cross-user response confusion via requestID reuse in httpTriggerHandler due to missing workflow/session binding in `h.callbacks` - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`h.callbacks` is keyed only by the user-supplied JSON-RPC `req.ID`, with no binding to the workflowID or requesting session stored per-node-response validation beyond shard membership. Once a `requestID` is cleaned up (deleted from `h.callbacks` after quorum is reached), it becomes immediately reusable by any caller for a different workflow, and a late-arriving node response for the *old* execution that still carries the reused `requestID` will be routed into the new caller's `savedCallback` if the responding node's shard happens to be one of the new workflow's assigned shards.

### Finding Description
`setupCallback` guards only against an ID being *currently* in-flight, not against reuse of a previously-used ID: [1](#0-0) 

`cleanupCallback` deletes the map entry and closes `doneCh` as soon as the first shard reaches quorum, but this only signals `sendToShard` retry loops to stop on their *next* select iteration — it cannot cancel a network round trip already in flight (`shard.connMgr.SendToNode` call already issued, awaiting the node's async reply): [2](#0-1) [3](#0-2) 

`HandleNodeTriggerResponse` then looks up the callback purely by `resp.ID` and validates only that the responding node's shard is one the *current occupant* of that slot is assigned to — there is no check that the response actually corresponds to the workflow/execution the current `savedCallback` was created for: [4](#0-3) 

`IdenticalNodeResponseAggregator.CollectAndAggregate` aggregates purely by response-content digest and threshold count, with no awareness of workflowID or execution identity either: [5](#0-4) 

So the exploit sequence is: (1) user1 sends `workflows.execute` with `id=X` for workflowA; (2) quorum is reached, `saved.SendResponse` fires for user1, `cleanupCallback(X)` deletes the map entry, but one node's reply is still in flight over the network (already dispatched by `sendToShard`'s goroutine, not cancellable); (3) attacker/user2 immediately sends `id=X` for workflowB (sharing at least one shard/donID with workflowA), passing `setupCallback`'s "not found" check trivially since the entry was deleted; (4) the stale node reply for workflowA's execution arrives keyed by `resp.ID = X`, matches `h.callbacks[X]` (now user2's entry), passes the shard-membership check (since workflowB is assigned to that shard too), and is aggregated/delivered via `saved.SendResponse` into user2's callback — delivering user1's workflow-execution result data to user2.

### Impact Explanation
This is a cross-user response confusion: an unrelated caller can receive workflow execution result data belonging to another user's job run through pure requestID collision, with no authorization or workflow-identity check tying the delivered node response back to the workflow/owner that registered the callback. Depending on what the HTTP trigger response contains (workflow output payloads), this can leak sensitive execution data across tenants/workflow owners.

### Likelihood Explanation
Exploitation requires: the attacker to know/guess a `requestID` that a different, unrelated user is actively using (or has very recently finished using) for a request whose workflow shares a shard with the attacker's target workflow; and a race window bounded by node round-trip latency between `cleanupCallback` and the stale node reply's arrival. Both `req.ID` values and the timing of a victim's request are not directly observable to an unprivileged remote attacker in the typical case, making this a low-to-moderate likelihood, timing-dependent race rather than a trivially repeatable exploit. However, no additional privilege beyond sending a normal gateway `workflows.execute` request with a chosen `id` is required, and the underlying code has no structural defense (workflow/session binding) against it once the ID is known.

### Recommendation
Bind each `savedCallback` to the workflowID (and/or a unique per-registration nonce/session token) it was created for, and validate that a node response's originating workflow/execution matches the `savedCallback`'s recorded workflowID before aggregating or delivering it in `HandleNodeTriggerResponse`. Alternatively, derive the internal routing key from a value that cannot collide across distinct registrations (e.g., include a monotonically-increasing generation counter or UUID alongside `req.ID` in the map key), so a stale reply for a prior registration can never match a newer one even if the raw `requestID` is reused.

### Proof of Concept
Go integration test plan (`http_trigger_handler_test.go`):
1. Set up a multi-workflow scenario where workflowA and workflowB are both assigned to the same shard (reuse `createMultiShardTriggerHandler`/`registerWorkflowOnShards` helpers).
2. Issue `HandleUserTriggerRequest` for workflowA with `id = "X"`, and use a mock `connMgr` (`mockDon`) whose `SendToNode` for one node blocks/delays until a signal is given (simulating an in-flight retry not yet observed by `doneCh`).
3. Drive quorum for workflowA with the other nodes so `cleanupCallback("X")` runs and `h.callbacks["X"]` is deleted while the delayed node's send is still pending.
4. Immediately call `HandleUserTriggerRequest` again with `id = "X"` for workflowB — assert it succeeds (`setupCallback` allows reuse).
5. Release the delayed node reply carrying workflowA's stale result with `resp.ID = "X"`, delivered via `HandleNodeTriggerResponse`.
6. Assert (currently failing) that workflowB's callback should NOT receive workflowA's payload — i.e., `HandleNodeTriggerResponse` should reject the response because the recorded workflowID on `h.callbacks["X"]` (workflowB) doesn't match the workflow the stale node reply belongs to, after adding a `workflowID`/execution-binding field to `savedCallback` and a corresponding check in `HandleNodeTriggerResponse`.

// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}

	// Route the response into the aggregator for the shard that owns this node.
	shard, ok := h.nodeAddrToShard[nodeAddr]
	if !ok {
		return fmt.Errorf("received trigger response from unknown node %s (no owning shard)", nodeAddr)
	}
	agg, ok := saved.responseAggregators[shard.donID]
	if !ok {
		// The node belongs to a shard this workflow isn't assigned to (or the
		// callback was captured before the workflow was assigned there).
		return fmt.Errorf("node %s (shard %s) is not assigned to workflow for request ID %s", nodeAddr, shard.donID, resp.ID)
	}

func (agg *IdenticalNodeResponseAggregator) CollectAndAggregate(
	resp *jsonrpc.Response[json.RawMessage],
	nodeAddress string) (*jsonrpc.Response[json.RawMessage], error) {
	if resp == nil {
		return nil, errors.New("response cannot be nil")
	}
	if nodeAddress == "" {
		return nil, errors.New("node address cannot be empty")
	}

	key, err := resp.Digest()
	if err != nil {
		return nil, fmt.Errorf("error generating digest for response: %w", err)
	}

	// Check if the node already submitted a different response
	if oldKey, exists := agg.nodeToResponse[nodeAddress]; exists && oldKey != key {
		if nodes, ok := agg.responses[oldKey]; ok {
			nodes.Remove(nodeAddress)
			// Clean up empty response groups
			if len(nodes) == 0 {
				delete(agg.responses, oldKey)
			}
		}
	}

	if _, ok := agg.responses[key]; !ok {
		agg.responses[key] = make(StringSet)
	}
	agg.responses[key].Add(nodeAddress)
	agg.nodeToResponse[nodeAddress] = key

	if len(agg.responses[key]) >= agg.threshold {
		return resp, nil
	}

	return nil, nil
}
