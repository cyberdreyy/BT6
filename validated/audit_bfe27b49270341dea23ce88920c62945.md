### Title
Unsound `unsafe` type-punning between `alloy_eips::eip4844::Blob` and `c_kzg::Blob` via raw pointer transmutation - (File: `crates/consensus/providers/src/blobs.rs`)

### Summary
`OnlineBlobProvider::blobs_with_proofs` reinterprets a `Box<alloy_eips::eip4844::Blob>` as a `Box<c_kzg::Blob>` (and back) using `Box::from_raw(Box::into_raw(..) as *mut OtherType)`, relying only on a comment ("all types have the same size and alignment") rather than any compiler-enforced layout guarantee.

### Finding Description
`blobs_with_proofs` performs two raw-pointer type-punning casts between independently-defined structs: [1](#0-0) 

Neither `alloy_eips::eip4844::Blob` nor `c_kzg::Blob` is declared `#[repr(C)]`/`#[repr(transparent)]` in this codebase's usage context — the cast assumes their internal layouts (a 131072-byte array wrapper) are identical, which the Rust language does not guarantee for two unrelated `#[repr(Rust)]` types even if they currently happen to contain a single fixed-size byte array. This is structurally the same bug class as GHSA-hvqc-pc78-x9wh (raw-cpuid): constructing/reinterpreting typed memory from a type whose layout is not `repr(C)`-guaranteed is undefined behavior, regardless of whether the current compiler happens to lay both types out identically. A future compiler version, a different codegen backend, or LTO/cross-crate inlining decisions could change field/array padding or reorder internal representation, causing the `Box<c_kzg::Blob>` (and the round-tripped `Box<Blob>`) to alias memory of the wrong size/alignment, corrupting the heap or invoking `c_kzg`'s FFI-backed KZG routines (`blob_to_kzg_commitment`, `compute_blob_kzg_proof`) on a misinterpreted allocation.

This code path is exercised by `OnlineBlobProvider::fetch_blobs_with_proofs`, which is invoked by the fault-proof host program: [2](#0-1) 

and consumed from `crates/proof/host/src/handler.rs`, i.e., it runs while assembling L1 blob preimages/KZG proofs for the fault-dispute-game program. Every blob referenced by an L1 batcher transaction (attacker-influenceable content, since anyone can post arbitrary EIP-4844 blob data to L1) is fed through this transmute during preimage/proof preparation.

### Impact Explanation
If the two `Blob` types' in-memory layout ever diverges (compiler version bump, target architecture change, or crate upgrade), this becomes exploitable UB: the KZG library would operate on a corrupted/misaligned buffer, and the round-tripped `Box<Blob>` returned to callers could contain incorrect data or corrupt heap metadata. In the context of the fault-proof host program this can lead to a node halt (crash while preparing dispute-game preimages) or, in the worst case, a wrong KZG proof/commitment being derived and fed into the fault-proof program, undermining a dispute-game verification path. Because Rust gives no diagnostic for this misuse (it silently compiles), the risk is latent and could be triggered by nothing more than a toolchain or dependency update, not by any single malicious action — matching the "always UB regardless of trigger" characterization of the original advisory.

### Likelihood Explanation
Today, both types most likely happen to share a compatible bit-for-bit layout (both are effectively `[u8; 131072]` wrappers), so under current toolchains this may not manifest as an observable fault. However, because the invariant is not enforced by `#[repr(C)]`/static assertions, likelihood of triggering depends entirely on compiler/toolchain internals outside the project's control — the same characterization that earned the original raw-cpuid issue a High severity rating despite requiring no attacker action.

### Recommendation
- Add `#[repr(C)]` (or a `static_assertions::assert_eq_size!`/`assert_eq_align!` check) to statically pin the layout compatibility assumption, or
- Avoid the transmute entirely and construct the `c_kzg::Blob` from the byte slice via a safe, checked conversion (e.g. `c_kzg::Blob::from_bytes(&blob.0)` or equivalent constructor), accepting the copy cost, since this is not a hot path relative to blob fetching over the network.
- Add a compile-time size/alignment assertion (`const _: () = assert!(size_of::<Blob>() == size_of::<c_kzg::Blob>());`) as a minimum safeguard if the transmute must be kept for performance.

### Proof of Concept
Not applicable as a triggerable exploit today (the bug is a language/layout soundness violation, not a data-dependent bug); the reachable path can be demonstrated by tracing:
`OnlineBlobProvider::fetch_blobs_with_proofs` (`crates/consensus/providers/src/blobs.rs:162-179`) → `blobs_with_proofs` (`crates/consensus/providers/src/blobs.rs:122-154`) → invoked from `crates/proof/host/src/handler.rs` while preparing L1 blob preimages for the fault-proof program, using blob data originating from L1 batcher transactions.

    /// Converts a vector of boxed blobs to a vector of blobs with their KZG commitments and proofs.
    ///
    /// Note: for performance reasons, we need to transmute the blobs to the `c_kzg::Blob` type to
    /// avoid the overhead of moving the blobs around or reallocating the memory.
    fn blobs_with_proofs(
        blobs: Vec<BoxedBlob>,
    ) -> Result<Vec<BlobWithCommitmentAndProof>, c_kzg::Error> {
        blobs
            .into_iter()
            .map(|blob| {
                let kzg_settings = EnvKzgSettings::Default;

                // SAFETY: all types have the same size and alignment
                let kzg_blob =
                    unsafe { Box::from_raw(Box::<Blob>::into_raw(blob.blob) as *mut c_kzg::Blob) };

                let commitment = kzg_settings
                    .get()
                    .blob_to_kzg_commitment(&kzg_blob)
                    .map(|blob| blob.to_bytes())?;
                let proof = kzg_settings
                    .get()
                    .compute_blob_kzg_proof(&kzg_blob, &commitment)
                    .map(|proof| proof.to_bytes())?;

                // SAFETY: all types have the same size and alignment
                let alloy_blob =
                    unsafe { Box::from_raw(Box::<c_kzg::Blob>::into_raw(kzg_blob) as *mut Blob) };

                Ok(BlobWithCommitmentAndProof {
                    blob: alloy_blob,
                    kzg_commitment: FixedBytes::from(*commitment),
                    kzg_proof: FixedBytes::from(*proof),
                })
            })
            .collect()
    }

    pub async fn fetch_blobs_with_proofs(
        &self,
        block_ref: &BlockInfo,
        blob_hashes: &[B256],
    ) -> Result<Vec<BlobWithCommitmentAndProof>, BlobProviderError> {
        if blob_hashes.is_empty() {
            return Ok(Default::default());
        }

        // Calculate the slot for the given timestamp.
        let slot = Self::slot(self.genesis_time, self.slot_interval, block_ref.timestamp)?;

        // Fetch blobs for the slot.
        let blobs = self.fetch_filtered_blobs(slot, blob_hashes).await?;

        Self::blobs_with_proofs(blobs)
            .map_err(|e| BlobProviderError::Backend(format!("KZG commitment error: {e}")))
    }
