This feature is a cluster-governed activation (`syscall_parameter_address_restrictions::ID`), not something an unprivileged attacker can toggle. It has already shipped (SIMD-0459) and is treated as an already-existing/legacy code path guarded by feature-gate `is_active` checks in `CallerAccount::from_account_info` / `from_sol_account_info`.### Answer

No vulnerability found for this question.

**Reasoning:** The pointer-aliasing protections in `CallerAccount::from_account_info`/`from_sol_account_info` (the `check_account_info_pointer` calls at [1](#0-0)  and [2](#0-1) ) are gated by `invoke_context.get_feature_set().syscall_parameter_address_restrictions`, which is a cluster-wide, validator-governed feature (SIMD-0459) declared at [3](#0-2)  and activated via stake-weighted governance/genesis (`activate_all_features`/`activate_feature` at [4](#0-3) ), not by an individual unprivileged attacker. An attacker deploying a program and crafting `AccountInfo`/`SolAccountInfo` structs has no way to "disable" this feature gate on a live, default-configured cluster where the feature is already activated — this is exactly the "non-default configuration" / "requires a privileged or node-level actor to change consensus-critical config" scenario the rules exclude, since only supermajority-stake governance (or a custom/non-default genesis) can flip this feature off. The scoped precondition in the question ("when syscall_parameter_address_restrictions is disabled by feature gate ordering") is not attacker-reachable under the stated threat model of an unprivileged actor on a standard/default-configured Agave cluster.

fn do_activate_all_features<const IS_ALPENGLOW: bool>(genesis_config: &mut GenesisConfig) {
    // Activate all features at genesis in development mode
    for feature_id in FeatureSet::default().inactive() {
        if IS_ALPENGLOW || *feature_id != agave_feature_set::alpenglow::id() {
            activate_feature(genesis_config, *feature_id);
        }
    }
}

pub fn deactivate_features(
    genesis_config: &mut GenesisConfig,
    features_to_deactivate: &Vec<Pubkey>,
) {
    // Remove all features in `features_to_skip` from genesis
    for deactivate_feature_pk in features_to_deactivate {
        if FEATURE_NAMES.contains_key(deactivate_feature_pk) {
            genesis_config.accounts.remove(deactivate_feature_pk);
        } else {
            warn!(
                "Feature {deactivate_feature_pk:?} set for deactivation is not a known Feature \
                 public key"
            );
        }
    }
}

pub fn activate_feature(genesis_config: &mut GenesisConfig, feature_id: Pubkey) {
    genesis_config.accounts.insert(
        feature_id,
        Account::from(feature::create_account(
            &Feature {
                activated_at: Some(0),
            },
            std::cmp::max(genesis_config.rent.minimum_balance(Feature::size_of()), 1),
        )),
    );
}
