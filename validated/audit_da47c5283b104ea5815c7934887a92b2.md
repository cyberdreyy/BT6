### Title
Unauthenticated wrapper gRPC endpoint allows attacker-controlled SSRF via `InitGracefulShutdownRequest.ShutdownCallback` - (File: `helpers/runner_wrapper/api/shutdown_callback.go`)

### Summary
The `gitlab-runner wrapper` command exposes a gRPC server (`server.Server.InitGracefulShutdown`) that accepts a `ShutdownCallback{Url, Method, Headers}` from any caller able to reach `GRPCListen`, with no authentication and no destination validation. When the wrapped process exits, `Wrapper.sendShutdownCallback` invokes `ShutdownCallback.Run`, which performs `http.DefaultClient.Do` against the caller-supplied URL/method/headers verbatim.

### Finding Description
`Server.InitGracefulShutdown` (`helpers/runner_wrapper/api/server/server.go:66-93`) builds a `ShutdownCallbackDef` directly from the incoming protobuf fields (`req.GetShutdownCallback().GetUrl()/.GetMethod()/.GetHeaders()`) with no validation, and passes it to `wrapper.InitiateGracefulShutdown`. `Wrapper.InitiateGracefulShutdown` (`helpers/runner_wrapper/wrapper.go:209-237`) stores it as `w.shutdownCallback` whenever `URL() != ""` — no scheme allowlist, no host/IP checks. On wrapped-process exit, `handleWrappedProcessShutdown` → `sendShutdownCallback` → `ShutdownCallback.Run` (`helpers/runner_wrapper/api/shutdown_callback.go:86-116`) builds an `http.NewRequestWithContext` with the attacker-chosen method/URL, adds attacker-chosen headers, and executes it via `http.DefaultClient.Do` with zero destination filtering (no block on link-local/metadata ranges such as `169.254.169.254`, no scheme restriction beyond what `net/http` itself accepts).

The gRPC server itself is created with no interceptors/auth (`server.New`, `helpers/runner_wrapper/api/server/server.go:30-36`) and the client dials with `insecure.NewCredentials()` (`helpers/runner_wrapper/api/client/client.go:37-38`), and the default listen address is `tcp://localhost:7777` (`commands/wrapper.go:23`), configurable to any interface via `--grpc-listen`. There is no allowlist/validation logic anywhere in this path that would stop a caller from targeting an internal/metadata address.

### Impact Explanation
If an unprivileged actor can reach the wrapper's gRPC listener (a precondition inherited from the prior reachability question, not established anew here), they can force the trusted host process running `gitlab-runner wrapper` to issue an arbitrary outbound HTTP request — including to cloud metadata endpoints (e.g. `169.254.169.254`) or other internal-only services — with attacker-chosen method and headers. Because the request originates from the trusted runner host (not from an isolated job sandbox), this is a genuine SSRF primitive that could be used to steal instance credentials or probe internal infrastructure the runner host can reach.

### Likelihood Explanation
The vulnerability requires network reachability to the wrapper's gRPC port, which is the precondition explicitly deferred to "the prior question." Within `helpers/runner_wrapper`'s own code, once that reachability exists, exploitation is trivial and fully reliable: a single `InitGracefulShutdown` gRPC call with an arbitrary `ShutdownCallback` is sufficient, and the callback fires deterministically as soon as the wrapped process exits (which the same caller can also trigger, since `InitGracefulShutdown` itself signals the process). There is no rate limiting, allowlist, or auth check anywhere in this path.

### Recommendation
- Require authentication/authorization on the wrapper gRPC server (e.g., mTLS or a shared token) rather than relying solely on network-layer isolation.
- Validate `ShutdownCallback.URL` against an explicit allowlist of schemes/hosts (or disallow the feature entirely for untrusted callers), and reject/rewrite requests targeting link-local, loopback, and cloud metadata address ranges (e.g., `169.254.0.0/16`, `fd00:ec2::254`, etc.) before calling `http.DefaultClient.Do`.
- Constrain allowed `Method` values and sanitize/limit `Headers` (avoid arbitrary header injection, e.g. `Host`, `Authorization` overrides) in `defaultShutdownCallback.Run`.

### Proof of Concept
Go unit test extending `helpers/runner_wrapper/wrapper_test.go` / `shutdown_callback_test.go`:
```go
func TestShutdownCallback_Run_SSRFToMetadata(t *testing.T) {
    // Arrange: stand up an httptest server simulating a "metadata" endpoint
    var gotMethod string
    var gotHeader string
    ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        gotMethod = r.Method
        gotHeader = r.Header.Get("X-Attacker")
        w.WriteHeader(200)
    }))
    defer ts.Close()

    def := api.NewShutdownCallbackDef(ts.URL, "PUT", map[string]string{"X-Attacker": "1"})
    cb := api.NewShutdownCallback(logrus.New(), def)

    // Act
    cb.Run(context.Background())

    // Assert: the host process executed the attacker-chosen method/headers with
    // no validation — proving the missing allowlist/SSRF guard.
    assert.Equal(t, "PUT", gotMethod)
    assert.Equal(t, "1", gotHeader)
}
```
Additional integration/PoC: drive it end-to-end through `server.Server.InitGracefulShutdown` with a crafted `pb.InitGracefulShutdownRequest{ShutdownCallback: &pb.ShutdownCallback{Url: "http://169.254.169.254/latest/meta-data/iam/security-credentials/", Method: "GET"}}` against a running wrapper, and assert that `defaultShutdownCallback.Run` still attempts the request (only failing at the network layer in a non-cloud test environment) rather than being rejected by any allowlist check — confirming no such check exists in `helpers/runner_wrapper/api/shutdown_callback.go`.
