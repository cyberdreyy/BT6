### Title
Legacy gateway user-message handler binds capability responses only by attacker-controlled `MessageId`, letting an unprivileged attacker with a differently-signed but identical `MessageBody` hijack a victim's in-flight response - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`api.Message.Validate()`/`ExtractSigner()` derive `Body.Sender` purely from the signature over the `MessageBody` bytes and never bind the recovered sender to ownership of a given `MessageId`. `handler.HandleLegacyUserMessage` then stores the caller's callback in the shared `h.savedCallbacks` map keyed solely by the attacker-controllable `msg.Body.MessageId`, with no check for an existing/in-flight entry (unlike the newer `httpTriggerHandler.setupCallback`, which explicitly rejects reused IDs with `jsonrpc.ErrConflict`). An attacker who observes or predicts a victim's plaintext `MessageBody` (MessageId/Method/DonId/Receiver/Payload) can sign it with their own key and POST it while the victim's request is still in flight, overwriting the victim's `savedCallbacks` entry so the DON's eventual response for that `MessageId` is delivered to the attacker instead of the victim.

### Finding Description
`Message.Validate()` only checks structural constraints and recovers the signer with `ExtractSigner()`, then unconditionally sets `m.Body.Sender = utils.StringToHex(string(signerBytes))`: [1](#0-0) 

Because the signature only covers `MessageId`, `Method`, `DonId`, `Receiver`, and `Payload` (`GetRawMessageBody`), two different private keys can produce two valid `Message` values with *identical* `Body` but different `Sender` — nothing in `Validate()` ties a `MessageId` to a fixed original sender: [2](#0-1) 

The gateway entry point `ProcessRequest` treats any legacy request (with a `DonId`) that passes `Validate()` as legitimate and hands it, with a brand-new local `callback`, to the DON handler: [3](#0-2) 

`handler.HandleLegacyUserMessage` stores this callback keyed only by `msg.Body.MessageId`, with **no check for an existing in-flight entry**: [4](#0-3) 

Compare this to the newer `httpTriggerHandler.setupCallback`, which explicitly detects and rejects ID reuse: [5](#0-4) 

When a node eventually responds, `handleWebAPITriggerMessage` looks up and deletes `h.savedCallbacks[msg.Body.MessageId]` and forwards the payload to whichever callback is currently registered — it performs no check that the responding message's content matches the original requester's identity, only that the node's signature matches `nodeAddr`: [6](#0-5) [7](#0-6) 

Exploit flow: attacker observes/predicts a victim's exact plaintext `MessageBody` (e.g., a public trigger topic + timestamp + payload, or replayed/leaked traffic) for a still-in-flight legacy request. Attacker signs that exact body with their own key (`Validate()`/`ExtractSigner()` happily accepts it and sets `Body.Sender` to the attacker's address — this is "by design" for signature verification, but nothing prevents `MessageId` reuse). Attacker POSTs to `/gateway` before the victim's response arrives; `HandleLegacyUserMessage` overwrites `h.savedCallbacks[MessageId]` with the attacker's own `Callback`. The subsequent DON response tied to that `MessageId` (whether generated for the victim's original forwarded request or the attacker's re-forwarded duplicate) is delivered to whichever callback is currently in the map — the attacker's — so the attacker's HTTP request receives the capability execution result instead of the victim.

### Impact Explanation
This is a cross-user response confusion / request-hijacking bug: an unprivileged, unauthenticated attacker can redirect the result of another user's capability execution (webAPI trigger/target/compute action) to themselves by racing a duplicate `MessageId`. This matches the "capability execution consumed/redirected" scoped impact and the Chainlink bounty class for unauthorized action on/exposure of another user's job execution result.

### Likelihood Explanation
Preconditions: attacker needs only network access to the gateway's public HTTP endpoint and the exact plaintext `MessageBody` of a victim's in-flight request (obtainable via shared/public trigger topics, logs, or traffic observation) — no credentials, no operator/admin access, no node key. The race window is the round-trip time to the DON, which is attacker-controllable in effect since the attacker can retry indefinitely until they win the race against the legitimate response. This is reproducible via a deterministic unit/integration test that doesn't rely on real network timing (directly manipulating `h.savedCallbacks`).

### Recommendation
- Bind `savedCallbacks` entries to `(MessageId, Sender)` pairs, or reject `HandleLegacyUserMessage` calls when a `MessageId` is already active (mirroring `httpTriggerHandler.setupCallback`'s `ErrConflict` behavior).
- Verify that node responses' echoed `MessageId`/context match the original requester's `Sender`, not just the responding node's address.
- Consider deriving `MessageId` server-side (e.g., hash including the recovered `Sender`) rather than trusting a client-supplied ID as the sole lookup key.

### Proof of Concept
Go handler-level test plan (extends `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Build `victimMsg` via `triggerRequest(t, victimKey, topics, "", "", "")` with `MessageId = "12345"`.
2. Copy `victimMsg.Body` into `attackerMsg.Body` unchanged (same `MessageId`/`Method`/`DonId`/`Payload`), then `attackerMsg.Sign(attackerKey)` and `attackerMsg.Validate()` — assert `attackerMsg.Body.Sender != victimMsg.Body.Sender` while all other `Body` fields are `Equal`.
3. Call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCallback)`, then before resolving it, call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCallback)`.
4. Inspect `handler.savedCallbacks["12345"]` and assert it now equals `attackerCallback`, not `victimCallback` — demonstrating the callback for the victim's `MessageId` was silently overwritten.
5. Simulate the DON response via `handler.HandleNodeMessage(ctx, nodeResp, nodeAddr)` for `MessageId = "12345"` and assert that `attackerCallback.Wait()` receives the payload while `victimCallback.Wait()` times out/never resolves — proving cross-user response hijack.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func GetRawMessageBody(msgBody *MessageBody) [][]byte {
	alignedMessageId := make([]byte, MessageIdMaxLen)
	copy(alignedMessageId, msgBody.MessageId)
	alignedMethod := make([]byte, MessageMethodMaxLen)
	copy(alignedMethod, msgBody.Method)
	alignedDonId := make([]byte, MessageDonIdMaxLen)
	copy(alignedDonId, msgBody.DonId)
	alignedReceiver := make([]byte, MessageReceiverLen)
	copy(alignedReceiver, msgBody.Receiver)
	return [][]byte{alignedMessageId, alignedMethod, alignedDonId, alignedReceiver, msgBody.Payload}
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
