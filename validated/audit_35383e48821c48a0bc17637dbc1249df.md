### Title
Unprivileged lender can force an honest borrower into `defaulted` state by donating receipt strategyTokens to the CDO, inflating `getContractValue()` and the expected epoch interest pull — (File: `contracts/IdleCDOEpochVariant.sol`)

### Summary
`_skimDonatedAssets` only sweeps raw `token` (underlying) donations to `feeReceiver`; it never sweeps `strategyToken`. `getContractValue()` in `IdleCDOCreditVault` counts the full `strategyToken` balance of the CDO. A KYC-passing lender can obtain strategyToken receipts for free via `requestWithdraw` (which mints receipt tokens to the user), transfer them to the CDO during the buffer period, and thereby inflate `expectedEpochInterest` computed in `startEpoch`. At `stopEpoch`, `getFundsFromBorrower` tries to pull more than the honest borrower owes/approved, the transfer fails, and `_handleBorrowerDefault` marks the pool defaulted — freezing all withdrawals and forcing a loss haircut at `finalizeDefault`.

### Finding Description
- `IdleCDOCreditVault.getContractValue()` returns `_contractTokenBalance(strategyToken) + _contractTokenBalance(token) - unclaimedFees` (`contracts/IdleCDOCreditVault.sol:125-128`). Any `strategyToken` sitting on the CDO counts as NAV.
- `_skimDonatedAssets()` only transfers `token` to `feeReceiver` (`contracts/IdleCDOEpochVariant.sol:794-796`). It runs at `startEpoch` (line 242), `_stopEpoch` (line 355), `_deposit` (line 647), `requestWithdraw` (line 747) — but donated `strategyToken`s are never removed.
- `IdleCreditVault.requestWithdraw` burns CDO-held strategyTokens for principal but mints `_amount` of receipt strategyTokens to the user (`contracts/strategies/idle/IdleCreditVault.sol:273-275`). These are freely transferable ERC20 tokens.
- `startEpoch` computes `expectedEpochInterest = pendingWithdrawFees + _calcInterest(getContractValue())` (lines 260-262), where `_calcInterest` scales with the inflated NAV. The borrower then repays at `stopEpoch` via `try this.getFundsFromBorrower(_amountToPullFromBorrower + _pendingWithdraws)` (line 408); an honest borrower approving the true owed amount makes this `safeTransferFrom` revert, hitting the `catch` at line 501 and `_handleBorrowerDefault` (line 504), which sets `defaulted = true`, pauses, and disables withdraw requests (lines 577-599).
- `defaulted` permanently gates `startEpoch`, `restoreOperations`, and `_beforeUnpause`; the only exit is `finalizeDefault`, which applies an aggregate recovery multiplier — i.e., a real haircut on all LPs and pending receipts — even though the borrower never missed a payment.

### Impact Explanation
An unprivileged KYC'd lender can permanently impair the pool: `defaulted = true` freezes all lender withdrawals, and `finalizeDefault` distributes only the recovered amount pro-rata, crystallizing a loss equal to the unrecovered gap (the donated amount plus any reserve shortfall) on every LP. This is theft-adjacent freezing with quantified loss — the broken invariant is that `strategyToken` balance equals accounted NAV, and solvency/loss-waterfall integrity is broken because an artificial NAV inflation triggers the default path.

### Likelihood Explanation
Requirements are modest: the attacker must be a wallet allowed by Keyring (an accepted attacker class), hold any tranche balance, request a withdraw (receiving receipt tokens at no capital cost — the receipt is still a claim), and transfer those tokens to the CDO before `startEpoch`. The griefing cost is the forfeit of the receipt claim, but the induced haircut at `finalizeDefault` can exceed the donation if the reserve cannot cover inflated expectations. No privileged cooperation is needed; the honest borrower's correct allowance is precisely what triggers the revert. Existing guards (`_skimDonatedAssets`, `_checkNotAllowed`, `onlyIdleCDO`) do not cover the strategyToken donation path.

### Recommendation
Sweep `strategyToken` donations the same way as underlying donations — e.g., track the expected strategyToken balance (or compare against `totalSupply` accounting in `IdleCreditVault`) and burn or forward the excess inside `_skimDonatedAssets`, or make `getContractValue()` use an internally tracked NAV rather than raw `balanceOf(strategyToken)`.

### Proof of Concept
```solidity
// test/foundry/PocStrategyTokenDonationDefault.t.sol
function testPocStrategyTokenDonationForcedDefault() external {
    // Setup: attacker is a KYC'd lender (user1), deposit + run a normal epoch,
    // then during buffer requestWithdraw so IdleCreditVault mints receipt
    // strategyTokens to attacker.
    uint256 amount = 10_000 * ONE_SCALE;
    idleCDO.depositAA(amount);
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, initialProvidedApr, _expectedFundsEndEpoch());

    // Attacker requests withdraw -> receipt strategyTokens minted to attacker
    uint256 mintedAA = AAtranche.balanceOf(user1);
    vm.prank(user1);
    cdoEpoch.requestWithdraw(mintedAA / 2, address(AAtranche));
    uint256 receipts = strategy.balanceOf(user1);
    assertGt(receipts, 0);

    // Attacker donates the receipt tokens to the CDO during buffer.
    // _skimDonatedAssets at startEpoch only removes `token`, not strategyToken.
    vm.prank(user1);
    strategy.transfer(address(cdoEpoch), receipts);

    uint256 navPre = cdoEpoch.getContractValue(); // inflated by `receipts`

    // Manager starts the epoch; expectedEpochInterest is computed on inflated NAV.
    vm.prank(manager);
    cdoEpoch.startEpoch();
    uint256 inflatedInterest = cdoEpoch.expectedEpochInterest();
    // Borrower is honest: approves only the true interest owed, i.e.
    // interest on the real (non-inflated) NAV + pendingWithdraws.
    uint256 trueInterest = _expectedFundsEndEpoch();
    vm.startPrank(borrower);
    underlying.approve(address(cdoEpoch), trueInterest + strategy.pendingWithdraws());
    deal(address(underlying), borrower, trueInterest + strategy.pendingWithdraws());
    vm.stopPrank();

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // Pull exceeds borrower's approval -> transferFrom reverts ->
    // catch -> _handleBorrowerDefault marks an honest borrower defaulted.
    assertEq(cdoEpoch.defaulted(), true, 'honest borrower not forced into default');
    // All lender withdrawals are now frozen pending finalizeDefault haircut.
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.claimWithdrawRequest();
}
```

**Uncertainty noted:** I did not fully verify `IdleCreditVault`'s `borrower` approval mechanics or whether `prepareStopEpochWithApr0`/`previewLossAdjustedWithdrawFunds` can absorb the inflated pull amount in every mode (fixed-APR vs APR0/minted-interest). The core flaw — unswept `strategyToken` donation inflating `getContractValue()` and `expectedEpochInterest` — is confirmed in the code paths cited; the PoC should be run against a fork to confirm the revert path lands in `_handleBorrowerDefault` rather than an earlier check.
