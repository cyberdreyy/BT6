### Title
Unbounded recursion in `TrieNode::decode` allows fault-proof program stack-overflow crash on attacker-supplied MPT preimages - (File: crates/proof/mpt/src/node.rs)

### Summary
`TrieNode::decode` (and its helpers `try_decode_leaf_or_extension_payload`) recursively parse nested Merkle Patricia Trie nodes with no depth limit, unlike the sibling CBOR parser in this codebase which explicitly enforces `MAX_CBOR_NESTING_DEPTH` to guard against exactly this class of bug.

### Finding Description
`TrieNode::decode` dispatches on the RLP header and, for `Extension`/list nodes, calls `Self::decode` again on the child bytes, and for `Branch` nodes calls `Vec::<Self>::decode`, which recurses into `Self::decode` for each of the 17 slots: [1](#0-0) 
The leaf/extension payload path also recurses via `Self::decode(buf)` for extension children: [2](#0-1) 

There is no depth counter or nesting limit anywhere in this crate — a `grep` for `depth`/`recursion` in `crates/proof/mpt/**` only matches a doc comment, confirming no bound exists. This is the same bug class as CVE-2016-9937: a recursive parser that keeps calling itself on nested, attacker-influenced input until the call stack is exhausted, rather than being explicitly length/depth-limited. The codebase clearly recognizes this exact hazard elsewhere: the CBOR/COSE attestation parser used for TEE registration enforces a hard nesting cap and rejects deep documents: [3](#0-2) 
No equivalent guard exists for `TrieNode::decode`, which is the parser used throughout the fault-proof program (`crates/proof/proof`, `crates/proof/mpt`) to reconstruct L1/L2 state and storage tries from preimages fetched via the `PreimageOracle`.

Preimages are keyed by `keccak256`/`sha256` digests (`PreimageKeyType::Keccak256`/`Sha256`) as defined in `PreimageKey`: [4](#0-3) 
While a legitimate MPT preimage's bytes are constrained by having to hash to a value the requester already committed to (limiting an attacker's freedom to fabricate arbitrary nesting under a chosen hash), I was not able to fully verify — within the remaining investigation budget — whether every call site that constructs a `TrieNode` from oracle-fetched bytes (e.g., in `crates/proof/proof/src/l1/chain_provider.rs`, `crates/proof/proof/src/l2/chain_provider.rs`, `crates/proof/host/src/backend/*`) validates hash-preimage correspondence *before* calling `TrieNode::decode`, or whether decode is attempted first and validated after. If decode-before-hash-check occurs anywhere in the trusted/untrusted preimage-serving path (e.g., a dispute-game counterparty acting as the untrusted preimage server during offline/kv-store-backed execution), an attacker-controlled byte sequence could be handed to `TrieNode::decode` prior to the hash being checked, allowing a crafted deeply-nested (but still hash-colliding-free, since it's the attacker's own served bytes prior to verification) payload to drive unbounded recursion.

### Impact Explanation
If reachable with attacker-controlled bytes before hash verification, a stack overflow in the fault-proof program's on-chain-equivalent execution would crash the program that computes the claimed output root — i.e., a node halt / inability to produce a provable output during dispute-game resolution, which is one of the accepted impacts (node halt / wrong or unobtainable provable output root).

### Likelihood Explanation
Uncertain. The likelihood hinges entirely on whether any code path calls `TrieNode::decode` on oracle-supplied bytes before verifying `keccak256(bytes) == requested_key`. I could not confirm or rule this out within the given tool budget — the preimage-serving/backend code (`crates/proof/host/src/backend/online.rs`, `offline.rs`, `crates/proof/proof/src/l1/chain_provider.rs`, `l2/chain_provider.rs`) would need to be read in full to determine ordering of hash-check vs. decode. Given the codebase's own precedent of guarding CBOR parsing against this exact bug class, I flag this as a real risk needing confirmation rather than a proven exploit.

### Recommendation
Add an explicit nesting-depth counter/limit to `TrieNode::decode` (mirroring `MAX_CBOR_NESTING_DEPTH` in `crates/proof/tee/registrar/src/cbor.rs`), and audit every preimage-consumption call site to ensure `keccak256`/`sha256` verification of the returned bytes happens strictly before any `TrieNode::decode` (or other recursive parse) is invoked on them.

### Proof of Concept
Not constructed — doing so requires confirming the exact ordering of hash verification vs. decode across `crates/proof/host` and `crates/proof/proof` backends, which was not completed within the investigation budget. A concrete PoC would craft a deeply nested RLP list of `Extension`/`Branch` headers (e.g., thousands of nested single-byte-prefixed extension nodes) and feed it into whichever `TrieNode::decode` call site accepts unverified oracle bytes, driving the call stack to overflow.

impl Decodable for TrieNode {
    /// Attempts to decode the [`TrieNode`].
    fn decode(buf: &mut &[u8]) -> alloy_rlp::Result<Self> {
        // Peek at the header to determine the type of Trie node we're currently decoding.
        let header = Header::decode(&mut (**buf).as_ref())?;

        if header.list {
            // Peek at the RLP stream to determine the number of elements in the list.
            let list_length = rlp_list_element_length(&mut (**buf).as_ref())?;

            match list_length {
                BRANCH_LIST_LENGTH => {
                    let list = Vec::<Self>::decode(buf)?;
                    Ok(Self::Branch { stack: list })
                }
                LEAF_OR_EXTENSION_LIST_LENGTH => {
                    // Advance the buffer to the start of the list payload.
                    buf.advance(header.length());
                    // Decode the leaf or extension node's raw payload.
                    Self::try_decode_leaf_or_extension_payload(buf)
                        .map_err(|_| alloy_rlp::Error::UnexpectedList)
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        } else {
            match header.payload_length {
                0 => {
                    buf.advance(header.length());
                    Ok(Self::Empty)
                }
                32 => {
                    let commitment = B256::decode(buf)?;
                    Ok(Self::new_blinded(commitment))
                }
                _ => Err(alloy_rlp::Error::UnexpectedLength),
            }
        }
    }
