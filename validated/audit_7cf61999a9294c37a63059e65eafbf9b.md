### Title
Unauthenticated `/health` endpoint discloses raw internal error strings via `presenters.Check{Output: err.Error()}` - ([File: core/web/health_controller.go])

### Summary
`HealthController.Health` is registered without any authentication middleware at `core/web/router.go:220-228` (`r.GET("/health", hc.Health)`), and returns the raw `err.Error()` string from every failing health check as the `Output` field of `presenters.Check`. Any unauthenticated caller can hit `GET /health` (optionally with `?failing`) and receive verbatim internal error text — e.g., DB driver errors, DSNs, RPC endpoint URLs, or internal component/service names — with no redaction.

### Finding Description
`healthRoutes` wires `/health` and `/health.txt` on the base (unauthenticated) router group in `core/web/router.go:220-228`, alongside `/readyz` and `/public-readyz`. Unlike `PublicReadyz`, whose doc comment explicitly states it "never returns per-check details ... to avoid leaking internal service state on publicly reachable endpoints" (`core/web/health_controller.go:27-37`), `Health` unconditionally builds `presenters.Check` entries with `Output: err.Error()` for every failing check (`core/web/health_controller.go:99-116`), and serializes them via JSON, HTML, or plaintext (`writeTextTo`, `checkTree.WriteHTMLTo`) depending on `Accept` header negotiation — with no filtering or sanitization of the error text or the health check `name` (which is the fully-qualified internal service/component name, e.g. `EVM.RPC.Client`, `DB`, etc.). Health-check errors in Chainlink commonly originate from DB pings, chain RPC dialers, and other service `HealthReport()` implementations, which frequently wrap the underlying driver error (which can include DSN-like connection strings, hostnames, or ports) via `fmt.Errorf`/`errors.Wrap`. Because `Health` performs no error-message allowlisting/redaction and no authentication check gates the route, any unauthenticated attacker can enumerate exact internal component names and their raw error text by repeatedly polling `/health` (or `/health?failing` to filter to only failing checks) during outages or misconfigurations.

### Impact Explanation
This is an information-disclosure issue: an unauthenticated attacker can learn internal service topology (via `Check.Name`) and error content (via `Check.Output`) that may include connection strings, internal hostnames/ports, file paths, or other DB/RPC configuration hints, aiding reconnaissance for further attacks. It does not directly enable auth bypass, key disclosure, or fund movement on its own, so it maps to a lower-severity "sensitive information disclosure" bounty class rather than a critical node-compromise finding.

### Likelihood Explanation
No preconditions or credentials are required — the route is registered unauthenticated at `core/web/router.go:224-227`. The condition is opportunistic: it only yields sensitive data when a registered health check is actually failing (e.g., during a DB outage, RPC misconfiguration, or transient connectivity issue), which is realistically reachable in production operational scenarios. The attacker can repeat the request indefinitely at no cost (`GET /health` or `GET /health?failing`).

### Recommendation
Apply the same design used for `PublicReadyz` to `Health`/`Readyz`'s public exposure: either (a) require authentication for the detailed `/health` and `/readyz?full` outputs and only expose a minimal public status (pass/fail, no `Output`/error text) on unauthenticated routes, or (b) sanitize/redact `err.Error()` before placing it into `presenters.Check.Output` (e.g., strip connection-string-like substrings, or only expose a generic error class rather than the full wrapped error chain).

### Proof of Concept
1. In `core/web/health_controller_test.go`, register a fake `chainlink.Application`/health checker (as already scaffolded in that file) whose `IsHealthy()` returns `false` and an error map containing one entry, e.g. `errors.New("failed to connect: postgres://user:pass@10.0.0.5:5432/dbname")`.
2. Issue `GET /health` against the test router without any `Authorization`/session cookie.
3. Assert the HTTP response body's `checks[].output` (JSON) — or plaintext/HTML variant via `Accept: text/plain` / `text/html` — contains the literal DSN string `postgres://user:pass@10.0.0.5:5432/dbname`, demonstrating the raw error is exposed unauthenticated.
4. Expected (fixed) behavior: the test should instead assert that `Output` does not contain the raw error/DSN, or that the unauthenticated response contains no `Output` field at all. [1](#0-0) [2](#0-1) [3](#0-2)

```go
func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}
```

```go
func healthRoutes(app chainlink.Application, r *gin.RouterGroup) {
	hc := HealthController{app}
	r.GET("/readyz", hc.Readyz)
	r.GET("/public-readyz", hc.PublicReadyz)
	r.GET("/health", hc.Health)
	r.GET("/health.txt", func(context *gin.Context) {
		context.Request.Header.Set("Accept", gin.MIMEPlain)
	}, hc.Health)
}
```
