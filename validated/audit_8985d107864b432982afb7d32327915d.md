## Finding

### Title
CARVE branch of `check_latest_block_in_tenure` lets an attacker's miner slot indefinitely refresh `last_activity_time` without ever producing a signed block, suppressing `is_timed_out` fallback - (File: stacks-signer/src/chainstate/mod.rs)

### Summary
`check_latest_block_in_tenure`'s pre-commit ("CARVE") branch treats any conflicting-height proposal against a fresh, unsigned `PreCommitted` block as pure miner "activity" and never vetoes it [1](#0-0) . Because `mark_pre_committed` is set per-signer locally the moment that signer's own node validates any proposal — with no quorum required — a single miner (one BTC-won slot) can keep feeding each signer a stream of distinct, conflicting, node-validatable proposals at the same/lower height, repeatedly hitting the CARVE branch and calling `update_last_activity_time` on every proposal, while never letting any one candidate accumulate the 70% pre-commit weight needed to be signed. `is_timed_out` in both v1 and v2 measures only elapsed time since `last_activity_time` (once `has_signed_block_in_tenure` is false) [2](#0-1) [3](#0-2) , so this refresh loop prevents `check_miner_inactivity` from ever falling back to the prior sortition's miner (`make_miner_state`) [4](#0-3) , even though no block in the tenure ever reaches global acceptance.

### Finding Description
The wedge: `is_timed_out` is defined purely as "no signed block in this tenure AND elapsed-since-last-activity > block_proposal_timeout." There is no separate, activity-independent ceiling on how long a tenure may run without producing a signed block. The intended safety valve for a non-progressing tenure is exactly this activity timeout, and `check_latest_block_in_tenure`'s CARVE branch is explicitly designed to *not* veto a conflicting proposal against a stale-but-unsigned pre-commit, while still refreshing the activity clock — the code comment says "The miner may just be slow, so count this invalid block proposal towards valid miner activity" [5](#0-4)  and, for the pre-commit case, "A block we have only pre-committed to must NOT veto this proposal, but... this should still count as activity for the miner" [6](#0-5) .

Crucially, entering `PreCommitted` state (which arms the CARVE branch's `is_fresh_pre_commit` check) requires no signer quorum: it happens the instant *that individual signer's own node* returns validation OK for any proposal, in `handle_block_validate_ok` → `mark_pre_committed` [7](#0-6) [8](#0-7) . So a lone miner, without any other signer's cooperation, can locally arm the CARVE branch on every signer independently just by getting each successive candidate block past node validation.

Exploit flow: the attacker (the actual sortition winner for this tenure) crafts and gossips a sequence of syntactically distinct BlockProposals (e.g., varying `timestamp`) at the same/conflicting `chain_length`. For each signer: proposal 1 passes proposal-arrival checks (no signed tip yet, node tip below chain_length) and gets validated/pre-committed locally. Proposal 2 (a sibling at the same height) hits `check_latest_block_in_tenure`: `get_tenure_last_block_info` returns `None` (still no *signed* block, only a pre-commit) [9](#0-8) , so it falls to CARVE; `get_last_accepted_block` returns the fresh `PreCommitted` proposal 1 with `chain_length` ≥ proposal 2's, `is_fresh_pre_commit` is true, so `update_last_activity_time` fires and the check still returns `true` (not vetoed) [10](#0-9) . Repeat with proposal 3, 4, ... — each refreshes `last_activity_time` on every signer, while no single hash ever crosses the 70% pre-commit weight needed for `mark_locally_accepted`/signing (`handle_block_pre_commit`) [11](#0-10) . `is_timed_out`'s `has_signed_block_in_tenure` check stays false and `elapsed` never exceeds `block_proposal_timeout`, so `check_miner_inactivity` never invokes `make_miner_state` to hand the tenure to the prior sortition's miner.

Existing guards that do NOT stop this: `reorg_attempts_activity_timeout` only bounds the *signed*-tip (LSB) branch, not CARVE; `tenure_last_block_proposal_timeout` bounds only the individual pre-commit's own freshness (`approved_time` staleness), not the cumulative activity-timer reset pattern — a fresh pre-commit can simply be re-armed by the next conflicting proposal validating OK. The NODE branch (asking `get_tenure_tip`) does not veto either, since the node has not accepted any block in the brand-new tenure yet.

### Impact Explanation
This breaks the bounded-liveness guarantee documented for `check_miner_inactivity`/`is_timed_out`: "every valid proposal from a new tenure should be reachable within `block_proposal_timeout`," but here activity resets without progress, matching the High-severity category "a signer wedged into never signing valid blocks (liveness)." The attack is fully repeatable for as long as the attacker holds the miner slot for that tenure, and it requires nothing beyond a single miner slot plus StackerDB/gossip access to broadcast proposals — no majority of signers, no compromised keys, no privileged role.

### Likelihood Explanation
Preconditions are modest and squarely within the stated attacker capability: win one sortition (one miner slot), then repeatedly craft and gossip BlockProposals with distinct nonces/timestamps at the same conflicting height, ensuring each is node-validatable (a lightweight, achievable condition since it is not yet part of any accepted chain). No other signer's cooperation, private key, or the auth token is needed; `mark_pre_committed` triggers independently, per signer, on that signer's own node validation. The only cost to the attacker is generating and broadcasting new proposals faster than `tenure_last_block_proposal_timeout`/`block_proposal_timeout` elapse, which is cheap.

### Recommendation
Bound the CARVE-branch activity credit independent of proposal churn: e.g., cap the total time a tenure may extend its own activity window via pre-commit-only "activity" (as opposed to activity following an actual signed block), or require `is_timed_out` to consider an absolute maximum age since the tenure's first proposal/burn-block-receipt (not just elapsed-since-last-activity) before disallowing fallback. Alternatively, stop refreshing `last_activity_time` on CARVE hits once a bounded number of unsigned conflicting proposals have been observed in the tenure, forcing the tenure to either converge to a signed block or time out.

### Proof of Concept
Extend `stacks-signer/src/chainstate/tests/v2.rs`'s `pre_committed_block_does_not_veto_replacement` pattern:
1. Set up `setup_test_environment` with a short `tenure_last_block_proposal_timeout` (e.g. 2s) and `block_proposal_timeout` (e.g. 3s) for `SortitionState::is_timed_out`.
2. Insert `existing_block_proposal` and `mark_pre_committed()` (simulating this signer's own node validating the miner's first candidate).
3. Loop N times (N × interval > 3s of wall-clock, but each interval < 2s): construct a new sibling block at the same `chain_length` (varying `timestamp`), call `SortitionData::check_latest_block_in_tenure` on it, assert it returns `Ok(true)` (not vetoed) each time, and re-mark a new `PreCommitted` block (simulating each new proposal validating OK before the previous pre-commit goes stale) so `get_last_accepted_block`/`is_fresh_pre_commit` keeps returning true.
4. After the loop (elapsed wall-clock > `block_proposal_timeout`), assert `signer_db.get_last_activity_time(&tenure_id)` is recent (within the last interval), and assert `SortitionState::is_timed_out(&tenure_id, &signer_db, ..., block_proposal_timeout)` returns `false`, despite `has_signed_block_in_tenure(&tenure_id)` being `false` throughout and total elapsed time exceeding `block_proposal_timeout`.
5. Contrast with a control case where no further proposals arrive after the first pre-commit: assert `is_timed_out` returns `true` once elapsed time exceeds `block_proposal_timeout`, demonstrating the reset is caused specifically by the repeated CARVE-branch activity credit.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    pub fn check_miner_inactivity(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        eval: &GlobalStateEvaluator,
    ) -> Result<(), SignerChainstateError> {
        let Self::Initialized(ref mut state_machine) = self else {
            // no inactivity if the state machine isn't initialized
            return Ok(());
        };

        let MinerState::ActiveMiner { ref tenure_id, .. } = state_machine.current_miner else {
            // no inactivity if there's no active miner
            return Ok(());
        };

        let version = SortitionStateVersion::from_protocol_version(
            state_machine.active_signer_protocol_version,
        );
        let is_timed_out = SortitionState::is_timed_out(
            &version,
            tenure_id,
            db,
            client.get_signer_address(),
            proposal_config,
            eval,
        )?;

        if !is_timed_out {
            return Ok(());
        }

        // the tenure timed out, try to see if we can use the prior tenure instead
        let CurrentAndLastSortition { last_sortition, .. } =
            client.get_current_and_last_sortition()?;
        let Some(last_sortition) = last_sortition
            .and_then(|val| SortitionData::try_from(val).ok())
            .map(|data| SortitionState::new(version, data))
        else {
            warn!("Signer State: Current miner timed out due to inactivity, but could not find a valid prior miner. Allowing current miner to continue");
            return Ok(());
        };

        let sortition_data = last_sortition.data();
        // If we already reverted to the last sortition miner, don't time it out as it means we have already timed out the current sorititon miner
        // as there is no other miner available.
        if &sortition_data.consensus_hash == tenure_id {
            warn!("Signer State: Last sortition miner has timed out, but no prior valid miner. Allowing last sortition miner to continue");
            return Ok(());
        }

        // Only revert to the prior miner if its tenure is the canonical Stacks tip's
        // tenure. A miner only continues (extends) a tenure it won, so if the canonical
        // tip is in some other tenure due to a Bitcoin reorg orphaning the prior
        // sortition's tenure, the prior miner's node has already stopped mining and
        // will never propose again.
        let stacks_tip_ch = client.get_peer_info()?.stacks_tip_consensus_hash;
        if sortition_data.consensus_hash != stacks_tip_ch {
            warn!(
                "Signer State: Current miner timed out due to inactivity, but the canonical stacks tip is not in the prior miner's tenure, so the prior miner cannot continue it. Allowing current miner to continue";
                "stacks_tip_consensus_hash" => %stacks_tip_ch,
                "prior_sortition_consensus_hash" => %sortition_data.consensus_hash,
            );
            return Ok(());
        }

        if !last_sortition.is_tenure_valid(db, client, proposal_config, eval)? {
            warn!("Signer State: Current miner timed out due to inactivity, but prior miner is not valid. Allowing current miner to continue");
            return Ok(());
        }
        let new_active_tenure_ch = &sortition_data.consensus_hash;
        let inactive_tenure_ch = tenure_id.clone();
        state_machine.current_miner = Self::make_miner_state(
            sortition_data.clone(),
            client,
            db,
            proposal_config.tenure_last_block_proposal_timeout,
        )?;
