### Title
Attacker-controlled `MaskPhrase` that is a byte-prefix of a token prefix (e.g. `glpa` vs `glpat-`) suppresses `tokensanitizer` masking of the following secret - ([File: common/buildlogger/build_logger.go], [File: common/buildlogger/internal/masker/masker.go], [File: common/buildlogger/internal/tokensanitizer/token_masker.go])

### Summary
`Logger.wrap` chains masker writers before the `tokensanitizer` writer, so raw log bytes hit the `MaskPhrase` masker first and the `tokensanitizer` prefix-scanner second. A pipeline author can define a `Masked` CI/CD variable whose value is a strict prefix of a default token prefix (e.g. `glpa` vs. `glpat-`); when that phrase is fully matched inside a real `glpat-` token in the log stream, the masker consumes and replaces those bytes and forwards only the remainder to `tokensanitizer`, which then never sees the full prefix and fails to recognize/mask the token.

### Finding Description
`Logger.wrap` builds the writer chain in this order (outermost first, since later constructions wrap the previous writer as `next`): [1](#0-0) 
Concretely, writes flow `Sync -> masker -> urlsanitizer -> tokensanitizer -> timestamper -> base`, meaning `MaskPhrase` matching happens strictly before `tokensanitizer`'s prefix-based token masking.

`masker.Write` tracks partial phrase matches in `m.matching`, and once a phrase is fully matched it replaces those exact bytes with `[MASKED]` and resumes scanning from the next byte, forwarding whatever remains unmatched to the next writer in the chain: [2](#0-1) 

If the `MaskPhrase` is `"glpa"` (a 4-byte strict prefix of the default token prefix `"glpat-"`) and the log stream later contains a real token `glpat-XXXXXXXXXXXXXXXXXXXX`, the masker matches and consumes `"glpa"`, replaces it with `[MASKED]`, and forwards only the trailing `"t-XXXXXXXXXXXXXXXXXXXX"` downstream. `tokensanitizer.Write` independently tracks its own `m.matching` against its full prefix (`"glpat-"`) and requires seeing that entire prefix sequence starting from `'g'`: [3](#0-2) 
Since the input it now receives begins with `'t'` (not `'g'`), and no other `'g'` exists in the remainder, `tokensanitizer` never begins prefix matching, and forwards `"t-XXXXXXXXXXXXXXXXXXXX"` to the base trace completely unmasked - leaking essentially the entire token except the 4 bytes coincidentally consumed by the masker.

The `MaskPhrase` list is fully attacker-controlled: it is populated from the value of every job variable marked `Masked: true`, which any pipeline author can set: [4](#0-3) [5](#0-4) 

Existing protections (`tokensanitizer`'s own prefix state machine, the masker's own re-sync-on-mismatch logic) do not stop this because they operate as independent, non-communicating writers in a pipeline - the masker has no knowledge that the bytes it strips out are also meaningful to a writer further down the chain, and there is no reservation/lookahead across the two mechanisms to prevent one from truncating input the other depends on.

### Impact Explanation
A pipeline author can, in their own job, register an innocuous short masked variable value that happens to share a prefix with `glpat-` (or any other registered `MaskTokenPrefixes`/default token prefix). This silently disables `tokensanitizer`'s automatic masking for any subsequent occurrence of that token type in the same job's trace (e.g., in verbose curl output, debug logs, error messages) that would otherwise have been redacted without the author needing to know the token value in advance. This weakens a security control (automatic secret redaction) that is relied upon as a compensating control for tokens/secrets appearing incidentally in build output, potentially exposing tokens (e.g., `CI_JOB_TOKEN`, deploy/PAT tokens) in job logs, artifacts of logs, or downstream log storage that are otherwise expected to be masked.

### Likelihood Explanation
Highly feasible: no special privileges are required beyond normal CI/CD variable definition rights (defining a `Masked` variable with an attacker-chosen short value is a standard, supported use case). The trigger requires only that a real `glpat-`-prefixed (or other default-prefixed) token appear later in the same trace stream, which happens routinely (e.g., via `git` remote URLs, curl commands, or error output containing tokens). It is deterministic and reproducible in a single `Write()` call - no chunk-boundary timing tricks needed.

### Recommendation
Reorder or coordinate the writer chain so that `tokensanitizer` (fixed, security-critical, well-known prefixes) processes bytes before user-defined `MaskPhrase` masking, or make the two masking layers aware of each other's held-back "matching" buffers so that a phrase-in-progress that is a prefix of a `MaskTokenPrefixes` entry does not get finalized/forwarded until it's confirmed not to be the start of an in-progress token match. Alternatively, reject/warn on `Masked` variable values that are exact byte-prefixes of any configured token prefix (default or custom), since these are inherently unsafe as mask phrases in this pipelined architecture.

### Proof of Concept
Extend the existing `common/buildlogger/internal/build_logger_fuzz.go`-style property to combine a mask phrase and a token prefix in adjacent bytes and assert full masking:

```go
func TestMaskPhrasePrefixDefeatsTokenSanitizer(t *testing.T) {
    buf := new(bytes.Buffer)
    w := io.WriteCloser(nopWriteCloser{buf})
    w = tokensanitizer.New(w, [][]byte{[]byte("glpat-")})
    w = masker.New(w, [][]byte{[]byte("glpa")}) // attacker-chosen masked variable value

    secret := "glpat-XXXXXXXXXXXXXXXXXXXX"
    _, err := fmt.Fprintf(w, "token in log: %s\n", secret)
    require.NoError(t, err)
    require.NoError(t, w.Close())

    out := buf.String()
    assert.NotContains(t, out, "XXXXXXXXXXXXXXXXXXXX", "token suffix leaked because MaskPhrase consumed the tokensanitizer prefix")
}
```
Expected today: the assertion fails, confirming the leak (`out` contains `[MASKED]t-XXXXXXXXXXXXXXXXXXXX`). After a fix, the test should pass with the token fully replaced by `[MASKED]`.

func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
		w = timestamper.New(w, timestamper.StreamType(streamType), uint8(streamID), true)
	}

	w = tokensanitizer.New(w, l.maskTokenPrefixes)
	w = urlsanitizer.New(w)
	w = masker.New(w, l.maskPhrases)
	w = internal.NewSync(w)

	return w
}
