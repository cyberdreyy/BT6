### Title
Stale confirmations from removed multisig members are still counted toward the approval threshold - ([File: multisig2/src/lib.rs])

### Summary
`delete_member` in `multisig2/src/lib.rs` removes a departing member from the `members` set and purges only the requests that member itself *originated*, but never scans the `confirmations` map to strip that member's approval from requests originated by *other* members. `confirm` later tallies approvals purely by `confirmations.len()` without re-validating that every recorded confirmer is still in `self.members`, so a request can execute with fewer live-member approvals than `num_confirmations` requires.

### Finding Description
`confirm` treats the size of the stored confirmation set as proof of sufficient authorization: [1](#0-0) 

The set is keyed by `member.to_string()` and is never revalidated against current membership. When a member is removed, `delete_member` only clears requests that member itself added (`r.member == member`), leaving any *confirmations* that member cast on other members' pending requests untouched: [2](#0-1) 

There is no code path anywhere in the contract that walks `self.confirmations` to drop a departing member's entries from requests they did not author. As a result the invariant the contract is supposed to enforce — "a request executes only once `num_confirmations` *current* members have approved it" — can be broken: `confirmations.len()` can include one or more accounts/keys that are no longer members of `self.members` at all.

This is the multisig analog of the reported bug class ("counted vs. actually valid" mismatch causing an integrity violation): the Aptos report was about SecretShare fields not being validated against the author's real weight before being trusted; here, confirmation-set membership is not validated against the live member set before being trusted as a vote toward the K-of-N threshold.

### Impact Explanation
This breaks the core custody/authorization binding of the multisig: **confirmations counted == live members who approved**. If it diverges, a `Transfer`, `FunctionCall`, `AddKey`/`DeleteMember`, or `DeployContract` request can be executed with actual live-member approvals below the configured `num_confirmations` threshold — i.e., a multisig request executed below threshold, which the rules explicitly classify as Critical impact (funds moved, keys added, or contract code deployed without the required quorum of currently-trusted parties).

### Likelihood Explanation
No privileged action beyond ordinary multisig operation is required: an existing member (later removed) confirms a pending request from another member, then any legitimate `DeleteMember` request (routine key rotation/offboarding, requiring only normal member confirmations, no owner/foundation/attacker-supplied key needed) removes that member. The stale confirmation silently persists and just needs the remaining confirmations to reach the threshold count. This is a normal usage sequence (add member, confirm requests, later remove a member) rather than an edge case, so it is readily triggerable by unprivileged flow of legitimate multisig business.

### Recommendation
When removing a member in `delete_member`, iterate all entries in `self.requests`/`self.confirmations` (not just those the removed member authored) and remove the departing member's key from every stored confirmation `HashSet`. Alternatively, validate membership of each confirmer at `confirm`-time (e.g., filter `confirmations` against `self.members` before comparing `len()` to `num_confirmations`) so stale/removed identities can never count toward the threshold.

### Proof of Concept
1. Deploy `multisig2` with `num_confirmations = 3` and members `{A, B, C, D}`.
2. `B` calls `add_request` for a `Transfer` request (`request_id = R`), 0 confirmations so far.
3. `A` calls `confirm(R)` → `confirmations[R] = {A}` (per `multisig2/src/lib.rs:294-315`).
4. `A`, `C`, `D` jointly pass a separate `DeleteMember { member: A }` request (3-of-4, legitimate offboarding). `delete_member` removes `A` from `self.members` and deletes only requests `A` had authored — `R` (authored by `B`) is untouched, so `confirmations[R]` still contains `A` (`multisig2/src/lib.rs:356-379`).
5. `C` then `D` call `confirm(R)`. `confirmations[R].len()` goes `1 → 2 → 3`, hitting `>= num_confirmations` on `D`'s call, and `execute_request` fires the `Transfer` (`multisig2/src/lib.rs:304-309`).
6. The transfer executed with only `C` and `D` as genuine current-member approvals — one confirmation short of the required 3-of-4 threshold, since `A`'s vote was cast while a member but should have been invalidated upon removal.

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
