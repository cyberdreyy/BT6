### Title
`get_token_account_balance` accepts a Mint pubkey with attacker-controlled data regardless of account owner, allowing forged `decimals`/balance reporting - ([File: rpc/src/rpc.rs], [File: rpc/src/parsed_token_accounts.rs])

### Summary
`JsonRpcRequestProcessor::get_token_account_balance` reads the `mint` field from an attacker-supplied `TokenAccount`, then calls `get_mint_owner_and_additional_data`, which unpacks that mint account's raw bytes as `StateWithExtensions::<Mint>` without ever validating that the mint account's owner is a known SPL Token program. Because the returned owner is discarded (`let (_, data) = get_mint_owner_and_additional_data(...)`), an attacker can point `mint` at any account they control (owned by any program, including one they deploy themselves) whose data happens to be a validly-shaped 82-byte `Mint` layout, and the RPC will report fabricated `decimals`/`ui_amount` for the queried token account.

### Finding Description
In `rpc/src/rpc.rs`:

```rust
pub fn get_token_account_balance(...) -> Result<RpcResponse<UiTokenAmount>> {
    let bank = self.bank(commitment);
    let account = bank.get_account(pubkey)...;
    if !is_known_spl_token_id(account.owner()) { ... }         // only checks the TOKEN ACCOUNT's owner
    let token_account = StateWithExtensions::<TokenAccount>::unpack(account.data())...;
    let mint = &Pubkey::from_str(&token_account.base.mint.to_string())...;
    let (_, data) = get_mint_owner_and_additional_data(&bank, mint)?;  // mint owner discarded!
    let balance = token_amount_to_ui_amount_v3(token_account.base.amount, &data);
    Ok(new_response(&bank, balance))
}

`get_mint_owner_and_additional_data` (in `rpc/src/parsed_token_accounts.rs`) fetches whatever account resides at `mint` and unpacks its bytes as a `Mint`, with **no owner/program check at all**:

```rust
pub(crate) fn get_mint_owner_and_additional_data(bank: &Bank, mint: &Pubkey) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() { ... }
    else {
        let mint_account = bank.get_account(mint).ok_or_else(...)?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string()))
        .map(|mint| SplTokenAdditionalDataV2 { decimals: mint.base.decimals, ... })
}
``` [2](#0-1) 

Only the token account itself is checked with `is_known_spl_token_id`; the mint account referenced inside its `mint` field is never checked for token-program ownership before its bytes are parsed as `Mint`. Because `StateWithExtensions::<Mint>::unpack` is a pure byte-layout parser (checks length/tag bytes, not the account owner), any account whose raw data matches the `Mint` layout — regardless of which program owns it — will successfully unpack and yield attacker-chosen `decimals`, `supply`, extension configs, etc. `get_token_account_balance` then feeds that forged data into `token_amount_to_ui_amount_v3` and returns it as the RPC response for `getTokenAccountBalance`.

An attacker can build this scenario entirely with normal, permissionless on-chain actions: create/own a `TokenAccount`-shaped account under the real SPL Token program with an arbitrary `mint` pubkey field, and separately create (via `system_instruction::create_account` combined with a program they control, or any other means of writing 82 attacker-chosen bytes into an account) a second account whose data matches the `Mint` byte layout but is not owned by any token program. No validator, leader, or privileged control is required.

### Impact Explanation
For the single `getTokenAccountBalance` call the attacker issues on their own crafted account pair, the RPC reports a `decimals`/`ui_amount`/`ui_amount_string` value that is entirely attacker-fabricated rather than derived from a genuine SPL Mint validated by a token program. This is a parse-fidelity / misreported-account-data bug: the returned `UiTokenAmount.decimals` is "untethered from any real mint," matching the "wrong data returned for a query" bounty category, scoped strictly to the querying client's own account/mint pair.

### Likelihood Explanation
Fully feasible with a single unprivileged client and a single JSON-RPC call at normal request rates. It only requires the attacker to control two accounts they create themselves (a token account with an arbitrary `mint` field, and an account whose bytes coincidentally/deliberately match the 82-byte `Mint` layout). No special timing, staking, or multiple-client coordination is needed, making it trivially repeatable.

### Recommendation
In `get_mint_owner_and_additional_data` (and/or in `get_token_account_balance`), validate that the mint account's owner is `is_known_spl_token_id` before calling `get_additional_mint_data`/`StateWithExtensions::<Mint>::unpack`, mirroring the check already performed in `get_token_supply` and `get_token_program_id_and_mint`. Reject with `Error::invalid_params("Invalid param: not a Token mint")` when the owner check fails.

```rust
pub(crate) fn get_mint_owner_and_additional_data(
    bank: &Bank,
    mint: &Pubkey,
) -> Result<(Pubkey, SplTokenAdditionalDataV2)> {
    if mint == &spl_token_interface::native_mint::id() {
        Ok((
            spl_token_interface::id(),
            SplTokenAdditionalDataV2::with_decimals(spl_token_interface::native_mint::DECIMALS),
        ))
    } else {
        let mint_account = bank.get_account(mint).ok_or_else(|| {
            Error::invalid_params("Invalid param: could not find mint".to_string())
        })?;
        let mint_data = get_additional_mint_data(bank, mint_account.data())?;
        Ok((*mint_account.owner(), mint_data))
    }
}

fn get_additional_mint_data(bank: &Bank, data: &[u8]) -> Result<SplTokenAdditionalDataV2> {
    StateWithExtensions::<Mint>::unpack(data)
        .map_err(|_| {
            Error::invalid_params("Invalid param: Token mint could not be unpacked".to_string())
        })
        .map(|mint| {
            let interest_bearing_config = mint
                .get_extension::<InterestBearingConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            let scaled_ui_amount_config = mint
                .get_extension::<ScaledUiAmountConfig>()
                .map(|x| (*x, bank.clock().unix_timestamp))
                .ok();
            SplTokenAdditionalDataV2 {
                decimals: mint.base.decimals,
                interest_bearing_config,
                scaled_ui_amount_config,
            }
        })
}
