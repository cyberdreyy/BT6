### Title
Response cache key omits WorkflowID, allowing cross-workflow cached HTTP response reuse for the same workflow owner - (File: core/services/gateway/handlers/capabilities/v2/response_cache.go)

### Summary
`responseCache.Fetch`/`Set` key cached `OutboundHTTPResponse` values solely by `gateway_common.OutboundHTTPRequest.Hash()`. The README for this component explicitly states the cache is meant to be "Workflow-scoped" and generated "from workflow ID and request hash" [1](#0-0) , but the actual `Hash()` implementation (validated via `TestRequestHash`) is documented to produce **the same hash regardless of `WorkflowID`**, while distinguishing on `WorkflowOwner` [2](#0-1) [3](#0-2) .

### Finding Description
The cache map itself is documented as "keyed by a hash of the request (method, URL, headers, body, workflowOwner)" — notably omitting workflow ID from that comment as well [4](#0-3) . `Fetch` and `Set` use `req.Hash()` as the sole cache key for both read and write paths [5](#0-4) . This is invoked from `makeOutgoingRequest`, which is triggered by any workflow node's outbound HTTP action request reaching the gateway [6](#0-5) .

Because `WorkflowID` is not part of the hash, two different workflows belonging to the same `WorkflowOwner` (an unprivileged, multi-tenant actor scenario where one owner can run several distinct workflows) that happen to issue outbound HTTP requests with the same method/URL/headers/body will collide on the same cache key. A response fetched for Workflow A can be served to Workflow B under the same owner, exactly analogous to the Allora bug where forecast-score data was inserted into the inference-score storage slot due to using the wrong identifying key — data intended for one entity is silently associated with a different entity because the storage key omits a critical discriminator.

### Impact Explanation
This breaks the documented invariant of "Workflow Isolation... to prevent cross-workflow data leakage" [7](#0-6) . A workflow could receive a stale or wrong HTTP response body/headers/status originally fetched by an unrelated workflow (same owner, different workflow) — e.g., different endpoints or authenticated responses reused across workflow contexts, causing wrong data to flow into automated on-chain/off-chain actions taken by that workflow. Since these are cacheable status codes (2xx/4xx) and TTL can be up to 10 minutes by default, misrouted response data could persist and be replayed across executions.

### Likelihood Explanation
Reachable from an unprivileged workflow author: any user who owns multiple workflows that issue HTTP Action requests with matching method/URL/headers/body (a common scenario, e.g., calling the same external API endpoint) triggers this collision without needing any special privilege, malicious peer, or gateway-operator access — the request path is a normal HTTP Action + `CacheSettings.Store`/`MaxAgeMs` usage as demonstrated in tests like `TestHandleNodeMessage` ("returns cached response if available") [8](#0-7) .

### Recommendation
Include `WorkflowID` (or a full workflow selector including owner+ID) as part of the cache key/hash computed in `OutboundHTTPRequest.Hash()`, matching the documented design intent of workflow-scoped caching, so that responses cannot be shared across distinct workflows even under the same owner.

### Proof of Concept
1. Workflow A (owner `0xabc`, workflowID `wf-1`) issues an `OutboundHTTPRequest{Method: "GET", URL: "https://api.example.com/data", CacheSettings:{Store:true, MaxAgeMs: 600000}}`; gateway fetches and caches the response keyed by `req.Hash()` (owner-scoped, ID-agnostic) via `Set`/`Fetch` in `response_cache.go`.
2. Workflow B (same owner `0xabc`, different workflowID `wf-2`) issues an outbound request with identical method/URL/headers/body but a different `WorkflowID`.
3. Per `TestRequestHash`'s documented behavior ("having different workflowID results in same Hash"), `req.Hash()` for Workflow B matches Workflow A's cache entry, so `responseCache.Fetch` returns Workflow A's cached response to Workflow B without making a fresh outbound call — data crosses workflow boundaries despite the intended workflow-level isolation.

6. **Response Caching**: Stores cacheable responses (2xx, 4xx status codes) only if `CacheSettings.Store` is `true`
7. **Node Response**: Sends HTTP response back to requesting node

- **Cache Key**: Generated from workflow ID and request hash
- **Cache Invalidation**: Time-based expiration with periodic cleanup
- **Cache Strategy**: All cacheable responses are cached; Non-zero `CacheSettings.MaxAgeMs` determines whether to return a cached value or make a fresh request

func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}

	// Slow path: singleflight deduplicates concurrent fetches per key.
	// Cache check + store happen inside the flight so the key isn't released
	// until the result is cached, closing the race window between singleflight
	// completion and cache write.
	result, _, _ := rc.flight.Do(cacheKey, func() (any, error) {
		// Re-check cache: a previous flight may have just stored the result.
		rc.cacheMu.RLock()
		cachedResp, exists := rc.cache[cacheKey]
		rc.cacheMu.RUnlock()
		if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
			rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
			return cachedResp.response, nil
		}

		response := fetchFn()

		if storeOnFetch && isCacheableStatusCode(response.StatusCode) {
			rc.cacheMu.Lock()
			rc.cache[cacheKey] = &cachedResponse{
				response: response,
				storedAt: time.Now(),
			}
			rc.cacheMu.Unlock()
		}

		return response, nil
	})

	return result.(gateway.OutboundHTTPResponse)
}

// Set caches a response if it is cacheable (2xx or 4xx and cache is empty or expired for the given request)
func (rc *responseCache) Set(req gateway.OutboundHTTPRequest, response gateway.OutboundHTTPResponse) {
	rc.cacheMu.Lock()
	defer rc.cacheMu.Unlock()
	if isCacheableStatusCode(response.StatusCode) && rc.isExpiredOrNotCached(req) {
		rc.cache[req.Hash()] = &cachedResponse{
			response: response,
			storedAt: time.Now(),
		}
	}
}

func (h *gatewayHandler) makeOutgoingRequest(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	requestID := resp.ID
	h.lggr.Debugw("handling outgoing message", "requestID", requestID, "nodeAddr", nodeAddr)
	var req gateway_common.OutboundHTTPRequest
	err := json.Unmarshal(*resp.Result, &req)
	if err != nil {
		return fmt.Errorf("failed to unmarshal HTTP request from node %s: %w", nodeAddr, err)
	}
	timeout := time.Duration(req.TimeoutMs) * time.Millisecond
	httpReq := network.HTTPRequest{
		Method:           req.Method,
		URL:              req.URL,
		Headers:          req.Headers, //nolint:staticcheck // forward deprecated Headers for backward compatibility; request uses MultiHeaders when set
		MultiHeaders:     req.MultiHeaders,
		Body:             req.Body,
		MaxResponseBytes: req.MaxResponseBytes,
		Timeout:          timeout,
	}

	sendResponseTimeout := time.Duration(defaultSendResponseTimeoutMs) * time.Millisecond

	// send response to node async
	h.wg.Go(func() {
		// not cancelled when parent is cancelled to ensure the goroutine can finish
		baseCtx := context.WithoutCancel(ctx)
		httpCtx, httpCancel := context.WithTimeout(baseCtx, timeout)
		defer httpCancel()
		l := logger.With(h.lggr, "requestID", requestID, "method", req.Method, "timeout", req.TimeoutMs)
		var outboundResp gateway_common.OutboundHTTPResponse
		callback := h.createHTTPRequestCallback(httpCtx, requestID, httpReq, req)
		if req.CacheSettings.MaxAgeMs > 0 {
			h.metrics.IncrementCacheReadCount(ctx, h.lggr)
			outboundResp = h.responseCache.Fetch(httpCtx, req, callback, req.CacheSettings.Store)
		} else {
			outboundResp = callback()
			if req.CacheSettings.Store {
				h.responseCache.Set(req, outboundResp)
			}
		}
