### Title
Missing zero-address check in `grant_role` lets an admin brick DefaultAdmin control by granting the role to `Address::ZERO` - (File: `crates/common/precompiles/src/b20_asset/logic/v1.rs` and the v2/`b20_stablecoin` equivalents)

### Summary
`grant_role`/`grant_role_unchecked` in the B-20 asset and stablecoin precompile logic accept any `account`, including `Address::ZERO`, and unconditionally set the role bit and bump `role_member_count` when granting `DefaultAdmin`.

### Finding Description
`grant_role` performs authorization checks (role-admin mutation availability, role-admin match) but never validates that `account != Address::ZERO` [3](#0-2) . `grant_role_unchecked` then sets `has_role(role, account) = true` and, for `DefaultAdmin`, increments `role_member_count` without any address validation [4](#0-3) . `role_member_count` is the sole signal `revoke_role`/`renounce_role` use to block removing the last `DefaultAdmin` [2](#0-1) . A count inflated by a zero-address grant that can never be exercised (no EOA/contract can send a transaction as `Address::ZERO`) defeats this safety check.

### Impact Explanation
If the sole `DefaultAdmin` accidentally (or is tricked into) calling `grantRole(DefaultAdmin, address(0))`, `role_member_count` becomes 2. The real admin can then revoke or renounce their own `DefaultAdmin` role because the "last admin" guard sees a count of 1 remaining (the phantom zero-address holder), even though no address can ever act as that admin. The token permanently loses all admin-gated capability (pause control, seize/mint policy administration, further role management), which is a permanent freezing of governance/funds-management functions — analogous in root cause and severity to the referenced `LMPVault::setRewarder` zero-address issue.

### Likelihood Explanation
Requires a privileged `DefaultAdmin`-role caller (or someone with role-admin rights over `DefaultAdmin`) to mistakenly pass `Address::ZERO` as the grantee — same low-but-nonzero likelihood profile as the original report (accidental misconfiguration by a privileged actor), with high impact once triggered.

### Recommendation
Add a zero-address check in `grant_role`/`grant_role_unchecked` (and the analogous v2/`b20_stablecoin` copies) that reverts with an `InvalidReceiver`/`InvalidAccount`-style error when `account == Address::ZERO`, mirroring the `NonZeroAddress` wrapper already used elsewhere in this crate for transfer parties [5](#0-4) .

### Proof of Concept
1. Deploy a B-20 asset/stablecoin token; `ADMIN` holds `DefaultAdmin` (`role_member_count(DefaultAdmin) == 1`).
2. `ADMIN` calls `grantRole(DefaultAdmin, address(0))` — succeeds, no zero check; `role_member_count(DefaultAdmin)` becomes 2, `has_role(DefaultAdmin, address(0)) == true`.
3. `ADMIN` calls `renounceRole(DefaultAdmin, ADMIN)` (or `revokeRole` targeting itself) — the `LastAdminCannotRenounce` check compares `role_member_count == 1`, which is now false (it's 2), so the call succeeds.
4. Token now has zero addresses capable of exercising `DefaultAdmin` (the only holder is `Address::ZERO`, which can never sign a transaction), permanently locking all admin-gated functionality.

//! Non-zero address wrapper for B-20 transfer parties.

use alloy_primitives::Address;

/// Error returned when constructing a [`NonZeroAddress`] from [`Address::ZERO`].
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ZeroAddressError;

/// An [`Address`] proven not to be the zero address.
///
/// Construction fails with [`ZeroAddressError`] for the zero address. Callers map that into the
/// appropriate typed revert (`InvalidReceiver`, `InvalidSender`, …). The private field preserves
/// the invariant: there is no public way to wrap [`Address::ZERO`].
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct NonZeroAddress(Address);

impl NonZeroAddress {
    /// Returns a non-zero address, or [`ZeroAddressError`] if `address` is zero.
    pub fn new(address: Address) -> Result<Self, ZeroAddressError> {
        if address == Address::ZERO { Err(ZeroAddressError) } else { Ok(Self(address)) }
    }

    /// Returns the wrapped address.
    pub const fn get(self) -> Address {
        self.0
    }
}
