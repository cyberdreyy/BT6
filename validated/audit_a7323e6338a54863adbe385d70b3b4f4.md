### Title
Zip-slip path traversal in `ExtractZipArchive` allows `lchmod` (and file writes) outside the extraction root - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` in `helpers/archives/zip_extract.go` uses `zip.File.Name` directly as a filesystem path for extraction (`extractZipFile`) and, in a second pass, for permission changes via `lchmod(file.Name, file.Mode())` (`helpers/archives/os_unix.go`). No component of the code validates that `file.Name` stays within the extraction working directory, so an archive entry named e.g. `../victim/file` is written/chmod'd relative to the current working directory, not confined to it.

### Finding Description
`ExtractZipArchive` iterates `archive.File` twice [1](#0-0) . In the first pass, `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on entry type, `os.Mkdir`/`os.Symlink`/`os.OpenFile` — all using the raw, attacker-controlled `file.Name` [2](#0-1) . In the second pass, `lchmod(file.Name, file.Mode())` calls `unix.Fchmodat(unix.AT_FDCWD, name, ...)` with the same unsanitized name [3](#0-2) .

The only path-related check performed anywhere in this flow is `errorIfGitDirectory`, which only rejects paths whose first cleaned component is `.git` — it does not detect or reject `..` traversal segments [4](#0-3) . There is no `filepath.Clean`/prefix check confining `file.Name` to the extraction root, and no rejection of absolute paths or `..` components in `extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, or the `lchmod` pass.

`ExtractZipArchive` is called from `ExtractZipFile`, which is invoked by the cache extractor command (`CacheExtractorCommand`) and legacy zip extractor used for job artifacts/cache restoration [5](#0-4) . Because cache/artifact archives are downloaded from job-influenced storage locations and their internal zip entry names are fully attacker-controlled (a job can push a cache/artifact zip with crafted `FileHeader.Name` values), a malicious job can supply a zip whose entries contain `../` segments. During extraction (which runs relative to the job's designated cache/build directory), those entries escape that directory. In the second pass, `lchmod` will then apply `Fchmodat` to that escaped, attacker-chosen path — chmod'ing (and via pass one, overwriting/creating) files outside the intended per-job workspace, e.g. another job's checkout or a shared cache directory sibling path, if reachable from the extraction CWD and permissions allow it.

### Impact Explanation
This allows a job-controlled archive to write files and alter permissions (`chmod`) at paths outside the intended extraction root, reachable via relative traversal from the current working directory used during extraction. In a shared-filesystem environment (e.g. shell executor, or any executor where multiple jobs' build/cache directories share a common parent that the job process can traverse to), this lets an unprivileged pipeline author tamper with sibling job/cache directories' file permissions and content, which is exactly the cross-tenant file-integrity violation described in the invariant "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
Exploitability depends entirely on filesystem layout at extraction time: the extraction happens relative to the process's current working directory, and the traversal must resolve to a path the runner process has permission to write. On shared-host shell/no-isolation executors where multiple jobs' cache/build directories are siblings under a common parent writable by the job user, this is directly reachable and repeatable — the attacker fully controls the zip contents (cache/artifact archives are round-tripped through the job) and no code path sanitizes `..` segments before extraction or `lchmod`.

### Recommendation
Before processing each `zip.File` in `ExtractZipArchive`/`extractZipFile`, resolve `filepath.Join(extractionRoot, file.Name)` and verify (using `filepath.Clean` and a prefix check, or `filepath.Rel` + reject if the result starts with `..`) that the resulting path stays within the intended extraction root; reject (or skip with a warning, consistent with the existing `errorIfGitDirectory` pattern) any entry whose name is absolute or contains a `..` component that escapes the root. Apply the same validation before the `lchmod` pass, since it iterates the same `archive.File` list independently.

### Proof of Concept
Go test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_RejectsPathTraversal(t *testing.T) {
    tmpRoot := t.TempDir()
    extractDir := filepath.Join(tmpRoot, "job-cache")
    require.NoError(t, os.MkdirAll(extractDir, 0o755))
    victimDir := filepath.Join(tmpRoot, "victim")
    require.NoError(t, os.MkdirAll(victimDir, 0o755))
    victimFile := filepath.Join(victimDir, "file")
    require.NoError(t, os.WriteFile(victimFile, []byte("original"), 0o644))

    // Build a zip with a traversal entry: "../victim/file"
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    w, _ := zw.CreateHeader(&zip.FileHeader{Name: "../victim/file", Method: zip.Deflate})
    w.Write([]byte("PWNED"))
    zw.Close()

    origWD, _ := os.Getwd()
    defer os.Chdir(origWD)
    require.NoError(t, os.Chdir(extractDir))

    reader, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)
    _ = ExtractZipArchive(reader) // currently succeeds and overwrites victimFile

    content, _ := os.ReadFile(victimFile)
    // Expected (fixed) behavior: victim file untouched
    assert.Equal(t, []byte("original"), content, "zip entry escaped extraction root and overwrote sibling file")
}
```
Expected assertion after a fix: extraction/`lchmod` for `../victim/file` is rejected/skipped and `victimFile` content/permissions remain unchanged; before the fix, the content becomes `"PWNED"`, proving the escape.

```go
func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
```
