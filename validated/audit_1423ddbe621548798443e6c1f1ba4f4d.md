### Title
Unprotected Chainlink `latestRoundData` calls in `getChainlinkPrice()` can permanently brick epoch lifecycle and freeze all user funds - (File: contracts/strategies/usual/IdleUsualStrategy.sol)

### Summary
`IdleUsualStrategy.getChainlinkPrice()` performs a raw external call to the USD0++ Chainlink aggregator (`USD0ppOracle.latestRoundData()`) with no try/catch and a hard `require` on a 24-hour staleness window. This function is invoked inside the epoch state machine — `IdleCDOUsualVariant.startEpoch()` and `IdleCDOUsualVariant.stopEpoch()` — and in `initialize()` and `setOraclePrice()`. If the feed is blocked by Chainlink's multisig, paused, or simply misses one 24h heartbeat, `stopEpoch()` always reverts, leaving `isEpochRunning == true` and `allowAAWithdraw == allowBBWithdraw == false` forever — all senior and junior tranche funds frozen.

### Finding Description
The analog of the Blueberry `ChainlinkAdapterOracle.getPrice()` DoS maps directly onto the Usual variant's oracle surface:

- `getChainlinkPrice()` calls `IOracle(USD0ppOracle).latestRoundData()` directly; a revert in the aggregator (feed blocked/deprecated) or `updatedAt <= block.timestamp - 24 hours` reverts the whole transaction — there is no fallback and no try/catch (`contracts/strategies/usual/IdleUsualStrategy.sol:164-172`).
- `IdleCDOUsualVariant.stopEpoch()` must call `_strategy.getChainlinkPrice()` before re-enabling withdrawals (`contracts/IdleCDOUsualVariant.sol:77-83`). During a running epoch, deposits are paused and both `allowAAWithdraw`/`allowBBWithdraw` are `false` (`startEpoch`, lines 52-55). The only exit path for tranche holders is the owner calling `stopEpoch()`.
- `setOraclePrice()` additionally calls `IUSD0pp(USD0pp).getFloorPrice()` unprotected (line 159), so even the manual-owner fallback cannot bypass a broken feed path, and `initialize()` itself calls `getChainlinkPrice()` (line 71), bricking deployment if the feed is down.
- `TranchesChainlinkOracle.latestRoundData()` similarly returns `cdo.virtualPrice(...)` raw, so any revert in `virtualPrice` propagates to Morpho liquidations relying on it.

### Impact Explanation
Temporary-to-permanent freezing of the entire vault TVL. While the epoch is running, no `withdrawAA`/`withdrawBB` is possible; if the USD0++ feed is blocked or stays stale, `stopEpoch()` can never succeed and 100% of `lastNAVAA + lastNAVBB` remains locked in the strategy (loss = full contract value for the duration of the outage; permanent if the feed is abandoned). This matches the accepted impact class "temporary freezing / permanent freezing of funds" with quantified loss equal to total NAV.

### Likelihood Explanation
Not attacker-triggered, but externally triggered: Chainlink multisigs can block feeds at will (per the cited OZ guidance), and the tight `updatedAt > block.timestamp - 24 hours` check means a single missed heartbeat — which the code comments acknowledge is the feed's actual heartbeat — is sufficient to DoS `stopEpoch()` until the next update. No privileged misbehavior is required.

### Recommendation
Wrap the feed read defensively and decouple epoch settlement from a live oracle read:

```solidity
function getChainlinkPrice() public view returns (uint256) {
    try IOracle(USD0ppOracle).latestRoundData() returns (
        uint80, int256 answer, uint256, uint256 updatedAt, uint80
    ) {
        require(updatedAt > block.timestamp - 24 hours, "Stale price");
        require(answer > 0, "Negative price");
        return uint256(answer) * 1e10;
    } catch {
        return oraclePrice; // last good stored price
    }
}
```

Also allow `stopEpoch` to accept an explicit price (or fall back to `oraclePrice`/`getFloorPrice`) so the owner can always settle the epoch, and apply the same try/catch to the `getFloorPrice()` call in `setOraclePrice`.

    vm.warp(block.timestamp + 7 days);

    vm.prank(aaHolder);
    vm.expectRevert();
    cdo.withdrawAA(0);

```text
  function stopEpoch() external {
    _checkOnlyOwner();
    // if the epoch is not running we revert
    require(isEpochRunning && block.timestamp >= epochEndDate, "9");

    IdleUsualStrategy _strategy = IdleUsualStrategy(strategy);
    // we fetch and set oracle price for reference
    uint256 _oraclePrice = _strategy.getChainlinkPrice();
    _strategy.setOraclePrice(_oraclePrice);

    // we unpause redeems only
    allowAAWithdraw = true;
    allowBBWithdraw = true;
    // set epoch as not running
    isEpochRunning = false;

    // if usd0++ price is 1$ or more then junior doesn't owe anything to senior
    if (_oraclePrice >= oneToken) {
      return;
    }
    // if price is less than 1$ we calculate how much junior should give to senior considering 1 usd0++ = 1$
    // eg price is 0.9$, lastNAVAA is 100 usd0++ (ie 90$) and targetAATVL should be 100$ so 100 / 0.9 = 111.11 usd0++
    // so we do lastNAVAA * (1 / oraclePrice) = 100 * (1 / 0.9) = 111.11
    uint256 targetAATVL = lastNAVAA * oneToken / _oraclePrice;

    // we increase the lastNAVAA so that the senior tranche is at par with 1$
    lastNAVAA += targetAATVL - lastNAVAA;

    // this will cause the next updateAccounting call to account a loss which will be absorbed by the junior tranche
    _updateAccounting();    
```
