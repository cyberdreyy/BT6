### Title
Arbitrary ERC4626 vault accepted in permissionless `deployRevolvingCreditVault` gives attacker full control of pooled lender funds and epoch interest pricing - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory.deployRevolvingCreditVault` is callable by anyone and accepts a fully caller-supplied `programmableBorrowerParams.vault` address. The only validation is `IERC4626(_vault).asset() == underlyingToken` inside `ProgrammableBorrower.initialize`. Once deployed, the `ProgrammableBorrower` unconditionally deposits all pooled lender funds into this arbitrary contract via `_depositToVault` on `onStartEpoch`, and `IdleCDOEpochVariant` treats the vault-dependent `totalInterestDueNow()` as the single source of truth for epoch interest. A malicious ERC4626 can keep deposited funds, refuse withdrawals to permanently freeze or force default of the facility, and fabricate share valuations to corrupt tranche pricing — the same failure mode as UNCX's arbitrary position manager. There is no whitelist or vetting of the vault contract.

### Finding Description
- `deployRevolvingCreditVault` is `external` with no access control: any EOA can deploy a revolving credit vault and pass any address as `ProgrammableBorrowerParams.vault` [1](#0-0) .
- `ProgrammableBorrower.initialize` only checks `_vault != 0` and `IERC4626(_vault).asset() == underlying`; the vault is then granted unlimited underlying allowance [2](#0-1) .
- At every `startEpoch`, `onStartEpoch` calls `_depositToVault(underlyingToken.balanceOf(address(this)), 0)`, pushing the entire pool balance (all lender deposits routed through the strategy) into the attacker-controlled contract [3](#0-2) [4](#0-3) .
- `IdleCDOEpochVariant._resolveStopEpochInterest` unconditionally returns `IProgrammableBorrower(_borrower()).totalInterestDueNow()` in programmable mode, and `totalInterestDueNow` derives entirely from `vault.convertToAssets(vault.balanceOf(this))` (`_currentVaultAssets` / `_vaultNetInterest`) — a view the malicious vault fully controls [5](#0-4) [6](#0-5) .
- `onStopEpoch` relies on `vault.withdraw(shortfall, ...)`; a vault that reverts forces `StopEpochVaultLiquidityUnavailable`, and a vault that simply never returns assets makes the subsequent `transferFrom` fail, driving the pool into default while funds sit in the malicious contract [7](#0-6) .
- `setVault` is owner/manager-gated, so post-deploy the vault cannot be swapped by an attacker — but the initial deployment already hands complete execution control to the arbitrary contract, exactly like UNCX's per-lock `positionManager` parameter.

### Impact Explanation
A lender (KYC'd or not, depending on `keyring` param) depositing AA tranches into such a vault loses funds the moment the first epoch starts: `depositAA → startEpoch → onStartEpoch → vault.deposit(all)` transfers the entire pool balance to the attacker's contract, which can keep the tokens (the `safeApprove` allowance already granted means it can also pull any residual). Alternatively the vault can simply revert on `withdraw`/`redeem`, permanently freezing lender principal and wedging the pool into `StopEpochVaultLiquidityUnavailable`/default. The invariant broken is solvency/fair redemption: real underlying leaves the system while tranche holders hold claims it can never satisfy. Loss = 100% of deposited pool funds.

### Likelihood Explanation
This requires victims to deposit into an attacker-deployed vault instance. Because the deployer also chooses `implementation`, `manager`, `borrower`, and `keyring`, a sophisticated depositor can in principle audit the parameters — but the factory emits a uniform `CreditVaultDeployed` event and there is no registry, whitelist, or implementation pinning distinguishing legitimate deployments from malicious ones, so a spoofed deployment is indistinguishable on-chain except by inspecting init params. This mirrors the UNCX scenario (users opted into pools configured with arbitrary manager contracts); the recommended remediation there — whitelisting the trusted external contract — applies here identically. Likelihood is medium-low (social/trapping component), but the technical flaw (unvalidated arbitrary external contract holding all funds and pricing all yield) is unconditional once deposits exist.

### Recommendation
Maintain an owner-controlled whitelist of permitted ERC4626 vaults (and ideally of `implementation` addresses) in `IdleCreditVaultFactory`, reverting in `deployRevolvingCreditVault` when `programmableBorrowerParams.vault` is not whitelisted — analogous to the UNCX fix of whitelisting position managers. Additionally, `ProgrammableBorrower` should defensively verify share/asset consistency after `vault.deposit` (e.g., snapshot `convertToAssets(balanceOf(this))` delta ≈ deposited amount) so a vault that accepts deposits but returns worthless shares fails fast before funds accumulate.

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
    epochWithdrawnFromVault = 0;
    epochAccountingActive = true;
    emit EpochAccountingStarted(startAssets);
  }

  function onStopEpoch(uint256 _amountRequired, bool _isRequestingAllFunds) external nonReentrant returns (bool success) {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // if we want to close the pool and the borrower still owes any amount, consider it a failure and let IdleCDO handle it as a default instead of a close. 
    if (_isRequestingAllFunds && (borrowerPrincipal != 0 || borrowerInterestDebt != 0 || borrowerInterestAccrued != 0)) {
      return false;
    }

    uint256 onHand = underlyingToken.balanceOf(address(this));
    if (_amountRequired > onHand) {
      uint256 shortfall = _amountRequired - onHand;
      // If the vault shares do not economically cover the shortfall, let IdleCDO's later
      // transferFrom fail and use the existing default path. Only an otherwise-covered ERC4626
      // withdrawal failure should make stopEpoch retryable.
      if (shortfall > _currentVaultAssets()) return true;
      try vault.withdraw(shortfall, address(this), address(this)) returns (uint256 shares) {
        if (epochAccountingActive) {
          epochWithdrawnFromVault += shortfall;
        }
        emit WithdrawnFromVault(shortfall, shares, address(this));
      } catch {
        revert StopEpochVaultLiquidityUnavailable();
      }
    }

    // `totalInterestDueNow()` was already read by IdleCDO before calling this hook, so once the
    // stop flow begins we can clear the previous carry and snapshot the remaining vault sleeve
    // as the baseline for measuring buffer-period vault PnL before the next epoch starts.
    bufferedVaultDelta = 0;
    bufferInterest = 0;
    bufferStartVaultAssets = _currentVaultAssets();

    // Stop reserving epoch-end withdraw liquidity once IdleCDO has started the stop flow.
    epochPendingWithdraws = 0;
    epochAccountingActive = false;
    emit EpochAccountingStopped();
    success = true;
  }

  function totalInterestDueNow() external view returns (uint256) {
    (uint256 vaultInterest, uint256 loss) = _vaultNetInterest();
    uint256 totalGain = vaultInterest + borrowerInterestAccruedNow() + bufferInterest;
    return totalGain > loss ? totalGain - loss : 0;
  }

  /// @notice Compute the net vault delta split into interest and loss (mutually exclusive).
  function _vaultNetInterest() internal view returns (uint256 interest, uint256 loss) {
    if (!epochAccountingActive) return (0, 0);
    uint256 earnedAssets = _currentVaultAssets() + epochWithdrawnFromVault;
    uint256 principalAssets = epochStartVaultAssets + epochDepositedToVault;
    int256 netDelta = bufferedVaultDelta + int256(earnedAssets) - int256(principalAssets);
    if (netDelta > 0) {
      interest = uint256(netDelta);
    } else {
      loss = uint256(-netDelta);
    }
  }
