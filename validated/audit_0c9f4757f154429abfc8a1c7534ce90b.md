### Title
`MetaOracle::combine` uses oracle-derived `max_timestamp` instead of current clock time, allowing arbitrarily stale price data to pass the freshness filter — (File: `crates/sui-oracle/move/oracle/sources/meta_oracle.move`)

---

### Summary

The `oracle::meta_oracle` framework package ships a `combine()` function that is supposed to reject oracle data older than `time_window_ms`. Instead of comparing each data point's timestamp against the current wall-clock time (`sui::clock::Clock`), it computes a floor from the last oracle's own stored timestamp. When all contributing oracles have stopped updating, every data point still passes the freshness check, and arbitrarily stale prices are silently accepted as trusted.

---

### Finding Description

`MetaOracle<T>` carries a field `max_timestamp: u64` that is updated in `add_simple_oracle`:

```move
// meta_oracle.move line 38-44
public fun add_simple_oracle<T: copy + drop + store>(
    meta_oracle: &mut MetaOracle<T>, oracle: &SimpleOracle
) {
    let oracle_data = oracle::simple_oracle::get_latest_data(oracle, meta_oracle.ticker);
    if (option::is_some(&oracle_data)) {
        meta_oracle.max_timestamp = data::timestamp(option::borrow(&oracle_data));
    };
    vector::push_back(&mut meta_oracle.oracle_data, oracle_data);
}
``` [1](#0-0) 

`max_timestamp` is overwritten on every call, so after N oracles are added it holds the timestamp of the **last** oracle added, not the maximum and not the current time.

Neither `add_simple_oracle` nor `combine` accepts a `&Clock` argument. The `sui::clock` module is imported by `simple_oracle.move` for `submit_data` but is never threaded into the read path. [3](#0-2) 

**Two compounding defects:**

1. `max_timestamp` is the *last-added* oracle's timestamp, not the maximum across all oracles. If oracles are added in ascending timestamp order the variable is correct by accident; in any other order it is wrong.
2. Even if it were the true maximum, comparing oracle timestamps against each other (relative consistency) is not the same as comparing them against the current time (absolute freshness). If every oracle stopped publishing one hour ago and their timestamps are within `time_window_ms` of each other, `min_timestamp` is also one hour old and every data point passes.

The `trusted_fx` usage pattern in the test module illustrates the intended consumer:

```move
let mut meta_oracle = meta_oracle::new<DecimalValue>(3, 60000, string::utf8(b"SUIUSD"));
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle1);
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle2);
meta_oracle::add_simple_oracle(&mut meta_oracle, oracle3);
let trusted_data = meta_oracle::median(meta_oracle);   // no Clock, no wall-time check
``` [4](#0-3) 

A developer reading the API sees `time_window_ms` and reasonably concludes the framework enforces that prices are no older than that window relative to *now*. The implementation does not deliver that guarantee.

---

### Impact Explanation

Any on-chain package that calls `meta_oracle::median()` to price assets, compute collateral ratios, or settle positions will silently consume prices that may be hours or days old whenever the oracle operators' off-chain uploader stops running. The `TrustedData<T>` returned carries no staleness flag; downstream code has no way to detect the problem. This constitutes harmful smart-contract behavior (High/Medium under the allowed impact gate).

---

### Likelihood Explanation

The off-chain uploader (`crates/sui-oracle/src/lib.rs`) is a separate process. Any network partition, process crash, or key rotation that interrupts it causes the on-chain `SimpleOracle` objects to stop advancing. Because the freshness check is self-referential, the stale state is invisible to `combine()`. An ordinary user (unprivileged caller) can trigger a transaction that reads the stale price at any time after the uploader stops; no special privilege is required.

---

### Recommendation

1. Add `clock: &Clock` parameters to both `add_simple_oracle` and `combine` (or to `median`/`mean` wrappers).
2. In `combine`, replace the self-referential floor with an absolute floor:
   ```move
   let now_ms = sui::clock::timestamp_ms(clock);
   let min_timestamp = now_ms - time_window_ms;
   ```
3. Fix `add_simple_oracle` to track the true maximum across all added oracles rather than overwriting on each call, so the relative-consistency check is also correct when it is used alongside the absolute check.

---

### Proof of Concept

**Setup:**
- Deploy the `oracle` package.
- Call `simple_oracle::submit_data` at time T=1000 ms for three `SimpleOracle` objects, recording price = 100.
- Wait until the current clock is T=1000000 ms (≈16 minutes later); the uploader has stopped.

**Trigger (any unprivileged user):**
```move
// time_window_ms = 60000 (60 s)
let mut meta = meta_oracle::new<DecimalValue>(3, 60000, utf8(b"SUIUSD"));
meta_oracle::add_simple_oracle(&mut meta, oracle1); // max_timestamp ← 1000
meta_oracle::add_simple_oracle(&mut meta, oracle2); // max_timestamp ← 1000
meta_oracle::add_simple_oracle(&mut meta, oracle3); // max_timestamp ← 1000
// min_timestamp = 1000 - 60000 → underflow or 0 (u64 wraps)
// every oracle timestamp (1000) > 0 → all three pass
let trusted = meta_oracle::median(meta);            // returns price = 100
``` [5](#0-4) 

**Observed:** `median()` returns the 16-minute-old price of 100 without error.

**Expected:** The call should abort because all data is older than `time_window_ms` relative to the current clock.

**Note on underflow:** When `max_timestamp (1000) < time_window_ms (60000)`, the subtraction `max_timestamp - time_window_ms` underflows a `u64`, wrapping to a very large value. This makes `min_timestamp` enormous, causing *all* oracles to be filtered out and the `assert!(vector::length(&values) >= threshold)` to abort — a denial-of-service rather than stale-data acceptance in this edge case. For the more realistic scenario where `max_timestamp > time_window_ms` (oracles were updated at least once after the window duration has elapsed since genesis), the stale-data acceptance path is reached. [6](#0-5)
