## Analysis

The External Report describes a gas-griefing/race-condition class of bug: an unprivileged client can cheaply flood a system with unvalidated requests, forcing many privileged actors (routers) to redundantly perform costly work with no proof-of-legitimacy or rate limiting on the request itself.

A structural analog exists in chainlink's Gateway `capabilities` handler used for legacy Web API trigger requests.

### Vulnerable Path

`ProcessRequest` in `core/services/gateway/gateway.go` decodes and (for legacy DON-ID requests) calls `msg.Validate()` before dispatching to `HandleLegacyUserMessage`: [1](#0-0) 

`Message.Validate()` only checks field lengths and that *some* valid ECDSA signature exists — it recovers whatever address signed the payload via `ExtractSigner`, but never checks that address against any allowlist: [2](#0-1) 

Any unprivileged internet client can generate a throwaway private key, sign an arbitrary payload, and produce a message that passes `Validate()` — there is no proof of identity, stake, or fee tied to the sender.

That validated message is then routed to `HandleLegacyUserMessage`, which explicitly documents the missing check with `// TODO: apply allowlist and rate-limiting here`, and then unconditionally broadcasts the message to **every member of the DON**: [3](#0-2) 

This is confirmed by the handler's own test suite, which contains an explicit unresolved TODO acknowledging the gap: [4](#0-3) 

By contrast, the newer `OutgoingConnectorHandler.HandleGatewayMessage` path does implement per-sender and global incoming rate limiting before processing: [5](#0-4) 

showing that rate-limiting/allowlisting is a known, applied mitigation elsewhere in the gateway — but is missing specifically in the legacy capabilities handler's broadcast path.

Downstream, actual workflow triggering does check `allowedSenders` per-workflow before firing an event to a node's capability channel: [6](#0-5) 

so this analog does **not** grant unauthorized workflow execution — the impact is limited to unauthenticated amplification/resource-consumption (each single client-forged message is broadcast to and processed — JSON unmarshal, timestamp check, method check, request construction, network send — by every node in the DON, with zero cost or rate limit imposed on the sender at the gateway ingress). This is a DoS/amplification concern rather than a fund-movement or authorization bypass, which is a weaker match to the report's most severe consequences (free/failed transactions draining router gas), but it is the same root-cause pattern: missing validation/rate-limiting before an unprivileged request causes privileged infrastructure to perform work at victim expense.

### Title
Missing allowlist/rate-limiting on legacy Gateway webhook-trigger messages allows unauthenticated broadcast amplification across an entire DON - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The Gateway's legacy `HandleLegacyUserMessage` path accepts any message that carries a valid-format ECDSA signature (which anyone can self-generate) and, per an explicit unresolved TODO, performs no allowlist or rate-limiting check before broadcasting the message to every node in the target DON.

### Finding Description
`Message.Validate()` [2](#0-1)  only verifies structural correctness and that a signature recovers to *an* address — not that the address is authorized. `HandleLegacyUserMessage` [3](#0-2)  then broadcasts the request to `h.donConfig.Members` unconditionally, with the comment `// TODO: apply allowlist and rate-limiting here` marking the gap. This mirrors the reported bug class: absence of validation prior to performing costly, fan-out work triggered by an unprivileged, cheaply-forged request.

### Impact Explanation
An unauthenticated client can cheaply mint new signing keys and continuously submit messages that pass `Validate()`, forcing the Gateway to broadcast to and force processing on every node in a DON with no per-sender/global rate limit at this ingress path (unlike the `OutgoingConnectorHandler` path which does rate-limit [5](#0-4) ). This is a resource-amplification/DoS vector against the DON's capability-processing nodes, though the per-workflow `allowedSenders` check in `trigger.go` [6](#0-5)  prevents unauthorized workflow execution itself.

### Likelihood Explanation
High — the path is internet-reachable via the Gateway's HTTP-facing `ProcessRequest`, requires no privileged credentials, and the missing check is explicitly acknowledged as unimplemented in both the handler and its test file.

### Recommendation
Implement sender allowlisting and per-sender/global rate limiting in `HandleLegacyUserMessage` before broadcasting to DON members, consistent with the pattern already used in `OutgoingConnectorHandler.HandleGatewayMessage`.

### Proof of Concept
Not independently executable from static analysis alone; the report is supported by the code paths cited above (missing allowlist check at `handler.go:384`, corresponding TODO in `handler_test.go:365`, and the signature-only `Validate()` in `message.go`).

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
