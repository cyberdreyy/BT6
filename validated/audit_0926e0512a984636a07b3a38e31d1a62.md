## Analysis

The Malt `RewardThrottle` bug is a class of **shared-state overwrite race**: a privileged call intends to durably record a fact (`activeEpoch` progression), but an unprivileged/uncoordinated call writing to the *same key* can run first (or later) and stomp the intended record, silently invalidating a legitimate prior decision.

The stacks-signer codebase has a structurally identical pattern in the **reorg-permit bookkeeping**: `superseded_tenures` is a table keyed *only* by the superseded tenure's `consensus_hash`, written with `INSERT OR REPLACE`, so only the single most-recently-recorded permit for a given superseded tenure survives. [1](#0-0) 

This record is written every time any single sortition (one miner winning one slot, requiring no majority of signers) reorgs a tenure that qualifies under the "poorly timed" rule in `check_parent_tenure_choice`: [2](#0-1) 

`record_superseded_tenure` performs the write: [3](#0-2) 

Later, a signer's willingness to sign a block that conflicts with an earlier signature it placed depends on whether the *recorded* permit still stands, checked solely against the *single latest* `superseded_by` sortition for that consensus hash: [4](#0-3) [5](#0-4) 

### The analog

1. Tenure A is legitimately reorged by tenure B (a single miner's sortition), satisfying the poor-timing rule. `mark_tenure_superseded(A, ..., superseded_by=B)` is recorded — this is the intended, "populateFromPreviousThrottle"-equivalent write establishing that signatures over A must no longer block B.
2. Before B is fully confirmed/settled, another single-slot miner produces sortition C that also reorgs past A (and B), and C likewise satisfies the poor-timing rule (e.g., because B itself is still an empty/very young tenure). `check_parent_tenure_choice`/`record_superseded_tenure` runs again and calls `mark_tenure_superseded(A, ..., superseded_by=C)` — this **overwrites** the row for A, exactly like `fillInEpochGaps` overwriting/invalidating `populateFromPreviousThrottle`'s intended state.
3. If C's own sortition is subsequently orphaned by an ordinary burnchain fork (a routine, single-miner-triggerable event this doc explicitly treats as commonplace — see `reorg_permit_stands`'s 404 handling), `reorg_permit_stands` for A now evaluates C's (orphaned) sortition instead of B's (possibly still-canonical) one, and returns `false`.
4. The originally-valid permit for B is lost. `conflict_still_blocks`/`get_signed_conflicts` now treats the signer's earlier signature over A as still live and blocking, causing the signer to refuse to sign the legitimate, still-canonical block in tenure B — a liveness wedge: the signer is stuck refusing to sign a valid, permitted block because an unrelated, later-orphaned single-slot miner's reorg attempt clobbered the durable permit record for the same superseded tenure.

This matches the required impact category: a signer wedged into never signing a valid block due to loss of a durably-recorded exclusion, triggered solely by ordinary single-miner/gossip activity (no signer majority, no key compromise).

### Title
Reorg-permit record for a superseded tenure can be overwritten by a later, unrelated reorg attempt, wedging a signer out of signing an already-permitted block - (File: `stacks-signer/src/signerdb.rs`)

### Summary
`SignerDb::mark_tenure_superseded` stores at most one "who superseded me" record per superseded tenure (`PRIMARY KEY (consensus_hash)`, `INSERT OR REPLACE`). Any single sortition that reorgs a qualifying (empty/poorly-timed) tenure overwrites this record, discarding the identity of a previous, still-relevant permitting tenure.

### Finding Description
`check_parent_tenure_choice` records a superseded-tenure permit every time a new tenure's parent choice reorgs a qualifying prior tenure [6](#0-5) , via `record_superseded_tenure` → `SignerDb::mark_tenure_superseded` [3](#0-2) . The DB write is keyed only by the superseded tenure's consensus hash and unconditionally replaces any prior row [1](#0-0) . Consequently, if tenure A is legitimately superseded by tenure B, and later a different, also-qualifying tenure C reorgs past A again, the stored permit silently changes from "A is excluded because B is canonical" to "A is excluded because C is canonical" — with no accumulation, versioning, or precedence rule protecting B's earlier, potentially still-valid permit.

`reorg_permit_stands` (used by `conflict_still_blocks`/`get_signed_conflicts` at pre-commit/signing time) only consults this single latest record [4](#0-3) [5](#0-4) . If the tenure that most recently overwrote the record (C) is itself later orphaned by an ordinary burnchain fork — which the documentation explicitly treats as a routine event requiring no privileged actor — `reorg_permit_stands` returns `false`, and the conflict over A is restored as live, even though B's original, independently valid permit is what should still be governing.

### Impact Explanation
This is a liveness wedge (High): the signer, having already signed a block in tenure A, becomes unable to sign the block in tenure B that it was correctly permitted to sign, because a later and unrelated single-miner reorg attempt (C) clobbered the durable record naming B as the permitting tenure. The signer is stuck treating A as a live, blocking conflict until A's own signature times out — a self-inflicted delay caused purely by record-overwrite ordering, not by any property of B's own validity.

### Likelihood Explanation
Only a single sortition win (one miner, one slot) is needed to trigger the overwrite, and only an ordinary burnchain fork is needed to orphan the overwriting tenure afterward — both are routine occurrences already discussed at length in the codebase's own documentation of reorg handling, not privileged or majority-signer actions. No signer collusion or key compromise is required.

### Recommendation
Do not use a single-row-per-superseded-tenure model that unconditionally replaces the permitting record. Either (a) retain history of all permits per superseded tenure and treat the conflict as excluded if *any* recorded permitting sortition is still canonical, or (b) only allow overwriting the `superseded_by_*` fields for a given superseded tenure if the new permitting sortition is confirmed to build on/supersede the previously recorded permitting sortition, so an unrelated later reorg attempt cannot erase a still-valid earlier permit.

### Proof of Concept
1. Tenure A produces zero blocks (or a poorly-timed first block).
2. Tenure B's sortition reorgs past A; `check_parent_tenure_choice` records `mark_tenure_superseded(A, ..., superseded_by=B)`. A signer that had signed a block in A now signs B's block because `reorg_permit_stands` returns true for A's conflict.
3. Before B is confirmed, tenure C's sortition also reorgs past A (satisfying the same poor-timing rule, e.g., because B is itself still empty), calling `mark_tenure_superseded(A, ..., superseded_by=C)` again — overwriting B's record via `INSERT OR REPLACE` [7](#0-6) .
4. A subsequent burnchain fork orphans C's sortition (B remains/returns to canonical). At the next pre-commit/signing evaluation for a block in B, `reorg_permit_stands` checks C's (now-orphaned) burn hash, returns false, and A's conflict is restored as live [8](#0-7) .
5. The signer now refuses to sign B's block, wedged by a record overwrite it has no way to detect or recover from except waiting for A's own signature-freshness timeout.

    pub fn check_parent_tenure_choice(
        &self,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        first_proposal_burn_block_timing: &Duration,
    ) -> Result<bool, SignerChainstateError> {
        // if the parent tenure is the last sortition, it is a valid choice.
        // if the parent tenure is a reorg, then all of the reorged sortitions
        //  must either have produced zero blocks _or_ produced their first (and only) block
        //  very close to the burn block transition.
        if self.prior_sortition == self.parent_tenure_id {
            return Ok(true);
        }
        info!(
            "Most recent miner's tenure does not build off the prior sortition, checking if this is valid behavior";
            "sortition_state.consensus_hash" => %self.consensus_hash,
            "sortition_state.prior_sortition" => %self.prior_sortition,
            "sortition_state.parent_tenure_id" => %self.parent_tenure_id,
        );

        let tenures_reorged =
            client.get_tenure_forking_info(&self.parent_tenure_id, &self.prior_sortition)?;
        if tenures_reorged.is_empty() {
            warn!("Miner is not building off of most recent tenure, but stacks node was unable to return information about the relevant sortitions. Marking miner invalid.");
            return Ok(false);
        }

        // this value *should* always be some, but try to do the best we can if it isn't
        let sortition_state_received_time =
            signer_db.get_burn_block_receive_time(&self.burn_block_hash)?;

        // Track which tenures are superseded by the reorg, then mark them in
        // the DB after the reorg is permitted.
        let mut superseded_tenures = Vec::new();
        for tenure in tenures_reorged.iter() {
            if tenure.consensus_hash == self.parent_tenure_id {
                // this was a built-upon tenure, no need to check this tenure as part of the reorg.
                continue;
            }

            // disallow reorg if more than one block has already been signed
            let globally_accepted_blocks =
                signer_db.get_globally_accepted_block_count_in_tenure(&tenure.consensus_hash)?;
            if globally_accepted_blocks > 1 {
                warn!(
                    "Miner is not building off of most recent tenure, but a tenure they attempted to reorg has already more than one globally accepted block.";
                    "parent_tenure" => %self.parent_tenure_id,
                    "last_sortition" => %self.prior_sortition,
                    "violating_tenure_id" => %tenure.consensus_hash,
                    "violating_tenure_first_block_id" => ?tenure.first_block_mined,
                    "globally_accepted_blocks" => globally_accepted_blocks,
                );
                return Ok(false);
            }

            let Some(first_block_mined) = &tenure.first_block_mined else {
                // The node saw no blocks in this tenure, so the reorg takes nothing away from
                // the canonical chain. We may still hold a signature over a block in it that
                // the node has never seen (a block we accept locally is not handed to the node
                // until the whole signer set has signed it), so the reorg must still be
                // recorded if it is permitted.
                superseded_tenures.push(tenure);
                continue;
            };
            let Some(local_block_info) =
                signer_db.get_first_approved_block_in_tenure(&tenure.consensus_hash)?
            else {
                warn!(
                    "Miner is not building off of most recent tenure, but a tenure they attempted to reorg has already mined blocks, and there is no local knowledge for that tenure's block timing.";
                    "parent_tenure" => %self.parent_tenure_id,
                    "last_sortition" => %self.prior_sortition,
                    "violating_tenure_id" => %tenure.consensus_hash,
                    "violating_tenure_first_block_id" => %first_block_mined,
                );
                return Ok(false);
            };

            let checked_proposal_timing = if let Some(sortition_state_received_time) =
                sortition_state_received_time
            {
                // how long was there between when the proposal was received and the next sortition started?
                let proposal_to_sortition = if let Some(approved_at) =
                    local_block_info.approved_time
                {
                    sortition_state_received_time.saturating_sub(approved_at)
                } else {
                    info!("We did not sign over the reorged tenure's first block, considering it as a late-arriving proposal");
                    0
                };
                if Duration::from_secs(proposal_to_sortition) < *first_proposal_burn_block_timing {
                    info!(
                        "Miner is not building off of most recent tenure. A tenure they reorg has already mined blocks, but the block was poorly timed, allowing the reorg.";
                        "parent_tenure" => %self.parent_tenure_id,
                        "last_sortition" => %self.prior_sortition,
                        "violating_tenure_id" => %tenure.consensus_hash,
                        "violating_tenure_first_block_id" => %first_block_mined,
                        "violating_tenure_proposed_time" => local_block_info.proposed_time,
                        "new_tenure_received_time" => sortition_state_received_time,
                        "new_tenure_burn_timestamp" => self.burn_header_timestamp,
                        "first_proposal_burn_block_timing_secs" => first_proposal_burn_block_timing.as_secs(),
                        "proposal_to_sortition" => proposal_to_sortition,
                    );
                    superseded_tenures.push(tenure);
                    continue;
                }
                true
            } else {
                false
            };

            warn!(
                "Miner is not building off of most recent tenure, but a tenure they attempted to reorg has already mined blocks.";
                "parent_tenure" => %self.parent_tenure_id,
                "last_sortition" => %self.prior_sortition,
                "violating_tenure_id" => %tenure.consensus_hash,
                "violating_tenure_first_block_id" => %first_block_mined,
                "checked_proposal_timing" => checked_proposal_timing,
            );
            return Ok(false);
        }
        // Every reorged tenure cleared the rules, so the reorg is permitted.
        for tenure in superseded_tenures {
            self.record_superseded_tenure(signer_db, tenure);
        }
        Ok(true)
    }

    /// Whether a reorg permit recorded for this conflict's tenure still stands.
    ///
    /// `check_parent_tenure_choice` records a permit when the reorg-timing rules sanction a
    /// later tenure replacing what the conflict's tenure built (see
    /// [`SignerDb::mark_tenure_superseded`]). A standing permit excludes the conflict entirely:
    /// our signature must not stand in the way of a replacement we sanctioned. But the permit
    /// is only as alive as the sortition it was granted to: if a burnchain fork orphaned the
    /// permitting sortition, the reorg we sanctioned can no longer happen, and the record must
    /// not keep suppressing the conflict.
    ///
    /// A false 404 here (e.g. from a node still catching up) only restores a conflict the
    /// permit could have excluded, which at worst delays the replacement, so unlike
    /// `conflict_still_blocks` no tip-height guard is needed. A node error voids the permit for
    /// the same reason: blocking is the direction that can be taken back.
    fn reorg_permit_stands(
        &self,
        stacks_client: &StacksClient,
        conflict: &SignedConflictInfo,
    ) -> bool {
        let Some(superseded_by) = &conflict.superseded_by else {
            return false;
        };
        match stacks_client.get_sortition_by_burn_hash(&superseded_by.burn_block_hash) {
            Ok(_) => true,
            Err(ClientError::RequestFailure(reqwest::StatusCode::NOT_FOUND)) => {
                info!("{self}: The tenure we permitted to reorg a conflicting block's tenure was itself orphaned by a burnchain fork. The permit no longer excludes the conflict.";
                    "conflicting_consensus_hash" => %conflict.consensus_hash,
                    "superseded_by_consensus_hash" => %superseded_by.consensus_hash,
                    "superseded_by_burn_block_hash" => %superseded_by.burn_block_hash,
                );
                false
            }
            Err(e) => {
                warn!("{self}: Failed to check whether the sortition that permitted a reorg is still canonical: {e:?}. Treating the permit as void.";
                    "conflicting_consensus_hash" => %conflict.consensus_hash,
                    "superseded_by_consensus_hash" => %superseded_by.consensus_hash,
                );
                false
            }
        }
    }
