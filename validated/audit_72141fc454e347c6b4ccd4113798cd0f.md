### Title
Multisig executes requests below the intended confirmation threshold because confirmations from removed members are never purged - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
When a member/key is removed from the multisig via `DeleteKey` (in `multisig`) or `DeleteMember` (in `multisig2`), the contract only deletes **requests originally created** by that key/member. It never scans other still-pending requests to strip out **confirmations** that the removed key/member had already cast on them. Those stale confirmations remain counted toward `num_confirmations` in `confirm()`, so a request can later be executed using fewer live-member confirmations than the configured threshold — exactly the "recorded claim vs. current entitlement" binding break described in the report (there, an arbitrary `strategyId` bypassed a per-strategy check; here, a stale confirmation from a de-authorized signer bypasses the per-request confirmation-threshold check).

### Finding Description
`confirm()` in both contracts only checks that the current caller hasn't already confirmed, then compares the *size* of the stored confirmations set against `num_confirmations`: [1](#0-0) 

The removal logic executed when a key is deleted (`DeleteKey`) only purges requests whose *creator* (`signer_pk`) matches the removed key — it does not touch the `confirmations` sets of other requests that this key had merely confirmed: [2](#0-1) 

The same gap exists in `multisig2`'s `delete_member`, which filters only on `r.member == member` (the request creator) before clearing confirmations: [3](#0-2) 

`assert_valid_request` / `confirm` never re-validate that every public key/member already present in a request's `confirmations` set is still a current member at confirmation or execution time: [4](#0-3) [5](#0-4) 

As a result, the binding the contract is supposed to enforce — `count(live-member confirmations on request R) >= num_confirmations` — is broken. What actually gets counted is `count(all confirmations ever cast on request R, including from now-removed keys) >= num_confirmations`.

### Impact Explanation
This lets a multisig request execute (transfers, `AddKey`/`AddMember`, `DeployContract`, `FunctionCall`, etc.) with fewer genuinely-authorized signers than `num_confirmations` requires, because one or more of the counted confirmations came from a key/account that was later removed from the multisig. This directly matches the "Critical" impact bucket: a multisig request executed below threshold, potentially moving NEAR/wNEAR or deploying arbitrary code with insufficient authorization.

### Likelihood Explanation
This requires no special privilege beyond being (or having been) a legitimate multisig member/key holder at some point — no foundation, owner, or out-of-scope actor is needed. It is triggered by an entirely ordinary operational sequence: a member confirms a pending request, the group later removes that member for routine security hygiene (e.g., suspected key compromise, employee offboarding), and the stale confirmation silently remains valid. Given that key rotation/removal is a normal multisig operation, this is a realistic, moderate-likelihood scenario, not a contrived edge case.

### Recommendation
When removing a key (`DeleteKey`) or member (`DeleteMember`), iterate over **all** pending requests' `confirmations` sets (not just requests created by that key/member) and remove the departing key/member's entry from each. Alternatively, at `confirm()`/execution time, filter the stored confirmations set to only those keys/members that are still valid before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize `multisig` with 4 keys `K1..K4` and `num_confirmations = 3`.
2. `K1` calls `add_request` to create request `R` (a `Transfer`), 0 confirmations.
3. `K2` calls `confirm(R)` → confirmations = `{K2}` (1/3).
4. Separately, the group creates and confirms (with `K1`, `K3`, `K4`) a request that executes `DeleteKey { public_key: K2 }` to revoke `K2` (e.g., because `K2`'s device was lost). This executes via `execute_request`, calling `promise.delete_key(K2)`; per [2](#0-1)  it only removes requests created *by* `K2`; `R` (created by `K1`) is untouched and its confirmations set still contains `K2`.
5. `K1` calls `confirm(R)` → confirmations = `{K2, K1}` (2/3).
6. `K3` calls `confirm(R)` → confirmations = `{K2, K1, K3}` reaches 3 → `execute_request(R)` runs the transfer.
7. The transfer executed with only 2 currently-valid signers (`K1`, `K3`) plus one stale, revoked signer (`K2`), even though the policy requires 3 live confirmations.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
