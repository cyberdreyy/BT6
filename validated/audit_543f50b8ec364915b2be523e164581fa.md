### Title
Pausing the vault (`whenNotPaused` on `MultiDepositorVault.exit`) blocks all user redemptions/withdrawals, freezing funds - ([File: v3/src/core/MultiDepositorVault.sol])

### Summary
`MultiDepositorVault.exit()` is gated by the `whenNotPaused` modifier inherited from `BaseVault`/OpenZeppelin `Pausable`. [1](#0-0)  Since `ProvisionerV2.redeem`/`withdraw`/`cancelRequest`/`solveRequestsVault` all ultimately call `IMultiDepositorVault.exit(...)` to burn units and release tokens, any pause of the vault (triggered via `BaseVault.pause()`, callable by an auth-holder or guardian) makes it impossible for ordinary users to redeem their units, cancel pending requests, or receive refunds until the vault is unpaused. [2](#0-1)  This mirrors the OmniPool `repay()` pattern: an emergency-pause mechanism unconditionally blocks the user-side "exit" function, rather than only blocking guardian-driven state changes.

### Finding Description
- `BaseVault.pause()` sets the `Pausable` paused flag and is callable by `onlyAuthOrGuardian` (owner/auth or any registered guardian). [2](#0-1) 
- `MultiDepositorVault.enter()` and `exit()`, the only functions that mint/burn vault units and move tokens in/out of the vault, are both decorated with `whenNotPaused`. [3](#0-2) 
- `ProvisionerV2.redeem()` and `withdraw()` (the synchronous user-facing redemption paths) call `_syncRedeem`, which ultimately calls `MultiDepositorVault.exit`; these functions only check `solvingNotPaused` and `PRICE_FEE_CALCULATOR.isVaultPaused` in some paths, but the `exit()` call itself will still revert due to `whenNotPaused` on the vault regardless of those other checks. [4](#0-3) 
- `ProvisionerV2.cancelRequest()` (self-cancel of a pending redeem/deposit request, an ordinary-user action with no auth requirement other than `msg.sender == request.user`) also calls `MultiDepositorVault.exit` for the redeem-cancellation-fee burn path and, via `_clearHashAndTransferRefund`, for transferring back escrowed vault units on refund — both revert while the vault is paused. [5](#0-4) 
- The broken invariant: pausing the vault (an administrative safety action) should not simultaneously disable the user's ability to exit/cancel and recover already-escrowed funds — exactly the invariant broken by OmniPool's `whenNotPaused repay()`.

### Impact Explanation
While the vault is paused, ordinary users cannot call `redeem`, `withdraw`, or `cancelRequest` to retrieve tokens/units — this is a freeze of user funds and unclaimed refunds for the duration of the pause. This matches Immunefi's "temporary freezing of user funds" Medium-severity category. Unlike the OmniPool lending scenario there is no on-chain liquidation of collateral triggered by the freeze in this codebase (no borrow/liquidation mechanics exist for vault shares), so the impact is limited to temporary fund/refund freezing rather than confiscation of collateral.

### Likelihood Explanation
No malicious actor is required: any legitimate pause of the vault (owner or guardian, an expected day-to-day operational action, e.g. in response to a guardian compromise or oracle issue) will, as an unavoidable side effect, block all user redemptions, withdrawals, and self-cancellations until unpause. The precondition (vault paused) is a normal, expected operational state, not a rare edge case, making this readily reachable.

### Recommendation
Do not gate the user-exit path (`MultiDepositorVault.exit`) with the same `whenNotPaused` modifier as `enter`. Split pause semantics: pausing should stop new deposits/guardian submissions (`enter`, `submit`) but the `exit` function (and the `ProvisionerV2` redemption/cancellation flows that route through it) should remain callable so users can retrieve funds even during a pause, analogous to how OmniPool removed `whenNotPaused` from `repay()`.

### Proof of Concept
1. Deploy `MultiDepositorVault` + `ProvisionerV2` per the standard test harness; have a user deposit tokens via `ProvisionerV2.deposit`, receiving vault units.
2. Have the owner/guardian call `BaseVault.pause()` on the vault.
3. As the user, call `ProvisionerV2.redeem(token, unitsIn, minTokensOut, receiver)` — assert it reverts with `Pausable: paused` (bubbled up from `MultiDepositorVault.exit`), even though the user holds sufficient units and price data is fresh.
4. Similarly, have a user with a pending async redeem request call `ProvisionerV2.cancelRequest(token, request)` while the vault is paused — assert it reverts for the same reason, freezing already-escrowed vault units that should be returnable.
5. Unpause and confirm the same calls succeed, demonstrating the freeze was solely caused by the `whenNotPaused` modifier on `exit`.

    function enter(address sender, IERC20 token, uint256 tokenAmount, uint256 unitsAmount, address recipient)
        external
        whenNotPaused
        onlyProvisioner
    {
        // Interactions: pull tokens from the sender
        if (tokenAmount > 0) token.safeTransferFrom(sender, address(this), tokenAmount);

        // Effects: mint units to the recipient
        _mint(recipient, unitsAmount);

        // Log the enter event
        emit Enter(sender, recipient, token, tokenAmount, unitsAmount);
    }

    /// @inheritdoc IMultiDepositorVault
    function exit(address sender, IERC20 token, uint256 tokenAmount, uint256 unitsAmount, address recipient)
        external
        whenNotPaused
        onlyProvisioner
    {
        // Effects: burn units from the sender
        _burn(sender, unitsAmount);

        // Interactions: transfer tokens to the recipient
        if (tokenAmount > 0) token.safeTransfer(recipient, tokenAmount);

        // Log the exit event
        emit Exit(sender, recipient, token, tokenAmount, unitsAmount);
    }

    /// @inheritdoc IProvisionerV2
    function cancelRequest(IERC20 token, RequestV2 calldata request) external nonReentrant {
        // Requirements: self-cancel caller must be request user
        require(msg.sender == request.user, Aera__CallerIsNotRequestUser());

        if (_isRequestTypeDeposit(request.requestType)) {
            // Requirements: deposit cancellation toggle must be enabled
            require(_depositCancellationsEnabled, Aera__DepositRequestCancellationDisabled());

            uint256 refundAmount = request.tokens;
            // Requirements: pre-deadline self-cancel applies cancellation fee
            if (block.timestamp < request.deadline) {
                uint256 cancellationFee = _computeDepositCancellationFeeTokens(token);
                // Requirements: cancellation fee cannot exceed escrowed amount
                require(cancellationFee <= refundAmount, Aera__CancellationFeeExceedsRequestAmount());
                if (cancellationFee != 0) {
                    unchecked {
                        // unchecked: safe because cancellationFee <= refundAmount is enforced above
                        refundAmount -= cancellationFee;
                    }
                    // Interactions: transfer cancellation fee to vault
                    token.safeTransfer(MULTI_DEPOSITOR_VAULT, cancellationFee);
                }
            }

            // Effects + interactions: clear hash, emit refund event, and transfer net token amount with fallback
            _clearHashAndTransferRefund(token, request, msg.sender, refundAmount, token);
        } else {
            // Requirements: redeem cancellation toggle must be enabled
            require(_redeemCancellationsEnabled, Aera__RedeemRequestCancellationDisabled());

            // Interactions: compute redeem request size in numeraire with protocol-favoring rounding
            uint256 requestNumeraire = PRICE_FEE_CALCULATOR.convertUnitsToNumeraire(
                MULTI_DEPOSITOR_VAULT, request.units, Math.Rounding.Ceil
            );
            // Requirements: redeem self-cancel must not exceed configured cap
            require(requestNumeraire <= _redeemCancellationCapNumeraire, Aera__RequestAmountExceedsRefundCap());

            uint256 refundAmount = request.units;
            // Requirements: pre-deadline self-cancel applies cancellation fee
            if (block.timestamp < request.deadline) {
                uint256 cancellationFee = _computeRedeemCancellationFeeUnits(requestNumeraire);
                // Requirements: cancellation fee cannot exceed escrowed amount
                require(cancellationFee <= refundAmount, Aera__CancellationFeeExceedsRequestAmount());
                if (cancellationFee != 0) {
                    unchecked {
                        // unchecked: safe because cancellationFee <= refundAmount is enforced above
                        refundAmount -= cancellationFee;
                    }
                    // Interactions: burn cancellation fee units from provisioner escrow
                    IMultiDepositorVault(MULTI_DEPOSITOR_VAULT)
                        .exit(address(this), token, 0, cancellationFee, address(this));
                }
            }

            // Effects + interactions: clear hash, emit refund event, and transfer net unit amount with fallback
            _clearHashAndTransferRefund(token, request, msg.sender, refundAmount, IERC20(MULTI_DEPOSITOR_VAULT));
        }
    }

        external
        anyoneButVault

    {

        // Requirements: check that the caller does not have its units locked
