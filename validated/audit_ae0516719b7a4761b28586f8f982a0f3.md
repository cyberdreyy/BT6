### Title
Hard-coded 24h staleness threshold equal to the feed heartbeat can brick `stopEpoch`, freezing all tranche withdrawals - ([File: contracts/strategies/usual/IdleUsualStrategy.sol])

### Summary
`IdleUsualStrategy.getChainlinkPrice()` reverts with `"Stale price"` whenever the USD0++ Chainlink feed's `updatedAt` is older than exactly 24 hours, but the feed itself only guarantees a 24-hour heartbeat (plus 50 bps deviation). Any keeper/update delay past the heartbeat — even seconds — makes `IdleCDOUsualVariant.stopEpoch()` and `startEpoch()` revert, with no fallback path. During a running epoch deposits are paused and both `allowAAWithdraw`/`allowBBWithdraw` are false, so every tranche holder's funds remain locked until the feed happens to update.

### Finding Description [1](#0-0) 

`getChainlinkPrice()` enforces `require(updatedAt > block.timestamp - 24 hours, "Stale price")`. The code comment itself acknowledges the feed has "a 24 hours hearbeat" and updates only on a 50 bps deviation. Setting the accepted staleness window equal to the feed's own heartbeat means there is zero margin: if Chainlink's updater is delayed by any amount (congestion, keeper lag, deviation threshold interaction), the call reverts.

This call sits unconditionally on the critical epoch-transition paths:

- `stopEpoch()` calls `_strategy.getChainlinkPrice()` before re-enabling withdrawals (`allowAAWithdraw = true; allowBBWithdraw = true`) [2](#0-1) . During the running epoch, `startEpoch` sets both flags to `false` and pauses the contract [3](#0-2) , so no AA or BB holder can withdraw while the epoch is running.
- `startEpoch()` also calls `getChainlinkPrice()` for `priceAtStartEpoch` [4](#0-3) .
- `initialize()` calls `getChainlinkPrice()` too, so the strategy cannot even be deployed/initialized while the feed is older than 24h [5](#0-4) .

There is a manual override `setOraclePrice()` callable by owner or the CDO [6](#0-5) , but it is useless as a mitigation for `stopEpoch`: the function calls `getChainlinkPrice()` *first* and reverts before reaching `setOraclePrice`. There is no code path to stop an epoch without a fresh Chainlink round.

### Impact Explanation
Temporary freezing of all user funds in the vault. While the epoch is running and `updatedAt` is older than 24h, `stopEpoch` cannot be executed, `allowAAWithdraw`/`allowBBWithdraw` remain `false`, and the contract remains paused — so 100% of deposited underlying is inaccessible to every tranche holder. The freeze lasts as long as the feed stays stale, which is entirely outside the protocol's control. This is the same bug class as the referenced report: a staleness `maxLatency` that is too tight relative to the oracle's real update cadence causes reverts on a user-facing path.

### Likelihood Explanation
No attacker action is required; the trigger is ordinary oracle behavior. A 24-hour heartbeat feed routinely approaches its staleness boundary — the window between "feed fresh enough" and "epoch end" narrows continuously, and any delay in the Chainlink update (or an epoch ending shortly after the last heartbeat tick) puts the revert condition in effect. Since the revert depends on timing alignment between `epochEndDate` and the feed's update schedule, occurrences are expected rather than exceptional over many epochs.

### Recommendation
Allow a staleness window strictly larger than the feed's maximum heartbeat, e.g. `updatedAt > block.timestamp - 25 hours` or `36 hours` (or make the threshold configurable), so a single missed/delayed heartbeat does not revert. Additionally, provide a fallback in `stopEpoch` — e.g. catch the revert and let the owner supply the price via `setOraclePrice` (already floor-bounded by `getFloorPrice()`), so the epoch can always be closed.

### Proof of Concept
Foundry fork test (mainnet, `USD0ppOracle` at `0xFC9e30Cf89f8A00dba3D34edf8b65BCDAdeCC1cB`):

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/IdleCDOUsualVariant.sol";
import "../../contracts/strategies/usual/IdleUsualStrategy.sol";

contract StaleOracleStopsEpoch is Test {
  IdleCDOUsualVariant cdo;      // deployed Usual-variant CDO
  IdleUsualStrategy strategy;   // its strategy
  address owner;                // cdo owner (honest)

  function test_stopEpochRevertsOnStaleFeed() public {
    // 1. Epoch is running: owner called startEpoch(7 days)
    vm.prank(owner);
    cdo.startEpoch(7 days);

    // 2. Warp to epoch end AND to a point where the Chainlink
    //    USD0++ feed's updatedAt is > 24h old (heartbeat delay).
    (, , , uint256 updatedAt, ) =
      IOracle(strategy.USD0ppOracle()).latestRoundData();
    vm.warp(updatedAt + 24 hours + 1);

    // 3. Owner (honest) tries to stop the epoch to re-enable withdrawals.
    vm.prank(owner);
    vm.expectRevert("Stale price");
    cdo.stopEpoch();

    // 4. Withdrawals stay disabled -> all AA/BB funds locked.
    assertFalse(cdo.allowAAWithdraw());
    assertFalse(cdo.allowBBWithdraw());
  }
}
```

The same revert can be shown for `startEpoch` and for `IdleUsualStrategy.initialize` by warping past `updatedAt + 24 hours`.

    // Oracle it is not updated frequently but only if there is a deviation of 50 bips from
