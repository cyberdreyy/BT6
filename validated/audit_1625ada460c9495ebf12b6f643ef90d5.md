## Analog Found

### Title
Global signer-state agreement threshold rounds down instead of up, letting sub-70% weight lock in a "current miner" / protocol-version / tx-replay view used to gate block signing — (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` implements the "≥70% supermajority" check with floor (truncating) division, while the consensus-critical equivalent, `NakamotoBlockHeader::compute_voting_weight_threshold`, ceils the same 70% ratio. The two are supposed to encode the identical supermajority concept, but for any `total_weight` where `total_weight * 7` is not a multiple of 10, `reached_agreement` accepts a strictly smaller vote weight than the "real" 70% threshold used for signature verification. Because `reached_agreement` gates what the signer network treats as the globally-agreed current miner/tenure, protocol version, and tx-replay set — all of which feed directly into whether a signer accepts or rejects a block proposal — a sub-supermajority set of signer weight can cause `determine_global_state()` to converge on a view that the "hard" 70% threshold would not actually support.

### Finding Description
The chainstate-level supermajority threshold is defined with an explicit ceiling: [1](#0-0) 

This ceiled threshold is what `verify_signer_signatures` uses to validate a block's actual signer signatures, and it is also what `stacks-signer/src/v0/signer.rs` uses for pre-commit and signature-tallying decisions (`min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)`): [2](#0-1) 

By contrast, the "global agreement" primitive used by the *state-machine* layer — which decides the canonical current miner, active protocol version, burn view, and tx-replay set that every signer capitulates to — uses plain floor division with no ceiling adjustment: [3](#0-2) 

`reached_agreement` is the sole gate for `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (including the tx-replay-set/majority-prefix logic): [4](#0-3) [5](#0-4) 

`determine_global_state()`'s output is not cosmetic — it is the authoritative `current_miner` (tenure_id/consensus_hash/parent_tenure_id) that `GlobalStateView::check_proposal` uses to accept or reject a block proposal in the post-global-state-activation signing path: [6](#0-5) [7](#0-6) 

So the same conceptual "70% of weight agree" check is implemented with two different rounding directions in two places that are supposed to be equivalent: the hard signature-verification path ceils (requires *at least* `ceil(0.7*T)`), while the soft state-agreement path floors (accepts as low as `floor(0.7*T)`). For any `total_weight` where `total_weight*7 % 10 != 0`, this creates a window of weight where `reached_agreement` reports "supermajority reached" while `compute_voting_weight_threshold` would not consider the same weight sufficient to seat a signature-verified block.

### Impact Explanation
This breaks the intended equality between "aggregated agreement weight" and "verified acceptance weight" for the state-machine views that gate signing. A signer whose `determine_global_state()` locks onto a `current_miner`/tenure view backed by only `floor(0.7*T)` weight (not the true `ceil(0.7*T)` supermajority) will use that view to validate/accept subsequent block proposals via `check_proposal` — i.e. it treats a proposal as coming from the "canonical" miner and proceeds to the signing checks based on a weaker-than-designed agreement bar. Because different signers can straddle this window differently (depending on gossip timing/StackerDB propagation), this is a concrete path to divergent global-state views across honestly-participating signers: some signers settle on miner/tenure view A at exactly the floor threshold while a true ceil-70% supermajority never actually forms behind it, and other, slower-updating signers retain a different view. This matches the "signer wedged acting on a stale/incorrect consensus view" class of High-impact issue: signers can get stuck disagreeing about the canonical miner/tenure/replay-set because the "agreement" check that is supposed to mirror the hard 70% signature threshold is systematically weaker.

The magnitude of the gap is `1` unit of signer weight at most, so its practical severity scales inversely with `total_weight` (negligible for large reward-slot totals, up to ~9% of weight for very small totals, e.g. `total_weight=11` → floor gives 7/11≈63.6% while the ceil threshold requires 8/11≈72.7%).

### Likelihood Explanation
This does not require attacker control of a majority or another signer's key — it is a pre-existing rounding defect triggered purely by the natural distribution of honest `StateMachineUpdate` gossip and any `total_weight` value not evenly divisible per the 7/10 ratio. It is reachable any time signers evaluate `determine_global_state`/`determine_global_burn_view`/`determine_latest_supported_signer_protocol_version`, i.e. on every block-proposal validation cycle post-global-state activation (`check_block_against_global_state`). No special crafted message beyond normal state-machine gossip is needed; the discrepancy is deterministic given the weight distribution.

### Recommendation
Make `reached_agreement` use the same ceiling logic as `NakamotoBlockHeader::compute_voting_weight_threshold` (i.e., `>= ceil(total_weight * NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD / 10)`) so that "global agreement" and "verified block-signature threshold" enforce identical supermajority weight. Ideally, factor out a single shared threshold-computation helper used by both `stackslib`'s `compute_voting_weight_threshold` and `libsigner`'s `GlobalStateEvaluator` to prevent this class of divergence from being reintroduced.

### Proof of Concept
1. Construct a reward set with `total_weight = 11` (e.g., 11 signers of weight 1, or any equivalent weight distribution summing to 11).
2. Have exactly 7 units of weight (63.6%) broadcast `StateMachineUpdate` messages agreeing on `current_miner = A` (tenure/consensus_hash `T_A`), while the remaining 4 units of weight (36.4%) do not.
3. Call `GlobalStateEvaluator::determine_global_state()` on a signer observing this weight distribution — per [8](#0-7) , `reached_agreement(7)` returns `true` (`7 >= 11*7/10 = 7`), so the evaluator settles on miner `A`.
4. Compare against `NakamotoBlockHeader::compute_voting_weight_threshold(11)` per [9](#0-8) , which returns `8` — i.e., the actual signature-verification path (and the pre-commit/signature-tally path in `stacks-signer/src/v0/signer.rs`) would require 8 units of weight, not 7, to consider the same 70% bar crossed.
5. The signer now treats miner `A`'s tenure (`T_A`) as canonical for `check_proposal` purposes based on only 63.6% agreement, a full "unit" of weight short of the 72.7% that the hard signing threshold requires for the same reward set — demonstrating the aggregated-weight-vs-verified-accept-weight mismatch.

    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
