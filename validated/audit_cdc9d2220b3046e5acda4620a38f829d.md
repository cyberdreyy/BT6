### Title
Stale `BlockValidationResponse` Causes Signer to Broadcast a Real Signature Over an Already Globally-Rejected/Decided Block — ([File: stacks-signer/src/signerdb.rs], [File: stacks-signer/src/v0/signer.rs])

### Summary
`BlockInfo::mark_pre_committed` and `BlockInfo::mark_locally_accepted` set the block's `valid`/`signed_self` fields as unconditional side effects *before* calling `move_to()`, which is the function that actually enforces the state machine. When `move_to()` fails (because the block already reached a terminal state through another path), the side-effect fields are **not rolled back**, and the calling code in `signer.rs` treats "already reached consensus" as an acceptable reason to keep going rather than abort — ultimately producing and broadcasting a real ECDSA signature over a block whose formal state transition to "signed" was rejected by the very state machine meant to gate it.

### Finding Description
`BlockInfo::mark_pre_committed`: [1](#0-0) 

`BlockInfo::mark_locally_accepted`: [2](#0-1) 

Both functions mutate `self.valid` / `self.signed_self` / `self.approved_time` **unconditionally**, then call `self.move_to(state)`, whose legality is governed by `check_state`: [3](#0-2) 

`check_state` explicitly forbids `PreCommitted` from anything but `Unprocessed`, and forbids `LocallyAccepted` once the block is `GloballyAccepted`/`GloballyRejected`. So when a delayed `BlockValidationResponse` arrives for a block that the signer already learned is globally decided through another path (a peer's pre-commit/acceptance gossip, or the node's `NewBlock` event advancing `mark_globally_accepted`/marking a sibling `mark_globally_rejected`), `mark_pre_committed`/`mark_locally_accepted` will **return `Err`**, but `valid` and `signed_self` have already been stamped.

The caller ignores this properly in the "reject" branch, but in `handle_block_validate_ok` the error is deliberately swallowed whenever consensus was already reached: [4](#0-3) 

This falls through to `insert_block` (persisting the now-poisoned `valid = Some(true)`), `send_block_pre_commit`, and `handle_block_pre_commit` for ourselves — even though the block never legitimately reached `PreCommitted`.

`handle_block_pre_commit`'s only gate for proceeding toward a signature is the (now falsely-set) `valid` flag: [5](#0-4) 

If the pre-commit/threshold and chainstate re-checks (section 5 of the flow, `check_block_against_signer_db_state`, `get_signed_conflicts`) don't happen to catch this particular already-decided block (the docs themselves note the re-check "only ever looks at one tenure," so a sibling decided in a different tenure is invisible to it), execution reaches the unconditional sign step: [6](#0-5) 

Here, `mark_locally_accepted(false)` is called again; if the block is already `GloballyRejected`/`GloballyAccepted`, `move_to` fails again — but the code only *warns* when consensus was not reached, and otherwise proceeds unconditionally to `create_block_acceptance` (a real signature over the block header) and `send_block_response`, broadcasting that signature regardless of the failed transition.

This is the direct analog of the NFT report's root cause: a durable flag (`valid`/`signed_self`, analogous to `_nftContractToTokenIdToFirstSaleCompleted`) is set as a side effect of an operation whose real gating step (the state-machine `move_to`, analogous to the correctly-ordered fund distribution) can fail — and the caller's "it's fine, we already reached a decision elsewhere" shortcut lets the side effect stand and cascade into producing a genuine, broadcast artifact (a cryptographic signature) that should never have been produced for that block.

### Impact Explanation
This lets a signer broadcast a real signature acceptance for a block it never validly transitioned into a signed state — i.e., a signature attached to a block already decided as rejected (or conflicting with an already-accepted sibling) by the signer's own bookkeeping. That is a "rejection recounted as an acceptance" / a signature over a block the signer's own state machine says is invalid or conflicting, directly matching the Critical impact bucket in scope.

### Likelihood Explanation
Triggering requires only ordinary asynchronous message timing that a lone miner plus normal gossip can create: submit a block for validation, let the validation response be delayed (busy node, slow RPC), while the block (or a competing sibling at the same height/tenure) is resolved to a terminal global state via other signers' gossip or the node's own `NewBlock` event. No majority of signers, no other signer's key, and no auth-token access is needed — only the pre-existing race between the signer's node-validation round trip and the rest of the signer set's/its own node's block-decision events.

### Recommendation
- Make `mark_pre_committed` and `mark_locally_accepted` transactional: only stamp `valid`/`approved_time`/`signed_self` if `move_to` succeeds (check the state transition first, or roll back the fields on `Err`).
- In `handle_block_validate_ok` and the pre-commit sign path, treat a failed `move_to` as authoritative: never proceed to `send_block_pre_commit`/`create_block_acceptance`/`send_block_response` when the state transition itself was rejected, even if `has_reached_consensus()` is true for a *different* reason.
- Add a regression test that delivers a `BlockValidationResponse::Ok` for a block after it has already been marked `GloballyRejected` (or after a sibling at the same height was marked `GloballyAccepted`) and assert no signature is created or broadcast.

### Proof of Concept
1. Signer submits block `B` (hash `h1`) for validation (`submit_block_for_validation`); `block_info.valid == None`, `state == Unprocessed`.
2. Before the node answers, the signer set gossips enough pre-commits/acceptances for a competing block at the same height (or its own tenure's real tip advances), and the signer's `NewBlock`/pre-commit handling calls `mark_globally_rejected()` on `h1`'s tracked `BlockInfo` (state → `GloballyRejected`; `valid` remains `None` since `mark_globally_rejected` never touches it) — see [7](#0-6) .
3. The delayed `BlockValidationResponse::Ok` for `h1` now arrives. `handle_block_validate_ok` sees `block_info.valid.is_some() == false` (still `None`), passes the syntactic/chainstate checks, and calls `mark_pre_committed()`, which sets `valid = Some(true)` then fails `move_to(PreCommitted)` (prev state `GloballyRejected`).
4. Because `block_info.has_reached_consensus()` is true, the code does not `return`; it inserts the block (now `valid = Some(true)`), sends a pre-commit, and calls `handle_block_pre_commit` on itself — bypassing the `!valid.unwrap_or(false)` guard that should have stopped it.
5. If the pre-commit threshold/conflict checks don't independently catch this (blind spot noted in the code's own comments for cross-tenure siblings), execution reaches the `mark_locally_accepted(false)` call, which again fails its `move_to`, but the code proceeds anyway to `create_block_acceptance` and `send_block_response`, broadcasting a genuine signature over block `h1` after it was already resolved as globally rejected.

Note: full end-to-end confirmation would require tracing `has_reached_consensus()`'s exact definition and `stacks_block_arrival`'s precise sibling-matching logic in `signer_state.rs`, which the available index snippets did not fully expose; the core defect — unconditional side-effect mutation ahead of a fallible `move_to`, and the caller's unconditional fall-through afterward — is directly confirmed in the cited `signerdb.rs`/`signer.rs` code.

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
