### Title
External ERC4626 vault liquidity/health failure permanently or repeatedly blocks `stopEpoch` with no emergency bypass — programmable-borrower pools cannot be stopped or closed while `vault.withdraw`/`convertToAssets` fails (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
`IdleCDOEpochVariant._stopEpoch` calls `IProgrammableBorrower.onStopEpoch`, which must pull liquidity out of an external ERC4626 vault via `vault.withdraw` and value the sleeve via `vault.convertToAssets`. If the external vault is in an emergency state (paused redemptions, drained liquidity, or a reverting valuation view), `stopEpoch` reverts (`StopEpochVaultLiquidityUnavailable`) and no alternative path exists to end the epoch without the vault: `emergencyExitVault` also goes through `vault.redeem`, and `setVault` reverts while `vault.balanceOf(this) != 0`. An unprivileged attacker who can keep the underlying vault illiquid (e.g., borrowing out the liquidity that backs a Morpho-style ERC4626) can repeatedly grief every `stopEpoch` attempt, and the only operator escape (`rescueTokens` on the share token) silently converts a solvent position into a protocol `defaulted` state.

### Finding Description
In `ProgrammableBorrower.onStopEpoch` (line 231), when the requested amount exceeds on-hand cash, the shortfall is withdrawn from the external vault. The guarded early-return only fires when the shares cannot economically cover the shortfall (`shortfall > _currentVaultAssets()` at line 245); otherwise a reverting `vault.withdraw` is caught and re-thrown as `StopEpochVaultLiquidityUnavailable` (lines 246-253). The comment in `IdleCDOEpochVariant` states "Hook reverts bubble so transient ERC4626 liquidity failures can be retried" (`contracts/IdleCDOEpochVariant.sol:396-398`) — but the retry assumes the vault recovers, and nothing else in the flow can proceed:

- `_resolveStopEpochInterest` reads `totalInterestDueNow()` → `_vaultNetInterest()` → `_currentVaultAssets()` → `vault.convertToAssets` (lines 330-334, 545-549). If the vault's valuation view reverts (oracle failure inside the vault, paused markets), `stopEpoch` reverts *before* `onStopEpoch` is even reached, so it cannot be retried at all — it simply always reverts.
- `emergencyExitVault` (line 361) is the nominal emergency response, but it calls `vault.redeem`, which reverts under the same conditions that broke `vault.withdraw`.
- `setVault` (line 158) cannot swap the integration while shares are held: `if (epochAccountingActive || vault.balanceOf(address(this)) != 0) revert NotAllowed();` (line 165) — and `epochAccountingActive` stays `true` precisely because the epoch can't stop.
- The only remaining escape is `rescueTokens` (line 602) pulling the share token out, which makes `_currentVaultAssets()` return 0. That registers the entire position as a vault loss inside `_vaultNetInterest`, makes `shortfall > _currentVaultAssets()` true so `onStopEpoch` returns success, and then the subsequent `transferFrom` in `getFundsFromBorrower` fails because the cash isn't there → `catch` → `_handleBorrowerDefault` (`IdleCDOEpochVariant.sol:501-505`). A solvent pool is pushed into `defaulted = true`, deposits paused, withdraw requests disabled, and lenders are routed through the default/recovery machinery purely because of an external vault failure.

Invariant broken: the pool's epoch state machine has no fault-isolation between itself and the ERC4626 sleeve — the external contract's emergency state propagates into either a permanent epoch-stop revert or a forced (misclassified) borrower default.

### Impact Explanation
- **Temporary freezing (griefable):** an unprivileged attacker with capital can repeatedly drain the liquidity backing the vault's asset (e.g., borrowing available liquidity on the underlying Morpho markets) around each `stopEpoch` call, keeping the epoch un-stoppable and all withdrawal requests unclaimable. There is no rate limit or alternative stop path; the attacker only needs to win each retry.
- **Forced misclassified default / permanent degradation:** if the vault's failure is durable (paused redemption, reverting `convertToAssets`), the only recovery forces `defaulted = true` on a solvent borrower, freezing deposits/requests and routing all lender claims through `finalizeDefault`/recovery instead of normal claims — a strictly worse and slower outcome with loss-socialization mechanics applied to a non-default.
- Loss quantification is bounded by full pool TVL parked in the vault sleeve (all undrawn principal is deposited via `_depositToVault` at `onStartEpoch`, line 216), minus whatever the operator eventually recovers via `rescueTokens` out-of-band.

### Likelihood Explanation
Medium. Triggering does not require any privileged role: any third party able to reduce vault liquidity below the epoch-end shortfall (flash or sustained borrowing of the underlying liquidity, or natural utilization spikes) causes `stopEpoch` to revert. A durable vault emergency (curator pause, oracle stall) additionally breaks the `convertToAssets` view path, which `stopEpoch` reads before the try/catch region, making the freeze unconditional. The design deliberately makes hook reverts bubble for "transient" failures but provides no circuit breaker for durable ones.

### Recommendation
Add a pause/bypass path for the external vault integration, e.g.:
- An owner/manager `forceStopEpoch` variant in `IdleCDOEpochVariant` that skips `onStopEpoch`'s vault withdrawal and pulls only on-hand cash, treating the vaulted remainder as an explicit realized loss (or an explicit pending claim) rather than reverting or silently defaulting.
- A vault-isolation flag on `ProgrammableBorrower` that, when set, makes `_currentVaultAssets()`/`totalInterestDueNow()` use a last-good snapshot and makes `onStopEpoch` return a partial-liquidity result instead of reverting, so `stopEpoch` can settle what is available.
- Extend `setVault`/`emergencyExitVault` with an owner-only "stranded position" mode that accounts for the shares explicitly (e.g., records `strandedVaultShares`) instead of requiring `balanceOf == 0` or a successful `redeem`.

### Proof of Concept
Reproducible on a Foundry mainnet fork using the existing `test/foundry/ProgrammableBorrowerCreditVault.t.sol` harness (which already deploys `ProgrammableBorrower` against the Steakhouse USDC Morpho vault):

```solidity
// test/foundry/VaultEmergencyNoBypass.t.sol
function testStopEpochFrozenByVaultIlliquidity() external {
    uint256 amount = 10_000 * oneScale;
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);
    idleCDO.depositAA(amount);          // lender deposit
    _startEpochAndCheckPrices(0);       // onStartEpoch -> _depositToVault -> all cash into Morpho vault

    // Unprivileged attacker: borrow all available liquidity backing the vault
    // (Morpho markets), such that vault.withdraw(shortfall,..) reverts with
    // insufficient liquidity. Equivalent: vm.mockCallRevert on vault.withdraw.
    _drainMorphoLiquidity();            // attacker EOA, no privileges

    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch());
    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    vm.expectRevert(StopEpochVaultLiquidityUnavailable.selector);
    cdoEpoch.stopEpoch(initialProvidedApr, 0);   // reverts; epoch unstoppable

    // Retry loop: attacker keeps liquidity drained -> every retry reverts.
    // Owner escape routes also fail:
    vm.expectRevert();                   // vault.redeem reverts too
    programmableBorrower.emergencyExitVault(0);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    programmableBorrower.setVault(makeAddr("newVault")); // balanceOf != 0 while epochAccountingActive

    // Only remaining path: rescueTokens pulls share token -> views return 0
    // -> shortfall > _currentVaultAssets() -> transferFrom fails -> catch
    // -> _handleBorrowerDefault: defaulted == true on a solvent pool.
    uint256 shares = morphoVault.balanceOf(address(programmableBorrower));
    programmableBorrower.rescueTokens(address(morphoVault), owner, shares);
    vm.prank(manager);
    cdoEpoch.stopEpoch(initialProvidedApr, 0);
    assertTrue(cdoEpoch.defaulted(), "solvent pool forced into default by external vault failure");
}
```

Note: the exact `_drainMorphoLiquidity()` step depends on the forked vault's market composition; equivalently the test can `vm.mockCallRevert`/`vm.mockCall` `withdraw`/`convertToAssets` to simulate the vault's emergency state, which is sufficient to demonstrate the missing bypass. Uncertainty: whether a *fully durable* revert of `convertToAssets` is realistically reachable on the specific deployed vault — for the pure liquidity-draining variant only `withdraw` needs to revert, which is clearly reachable by an unprivileged borrower of the underlying liquidity.
