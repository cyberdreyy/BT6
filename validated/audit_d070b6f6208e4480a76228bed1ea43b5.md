### Title
GET /v2/bridge_types discloses every configured bridge's `OutgoingToken` to any authenticated low-privilege (view-role) user - ([File: core/web/bridge_types_controller.go])

### Summary
The `BridgeTypesController.Index` handler builds `presenters.BridgeResource` for every stored bridge and returns them verbatim, and `BridgeResource.OutgoingToken` is serialized unconditionally (no `omitempty`, no redaction). The route `GET /v2/bridge_types` is registered with only `paginatedRequest(bt.Index)` — unlike the mutating bridge routes it is not wrapped in `auth.RequiresEditRole`/`auth.RequiresAdminRole` — so any authenticated caller (including a view-role session or API token) can enumerate and harvest every bridge's `OutgoingToken` in one call.

### Finding Description
`core/web/router.go` registers:
```go
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
``` [1](#0-0) 

Only the `authv2` session/token-authentication middleware (`auth.AuthenticateByToken`/`auth.AuthenticateBySession`) gates `Index`/`Show`; it does not require edit or admin role, so a view-role user is sufficient. [2](#0-1) 

`Index` fetches all bridges page by page and converts each into a `BridgeResource` via `presenters.NewBridgeResource`, which copies `OutgoingToken` directly from the DB model: [3](#0-2) [4](#0-3) 

The `BridgeResource` struct tags `OutgoingToken` as `json:"outgoingToken"` with no `omitempty` or redaction, unlike `IncomingToken` which is commented as "only provided when creating a Bridge" but is not actually suppressed on Index/Show either: [5](#0-4) 

Because there is no role check and no field redaction, any caller who can authenticate (view role via session, or a restricted API token) can call `GET /v2/bridge_types` and receive the `outgoingToken` for every configured bridge in the paginated array — this token is what the node uses to authenticate outbound calls to the configured external adapter, so possessing it lets the caller forge/replay requests to that adapter as the node.

### Impact Explanation
This is a credential-disclosure vulnerability: a low-privilege authenticated user (view role) can bulk-harvest all external-adapter `OutgoingToken`s via a single paginated GET, without needing edit/admin role. This matches the "sensitive information disclosure" / "unauthorized secret disclosure" bounty class, since the tokens are meant to authorize calls to external adapters and their exposure to unauthorized callers lets those callers impersonate the node's outbound bridge traffic.

### Likelihood Explanation
Trivial to exploit: only precondition is any valid authenticated session or API token (view role is explicitly sufficient because the route lacks `RequiresEditRole`/`RequiresAdminRole`). No additional bypass or timing is required — a single `GET /v2/bridge_types` (optionally paginated across all bridges) discloses all tokens.

### Recommendation
Add `auth.RequiresEditRole` (or a dedicated role check) to `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName`, and/or redact `OutgoingToken` (and `IncomingToken`) from `presenters.BridgeResource` in list/show responses, only exposing it in `Create`/rotation responses as already done for `IncomingToken` in `Create`.

### Proof of Concept
Go handler-level integration test plan (pattern based on `core/web/bridge_types_controller_test.go`):
1. Set up test app/client via `cltest.NewApplication`; create a session/client authenticated with the `view` role only.
2. Create 2+ bridges via admin/edit client using `BridgeTypesController.Create`, capturing their `OutgoingToken`s from ORM.
3. Using the view-role client, perform `client.Get("/v2/bridge_types?size=25")`.
4. Assert HTTP 200 (not 403), and parse the JSONAPI array of `bridges` resources.
5. Assert each returned resource's `outgoingToken` attribute equals the corresponding bridge's stored `OutgoingToken`, proving disclosure to a view-role caller.

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}
```
