### Title
Global state consensus threshold in `GlobalStateEvaluator` rounds down instead of up, diverging from the block-signing threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70%-style consensus threshold with a plain integer division (`floor`), while the canonical block-approval threshold used everywhere else in the protocol, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds the same quantity *up* (`ceil`). This is the exact "rounding in the incorrect direction" bug class from the report: the same conceptual threshold is computed two different ways in two places that must agree, and the diverging one floors when it should ceil.

### Finding Description
The canonical, tested implementation of the signer approval threshold is: [1](#0-0) 

which computes `ceil(total_weight * 7 / 10)` (verified by `test_compute_voting_weight_threshold`, e.g. `511 -> 358`, not `357`): [2](#0-1) 

This ceiling threshold is what `stacks-signer` uses to decide when a block has enough accept-weight to broadcast, and when enough reject-weight makes 70% unreachable: [3](#0-2) [4](#0-3) 

However, `GlobalStateEvaluator` (used by the global-state-machine signer protocol version to agree on the current miner, burn-view, supported protocol version, and tx-replay-set) computes the *same* 7/10 threshold with `floor` instead of `ceil`: [5](#0-4) 

For any `total_weight` where `total_weight * 7` is not a multiple of 10, `reached_agreement` accepts one unit of weight *less* than the ceiling threshold used for actual block signing (e.g. `total_weight = 511`: ceil = 358, but `reached_agreement` accepts at 357). Symmetrically, `reached_disagreement` also floors `total_weight * 3 / 10`, understating the blocking-minority weight needed to declare disagreement, by up to one unit relative to what `total_weight - min_weight` (the reject-side threshold in `store_and_process_block_rejection`) would produce.

`reached_agreement`/`reached_disagreement` are the core primitives for `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state`, all of which gate what the signer believes the current miner/burn-view/protocol-version to be: [6](#0-5) [7](#0-6) 

### Impact Explanation
This breaks the intended equality between "the weight required for the global-state consensus decision" and "the weight required for a block to actually be signed/approved," off by exactly one signer-weight unit whenever `total_weight * 7 mod 10 != 0` (i.e., most reward-set sizes). Because the global state (current miner, burn view, protocol version, replay set) is accepted with a weight that is provably below the real supermajority requirement in these cases, a signer set can lock in a "global" view (e.g., which miner is authoritative, or which burn block/tenure is canonical from the signers' perspective) with less support than the protocol's 70% supermajority guarantee is supposed to provide. Under the classification given, this is a threshold/equality break between "aggregated weight" and "verified/true threshold" that can misdirect which miner/tenure a signer treats as canonical, which is a systemic safety-relevant equality violation rather than a purely cosmetic rounding issue.

### Likelihood Explanation
No majority of malicious signers is required — this is a deterministic arithmetic discrepancy that fires on ordinary, naturally-occurring reward-set weight distributions (any `total_weight` not evenly divisible in the `*7/10` computation, which is most reward cycles). It requires no attacker action beyond normal participation by signers whose weights happen to sum to a value that triggers the off-by-one; it is a latent bug present in every reward cycle where the ceiling/floor computations diverge.

### Recommendation
Change `reached_agreement` and `reached_disagreement` in `libsigner/src/v0/signer_state.rs` to use the same ceiling arithmetic as `NakamotoBlockHeader::compute_voting_weight_threshold` (i.e., round the required-weight threshold up, not down), or better, factor out a single shared threshold function used by both `stackslib` and `libsigner` so the two can never diverge again.

### Proof of Concept
1. Configure a reward cycle whose signer weights sum to `total_weight = 511` (any value where `total_weight * 7 % 10 != 0` works).
2. Per `compute_voting_weight_threshold`, the true block-signing approval threshold is `358` [2](#0-1) .
3. Accumulate exactly `357` weight of matching `StateMachineUpdate`s for a given `(burn_block, current_miner, protocol_version)` tuple and call `GlobalStateEvaluator::determine_global_state()` / `determine_global_burn_view()`.
4. `reached_agreement(357)` evaluates `357 >= (511*7)/10 = 357` → `true`, so the global state is accepted with only 357/511 weight (~69.86%), one unit short of the actual 358 required by `compute_voting_weight_threshold`, demonstrating the divergence between the two thresholds used within the same overall signer protocol.     pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

                continue;

            let tx_replay_set = update.content.tx_replay_set();

                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),

                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),

            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
