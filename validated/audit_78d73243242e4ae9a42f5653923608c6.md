### Title
Legacy zip extractor (`ziplegacy`/`archives.ExtractZipArchive`) performs no path-traversal or symlink-target validation, allowing artifact zip entries to write/symlink outside the consuming job's working directory - (File: helpers/archives/zip_extract.go)

### Summary
`ArtifactsDownloaderCommand.Execute` extracts a downloaded artifacts archive via `archive.NewExtractor(format, f, size, wd)` [1](#0-0) . For the `Zip`/`ZipZstd` formats (the default unless `FF_USE_FASTZIP` is enabled), the extractor is `ziplegacy.extractor`, whose `Extract` completely ignores the `dir` field and delegates to `archives.ExtractZipArchive`, which writes files using the raw, unsanitized `zip.File.Name` with no containment check [2](#0-1) [3](#0-2) . This is a classic Zip-Slip: no `filepath.Join`+prefix check like the one present in `tarzstd`'s extractor is performed for zip entries.

### Finding Description
`ExtractZipArchive` iterates `archive.File` and calls `extractZipFile(file)` for each entry [4](#0-3) . `extractZipFile` creates parent directories with `os.MkdirAll(filepath.Dir(file.Name), ...)` and then, depending on entry type, calls `os.Mkdir(file.Name, ...)`, `os.OpenFile(file.Name, ...)`, or for symlinks `os.Symlink(string(data), file.Name)` [5](#0-4) . `file.Name` comes directly from the zip central directory entry name and is never validated against `..` traversal, absolute paths, or checked to remain under a base directory - contrast this with `tarzstd_extractor.go`, which explicitly computes `path := filepath.Abs(filepath.Join(e.dir, hdr.Name))` and rejects it if it doesn't have `e.dir` as prefix [6](#0-5) . The only sanitization applied anywhere in `ExtractZipArchive` is a `.git` directory heuristic (`errorIfGitDirectory`), which is unrelated to path traversal and does not block `../` sequences that don't start with `.git` [7](#0-6) .

Critically, `ziplegacy.extractor.Extract` never uses the `dir` parameter passed via `archive.NewExtractor(format, f, size, wd)` at all - it calls `archives.ExtractZipArchive(zr)` with no directory argument [8](#0-7) . Containment is only accidental: it relies entirely on the caller's current working directory already being the intended target and on `file.Name` never containing `../` or an absolute path - an assumption the code does not enforce.

Reachable path: an attacker who authors an upstream job (dependency job, consumed via `dependencies:`/`needs:`) controls the entire uploaded artifacts archive content, including the zip central-directory `Name` field for each entry (e.g. `../../../etc/cron.d/x` or a symlink entry named `link` with target content `/etc/passwd`-adjacent path, or entries with target directories elsewhere on the runner filesystem). When the downstream job's `gitlab-runner-helper artifacts-downloader` runs, it calls `Execute` → `openArchive` → `archive.NewExtractor(archive.Zip, f, size, wd)` → `ziplegacy.NewExtractor` → `Extract()` → `archives.ExtractZipArchive`, which will write/symlink at the attacker-chosen relative-traversal path with no rejection [9](#0-8) .

This is the default code path unless `FF_USE_FASTZIP=true`, in which case `fastzip.NewExtractor`/`saracen/fastzip` (a third-party library with its own path-traversal protections) is used instead for `Zip`/`ZipZstd` [10](#0-9) . `ZipZstd` decompression falls back to the legacy vulnerable path unless fastzip's feature flag overrides it as well [11](#0-10) .

### Impact Explanation
An unprivileged pipeline author who controls an upstream job whose artifacts are consumed by a downstream job (or by cache extraction, which shares the same vulnerable `ExtractZipArchive`/`ziplegacy` path via `CacheExtractorCommand.Execute` [12](#0-11) ) can write arbitrary files or create arbitrary symlinks outside the intended artifact/cache extraction root on the executor filesystem that runs the downstream job's helper. This breaks the invariant that "file operations must stay within intended build/cache/artifact roots" and can lead to file overwrite/planting outside the job workspace on shared/persistent executors (e.g., shell, docker with host-mounted paths, or any runner where the helper process has meaningful filesystem access beyond the job's own directory).

### Likelihood Explanation
This is directly and repeatably reachable: any pipeline that (a) has a project maintainer/author able to define a job producing artifacts and (b) has a downstream job consuming those artifacts satisfies the precondition, both of which are standard, unprivileged CI features (`artifacts:`, `dependencies:`/`needs:`). The bug is deterministic per crafted archive and does not depend on race conditions, admin misconfiguration, or third-party compromise - it triggers by default because `ziplegacy` (not `fastzip`) is the default zip extractor absent `FF_USE_FASTZIP`.

### Recommendation
In `helpers/archives/zip_extract.go`, add path containment validation before extracting each `zip.File` entry: resolve `filepath.Join(baseDir, file.Name)` (with `baseDir` explicitly threaded through from `ziplegacy.extractor.dir` instead of being discarded), reject entries whose cleaned resulting path is not a descendant of `baseDir` (mirroring the check already present in `tarzstd_extractor.go`), and validate/reject symlink entries whose target (or whose own path) would escape `baseDir`. Apply the same fix to `extractZipSymlinkEntry`'s target validation to prevent symlinks pointing outside the target root even when the symlink's own location is contained.

### Proof of Concept
Go unit test (differential across formats), added alongside `commands/helpers/archive/archive_test.go`:

```go
func TestExtractorPathTraversalRejected(t *testing.T) {
    payloads := []string{"../../evil.txt", "../evil-symlink"}
    for _, format := range []archive.Format{archive.Zip, archive.TarZstd} {
        t.Run(string(format), func(t *testing.T) {
            for _, name := range payloads {
                buf := craftMaliciousArchive(t, format, name) // zip/tar entry with traversal name
                dir := t.TempDir()
                extractor, err := archive.NewExtractor(format, bytes.NewReader(buf), int64(len(buf)), dir)
                require.NoError(t, err)

                err = extractor.Extract(context.Background())

                // Expect rejection AND no file written outside dir
                assert.Error(t, err, "expected traversal entry %q to be rejected for format %s", name, format)
                _, statErr := os.Stat(filepath.Join(filepath.Dir(dir), "evil.txt"))
                assert.True(t, os.IsNotExist(statErr), "traversal entry escaped target dir for format %s", format)
            }
        })
    }
}
```
Expected current result: the `archive.TarZstd` case rejects the traversal entry (existing `strings.HasPrefix` check), while `archive.Zip` (ziplegacy) succeeds in extracting/symlinking outside `dir`, demonstrating the inconsistency and confirming the vulnerability.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}
