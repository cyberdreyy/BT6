### Title
Panic (negative `strings.Repeat` count) in `normalizeHex` reachable via crafted `workflowID` in gateway HTTP-trigger requests - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` only rejects a `workflowID` whose *total string length* exceeds `workflowIDLength` (66, i.e. `"0x"` + 64 hex chars), but does not require the `"0x"` prefix to be present or the length to be exact. An attacker can submit a 66-character raw hex string (no `0x` prefix) that passes validation, but when passed to `normalizeHex` produces a negative padding count, causing `strings.Repeat` to panic.

### Finding Description
`validateWorkflowID` calls `validateHexInput(workflowID, workflowIDLength)`: [1](#0-0) 

`validateHexInput` checks `len(input) > expectedLength` (66) as the only length constraint, and separately validates the string is lowercase hex (after optionally trimming a `0x` prefix). It does **not** verify that the input, once the `0x` prefix is stripped, has exactly `expectedLength-2` (64) hex characters, nor that the `0x` prefix is present at all.

If an attacker submits `workflowID` as exactly 66 lowercase hex characters with **no** `0x` prefix (e.g. a valid 33-byte value expressed in hex), `len(input) == 66` (not `>` 66) so the length check passes, and `hex.DecodeString` on the 66-char string succeeds because 66 is even.

This value is then passed into `resolveWorkflowID`: [2](#0-1) 

which calls `normalizeHex(workflowID, workflowIDLength)`: [3](#0-2) 

Since the input has no `0x` prefix, `strings.TrimPrefix` is a no-op, so `hexStr` retains its full 66-character length. `expectedHexLength` is computed as `length-2 = 64`. The padding count becomes `expectedHexLength-len(hexStr) = 64-66 = -2`. Go's `strings.Repeat` panics with `"strings: negative Repeat count"` when given a negative count, so this call panics.

No `recover()` was found in the gateway handler chain (`http_handler.go`, `http_trigger_handler.go`) between the JSON-RPC message dispatch (`HandleJSONRPCUserMessage`) and `normalizeHex`, meaning the panic propagates up through `HandleUserTriggerRequest` and `HandleJSONRPCUserMessage` unguarded within that call path.

### Impact Explanation
An unauthenticated/unprivileged gateway client can trigger a runtime panic in a core request-processing path by sending a single crafted `WorkflowExecute` JSON-RPC message with a malformed `workflowID`. Depending on how the outer JSON-RPC/websocket message-processing goroutine handles panics (not verifiable further within the indexed context), this can crash the goroutine handling gateway node connections or, if unrecovered, the gateway process itself — a denial-of-service impact reachable by a completely unauthenticated caller (no signature/JWT auth is required to reach `resolveWorkflowID`, which is called before `authorizeRequest`/JWT verification).

### Likelihood Explanation
Trivial to trigger: no authentication, no valid JWT, no rate-limit bypass needed — just a syntactically-almost-valid `workflowID` field (66 lowercase hex chars, no `0x` prefix) in an otherwise well-formed HTTP trigger request. It is deterministic and repeatable on every call.

### Recommendation
In `validateHexInput`, require the `0x` prefix explicitly and validate the exact expected hex length after stripping it (rather than only an upper bound on the combined string length). Additionally, harden `normalizeHex` to return an error (instead of silently computing a possibly negative repeat count) when `len(hexStr) > expectedHexLength`.

### Proof of Concept
Go unit test (table-based) in `http_trigger_handler_test.go`:

Expected (current, buggy) behavior: the test panics inside `normalizeHex` (`strings: negative Repeat count`) instead of returning a clean validation error, demonstrating that `validateHexInput` fails to reject this malformed input before it reaches `normalizeHex`.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func (h *httpTriggerHandler) validateWorkflowID(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {

	return nil
}

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}

		}
