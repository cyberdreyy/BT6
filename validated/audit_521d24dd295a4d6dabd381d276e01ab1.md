### Title
Stale confirmations from deleted multisig members are still counted toward `num_confirmations`, allowing a request to execute below the live-member threshold - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only purges pending requests that were *originally created* by the member being removed. It does not scan the `confirmations` map for other pending requests that the removed member had already confirmed as a co-signer. Those stale confirmations remain in the `confirmations` set and continue to be counted by `confirm()`'s threshold check (`confirmations.len() as u32 + 1 >= self.num_confirmations`), which never re-validates that each recorded confirmation still belongs to a currently active member. [1](#0-0) 

### Finding Description
This maps to the same root-cause bug class as the CLMM "active bin" report: a piece of state (the active bin / here, a member's confirmation) is trusted to still be valid by a later code path, but a legitimate removal action (`burn` / here, `delete_member`) only cleans up the specific structure it directly owns (the bin table entry / here, requests it originated) and leaves other structures that reference the removed entity (the swap logic's `active_bin_id` lookup / here, other requests' `confirmations` sets) unrepaired.

Concretely:
1. Members A, B, C, D form a 3-of-4 multisig (`num_confirmations = 3`).
2. Member A creates request X (`add_request`); Member B confirms it (`confirm`) — `confirmations` for X now = `{B}` (1 of 3, request not yet executed). [2](#0-1) [3](#0-2) 
3. Separately, the group creates and confirms a `DeleteMember { member: B }` request and executes it. `delete_member` removes B from `self.members`, removes B's own `num_requests_pk` entry, and removes only requests where `r.member == B` (i.e., requests B *authored*) — request X, authored by A, is untouched, and B's confirmation entry inside X's `confirmations` set is never removed. [4](#0-3) 
4. Member C then calls `confirm(X)`. `confirm()` computes `confirmations.len() as u32 + 1 >= self.num_confirmations` → `1 (stale B) + 1 (C) = 2 + 1 ≥ 3` is false, but with one more confirmer the stale entry is silently combined with live confirmers to reach the threshold with fewer than `num_confirmations` *currently valid* members actually agreeing. [3](#0-2) 
5. `execute_request` then runs the request's actions (e.g., `Transfer`, `AddKey`, `FunctionCall`) as if the full K-of-N threshold of live members had approved, even though one of the counted approvals came from an account/key that is no longer a member of the multisig. [5](#0-4) 

The equality this breaks: `confirmations counted == confirmations from currently live members`. After a `DeleteMember` action, this invariant no longer holds for any request the removed member had co-signed but not authored, because `confirm()` never re-checks `self.members.contains(&confirmer)` for previously stored confirmations.

### Impact Explanation
This directly matches the "Critical" impact category: a multisig request can be executed below the intended threshold of currently active members. Since `MultiSigRequestAction` includes `Transfer`, `AddKey` (full-access key grants), `FunctionCall`, and further `DeleteMember`/`AddMember` actions, an attacker scenario is: a former/compromised member's stale confirmation combines with fewer live members than `num_confirmations` to authorize a NEAR transfer or an `AddKey` grant, moving funds or granting access that the current membership did not actually approve at the required threshold.

### Likelihood Explanation
The trigger sequence is a legitimate, unprivileged usage pattern of the contract's own state machine (add request → partial confirm → later remove one of the confirming members via a separate, unrelated `DeleteMember` request → resume confirming the still-pending earlier request). No foundation, redeploy, or external actor is required — it is an emergent consequence of the contract's own bookkeeping gap, so it can occur in any deployment with turnover in membership while requests are outstanding (which the contract explicitly supports via `active_requests_limit` / `REQUEST_COOLDOWN` allowing multiple pending requests to be alive at once).

### Recommendation
In `delete_member`, when removing a member, also scan the `confirmations` map for all pending requests and strip that member's entry from each request's confirmation set (not just remove requests the member authored). Alternatively/additionally, in `confirm()` and in the threshold check, filter `confirmations` to only those entries where `self.members.contains(...)` is true before comparing against `self.num_confirmations`, so stale confirmations from removed members never count toward execution.

### Proof of Concept
1. Initialize `MultiSigContract::new(members = [A, B, C, D], num_confirmations = 3)`.
2. As A: `add_request(X)` (e.g., `Transfer` to some receiver).
3. As B: `confirm(X)` → `confirmations[X] = {B}`.
4. As A, B, C (3 confirmations reached): `add_request_and_confirm` + `confirm` a `DeleteMember { member: B }` request targeting the multisig itself, causing `delete_member` to run and remove B from `self.members`; note request X is untouched because `r.member == A`, not `B`, so `confirmations[X]` still contains B.
5. As C: `confirm(X)` → `confirmations[X].len() + 1 = 2 >= num_confirmations (3)`? No — but this shows the stale entry persists at count 1; add one more legitimate live confirmer (only 2 live members, C and D, are actually confirming) and the check still succeeds using B's stale entry, executing `X`'s `Transfer` action with only 2 of the current 3 live members (C, D) actually having approved, while B's obsolete approval is silently reused. This is directly verifiable by inspecting `self.confirmations.get(&request_id)` before and after step 4 — it is unchanged, and `confirm()` performs no liveness check against `self.members` on stored entries.     pub fn add_request(&mut self, request: MultiSigRequest) -> RequestId {
        let current_member = self.current_member().unwrap_or_else(|| {
            env::panic_str(
                "Predecessor must be a member or transaction signed with key of given account",
            )
        });
        // track how many requests this key has made
        let num_requests = self
            .num_requests_pk
            .get(&current_member.to_string())
            .unwrap_or(0)
            + 1;
        assert(
            num_requests <= self.active_requests_limit,
            "Account has too many active requests. Confirm or delete some.",
        );
        self.num_requests_pk
            .insert(&current_member.to_string(), &num_requests);
        // add the request
        let request_added = MultiSigRequestWithSigner {
            member: current_member,
            added_timestamp: env::block_timestamp(),
            request,
        };
        self.requests.insert(&self.request_nonce, &request_added);
        let confirmations = HashSet::new();
        self.confirmations
            .insert(&self.request_nonce, &confirmations);
        self.request_nonce += 1;
        self.request_nonce - 1
    }

    /// Add request for multisig and confirm with the pk that added.
    pub fn add_request_and_confirm(&mut self, request: MultiSigRequest) -> RequestId {
        let request_id = self.add_request(request);
        self.confirm(request_id);
        request_id
    }

    fn execute_request(&mut self, request: MultiSigRequest) -> PromiseOrValue<bool> {
        let mut promise = Promise::new(request.receiver_id.clone());
        let receiver_id = request.receiver_id.clone();
        let num_actions = request.actions.len();
        for action in request.actions {
            promise = match action {
                MultiSigRequestAction::Transfer { amount } => promise.transfer(amount.into()),
                MultiSigRequestAction::CreateAccount => promise.create_account(),
                MultiSigRequestAction::DeployContract { code } => {
                    promise.deploy_contract(code.into())
                }
                MultiSigRequestAction::AddMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.add_member(promise, member)
                }
                MultiSigRequestAction::DeleteMember { member } => {
                    self.assert_self_request(receiver_id.clone());
                    self.delete_member(promise, member)
                }
                MultiSigRequestAction::AddKey {
                    public_key,
                    permission,
                } => {
                    self.assert_self_request(receiver_id.clone());
                    if let Some(permission) = permission {
                        promise.add_access_key(
                            public_key.into(),
                            permission
                                .allowance
                                .map(|x| x.into())
                                .unwrap_or(DEFAULT_ALLOWANCE),
                            permission.receiver_id,
                            permission.method_names.join(","),
                        )
                    } else {
                        // wallet UI should warn user if receiver_id == env::current_account_id(), adding FAK will render multisig useless
                        promise.add_full_access_key(public_key.into())
                    }
                }
                MultiSigRequestAction::FunctionCall {
                    method_name,
                    args,
                    deposit,
                    gas,
                } => promise.function_call(
                    method_name,
                    args.into(),
                    deposit.into(),
                    Gas::from(gas.0),
                ),
                // the following methods must be a single action
                MultiSigRequestAction::SetNumConfirmations { num_confirmations } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.num_confirmations = num_confirmations;
                    return PromiseOrValue::Value(true);
                }
                MultiSigRequestAction::SetActiveRequestsLimit {
                    active_requests_limit,
                } => {
                    self.assert_one_action_only(receiver_id, num_actions);
                    self.active_requests_limit = active_requests_limit;
                    return PromiseOrValue::Value(true);
                }
            };
        }
        promise.into()
    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
