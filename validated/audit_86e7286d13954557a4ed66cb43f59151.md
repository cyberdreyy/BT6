### Title
Stale confirmations from removed multisig members still count toward the approval threshold, allowing requests to execute below the effective live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only purges requests that were *added* by the removed member and clears their `num_requests_pk` entry, but it never removes that member's prior confirmation entries from `self.confirmations` for requests they had merely *confirmed* (but not added). `confirm()` then determines whether a request has reached quorum purely by counting the size of the `confirmations` `HashSet`, without checking that every entry in that set still corresponds to a current member. This breaks the binding "confirmations counted == confirmations by live members," allowing a request to execute with fewer genuinely-authorized (live) confirmations than `num_confirmations` requires.

### Finding Description
`confirm()` in `multisig2/src/lib.rs` (lines 292-315) accepts a confirmation, and once `confirmations.len() as u32 + 1 >= self.num_confirmations`, executes the request: [1](#0-0) 

`delete_member`, invoked via a `DeleteMember` request action (lines 356-379), removes:
- requests **added** by the removed member (`r.member == member`), and
- the removed member's `num_requests_pk` entry, and
- the member itself / its access key.

It does **not** scan `self.confirmations` for other still-pending requests that the removed member had already confirmed: [2](#0-1) 

Because `confirm()` never re-validates the identities stored inside a request's `confirmations` set against the current `self.members` set, a confirmation recorded by a member who is later removed keeps counting toward quorum for that pre-existing request.

### Impact Explanation
This breaks the core custody/authorization binding of the multisig: "number of confirmations counted" must equal "number of confirmations by currently-authorized members" for a request to be safely executed (e.g. a `Transfer`, `FunctionCall` with deposit, `AddKey`, `DeployContract`, etc.). If it diverges, a request (including fund transfers) can execute having received fewer live, currently-authorized approvals than the configured `num_confirmations` threshold — i.e. a multisig request executed below the intended threshold, moving NEAR funds (or granting keys / deploying code) with insufficient live authorization. This matches the Critical impact category "a multisig request executed below threshold."

### Likelihood Explanation
Requires normal use of the contract's own multi-step flow (adding a request, partial confirmation, followed by a separate `DeleteMember` request removing one of the confirming members, followed by one more confirmation from a still-live member) — no external compromise, key theft, or owner privilege is needed beyond the standard member/threshold operations the contract exposes. Any set of members that includes a member expected to later leave (e.g. temporary/rotating signer) is exposed to this once that member's stale confirmations linger on other pending requests.

### Recommendation
When executing `delete_member`, iterate over all pending requests' `confirmations` sets and remove the deleted member's identity from every set (not only requests it originated), and/or, in `confirm()`, filter the `confirmations` set to only members present in `self.members` before comparing its length against `self.num_confirmations`.

### Proof of Concept
Conceptual sequence against `multisig2/src/lib.rs`:
1. Contract initialized with members `{A, B, C, D}` and `num_confirmations = 3`.
2. `A` (as adder) creates request `R` (e.g. `Transfer` of contract funds to an attacker-controlled `receiver_id`) via `add_request`.
3. `A` confirms `R` (`confirmations = {A}`), `B` confirms `R` (`confirmations = {A, B}`) — quorum (3) not yet reached, `R` stays pending.
4. `D` creates and the group confirms (via `A`, `C`, `D` — 3 live confirmations) a separate `DeleteMember { member: B }` request targeting the multisig itself; this executes, removing `B` from `self.members` and revoking `B`'s key, but `R`'s `confirmations` set still contains `B`.
5. `C` (a live member) now calls `confirm(R)`: `confirmations.len() (2, still counting stale B) + 1 = 3 >= num_confirmations (3)` → `execute_request(R)` runs.
6. `R` (the `Transfer`) executes having received live approval only from `A` and `C` — one fewer live approval than the configured 3-of-N threshold, because the stale confirmation from removed member `B` was counted. [1](#0-0) [2](#0-1)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
