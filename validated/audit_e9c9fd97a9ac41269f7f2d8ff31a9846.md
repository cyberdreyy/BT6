### Title
Unauthenticated `MethodPublicKeyGet` requests can trigger unbounded DON fan-out via `fanOutToVaultNodes`, enabling amplification/DoS - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`HandleJSONRPCUserMessage` explicitly skips authorization for `vaulttypes.MethodPublicKeyGet` and, whenever the cache is empty, forwards the request to every DON member via `fanOutToVaultNodes`/`SendToNode`. There is no per-request-ID dedup or rate limit at the ingress side of this path, so an attacker who submits many uniquely-`ID`ed unauthenticated requests before (or whenever) the cache is unset can force one `SendToNode` call per DON member per request, unboundedly.

### Finding Description
In `HandleJSONRPCUserMessage`, requests with `req.Method == vaulttypes.MethodPublicKeyGet` bypass `h.requestProcessor.ProcessRequest` entirely — no signature, allow-list, or JWT check is performed: [1](#0-0) 

If `getCachedPublicKey()` returns `nil` (cache not yet populated, or invalidated), the handler calls `newActiveRequest` and `handlePublicKeyGet`, which — on a cache miss — calls `fanOutToVaultNodes`: [2](#0-1) 

`fanOutToVaultNodes` iterates over every DON member and issues a `SendToNode` call per member, with no batching, coalescing, or rate limiting applied to this outbound fan-out: [3](#0-2) 

The only ID-related guard is `newActiveRequest`, which rejects a *duplicate* `req.ID` while one is still pending, but does nothing to limit the *rate* of distinct IDs: [4](#0-3) 

The only rate limiter present in this handler, `h.nodeRateLimiter`, is applied to inbound node **responses** in `HandleNodeMessage`, not to outbound requests generated from user traffic: [5](#0-4) 

Thus, an unauthenticated attacker who sends a flood of `MethodPublicKeyGet` requests each with a unique `req.ID` (satisfying only the trivial `req.ID != "" && len(req.ID) <= 200` check) can trigger one `SendToNode` fan-out per request per DON member as long as the public key cache is empty. Although the code comment claims "we cache this value quite aggressively so don't need to worry about DoS," the cache is only populated asynchronously by a 1-minute ticker (`tickerVaultPublicKeyRefresh`) via `fetchVaultPublicKey`, so there is a real window (startup, cache eviction/failure, or any period before the first successful refresh) during which every unauthenticated request results in fan-out amplification, and nothing bounds the number of distinct in-flight requests an unauthenticated caller may create in that window.

### Impact Explanation
This maps to an availability/quota-degradation impact: an unauthenticated caller can cause outsized load against every vault DON node (`SendToNode` per member per unique request), potentially starving node-side processing capacity and node rate limiters that are shared with legitimate, authenticated secret operations (create/update/delete/list), degrading availability for authorized users. It does not directly bypass authentication for secrets or leak secret material (the public key itself is intentionally public), so the impact is scoped to node-side congestion/availability rather than confidentiality or fund movement.

### Likelihood Explanation
No credentials are required at all — `MethodPublicKeyGet` is unauthenticated by design. The only preconditions are: (1) the attacker can reach the gateway's JSON-RPC ingress for the vault handler, and (2) the shared public-key cache is momentarily empty (startup window, after a refresh failure, or any gap before `fetchVaultPublicKey`'s periodic success). The attacker only needs to generate unique `req.ID` values (trivial, e.g., UUIDs) to avoid the duplicate-ID rejection in `newActiveRequest`, making the attack fully repeatable and requiring no special network position, node compromise, or account.

### Recommendation
Add a coalescing mechanism (e.g., single-flight/locking around `handlePublicKeyGet` so concurrent cache-miss requests share one in-flight `fanOutToVaultNodes` call instead of one per request) and/or an explicit ingress-side rate limiter (per-IP or global) specifically gating unauthenticated `MethodPublicKeyGet` traffic before it reaches `fanOutToVaultNodes`, independent of `nodeRateLimiter` which only governs inbound node responses.

### Proof of Concept
Go handler-level test plan (in `core/services/gateway/handlers/vault/handler_test.go` style, using the existing mock `DON`/`SendToNode` mock):
1. Construct a `handler` with an empty `cachedPublicKeyGetResponse`/`cachedPublicKeyObject` (simulate cold cache/startup).
2. Configure a mock `gwhandlers.DON` with N members and count `SendToNode` invocations.
3. In a loop, call `HandleJSONRPCUserMessage` M times with `req.Method = vaulttypes.MethodPublicKeyGet` and a unique `req.ID` each iteration (e.g., `uuid.New().String()`), no `req.Auth` set.
4. Assert: `SendToNode` was invoked `M * N` times (no dedup, no rate limiting), and there exists no mechanism (single-flight lock, ingress rate limiter) that caps this count to something less than `M * N` for unauthenticated traffic.
5. Expected/desired behavior after fix: with a fix applied, concurrent/rapid unauthenticated cache-miss requests should be coalesced or rate-limited such that `SendToNode` call count does not scale linearly with unauthenticated request volume.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}
