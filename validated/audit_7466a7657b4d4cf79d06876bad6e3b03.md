### Title
Expired-request cleanup leaks raw per-node JSON-RPC responses to the requesting user - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`handler.removeExpiredRequests` builds a debug string via `fmt.Fprintf` over every node's raw `jsonrpc.Response[json.RawMessage]` (node address plus full `%v`-formatted response, including `Result`/`Error` fields) and passes it both as the error message and as the `data` field to `h.errorResponse(... api.RequestTimeoutError ...)`, which is returned directly to the requesting client with no redaction.

### Finding Description
When a request (e.g. `vault_secretsList`/`secretsCreate`/`secretsUpdate`/`secretsDelete`) fails to reach quorum before `h.requestTimeout` elapses, `removeExpiredRequests` iterates over `er.copiedResponses()` — the per-node `jsonrpc.Response[json.RawMessage]` objects collected in `HandleNodeMessage` via `ar.addResponseForNode` [1](#0-0) . It formats each node key and its full response with `%v` into `nodeResponsesStr`: [2](#0-1) 

This string is embedded both in the error message (`errors.New("... Available responses: "+nodeResponsesStr)`) and passed as the `data` argument to `h.errorResponse`. Unlike other error codes in `errorResponse` (e.g. `NodeReponseEncodingError`, which explicitly replaces `err` with a generic message to "intentionally hide the error from the user"), the `api.RequestTimeoutError` case is a no-op — it does not sanitize `err` or `data` before encoding: [3](#0-2) 

The resulting `UserCallbackPayload.RawResponse` is sent straight back to the caller via `sendResponse` → `userRequest.SendResponse(resp)` [4](#0-3) , with no authentication/authorization gate on the *response* path (the gateway does not filter response payloads by role).

What the leaked `jsonrpc.Response[json.RawMessage]` can contain depends on the method and per-node partial state at the moment of timeout: it includes each responding node's address (`nodeKey`, from `h.donConfig.Members`) and the full raw `Result`/`Error` JSON of that node's individual (non-aggregated, non-quorum) response. Because the value is captured before quorum/aggregation succeeds, it may include diagnostic node-side error text, or per-node result payloads that the client would otherwise only receive after aggregation. Whether raw ciphertext (e.g. `EncryptedValue`/`EncryptedDecryptionKeyShares`) can appear here depends on whether a given method's node responses carry such fields prior to aggregation — that data flow is asserted by design elsewhere in the vault flow (e.g. `GetSecretsResponse.Responses[].Result.Data.EncryptedValue`) but the vault gateway handler here only implements `SecretsCreate/Update/Delete/List/PublicKeyGet`, not `GetSecrets`, so in the current vault gateway handler the "Result" content is not raw secret plaintext ciphertext but still is internal per-node diagnostic response data (including node identifiers/addresses and any node-supplied error text) that the requesting user was never intended to see verbatim.

### Impact Explanation
Chainlink bounty impact class: information disclosure of internal node/aggregator debug information to an unauthenticated/unprivileged requester. Concretely: (1) exposure of `donConfig.Members` node addresses tied to a specific request/timeout event, which reveals DON topology/participation details beyond what the aggregated protocol response is meant to expose; (2) exposure of raw, non-aggregated per-node JSON-RPC `Result`/`Error` content (including any node-side diagnostic messages) that bypasses the intended aggregation/redaction boundary; and (3) exposure of internal Go `%v` struct formatting which can echo internal field values that were never meant to be serialized to an untrusted party. This is a real, code-verified information-disclosure bug, but it is bounded — it does not by itself grant authentication bypass, fund movement, or privilege escalation, and no plaintext secret value crosses this path in the vault gateway handler as currently implemented.

### Likelihood Explanation
Highly reproducible: any authenticated-but-unprivileged caller (or any attacker able to submit a properly signed/authorized vault write or list request, since normal authorization via `requestProcessor.ProcessRequest` is all that's needed to reach `newActiveRequest`) can trigger this simply by causing slow/partial node responses relative to `h.requestTimeout` (default 30s, or `defaultCleanUpPeriod` 5s poll) — no elevated privileges are required, only the ability to make a normal vault request and have less than quorum of nodes answer before timeout. This is deterministic and repeatable in unit tests using the `clockwork.Clock` fake already used by the handler's tests.

### Recommendation
For `api.RequestTimeoutError` in `h.errorResponse`, do not embed the raw per-node `nodeResponsesStr` (built via `%v` over `jsonrpc.Response[json.RawMessage]`) in the user-facing error message or `data` field. Log the detailed per-node diagnostic content server-side only (`h.lggr.Errorw(...)` with structured fields), and return a generic timeout message/error code to the caller, mirroring the existing `NodeReponseEncodingError` sanitization pattern in the same `switch`.

### Proof of Concept
Go unit test plan (table-driven, in `core/services/gateway/handlers/vault/handler_test.go`):
1. Construct a `handler` via existing `setupHandler(t)` helper with a fake `clockwork.Clock`.
2. Submit a `MethodSecretsList` (or `SecretsCreate`) request via `HandleJSONRPCUserMessage`, obtaining `ar`.
3. Simulate one (but less than quorum) node response via `HandleNodeMessage` with a `jsonrpc.Response[json.RawMessage]` whose `Result` contains a marker string, e.g. `{"marker":"SENSITIVE_NODE_DEBUG_DATA"}`, and node address `"0xNodeAddr"`.
4. Advance the fake clock past `h.requestTimeout` and invoke `h.removeExpiredRequests(ctx)` directly.
5. Capture the `UserCallbackPayload` delivered to `callback.Wait(ctx)`.
6. Assert `resp.ErrorCode == api.RequestTimeoutError`, then decode `resp.RawResponse` and assert that neither the error `message` field nor the `data` field contains the substrings `"SENSITIVE_NODE_DEBUG_DATA"` or the node address `"0xNodeAddr"` — expected to fail against current code (confirming the leak), and pass once the fix redacts the timeout error content.

func (ar *activeRequest) addResponseForNode(nodeAddr string, resp *jsonrpc.Response[json.RawMessage]) bool {
	ar.mu.Lock()
	defer ar.mu.Unlock()
	_, exists := ar.responses[nodeAddr]
	if exists {
		return false
	}

	ar.responses[nodeAddr] = resp
	return true
}

func (h *handler) errorResponse(
	req jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
	data []byte,
) gwhandlers.UserCallbackPayload {
	switch errorCode {
	case api.FatalError:
	case api.NodeReponseEncodingError:
		h.lggr.Errorw(err.Error(), "requestID", req.ID)
		// Intentionally hide the error from the user
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		paramsStr := ""
		if req.Params != nil {
			paramsStr = string(*req.Params)
		}
		h.lggr.Errorw("invalid params", "requestID", req.ID, "params", paramsStr)
		err = errors.New("invalid params error: " + err.Error())
	case api.UnsupportedMethodError:
		h.lggr.Errorw("unsupported method", "requestID", req.ID, "method", req.Method, "error", err.Error())
		err = errors.New("unsupported method(" + req.Method + "): " + err.Error())
	case api.UserMessageParseError:
		h.lggr.Errorw("user message parse error", "requestID", req.ID, "error", err.Error())
		err = errors.New("user message parse error: " + err.Error())
	case api.NoError:
	case api.UnsupportedDONIdError:
	case api.ConflictError:
	case api.HandlerError:
	case api.LimitExceededError:
	case api.RequestTimeoutError:
	case api.StaleNodeResponseError:
		// Unused in this handler
	}

	// Strip the owner prefix from the json response ID before sending it back to the user
	// This ensures compliance with JSONRPC 2.0 spec, which requires response id to match request id
	index := strings.Index(req.ID, vaulttypes.RequestIDSeparator)
	if index != -1 {
		req.ID = req.ID[index+2:]
	}

	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			data,
		),
		ErrorCode: errorCode,
	}
}

func (h *handler) sendResponse(ctx context.Context, userRequest *activeRequest, resp gwhandlers.UserCallbackPayload) error {
	switch resp.ErrorCode {
	case api.StaleNodeResponseError:
	case api.FatalError:
	case api.NodeReponseEncodingError:
	case api.RequestTimeoutError:
	case api.HandlerError:
	case api.ConflictError:
	case api.LimitExceededError:
		h.metrics.requestInternalError.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
			attribute.String("error", resp.ErrorCode.String()),
		))
	case api.InvalidParamsError:
	case api.UnsupportedMethodError:
	case api.UserMessageParseError:
	case api.UnsupportedDONIdError:
		h.metrics.requestUserError.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
		))
	case api.NoError:
		h.metrics.requestSuccess.Add(ctx, 1, metric.WithAttributes(
			attribute.String("don_id", h.donConfig.DonId),
		))
	}

	err := userRequest.SendResponse(resp)
	if err != nil {
		h.lggr.Errorw("error sending response to user", "requestID", userRequest.req.ID, "error", err)
		return err
	}

	h.mu.Lock()
	defer h.mu.Unlock()
	delete(h.activeRequests, userRequest.req.ID)
	h.lggr.Debugw("response sent to user", "requestID", userRequest.req.ID, "errorCode", resp.ErrorCode)
	return nil
}
