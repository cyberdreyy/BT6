Based on my research, I found a strong analog in marginfi-v2 to the veALCX merge bug: a balance-closing path that discards accrued-but-unclaimed reward state instead of settling it first.

### Title
Permanent freezing of unclaimed emissions when closing a balance via `lending_account_close_balance` / `withdraw_all` - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
Similar to the veALCX `merge()` bug (which burns an NFT without first claiming its accrued ALCX), marginfi's `Balance::close()` wipes an entire `Balance` slot — including `emissions_outstanding`, the field tracking a position's accrued-but-unpaid reward tokens — without first settling or transferring that value anywhere.

### Finding Description
`Balance` stores `emissions_outstanding`, described as "Unclaimed emissions rewards for this position" [1](#0-0) . When a balance is closed, `BalanceImpl::close()` simply overwrites the entire struct with `Self::empty_deactivated()`, which hard-codes `emissions_outstanding` back to zero: [2](#0-1) [3](#0-2) 

This `close()` is invoked directly by `close_balance()` in the `BankAccountWrapper`, which validates asset/liability shares are zero but never inspects or settles `emissions_outstanding` before calling `balance.close()`: [4](#0-3) 

This is reached from the permissionless-by-authority instruction `lending_account_close_balance`, which loads the balance, calls `bank_account.close_balance(...)`, and returns — with no emissions claim step anywhere in the instruction handler: [5](#0-4) 

The same `balance.close()` call (and therefore the same zeroing of `emissions_outstanding`) is also used by `withdraw_all()`, which is the path taken when a user withdraws their full position (`withdraw_all = true`) — the documented "only way to close a Balance": [6](#0-5) [7](#0-6) 

Notably, the codebase defines a purpose-built error `CannotCloseOutstandingEmissions` ("Cannot close balance because of outstanding emissions"), which strongly indicates the intended design required a guard against exactly this scenario: [8](#0-7) . However, this error is never actually thrown anywhere in the program's instruction/state code — it only appears in `errors.rs` and in a test helper string reference, not in any check/require call in `close_balance.rs`, `withdraw.rs`, or `marginfi_account.rs`. This means the safeguard that should prevent (or force settlement before) closing a balance with nonzero `emissions_outstanding` is effectively dead/unwired.

### Impact Explanation
If a user's `Balance.emissions_outstanding` is nonzero (e.g., they haven't yet had emissions airdropped/settled for the current period) and they either withdraw their entire position (`withdraw_all`) or explicitly close a zero-balance position (`lending_account_close_balance`), the accrued emissions value stored in that struct field is unconditionally reset to zero and the balance slot is freed for reuse — with no transfer, no event capturing the forfeited amount, and no path to recover it. This is a durable, unrecoverable loss of value for the affected user, directly analogous to the ALCX freezing described in the source report.

### Likelihood Explanation
This requires only unprivileged, permissionless-by-authority user actions (a normal `lending_account_withdraw` with `withdraw_all=true`, or `lending_account_close_balance`) combined with the ordinary, expected condition that emissions haven't been settled to the user yet (per the project's own documentation, emissions are delivered by off-chain airdrop "typically on Wednesday," so nonzero `emissions_outstanding` is a normal, common state [9](#0-8) ). No admin/validator/privileged role is needed to trigger it.

### Recommendation
Before calling `balance.close()` in both `close_balance()` and `withdraw_all()`, either (a) require `emissions_outstanding` to be zero (reinstating and wiring up `MarginfiError::CannotCloseOutstandingEmissions`), or (b) settle/flush `emissions_outstanding` to the user (or an emissions-claim record) prior to zeroing the balance, mirroring how the referenced VotingEscrow.sol `withdraw()` claims rewards before burning.

### Proof of Concept
Note: I could not execute or fully trace the runtime emissions-settlement flow (e.g., whether `emissions_outstanding` is normally incremented/settled elsewhere in a step I didn't reach, such as inside `lending_account_withdraw`'s handler in `programs/marginfi/src/instructions/marginfi_account/withdraw.rs`, which I was unable to inspect before the iteration limit). This is a code-level trace showing the guard is unwired and the zeroing is unconditional; a concrete on-chain reproduction (deposit → let emissions accrue on a bank with `EMISSIONS_FLAG_LENDING_ACTIVE` set → `withdraw_all` or `lending_account_close_balance` → assert `emissions_outstanding` was nonzero before and the funds were never paid out) would be needed to fully confirm exploitability and should be run by a background agent with repo access to the full instruction handlers and test fixtures (e.g., extending `programs/marginfi/tests/user_actions/close_balance.rs` or `programs/marginfi/tests/misc/emissions_deposit.rs`).

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
