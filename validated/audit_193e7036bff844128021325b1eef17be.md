Confirmed: the vulnerability exists in `multisig2/src/lib.rs`. `delete_member` (lines 355-379) only purges `confirmations`/`requests` entries for requests where `r.member == member` (i.e., requests originated by the removed member as the *requester*), but does not scan and strip that member's confirmation entries from `confirmations` sets of *other* pending requests they had previously confirmed as a co-signer via `confirm()` (line 294-315). Since `confirm()` counts raw `confirmations.len()`, a stale confirmation from a removed member still counts toward `num_confirmations`, breaking the intended binding "confirmations counted == live members who confirmed."

### Title
Stale Confirmations From Removed Multisig Members Bypass Live-Member Threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::delete_member` in [1](#0-0)  removes a member's own *requests* and their confirmations, but never removes that member's confirmation entries from `confirmations` sets of requests they had confirmed but did not originate. `confirm()` at [2](#0-1)  simply checks `confirmations.len() as u32 + 1 >= self.num_confirmations`, so a stale confirmation left by a departed/removed member is counted as equal to a confirmation from a currently live member.

### Finding Description
The multisig's core custody binding is: `confirmations counted == confirmations from currently live members`. `delete_member` only filters `self.requests.iter()` for entries where `r.member == member` (the request's *originator*) at [3](#0-2) , then removes `self.members` and any access key. It never inspects `self.confirmations` values (the `HashSet<String>` of confirming members) to strip out the removed member's string from confirmation sets of requests originated by *other* members. Meanwhile `confirm()` treats `confirmations.len()` as a proxy for the number of authorized live signers, with no re-validation that every entry in the set still belongs to `self.members`. Consequently, once a member is removed, any pending request they previously confirmed still has their confirmation "baked in" and counted toward the threshold, even though `self.members` no longer contains them.

### Impact Explanation
This breaks the K-of-N authorization guarantee that the multisig exists to enforce: a request can execute with fewer than K currently-authorized signers agreeing, because a removed (e.g., compromised, offboarded, or otherwise revoked) member's stale confirmation still counts. This is a threshold bypass allowing a request (including `Transfer`, `FunctionCall`, `AddKey`/`AddMember`) to execute below the intended live-member quorum, potentially moving funds or granting access with insufficient current authorization — matching the Critical impact category "a multisig request executed below threshold."

### Likelihood Explanation
The scenario requires only ordinary lifecycle events already supported by the contract: a member confirms a pending request (normal operation), and later that member is removed via `DeleteMember` (a normal, expected operational action, e.g., revoking a departing employee or a suspected-compromised key) while that request is still outstanding. No special privilege beyond what the contract already grants to any member is required to trigger the bug; the removed member does not need to act again — the stale state alone causes miscounting on the next legitimate confirmation.

### Recommendation
When executing `DeleteMember`, iterate over all entries in `self.confirmations` (not just requests where `r.member == member`) and remove the deleted member's string from every confirmation set. Alternatively, have `confirm()`/execution counting re-validate that every string in a confirmations set still corresponds to a current `self.members` entry before comparing against `num_confirmations`.

### Proof of Concept
1. Deploy `MultiSigContract::new` with members `{A, B, C}` and `num_confirmations = 2`.
2. `B` calls `add_request` to create request R1 (any `MultiSigRequestAction::Transfer`), then `B` calls `confirm(R1)` — `confirmations[R1] = {B}` (1 of 2, not yet executed) per [2](#0-1) .
3. Separately, `A`, `B`, `C` create and confirm a `DeleteMember{member: B}` request that reaches quorum and executes, removing `B` from `self.members` via [4](#0-3) . Note R1 (originated by `B`, but that's irrelevant here — the point is any request `B` had *confirmed* but not *originated*) is untouched because the filter in `delete_member` only matches `r.member == member` i.e. requests *originated* by `B`; if `B` had instead confirmed a request originated by `A` (call it R2, `confirmations[R2] = {B}`), R2 would survive removal untouched.
4. Now only `A` and `C` are live members, requiring 2 live confirmations for quorum. `A` calls `confirm(R2)`. `confirmations.len() + 1 == 2 >= num_confirmations`, so R2 executes — using `B`'s stale, no-longer-authorized confirmation plus `A`'s, i.e., only 1 truly live member (`A`) actually re-affirmed R2 at execution time, yet the request executes as if 2 live members agreed.

        self.assert_valid_request(request_id);

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
