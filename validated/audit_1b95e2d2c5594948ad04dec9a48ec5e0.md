### Title
Log suppression in `pathErrorTracker.actionable` degrades observability of extraction errors but is not itself an escape or tampering vector - ([File: helpers/archives/path_error_tracker.go])

### Summary
`pathErrorTracker.actionable` deduplicates *logging* of `os.PathError` values by `Op` only, so if `ExtractZipArchive` encounters many entries producing the same `Op` (e.g. repeated "open" errors) but different `Path` values, only the first is logged and the rest are silently suppressed. However, log suppression does not gate or permit any additional file write — `ExtractZipFile`/`extractZipFile` already writes wherever `file.Name` points regardless of whether the resulting error is "actionable," so the tracker cannot be the mechanism that enables cross-boundary writes.

### Finding Description
`pathErrorTracker.actionable` tracks only `pathErr.Op` (e.g. `"open"`, `"mkdir"`, `"chmod"`) in a `map[string]bool`, not `pathErr.Path`, so after the first PathError of a given Op is logged, every subsequent PathError sharing that Op is suppressed regardless of its distinct `Path` value. [1](#0-0) 

In `ExtractZipArchive`, this is used purely to decide whether to `logrus.Warningf` about an error returned from `extractZipFile`, `lchmod`, or `processZipExtra` — the loop always continues to the next entry regardless of the tracker's verdict: [2](#0-1) 

Critically, `extractZipFile` (via `extractZipFileEntry`/`extractZipSymlinkEntry`) operates directly on `file.Name` from the zip header, with **no root-confinement / zip-slip check** (no `filepath.Abs` + prefix check against a target directory, unlike `tarzstd_extractor.go`'s explicit chroot-style guard): [3](#0-2) [4](#0-3) 

The write/tamper action (`os.OpenFile`, `os.Symlink`, `os.MkdirAll`) happens on **success**, i.e. when there is *no* PathError at all — the tracker only ever fires on failed operations. A crafted entry that successfully traverses outside the intended root (e.g. `../../other-project/file`) and succeeds in writing does not produce a `PathError` in the first place, so `actionable` is irrelevant to that specific attack path. The tracker only affects visibility of *failed* filesystem operations sharing an `Op`, not successful ones.

### Impact Explanation
The scoped impact described in the question — "silent mass cross-project file tampering with degraded detectability" enabled by log suppression — does not hold: log deduplication in `actionable` never blocks, permits, or alters an extraction outcome; it only reduces log verbosity for *failed* operations of the same syscall type. If a real zip-slip/path-traversal write were possible in `helpers/archives/zip_extract.go` (a separate, more serious concern given the absence of a root-confinement check compared to the `tarzstd` extractor), it would manifest as a *successful* write with no error at all, bypassing `actionable` entirely rather than being "suppressed" by it. Thus the specific causal chain claimed in the question (PathError suppression → silent cross-project tampering) is not supported by the code.

### Likelihood Explanation
Not applicable — the finding as stated does not describe a real exploitable chain through `pathErrorTracker.actionable`. The genuinely interesting adjacent question (whether `helpers/archives` zip extraction lacks a root-confinement check present elsewhere, e.g. `tarzstd_extractor.go`) is a separate, unverified issue outside the scope of this specific question about `actionable`'s suppression behavior, and would require separately confirming which code paths (artifact download, cache extraction) invoke `archives.ExtractZipArchive` versus the fastzip/tarzstd extractors, and whether the working directory is already isolated per-job such that traversal targets remain within job-owned storage.

### Recommendation
No fix is warranted for `pathErrorTracker.actionable` itself under the scoped invariant in this question, since it does not gate or hide a tampering action, only warning verbosity for a subset of failure cases. If auditability of repeated failures is a goal, `seenOps` could additionally key on `pathErr.Path` (or log a periodic count of suppressed errors), but this is a defense-in-depth/observability improvement, not a security vulnerability fix.

### Proof of Concept
Not applicable as a vulnerability PoC. A test could show `actionable`'s dedup behavior (already covered by `TestPathErrorIsActionableTheFirstTimeOnly` in `helpers/archives/path_error_tracker_test.go`) and that `ExtractZipArchive` still performs (or attempts) every entry's extraction regardless of logging suppression, confirming no operation is skipped due to `actionable`'s return value — which is expected/benign behavior, not a bug matching the question's claimed exploit. func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

func TestPathErrorIsActionableTheFirstTimeOnly(t *testing.T) {
	pathErr1 := &os.PathError{Op: "anything"}
	pathErr2 := &os.PathError{Op: "anything"}
	pathErr3 := &os.PathError{Op: "something else"}
	tracker := newPathErrorTracker()

	assert.True(t, tracker.actionable(pathErr1), "Should be actionable the first time an Op is seen")
	assert.False(
		t,
		tracker.actionable(pathErr2),
		"Should not be actionable if the same Op is seen in a different instance",
	)
	assert.False(
		t,
		tracker.actionable(pathErr1),
		"Should not be actionable if the same instance is passed again",
	)
	assert.True(t, tracker.actionable(pathErr3), "Another Op should be actionable")
}
