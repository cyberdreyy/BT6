### Title
Path traversal in artifact metadata filename write via unsanitized `artifactName` - ([File: commands/helpers/artifact_metadata.go])

### Summary
`(*artifactStatementGenerator).generateStatementToFile` builds the metadata sidecar file path with `filepath.Join(opts.artifactsWd, fmt.Sprintf(artifactsStatementFormat, opts.artifactName))` and never sanitizes `opts.artifactName`, unlike the sibling `artifactFilename` in `commands/helpers/artifacts_uploader.go:79-96`, which explicitly calls `filepath.Base(name)` before use. Since `opts.artifactName` is populated directly from `c.Name` (the job's `artifacts:name`, expanded via `shell.Expand` with CI variables), a pipeline author can supply a value containing `../` sequences to make `os.WriteFile` write the generated attestation JSON outside the intended build/artifacts working directory.

### Finding Description
In `commands/helpers/artifacts_uploader.go`, `Execute` calls:
```go
metadataFile, err := c.generateStatementToFile(generateStatementOptions{
    artifactName: c.Name,
    ...
})
``` [1](#0-0) 

`c.Name` originates from the `--name` flag driven by the job's `artifacts:name` CI configuration, and is only shell-expanded (no path sanitization) in `normalizeArgs`: [2](#0-1) 

In `generateStatementToFile`, the target file path is computed as:
```go
file := filepath.Join(opts.artifactsWd, fmt.Sprintf(artifactsStatementFormat, opts.artifactName))
err = os.WriteFile(file, b, 0o644)
``` [3](#0-2) 

`filepath.Join` performs `Clean`, so `../` segments in `artifactName` are resolved and can walk the resulting path outside `opts.artifactsWd` (the build directory, `c.wd`). By contrast, the sibling function used for the actual archive filename explicitly confines the name via `filepath.Base`: [4](#0-3) 

This asymmetry means the archive itself is streamed to the network (not written to a local path derived from the unsanitized name), while the metadata JSON is written directly to local disk with no equivalent confinement — a real, exploitable inconsistency, not merely a style issue.

### Impact Explanation
An unprivileged pipeline author who sets `artifacts:name` (or a CI variable feeding it) to a value like `../../../../tmp/pwned` (when `GenerateArtifactsMetadata`/provenance generation is enabled for the job) can cause the runner helper process to write an attacker-triggered file (`<traversed-path>-metadata.json`, containing SLSA provenance JSON) outside the job's working directory, anywhere writable by the job/helper process user. This is a local file-write-outside-root issue (violates the "file operations must stay within intended build/artifact roots" invariant). It does not directly leak secrets (content is provenance metadata, not attacker-supplied bytes), but it can overwrite existing files at attacker-chosen paths within the process's write permissions (e.g., other files in a shared build root, or on shell executors, other locations on the host reachable by the runner user), and can also be used to plant files outside the workspace that later steps or other jobs sharing the same filesystem might process.

### Likelihood Explanation
Preconditions: the job/runner must have `GenerateArtifactsMetadata` enabled (build attestation/provenance feature) and the pipeline author controls `artifacts:name`. Given those, the exploit requires no special privilege beyond authoring a `.gitlab-ci.yml` — it's fully attacker-reachable and deterministic/repeatable. The main uncertainty (not verifiable from available context) is exactly which executors/configurations enable `GenerateArtifactsMetadata` by default and how strictly `artifacts:name` values are otherwise constrained upstream before reaching this helper; I could not find any sanitization of `c.Name` prior to `normalizeArgs`'s `shell.Expand` call.

### Recommendation
Sanitize `opts.artifactName` in `generateStatementToFile` the same way `artifactFilename` does — apply `filepath.Base` (and reject/replace empty or `.`/`..` results) before formatting `artifactsStatementFormat`, and additionally verify the resulting joined path stays within `opts.artifactsWd` (e.g., via `filepath.Rel` check) before calling `os.WriteFile`, defense-in-depth against any remaining traversal vectors.

### Proof of Concept
Go unit test in `commands/helpers/artifact_metadata_test.go` style:
```go
func TestGenerateMetadataToFile_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    outsideDir := t.TempDir() // simulate directory outside artifactsWd

    g := &artifactStatementGenerator{
        StartedAtRFC3339: time.Now().Format(time.RFC3339),
        EndedAtRFC3339:   time.Now().Add(time.Minute).Format(time.RFC3339),
    }

    // craft artifactName to escape tmpDir into outsideDir
    rel, _ := filepath.Rel(tmpDir, outsideDir)
    maliciousName := filepath.Join(rel, "evil")

    file, err := g.generateStatementToFile(generateStatementOptions{
        artifactName: maliciousName,
        files:        map[string]os.FileInfo{},
        artifactsWd:  tmpDir,
        jobID:        1,
    })
    require.NoError(t, err)

    // Assert the written file escaped the intended root
    relCheck, err := filepath.Rel(tmpDir, file)
    require.NoError(t, err)
    assert.True(t, strings.HasPrefix(relCheck, ".."), "metadata file escaped artifactsWd: %s", file)

    // Compare against artifactFilename's confinement for the same crafted name
    uploader := &ArtifactsUploaderCommand{}
    confinedName := uploader.artifactFilename(maliciousName, spec.ArtifactFormatZip)
    assert.False(t, strings.Contains(confinedName, ".."), "artifactFilename correctly confines the name")
}
```
Expected assertions: the metadata file path produced by `generateStatementToFile` resolves outside `tmpDir` (proving the traversal), while `artifactFilename` for the identical crafted name never contains `..` (proving the sanitization asymmetry).

func (c *ArtifactsUploaderCommand) artifactFilename(name string, format spec.ArtifactFormat) string {
	name = filepath.Base(name)
	if name == "" || name == "." {
		name = DefaultUploadName
	}

	switch format {
	case spec.ArtifactFormatZip, spec.ArtifactFormatZipZstd:
		return name + ".zip"

	case spec.ArtifactFormatGzip:
		return name + ".gz"

	case spec.ArtifactFormatTarZstd:
		return name + ".tar.zst"
	}
	return name
}
```
