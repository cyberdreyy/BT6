### Title
Staking pool orphans validator rewards when `total_stake_shares` reaches zero, permanently freezing funds and bricking future staking - ([File: staking-pool/src/internal.rs])

### Summary
`StakingContract::internal_ping()` always adds the full realized reward (`owners_fee` and `remaining_reward`) into `total_staked_balance`, but only mints new "stake" shares for the owner if `num_shares_from_staked_amount_rounded_down(owners_fee) > 0`. If `total_stake_shares` is `0` at the moment a reward is realized (which happens whenever every delegator has fully unstaked), the reward balance is added to `total_staked_balance` with zero shares minted to back it. This orphans the reward: it can never be redeemed by anyone, and any subsequent attempt to stake reverts, permanently bricking the pool's staking function while the orphaned NEAR sits frozen in the contract.

### Finding Description
`internal_ping()` computes rewards purely from the delta between the actual on-chain balance (`account_locked_balance() + account_balance()`) and the last recorded `last_total_balance`, and unconditionally credits that delta into `total_staked_balance`: [1](#0-0) 

Note that `self.total_staked_balance += owners_fee;` happens unconditionally, "no matter whether the owner received any shares or not" (per the code comment), and `self.total_staked_balance += remaining_reward;` never mints shares for existing delegators either — it relies on existing share holders benefiting from price appreciation.

This creates an equality that can be broken: `total_staked_balance` (claims backing) is supposed to always be redeemable via `total_stake_shares` at a "price" of `total_staked_balance / total_stake_shares`. When `total_stake_shares == 0` but `total_staked_balance > 0`, this ratio is undefined and unclaimable — the binding "recorded staked balance ⇔ shares that can redeem it" is broken.

`total_stake_shares` legitimately reaches `0` whenever the last delegator (and the owner, if they hold no fee shares) fully unstakes via `unstake_all()`: [2](#0-1) 

Because NEAR's native unstaking takes `NUM_EPOCHS_TO_UNLOCK` (4) epochs to settle, the underlying validator stake continues earning protocol-level rewards during that window even though `total_staked_balance`/`total_stake_shares` were already zeroed out in this transaction. On any subsequent epoch, an unprivileged caller invoking the public `ping()` method (or any action that calls `internal_ping()`, e.g. `deposit()`) will pick up this residual reward and orphan it into `total_staked_balance` with no shares minted, since `num_shares_from_staked_amount_rounded_down` returns `0` when `total_stake_shares == 0`: [3](#0-2) [4](#0-3) 

Once this occurs, any future staker who attempts to join the pool triggers a hard revert, because `internal_stake` asserts `num_shares > 0`, and with `total_stake_shares == 0` the computed shares will always be `0`: [5](#0-4) 

### Impact Explanation
This breaks the custody binding between recorded claims (`total_staked_balance`) and the shares that are supposed to be able to redeem them (`total_stake_shares`). The orphaned reward amount becomes permanently frozen NEAR: it cannot be withdrawn (there is no share-less redemption path) and the pool becomes permanently unable to accept new stakers going forward (`stake`/`stake_all`/`deposit_and_stake` will revert). This matches the "funds permanently frozen" / broken-invariant High-impact criteria, and is directly analogous to the referenced Cap Finance issue where realized rewards become detached from the accounting that is supposed to track and distribute them.

### Likelihood Explanation
No privileged role, redeploy, or special preconditions are required. Any set of unprivileged delegators fully unstaking their positions (a completely normal, permitted action) creates the zero-share window; any unprivileged caller triggering `ping()` in a subsequent epoch (also a completely normal, permission-less public call) realizes and orphans the reward. This is a naturally reachable state in the pool's ordinary lifecycle, not a contrived edge case requiring attacker-controlled deployment parameters.

### Recommendation
When realizing a reward while `total_stake_shares == 0` (i.e., no shares exist to absorb it), do not silently add it to `total_staked_balance`. Instead, either: (a) skip crediting/realizing rewards until at least one delegator has staked again (mirroring the "don't distribute if there's nobody to receive it" root-cause fix suggested for the referenced report), or (b) mint an initial share basis atomically instead of allowing `total_stake_shares` to hit exactly `0` while `total_staked_balance` might still receive residual protocol rewards from the still-unwinding validator stake.

### Proof of Concept
1. Owner deploys pool with `reward_fee_fraction = 0` (or owner holds shares only via fee, doesn't matter for the zero-share window).
2. Alice deposits and stakes `X` NEAR: `total_staked_balance = X`, `total_stake_shares = X`.
3. Alice calls `unstake_all()`: `total_staked_balance = 0`, `total_stake_shares = 0`, `internal_restake()` initiates a full unstake at the protocol level (`Promise::stake(0, ...)`), but the actual validator-locked balance takes `NUM_EPOCHS_TO_UNLOCK` (4) epochs to fully unwind and continues earning protocol rewards in the meantime.
4. In the next epoch (before the unstake fully settles), anyone calls the public `ping()`. `internal_ping()` observes `total_balance > last_total_balance` (due to residual validator reward), computes `total_reward > 0`, and executes `self.total_staked_balance += owners_fee;` / `self.total_staked_balance += remaining_reward;` while `total_stake_shares` stays `0` (no shares minted, since `num_shares_from_staked_amount_rounded_down` divides by the previous zero balance/shares state and yields `0`).
5. `total_staked_balance` is now `> 0` while `total_stake_shares == 0` — reward is orphaned.
6. Bob attempts `deposit_and_stake()`: `internal_stake` computes `num_shares = 0` and hits `assert!(num_shares > 0, ...)`, reverting. The pool can never accept a new staker again, and the orphaned reward NEAR is permanently unreachable.

    pub(crate) fn inner_unstake(&mut self, amount: u128) {
        assert!(amount > 0, "Unstaking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        assert!(
            self.total_staked_balance > 0,
            "The contract doesn't have staked balance"
        );
        // Calculate the number of shares required to unstake the given amount.
        // NOTE: The number of shares the account will pay is rounded up.
        let num_shares = self.num_shares_from_staked_amount_rounded_up(amount);
        assert!(
            num_shares > 0,
            "Invariant violation. The calculated number of \"stake\" shares for unstaking should be positive"
        );
        assert!(
            account.stake_shares >= num_shares,
            "Not enough staked balance to unstake"
        );

        // Calculating the amount of tokens the account will receive by unstaking the corresponding
        // number of "stake" shares, rounding up.
        let receive_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);
        assert!(
            receive_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        account.stake_shares -= num_shares;
        account.unstaked += receive_amount;
        account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;
        self.internal_save_account(&account_id, &account);

        // The amount tokens that will be unstaked from the total to guarantee the "stake" share
        // price never decreases. The difference between `receive_amount` and `unstake_amount` is
        // paid from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let unstake_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);

        self.total_staked_balance -= unstake_amount;
        self.total_stake_shares -= num_shares;

    pub(crate) fn num_shares_from_staked_amount_rounded_down(
        &self,
        amount: Balance,
    ) -> NumStakeShares {
        assert!(
            self.total_staked_balance > 0,
            "The total staked balance can't be 0"
        );
        (U256::from(self.total_stake_shares) * U256::from(amount)
            / U256::from(self.total_staked_balance))
        .as_u128()
    }
