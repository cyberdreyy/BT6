## Title
Per-tenure "more than one signed block" reorg guard in `check_parent_tenure_choice` can be bypassed by chaining many single-block tenures - (File: `stacks-signer/src/chainstate/mod.rs`)

### Summary
`SortitionData::check_parent_tenure_choice` is meant to stop a miner from reorging away tenures that already have real, signed history: it explicitly disallows a reorg when a reorged tenure has more than one globally-accepted block. But the check is applied independently to *each* tenure being reorged rather than to the cumulative amount of history the whole reorg discards, so a sequence of many single-block tenures can be reorged away in one shot even though the combined loss is many blocks — exactly the "split a large action into many small ones to dodge a per-item cap" pattern from the source report.

### Finding Description
`check_parent_tenure_choice` walks every tenure between the prior sortition and the new tenure's chosen parent (`tenures_reorged`), and for each one individually enforces: [1](#0-0) 

If `globally_accepted_blocks > 1` for a *single* reorged tenure, the whole reorg is refused. Otherwise (0 or 1 globally accepted block in that tenure), the tenure is either skipped (no blocks) or subjected only to the poor-timing check: [2](#0-1) 

and, if it passes, added to `superseded_tenures`, which are then all marked as superseded once the *whole* reorg is accepted: [3](#0-2) 

Nothing sums `globally_accepted_blocks` (or "poorly-timed" verdicts) across the tenures in `tenures_reorged`. A one-slot miner that wins several consecutive sortitions, each producing exactly one block per tenure timed close enough to the following sortition to satisfy `first_proposal_burn_block_timing`, can build a chain of N single-block tenures. A later competing tenure can then reorg *all* of them in a single `check_parent_tenure_choice` call: each individual tenure has `globally_accepted_blocks <= 1`, so the `>1` guard never fires for any of them, and each individually passes the poor-timing test, so the loop reaches the end and returns `Ok(true)` — permitting the entire multi-block, multi-tenure reorg.

Once permitted, `record_superseded_tenure` marks every one of those N previously-signed tenures as superseded, so the signatures the signer already placed on their blocks stop counting as conflicts (via `reorg_permit_stands`, consumed in the pre-commit conflict check): [4](#0-3) 

The signer then goes on to sign the new, competing tenure's block, discarding N previously globally-accepted blocks — even though the guard's stated intent (see its own doc comment) is to cap this at one block: [5](#0-4) 

### Impact Explanation
This lets a single miner engineer a signer into repeatedly signing blocks on a chain that discards more previously-finalized (globally accepted) history than the "no more than one signed block" invariant is supposed to allow, i.e. the signer ends up signing a conflicting/non-canonical replacement chain that the protection was explicitly designed to prevent. That matches the Critical bucket ("a signer signing an invalid, non-canonical, or conflicting block").

### Likelihood Explanation
No majority of signers, no other signer's key, and no auth token are required — a single miner (one slot) that can win consecutive sortitions and time its single-block tenures near the sortition boundary can construct the scenario deterministically over several tenures. It relies purely on normal proposal/gossip flow through `check_parent_tenure_choice`.

### Recommendation
Aggregate the reorg-safety check across the whole `tenures_reorged` set instead of per tenure: sum `globally_accepted_blocks` (and/or count of poorly-timed vs. not) over all tenures being discarded by this single reorg decision, and reject the reorg if that total exceeds the intended one-block cap, rather than checking each tenure's count in isolation.

### Proof of Concept
1. Miner M wins sortition for tenure T1, produces exactly 1 block, timed such that the block's proposal-to-next-sortition gap is `< first_proposal_burn_block_timing` (satisfies the "poorly timed" exemption).
2. Sortition occurs; M again wins tenure T2, again produces exactly 1 block with the same poor timing property, building on T1.
3. Repeat for T3 … TN (N single-block, poorly-timed tenures), each of which gets globally accepted by signers.
4. M then wins a new sortition and proposes a tenure-change block whose parent is the tenure *before* T1 (i.e., it reorgs away T1..TN in one shot).
5. `check_parent_tenure_choice` iterates `tenures_reorged = [T1, ..., TN]`; each has `globally_accepted_blocks == 1`, so the `>1` guard never trips, and each individually satisfies the poor-timing exemption, so the function returns `Ok(true)`.
6. All of T1..TN are marked superseded; the signer's earlier signatures on T1..TN blocks no longer block signing; the signer signs the new competing tenure, resulting in N previously globally-accepted blocks being discarded in a single reorg despite the intended "more than one signed block" cap. [6](#0-5)

    pub fn check_parent_tenure_choice(
        &self,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        first_proposal_burn_block_timing: &Duration,
    ) -> Result<bool, SignerChainstateError> {
        // if the parent tenure is the last sortition, it is a valid choice.
        // if the parent tenure is a reorg, then all of the reorged sortitions
        //  must either have produced zero blocks _or_ produced their first (and only) block
        //  very close to the burn block transition.
        if self.prior_sortition == self.parent_tenure_id {
            return Ok(true);
        }
        info!(
            "Most recent miner's tenure does not build off the prior sortition, checking if this is valid behavior";
            "sortition_state.consensus_hash" => %self.consensus_hash,
            "sortition_state.prior_sortition" => %self.prior_sortition,
            "sortition_state.parent_tenure_id" => %self.parent_tenure_id,
        );

        let tenures_reorged =
            client.get_tenure_forking_info(&self.parent_tenure_id, &self.prior_sortition)?;
        if tenures_reorged.is_empty() {
            warn!("Miner is not building off of most recent tenure, but stacks node was unable to return information about the relevant sortitions. Marking miner invalid.");
            return Ok(false);
        }

        // this value *should* always be some, but try to do the best we can if it isn't
        let sortition_state_received_time =
            signer_db.get_burn_block_receive_time(&self.burn_block_hash)?;

        // Track which tenures are superseded by the reorg, then mark them in
        // the DB after the reorg is permitted.
        let mut superseded_tenures = Vec::new();
        for tenure in tenures_reorged.iter() {
            if tenure.consensus_hash == self.parent_tenure_id {
                // this was a built-upon tenure, no need to check this tenure as part of the reorg.
                continue;
            }

            // disallow reorg if more than one block has already been signed
            let globally_accepted_blocks =
                signer_db.get_globally_accepted_block_count_in_tenure(&tenure.consensus_hash)?;
            if globally_accepted_blocks > 1 {
                warn!(
                    "Miner is not building off of most recent tenure, but a tenure they attempted to reorg has already more than one globally accepted block.";
                    "parent_tenure" => %self.parent_tenure_id,
                    "last_sortition" => %self.prior_sortition,
                    "violating_tenure_id" => %tenure.consensus_hash,
                    "violating_tenure_first_block_id" => ?tenure.first_block_mined,
                    "globally_accepted_blocks" => globally_accepted_blocks,
                );
                return Ok(false);
            }
