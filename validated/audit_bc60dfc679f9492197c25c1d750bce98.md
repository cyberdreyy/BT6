### Title
Unsanitized secret `variableKey` allows path traversal in file-backed variable materialization - (File: `shells/bash.go`, `shells/powershell.go`, reached via `common/secrets.go`)

### Summary
The `secrets:` map key (`variableKey`) is passed unsanitized from `defaultSecretsResolver.Resolve`/`handleSecret` into a `spec.Variable{Key: variableKey, File: true}`, which the shell writers then use directly as a filename joined with the job's temporary/variables directory. Because the join uses `path.Join`/`filepath` semantics that normalize `..` segments, a crafted key such as `../../malicious` causes the on-disk file for the "file secret" to be written outside the intended variables directory.

### Finding Description
`defaultSecretsResolver.Resolve` iterates the job's `spec.Secrets` map and calls `handleSecret(variableKey, secret)` without any validation of `variableKey` [1](#0-0) . `handleSecret` builds `&spec.Variable{Key: variableKey, File: secret.IsFile(), ...}` directly from the raw map key [2](#0-1) . The azure-key-vault resolver only resolves the secret *value*; it has no knowledge of or control over `variableKey` at all [3](#0-2) .

Downstream, when the shell script is generated, `BashWriter.Variable` handles `File: true` variables by computing `variableFile := b.TmpFile(variable.Key)`, where `TmpFile` does `b.cleanPath(path.Join(b.TemporaryPath, name))` [4](#0-3) [5](#0-4) . `path.Join` calls `path.Clean`, which collapses `..` segments against the preceding path components — a `variable.Key` of `"../../malicious"` therefore resolves outside `TemporaryPath` (e.g., `/builds/proj/tmp` + `../../malicious` → `/builds/malicious`). The same pattern exists in `PsWriter.Variable`/`TmpFile` for PowerShell [6](#0-5) .

No sanitization/allow-list of characters (e.g., rejecting `/`, `\`, or `..`) is applied to `variableKey` anywhere in this path — not in `spec.Secrets` parsing, not in `defaultSecretsResolver`, and not in the shell writers before the path join.

### Impact Explanation
An unprivileged job author who can define a `secrets:` entry with an attacker-chosen map key (e.g. `secrets: {"../../malicious": {vault: ..., file: true}}`) can cause the runner-generated job script to write the resolved (masked) secret value to a file path outside the job's dedicated variables/temp directory, within the reach of the executor's working filesystem. This breaks the invariant that "file operations must stay within intended build/cache/artifact roots" for the specific variables directory, and could be leveraged to overwrite files the runner itself created earlier in the same filesystem tree (e.g. sibling temp files, other file-variables, or cache/build-adjacent paths depending on directory depth and `..` count), independent of any script command the job runs.

### Likelihood Explanation
Feasibility is high and fully attacker-controlled: no privileged action, external compromise, or malicious peer is required — only the ability to write a `.gitlab-ci.yml`/pipeline definition with a `secrets:` block containing a crafted key and a resolvable file-type secret (precondition already stated as satisfied). The bug reproduces deterministically given `path.Join`'s well-known `..`-collapsing behavior, and is already implicitly exercised by unit tests in `bash_test.go`/`powershell_test.go` that only test benign keys, never `..`-laden ones [7](#0-6) .

### Recommendation
Sanitize/validate `variableKey` before constructing file-backed `spec.Variable`s — reject or escape keys containing path separators (`/`, `\`) or `..` segments in `defaultSecretsResolver.handleSecret` (`common/secrets.go`), and/or make `BashWriter.TmpFile`/`PsWriter.TmpFile` defensively confine the resulting path to remain within `TemporaryPath` (e.g., using `filepath.Rel` + rejecting results that start with `..`, or `filepath.Base` on the key component before joining).

### Proof of Concept
Go unit test targeting `shells/bash.go`:
```go
func Test_BashWriter_Variable_PathTraversal(t *testing.T) {
    bw := BashWriter{TemporaryPath: "/builds/project/tmp"}
    bw.Variable(spec.Variable{Key: "../../malicious", Value: "secret", File: true})
    out := bw.String()
    // Assert the generated script never writes outside TemporaryPath
    assert.NotContains(t, out, "> \"/builds/malicious\"")
    assert.Contains(t, out, "/builds/project/tmp/")
}
```
Expected (current, buggy) behavior: the generated script contains `printf '%s' $'secret' > "/builds/malicious"`, i.e. outside `/builds/project/tmp`, proving the escape. A companion integration/fuzz test can drive this through `common/secrets.go`'s `defaultSecretsResolver.Resolve` with a `spec.Secrets{"../../malicious": secret}` map and an azure-key-vault mock resolving successfully with `IsFile()==true`, asserting the emitted `spec.Variable.Key` still contains `..`/`/` and that downstream shell generation is not confining it.

func (v *azureKeyVaultResolver) Resolve() (string, error) {
	if !v.IsSupported() {
		return "", secrets.NewResolvingUnsupportedSecretError(resolverName)
	}

	secret := v.secret.AzureKeyVault
	s, err := newVaultService(secret.Server)
	if err != nil {
		return "", err
	}

	name := secret.Name
	version := secret.Version

	data, err := s.GetSecret(name, version)

	if err != nil {
		return "", err
	}

	return fmt.Sprintf("%v", data), nil
}

func (b *BashWriter) Variable(variable spec.Variable) {
	if variable.File {
		variableFile := b.TmpFile(variable.Key)
		b.Linef("mkdir -p %q", helpers.ToSlash(b.TemporaryPath))
		b.Linef("printf '%%s' %s > %q", b.escape(variable.Value), variableFile)
		b.Linef("export %s=%q", b.escape(variable.Key), variableFile)
	} else {
		if b.isTmpFile(variable.Value) {
			variable.Value = b.cleanPath(variable.Value)
		}
		b.Linef("export %s=%s", b.escape(variable.Key), b.escape(variable.Value))
	}
}

func (p *PsWriter) Variable(variable spec.Variable) {
	if variable.File {
		variableFile := p.TmpFile(variable.Key)
		p.MkDir(p.TemporaryPath)
		p.Linef(
			"[System.IO.File]::WriteAllText(%s, %s)",
			p.resolvePath(variableFile),
			psQuoteVariable(variable.Value),
		)
		p.Linef("${%s}=%s", variable.Key, p.resolvePath(variableFile))
	} else {
		if p.isTmpFile(variable.Value) {
			variable.Value = p.cleanPath(variable.Value)
		}

		p.Linef("${%s}=%s", variable.Key, psQuoteVariable(variable.Value))
	}

	p.Linef("${env:%s}=${%s}", variable.Key, variable.Key)
}
