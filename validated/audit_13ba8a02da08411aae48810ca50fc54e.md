### Title
Repeated conflicting/rejected block proposals let a one-slot miner indefinitely refresh its own tenure's activity clock, wedging signer fallback - ([File: stacks-signer/src/chainstate/mod.rs])

### Summary
`check_latest_block_in_tenure` treats a rejected block proposal that conflicts with another tenure's *locally-accepted-only* (not yet globally accepted) last block as unconditional "miner activity" for the proposer's own tenure, regardless of how long ago that conflict was created. Because this activity credit resets `is_timed_out`'s clock, a miner holding the current slot can keep the tenure's inactivity timer alive forever by sending nothing but conflicting/invalid proposals, preventing signers from ever falling back to a prior miner and stalling block production — a liveness wedge.

### Finding Description
`check_latest_block_in_tenure` (`stacks-signer/src/chainstate/mod.rs:376-478`) is called with a `tenure_id` (the *parent* tenure for a tenure-change block, the block's *own* tenure otherwise) and looks up that tenure's last signed block via `SortitionData::get_tenure_last_block_info`. [1](#0-0) 

When the newly-proposed block does not confirm enough of that tenure (`chain_length <= info.block.header.chain_length`), the proposal is rejected, but the code still decides whether to count it as valid "miner activity":

```
if info.signed_group.is_none_or(|signed_time| {
    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
}) {
    ...
    signer_db.update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
}
``` [2](#0-1) 

`Option::is_none_or` returns `true` unconditionally when `signed_group` is `None`. The intended time bound (`reorg_attempts_activity_timeout`) is only applied when the conflicting block *was* globally accepted (`signed_group` set). If the conflicting tenure's last block is only **locally accepted** (a comment elsewhere confirms `signed_group` is only set once "the group threshold is observed" and is otherwise `None` — see `stacks-signer/src/v0/signer.rs:2525-2537`), the freshness gate is skipped entirely, and `update_last_activity_time` fires every time, no matter how stale the underlying conflict actually is.

Crucially, `update_last_activity_time` is keyed on `block.header.consensus_hash` — the **proposer's own new tenure**, not the `tenure_id` being checked against. [3](#0-2) 

This activity timestamp is exactly what feeds `is_timed_out` in both protocol versions:

```
let last_activity = db.get_last_activity_time(sortition)?...unwrap_or(received_time);
...
Ok(elapsed > block_proposal_timeout)
``` [4](#0-3) [5](#0-4) 

`is_timed_out` is the single trigger that lets signers fall back to the prior tenure when the current miner goes silent (`check_miner_inactivity`, section 8 of `docs/signer-flows.md`): [6](#0-5) 

So the equality/threshold this breaks is: *"time since last genuine miner activity vs. `block_proposal_timeout`"*. A miner can keep that comparison perpetually false — without ever producing a single validly-signed block — by repeatedly proposing conflicting blocks against a tenure whose head is only locally (not globally) accepted, since the freshness check that should gate this activity credit is bypassed for that case.

### Impact Explanation
This is a High-severity liveness wedge: the current one-slot miner, by itself, can indefinitely suppress the inactivity fallback (`is_timed_out` never returns `true`), so signers never execute `FALL["fall back to prior tenure"]`. No majority of signers, no other signer's key, and no auth token are required — only the currently-active miner's ordinary ability to submit block proposals. The chain stalls behind an unproductive/malicious miner until the operator intervenes, satisfying the High-impact category "a signer wedged into never signing valid blocks... or acting on a stale... threshold."

### Likelihood Explanation
Likelihood is moderate-to-high in scenarios where a miner's own or a preceding tenure's last block is locally-but-not-yet-globally accepted (e.g., during a slow signature aggregation, a stalled push to the node, or right after a tenure handoff) — a routine, not rare, condition given the existing "50/50 pre-commit/signature split" scenarios documented in the codebase itself. Within that window, the exploit requires only cheap, repeated proposal submissions from the current miner; no cryptographic breakage, no cooperation from other signers, and no bitcoin-level control are needed.

### Recommendation
Apply the same `reorg_attempts_activity_timeout` freshness bound to the `signed_group.is_none()` (locally-accepted-only) branch that is already applied to the globally-accepted branch — e.g., derive a comparable "accepted since" timestamp for locally-accepted blocks and require it to be within `reorg_attempts_activity_timeout` before crediting activity, instead of unconditionally granting activity whenever `signed_group` is absent. Alternatively, bound the total activity-refresh window per tenure independent of individual proposal timestamps, so repeated conflicting proposals cannot indefinitely extend `is_timed_out`'s clock.

### Proof of Concept
1. Tenure A's last block reaches `LocallyAccepted` (70% pre-commit/signature weight) but is not yet observed as globally accepted by this signer (`signed_group` stays `None`), e.g. due to a delayed `broadcast_signed_block`/node ingestion.
2. A new miner starts tenure B (a tenure-change block whose `tenure_id` for the check is tenure A).
3. Miner B repeatedly submits tenure-change block proposals for tenure B whose `chain_length` does not exceed tenure A's locally-accepted tip — each is rejected by `check_latest_block_in_tenure`.
4. Because `info.signed_group` is `None` for tenure A's last block, the `is_none_or` freshness gate is bypassed on every single one of these rejected proposals, and `signer_db.update_last_activity_time(&block.header.consensus_hash, now)` is called every time, refreshing tenure B's own activity clock.
5. `SortitionState::is_timed_out` for tenure B (v1: `stacks-signer/src/chainstate/v1.rs:55-94`; v2: `stacks-signer/src/chainstate/v2.rs:46-89`) never exceeds `block_proposal_timeout`, since `get_last_activity_time` keeps advancing.
6. Signers therefore never invoke the `FALL` transition (`check_miner_inactivity`) to fall back to the prior tenure's miner, and no valid block is ever signed for tenure B — the chain stalls as long as miner B keeps repeating step 3, at negligible cost.

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }

    /// Check if the sortition identified by the ConsensusHash is timed out based on
    /// the blocks within the signer db and the block proposal timeout
    pub fn is_timed_out(
        sortition: &ConsensusHash,
        signer_db: &SignerDb,
        eval: &GlobalStateEvaluator,
        local_address: &StacksAddress,
        timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = signer_db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) =
            signer_db.get_burn_block_received_time_from_signers(eval, sortition, local_address)?
        else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = signer_db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };
        if elapsed > timeout {
            info!("Sortition has timed out";
                "sorition" => %sortition,
                "timeout" => %timeout.as_secs(),
                "elapsed" => %elapsed.as_secs()
            )
        }
        Ok(elapsed > timeout)
    }
