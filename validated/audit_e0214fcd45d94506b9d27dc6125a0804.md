## Title
Stale Confirmations From Deleted Members Are Still Counted Toward the Multisig Execution Threshold - (File: multisig2/src/lib.rs)

### Summary
`MultiSigContract::confirm` in `multisig2/src/lib.rs` counts entries in the `confirmations` `HashSet<String>` for a request without verifying that each entry still corresponds to a *current* multisig member. `delete_member` only purges requests and confirmations for requests **created (added)** by the removed member — it does not scan and strip that member's confirmation from other pending requests they had merely confirmed. A confirmation recorded by a member before their removal therefore remains valid "weight" toward `num_confirmations`, breaking the equality `confirmations counted == live members who confirmed`.

### Finding Description
`confirm()` reads the confirmations set and checks only whether the *current* caller already confirmed, then compares set size to the threshold: [1](#0-0) 

Member removal (`DeleteMember` → `delete_member`) removes the deleted member from `self.members` and cleans up *only* requests where that member was the original requester (`r.member == member`), never scrubbing that member's `confirmations` entries from any other request they had confirmed: [2](#0-1) 

Consequently, if member A confirms request R (added to the `confirmations` set for R), and is later removed via a separate `DeleteMember` request, R's confirmation set still contains A's identifier. When enough *current* members later confirm R, `confirmations.len() as u32 + 1 >= self.num_confirmations` at line 304 counts A's stale confirmation as live, letting the request execute with fewer than `num_confirmations` currently-authorized signers.

### Impact Explanation
This is a Critical-class issue per the custody binding invariant: "confirmations counted versus live members." It allows a multisig request (including `Transfer`, `FunctionCall`, `AddKey`, `DeployContract`, etc.) to be executed below the configured K-of-N threshold of currently trusted members, i.e. funds or privileged actions can be authorized by fewer live signers than the account owner intended — a wrongly-authorized execution of custody-affecting actions (including moving NEAR held by the multisig account).

### Likelihood Explanation
Reaching this requires: (1) a request added and confirmed by member A but not yet reaching threshold, (2) a separate governance action removing A as a member, (3) A's stale confirmation persisting on the still-pending request, and (4) sufficient additional confirmations from remaining current members to reach the old count including the stale one. This is a realistic operational sequence (member rotation is a normal multisig lifecycle event) and requires no attacker-controlled deployment, key theft, or foundation-only actions — only normal multisig membership churn while a request is outstanding, which unprivileged/normal members can trigger through ordinary confirm/delete-member flows.

### Recommendation
When executing `DeleteMember`, iterate all pending `requests`/`confirmations` and remove the deleted member's entry from every `confirmations` set (not just requests they originated), or alternatively re-validate at `confirm()` time that every entry in the stored `confirmations` set still belongs to `self.members` before counting toward the threshold.

### Proof of Concept
1. Deploy `multisig2` with 3 members {A, B, C}, `num_confirmations = 3`.
2. Member A calls `add_request_and_confirm(request_transfer)` → confirmations = {A}.
3. Separately, members confirm and execute a `DeleteMember{A}` request (assuming `num_confirmations` for that governance action can be met by B, C, and a third member D added earlier, or a lower threshold applies) — A is removed from `self.members`, but the confirmation entry "A" on `request_transfer` is untouched because `delete_member` only cleans requests originated by A.
4. Members B and C each call `confirm(request_transfer)`. On C's call, `confirmations.len() (2, containing stale A + B) + 1 >= 3` is true, so the transfer executes with only 2 genuinely live confirmations (B, C) plus one stale one from removed member A, even though 3 live confirmations were required.     /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
