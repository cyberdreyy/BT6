### Title
Zip-Slip path traversal in `ExtractZipArchive`/`lchmod` allows chmod (and file write) outside the extraction root - ([File: helpers/archives/zip_extract.go], [File: helpers/archives/os_unix.go])

### Summary
`ExtractZipArchive` never sanitizes `zip.File.Name` for `../` path-traversal segments before using it in `os.Mkdir`, `os.OpenFile`, `os.Symlink`, and in the second-pass `lchmod` call. An unprivileged CI job can craft an artifact/cache zip with a `FileHeader.Name` such as `../victim/file`, causing both the write phase and the `unix.Fchmodat(unix.AT_FDCWD, name, ...)` chmod phase to operate on a path outside the intended extraction directory.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) iterates `archive.File` twice: first calling `extractZipFile` (which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then `os.OpenFile`/`os.Mkdir`/`os.Symlink` directly on `file.Name`), then calling `lchmod(file.Name, file.Mode())` which resolves to `unix.Fchmodat(unix.AT_FDCWD, name, ...)` on Unix (helpers/archives/os_unix.go:12-29). The only validation applied to `file.Name` is `errorIfGitDirectory`, which merely checks whether the cleaned path's first component is `.git` (helpers/archives/path_check_helper.go:13-19); it performs no check for `..` segments or absolute paths. There is no `filepath.Clean`+prefix check, no `filepath.Rel` validation against the extraction root, and no chroot/chdir confinement — `extractor.dir` in `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32` is even stored but never used to constrain the extraction, relying entirely on the process's current working directory. Consequently, a `FileHeader.Name` of `../victim/file` will (1) write/overwrite `../victim/file` relative to CWD during the write pass, and (2) `Fchmodat(AT_FDCWD, "../victim/file", mode, ...)` during the chmod pass, both resolving outside the intended cache/artifact/checkout root.

### Impact Explanation
Since the write pass already performs the traversal (`os.OpenFile(file.Name, ...)` with an unsanitized `../` path) before `lchmod` runs, the practical impact combines content overwrite and permission tampering on files outside the job's workspace — e.g., another job's checkout or shared cache directory contents on the same host/executor (shell/docker-with-shared-volume scenarios where multiple jobs share a filesystem root), matching the "cross-tenant cache/artifact/checkout/helper-state poisoning" scope.

### Likelihood Explanation
Exploitation only requires an unprivileged pipeline author to produce a cache or artifact zip with attacker-chosen entry names (trivial via `archive/zip`'s `zip.Writer` API, which does not restrict `FileHeader.Name`), then have Runner extract that archive on a subsequent job/pipeline run via the `artifacts:paths`/`cache` restore mechanism that calls `ExtractZipArchive`. This is highly repeatable and requires no special privileges beyond authoring a `.gitlab-ci.yml` job that produces the malicious archive.

### Recommendation
Before any file operation in `extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and before the `lchmod` call, validate that `filepath.Clean(file.Name)` does not start with `..` or an absolute path separator, or resolve the target relative to a known extraction root and verify with `filepath.Rel`/prefix checks (analogous to the existing `.git` guard in `path_check_helper.go`) that the resolved path stays within that root; reject or skip entries that fail the check, consistent with standard zip-slip mitigations.

### Proof of Concept
```go
func TestExtractZipArchive_PathTraversal(t *testing.T) {
    tmp := t.TempDir()
    victimDir := filepath.Join(filepath.Dir(tmp), "victim")
    require.NoError(t, os.MkdirAll(victimDir, 0o755))
    victimFile := filepath.Join(victimDir, "file")
    require.NoError(t, os.WriteFile(victimFile, []byte("orig"), 0o600))

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    fh := &zip.FileHeader{Name: "../victim/file"}
    fh.SetMode(0o777)
    w, _ := zw.CreateHeader(fh)
    _, _ = w.Write([]byte("owned"))
    require.NoError(t, zw.Close())

    // chdir into tmp to emulate extraction root
    wd, _ := os.Getwd()
    defer os.Chdir(wd)
    os.Chdir(tmp)

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    _ = archives.ExtractZipArchive(zr)

    info, err := os.Stat(victimFile)
    require.NoError(t, err)
    // Assert content/permissions were changed outside extraction root
    assert.NotEqual(t, os.FileMode(0o600), info.Mode().Perm(), "victim file mode should not have been altered")
    content, _ := os.ReadFile(victimFile)
    assert.NotEqual(t, "orig", string(content), "victim file content should not have been overwritten")
}
```
Expected (buggy) result: the assertions fail because `victimFile`'s content and mode are modified, proving both the write and `lchmod` phases escape the extraction root.
