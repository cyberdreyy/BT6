### Title
Unbounded inactivity-timeout reset via `get_last_activity_time` allows a winning miner to indefinitely stall tenure fallback - (File: `stacks-signer/src/chainstate/v1.rs`)

### Summary
`SortitionState::is_timed_out` computes elapsed inactivity from `SignerDb::get_last_activity_time`, falling back to `get_burn_block_receive_time_ch` only when no activity timestamp exists yet, with no upper bound tied to the original burn-block receipt time. Because `last_activity` is refreshable by continuing miner activity (proposal resubmission/tenure traffic that the winning miner fully controls) short of an actual signed block, the timeout is effectively re-armable indefinitely, defeating the intended bounded-liveness guarantee.

### Finding Description
The relevant logic in [1](#0-0)  is:

```
let has_block = db.has_signed_block_in_tenure(sortition)?;
if has_block { return Ok(false); }
let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else { return Ok(false); };
let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
let last_activity = db.get_last_activity_time(sortition)?
    .map(|time| UNIX_EPOCH + Duration::from_secs(time))
    .unwrap_or(received_time);
let elapsed = SystemTime::now().duration_since(last_activity)...;
Ok(elapsed > block_proposal_timeout)
```

The only hard stop against timing out is `has_signed_block_in_tenure` — i.e., a fully-signed block, as the code comment itself explains, explicitly to prevent pre-commits (which carry no signature) from suppressing the timeout indefinitely: [2](#0-1) .

However, the elapsed baseline used for the actual comparison is `last_activity`, not a value bounded relative to `received_time`. Any mechanism that advances `get_last_activity_time(sortition)` — such as the winning miner (attacker) re-submitting proposals or other tenure-related signer traffic for the same consensus hash at intervals under `block_proposal_timeout` — resets the elapsed clock to zero each time, and `is_timed_out` never returns `true` because `elapsed` measured from `last_activity` never exceeds the timeout, regardless of how much total time has passed since `received_time`. The design comment shows the authors were aware that pre-commits alone must not block the timeout, but the fix (checking `has_signed_block_in_tenure`) does not address the more general problem that the elapsed-time *baseline* itself is fully attacker-resettable, since it only requires activity short of a full signature.

`is_timed_out` is invoked from `check_proposal` for both the current and last sortition [3](#0-2) [4](#0-3) , and is the sole gate that flips `miner_status` to `InvalidatedBeforeFirstBlock`, which is what allows the signer to fall back to the previous sortition's miner via `ProposedBy::LastSortition` [5](#0-4) . If this gate never trips, the signer set can never fail over away from the misbehaving/stalling current miner.

I was not able to fully trace, within the available tool budget, every call site that writes `update_last_activity_time` in `signerdb.rs` / `v0/signer_state.rs` / `chainstate/mod.rs` to enumerate precisely which non-completion events refresh it (this needs further verification). But the structural flaw is confirmed directly in `is_timed_out`: it lacks any ceiling on total elapsed time since `received_time`, so any legitimate write to `last_activity_time` short of a full signed block — which the winning miner can trigger at will by continuing to interact with the tenure — defeats the bounded timeout by construction.

### Impact Explanation
This breaks the bounded-liveness guarantee: `is_timed_out` is supposed to guarantee fallback to the prior miner within `block_proposal_timeout` of a tenure's burn block, "regardless of unrelated gossip." Instead, a winning-but-malicious miner (or any input capable of nudging `last_activity`) can hold the tenure hostage indefinitely — the miner_status is never marked `InvalidatedBeforeFirstBlock`, and `last_sortition`-based fallback in `check_proposal` [5](#0-4)  is never reached. This matches the High-severity category: "a signer wedged into never signing valid blocks (liveness)" — the tenure stalls with no recovery path short of the attacker eventually completing a real signed block (which they can indefinitely avoid).

### Likelihood Explanation
Preconditions are modest and match the stated unprivileged-attacker model: the attacker needs to win one miner slot (achievable with their own BTC) and be able to submit at least one valid proposal to get pre-committed, then simply avoid ever letting a block reach full signature while continuing enough tenure-related activity to keep `last_activity` fresh. No majority-signer collusion, no compromised keys, and no local/node access is required — only the attacker's own miner role plus normal message gossip that any signer already processes. This is repeatable every time the attacker wins a sortition slot.

### Recommendation
Bound the elapsed computation in `is_timed_out` by the original `received_time`, not solely by the resettable `last_activity`. For example, compute the timeout as the *minimum* of `(now - last_activity)` and `(now - received_time)`, or enforce a hard ceiling: `elapsed_since_receipt > max_timeout_ceiling` triggers timeout unconditionally regardless of subsequent activity, so that no amount of gossip/proposal resubmission short of `has_signed_block_in_tenure` can indefinitely suppress the fallback.

#[test]
fn is_timed_out_not_resettable_by_repeated_activity_without_signed_block() {
    let db = test_signer_db("is_timed_out_activity_reset.sqlite");
    let sortition = ConsensusHash([0x11; 20]);
    let block_proposal_timeout = Duration::from_secs(30);

    // record burn block receipt time far in the past
    let received_ts = get_epoch_time_secs() - 120;
    db.insert_burn_block_receive_time_for_test(&sortition, received_ts); // helper to seed table

    // simulate attacker repeatedly refreshing last_activity_time
    // just under the timeout, without ever producing a signed block
    for _ in 0..5 {
        db.update_last_activity_time(&sortition, get_epoch_time_secs()).unwrap();
        // sleep less than block_proposal_timeout between refreshes
        std::thread::sleep(Duration::from_secs(5));
        assert!(!db.has_signed_block_in_tenure(&sortition).unwrap());
        // BUG: with current code, this stays false indefinitely
        assert!(!SortitionState::is_timed_out(&sortition, &db, block_proposal_timeout).unwrap());
    }

    // EXPECTED (fixed) behavior: once elapsed since received_ts exceeds
    // a hard ceiling, is_timed_out must return true even though
    // last_activity was just refreshed.
    assert!(
        SortitionState::is_timed_out(&sortition, &db, block_proposal_timeout).unwrap(),
        "is_timed_out must trip based on received_time ceiling, not resettable last_activity"
    );
}

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
