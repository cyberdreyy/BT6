### Title
Attacker dust `requestDeposit` poisons epoch pending deposits, causing a permanent divide-by-zero revert in `IdleCDOEpochQueue.processDeposits` - ([contracts/IdleCDOEpochQueue.sol:244](contracts/IdleCDOEpochQueue.sol))

### Summary
A crafted-input crash analog: like the NULL-pointer deref in `dex_parse_debug_item`, a single attacker-controlled 1-wei `requestDeposit` makes the aggregate minted-tranche amount round to `0`, so `epochPrice[_epoch] = _pending * ONE_TRANCHE / _trancheMinted` panics on division by zero. The revert is permanent for that epoch's whole deposit batch, permanently blocking `processDeposits` and `claimDepositRequest` for every honest depositor queued in the same epoch.

### Finding Description
- `requestDeposit` accepts any `amount` (no minimum) and folds it into the shared aggregate `epochPendingDeposits[nextEpoch]` (`contracts/IdleCDOEpochQueue.sol:121-126`).
- During the buffer period, `processDeposits` deposits the entire aggregate via `depositAA`/`depositBB`, then computes `epochPrice[_epoch] = _pending * ONE_TRANCHE / _trancheMinted` (line 244).
- `_mintSharesAtCurrPrice` in `IdleCDOCreditVault.sol:346` computes `_minted = _amount * ONE_TRANCHE_TOKEN / _tranchePrice(_tranche)` with no zero-share check; `IdleCDOTranche.mint` of `0` does not revert.
- The epoch tranche price is `> 1e18` whenever the tranche has accrued any interest (priceAA/priceBB start at `oneToken` and grow). Once `virtualPrice > _pending * 1e18 / 1`, i.e. whenever the total queued batch is smaller than `virtualPrice / 1e12` underlying units for USDC (6 decimals), `_trancheMinted == 0`.
- More practically: the aggregate is shared, so the attacker only needs `epochPendingDeposits` to remain below the threshold — but even with large honest deposits, the attacker can queue alone in an epoch where only small deposits exist, or when TVL share is high. Once `_trancheMinted == 0`, line 244 reverts with a panic on every call, and `epochPendingDeposits[_epoch]` can never be cleared through the intended path.
- The prefunded variant explicitly guards this exact case (`_prefundedMinted == 0 ? virtualPrice : ...` at line 270), confirming the crash is unintended in the non-prefunded path.
- `claimDepositRequest` reverts while `epochPrice == 0`, so the "processed" path is permanently dead for that epoch; only the fallback `deleteRequest` rescue remains.

### Impact Explanation
Denial of service with fund impact: all underlyings queued for that epoch are frozen inside `IdleCDOEpochQueue` — the manager can never batch-process them, and every affected user must individually discover and call `deleteRequest` to recover funds. The attacker repeats the 1-wei deposit every epoch at negligible cost, so the queue's deposit flow is griefed indefinitely (temporary freezing of each victim's deposit for the duration, plus permanent loss of the batched-deposit path). Quantified loss = the entire `epochPendingDeposits[_epoch]` of honest users for the epoch (held in the queue contract until manual rescue).

### Likelihood Explanation
Requires only a KYC-passing wallet and 1 wei of underlying during a running epoch (`_checkAllowed` only gates on `isEpochRunning` + `isWalletAllowed`). Condition needed: queued batch small enough that `amount * 1e18 / tranchePrice == 0` — trivially reachable for a USDC pool once tranche price exceeds ~1e12 wei-normalized units, or whenever the attacker is the only queued depositor. No privileged action required.

### Recommendation
Mirror the prefunded fix in `processDeposits`: handle `_trancheMinted == 0` explicitly, e.g. `epochPrice[_epoch] = _trancheMinted == 0 ? _cdo.virtualPrice(tranche) : _pending * ONE_TRANCHE / _trancheMinted;` (line 244). Additionally enforce a minimum `requestDeposit` amount (e.g. ≥ `oneToken`) so a dust deposit cannot round a batch to zero shares.

### Proof of Concept
```solidity
// Foundry fork PoC (non-prefunded IdleCDOEpochVariant + IdleCDOEpochQueue, USDC underlying)
// Pre: epoch running, tranche virtualPrice > 1e18 (interest accrued), attacker is KYC-allowed.

function testDustDepositDivZeroFreeze() external {
    // 1) Honest user queues a small deposit (or attacker is alone in the epoch)
    deal(address(underlying), attacker, 1);
    vm.startPrank(attacker);
    underlying.approve(address(queue), 1);
    queue.requestDeposit(1);           // 1 wei -> epochPendingDeposits[nextEpoch] = 1
    vm.stopPrank();

    // 2) Epoch stops; manager calls processDeposits in buffer period
    _stopCurrentEpoch();               // manager-funded stop, epochNumber now == nextEpoch

    // 3) depositAA(1) mints 0 tranche tokens (1 * 1e18 / price(>1e18) == 0),
    //    then `_pending * ONE_TRANCHE / _trancheMinted` panics (division by zero)
    vm.expectRevert();                 // panic 0x12
    vm.prank(manager);
    queue.processDeposits();

    // Repeats forever: epochPendingDeposits stays 1, epochPrice stays 0,
    // claimDepositRequest reverts NotAllowed for every depositor of that epoch.
    assertEq(queue.epochPendingDeposits(strategy.epochNumber()), 1);
    assertEq(queue.epochPrice(strategy.epochNumber()), 0);
}
```
