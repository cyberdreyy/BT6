### Title
Signer can be wedged into rejecting every proposal (`NoSignerConsensus`) via a non-persisted `tx_replay_scope` that desyncs from the persisted `tx_replay_set` after a routine restart or global-state update - (File: `stacks-signer/src/v0/signer_state.rs`)

### Summary
`LocalStateMachine::bitcoin_block_arrival` derives `ReplayState` from two pieces of data that do not share the same lifetime: `tx_replay_set` (carried inside `SignerStateMachine`, which is part of the signer's persisted/propagated local state) and `tx_replay_scope` (a plain `ReplayScopeOpt` field kept only in memory on the `Signer` struct, reset to `None` on every process start). If a signer ever has a non-empty `tx_replay_set` while `tx_replay_scope` is `None`, `ReplayState::infer_state` returns `None`, and `bitcoin_block_arrival` returns `Err(SignerChainstateError::LocalStateMachineNotReady)` after having already replaced `self` with `LocalStateMachine::Uninitialized`. Any block proposal evaluated while `local_state_machine == Uninitialized` is later rejected with `NoSignerConsensus` in `check_block_against_global_state`, i.e. every proposal is rejected until a subsequent `NewBurnBlock` event happens to recover the state (by silently discarding the replay set). This is the same bug class as the reported `dettachFromManagedNFT`/`_vote` issue: a routine, always-reachable state transition recomputes over stale auxiliary data (a "killed gauge" analog: a dropped in-memory scope) and hard-fails instead of degrading gracefully, temporarily wedging a required action (there: detaching a veNFT; here: producing/accepting a signature).

### Finding Description
- `ReplayScope`/`ReplayScopeOpt` is explicitly documented as local, non-persisted state:
`stacks-signer/src/v0/signer_state.rs:126` — "Possibly caused by the scope being a local state in the `Signer` struct, which is not persisted."
- On `Signer::new`, `tx_replay_scope` is unconditionally initialized to `None`:
`stacks-signer/src/v0/signer.rs:318` (`tx_replay_scope: None,`).
- The `LocalStateMachine`'s `SignerStateMachine.tx_replay_set`, by contrast, is either loaded from the persisted/propagated `StateMachineUpdate` (via `global_state_evaluator`/signer DB `get_signer_state_machine_updates`) or carried across `bitcoin_block_arrival` calls in `prior_state_machine.tx_replay_set` — i.e. it can outlive the in-process `tx_replay_scope`.
- `bitcoin_block_arrival` (`stacks-signer/src/v0/signer_state.rs:561-638`) does:
  1. `let prior_state = std::mem::replace(self, Self::Uninitialized);` — self is optimistically nulled out.
  2. Computes `tx_replay_set` from `prior_state_machine.tx_replay_set`.
  3. `let replay_state = match ReplayState::infer_state(&tx_replay_set, tx_replay_scope) { Some(..) => ..., None => { warn!(...); return Err(SignerChainstateError::LocalStateMachineNotReady); } };`
  4. On this `None` branch, `self` is **not** restored to `prior_state`/`Pending` — it is left as `Uninitialized`, and the function returns `Err`.
- `ReplayState::infer_state` (`stacks-signer/src/v0/signer_state.rs:112-135`) returns `None` precisely when `replay_set` is non-empty but `scope_opt` is `None` — exactly the state produced by a process restart (or any other event that clears `tx_replay_scope` without also clearing `tx_replay_set`) while transaction replay is in progress.
- While `self.local_state_machine == LocalStateMachine::Uninitialized`, `check_block_against_global_state` cannot obtain a `MinerState::ActiveMiner` view; `determine_active_signer_protocol_version`/`check_block_against_state` fall back to `RejectReason::NoSignerConsensus` for every incoming proposal (`stacks-signer/src/v0/signer.rs:826-835`, `941-958`).
- Recovery is not immediate: the *next* `bitcoin_block_arrival` call sees `prior_state == LocalStateMachine::Uninitialized` and takes the `Self::place_holder(...)` branch, producing a fresh `SignerStateMachine` with `tx_replay_set = ReplayTransactionSet::none()`. That masks the symptom (the signer eventually starts validating again) but at the cost of silently discarding the transaction-replay set that the rest of the (majority-driven) network may still be legitimately enforcing, and only after this signer contributed zero votes/signatures for at least one burn-block cycle.

This exactly mirrors the reported analog: a routine "recompute" step (`_vote`/`_poke` re-derives votes over killed gauges; `bitcoin_block_arrival` re-derives replay state over a scope that "died" across a restart) that hard-fails on a stale/absent piece of auxiliary state instead of treating it as a benign, ignorable case, blocking a normal, single-actor-triggerable action (signing/validating blocks) until an unrelated external event repairs it.

### Impact Explanation
This matches the High-severity bucket: "a signer wedged into never signing valid blocks... or losing the equivocation guard on restart." Concretely:
- Any signer that restarts (deployment, crash-restart, upgrade) while `validate_with_replay_tx` is enabled and a replay set is active (a state reachable by any Bitcoin fork touching a prior tenure, not requiring a majority or malicious actor) will reject every block proposal it sees until the next `NewBurnBlock` event fires and forces the placeholder recovery path.
- During that window the signer contributes neither a pre-commit nor a rejection with useful information; if enough signers are restarted in the same window (e.g., during a coordinated software upgrade), the group could fail to reach the 70% pre-commit/acceptance threshold, stalling tenure production — a liveness wedge, not merely a single-signer inconvenience.
- Even for a single signer, this silently discards an in-progress transaction-replay commitment (`tx_replay_set` is reset to empty by the placeholder recovery) without going through the documented failsafe (`handle_possible_replay_failsafe`), which is a distinct correctness regression from the intended tx-replay protocol.

### Likelihood Explanation
Reaching this state does not require a majority of signers, another signer's key, or any privileged access — it only requires:
1. `validate_with_replay_tx` enabled (an ordinary, documented signer configuration used whenever tx-replay is exercised, e.g. after a Bitcoin fork), and
2. A signer process restart (or reset of the in-memory `Signer` struct) while `tx_replay_set` is non-empty.
Both conditions are part of ordinary operations (deployments/restarts happen routinely; the `tx_replay_set`/`tx_replay_scope` split is explicitly called out in the code's own doc comment as a known non-persistence gap), so this is readily reachable by a single node operator's normal maintenance action — no attacker action is even required, only bad timing relative to an in-progress replay window, similar to how the Solidity finding required only a routine gauge-kill (governance action) coinciding with a user's detach call.

### Recommendation
- Persist `tx_replay_scope` alongside `tx_replay_set` (e.g., in `SignerDb`), or derive it deterministically from state that *is* persisted, so a restart cannot desynchronize the two.
- In `bitcoin_block_arrival`, treat `ReplayState::infer_state` returning `None` the same way `_vote`'s recommended fix treats a killed gauge: recover gracefully instead of leaving `self` as `Uninitialized` and returning a hard `Err`. For example, on `None`, log a warning and fall back to `ReplayState::Unset` (clearing `tx_replay_set`/`tx_replay_scope` explicitly and continuing to initialize `self` normally) rather than aborting the whole state update and leaving the local state machine unusable.
- Ensure the `Err` early-return paths in `bitcoin_block_arrival` always leave `self` in a well-defined, non-`Uninitialized` state (mirroring the `node_behind_expected`/`node_on_equal_fork` branch, which correctly restores `self` to `Pending` before returning `Err`).

### Proof of Concept
1. Configure a signer with `validate_with_replay_tx = true`.
2. Trigger a Bitcoin fork so the signer enters `ReplayState::InProgress` with a non-empty `tx_replay_set` and a populated `tx_replay_scope` (see `handle_fork_for_new_replay`, `stacks-signer/src/v0/signer_state.rs:1210-1270`).
3. Restart the signer process (or otherwise reconstruct the `Signer` struct) without persisting `tx_replay_scope`; the reload path (`Signer::new`, `signer.rs:318`) sets `tx_replay_scope: None` while the reloaded/received `SignerStateMachine.tx_replay_set` remains non-empty (via `global_state_evaluator`/persisted updates).
4. On the next `NewBurnBlock` event, `bitcoin_block_arrival` calls `ReplayState::infer_state(&tx_replay_set /* non-empty */, &None)`, which returns `None` (`signer_state.rs:127-135`), causing `bitcoin_block_arrival` to `return Err(SignerChainstateError::LocalStateMachineNotReady)` with `self` left as `LocalStateMachine::Uninitialized`.
5. Any `BlockProposal` handled before the *next* `NewBurnBlock` event goes through `check_block_against_global_state`, which cannot get a global/local state view and rejects the proposal with `RejectReason::NoSignerConsensus` (`signer.rs:951-958`), i.e., the signer refuses to validate or sign any block during this window. impl ReplayState {
    /// Infers the appropriate `ReplayState` based on the contents of the replay transaction set
    /// and the optional scope.
    ///
    /// # Arguments
    ///
    /// * `replay_set` - A reference to a set of transactions intended for replay.
    /// * `scope_opt` - An optional scope defining the boundaries or context for the replay.
    ///
    /// # Returns
    ///
    /// * `Some(ReplayState::Unset)` if the `replay_set` is empty.
    /// * `Some(ReplayState::InProgress)` if the `replay_set` is non-empty and a `scope` is provided.
    /// * `None` if the `replay_set` is non-empty but no `scope` is provided.
    ///   - Possibly caused by the scope being a local state in the `Signer` struct, which is not persisted.
    fn infer_state(replay_set: &ReplayTransactionSet, scope_opt: &ReplayScopeOpt) -> Option<Self> {
        if replay_set.is_empty() {
            return Some(Self::Unset);
        }

        scope_opt
            .as_ref()
            .map(|scope| Self::InProgress(replay_set.clone(), scope.clone()))
    }

    /// Handle a new bitcoin block arrival
    #[allow(clippy::too_many_arguments)]
    pub fn bitcoin_block_arrival(
        &mut self,
        db: &mut SignerDb,
        client: &StacksClient,
        proposal_config: &ProposalEvalConfig,
        mut expected_burn_block: Option<NewBurnBlock>,
        tx_replay_scope: &mut ReplayScopeOpt,
        eval: &GlobalStateEvaluator,
        local_signer_protocol_version: u64,
    ) -> Result<(), SignerChainstateError> {
        // set self to uninitialized so that if this function errors,
        //  self is left as uninitialized.
        let prior_state = std::mem::replace(self, Self::Uninitialized);
        let prior_state_machine = match prior_state.clone() {
            // if the local state machine was uninitialized, just initialize it
            LocalStateMachine::Uninitialized => Self::place_holder(local_signer_protocol_version),
            LocalStateMachine::Initialized(signer_state_machine) => signer_state_machine,
            LocalStateMachine::Pending { update, prior } => {
                // This works as long as the pending updates are only burn blocks,
                //  but if we have other kinds of pending updates, this logic will need
                //  to be changed.
                match update {
                    StateMachineUpdate::BurnBlock(pending_burn_block) => {
                        match expected_burn_block {
                            None => expected_burn_block = Some(pending_burn_block),
                            Some(ref expected) => {
                                if pending_burn_block.burn_block_height > expected.burn_block_height
                                {
                                    expected_burn_block = Some(pending_burn_block);
                                }
                            }
                        }
                    }
                }

                prior.clone()
            }
        };

        let peer_info = client.get_peer_info()?;
        let next_burn_block_height = peer_info.burn_block_height;
        let next_burn_block_hash = peer_info.pox_consensus;
        let mut tx_replay_set = prior_state_machine.tx_replay_set.clone();

        if let Some(expected_burn_block) = expected_burn_block {
            // If the next height is less than the expected height, we need to wait.
            // OR if the next height is the same, but with a different hash, we need to wait.
            let node_behind_expected =
                next_burn_block_height < expected_burn_block.burn_block_height;
            let node_on_equal_fork = next_burn_block_height
                == expected_burn_block.burn_block_height
                && next_burn_block_hash != expected_burn_block.consensus_hash;
            if node_behind_expected || node_on_equal_fork {
                let err_msg = format!(
                    "Node has not processed the next burn block yet. Expected height = {}, Expected consensus hash = {}, Node height = {}, Node consensus hash = {}",
                    expected_burn_block.burn_block_height,
                    expected_burn_block.consensus_hash,
                    next_burn_block_height,
                    next_burn_block_hash,
                );
                *self = Self::Pending {
                    update: StateMachineUpdate::BurnBlock(expected_burn_block),
                    prior: prior_state_machine,
                };
                return Err(ClientError::InvalidResponse(err_msg).into());
            }

            let replay_state = match ReplayState::infer_state(&tx_replay_set, tx_replay_scope) {
                Some(valid_state) => valid_state,
                None => {
                    warn!(
                        "Tx Replay: Invalid state due to scope being not set while in replay mode!"
                    );
                    return Err(SignerChainstateError::LocalStateMachineNotReady);
                }
            };
