### Title
Locked ETH in `ActivationRegistry` precompile pre-Cobalt "accept-and-strand" path - (File: `crates/common/precompiles/src/activation/dispatch.rs`)

### Summary
The `ActivationRegistryStorage::dispatch_with_observer` function only rejects attached ETH (`call_value`) for calls made from `BaseUpgrade::Cobalt` onward. For the pre-Cobalt (`Beryl`) hardfork window, the code explicitly allows nonzero `call_value` to be accepted by the precompile without any mechanism to withdraw or refund it, mirroring the reported `CollateralEscrowV1.depositAsset()` bug class of "payable function accepts ETH with no exit path."

### Finding Description
The dispatch gate is:
```rust
// Activation-registry selectors are all nonpayable; reject attached ETH from Cobalt
// onward. Pre-Cobalt (Beryl) preserves the historical accept-and-strand behavior so
// replay of live-installed activation calls remains byte-identical.
if upgrade >= BaseUpgrade::Cobalt && !ctx.call_value().is_zero() {
    return recorder.record_base_error_result(
        ctx,
        BasePrecompileError::revert(IActivationRegistry::NonPayable {}),
    );
}
``` [1](#0-0) 

This is the only precompile dispatcher in the codebase with a conditional (hardfork-gated) non-payable check; every sibling dispatcher (`b20_asset`, `b20_factory`, `b20_stablecoin`, `policy`, `nonce`, `tx_context`) unconditionally rejects `call_value != 0` with `NonPayable` regardless of upgrade: [2](#0-1) [3](#0-2) [4](#0-3) 

The `inner()` handler for the activation registry only performs state-mutating operations (`isActivated`, `checkActivated`, `activate`, `deactivate`, `setAdmin`, `admin`) — none of it credits, tracks, or refunds any received value: [5](#0-4) 

Because precompile execution is not a regular contract with a balance-tracked `receive()`/`withdraw()` pair, any ETH attached to a Beryl-era call into this precompile is transferred to the precompile's address inside EVM state with no corresponding code path anywhere in the codebase to move it back out — it becomes permanently unreachable, exactly analogous to ETH stuck in `CollateralEscrowV1` via an unnecessary `payable` modifier with no withdrawal function.

### Impact Explanation
Any unprivileged sender who calls the `ActivationRegistry` precompile with nonzero `msg.value` while `BaseUpgrade::Beryl` is the active fork permanently loses that ETH — it is accepted into the precompile's account balance with no corresponding accounting, refund, or sweep mechanism in the code. This is a permanent freezing/loss of user funds, satisfying the Medium-severity bar for stuck value, matching the bug class from the original report.

### Likelihood Explanation
The likelihood is bounded by fork state: the accept-and-strand behavior only applies while `upgrade < BaseUpgrade::Cobalt` (i.e., on chains/replays still running Beryl). The comment states this is a deliberate replay-compatibility carve-out ("preserves the historical accept-and-strand behavior so replay of live-installed activation calls remains byte-identical"), implying this is intentional to keep byte-identical state transitions for a chain that already progressed through Beryl with this exact (buggy) behavior live. On any network currently active at or past Cobalt, the guard is fully closed and no further ETH can be stranded. Whether Base mainnet is still pre-Cobalt (making this a live, currently-reachable risk) or already past Cobalt (making this purely a historical/legacy replay quirk) could not be confirmed from the available index — the `crates/common/genesis/src/chain/upgrade.rs` and `rollup.rs` files were not readable in this session, so the exact activation timestamp/fork ordering for mainnet could not be verified.

### Recommendation
Confirm whether `BaseUpgrade::Cobalt` has already activated on all live networks. If any live/production chain is still pre-Cobalt, users can currently strand ETH via this precompile — consider either (a) accepting the byte-identical replay requirement only for pre-activation historical *replay* (not live consensus going forward), or (b) adding a state-gated retroactive rejection tied to a specific timestamp/height rather than a fork boundary, if replay compatibility must be preserved exactly. Regardless, document and audit any residual balance already stranded at the activation-registry precompile address to determine if remediation (e.g., a one-time sweep via a future upgrade) is warranted.

### Proof of Concept
1. On a chain/network where the active hardfork resolves to `BaseUpgrade::Beryl` (pre-Cobalt), send any transaction calling the `ActivationRegistry` precompile address (e.g., invoking `isActivated`) with `value > 0`.
2. `dispatch_with_observer` evaluates `upgrade >= BaseUpgrade::Cobalt && !ctx.call_value().is_zero()` — since `upgrade < Cobalt`, the guard short-circuits and the nonzero value is *not* rejected. [1](#0-0) 
3. The call proceeds to `inner()`, executes successfully, and the attached ETH is credited to the precompile address by the EVM value-transfer semantics inherent to any successful call carrying `value`.
4. No function in `activation/dispatch.rs` or elsewhere reads or transfers out the precompile's balance, so the ETH remains permanently locked at that address.

    fn inner(
        &mut self,
        calldata: &[u8],
        admin_config: ActivationAdminConfig,
    ) -> base_precompile_storage::Result<Bytes> {
        let set_admin_selector = IActivationRegistry::setAdminCall::SELECTOR;
        if !admin_config.state_enabled && calldata.get(..4) == Some(set_admin_selector.as_slice()) {
            return Err(BasePrecompileError::UnknownFunctionSelector(set_admin_selector));
        }

        match decode_precompile_call!(calldata, IActivationRegistry::IActivationRegistryCalls) {
            C::isActivated(call) => {
                let activated = self.is_activated(call.feature)?;
                Ok(IActivationRegistry::isActivatedCall::abi_encode_returns(&activated).into())
            }
            C::checkActivated(call) => {
                self.ensure_activated(call.feature)?;
                Ok(Bytes::new())
            }
            C::activate(call) => {
                self.activate(call.feature, admin_config)?;
                Ok(Bytes::new())
            }
            C::deactivate(call) => {
                self.deactivate(call.feature, admin_config)?;
                Ok(Bytes::new())
            }
            C::setAdmin(call) => {
                self.set_admin(call.newAdmin, admin_config)?;
                Ok(Bytes::new())
            }
            C::admin(_) => {
                Ok(IActivationRegistry::adminCall::abi_encode_returns(&self.admin(admin_config)?)
                    .into())
            }
        }
    }
