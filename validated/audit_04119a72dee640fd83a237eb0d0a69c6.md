I found a genuine accounting-corruption analog in `staking_contract.move` that mirrors the report's "unvalidated financial operation, wrong recipient credited" pattern, but rooted in Move share-accounting rather than ERC20 return values.

### Title
Stale operator commission shares are re-taxed and redirected to the new operator after `switch_operator` - (File: aptos-move/framework/aptos-framework/sources/staking_contract.move)

### Summary
`switch_operator` finalizes the outgoing operator's unpaid commission as a pending (not-yet-withdrawable) share entry in the `StakingContract`'s `distribution_pool`, keyed by the **old operator's address**, then changes `staking_contract.operator` to the new operator address without removing or protecting that entry. Any subsequent permissionless call to `distribute()`, or to `unlock_stake`/`request_commission` on the same contract, re-runs `update_distribution_pool` using the **current (new)** operator address as the "exempt" party. Because the old operator's address is no longer equal to the exempt address, their still-pending commission balance is treated as ordinary growth and taxed at the (possibly changed) commission rate, with the skimmed shares transferred to the new operator.

### Finding Description
In `switch_operator`, the outgoing operator's owed commission is settled into the distribution pool but not paid out immediately: [1](#0-0) 

`request_commission_internal` records this via `add_distribution(operator, staking_contract, operator, commission_amount)`, which stores a share entry keyed to the **old** operator address inside `staking_contract.distribution_pool`: [2](#0-1) [3](#0-2) 

`switch_operator` never removes this entry before overwriting `staking_contract.operator` with `new_operator`: [4](#0-3) 

Any later distribution event on the pool — including the permissionless `distribute` entry function or `unlock_stake`/`request_commission`/`update_commision` — calls `update_distribution_pool` with the **current** operator address as the sole exempt shareholder: [5](#0-4) 

`update_distribution_pool` charges `commission_percentage` on the value growth of every shareholder except the passed-in `operator`, transferring the skimmed shares directly to that `operator`: [6](#0-5) 

Since the old operator's address no longer matches `operator` (now the new operator), their already-earned, unpaid commission balance is misclassified as ordinary reward growth. Any rewards that continue to accrue on that pending_inactive balance while it awaits lockup expiry get taxed at the *current* (post-switch, possibly staker-adjusted) commission rate and the skimmed shares are transferred to the new operator via `pool_u64::transfer_shares`, not the staker or old operator.

### Impact Explanation
This corrupts operator commission share-accounting by crediting the wrong account: value that rightfully belongs to the old operator (already finalized as their commission before the switch) is siphoned to the new operator on every subsequent `distribute`/`unlock_stake`/`request_commission` call, as long as the old operator has not yet withdrawn it. `distribute` is explicitly documented as callable by anyone, so an attacker (e.g., a colluding staker + new operator) can trigger repeated syncs to maximize the skim, and the staker can even raise `commission_percentage` via `update_commision` right after the switch to increase the rate applied against the old operator's stuck funds. This directly matches the "Operator commission ... share-accounting corruption that credits the wrong account" impact category.

### Likelihood Explanation
`switch_operator` is a normal, unprivileged staker action (`public entry fun switch_operator`) requiring no special role beyond being the staker of an existing `staking_contract`, and `distribute`/`unlock_stake` are callable afterward by any account. The only precondition is that the old operator has an outstanding, not-yet-withdrawn commission distribution at switch time (a very common state, since operator commission unlocks only at the end of a stake pool lockup cycle).

### Recommendation
Before or during `switch_operator`, either (a) fully settle and remove the old operator's pending distribution-pool shares (paying them out or moving them to a structure not subject to being "netted" against the new operator), or (b) have `update_distribution_pool` skip commission taxation for *any* address that was previously used as an operator payee for that pool (or track distribution entries with an explicit "this is finalized commission, exempt from further taxation" flag) rather than comparing only against the pool's current `operator` field.

### Proof of Concept
1. Staker creates a `staking_contract` with `operator_A` and commission `C1`; validator earns rewards over several epochs so `operator_A` accrues unpaid commission.
2. Staker calls `request_commission(staker, staker, operator_A)` (or any action that internally calls `request_commission_internal`), which unlocks `operator_A`'s commission and records it as a distribution-pool share entry keyed to `operator_A`, still pending_inactive.
3. Before the lockup expires (so the pending commission has not been withdrawn), staker calls `switch_operator(staker, operator_A, operator_B, new_commission_percentage)`. This settles `operator_A`'s commission again into the pool (still unpaid) and overwrites `staking_contract.operator = operator_B`.
4. Time passes; the underlying stake pool's pending_inactive stake (which includes `operator_A`'s stuck commission balance) continues to earn staking rewards, increasing `distribution_pool.total_coins()`.
5. Anyone calls `distribute(staker, operator_B)` (public, permissionless). Inside `distribute_internal`, `update_distribution_pool(distribution_pool, distribution_amount, operator_B, commission_percentage)` runs: since `operator_A != operator_B`, the growth on `operator_A`'s pending balance is taxed at `commission_percentage` and those shares are transferred to `operator_B`.
6. `operator_A` ultimately receives less than their rightfully finalized commission; `operator_B` receives value it never earned, confirmed by tracing `pool_u64::transfer_shares(distribution_pool, shareholder, operator, shares_to_transfer)` in `update_distribution_pool`.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    /// Add a new distribution for `recipient` and `amount` to the staking contract's distributions list.
    fun add_distribution(
        operator: address,
        staking_contract: &mut StakingContract,
        recipient: address,
        coins_amount: u64,
    ) {
        let distribution_pool = &mut staking_contract.distribution_pool;
        let (_, _, _, total_distribution_amount) =
            stake::get_stake(staking_contract.pool_address);
        update_distribution_pool(
            distribution_pool,
            total_distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        distribution_pool.buy_in(recipient, coins_amount);
        let pool_address = staking_contract.pool_address;
        emit(AddDistribution { operator, pool_address, amount: coins_amount });
    }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
