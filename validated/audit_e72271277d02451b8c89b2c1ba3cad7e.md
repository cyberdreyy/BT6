### Title
Raw internal error messages (including database errors) from AuthenticateBySession/AuthenticateByToken leak verbatim to unauthenticated callers via jsonAPIError - ([File: core/web/auth/helpers.go])

### Finding Description
`jsonAPIError` in `core/web/auth/helpers.go` unwraps any non-`*models.JSONAPIErrors` error with `err.Error()` and writes it directly into the JSON response body: [1](#0-0) 

This function is invoked directly from the authentication middleware `Authenticate` in `core/web/auth/auth.go` whenever any auth method returns a non-`auth.ErrorAuthFailed` error: [2](#0-1) 

Critically, both `AuthenticateBySession` and `AuthenticateByToken` propagate underlying errors from the authentication provider (backed by the ORM/DB) without sanitizing them for any case other than `sql.ErrNoRows` / `clsessions.ErrUserSessionExpired`: [3](#0-2) [4](#0-3) 

If `AuthorizedUserWithSession` or `FindUserByAPIToken` (implemented in `core/sessions/localauth/orm.go`, `ldapauth/ldap.go`, or `oidcauth/oidc.go`) return anything other than `sql.ErrNoRows`/`ErrUserSessionExpired` — e.g., a query error, a connection error, or an error wrapped with `errors.Wrap` that embeds internal context (query text, connection parameters, LDAP bind details, etc.) — that error flows unmodified into `jsonAPIError`, and `err.Error()` is serialized verbatim into the HTTP 401 JSON response. An unauthenticated caller can trigger this simply by sending malformed/edge-case credentials (e.g., a session cookie referencing a state that causes a query failure, or hitting the endpoint during a DB connectivity blip) and inspect the response body for leaked internal details.

I was unable to fully verify the exact error-wrapping behavior inside `core/sessions/localauth/orm.go`, `ldapauth/ldap.go`, and `oidcauth/oidc.go` (i.e., whether any of these implementations currently wrap raw SQL/LDAP errors with sensitive parameters like connection strings) due to tool budget exhausted before reading those files — this is the remaining uncertainty. However, the control-flow defect is clear and confirmed: `Authenticate`/`jsonAPIError` provide no generic sanitization layer for non-`ErrorAuthFailed` errors returned by any `Authenticator` implementation, meaning any future or existing code path in those providers that returns a non-nil, non-`sql.ErrNoRows` error will have its raw message reflected to the caller.

### Impact Explanation
If any `Authenticator` implementation surfaces a wrapped low-level error (DB error text, connection info, internal query details) on an edge case, an unauthenticated attacker gets that information disclosed directly in the auth-failure response body. This matches Chainlink's "information disclosure via error message" bounty class — it does not by itself grant fund movement or auth bypass, but it can leak infrastructure details that aid further attacks (e.g., DB connection topology) and violates secret confinement expectations for a public-facing endpoint.

### Likelihood Explanation
Exploitability depends entirely on whether an `Authenticator` implementation actually returns an error with sensitive content for a condition other than "no such user"/"expired session" — this is unverified/uncertain in this codebase snapshot. Given the current confirmed code, `AuthenticateBySession`/`AuthenticateByToken` do forward arbitrary errors unmodified, so the vulnerability's precondition is "some downstream provider can return a sensitive-wrapped error," which is plausible but not proven from the files I was able to inspect.

### Recommendation
In `Authenticate` (or in `jsonAPIError` itself), never serialize raw `err.Error()` for authentication-failure responses to unauthenticated callers; map all non-`auth.ErrorAuthFailed` errors from `AuthenticateBySession`/`AuthenticateByToken`/`AuthenticateExternalInitiator` to a generic, fixed message (e.g., "internal error" / "unauthorized"), logging the detailed error server-side only, similar to the existing `sql.ErrNoRows` handling.

### Proof of Concept
Go handler-level test plan:
1. Create a mock `Authenticator` (using `core/sessions/mocks` or a custom stub) whose `AuthorizedUserWithSession` returns `errors.Wrap(errors.New("dial tcp 10.0.0.5:5432: connect refused (dsn: postgres://user:pass@host/db)"), "querying users")`.
2. Wire it into `auth.Authenticate(mockAuthr, auth.AuthenticateBySession)` as gin middleware in a test router.
3. Issue an HTTP request with a session cookie so `sessionID, ok := session.Get(...)` succeeds and the mock is invoked.
4. Assert the HTTP response status is 401 and the JSON body's error message field contains the wrapped string (e.g., "dsn:" or "postgres://") — if it does, the leak is confirmed.
5. Repeat with `AuthenticateByToken` using a mock `FindUserByAPIToken` that returns a similarly sensitive wrapped error (not `sql.ErrNoRows`).
6. Expected (secure) behavior: response body should contain only a generic message such as "Unauthorized", never the wrapped internal string.

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}
