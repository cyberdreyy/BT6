The reported bug class is specific to Solidity ERC20 `approve()` semantics (USDT-style tokens reverting on non-zero-to-nonzero allowance changes). This repository is a set of NEAR/Rust smart contracts (`staking-pool`, `lockup`, `multisig`, `w-near`, etc.) that use NEAR's native token model and NEP-141 fungible token transfers, not ERC20 allowances.

The only "allowance" concept present is NEAR's access-key `allowance` field used in `multisig/src/lib.rs` `MultiSigRequestAction::AddKey` for limiting gas/deposit spend by a function-call access key [1](#0-0) , which is unrelated to ERC20 token approval and cannot revert due to a non-zero prior allowance in the way USDT's `approve()` does. The w-near contract implements NEP-141 `ft_transfer`/`ft_transfer_call` directly via `near_contract_standards::impl_fungible_token_core!` [2](#0-1)  with no custom approve/allowance logic that could exhibit this bug class. The staking-pool, lockup, and other in-scope contracts move funds via native NEAR `Promise::transfer`/`stake` calls [3](#0-2) , not via any two-step approve pattern.

There is no reachable path in the in-scope repositories where an approve-to-zero-first requirement could break a custody binding (claims vs. NEAR held, shares charged vs. redeemed, etc.).

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }
