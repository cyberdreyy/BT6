### Title
Unauthenticated proxy to LOOP plugin pprof `/debug/pprof/symbol` (and related pprof/metrics endpoints) via `loopRoutes` - ([File: core/web/router.go], [File: core/web/loop_registry.go])

### Summary
`loopRoutes` registers `/plugins/:name/debug/pprof/symbol` (and the sibling `/plugins/:name/debug/pprof/*profile` and `/plugins/:name/metrics` routes) on the router group without any authentication middleware, unlike every other sensitive route group (`v2Routes`, `sessionRoutes`, `debugRoutes`) which explicitly wrap handlers with `auth.Authenticate`. `LoopRegistryServer.pluginPPROFPOSTSymbolHandler` reads the raw POST body and query parameters from the unauthenticated request and forwards them verbatim to the LOOP plugin's internal pprof HTTP server, returning the raw response body to the caller.

### Finding Description
In `core/web/router.go`, `NewRouter` builds an `api` group with only rate limiting and session cookie middleware (no auth), then calls `loopRoutes(app, api)`: [1](#0-0) 
Contrast this with `debugRoutes` and `sessionRoutes`, which explicitly wrap their handlers in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [2](#0-1) [3](#0-2) 

`pluginPPROFPOSTSymbolHandler` looks up the plugin by name, reads the raw request body, and issues an HTTP POST to `http://<loopHostName>:<PrometheusPort>/debug/pprof/symbol` on the internal LOOP plugin process, then copies the response back to the (unauthenticated) caller: [4](#0-3) 
The shared `doRequest` helper performs the actual proxying and response relay without any authorization check: [5](#0-4) 

The sibling `pluginPPROFHandler` (GET) is similarly unauthenticated and forwards `debug`, `gc`, and `seconds` query parameters straight through to the plugin's pprof endpoints (`heap`, `goroutine`, `profile`, `trace`, etc.), and `pluginMetricHandler` proxies `/metrics`: [6](#0-5) [7](#0-6) 

No caller-identity or role check occurs anywhere in this code path; the only gate is "does the named plugin exist" (`l.registry.Get(pluginName)`), which is not an authorization control. This confirms the vulnerable behavior: an anonymous caller can POST arbitrary bytes to `/plugins/:name/debug/pprof/symbol` and receive the plugin's raw pprof symbol-resolution response, and can likewise GET arbitrary pprof profiles (heap/goroutine/trace/CPU profile) from a live LOOP plugin process.

### Impact Explanation
This is an authentication-bypass / unauthenticated information-disclosure and resource-exhaustion vector against the LOOP plugin process (e.g. Median/Relayer plugins), which may hold in-memory secrets (signing keys, DB connection info) and whose full heap/goroutine/CPU profiles can be pulled by any unauthenticated caller. It also allows unauthenticated triggering of CPU/trace profiling (`seconds` parameter) against a live plugin process, causing resource consumption/DoS. This matches the "sensitive information disclosure" / "unauthorized access to node internals without valid credentials" bounty impact classes rather than fund loss, since the pprof symbol/profile data does not directly move funds but does expose internal process state and provides a foothold for further attack (memory-scraping for secrets, DoS).

### Likelihood Explanation
No credentials, session, or token are required — any network client that can reach the node's HTTP API can trigger this immediately and repeatably, provided at least one LOOP plugin is registered (`l.registry.Get(pluginName)` must succeed). This is a straightforward, deterministic, zero-privilege exploit path with no rate/role gating beyond the generic API rate limiter.

### Recommendation
Wrap `loopRoutes` (or at least the pprof/metrics proxy sub-routes) with the same `auth.Authenticate(...)` middleware used by `debugRoutes`/`v2Routes`, and require an admin-level role (`auth.RequiresAdminRole`) given the sensitivity of memory/CPU profiling data, consistent with how `/debug/vars` is protected.

### Proof of Concept
Go handler-level integration test plan:
1. Build a `gin.Engine` using `NewRouter` (or directly call `loopRoutes(app, api)` on a bare `gin.RouterGroup`) with a mock `chainlink.Application` and a `plugins.LoopRegistry` containing one registered plugin ("median") pointing at a `httptest.Server` that implements `/debug/pprof/symbol` (echoing "num_symbols: 1" or symbol data).
2. Issue an `httptest.NewRequest("POST", "/plugins/median/debug/pprof/symbol", bytes.NewBufferString("0xdeadbeef"))` with no `Authorization` header/cookie and no session.
3. Serve the request through the router and assert: response status is `200 OK` (not `401`/`403`), and the body matches/forwards the mocked plugin's pprof symbol response.
4. Repeat for `GET /plugins/median/debug/pprof/heap` and `GET /plugins/median/metrics` to confirm the same unauthenticated pass-through behavior, contrasted with a control test hitting `/v2/config` (which should return `401` without auth), demonstrating the discrepancy in "Authorization is exact" between `loopRoutes` and `v2Routes`.

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))

	unauth.POST("/sessions", sc.Create)

	auth.DELETE("/sessions", sc.Destroy)
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
