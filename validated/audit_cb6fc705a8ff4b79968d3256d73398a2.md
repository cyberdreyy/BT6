### Title
Stale zone-b DON membership cache can allow vault `GetSecrets` allowlist bypass during a capabilities-registry lookup failure - (File: core/capabilities/vault/zone_b_restriction.go)

### Summary
The reported Lighthouse bug is a class of "authoritative recomputation vs. stale cached value" mismatch: a security-relevant decision (proposer selection) is sometimes made from a freshly recomputed value and sometimes from a cached value that was computed under different conditions, and the two can disagree. The same pattern exists in `zoneBRestrictor.isZoneBWorkflowDON`, which is the authorization gate for restricting vault secret reads from "zone-b" workflow DONs to an allowlist of owners.

### Finding Description
`zoneBRestrictor.enforce` is the sole authorization check that decides whether a `GetSecrets` request from a given `workflowDonID` must pass the owner allowlist check [1](#0-0) . The zone membership used for that decision is resolved by `isZoneBWorkflowDON`, which normally queries the live capabilities registry, but falls back to a previously cached boolean (`zoneCache[workflowDonID]`) whenever the registry lookup fails [2](#0-1) .

The cache is written only on a successful resolution, and it stores whatever the DON's zone membership was *at the last successful lookup* [3](#0-2) . If a DON is later reclassified into the `zone-b` family (e.g. an operator moves the DON into the restricted family) but a request happens to race with a registry lookup failure (the code's own comments note this can happen "e.g., not yet synced after startup, or nil mid-update") before any subsequent successful lookup refreshes the cache, `isZoneBWorkflowDON` returns the stale `false` value instead of the new authoritative `true` value. In that window, `enforce` treats the caller as non-zone-b and skips the owner allowlist check entirely [4](#0-3) , exactly mirroring the root cause in the external report: a stale/cached security-relevant value is substituted for the freshly-computed authoritative one, producing an incorrect (here, permissive) security decision.

### Impact Explanation
If exploited, this allows a non-allowlisted workflow owner on a `zone-b` DON to read vault secrets that should be restricted, i.e. an allowlist bypass on the vault `GetSecrets` path reachable from an unprivileged client through the gateway handler that ultimately invokes this restrictor. Secret disclosure to unauthorized parties is a high-impact outcome for a secrets-management vault feature.

### Likelihood Explanation
The likelihood is low-to-moderate: it requires (1) an operator-driven event of newly classifying/moving a DON into the `zone-b` family, and (2) a coincident, transient capabilities-registry lookup failure before the cache is refreshed with the new classification. The comments in the code frame this as a legitimate, non-adversarial-but-possible race ("not yet synced after startup, or nil mid-update"), and the existing tests only validate that a *previously-cached* classification is preserved correctly across an outage (`TestZoneBRestrictor_RegistryOutageUsesCachedMembership`) [5](#0-4)  — they do not cover the reclassification-then-outage race, so this specific failure mode is untested.

### Recommendation
Do not fail open to a stale "not zone-b" cache entry when the registry is transiently unavailable. Instead:
- Fail closed (deny non-allowlisted reads) whenever the registry lookup fails, regardless of any prior cached value, or
- Bound the cache's validity with a TTL/staleness check and require the enforcement path to fail closed if the cache entry is older than a safety threshold, or
- Persist and revalidate DON family membership transitions synchronously with any registry mutation so the cache can never reflect a superseded classification.

### Proof of Concept
No standalone PoC is available from static analysis alone; reproducing requires orchestrating a capabilities-registry family-membership update for a target DON concurrent with an injected registry lookup failure (as simulated by `newOutageTestRestrictor`/`fake.fail.Store(true)` in the existing test harness [6](#0-5) ), then issuing a `GetSecrets` request from a non-allowlisted owner during that window to confirm `enforce` returns `nil` instead of the allowlist error.

func (z *zoneBRestrictor) enforce(ctx context.Context, workflowDonID uint32) error {
	enabled, err := z.restrictEnabled.Limit(ctx)
	if err != nil {
		return fmt.Errorf("could not evaluate zone-b vault read restriction gate: %w", err)
	}
	if !enabled {
		return nil
	}

	isZoneB, err := z.isZoneBWorkflowDON(ctx, workflowDonID)
	if err != nil {
		// Fail closed: if we cannot authoritatively resolve the caller's zone, do
		// not proceed. The registry is in-process, so this only fires for an
		// unknown/unregistered WorkflowDonID.
		return err
	}
	if !isZoneB {
		return nil
	}

	if err := z.ownerAllowed.AllowErr(ctx); err != nil {
		return fmt.Errorf("zone-b workflow DON may only read vault secrets for allowlisted workflow owners: %w", err)
	}
	return nil

func (z *zoneBRestrictor) isZoneBWorkflowDON(ctx context.Context, workflowDonID uint32) (bool, error) {
	don, err := z.capabilitiesRegistry.DONByID(ctx, workflowDonID)
	if err != nil {
		// The registry view can be transiently unavailable (e.g. not yet synced
		// after startup, or nil mid-update: DONByID returns "metadataRegistry
		// information not available"). That error is not specific to zone-b
		// callers, so failing closed here would block every vault GetSecrets read
		// DON-wide. Fall back to the last successfully-resolved membership for this
		// DON; only a never-before-resolved DON fails closed.
		if cached, ok := z.cachedZoneMembership(workflowDonID); ok {
			z.lggr.Warnw("capabilities registry lookup failed; using cached zone-b membership",
				"workflowDonID", workflowDonID, "isZoneB", cached, "err", err)
			return cached, nil
		}
		return false, fmt.Errorf("could not resolve caller workflow DON %d for zone-b vault read restriction: %w", workflowDonID, err)
	}
	// Case-insensitive match: family casing may vary across registry sources.
	isZoneB := slices.ContainsFunc(don.Families, func(family string) bool {
		return strings.EqualFold(family, zoneBFamily)
	})
	z.storeZoneMembership(workflowDonID, isZoneB)
	return isZoneB, nil
}

// MUST-2: a transient capabilities registry outage must not fail every vault
// read DON-wide. Once a DON's zone membership has been resolved, a subsequent
// registry lookup failure falls back to the cached value instead of erroring;
// a DON never resolved before still fails closed. Crucially, the cached value
// preserves the security decision in both directions: a cached zone-b DON stays
// denied during the outage rather than slipping through.
func TestZoneBRestrictor_RegistryOutageUsesCachedMembership(t *testing.T) {
	t.Parallel()
	const restrictEnabled = `{"global":{"VaultZoneBWorkflowGetSecretsRestrictEnabled":"true"}}`

	t.Run("cached zone-a membership survives outage (still allowed)", func(t *testing.T) {
		t.Parallel()
		z, fake := newOutageTestRestrictor(t, restrictEnabled)
		md := capabilities.RequestMetadata{WorkflowOwner: "0xdeadbeef", WorkflowDonID: zoneADonID}
		ctx := md.ContextWithCRE(t.Context())

		// Warm the cache while healthy: zone-a caller is allowed.
		require.NoError(t, z.enforce(ctx, zoneADonID))
		// Outage: cached (non-zone-b) membership keeps the read allowed.
		fake.fail.Store(true)
		require.NoError(t, z.enforce(ctx, zoneADonID))
	})

	t.Run("cached zone-b membership survives outage (still denied)", func(t *testing.T) {
		t.Parallel()
		z, fake := newOutageTestRestrictor(t, restrictEnabled)
		md := capabilities.RequestMetadata{WorkflowOwner: "0x" + allowlistedOwner, WorkflowDonID: zoneBDonID}
		ctx := md.ContextWithCRE(t.Context())

		// Warm the cache while healthy: zone-b + non-allowlisted owner is denied,
		// and the zone-b membership is cached.
		require.ErrorContains(t, z.enforce(ctx, zoneBDonID), "allowlisted workflow owners")

		// Outage: the cached zone-b membership must still be enforced. The caller
		// is denied via the allowlist, not allowed through by a resolve failure.
		fake.fail.Store(true)
		err := z.enforce(ctx, zoneBDonID)
		require.ErrorContains(t, err, "allowlisted workflow owners")
		require.NotContains(t, err.Error(), "could not resolve caller workflow DON")
	})
