### Title
Timestamping passthrough in `stepRunnerStream.pickMode` bypasses masking chain, allowing secret leakage via forged step-runner output - ([File: common/buildlogger/build_logger.go])

### Summary
`Logger.StepRunnerStream` returns a `stepRunnerStream` whose `pickMode` selects the raw `passthrough` writer (`internal.NewSync(l.base)`) whenever the first write matches `isPreStamped` and `l.timestamping` is true, deliberately skipping the `tokensanitizer`/`urlsanitizer`/`masker` chain built in `Logger.wrap`. Because the step-runner subprocess is external and its output is not validated against a trusted source before this dispatch, any byte stream matching the timestamp-header shape checked by `isPreStamped` at the first `Write` call reaches the trace verbatim, including any embedded secrets such as `private_token=...`.

### Finding Description
`Logger.wrap` (common/buildlogger/build_logger.go:213-224) constructs the normal defense-in-depth chain: `masker.New` → `urlsanitizer.New` → `tokensanitizer.New` → `timestamper.New`, in that write order. `StepRunnerStream` (build_logger.go:113-131) instead builds a `stepRunnerStream` that lazily picks, on the very first `Write`, between three code paths in `pickMode` (build_logger.go:167-178):

- `isPreStamped(p) && s.timestamping` → `s.chosen = s.passthrough` (raw `l.base`, no filters at all)
- `isPreStamped(p)` (timestamping off) → strips and demuxes via `innerstream`, still routed through per-type wrap chains
- default → `s.buildWrapped()`, i.e. the normal `l.wrap` chain

`isPreStamped` (build_logger.go:142-153) only checks that bytes 4,7,10,13,16,19,26,27 match the fixed positions of an RFC3339-like timestamp header (`YYYY-MM-DDTHH:MM:SS.UUUUUUZ `). This is a purely structural/positional check on attacker-influenceable bytes — it does not authenticate that the payload actually originated from the trusted step-runner subprocess, nor does it validate the remainder of the line. Any process capable of writing to this stream (the step-runner binary invoked per `executors/instance/steps.go`'s `Connect`/`steps.Execute` path, or any custom step/plugin whose stdout/stderr is proxied through step-runner to this writer) can produce a first write of the form `2024-01-01T00:00:00.000000Z <arbitrary content containing private_token=SECRET>` and have it copied unfiltered straight to `l.base`, i.e. directly into the job trace.

Once `s.chosen` is set via `sync.Once`, that decision is fixed for the lifetime of the writer (`s.once.Do(s.pickMode(p))` in `Write`), so a single well-formed first chunk locks in the unfiltered passthrough for the whole stream, and subsequent writes (even ones that don't look pre-stamped) still go through `s.chosen.Write(p)` = the raw passthrough, with no additional sanitization. No masking, `MaskPhrases`, `MaskTokenPrefixes`, or URL-parameter sanitization is applied on this path — the invariant that "all trace-bound output must pass through masking filters" is broken by design in this specific branch, as the accompanying doc comment for `StepRunnerStream` explicitly acknowledges ("bytes flow straight through to the base trace, preserving step-runner's headers").

### Impact Explanation
Any sensitive value embedded in an attacker-influenced step-runner/custom-step output line that happens to satisfy `isPreStamped`'s positional format is written verbatim into the CI job trace, completely bypassing GitLab Runner's masking defenses (`masker`, `urlsanitizer`, `tokensanitizer`). This defeats the runner's core secret-masking guarantee specifically for step-runner-sourced output when `Timestamping` is enabled, exposing tokens/URLs/credentials (e.g. `private_token=`, CI job tokens, registry credentials) in trace output visible to anyone with pipeline/job log read access.

### Likelihood Explanation
Preconditions are narrow but realistic: `Timestamping` must be enabled (the default in modern GitLab Runner configurations using `steps.Execute`), and the job must use the steps/step-runner mechanism (`Build.executeStepStage`) with a step whose output the attacker controls (a custom/community step, or a step-runner plugin invoking untrusted logic). Crafting a line matching the 28-byte positional check is trivial — the check only constrains 8 specific byte positions, leaving full freedom over the remaining content, including secret-looking substrings. This is deterministically reproducible: a single controlled first write to the stream fixes the bypass for the whole stream's lifetime via `sync.Once`.

### Recommendation
Do not fully bypass the sanitizer/masker chain for pre-stamped step-runner output. Instead, when timestamping is on and `isPreStamped(p)` is true, strip the pre-existing timestamp header, route the remaining body through the same `masker`/`urlsanitizer`/`tokensanitizer` filters used by `buildWrapped`/`buildStripped`, and re-attach (or preserve) the original timestamp header afterward — mirroring what the `isPreStamped && !timestamping` branch already does via `innerstream`/`buildStripped`, but without skipping sanitization. Alternatively, treat `s.passthrough` itself as `masker.New(urlsanitizer.New(tokensanitizer.New(l.base, ...)), l.maskPhrases)` (i.e., always wrap `l.base` with the sanitizer chain, only omitting the `timestamper.New` stage) so pre-stamped headers are preserved while content is still sanitized.

```go
// common/buildlogger/build_logger_passthrough_test.go
package buildlogger

import (
	"strings"
	"testing"

	"github.com/sirupsen/logrus"
)

// fakeTrace is a minimal Trace capturing all writes.
type fakeTrace struct {
	buf strings.Builder
}

func (f *fakeTrace) Write(p []byte) (int, error) { return f.buf.Write(p) }
func (f *fakeTrace) IsStdout() bool              { return false }

func TestStepRunnerStream_PreStampedTimestampingBypassesMasking(t *testing.T) {
	trace := &fakeTrace{}
	logger := New(trace, logrus.NewEntry(logrus.New()), Options{
		Timestamping: true,
		MaskPhrases:  []string{"SECRET"},
	})

	w := logger.StepRunnerStream(StreamWorkLevel, Stdout)

	// Pre-stamped header format per isPreStamped, embedding a sensitive
	// URL parameter that urlsanitizer would normally mask.
	line := []byte("2024-01-01T00:00:00.000000Z GET /repo.git?private_token=SECRET\n")

	if _, err := w.Write(line); err != nil {
		t.Fatalf("unexpected write error: %v", err)
	}
	_ = w.Close()

	out := trace.buf.String()
	if !strings.Contains(out, "private_token=SECRET") {
		t.Fatalf("expected masking bypass: secret should be present verbatim in trace, got: %q", out)
	}
}
```
Expected assertion: the raw string `private_token=SECRET` is present unmodified in the fake trace buffer, confirming that `stepRunnerStream.pickMode`'s passthrough branch delivers attacker-controlled, pre-stamped-format content to the trace without passing through `urlsanitizer.Write`, `masker`, or `tokensanitizer`. // StepRunnerStream returns a writer for output produced by step-runner.
```go
// The mode is picked on the first write:
//
//   - pre-stamped (per isPreStamped) and Timestamping is on: bytes flow
//     straight through to the base trace, preserving step-runner's headers
//     and avoiding double-stamping.
//   - pre-stamped and Timestamping is off: step-runner stamps anyway (it
//     has no knob to disable them), so bytes are demuxed by innerstream
//     and inner bodies routed through per-type wrap chains, giving the
//     stamp-free trace the caller asked for.
//   - not pre-stamped: bytes flow through one wrap chain with the
//     caller-supplied streamType.
func (l *Logger) StepRunnerStream(streamID int, streamType StreamType) io.WriteCloser {
	if l.base == nil {
		return internal.NewNopCloser(io.Discard)
	}

	return &stepRunnerStream{
		timestamping: l.timestamping,
		passthrough:  internal.NewSync(l.base),
		buildStripped: func() io.WriteCloser {
			return newInnerStreamStripper(
				l.wrap(l.base, streamID, Stdout),
				l.wrap(l.base, streamID, Stderr),
			)
		},
		buildWrapped: func() io.WriteCloser {
			return l.wrap(l.base, streamID, streamType)
		},
	}
}
```

```go
// isPreStamped reports whether p starts with a runner timestamper header
// (YYYY-MM-DDTHH:MM:SS.UUUUUUZ<space>). Validating the full shape, not
// just byte 26, hardens the detection against producers other than
// step-runner that might happen to put 'Z' at byte 26.
func isPreStamped(p []byte) bool {
	if len(p) < 28 {
		return false
	}
	return p[4] == '-' && p[7] == '-' && p[10] == 'T' &&
		p[13] == ':' && p[16] == ':' && p[19] == '.' &&
		p[26] == 'Z' && p[27] == ' '
}

func (s *stepRunnerStream) Write(p []byte) (int, error) {
	s.once.Do(s.pickMode(p))
	return s.chosen.Write(p)
}

func (s *stepRunnerStream) Close() error {
	// Close before any write: fall back to the wrap chain so Close has
	// something to delegate to.
	s.once.Do(s.pickMode(nil))
	return s.chosen.Close()
}

func (s *stepRunnerStream) pickMode(p []byte) func() {
	return func() {
		switch {
		case isPreStamped(p) && s.timestamping:
			s.chosen = s.passthrough
		case isPreStamped(p):
			s.chosen = s.buildStripped()
		default:
			s.chosen = s.buildWrapped()
		}
	}
}
```

```go
// wrap wraps the underlying writer with "filters". Order here somewhat
// matters, and the order they're instantiated in is the reverse order in which
// writes are processed, e.g. last added filter is the first to process data.
//
// order:
// - sync writer to ensure that multiple writes cannot happen concurrently
// - mask phrases (masker.New)
// - mask sensitive URL parameters (urlsanitizer.New)
// - mask secrets with a prefixed token (tokentanitizer.New)
// - split log lines and add timestamps (timestamper.New)
func (l *Logger) wrap(w io.WriteCloser, streamID int, streamType StreamType) io.WriteCloser {
	if l.timestamping {
		w = timestamper.New(w, timestamper.StreamType(streamType), uint8(streamID), true)
	}

	w = tokensanitizer.New(w, l.maskTokenPrefixes)
	w = urlsanitizer.New(w)
	w = masker.New(w, l.maskPhrases)
	w = internal.NewSync(w)

	return w
}
```
