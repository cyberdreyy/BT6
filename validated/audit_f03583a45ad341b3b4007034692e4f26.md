### Title
Stale OIDC-derived role cached in `oidc_user_api_tokens` is never revalidated against upstream IdP claims - ([File: core/sessions/oidcauth/oidc.go])

### Summary
The ERC2981 report's root cause is a value (`royaltyBps`) that gets updated in one place (`works[tokenId].strategy`) but is duplicated into a separate piece of state (`ERC2981`'s internal royalty mapping) that is never refreshed, so stale data is later used to make a payment decision. The same class of bug exists in the chainlink node's OIDC authenticator: a user's `Role` is a snapshot copied into a secondary, independently-queried table (`oidc_user_api_tokens`) at token-creation time, and there is no mechanism analogous to the LDAP module's `LDAPServerStateSyncer` to keep that cached role in sync with the source of truth (the IdP's claims).

### Finding Description
For session-based OIDC login, the role is derived fresh on every login from IdP claims via `IDClaimsToUserRole` in `handleTokenExchange` [1](#0-0) , so a session always reflects the latest IdP group membership.

However, API tokens are handled differently. `CreateAndSetAuthToken`/`SetAuthToken` writes the `user.Role` value it is handed (a snapshot, evaluated once) directly into the `oidc_user_api_tokens` table as a persisted column, alongside the token secret: [2](#0-1) 

`FindUserByAPIToken`, which is the function invoked on every API-authenticated request via `AuthenticateByToken`, simply reads back this cached `user_role` column with no revalidation against the identity provider: [3](#0-2) [4](#0-3) 

Unlike the LDAP driver, which ships a dedicated `LDAPServerStateSyncer.Work` background job that periodically re-queries the upstream directory and propagates any role change into both `ldap_sessions` and `ldap_user_api_tokens` via `UPDATE ... SET user_role = CASE ...` [5](#0-4) , the `oidcauth` package contains no equivalent syncer. I found no code path in `core/sessions/oidcauth/oidc.go` that re-derives or updates `oidc_user_api_tokens.user_role` after the token is created; the only writes to that table are the delete-then-insert in `SetAuthToken` itself (which requires the caller to already have the desired role in hand).

The `Role` stored in the API token record is therefore only as fresh as the moment the token was minted. If an administrator later reduces a user's privileges at the identity provider (e.g., removes them from an "Admin" claim group), the change takes effect for future login sessions (since sessions call `IDClaimsToUserRole` again), but any previously issued, still-unexpired API token continues to authenticate the caller with the old, higher-privileged `Role` value stored verbatim in `oidc_user_api_tokens`, for the entire remaining `UserAPITokenDuration` window.

### Impact Explanation
An unprivileged/downgraded actor who obtained an API token while still holding an elevated role (e.g., admin) retains that elevated access via the API-token authentication path even after their upstream IdP role is revoked, until the token expires or is manually deleted. Because chainlink node API tokens grant the ability to trigger job runs, manage bridges, keys, and other admin-level node operations depending on role, this is a concrete authorization/role bypass: the authoritative "current" role check is bypassed by presenting a static credential whose cached role value the system never re-validates.

### Likelihood Explanation
This requires (1) OIDC authentication to be enabled, (2) the affected user to have created an API token while privileged, and (3) an administrator subsequently narrowing that user's access at the IdP without knowing to also revoke the user's existing local API token (there is no automatic linkage communicated to admins that OIDC role changes don't propagate to tokens). This is a realistic day-2 operational scenario (offboarding/demotion) rather than a contrived edge case, but it does depend on the OIDC auth driver being configured, which is one of several supported `sessions` backends.

### Recommendation
Mirror the LDAP driver's design: introduce a periodic (or on-demand, at each `FindUserByAPIToken` call) revalidation of the OIDC-derived role against the current claims/IdP state, and update or purge `oidc_user_api_tokens.user_role` accordingly - analogous to how `LDAPServerStateSyncer.Work` reconciles `ldap_user_api_tokens` in `core/sessions/ldapauth/sync.go`. At minimum, document and enforce that any admin-driven role downgrade for OIDC users must also purge that user's existing `oidc_user_api_tokens` row, similar to how `localauth`'s `UpdateRole` deletes all `sessions` rows for the user on role change [6](#0-5) .

### Proof of Concept
1. Enable OIDC auth; log in as `user@example.com` who is mapped via IdP claims to `UserRoleAdmin`.
2. As `user@example.com`, call the API-token creation endpoint, which invokes `CreateAndSetAuthToken` → `SetAuthToken`, inserting a row into `oidc_user_api_tokens` with `user_role = 'admin'` [7](#0-6) .
3. Administrator removes `user@example.com` from the IdP's admin claim group (downgrading them to `view` for future logins).
4. Using the previously issued API token (`accessKey`/`secret` headers), call any admin-only endpoint. `AuthenticateByToken` → `FindUserByAPIToken` looks up the token row and returns the cached `user_role = 'admin'` without contacting the IdP [8](#0-7) , and the request succeeds with admin privileges despite the IdP-side downgrade.

// FindUserByAPIToken retrieves a possible stored user and role from the oidc_user_api_tokens table store
func (oi *oidcAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (clsessions.User, error) {
	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

// CreateAndSetAuthToken generates a new credential token with the user role
func (oi *oidcAuthenticator) CreateAndSetAuthToken(ctx context.Context, user *clsessions.User) (*auth.Token, error) {
	newToken := auth.NewToken()
	err := oi.SetAuthToken(ctx, user, newToken)
	if err != nil {
		return nil, err
	}
	return newToken, nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (oi *oidcAuthenticator) SetAuthToken(ctx context.Context, user *clsessions.User, token *auth.Token) error {
	if !oi.config.UserAPITokenEnabled() {
		return errors.New("API token is not enabled ")
	}

	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return fmt.Errorf("OIDCAuth SetAuthToken hashed secret error: %w", err)
	}

	err = sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Remove any existing API tokens
		if _, err = oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE user_email = $1", user.Email); err != nil {
			return fmt.Errorf("error executing DELETE FROM oidc_user_api_tokens: %w", err)
		}
		// Create new API token for user
		_, err = oi.ds.ExecContext(ctx,
			"INSERT INTO oidc_user_api_tokens (user_email, user_role, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1, $2, $3, $4, $5, $6, now())",
			user.Email,
			user.Role,
			token.AccessKey,
			salt,
			hashedSecret,
		)
		if err != nil {
			return fmt.Errorf("failed insert into oidc_user_api_tokens: %w", err)
		}
		return nil

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}
