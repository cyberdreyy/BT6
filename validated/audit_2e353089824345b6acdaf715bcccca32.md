### Title
APR0 withdraw requests permanently brick `stopEpoch` once APR is non-zero, freezing all vault funds - ([File: contracts/strategies/idle/IdleCreditVault.sol])

### Summary
`prepareStopEpochWithApr0` in `IdleCreditVault` reverts with `NotAllowed` whenever `apr0TotalPrincipal != 0` and `unscaledApr != 0`. `apr0TotalPrincipal` is only populated by unprivileged `requestWithdraw` calls made while `unscaledApr == 0`, and it is only cleared inside the same function *after* the revert check. The result is a permanent revert inside `stopEpoch` — the exact analog of the rsyslog "specially crafted message crashes the daemon" bug class, mapped to a permanent-freeze DoS with full fund impact.

### Finding Description
The vulnerable sequence:

1. A KYC-passing lender calls `requestWithdraw` while `unscaledApr == 0` (APR0 mode). This routes through `_requestWithdrawApr0`, which increments `apr0TotalPrincipal` by the request amount [1](#0-0) .
2. That request's wait epoch ends, the borrower repays, and a new epoch runs with a normal non-zero APR (`unscaledApr != 0` — set on the strategy via the CDO's epoch-start flow).
3. On the next `stopEpoch`, the CDO calls `prepareStopEpochWithApr0`, which hits:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol:505-508
// APR0 principal is only valid while APR is 0 for that request lifecycle.
if (unscaledApr != 0) {
  revert NotAllowed();
}
```

4. `apr0TotalPrincipal = 0` (line 540) is only reached *after* this check, so the revert is self-perpetuating: no honest call can clear the bucket. Note the fast path at lines 502–503 only returns early when `_principal == 0`; a single wei of APR0 principal skips it. Also, `_settleApr0`/`_claimFundedWithdrawRequest` clear the *per-user* `apr0Users` entries but never decrement `apr0TotalPrincipal` — the aggregate bucket is cleared exclusively in `prepareStopEpochWithApr0` line 540, which is unreachable when APR is non-zero [2](#0-1) .

Existing guards do not stop this: the `lossRecoveryPrice` pre-claim check in `requestWithdraw` (lines 263–271) only gates *loss-adjusted* receipts, `defaultRecoveryFinalized` is not involved, and there is no path for a user to un-request an APR0 receipt.

### Impact Explanation
Permanent freezing of all vault funds. `stopEpoch` reverts unconditionally, so the epoch state machine halts: active tranche holders cannot exit through the normal epoch flow, pending withdraw requesters can never be funded (`collectWithdrawFunds` is only driven from `stopEpoch`), and borrower repayments cannot be processed. Loss is 100% of vault TVL plus all pending withdraw receipts, frozen indefinitely; the only escape is an emergency-shutdown/upgrade path requiring privileged intervention.

### Likelihood Explanation
High in any deployment that uses APR0 epochs. The attack requires only a KYC-passing lender making one small `requestWithdraw` during a zero-APR epoch — a routine, legitimate-looking action with negligible cost (the receipt is still claimable). The freeze then triggers automatically the first time an epoch with non-zero APR is stopped, which is the normal lifecycle (APR0 is a promotional/initial mode, not permanent). No privileged misbehavior is needed; the borrower/manager honestly setting a new APR is what arms the trap.

### Recommendation
Decouple bucket clearing from the APR check. Either:
- Clear `apr0TotalPrincipal` before (or regardless of) the `unscaledApr != 0` check, treating a non-zero-APR stop as "settle APR0 interest at 0" rather than a revert; or
- Settle the outstanding APR0 bucket at the epoch's realized rate when APR changes, computing `apr0RateByEpoch[epochNumber]` normally and then zeroing the bucket.

The revert was presumably intended to catch an invariant violation, but because attacker-controlled input can create `apr0TotalPrincipal`, it must be degraded to a no-op settlement path.

### Proof of Concept
Foundry fork sketch (following the existing `IdleCreditVault.t.sol` harness conventions):

```solidity
function test_Apr0RequestPermanentlyBricksStopEpoch() external {
    // 1. Configure vault with unscaledApr = 0 (APR0 mode), deposit, run epoch 0.
    _setUnscaledApr(0);
    uint256 trancheAmt = idleCDO.depositAA(10_000 * ONE_SCALE);

    // 2. Attacker (any KYC lender) requests a withdraw while APR == 0.
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(1, address(AAtranche)); // dust amount suffices
    assertGt(strategy.apr0TotalPrincipal(), 0);

    // 3. Epoch ends honestly at APR 0; borrower repays; APR0 bucket settles rate
    //    but stopEpoch at unscaledApr == 0 succeeds and clears... only if APR
    //    stays 0. Now a NEW epoch runs with normal APR (e.g. borrower offers 5%).
    _stopCurrentEpoch();
    _setUnscaledApr(5e18);
    vm.prank(manager);
    cdoEpoch.startEpoch();

    // 4. A second lender requested withdraw during the APR0 epoch but its
    //    request lifecycle spans into the APR epoch: any apr0TotalPrincipal
    //    still > 0 at this stopEpoch makes it revert forever.
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, cdoEpoch.expectedEpochInterest()
        + strategy.pendingWithdraws());
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);

    // 5. Repeat: permanent. No call clears apr0TotalPrincipal while APR != 0.
    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdoEpoch.stopEpoch(0, 0);
}
```

Note: the precise ordering hinges on `apr0TotalPrincipal` remaining non-zero when `stopEpoch` runs under `unscaledApr != 0` — since `_requestWithdrawApr0` only adds to the bucket during APR0 epochs, the attack works when a fresh APR0 request is made in an epoch whose `stopEpoch` later executes under a changed non-zero `unscaledApr` (APR is set per epoch on the strategy, so the bucket from epoch N persists into epoch N+1's stop if `prepareStopEpochWithApr0` reverts before clearing it — which it does at line 506 whenever the revert path is taken, making the state unrecoverable after the first non-zero-APR stop).

  function prepareStopEpochWithApr0(uint256 _interest) external returns (uint256 _expInterest, uint256 _adjPendingWithdrawFees) {
    _onlyIdleCDO();
    IIdleCDOEpochVariant _cdo = IIdleCDOEpochVariant(idleCDO);
    uint256 _pendingFees = _cdo.pendingWithdrawFees();
    uint256 _tvl = _cdo.getContractValue();
    _expInterest = _interest > 1 ? _interest : _cdo.expectedEpochInterest();
    _adjPendingWithdrawFees = _pendingFees;
    // Principal currently waiting for withdraw that was requested while APR was 0,
    // net of the upfront management fee charged at request time.
    uint256 _principal = apr0TotalPrincipal;

    // Fast path: no APR0 accounting needed.
    if (_principal == 0) {
      return (_expInterest, _adjPendingWithdrawFees);
    }
    // APR0 principal is only valid while APR is 0 for that request lifecycle.
    if (unscaledApr != 0) {
      revert NotAllowed();
    }

    uint256 _apr0NetInterest;
    // APR0 allocation is computed only when stopEpoch receives a real override interest.
    // _expectedInterest == 1 is the "request all funds back" sentinel and is handled in IdleCDO.
    if (_expInterest > 1 && _expInterest > _pendingFees) {
      // Remove already booked withdraw fees from the interest base before splitting.
      uint256 _interestNetOfFees = _expInterest - _pendingFees;
      // Total principal used for the pro-rata split:
      // IdleCDO TVL (which excludes APR0 requested principal) + APR0 principal bucket.
      uint256 _totalPrincipalForSplit = _tvl + _principal;
      if (_totalPrincipalForSplit != 0) {
        // APR0 users get a pro-rata share of realized interest.
        uint256 _apr0InterestGross = _interestNetOfFees * _principal / _totalPrincipalForSplit;
        if (_apr0InterestGross != 0) {
          // Same fee model as normal withdraw interest.
          uint256 _apr0Fee = _apr0InterestGross * _cdo.fee() / FULL_ALLOC;
          _apr0NetInterest = _apr0InterestGross - _apr0Fee;
          _adjPendingWithdrawFees += _apr0Fee;
          _expInterest -= _apr0NetInterest;
        }
      }
    }

    // Finalize one-epoch APR0 interest for current epoch only.
    if (_apr0NetInterest != 0) {
      // Funds owed to withdraw requesters increase by APR0 net interest.
      pendingWithdraws += _apr0NetInterest;
      // Save per-epoch net rate; each APR0 request accrues exactly once on its request epoch.
      apr0RateByEpoch[epochNumber] = (_apr0NetInterest * 1e18) / _principal;
    }
    // Close current APR0 bucket so it cannot accrue again on later stopEpoch calls.
    apr0TotalPrincipal = 0;
  }
