### Title
View-role authenticated users can retrieve full RPC node connection strings (WSURL/HTTPURL) with no additional role check via GET /v2/nodes/:network or GET /v2/chains/:network/:ID/nodes - ([File: core/web/router.go])

### Summary
The `nodes` route group in `v2Routes` only requires base session/token authentication (`authv2`) with no `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, unlike sibling admin-sensitive routes (`UserController`, `LogController.Patch`, `PipelineJobSpecErrorsController.Destroy`) which are explicitly wrapped. `NodesController.Index` returns a `presenters.NodeResource` per node whose `Config` field is a full TOML marshal of the node configuration, including `WSURL` and `HTTPURL`, without any redaction.

### Finding Description
In `core/web/router.go`, the nodes routes are registered under `authv2` (session or API token auth only) with no additional role wrapper: [1](#0-0) 

This contrasts with adjacent routes in the same function that explicitly require elevated roles, e.g. `auth.RequiresAdminRole(uc.Index)` and `auth.RequiresEditRole(psec.Destroy)`: [2](#0-1) [3](#0-2) 

`NodesController.Index` builds a `presenters.NodeResource` for every `types.NodeStatus` returned by the relayer and serializes it directly in the JSON:API response with no field stripping: [4](#0-3) 

The CLI-side presenter (`NodePresenter`/`NodePresenters` in `core/cmd/nodes_commands.go`), which wraps `presenters.NodeResource` and calls the exact same HTTP endpoint path (`/v2/nodes/<network>`), confirms the `Config` field is populated with the full node TOML, including `WSURL` and `HTTPURL`: [5](#0-4) 

The integration test explicitly asserts that the value returned over the wire equals a raw `toml.Marshal` of the node (URLs included, unredacted): [6](#0-5) 

Because the URL scheme for EVM node connection strings supports embedding basic-auth credentials or API keys (e.g. `wss://user:apikey@host/ws`, or `https://host/rpc?apikey=SECRET`), any secret embedded in `WSURL`/`HTTPURL` in the operator's TOML/secrets configuration is reflected verbatim in the `Config` field of the JSON response. Since the route only requires base authentication and not `RequiresEditRole`, a view-role (or any authenticated, non-admin) API token/session holder can retrieve this data via `GET /v2/nodes/evm` or `GET /v2/chains/evm/:ID/nodes`.

### Impact Explanation
This is a credential/secret disclosure to a lower-privileged authenticated principal: a view-role user can read RPC endpoint URLs that may embed API keys or basic-auth secrets belonging to the operator's RPC provider (e.g. Infura/Alchemy keys). This matches the Chainlink bounty "sensitive information disclosure" / "unauthorized secret exposure" impact class, since it lets a restricted-role credential holder pivot to abusing the operator's third-party RPC provider quota/keys, and is a cross-privilege confidentiality violation (view role obtaining data intended for admin/edit-role management of infrastructure).

### Likelihood Explanation
Preconditions are minimal: any valid session or API token with the lowest role (view) is sufficient, since the route enforces no role check beyond authentication. The request is a single unauthenticated-role GET to a documented, stable endpoint (`/v2/nodes/:network`, `/v2/chains/:network/:ID/nodes`), fully repeatable, and requires no timing or race conditions. The only variable is whether the operator's configured `WSURL`/`HTTPURL` contains embedded credentials — a common real-world pattern for hosted RPC providers.

### Recommendation
- Strip or mask credential-bearing portions of `WSURL`/`HTTPURL` (and the `Config` TOML blob) in `presenters.NodeResource` before returning to any role below `Admin`/`Edit`, or redact userinfo/query-string secrets universally in the presenter regardless of role.
- Alternatively/additionally, wrap the `nodes` and `chains/:network/:ID/nodes` routes in `core/web/router.go` with `auth.RequiresEditRole` (or a new `RequiresViewRoleWithRedaction` pattern) so that only privileged roles receive full connection strings, while view-role responses omit `WSURL`/`HTTPURL`/`Config`.

### Proof of Concept
1. Add a handler-level integration test (in `core/web/nodes_controller_test.go` style) that:
   - Seeds an EVM chain/node config where `WSURL`/`HTTPURL` embed a fake secret, e.g. `wss://user:supersecretapikey@fake.rpc/ws`.
   - Creates an authenticated view-role session/API token (`auth.RoleView` per `sessions.User` fixtures used elsewhere in web tests).
   - Sends `GET /v2/nodes/evm` with the view-role credentials.
   - Asserts the JSON response body's `attributes.config` (or equivalent presenter field) does **not** contain the substring `supersecretapikey` — this assertion is expected to **fail** against current code, proving disclosure.
2. Cross-check with `GET /v2/chains/evm/:ID/nodes` using the same view-role session and node fixture, asserting the same redaction failure.
3. Compare against a control test using an admin-role session to confirm the same (unredacted) data is intentionally available to privileged roles, isolating the bug to the missing role check / missing redaction for lower-privileged roles.

```go
func (n *nodesController[R]) Index(c *gin.Context, size, page, offset int) {
	id := c.Param("ID")
	network := c.Param("network")

	var nodes []types.NodeStatus
	var count int
	var err error

	relayers := n.relayers
	if network != "" {
		relayers = relayers.List(chainlink.FilterRelayersByType(network))
	}

	ctx := c.Request.Context()
	if id == "" {
		// fetch all nodes
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size)
	} else {
		// fetch nodes for chain ID
		// backward compatibility
		var rid types.RelayID
		err = rid.UnmarshalString(id)
		if err != nil {
			rid.ChainID = id
			rid.Network = network
		}
		nodes, count, err = relayers.NodeStatuses(ctx, offset, size, rid)
	}

	resources := make([]R, 0, len(nodes))
	for _, node := range nodes {
		res := n.newResource(node)
		resources = append(resources, res)
	}

	paginatedResponse(c, "node", size, page, resources, count, err)
```
