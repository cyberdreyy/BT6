### Title
Stale confirmations from removed multisig members are counted toward quorum, allowing a request to execute below the live-member threshold - ([File: multisig2/src/lib.rs], [File: multisig/src/lib.rs])

### Summary
`confirm()` in both multisig contracts only validates that the *current* caller is a member and has not already confirmed; it never re-validates the *existing* entries already stored in a request's `confirmations` set against the *current* member list. When a member is removed via `DeleteMember` (multisig2) or `DeleteKey` (multisig), only requests that member itself *authored* are purged — confirmations that member cast on *other* pending requests are left untouched. Those stale confirmations continue to count toward `num_confirmations`, so a request can be executed with fewer genuinely live, authorized confirmations than the configured threshold.

### Finding Description
`confirm()` computes quorum purely from the size of the stored `confirmations` set: [1](#0-0) 

`delete_member()` only scrubs requests *created by* the removed member and the member's own `num_requests_pk` entry — it does not scan `self.confirmations` for entries referencing the removed member on other requests: [2](#0-1) 

`assert_valid_request()` (called from `confirm`) never re-checks that the previously accumulated confirmations still belong to current members: [3](#0-2) 

The same pattern exists in the legacy `multisig` contract: `DeleteKey` only removes requests signed by that key, not confirmations that key placed on other requests: [4](#0-3) [5](#0-4) 

Binding broken: `confirmations counted == live members who confirmed`. After a member removal, this equality no longer holds — the confirmation count can include a member that is no longer part of the multisig, letting `confirmations.len() >= num_confirmations` succeed even though the number of *currently authorized* confirmers is strictly lower than `num_confirmations`.

### Impact Explanation
This is a Critical-impact issue per the rules ("a multisig request executed below threshold"). A transfer, `FunctionCall`, `AddKey`/`AddMember`, or `DeployContract` request can be executed on the multisig's authority with only `num_confirmations - 1` (or fewer) genuinely live, current members having confirmed, because a stale confirmation from an already-removed member is still tallied. This breaks the fundamental security guarantee of the multisig (k-of-n live signer approval) and can lead to unauthorized transfer of NEAR/asset control, or unauthorized key/member additions.

### Likelihood Explanation
Requires no special privilege beyond being (or having been) a legitimate member at some point — an ordinary, otherwise-unprivileged member confirmation combined with a later, unrelated, valid removal of a different member is sufficient to create the stale-confirmation condition. No attacker-supplied malicious contract or callback is needed; it is a straightforward sequencing of standard multisig operations (`add_request`/`add_request_and_confirm`, `confirm`, `DeleteMember`/`DeleteKey`) that any set of members would perform in normal operation, making this readily reachable without any social engineering or privileged foundation/owner action.

### Recommendation
When removing a member/key (`DeleteMember`/`DeleteKey`), iterate over **all** pending requests' `confirmations` sets (not just requests authored by that member) and remove any entry referencing the removed member/key. Alternatively, on `confirm()`, re-validate every existing entry in the stored `confirmations` set against `self.members` (or the public key set) before counting them toward `num_confirmations`, discarding stale entries lazily.

### Proof of Concept
1. Multisig initialized with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. `A` calls `add_request_and_confirm(R)` where `R` is e.g. a `Transfer` request → `confirmations[R] = {A}`.
3. `D` calls `confirm(R)` → `confirmations[R] = {A, D}` (2 of 3, not yet executed).
4. Separately, members `A`, `B`, `C` legitimately pass a `DeleteMember { member: D }` request, removing `D` from `self.members`. `delete_member()` only removes requests *authored* by `D` and `D`'s `num_requests_pk` entry — `confirmations[R]` is untouched and still contains `D`.
5. `B` calls `confirm(R)` → `confirmations[R].len() == 3 >= num_confirmations (3)` → `execute_request(R)` runs.
6. Result: `R` executes with confirmations from `A`, `D` (no longer a member), and `B` — i.e., only 2 of the 3 *current* members (`A`, `B`, `C`) actually authorized it, one short of the configured threshold. [6](#0-5) [7](#0-6)

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
