### Title
Programmable-borrower hooks are invoked without interface verification, so a borrower contract lacking `IProgrammableBorrower` permanently bricks `stopEpoch` and freezes all lender funds - (File: contracts/IdleCDOEpochVariant.sol)

### Summary
Analogous to the Lido `OrderedCallbacksArray` issue — where a callback could be registered without proving it implements `processLidoOracleReport()`, making the oracle report revert — `IdleCDOEpochVariant` unconditionally performs external calls on the configured borrower address (`onStartEpoch`, `onStopEpoch`, `totalInterestDueNow`, `settleBorrowerInterest`, `onDefault`) whenever `isProgrammableBorrower` is set. Neither the borrower setter on `ProgrammableBorrower.sol` nor the CDO-side configuration validates that the target contract actually implements the `IProgrammableBorrower` interface (no EIP-165 / `supportsInterface` check, no probe call). If the borrower address is an EOA or a contract missing any of these methods, `stopEpoch` reverts forever and the epoch can never be stopped.

### Finding Description
In `contracts/IdleCDOEpochVariant.sol`, the epoch state machine calls into the borrower through a raw interface cast:

- `startEpoch` → `_startEpochProgrammableBorrower(_pendingWithdraws)` which calls `IProgrammableBorrower(_borrower()).onStartEpoch(...)` at `IdleCDOEpochVariant.sol:991-995`. A revert here would prevent the epoch from even starting (funds remain buffer-locked, withdrawals disabled via `allowAAWithdrawRequest = false` set at line 249-250).
- `stopEpoch` → `IProgrammableBorrower(_borrower()).onStopEpoch(...)` at `IdleCDOEpochVariant.sol:398`, and `totalInterestDueNow()` inside `_resolveStopEpochInterest` at `IdleCDOEpochVariant.sol:1004`.

If `isProgrammableBorrower == true` and `_borrower()` resolves to an address that does not implement these methods (EOA, wrong contract version, a plain `IProgrammableBorrower`-incompatible borrower), every `stopEpoch` call reverts inside `_resolveStopEpochInterest` before any accounting runs. Unlike the `sendFundsToBorrower`/`getFundsFromBorrower` paths (wrapped in `try/catch` at lines 295 and 408), the hook calls and the interest view call are *not* wrapped — the comment at line 397 even states "Hook reverts bubble", and the revert in `_resolveStopEpochInterest` happens before that hook is reached, so even the `_handleBorrowerDefault` fallback is unreachable.

On the borrower side, `ProgrammableBorrower.setBorrower` (`contracts/strategies/idle/ProgrammableBorrower.sol:176-186`) only checks `_borrower != address(0)` — there is no verification that any contract expected to expose the hook surface actually does, exactly the same gap as the Lido finding (no EIP-165-style capability check at registration time).

### Impact Explanation
Permanent freezing of all lender funds. Once `isEpochRunning` is true, the only path back to a claimable state is `stopEpoch` (or the default path reachable only *through* `stopEpoch`). With a non-conforming borrower address:

- `stopEpoch` reverts at `IdleCDOEpochVariant.sol:1004` (`totalInterestDueNow` on a non-implementer) or at line 398 (`onStopEpoch`), every time, for every caller.
- `_handleBorrowerDefault` and therefore `finalizeDefault`/`DefaultDistributor` recovery are unreachable because the revert happens before the `if (!...onStopEpoch(...))` branch completes.
- Withdrawal requests (`claimWithdrawRequest`, `claimInstantWithdrawRequest`) require a stopped epoch / vault-held funds; deposits are paused (`_pause()` at line 246). The entire TVL — including pending withdraw fees and accrued interest — is locked indefinitely.

Loss magnitude: 100% of pool NAV (`getContractValue()` plus funds already sent to the borrower/vault), matching the "permanent freezing" acceptance criterion.

### Likelihood Explanation
This is a configuration/mistake-class bug rather than an attacker-driven exploit — identical in shape to the source Lido report (a privileged but honest operator registers an incompatible address). Likelihood drivers:

- The owner/manager can enable `isProgrammableBorrower` or repoint the borrower between epochs; `ProgrammableBorrower.setBorrower` explicitly permits reassignment once `epochAccountingActive == false` and debt is cleared — precisely the window where a wrong or non-hook contract (e.g., the previous non-programmable borrower EOA, or a new borrower contract that doesn't inherit `IProgrammableBorrower`) can be wired in.
- There is no on-chain check anywhere in the registration path (`setBorrower`, factory deployment in `IdleCreditVaultFactory.sol`, or the `isProgrammableBorrower` flag setter) that the borrower implements the interface — a single mistaken address bricks the pool the next time `stopEpoch` is called.
- The failure is silent until the end of the epoch: `startEpoch`'s `onStartEpoch` call is also unwrapped, but if the flag is toggled *after* a successful start (or the contract implements only some methods), the first symptom appears at `stopEpoch`, when funds are already deployed to the borrower/vault and no recovery path exists.

Caveat: I could not fully confirm the exact setter code paths for `isProgrammableBorrower`/`_borrower()` in `IdleCDOEpochVariant.sol` (grep returned match counts without line context), but the unguarded interface calls at lines 398, 1004, and 991-995 are confirmed, and `ProgrammableBorrower.setBorrower` demonstrably performs no interface validation.

### Recommendation
Mirror the EIP-165 remediation from the Lido report:

1. Add a `supportsInterface(bytes4)` method to `IProgrammableBorrower` (implementing `IERC165`) in `contracts/interfaces/IProgrammableBorrower.sol`, and implement it in `contracts/strategies/idle/ProgrammableBorrower.sol` returning true for `type(IProgrammableBorrower).interfaceId`.
2. In every configuration path that sets the borrower or enables `isProgrammableBorrower` (`ProgrammableBorrower.setBorrower`, the CDO-side borrower/programmable-flag setters, and `IdleCreditVaultFactory` wiring), require `IERC165(candidate).supportsInterface(type(IProgrammableBorrower).interfaceId)` — or at minimum perform a probing `totalInterestDueNow()` staticcall — and revert otherwise.
3. Additionally, since EIP-165 can be lied about, consider making the `isProgrammableBorrower` flag immutable after the first successful `startEpoch`, or require an explicit two-step setter that test-calls `onStopEpoch(0,false)` semantics in a safe mode.

### Proof of Concept
Foundry fork PoC sketch:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;
import "forge-std/Test.sol";

contract NonConformingBorrower {
    // Receives funds but exposes no IProgrammableBorrower methods.
    receive() external payable {}
}

contract MissingCallbackFreezeTest is Test {
    IdleCDOEpochVariant cdo;      // deployed via factory as in ProgrammableBorrowerCreditVault.t.sol
    NonConformingBorrower badBorrower;

    function testStopEpochPermanentlyReverts() public {
        // 1. Lender deposits during buffer; epoch starts with a conforming borrower.
        idleCDO.depositAA(10_000e6);
        vm.prank(manager);
        cdo.startEpoch();

        // 2. Honest operator error: programmable flag stays on, but borrower is
        //    repointed (or was configured) to a contract with no IProgrammableBorrower.
        badBorrower = new NonConformingBorrower();
        // ... owner/manager setter call that repoints _borrower() to badBorrower ...
        // setBorrower only checks _borrower != address(0) — no interface check.

        // 3. After epochEndDate, every stopEpoch reverts in _resolveStopEpochInterest
        //    calling totalInterestDueNow() on badBorrower — before onStopEpoch,
        //    before _handleBorrowerDefault. Recovery is unreachable.
        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        vm.expectRevert(); // EVM revert on call to non-existent method
        cdo.stopEpoch(0, 0);

        // Repeat — never succeeds; all deposits + pending withdraws frozen.
        vm.prank(manager);
        vm.expectRevert();
        cdo.stopEpoch(0, 0);

        // 4. Users cannot claim: vault holds no funds, epoch never stopped.
        vm.expectRevert();
        cdo.claimWithdrawRequest();
    }
}
```

Key PoC points: the revert occurs at `IdleCDOEpochVariant.sol:1004` (unwrapped `totalInterestDueNow()` call on a non-implementer), ahead of the `onStopEpoch` hook at line 398 and the `_handleBorrowerDefault` fallback at line 401, so no privileged recovery path can unstick the epoch — full pool TVL is permanently frozen.
