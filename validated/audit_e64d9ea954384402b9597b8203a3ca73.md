### Title
Deprovisioned OIDC users retain full session/API-token access until natural expiry - no upstream revocation check exists ([File: core/sessions/oidcauth/oidc.go])

### Summary
`AuthorizedUserWithSession` and `FindUserByAPIToken` in `core/sessions/oidcauth/oidc.go` validate purely against locally-cached `oidc_sessions`/`oidc_user_api_tokens` rows and a time-based expiry, with no call back to the upstream IdP to check if the account/group membership is still valid. Combined with `DeleteUser` always returning `clsessions.ErrNotSupported`, there is no code path anywhere in the OIDC authenticator that revokes a session or API token when the upstream identity is disabled/removed.

### Finding Description
When a user authenticates via `handleTokenExchange`, the resulting role (derived once from OIDC group claims) is persisted into `oidc_sessions` and never re-validated against the IdP: [1](#0-0) 

Session validation in `AuthorizedUserWithSession` only checks `created_at + SessionTimeout() >= now()` against the local `oidc_sessions` table: [2](#0-1) 

Likewise, `FindUserByAPIToken` only checks `created_at + UserAPITokenDuration() >= now()` against `oidc_user_api_tokens`: [3](#0-2) 

The inline comments in both functions claim "sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation," but `reaper.go` only performs time-based deletion of stale rows — it never queries the OIDC provider to check for revoked/disabled accounts: [4](#0-3) 

Finally, `DeleteUser` — the only explicit de-provisioning hook exposed by the `AuthenticationProvider` interface — is a no-op that always fails, and no other function purges `oidc_sessions`/`oidc_user_api_tokens` rows for a given email outside of natural time expiry or explicit `DeleteUserSession`/`DeleteAuthToken` calls (which nothing triggers on IdP-side deprovisioning): [5](#0-4) 

Consequently, once a valid session cookie or API token has been issued, it remains fully authoritative for its entire local TTL window regardless of what happens to the corresponding account/groups at the IdP. This differs from the LDAP driver, which has a dedicated `core/sessions/ldapauth/sync.go` upstream sync mechanism.

### Impact Explanation
A de-provisioned/disabled identity (e.g., a terminated employee, or an account whose admin/edit group membership is revoked at the IdP) keeps full API access with its last-known role for up to `SessionTimeout()` (sessions) or `UserAPITokenDuration()` (API tokens). Depending on the cached role, this can mean retained Admin-level access to job specs, keys, bridges, and other sensitive node operations after the organization believes the identity has been cut off — an "undeletable access" class of authorization bypass.

### Likelihood Explanation
Precondition is simply possession of a previously-issued, still-time-valid session cookie or API token — no special privilege beyond what was already granted before revocation is required, and no admin/host access is needed by the credential holder to continue using it. This is fully deterministic and repeatable: any credential minted while the account was active continues to authenticate successfully until its stored `created_at` + duration lapses, since the code contains no upstream check to short-circuit this.

### Recommendation
Implement an upstream synchronization/revocation mechanism for the OIDC driver (analogous to `ldapauth/sync.go`), or reduce the trust window by periodically re-verifying against the IdP (e.g., via `UpstreamSyncInterval` as the misleading comment suggests) and purge `oidc_sessions`/`oidc_user_api_tokens` on detected revocation. At minimum, implement `DeleteUser` to purge all sessions/tokens for that email, and expose an admin-triggered revocation path instead of unconditionally returning `ErrNotSupported`.

### Proof of Concept
```go
func Test_OIDC_DeprovisionedUser_RetainsAccess(t *testing.T) {
    ctx := t.Context()
    db, oidcAuthProvider := setupAuthenticationProvider(t)

    // Simulate a user session created while the IdP account/group was active
    email := "revoked-user@example.com"
    session := clsessions.NewSession()
    _, err := db.ExecContext(ctx,
        "INSERT INTO oidc_sessions (id, user_email, user_role, created_at) VALUES ($1, $2, $3, now())",
        session.ID, email, clsessions.UserRoleAdmin)
    require.NoError(t, err)

    // Simulate upstream IdP deleting/disabling the account -- no local hook exists to
    // invalidate the session, so we call the only exposed de-provisioning API:
    err = oidcAuthProvider.DeleteUser(ctx, email)
    require.ErrorIs(t, err, clsessions.ErrNotSupported) // confirms no revocation occurred

    // The session remains valid and still returns Admin role
    user, err := oidcAuthProvider.AuthorizedUserWithSession(ctx, session.ID)
    require.NoError(t, err) // EXPECTED TO FAIL if properly revoked -- proves the gap
    require.Equal(t, clsessions.UserRoleAdmin, user.Role)

    // Same for API token
    apiToken := "revoked-user-token"
    _, err = db.ExecContext(ctx,
        "INSERT INTO oidc_user_api_tokens (user_email, user_role, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1,$2,$3,'','',now())",
        email, clsessions.UserRoleAdmin, apiToken)
    require.NoError(t, err)

    tokenUser, err := oidcAuthProvider.FindUserByAPIToken(ctx, apiToken)
    require.NoError(t, err) // EXPECTED TO FAIL if properly revoked
    require.Equal(t, clsessions.UserRoleAdmin, tokenUser.Role)
}
```

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
}
