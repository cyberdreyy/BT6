## Title
Zip archive extraction in `ziplegacy`/`archives.ExtractZipArchive` performs no path-traversal or absolute-path validation on entry names, allowing zip-slip file writes outside the job workspace - (`File: helpers/archives/zip_extract.go`, `commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`)

### Summary
The `ziplegacy.extractor.Extract` function stores a `dir` field but never uses it; it just parses the zip and calls `archives.ExtractZipArchive(zr)`, which writes each entry using the raw, attacker-controlled `file.Name` with no cleaning, no traversal check, and no confinement to any root directory. This is in stark contrast to the `tarzstd` extractor, which explicitly joins entries onto `e.dir`, computes an absolute path, and rejects any entry whose resolved path does not have `e.dir` as a prefix.

### Finding Description
`ziplegacy.NewExtractor` builds an `extractor{r, size, dir}` [1](#0-0) , but `Extract` never references `e.dir` — it only opens the zip reader and forwards to `archives.ExtractZipArchive` [2](#0-1) .

Inside `archives.ExtractZipArchive`, each `zip.File` is passed straight to `extractZipFile`, which does `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, depending on entry type, `os.OpenFile(file.Name, ...)`, `os.Symlink(data, file.Name)`, or `os.Mkdir(file.Name, ...)` [3](#0-2) . `file.Name` is used verbatim — it is never `filepath.Clean`ed, never checked for `..` segments, never rejected if absolute, and never joined against nor validated against any extraction root. `ExtractZipArchive` itself only special-cases `.git` directory entries via `errorIfGitDirectory`, which is unrelated to path confinement [4](#0-3) .

Compare this to `tarzstd.extractor.Extract`, which computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and then enforces `if !strings.HasPrefix(path, e.dir+string(filepath.Separator)) && path != e.dir { return fmt.Errorf(...) }` before ever touching the filesystem [5](#0-4) . No equivalent check exists anywhere on the zip extraction path.

Reachable call chain: `CacheExtractorCommand.Execute` opens the (possibly downloaded) cache archive and calls `archive.NewExtractor(format, f, size, wd)` then `extractor.Extract(...)` [6](#0-5) . When `format` resolves to the legacy zip extractor (the default decompressor for zip/zip+zstd unless fastzip's own extractor is explicitly wired in) [7](#0-6) , extraction proceeds with zero path confinement, regardless of the `wd` that was passed in and stored (but ignored) as `dir`.

### Impact Explanation
A malicious/crafted zip payload with an entry named e.g. `../../etc/cron.d/pwn` or an absolute path can cause `os.MkdirAll`/`os.OpenFile`/`os.Symlink` to create or overwrite files anywhere the extracting process has filesystem permissions, entirely outside the intended job/cache working directory. This is a classic "zip-slip" and directly violates the invariant that "file operations must stay within intended build/cache/artifact roots." Concrete impact is unauthorized file write/overwrite on the executor host outside the job workspace, potentially escalating to code execution if written to a path that is later executed (e.g., cron directories, shell profile files, or overwriting binaries the runner or job later invokes) when the runner process has sufficient privileges.

### Likelihood Explanation
Reaching this code only requires supplying a zip byte stream that the legacy zip extractor is asked to decompress — no additional authentication or privilege beyond controlling the archive content being extracted (cache download content, or any place the zip/ziplegacy extractor is invoked on job/attacker-influenced bytes). Constructing the malicious entry name is trivial with Go's standard `archive/zip` writer. The bug is deterministic and 100% repeatable: `extractZipFile` performs no validation whatsoever, so any crafted entry name is honored as-is.

### Recommendation
Add the same confinement logic used in `tarzstd`'s extractor to the zip extraction path: resolve each entry's target path via `filepath.Join(dir, file.Name)`, take `filepath.Abs`, and reject (return an error, do not silently skip) any entry whose resolved path does not stay within `dir` (checking both `strings.HasPrefix(path, dir+string(filepath.Separator))` and `path == dir`). This check should be added to `extractZipFile`/`ExtractZipArchive` in `helpers/archives/zip_extract.go`, and `ziplegacy.extractor.Extract` must actually pass and use its `e.dir` field (currently dead) to anchor extraction, mirroring `tarzstd_extractor.go` lines 57-64.

### Proof of Concept
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    tempFile, err := os.CreateTemp("", "archive")
    require.NoError(t, err)
    defer os.Remove(tempFile.Name())

    zw := zip.NewWriter(tempFile)
    w, err := zw.Create("../../tmp/zipslip_poc")
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())
    tempFile.Close()

    dir := t.TempDir()
    os.Chdir(dir)

    err = ExtractZipFile(tempFile.Name())
    // Expect: should error or refuse escape; current code succeeds and writes outside dir
    require.NoError(t, err) // demonstrates no rejection occurs

    _, statErr := os.Stat("/tmp/zipslip_poc")
    assert.NoError(t, statErr, "file was written outside extraction root")
    os.Remove("/tmp/zipslip_poc")
}
```
Expected (fixed) behavior: `ExtractZipFile`/`Extract` should return a non-nil error for the traversal entry and the file `/tmp/zipslip_poc` should never be created.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	for _, file := range archive.File {
		if err := lchmod(file.Name, file.Mode()); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}

		// Process zip metadata
		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}
