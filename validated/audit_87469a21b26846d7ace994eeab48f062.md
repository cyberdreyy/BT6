### Title
Missing role check on `/v2/debug/pprof/*` routes allows any authenticated (including view-role) user to access full pprof debug endpoints - ([File: core/web/router.go])

### Summary
`v2Routes` registers `metricRoutes(authv2)` at [1](#0-0) , and `metricRoutes` mounts all `net/http/pprof` handlers (`profile`, `trace`, `heap`, `goroutine`, `allocs`, `block`, `mutex`, `threadcreate`, `cmdline`, `symbol`) directly on that group without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper [2](#0-1) . The `authv2` group only enforces authentication (valid session or API token), not authorization by role [3](#0-2) , so any user with the lowest privilege role (`view`) can reach these handlers.

### Finding Description
Every other sensitive endpoint in `v2Routes` (key export/import, user management, transfers) is explicitly wrapped with `auth.RequiresAdminRole` or `auth.RequiresEditRole`/`RequiresRunRole`, e.g. key export at [4](#0-3) . In contrast, `metricRoutes(authv2)` is called at [1](#0-0)  and the routes it registers have no role predicate at all:
```
pprofGroup.GET("/profile", ginHandlerFromHTTP(pprof.Profile))
pprofGroup.GET("/trace", ginHandlerFromHTTP(pprof.Trace))
pprofGroup.GET("/goroutine", ginHandlerFromHTTP(pprof.Handler("goroutine").ServeHTTP))
pprofGroup.GET("/heap", ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP))
``` [5](#0-4) 

The `authv2` group's only gate is `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)` [3](#0-2) , which merely validates that the caller has a valid session/token and sets the authenticated user in context via `GetAuthenticatedUser`, without checking `user.Role` [6](#0-5) . Role checks only occur where handlers are explicitly wrapped with `RequiresRunRole`, `RequiresEditRole`, or `RequiresAdminRole` [7](#0-6) , none of which is applied to the pprof routes. Consequently a `view`-role user (the lowest privilege, normally read-only) or a token restricted to view access can call `GET /v2/debug/pprof/heap`, `/goroutine`, `/profile`, or `/trace` and obtain full heap/goroutine dumps and CPU profiles of the running node process.

### Impact Explanation
Heap and goroutine dumps from `pprof` can contain process memory contents, including in-memory key material, decrypted secrets, session tokens, or other sensitive state resident in the Go runtime, disclosed to a user who should only have view privileges. This matches Chainlink's "unauthorized information disclosure" / "sensitive data exposure via authorization bypass" bounty impact class — an authenticated low-privilege principal reaching functionality that should be gated at a higher trust level (effectively admin/operator-only debug tooling).

### Likelihood Explanation
Feasibility is high and directly reproducible: no special conditions are needed beyond obtaining a valid session cookie or API token for a `view`-role user (the lowest role explicitly supported by the system, `clsessions.UserRoleView`). The request is a single unauthenticated-role-check `GET` to a fixed, discoverable path (`/v2/debug/pprof/heap`, etc.), fully repeatable.

### Recommendation
Wrap each `pprofGroup` route registered in `metricRoutes` with `auth.RequiresAdminRole` (consistent with other sensitive debug/administrative endpoints such as key export/import and user management), or require a dedicated admin-only group when calling `metricRoutes(authv2)` in `v2Routes`.

### Proof of Concept
Extend the existing role-based routing test table (the `routesRolesMap`-style test in `core/web/auth/auth_test.go`, or an equivalent `core/web` router test) with an entry for `GET /v2/debug/pprof/heap` (and optionally `/profile`, `/trace`, `/goroutine`):
1. Set up a test server via `NewRouter` with a fake `Authenticator` that returns a user with `Role: clsessions.UserRoleView`.
2. Authenticate via session or `X-API-KEY`/`X-API-SECRET` headers.
3. `GET /v2/debug/pprof/heap`.
4. Assert current (vulnerable) behavior returns `http.StatusOK` with pprof payload, whereas expected/fixed behavior should return `http.StatusForbidden` for `view` role, matching the pattern used for `RequiresAdminRole`-protected routes elsewhere in the same table-driven test.

// Authenticate is middleware which authenticates the request by attempting to
// authenticate using all the provided methods.
func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

// GetAuthenticatedUser extracts the authentication user from the context.
func GetAuthenticatedUser(c *gin.Context) (*clsessions.User, bool) {
	obj, ok := c.Get(SessionUserKey)
	if !ok {
		return nil, false
	}

	user, ok := obj.(*clsessions.User)

	return user, ok
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
