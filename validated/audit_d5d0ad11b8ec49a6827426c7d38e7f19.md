### Title
`block_rejection_signer_addrs` primary key is scoped only to `signer_addr`, silently dropping a signer's rejection of any *new* block once they've ever rejected a different one — wedging the global-rejection threshold (File: `stacks-signer/src/signerdb.rs`)

### Summary
The bug class in the Ajna report is: a per-key nested/child state (`snapshot` inside `StakeInfo`) is not correctly scoped/cleared to the identity that should own it, so a later reuse of the outer key silently reuses/loses state that belongs to a different logical instance, corrupting an aggregate calculation. In this repo, `stacks-signer/src/signerdb.rs` has an analogous schema defect: the `block_rejection_signer_addrs` table is supposed to record, per `(signer_signature_hash, signer_addr)` pair, whether that signer rejected that specific block — but its `PRIMARY KEY` is declared on `signer_addr` alone.

### Finding Description
The table is created with:
```
CREATE TABLE IF NOT EXISTS block_rejection_signer_addrs (
    signer_signature_hash TEXT NOT NULL,
    signer_addr TEXT NOT NULL,
    PRIMARY KEY (signer_addr)
) STRICT;
``` [1](#0-0) 

but the read/write logic in `add_block_rejection_signer_addr` treats it as if the key were `(signer_signature_hash, signer_addr)`:
```rust
let qry = "SELECT reject_code FROM block_rejection_signer_addrs WHERE signer_signature_hash = ?1 AND signer_addr = ?2 LIMIT 1";
...
match existing_code {
    Some(code) if code == reject_code => { ... Ok(false) }
    Some(_) => { /* UPDATE ... WHERE signer_signature_hash = ?2 AND signer_addr = ?3 */ Ok(true) }
    None => {
        let insert_qry = "INSERT INTO block_rejection_signer_addrs (signer_signature_hash, signer_addr, reject_code) VALUES (?1, ?2, ?3)";
        ...
        Ok(true)
    }
}
``` [2](#0-1) 

Because the `SELECT ... WHERE signer_signature_hash = ?1 AND signer_addr = ?2` lookup is scoped to the *specific* block hash, once a signer address already has a row for a *different* block hash (from a previous rejection, of any tenure, any reward cycle — this table has no reward-cycle scoping or pruning), the lookup returns `None` for the new block. Execution falls into the `INSERT` branch, but since the table's real primary key is `signer_addr` alone, that `INSERT` collides with the pre-existing row and raises a `PRIMARY KEY` constraint violation, returning `Err(DBError)`.

The caller treats this failure as non-fatal:
```rust
match self.signer_db.add_block_rejection_signer_addr(block_hash, signer_address, reject_reason) {
    Err(e) => { warn!("{self}: Failed to save block rejection signature: {e:?}",); }
    Ok(false) => return,
    Ok(true) => (),
}
...
let rejection_addrs = match self.signer_db.get_block_rejection_signer_addrs(block_hash) { ... };
let total_reject_weight = self.compute_signature_signing_weight(rejection_addrs.iter().map(|(addr, _)| addr));
``` [3](#0-2) 

so it just logs a warning and continues computing `total_reject_weight` from `get_block_rejection_signer_addrs(block_hash)` — a query scoped by `signer_signature_hash = ?1` — which, because the INSERT never landed, silently omits that signer's rejection weight from the running tally used to decide `mark_globally_rejected`. [4](#0-3) 

### Impact Explanation
This breaks the equality between "actual verified local rejections by the signer set" and "the aggregated rejection weight the state machine uses to declare a block globally rejected." A single signer that has ever rejected one block will have every subsequent rejection of a *different* block silently dropped from persisted storage (only a rejection of the exact same `signer_signature_hash` can update the existing row). In a live network this condition is trivially reached — signers routinely reject multiple different block proposals over time (tenure extensions, re-proposals, forks). Once enough signers hit this PK collision on a given contested block, `total_reject_weight` computed in `store_and_process_block_rejection` can never reach the blocking-minority threshold even though a real supermajority locally rejected the block, so `mark_globally_rejected` is never invoked and the block/tenure state machine can wedge — no global rejection ever fires to unblock the miner/coordinator, and the miner cannot fall back to a new tenure via the normal rejection-threshold path. This matches the "High" impact category of a signer/tenure being wedged out of making forward progress due to a broken vote-aggregation invariant.

### Likelihood Explanation
No majority collusion, private key access, or auth_token is needed — this is triggered purely by normal operation: any signer rejecting two different blocks over the life of the signer process is sufficient to poison that address's row for all future distinct block hashes. The tests in the repo (`add_and_get_block_rejections`, `duplicate_block_rejections`, `reject_then_accept`, `accept_then_reject`) all only exercise a single `block_id` per test, which is consistent with this cross-block collision path being unexercised and unnoticed. [5](#0-4) 

### Recommendation
Fix the schema so the primary key matches the intended semantics, i.e. `PRIMARY KEY (signer_signature_hash, signer_addr)`, with an accompanying migration to correct any existing databases, and add a test that has the same signer address reject two distinct block hashes to confirm both rejections are persisted and counted independently.

### Proof of Concept
1. Signer S rejects block A (`sighash_A`) — `add_block_rejection_signer_addr(sighash_A, S, reason1)` inserts row `(sighash_A, S, reason1)`; the real PK is just `S`.
2. A different block B (`sighash_B`, e.g. a re-proposal after tenure retry, or a fork) is proposed and S also locally rejects it. `store_and_process_block_rejection` calls `add_block_rejection_signer_addr(sighash_B, S, reason2)`.
3. The lookup `WHERE signer_signature_hash = sighash_B AND signer_addr = S` returns no row (the stored row is for `sighash_A`), so the code takes the `None` branch and executes `INSERT INTO block_rejection_signer_addrs (sighash_B, S, reason2)`.
4. Because `signer_addr = S` already exists as the primary key from step 1, SQLite raises a `PRIMARY KEY` constraint violation; `add_block_rejection_signer_addr` returns `Err(...)`.
5. `store_and_process_block_rejection` logs a warning and proceeds; `get_block_rejection_signer_addrs(sighash_B)` does not include S, so S's weight is missing from `total_reject_weight` for block B, permanently (unless S later rejects `sighash_A` again, which frees nothing for `sighash_B`).
6. If a sufficient number of signers independently hit this same collision (any of them having rejected a prior distinct block), block B can never accumulate enough tallied rejection weight to cross the blocking-minority threshold in `store_and_process_block_rejection`, even though the true local-reject weight across the live signer set exceeds it — the tenure is wedged.

    pub fn add_block_rejection_signer_addr(
        &self,
        block_sighash: &Sha512Trunc256Sum,
        addr: &StacksAddress,
        reject_reason: RejectReasonPrefix,
    ) -> Result<bool, DBError> {
        // If this signer/block already has a signature, do not allow a rejection
        let sig_qry = "SELECT EXISTS(SELECT 1 FROM block_signatures WHERE signer_signature_hash = ?1 AND signer_addr = ?2)";
        let sig_args = params![block_sighash, addr.to_string()];
        let exists = self.db.query_row(sig_qry, sig_args, |row| row.get(0))?;
        if exists {
            warn!("Cannot add block rejection because a signature already exists.";
                "signer_signature_hash" => %block_sighash,
                "signer_address" => %addr,
                "reject_reason" => ?reject_reason
            );
            return Ok(false);
        }

        // Check if a row exists for this sighash/signer combo
        let qry = "SELECT reject_code FROM block_rejection_signer_addrs WHERE signer_signature_hash = ?1 AND signer_addr = ?2 LIMIT 1";
        let args = params![block_sighash, addr.to_string()];
        let existing_code: Option<i64> =
            self.db.query_row(qry, args, |row| row.get(0)).optional()?;

        let reject_code = reject_reason as i64;

        match existing_code {
            Some(code) if code == reject_code => {
                // Row exists with same reject_reason, do nothing
                debug!("Duplicate block rejection.";
                    "signer_signature_hash" => %block_sighash,
                    "signer_address" => %addr,
                    "reject_reason" => ?reject_reason
                );
                Ok(false)
            }
            Some(_) => {
                // Row exists but with different reject_reason, update it
                let update_qry = "UPDATE block_rejection_signer_addrs SET reject_code = ?1 WHERE signer_signature_hash = ?2 AND signer_addr = ?3";
                let update_args = params![reject_code, block_sighash, addr.to_string()];
                self.db.execute(update_qry, update_args)?;
                debug!("Updated block rejection reason.";
                    "signer_signature_hash" => %block_sighash,
                    "signer_address" => %addr,
                    "reject_reason" => ?reject_reason
                );
                Ok(true)
            }
            None => {
                // Row does not exist, insert it
                let insert_qry = "INSERT INTO block_rejection_signer_addrs (signer_signature_hash, signer_addr, reject_code) VALUES (?1, ?2, ?3)";
                let insert_args = params![block_sighash, addr.to_string(), reject_code];
                self.db.execute(insert_qry, insert_args)?;
                debug!("Inserted block rejection.";
                    "signer_signature_hash" => %block_sighash,
                    "signer_address" => %addr,
                    "reject_reason" => ?reject_reason
                );
                Ok(true)
            }
        }
    }

    /// Get all signer addresses that rejected the block (and their reject codes)
    pub fn get_block_rejection_signer_addrs(
        &self,
        block_sighash: &Sha512Trunc256Sum,
    ) -> Result<Vec<(StacksAddress, RejectReasonPrefix)>, DBError> {
        let qry =
            "SELECT signer_addr, reject_code FROM block_rejection_signer_addrs WHERE signer_signature_hash = ?1";
        let args = params![block_sighash];
        let mut stmt = self.db.prepare(qry)?;

        let rows = stmt.query_map(args, |row| {
            let addr: String = row.get(0)?;
            let addr = StacksAddress::from_string(&addr).ok_or(SqliteError::InvalidColumnType(
                0,
                "signer_addr".into(),
                rusqlite::types::Type::Text,
            ))?;
            let reject_code: i64 = row.get(1)?;

            let reject_code = u8::try_from(reject_code)
                .map_err(|_| {
                    SqliteError::InvalidColumnType(
                        1,
                        "reject_code".into(),
                        rusqlite::types::Type::Integer,
                    )
                })
                .map(RejectReasonPrefix::from)?;

            Ok((addr, reject_code))
        })?;

        rows.collect::<Result<Vec<_>, _>>().map_err(|e| e.into())
    }
