### Title
Bridge `OutgoingToken` credential disclosed to any authenticated role via ungated `GET /v2/bridge_types/:BridgeName` and `GET /v2/bridge_types` - ([File: core/web/router.go])

### Summary
`GET /v2/bridge_types/:BridgeName` and `GET /v2/bridge_types` are registered in `v2Routes` with no role wrapper (`auth.RequiresEditRole`/`auth.RequiresAdminRole`), unlike most other mutating bridge routes, mirroring the same under-gating pattern seen on `GET /v2/keys/dkgrecipient` in the same auth group. The handler serializes the bridge's plaintext `OutgoingToken` secret into the JSON response for any authenticated caller, including a view-role session.

### Finding Description
In `v2Routes` (`core/web/router.go`), the bridge routes are: [1](#0-0) 
`bt.Index` and `bt.Show` have no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper — only membership in the `authv2` group (any authenticated session via token or cookie) is required, the same shallow gating pattern as `authv2.GET("/keys/dkgrecipient", dkrkc.Index)` at line 389.

`BridgeTypesController.Show`/`Index` call `presenters.NewBridgeResource(bt)`: [2](#0-1) 
which maps `bridges.BridgeType.OutgoingToken` directly into `BridgeResource.OutgoingToken` with no `omitempty` and no redaction: [3](#0-2) 

`OutgoingToken` is a real plaintext bridge credential (generated via `utils.NewSecret(24)`) persisted and reused unencrypted in `BridgeType`: [4](#0-3) 
Unlike `IncomingToken` (which is only ever hashed/salted into `IncomingTokenHash` and never stored/returned outside the `Create` response), `OutgoingToken` is stored and served in plaintext on every `Show`/`Index`/`Update`/`Destroy` call, regardless of caller role, because there is no role check on the read paths and no redaction in the presenter.

### Impact Explanation
Any authenticated node user — including a low-privilege view-role account — can call `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` and obtain the plaintext `OutgoingToken` for every configured bridge. This token is a credential used to authenticate the node's outbound EA requests; its disclosure enables impersonation of the node to the external adapter or reuse of the secret beyond its intended scope — matching the bounty impact class of "sensitive credential/secret disclosure to unauthorized/low-privilege user."

### Likelihood Explanation
Trivial and fully repeatable: it only requires a valid session/API token of any role (the lowest, view/run role, is sufficient since there is no `RequiresEditRole`/`RequiresViewRole` gate on the `Show`/`Index` handlers), and a single unauthenticated-in-terms-of-authorization GET request. No race conditions or special timing needed.

### Recommendation
Add explicit minimum-role enforcement (`auth.RequiresViewRole` at least, or restrict to `RequiresEditRole`) on `authv2.GET("/bridge_types", ...)` and `authv2.GET("/bridge_types/:BridgeName", ...)`, and strip/redact `OutgoingToken` from `BridgeResource` for read endpoints (only exposing it, like `IncomingToken`, at creation time or to admin/edit roles). Apply the same audit to `GET /v2/keys/dkgrecipient` and other ungated `Index`/`Show` routes in `v2Routes`.

### Proof of Concept
Handler-level integration test plan (Go, using existing `cltest` helpers as in `core/web/bridge_types_controller_test.go`):
1. Create an application with a view-role authenticated client (`cltest.CreateJobRunViewerSession` or equivalent low-privilege session/API token).
2. As an admin/edit-role client, `POST /v2/bridge_types` to create a bridge, capturing the returned `outgoingToken`.
3. Using the view-role client, `GET /v2/bridge_types/{name}` and `GET /v2/bridge_types`.
4. Assert HTTP 200 and that the JSON response's `attributes.outgoingToken` equals the real secret token (proving disclosure), or — after the fix — assert HTTP 403/redacted empty value.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
}
