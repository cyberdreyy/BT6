No vulnerability found for this question.

**Analysis:**

The premise doesn't hold up against how `coins_to_redeem_to_ensure_min_stake` and `coins_to_transfer_to_ensure_min_stake` actually operate. Both functions take a `shareholder` parameter that is always the *caller's own* `delegator_address` — never another delegator's address [1](#0-0) . In `unlock` and `reactivate_stake`, the threshold logic only ever forces the *caller's own* balance either to zero-out entirely (redeem-all) or to be topped up to `MIN_COINS_ON_SHARES_POOL`, using the caller's own address as `shareholder` in both the source and destination pools [2](#0-1) . There is no code path where an unprivileged delegator's `unlock`/`reactivate_stake` calls redirect rounding dust into another delegator's shares balance or into `NULL_SHAREHOLDER`'s balance.

`NULL_SHAREHOLDER` shares are bought only during `add_stake` to temporarily hold add-stake fees, and are unrelated to the `unlock`/`reactivate_stake` rounding path [3](#0-2) .

The actual rounding behavior is that `pool_u64::redeem_shares` reduces `total_coins` and `total_shares` by the exact redeemed amount for the acting shareholder only [4](#0-3) ; any "lost" coin from integer division simply stays in the pool's `total_coins` without a corresponding share reduction, marginally raising the share price for *all* remaining shareholders pro-rata — it is not steered to a specific attacker-chosen delegator or to `NULL_SHAREHOLDER`. This exact behavior ("1 coins lost at redeem due to shares being burned") is documented and tested as expected precision loss, not an exploitable redirection [5](#0-4) .

Additionally, the file cited in the question's scope, `types/src/account_config/events/token_withdraw_event.rs`, is unrelated to delegation pool stake accounting — it only appears in `types/src/account_config/events/mod.rs` and has no connection to `delegation_pool.move`'s unlock/reactivate logic [6](#0-5) , further indicating the premised finding doesn't map to real code behavior.

Since the rounding logic is strictly self-referential (per-shareholder), there is no mechanism for an unprivileged delegator to accumulate dust into another party's `active`/`pending_active`/`pending_inactive`/`inactive` balance through repeated `unlock`/`reactivate_stake` cycles. The invariant that sum of balances tracks total pool stake (within rounding-per-operation, not cumulative-drift-toward-a-target) holds because dust always stays inside the same pool's `total_coins`, diffusing across all current holders rather than concentrating on one.

    fun coins_to_redeem_to_ensure_min_stake(
        src_shares_pool: &pool_u64::Pool,
        shareholder: address,
        amount: u64,
    ): u64 {
        // find how many coins would be redeemed if supplying `amount`
        let redeemed_coins = src_shares_pool.shares_to_amount(amount_to_shares_to_redeem(src_shares_pool, shareholder, amount));
        // if balance drops under threshold then redeem it entirely
        let src_balance = src_shares_pool.balance(shareholder);
        if (src_balance - redeemed_coins < MIN_COINS_ON_SHARES_POOL) {
            amount = src_balance;
        };
        amount
    }

    fun coins_to_transfer_to_ensure_min_stake(
        src_shares_pool: &pool_u64::Pool,
        dst_shares_pool: &pool_u64::Pool,
        shareholder: address,
        amount: u64,
    ): u64 {
        // find how many coins would be redeemed from source if supplying `amount`
        let redeemed_coins = src_shares_pool.shares_to_amount(amount_to_shares_to_redeem(src_shares_pool, shareholder, amount));
        // if balance on destination would be less than threshold then redeem difference to threshold
        let dst_balance = dst_shares_pool.balance(shareholder);
        if (dst_balance + redeemed_coins < MIN_COINS_ON_SHARES_POOL) {
            // `redeemed_coins` >= `amount` - 1 as redeem can lose at most 1 coin
            amount = MIN_COINS_ON_SHARES_POOL - dst_balance + 1;
        };
        // check if new `amount` drops balance on source under threshold and adjust
        coins_to_redeem_to_ensure_min_stake(src_shares_pool, shareholder, amount)
    }

    public fun redeem_shares(self: &mut Pool, shareholder: address, shares_to_redeem: u64): u64 {
        assert!(self.contains(shareholder), error::invalid_argument(ESHAREHOLDER_NOT_FOUND));
        assert!(self.shares(shareholder) >= shares_to_redeem, error::invalid_argument(EINSUFFICIENT_SHARES));

        if (shares_to_redeem == 0) return 0;

        let redeemed_coins = self.shares_to_amount(shares_to_redeem);
        self.total_coins -= redeemed_coins;
        self.total_shares -= shares_to_redeem;
