### Title
Post-default withdraw requests pay 1:1 from the default recovery reserve, draining funds owed to defaulted receipt holders - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.requestWithdraw` allows users to open withdraw requests after `defaultRecoveryFinalized` is set. These "post-default" requests mint receipt tokens and record `postDefaultRequests[_user]`, and `_claimPostDefaultWithdrawRequest` pays them 1:1 by calling `_transferDefaultRecovery`, which decrements `defaultRecoveryReserve`. However, that reserve was sized at finalization only for pre-default active LPs and pending receipts — no reserve is added for post-default requests. Each post-default claim therefore spends other claimants' haircut recovery funds, causing an underflow/DoS for later claimants. [1](#0-0) 

### Finding Description
When a borrower defaults, `finalizeDefaultRecovery` computes `reserveAmount = _recoveredAmount + prefundedReserve + defaultRecoveryReserve` and stores it as `defaultRecoveryReserve`, sized to cover `totalBasis` (active LP basis + `defaultPendingClaimBasis`) at `defaultRecoveryPrice`. [2](#0-1) 

After finalization, `requestWithdraw` takes an early branch: it burns CDO strategy tokens, mints receipt tokens to the user, and sets `postDefaultRequests[_user] = _amount` — without adding any underlying to the reserve or increasing any claim basis. [3](#0-2) 

`claimWithdrawRequest` then routes post-default receipts to `_claimPostDefaultWithdrawRequest`, which pays `amount` in full via `_transferDefaultRecovery`, directly decrementing `defaultRecoveryReserve`. [4](#0-3) [5](#0-4) [6](#0-5) 

The comment claims requests are "already-haircut" because the CDO passes a post-loss `virtualPrice`-based amount — but a haircut on the *request amount* does not fund the payout. The reserve has exactly `reserveAmount` tokens backing `totalBasis` of claims; every post-default claim is pure dilution. The attacker (any EOA who deposits/receives tranche tokens post-default, which `finalizeDefault` explicitly re-enables via `allowAAWithdrawRequest`/`allowBBWithdrawRequest`) can extract up to `defaultRecoveryReserve` at 1:1, while victims claiming at `defaultRecoveryPrice < 1` get a proportional haircut. [7](#0-6) 

### Impact Explanation
Direct theft of unclaimed default recovery funds. A post-default claimant receives underlying at par while defaulted receipt holders and instant-withdraw claimants are only entitled to `claimBasis * defaultRecoveryPrice / 1e18`. If an attacker claims early, later victims' `_transferDefaultRecovery` underflows (permanent revert of their claim) or pays less than the finalized price guarantees. Loss equals the attacker's post-default request amount, bounded only by `defaultRecoveryReserve`. This is a resource-leak analog of the CVE: an accounting path consumes a fixed pool (reserve) that it never replenished, leaking value per crafted request.

### Likelihood Explanation
High once a default is finalized. The attacker needs only tranche tokens obtained post-default (deposit or transfer — `IdleCDOTranche` transfers are open) and calls `requestWithdraw` then `claimWithdrawRequest`. No privileged action is required; `defaultRecoveryFinalized` blocks only users with pre-existing requests. The prerequisite is a borrower default with partial recovery — a scenario the code explicitly supports. One caveat: `_claimPostDefaultWithdrawRequest` burns the user's receipt `_burn(_user, amount)` where the minted amount equals the recorded claim, so the path executes cleanly.

### Recommendation
Either fund post-default claims independently (pull the haircut underlying into the reserve at request time, or pay post-default requests from CDO-held underlyings rather than `defaultRecoveryReserve`), or revert post-default claims once `defaultRecoveryFinalized` and route them through a separately-funded bucket. At minimum, apply `defaultRecoveryPrice` to post-default payouts and account for their basis in the reserve.

```text
  function _claimPostDefaultWithdrawRequest(address _user) internal returns (uint256 amount) {
    amount = postDefaultRequests[_user];
    if (amount == 0) return amount;
    postDefaultRequests[_user] = 0;
    // Post-default receipts are paid 1:1 because the haircut was applied when the request was made.
    _burn(_user, amount);
    _transferDefaultRecovery(_user, amount);
  }
```

```text
  function _transferDefaultRecovery(address _user, uint256 _amount) internal {
    if (_amount == 0) return;
    // Every defaulted or post-default claim consumes the isolated recovery reserve.
    defaultRecoveryReserve -= _amount;
    underlyingToken.safeTransfer(_user, _amount);
  }
```
