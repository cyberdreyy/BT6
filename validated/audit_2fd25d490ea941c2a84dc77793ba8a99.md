### Title
Repeated dust deposits can truncate and erase accrued management fees - (`contracts/IdleCDOCreditVault.sol`)

### Summary

`IdleCDOCreditVault` checkpoints `latestHarvestBlock` every time `_accrueManagementFee()` runs, even when the elapsed-time fee calculation rounds down to zero. Any wallet allowed to deposit can therefore submit repeated dust deposits and permanently prevent management-fee accrual for each interval.

### Finding Description

Every ordinary deposit calls `_updateAccounting()`, which immediately calls `_accrueManagementFee()` before updating tranche accounting. [1](#0-0) [2](#0-1)  Withdrawal requests expose another unprivileged path because `requestWithdraw()` calls `_updateAccounting()` before creating the request. [3](#0-2) 

The management-fee calculation uses elapsed time divided by `FULL_ALLOC * 365 days`. For a small enough `managedValue * managementFee * elapsed`, integer division returns zero, but `latestHarvestBlock` is still advanced to `block.timestamp`. The discarded remainder is never carried forward.

A KYC-passing lender can exploit this by calling `depositAA(1)` or `depositBB(1)` once per sufficiently short block interval during the open-deposit buffer. The interval is bounded by:

```solidity
elapsed < FULL_ALLOC * 365 days / (managedValue * managementFee)
```

For example, with 6-decimal USDC, `10_000e6` managed assets, and a `managementFee` of `1` basis point, a one-second interval produces zero fee. Repeating a dust deposit every second checkpoints zero fees indefinitely.

### Impact Explanation

Accrued management fees are permanently skipped rather than deferred. This inflates tranche NAV relative to the intended accounting and transfers value that should have gone to the configured fee recipients to tranche holders.

The per-transaction truncation is dust-sized, but it is repeatable for an entire buffer period. The total loss equals the management fee that would have accrued across all checkpointed intervals. On low-fee or low-TVL deployments and chains with cheap, frequent transactions, an attacker can erase substantially all management-fee yield without needing any privileged role.

### Likelihood Explanation

Likelihood depends on deployment parameters and chain conditions. The attack requires:

- a wallet passing `isWalletAllowed`;
- a nonzero management fee;
- an open deposit period;
- a transaction cadence faster than the zero-rounding threshold; and
- low enough transaction costs for repeated calls.

No borrower, owner, manager, guardian, oracle manipulation, or default is required. Existing donation skimming, KYC checks, default checks, and pause controls do not prevent this sequence because repeated deposits are intended behavior.

### Recommendation

Preserve the fee remainder across checkpoints or advance the timestamp only when an integer fee is accrued. A remainder-aware implementation should compute:

```solidity
uint256 numerator =
  managedValue * managementFee * elapsed + managementFeeRemainder;

unclaimedFees += numerator / (FULL_ALLOC * 365 days);
managementFeeRemainder = numerator % (FULL_ALLOC * 365 days);
latestHarvestBlock = block.timestamp;
```

Checkpointing only on a nonzero accrual is simpler, but retaining the remainder is safer because it preserves accurate accounting when `managedValue` or `managementFee` changes between interactions.

### Proof of Concept

Add this test to `test/foundry/IdleCreditVault.t.sol`, which already exposes `idleCDO`, `underlying`, `owner`, `ONE_SCALE`, and the deployment fixture:

```solidity
function testDustDepositsEraseManagementFees() external {
    uint256 managedValue = 10_000 * ONE_SCALE; // USDC-sized fixture
    uint256 rounds = 2 hours;                  // one tx per second

    // 1 basis point annual management fee.
    vm.prank(owner);
    idleCDO.setManagementFee(1);

    // Seed latestHarvestBlock, then create managed TVL in the same timestamp.
    idleCDO.depositAA(1);
    idleCDO.depositAA(managedValue);

    uint256 start = idleCDO.latestHarvestBlock();
    uint256 feesBefore = idleCDO.unclaimedFees();

    // 10_000 USDC at 1 bp accrues less than 1 wei per second:
    // 1e10 * 1 * 1 / (10_000 * 365 days) == 0.
    for (uint256 i = 1; i <= rounds; ++i) {
        vm.warp(start + i);
        idleCDO.depositAA(1);
    }

    uint256 skippedFee =
        managedValue *
        idleCDO.managementFee() *
        rounds /
        (FULL_ALLOC * 365 days);

    // The uninterrupted two-hour fee is nonzero...
    assertGt(skippedFee, 0);

    // ...but every dust deposit checkpointed a zero fee and discarded it.
    assertEq(idleCDO.unclaimedFees(), feesBefore);
    assertEq(idleCDO.latestHarvestBlock(), start + rounds);
}
```
