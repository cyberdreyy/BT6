### No vulnerability found for this question.

Analysis: In `BridgeTypesController.Create` [1](#0-0) , `bridges.NewBridgeType` generates `bta` (with plaintext `IncomingToken`/`OutgoingToken`) and `bt` (with `IncomingTokenHash`/`Salt`) purely as local variables. If `ValidateBridgeType` or `ValidateBridgeTypeNotExist` fails, the function returns immediately via `jsonAPIError`, which only serializes the validation error message (e.g. "MinimumContractPayment must be positive") [2](#0-1)  — it never touches `bta` or `bt`. No audit log call is reachable before `orm.CreateBridgeType` succeeds; the only `Audit(audit.BridgeCreated, ...)` call is after the ORM write succeeds and it logs only `bridgeName`, `bridgeConfirmations`, `bridgeMinimumContractPayment`, `bridgeURL` — never the tokens or salt/hash [3](#0-2) . Since Go is garbage-collected and neither struct is written to any log, database, or response on the failure path, the plaintext tokens/hash/salt are simply discarded in memory with no exploitable disclosure channel. This is speculative without a concrete leak path in the code.

	}
