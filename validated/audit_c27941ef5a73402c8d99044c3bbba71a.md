### Title
Unauthenticated flooding of the shared `savedCallbacks` map denies gateway trigger responses to other users - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` in the Chainlink Gateway's legacy web-api-capabilities handler stores every incoming user trigger message into a single shared, process-wide map (`h.savedCallbacks`) keyed only by the client-supplied `msg.Body.MessageId`, with no per-sender accounting and — per the code's own `// TODO: apply allowlist and rate-limiting here` comment — no authentication/allowlist check at that call site. This mirrors the Zcash `zebrad` mempool bug class: a single bounded shared resource pool (there, 25 download slots; here, `MaxSavedCallbacks`, default 20000 entries) that can be monopolized by one unprivileged sender because there is no per-peer/per-sender cap on how many slots one actor may hold.

### Finding Description
`HandleLegacyUserMessage` [1](#0-0)  is the gateway's entry point for legacy web-API trigger user messages. Before broadcasting the request to DON nodes it performs payload parsing and a staleness check, but explicitly defers authorization: `// TODO: apply allowlist and rate-limiting here` [2](#0-1) . It then unconditionally inserts the entry into the shared map:

```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
``` [3](#0-2) 

There is no check for map size at insertion time and no per-sender key or quota — any number of unique `MessageId` values from a single caller are accepted without limit until the periodic pruning goroutine runs. `savedCallbacks` is a single global map shared by all users of this handler instance [4](#0-3) .

The only backstop is a periodic reaper (`pruneCallbacks`), which runs every `CallbackPruneIntervalSec` (default 30s) [5](#0-4) . It removes expired entries by age (`CallbackMaxAgeSec`, default 120s) and, if the map still exceeds `MaxSavedCallbacks` (default 20000), sorts *all* remaining entries by creation time and evicts down to half of `maxSize`, indiscriminately deleting the oldest entries regardless of which sender created them: [6](#0-5) .

This is architecturally identical to the reported Zcash bug class:
- **No per-peer accounting**: the pool of slots (mempool: 25 concurrent downloads; here: `MaxSavedCallbacks` map entries) is shared across all callers with no per-sender cap.
- **No overload signaling / rejection at the boundary**: entries are admitted first, cleanup happens later; legitimate users whose callbacks get evicted receive no explicit error, they simply never get a trigger response (their `Callback` is deleted and forgotten, silently starving them — comparable to `FullQueue` being silently swallowed as `Response::Nil` in the Zcash report).
- **No misbehavior attribution**: the flooding sender is never identified, rate-limited, or blocked for this behavior, since rate-limiting is explicitly marked as a TODO on this legacy path.

By contrast, the newer v2 `httpTriggerHandler.callbacks` map applies a per-workflow (per-sender-equivalent) rate limiter (`checkRateLimit`) *before* inserting into its map [7](#0-6) , and the generic `RequestCache` used elsewhere keys entries by `{sender, id}` and can at least return "request cache is full" per attempt [8](#0-7) . The legacy `handler.go` path used by `HandleLegacyUserMessage`, however, lacks both protections.

### Impact Explanation
A single unauthenticated (or minimally authenticated) client can repeatedly submit legacy web-API trigger messages with distinct `MessageId` values faster than the 30-second prune interval, filling `savedCallbacks` up to `MaxSavedCallbacks` (20000 by default). Once full or once eviction runs, callbacks belonging to other legitimate users are evicted from the map before their corresponding node response arrives, causing `handleWebAPITriggerMessage` to find `found == false` and silently drop the response [9](#0-8) . This denies other users' legitimate trigger requests from ever completing (they will hang until their own client-side timeout), a denial-of-service on trigger response delivery for a shared gateway/DON instance — directly analogous to the mempool admission denial in the Zcash report, but expressed as gateway callback-slot exhaustion rather than mempool-slot exhaustion.

### Likelihood Explanation
Likelihood is moderate to high wherever this legacy `web-api-capabilities` handler path is still reachable and enabled: the code path has no authentication gate before insertion (marked TODO), so exploitation requires only network access to submit trigger messages with unique IDs, no valid workflow ownership, JWT, or node identity is required to occupy a slot. The main mitigating factors are: (1) this is the "legacy" handler — if the v2 `httpTriggerHandler` (which has per-workflow rate limiting) is the one actually deployed/enabled in current production configurations, exposure may be limited; and (2) exploitation window is bounded by the 30s prune cycle, requiring sustained flooding to keep the map near capacity.

### Recommendation
- Add per-sender (or per-connection) accounting to `savedCallbacks`, capping the number of concurrent in-flight callbacks any single sender/origin may hold, similar to the fix pattern described for the Zcash bug (a fraction of the total pool per peer).
- Implement the allowlist/rate-limiting noted in the `// TODO` comment before message insertion, rejecting excess requests from a single sender rather than silently admitting and later evicting other users' entries.
- When evicting due to capacity, prefer evicting entries from senders that hold a disproportionate share of the pool, and/or surface an explicit overload error back to the evicted caller instead of silent starvation.
- Consider migrating fully off this legacy handler to the v2 `httpTriggerHandler`/`RequestCache` path, which already applies per-workflow rate limiting and keyed-by-sender cache checks.

### Proof of Concept
1. Deploy a Gateway node with the legacy `web-api-capabilities` handler enabled and `MaxSavedCallbacks` at its default (20000).
2. From a single unauthenticated network client, send `HandleLegacyUserMessage`-routed trigger requests (method `MethodWebAPITrigger`) with a fresh random `MessageId` in each request, at a rate exceeding the 30-second `CallbackPruneIntervalSec` reap cycle's ability to age them out (i.e., send well above 20000/30s, or simply sustain traffic long enough for the map to approach `MaxSavedCallbacks`).
3. Concurrently, have a legitimate user submit a normal, valid trigger request.
4. Observe that once `savedCallbacks` reaches capacity, `pruneCallbacks` evicts oldest entries indiscriminately [10](#0-9) , which can include the legitimate user's callback before the corresponding node response is received, causing `handleWebAPITriggerMessage` to silently drop the eventual node response for that legitimate user [9](#0-8) , and the legitimate user experiences a timeout instead of a proper response.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	return nil

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
