### Title
Unauthenticated arbitrary-sender broadcast of `web_api_trigger` requests to all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`(h *handler) HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` validates only method name, payload decodability, and timestamp freshness for legacy `api.Message` requests, then unconditionally registers a `savedCallback` and forwards the request to every node in `h.donConfig.Members`. There is no check that `msg.Body.Sender` belongs to any allowlist of authorized users/keys, as flagged by the code comment `// TODO: apply allowlist and rate-limiting here`.

### Finding Description
The reachable path is: `gateway.ProcessRequest` (`core/services/gateway/gateway.go:218-292`) decodes the incoming JSON-RPC HTTP request, and for legacy requests (identified by `msg.Body.DonId != ""`) calls `msg.Validate()` and then directly invokes `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `msg.Validate()` checks message structure/signature format but does not perform any allowlist authorization against `msg.Body.Sender`.

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON-decodability, `payload.Timestamp != 0`, and message-age staleness [2](#0-1) . Immediately after these checks, and directly at the point marked by the comment `// TODO: apply allowlist and rate-limiting here` (line 384), the method verifies only that `msg.Body.Method == MethodWebAPITrigger`, builds a JSON-RPC request via `common.ValidatedRequestFromMessage(msg)`, stores a `savedCallback` keyed by `msg.Body.MessageId`, and then loops over `h.donConfig.Members`, calling `don.SendToNode(ctx, member.Address, req)` for every member [3](#0-2) . At no point is `msg.Body.Sender` checked against any node/DON-member allowlist, workflow-owner allowlist, or authenticated user session — the only preconditions are a syntactically valid signature (any ECDSA keypair works) and a non-stale timestamp.

### Impact Explanation
An attacker who can only produce an ECDSA-signed `api.Message` (no session, no API token, no DON/node identity) can cause the gateway to broadcast an arbitrary `web_api_trigger` payload to every member of a DON. This matches Chainlink's "unauthorized job run" impact class: the attacker forces the gateway (a trusted intermediary that DON nodes accept messages from) to originate trigger requests toward all DON nodes on behalf of a bogus sender, potentially triggering downstream workflow executions or resource consumption on the DON side, and consuming the gateway's `savedCallbacks` map (bounded by `MaxSavedCallbacks`/pruning, so DoS impact is limited but real).

### Likelihood Explanation
Feasibility is high and repeatable: the attacker needs no credentials beyond generating an ECDSA keypair and signing a message locally (per `api.Message` signing requirements enforced by `msg.Validate()`), and posting it to the gateway's public JSON-RPC HTTP endpoint. There is no rate limiting or allowlist check in this specific code path (the node-side `nodeRateLimiter` in `handleWebAPIOutgoingMessage` is unrelated and not applied here). Any unauthenticated network client can repeat this at will.

### Recommendation
Add a sender allowlist check in `HandleLegacyUserMessage` before saving the callback and broadcasting, validating `msg.Body.Sender` against an authorized set of triggerer identities (e.g., derived from workflow registry/owner allowlist configuration), and add per-sender rate limiting, exactly where the existing `// TODO: apply allowlist and rate-limiting here` comment indicates.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
