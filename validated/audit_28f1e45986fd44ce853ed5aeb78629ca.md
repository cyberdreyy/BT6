### Title
APR=0 withdrawal receipt permanently reverts `stopEpoch` once APR is raised, freezing the whole vault - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.prepareStopEpochWithApr0` hard-reverts whenever `apr0TotalPrincipal != 0` and the current `unscaledApr` is non-zero. An unprivileged lender can open an APR=0 withdraw request (which only requires `unscaledApr == 0` at request time); if the APR is subsequently raised before the epoch stops, every `stopEpoch` / `stopEpochWithDuration` call reverts. Epoch finalization is blocked, `epochNumber` never advances, pending withdraw receipts can never be claimed (`epochNumber <= lastWithdrawRequest` guard), and borrower repayments cannot be booked - a liveness DoS with fund impact, analogous to CVE-2018-2839's "easily exploitable hang/crash" bug class.

### Finding Description
In `requestWithdraw`, when `unscaledApr == 0` and the pool is not closed, the request is routed to `_requestWithdrawApr0`, which increments the global `apr0TotalPrincipal` bucket (`IdleCreditVault.sol:285-286`, `567-577`).

At epoch end, the CDO calls `prepareStopEpochWithApr0`, which contains:

```solidity
// contracts/strategies/idle/IdleCreditVault.sol:499-508
uint256 _principal = apr0TotalPrincipal;
if (_principal == 0) {
  return (_expInterest, _adjPendingWithdrawFees);
}
// APR0 principal is only valid while APR is 0 for that request lifecycle.
if (unscaledApr != 0) {
  revert NotAllowed();
}
```

There is no escape path: `apr0TotalPrincipal` is only cleared at the end of this same function (line 540) or inside `_clearWithdrawClaimForEpoch` during default recovery - both unreachable while `stopEpoch` reverts. Any honest `setAprs` change to a positive APR while an APR=0 receipt is outstanding therefore bricks epoch finalization. With `epochNumber` frozen, `_claimFundedWithdrawRequest` reverts for every pending requester via the `epochNumber <= lastWithdrawRequest[_user]` check (line 326), so all queued withdrawals are locked for the duration.

### Impact Explanation
Temporary freezing of funds at the scale of the entire vault TVL plus all pending withdraw receipts. While frozen, no epoch can stop, no interest can be settled, no normal/instant claim can be paid, and borrower repayment cannot be processed. The lock persists until APR is returned to 0 and a stopEpoch succeeds; an attacker can re-arm it each cycle by keeping a dust APR0 receipt open, and if APR policy genuinely needs to be non-zero, the freeze is effectively indefinite. Loss is quantifiable as all pending withdraw amounts plus TVL-yield denied during the freeze.

### Likelihood Explanation
The attacker only needs to be a KYC-passing lender making a normal `requestWithdraw` while APR is 0 - cheap and plausibly deniable. The trigger is an honest manager action (raising APR) which the rules explicitly allow sequencing around. Guard analysis: `NotAllowed` revert at line 506-508 has no bypass; the `_amount == 0` early return in `requestWithdraw` doesn't help; `defaultRecoveryFinalized` paths don't apply; only restoring APR to 0 unblocks it, so impact is temporary-freeze class, not permanent theft.

### Recommendation
Instead of reverting, settle the APR0 bucket at the last valid terms: either (a) treat outstanding APR0 receipts as settled with zero rate (`apr0RateByEpoch[epoch] = 0`, move `apr0TotalPrincipal` principal into the normal pending bucket), or (b) have `setAprs` revert when `apr0TotalPrincipal != 0` so APR cannot change mid-lifecycle of an APR0 request. Option (b) is a one-line check in `setAprs` and keeps `prepareStopEpochWithApr0`'s invariant meaningful.

### Proof of Concept
Foundry fork PoC sketch (mainnet fork, existing `IdleCreditVault.t.sol` harness):

```solidity
function testApr0ReceiptBlocksStopEpochAfterAprRaise() external {
    IdleCreditVault _strategy = IdleCreditVault(address(strategy));
    vm.prank(manager);
    _strategy.setAprs(0, 0);                    // APR = 0 regime

    uint256 mintedAA = idleCDO.depositAA(10000 * ONE_SCALE);
    _startEpochAndCheckPrices(0);
    _stopEpochAndCheckPrices(0, 0, _expectedFundsEndEpoch());

    // attacker: request withdraw while APR == 0 -> apr0TotalPrincipal > 0
    cdoEpoch.requestWithdraw(mintedAA / 4, address(AAtranche));
    assertGt(_strategy.apr0TotalPrincipal(), 0);

    _startEpochAndCheckPrices(1);
    // honest manager raises APR mid-lifecycle
    vm.prank(manager);
    _strategy.setAprs(500, 0);                  // unscaledApr != 0

    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    cdoEpoch.stopEpoch(initialProvidedApr, 0);  // prepareStopEpochWithApr0 reverts
    // epochNumber never advances -> all pending claims revert (epochNumber <= lastWithdrawRequest)
}
```
