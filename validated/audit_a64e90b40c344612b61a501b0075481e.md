### Title
`ExtractZipArchive` has no path-containment check, allowing zip-slip / absolute-path extraction outside the target directory - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` iterates `archive.File` entries and only runs `errorIfGitDirectory` before calling `extractZipFile`, which writes/symlinks/mkdirs directly using the raw, attacker-controlled `file.Name` from the zip header. There is no check that `file.Name` is relative, cleaned, or confined to the intended extraction root, so a crafted zip (used as a GitLab Runner cache/artifact archive) with an absolute path or `../` traversal sequences can write files outside the job's working directory.

### Finding Description
`ExtractZipArchive` (helpers/archives/zip_extract.go:85-110) only calls `errorIfGitDirectory(file.Name)` [1](#0-0) , which just checks whether the cleaned path's first component is `.git` [2](#0-1) . It does not reject absolute paths, `..` traversal, or paths that resolve outside the extraction root.

`extractZipFile` then uses `file.Name` unmodified: `os.MkdirAll(filepath.Dir(file.Name), ...)`, `os.OpenFile(file.Name, ...)`, `os.Symlink(string(data), file.Name)`, `os.Mkdir(file.Name, ...)` [3](#0-2) [4](#0-3) . `os.OpenFile`/`os.Mkdir`/`os.Symlink` accept absolute paths and `..`-containing relative paths as-is; Go's standard `archive/zip` package does not sanitize `zip.File.Name` on read. Consequently a zip entry named `/etc/passwd` or `../../other-project/build/secret` (or an absolute Windows/Unix path pointing at a sibling job's build directory) is extracted verbatim.

This function is reachable via `ExtractZipFile` and via `ziplegacy.extractor.Extract` (commands/helpers/archive/ziplegacy/zip_legacy_extractor.go:26-32) [5](#0-4) , which is used by the cache/artifact extraction path (`cache_extractor.go`, `artifacts_downloader.go`). Cache archives are downloaded from a URL that, while normally coming from GitLab, is fully attacker-influenced in content: a pipeline author controls what gets zipped into `cache.zip` (e.g., by adding a crafted file to the cache paths, or by controlling a custom cache/artifact backend response in self-managed/object-storage misconfig scenarios). The only defenses present (`errorIfGitDirectory`, the error-tracker for suppressing repeated log warnings) do not perform any containment check, so they do not stop this.

### Impact Explanation
An unprivileged pipeline author who can influence the contents of a cache or artifact zip can cause the Runner to write or symlink files to arbitrary absolute paths on the host/executor filesystem (subject to OS file permissions of the Runner process), including potentially overwriting files in another concurrently-running job's build directory when relative traversal (`../`) is used, breaking the "file operations must stay within intended build/cache/artifact roots" invariant.

### Likelihood Explanation
Feasible and repeatable: any job that can shape the archive fed into `ExtractZipArchive` (custom cache creation, crafted artifacts re-used as cache, or a compromised/custom artifact/cache storage backend) can embed a `zip.File` entry with an absolute or `..`-containing `Name`. No special runner configuration is needed beyond normal zip-based cache/artifact extraction (ziplegacy path), which is a standard code path.

### Recommendation
Before calling `extractZipFile`, validate each `file.Name`: reject or reject-and-clean entries that are absolute paths (`filepath.IsAbs`) or whose `filepath.Clean(filepath.Join(destDir, name))` does not have `destDir` as a prefix (the classic zip-slip guard), returning an error/skip similar to the `.git` check, and apply this consistently to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, and `extractZipFileEntry`.

### Proof of Concept
Go test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipArchive_RejectsAbsolutePath(t *testing.T) {
    buf := new(bytes.Buffer)
    zw := zip.NewWriter(buf)
    w, _ := zw.Create("/etc/passwd_pwned")   // absolute path entry
    w.Write([]byte("pwned"))
    zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    dir := t.TempDir()
    os.Chdir(dir)

    err := ExtractZipArchive(zr)
    require.NoError(t, err) // current behavior: no error surfaced

    _, statErr := os.Stat("/etc/passwd_pwned")
    assert.True(t, os.IsNotExist(statErr), "absolute-path entry should NOT be written outside extraction dir, but was")
}
```
Expected (fixed) behavior: the entry is rejected/skipped and `/etc/passwd_pwned` is never created; a companion test with `../escape.txt` should assert the file does not appear outside `dir`.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
