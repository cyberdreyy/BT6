### Title
Cross-user response hijacking via unauthenticated `MessageId` collision in the WebAPI trigger handler's `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`JsonRPCCodec.DecodeLegacyResponse` is a pure (de)serialization function that copies `response.ID` into `Body.MessageId` with no sender/session check — that is by design, since binding is supposed to happen at the handler layer [1](#0-0) . However, tracing to the actual enforcement point shows that `capabilities/handler.go`'s `savedCallbacks` map is keyed **solely by the attacker-controlled `MessageId`**, with no sender/requester binding and no duplicate-ID rejection, unlike the sibling `RequestCache` implementation which correctly keys on `{sender, id}` [2](#0-1) . This allows an unprivileged external caller to overwrite another in-flight caller's pending callback by reusing the same `MessageId`, causing the legitimate response to be delivered to the attacker instead.

### Finding Description
The gateway HTTP endpoint accepts a legacy user message whose `MessageId` comes directly from the attacker-supplied JSON-RPC request `id` field [3](#0-2) . `Message.Validate()` only checks length/format of `MessageId`, not uniqueness or any binding to session/caller identity [4](#0-3) .

In `capabilities/handler.go`, `HandleLegacyUserMessage` stores the caller's callback keyed purely by `msg.Body.MessageId`, with **no check for an existing entry** before overwriting it:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
``` [5](#0-4) 

When the DON node later replies, `handleWebAPITriggerMessage` looks the callback up **only by `MessageId`** and delivers the response to whichever callback currently occupies that slot, deleting the entry afterward:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
h.mu.Unlock()
``` [6](#0-5) 

`HandleNodeMessage` only validates that the node signature matches `nodeAddr` (the DON node, not the requesting user) [7](#0-6) ; it does not check that the `MessageId` still belongs to the same session/sender that originally issued it. This is the exact collision scenario the audit question describes: whichever caller currently owns the map slot for ID `X` receives the response for `X`, regardless of who issued the original request.

Exploit flow:
1. Legitimate user A sends a legacy `web_api_trigger` request with `MessageId = "X"`. `HandleLegacyUserMessage` stores A's callback at `savedCallbacks["X"]` and forwards the signed request to DON members.
2. Before the DON responds, attacker B (any unauthenticated/unprivileged API caller who can reach the gateway HTTP endpoint) sends their own legacy request also using `MessageId = "X"` (attacker fully controls this field and needs no privilege beyond standard API access). `HandleLegacyUserMessage` overwrites `savedCallbacks["X"]` with B's callback — A's callback reference is lost with no error.
3. When a DON node responds to the original request with `resp.ID = "X"` (echoing the ID it was sent), `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]` and delivers A's response data to B's HTTP connection.
4. A's original HTTP request hangs until the gateway's `callback.Wait(ctx)` timeout, receiving a spurious timeout error instead of the real response.

This is not caught by `msg.Validate()` (only checks signature format/length, not ID collision) and not caught by `DecodeLegacyResponse` (a stateless codec with no session context).

### Impact Explanation
This constitutes cross-user response confusion / unauthorized disclosure of another user's response data: an unprivileged attacker can steal payload data intended for another caller's WebAPI trigger response (e.g., workflow execution results routed through the gateway) simply by racing a colliding `MessageId`, and simultaneously deny service to the legitimate caller. This matches the "cross-user response confusion" / request impersonation impact class called out in scope.

### Likelihood Explanation
- Preconditions: attacker needs only standard access to the gateway's public HTTP JSON-RPC endpoint (no operator/admin/DON credentials) and the ability to sign a validly-formatted legacy message with any private key (self-generated), since `Validate()` only checks the signature is well-formed and recovers a signer, not that the signer is authorized for a specific `MessageId`.
- The attacker must guess/know the victim's `MessageId` and race it within the request's outstanding window (default callback max age ~120s, `defaultCallbackMaxAgeSec`), which is feasible if IDs are predictable, sequential, or reused by client tooling, or if the attacker controls/observes the client generating IDs.
- No rate limiting or duplicate-ID check exists to block the overwrite, unlike `handlers/common/requestcache.go`'s `{sender, id}` keyed cache which explicitly rejects duplicates [8](#0-7) .
- Repeatable: the race can be attempted repeatedly and cheaply since the attacker only pays for their own signed message.

### Recommendation
Key `savedCallbacks` (and the equivalent map in `handlers/handler.dummy.go`) by a composite of `{Sender, MessageId}` (or another caller-bound identifier) instead of `MessageId` alone, mirroring `handlers/common/requestcache.go`. Additionally, reject `HandleLegacyUserMessage` calls that attempt to reuse an ID/sender pair already present in the map instead of silently overwriting it, and verify that response delivery for a `MessageId` corresponds to the same requester context that created the entry.

### Proof of Concept
Go handler-layer integration test plan (in `core/services/gateway/handlers/capabilities/handler_test.go` style):
1. Construct `handler` via `NewHandler` with a fake `DON` that records sent requests.
2. Sign message A: `MessageId="dup-id"`, `Method=web_api_trigger`, with private key A; call `handler.HandleLegacyUserMessage(ctx, msgA, callbackA)`. Assert `savedCallbacks["dup-id"]` now references `callbackA`.
3. Before any node responds, sign message B: `MessageId="dup-id"` (same ID), with a different private key B; call `handler.HandleLegacyUserMessage(ctx, msgB, callbackB)`. Assert `savedCallbacks["dup-id"]` has been overwritten to `callbackB` and no error was returned to reject the collision.
4. Simulate a DON node response for `MessageId="dup-id"` (as would result from message A's forwarded request) via `handler.HandleNodeMessage(ctx, resp, nodeAddr)`.
5. Assert that `callbackB.Wait(ctx)` receives the response (data intended for caller A), while `callbackA.Wait(ctx)` times out / never receives a response — proving cross-user response hijacking and confirming the map has no sender-binding to prevent it.

func (*JsonRPCCodec) DecodeLegacyResponse(msgBytes []byte) (*Message, error) {
	var response jsonrpc2.Response[Message]
	err := json.Unmarshal(msgBytes, &response)
	if err != nil {
		return nil, err
	}
	if response.Error != nil {
		return nil, fmt.Errorf("received non-empty error field: %w", response.Error)
	}
	if response.Result == nil {
		return nil, errors.New("received empty result field")
	}

	response.Result.Body.MessageId = response.ID
	return response.Result, nil
}

type pendingRequest[T any] struct {

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalId]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
