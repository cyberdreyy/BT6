### Title
Unsanitized cache key under `FF_HASH_CACHE_KEYS` enables path traversal in `tryRenameAlternateFile` cache paths - (File: `commands/helpers/cache_archiver.go`)

### Summary
When the `FF_HASH_CACHE_KEYS` feature flag is enabled, the human-readable cache key used to build the `--alternate-file` (and, before hashing, the primary) local cache path is taken directly from the attacker-controlled `.gitlab-ci.yml` `cache:key` field without going through `cachekey.Sanitize`, so it is not confined to a virtual root. `tryRenameAlternateFile` then blindly creates directories and renames files at whatever path results from joining this untrusted key into the cache directory, with no check that the final path stays inside the intended cache root.

### Finding Description
`shells/abstract.go`'s `newCacheConfig` computes `rawKey` directly from `build.GetAllVariables().ExpandValue(userKey)` when a user-supplied cache key is present: [1](#0-0) 

Normally `sanitizer = cachekey.Sanitize`, which resolves `..`/`.` against a virtual root and cannot escape it. However, when `FF_HASH_CACHE_KEYS` is on, sanitization is explicitly bypassed:
```go
if build.IsFeatureFlagOn(featureflags.HashCacheKeys) {
    hasher = func(s string) string { return fmt.Sprintf("%x", sha256.Sum256([]byte(s))) }
    sanitizer = func(s string) (string, error) { return s, nil }
}
``` [2](#0-1) 

`humanKey` therefore becomes the raw, unsanitized, attacker-controlled key. The **primary** `ArchiveFile` uses `hashedKey = sha256(humanKey)` (safe — a hex digest), but the **alternate** path uses `cacheAlternateKey(humanKey, true)`, which — when hashing is enabled — returns `humanKey` verbatim (not hashed): [3](#0-2) 

This unsanitized `humanKey` is fed into `getArchivePath`, which joins it into the cache directory and only afterwards calls `filepath.Rel(build.BuildDir, file)`: [4](#0-3) 

Because `path.Join` cleans `..` segments, a cache key such as `"../../../../builds/some/other/artifact-path"` collapses the traversal and can resolve `AlternateArchiveFile` to a path outside `build.CacheDir`, including into `build.BuildDir` or sibling directories used for artifact staging/build state.

This resolved `AlternateArchiveFile` is passed straight to the `cache-archiver` helper as `--alternate-file`: [5](#0-4) 

`tryRenameAlternateFile` then performs the unsafe operation with no root-containment check: it `Stat`s `c.File`, `Stat`s `c.AlternateFile`, calls `os.MkdirAll(filepath.Dir(c.File), 0o700)` and finally `os.Rename(c.AlternateFile, c.File)`: [6](#0-5) 

None of the existing checks (`os.Stat` existence checks, `MkdirAll`) validate that `c.File`/`c.AlternateFile` remain within the cache root — they only check existence and create parent directories, which will happily create directories along an attacker-chosen traversal path and rename/move a file there.

### Impact Explanation
An unprivileged pipeline author who controls the `cache:key` (directly, or via CI/CD variables interpolated into the key) can, when the runner has `FF_HASH_CACHE_KEYS` enabled, cause the local "alternate" cache file to be placed or moved (via `os.Rename`) outside the intended per-job cache directory — potentially colliding with the build directory, artifact staging paths, or other build-state files that the runner or subsequent job stages read from. This can corrupt or overwrite runner-managed state that a different trust boundary (artifact/build-state handling) relies on, matching the "cross-job tampering or output corruption" impact class.

### Likelihood Explanation
- Precondition: `FF_HASH_CACHE_KEYS` must be enabled (opt-in, off by default) — this is a runner-operator configuration choice, not itself an attacker action.
- Given that precondition, the exploit requires only a normal, unprivileged pipeline author supplying a crafted `cache:key` value in `.gitlab-ci.yml` (or via a CI variable that feeds into the key) — fully within the described threat model of an "unprivileged GitLab user or pipeline author."
- No authentication, race conditions, or timing tricks needed beyond the deterministic path construction; reproducible on every job run with the crafted key.
- Because sanitization is fully skipped under the flag (not just weakened), the traversal is fully attacker-controlled and deterministic.

### Recommendation
- In `cacheAlternateKey` / `newCacheConfig`, never use the raw, unsanitized `humanKey` as a filesystem path component even when `FF_HASH_CACHE_KEYS` is on — always hash (or otherwise canonicalize/confine to a virtual root) whichever key variant is used to build a local file path, independent of which key is used for the human-readable metadata.
- Additionally, harden `tryRenameAlternateFile` (and `createZipFile`) in `commands/helpers/cache_archiver.go` with an explicit containment check: resolve `c.File`/`c.AlternateFile` to absolute paths and verify they are lexically within the expected cache root before calling `os.MkdirAll` or `os.Rename`, refusing the operation otherwise.

### Proof of Concept
Go unit test plan for `shells/abstract_test.go` / `commands/helpers/cache_archiver_test.go`:
1. Build a `common.Build` with `FeatureFlags: {featureflags.HashCacheKeys: true}`, `CacheDir: "/builds/group/project/cache"`, `BuildDir: "/builds/group/project"`, and `Job.Cache[0].Key = "../../../../builds/group/project/artifacts/output"`.
2. Call `newCacheConfig(build, key)` and assert that `cacheConfig.AlternateArchiveFile` resolves (after `filepath.Rel`) to a path pointing into `/builds/group/project/artifacts/...` rather than staying under `CacheDir`.
3. In `commands/helpers/cache_archiver_test.go`, construct a `CacheArchiverCommand` with `File` pointing at a non-existent path inside a temp "cache root" and `AlternateFile` set to the traversal-resolved path from step 2 (created with dummy contents outside the cache root). Call `tryRenameAlternateFile()` and assert that the file ends up renamed to a location outside the intended cache root, demonstrating collision with an "artifact" path placed in the test fixture.

func (c *CacheArchiverCommand) tryRenameAlternateFile() {
	if c.AlternateFile == "" || c.AlternateFile == c.File {
		return
	}

	_, err := os.Stat(c.File)
	if err == nil {
		logrus.Debugln("Primary cache file already exists locally, skipping rename from alternate")
		return
	}
	if !errors.Is(err, fs.ErrNotExist) {
		logrus.WithError(err).Warningln("Failed to stat primary cache file")
		return
	}

	if _, err := os.Stat(c.AlternateFile); err != nil {
		logrus.Debugln("Alternate cache file not found locally, nothing to rename")
		return
	}

	if err := os.MkdirAll(filepath.Dir(c.File), 0o700); err != nil {
		logrus.WithError(err).Warningln("Failed to create directory for cache file rename")
		return
	}

	if err := os.Rename(c.AlternateFile, c.File); err != nil {
		logrus.WithError(err).Warningln("Failed to rename alternate cache file to primary")
		return
	}

	logrus.Infoln("Renamed alternate cache file to primary")
}
