### Title
Missing role-based authorization on `GET /v2/external_initiators` discloses plaintext `OutgoingToken` to low-privilege users - ([File: core/web/router.go, core/web/external_initiators_controller.go])

### Summary
`ExternalInitiatorsController.Index` is registered at `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` with only the generic authentication middleware and no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, unlike `Create`/`Destroy` which are gated with `auth.RequiresEditRole`. The presenter returned by `Index`, `presenters.ExternalInitiatorResource`, includes the plaintext `OutgoingToken` field with no redaction. As a result, any authenticated caller regardless of role (view or run role session/API token) can enumerate all `ExternalInitiator` records and read their `OutgoingToken` secret.

### Finding Description
The route table in `core/web/router.go` shows:
```go
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))
``` [1](#0-0) 
Only `Create` and `Destroy` are wrapped in `auth.RequiresEditRole`; `Index` is reachable by any account that passes `auth.Authenticate` (session or API token), including accounts with `view` or `run` role.

`ExternalInitiatorsController.Index` builds its response purely from the ORM without any additional role check:
```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	...
	resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	...
}
``` [2](#0-1) 

`presenters.ExternalInitiatorResource` and its constructor copy `OutgoingToken` verbatim into the JSON response, unredacted:
```go
type ExternalInitiatorResource struct {
	...
	OutgoingToken string         `json:"outgoingToken"`
	...
}
func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		...
		OutgoingToken: ei.OutgoingToken,
		...
	}
}
``` [3](#0-2) 

This is confirmed by the existing integration test, which explicitly asserts the raw `OutgoingToken` value round-trips through the Index API response unredacted:
```go
assert.Equal(t, eiBar.OutgoingToken, externalInitiators[0].OutgoingToken)
...
assert.Equal(t, eiFoo.OutgoingToken, externalInitiators[0].OutgoingToken)
``` [4](#0-3) 

Note: `OutgoingSecret` (the pair used alongside `OutgoingToken`) is not part of `ExternalInitiatorResource`—it is only ever returned once, at creation time, in `presenters.ExternalInitiatorAuthentication`. So only `OutgoingToken` is exposed by `Index`, not `OutgoingSecret`.

Regarding the "EI credential holder" angle: `/v2/external_initiators` sits behind `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`, i.e., it requires a normal user session or API token, not external-initiator (`X-Chainlink-EA-*`) credentials, so EI credential holders cannot reach this endpoint through their EI auth alone. The concrete, provable gap is the missing role check for authenticated view/run-role users.

### Impact Explanation
A user with only `view` or `run` role (which should not be able to manage bridges/external initiators, a capability reserved for `edit`/`admin` per the `RequiresEditRole` gating on `Create`/`Destroy`) can list all configured external initiators and obtain each one's `OutgoingToken`. This token is a credential the node presents to the external initiator's own service; disclosing it to unauthorized internal roles breaks the intended secret confinement (only edit/admin should manage/see these credentials) and could let a lower-privileged, semi-trusted API-token holder impersonate the node's outbound identity toward the configured EI endpoint. This matches a secret/credential disclosure and role/authorization-bypass impact class.

### Likelihood Explanation
Trivial and fully repeatable: it only requires an existing authenticated API token or session with the lowest privilege role (`run` or `view`); no admin/edit privilege, no misconfiguration, and no additional condition is needed. Any environment that has created API tokens with restricted roles (common practice) and has at least one `ExternalInitiator` configured is affected.

### Recommendation
Wrap `Index` with the same authorization level as `Create`/`Destroy` (`auth.RequiresEditRole`, or at minimum `RequiresAdminRole`), i.e.:
```go
authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))
```
Additionally, remove `OutgoingToken` from `presenters.ExternalInitiatorResource` (or mask/redact it) so it is never echoed back after creation, consistent with how secrets are typically shown only once at creation time.

### Proof of Concept
Handler-level integration test plan (extends `TestExternalInitiatorsController_Index` in `core/web/external_initiators_controller_test.go`):
1. Create an app with `ExternalInitiatorsEnabled = true`.
2. Insert an `ExternalInitiator` via `cltest.MustInsertExternalInitiatorWithOpts` with a known `OutgoingToken`.
3. Create an API token/session scoped to `run` role (or `view` role) only — e.g. using existing test helpers that mint a run-role authenticated client.
4. Call `GET /v2/external_initiators` with that run-role client.
5. Assert:
   - Expected (secure): response is `403 Forbidden` (once `RequiresEditRole`/`RequiresAdminRole` is added).
   - Current (vulnerable): response is `200 OK` and `presenters.ExternalInitiatorResource.OutgoingToken` in the response body equals the plaintext token inserted in step 2 — demonstrating a `run`-role token can read the secret.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
