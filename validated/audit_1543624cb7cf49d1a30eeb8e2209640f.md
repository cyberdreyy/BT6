## Analysis Result

### Title
Front-runnable `kamino_harvest_reward()` computes only the balance delta, permanently locking pre-existing/front-run Kamino Farms rewards in the bank's reward ATA - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
`kamino_harvest_reward()` reproduces the exact H‑1 bug pattern: it snapshots the reward ATA balance before and after an external CPI call, and sweeps out only the *difference* rather than the full balance. Because the underlying Kamino Farms `harvest_reward` instruction can be made callable for the bank's `user_state`/`liquidity_vault_authority` without the vault authority's own transaction when a farm enables permissionless harvesting (see the dedicated error `HarvestingNotPermissionlessPayerMismatch`), any pending reward can be routed into `user_reward_ata` by a third party before marginfi's own instruction executes, or split across multiple prior harvests, leaving marginfi's calculated `received` at 0 while real tokens remain sitting in the PDA-owned ATA with no other instruction able to sweep them out.

### Finding Description
```rust
pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}
``` [1](#0-0) 

`cpi_transfer_obligation_owner_to_destination` transfers exactly the passed-in `amount` (the delta), not the full ATA balance: [2](#0-1) 

`user_reward_ata` is an ATA owned by the bank's `liquidity_vault_authority` PDA — the only signer capable of authorizing an outbound transfer from it is this same instruction, via `bank_signer!`: [3](#0-2) 

Kamino Farms' own program explicitly defines a permissionless-harvest mode, with the payer/owner match only enforced when that mode is off: [4](#0-3) 

If a farm reward is (or becomes) configured for permissionless harvesting, any signer can invoke Kamino Farms' `harvest_reward` directly against the bank's `user_state`, causing the pending reward tokens to land in `user_reward_ata` (owned by the bank's `liquidity_vault_authority`) outside of marginfi's instruction. When marginfi's `kamino_harvest_reward` is subsequently called, `pre_transfer_balance` already includes those tokens, so `post_transfer_balance - pre_transfer_balance` computes to 0 (or understates the true pending amount), and `cpi_transfer_obligation_owner_to_destination(0)` moves nothing out. Because no other marginfi instruction is able to sign for `liquidity_vault_authority` to sweep this ATA, the tokens are permanently stranded — the same "netBalance always 0, reward locked forever" defect described in the H‑1 report for `TreasuryAction.claimCOMPAndTransfer()`.

### Impact Explanation
Reward tokens (Kamino Farms incentives destined for the marginfi global fee wallet, which are later redistributed to depositors per the protocol's stated policy) can be permanently locked in a PDA-owned account with no recovery path in the current instruction set, since only the delta — not the full balance — is ever swept. This is a durable loss of protocol/user-destined funds, matching the funds-locked criteria that caused the original report to be escalated to High.

### Likelihood Explanation
Likelihood depends on Kamino Farms reward configuration: the exploit requires a reward/farm where permissionless harvesting is enabled (a Kamino-side, non-marginfi-controlled setting) so an outside party can trigger `harvest_reward` targeting the bank's `user_state` ahead of marginfi's own call. This is not guaranteed for every farm, but it is a supported, documented Kamino feature, and once enabled for any reward mint the front-run is trivial, cheap (no economic outlay required beyond a transaction), and repeatable every time new rewards accrue.

### Recommendation
Do not rely on a balance-delta computed inside the instruction. Instead, sweep the entire current balance of `user_reward_ata` to `destination_token_account` after the CPI call (mirroring the fix already applied in `drift_claim_bad_debt`'s `cpi_transfer_to_destination`, which transfers `accessor::amount(&self.claimant_token_account...)` in full): [5](#0-4) 

### Proof of Concept
1. Attacker identifies a Kamino Farms reward mint/farm configured with permissionless harvesting for the obligation backing a marginfi Kamino-wrapped bank.
2. Attacker (or anyone) directly invokes Kamino Farms' `harvest_reward` targeting the bank's `user_state`/`liquidity_vault_authority`, causing pending rewards to be transferred into `user_reward_ata` outside of marginfi's control.
3. Anyone later calls marginfi's `kamino_harvest_reward`; `pre_transfer_balance` already reflects the tokens deposited in step 2, so the internal CPI call to Kamino harvests 0 additional tokens (or the farm has already zeroed the claimable amount), making `received = post_transfer_balance - pre_transfer_balance == 0`.
4. `cpi_transfer_obligation_owner_to_destination(0)` transfers nothing to the global fee wallet, while the actual reward tokens remain stuck in `user_reward_ata`, which only this same instruction (and only for the delta amount) is capable of debiting via the `liquidity_vault_authority` PDA signature.

    pub fn cpi_transfer_obligation_owner_to_destination(&self, amount: u64) -> MarginfiResult {
        let program = self.token_program.to_account_info();
        let accounts = TransferChecked {
            from: self.user_reward_ata.to_account_info(),
            to: self.destination_token_account.to_account_info(),
            authority: self.liquidity_vault_authority.to_account_info(),
            mint: self.reward_mint.to_account_info(),

        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =

        let decimals = self.reward_mint.decimals;
        transfer_checked(cpi_ctx, amount, decimals)?;
        Ok(())
    }

    fn cpi_transfer_to_destination(&self) -> MarginfiResult<u64> {
        let amount = accessor::amount(&self.claimant_token_account.to_account_info())?;

        let accounts = Transfer {

            authority: self.liquidity_vault_authority.to_account_info(),

        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(self.token_program.key(), accounts, signer_seeds);

        token::transfer(cpi_ctx, amount)?;
        Ok(amount)
    }
