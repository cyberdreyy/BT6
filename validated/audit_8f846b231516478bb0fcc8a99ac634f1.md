### Title
Gateway-wide MessageId uniqueness is not enforced, allowing callback hijack via savedCallbacks overwrite in capabilities handler - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`gateway.ProcessRequest` only bounds `jsonRequest.ID` to 200 characters and never checks it for uniqueness against in-flight requests. The capabilities WebAPI handler's `HandleLegacyUserMessage` stores each request's response `Callback` in `h.savedCallbacks` keyed solely by `msg.Body.MessageId`, unconditionally overwriting any existing entry, and does not enforce sender authorization ("TODO: apply allowlist and rate-limiting here"). An attacker who can produce a validly self-signed legacy message with a MessageId colliding with a victim's in-flight WebAPITrigger request to the same DON can hijack the victim's node response.

### Finding Description
`gateway.ProcessRequest` decodes the request, validates only ID length, and dispatches to the target handler with a per-request `callback := handlerscommon.NewCallback()`: [1](#0-0) [2](#0-1) 

For legacy DON-routed messages, `msg.Validate()` only checks field lengths and recovers *whatever* key signed the message via `ExtractSigner` — it does not check that the signer is an authorized/allowlisted user: [3](#0-2) 

In `capabilities/handler.go`, `HandleLegacyUserMessage` stores the caller's `Callback` keyed only by `msg.Body.MessageId`, with an explicit TODO noting the missing allowlist/rate-limit check, and no check for an existing/duplicate entry before overwriting: [4](#0-3) [5](#0-4) 

When a DON node later responds to a `MethodWebAPITrigger` message, `HandleNodeMessage` routes to `handleWebAPITriggerMessage`, which looks up `h.savedCallbacks[msg.Body.MessageId]`, deletes it, and delivers the response payload to whatever `Callback` is currently stored — with no verification that the caller who registered that callback is the same party the DON intended to respond to: [6](#0-5) [7](#0-6) 

Exploit flow: victim sends a legitimate `MethodWebAPITrigger` legacy message with `MessageId = X` to DON `D`; this registers `savedCallbacks[X] = victimCallback` and forwards to DON nodes. Before the node responds, an attacker crafts and self-signs (any private key works — no allowlist enforced) another legacy message with the same `MessageId = X` and `DonId = D`, which overwrites `savedCallbacks[X] = attackerCallback`. When the DON node responds to `X`, the gateway delivers the response — which was actually produced for the victim's trigger — to the attacker's HTTP connection, since the map lookup only uses `MessageId` and does not check requester identity.

### Impact Explanation
This is a cross-user response confusion vulnerability: an unauthenticated attacker can receive a webhook/trigger response payload that was intended for a different user's in-flight gateway request, and simultaneously deny the victim their legitimate response (denial of service for the victim). This matches the "unauthorized action on another user's job/subscription/secret" / "attacker-controlled data returned to another user" impact class, scoped to the WebAPI trigger capability path.

### Likelihood Explanation
Exploitability requires: (1) the attacker be able to produce a validly-signed (self-signed, since no allowlist check exists on this path) legacy `MethodWebAPITrigger` message, (2) know or guess the victim's `MessageId` and target `DonId`, and (3) win a race window between the victim's request registration and the DON node's response. Since `MessageId` is entirely user/client-supplied (not a server-generated secret) and there is no gateway-level or handler-level uniqueness check, and the code contains an explicit `// TODO: apply allowlist and rate-limiting here` acknowledging the missing sender check, this is a realistic, low-privilege, repeatable condition — limited mainly by the attacker's ability to learn/predict the victim's MessageId and timing.

### Recommendation
- Enforce MessageId uniqueness at the gateway (`gateway.ProcessRequest`) or at minimum within each handler's `savedCallbacks`/similar maps: reject (rather than silently overwrite) a new request whose ID already has a live, unexpired entry.
- Add sender authorization/allowlisting for user-facing legacy messages in `capabilities/handler.go`'s `HandleLegacyUserMessage` per the existing TODO, so an attacker cannot register arbitrary callbacks for arbitrary DON IDs without being an authorized sender.
- Bind delivered responses to the original requester's identity/session (not merely the MessageId) so an overwritten map entry cannot silently redirect data across callers.

### Proof of Concept
Handler-level integration test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Set up the handler with a mocked `DON`.
2. Simulate victim: call `handler.HandleLegacyUserMessage(ctx, victimMsg, victimCallback)` with `MessageId = "shared-id"`, `DonId = donID`. Assert `handler.savedCallbacks["shared-id"].Callback == victimCallback`.
3. Simulate attacker: before the node responds, call `handler.HandleLegacyUserMessage(ctx, attackerMsg, attackerCallback)` with the same `MessageId = "shared-id"` and same `DonId`, signed with a different/arbitrary key. Assert this call succeeds (no error, no uniqueness check) and `handler.savedCallbacks["shared-id"].Callback == attackerCallback` (victim's entry overwritten).
4. Simulate the DON node responding to `MessageId = "shared-id"` with the victim's intended payload via `handler.HandleNodeMessage(ctx, resp, nodeAddr)`.
5. Assert `attackerCallback.Wait(ctx)` receives the victim's payload, and `victimCallback.Wait(ctx)` times out/never receives a response — demonstrating cross-user response hijack and confirming the invariant "isolation across concurrent requests" is violated.

	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())

		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}
