### Title
Global (non-namespaced) `activeRequests` map allows request-ID squatting causing denial-of-service against another user's confidential-relay request - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.newActiveRequest` keys `activeRequests` solely by the attacker-controlled JSON-RPC `req.ID` with no per-sender/tenant component, so any authenticated gateway caller can pre-claim an ID that another legitimate user is expected to use for the same DON/method and cause that user's real request to be rejected with "request ID already exists". Code analysis shows this **cannot** lead to the attacker receiving the other user's aggregated bundle response, because the colliding second call is rejected *before* a `Callback` is ever registered in `activeRequests`.

### Finding Description
`newActiveRequest` (core/services/gateway/handlers/confidentialrelay/handler.go:368-383) checks `h.activeRequests[req.ID] != nil` under `h.mu` and, if present, returns an error without registering the caller's `Callback` [1](#0-0) . The `activeRequests` map is a single `map[string]*activeRequest` shared across all callers of the handler/DON, keyed only by `req.ID`, with no sender identity, session, or address bound into the key [2](#0-1) . `req.ID` originates directly from the caller-supplied JSON-RPC request routed in via `HandleJSONRPCUserMessage` (core/services/gateway/handlers/confidentialrelay/handler.go:349-366), with only an emptiness and length check (≤200 chars) — no per-user namespacing, signature-derived prefix, or uniqueness salt is added [3](#0-2) .

Because whichever caller's `newActiveRequest` call wins the `h.mu` lock first is the one whose `Callback` gets stored in the `activeRequest` struct, and the loser's call returns immediately with an error and never stores a `Callback`, the eventual response produced by `sendResponseAndClearRequest` (core/services/gateway/handlers/confidentialrelay/handler.go:659-679) is always delivered only to the winner's `Callback` — the attacker's own losing call never gets a `Callback` object hooked into `activeRequests`, so it cannot receive the winner's bundle. The "worse" outcome hypothesized in the question (attacker receiving the legitimate user's bundle) is therefore not reachable through this code path.

What *is* reachable: if an attacker can predict or race a request ID that a target legitimate user will use for the same DON (e.g., a monotonic counter, timestamp-based ID, or an ID leaked/observed elsewhere), the attacker can pre-register that ID first, so the legitimate user's subsequent genuine call to `HandleJSONRPCUserMessage` fails outright with `"request ID already exists"` and never gets forwarded to the DON at all — a per-request denial of service against another authenticated user's request, with no privilege beyond the ability to send gateway JSON-RPC requests.

### Impact Explanation
This is a limited, non-persistent denial-of-service: an attacker who can guess or predict another user's `req.ID` (scoped to the DON/method) can cause a single specific request from that user to be rejected instead of relayed, denying service for that request only. There is no key/secret disclosure, no cross-user response leakage, and no fund movement or unauthorized job execution — it maps to a low-severity availability/interference impact, not the "cross-user response confusion" class hypothesized in the question.

### Likelihood Explanation
Exploitability strictly depends on the attacker being able to predict or observe another authenticated user's `req.ID` before that user's real request arrives — request IDs are typically client-generated (e.g., random UUIDs) which would make this impractical in most deployments; if a caller uses predictable IDs (sequential counters, fixed constants, timestamps), an attacker with any credential able to reach `HandleJSONRPCUserMessage` for the same DON/method could feasibly race the ID. No further privilege is required beyond sending a JSON-RPC request to the gateway.

### Recommendation
Namespace `activeRequests` keys by a combination of the caller's identity (sender/session/auth key) and `req.ID`, rather than `req.ID` alone, so unrelated callers cannot collide on the same key even if they choose identical IDs.

### Proof of Concept
Go unit test in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct two independent `gwhandlers.Callback` mocks, `callbackA` (legitimate user) and `callbackB` (attacker).
2. Call `h.newActiveRequest(reqWithID("dup-id"), callbackA)` — assert it succeeds and returns a non-nil `*activeRequest` referencing `callbackA`.
3. Call `h.newActiveRequest(reqWithID("dup-id"), callbackB)` — assert it returns the error `"request ID already exists: dup-id"` and a nil `*activeRequest`.
4. Drive the first `activeRequest` to completion (e.g., call `h.sendResponseAndClearRequest(ctx, ar, payload)`), and assert `callbackA.SendResponse` was invoked exactly once with the expected payload, and `callbackB.SendResponse` was never invoked — confirming no cross-user response delivery occurs, only a rejection (DoS) of the second caller.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
