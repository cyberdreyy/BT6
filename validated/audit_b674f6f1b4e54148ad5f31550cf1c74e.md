### Title
Legacy web_api_trigger user messages bypass allowlist/rate-limiting and are broadcast to all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` validates only signature well-formedness, staleness, and method name before forwarding the raw user-supplied JSON-RPC request to every member of the DON, skipping the allowlist/rate-limiting check marked by the `TODO: apply allowlist and rate-limiting here` comment. Any sender who can produce a validly-signed `MethodWebAPITrigger` envelope — regardless of whether their address/workflow is registered in any allowlist — gets their payload fanned out to all `donConfig.Members`.

### Finding Description
The request path is: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218-292) decodes the JSON-RPC envelope, and for legacy requests only calls `msg.Validate()` [1](#0-0)  which merely checks field lengths/formatting and recovers the signer address via `ExtractSigner` [2](#0-1)  — it does not check the sender/workflow against any allowlist. It then dispatches straight to `h.HandleLegacyUserMessage(ctx, msg, callback)` [3](#0-2) .

Inside `HandleLegacyUserMessage`, the checks performed are: payload JSON-decodable, `Timestamp != 0`, message not stale, and `msg.Body.Method == MethodWebAPITrigger` [4](#0-3) . Immediately after the method check, the code contains the explicit marker: [5](#0-4) 
No allowlist lookup or sender-authorization/quota check is performed anywhere in this function or in `ValidatedRequestFromMessage` (core/services/gateway/handlers/common/message_util.go:82-105), which only re-marshals the message into a JSON-RPC request without any authorization logic. The function then unconditionally loops over all configured DON members and sends the request to each: [6](#0-5) 

Thus any correctly-signed message (the signer can be any keypair the attacker controls — signature validity does not imply allowlist membership) with `MethodWebAPITrigger` and a non-stale timestamp will be broadcast to every DON node, regardless of whether the sender/workflow is authorized.

### Impact Explanation
This matches the "allowlist/quota bypass" impact class explicitly listed in scope. An unauthorized sender can trigger workflow execution fan-out to all DON nodes for a `web_api_trigger` payload that is not tied to any registered/authorized workflow, causing unauthorized workflow triggers and resource consumption across the DON, and negating the intended design (allowlist-gated dispatch) referenced by the TODO comment.

### Likelihood Explanation
The only precondition is the ability to produce a message with a valid ECDSA signature (over the message body, using an attacker-owned key) and a `MethodWebAPITrigger` method with a fresh timestamp — signature validity is a self-signed check (`ExtractSigner` recovers whichever address signed it; it does not check that address against any allowlist). No privileged credentials, admin access, or knowledge of allowlist contents are required, making this trivially and repeatedly reproducible by any external client able to reach the gateway's legacy user endpoint.

### Recommendation
Implement the allowlist/rate-limiting check called out by the TODO before forwarding to DON members: after signature/staleness/method validation, look up `msg.Body.Sender` (and/or the workflow/receiver referenced in the payload) against the configured DON/service allowlist and reject (return `api.UnauthorizedError`-style response) if not present; also apply a per-sender rate limiter (similar to `h.nodeRateLimiter` but keyed on user sender) prior to the `don.SendToNode` fan-out loop.

### Proof of Concept
Go handler-level test plan (extending `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Construct a `handler` via `NewHandler` with a `donConfig` containing several `Members` and a mock `handlers.DON` (`mocks.DON`) that records calls to `SendToNode`.
2. Build an `api.Message` with `Body.Method = MethodWebAPITrigger`, a valid `webapicap.TriggerRequestPayload` with current `Timestamp`, sign it with an arbitrary/unregistered private key (not present in any allowlist config), and set `Body.Sender` accordingly.
3. Call `h.HandleLegacyUserMessage(ctx, msg, callback)`.
4. Assert: no error is returned, `mockDON.SendToNode` is called once per member in `donConfig.Members` (i.e., `len(donConfig.Members)` invocations) with the forwarded request — demonstrating the message reaches all DON nodes despite the sender not being allowlisted.
5. (Contrast) Note that no test path exists that rejects based on sender identity/allowlist, confirming the absence of the enforcement described by the TODO.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
