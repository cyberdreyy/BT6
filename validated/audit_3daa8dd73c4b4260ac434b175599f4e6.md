### Title
Unauthenticated disclosure of internal LOOP plugin Prometheus metrics via `/plugins/:name/metrics` - ([File: core/web/loop_registry.go])

### Finding Description
`NewRouter` in `core/web/router.go` builds a single route group `api` that only applies rate limiting and session middleware, then calls `loopRoutes(app, api)` alongside `debugRoutes`, `healthRoutes`, `sessionRoutes`, and `v2Routes` [1](#0-0) . Unlike the GraphQL `/query` endpoint, which explicitly wraps its handler with `auth.AuthenticateGQL(...)` [2](#0-1) , `loopRoutes` is registered with no equivalent `auth.Authenticate`/session-role gate visible at the call site. The handler it wires up, `pluginMetricHandler` in `core/web/loop_registry.go`, looks up the plugin by name in the `LoopRegistry`, builds an internal URL `http://<loopHostName>:<PrometheusPort>/metrics`, fetches it, and writes the raw response body straight back to the caller with `gc.Data(http.StatusOK, "text/plain", b)` — with no authentication or authorization check inside the handler itself [3](#0-2) . The comment "this endpoint is internal btw the node and plugin" reflects the intended trust boundary (Prometheus scraping the node), but the route is mounted on the same externally-reachable `api` group as the rest of the authenticated node API, and the handler itself performs no caller-identity check, so any request reaching the node's HTTP port can hit this path.

### Impact Explanation
An unauthenticated caller who can reach the node's HTTP listener can retrieve Prometheus metrics text proxied from any registered LOOP plugin's internal port, exposing internal metric names, labels, and potentially sensitive operational data (job/plugin internals, request rates, error counts) that should only be accessible to a trusted metrics-scraping system. This maps to an information-disclosure impact class rather than direct fund loss or key compromise, but it does violate the intended internal-only trust boundary of plugin metrics.

### Likelihood Explanation
No preconditions are required beyond a plugin being registered in the `LoopRegistry` (which happens for any node running LOOP plugins) and network reachability to the node's exposed HTTP port. The request is a single unauthenticated GET, fully repeatable, with no rate limiting beyond the generic `api` group's `AuthenticatedPeriod`/`Authenticated` rate limiter, which does not require credentials to consume.

### Recommendation
Require authentication (and an appropriate role, e.g., admin/operator) before serving `/plugins/:name/metrics` and the related pprof endpoints, mirroring the pattern used for `/query` (`auth.AuthenticateGQL`) or the standard `auth.Authenticate` middleware used elsewhere in `v2Routes`. Alternatively, bind the LOOP plugin metrics/pprof endpoints to a separate internal-only listener/port that is not exposed on the public API port.

### Proof of Concept
1. In a Go test using `httptest`, construct the router via `NewRouter` (or directly mount `loopRoutes` on a `gin.Engine`) with a `chainlink.Application` stub whose `GetLoopRegistry()` returns a `LoopRegistry` containing one registered plugin (e.g., name `"test-plugin"`, `EnvCfg.PrometheusPort` pointing to a local `httptest.NewServer` that serves fake Prometheus text).
2. Issue `GET /plugins/test-plugin/metrics` with no `Authorization` header, no session cookie, and no API token.
3. Assert the response status is `200 OK` and the body equals the fake metrics text served by the internal stub server, confirming that no `auth.Authenticate`/role check intercepted the request. Compare against a control request to an authenticated route (e.g., `/v2/...`) which should return `401`/`403` without credentials, to demonstrate the asymmetry.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
