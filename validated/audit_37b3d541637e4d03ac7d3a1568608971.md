### Title
Unauthenticated disclosure of internal LOOP plugin Prometheus metrics via `GET /plugins/:name/metrics` - (File: core/web/loop_registry.go)

### Summary
The `loopRoutes` function registers `/discovery`, `/plugins/:name/metrics`, and the pprof-forwarding endpoints directly on the top-level `api` router group with no authentication middleware, unlike every other sensitive route in `router.go`. As a result, any unauthenticated client can call `pluginMetricHandler` for a real registered plugin and receive the plugin's raw internal Prometheus metrics.

### Finding Description
In `core/web/router.go`, `loopRoutes(app, api)` is called at line 91 directly on the base `api` group (which only has rate-limiting and session middleware attached, not an authentication check): [1](#0-0) 

Compare this to every other route group in the file — `debugRoutes` wraps its group with `auth.Authenticate(...)` [2](#0-1) , `v2Routes`'s `authv2` group requires token/session auth [3](#0-2) , and even the internal `metricRoutes` (pprof) is deliberately mounted inside the authenticated `authv2` group with a comment "Debug routes accessible via authentication" [4](#0-3) . In contrast, `loopRoutes` registers: [5](#0-4) 

`pluginMetricHandler` looks up the plugin by name via `l.registry.Get(pluginName)`, then proxies a GET request to the plugin's internal Prometheus endpoint (`http://<loopHostName>:<PrometheusPort>/metrics`) and returns the raw response body to the caller with `StatusOK`, performing no auth/session/token check whatsoever: [6](#0-5) 

Any unauthenticated attacker who knows or guesses a registered plugin name (discoverable via the equally unauthenticated `/discovery` endpoint, which lists all registered plugin names in `LabelMetaPluginName`) can fetch that plugin's raw Prometheus metrics, which may include internal hostnames, operation counts, and other internal resource identifiers.

### Impact Explanation
This is an authentication-bypass information disclosure: an unprivileged, unauthenticated attacker gains access to internal operational telemetry (LOOP plugin Prometheus metrics) that should require at minimum a valid session/token, matching the "authentication soundness" / information disclosure impact class in the Chainlink bounty program. It also reveals the internal `discoveryHandler`/`pluginMetricPath` topology (host:port layout, plugin names) via `/discovery`, aiding further reconnaissance.

### Likelihood Explanation
Trivial and fully repeatable: no credentials, tokens, or special role are required — a bare `GET /plugins/<name>/metrics` (with `<name>` discoverable via the also-unauthenticated `GET /discovery`) is sufficient whenever any LOOP plugin is registered in `plugins.LoopRegistry`, which is standard when the node runs LOOPP plugins (e.g., median, mercury).

### Recommendation
Wrap `loopRoutes`'s router group with the same authentication middleware used elsewhere (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), or move `/plugins/:name/metrics`, `/discovery`, and the pprof endpoints into the authenticated `authv2` group as is already done for `metricRoutes`.

### Proof of Concept
1. In a `core/web` handler-level test (similar to `loop_registry_internal_test.go`), construct a `gin.Engine` via `NewRouter` (or directly call `loopRoutes` on an unauthenticated `gin.RouterGroup`) with a `chainlink.Application` mock whose `GetLoopRegistry()` returns a registry containing a plugin named `mockLoopImpl` pointing at a `httptest.Server` serving canned Prometheus text.
2. Issue `httptest.NewRequest("GET", "/plugins/mockLoopImpl/metrics", nil)` with no `Authorization` header and no session cookie, and serve it through the router.
3. Assert `recorder.Code == http.StatusOK` and that `recorder.Body` contains the mocked metrics content (e.g., a distinctive metric name/value), proving metrics were returned without any auth challenge (expect `StatusUnauthorized` if properly protected).
4. Optionally also request `GET /discovery` unauthenticated and assert it returns the plugin's name/target in JSON, confirming the reconnaissance path to obtain valid plugin names.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
