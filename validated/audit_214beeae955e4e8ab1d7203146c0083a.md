### Title
Stale confirmations from removed multisig members are not purged from other pending requests, allowing execution below the live-member threshold - (File: `multisig2/src/lib.rs`)

### Summary
`MultiSigContract::delete_member` only removes requests and confirmations that were *created* by the member being deleted; it does not scan the `confirmations` map for confirmations that the deleted member cast on *other* members' pending requests. As a result, a removed member's confirmation continues to count toward `num_confirmations` on any request they previously confirmed but did not author, letting a request execute with fewer live (still-authorized) confirmers than the configured threshold.

### Finding Description
`confirm()` counts entries in `self.confirmations.get(&request_id)` and executes the request once `confirmations.len() + 1 >= self.num_confirmations`: [1](#0-0) 

`delete_member()` is the only place that prunes confirmation state when membership changes, but it filters by `r.member == member` — i.e. only requests *authored* by the deleted member — and removes those requests/confirmations entirely. It never inspects `confirmations` entries where the deleted member is merely a *confirmer* on someone else's request: [2](#0-1) 

The invariant the contract is supposed to maintain is:
`confirmations_recorded(request) == confirmations_by_current_live_members(request)`

After a `DeleteMember` action executes, this equality breaks for any request that the removed member had confirmed but did not create: the confirmation entry (their `MultisigMember::to_string()` key in the `HashSet<String>`) remains in `self.confirmations`, even though `self.members` no longer contains them. `confirm()` never re-validates that existing confirmation-set entries are still current members — it only checks that the *new* confirmer (`current_member()`) is valid and has not already confirmed. The stale entry from the removed member is simply counted alongside new confirmations.

### Impact Explanation
This allows a multisig request to be executed with fewer live/authorized confirmations than `num_confirmations` requires — e.g. with `num_confirmations = 3` and members `{A,B,C,D}`: B confirms request R (created by A) while still a member (`confirmations = {B}`). Later, members remove B via a `DeleteMember` request. B's confirmation on R is never purged (since R.member == A, not B). Only C additionally confirms; `confirmations = {B, C}`, count 2, and the confirming member A (as the 3rd distinct confirmer, since len()+1 >= 3) triggers execution — but B, one of the counted "confirmers," is no longer an authorized signer. The multisig executes an arbitrary action (`Transfer`, `FunctionCall`, `AddKey`, etc.) on the basis of confirmations from fewer live members than the configured threshold, i.e. "a multisig request executed below threshold" — explicitly a Critical-impact scenario per the custody-binding categories for this scan (funds transferred, keys added, or contracts deployed with insufficient live authorization).

### Likelihood Explanation
This requires no privileged access beyond being (at some point) a legitimate multisig member who confirms a request and is later removed — a completely ordinary lifecycle event for any multisig (member rotation, key compromise response, etc.). Any request left pending (not yet fully confirmed) at the time a confirming member is removed is silently left in this broken state; no special timing or race condition beyond normal operational sequencing is needed.

### Recommendation
In `delete_member`, iterate over all entries in `self.confirmations` (not just requests authored by the removed member) and strip the deleted member's identifier from every confirmation set; alternatively, have `confirm()` filter/re-validate confirmation sets against `self.members` before counting them (e.g. `confirmations.iter().filter(|c| self.members.contains(...)).count()`), so stale confirmations from removed members never count toward `num_confirmations`.

### Proof of Concept
1. Initialize `MultiSigContract::new([A, B, C, D], 3)`.
2. `A` calls `add_request` to create request `R` (e.g. `Transfer` to some receiver). `R.member == A`.
3. `B` calls `confirm(R)` → `confirmations[R] = {B}` (len 1 < 3, not yet executed).
4. Separately, `A`, `C`, `D` (or however many needed) submit and confirm a `DeleteMember{ member: B }` request, which executes and removes `B` from `self.members`. Per `delete_member` (lines 356-379), only requests where `r.member == B` are purged — `R` (authored by `A`) is untouched, so `confirmations[R]` still equals `{B}`.
5. `C` calls `confirm(R)` → `confirmations[R] = {B, C}`, `len() = 2`.
6. `A` (or any remaining member) calls `confirm(R)` → `confirmations.len() + 1 = 3 >= num_confirmations (3)` → `execute_request(R)` fires, even though the actual live confirmers were only `A` and `C` (B, whose confirmation is still counted, is no longer a member). [1](#0-0) [2](#0-1)

    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
