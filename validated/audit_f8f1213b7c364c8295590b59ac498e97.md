The core issue in the audit report is a classic **"push-payment griefing"** pattern: a loop that pushes funds to multiple recipients synchronously, where a single recipient that reverts on receipt bricks the whole batch for everyone else. I found a direct Move-native analog of this exact pattern in `aptos_framework::vesting::distribute()`.

### Title
Unprivileged shareholder can permanently brick vesting-contract distribution and termination by disabling direct coin transfers - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute()` iterates over **every** shareholder of a vesting contract in a single atomic loop and pushes their share of withdrawable coins via `aptos_account::deposit_coins()`. If any one shareholder's default recipient address (the shareholder itself, when no beneficiary is set) is unable to accept an un-registered direct coin deposit, the whole transaction aborts — exactly like the auction house being bricked by one bad `onERC721Received()` implementation.

### Finding Description
`aptos_account::deposit_coins()` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the recipient is not yet registered for the coin type **and** has opted out of direct transfers via `set_allow_direct_coin_transfers(false)`: [1](#0-0) 

`vesting::distribute()` loops over all shareholders of the `grant_pool` and calls `deposit_coins` for each one's `recipient_address` (the shareholder itself, unless a beneficiary was explicitly set): [2](#0-1) 

Any shareholder can unilaterally, at any time before `distribute()` is next called, invoke `aptos_account::set_allow_direct_coin_transfers(false)` on their own account without ever registering an `AptosCoin` `CoinStore`. This is a fully unprivileged, self-contained action — no elevated role is required.

Once that condition holds for even one shareholder, every future call to `distribute()` for that vesting contract aborts inside the `for_each_ref` loop, before any other shareholder receives their share, because the entire entry function reverts (Move transactions are atomic).

This also blocks contract termination, since `terminate_vesting_contract()` unconditionally calls `distribute()` first: [3](#0-2) 

Unlike `set_beneficiary()`, which does enforce `assert_account_is_registered_for_apt(new_beneficiary)` before accepting a beneficiary change: [4](#0-3) 

...there is no equivalent registration/acceptance check performed on the **default shareholder address** at `create_vesting_contract` time or at `distribute()` time. The admin flow comment even documents that `distribute` is a prerequisite gate for termination and withdrawal, without any way to skip a stuck shareholder: [5](#0-4) 

### Impact Explanation
A single unprivileged shareholder can permanently DoS reward/vested-coin distribution for **all other shareholders** of the same vesting contract, and also permanently block the admin from ever terminating that contract and reclaiming remaining stake via `admin_withdraw`. This traps all co-shareholders' vested and reward balances with no on-chain recovery path (there is no "skip bad recipient" mechanism, and the offending shareholder controls whether to ever fix their own opt-out flag). This satisfies "permanent lock or non-recoverable loss of claim rights in ... vesting flows."

### Likelihood Explanation
High likelihood: `set_allow_direct_coin_transfers(false)` is a normal, publicly documented user-facing API requiring no special privilege, and many vesting contracts have multiple shareholders added at creation without any registration/acceptance verification. Any shareholder — malicious or merely careless — can trigger this state.

### Recommendation
- In `distribute()`, wrap each per-shareholder deposit in a way that cannot abort the whole batch (e.g., detect ineligibility and route the funds to a claimable/pending balance keyed by shareholder rather than pushing synchronously), or
- Enforce the same `assert_account_is_registered_for_apt`-style check on every shareholder address at `create_vesting_contract` time (as already done for `withdrawal_address` and `set_beneficiary`), and re-validate/skip non-compliant shareholders instead of aborting the entire distribution, and
- Decouple `terminate_vesting_contract` from a successful `distribute()` call so admin recovery is never blocked by one uncooperative shareholder.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `[S1, S2]` via `create_vesting_contract`, no beneficiaries set.
2. `S1` calls `aptos_account::set_allow_direct_coin_transfers(false)` on their own account and never registers a `CoinStore<AptosCoin>`.
3. Time passes, rewards/vested coins accumulate and become withdrawable.
4. Anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches `S1`, calls `aptos_account::deposit_coins(S1, ...)`, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` since `S1` is unregistered and opted out.
6. The whole transaction reverts — `S2` receives nothing, and this repeats for every future `distribute()`/`distribute_many()`/`terminate_vesting_contract()` call as long as `S1`'s configuration is unchanged.

        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);

            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);

    /// Terminate the vesting contract and send all funds back to the withdrawal address.
    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);
