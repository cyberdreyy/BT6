### Title
Legacy staked-oracle NAV calculation reverts (and freezes the bank) if pool delegation drops below the hard-coded 1 SOL bootstrap - (File: `programs/marginfi/src/state/price.rs`)

### Summary
`legacy_staked_pool_delegated_value` subtracts a hard-coded `1_000_000_000` lamports ("non-refundable bootstrap stake") from the pool's `delegation.stake` using `checked_sub`, which errors out via `math_error!()` if the delegated stake is ever below that threshold. This mirrors the reported `DAIInterestRateModel.dsrPerBlock` bug class: a subtraction of an assumed-always-present offset that reverts once the underlying external value dips under the offset, and that revert occurs inside a routine invoked on essentially every user-facing action.

### Finding Description
`legacy_staked_pool_delegated_value` is used for `OracleSetup::StakedWithPythPush` banks while `bank.on_ramp_transition()` reports `OnRampTransition::PreTransition` (the default/current SVSP migration state): [1](#0-0) 

```
fn legacy_staked_pool_delegated_value(pool_stake_info: &AccountInfo) -> MarginfiResult<u64> {
    ...
    Ok(stake
        .delegation
        .stake
        .checked_sub(1_000_000_000)
        .ok_or_else(math_error!())?)
}
```

This is called from the price-loading path used by every staked-bank oracle read: [2](#0-1) 

That price-loading path is not admin-only — it backs `lending_pool_pulse_bank_price_cache` (explicitly documented as "(Permissionless) Refresh the cached oracle price for a bank") as well as the price fetch performed inside every deposit, withdraw, borrow, repay, and liquidation instruction that touches the bank: [3](#0-2) [4](#0-3) 

The code comment assumes the SPL single-validator stake pool always retains its "initial non-refundable 1 SOL bootstrap stake" on top of user deposits, so `delegation.stake` is assumed to never be less than `1_000_000_000`. That assumption is not enforced anywhere in the marginfi program itself — it depends entirely on external SPL single-pool program state and validator/stake-account lifecycle behavior (e.g., transient deactivation windows, partial/edge-case withdrawal sequences, or any future/alternate pool implementation that does not guarantee the 1 SOL floor). If `delegation.stake` is ever observed below `1e9` lamports while the bank is still in `PreTransition` mode, this subtraction underflows and the whole call reverts.

### Impact Explanation
Because this code executes inside the shared oracle-loading routine, a revert here does not just fail a single "poke"-style refresh — it blocks every operation that needs the bank's price for that staked asset: permissionless price pulsing, deposits, withdrawals, borrows, repayments, and — critically — liquidations and bad-debt settlement for that bank. This is a durable freeze of an entire bank's price-dependent functionality with direct financial consequences: positions can no longer be liquidated even if they become unhealthy, and depositors/borrowers on that bank are locked out until an admin intervenes (e.g., by forcing the on-ramp transition or otherwise fixing the underlying pool). This matches the "durable freeze/inconsistency with financial effect" criterion.

### Likelihood Explanation
This path (`OnRampTransition::PreTransition`) is explicitly documented as the current/default state before the SVSP on-ramp rollout completes, so it is live in production today, not a hypothetical future-only configuration. The trigger condition — delegated stake dropping under 1 SOL — is outside marginfi's control since it depends on the state of the external SPL single-validator stake pool account, which any user can influence, and unlike the interest-rate curve case there is no on-chain validation in marginfi enforcing the 1 SOL floor before this subtraction runs. This makes it a plausible, unprivileged-triggerable condition rather than a purely theoretical one, though it does require the specific external pool state to occur.

### Recommendation
Replace the hard `checked_sub` with a saturating subtraction (consistent with the newer `staked_pool_net_asset_value` implementation, which already uses `saturating_sub`), e.g. `stake.delegation.stake.saturating_sub(1_000_000_000)`, so that a pool balance at or below the bootstrap floor degrades to a zero/near-zero valuation rather than reverting and freezing the bank. Additionally, consider validating/asserting the expected invariant out-of-band (e.g., via monitoring) rather than relying on an unchecked external assumption baked into a hot, permissionless code path.

### Proof of Concept
1. Bank is configured with `OracleSetup::StakedWithPythPush` and remains in `OnRampTransition::PreTransition` (default state prior to SVSP on-ramp rollout completion), as exercised in `legacy_staked_price_ignores_onramp_and_underprices_when_onramp_has_lamports`.
2. The associated single-validator stake pool account's `delegation.stake` becomes less than `1_000_000_000` lamports (e.g., through external pool-lifecycle behavior not controlled by marginfi).
3. Any subsequent call that needs this bank's price — `lending_pool_pulse_bank_price_cache`, or any deposit/withdraw/borrow/repay/liquidate touching the bank — invokes `legacy_staked_pool_delegated_value`, which executes `checked_sub(1_000_000_000)` on the sub-threshold value and returns `None`, causing `math_error!()` to trigger a hard revert for every such transaction, freezing the bank's price-dependent operations, including liquidation of unhealthy positions.

use crate::state::bank::BankImpl;
use crate::state::price::OraclePriceFeedAdapter;
use crate::{MarginfiError, MarginfiResult};
use anchor_lang::prelude::*;
use marginfi_type_crate::types::{Bank, MarginfiGroup};

/// (permissionless) Refresh the cached oracle price for a bank.
pub fn lending_pool_pulse_bank_price_cache<'info>(
    ctx: Context<'info, LendingPoolPulseBankPriceCache<'info>>,
) -> MarginfiResult {
    let clock = Clock::get()?;

    let mut bank = ctx.accounts.bank.load_mut()?;

    let price_for_cache = OraclePriceFeedAdapter::get_price_and_confidence_for_cache(
        &bank,
        ctx.remaining_accounts,
        &clock,
    )?;

    bank.update_cache_price(Some(price_for_cache))?;

    Ok(())
}
