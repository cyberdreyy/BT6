The vulnerability is real. `lending_pool_clone_emode` performs a full overwrite of `destination_bank.emode` from `copy_from_bank.emode` with no re-validation against `destination_bank.config`, while every other entry point that mutates emode state (`lending_pool_configure_bank_emode` and `lending_pool_configure_bank`) explicitly calls `validate_entries_with_liability_weights` against the bank's own current config immediately after the mutation.### Title
Unvalidated `lending_pool_clone_emode` copy allows stale emode entries to violate CW < LW invariant against the destination bank's own liability weights - (File: `programs/marginfi/src/instructions/marginfi_group/emode_clone.rs`)

### Summary
`lending_pool_clone_emode` blindly overwrites `destination_bank.emode` with `source_bank.emode` and never calls `validate_entries_with_liability_weights` against `destination_bank.config`, unlike every other mutation path (`lending_pool_configure_bank_emode`, `lending_pool_configure_bank`) which does. Because the cloned `EmodeEntry.asset_weight_init/maint` values were only ever validated against the *source* bank's own liability weights (and against the group's max-leverage caps using that source config), they can silently exceed the destination bank's own liability weights, breaking the CW < LW price-conservatism invariant for that bank as soon as the clone completes (or after a later, otherwise-valid `configure_bank` change to *either* bank).

### Finding Description
`EmodeSettings.emode_config` entries are keyed by `collateral_bank_emode_tag` and store `asset_weight_init/maint`, which are looked up via `Bank::get_asset_weight` [1](#0-0)  when a bank is used as collateral against a liability bank whose reconciled emode config contains a matching tag. The safety invariant CW < LW (and the leverage cap) is enforced only at write time by `validate_entries_with_liability_weights`, which computes the *liability* weight from `bank_config` — i.e. the same bank that owns the emode entries — and checks each entry's asset weight against it [2](#0-1) .

This validation is correctly invoked in:
- `lending_pool_configure_bank_emode`, immediately after writing new entries [3](#0-2) 
- `lending_pool_configure_bank`, immediately after any config change (re-validates existing entries against the bank's new liability weights) [4](#0-3) , and this path is proven to matter by the existing test `configure_bank_rejects_invalid_emode_leverage_on_weight_update` [5](#0-4) .

But `lending_pool_clone_emode` does neither:
```
let source_bank = ctx.accounts.copy_from_bank.load()?;
let mut destination_bank = ctx.accounts.copy_to_bank.load_mut()?;
destination_bank.emode = source_bank.emode;
``` [6](#0-5) 

No call to `validate_entries_with_liability_weights(&destination_bank.config, ...)` is made after the assignment. The `LendingPoolCloneEmode` accounts struct only enforces `has_one = group` on both banks (same-group binding) and a signer check for `group.admin`/`group.emode_admin` [7](#0-6)  — none of these guards re-derive or re-check the entries against the destination bank's own `liability_weight_init/maint`.

Because two banks in the same group frequently have different liability weights (different assets, different risk parameters), the entries copied from `copy_from_bank` (valid for its own LW) are not guaranteed valid for `copy_to_bank`'s LW. This can produce a state where an entry's `asset_weight_maint` (or `_init`) is ≥ `copy_to_bank.config.liability_weight_maint/_init`, which is exactly the state `validate_entries_with_liability_weights` is designed to reject (see `test_validate_emode_with_liability_weights_invalid_cw_exceeds_lw`) [8](#0-7) . `Bank::get_asset_weight`'s `max(bank_weight, emode_weight)` only guards against emode *reducing* a bank's base asset weight; it provides no protection against the emode weight exceeding the liability bank's own liability weight [9](#0-8) .

Once this stale, over-generous emode entry exists on `copy_to_bank`, any unprivileged user can deposit a matching-tagged collateral bank and borrow from `copy_to_bank`; the risk engine (`get_health_components` → `calc_weighted_asset_value_standalone` → `bank.get_asset_weight`) will apply the inflated `asset_weight`, understating the position's true risk and overstating collateral value relative to the borrowed liability's weight.

### Impact Explanation
This breaks the PRICE_CONSERVATISM invariant (CW < LW) for `copy_to_bank`, allowing unprivileged depositors to obtain undercollateralized borrowing positions that the leverage-cap and CW<LW checks were specifically designed to prevent. This is a genuine misvaluation/understated-liability class issue with direct financial impact (bad debt risk to the pool), not a pure-liquidity, oracle-data, or admin-best-practice issue, so it falls within scope.

### Likelihood Explanation
Preconditions require an admin/emode_admin to run `lending_pool_clone_emode` between two banks whose liability weights differ (a plausible, non-malicious operational action explicitly enabled and documented as a normal feature — "Useful when applying emode settings from e.g. one LST to another"). No malicious admin intent or key compromise is needed; the bug is that the instruction itself omits a check present everywhere else. Once cloned, exploitation by an ordinary depositor/borrower requires no special privilege — it uses only the standard deposit/borrow instructions. This is fully repeatable and deterministic given the missing check.

### Recommendation
In `lending_pool_clone_emode`, after `destination_bank.emode = source_bank.emode;`, call `destination_bank.emode.validate_entries_with_liability_weights(&destination_bank.config, group.emode_max_init_leverage, group.emode_max_maint_leverage)?;` (mirroring `lending_pool_configure_bank_emode` and `lending_pool_configure_bank`), rejecting the clone if the destination bank's own weights make any copied entry unsafe.

### Proof of Concept

1. Create two banks in the same group, `bank_a` (liability_weight_init/maint = 1.2/1.0) and `bank_b` (liability_weight_init/maint = 1.05/1.02, i.e. tighter).
2. Call `try_lending_pool_configure_bank_emode(bank_a, tag, [entry{asset_weight_init=0.84, asset_weight_maint=0.9}])` — validated and accepted against `bank_a`'s LW (3.3x/10x leverage, within default caps).
3. Call `try_lending_pool_clone_emode(bank_a, bank_b)` as admin — currently succeeds unconditionally.
4. Assert (expected failure of the fix, or exploit demonstration pre-fix): compute `bank_b.emode.validate_entries_with_liability_weights(&bank_b.config, group.emode_max_init_leverage, group.emode_max_maint_leverage)` directly and show it returns `Err(BadEmodeConfig)` or `Err(MaxInitLeverageExceeded)`/`MaxMaintLeverageExceeded)`, because `0.9 >= 1.02*asset_maint_w`'s bound is violated (choose weights such that `asset_weight_maint >= bank_b`'s maint LW, e.g. asset_maint_w=0.9 vs bank_b liab_maint_w=0.85).
5. Confirm that `try_lending_pool_clone_emode` itself returned `Ok(())` in step 3 despite this — proving the missing guard.
6. (End-to-end) Have an unprivileged user deposit into a collateral bank tagged to match, then borrow from `bank_b`, and assert via `get_health_components`/risk engine that the account's computed asset weight equals the stale emode weight rather than being clamped by `bank_b`'s own liability weight — demonstrating the phantom collateral/understated liability in practice.

        &self,
        requirement_type: RequirementType,

    ) -> I80F48 {
        if let Some(emode_entry) = emode_config.find_with_tag(self.emode.emode_tag) {
            let bank_weight = self
                .config
                .get_weight(requirement_type, BalanceSide::Assets);
            let emode_weight = match requirement_type {
                RequirementType::Initial => I80F48::from(emode_entry.asset_weight_init),
                RequirementType::Maintenance => I80F48::from(emode_entry.asset_weight_maint),
                RequirementType::Equity => I80F48::ONE,
            };
            max(bank_weight, emode_weight)
        } else {
            self.config
                .get_weight(requirement_type, BalanceSide::Assets)
        }
    }

    fn validate_entries_with_liability_weights(
        &self,
        bank_config: &BankConfig,
        emode_max_init_leverage: u32,
        emode_max_maint_leverage: u32,
    ) -> MarginfiResult {
        let liab_init_w: I80F48 = bank_config.get_weight(
            RequirementType::Initial,
            marginfi_type_crate::types::BalanceSide::Liabilities,
        );
        let liab_maint_w: I80F48 = bank_config.get_weight(
            RequirementType::Maintenance,
            marginfi_type_crate::types::BalanceSide::Liabilities,
        );

        let max_allowed_init_leverage: I80F48 = u32_to_basis(emode_max_init_leverage);
        let max_allowed_maint_leverage: I80F48 = u32_to_basis(emode_max_maint_leverage);

        for entry in self.emode_config.entries {
            if entry.is_empty() {
                continue;
            }
            let asset_init_w: I80F48 = I80F48::from(entry.asset_weight_init);
            let asset_maint_w: I80F48 = I80F48::from(entry.asset_weight_maint);

            // Basic sanity checks
            check!(
                asset_init_w >= I80F48::ZERO,
                MarginfiError::BadEmodeConfig,
                "emode entry tag {}: asset_init_w ({}) must be >= 0",
                entry.collateral_bank_emode_tag,
                asset_init_w
            );
            check!(
                asset_maint_w >= asset_init_w,
                MarginfiError::BadEmodeConfig,
                "emode entry tag {}: asset_maint_w ({}) must be >= asset_init_w ({})",
                entry.collateral_bank_emode_tag,
                asset_maint_w,
                asset_init_w
            );

            let max_leverage_init = calculate_max_leverage(asset_init_w, liab_init_w)?;
            check!(
                max_leverage_init <= max_allowed_init_leverage,
                MarginfiError::MaxInitLeverageExceeded,
                "emode entry tag {}: init leverage ({}) exceeds max allowed ({})",
                entry.collateral_bank_emode_tag,
                max_leverage_init,
                max_allowed_init_leverage
            );

            let max_leverage_maint = calculate_max_leverage(asset_maint_w, liab_maint_w)?;
            check!(
                max_leverage_maint <= max_allowed_maint_leverage,
                MarginfiError::MaxMaintLeverageExceeded,
                "emode entry tag {}: maint leverage ({}) exceeds max allowed ({})",
                entry.collateral_bank_emode_tag,
                max_leverage_maint,
                max_allowed_maint_leverage
            );
        }

        // Validate that no duplicates exist (other than EMODE_TAG_EMPTY - 0)
        self.check_dupes()?;

        Ok(())
    }

async fn configure_bank_rejects_invalid_emode_leverage_on_weight_update(
    bank_mint: BankMint,
) -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;
    let bank = test_f.get_bank(&bank_mint);

    let liab_init_w = I80F48::from_num(1.5);
    let liab_maint_w = I80F48::from_num(1.5);
    bank.update_config(
        BankConfigOpt {
            liability_weight_init: Some(liab_init_w.into()),
            liability_weight_maint: Some(liab_maint_w.into()),
            ..BankConfigOpt::default()
        },
        None,
    )
    .await?;

    let asset_init_w = liab_init_w * I80F48::from_num(0.9);
    let asset_maint_w = liab_maint_w * I80F48::from_num(0.9);

    let emode_tag = 1u16;
    let emode_entries = vec![EmodeEntry {
        collateral_bank_emode_tag: emode_tag,
        flags: 0,
        pad0: [0, 0, 0, 0, 0],
        asset_weight_init: asset_init_w.into(),
        asset_weight_maint: asset_maint_w.into(),
    }];

    test_f
        .marginfi_group
        .try_lending_pool_configure_bank_emode(&bank, emode_tag, &emode_entries)
        .await?;

    // Tighten base weights to push emode leverage above max while remaining a valid bank config.
    let new_liab_init_w = asset_init_w / I80F48::from_num(0.96);
    let new_liab_maint_w = asset_maint_w / I80F48::from_num(0.96);

    let res = test_f
        .marginfi_group
        .try_lending_pool_configure_bank(
            &bank,
            BankConfigOpt {
                liability_weight_init: Some(new_liab_init_w.into()),
                liability_weight_maint: Some(new_liab_maint_w.into()),
                ..BankConfigOpt::default()
            },
        )
        .await;

    assert!(
        res.is_err(),
        "Updating base weights that push emode leverage above limits should fail"
    );
    assert_custom_error!(res.unwrap_err(), MarginfiError::MaxInitLeverageExceeded);
