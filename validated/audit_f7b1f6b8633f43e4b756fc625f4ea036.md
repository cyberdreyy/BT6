### Title
Removing a member from `multisig2` does not purge that member's confirmations on requests authored by other members, allowing a request to execute below the live-member confirmation threshold - (File: `multisig2/src/lib.rs`)

### Summary
The custody binding a k-of-n multisig must preserve is: `confirmations_counted == confirmations_from_live_members`. In `multisig2/src/lib.rs`, `delete_member` only purges confirmations for requests that the removed member *originated* (`r.member == member`), but not confirmations that removed member cast on requests *authored by someone else*. Those stale confirmations remain in the `confirmations: LookupMap<RequestId, HashSet<String>>` map keyed by `request_id`, and `confirm` (line 304) counts `confirmations.len() + 1 >= self.num_confirmations` without re-validating that every entry in the set is still a current member. This lets a request execute using a confirmation from an account that is no longer part of the multisig.

### Finding Description
`delete_member` [1](#0-0)  removes outstanding requests and their confirmation sets only for requests whose *originating* member (`request_with_signer.member`, set at `add_request` time [2](#0-1) ) equals the member being deleted:

```
let request_ids: Vec<u32> = self.requests.iter()
    .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
    .collect();
for request_id in request_ids {
    self.confirmations.remove(&request_id);
    self.requests.remove(&request_id);
}
```

It never scans the `confirmations` sets of requests authored by *other* members to strip out the removed member's entry. `confirm` then simply checks the raw count of the stored `HashSet<String>` against `num_confirmations` [3](#0-2) , with no re-check that each string in that set still corresponds to a member in `self.members`.

### Impact Explanation
This is Critical: a multisig request can be executed with fewer *live* confirmations than the configured threshold, because a stale confirmation from a removed member is still counted. Concretely, with `num_confirmations = k` out of `n` members, a request can execute with only `k-1` live signers plus one confirmation from a member who has since been removed — i.e., the equality `confirmations_counted == confirmations_from_live_members` is broken, and `MultiSigRequestAction::Transfer`, `AddKey`, `AddMember`, etc. can be pushed through below the intended threshold (funds moved, or keys/members added, by a party the remaining organization no longer trusts).

### Likelihood Explanation
Reachable by any current multisig member with no special privilege beyond normal membership (`add_request`/`confirm` are open to any `MultisigMember`). It requires: (1) a member confirms (but does not author) some request, (2) that member is later removed via `DeleteMember`, and (3) the request they confirmed reaches threshold afterward using the stale confirmation. This is a realistic operational sequence (e.g. removing a compromised/departing member) rather than a contrived edge case, and no owner/root privilege or victim key is required — any member combination suffices.

### Recommendation
When deleting a member, iterate over **all** active requests' confirmation sets (not just those the member authored) and remove that member's entry; alternatively, validate in `confirm`/`execute_request` that every confirming identity in the stored set is still present in `self.members` before counting it toward `num_confirmations`.

### Proof of Concept
1. Initialize `multisig2` with `members = [A, B, C, D]`, `num_confirmations = 3`.
2. `A` calls `add_request` with a `Transfer` action to some receiver (`request.member = A`), then `A` calls `confirm(request_id)` → `confirmations = {A}` (count 1, threshold 3 not met) [4](#0-3) .
3. `D` (soon to be removed) calls `confirm(request_id)` → `confirmations = {A, D}` (count 2, still below 3) [5](#0-4) .
4. Separately, `B` authors and the group confirms a `DeleteMember { member: D }` request with 3 confirmations, which executes and removes `D` from `self.members` [1](#0-0) . Because the Transfer request from step 2 was authored by `A`, not `D`, `delete_member`'s cleanup loop does not touch it — `confirmations = {A, D}` on that request is untouched.
5. Now only `A, B, C` remain as members. `B` calls `confirm(request_id)` on the original Transfer request → `confirmations.len() + 1 = 3 >= num_confirmations (3)` → the request executes, moving funds, even though only 2 live members (`A`, `B`) actually authorized it; the third "confirmation" belongs to `D`, who is no longer a member.

    }

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
