### Title
Multisig executes requests below the live-member confirmation threshold because `delete_member` fails to purge a removed member's stale confirmations from other pending requests - ([File: multisig2/src/lib.rs])

### Summary
`MultiSigContract::delete_member` in `multisig2/src/lib.rs` only removes requests that were *created by* the member being deleted, but it never scrubs that member's confirmations from requests created by *other* members. `confirm` later counts confirmations purely by set size (`confirmations.len() as u32 + 1 >= self.num_confirmations`) without checking whether every confirming identity is still a current member. A member who confirmed a pending request and was subsequently removed still counts toward that request's threshold, letting a request execute with fewer live approvers than `num_confirmations` requires.

### Finding Description
The binding the multisig is supposed to preserve is:

```
confirmations counted for a request == confirmations from members who are still live members
```

`confirm` increments and checks this count purely from the `confirmations: LookupMap<RequestId, HashSet<String>>` map: [1](#0-0) 

`delete_member`, invoked from `execute_request`'s `DeleteMember` action, removes the deleted member from `self.members` and cleans up only requests where `r.member == member` (i.e., requests the removed member had *authored*): [2](#0-1) 

It never iterates `self.confirmations` to strip the removed member's entry from confirmation sets belonging to requests authored by other members. `current_member()` in `confirm` is only used to validate the *caller* is a live member at the time they confirm — it is never re-checked for confirmations recorded earlier by now-removed members: [3](#0-2) 

So a stale confirmation string persists in a pending request's `HashSet<String>` after the member who made it is deleted, and it is still summed into the threshold check the next time someone confirms.

### Impact Explanation
This breaks the authorization threshold invariant of the multisig: a `Transfer`, `AddKey`, `AddMember`, `FunctionCall`, or any other request can be executed with fewer *currently live* member approvals than `num_confirmations`. This is a threshold-authorization bypass matching the Critical impact category "a multisig request executed below threshold" — funds or privileged actions (adding a full-access key, transferring NEAR out of the account) can be pushed through by a minority of live members, using a "confirmation ghost" left behind by a removed member.

### Likelihood Explanation
No special privilege beyond ordinary multisig membership is required. Any member (including a compromised/malicious one) can confirm a pending request, and any legitimate governance action to remove that member (e.g., because their key was compromised) will leave their confirmation intact on any request they touched before being removed. The scenario is a normal, foreseeable multisig operational sequence (member confirms, then gets removed) rather than a contrived edge case, making this readily reachable in production key-rotation/offboarding flows.

### Recommendation
When deleting a member in `delete_member`, iterate all pending `requests`/`confirmations` and remove the deleted member's string from every confirmation `HashSet`, not just the requests they authored. Alternatively, when counting confirmations in `confirm`, filter the stored confirmation set to only those entries still present in `self.members` before comparing against `num_confirmations`.

### Proof of Concept
1. Initialize multisig with members `[A, B, C, D]` and `num_confirmations = 3`.
2. `A` calls `add_request` to create request `R1` (e.g., `Transfer` of funds).
3. `D` calls `confirm(R1)` → `confirmations[R1] = {D}` (1 of 3).
4. Separately, `A`, `B`, `C` create and confirm a `DeleteMember { member: D }` request, which reaches 3 confirmations and executes `delete_member(D)`. Per `multisig2/src/lib.rs:361-371`, this only deletes requests authored by `D`; `R1`'s `confirmations` set (authored by `A`, containing `D`'s stale entry) is untouched. `D` is removed from `self.members`.
5. `A` calls `confirm(R1)` → `confirmations[R1] = {D, A}` (2).
6. `B` calls `confirm(R1)` → `confirmations.len() + 1 = 3 >= num_confirmations(3)` → `R1` executes.

Result: `R1` (e.g., a `Transfer`) executes with only two currently-live members (`A`, `B`) having approved, one short of the required 3-of-4 (now 3-of-3) threshold, because the removed member `D`'s confirmation was never purged.

    /// Confirm given request with given signing key.
    /// If with this, there has been enough confirmation, a promise with request will be scheduled.
    pub fn confirm(&mut self, request_id: RequestId) -> PromiseOrValue<bool> {
        self.assert_valid_request(request_id);
        let member = self
            .current_member()
            .unwrap_or_else(|| env::panic_str("Must be validated above"));
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert(
            !confirmations.contains(&member.to_string()),
            "Already confirmed this request with this key",
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************
            NOTE: If the tx execution fails for any reason, the request and confirmations are removed already, so the client has to start all over
            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(member.to_string());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    /// Delete member from the list. Removes access key if the member is key based.
    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
