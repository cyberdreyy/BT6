### Title
Credit vault deployment permits a zero borrower and deterministically defaults user deposits on epoch start - (File: `contracts/strategies/idle/IdleCreditVault.sol`)

### Summary
`IdleCreditVault.initialize` stores `borrower = _borrower` without rejecting `address(0)`, even though the later `setBorrower` path explicitly rejects the same value. The permissionless `IdleCreditVaultFactory.deployCreditVault` validates only `strategyData.manager`, so an unprivileged caller can deploy a malformed credit vault with `borrower == address(0)`. When the honest manager later calls `startEpoch`, the CDO attempts to transfer the pooled underlying to the zero borrower. For a standard ERC20 that rejects zero-address recipients, the self-call is caught, the vault is marked defaulted, and user funds are locked in the strategy’s default-recovery reserve instead of entering a usable borrower position. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
The missing validation is in `contracts/strategies/idle/IdleCreditVault.sol:124-143`:

```solidity
borrower = _borrower;
manager = _manager;
```

No zero-address check is applied to `_borrower` during initialization. [1](#0-0) 

The analogous mutable setter contains the missing guard:

```solidity
require(_borrower != address(0), "IS_0");
borrower = _borrower;
```

This shows that a zero borrower is not an intended operational state. [2](#0-1) 

The factory’s standard credit-vault path rejects only a zero manager and forwards `strategyData.borrower` directly into `IdleCreditVault.initialize`. [5](#0-4) [6](#0-5) 

After users deposit, `startEpoch` calculates the surplus underlying and calls `sendFundsToBorrower`, which transfers to `_borrower()` through an external self-call so failures can be caught. [7](#0-6) 

For an ERC20 that rejects transfers to `address(0)`, that call reverts. The catch block moves the entire borrower-bound amount to the strategy, records it as `defaultRecoveryReserve`, and invokes `_handleBorrowerDefault`. [8](#0-7) [9](#0-8) 

`_handleBorrowerDefault` sets `defaulted = true`, pauses the pool, stops the epoch, and disables further withdrawal requests. [10](#0-9) 

### Impact Explanation
A vault created through the factory can therefore be permanently configured to fail on the first epoch start.

For a deposited principal `N`, the attacker or malformed deployment causes:

1. Victims deposit `N` underlying and receive AA tranche tokens.
2. The honest manager starts the first epoch.
3. The strategy returns the deposits to the CDO.
4. The CDO attempts `transfer(address(0), N)`.
5. The token reverts, the catch path reserves `N` in the strategy, and the vault enters `defaulted`.
6. Normal deposits and withdrawal requests remain disabled until the honest owner or manager finalizes default recovery.

The loss is not merely a revert. Finalization divides the `N` recovery reserve across both the active principal and the borrower-owed default interest basis. If the active claim basis is `N + I`, the recovery ratio is approximately `N / (N + I)`, so users receive only that fraction of their principal unless an external recovery source tops up the missing interest. [11](#0-10) [12](#0-11) 

Example: with `N = 1,000,000` underlying and expected/default interest basis `I = 10,000`, the reserve supports approximately `99.0099%` of the recorded claims. Users lose about `9,901` underlying in aggregate even though all `1,000,000` principal is still held by the strategy.

For an underlying token that does not reject zero-address transfers, the outcome can be worse: the `N` underlying may be burned or become permanently inaccessible while the pool still records borrower exposure.

### Likelihood Explanation
The deployment path is externally callable and does not require a privileged attacker. [13](#0-12) 

The exploit requires social or operational conditions: a creator must deploy a vault with `borrower = address(0)`, victims must deposit into that vault, and its honest manager must start the epoch. It does not corrupt an existing correctly configured credit vault. The zero borrower is reachable by either a malicious vault creator or an accidental deployment because the factory and strategy initializer both omit the check.

Once the malformed vault has deposits and `startEpoch` is invoked, the default is deterministic for standard ERC20 implementations. Existing guards do not prevent it: deposits are accepted while no Keyring contract is configured, the zero borrower is never checked, and the borrower-transfer failure is intentionally converted into the default path. [14](#0-13) [4](#0-3) 

### Recommendation
Validate the borrower at initialization in `IdleCreditVault.initialize`:

```solidity
if (
    _underlyingToken == address(0) ||
    _owner == address(0) ||
    _manager == address(0) ||
    _borrower == address(0)
) {
    revert InvalidAddress();
}
```

At minimum, mirror the existing setter rule:

```solidity
require(_borrower != address(0), "IS_0");
```

The factory should also fail early before deploying proxies:

```solidity
if (strategyData.manager == address(0) || strategyData.borrower == address(0)) revert Is0();
```

The revolving-credit path already relies on `ProgrammableBorrower.initialize`, which rejects a zero borrower, but adding the factory check makes both deployment families consistent and prevents partial deployments. [15](#0-14) 

### Proof of Concept
The following Foundry test deploys the real factory and credit-vault implementations, configures a nonzero manager and fee receiver, but leaves the borrower as `address(0)`. A lender deposits `1,000,000` tokens, the manager starts the epoch, and the vault deterministically defaults with all principal trapped in the recovery reserve.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

import "../contracts/IdleCreditVaultFactory.sol";
import "../contracts/IdleCDOEpochVariant.sol";
import "../contracts/strategies/idle/IdleCreditVault.sol";

contract PoCToken is ERC20 {
    constructor() ERC20("Proof USDC", "pUSDC") {
        _mint(msg.sender, 10_000_000e18);
    }

    function decimals() public pure override returns (uint8) {
        return 18;
    }
}

contract ZeroBorrowerPoC is Test {
    bytes32 internal constant DEPLOYED =
        keccak256("CreditVaultDeployed(address,address,address,address,address,address)");

    PoCToken internal token;
    IdleCreditVaultFactory internal factory;

    address internal treasury = makeAddr("treasury");
    address internal proxyAdmin = makeAddr("proxyAdmin");
    address internal attacker = makeAddr("attacker");
    address internal manager = makeAddr("manager");
    address internal feeReceiver = makeAddr("feeReceiver");
    address internal lender = makeAddr("lender");

    function setUp() external {
        vm.warp(100 days);
        token = new PoCToken();

        IdleCreditVaultFactory factoryImpl = new IdleCreditVaultFactory();
        TransparentUpgradeableProxy factoryProxy = new TransparentUpgradeableProxy(
            address(factoryImpl),
            proxyAdmin,
            abi.encodeWithSelector(
                IdleCreditVaultFactory.initialize.selector,
                treasury,
                proxyAdmin
            )
        );
        factory = IdleCreditVaultFactory(address(factoryProxy));

        token.transfer(lender, 1_000_000e18);
    }

    function testZeroBorrowerFirstEpochDefaultsAndReservesPrincipal() external {
        IdleCDOEpochVariant cdoImpl = new IdleCDOEpochVariant();
        IdleCreditVault strategyImpl = new IdleCreditVault();

        IdleCreditVaultFactory.CreditVaultParams memory cvParams =
            IdleCreditVaultFactory.CreditVaultParams({
                implementation: address(cdoImpl),
                limit: 0,
                underlying: address(token),
                apr: 10e16, // 10% APR
                epochDuration: 30 days,
                bufferPeriod: 1 days,
                instantWithdrawDelay: 3 days,
                instantWithdrawAprDelta: 0,
                disableInstantWithdraw: true,
                keyringPolicy: 0,
                feeReceiver: feeReceiver,
                fees: 5_000,
                managementFee: 500,
                isInterestMinted: false,
                isDepositDuringEpochDisabled: true
            });

        IdleCreditVaultFactory.StrategyData memory strategyData =
            IdleCreditVaultFactory.StrategyData({
                implementation: address(strategyImpl),
                manager: manager,
                borrower: address(0), // missing validation
                borrowerName: "ZeroBorrower"
            });

        IdleCreditVaultFactory.AncillaryParams memory ancillary =
            IdleCreditVaultFactory.AncillaryParams({
                keyring: address(0),
                queueImplementation: address(0),
                prefundedDepositWindow: 0,
                writeOffImplementation: address(0)
            });

        vm.prank(attacker);
        vm.recordLogs();
        factory.deployCreditVault(cvParams, strategyData, ancillary);

        (address cdoAddr, address strategyAddr) = _decodeDeployment(vm.getRecordedLogs());
        IdleCDOEpochVariant cdo = IdleCDOEpochVariant(cdoAddr);
        IdleCreditVault strategy = IdleCreditVault(strategyAddr);

        assertEq(strategy.borrower(), address(0));

        uint256 principal = 1_000_000e18;
        vm.startPrank(lender);
        token.approve(address(cdo), principal);
        cdo.depositAA(principal);
        vm.stopPrank();

        // First epoch can begin immediately because initialization places
        // epochEndDate in the past and the configured buffer has elapsed.
        vm.prank(manager);
        cdo.startEpoch();

        assertTrue(cdo.defaulted());
        assertFalse(cdo.isEpochRunning());
        assertTrue(cdo.paused());
        assertFalse(cdo.allowAAWithdrawRequest());
        assertFalse(cdo.allowBBWithdrawRequest());

        // The failed transfer to address(0) put all principal in the strategy's
        // isolated default-recovery reserve instead of making it a live loan.
        assertEq(strategy.defaultRecoveryReserve(), principal);
        assertEq(token.balanceOf(address(strategy)), principal);
        assertEq(token.balanceOf(address(cdo)), 0);
    }

    function _decodeDeployment(Vm.Log[] memory logs)
        internal
        pure
        returns (address cdo, address strategy)
    {
        for (uint256 i = 0; i < logs.length; i++) {
            if (logs[i].topics[0] == DEPLOYED) {
                (cdo, strategy,,,,) = abi.decode(
                    logs[i].data,
                    (address, address, address, address, address, address)
                );
                return (cdo, strategy);
            }
        }
        revert("CreditVaultDeployed not found");
    }
}
```

Expected result: deployment succeeds despite `borrower == address(0)`, but `startEpoch` marks the vault defaulted and reserves all deposited principal for recovery rather than establishing a normal borrower position.

  function _defaultActiveInterestBasis(IIdleCDOEpochVariant _cdo) internal view returns (uint256 activeInterest) {
    uint256 expectedInterest = _cdo.expectedEpochInterest();
    uint256 pendingFees = _cdo.pendingWithdrawFees();
    if (expectedInterest <= pendingFees) return activeInterest;
    // Pending redeemers already include their net interest in pendingWithdraws; active LPs need
    // the same borrower-owed interest basis, net of performance fees, before applying recovery.
    activeInterest = expectedInterest - pendingFees;
    activeInterest -= activeInterest * _cdo.fee() / FULL_ALLOC;

  function _handleBorrowerDefault(uint256 funds) internal {
    defaulted = true;
    // Do not reopen instant claims here. They remain disabled when funding is pending;
    // successful full funding is the only path that enables them before finalization.

    if (isProgrammableBorrower) {
      IProgrammableBorrower(_borrower()).onDefault();
    }

    // deposits should be already prevented
    if (!paused()) {
      _pause();
    }

    // stop the current epoch
    isEpochRunning = false;

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;
