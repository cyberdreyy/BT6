### Title
Zip artifact extraction creates unvalidated symlinks with attacker-controlled targets - ([File: helpers/archives/zip_extract.go])

### Summary
`extractZipSymlinkEntry` reads the raw symlink target from the zip entry's file data and passes it directly to `os.Symlink` without checking whether the target is an absolute path or contains `../` traversal segments. This allows an artifact zip to plant a symlink inside the extraction directory that points anywhere on the filesystem the extracting process/container can reach.

### Finding Description
`extractZipFile` dispatches entries whose `file.Mode()&os.ModeType == os.ModeSymlink` to `extractZipSymlinkEntry`: [1](#0-0) 

The function opens the entry, reads its content via `io.ReadAll` (the content of a zip symlink entry is the link target text), removes any existing file at `file.Name`, and calls `os.Symlink(string(data), file.Name)`. There is no check that `data` is relative, no check that it stays within the extraction root, and no rejection of absolute paths (`/etc/shadow`) or traversal sequences (`../../secret`). The only path-related guard in the extraction pipeline is `errorIfGitDirectory`, which only blocks entries whose *own name* starts with `.git` — it does not inspect symlink targets at all: [2](#0-1) 

`ExtractZipArchive`/`ExtractZipFile` invoke this path unconditionally for every symlink entry in the archive: [3](#0-2) 

This code is reached from `commands/helpers/artifacts_downloader.go`, which downloads a job's artifacts archive and extracts it into the job's working directory via the extractor abstraction (`archive.NewExtractor(format, f, size, wd)` → `extractor.Extract(...)`): [4](#0-3) 

An attacker who controls a job's script output (or crafts artifacts directly, e.g. via a project they control) can produce a zip containing a symlink entry whose target is `/etc/shadow` or a traversal path. When another job (in the same or a different project, via `dependencies:`/cross-project `needs:` artifact download) extracts this archive, the symlink is created inside that job's workspace pointing outside the intended root, with no validation rejecting it.

### Impact Explanation
The impact depends on what later touches the symlink path: if a downstream job's script, `cache:paths`, or `artifacts:paths` glob happens to read or re-archive the symlinked path, the content of the out-of-workspace file (readable by the consuming job's process/container user) can be exposed in that job's logs, cache, or re-uploaded artifacts. This is a real path/file-operation-boundary violation — "file operations must stay within intended build/cache/artifact roots" is broken because the extraction step itself creates a symlink that can point arbitrarily outside that root. The severity in practice is bounded by whatever the consuming job already has read access to (its own container/host user permissions) and requires a downstream step that dereferences the specific symlinked filename, so it is not a direct arbitrary-file-read on its own, but it is a genuine building block for cross-job/cross-project information exposure when artifacts are shared across pipelines/projects.

### Likelihood Explanation
The precondition is straightforward for the producing side (any pipeline author can commit a crafted zip as a job artifact) but the exploit requires a downstream consumer that (a) downloads the crafted artifact and (b) has processing logic that dereferences the exact symlink name afterward (e.g. a known cache path or a wildcard `artifacts:paths`/`cache:paths` entry). This makes the finding fully reproducible at the extraction layer (100% - no target validation exists) but conditionally impactful depending on consumer pipeline configuration, so it is a moderate/plausible rather than trivially universal exploit chain.

### Recommendation
In `extractZipSymlinkEntry`, validate the symlink target before calling `os.Symlink`: reject absolute targets, and resolve the target relative to `file.Name`'s directory, verifying (via `filepath.Clean`/`filepath.Rel`) that the resolved path does not escape the extraction root (analogous to zip-slip protections applied to `file.Name` itself). Entries failing this check should be skipped with a warning, consistent with the existing `errorIfGitDirectory`/tracker warning pattern already used for `.git` entries.

### Proof of Concept
```go
func TestExtractZipSymlinkEntryRejectsEscapingTarget(t *testing.T) {
    testInWorkDir(t, func(t *testing.T, fileName string) {
        f, err := os.Create(fileName)
        require.NoError(t, err)
        zw := zip.NewWriter(f)

        hdr := &zip.FileHeader{Name: "evil"}
        hdr.SetMode(os.ModeSymlink | 0o777)
        w, err := zw.CreateHeader(hdr)
        require.NoError(t, err)
        _, err = w.Write([]byte("/etc/shadow"))
        require.NoError(t, err)
        require.NoError(t, zw.Close())
        f.Close()

        err = ExtractZipFile(fileName)
        require.NoError(t, err)

        // Expected (currently failing): symlink should NOT be created pointing outside the root
        target, lerr := os.Readlink("evil")
        assert.Error(t, lerr, "symlink with absolute/escaping target should have been rejected")
        _ = target
    })
}
```
Running this against the current implementation shows `os.Readlink("evil")` succeeds and returns `/etc/shadow`, confirming the unvalidated symlink is created.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		}

		if err := processZipExtra(&file.FileHeader); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}

	return nil
}

func ExtractZipFile(fileName string) error {
	archive, err := zip.OpenReader(fileName)
	if err != nil {
		return err
	}
	defer func() { _ = archive.Close() }()

	return ExtractZipArchive(&archive.Reader)
}
```

```go
func isPathAGitDirectory(path string) bool {
	parts := strings.Split(filepath.Clean(path), string(filepath.Separator))
	if len(parts) > 0 && parts[0] == ".git" {
		return true
	}
	return false
}

func errorIfGitDirectory(path string) *os.PathError {
	if !isPathAGitDirectory(path) {
		return nil
	}

	return &os.PathError{
		Op:   ".git inside of archive",
		Path: path,
		Err:  errors.New("trying to archive or extract .git path"),
	}
}
```
