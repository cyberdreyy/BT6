### Title
Unauthenticated disclosure of internal service health details via `/readyz?full=true` and `/health` - ([File: core/web/router.go], [File: core/web/health_controller.go])

### Summary
`healthRoutes` registers `/readyz`, `/health`, and `/health.txt` on the unauthenticated `api` router group (only rate-limiting and session middleware, no `auth.Authenticate`), while `Readyz` (with `?full=true`) and `Health` return per-service check names and raw error strings. This directly contradicts the `PublicReadyz` design intent stated in its doc comment ("to avoid leaking internal service state on publicly reachable endpoints"), since the "public" minimal-output variant coexists with the verbose, still-unauthenticated `/readyz` and `/health`.

### Finding Description
In `core/web/router.go`, the `api` group is created with only rate limiting and session middleware: [1](#0-0) 
`healthRoutes` is invoked on this `api` group with no `auth.Authenticate` wrapper, unlike `sessionRoutes`, which explicitly creates a separate `auth` sub-group with `auth.Authenticate(...)` for authenticated endpoints such as `DELETE /sessions`: [2](#0-1) 

The `Readyz` handler, when called with `?full=true`, iterates over all health-check errors and returns each check's name and `err.Error()` string as JSON: [3](#0-2) 

The `Health` handler unconditionally builds and returns the same kind of per-check name/status/error-output list (JSON, HTML, or plaintext depending on `Accept` header), with no query parameter needed to suppress details: [4](#0-3) 

By contrast, `PublicReadyz` was specifically written to strip all such detail regardless of query parameters, per its own doc comment: [5](#0-4) 

Since `/readyz`, `/health`, and `/health.txt` sit on the same unauthenticated group as `/public-readyz`, any unauthenticated caller can request `/health` or `/readyz?full=true` and receive internal service names and error text (e.g., failing chain client, DB, or subservice error messages) that `PublicReadyz` was designed to withhold from public callers.

### Impact Explanation
This is an unauthenticated information-disclosure vulnerability: internal subsystem names, health states, and raw error strings (which can include connection details, chain/RPC identifiers, or internal component names) are exposed to any network-reachable, unauthenticated caller. This maps to Chainlink's "sensitive information disclosure" bounty impact class — it reveals internal service topology/state that could aid further targeted attacks (e.g., identifying a failing/degraded subsystem to exploit), though it does not by itself grant privilege escalation or fund movement.

### Likelihood Explanation
No preconditions or credentials are required — the endpoints are on an unauthenticated router group reachable by any client that can reach the node's HTTP API (which is often exposed for load-balancer health checks). The exploit is a single GET request (`GET /health` or `GET /readyz?full=true`), fully repeatable, and requires no timing or race conditions.

### Recommendation
Restrict `/readyz` (with `?full=true`) and `/health`/`/health.txt` to authenticated/internal-only access (e.g., move them behind `auth.Authenticate` or bind them to an internal-only listener/network), or make them behave like `PublicReadyz` by stripping per-check details by default and only exposing them under an authenticated route. At minimum, apply the same "no detail leakage" design used in `PublicReadyz` to any endpoint reachable without authentication.

### Proof of Concept
Extend `core/web/health_controller_test.go`:
1. Configure a mock `Checker` whose `IsReady`/`IsHealthy` return `false` with a map containing a fake sensitive error, e.g. `map[string]error{"internal-db": errors.New("failed to connect to postgres://user:pass@host/db")}`.
2. Using an unauthenticated `app.NewHTTPClient(nil)` (no session/API key), call `GET /readyz?full=true` and assert the response body contains the check name `"internal-db"` and the error string.
3. Call `GET /health` (no auth) and assert the same leakage in JSON/HTML/plaintext depending on `Accept` header.
4. Call `GET /public-readyz?full=true` with the same failing checker and assert the body is empty (as already covered by `TestHealthController_PublicReadyz`), demonstrating the asymmetry: `/public-readyz` withholds details while `/readyz` and `/health` leak them to the same unauthenticated caller.

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {
	case gin.MIMEJSON:
		break // default

	case gin.MIMEHTML:
		if err := newCheckTree(checks).WriteHTMLTo(c.Writer); err != nil {
			hc.App.GetLogger().Errorw("Failed to write HTML health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return

	case gin.MIMEPlain:
		if err := writeTextTo(c.Writer, checks); err != nil {
			hc.App.GetLogger().Errorw("Failed to write plaintext health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return
	}

	slices.SortFunc(checks, presenters.CmpCheckName)
	jsonAPIResponseWithStatus(c, checks, "checks", status)
}
