### Title
View-role users can enumerate all External Initiators' `AccessKey` and `OutgoingToken` secrets via GET /v2/external_initiators - ([File: core/web/external_initiators_controller.go])

### Finding Description
`ExternalInitiatorsController.Index` calls `presenters.NewExternalInitiatorResource(initiator)` for every row returned from `eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)` and returns the full paginated list to the caller. [1](#0-0) 

`presenters.ExternalInitiatorResource` includes `AccessKey` and `OutgoingToken` fields taken directly from the DB-stored `bridges.ExternalInitiator` struct, and `NewExternalInitiatorResource` copies them verbatim into the JSON response. [2](#0-1) 

The underlying `bridges.ExternalInitiator` model stores `AccessKey`, `HashedSecret`, `OutgoingSecret`, and `OutgoingToken` in plaintext (except `HashedSecret`), where `OutgoingToken`/`OutgoingSecret` are the credentials the node uses to authenticate its outbound callback requests to the external initiator's webhook endpoint. [3](#0-2) 

The route `GET /v2/external_initiators` is registered under `authv2` (session/API-token auth only, not requiring edit/admin) with no role wrapper (`paginatedRequest(eia.Index)`, unlike `Create`/`Destroy` which use `auth.RequiresEditRole`). [4](#0-3) 

The route's RBAC test table explicitly confirms `viewOnlyAllowed=true` for `GET /v2/external_initiators`, meaning a user with only the `view` role is permitted to call this endpoint. [5](#0-4) 

As a result, any authenticated user with the lowest privilege role (`view`) — including users who did not create or own any given External Initiator registration — can list every EI in the node and read its `AccessKey` and `OutgoingToken`, which is a real credential used to authenticate outbound requests from the node to that EI's endpoint. Note that `OutgoingSecret`, `HashedSecret`, and the incoming `Secret` are NOT exposed by this presenter (they are only returned once, at creation time, via `NewExternalInitiatorAuthentication` in `Create`), so the exposure is partial (limited to `AccessKey` + `OutgoingToken`), not the full credential set claimed in the question. [6](#0-5) 

### Impact Explanation
A low-privileged view-role user can obtain the `OutgoingToken` (a live authentication credential used by the node to call back into the external initiator's service) belonging to EIs registered by other users/operators. This is a cross-user secret disclosure: the view-role user was never meant to see credentials for EIs they don't own. An attacker holding this token could impersonate the node's outbound authenticated callback toward that EI's webhook, matching the "key or secret disclosure" bounty impact class. `AccessKey` alone is less sensitive since it cannot authenticate without the (never re-exposed) incoming `Secret`.

### Likelihood Explanation
Precondition is minimal: any authenticated user with only `view` role (or an API token scoped to view) can call the endpoint with no additional exploitation steps — it's a simple GET request repeatable at will to enumerate all registered EIs and their `OutgoingToken` values. No auth bypass or role-escalation is needed since the route intentionally allows view role, and no per-EI ownership/ACL check exists to scope results to the requesting principal.

### Recommendation
Restrict `GET /v2/external_initiators` to require at least `edit`/`admin` role via `auth.RequiresEditRole` (consistent with `Create`/`Destroy`), or strip `OutgoingToken`/`AccessKey` from `ExternalInitiatorResource` for non-privileged roles, or redact these fields entirely from list responses (only expose them once at creation, as already done for `OutgoingSecret`/`HashedSecret`/incoming `Secret`).

### Proof of Concept
1. Start app with `ExternalInitiatorsEnabled = true`.
2. Create two external initiators via ORM (`cltest.MustInsertExternalInitiatorWithOpts`) with distinct `AccessKey`/`OutgoingToken` values, simulating ownership by different operators.
3. Create an HTTP client authenticated as a user with `Role: sessions.UserRoleView` (see `cltest.CreateUserWithRole` / test client helpers used in `auth_test.go`'s RBAC table).
4. `GET /v2/external_initiators` with that view-role session/API token.
5. Assert `http.StatusOK`.
6. Parse JSON body and assert it contains the `outgoingToken` and `accessKey` values for **both** EIs (i.e., a view-role user, not the creator, receives EI credentials it should not be entitled to see), while confirming `outgoingSecret`/`hashedSecret`/`incomingSecret` fields are absent (already redacted) — demonstrating partial but real secret disclosure to a low-privilege actor.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// ExternalInitiatorAuthentication includes initiator and authentication details.
type ExternalInitiatorAuthentication struct {
	Name           string        `json:"name,omitempty"`
	URL            models.WebURL `json:"url"`
	AccessKey      string        `json:"incomingAccessKey,omitempty"`
	Secret         string        `json:"incomingSecret,omitempty"`
	OutgoingToken  string        `json:"outgoingToken,omitempty"`
	OutgoingSecret string        `json:"outgoingSecret,omitempty"`
}

// NewExternalInitiatorAuthentication creates an instance of ExternalInitiatorAuthentication.
func NewExternalInitiatorAuthentication(
	ei bridges.ExternalInitiator,
	eia auth.Token,
) *ExternalInitiatorAuthentication {
	var result = &ExternalInitiatorAuthentication{
		Name:           ei.Name,
		AccessKey:      ei.AccessKey,
		Secret:         eia.Secret,
		OutgoingToken:  ei.OutgoingToken,
		OutgoingSecret: ei.OutgoingSecret,
	}
	if ei.URL != nil {
		result.URL = *ei.URL
	}
	return result
}
