### Title
Stale confirmations from deleted multisig members remain counted toward the confirmation threshold, allowing requests to execute below threshold - (File: `multisig/src/lib.rs`, `multisig2/src/lib.rs`)

### Summary
When a multisig key/member is removed via `DeleteKey`/`DeleteMember`, the contract only purges **requests that key originally created** (`signer_pk == pk` / `r.member == member`). It never scrubs **confirmations that the same key placed on other, still-pending requests**. Those stale confirmations continue to count toward `num_confirmations`, so a request can later execute with fewer *live* authorized confirmers than the configured threshold — the same class of bug as the reported "auction still exists even after loan paid off": a piece of state (a confirmation / an auction) that should be invalidated when its underlying condition changes (key revoked / loan repaid) is left dangling and still influences downstream settlement (request execution / liquidation).

### Finding Description
In `multisig/src/lib.rs`, `execute_request`'s `DeleteKey` branch: [1](#0-0) 
only removes requests whose `signer_pk` (the request's original creator) equals the deleted key, clearing `confirmations` for *those* requests only. It does not scan `self.confirmations` for entries where the deleted key appears as a **confirmer** of requests created by other members.

`confirm()` counts confirmations purely by set membership/size, with no re-validation that all confirming keys are still active members: [2](#0-1) 

So the binding that should hold is:
```
count(live-member confirmations on request R) >= num_confirmations  ⇒ execute R
```
But the actual code enforces only:
```
count(confirmations-ever-added on request R, including revoked keys) >= num_confirmations  ⇒ execute R
```
These diverge once any confirming key is deleted after confirming but before the request executes.

The identical pattern exists in `multisig2/src/lib.rs`'s `delete_member`, which only cleans requests filtered by `r.member == member` (the creator), not by confirmer: [3](#0-2) 
combined with `confirm()`'s unconditional counting: [4](#0-3) 

### Impact Explanation
This breaks the multisig authorization boundary: a request can be executed (fund transfer, key/member addition, function call, etc.) with fewer than `num_confirmations` *currently authorized* signers, because one or more of the counted confirmations belong to a key/member that has already been revoked. This is a multisig request executed below threshold — a Critical-severity outcome per the funds-authorization boundary (arbitrary transfers, key additions, or contract calls could be pushed through with effectively less than the required quorum of live signers).

### Likelihood Explanation
This requires no privileged/foundation/attacker-key access beyond what any multisig member already legitimately has: a member confirms a pending request (normal operation), and later any key/request removes that member (e.g., off-boarding an employee or rotating a compromised key) — a routine, expected admin action, not a misuse of privilege. No documented initialization assumption is violated, and no owner/foundation-only or social-engineering step is needed; the stale-confirmation window exists purely from the ordering of two otherwise-normal operations (confirm, then delete-member/key).

### Recommendation
When a key/member is removed, iterate all active requests' confirmation sets (not just requests it authored) and remove that key/member from any `confirmations` entries it appears in, re-evaluating threshold membership. Alternatively, validate at `confirm()`/execution time that every public key/member counted in a request's confirmation set is still present in the current member set (or `num_requests_pk`/members collection) before treating it as satisfying `num_confirmations`.

### Proof of Concept
1. Multisig initialized with `num_confirmations = 2`, members {A, B, C}.
2. B creates Request R (e.g., `Transfer`). A calls `confirm(R)` → `confirmations[R] = {A}` (1/2, not yet executed). [2](#0-1) 
3. Members (via a separate quorum-confirmed request) execute `DeleteKey { public_key: A }` to remove A (e.g., A is departing or A's key is suspected compromised). The cleanup only removes requests where `signer_pk == A`; since R was created by B, R and its confirmation set `{A}` are untouched. [1](#0-0) 
4. C calls `confirm(R)`. `confirmations[R].len() + 1 == 2 >= num_confirmations`, so R executes — even though A is no longer an authorized key and only C is a genuinely live confirmer besides the original creator B's implicit intent. [5](#0-4) 

This executes a multisig request with only one truly live, currently-authorized confirming key beyond the request creator, below the intended 2-of-3 threshold.

        self.assert_valid_request(request_id);

        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

            ********************************/

        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);

        }

    fn delete_member(&mut self, promise: Promise, member: MultisigMember) -> Promise {
        assert(
            self.members.len() - 1 >= self.num_confirmations as u64,
            "Removing given member will make total number of members below number of confirmations",
        );
        // delete outstanding requests by public_key
        let request_ids: Vec<u32> = self
            .requests
            .iter()
            .filter_map(|(k, r)| if r.member == member { Some(k) } else { None })
            .collect();
        for request_id in request_ids {
            // remove confirmations for this request
            self.confirmations.remove(&request_id);
            self.requests.remove(&request_id);
        }
        // remove num_requests_pk entry for member
        self.num_requests_pk.remove(&member.to_string());
        self.members.remove(&member);
        match member {
            MultisigMember::AccessKey { public_key } => promise.delete_key(public_key.into()),
            MultisigMember::Account { account_id: _ } => promise,
        }
    }
