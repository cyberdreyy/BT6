### Title
Integer overflow in `pprofURLVals` timeout computation allows unbounded/unpredictable proxied-request duration - ([File: core/web/loop_registry.go])

### Finding Description
`pprofURLVals` parses the `seconds` query parameter with `strconv.Atoi` and, only if parsing succeeds, computes `timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second` [1](#0-0) . For a query value that overflows `strconv.Atoi`'s range (e.g. `99999999999999999999`), `ParseInt` returns a non-nil `ErrRange` error, so the `err == nil` guard correctly rejects it and the default `PPROFOverheadSeconds * time.Second` (30s) is used — this specific "very large decimal string" case in the question is **not** exploitable because the error check blocks it.

However, a value that is a *valid* `int` but close to `math.MaxInt64` (e.g. `seconds=9223372036854775807`) passes the `err == nil` check. The subsequent `i + PPROFOverheadSeconds` addition and `time.Duration(...) * time.Second` multiplication are unchecked signed-integer arithmetic that silently wraps in Go, producing an unpredictable (and potentially huge, or unpredictable sign) `timeout` value that is then passed straight into `context.WithTimeout(gc.Request.Context(), timeout)` in `doRequest` [2](#0-1) . There is no clamping or upper/lower bound check on the computed timeout before it is used to bound the proxied HTTP request to the internal plugin pprof endpoint. `doRequest` also uses `http.DefaultClient` (which has no built-in timeout), relying entirely on the `ctx` deadline for bounding request duration [3](#0-2) .

### Impact Explanation
If the wrapped arithmetic yields a very large positive duration, a single request can force the server to hold open a goroutine and TCP connection to the internal plugin for a duration far beyond the intended ~30s+seconds cap, tying up server resources per request and enabling a low-cost resource-exhaustion/DoS vector if this endpoint is reachable without privileged access. This matches a scoped "denial-of-service via unauthenticated/low-privilege single request" bounty class, but is limited to whatever authorization gate protects `/plugins/:name/debug/pprof/*` in the router.

### Likelihood Explanation
I was unable to fully confirm from the available index whether the `/plugins/:name/debug/pprof/*` route is registered behind session/API-token authentication middleware in `core/web/router.go` (grep matches were found but I could not retrieve the surrounding route-group/auth context before running out of iterations). If this endpoint requires authenticated operator access, the practical severity is much lower since it would need a valid session/API-token role rather than being fully unauthenticated. This is a material uncertainty that should be verified before treating this as fully unauthenticated-exploitable.

### Recommendation
- Reject or clamp `seconds` values instead of relying on `strconv.Atoi`'s error alone; validate the parsed value against a sane upper/lower bound (e.g. `0 <= i <= maxAllowedSeconds`) before using it in duration arithmetic.
- Use overflow-safe arithmetic (or perform the addition/multiplication in a wider representation and check bounds) before constructing `time.Duration`.
- Cap the final computed `timeout` passed to `context.WithTimeout` to a fixed maximum (e.g. a few minutes) regardless of user input.
- Confirm and, if missing, enforce authentication/authorization on the plugin pprof proxy routes in `core/web/router.go`.

### Proof of Concept
Table-driven Go unit test directly against `pprofURLVals`:
```go
func TestPprofURLVals_Overflow(t *testing.T) {
    cases := []struct{
        seconds string
    }{
        {"99999999999999999999"},           // exceeds int64 range -> Atoi errors, should stay at default
        {strconv.FormatInt(math.MaxInt64, 10)}, // valid int64, triggers overflow in i+PPROFOverheadSeconds
        {"-40"},                            // negative timeout after +30
    }
    for _, c := range cases {
        gc := ginContextWithQuery(map[string]string{"seconds": c.seconds})
        _, timeout := pprofURLVals(gc)
        assert.True(t, timeout >= 0, "timeout must not be negative for input %s", c.seconds)
        assert.True(t, timeout <= 5*time.Minute, "timeout must be bounded for input %s", c.seconds)
    }
}
```
Expected (current) result: the `math.MaxInt64` case fails the bound assertion due to wraparound arithmetic, demonstrating the unchecked overflow; after applying bounds-checking/clamping in `pprofURLVals`, all cases pass.

	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)

		return
	}
	res, err := http.DefaultClient.Do(req)

		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))

	}
