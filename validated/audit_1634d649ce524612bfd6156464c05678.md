### Title
Aggregated-weight block acceptance bypasses the signer's own chainstate/conflict re-check, letting a rejecting/unvalidated signer be forced into accepting and pushing a conflicting block - (File: `stacks-signer/src/v0/signer.rs`)

### Summary
`store_and_process_block_signature` marks a block `LocallyAccepted` and broadcasts it to the node purely because the *sum of other signers' signature weight* crosses the 70% threshold, without ever calling `check_block_against_signer_db_state` (the conflict/tenure-tip re-check that guards every other path that produces a signature or a push to the node). This breaks the "aggregated-weight vs verified-accepts" equality: reaching the weight threshold is treated as sufficient proof of safety even when the local signer's own DB state says otherwise.

### Finding Description
Every other path that ends in a signature or a push to the node performs a fresh safety re-check immediately beforehand:
- The pre-commit → signature path calls `check_block_against_signer_db_state` and then `get_signed_conflicts`/`conflict_still_blocks`/`reorg_permit_stands` before calling `mark_locally_accepted` [3](#0-2) .
- `handle_block_validate_ok` re-checks `check_block_against_signer_db_state` before even pre-committing [4](#0-3) .

But `store_and_process_block_signature`, invoked from `handle_block_signature` whenever a peer's `BlockAccepted` message is received, only checks weight arithmetic: [5](#0-4) 

Once `min_weight <= total_signature_weight`, it unconditionally calls `block_info.mark_locally_accepted(true)` and `broadcast_signed_block`, which calls `handle_post_block` → `stacks_client.post_block(block)` with **no call to `check_block_against_signer_db_state`, `get_signed_conflicts`, or any tenure/height conflict logic**. `BlockInfo::check_state` explicitly permits `LocallyRejected -> LocallyAccepted` [6](#0-5) , so a block this very signer already flagged and rejected via `mark_locally_rejected` (e.g. because `check_block_against_signer_db_state` found it conflicts with an already-signed sibling, or its tenure lost the reorg race) can be silently flipped to `LocallyAccepted` and physically pushed to the local stacks-node the moment enough *other* signers' signatures accumulate — none of which necessarily incorporate the newer information that caused this signer's own rejection, since each signer's rejection reasoning is derived from its own, possibly more up-to-date, local chainstate view.

This is the direct analog of the Sherlock report's core defect: a state-mutating path (`transferPosition`) that performs the "did the right party ask for this" bookkeeping (a `require`/weight check) but skips the semantic safety check (`address(0)`) that every sibling path enforces. Here, the semantic safety check that is skipped is the conflict/tenure re-validation that gates every other acceptance path.

### Impact Explanation
This can cause a signer to push a block to its own node's `/v3/block/postblock` endpoint (i.e. treat it as canonical/accepted) that its own chainstate logic has already determined is a conflicting sibling or otherwise unsafe — the "rejection recounted as an accept" impact class. Because the check is entirely omitted (not merely weakened), the signer's local safety invariant that "no acceptance/broadcast happens without `check_block_against_signer_db_state` passing" is broken specifically on the aggregated-weight path, undermining the guarantee documented for every other path in `docs/signer-flows.md` sections 4 and 5.

### Likelihood Explanation
No majority collusion or malicious key is required: this triggers whenever legitimate, correctly-signed `BlockAccepted` messages (from honest peers who signed before observing a conflict, or under a race with `handle_block_pre_commit`'s conflict logic) arrive after this signer has already locally rejected the same `signer_signature_hash` for chainstate reasons. `store_and_process_block_signature` is called on every incoming `BlockAccepted`/self-signature event [7](#0-6) , so the gap is on the hot path of normal peer-message processing, not a rare corner case.

### Recommendation
Before calling `block_info.mark_locally_accepted(true)` and `broadcast_signed_block` in `store_and_process_block_signature`, re-run `check_block_against_signer_db_state` (mirroring the pre-commit path at lines 1345-1366) and abort the broadcast/acceptance (instead reporting the rejection) if the block now fails that check.

### Proof of Concept
1. Signer S validates block B, detects (via `check_block_against_signer_db_state`) that B conflicts with an already-signed sibling at the same height, and calls `mark_locally_rejected` (allowed transition per `check_state`, `stacks-signer/src/signerdb.rs:313-329`).
2. Several other honest signers, whose local pre-commit conflict recheck ran earlier (before the sibling was signed) or under a race window, still produce valid `BlockAccepted` signatures over B and gossip them.
3. Each such message reaches S's `handle_block_signature` → `store_and_process_block_signature` (`stacks-signer/src/v0/signer.rs:2372-2538`). S stores each signature via `add_block_signature` and recomputes `total_signature_weight`; once it crosses `min_weight`, S executes `mark_locally_accepted(true)` (overriding its own `LocallyRejected` state) and `broadcast_signed_block` → `handle_post_block` → `stacks_client.post_block(block)`, pushing the block S had itself flagged as conflicting straight to its own node, with zero re-check of the conflict it detected in step 1.

    /// Attempt to post a block to the stacks-node and handle the result
    pub fn handle_post_block(&mut self, stacks_client: &StacksClient, block: &NakamotoBlock) {
        #[cfg(any(test, feature = "testing"))]
        if self.test_skip_block_broadcast(block) {
            return;
        }
        let block_hash = block.header.signer_signature_hash();
        match stacks_client.post_block(block) {
            Ok(accepted) => {
                debug!("{self}: Block {block_hash} accepted by stacks node: {accepted}");
                if let Err(e) = self
                    .signer_db
                    .set_block_broadcasted(&block_hash, get_epoch_time_secs())
                {
                    warn!("{self}: Failed to set block broadcasted for {block_hash}: {e:?}");
                }
            }
            Err(e) => {
                warn!("{self}: Failed to broadcast block {block_hash} to the node: {e}")
            }
        }
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
