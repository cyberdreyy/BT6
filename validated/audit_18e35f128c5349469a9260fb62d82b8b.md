### No vulnerability found for this question.

The `LendingPoolConfigureBank` accounts struct enforces `has_one = admin @ MarginfiError::Unauthorized` on `group` and `has_one = group @ MarginfiError::InvalidGroup` on `bank` [1](#0-0) . These Anchor account constraints are validated during account deserialization, before `lending_pool_configure_bank`'s instruction body ever runs [2](#0-1) . This means any signer who is not the exact `admin` stored in the targeted `MarginfiGroup`, or any `bank` account not bound to that `group` via `has_one`, causes the transaction to fail with `Unauthorized` or `InvalidGroup` at the account-validation stage — no protected field of the `Bank` account (deposit/borrow limits, weights, oracle config, asset tag, etc.) is touched before this check, since `bank.load_mut()` and the subsequent `configure`/`configure_unfrozen_fields_only` calls only happen after successful account validation [3](#0-2) .

There is no "late binding" or deferred authorization check in this instruction — authority and bank/group binding are both resolved atomically by Anchor before any state mutation, so a replay under a different, unprivileged signer cannot reach the configuration-writing code path at all.

pub fn lending_pool_configure_bank(

    bank_config: BankConfigOpt,
) -> MarginfiResult {

    // If settings are frozen, you can only update the deposit and borrow limits, everything else is ignored.
