## Title
Unprivileged front-running of `LockupFactory::create` permanently squats a victim's deterministic lockup address with `vesting_schedule=None` / `foundation_account_id=None` - (`lockup-factory/src/lib.rs`)

## Summary
`LockupFactory::create` derives the lockup account name deterministically from only `owner_account_id` (`sha256(owner_account_id)[..20]` hex-encoded, `.{factory}`), with no check on `predecessor_account_id` or on whether the deployment matches any authorized grant plan. Any unprivileged account can call `create` first with `owner_account_id = victim.near` and `vesting_schedule = None`, paying only the `MIN_ATTACHED_BALANCE` (3.5 NEAR), permanently occupying that address before the legitimate, vesting-carrying grant transaction can land.

## Finding Description
Binding claimed: `LockupArgs.vesting_schedule` (deployed) == the vesting terms the entitled grantor configured for `owner_account_id`, and `LockupArgs.foundation_account_id` == `Some(foundation_account_id)` whenever a vesting schedule was intended.

Code path:
- `create()` computes the lockup account deterministically from `owner_account_id` alone: [1](#0-0) 
- `foundation_account_id` in the deployed `LockupArgs` is only set `Some(...)` when the caller-supplied `vesting_schedule` argument `is_some()`: [2](#0-1) 
- There is no restriction on who may call `create`, nor any binding between `predecessor_account_id` and `owner_account_id`; anyone can supply any `owner_account_id` and any `vesting_schedule` (including `None`): [3](#0-2) 
- The deployment is a `Promise::new(lockup_account_id).create_account()...`. `create_account` on an already-existing account fails the receipt, and the failure is handled purely as a deposit-refund case in the callback, with no re-check of address ownership intent: [4](#0-3) 
- The lockup contract's `new()` only enforces internal consistency (foundation set iff vesting present), not that the caller was authorized to pick these terms for this `owner_account_id`: [5](#0-4) 

Exploit flow:
1. Attacker learns (or predicts) that `victim.near` is slated to receive a vesting grant.
2. Attacker calls `create(owner_account_id="victim.near", lockup_duration=..., vesting_schedule=None, ...)` attaching only `MIN_ATTACHED_BALANCE`, before the foundation/grantor's funding transaction executes.
3. The deterministic address `sha256("victim.near")[..20].lockup-factory` gets created with `vesting_information = VestingInformation::None` and `foundation_account_id = None`, and `owner_account_id = "victim.near"`.
4. When the legitimate grantor later calls `create` with the real vesting schedule and full grant deposit for the same `owner_account_id`, `create_account()` fails because the account already exists; the whole receipt fails and the deposit is refunded to the legitimate caller via `on_lockup_create`'s failure branch — the grant can never be deployed at the canonical address for `victim.near` on that factory.

No existing guard (`assert_self()`, `is_promise_success()`, deposit-amount check) prevents this because none of them check identity of the caller against `owner_account_id`, nor lock the address to a pre-committed vesting configuration.

## Impact Explanation
This matches the Critical category "a lockup deployed with parameters its rightful creator never chose." The termination/vesting right that the NEAR Foundation (or other grantor) is entitled to configure for `owner_account_id` is permanently and irreversibly stripped for that specific account name on this factory, since lockup account names are unique per `owner_account_id` and the factory cannot redeploy over an existing account. The blast radius is global: any account name that is publicly known to be a future grant recipient can be squatted by anyone at low cost (3.5 NEAR), and this is repeatable across every distinct `owner_account_id`/victim.

## Likelihood Explanation
The precondition is simply that the attacker knows or predicts the `owner_account_id` before the legitimate grant is deployed — plausible for known employees, public grant recipients, or announced allocations. Cost is only `MIN_ATTACHED_BALANCE` (3.5 NEAR) plus gas, no special privileges or victim keys required, and `create` is a fully public, unauthenticated method as shown above.

## Recommendation
Bind lockup creation to an authorized initiator: e.g., require `predecessor_account_id` to be the `foundation_account_id` (or another explicitly whitelisted grantor) whenever a vesting schedule/foundation right is intended, or require the creation call itself to be signed/initiated by the entitled grantor rather than allowing any account to pre-create a "vesting-free" lockup for an arbitrary `owner_account_id`. Alternatively, incorporate a grantor-controlled salt/nonce into the account-name derivation so squatting an address requires collusion with, or a prior commitment from, the entitled party.

## Proof of Concept
```rust
// lockup-factory/src/lib.rs tests module (extending existing tests)
#[test]
fn test_attacker_squats_victim_lockup_without_vesting() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());

    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    const LOCKUP_DURATION: u64 = 63036000000000000;
    let lockup_duration: WrappedTimestamp = LOCKUP_DURATION.into();

    // Attacker (unrelated account) squats victim's deterministic lockup address
    // with vesting_schedule = None, using only the minimum deposit.
    context.is_view = false;
    context.predecessor_account_id = String::from("attacker.testnet");
    context.attached_deposit = MIN_ATTACHED_BALANCE; // 3.5 NEAR
    testing_env!(context.clone());
    contract.create(
        account_tokens_owner(), // "victim" owner_account_id
        lockup_duration,
        None,
        None, // <-- attacker chooses vesting_schedule = None
        None,
        None,
    );

    // Confirm deployed LockupArgs would have foundation_account_id = None
    // (captured via the serialized function_call args / or by asserting
    // the deployed lockup's `get_foundation_account_id` view returns None
    // after simulating the deploy in a near-workspaces/near-sdk-sim test),
    // while the legitimate grant plan required Some(foundation_account_id).

    // Now simulate the legitimate grantor's later attempt for the SAME owner:
    context.predecessor_account_id = String::from("legit_funder.testnet");
    context.attached_deposit = ntoy(1_000_000); // full grant amount
    testing_env!(context.clone());
    let vesting_schedule = Some(VestingScheduleOrHash::VestingHash(/* real hash */ vec![0u8;32].into()));
    contract.create(
        account_tokens_owner(),
        lockup_duration,
        None,
        vesting_schedule,
        None,
        None,
    );
    // Simulate create_account() failing because the account already exists:
    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed);
    let res = contract.on_lockup_create(
        lockup_account(),
        ntoy(1_000_000).into(),
        String::from("legit_funder.testnet"),
    );
    assert_eq!(res, false); // legitimate grant is refunded, never deployed
    // Assert: deployed lockup at `lockup_account()` still has
    // foundation_account_id == None / vesting_information == VestingInformation::None,
    // permanently diverging from the intended Some(foundation_account_id) binding.
}
```

    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
