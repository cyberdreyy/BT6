### Title
Griefing operator/shareholder can permanently freeze staker's stake in `staking_contract` by disabling direct coin transfers - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` pays out every shareholder of a pool's `distribution_pool` (staker, operator, and any past operators still owed dust/commission) via `aptos_account::deposit_coins` inside a single atomic loop. `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient has never registered a `CoinStore<AptosCoin>` and has explicitly opted out of unsolicited coin transfers via `aptos_account::set_allow_direct_coin_transfers(signer, false)`. Any shareholder — most naturally the operator — can pre-configure their own address this way, fully unprivileged, before or after being assigned to a staking contract. Because `unlock_stake`, `switch_operator`, `request_commission`, and `distribute` all call `distribute_internal` first and the whole transaction reverts on any failed deposit, the operator can permanently block the staker (and themselves) from ever withdrawing stake through this module once any commission value has accrued into the distribution pool. This is the Move/Aptos analog of the GoGoPool `cancelMinipoolByMultisig` push-payment DoS: a party can grief a shared multi-party payout to prevent state transitions others depend on.

### Finding Description
`distribute_internal` in `staking_contract.move` (lines 855-920) redeems every shareholder from the `distribution_pool` and pushes their share of the unlocked coins with `aptos_account::deposit_coins`: [1](#0-0) 

`aptos_account::deposit_coins` aborts if the recipient has no `CoinStore<CoinType>` registered *and* has disabled direct transfers via `can_receive_direct_coin_transfers`: [2](#0-1) 

Any signer can unprivilegedly flip this flag for their own address, with no requirement that a `CoinStore` ever be registered: [3](#0-2) 

`distribute_internal` is invoked, unconditionally and non-optionally, at the start of every state-changing entry point that touches the staking contract's funds:
- `unlock_stake` (staker's own withdrawal path) forces `distribute_internal` before computing the withdrawal amount: [4](#0-3) 
- `switch_operator` (staker's only way to move away from a bad operator) also forces `distribute_internal` on the old operator's pool before it can remove/re-add the contract: [5](#0-4) 
- `request_commission` and the public `distribute` entry function likewise route through `distribute_internal`: [6](#0-5) 

Additionally, `update_distribution_pool` (called from both `add_distribution` and `distribute_internal`) automatically transfers commission-equivalent shares to the operator on *every* value increase of the pool — even without the operator ever calling `request_commission` — so the operator will hold nonzero shares in `distribution_pool` as soon as the pool has accrued any reward-driven value change: [7](#0-6) 

Since the entire `distribute_internal` loop is inside one atomic Move transaction, one failing recipient (the griefing operator) aborts the whole call, including the redemption of the staker's own, unrelated shares in the same pool. Because the staker never holds `owner_cap` directly (it is held inside the `StakingContract` resource, only reachable through these gated entry functions), there is no alternate path for the staker to reach their locked stake.

### Impact Explanation
A malicious or simply uncooperative operator can permanently strand a staker's principal and rewards inside a `staking_contract` stake pool. Once any commission value has flowed into the `distribution_pool` (which happens automatically as rewards accrue, not only via explicit `request_commission`), the operator's un-receivable address becomes a shareholder that must be paid on every subsequent call to `unlock_stake`, `switch_operator`, `request_commission`, or `distribute`. This blocks:
- The staker's ability to unlock or withdraw their own stake (`unlock_stake`/`unlock_rewards`).
- The staker's only remedy of moving to a different operator (`switch_operator`/`switch_operator_with_same_commission`).
- Payment of legitimate future commission to the operator itself (self-inflicted, but also griefs the staker).

This is a "permanent lock or non-recoverable loss of claim rights in stake ... flows," matching the required impact category, and it requires no privileged role — only a signer controlling the operator address (or any account that accrues distribution-pool shares) calling a fully public, unprivileged function (`set_allow_direct_coin_transfers`).

### Likelihood Explanation
High likelihood: `set_allow_direct_coin_transfers(signer, false)` is a standard, fully public, unprivileged framework function that any account can call on itself at any time, and never registering `CoinStore<AptosCoin>` requires no special setup — it's simply not calling `coin::register`. An operator address chosen for a `staking_contract` (or an existing operator) can proactively configure itself this way, either maliciously to hold a staker's funds hostage, or inadvertently (e.g., an account created purely as a signer/multisig that intentionally restricts unsolicited deposits for security reasons, unaware it holds an operator role). No governance or admin assumption is required, and the code path is reachable by any staker who has entered a `create_staking_contract` relationship with such an operator.

### Recommendation
Change `distribute_internal` to use a pull-over-push accounting model for the shares that fail to deposit: instead of aborting the whole distribution when `aptos_account::deposit_coins` would fail for one recipient, catch that recipient's inability to receive (e.g., via `coin::is_account_registered` and `aptos_account::can_receive_direct_coin_transfers` checks) and route their share into an escrow/claimable balance the recipient can pull later, rather than looping a push-transfer that can block all other shareholders' redemptions in the same transaction. At minimum, `unlock_stake` and `switch_operator` should not require the operator's own commission payout to succeed before allowing the staker to redeem their unrelated, independent shares.

### Proof of Concept
1. Operator `O` calls `aptos_account::set_allow_direct_coin_transfers(O, false)` on a fresh account that has never called `coin::register<AptosCoin>`.
2. Staker `S` calls `staking_contract::create_staking_contract(S, O, voter, 100, 10, seed)`, creating a staking contract with 10% commission to `O`.
3. `O` joins the validator set; an epoch passes and the stake pool accrues rewards, which via `update_distribution_pool` grants `O` nonzero shares in `distribution_pool` even without `O` calling `request_commission`.
4. `S` calls `staking_contract::unlock_stake(S, O, amount)` to withdraw part of their principal.
5. Internally, `unlock_stake` calls `distribute_internal`, which iterates `distribution_pool`'s shareholders, reaches `O`, and calls `aptos_account::deposit_coins(O, coins)`.
6. Since `O` has no `CoinStore<AptosCoin>` and `can_receive_direct_coin_transfers(O) == false`, this call aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, reverting the entire transaction.
7. `S` retries `unlock_stake`, `switch_operator`, and `distribute` — all abort identically, because they all force `distribute_internal` first. `S`'s stake principal remains permanently locked in the pool as long as `O` keeps direct transfers disabled and unregistered.

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
