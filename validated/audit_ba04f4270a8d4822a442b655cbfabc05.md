### Title
Global `savedCallbacks` map keyed only by attacker-controlled `MessageId` allows cross-user response hijack / denial of response delivery - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` stores each user request's callback in a single shared `map[string]*savedCallback` keyed solely by `msg.Body.MessageId`, a value fully controlled by the requester and validated only for length/charset, not uniqueness or ownership [1](#0-0) . Because the map is shared across all senders to the DON and the write is an unconditional overwrite, any unprivileged, signed gateway client can submit a request whose `MessageId` matches a victim's still-pending `MessageId`, silently replacing the victim's saved callback with the attacker's before the DON node responds.

### Finding Description
`api.Message.Validate()` only checks that `MessageId` is non-empty, ≤128 bytes, and doesn't end in a null byte — it never enforces randomness/uniqueness and it computes `Sender` independently from the ECDSA signature, with no binding between `Sender` and `MessageId` [2](#0-1) . `ValidatedMessageFromReq` simply copies the caller-supplied JSON-RPC `ID` into `msg.Body.MessageId` [3](#0-2) .

In `handler.HandleLegacyUserMessage`, after validation the handler unconditionally writes into the shared map:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [1](#0-0) 

There is no check for an existing entry with the same key, and no check that the existing entry (if any) belongs to the same sender. Any second unprivileged request bearing the same `MessageId` as a victim's in-flight request instantly clobbers the victim's `savedCallback` (which holds the victim's response callback/connection), before the map's `sync.Mutex`-protected read side (`handleWebAPITriggerMessage`) ever fires:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageId]
delete(h.savedCallbacks, msg.Body.MessageId)
h.mu.Unlock()
if found {
    return savedCb.SendResponse(...)
}
``` [4](#0-3) 

When the targeted DON node eventually replies to that `MessageId`, the map lookup now resolves to the attacker's saved callback (the victim's was overwritten), so:
1. The victim's original callback reference is lost — the victim never receives the DON's response ("never receive their node's legitimate response").
2. The DON's response payload (which may contain execution results/data intended for the victim) is instead delivered to the attacker's connection — cross-user response confusion.

This is a stronger and more direct variant of the eviction/prune scenario described in the question: the attacker does not even need to fill `MaxSavedCallbacks` or race the `CallbackPruneIntervalSec` ticker — a single well-timed request with the victim's exact `MessageId` string achieves immediate overwrite. The additional flood-based eviction path (via `pruneCallbacks` trimming to `maxSize/2` when `len(savedCallbacks) > MaxSavedCallbacks`, see `pruneCallbacks` at lines 299-339) provides a secondary, probabilistic mechanism to evict a victim's entry early, but the direct key-collision overwrite above is the deterministic root cause: the map's uniqueness invariant depends entirely on `MessageId` never colliding across independent senders, and nothing in the code enforces that.

### Impact Explanation
Scoped impact: denial of response delivery to a targeted victim, and potentially disclosure of the victim's DON node response payload to the attacker (cross-user response confusion). This matches Chainlink's bounty class for "cross-user response confusion / unauthorized access to another user's job data" since the attacker (an unprivileged, arbitrary signed gateway client) can, without any elevated role, hijack a specific victim's pending webapi-trigger response by guessing or observing the victim's `MessageId` and racing a same-ID request into the shared handler.

### Likelihood Explanation
Exploitability requires only: (1) any valid signing key able to send gateway/DON node messages that reach `HandleLegacyUserMessage` (no special role, matches the "unprivileged attacker" threat model), and (2) knowledge of the victim's `MessageId` value, which is attacker/client-chosen and often predictable/sequential per the question's premise, or observable (e.g., echoed back in earlier interactions, or reused patterns). No signature forgery is needed — the attacker signs their own request with their own key; the overwrite works purely due to the shared unkeyed-by-sender map. This makes the attack reliably reproducible with a simple two-request race, higher likelihood than the flood-to-`MaxSavedCallbacks` variant.

### Recommendation
Namespace `savedCallbacks` keys by `(Sender, MessageId)` instead of `MessageId` alone, or reject/generate-server-side a `MessageId` if one already exists in the map instead of silently overwriting it in `HandleLegacyUserMessage`. Additionally, consider deriving `MessageId` server-side (e.g., UUID) rather than trusting client input for map-key purposes, and add an explicit check in the write path (line 412) that returns an error/collision response when `msg.Body.MessageId` already has a live entry for a different sender.

### Proof of Concept
Go handler-level integration test plan (extends `core/services/gateway/handlers/capabilities/handler_test.go`):
1. Instantiate `handler` with default config via `NewHandler`.
2. Craft `msgVictim` with `MessageId = "12345"`, signed by victim's private key, method `MethodWebAPITrigger`; call `h.HandleLegacyUserMessage(ctx, msgVictim, victimCallback)` where `victimCallback` is a mock `handlers.Callback` capturing `SendResponse` calls.
3. Before the DON responds, craft `msgAttacker` with the same `MessageId = "12345"`, signed by attacker's own key (different sender), and call `h.HandleLegacyUserMessage(ctx, msgAttacker, attackerCallback)`.
4. Assert `h.savedCallbacks["12345"].Callback == attackerCallback` (not `victimCallback`) — proving overwrite occurred without any ownership check.
5. Simulate the DON node responding to `MessageId = "12345"` via `h.HandleNodeMessage` with `MethodWebAPITrigger`; assert `attackerCallback.SendResponse` was invoked and `victimCallback.SendResponse` was never called — proving the victim never receives its response and the attacker receives it instead.
6. Assert no error/log path in `HandleLegacyUserMessage` currently rejects the second (colliding) write, confirming the missing collision/ownership check at handler.go lines 411-414.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageId) == 0 || len(m.Body.MessageId) > MessageIdMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageId, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonId) == 0 || len(m.Body.DonId) > MessageDonIdMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonId, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
