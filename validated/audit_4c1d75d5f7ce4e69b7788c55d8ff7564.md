### Title
Zip-slip in `extractZipFile`/`ExtractZipArchive` allows cache/artifact extraction to write files outside `CacheDir`/`RootDir`, bypassing `changeFilesOwnership` — (File: `helpers/archives/zip_extract.go`)

### Summary
`extractZipFile` and `ExtractZipArchive` in `helpers/archives/zip_extract.go` use the zip entry's raw `file.Name` with no path-containment check, unlike the sibling `tarzstd` extractor which explicitly enforces a chroot boundary. The legacy zip extractor (`commands/helpers/archive/ziplegacy/zip_legacy_extractor.go`) forwards directly into this unsafe function and completely ignores the `dir` parameter it is supposed to sandbox extraction to, so a crafted cache/artifact zip can write files anywhere the helper process can write — outside the two directories (`CacheDir`, `RootDir`) that `AbstractShell.cacheExtractor`/`downloadAllArtifacts` later `chown -R` via `changeFilesOwnership`.

### Finding Description
`extractZipFile` builds the destination path straight from the archive entry, with no join against nor validation against a base directory: [1](#0-0) 

`extractZipFileEntry`/`extractZipSymlinkEntry`/`extractZipDirectoryEntry` then `os.Create`/`os.Symlink`/`os.Mkdir` directly on `file.Name`: [2](#0-1) 

`ExtractZipArchive` iterates all entries and calls `extractZipFile` for each, with the only special-case check being a `.git`-directory warning, not a containment check: [3](#0-2) 

This is in stark contrast to `tarzstd`'s extractor, which explicitly resolves each entry against its target dir and rejects escapes: [4](#0-3) 

The legacy zip extractor, which implements the `archive.Extractor` interface (whose contract states "The extractor will extract files to the directory provided"), stores `dir` but never uses it in `Extract`, forwarding straight into the unsafe path: [5](#0-4) [6](#0-5) 

The call chain matches the question's description: `AbstractShell.cacheExtractor` (and `downloadAllArtifacts`) writes cache-extraction shell code that invokes the `cache-extractor` internal CLI, then unconditionally runs `changeFilesOwnership` over only `CacheDir`/`RootDir`: [7](#0-6) [8](#0-7) 

Because the zip extraction path performs no containment check (and, for the legacy zip path, ignores the target directory entirely), a malicious zip entry named e.g. `../../../../tmp/evil.sh` or an absolute path can be written outside `CacheDir`/`RootDir`. `changeFilesOwnership`'s `chown -R` is scoped only to those two directories, so the planted file retains helper-container ownership/permissions and is never normalized to build-container ownership — landing outside the intended jail on any host/volume shared across jobs/pipelines (docker/kubernetes executors with a helper container sharing a volume with the build container).

### Impact Explanation
An attacker who controls the content of a downloaded cache archive (e.g., by uploading a crafted zip to the cache storage backend using the job's presigned cache URL, replacing the runner-generated archive) can cause the extraction step to plant arbitrary files at attacker-chosen paths outside the managed build/cache tree. On docker/kubernetes executors where the helper container's filesystem/volume is shared with the build container (or persists on a shared host path across job runs), this results in a file with helper-container ownership/permissions sitting outside any directory the runner subsequently ownership-normalizes or cleans, potentially readable/executable by a later job reusing the same shared volume/host path — a persistent artifact outside the runner's trust boundary.

### Likelihood Explanation
Preconditions: docker or kubernetes executor with a helper container that shares a volume/host path with the build container, and attacker control over cache archive bytes (achievable by a normal pipeline author since caches are fetched via presigned URLs the job itself has access to, allowing substitution of the archive content before the runner's `cache-extractor` step downloads and extracts it). The zip-slip write itself requires no additional privilege — `extractZipFile` performs no path validation at all, so exploitation is deterministic and repeatable, and the legacy zip extractor's outright disregard for the `dir` parameter makes this a structural (not edge-case) flaw for zip archives.

### Recommendation
Add the same containment logic used in `tarzstd_extractor.go` to `helpers/archives/zip_extract.go`: resolve each `file.Name` against an explicit target directory with `filepath.Join` + `filepath.Abs`, and reject/skip any entry whose resolved path does not have the target directory as a strict prefix, before any `Mkdir`/`Create`/`Symlink` call. Additionally, fix `ziplegacy.extractor.Extract` to actually pass/use its stored `dir` field (chdir into it, or thread it through to `ExtractZipArchive`) so the `archive.Extractor` interface contract is honored, and add a regression test asserting that path-traversal and absolute-path zip entries never escape the extraction root.

### Proof of Concept
Go unit test in `helpers/archives/zip_extract_test.go`:
```go
func TestExtractZipFile_PathTraversal(t *testing.T) {
    tempDir := t.TempDir()
    outsideMarker := filepath.Join(tempDir, "..", "zip_slip_pwned.txt")
    defer os.Remove(outsideMarker)

    testOnArchive(t, func(t *testing.T, archive *zip.Writer) {
        w, err := archive.Create("../zip_slip_pwned.txt")
        require.NoError(t, err)
        _, err = w.Write([]byte("pwned"))
        require.NoError(t, err)
    }, func(t *testing.T, fileName string) {
        wd, _ := os.Getwd()
        defer os.Chdir(wd)
        os.Chdir(tempDir)

        err := ExtractZipFile(fileName)
        require.NoError(t, err) // currently succeeds, proving no containment check

        _, statErr := os.Stat(outsideMarker)
        assert.False(t, os.IsNotExist(statErr), "file must NOT be created outside extraction root")
    })
}
```
Expected (post-fix) assertion: `ExtractZipFile`/`ExtractZipArchive` must return an error (or skip the entry) for any zip entry resolving outside the target directory, and `outsideMarker` must not exist. Currently the test demonstrates the file is created outside the root, confirming the vulnerability.

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

func (b *AbstractShell) changeFilesOwnership(w ShellWriter, info common.ShellScriptInfo, dir ...string) {
	// The shell is not set the same way depending on the unit test
	// Some unit tests use info->Build->Runner->Shell while other use info->Shell
	shellName := info.Shell
	if shellName == "" {
		// GetDefaultShell will panic, if it can't find a default shell
		shellName = info.Build.Runner.Shell
	}

	// umask 0000 disabling is only support for UNIX-Like shells
	// We therefore don't do anything for PowerShell/pwsh
	if slices.Contains([]string{SNPowershell, SNPwsh}, shellName) {
		return
	}

	// ensure all parts are quoted with single quotes, so that whitespaces
	// and all don't trip us up and to ensure no unwanted variable expansion is happening
	unquotedUidGidFile := fmt.Sprintf(`%s/%s`, info.Build.RootDir, BuildUidGidFile)
	quotedUidGidFile := fmt.Sprintf(`'%s'`, unquotedUidGidFile)

	// unquotedUidGidFile file is only created when FF_DISABLE_UMASK_FOR_KUBERNETES_EXECUTOR is enabled
	w.IfFile(unquotedUidGidFile) // IfFIle does use `%q` internally
	for _, d := range dir {
		if strings.TrimSpace(d) == "" {
			continue
		}
		w.IfDirectory(d)
		w.Line(fmt.Sprintf(`chown -R "$(stat -c '%%u:%%g' %s)" '%s'`, quotedUidGidFile, d))
		if info.Build.IsDebugModeEnabled() {
			w.Line(fmt.Sprintf(`echo "Setting ownership for %s to $(stat -c '%%u:%%g' %s)"`, d, quotedUidGidFile))
		}
		w.EndIf()
	}
	w.EndIf()
}
