### Title
Unfunded instant-withdraw receipts from older epochs are excluded from default recovery basis, inflating `defaultRecoveryPrice` and permanently freezing honest claims - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`defaultPendingClaimBasis()` computes the instant-withdraw claim basis using only `instantWithdrawClaimsByEpoch[epochNumber]` — the current (defaulted) epoch. `pendingInstantWithdraws`, however, is an aggregate that can carry unfunded instant receipts from earlier epochs when `collectInstantWithdrawFunds` collects only part of the pending amount at `startEpoch`. Recovery finalization therefore reads an out-of-scope (too narrow) epoch index, mirroring the out-of-bounds/incorrectly-scoped read class of CVE-2018-11737: a stale/aggregate counter is treated as belonging to a single index. The inflated `defaultRecoveryPrice` overpays active LPs and default-epoch claimants, and the missing basis is never payable afterward.

### Finding Description
At epoch start, `IdleCreditVault.collectInstantWithdrawFunds` reduces `pendingInstantWithdraws` only by the amount actually collected from the CDO [1](#0-0) . If the CDO's available cash is insufficient, the remainder stays pending while `epochNumber` advances (incremented in `deposit()` during a running epoch) [2](#0-1) . Instant receipts from the old epoch remain in `instantWithdrawsRequestsByEpoch[user][oldEpoch]` and `instantWithdrawsRequests[user]`, but `instantWithdrawClaimsByEpoch` is keyed per request epoch [3](#0-2) .

On default, `finalizeDefaultRecovery` calls `defaultPendingClaimBasis`, which adds only `instantWithdrawClaimsByEpoch[epochNumber]` (current epoch) when `pendingInstantWithdraws != 0` [4](#0-3) . The older unfunded instant claims are absent from `totalBasis`, so `recoveryPrice = reserveAmount * RECOVERY_FULL / totalBasis` is too large [5](#0-4) . The minted active NAV `activeBasis * recoveryPrice` is likewise inflated [6](#0-5) .

At claim time, `_claimDefaultedInstantWithdrawRequest` only clears/pays basis for `defaultRecoveryEpoch` [7](#0-6) . The leftover `instantWithdrawsRequests[_user]` (older unfunded receipts) is then paid at par via `_transferFundedClaim` [8](#0-7) , but `_transferFundedClaim` forbids spending `defaultRecoveryReserve` [9](#0-8) . Since those receipts were never funded, the claim reverts — permanently freezing them — while the inflated `recoveryPrice` has already redistributed their economic share to default-epoch claimants and active holders.

### Impact Explanation
- **Theft via inflated recovery price**: default-epoch instant claimants and active tranche holders receive `reserveAmount / (understated basis)`, extracting value that should have been shared pro rata with older unfunded instant receipt holders.
- **Permanent freezing**: older-epoch instant receipts can never be paid — they are not in the reserve basis (so no haircut path pays them) and the funded path reverts because nothing outside the reserve backs them.
- Loss is proportional to the stale `pendingInstantWithdraws` remainder: if X underlying of instant claims from a prior epoch was never collected, the recovery basis is understated by X, overpaying all other claimants by roughly `reserve * X / totalBasis`.

### Likelihood Explanation
Requires: (1) `allowInstantWithdraw` enabled; (2) an epoch where CDO cash at `startEpoch` covers only part of instant claims so `pendingInstantWithdraws` carries over; (3) a subsequent borrower default finalized via `finalizeDefaultRecovery`. Attacker is just a KYC-passed lender holding a mature instant receipt — honest manager/borrower sequencing suffices. The `NotAllowed` guard in `requestWithdraw` and the reserve guard in `_transferFundedClaim` do not prevent this; they actually convert the missing basis into a permanent revert.

### Recommendation
Track aggregate unfunded instant basis rather than a single epoch's: either maintain a global `instantWithdrawClaimsTotal` that is decremented when receipts are funded/claimed (mirroring `pendingInstantWithdraws`), or sum `instantWithdrawClaimsByEpoch` across all epochs with non-zero claims. `defaultPendingClaimBasis` should include every still-unfunded instant claim, and `_claimDefaultedInstantWithdrawRequest` should iterate/aggregate all epochs' basis for the user, not only `defaultRecoveryEpoch`.

### Proof of Concept
Foundry fork sketch (contracts-only, no mocks needed beyond existing test harness in `test/foundry/IdleCreditVault.t.sol`):

```solidity
// 1. Enable instant withdraws (setInstantWithdrawParams via manager).
// 2. Epoch 1 running: user1 calls requestInstantWithdraw -> instantWithdrawsRequestsByEpoch[user1][1] = A.
// 3. startEpoch: CDO collects only part of instant funds ->
//    collectInstantWithdrawFunds(a) with a < A, pendingInstantWithdraws = A - a.
// 4. Epoch 2 running: user2 requests instant withdraw B ->
//    instantWithdrawClaimsByEpoch[2] = B; pendingInstantWithdraws = (A - a) + B.
// 5. Borrower defaults; finalizeDefaultRecovery(recovered, source):
//    basis = pendingWithdraws + instantWithdrawClaimsByEpoch[2]  // misses (A - a)
//    recoveryPrice inflated; active NAV minted up to activeBasis * price.
// 6. user2 claims: gets B * recoveryPrice (overpaid) from reserve.
// 7. user1 claims: _claimDefaultedInstantWithdrawRequest clears only epoch-2 basis
//    (zero for user1); then _transferFundedClaim(user1, A - a) reverts because
//    balance - defaultRecoveryReserve < amount. user1's receipt is frozen forever.
// Assert: underlying.balanceOf(user1) unchanged; claim reverts with NotAllowed();
//         sum of paid claims > reserveAmount * (1 - staleShare).
```

Caveat: steps 3 and 5 depend on `IdleCDOEpochVariant`/`getInstantWithdrawFunds` allowing partial instant collection and on the default-finalization call path in the CDO; I verified the strategy-side accounting but did not fully trace the CDO-side collection amount in this pass.

```text
  function _claimDefaultedInstantWithdrawRequest(address _user) internal returns (uint256 claimBasis) {
    uint256 defaultEpoch = defaultRecoveryEpoch;
    claimBasis = instantWithdrawsRequestsByEpoch[_user][defaultEpoch];
    if (claimBasis == 0) return claimBasis;

    instantWithdrawsRequestsByEpoch[_user][defaultEpoch] = 0;
    instantWithdrawsRequests[_user] -= claimBasis;
    uint256 pending = pendingInstantWithdraws;
    // `pendingInstantWithdraws` is only the unfunded remainder. If this user's claim is larger,
    // the extra amount was already counted as prefunded reserve during default finalization.
    pendingInstantWithdraws = claimBasis >= pending ? 0 : pending - claimBasis;
    instantWithdrawClaimsByEpoch[defaultEpoch] -= claimBasis;
    _burn(_user, claimBasis);
    _transferDefaultRecovery(_user, (claimBasis * defaultRecoveryPrice) / RECOVERY_FULL);
  }
```
