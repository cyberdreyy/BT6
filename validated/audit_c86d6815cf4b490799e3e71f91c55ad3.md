The bug class — relying on an unvalidated externally-controlled value in a sensitive computation — maps cleanly to `ProgrammableBorrower._vaultNetInterest`, which treats the ERC4626 vault's `convertToAssets` as ground truth for epoch interest. A donation to the vault is booked as real yield and minted into tranche NAV without backing.

### Title
Unvalidated ERC4626 vault valuation lets a vault user mint unbacked tranche NAV via donation - ([File: contracts/strategies/idle/ProgrammableBorrower.sol](contracts/strategies/idle/ProgrammableBorrower.sol))

### Summary
In programmable-borrower mode, `stopEpoch` prices the entire epoch's yield from `IProgrammableBorrower(borrower).totalInterestDueNow()` (`contracts/IdleCDOEpochVariant.sol:1001-1008`). That value is computed in `_vaultNetInterest` as `convertToAssets(shares) + epochWithdrawnFromVault - epochStartVaultAssets - epochDepositedToVault` (`contracts/strategies/idle/ProgrammableBorrower.sol:337-347`). Because `epochDepositedToVault` is only incremented on the borrower's own `_depositToVault` calls (`:378-385`), any direct underlying transfer to the external ERC4626 vault by a third party inflates `convertToAssets` and is reported as genuine epoch interest. `stopEpoch` then calls `mintStrategyTokens(_grossInterest)` (`IdleCDOEpochVariant.sol:428-433`), creating strategy tokens — and hence tranche NAV — that are backed by nothing at the CDO level.

### Finding Description
The CDO validates none of the value returned by `totalInterestDueNow`. It is taken as `_resolvedInterest`, flows into `_grossInterest`, and in minted-interest mode (mandatory for programmable borrowers, `setIsInterestMinted` reverts otherwise at `IdleCDOEpochVariant.sol:166-170`) is converted directly into strategy-token supply via `_strategy.mintStrategyTokens(_grossInterest)`. Every unit of fake "interest" inflates `priceAA`/`priceBB` through `_updateAccounting` without a corresponding underlying inflow: the donation is already inside the external vault and cannot be pulled twice — `onStopEpoch` withdraws only `shortfall` up to the borrower's vault assets, and the donated amount is simultaneously counted as vault profit and remains claimable by the donor through their own vault shares.

Attack sequence in a running, programmable, minted-interest epoch:
1. Attacker (a KYC-passing lender and ordinary user of the borrower's ERC4626 vault) deposits D underlying into the vault, receiving shares at fair price.
2. Attacker donates X underlying directly to the vault contract. `convertToAssets` rises; the programmable borrower's sleeve gains `X * f` where `f` is its share of the vault. `_vaultNetInterest` reports this as `interest`.
3. Manager calls `stopEpoch(0, 0)` — an honest action the attacker merely sequences around. `mintStrategyTokens` mints `~X*f` unbacked strategy tokens; tranche prices inflate.
4. Attacker redeems their vault shares (recovering ~D plus their pro-rata share of the donation, i.e. most of X back through vault appreciation) and also requests/claims a tranche withdrawal at the inflated price, paid from real borrower principal.

The same X is thus counted twice: once in the attacker's vault-share value, once in minted CDO NAV.

### Impact Explanation
Broken invariant: fair mint/burn and solvency. `mintStrategyTokens` mints claims against borrower assets that were never lent out. Losses materialize when withdrawal receipts and tranche redemptions are claimed at inflated prices: early claimers (the attacker) are paid in real underlying while later LPs' receipts become undercollateralized — direct theft from other LPs quantified at `X * f * (attacker tranche share)`, with the attacker's principal cost largely refunded through the vault-share leg.

### Likelihood Explanation
Requires a programmable-borrower deployment, an ERC4626 vault that accepts raw donations (standard for MetaMorpho/ERC4626 — `totalAssets` includes the raw balance), and an attacker who is both a vault shareholder and a KYC'd tranche holder. Both roles are explicitly unprivileged. No privileged misbehavior is needed; `stopEpoch` is a normal manager call. Cost is roughly the non-recovered fraction of the donation (`X * f` leaking to other vault shareholders is bounded since MetaMorpho vaults track assets internally, donations still accrue pro-rata — attacker picks `X` to exceed profit threshold).

### Recommendation
Have `ProgrammableBorrower` snapshot vault share price (`convertToAssets(1 share)` or totalAssets/totalSupply) at `startEpochAccounting` and measure yield as `shares * (priceNow - priceStart)` rather than raw asset deltas, or compare `convertToAssets` against a donation-resistant `previewRedeem`/tracked baseline so unsolicited inflows are excluded. Alternatively, cap `totalInterestDueNow` at the contractual `borrowerInterestAccruedNow() + bufferInterest` plus realized (withdrawn) vault gains only.

### Proof of Concept
Foundry fork (mainnet, MetaMorpho `STEAKHOUSE_USDC` vault as in `test/foundry/ProgrammableBorrowerCreditVault.t.sol`):

```solidity
function testVaultDonationInflatesEpochInterest() external {
    uint256 amount = 10_000 * oneScale;
    vm.prank(owner);
    cdoEpoch.setIsInterestMinted(true);
    idleCDO.depositAA(amount);
    _startEpochAndCheckPrices(0);

    // attacker: KYC'd LP + ordinary Morpho vault user
    address attacker = makeAddr("attacker");
    deal(defaultUnderlying, attacker, 2_000 * oneScale);
    vm.startPrank(attacker);
    underlying.approve(address(morphoVault), type(uint256).max);
    morphoVault.deposit(1_000 * oneScale, attacker);       // fair-priced shares
    underlying.transfer(address(morphoVault), 1_000 * oneScale); // donation
    vm.stopPrank();

    uint256 interestBefore = programmableBorrower.totalInterestDueNow();
    vm.warp(cdoEpoch.epochEndDate() + 1);
    uint256 interestAfter = programmableBorrower.totalInterestDueNow();
    // donated X * (PB vault share fraction) shows up as fake interest
    assertGt(interestAfter - interestBefore, 0);

    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // NAV inflated by unbacked minted strategy tokens
    assertApproxEqAbs(cdoEpoch.lastEpochInterest(), interestAfter, 10);
    // attacker redeems vault shares (recovers donation share) AND
    // withdraws tranche position at inflated price -> insolvency for later LPs
}
```
