### Title
Unsafe arbitrary ERC20 transfer in `claim` marks prize as claimed even when transfer silently fails - (contracts/MerkleClaim.sol)

### Summary
`MerkleClaim.claim` verifies a merkle proof, sets `hasClaimed[to] = true`, and then performs a raw `IERC20Upgradeable(token).transfer(to, amount)` without checking the return value. For ERC20 tokens that return `false` (or return no data) on failure instead of reverting, the claim state is permanently consumed while the user receives nothing — the exact bug class in the Footium `claimERC20Prize` report. [1](#0-0) 

### Finding Description
`claim` at `contracts/MerkleClaim.sol:52-67`:

1. Checks `hasClaimed[to]` and verifies the merkle proof for `(to, amount)`.
2. Sets `hasClaimed[to] = true` — the one-shot claim flag is burned **before** the transfer.
3. Calls `IERC20Upgradeable(token).transfer(to, amount)` on an arbitrary token configured at `initialize` time.

Because the low-level call's boolean return is ignored, a token that fails by returning `false` (e.g., tokens like the old ZRX/OMG-style implementations, or any custom token deployed for this distribution) lets the function complete successfully with zero tokens moved. The user can never retry — `AlreadyClaimed()` reverts on any subsequent call — and the tokens remain in the contract, recoverable only by `TL_MULTISIG` via `sweep` after 60 days (`contracts/MerkleClaim.sol:69-75`).

This is analogous to Footium's `claimERC20Prize`: a merkle-gated one-time claim that updates accounting state (`hasClaimed`) around an unchecked ERC20 transfer to an arbitrary token.

### Impact Explanation
A legitimate claimee (unprivileged user) loses their entire airdrop/claim allocation permanently if the configured `token` silently returns `false` on transfer. Loss = full `amount` owed per the merkle leaf. The contract retains the tokens, so the loss is a direct theft-by-misaccounting of the user's claim — the "one receipt one payout" invariant is broken: the receipt (`hasClaimed`) is consumed without a payout.

### Likelihood Explanation
Medium. Exploitability depends on the token configured in `initialize` being a non-reverting-on-failure ERC20; `token` is arbitrary (`initialize(bytes32,address)` accepts any address, `contracts/MerkleClaim.sol:37-44`). For standard reverting tokens (USDC reverting variants, WETH, etc.) the call simply reverts and no harm occurs. But the contract is explicitly designed to distribute "an ERC20" chosen at deployment, so any silent-failing token exposes every claimee. Note: the victim is the user, not an attacker profiting directly — the "theft" materializes when `TL_MULTISIG` sweeps the stranded tokens after 60 days.

### Recommendation
Use OpenZeppelin's `SafeERC20Upgradeable.safeTransfer` for the payout in `claim` (and in `sweep`), matching the pattern already used elsewhere in the codebase (e.g., `TrancheWrapper._redeem` uses `SafeERC20Upgradeable.safeTransfer` at `contracts/TrancheWrapper.sol:265`). This reverts on a `false` return, preserving `hasClaimed = false` semantics via reversion and allowing the user to retry.

```solidity
// contracts/MerkleClaim.sol
import { SafeERC20Upgradeable } from "@openzeppelin/contracts-upgradeable/token/ERC20/utils/SafeERC20Upgradeable.sol";

// in claim():
SafeERC20Upgradeable.safeTransfer(IERC20Upgradeable(token), to, amount);
```

### Proof of Concept
Foundry PoC sketch (fork or local — a local mock suffices since the bug is token-behavior dependent):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {MerkleClaim} from "../contracts/MerkleClaim.sol";
import {MerkleProofUpgradeable} from "@openzeppelin/contracts-upgradeable/utils/cryptography/MerkleProofUpgradeable.sol";

/// Token that returns false instead of reverting on failed transfers
contract SilentFailToken {
    mapping(address => uint256) public balanceOf;
    string public name = "SFT"; string public symbol = "SFT"; uint8 public decimals = 18;
    function mint(address to, uint256 amt) external { balanceOf[to] += amt; }
    function transfer(address to, uint256 amt) external returns (bool) {
        // simulate an internal condition that fails silently
        if (amt > 0) return false;      // always fails "silently"
        return true;
    }
}

contract MerkleClaimUnsafeTransferTest is Test {
    MerkleClaim claim;
    SilentFailToken token;
    address alice = address(0xA11CE);
    uint256 amount = 100e18;
    bytes32 root;
    bytes32[] proof; // single-leaf tree => empty proof

    function setUp() public {
        claim = new MerkleClaim();
        token = new SilentFailToken();
        // leaf for (alice, amount)
        bytes32 leaf = keccak256(bytes.concat(keccak256(abi.encode(alice, amount))));
        root = leaf; // single-leaf merkle tree
        claim.initialize(root, address(token));
        token.mint(address(claim), amount);
    }

    function test_claimSilentFailureBurnsClaim() public {
        vm.prank(alice);
        claim.claim(alice, amount, proof);          // succeeds, no revert
        assertEq(token.balanceOf(alice), 0);        // but alice got nothing
        assertTrue(claim.hasClaimed(alice));        // claim burned
        vm.prank(alice);
        vm.expectRevert(MerkleClaim.AlreadyClaimed.selector);
        claim.claim(alice, amount, proof);          // cannot retry — funds stuck until sweep
    }
}
```

Expected result: `test_claimSilentFailureBurnsClaim` passes, demonstrating that Alice's claim flag is consumed while she receives zero tokens, and her only recourse is the multisig `sweep` after 60 days.

```text
  function claim(address to, uint256 amount, bytes32[] calldata proof) external {
    // Throw if address has already claimed tokens
    if (hasClaimed[to]) revert AlreadyClaimed();

    // Verify merkle proof, or revert if not in tree,
    // double keccak is preferred https://github.com/OpenZeppelin/merkle-tree#user-content-fn-1-786ed85226485d53b8a7834b144c1642
    bytes32 leaf = keccak256(bytes.concat(keccak256(abi.encode(to, amount))));
    bool isValidLeaf = MerkleProofUpgradeable.verify(proof, merkleRoot, leaf);
    if (!isValidLeaf) revert NotInMerkle();

    // Set address to claimed
    hasClaimed[to] = true;

    // Transfer tokens to claimee
    IERC20Upgradeable(token).transfer(to, amount);
  }
```
