### Title
Missing zero-address check on vote-account withdrawer authorization allows permanent lock of vote-account funds - (File: `programs/vote/src/vote_state/mod.rs`)

### Summary
The `authorize` function in the vote program's state module updates the vote account's authorized voter or authorized withdrawer to an attacker- or user-supplied `Pubkey` without ever checking that the new authority is not `Pubkey::default()` (the all-zero pubkey). Because no private key exists for the all-zero pubkey, setting the withdrawer (or voter) authority to it via `VoteInstruction::Authorize`/`AuthorizeChecked` permanently locks the vote account's funds and voting rights, mirroring the reported "missing zero checks" bug class from the Maple contracts (e.g. `setBorrower`/`setLender` accepting `address(0)`).

### Finding Description
`authorize()` in [1](#0-0) . For `VoteAuthorize::Withdrawer` it directly stores the caller-supplied value: `vote_state.set_authorized_withdrawer(*authorized);` with no validation that `*authorized != Pubkey::default()`. The `VoteAuthorize::Voter` branch similarly forwards the raw `authorized` value into `set_new_authorized_voter` with no zero check.

This instruction (`VoteInstruction::Authorize` / `AuthorizeChecked`) is reachable by any ordinary user transaction that holds the current authorized withdrawer/voter signature — it requires no special validator privilege, and is exposed through the standard CLI/RPC path shown in [2](#0-1) , which for the unchecked variant simply forwards whatever pubkey the caller/front-end supplies as `new_authorized_pubkey` with `.unwrap()` and no zero-address guard.

Once the authorized withdrawer is set to `Pubkey::default()`, the withdraw path is permanently unreachable: `withdraw()` in [3](#0-2) , which can never succeed because no keypair corresponds to the all-zero pubkey (it cannot produce a valid signature), and no further `Authorize` call can succeed either since that also requires a signature from the (now unreachable) current authorized withdrawer.

### Impact Explanation
Setting the authorized withdrawer to the zero pubkey permanently locks all lamports in the vote account (delegated stake rewards accrue there) — the funds become unrecoverable since `withdraw()` and any subsequent `Authorize` call require a signature from an address that has no corresponding private key. This is a genuine state-mutation bug with concrete, irreversible fund loss, analogous to the Maple `setBorrower`/`setLender(address(0))` scenario in the source report. It requires no elevated privilege — any account holding the current withdrawer/voter authority signature (including a front-end/wallet bug feeding an uninitialized or zeroed pubkey) can trigger it.

### Likelihood Explanation
Likelihood is low-to-moderate: exploitation is not attacker-initiated against a victim without cooperation — it requires the legitimate authorized withdrawer to submit (knowingly or via a front-end bug/UI defect) an `Authorize`/`AuthorizeChecked` instruction with the zero pubkey as the new authority. The exploit scenario described in the source report (a front-end bug using an uninitialized variable as the new-authority parameter) applies directly here, since the CLI/RPC path performs no zero-address validation before constructing and submitting the instruction.

### Recommendation
Add an explicit zero-address (`Pubkey::default()`) check in `authorize()` (and any other instruction handler accepting a new authority pubkey, e.g. stake program's authorize) before calling `set_authorized_withdrawer`/`set_new_authorized_voter`, returning `InstructionError::InvalidArgument` if the new authority is the default pubkey. Apply the same validation at the CLI parsing layer (`parse_vote_authorize`) as a defense-in-depth measure, and consider a broader audit for other authority-setting instructions (`stake_instruction::authorize`, `system_instruction::assign`) that similarly accept unauthenticated new-authority parameters without zero-address checks.

### Proof of Concept
1. Create and fund a vote account, with account A as the current authorized withdrawer.
2. A submits `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)` (or the `AuthorizeChecked` variant with `Pubkey::default()`), signed by A. This succeeds because `authorize()` performs no validation on the new authority value — see [4](#0-3) .
3. Any subsequent `VoteInstruction::Withdraw` fails permanently because `verify_authorized_signer(vote_state.authorized_withdrawer(), signers)` in [3](#0-2)  can never be satisfied by any real signer, since the all-zero pubkey has no corresponding private key.
4. Any subsequent `Authorize` call to fix the withdrawer also fails for the same reason, permanently locking the account's lamports.

Note: I was unable to fully trace whether an equivalent zero-check gap exists in the stake program's `authorize` instruction handler within the available index (the file/function was not found via search), so that path remains unverified and is not asserted here as a confirmed second instance.

    signers: &HashSet<Pubkey, S>,

    is_vote_authorize_with_bls_enabled: bool,
    consume_pop_compute_units: F,
) -> Result<(), InstructionError>
where
    F: FnOnce() -> Result<(), InstructionError>,
{
    let mut vote_state = get_vote_state_handler_checked(vote_account, target_version)?;

    match vote_authorize {
        VoteAuthorize::Voter => {
            if is_vote_authorize_with_bls_enabled && vote_state.has_bls_pubkey() {
                return Err(InstructionError::InvalidInstructionData);
            }
            let authorized_withdrawer_signer =
                verify_authorized_signer(vote_state.authorized_withdrawer(), signers).is_ok();

            vote_state.set_new_authorized_voter(
                authorized,
                clock.epoch,
                clock
                    .leader_schedule_epoch
                    .checked_add(1)

                    // current authorized withdrawer or authorized voter must say "yay"
                    if authorized_withdrawer_signer {
                        Ok(())
                    } else {
                        verify_authorized_signer(&epoch_authorized_voter, signers)
                    }

pub fn parse_vote_authorize(
    matches: &ArgMatches<'_>,
    default_signer: &DefaultSigner,
    wallet_manager: &mut Option<Rc<RemoteWalletManager>>,
    vote_authorize: VoteAuthorize,
    checked: bool,
) -> Result<CliCommandInfo, CliError> {
    let vote_account_pubkey =
        pubkey_of_signer(matches, "vote_account_pubkey", wallet_manager)?.unwrap();
    let (authorized, authorized_pubkey) = signer_of(matches, "authorized", wallet_manager)?;

    let sign_only = matches.is_present(SIGN_ONLY_ARG.name);
    let dump_transaction_message = matches.is_present(DUMP_TRANSACTION_MESSAGE.name);
    let blockhash_query = BlockhashQuery::new_from_matches(matches);
    let nonce_account = pubkey_of(matches, NONCE_ARG.name);
    let memo = matches.value_of(MEMO_ARG.name).map(String::from);
    let (nonce_authority, nonce_authority_pubkey) =
        signer_of(matches, NONCE_AUTHORITY_ARG.name, wallet_manager)?;
    let (fee_payer, fee_payer_pubkey) = signer_of(matches, FEE_PAYER_ARG.name, wallet_manager)?;
    let compute_unit_price = value_of(matches, COMPUTE_UNIT_PRICE_ARG.name);

    let use_v2_instruction = matches.is_present("use_v2_instruction");
    if use_v2_instruction && vote_authorize != VoteAuthorize::Voter {
        return Err(CliError::BadParameter(
            "--use-v2-instruction is only supported for voter authorization".to_owned(),
        ));
    }

    let mut bulk_signers = vec![fee_payer, authorized];

    let new_authorized_pubkey = if checked {
        let (new_authorized_signer, new_authorized_pubkey) =
            signer_of(matches, "new_authorized", wallet_manager)?;
        bulk_signers.push(new_authorized_signer);
        new_authorized_pubkey.unwrap()
    } else {
        pubkey_of_signer(matches, "new_authorized_pubkey", wallet_manager)?.unwrap()
    };
    if nonce_account.is_some() {
        bulk_signers.push(nonce_authority);
    }
    let signer_info =
        default_signer.generate_unique_signers(bulk_signers, matches, wallet_manager)?;

    Ok(CliCommandInfo {
        command: CliCommand::VoteAuthorize {
            vote_account_pubkey,
            new_authorized_pubkey,
            vote_authorize,
            use_v2_instruction,
            sign_only,
            dump_transaction_message,
            blockhash_query,
            nonce_account,
            nonce_authority: signer_info.index_of(nonce_authority_pubkey).unwrap(),
            memo,
            fee_payer: signer_info.index_of(fee_payer_pubkey).unwrap(),
            authorized: signer_info.index_of(authorized_pubkey).unwrap(),
            new_authorized: if checked {
                signer_info.index_of(Some(new_authorized_pubkey))
            } else {
                None
            },
            compute_unit_price,
        },
        signers: signer_info.signers,
    })
}
