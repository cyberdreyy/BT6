## #Vulnerability found for this question.

### Title
Stale cached `user_role` in `ldap_user_api_tokens` grants continued Edit-level access after upstream LDAP group downgrade - ([File: core/sessions/ldapauth/ldap.go])

### Summary
`ldapAuthenticator.FindUserByAPIToken` authorizes API-token requests purely from the locally cached `user_role` column in `ldap_user_api_tokens`, checking only token expiry and never re-querying the upstream LDAP directory. Role revocation only happens when the separate `LDAPServerStateSyncer.Work` background job runs, which by default (`UpstreamSyncInterval = '0s'`) executes only once at node startup and never again, so a token minted while the user was in `EditUserGroupCN` keeps working at Edit-level indefinitely after the user is removed from that group upstream.

### Finding Description
`AuthenticateByToken` in [1](#0-0)  is the gRPC/REST auth middleware entry point for the `X-API-KEY`/`X-API-SECRET` headers; it calls `authr.FindUserByAPIToken(ctx, token.AccessKey)` and trusts the returned `user.Role` directly to populate `SessionUserKey`, which `RequiresEditRole`/`RequiresAdminRole` later check.

`FindUserByAPIToken` itself only does a single SQL lookup and expiry check, with no upstream LDAP re-validation: [2](#0-1) 

Role synchronization against the upstream LDAP server is entirely decoupled from the request path and is only performed by `LDAPServerStateSyncer.Work`, invoked either once at `Start()` (when `UpstreamSyncInterval` is the zero/default value `'0s'`) or on a ticker when the interval is non-zero: [3](#0-2) [4](#0-3) 

This contradicts the package-level doc comment claiming "This sync happens for every auth endpoint hit, and via the defined sync interval" [5](#0-4) ; in the actual implementation, `AuthenticateByToken` → `FindUserByAPIToken` never triggers or checks against `Work`/upstream sync. The `user_role` value cached at token-creation time in `SetAuthToken` [6](#0-5)  is the sole source of truth used for authorization until the next `Work` run rewrites it via the `CASE WHEN` bulk update [7](#0-6) . With the documented default `UpstreamSyncInterval = '0s'`, that update never recurs after node startup, so a demoted user's previously issued token retains Edit (or Admin) authorization indefinitely (until token expiry, up to `UserAPITokenDuration`, default 240h).

### Impact Explanation
A user demoted from the `EditUserGroupCN` (or `AdminUserGroupCN`) group upstream continues to successfully call any `RequiresEditRole`/`RequiresAdminRole`-gated REST endpoint using their previously issued API token, performing privileged mutating actions (e.g., editing jobs, bridges, keys) they should no longer be authorized for. This is a role/authorization-bypass class impact: revoked privileges are not enforced, and with the default `UpstreamSyncInterval='0s'` config the exposure window is effectively unbounded (until manual node restart or non-default interval configuration).

### Likelihood Explanation
Feasibility is high and fully attacker-controlled once the precondition is met: the user only needs to have previously created an API token while holding Edit/Admin group membership (via `SetAuthToken`/`CreateAndSetAuthToken`, a normal, documented user action) and then be removed from that LDAP group. No additional credentials, race conditions, or special access are required — a simple authenticated `X-API-KEY`/`X-API-SECRET` request reproduces it every time, and it is repeatable for the life of the token (up to `UserAPITokenDuration`) as long as the operator has not manually configured a non-zero `UpstreamSyncInterval` (which is not the default).

### Recommendation
Re-validate the cached role against the sync state on every `FindUserByAPIToken` (and `AuthorizedUserWithSession`) call, or trigger an on-demand upstream LDAP sync/staleness check at authentication time when `UpstreamSyncInterval` is `'0s'` or has elapsed, matching the behavior described in the package doc comment. At minimum, disallow `UpstreamSyncInterval='0s'` from meaning "sync only once at startup, never again" and instead enforce a bounded default re-sync interval, or perform a lightweight upstream membership check inline in `FindUserByAPIToken` before trusting the cached role for privileged operations.

2. Do NOT invoke `LDAPServerStateSyncer.Work` (simulating default `UpstreamSyncInterval='0s'` behavior after startup, or simulating the user being removed from the upstream group before the next sync tick), and mock the LDAP client's group-membership response for this user to no longer include `EditUserGroupCN`.
3. Call `ldapAuthProvider.FindUserByAPIToken(ctx, apiToken)`.
4. Assert `user.Role == sessions.UserRoleEdit` is returned (demonstrating stale privilege) even though a fresh `ldapGroupMembersListToUser` query against the mocked upstream would return a lower role — proving `FindUserByAPIToken` never reconciles against current upstream truth.
5. Handler-level integration variant: issue an HTTP request to an `auth.RequiresEditRole`-wrapped endpoint with the stale token's `X-API-KEY`/`X-API-SECRET` headers and assert `200 OK` instead of `401/403`, confirming end-to-end privileged access after downgrade.

		return err
	}

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (l *ldapAuthenticator) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	if !l.config.UserApiTokenEnabled() {
		return errors.New("API token is not enabled ")
	}

	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return fmt.Errorf("LDAPAuth SetAuthToken hashed secret error: %w", err)
	}

	err = sqlutil.TransactDataSource(ctx, l.ds, nil, func(tx sqlutil.DataSource) error {
		// Is this user a local CLI Admin or upstream LDAP user?
		// Check presence in local users table. Set localauth_user column true if present.
		// This flag omits the session/token from being purged by the sync daemon/reaper.go
		isLocalCLIAdmin := false
		err = l.ds.QueryRowxContext(ctx, "SELECT EXISTS (SELECT 1 FROM users WHERE email = $1)", user.Email).Scan(&isLocalCLIAdmin)
		if err != nil {
			return fmt.Errorf("error checking user presence in users table: %w", err)
		}

		// Remove any existing API tokens
		if _, err = l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE user_email = $1", user.Email); err != nil {
			return fmt.Errorf("error executing DELETE FROM ldap_user_api_tokens: %w", err)
		}
		// Create new API token for user
		_, err = l.ds.ExecContext(
			ctx,
			"INSERT INTO ldap_user_api_tokens (user_email, user_role, localauth_user, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1, $2, $3, $4, $5, $6, now())",
			user.Email,
			user.Role,
			isLocalCLIAdmin,
			token.AccessKey,
			salt,
			hashedSecret,
		)
		if err != nil {
			return fmt.Errorf("failed insert into ldap_user_api_tokens: %w", err)
		}
		return nil
	})
	if err != nil {
		return errors.New("error creating API token")
	}

	l.auditLogger.Audit(audit.APITokenCreated, map[string]any{"user": user.Email})
	return nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}
