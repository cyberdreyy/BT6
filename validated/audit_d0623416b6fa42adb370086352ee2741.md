Based on direct inspection of `helpers/archives/zip_extract.go`, this is a real bug: **the zip extraction code performs zero path validation on `zip.File.Name`.**

### Title
Zip archive extraction writes files using unsanitized `zip.File.Name`, allowing absolute-path/`..` escape from the cache/artifact extraction root - (File: `helpers/archives/zip_extract.go`)

### Summary
`ExtractZipArchive` and its helpers (`extractZipFile`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, `extractZipFileEntry`, and the final `lchmod` pass) use `file.Name` verbatim for `os.MkdirAll`, `os.Mkdir`, `os.OpenFile`, `os.Symlink`, and `lchmod`, with no check for absolute paths, drive-relative paths, or `..` traversal segments. The only pre-extraction validation present is `errorIfGitDirectory`, which only flags `.git` paths and does not stop extraction. This means any zip archive whose entries contain absolute or traversal names will be written outside the intended extraction directory.

### Finding Description
`extractZipFile` computes the parent directory with `filepath.Dir(file.Name)` and calls `os.MkdirAll(..., 0o777)` directly on it [1](#0-0) , then dispatches to `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry`, all of which call filesystem primitives (`os.Mkdir`, `os.Symlink`, `os.OpenFile`) with the raw `file.Name` [2](#0-1) . `ExtractZipArchive` then does a second pass calling `lchmod(file.Name, file.Mode())` on every entry, again unsanitized [3](#0-2) . The only check applied per-entry is `errorIfGitDirectory`, which is unrelated to path confinement — it only special-cases `.git` paths and does not enforce that the resulting path stays within any base directory [4](#0-3) .

Critically, the legacy zip extractor wrapper (`ziplegacy.extractor.Extract`) discards the `dir` parameter entirely and calls `archives.ExtractZipArchive(zr)` with no join/chroot/chdir against `e.dir` [5](#0-4) . Confinement to the cache/build directory relies entirely on the current working directory being correct and on the zip entries themselves never containing absolute paths or `..` — an assumption not enforced anywhere in this code path. `CacheExtractorCommand.Execute` passes `wd` (current working directory) into `archive.NewExtractor` and then just calls `extractor.Extract(ctx)` [6](#0-5) , with no post-extraction verification that written files stayed under `wd`.

### Impact Explanation
If a `zip.File.Name` value of `/etc/cron.d/x` (or any absolute/`..`-containing path) reaches `ExtractZipArchive`, `os.MkdirAll(filepath.Dir(file.Name), 0o777)` will create `/etc/cron.d` if missing (subject to OS permissions of the runner process) and the subsequent `extractZipFileEntry`/`extractZipSymlinkEntry`/`lchmod` calls will write/chmod that absolute path directly — a classic "zip-slip" arbitrary file write, entirely outside the confined cache/artifact extraction root. This directly violates the stated invariant that "file operations must stay within intended build/cache/artifact roots."

### Likelihood Explanation
The extraction function itself is provably unguarded — this is confirmed directly from the source with no ambiguity. What I could **not** fully verify in this session is the archive-creation side (`zip_archive.go`, not reviewed due to iteration limits): whether the runner's own cache/artifact archiver can be induced (e.g., via a symlink under `cache:paths`/`artifacts:paths` pointing outside the project working directory) to write an absolute or traversal `zip.File.Name` into a cache/artifact zip that a job later has extracted for it. If the archiver already sanitizes names to be relative to the build directory in all cases, the practical reachability from a normal pipeline author is reduced (still reachable via a compromised/malicious cache blob if project-level cache storage isn't strictly access-controlled, which is outside "external service compromise" scope). Regardless of that unresolved question, the extraction routine has no defense-in-depth: it does not validate that resolved paths stay under the extraction root, which is the root-cause bug being asked about.

### Recommendation
In `helpers/archives/zip_extract.go`, before acting on any `file.Name`, resolve it against the intended extraction root (e.g., `filepath.Join(root, file.Name)`), reject entries where `filepath.Clean` of the joined path escapes `root` (compare with `filepath.Rel` or a prefix check after `filepath.EvalSymlinks`/`filepath.Abs` normalization), and reject/skip absolute paths and paths containing `..` segments outright — mirroring the existing `errorIfGitDirectory` guard pattern but enforcing containment rather than just `.git` exclusion. Apply the same check before the `lchmod` pass. Ensure `ziplegacy.extractor.Extract` actually uses `e.dir` as the confinement root rather than relying implicitly on CWD.

```go
func TestExtractZipArchiveAbsolutePathEscape(t *testing.T) {
    tmpDir := t.TempDir()
    origWd, _ := os.Getwd()
    require.NoError(t, os.Chdir(tmpDir))
    defer os.Chdir(origWd)

    escapeTarget := filepath.Join(t.TempDir(), "escape") // outside tmpDir tree

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)
    w, err := zw.CreateHeader(&zip.FileHeader{Name: escapeTarget, Method: zip.Deflate})
    require.NoError(t, err)
    _, err = w.Write([]byte("pwned"))
    require.NoError(t, err)
    require.NoError(t, zw.Close())

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    require.NoError(t, err)

    err = ExtractZipArchive(zr)
    require.NoError(t, err)

    // Bug: file gets written outside tmpDir despite extraction being invoked in tmpDir
    _, statErr := os.Stat(escapeTarget)
    assert.NoError(t, statErr, "expected escape file to exist outside extraction root, proving containment is not enforced")
}
```
Expected result on the current code: the assertion passes (file created at `escapeTarget`, outside `tmpDir`), proving the missing containment check. After the fix, `ExtractZipArchive` should return an error for this entry and no file should be created at `escapeTarget`.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}
```
