### Title
Staking pool's undelayed share minting lets late stakers front-run `internal_ping`'s reward distribution and dilute existing delegators' rewards - (File: `staking-pool/src/internal.rs`)

### Summary
`StakingContract::internal_ping` (`staking-pool/src/internal.rs:192-250`) distributes *any* balance increase observed on the pool account — validator rewards, gas-fee rebates, or a plain/arbitrary NEAR transfer to the contract — as reward to whatever `total_stake_shares` exist at the moment the next epoch-boundary `ping` executes. Because `internal_stake` (`staking-pool/src/internal.rs:70-122`) mints shares immediately at the pre-reward price with no lock-up/vesting period, any unprivileged account can watch for an impending balance increase (e.g. a "profit"/reward transfer landing in the pool, which the contract's own README explicitly says will be "distributed to the active stake participants... in the next epoch") and quickly `deposit_and_stake` before the epoch switches, thereby claiming a pro‑rata slice of a reward it did not help earn — at the direct expense of the delegators who were staked the whole time.

### Finding Description
The custody/settlement binding that should hold is: *reward credited to a share == reward actually earned while that share was outstanding*. `internal_ping` breaks this equality:

```
staking-pool/src/internal.rs:205-234
let total_balance = env::account_locked_balance() + env::account_balance() - env::attached_deposit();
...
let total_reward = total_balance - self.last_total_balance;
...
let remaining_reward = total_reward - owners_fee;
self.total_staked_balance += remaining_reward;   // <- shared pro-rata over CURRENT total_stake_shares
```
The reward is computed purely as "new balance minus last recorded balance" and applied to every share that exists in `total_stake_shares` at the moment `internal_ping` runs — regardless of how recently those shares were purchased. `internal_stake` (`staking-pool/src/internal.rs:70-122`) has no delay: shares are minted and immediately eligible for the next reward the instant they are bought, at the price computed before that reward is applied.

The contract's own README acknowledges the exact "external" pattern from the report — an arbitrary/injected transfer being distributed as profit to whoever holds shares at the next `ping`: [1](#0-0) 

Sequence:
1. Alice deposits/stakes `X` shares (epoch `E`).
2. A transfer lands on the pool account (owner funding rewards, gas rebate, or any account sending NEAR directly), or validator rewards accrue — this increases `env::account_balance()`/`env::account_locked_balance()` but is not yet recognized because `internal_ping` only acts on epoch change: [2](#0-1) 
3. Bob, observing this (mempool visibility of the incoming transfer, or simply knowing rewards are pending), calls `deposit_and_stake`, which runs `internal_ping()` first (no-op, same epoch) then buys shares at the *pre-reward* price via `internal_stake`: [3](#0-2) 
4. When the epoch switches, the next `ping` (from any actor) distributes the *entire* accumulated reward pro-rata over `total_stake_shares`, which now includes Bob's freshly-bought, unearned shares: [4](#0-3) 

Bob captures a reward slice identical in kind to the `MembershipERC1155::sendProfit` front-run described in the report, diluting Alice's payout, and — unlike the reported case — Bob's window to act is the *entire remaining length of the current epoch* (up to ~12 hours), not a single block, making this materially easier to exploit than the original finding.

### Impact Explanation
This meets the High-impact bar: "rewards or fees mis-attributed... where another party settles on it." Existing delegators (e.g. Alice) receive less reward than they are entitled to, while a late, unentitled staker (Bob) receives a reward payout he did not earn, funded at the expense of long-term stakers, each time `internal_ping` (`staking-pool/src/internal.rs:192-250`) fires.

### Likelihood Explanation
No privileged role, redeploy, or malicious validator is required — any account can call the public `deposit_and_stake` (`staking-pool/src/lib.rs:227-236`). The only requirement is observing (or simply timing around) a balance increase to the pool before the next epoch boundary, which the contract's documented behavior confirms happens for gas rebates, validator rewards, and even accidental/intentional plain transfers [1](#0-0) . Because the window spans an entire epoch rather than a single transaction, likelihood is higher than in the originally reported analog.

### Recommendation
Introduce a minimum holding/vesting delay before newly staked shares become eligible for reward distribution (e.g., only shares that existed as of the *start* of the epoch being rewarded should participate in that epoch's `internal_ping` distribution), mirroring the "membership delay" mitigation recommended in the referenced report.

### Proof of Concept
Based on the existing test harness (`staking-pool/src/lib.rs` `Emulator`, see `test_stake_with_fee`/`test_two_delegates` patterns), the exploit sequence is:
1. Alice deposits and stakes `ntoy(1_000_000)` in epoch `E` (`emulator.contract.deposit(); emulator.contract.stake(...)`).
2. Simulate a reward/transfer arriving on the pool account by increasing `emulator.locked_amount` (as done via `emulator.locked_amount = locked_amount + ntoy(...)` in existing tests) — representing validator reward or an external transfer — while still in epoch `E` (no `skip_epochs` yet, so `ping` is a no-op per `staking-pool/src/internal.rs:194-199`).
3. Bob calls `deposit()`/`stake()` for a large amount in the same epoch `E`, right before the epoch switches — his shares are minted at the current (pre-distribution) price via `internal_stake` (`staking-pool/src/internal.rs:70-122`).
4. Advance the epoch (`emulator.skip_epochs(1)`) and call `ping()`.
5. Observe via `get_account_staked_balance` that Bob receives a proportional share of the reward pool that accrued before he ever staked, reducing Alice's proportional share versus what it would have been had Bob not joined before the `ping`. [5](#0-4) [6](#0-5) [3](#0-2)

    pub(crate) fn internal_stake(&mut self, amount: Balance) {
        assert!(amount > 0, "Staking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        // Calculate the number of "stake" shares that the account will receive for staking the
        // given amount.
        let num_shares = self.num_shares_from_staked_amount_rounded_down(amount);
        assert!(
            num_shares > 0,
            "The calculated number of \"stake\" shares received for staking should be positive"
        );
        // The amount of tokens the account will be charged from the unstaked balance.
        // Rounded down to avoid overcharging the account to guarantee that the account can always
        // unstake at least the same amount as staked.
        let charge_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);
        assert!(
            charge_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        assert!(
            account.unstaked >= charge_amount,
            "Not enough unstaked balance to stake"
        );
        account.unstaked -= charge_amount;
        account.stake_shares += num_shares;
        self.internal_save_account(&account_id, &account);

        // The staked amount that will be added to the total to guarantee the "stake" share price
        // never decreases. The difference between `stake_amount` and `charge_amount` is paid
        // from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let stake_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);

        self.total_staked_balance += stake_amount;
        self.total_stake_shares += num_shares;

        env::log(
            format!(
                "@{} staking {}. Received {} new staking shares. Total {} unstaked balance and {} staking shares",
                account_id, charge_amount, num_shares, account.unstaked, account.stake_shares
            )
                .as_bytes(),
        );
        env::log(
            format!(
                "Contract total staked balance is {}. Total number of shares {}",
                self.total_staked_balance, self.total_stake_shares
            )
            .as_bytes(),
        );
    }

    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true
    }
