### Title
Escrowed tranche tokens can be fulfilled for zero underlying when a write-off request has `underlyings == 0` - (File: contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow` lets a lender escrow tranche tokens in exchange for a requested amount of underlying, which any wallet (a "fulfiller", typically the borrower) pays to take the tranches. `createWriteOffRequest()` validates `amount != 0` but never validates `underlyingsRequested != 0`, and `fullfillWriteOffRequest()` checks only that `_underlyings >= currentRequest.underlyings`. When `underlyings == 0`, a fulfiller can pass `_underlyings = 0`, pay nothing, and still receive all escrowed tranche tokens. This is the same bug class as the external report: no explicit check that a nonzero asset amount can be claimed while providing zero payment.

### Finding Description
In `createWriteOffRequest`, only the tranche `amount` is checked for nonzero; `underlyingsRequested` may be 0. [1](#0-0) 

In `fullfillWriteOffRequest`, the only price check is `_underlyings < currentRequest.underlyings`, so `_underlyings = 0` passes when the request's `underlyings` is 0. The fee computation `(_underlyings * _exitFee) / FULL_VALUE` is then 0, the user receives `_underlyings - _totFee = 0`, and the fulfiller still receives `_tranches` (the full escrowed amount, since `_tranches` must equal `currentRequest.tranches`). [2](#0-1) 

There is no analog of the recommended `actualTopUpTokens == 0 && actualSeizeTokens > 0` guard anywhere: a nonzero seize of tranche tokens is settled with zero underlying. Tranche tokens are not worthless — they represent a claim on the credit vault redeemable via `IdleCDOEpochVariant` withdrawal paths or burnable by the borrower via `writeOffDeposit`, so the fulfiller acquires real value for free.

### Impact Explanation
Direct theft: any unprivileged EOA can call `fullfillWriteOffRequest(victim, victimRequest.tranches, 0)` and receive all of the victim's escrowed tranche tokens while transferring 0 underlying. The lender loses the entire tranche position they escrowed (quantified loss = `currentRequest.tranches`, whose underlying value equals `tranches * virtualPrice / 1e18`). The lender also cannot simply fix the request afterward because `deleteWriteOffRequest` may be front-run by the free fulfillment, and a zero-price request can persist indefinitely.

### Likelihood Explanation
The exploit requires a write-off request with `underlyings == 0` to exist. The contract permits this: `createWriteOffRequest` accepts `underlyingsRequested = 0` and even accumulates it via `currentRequest.underlyings + underlyingsRequested`, so a lender adding tranches to an existing request can leave the aggregate ask at 0. This is plausible as a fat-finger/integrator error (e.g., a UI defaulting the field to 0), and is exactly the kind of edge case the external report recommended guarding explicitly even though it seemed unlikely under current parameters. No privileged role misbehavior is needed; the fulfiller is an explicitly in-scope unprivileged attacker class ("a write-off fulfiller").

### Recommendation
Mirror the external fix: revert when a nonzero tranche amount would be exchanged for zero underlying.

```solidity
// in fullfillWriteOffRequest, after the WrongRequest check
if (_underlyings == 0 && _tranches > 0) {
    revert WrongRequest(); // or a dedicated ZeroPayment error
}
```

Optionally also require `underlyingsRequested != 0` in `createWriteOffRequest` so zero-price requests cannot be created unintentionally.

```solidity
function testFulfillForFree() public {

    // 1. Lender escrows tranches but (mis)configures a zero underlying ask —
    //    permitted because createWriteOffRequest does not check it.
    vm.startPrank(lender);
    tranche.approve(address(escrow), trancheAmt);
    escrow.createWriteOffRequest(trancheAmt, 0);
    vm.stopPrank();

    (uint256 t, uint256 u) = escrow.userRequests(lender);
    assertEq(t, trancheAmt);
    assertEq(u, 0);

    // 2. Unprivileged attacker fulfills with _underlyings = 0.
    //    No approve needed since 0 tokens are pulled.
    uint256 attackerTranchePre = tranche.balanceOf(attacker);
    vm.prank(attacker);
    escrow.fullfillWriteOffRequest(lender, trancheAmt, 0);

    // 3. Attacker receives all escrowed tranches for free; lender received nothing.
    assertEq(tranche.balanceOf(attacker), attackerTranchePre + trancheAmt);

}
```

```text
  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
```

```text
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
```
