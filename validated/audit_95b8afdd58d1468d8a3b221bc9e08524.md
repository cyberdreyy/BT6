### Title
Unauthenticated access to LOOP plugin pprof/metrics/discovery endpoints allows information disclosure and resource-exhaustion via unauthenticated proxy - ([File: core/web/loop_registry.go])

### Summary
`loopRoutes` in `core/web/router.go` registers four handlers from `LoopRegistryServer` (`discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) directly on the base `api` group without any `auth.Authenticate` middleware or `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, unlike every comparable route in `v2Routes` (including the node's own `metricRoutes(authv2)` pprof group). None of the four handler functions call `auth.GetAuthenticatedUser` or check `clsessions.UserRoleView/Run/Edit/Admin`.

### Finding Description
`loopRoutes(app, api)` is called at [1](#0-0) , mounting its routes on the plain `api` group (session middleware + rate limiter only, no `auth.Authenticate`):
```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
``` [2](#0-1) 

Contrast this with the node's own pprof endpoints, which are deliberately wrapped in the authenticated group `authv2` via `metricRoutes(authv2)` at [3](#0-2) , and every other sensitive v2 route which is wrapped with `auth.RequiresEditRole`/`auth.RequiresAdminRole` (e.g. lines 251-443). No such wrapper is present for `loopRoutes`.

None of `pluginMetricHandler` [4](#0-3) , `pluginPPROFHandler` [5](#0-4) , `pluginPPROFPOSTSymbolHandler` [6](#0-5) , or `discoveryHandler` [7](#0-6)  reference `auth.GetAuthenticatedUser`, `clsessions.UserRoleView/Run/Edit/Admin`, or any `auth.RequiresXRole` wrapper. The existing unit tests in `core/web/loop_registry_internal_test.go` only cover marshal/write-error paths and never assert on auth, confirming there is no auth check anywhere in this call path.

An unauthenticated attacker who can reach the node's HTTP listener can therefore:
- Enumerate registered LOOP plugins via `GET /discovery` (plugin names, ports, hostnames).
- Pull full Prometheus metrics for any named plugin via `GET /plugins/:name/metrics` (proxied from the internal LOOP process, potentially containing operational/internal state).
- Trigger `net/http/pprof` endpoints on the plugin's internal debug port via `GET /plugins/:name/debug/pprof/*profile` and `POST /plugins/:name/debug/pprof/symbol` — including `profile` (CPU profiling for attacker-chosen `seconds`, tying up the plugin process) and `trace`/`goroutine`/`heap` dumps that can leak internal stack traces, addresses, and other memory contents from the LOOP plugin process, and can be used as a remote unauthenticated CPU/memory exhaustion vector.

### Impact Explanation
This is an authentication/authorization-wrapper omission (missing `auth.Authenticate` + role check) on a full handler family, not a subtler logic bug — the routes are registered with zero auth middleware while structurally identical routes (`metricRoutes`) are wrapped in `authv2`. Impact: unauthenticated information disclosure of internal LOOP plugin runtime data (metrics/pprof/heap/goroutine dumps) and an unauthenticated resource-exhaustion / limited DoS vector against LOOP plugin processes (e.g., long-running CPU profile/trace requests), reachable by any network client with no credentials.

### Likelihood Explanation
Trivial and fully repeatable: no credentials, tokens, or session are required; only the node's HTTP port must be reachable (same precondition as any other unauthenticated node.js endpoint). It requires only that at least one LOOP plugin be registered (`plugins.LoopRegistry`), which is standard when LOOP plugins (e.g., median, EVM relayer LOOPPs) are enabled.

### Recommendation
Wrap `loopRoutes`' router group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` and apply `auth.RequiresEditRole` or `auth.RequiresAdminRole` to the four routes, consistent with how `metricRoutes(authv2)` and other sensitive routes in `v2Routes` are protected.

### Proof of Concept
Go handler-level integration test plan (`core/web/router_test.go` style, using `SetupJSONAPITest`/gin test harness already used elsewhere in the package):
1. Build the router via `NewRouter(app, nil)` with a `plugins.LoopRegistry` containing at least one registered plugin (name `"test"`, `EnvCfg.PrometheusPort` set to a stub HTTP server).
2. For each of the 4 routes — `GET /discovery`, `GET /plugins/test/metrics`, `GET /plugins/test/debug/pprof/heap`, `POST /plugins/test/debug/pprof/symbol` — issue an `httptest.NewRequest` with **no** `Authorization` header and **no** session cookie.
3. Assert current (vulnerable) behavior: response status is `200`/`404` (plugin-not-found) rather than `401 Unauthorized`/`403 Forbidden`.
4. Add a table-driven test enumerating every route registered inside `loopRoutes` (reflect over `r.Routes()` filtered by handler names matching `LoopRegistryServer`) and assert each has a preceding `auth.RequiresEditRole`/`auth.RequiresAdminRole`-wrapped handler in the chain; the test should fail today, proving zero call sites reference the role wrapper.
5. After applying the recommended fix, the same requests should return `401` (no session/token) confirming the wrapper closes the gap.

func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

	pluginName := gc.Param("name")

	if !ok {

	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)

	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
