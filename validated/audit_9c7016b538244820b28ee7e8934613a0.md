### Title
Unauthenticated fan-out to DON nodes in `confidentialrelay` handler's `HandleJSONRPCUserMessage` - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`(*handler).HandleJSONRPCUserMessage` in the `confidentialrelay` package only validates the JSON-RPC request ID length before creating an `activeRequest` and calling `fanOutToNodes`, with no signature/authentication check, no `donConfig.DONConfig` membership check, no workflow-owner allowlist check, and no subscription/quota check. This differs from the sibling `vault` handler, which gates all sensitive methods through `h.requestProcessor.ProcessRequest` before fanning out.

### Finding Description
The gateway ingress path (`core/services/gateway/gateway.go:218-292`, `ProcessRequest`) decodes the raw JSON-RPC request and, for a non-legacy request, routes it directly to the resolved handler's `HandleJSONRPCUserMessage`: [1](#0-0) 

For the `confidentialrelay` service, that handler is: [2](#0-1) 

The only checks performed are `req.ID != ""` and `len(req.ID) <= 200`. No code path checks `req.Auth`, no signature verification, no lookup against `h.donConfig.Members`/workflow-owner allowlists, and no balance/subscription check, before `h.fanOutToNodes(ctx, l, ar)` dispatches the request to DON members. By contrast, the `vault` handler explicitly calls `h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)` and rejects unauthorized requests before doing any node dispatch for non-public-key methods: [3](#0-2) 

The confidentialrelay handler's own comment on the node-response path acknowledges that authorization/signature verification is deferred entirely to the enclave running on the node ("the enclave remains responsible for signature and quorum verification"): [4](#0-3) 

This confirms that the gateway itself performs zero authorization before dispatching `MethodSecretsGet`/`MethodCapabilityExec` requests to every DON member (`h.donConfig.Members`), meaning any unauthenticated caller reaching the gateway's HTTP/WS ingress can trigger a full fan-out to the DON for arbitrary request IDs.

### Impact Explanation
Any unauthenticated external caller can force the gateway to dispatch requests to every node in the DON (`len(h.donConfig.Members)` sends per call), consuming node network/compute resources for each request, with no allowlist or quota gate in front of it. This is a resource-exhaustion/DoS vector against DON node execution resources, matching the "unauthorized job run" / griefing-resource-consumption class of impact — the actual secret/data disclosure is still blocked by the enclave downstream, but node compute and bandwidth are consumed without authorization.

### Likelihood Explanation
No credentials are required: any client capable of sending a raw JSON-RPC POST to the gateway HTTP endpoint for the confidentialrelay service can repeat this an unbounded number of times (bounded only by generic gateway/system rate limits, if any exist upstream, which were not found in this handler). This makes the issue trivially and repeatably exploitable by an unprivileged actor.

### Recommendation
Add a request-side authorization/rate-limiting gate to `confidentialrelay.HandleJSONRPCUserMessage`, mirroring the `vault` handler's `requestProcessor.ProcessRequest` pattern, before calling `fanOutToNodes` — validate signed request authorization, workflow-owner allowlist membership, and/or apply a per-caller rate limiter, rejecting requests that fail these checks prior to consuming DON node resources.

### Proof of Concept
Go handler-level test plan:
1. Construct a `confidentialrelay.handler` via its constructor with a mock `DON`/`donConfig.Members` set and a stub `Callback`.
2. Build a `jsonrpc.Request[json.RawMessage]{ID: "test", Method: MethodSecretsGet}` with `Auth` left empty/unset (no signature).
3. Call `handler.HandleJSONRPCUserMessage(ctx, req, callback)` directly.
4. Assert: (a) no error indicating "unauthorized"/"forbidden" is returned, (b) the mock DON's `SendToNode` is invoked once per member in `donConfig.Members` (confirming fan-out occurred), (c) `h.activeRequests[req.ID]` is populated — demonstrating that an unauthenticated, unsigned request reaches and executes `fanOutToNodes`.

```go
func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}
```
