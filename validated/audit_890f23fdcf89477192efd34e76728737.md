### Title
Zip extractor performs no path-confinement check, unlike the tar+zstd extractor - (File: `helpers/archives/zip_extract.go`)

### Summary
`extractZipFile` and its helpers (`extractZipFileEntry`, `extractZipDirectoryEntry`, `extractZipSymlinkEntry`) write files using `file.Name` directly with no `filepath.Join(dir, ...)` and no path-confinement check, whereas the tar+zstd extractor explicitly joins the target `dir` with the entry name and rejects any resolved path that escapes it. This is a real, format-dependent gap: the same malicious archive-entry name (`../../../../tmp/pwned`) that `tarzstd`'s `Extract` rejects with `"cannot be extracted outside of chroot"` is not rejected by the zip code path at all.

### Finding Description
`archives.ExtractZipArchive` iterates `archive.File` entries and calls `extractZipFile(file)` for each [1](#0-0) . `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then dispatches to `extractZipDirectoryEntry`/`extractZipSymlinkEntry`/`extractZipFileEntry`, all of which use `file.Name` verbatim as the filesystem path passed to `os.Mkdir`, `os.Symlink`, or `os.OpenFile` [2](#0-1) . There is no `dir` parameter threaded into this code at all — it operates purely on the process's current working directory and the raw entry name from the zip's central directory, which is fully attacker-controlled (a job author can produce/upload an arbitrary cache/artifact zip).

By contrast, `tarzstd`'s `extractor.Extract` explicitly computes `path, err = filepath.Abs(filepath.Join(e.dir, hdr.Name))` and enforces `strings.HasPrefix(path, e.dir+string(filepath.Separator))`, returning an error and aborting extraction of that entry if it would land outside `e.dir` [3](#0-2) .

Confirming the format-dependent nature of the gap: `ziplegacy.extractor.Extract` (which implements the `archive.Extractor` interface used by the generic dispatcher `archive.NewExtractor`) accepts a `dir` field in its struct but **never uses it** — it just calls `zip.NewReader` and `archives.ExtractZipArchive(zr)`, passing no directory information downstream at all [4](#0-3) . The `dir` argument is silently discarded. This is in stark contrast to `tarzstd.NewExtractor`, which stores `dir` and actively uses it for confinement [5](#0-4) , and to `fastzip.extractor.Extract`, which passes `e.dir` into the third-party `fastzip.NewExtractorFromReader` library call (that library is expected to perform its own path sanitization, though this was not independently verified here) [6](#0-5) .

Formats are selectable via the `archive.Format` constants `Zip`, `ZipZstd`, `TarZstd` registered in the generic dispatcher `archive.NewExtractor(format, r, size, dir)` [7](#0-6) , meaning the extractor actually invoked for a cache/artifact archive depends on job/runner configuration (`Zip` format maps to the `ziplegacy` package based on the file naming convention seen in the codebase). Since `ziplegacy`'s path is entirely unconfined, any entry name containing `../` sequences is written relative to the process's current working directory with no restriction, which is the classic "Zip Slip" pattern.

I was not able to fully trace, within the remaining tool budget, the exact call site that sets the process's current working directory (`os.Chdir`) before invoking `ExtractZipArchive`/`cache_extractor.go`/`artifacts_downloader.go`, so I cannot confirm with 100% certainty what directory a resolved `../../../../tmp/pwned` would ultimately land relative to at runtime. However, this does not change the core finding: the confinement check that exists in the tar+zstd path is structurally absent from the zip path — the `dir` value is dropped on the floor in `ziplegacy.extractor.Extract` and is never joined or validated against in `helpers/archives/zip_extract.go`. Regardless of what the current working directory happens to be at extraction time, `file.Name` (attacker-controlled) is used unsanitized as an absolute/relative filesystem path for `os.Mkdir`/`os.Symlink`/`os.OpenFile`, so a name like `/tmp/pwned` (absolute) or many `../` segments will write outside of the intended build/cache directory tree regardless of the extraction cwd.

### Impact Explanation
An unprivileged pipeline author who controls the contents of a cache or artifact archive (or who can cause the runner to select the `zip`/legacy-zip extraction path) can craft a zip entry whose name is `../../../../tmp/pwned` or an absolute path, and have the runner write/overwrite files anywhere the runner process has filesystem permissions — outside the job's build/cache directory. This violates the "File operations must stay within intended build/cache/artifact roots" invariant and, depending on shared-runner filesystem layout, can affect other jobs/tenants sharing the same host/build path space.

### Likelihood Explanation
No special privileges are required beyond normal ability to control cache/artifact archive format and contents (a standard CI capability). The bug is deterministic and format-selection is the only "precondition," which is plausible given the code registers multiple selectable zip variants (`Zip`, `ZipZstd`) alongside `TarZstd`. This is trivially and repeatably reproducible with a unit test constructing a `zip.Writer` with a hostile entry name.

### Recommendation
Add the same path-confinement check used in `tarzstd_extractor.go` to the zip extraction path: thread a `dir` parameter through `ExtractZipArchive`/`ExtractZipFile`/`extractZipFile` (and its dir/symlink/file entry helpers), compute `filepath.Abs(filepath.Join(dir, file.Name))` for every entry, and reject/skip entries whose resolved path does not have `dir` as a prefix, mirroring the `tarzstd` behavior. Ensure `ziplegacy.extractor.Extract` actually uses its stored `dir` field instead of discarding it.

func extractZipDirectoryEntry(file *zip.File) (err error) {
	err = os.Mkdir(file.Name, file.Mode().Perm())

	// The "directory does exist" error is not an error for us
	if os.IsExist(err) {
		err = nil
	}
	return
}

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}
