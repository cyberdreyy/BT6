## Analysis

The reported bug's core pattern — a reentrant/nested call mutates persisted state via its own fresh copy, while the outer caller still holds a **stale in-memory snapshot** that it later writes back, silently clobbering the nested update (deleting `initialGas`/`userFeeInfo` after the reentrant call already zeroed them) — has a structural analog in `process_pending_responses_for_block`.

### Title
Stale `BlockInfo` write-back in `process_pending_responses_for_block` can erase a just-broadcast self-signature, decoupling the signer's outbound acceptance from its own SignerDB record

### Summary
`process_pending_responses_for_block` holds a single `&mut BlockInfo` across three sequential replay loops (pre-commits, rejections, signatures) for early votes that arrived before the block proposal itself.

### Finding Description
When a block proposal arrives, `handle_block_proposal` builds a fresh, `Unprocessed` `BlockInfo`, stores it, then replays any early votes via `process_pending_responses_for_block(..., &mut block_info, pending_responses)` [1](#0-0) .

Inside that function, the pre-commit loop calls `handle_block_pre_commit`, which independently performs its *own* `block_lookup_by_reward_cycle`, mutates that fresh copy, and persists it via `signer_db.insert_block` — this path can advance the block all the way to `LocallyAccepted` (signing and broadcasting our acceptance) if the pre-commit weight threshold and conflict checks pass: it calls `mark_locally_accepted`, `handle_block_signature`, and `send_block_response`, i.e. it emits our own signature to the rest of the signer set [2](#0-1) . Critically, none of this touches the caller's outer `block_info` reference in `process_pending_responses_for_block` [3](#0-2) .

The very next loop in the same function replays queued rejections against that **same stale** outer `block_info` via `store_and_process_block_rejection` [4](#0-3) . That function checks `block_info.has_reached_consensus()` on the stale copy (still `Unprocessed`), tallies stored rejection weight, and — if the reject threshold is reached — calls `block_info.mark_globally_rejected()` followed by `self.signer_db.insert_block(block_info)` [5](#0-4) . `BlockInfo::check_state` only validates the transition *within the in-memory object being mutated* (`Unprocessed -> GloballyRejected` is legal) [6](#0-5) ; `insert_block` performs no optimistic-concurrency check against the row `handle_block_pre_commit` just wrote. The write therefore **overwrites the `LocallyAccepted`/`signed_self` record with a `GloballyRejected` record that has no signature**, even though this signer has already broadcast a valid `BlockResponse::Accepted` for that exact block to every peer.

### Impact Explanation
This breaks the "signed vs. persisted" equality the whole equivocation-guard design depends on. Other signers count the already-broadcast acceptance toward the network's 70% threshold, but this signer's own SignerDB no longer shows the block as signed. Downstream, `get_signed_conflicts`/`check_block_against_signer_db_state`, which the pre-commit and re-proposal paths rely on to prevent signing two conflicting blocks at the same height (documented in `docs/signer-flows.md` section 5) [7](#0-6) , will find no record of this signature and can let the signer later place a second, conflicting signature on a sibling block at the same height/tenure — the exact equivocation scenario the guard exists to prevent. This is a High-impact "losing the equivocation guard" / state-machine wedge consistent with the scope's Critical/High bar.

### Likelihood Explanation
Reachable with ordinary message propagation: pre-commit and rejection votes routinely arrive before the proposal itself and are queued via `drain_pending_block_responses`/pending tables, then replayed in this fixed order by `process_pending_responses_for_block` [8](#0-7) . No majority collusion, no other signer's key, and no auth token access are required — only normal gossip timing (a single slot miner/network delay causing early votes to precede the proposal).

### Recommendation
`process_pending_responses_for_block` should re-fetch `block_info` from `signer_db` (or pass the hash and re-load) between each replay loop — or at minimum before `store_and_process_block_rejection`/`store_and_process_block_signature` — instead of reusing a single in-memory snapshot across calls that can independently persist newer state. Alternatively, `insert_block` could enforce optimistic concurrency (e.g., compare-and-swap on `state`) to reject stale overwrites.

### Proof of Concept
1. Signer S has not yet received block proposal `B` for height `h`.
2. Two early votes for `B` arrive out of order and get queued: a pre-commit from signer P (pushing S past the pre-commit threshold once `B` arrives) and a rejection from signer R (queued earlier, contributing toward the reject threshold).
3. Proposal `B` arrives; `handle_block_proposal` builds a fresh `BlockInfo`, validates it, stores it, and calls `process_pending_responses_for_block`.
4. The pre-commit loop replays P's pre-commit via `handle_block_pre_commit`, which (using its own DB-loaded copy) crosses the pre-commit threshold, passes the conflict checks, calls `mark_locally_accepted`, and broadcasts S's own `BlockResponse::Accepted` for `B` to the network, persisting `LocallyAccepted` to `signer_db`.
5. The rejection loop then replays R's stale-queued rejection via `store_and_process_block_rejection`, using the *original* stale `block_info` (still `Unprocessed`). If the reject weight (from R plus any other previously stored rejections) crosses the reject threshold, it calls `mark_globally_rejected` and `signer_db.insert_block(block_info)`, overwriting S's DB record to `GloballyRejected` with `signed_self = None`.
6. S has now broadcast a valid acceptance signature for `B` to the network (counted by peers) while its own SignerDB shows `B` as globally rejected and unsigned, breaking the guard that prevents S from later signing a conflicting sibling block at height `h`.

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
