### Title
Zip extraction allows a directory-then-symlink swap to redirect a later path outside the extraction root - ([File: helpers/archives/zip_extract.go])

### Summary
`ExtractZipArchive` processes `archive.File` entries strictly in stored (attacker-controlled) order with no path-containment validation of file names or symlink targets. A crafted cache/artifact zip can create a directory, replace it with a symlink pointing outside the extraction root, then write a file through that symlink path, achieving a write outside the intended cache/build root.

### Finding Description
`ExtractZipArchive` iterates `archive.File` in the order stored in the zip and dispatches each to `extractZipFile`, which calls `extractZipDirectoryEntry`, `extractZipSymlinkEntry`, or `extractZipFileEntry` based on entry type [1](#0-0) . None of these functions, nor `ExtractZipArchive` itself, validate that `file.Name` stays within the destination root, nor that a symlink's target (the decompressed link data used in `os.Symlink(string(data), file.Name)`) points inside the root [2](#0-1) . The only pre-extraction check is `errorIfGitDirectory`, which only rejects `.git` paths and has nothing to do with path containment [3](#0-2) .

Exploit flow:
1. Entry `shared/` (directory) is extracted via `extractZipDirectoryEntry`, creating an empty directory `shared` (`os.Mkdir`, tolerating `os.IsExist`) [4](#0-3) .
2. Entry `shared` (symlink) is extracted via `extractZipSymlinkEntry`, which unconditionally does `os.Remove(file.Name)` (succeeds because the directory is empty) followed by `os.Symlink(string(data), file.Name)`, replacing `shared` with a symlink to an attacker-chosen out-of-root path such as `/tmp/outside` [5](#0-4) .
3. Entry `shared/payload` (regular file) is extracted via `extractZipFile` -> `extractZipFileEntry`. Before that, `extractZipFile` calls `os.MkdirAll(filepath.Dir(file.Name), 0o777)` on `shared`, which resolves the symlink (if it points to an existing directory this is a no-op success), and then `extractZipFileEntry` opens `shared/payload`, which the OS resolves through the symlink to `/tmp/outside/payload`, and writes attacker content there [6](#0-5) .

This zip is fed to `archives.ExtractZipArchive` from the legacy zip extractor used by `commands/helpers/cache_extractor.go`'s `CacheExtractorCommand.Execute`, which downloads a cache archive (fully attacker-controlled content, since the same pipeline author previously created it via the cache archiver) and extracts it into the job working directory with `archive.NewExtractor(format, f, size, wd).Extract(...)` [7](#0-6) [8](#0-7) . No step in this call chain validates that resolved paths stay under `wd`.

### Impact Explanation
An attacker who controls the content of a cache archive (any pipeline author, since caches are created from files under their own job's control) can arrange zip entry order to redirect a nested path outside the intended extraction root, achieving an out-of-root file write on the runner's host/container filesystem at cache-restore time. This is a concrete path/file-system boundary violation matching the scoped impact (cross-boundary write via directory→symlink swap during a single archive extraction).

### Likelihood Explanation
Fully feasible and repeatable: it only requires building a zip with three entries in a specific order (`archive/zip` package allows arbitrary entry order and arbitrary symlink target content), no special runner configuration or privileges beyond running a normal pipeline that populates and later restores a cache. The vulnerable code has no defenses against this ordering (no path containment check on names, no target validation on symlinks, no re-validation of an already-created path before writing through it).

### Recommendation
Before creating/writing any entry, resolve `filepath.Join(root, file.Name)` and verify (via `filepath.EvalSymlinks` on the existing parent chain, or by tracking previously-created paths within the extraction and refusing to traverse through them) that the final write target stays under the extraction root. Additionally, validate symlink targets (`string(data)`) so that absolute paths or paths that resolve (relative to the link's location) outside root are rejected, and refuse to overwrite a directory entry created earlier in the same archive with a symlink pointing outside root, i.e. treat entry names as append-only/immutable per extraction rather than trusting later entries to safely replace earlier ones.

### Proof of Concept
```go
func TestExtractZipArchive_SymlinkSwapEscapesRoot(t *testing.T) {
    outsideDir := t.TempDir() // simulates "/tmp/outside"
    root := t.TempDir()
    origWd, _ := os.Getwd()
    _ = os.Chdir(root)
    defer os.Chdir(origWd)

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)

    // 1. directory entry "shared/"
    dh := &zip.FileHeader{Name: "shared/"}
    dh.SetMode(os.ModeDir | 0o755)
    w, _ := zw.CreateHeader(dh)
    _ = w // no data needed for dir

    // 2. symlink entry "shared" -> outsideDir
    sh := &zip.FileHeader{Name: "shared"}
    sh.SetMode(os.ModeSymlink | 0o777)
    w, _ = zw.CreateHeader(sh)
    _, _ = w.Write([]byte(outsideDir))

    // 3. file entry "shared/payload"
    fh := &zip.FileHeader{Name: "shared/payload"}
    fh.SetMode(0o644)
    w, _ = zw.CreateHeader(fh)
    _, _ = w.Write([]byte("attacker-data"))

    _ = zw.Close()

    zr, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    _ = archives.ExtractZipArchive(zr)

    // Assert payload was NOT written outside the root
    _, err := os.Stat(filepath.Join(outsideDir, "payload"))
    assert.True(t, os.IsNotExist(err), "payload must not exist outside extraction root, but escaped to %s", outsideDir)
}
```
Expected (buggy) behavior today: the assertion fails — `payload` is created under `outsideDir`, proving the escape. After a fix enforcing root containment, the test should pass (file not created outside root, and extraction should either skip the entry or error).

func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	data, err = io.ReadAll(in)
	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}
	defer func() { _ = in.Close() }()

	// Remove file before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}

func ExtractZipArchive(archive *zip.Reader) error {
	tracker := newPathErrorTracker()

	for _, file := range archive.File {
		if err := errorIfGitDirectory(file.Name); tracker.actionable(err) {
			printGitArchiveWarning("extract")
		}

		if err := extractZipFile(file); tracker.actionable(err) {
			logrus.Warningf("%s: %s (suppressing repeats)", file.Name, err)
		}
	}
