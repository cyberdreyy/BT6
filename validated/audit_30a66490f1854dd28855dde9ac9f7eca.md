### Title
`RpcClient::get_supply` can panic the validator via unchecked subtraction of `non_circulating_supply.lamports` from `total_supply` - (File: rpc/src/rpc.rs)

### Summary
The `getSupply` JSON-RPC method computes `circulating: total_supply - non_circulating_supply.lamports` using a plain, non-checked/non-saturating subtraction. `total_supply` is `bank.capitalization()` and `non_circulating_supply.lamports` is computed independently by scanning stake-program accounts and a hardcoded non-circulating account list. If the independently-computed non-circulating sum ever exceeds capitalization (e.g., due to any accounting drift/edge case between the hardcoded/derived non-circulating set and `capitalization()`), this subtraction underflows a `u64`, which panics in debug/overflow-checked builds and would produce a wildly wrong value on wrapping builds. [1](#0-0) 

### Finding Description
`get_supply` first calls `self.calculate_non_circulating_supply(&bank)`, which delegates to `calculate_non_circulating_supply` in `runtime/src/non_circulating_supply.rs`. That function builds a `HashSet` of non-circulating pubkeys (a hardcoded mainnet-beta list plus any stake accounts that are locked or whose withdraw authority is on a hardcoded list), then sums `bank.get_balance(pubkey)` over that set to produce `NonCirculatingSupply.lamports`. [2](#0-1) 

Back in the RPC handler, `total_supply` comes from `bank.capitalization()`, a value maintained incrementally by the runtime as accounts are created/credited/debited across the entire ledger — a completely independent accounting path from the non-circulating-accounts scan. The handler then does:

```rust
circulating: total_supply - non_circulating_supply.lamports,
```

with ordinary `-` (not `checked_sub`/`saturating_sub`), unlike other lamport arithmetic elsewhere in the codebase which consistently uses `checked_sub`/`saturating_sub` (e.g. `transaction-context/src/instruction_accounts.rs` `checked_sub_lamports`, `rpc/src/rpc_subscriptions.rs` `checked_sub`). [3](#0-2) [4](#0-3) 

This is directly analogous to the Tokemak `LMPVault._withdraw()` bug class: two quantities (`totalAssetsToPull` vs `debtDecrease`/`totalAssetsPulled` in the original; `capitalization()` vs the independently-scanned non-circulating sum here) are computed via separate code paths/loops and then subtracted without a bound/`Math.max` check, creating an underflow if the invariant "subtrahend ≤ minuend" is ever violated by drift between the two paths.

### Impact Explanation
`getSupply` is an unprivileged, unauthenticated JSON-RPC method reachable by any client with a single call. If the underflow is triggered (e.g., a future/edge-case addition to the hardcoded non-circulating list, a stake account balance quirk, or any transient state where the independently tracked `capitalization()` diverges from the scanned non-circulating total), the subtraction panics the RPC thread. Depending on build flags (`overflow-checks`) this is either a hard panic (crashing/aborting the RPC-serving thread/process) or, on wrapping builds, an enormous incorrect `circulating` value returned to the caller (wrong data returned from a query). Either outcome fits the "concrete validator-process crash from one request" / "wrong data returned from a query" categories.

### Likelihood Explanation
Likelihood is moderate-to-low under normal current-mainnet conditions (the hardcoded lists were presumably validated against current capitalization), but the code contains no invariant check or safe arithmetic to guarantee the sum of the scanned non-circulating accounts can never exceed `capitalization()`. Any future change (new frozen program accounts, stake-account reward edge cases, or a bug in the hardcoded list) can silently violate this invariant, and the RPC layer has no defensive check. This mirrors exactly the root cause the external report calls out: relying on an assumed ordering/bound between two independently derived running totals without enforcing it via `checked_sub`/`saturating_sub` or an explicit `Math.max`/bound check.

### Recommendation
Replace the raw subtraction with a checked/saturating operation and handle the (should-never-happen) underflow gracefully instead of panicking:

```rust
circulating: total_supply.saturating_sub(non_circulating_supply.lamports),
```
or, to surface it as a detectable error rather than silently masking it:
```rust
let circulating = total_supply
    .checked_sub(non_circulating_supply.lamports)
    .ok_or_else(|| RpcCustomError::ScanError {
        message: "non-circulating supply exceeds total supply".to_string(),
    })?;
```
This aligns `get_supply` with the safe-arithmetic patterns already used elsewhere in the codebase (`checked_add_lamports`/`checked_sub_lamports`, `RecentItems::push`'s `checked_sub`).

### Proof of Concept
A deterministic PoC requires constructing a bank state where the stake-account scan (or a future addition to `non_circulating_accounts()`) sums to more than `bank.capitalization()`. This cannot be demonstrated purely from static analysis; it would require a Devin session with terminal/test access to build a custom genesis/bank in `runtime/src/non_circulating_supply.rs`'s test harness (as in `test_calculate_non_circulating_supply`) with an artificially inflated non-circulating account balance exceeding total capitalization, then call the equivalent of `get_supply`'s subtraction to confirm a panic under `overflow-checks = true`, and confirm wraparound under release-without-overflow-checks builds.

    async fn get_supply(
        &self,
        config: Option<RpcSupplyConfig>,
    ) -> RpcCustomResult<RpcResponse<RpcSupply>> {
        let config = config.unwrap_or_default();
        let bank = self.bank(config.commitment);
        let non_circulating_supply =
            self.calculate_non_circulating_supply(&bank)
                .await
                .map_err(|e| RpcCustomError::ScanError {
                    message: e.to_string(),
                })?;
        let total_supply = bank.capitalization();
        let non_circulating_accounts = if config.exclude_non_circulating_accounts_list {
            vec![]
        } else {
            non_circulating_supply
                .accounts
                .iter()
                .map(|pubkey| pubkey.to_string())
                .collect()
        };

        Ok(new_response(
            &bank,
            RpcSupply {
                total: total_supply,
                circulating: total_supply - non_circulating_supply.lamports,
                non_circulating: non_circulating_supply.lamports,
                non_circulating_accounts,
            },
        ))
    }

pub fn calculate_non_circulating_supply(bank: &Bank) -> ScanResult<NonCirculatingSupply> {
    debug!("Updating Bank supply, epoch: {}", bank.epoch());
    let mut non_circulating_accounts_set: HashSet<Pubkey> = HashSet::new();

    for key in non_circulating_accounts() {
        non_circulating_accounts_set.insert(key);
    }
    let withdraw_authority_list = withdraw_authority();

    let clock = bank.clock();
    let stake_accounts = if bank
        .rc
        .accounts
        .accounts_db
        .account_indexes
        .contains(&AccountIndex::ProgramId)
    {
        bank.get_filtered_indexed_accounts(
            &IndexKey::ProgramId(stake::program::id()),
            // The program-id account index checks for Account owner on inclusion. However, due to
            // the current AccountsDb implementation, an account may remain in storage as a
            // zero-lamport Account::Default() after being wiped and reinitialized in later
            // updates. We include the redundant filter here to avoid returning these accounts.
            |account| account.owner() == &stake::program::id(),
            None,
        )?
    } else {
        bank.get_program_accounts(&stake::program::id())?
    };

    for (pubkey, account) in stake_accounts.iter() {
        let stake_account = account
            .deserialize_data::<StakeStateV2>()
            .unwrap_or_default();
        match stake_account {
            StakeStateV2::Initialized(meta)
                if (meta.lockup.is_in_force(&clock, None)
                    || withdraw_authority_list.contains(&meta.authorized.withdrawer)) =>
            {
                non_circulating_accounts_set.insert(*pubkey);
            }
            StakeStateV2::Stake(meta, _stake, _stake_flags)
                if (meta.lockup.is_in_force(&clock, None)
                    || withdraw_authority_list.contains(&meta.authorized.withdrawer)) =>
            {
                non_circulating_accounts_set.insert(*pubkey);
            }
            _ => {}
        }
    }

    let lamports = non_circulating_accounts_set
        .iter()
        .map(|pubkey| bank.get_balance(pubkey))
        .sum();

    Ok(NonCirculatingSupply {
        lamports,
        accounts: non_circulating_accounts_set.into_iter().collect(),
    })
}
