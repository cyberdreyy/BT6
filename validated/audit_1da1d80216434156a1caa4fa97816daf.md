### Title
Second-pass metadata operations (`lchmod`/`os.Chtimes`) follow symlinks introduced by later archive entries, allowing permission/timestamp tampering on attacker-chosen paths - (File: helpers/archives/zip_extract.go)

### Summary
`ExtractZipArchive` extracts all archive entries in a first loop, then in a second loop re-iterates the same entries and applies `lchmod(file.Name, file.Mode())` and `processZipExtra`→`processZipTimestampField`'s `os.Chtimes(file.Name, ...)` using each entry's *original, stale* `zip.FileHeader.Mode()`, without re-checking what currently exists at `file.Name` on disk. Because `extractZipSymlinkEntry` performs no validation of the symlink target and archive order is fully attacker-controlled, an attacker can make a name that was created as a regular file in the first pass become a symlink to an arbitrary path by the time the metadata pass runs, causing `Chtimes`/`chmod` to operate on the attacker-chosen target instead of the extracted file.

### Finding Description
`ExtractZipArchive` [1](#0-0)  runs two passes over `archive.File`:

1. First loop calls `extractZipFile` for every entry, which dispatches on `file.Mode() & os.ModeType` to create directories, symlinks (`extractZipSymlinkEntry`), or regular files (`extractZipFileEntry`) [2](#0-1) . `extractZipSymlinkEntry` reads the link target straight from the entry's data with **no validation** and unconditionally removes any existing path before creating the symlink [3](#0-2) .
2. Second loop iterates the *same* `archive.File` slice again and, per entry, calls `lchmod(file.Name, file.Mode())` and `processZipExtra(&file.FileHeader)` → `processZipTimestampField`, which calls `os.Chtimes(file.Name, ...)` when `file.Mode().IsRegular()` or `IsDir()` [4](#0-3) .

Both metadata calls use `file.Name` as a plain path string and `file.Mode()` as recorded in that entry's header — they never re-`Lstat` the path to confirm it is still the same file-type object the first loop created for *that* entry.

Exploit flow (single crafted zip, no external race needed since the archive controls both passes deterministically):
- Entry A: regular file named `X`, mode `0644`, with a zip timestamp extra field.
- Entry B: symlink also named `X` (placed after A in the archive), whose link data points to an attacker-chosen absolute or relative path (`extractZipSymlinkEntry` performs no target validation, so `../../../home/gitlab-runner/.ssh/id_rsa` or any writable absolute path is accepted).

After the first loop completes, `X` is a symlink to the attacker's target (B's `os.Remove`+`os.Symlink` overwrote A's regular file). In the second loop, entry A is processed with its own recorded mode (`0644`, non-symlink):
- `lchmod("X", 0644)`: on Linux, `mode&os.ModeSymlink == 0` (A's declared mode has no symlink bit) so the "skip symlink" branch is not taken, and `flags` stays `0` — `Fchmodat` therefore follows the symlink and chmod's the real target file [5](#0-4) .
- `processZipTimestampField`: A's mode `IsRegular()` is `true`, so `os.Chtimes("X", ...)` is called; `os.Chtimes` always follows symlinks (no L-variant is used), so it changes mtime/atime of the attacker's target file [6](#0-5) .

Entry B itself is safe (its own mode has `ModeSymlink` set, so `lchmod` is skipped on Linux, and `IsRegular()`/`IsDir()` are false so `Chtimes` is skipped) — the vulnerability is specifically that entry A's stale metadata is applied to whatever now occupies path `X`. No existing check in this file re-validates the on-disk type or that `X` still resides inside the extraction root; `errorIfGitDirectory` only blocks `.git`-prefixed names [7](#0-6)  and does nothing for this case.

### Impact Explanation
An attacker who controls the content of a zip archive that the runner extracts (a job artifact or cache archive) can cause the runner process to `chmod`/`chtimes` an arbitrary filesystem path reachable by symlink from the extraction directory, limited only by the OS permissions of the runner process/user. This can widen or narrow permissions on unrelated files (e.g. relaxing perms on a private key or config file so it becomes readable/writable by other processes/users on a shared host), or tamper with timestamps of files outside the job's working directory — both real integrity/confidentiality violations beyond the intended "operate only inside job root" invariant. It does not grant arbitrary file content write or privilege escalation (mode bits are masked by `Perm()`, and `Chtimes`/`chmod` don't allow writing data), so impact is limited to permission/timestamp tampering, not code execution.

### Likelihood Explanation
Fully attacker-controlled and deterministic — it only requires crafting a zip archive with two same-named entries in the desired order (regular file then symlink) and getting the runner to extract it (e.g., as a job artifact/cache download, which is a normal, unprivileged job capability). No timing/race window against another process is required, since the ordering is guaranteed by the archive's own entry sequence and the two sequential loops inside a single function call. This makes it highly reliable/repeatable.

### Recommendation
In the second pass of `ExtractZipArchive`, `Lstat` the resolved path before applying `lchmod`/`Chtimes` and verify the on-disk file type matches the type that entry actually created (not just trust `file.Mode()` from the header), and use symlink-safe/no-follow syscalls consistently (e.g., use `AT_SYMLINK_NOFOLLOW` unconditionally in `lchmod`, and use `unix.Lutimes`/`UtimesNanoAt` with `AT_SYMLINK_NOFOLLOW` instead of `os.Chtimes` for metadata restoration). Additionally, validate/normalize `file.Name` and symlink targets in `extractZipSymlinkEntry`/`extractZipFile` to ensure they resolve within the extraction root before any filesystem operation, and reject duplicate entry names that change file type across passes.

### Proof of Concept
Go integration test in `helpers/archives`:
```go
func TestExtractZipArchive_SymlinkSwapCausesMetadataTOCTOU(t *testing.T) {
    dir := t.TempDir()
    outside := filepath.Join(t.TempDir(), "victim")
    require.NoError(t, os.WriteFile(outside, []byte("secret"), 0o600))

    buf := &bytes.Buffer{}
    zw := zip.NewWriter(buf)

    // Entry A: regular file "X", mode 0644, with timestamp extra field
    hdrA := &zip.FileHeader{Name: "X", Method: zip.Deflate}
    hdrA.SetMode(0o644)
    wA, _ := zw.CreateHeader(hdrA)
    wA.Write([]byte("payload"))

    // Entry B: symlink "X" -> outside (created after A)
    hdrB := &zip.FileHeader{Name: "X", Method: zip.Store}
    hdrB.SetMode(os.ModeSymlink | 0o777)
    wB, _ := zw.CreateHeader(hdrB)
    wB.Write([]byte(outside))

    zw.Close()

    r, _ := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))

    origInfo, _ := os.Lstat(outside)

    wd, _ := os.Getwd()
    os.Chdir(dir)
    defer os.Chdir(wd)

    err := ExtractZipArchive(r)
    require.NoError(t, err)

    newInfo, err := os.Lstat(outside)
    require.NoError(t, err)

    // Assert: victim file's mode/mtime were NOT altered by extraction of entry "X"
    assert.Equal(t, origInfo.Mode().Perm(), newInfo.Mode().Perm(),
        "victim file permissions were changed via symlink-followed lchmod")
    assert.Equal(t, origInfo.ModTime(), newInfo.ModTime(),
        "victim file mtime was changed via symlink-followed Chtimes")
}
```
Expected current (buggy) behavior: on Linux, `outside`'s permission bits become `0644` (from entry A's `lchmod` following the symlink) and/or its mtime is altered by `os.Chtimes`, failing the assertions — demonstrating the metadata pass reaching outside the intended extraction target via the swapped symlink.

```go
func extractZipSymlinkEntry(file *zip.File) (err error) {
	var data []byte
	in, err := file.Open()
	if err != nil {
		return err
	}

	if err != nil {
		return err
	}

	// Remove symlink before creating a new one, otherwise we can error that file does exist
	_ = os.Remove(file.Name)
	err = os.Symlink(string(data), file.Name)
	return
}
```

```go
func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
```

```go
func processZipTimestampField(data []byte, file *zip.FileHeader) error {
	if !file.Mode().IsDir() && !file.Mode().IsRegular() {
		return nil
	}

	var tsField ZipTimestampField
	err := binary.Read(bytes.NewReader(data), binary.LittleEndian, &tsField)
	if err != nil {
		return err
	}

	if (tsField.Flags & 1) == 1 {
		modTime := time.Unix(int64(tsField.ModTime), 0)
		acTime := time.Now()
		return os.Chtimes(file.Name, acTime, modTime)
	}

	return nil
}
```

```go
func lchmod(name string, mode os.FileMode) error {
	var flags int

	if runtime.GOOS == "linux" {
		// Linux does not support changing modes on symlinks.
		if mode&os.ModeSymlink != 0 {
			return nil
		}
	} else {
		flags = unix.AT_SYMLINK_NOFOLLOW
	}

	err := unix.Fchmodat(unix.AT_FDCWD, name, uint32(mode.Perm()), flags)
	if err != nil {
		return &os.PathError{Op: "lchmod", Path: name, Err: err}
	}
	return nil
```
