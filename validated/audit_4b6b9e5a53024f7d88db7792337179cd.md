### Title
Incorrect Calculation of the 70% Global-Agreement Threshold Due to Floor vs Ceiling Rounding Mismatch — (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` and `reached_disagreement` compute the 70%/30% weight thresholds used to decide the signer set's *global state* (current miner, burn-block view, protocol version, tx-replay set) with truncating (floor) integer division. The canonical threshold used everywhere else in the codebase to enforce the "70% of signer weight" rule — `NakamotoBlockHeader::compute_voting_weight_threshold` — instead rounds *up* (ceiling). Whenever `total_weight` is not an exact multiple of 10, these two "70%" thresholds diverge, and the signer state machine will declare "agreement" with strictly less than 70% of the actual signer weight. [1](#0-0) [2](#0-1) 

### Finding Description
The consensus-critical threshold in the codebase is `NakamotoBlockHeader::compute_voting_weight_threshold`, which computes `ceil(total_weight * 7 / 10)`:

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD; // 7
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
``` [2](#0-1) 

This is the threshold enforced on-chain for a valid block signature (`verify_signer_signatures`), and it is also what the v0 signer uses for block pre-commit/signing/rejection tallies (`compute_voting_weight_threshold`, called from `handle_block_pre_commit`, `store_and_process_block_signature`, `store_and_process_block_rejection`). [3](#0-2) 

However, `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` — which decide whether the *signer set's global state machine* (current miner, burn-block view, active protocol version, tx-replay set) has reached consensus — use plain truncating division instead:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}

pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
``` [1](#0-0) 

For any `total_weight` where `total_weight * 7` is not a multiple of 10, `reached_agreement`'s floor-divided threshold is strictly *lower* than the ceiling-divided threshold that the rest of the protocol (and the block-signing rule itself) treats as "70%". Example: `total_weight = 13` → true 70% = 9.1, so the correct/consistent (ceiling) requirement is `10`, but `reached_agreement` accepts a vote_weight of `9` (69.2%) as sufficient, because `13*7/10 = 9` (floor).

This function is the sole gate for `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which fixes the agreed `current_miner`, `burn_block`/`burn_block_height`, and `tx_replay_set`): [4](#0-3) [5](#0-4) 

and it is also used directly in `stacks-signer/src/signerdb.rs` to decide when a burn-view has been "globally" acknowledged: [6](#0-5) 

The consequence is exactly the class of bug the reference CVE describes (CWE-682 Incorrect Calculation, division-rounding logic error causing execution down the wrong path): the "70%" agreement gate that governs which miner/burn-view/reward-cycle-state the signer's local state machine adopts as canonical is silently weaker than the "70%" gate that governs actual block-signature validity. This creates an equality mismatch between "70% as computed for block signing" and "70% as computed for signer global-state agreement" — for a `total_weight` value where these differ (any value not a multiple of 10), a set of signers slightly under the intended supermajority can force the group's global state (e.g., `current_miner`) to flip to a state that a true 70%-weight majority did not actually agree to.

### Impact Explanation
This falls into the High-impact bucket: signers can be caused to act on a state ("current_miner", global burn view, active protocol version, or tx-replay set) that does not actually have the intended 70% weight support, i.e., "acting on a stale reward set/threshold" contrary to the protocol's approval-threshold invariant. Because `determine_global_state` feeds directly into which miner the signer follows and what transaction-replay set it applies, an incorrectly-declared "global agreement" (below true 70%) can cause the signer set to diverge from consensus intent, undermining the guarantee that state-machine decisions require the same supermajority as block signing.

### Likelihood Explanation
The discrepancy is deterministic and requires no adversarial signer collusion beyond ordinary gossip of `StateMachineUpdate` messages that the protocol already exchanges — it triggers automatically whenever the signer set's `total_weight` (sum of per-address `weight` derived from stacked amounts) is not an exact multiple of 10, which is the common case in practice (reward-cycle weights are derived from stacking amounts and are not designed to sum to multiples of 10). Any set of signers whose combined weight lands in the gap between the floor and ceiling thresholds (up to just under one weight-unit-in-ten short of true 70%) will trigger this incorrect "agreement," with no elevated privileges required.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same rounding semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling division for the approval threshold, and the complementary rounding for the blocking-minority threshold), or better, have `reached_agreement` call into `compute_voting_weight_threshold` directly so there is a single source of truth for what "70%" means across block-signing and global-state consensus.

### Proof of Concept
1. Construct a signer set whose per-address weights sum to `total_weight = 13` (e.g., weights `2,2,2,2,2,2,1`).
2. Have signers controlling weight `9` (69.2%) broadcast identical `StateMachineUpdate` content (e.g., the same `current_miner`).
3. `GlobalStateEvaluator::determine_global_state` will call `reached_agreement(9)`, which evaluates `9 >= 13*7/10 = 9` → `true`, declaring global agreement on `current_miner` with only 69.2% of weight.
4. Meanwhile, `NakamotoBlockHeader::compute_voting_weight_threshold(13)` returns `10` (ceiling of 9.1) — the value that would actually be required to make that same 70% claim valid for a block signature.
5. The signer set now treats a sub-70%-weight view as the canonical global state, contrary to the protocol's approval invariant enforced elsewhere. [1](#0-0) [2](#0-1)

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
