### Title
Zip-Slip path traversal in legacy zip extractor allows writing files outside job working directory - ([File: helpers/archives/zip_extract.go])

### Summary
`archives.ExtractZipArchive` (invoked via `ziplegacy.extractor.Extract`, which is registered as the `Zip` format extractor and reachable from `CacheExtractorCommand.Execute` → `openArchive` → `archive.NewExtractor(archive.Zip, ...)`) uses `zip.File.Name` verbatim as a filesystem path with no validation that it stays within the working directory, allowing classic zip-slip path traversal.

### Finding Description
`extractZipFile` in `helpers/archives/zip_extract.go` creates parent directories with `os.MkdirAll(filepath.Dir(file.Name), 0o777)` and then, via `extractZipFileEntry`/`extractZipDirectoryEntry`/`extractZipSymlinkEntry`, calls `os.OpenFile(file.Name, ...)`, `os.Mkdir(file.Name, ...)`, or `os.Symlink(string(data), file.Name)` directly using the attacker-controlled `file.Name` string from the zip archive. [1](#0-0) [2](#0-1) 

The only pre-extraction check applied per entry is `errorIfGitDirectory`, which only rejects paths whose first cleaned component is `.git` — it does nothing to reject `..` segments or absolute paths. [3](#0-2) [4](#0-3) 

The `ziplegacy.extractor` struct even stores a `dir` field (intended to scope extraction to a target directory) but `Extract()` never uses it — it never joins `file.Name` with `e.dir`, never validates that the resolved path is a descendant of `e.dir`, and never even `chdir`s into it. It simply calls `archives.ExtractZipArchive(zr)`, which operates on raw `file.Name` values relative to the process's current working directory. [5](#0-4) 

Reachability: `CacheExtractorCommand.Execute` computes `wd` via `os.Getwd()`, downloads the cache/artifact archive (attacker-controlled content, e.g. pushed to cache by a prior job or replayed from an artifact), opens it via `openArchive`, and calls `archive.NewExtractor(format, f, size, wd)` → for the `Zip` format this resolves to `ziplegacy.NewExtractor` → `extractor.Extract` → `archives.ExtractZipArchive`. [6](#0-5) 

Because no component validates that `filepath.Clean(file.Name)` stays within `wd` (no rejection of leading `../`, no `filepath.Rel`/prefix check, no path-jail), a maliciously named zip entry such as `../../evil.sh` will cause `os.MkdirAll`/`os.OpenFile` to write outside the job's working directory, anywhere the runner process has filesystem permission to write.

### Impact Explanation
An unprivileged pipeline author who controls cache or artifact zip contents can write arbitrary files (including symlinks, via `extractZipSymlinkEntry`) to paths outside the job workspace, up to the filesystem permissions of the runner/executor process. In shell-executor or unisolated contexts this can overwrite runner-adjacent scripts/config or plant files elsewhere on the host filesystem — a concrete file-write-outside-job-root vulnerability matching the scoped impact.

### Likelihood Explanation
Fully attacker-reachable with only standard, unprivileged job capabilities: any pipeline author can push a crafted cache archive (`cache: paths` + custom zip entry names are not achievable through normal `cache:` config, but the same code path is exercised for any zip pulled as a cache blob — e.g. via a cache key collision, a compromised/pushed cache blob, or a replayed artifact used as cache) and have the runner extract it via `cache-extractor`. The vulnerable code (`extractZipFile`/`extractZipFileEntry`) is deterministic and always reachable whenever `Zip` format extraction occurs; no feature flags or opt-in guards protect it.

### Recommendation
Before performing any filesystem operation in `extractZipFile`/`extractZipDirectoryEntry`/`extractZipFileEntry`/`extractZipSymlinkEntry`, resolve `file.Name` against the intended extraction root (the `dir` passed to `ziplegacy.NewExtractor`, or `wd`) using `filepath.Clean`/`filepath.Join`, and reject any entry whose cleaned, joined path is not a descendant of that root (equivalent to checking `strings.HasPrefix(resolvedPath, root+string(filepath.Separator))` after `filepath.Clean`, or using `filepath.Rel` and rejecting results starting with `..`). Also validate symlink targets so they cannot point outside the root. Apply the same check consistently to all zip/tar extractors (`fastzip`, `tarzstd`, etc.) if not already present there.

### Proof of Concept
```go
package archives

import (
    "archive/zip"
    "bytes"
    "os"
    "path/filepath"
    "testing"
)

func TestExtractZipArchive_PathTraversalRejected(t *testing.T) {
    tmpRoot := t.TempDir()
    wd, _ := os.Getwd()
    _ = os.Chdir(tmpRoot)
    defer os.Chdir(wd)

    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    fw, _ := zw.Create("../../evil.sh")
    _, _ = fw.Write([]byte("#!/bin/sh\necho pwned\n"))
    _ = zw.Close()

    zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
    if err != nil {
        t.Fatal(err)
    }

    _ = ExtractZipArchive(zr)

    escapedPath := filepath.Join(tmpRoot, "..", "..", "evil.sh")
    if _, err := os.Stat(escapedPath); err == nil {
        t.Fatalf("zip-slip succeeded: file created outside extraction root at %s", escapedPath)
    }
}
```
Expected (post-fix) assertion: `ExtractZipArchive` returns a non-nil error for the `../../evil.sh` entry and `evil.sh` is never created outside `tmpRoot`. Current behavior (pre-fix): no error is returned and the file is written outside `tmpRoot`, confirming the vulnerability.

func extractZipFileEntry(file *zip.File) (err error) {
	var out *os.File
	in, err := file.Open()
	if err != nil {
		return err
	}

	out, err = os.OpenFile(file.Name, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, file.Mode().Perm())
	if err != nil {
		return err
	}
	defer func() { _ = out.Close() }()
	_, err = io.Copy(out, in)

	return
}

func extractZipFile(file *zip.File) (err error) {
	// Create all parents to extract the file
	err = os.MkdirAll(filepath.Dir(file.Name), 0o777)
	if err != nil {
		return err
	}

	switch file.Mode() & os.ModeType {
	case os.ModeDir:
		err = extractZipDirectoryEntry(file)

	case os.ModeSymlink:
		err = extractZipSymlinkEntry(file)

	case os.ModeNamedPipe, os.ModeSocket, os.ModeDevice:
		// Ignore files of these types
		logrus.Warningf("File ignored: %q", file.Name)

	default:
		err = extractZipFileEntry(file)
	}
	return
}
