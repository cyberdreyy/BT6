### Title
Instant-withdraw delay can exceed the epoch duration and block epoch settlement - ([File: contracts/IdleCDOEpochVariant.sol](contracts/IdleCDOEpochVariant.sol))

### Summary
`setInstantWithdrawParams` accepts an arbitrary `instantWithdrawDelay`, while `setEpochParams` accepts an arbitrary nonzero `epochDuration`. If the delay is greater than the epoch duration, an epoch containing unfunded instant-withdrawal requests cannot be stopped at `epochEndDate`. `stopEpoch` reverts while `pendingInstantWithdraws != 0`, but `getInstantWithdrawFunds` remains unavailable until `instantWithdrawDeadline`.

### Finding Description
`instantWithdrawDelay` is set without an upper bound in `setInstantWithdrawParams`.

```solidity
instantWithdrawDelay = _delay;
```

When an epoch starts, the contract independently sets:

```solidity
epochEndDate = block.timestamp + epochDuration;
instantWithdrawDeadline = block.timestamp + instantWithdrawDelay;
```

Instant requests are created during the buffer period when the APR has decreased enough to satisfy `lastEpochApr > currentApr + instantWithdrawAprDelta`. At `startEpoch`, available CDO cash is transferred to the strategy to cover them. If the request amount exceeds available cash, `pendingInstantWithdraws` remains nonzero.

After `epochEndDate`, settlement is blocked by `_pendingInstant() != 0` in `_stopEpoch`. However, `getInstantWithdrawFunds` also reverts until `block.timestamp >= instantWithdrawDeadline`. For `instantWithdrawDelay > epochDuration`, this creates a deadlock window:

```text
epochEndDate reached
    -> stopEpoch cannot run because pendingInstantWithdraws != 0
    -> getInstantWithdrawFunds cannot run because deadline has not passed
```

The broken invariant is timely epoch settlement and access to funded withdrawals.

### Impact Explanation
A lender can trigger this condition with an instant-withdrawal request that is larger than the cash available at epoch start. All epoch settlement is then delayed until `instantWithdrawDeadline`, temporarily freezing borrower repayment processing, normal withdrawal funding, fee settlement, and reopening of deposit/request functionality.

The delay is bounded by the configured `instantWithdrawDelay`. With an arbitrarily large configured delay, the freeze can be arbitrarily long. The condition requires the honest owner or manager to configure `instantWithdrawDelay > epochDuration`, but it is then triggerable by an unprivileged KYC-passing lender.

### Likelihood Explanation
Likelihood depends on inconsistent privileged configuration. No external oracle failure or privileged malicious action is required after configuration. A normal lender only needs:

1. Instant withdrawals enabled.
2. APR reduced by more than `instantWithdrawAprDelta`.
3. An instant request larger than cash available to the CDO at `startEpoch`.

Existing checks do not prevent the inconsistent timing relationship.

### Recommendation
Enforce the timing invariant wherever either parameter is changed:

```solidity
require(instantWithdrawDelay <= epochDuration, "invalid instant delay");
```

`setEpochParams` should similarly reject an `epochDuration` lower than the currently configured `instantWithdrawDelay`. Alternatively, cap the effective deadline at `epochEndDate`:

```solidity
instantWithdrawDeadline = block.timestamp +
    (instantWithdrawDelay < epochDuration ? instantWithdrawDelay : epochDuration);
```

The explicit validation is preferable because it makes invalid configuration impossible rather than silently changing the configured deadline.

### Proof of Concept
```solidity
function testInstantDelayLongerThanEpochBlocksStop() public {
    uint256 depositAmount = 1_000e6;

    // Honest configuration creates inconsistent deadlines.
    vm.startPrank(owner);
    cdo.setEpochParams(30 days, bufferPeriod);
    cdo.setInstantWithdrawParams(31 days, aprDelta, false);
    vm.stopPrank();

    // Complete a prior epoch so `lastEpochApr` is populated.
    depositAA(lender, depositAmount);
    startEpochAsManager();
    repayAndStopEpochAsManager();

    // Honest manager lowers APR enough to activate instant withdrawals.
    setNextEpochApr(lastEpochApr - aprDelta - 1);

    // During buffer period, a KYC-passing lender requests withdrawal.
    vm.prank(lender);
    uint256 requested = cdo.requestWithdraw(0, AAtranche);
    assertGt(requested, 0);
    assertEq(creditVault.pendingInstantWithdraws(), requested);

    // Ensure CDO cash available at start is less than the instant request,
    // leaving pendingInstantWithdraws nonzero.
    startEpochAsManager();
    assertGt(creditVault.pendingInstantWithdraws(), 0);

    // Epoch duration has elapsed, but instant deadline has not.
    vm.warp(cdo.epochEndDate());

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdo.getInstantWithdrawFunds();

    vm.prank(manager);
    vm.expectRevert(NotAllowed.selector);
    cdo.stopEpoch(newApr, 0);

    // Settlement remains frozen until instantWithdrawDeadline.
    vm.warp(cdo.instantWithdrawDeadline());
    vm.prank(manager);
    cdo.getInstantWithdrawFunds();
}
```
