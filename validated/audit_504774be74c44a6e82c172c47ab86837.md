### Title
Unrestricted ETH acceptance permanently locks funds in `ConvexStrategyETH` - (File: `contracts/strategies/convex/ConvexStrategyETH.sol`)

### Summary
`ConvexStrategyETH` exposes an unrestricted `receive()` function, so any EOA or contract can send ETH to either the implementation contract or a proxy strategy instance. The ETH is not included in strategy accounting and cannot be recovered because the only emergency recovery function transfers ERC-20 tokens rather than native ETH. [1](#0-0) [2](#0-1) 

### Finding Description
`_depositInCurve()` unwraps only the contract’s WETH balance and deposits exactly that amount into Curve. A direct ETH transfer does not increase the WETH balance, so the donated ETH is never deposited, tracked, or credited to any depositor. [3](#0-2) 

The contract needs to receive ETH for `IWETH9.withdraw()`, but `receive()` does not restrict the sender to the WETH contract or another expected ETH source. [4](#0-3) 

For the deployed implementation, the constructor permanently marks the strategy as initialized by setting `curveLpToken` to `address(1)`. Consequently, the implementation cannot be initialized and has no owner capable of invoking privileged recovery paths. [5](#0-4) [6](#0-5) 

For an initialized proxy instance, `transferToken()` is limited to `IERC20Detailed.safeTransfer()` and cannot move native ETH. Strategy deposits, redemptions, reward redemption, and Curve deposits likewise contain no native-ETH withdrawal path for unrelated ETH already held by the contract. [2](#0-1) 

### Impact Explanation
Any ETH transferred directly to the implementation or an active strategy proxy is permanently frozen. The sender loses the full amount transferred, and neither the CDO nor the strategy owner can recover it through an exposed function.

The issue is independent of the credit-vault epoch phase and remains exploitable while a pool is in the buffer phase, while an epoch is running, or after it has stopped. The broken invariant is donation isolation: assets outside the supported accounting flow can enter the contract but can never be accounted for or withdrawn.

### Likelihood Explanation
Likelihood is low because an unprivileged sender has no financial incentive to donate ETH and the issue primarily requires an accidental transfer or mistaken user interaction. However, execution is trivial: a plain ETH transfer with empty calldata succeeds because the fallback path is unrestricted. [7](#0-6) 

### Recommendation
Restrict `receive()` to expected ETH senders, such as `WETH` and, if necessary, the configured Curve pool:

```solidity
receive() external payable {
    require(msg.sender == WETH, "only-weth");
}
```

If Curve can return ETH from the pool address, allow both `WETH` and `_curvePool(curveLpToken)`. If the implementation itself must reject ETH even where the proxy must accept it, record `IMPLEMENTATION = address(this)` as an immutable in the constructor and require `address(this) != IMPLEMENTATION` in `receive()`.

Alternatively, add an explicit owner-only native-ETH rescue function for initialized strategy instances. Restricting `receive()` is preferable because it prevents accidental loss rather than relying on intervention after funds are trapped.

### Proof of Concept
The following Foundry test deploys the uninitialized implementation, demonstrates that a plain ETH transfer succeeds, and confirms that initialization cannot later establish an owner capable of using privileged recovery functions:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.10;

import "forge-std/Test.sol";
import "../../contracts/strategies/convex/ConvexStrategyETH.sol";

contract ConvexStrategyETHReceiveTest is Test {
    function test_ETHSentToImplementationIsLocked() public {
        vm.createSelectFork(vm.envString("ETH_RPC_URL"));

        ConvexStrategyETH implementation = new ConvexStrategyETH();
        assertEq(implementation.curveLpToken(), address(1));

        address sender = makeAddr("sender");
        uint256 amount = 1 ether;
        vm.deal(sender, amount);

        vm.prank(sender);
        (bool success,) = address(implementation).call{value: amount}("");
        assertTrue(success);
        assertEq(address(implementation).balance, amount);
        assertEq(sender.balance, 0);

        ConvexBaseStrategy.CurveArgs memory curveArgs =
            ConvexBaseStrategy.CurveArgs({
                deposit: address(0),
                depositor: address(0),
                depositPosition: 0
            });
        ConvexBaseStrategy.Reward[] memory rewards =
            new ConvexBaseStrategy.Reward[](0);
        ConvexBaseStrategy.Weth2Deposit memory weth2Deposit =
            ConvexBaseStrategy.Weth2Deposit({
                router: address(0),
                path: new address[](0)
            });

        vm.expectRevert("Initialized");
        implementation.initialize(
            0,
            address(this),
            0,
            curveArgs,
            rewards,
            weth2Deposit
        );

        // The 1 ETH remains locked: there is no native-ETH withdrawal path,
        // and transferToken() only supports ERC20Detailed.safeTransfer().
        assertEq(address(implementation).balance, amount);
    }
}
```
