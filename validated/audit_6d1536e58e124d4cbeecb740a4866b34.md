## Finding

Valid — but the concrete bug is a missing fee-sum validation in `createDstEscrow`, not a silent underflow (Solidity 0.8.23 uses checked arithmetic, so line 92 reverts rather than wrapping).

### Title
Missing fee-sum validation in `createDstEscrow` allows a griefing/fund-freeze via permanent revert in `EscrowDst._withdraw` - (File: `contracts/BaseEscrowFactory.sol`, `contracts/EscrowDst.sol`)

### Summary
`EscrowDst._withdraw` computes `immutables.amount - integratorFeeAmount - protocolFeeAmount` without checking that the sum of fees is `<= amount`. [1](#0-0) 
On the source-chain path, `_postInteraction` explicitly enforces `integratorFeeAmount + protocolFeeAmount >= takingAmount` must revert, preventing fee amounts from exceeding the transferred amount. [2](#0-1) 
However, `createDstEscrow` accepts a caller-supplied `Immutables` struct (including the `parameters` bytes that encode `protocolFeeAmount`/`integratorFeeAmount`) with **no equivalent check** against `dstImmutables.amount`. [3](#0-2) 

### Finding Description
Any unprivileged taker calling `createDstEscrow` fully controls the `Immutables.parameters` bytes that later get decoded by `ImmutablesLib.integratorFeeAmountCd`/`protocolFeeAmountCd` in `EscrowDst._withdraw`. [4](#0-3) 
Because `_withdraw` is guarded only by `onlyValidImmutables(immutables.hash())` (matching against the value hashed at deployment) and `onlyValidSecret`, there is no cross-check tying the dst-side fee parameters back to the fee parameters the Limit Order Protocol computed and emitted on the source chain (`DstImmutablesComplement.parameters` in `_postInteraction`). [5](#0-4) 
A taker can therefore deploy a destination escrow, fund it with the maker's expected amount, but embed `integratorFeeAmount + protocolFeeAmount > amount`. Under Solidity 0.8.23's checked arithmetic, the subtraction at line 92 reverts (rather than underflowing silently), so `withdraw`/`publicWithdraw` can never succeed for that escrow. [6](#0-5) 
Because `cancel()` performs a plain, fee-agnostic transfer of `immutables.amount` back to `taker` (not maker) once `DstCancellation` elapses, the taker (who funded the escrow) can always recover their own deposited tokens after the timelock, while the maker — who is expecting to receive the dst-chain proceeds — never gets paid from this escrow. [7](#0-6) 
Meanwhile, the same taker can still redeem the maker's source-chain funds via `EscrowSrc` using the secret revealed for this swap (secret reuse across src/dst is by design), so the taker profits from the source-side leg while the maker is denied the destination-side leg.

### Impact Explanation
This does not corrupt an arithmetic invariant into a silently-wrong payout (the claim of "underflow" is inaccurate for 0.8.x checked math), but it does allow an unprivileged taker to permanently deny the maker's expected proceeds on a specific destination escrow for the full `DstWithdrawal`→`DstCancellation` window, and functionally forever if the taker never lets it cancel favorably to the maker (funds simply route back to taker, not maker). This fits the "temporary freezing of funds during the live swap lifecycle" High-severity bucket, and the missing parity check with `_postInteraction`'s `InvalidFeeAmounts` guard is a genuine business-logic gap.

### Likelihood Explanation
Medium-High: `createDstEscrow` is a fully public, unprivileged entrypoint; any taker filling an order and then deploying the corresponding dst escrow directly controls the `parameters` bytes and can trivially set fee amounts exceeding `amount` in a single crafted call.

### Recommendation
Add the same guard used in `_postInteraction` to `createDstEscrow`: decode `dstImmutables.parameters` and revert (e.g. with `InvalidFeeAmounts`) if `integratorFeeAmount + protocolFeeAmount >= dstImmutables.amount`, mirroring the check at [8](#0-7) 
so the destination path enforces the same invariant as the source path before funds are locked.

### Proof of Concept
1. Taker fills a maker's order normally on the source chain (or independently); maker's funds get locked in `EscrowSrc`.
2. Taker calls `createDstEscrow` with a crafted `Immutables.parameters = abi.encode(protocolFeeAmount, integratorFeeAmount, protocolFeeRecipient, integratorFeeRecipient)` such that `protocolFeeAmount + integratorFeeAmount > amount`, funding the escrow with `amount` tokens/native value as required by lines 166-182. [9](#0-8) 
3. Once the secret is revealed (e.g., by maker to enable the src withdrawal), any call to `EscrowDst.withdraw`/`publicWithdraw` reverts at line 92's subtraction, forever preventing the maker from receiving the dst-side payout from that escrow. [10](#0-9) 
4. After `DstCancellation`, the taker calls `cancel()` and reclaims the full `amount` (their own deposited funds) plus retrieves the safety deposit — the maker gets nothing from the destination leg while the taker may have already withdrawn the maker's source-chain funds using the revealed secret. [7](#0-6)

            _uniTransfer(immutables.token.get(), immutables.integratorFeeRecipientCd().get(), integratorFeeAmount);

        _uniTransfer(immutables.token.get(), immutables.maker.get(), amount);

    }

    function createDstEscrow(IBaseEscrow.Immutables calldata dstImmutables, uint256 srcCancellationTimestamp) external payable {
        address token = dstImmutables.token.get();
        uint256 nativeAmount = dstImmutables.safetyDeposit;
        if (token == address(0)) {
            nativeAmount += dstImmutables.amount;
        }
        if (msg.value != nativeAmount) revert InsufficientEscrowBalance();

        IBaseEscrow.Immutables memory immutables = dstImmutables;
        immutables.timelocks = immutables.timelocks.setDeployedAt(block.timestamp);
        // Check that the escrow cancellation will start not later than the cancellation time on the source chain.
        if (immutables.timelocks.get(TimelocksLib.Stage.DstCancellation) > srcCancellationTimestamp) revert InvalidCreationTime();

        bytes32 salt = immutables.hashMem();
        address escrow = _deployEscrow(salt, msg.value, ESCROW_DST_IMPLEMENTATION);
        if (token != address(0)) {
            IERC20(token).safeTransferFrom(msg.sender, escrow, immutables.amount);
        }

        emit DstEscrowCreated(escrow, immutables.hashlock, immutables.taker);
    }

    function protocolFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x20) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(parameters.offset)
        }
    }

    /**
     * @notice Returns the integrator fee amount from the immutables (calldata version).
     * @param immutables The immutables to extract the fee from.
     * @return ret The integrator fee amount.
     */
    function integratorFeeAmountCd(IBaseEscrow.Immutables calldata immutables) external pure returns (uint256 ret) {
        bytes calldata parameters = immutables.parameters;
        if (parameters.length < 0x40) revert IndexOutOfRange();
        assembly ("memory-safe") {
            ret := calldataload(add(parameters.offset, 0x20))
        }
    }
