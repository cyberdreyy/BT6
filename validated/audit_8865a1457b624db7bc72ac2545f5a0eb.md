### Title
Dust APR0 withdraw request bricks `stopEpoch` once APR is raised, freezing vault funds or forcing a zero-yield epoch - (File: contracts/strategies/idle/IdleCreditVault.sol)

### Summary
A low-privileged, KYC'd lender can poison the epoch state machine by submitting a dust `requestWithdraw` while the vault is in APR0 mode (`unscaledApr == 0`). This sets `apr0TotalPrincipal != 0` via `_requestWithdrawApr0`. If the honest manager later sets a non-zero APR (e.g., when pricing the next epoch), every subsequent `stopEpoch` call reverts in `prepareStopEpochWithApr0` with `NotAllowed()`. The vault is frozen until the manager is forced to roll the APR back to 0 — meaning the attacker either holds the entire TVL hostage or forces a full epoch with zero interest for all lenders.

### Finding Description
`requestWithdraw` routes requests to `_requestWithdrawApr0` whenever `unscaledApr == 0` and the pool is not closed:

```solidity
if (unscaledApr == 0 && !isClosed) {
  _requestWithdrawApr0(_amount, _user);
}
```

`_requestWithdrawApr0` increments the global bucket:

```solidity
_apr0User.principal += _amount;
apr0TotalPrincipal += _amount;
```

`prepareStopEpochWithApr0` — invoked by `IdleCDOEpochVariant` during `stopEpoch` — hard-reverts whenever the bucket is non-empty and APR is non-zero:

```solidity
if (_principal == 0) {
  return (_expInterest, _adjPendingWithdrawFees);
}
// APR0 principal is only valid while APR is 0 for that request lifecycle.
if (unscaledApr != 0) {
  revert NotAllowed();
}
```

Crucially, `apr0TotalPrincipal` is only cleared at the end of `prepareStopEpochWithApr0` (line 540), which is unreachable once the revert path is taken — the poisoned state is self-perpetuating across every `stopEpoch` attempt while APR stays positive. There is no path that skips or overrides this check: `stopEpochWithDuration` and loss-adjusted stops equally depend on epoch settlement, and `requestWithdraw` has no minimum amount, so 1 wei of tranche tokens suffices. No existing guard (KYC, `onlyIdleCDO`, epoch gating) stops it — the attacker uses a fully legitimate code path.

### Impact Explanation
- While poisoned, `stopEpoch` always reverts: the epoch can never end, `pendingWithdraws` can never be collected via `collectWithdrawFunds`, instant claims stall, and all deposited underlying plus accrued interest are locked (temporary freezing of the full TVL).
- The only recovery is for the manager to set APR back to 0 and stop the epoch — crystallizing a zero-interest epoch and denying yield to every other lender, with the attacker able to re-poison each subsequent APR0 window at dust cost.
- Loss: unbounded-duration freeze of 100% of vault TVL, or forced forfeiture of one full epoch of protocol-wide interest (up to `expectedEpochInterest` + `pendingWithdrawFees`).

### Likelihood Explanation
- Requires only a KYC-passing lender (an in-scope unprivileged role) and one ordinary `requestWithdraw` of dust during an APR0 phase — APR transitions from 0 to positive during a borrower's repayment cycle are a normal operational event, not an edge case.
- The revert is deterministic: no race conditions, no privileged misconfiguration, no external oracle dependence.
- Cost to attacker: gas plus 1 wei; no capital is at risk since the receipt remains claimable.

### Recommendation
- In `prepareStopEpochWithApr0`, handle `unscaledApr != 0` gracefully instead of reverting: settle the outstanding APR0 bucket at the stored `apr0RateByEpoch` rate (or at zero interest if the rate is unavailable) and zero `apr0TotalPrincipal`, so a stale APR0 bucket can never block epoch settlement.
- Alternatively, clear `apr0TotalPrincipal` and settle per-user APR0 buckets at `setApr`/`setAprs` time when the APR moves off zero.
- As defense-in-depth, enforce a minimum `requestWithdraw` amount or require APR0 requests to be settled before a non-zero APR can be committed.

### Proof of Concept
Foundry fork test (against the existing `IdleCreditVault.t.sol` harness):

```solidity
function testApr0DustBlocksStopEpoch() external {
    _setFeeParams(TL_MULTISIG, 0, FULL_ALLOC, cdoEpoch.managementFee());
    vm.prank(owner);
    cdoEpoch.setIsAYSActive(false);
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0); // APR0 mode

    uint256 amount = 10000 * ONE_SCALE;
    idleCDO.depositAA(amount);                       // honest LP TVL

    // attacker: KYC'd lender deposits dust and requests withdraw while apr == 0
    address attacker = makeAddr('apr0-griefer');
    _depositWithUser(attacker, ONE_SCALE, true);
    vm.prank(attacker);
    cdoEpoch.requestWithdraw(0, address(AAtranche)); // requests full dust position

    assertGt(strategy.apr0TotalPrincipal(), 0, 'apr0 bucket poisoned');

    // honest ops: manager prices next epoch with positive APR
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(initialProvidedApr, initialProvidedApr);

    _startEpochAndCheckPrices(0);
    vm.warp(cdoEpoch.epochEndDate() + 1);
    deal(defaultUnderlying, borrower, _expectedFundsEndEpoch(), true);
    vm.prank(borrower);
    underlying.approve(address(cdoEpoch), _expectedFundsEndEpoch());

    // every stopEpoch attempt reverts -> epoch cannot end, TVL frozen
    vm.expectRevert(abi.encodeWithSelector(NotAllowed.selector));
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0);

    // forced recovery: manager must roll APR to 0 -> zero-interest epoch for all LPs
    vm.prank(manager);
    IdleCreditVault(address(strategy)).setAprs(0, 0);
    vm.prank(manager);
    cdoEpoch.stopEpoch(0, 0); // succeeds, but epoch earned nothing
}
```

Note: this assessment is based on the `IdleCreditVault.sol` code paths traced above; I was unable to fully inspect `IdleCDOEpochVariant.stopEpoch`'s exact call sequence into `prepareStopEpochWithApr0`, so the PoC assumes it is invoked on every stop, consistent with its `_onlyIdleCDO` gating and the test suite's APR0 flows (`testApr0WithdrawGetsInterestAtStopEpoch`). If `stopEpoch` can bypass `prepareStopEpochWithApr0` in some modes, the freeze reduces to those modes where it is called.
