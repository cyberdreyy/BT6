Based on my research, I found a credible local analog to the reported bug class. The Layer Zero bug involved an unexpected recipient rejecting a native-token transfer and reverting an otherwise valid batch operation. Aptos's `vesting` and `staking_contract` modules have a structurally identical pattern: a single unprivileged, self-inflicted "cannot receive" condition on one recipient can revert a shared batch-distribution transaction, permanently blocking payout to every other co-shareholder/staker in that same pool.

### Title
Griefing via `set_allow_direct_coin_transfers(false)` permanently blocks batch stake/vesting distribution to all co-shareholders - (File: aptos-move/framework/aptos-framework/sources/vesting.move)

### Summary
`vesting::distribute` and `staking_contract::distribute_internal` both withdraw a single lump of unlocked/inactive coins and then loop over **all** shareholders/distribution-pool recipients in one transaction, paying each one via `aptos_account::deposit_coins`. [1](#0-0) [2](#0-1)  `aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is not yet registered for the coin type and has opted out via `can_receive_direct_coin_transfers`. [3](#0-2)  Any account can opt out at any time by calling the public entry function `set_allow_direct_coin_transfers(account, false)`. [4](#0-3)  Because the payout loop processes every shareholder/recipient inside a single atomic transaction, one such unregistered, opted-out recipient causes the whole `distribute()` call to abort — exactly like the Layer Zero bug where one un-payable recipient reverted a shared batch operation.

### Finding Description
`vesting::distribute(contract_address)` is a permissionless entry function that withdraws all currently withdrawable stake and iterates every shareholder of the vesting contract's `grant_pool`, calling `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each one in the same transaction: [5](#0-4) 

`staking_contract::distribute_internal` follows the identical pattern for its `distribution_pool`, which can hold up to `MAXIMUM_PENDING_DISTRIBUTIONS` recipients (staker plus any past/present operators from prior `switch_operator` calls): [6](#0-5) 

The shared payout helper `aptos_account::deposit_coins` will abort instead of silently succeeding when the target account (a) has never registered a `CoinStore`/primary store for the coin type, and (b) has explicitly disabled arbitrary direct coin transfers: [3](#0-2) 

Any account — including a shareholder added to a vesting contract by the admin, or a delegator/staker who has never received a coin transfer before — can call the permissionless entry function `set_allow_direct_coin_transfers(account, false)` to set this flag, and can do so via a sponsored (fee-payer) transaction without ever holding APT itself: [4](#0-3) 

Because the payout loops in `vesting::distribute` and `staking_contract::distribute_internal` are all-or-nothing (a single `Coin<AptosCoin>` object is progressively drained across all recipients in one function), a single such "unregistered + opted-out" recipient anywhere in the shareholder/distribution list causes the entire transaction to abort, and there is no per-recipient skip/retry mechanism. Every subsequent call to `distribute()` will keep reverting the same way until that recipient's coin store becomes registered.

### Impact Explanation
This blocks the unlock/reactivate/withdraw claim rights of every *other, honest* shareholder or staker sharing the same vesting contract or staking contract with the griefing recipient — not just the griefer's own funds. Since:
- `vesting::distribute` pays out **all** shareholders of a vesting contract in one call,
- `staking_contract::distribute_internal` pays out **all** pending distributions (staker, current operator, and any past operators still owed commission after `switch_operator`) in one call,

a single malicious co-shareholder or ex-operator can permanently strand the withdrawable stake/rewards of everyone else tied to that pool. This matches "Permanent lock or non-recoverable loss of claim rights" and "share-accounting corruption that... traps value" from the required impact set, since inactive/unlocked coins sit trapped in the stake pool with no way for honest parties to extract just their own share.

### Likelihood Explanation
The precondition (target account not yet registered for `AptosCoin` and opted out of direct transfers) is realistic for freshly-created shareholder/beneficiary/operator addresses that admins add to `create_vesting_contract` or `create_staking_contract` before those addresses have ever transacted, and Aptos's fee-payer/sponsored-transaction support lets an attacker call `set_allow_direct_coin_transfers(false)` without needing to hold or receive any APT first. No special privilege is required — any of the addresses listed as shareholders/operators can perform this unprivileged action. The main mitigating factor is that most actively-used addresses already have a registered `CoinStore`/primary store (needed to pay their own gas), which narrows the attack to newly-provisioned or intentionally-fresh addresses.

### Recommendation
Make the batch distribution loops resilient to individual recipient failures, e.g., wrap each `aptos_account::deposit_coins` call so a failure for one recipient does not abort the whole transaction (skip and retain that recipient's share for a later, isolated claim), or require/verify up-front that all listed shareholders/operators are already registered before adding them to the pool, or add a per-recipient "pull" style withdrawal instead of a push loop that redeems all shares atomically.

### Proof of Concept
1. Admin creates a vesting contract with shareholders `[S1, S2]` via `vesting::create_vesting_contract`, where `S2` is a freshly generated address that has never transacted and has no `CoinStore<AptosCoin>`. [7](#0-6) 
2. `S2` (or anyone with `S2`'s key) submits a fee-payer/sponsored transaction calling `aptos_account::set_allow_direct_coin_transfers(S2, false)`, requiring no APT balance of its own. [4](#0-3) 
3. After the vesting/staking lockup period elapses and rewards/vested coins become withdrawable, anyone calls `vesting::distribute(contract_address)` (or `staking_contract::distribute`).
4. The loop reaches `S2`, calls `aptos_account::deposit_coins(S2, coins)`; since `S2` is unregistered and has opted out, `can_receive_direct_coin_transfers` returns false and the call aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. [8](#0-7) 
5. The entire `distribute()` transaction reverts, so `S1` (and any other legitimate shareholder) can never claim their already-unlocked stake/rewards as long as `S2` keeps its `DirectTransferConfig` disabled and unregistered.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
