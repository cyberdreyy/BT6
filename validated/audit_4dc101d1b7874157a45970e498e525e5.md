### Title
Name squatting a planned multisig sub-account lets an attacker deploy a factory multisig with attacker-chosen members - (File: `multisig-factory/src/lib.rs`)

### Summary
`MultisigFactory::create` lets **any unprivileged caller** choose an arbitrary `name`, `members` list and `num_confirmations`, and deploys `<name>.<factory>` with exactly those attacker-supplied members, with no binding between `name` and the caller's identity and no registry of reserved names. Whoever calls `create("alice", ...)` first permanently owns `alice.<factory>`, so if a future user or protocol trusts that sub-account name as "Alice's multisig" without verifying its members, an attacker who front-ran the name squat fully controls the contract.

### Finding Description
The invariant the question tests is: `members_stored_at("<name>.<factory>") == members_the_rightful_owner_of_<name>_intended`. This does not hold, because the contract never checks who is entitled to `name`: [1](#0-0) 

`create` takes `name: AccountId`, `members: Vec<MultisigMember>`, `num_confirmations: u64` directly from the caller, builds `account_id = format!("{}.{}", name, env::current_account_id())`, and issues a single atomic promise batch: `create_account()` → `deploy_contract(CODE)` → `transfer(deposit)` → `function_call("new", {members, num_confirmations})`. There is:
- no `assert_owner`/`assert_self`/predecessor-derived name (unlike `lockup-factory`, which derives the sub-account name from `sha256(owner_account_id)` so the deployed lockup's `owner_account_id` is bound to the caller-supplied owner regardless of who submits the tx — see `lockup-factory/src/lib.rs` `create`, lines 108-166),
- no uniqueness registry of `name` (unlike `staking-pool-factory`, which at least maintains `staking_pool_account_ids: UnorderedSet<AccountId>` and validates `is_valid_account_id`, though it too separates `staking_pool_id` from `owner_id` and shares the same underlying squatting weakness),
- no `.then()` callback at all, so there is no `on_create` handler, no `is_promise_success()` check, and no deposit-refund-on-failure path present in the sibling factories (`staking-pool-factory/src/lib.rs` `on_staking_pool_create`, lines 200-239; `lockup-factory/src/lib.rs` `on_lockup_create`, lines 171-198).

Because NEAR only permits an account's direct parent to create a sub-account (here, the factory contract itself, since it is the predecessor of the dispatched `create_account` action), the *only* path to create `<name>.<factory>` is through this `create` entrypoint. Whoever's `create("alice", ...)` transaction lands first wins the name permanently — `create_account` on an already-existing account fails the entire action batch atomically. There is no guard (`assert_owner`, `assert_self`, `is_promise_success`, `assert_one_yocto`, or any name-ownership check) anywhere in this function that prevents an unrelated caller from claiming any `name`.

Exploit flow: attacker calls `create("alice", [MultisigMember::AccessKey{attacker_pubkey}], 1)` with the required deposit before the real Alice submits her own `create("alice", ...)`. `alice.<factory>` is deployed with only the attacker's key as a member and `num_confirmations = 1`, fully controlled by the attacker. Alice's later legitimate `create("alice", ...)` call fails outright (the whole batch panics because the account already exists), with no recovery. Any third party (or Alice herself, mistakenly) that treats `alice.<factory>` as Alice's trusted multisig and sends funds or grants it privileges hands control to the attacker.

### Impact Explanation
Funds or privileges directed at `<name>.<factory>` end up under attacker-chosen keys/accounts rather than the members the rightful `name` owner intended — this matches the Critical category "an account ... deployed with parameters its rightful creator never chose." The blast radius is any sub-account name an attacker anticipates a legitimate party will want (e.g., a well-known project or DAO name), and it's repeatable across arbitrarily many names/attempts, each costing only the storage deposit for one multisig deployment.

### Likelihood Explanation
Low cost, no special privileges required: any account can call `create` with an attached deposit sized to cover the multisig contract's storage, choosing any `name` and any `members`/`num_confirmations`. The only precondition is being first to submit for a given `name`, which is trivially achievable by monitoring mempool/public announcements of an intended multisig name or simply squatting popular/predictable names speculatively. This is fully repeatable across accounts and requires no redeploy, no foundation/owner privilege, and no victim key.

### Recommendation
Bind the deployed sub-account's authority to a value the attacker cannot forge, analogous to `lockup-factory`'s approach: e.g., derive `account_id` deterministically from a hash of the intended owner/members (so squatting with different members produces a different address), or require the caller to prove control of `name` (e.g., only allow `create` when `env::predecessor_account_id()` matches or is a prefix-authorized account for `name`), and add a `.then()` callback (`assert_self` + `is_promise_success`) to detect failed/duplicate creation and refund the depositor, matching the pattern already used in `staking-pool-factory` and `lockup-factory`.

        let mut factory = MultisigFactory::default();
        let attacker_key: Base58PublicKey =
            "11111111111111111111111111111111111111111".try_into().unwrap();
        let attacker_members = vec![MultisigMember::AccessKey { public_key: attacker_key }];
        let _promise = factory.create("alice".to_string(), attacker_members.clone(), 1);
        // Promise action batch scheduled for "alice.multisig-factory.near" contains
        // attacker_members, not the real owner's intended members.

        // demonstrating the name is now permanently squatted with attacker-chosen members
        // and no callback/refund path exists to recover or detect this.
        testing_env!(ctx("alice.near", 10_000_000_000_000_000_000_000_000));

        // fails because "alice.multisig-factory.near" already exists — proving
        // members_stored_at("alice.multisig-factory.near") == attacker_members,
        // not legit_members, violating the intended binding.
        let _ = factory.create("alice".to_string(), legit_members, 1);
    }

/// This gas spent on the call & account creation, the rest goes to the `new` call.
const CREATE_CALL_GAS: u64 = 50_000_000_000_000;

#[derive(Serialize, Deserialize)]
#[serde(crate = "near_sdk::serde", untagged)]
pub enum MultisigMember {
    AccessKey { public_key: Base58PublicKey },
    Account { account_id: AccountId },
}

#[near_bindgen]
#[derive(BorshSerialize, BorshDeserialize, Default)]
pub struct MultisigFactory {}

#[near_bindgen]
impl MultisigFactory {
    #[payable]
    pub fn create(
        &mut self,
        name: AccountId,
        members: Vec<MultisigMember>,
        num_confirmations: u64,
    ) -> Promise {
        let account_id = format!("{}.{}", name, env::current_account_id());
        Promise::new(account_id)
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                json!({ "members": members, "num_confirmations": num_confirmations })
                    .to_string()
                    .as_bytes()
                    .to_vec(),
                0,
                env::prepaid_gas() - CREATE_CALL_GAS,
            )
    }
}

    #[payable]
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }

    /// Callback after a lockup was created.
    /// Returns the promise if the lockup creation succeeded.
    /// Otherwise refunds the attached deposit and returns `false`.
    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
