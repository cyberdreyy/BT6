## Finding

Confirmed vulnerability. The route registration for LOOP plugin pprof forwarding lacks any authentication middleware, unlike the equivalent core node `/debug/*` and `/debug/pprof/*` routes.

In `core/web/router.go`, `NewRouter` mounts `loopRoutes(app, api)` directly on the top-level `api` group, which only carries rate-limiting and session middleware — no `auth.Authenticate`: [1](#0-0) 

Compare this with `debugRoutes`, which explicitly wraps `/debug/vars` in `auth.Authenticate(...)`: [2](#0-1) 

`loopRoutes` registers the plugin pprof forwarding endpoints with no such wrapper at all: [3](#0-2) 

`pluginPPROFHandler` takes `:name` and `*profile` params straight from the URL, resolves the plugin's internal Prometheus port from the registry, and proxies the request to the LOOP plugin's `/debug/pprof/<profile>` endpoint, returning the raw response body to the caller: [4](#0-3) [5](#0-4) 

Since no `auth.Authenticate` middleware sits in front of this route (unlike `/debug/vars` and `/sessions`), an unauthenticated attacker can hit `GET /plugins/<name>/debug/pprof/heap`, `/goroutine`, `/profile` (CPU), or `/trace` and receive the full raw pprof dump of the target LOOP plugin process, including stack traces, goroutine dumps, and heap memory content that can contain key material or configuration held in-process.

### Title
Unauthenticated LOOP plugin pprof endpoint exposes full memory/goroutine/CPU profiles - (File: core/web/router.go)

### Summary
`loopRoutes` in `core/web/router.go` registers `/plugins/:name/debug/pprof/*profile` on the unauthenticated `api` group, with no `auth.Authenticate` middleware applied (unlike `/debug/vars` in `debugRoutes`). This lets any unauthenticated network client fetch full pprof heap/goroutine/CPU profiles of a registered LOOP plugin process via `LoopRegistryServer.pluginPPROFHandler`.

### Finding Description
`NewRouter` builds the `api` group with only rate-limiting and session middleware, then calls `loopRoutes(app, api)` without any auth wrapper, whereas `debugRoutes` explicitly wraps `/debug/vars` with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`. `loopRoutes` registers `GET /plugins/:name/debug/pprof/*profile` -> `pluginPPROFHandler`, and `POST /plugins/:name/debug/pprof/symbol` -> `pluginPPROFPOSTSymbolHandler`, both unauthenticated. `pluginPPROFHandler` looks up the plugin by name in the `LoopRegistry`, builds an internal URL to the plugin's Prometheus/pprof port, forwards the request (including `debug`, `gc`, `seconds` query params), and streams the raw response body back to the original caller via `doRequest`. No session cookie, API token, or role check gates this path, so any network-reachable unauthenticated client can pull `heap`, `goroutine`, `profile` (CPU), `allocs`, `block`, `mutex`, `threadcreate`, or `trace` dumps of the plugin process.

### Impact Explanation
This is a memory/goroutine/CPU-profile disclosure vulnerability. Pprof heap and goroutine dumps can reveal in-process secrets (private keys, credentials, decrypted config, DB connection strings) and full stack traces of the LOOP plugin process, aiding further attacks or directly leaking key material — matching Chainlink's "sensitive information disclosure" / key-material exposure bounty class.

### Likelihood Explanation
No preconditions or credentials are required — this is directly reachable by any unauthenticated client with network access to the node's HTTP API, with a single `GET` request. It is fully repeatable and requires only knowledge or brute-forcing of a registered plugin `name`.

### Recommendation
Wrap `loopRoutes` (or at least the `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` middleware used for `/debug/vars` in `debugRoutes`, so pprof access requires an authenticated admin session/token.

### Proof of Concept
Handler-level integration test:
1. Build a `gin.Engine` via `NewRouter` (or directly mount `loopRoutes` on an unauthenticated `gin.RouterGroup`) with a `LoopRegistry` containing one registered test plugin exposing a pprof server.
2. Issue `GET /plugins/<name>/debug/pprof/heap` with no `Authorization` header and no session cookie.
3. Assert the response status is `200 OK` and the body is a binary pprof profile (not `401`/`403`), demonstrating the missing auth check, in contrast to a control request to `GET /debug/vars` without auth which should return `401`.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```
