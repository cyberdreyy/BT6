### Title
Path traversal in `BashWriter.TmpFile` allows File-type variable `Key` to escape `TemporaryPath` - (File: `shells/bash.go`)

### Summary
`BashWriter.TmpFile` builds the temp-file path with `path.Join(b.TemporaryPath, name)` and relies solely on Go's automatic `..`-cleaning, with no check that the resulting path is still rooted under `TemporaryPath`. `BashWriter.Variable` calls this helper with the untrusted variable `Key` when `variable.File` is true, so a `Key` such as `../../../tmp/poc` produces a `printf ... > %q` line targeting a path outside the job's temporary directory.

### Finding Description [1](#0-0) 
`TmpFile` does: `path.Join(b.TemporaryPath, name)` then `b.cleanPath(...)` which only calls `b.Absolute(name)` — there is no containment check comparing the result against `b.TemporaryPath`. A prefix-check helper, `isTmpFile`, exists elsewhere in the file but is documented as usable only on *unmodified* paths and is not invoked from `TmpFile` or `Variable` to validate the joined result: [2](#0-1) .

`Variable` is entered with `variable spec.Variable` and branches on `variable.File`: [3](#0-2) . If `TmpFile(variable.Key)` is used (as the question describes) to build the file destination for `printf ... > %q`, a `Key` containing `../../../etc/cron.d/x`-style segments will `path.Join`-clean to a path outside `TemporaryPath`, and the generated shell line will write attacker-controlled content there when the job script executes in the build container/host.

The `NewBashWriter` constructor sets `TemporaryPath` from `build.TmpProjectDir()` [4](#0-3) , confirming this is meant to scope all such writes to the job's own temp directory — an invariant `TmpFile` does not enforce.

### Impact Explanation
If reachable, this breaks the "file operations must stay within intended build/cache/artifact roots" invariant: an unprivileged pipeline author could get the generated job script to write a File-typed CI/CD variable's value to an arbitrary path reachable from the build environment (e.g. outside the ephemeral build directory but still constrained by the OS-level permissions of the user running the job script — shell executor running as a low-privileged CI user, or the confined filesystem of a container in docker/kubernetes executors).

### Likelihood Explanation
Feasibility hinges entirely on whether a `Key` string containing `/` and `..` can actually reach `BashWriter.Variable` at all. GitLab's variable-key validation is enforced upstream in GitLab (Rails backend / CI schema), not in this Runner repository, and standard CI/CD variable keys (project/group/instance variables, `variables:` in `.gitlab-ci.yml`, dotenv-report variables validated via `isValidDotEnvKey`, which requires `^[A-Za-z_][A-Za-z0-9_]*$`) are all restricted to identifier-safe characters that exclude `/` and `.`. That upstream restriction is outside this repository and could not be verified here. Within the Runner codebase alone, `TmpFile`/`Variable` contain no defense-in-depth check, so if any current or future code path supplies an unsanitized `Key` (e.g. a new variable source, an API/trigger path that doesn't reuse the same regex, or a refactor that changes call order), the write would escape `TemporaryPath` with no Runner-side backstop.

### Recommendation
Add containment validation inside `BashWriter.TmpFile` (or `cleanPath`) that verifies the resolved path is still prefixed by `b.TemporaryPath` (reusing/generalizing the existing `isTmpFile` logic) and reject/sanitize the variable `Key` before use, rather than relying on upstream GitLab validation as the only safeguard.

### Proof of Concept
```go
func TestBashWriter_Variable_PathTraversal(t *testing.T) {
    w := &BashWriter{TemporaryPath: "/builds/tmp"}
    w.Variable(spec.Variable{
        Key:   "../../../tmp/poc",
        Value: "pwned",
        File:  true,
    })
    script := w.String()
    // Assert the generated redirect target is NOT escaping TemporaryPath
    require.NotContains(t, script, "/tmp/poc")
    require.True(t, strings.Contains(script, "/builds/tmp/"))
}
```
Render the script and execute it under a sandboxed bash with `TemporaryPath` fixed to a throwaway directory; assert no file is created outside that directory (e.g. by checking `/tmp/poc` does not exist after running the script). Because upstream key-format enforcement could not be confirmed from this repository, the PoC should also include an integration test that drives the full path from a mocked job payload with `Key: "../../../tmp/poc"` to confirm whether GitLab-side/Runner-side validation intercepts it before reaching `BashWriter.Variable`.
