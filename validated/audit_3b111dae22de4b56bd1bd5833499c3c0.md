### Title
Confidential-relay `req.ID` reuse allows a stale node response for a deleted request to be misrouted into a new, unrelated request via `activeRequests` map key collision - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`newActiveRequest` rejects a new request only if the exact same `req.ID` string is already present in `h.activeRequests`, and `HandleNodeMessage` looks up the pending request purely by `resp.ID` with no other correlation. Because the map entry is deleted only *after* the winning response has already been sent (`sendResponseAndClearRequest`), a race window exists in which a second caller can register a brand-new `activeRequest` under the same, now-free ID before a late/slow node response for the original (already-completed) request arrives, causing that stale response to be merged into the second caller's bundle.

### Finding Description
`HandleJSONRPCUserMessage` accepts an attacker-controlled `req.ID` (any string ≤200 chars) and calls `newActiveRequest`, whose only uniqueness guard is a map presence check: [1](#0-0) 

`HandleNodeMessage` resolves the pending request purely by the JSON-RPC response ID, with no additional token, session salt, or ownership check tying the response to a specific `activeRequest` instance: [2](#0-1) 

Completion removes the map entry only *after* the response has already been delivered to the original caller's callback: [3](#0-2) 

Exploit flow: user A submits a request with `req.ID = "dup"`. It completes (quorum reached from most nodes) and is deleted from `h.activeRequests` in `sendResponseAndClearRequest`. Immediately after the delete, user B submits a request with the same `req.ID = "dup"`; `newActiveRequest`'s existence check now passes since the key is free, and a brand-new `activeRequest` (B's) is registered under `"dup"`. If a slow node's response for A's original (already-completed) request arrives after this point, `HandleNodeMessage` calls `h.getActiveRequest("dup")`, which returns B's `activeRequest`, and `ar.addResponseForNode` stores A's stale, unrelated response into B's `responses` map. `h.bundler.Bundle` then combines this stale entry with B's own collected responses using B's `ar.req` context, potentially forwarding a `SignedSecretsResponseResult`/`SignedCapabilityResponseResult` that was never generated for B's request into B's callback/bundle.

None of the existing checks stop this: the "request ID already exists" check only protects against *concurrent* reuse, not reuse after deletion; `addResponseForNode` only dedupes per-node-address within the same `activeRequest`, and the bundler explicitly does not verify request/response correlation itself — per its own doc comment, "The gateway makes no trust decision; the enclave verifies signatures." That means the gateway will happily merge a stale per-node response from a different logical request into another user's bundle, relying entirely on downstream enclave verification of the individual signed record's own content to catch the mismatch. If that downstream verification is content/scoped correctly, the immediate practical impact is response/bundle pollution and potential quorum accounting corruption for B's request rather than plaintext secret disclosure (the payload would still be encrypted for A's session), but it constitutes a real cross-user response misrouting defect at the gateway trust boundary described in the audited scope.

### Impact Explanation
This is a cross-user response confusion bug: a gateway-level trust boundary (per-request `activeRequests` map, keyed only by attacker-supplied `req.ID`) fails to guarantee response isolation between two unrelated confidential-relay requests that reuse an ID. Depending on what the enclave-side verification actually checks (not visible in this repo/index), the practical result ranges from bundle/bookkeeping corruption and denial of a clean quorum for user B, up to delivery of ciphertext/signed artifacts that were never intended for B's request into B's response bundle — a form of unauthorized cross-user data delivery at the gateway layer. This maps to Chainlink's "cross-user response confusion" bounty impact class.

### Likelihood Explanation
Exploitability requires: (1) attacker control of `req.ID` (confirmed — no forced randomness, only a ≤200-char length check), (2) precise timing so that user A's request fully completes and is deleted from the map, and a second request with the same ID is registered, before a genuinely slow/late node response for A arrives. This is a narrow, timing-dependent race rather than a trivially reliable exploit — it depends on network/node response latency being naturally out of order relative to gateway completion, which an attacker cannot fully control from outside (they don't control node response timing directly), only their own request submission timing. This lowers real-world reliability but does not eliminate the underlying design flaw: the map has no defense against ID reuse plus a late, out-of-band response for the freed ID.

### Recommendation
Do not key in-flight responses solely by the attacker-supplied `req.ID`. Generate an internal, gateway-side unique correlation token (e.g., UUID) per `activeRequest` at creation time, store responses keyed by that internal token, and validate that a node response's context (internal token, or at minimum a monotonic generation counter incremented per reuse of the same `req.ID`) matches the currently active request before calling `addResponseForNode`. Alternatively, retain tombstones for recently-completed IDs for at least `nodeSendTimeout` so a freed ID cannot be immediately reused, closing the race window entirely.

### Proof of Concept
Go test plan (`handler_test.go`):
1. Configure a `handler` with a fake `clockwork.Clock` and a mock `DON`/`bundler` that allow controlling response timing precisely.
2. Submit request A with `req.ID = "dup"` via `HandleJSONRPCUserMessage`; drive it to completion (simulate enough signed node responses to hit quorum) so `sendResponseAndClearRequest` runs and deletes `"dup"` from `h.activeRequests`.
3. Immediately after deletion (synchronize via a test hook or by controlling `h.mu` access order), submit request B with `req.ID = "dup"` and a different `req.Params`/callback.
4. Call `h.HandleNodeMessage` with a response bearing `ID = "dup"` and payload data that is recognizably tied to A's original request (e.g., a marker in `Result`).
5. Assert that B's `activeRequest.responses` does NOT contain A's stale response, and that B's callback (`SendResponse`) is never invoked with a bundle containing A's marker data — i.e., add an explicit ownership/generation check and assert the test fails without it (reproducing the bug) and passes once a per-request internal token check is added.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

	added := ar.addResponseForNode(nodeAddr, resp)
	if !added {
		l.Errorw("duplicate response from node, ignoring", "nodeAddr", nodeAddr)
		return nil
	}

func (h *handler) sendResponseAndClearRequest(ctx context.Context, ar *activeRequest, payload gwhandlers.UserCallbackPayload) error {
	if !ar.completed.CompareAndSwap(false, true) {
		// Another path already answered this request.
		return nil
	}

	sendErr := ar.SendResponse(payload)

	h.mu.Lock()
	delete(h.activeRequests, ar.req.ID)
	h.mu.Unlock()

	if sendErr != nil {
		h.lggr.Errorw("error sending response to user", "requestID", ar.req.ID, "error", sendErr)
		return sendErr
	}

	h.recordMetrics(ctx, payload.ErrorCode)
	h.lggr.Debugw("response sent to user", "requestID", ar.req.ID, "errorCode", payload.ErrorCode)
	return nil
}
