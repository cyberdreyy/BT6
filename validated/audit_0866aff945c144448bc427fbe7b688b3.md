### Title
Retrospective `has_unprocessed_blocks()` check in `cleanup_stale_signers` lets a delayed but still-valid outgoing-cycle `BlockProposal` be permanently dropped after the `ConfiguredSigner` for that cycle is deleted - ([File: stacks-signer/src/runloop.rs])

### Summary
`cleanup_stale_signers` decides whether to delete an old-cycle `ConfiguredSigner` purely from state the signer instance has *already seen* (`has_unprocessed_blocks()`), with no knowledge of messages that have not arrived yet. Because the `RunLoop::run_one_pass` dispatch loop only forwards events to whatever `ConfiguredSigner` entries currently exist in `self.stacks_signers` (keyed by `reward_cycle % 2`, at most 2 live slots), a `BlockProposal`/tenure-extend for the just-retired cycle that arrives after cleanup has no live signer object to route to, and is silently unactionable.

### Finding Description
The wedge/equality being broken: "every valid block for reward cycle N eventually reaches a bounded signer decision" - broken because after `current_reward_cycle` advances to N+1, `cleanup_stale_signers(N+1)` removes the `ConfiguredSigner` for cycle N as soon as `reward_cycle < current_reward_cycle && !signer.has_unprocessed_blocks()`: [1](#0-0) 

`has_unprocessed_blocks()` can only reflect blocks the signer instance has already observed and recorded in `signerdb` - it has no way to know about a still-in-flight `BlockProposal` for cycle N that has not yet been gossiped/received. Once the cleanup pass runs (triggered by `refresh_runloop` on a `NewBurnBlock` event crossing the cycle boundary): [2](#0-1) 

the entry keyed at `N % 2` is deleted from `stacks_signers`. `run_one_pass` subsequently dispatches every later event only to whatever `ConfiguredSigner` objects remain in the map: [3](#0-2) 

If the miner who won the outgoing cycle N's final tenure withholds their `BlockProposal` (or tenure-extend) message until after the Bitcoin block that flips `current_reward_cycle` to N+1 has been observed by `refresh_runloop`, and until after `cleanup_stale_signers` has already run and removed the N-indexed `ConfiguredSigner`, that late-arriving proposal has no live signer instance for cycle N to be routed to. There is no re-creation path for `ConfiguredSigner`s of a *past* cycle - `refresh_signer_config` is only ever called for `current_reward_cycle` and `next_reward_cycle` going forward. The proposal is effectively unroutable.

This requires only: (1) winning a single sortition (attacker's own tenure, achievable with one BTC-funded miner slot - explicitly in-scope per the attacker model), and (2) delaying their own gossip of the `BlockProposal` message past the boundary-crossing burn event - no majority of signers, no compromised keys, no auth_token, and no local host access are needed.

### Impact Explanation
This breaks the bounded-liveness guarantee: a still-valid block/tenure-extend for the outgoing cycle can never be routed to a signer instance for evaluation once cleanup has fired, so it can never accumulate signatures from that signer and, if enough signers are delayed the same way, the block/tenure can never finalize. This matches the "High - signer wedged into never signing valid blocks (liveness)" impact category. The exploit is attacker-repeatable at every reward-cycle boundary where the attacker holds the final tenure slot of the outgoing cycle.

### Likelihood Explanation
Preconditions are narrow but realistic: the attacker must win the sortition for a tenure that straddles (or immediately precedes) a reward-cycle boundary, and must time their `BlockProposal`/tenure-extend broadcast to land after the local signer processes the boundary-crossing `NewBurnBlock` event and runs `cleanup_stale_signers`. Reward-cycle boundaries are infrequent relative to tenures (roughly every ~2 weeks on mainnet), so the attack window is rare per-cycle but fully attacker-controlled once the boundary tenure is won - cost is a single BTC-funded sortition plus normal StackerDB gossip, no other privilege required, and repeatable at each future cycle boundary the attacker wins.

### Recommendation
Make `cleanup_stale_signers` forward-aware instead of purely retrospective: either (a) delay deletion of an old-cycle `ConfiguredSigner` until after `tenure_last_block_proposal_timeout`/`block_proposal_max_age_secs` has definitively elapsed since the last known activity for that tenure (not merely "no currently-known unprocessed blocks"), or (b) retain a grace-period placeholder/dead-letter path so a late but still-within-timeout proposal for the just-retired cycle can still be routed to a transient handler capable of producing a rejection/acceptance decision before the signer object is fully torn down.

        }

            self.state = State::NoRegisteredSigners;
        } else {
            self.state = State::RegisteredSigners;
        }
        Ok(())

    fn cleanup_stale_signers(&mut self, current_reward_cycle: u64) {
        #[cfg(any(test, feature = "testing"))]
        if TEST_SKIP_SIGNER_CLEANUP.get() {
            warn!("Skipping signer cleanup due to testing directive.");
            return;
        }
        let mut to_delete = Vec::new();
        for (idx, signer) in &mut self.stacks_signers {
            let reward_cycle = signer.reward_cycle();
            if reward_cycle >= current_reward_cycle {
                // We are either the current or a future reward cycle, so we are not stale.
                continue;
            }
            match signer {
                ConfiguredSigner::RegisteredSigner(signer) => {
                    if !signer.has_unprocessed_blocks() {
                        debug!("{signer}: Signer's tenure has completed.");
                        to_delete.push(*idx);
                    }
                }
                ConfiguredSigner::NotRegistered { .. } => {
                    debug!("{signer}: Unregistered signer's tenure has completed.");
                    to_delete.push(*idx);
                }
            }
        }
        for idx in to_delete {
            self.stacks_signers.remove(&idx);
        }
    }
