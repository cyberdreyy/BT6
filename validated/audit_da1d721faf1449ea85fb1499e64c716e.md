### Title
Single-handler shortcut in `multiHandler.getHandler` bypasses per-method allowlist, letting arbitrary `req.Method` values reach `confidentialrelay.handler.HandleJSONRPCUserMessage` and fan out to DON nodes - ([File: core/services/gateway/multihandler.go])

### Summary
`multiHandler.getHandler` skips the `methodToHandler` allowlist entirely whenever a service has exactly one registered handler type, routing every JSON-RPC request to that handler regardless of `req.Method`. `confidentialrelay.handler.HandleJSONRPCUserMessage` never re-validates `req.Method` against the list returned by `Methods()` (`MethodSecretsGet`, `MethodCapabilityExec`), so an attacker-supplied arbitrary method proceeds straight to `newActiveRequest` and `fanOutToNodes`, which forwards the raw request to every DON member.

### Finding Description
`NewMultiHandler` builds two maps: `typeToHandler` (handler-type name → handler) and `methodToHandler` (declared method → handler), the latter populated only from each handler's `Methods()` return value [1](#0-0) . Routing for both `HandleJSONRPCUserMessage` and `HandleLegacyUserMessage` goes through `getHandler`:

```go
func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}
	handler, ok := m.methodToHandler[method]
	...
}
``` [2](#0-1) 

When a gateway service is configured with only one handler (a supported, common configuration — e.g. a service that only registers the `confidentialrelay` handler), `len(m.typeToHandler) == 1` and the method-allowlist check (`m.methodToHandler[method]`) is never consulted — the request is unconditionally routed to that single handler regardless of `req.Method`.

`HandleJSONRPCUserMessage` in the confidential-relay handler only validates `req.ID` (non-empty, ≤200 chars) and never checks `req.Method` against `MethodSecretsGet`/`MethodCapabilityExec` (the values returned by `Methods()`) before creating the active request and fanning out: [3](#0-2) 

`fanOutToNodes` then sends the raw `ar.req` (with the attacker-controlled `Method` field) to every member of the DON via `h.don.SendToNode`: [4](#0-3) 

The top-level `gateway.ProcessRequest` also performs no method-allowlist check before invoking the handler — it only routes by service name / DON ID and forwards `jsonRequest.Method` straight into `HandleJSONRPCUserMessage`: [5](#0-4) 

Thus the exactness invariant "only declared methods (`Methods()`) are servable" is violated whenever a service has a single handler type: the multi-handler dispatch layer's allowlist is bypassed by the `len==1` shortcut, and the handler itself performs no compensating check.

### Impact Explanation
An unprivileged attacker able to reach the gateway's user HTTP endpoint (any client of the node/gateway API) can submit a JSON-RPC request with an arbitrary/unsupported `Method` string, valid `DonId`/service routing, and a valid `ID`, and have it fanned out unmodified to every node in the DON. This is an authorization-exactness bypass: the gateway is documented to serve only `MethodSecretsGet` and `MethodCapabilityExec` for this handler, but any method string is forwarded to nodes, expanding the DON-facing attack surface to unvalidated/unsupported operations and enabling request smuggling of unintended methods into the node-facing JSON-RPC channel (matches Chainlink bounty class: allowlist/authorization bypass leading to unauthorized action reaching DON nodes).

### Likelihood Explanation
No special privileges are required beyond normal access to the gateway's user-facing endpoint for a configured service; the only precondition is that the targeted service is configured with a single handler type (a realistic, non-misconfiguration deployment shape, since `confidentialrelay` and `vault` services are commonly configured with one handler each per DON). The exploit is a single HTTP request with an arbitrary `Method` field and is fully repeatable.

### Recommendation
Remove the `len(m.typeToHandler) == 1` shortcut in `multiHandler.getHandler`, or keep it but still validate `method` against `methodToHandler` (or the handler's own `Methods()`) before dispatch. Additionally, add a defense-in-depth check inside `confidentialrelay.handler.HandleJSONRPCUserMessage` (and other handlers) that rejects any `req.Method` not contained in the handler's own `Methods()` list before calling `fanOutToNodes`.

### Proof of Concept
1. Construct a `confidentialrelay` `handler` via `NewHandler` with a minimal `donConfig`/mock `don`/mock `bundler` (as in `core/services/gateway/handlers/confidentialrelay/handler_test.go`).
2. Call `handler.HandleJSONRPCUserMessage(ctx, jsonrpc.Request[json.RawMessage]{ID: "req1", Method: "unsupported.method"}, callback)` directly.
3. Assert that `don.SendToNode` (mock) is invoked (i.e., `fanOutToNodes` ran) despite `"unsupported.method"` not being in `handler.Methods()` — demonstrating the handler itself performs no method check.
4. Separately, construct a `multiHandler` via `NewMultiHandler` with a single `config.Handler` entry (e.g., only `confidentialrelay`), call `multiHandler.HandleJSONRPCUserMessage` with `Method: "unsupported.method"`, and assert it is routed to the handler (via the mock `don.SendToNode` being called) instead of returning a "no handler found for method" error, confirming the `len==1` shortcut bypasses `methodToHandler`.

func NewMultiHandler(handlerFactory HandlerFactory, hdlrs []config.Handler, shardedDONs []config.ShardedDONConfig, shardsConnMgrs [][]handlers.DON) (handlers.Handler, error) {
	methodToHandler := map[string]handlers.Handler{}
	typeToHandler := map[string]handlers.Handler{}
	for _, h := range hdlrs {
		hdlr, err := handlerFactory.NewHandler(h.Name, h.Config, shardedDONs, shardsConnMgrs)
		if err != nil {
			return nil, fmt.Errorf("failed to create handler %s: %w", h.Name, err)
		}

		typeToHandler[h.Name] = hdlr

		for _, method := range hdlr.Methods() {
			if _, exists := methodToHandler[method]; exists {
				return nil, fmt.Errorf("duplicate handler for method %s: methods must be globally unique across handlers", method)
			}

			methodToHandler[method] = hdlr
		}
	}

func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}
