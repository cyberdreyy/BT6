## Title
Division-before-multiplication in `jovian_da_footprint` truncates the Jovian DA-footprint gas estimate, allowing block DA-limit bypass - ([File: crates/common/l1-fees/src/params.rs])

### Summary
`L1FeeParams::jovian_da_footprint` computes the Jovian DA-footprint gas by dividing the FastLZ-estimated compressed size by `1e6` *before* multiplying by the `da_footprint_gas_scalar`, instead of multiplying first and dividing last. This is the same `(a/b)*c` precision-loss bug class flagged in the referenced report for `Reth.deposit()`'s `minOut`/`idealOut` computation.

### Finding Description
`tx_estimated_size_fjord` returns the FastLZ compressed-size estimate scaled by `1e6` (the comment on the type explicitly says "scaled by 1e6"): [1](#0-0) . Every other consumer of this scaled value multiplies first, then divides by `1e6` last, preserving precision — see `data_gas_fjord` [2](#0-1) , `L1FeeParams::data_gas` [3](#0-2) , and `calculate_tx_l1_cost_fjord` [4](#0-3) .

`jovian_da_footprint`, however, reverses the order: it first divides the scaled estimate by `1e6`, discarding the sub-1e6 remainder, and only then multiplies by `scalar`: [5](#0-4) 

Since `tx_estimated_size_fjord` is computed as `fastlz_size * 836_500 - 42_585_600` (clamped to a minimum of `100_000_000`), the pre-division remainder discarded by `wrapping_div(1_000_000)` can be up to `999_999`. Multiplying the truncated quotient by an attacker/protocol-influenced `scalar` afterward means every unit of truncated remainder — worth up to `(999_999/1_000_000) * scalar` gas — is lost from the final result, compared to computing `estimated_size * scalar / 1_000_000` (multiply-then-divide, the pattern used everywhere else in this same file).

### Impact Explanation
The DA-footprint value returned by this function is accumulated per-block as `da_footprint_used` and checked against the Jovian DA-footprint block limit (per the linked spec comment) in the block executor: [6](#0-5) . Systematic under-counting of DA-footprint gas for every transaction in a block allows blocks to be built/accepted whose true DA usage exceeds the intended Jovian DA-footprint block limit, undermining the resource-metering guarantee the feature is meant to enforce (blocks admitted with more L1 data-availability weight than the protocol limit allows). Because the truncation direction is deterministic and always favors under-counting, it can be exploited systematically across many transactions to accumulate DA usage beyond the block limit.

### Likelihood Explanation
This bug triggers on essentially every transaction once Jovian is active and `da_footprint_gas_scalar` is set (i.e., on every user-submitted transaction), since `tx_estimated_size_fjord`'s pre-division remainder is non-zero for the vast majority of calldata sizes. No special conditions or malicious actor cooperation beyond normal transaction submission are required, making this a routine, deterministic miscalculation rather than an edge case.

### Recommendation
Refactor `jovian_da_footprint` to multiply before dividing, matching the pattern used in `data_gas` and `calculate_tx_l1_cost_fjord`:
```rust
pub fn jovian_da_footprint(&self, input: &[u8]) -> u64 {
    let Some(scalar) = self.da_footprint_gas_scalar else {
        return 0;
    };
    U256::from(tx_estimated_size_fjord(input))
        .saturating_mul(scalar)
        .wrapping_div(U256::from(1_000_000u64))
        .saturating_to::<u64>()
}
```

### Proof of Concept
1. Set `da_footprint_gas_scalar = Some(U256::from(7))` (as in the existing test) and pick calldata whose `tx_estimated_size_fjord` result is not an exact multiple of `1e6`, e.g. `fastlz_size` such that `fastlz_size*836_500 - 42_585_600 = 100_500_000` (500,000 remainder after `/1e6`).
2. Current code: `100_500_000 / 1_000_000 = 100` (remainder 500_000 discarded), `100 * 7 = 700`.
3. Correct multiply-first order: `100_500_000 * 7 = 703_500_000`, `/1_000_000 = 703`.
4. The difference (`703` vs `700`) is under-reported DA-footprint gas per transaction; repeated across a full block's worth of transactions, the cumulative `da_footprint_used` tracked in `BaseBlockExecutor` [6](#0-5)  falls below the true DA usage, permitting the block to pass the Jovian DA-footprint limit check while actually exceeding it.

/// Calculate the estimated compressed transaction size in bytes, scaled by 1e6.
/// This value is computed based on the following formula:
/// max(minTransactionSize, intercept + fastlzCoef*fastlzSize)
pub fn tx_estimated_size_fjord(input: &[u8]) -> u64 {
    let fastlz_size = flz_compress_len(input) as u64;

    fastlz_size
        .saturating_mul(L1_COST_FASTLZ_COEF)
        .saturating_sub(L1_COST_INTERCEPT)
        .max(MIN_TX_SIZE_SCALED)
}
