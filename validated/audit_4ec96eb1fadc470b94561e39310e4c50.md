### Title
Shell command injection via unescaped `%q`-quoted project directory path in `executeChownOnDir` - ([File: executors/docker/docker_command.go])

### Summary
`executeChownOnDir` builds a shell command line with Go's `fmt.Sprintf("chown -RP -- %d:%d %q", uid, gid, dir)` and feeds it as raw stdin to a `/bin/bash` process running inside the helper container via `exec.Docker.Exec` [1](#0-0) . Go's `%q` verb produces a *Go*-syntax quoted string (escaping backslashes/quotes/control chars) but does **not** neutralize shell metacharacters such as `$`, `` ` ``, or `!`, which remain active even inside bash double quotes, so a `dir` value containing `$(...)` or backticks results in command substitution being executed by the shell that consumes this stdin.

### Finding Description
`changeFilesOwnership` → `executeChown` → `executeChownOnDir` is only reached when `FF_DISABLE_UMASK_FOR_DOCKER_EXECUTOR` is enabled and the job image does not run as root [2](#0-1) . In that mode the helper container's entrypoint is `/bin/bash` rather than the normal `gitlab-runner-helper` binary [3](#0-2) , meaning stdin written through `exec.IOStreams.Stdin` is interpreted as shell script text by bash, not as an argv array passed to a discrete `chown` process. `dockerExec.Exec` (the `Docker` interface in `executors/docker/internal/exec/exec.go`) simply pipes `streams.Stdin` bytes into the attached container connection with no masking or escaping of its own [4](#0-3) . The `dir` argument passed in is `s.Build.FullProjectDir()` / `s.Build.TmpProjectDir()` [5](#0-4) , values that are influenced by job-controlled build-directory configuration (e.g. custom build dir / clone path job variables). Because `%q` only performs Go-string escaping and shell double-quotes still allow `$()`/backtick command substitution and `$VAR` expansion, any metacharacter of that kind embedded in the directory string is executed by bash when the crafted stdin line is run, achieving injection into the helper-container shell process.

### Impact Explanation
If a job can influence the resulting `FullProjectDir()`/`TmpProjectDir()` string to include `$(...)`/backtick sequences, the injected command runs as the entrypoint shell of the **helper container**, not the (already attacker-controlled) build container. Since this chown step exists specifically to fix ownership for non-root job images, the helper container in this flow typically has elevated access relative to the sandboxed build container (it mounts the build/cache directories and performs privileged filesystem operations), so escaping into it via injection is a more meaningful boundary crossing than "just running more code in my own container" — it is a bug even though its real-world blast radius depends on what the helper container additionally exposes (mounted volumes, credentials, etc.), which I could not fully enumerate.

### Likelihood Explanation
Exploitation requires two things I could confirm and one I could not fully verify in the time available:
- Confirmed: the code path exists and is reachable whenever `FF_DISABLE_UMASK_FOR_DOCKER_EXECUTOR` is on and the job image is non-root [2](#0-1) .
- Confirmed: the quoting primitive used (`%q`) is the wrong tool for shell-safety — it is a Go-string quoting function, not a POSIX-shell quoting function, so this is a real, demonstrable defect regardless of what currently constrains `dir`'s contents.
- **Unverified**: whether GitLab Runner's custom-build-dir / clone-path validation (which I located references to in `common/build.go` but did not get to fully read) rejects paths containing `$`, backticks, or similar shell metacharacters before they reach `FullProjectDir()`/`TmpProjectDir()`. If that validation already strips or rejects such characters, the practical exploitability of this specific sink is blocked even though the unsafe quoting pattern remains a latent risk. I was not able to conclusively confirm or rule this out within my remaining iterations.

Because of that unresolved precondition, I can confirm the root-cause defect (unsafe `%q` used where shell-escaping is required) but cannot confirm end-to-end attacker reachability with full confidence.

### Recommendation
Do not construct shell command strings via `fmt.Sprintf`/`%q` for values that are executed by a shell interpreter. Either: (1) avoid running through `/bin/bash` for this operation and instead exec `chown` directly with an argv array (no shell involved), or (2) if a shell must be used, properly single-quote the value using POSIX-safe quoting (wrap in `'...'` and escape embedded `'` as `'\''`) rather than Go's `%q`. Additionally, independently confirm/enforce that `common/build.go`'s custom build dir / clone path validation rejects shell metacharacters, as defense in depth.

func TestExecuteChownOnDir_ShellMetacharacterInjection(t *testing.T) {
    dockerExecMock := new(exec.MockDocker) // mocks Docker.Exec
    var capturedStdin string
    dockerExecMock.On("Exec", mock.Anything, mock.Anything, mock.Anything, mock.Anything).
        Run(func(args mock.Arguments) {
            streams := args.Get(2).(exec.IOStreams)
            b, _ := io.ReadAll(streams.Stdin)
            capturedStdin = string(b)
        }).Return(nil)

    s := &commandExecutor{ /* minimal setup */ }
    maliciousDir := `/builds/project$(touch /tmp/pwned)`

    _ = s.executeChownOnDir(&container.InspectResponse{ID: "c1"}, dockerExecMock, 1000, 1000, maliciousDir)

    // Assert the generated stdin still contains an *unescaped* $(...) sequence,
    // proving %q did not neutralize shell command substitution.
    assert.Contains(t, capturedStdin, "$(touch /tmp/pwned)")
}

func (s *commandExecutor) changeFilesOwnership() error {
	if !s.isUmaskDisabled() {
		return nil
	}

	dockerExec := exec.NewDocker(s.Context, s.dockerConn, s.waiter, s.Build.Log())
	inspect := user.NewInspect(s.dockerConn, dockerExec)
	imageSHA := s.buildContainer.Image
	imageName := s.Build.Image.Name

	log := s.Build.Log().WithFields(logrus.Fields{
		"imageSHA":  imageSHA,
		"imageName": imageName,
	})
	log.Debug("Checking if image runs with root user")

	usesRoot, err := inspect.IsRoot(s.Context, imageSHA)
	if err != nil {
		return fmt.Errorf("checking if image %q runs as root: %w", imageName, err)
	}

	if usesRoot {
		log.Debug("Image uses root user")
		return nil
	}

	log.Debug("Image doesn't use root user")

	uid, gid, err := getUIDandGID(s.Context, log, inspect, s.buildContainer.ID, imageSHA)
	if err != nil {
		return err
	}

	if uid == 0 {
		return nil
	}

	return s.executeChown(dockerExec, uid, gid)

func (s *commandExecutor) executeChownOnDir(
	c *container.InspectResponse,
	dockerExec exec.Docker,
	uid int,
	gid int,
	dir string,
) error {
	s.BuildLogger.Println(fmt.Sprintf("Changing ownership of files at %q to %d:%d", dir, uid, gid))

	output := new(bytes.Buffer)
	// limit how much data we read from the container log to
	// avoid memory exhaustion
	lw := limitwriter.New(output, 1024)
	streams := exec.IOStreams{
		Stdin:  strings.NewReader(fmt.Sprintf("chown -RP -- %d:%d %q", uid, gid, dir)),
		Stderr: lw,
		Stdout: lw,
	}

	err := dockerExec.Exec(s.Context, c.ID, streams, nil)
