### Title
Unpermissioned `LockupFactory::create` allows address-squatting a victim's deterministic lockup account with attacker-chosen parameters - (File: lockup-factory/src/lib.rs)

### Summary
`LockupFactory::create` derives the lockup account id purely from `sha256(owner_account_id)[..20].<factory>` with no check that the caller is `owner_account_id` or any authorized party, and no check that the target account doesn't already have a pending/rightful creation. Any unprivileged account can call `create(owner_account_id="victim.near", ..., whitelist_account_id=Some("attacker-whitelist.near"))` with the minimum deposit, permanently taking that deterministic address before the legitimate funder does, and NEAR account creation is a one-shot event so the legitimate later `create` call fails and gets refunded.

### Finding Description
The broken binding is: `LockupContract@sha256("victim.near")[..20].<factory> == LockupArgs{owner_account_id: "victim.near", ...real-vesting-schedule/whitelist chosen by legitimate funder}`. In practice, after the attack, it equals `LockupArgs{owner_account_id: "victim.near", staking_pool_whitelist_account_id: "attacker-whitelist.near", lockup_duration: 0, ...}` chosen entirely by the attacker.

Code path: [1](#0-0) [2](#0-1) 

`create` is `#[payable]` and only asserts `env::attached_deposit() >= MIN_ATTACHED_BALANCE` [3](#0-2) . It never checks `env::predecessor_account_id() == owner_account_id.as_ref()`, nor does it check whether an account at `lockup_account_id` is already reserved/intended for someone else. The lockup account id is fully deterministic from `owner_account_id` and the factory's own account id: [4](#0-3) . The attacker supplies `whitelist_account_id`, `vesting_schedule`, `lockup_duration`, etc., which are serialized directly into `LockupArgs` and sent to the `new` function call of the newly created contract: [5](#0-4) .

Because `Promise::new(lockup_account_id).create_account()` is atomic at the protocol level, whichever transaction executes `create_account` first wins that account id permanently; a subsequent legitimate `create` call for the same `owner_account_id` will have its `create_account()` fail, triggering the refund path in `on_lockup_create` (`is_promise_success()` false branch) [6](#0-5) , but the address itself remains permanently squatted with the attacker's parameters (contract already deployed and initialized from the attacker's earlier successful call). No `assert_self`, `assert_owner`, or account-existence-reservation guard exists to prevent this, since the only guard present (`assert_self()` in the callback) is irrelevant to front-running the address itself.

### Impact Explanation
The victim ('victim.near') can never receive a lockup at the canonical deterministic address the ecosystem/tooling expects for them; instead that account is a lockup deployed and owned per attacker-chosen `LockupArgs` (e.g., `staking_pool_whitelist_account_id` pointing to an attacker-controlled staking pool, or `lockup_duration = 0`/no vesting so funds are immediately liquid to whoever the attacker set as owner — here `owner_account_id` is still "victim.near", but "victim.near" never approved these terms and the real funder's larger deposit and real vesting terms are rejected). This matches the Critical category "a lockup deployed with parameters its rightful creator never chose." It's repeatable against any not-yet-created victim owner account, at negligible cost (MIN_ATTACHED_BALANCE, i.e., 3.5 NEAR, which can be later reclaimed by acting as owner if the attacker also controls `owner_account_id`, or wasted if targeting a real third party purely to grief/squat).

### Likelihood Explanation
Preconditions are trivial: the target lockup account (`hex(sha256(owner_account_id)[..20]).<factory>`) must not yet exist, which is true for any account whose real lockup grant hasn't been created yet — a state known/guessable by anyone observing typical grant-creation announcements or timing. The attacker only needs `MIN_ATTACHED_BALANCE` (3.5 NEAR) and a single function call; no special permissions, keys, or foundation status required. This is straightforward front-running achievable by any account on the network, including via mempool/transaction-timing races, and is repeatable across many victim accounts.

### Recommendation
Restrict `create` to be callable only by `owner_account_id` itself (`assert_eq!(env::predecessor_account_id(), owner_account_id.as_ref())`), or require an additional unpredictable/owner-signed component (e.g., a `salt` supplied via a signed message from `owner_account_id`, or restrict factory usage to the account itself calling `create` on its own behalf) so the deterministic address cannot be squatted by third parties before the legitimate owner acts.

```rust
// lockup-factory/src/lib.rs tests module
#[test]
fn test_address_squatting_by_unprivileged_attacker() {
    let mut context = VMContextBuilder::new()
        .current_account_id(account_factory())
        .predecessor_account_id(account_near())
        .finish();
    testing_env!(context.clone());
    let mut contract = LockupFactory::new(whitelist_account_id(), foundation_account_id());

    // Attacker calls create() for victim's owner_account_id with attacker-chosen whitelist
    context.predecessor_account_id = "attacker.testnet".to_string();
    context.attached_deposit = ntoy(35);
    testing_env!(context.clone());
    contract.create(
        account_tokens_owner(), // "tokenowner.testnet" == victim owner
        0.into(),                // lockup_duration = 0, attacker-chosen
        None,
        None,
        None,
        Some("attacker-whitelist.testnet".try_into().unwrap()), // attacker-chosen whitelist
    );

    // Simulate the create_account/deploy/new promise succeeding (attacker wins the race)
    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    testing_env_with_promise_results(context.clone(), PromiseResult::Successful(vec![]));
    assert!(contract.on_lockup_create(
        lockup_account(),
        ntoy(35).into(),
        "attacker.testnet".to_string(),
    ));

    // Now the legitimate funder tries to create the real grant for the same owner
    context.predecessor_account_id = "real-funder.testnet".to_string();
    context.attached_deposit = ntoy(1000); // real, larger grant
    testing_env!(context.clone());
    contract.create(
        account_tokens_owner(),
        WrappedDuration::from(63036000000000000u64), // real duration
        None,
        None,
        None,
        None, // real default whitelist
    );

    // Simulate create_account() failing because the account already exists (attacker squatted it)
    context.predecessor_account_id = account_factory();
    context.attached_deposit = ntoy(0);
    context.account_balance += ntoy(1000);
    testing_env_with_promise_results(context.clone(), PromiseResult::Failed);
    let res = contract.on_lockup_create(
        lockup_account(),
        ntoy(1000).into(),
        "real-funder.testnet".to_string(),
    );
    // Legitimate creation fails and refunds; attacker's LockupArgs remain permanently deployed
    assert_eq!(res, false);
}
```
This demonstrates: `LockupContract@lockup_account() == attacker's LockupArgs{lockup_duration:0, whitelist:"attacker-whitelist.testnet"}` while the real funder's `create` call for the same `owner_account_id` fails (`on_lockup_create` returns `false`, deposit refunded), proving the binding is broken and the deterministic address is permanently occupied with parameters the rightful creator never chose.

```rust
    #[payable]
    pub fn create(
        &mut self,
        owner_account_id: ValidAccountId,
        lockup_duration: WrappedDuration,
        lockup_timestamp: Option<WrappedTimestamp>,
        vesting_schedule: Option<VestingScheduleOrHash>,
        release_duration: Option<WrappedDuration>,
        whitelist_account_id: Option<ValidAccountId>,
    ) -> Promise {
        assert!(env::attached_deposit() >= MIN_ATTACHED_BALANCE, "Not enough attached deposit");

        let byte_slice = env::sha256(owner_account_id.as_ref().as_bytes());
        let lockup_account_id =
            format!("{}.{}", hex::encode(&byte_slice[..20]), env::current_account_id());

        let mut foundation_account: Option<AccountId> = None;
        if vesting_schedule.is_some() {
            foundation_account = Some(self.foundation_account_id.clone());
        };

        // Defaults to the whitelist account ID given on init call.
        let staking_pool_whitelist_account_id = if let Some(account_id) = whitelist_account_id {
            account_id.into()
        } else {
            self.whitelist_account_id.clone()
        };

        let transfers_enabled: WrappedTimestamp = TRANSFERS_STARTED.into();
        Promise::new(lockup_account_id.clone())
            .create_account()
            .deploy_contract(CODE.to_vec())
            .transfer(env::attached_deposit())
            .function_call(
                b"new".to_vec(),
                near_sdk::serde_json::to_vec(&LockupArgs {
                    owner_account_id,
                    lockup_duration,
                    lockup_timestamp,
                    transfers_information: TransfersInformation::TransfersEnabled {
                        transfers_timestamp: transfers_enabled,
                    },
                    vesting_schedule,
                    release_duration,
                    staking_pool_whitelist_account_id,
                    foundation_account_id: foundation_account,
                })
                    .unwrap(),
                NO_DEPOSIT,
                gas::LOCKUP_NEW,
            )
            .then(ext_self::on_lockup_create(
                lockup_account_id,
                env::attached_deposit().into(),
                env::predecessor_account_id(),
                &env::current_account_id(),
                NO_DEPOSIT,
                gas::CALLBACK,
            ))
    }
```

```rust
    pub fn on_lockup_create(
        &mut self,
        lockup_account_id: AccountId,
        attached_deposit: U128,
        predecessor_account_id: AccountId,
    ) -> bool {
        assert_self();

        let lockup_account_created = is_promise_success();

        if lockup_account_created {
            env::log(
                format!("The lockup contract {} was successfully created.", lockup_account_id)
                    .as_bytes(),
            );
            true
        } else {
            env::log(
                format!(
                    "The lockup {} creation has failed. Returning attached deposit of {} to {}",
                    lockup_account_id, attached_deposit.0, predecessor_account_id
                )
                    .as_bytes(),
            );
            Promise::new(predecessor_account_id).transfer(attached_deposit.0);
            false
        }
    }
```
