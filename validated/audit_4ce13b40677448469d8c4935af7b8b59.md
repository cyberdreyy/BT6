No `recover()` call exists anywhere in `core/services/gateway/**`, and `h.wg.Go(func() {...})` (used in both `core/services/gateway/handlers/capabilities/v2/http_handler.go` `makeOutgoingRequest` and `core/services/gateway/handlers/capabilities/handler.go` `handleWebAPIOutgoingMessage`) does not wrap the goroutine body in a panic-recovery block. Since Go terminates the entire process on an unrecovered panic in any goroutine, this confirms the finding below.

### Title
Unrecovered panic in shared HTTP response-cache singleflight group crashes the entire Gateway, griefing all workflow users - (File: core/services/gateway/handlers/capabilities/v2/response_cache.go)

### Summary
The Gateway's `responseCache.Fetch` [1](#0-0)  deduplicates concurrent outbound HTTP requests using `singleflight.Group`, keyed only by a hash of method/URL/headers/body/workflowOwner (explicitly *not* including `WorkflowID`, per the test `TestRequestHash` "having different workflowID results in same Hash") [2](#0-1) . If the `fetchFn` passed into `Fetch` panics, the test suite itself documents that the panic propagates to **every concurrent waiter** sharing that singleflight key [3](#0-2) , and separately that it propagates to the caller at all [4](#0-3) . The `fetchFn` itself is `h.createHTTPRequestCallback`, which makes an outbound HTTP call to a URL fully controlled by the requesting workflow/node [5](#0-4) , and this callback runs inside an unrecovered background goroutine (`h.wg.Go(func() {...})`) with no `recover()` anywhere in the call chain [6](#0-5) .

### Finding Description
This is the direct analog of the reported bug class: in the C4 report, an unprivileged Staker deploys a contract at the `payer` address that reverts on `receive()`, so that whenever the shared `execute()` flow interacts with that address it aborts the whole transaction and denies service (griefs) any Keeper that touches it — even though the Keeper had no way to isolate that specific interaction.

Here, the unprivileged actor is any workflow owner/node who can specify an arbitrary outbound `URL` in an `OutboundHTTPRequest` (`gateway_common.OutboundHTTPRequest.URL`, processed in `makeOutgoingRequest`) [7](#0-6) . The HTTP send path (`h.send` → `h.httpClient.Send` or the mTLS client) is reachable purely from data the requesting node controls, and its result is consumed by `createHTTPRequestCallback` which builds `gateway_common.OutboundHTTPResponse` from the returned headers/body/status code [5](#0-4) . Any code path in that response-construction logic (or in any transitively-called library) that can panic on attacker-influenced input (e.g. malformed/oversized headers, unexpected encodings, nil-dereferences on edge-case responses) will panic inside the `fetchFn` supplied to `responseCache.Fetch`.

Because `Fetch` uses `singleflight.Group.Do` keyed by `req.Hash()` (which folds in only method+URL+headers+body+workflowOwner, not per-request or per-workflow identifiers) [8](#0-7) , multiple concurrent requests — potentially from different workflows/executions belonging to the same owner, or from different nodes hitting the same external target — collapse onto one shared flight. The test `TestFetch_PanicInFetchFn_PropagatedToAllWaiters` proves that a single panicking fetch takes down every other concurrent caller riding that flight, not just the caller that happened to trigger it [3](#0-2) . Since the whole call is made inside a bare `h.wg.Go(func() {...})` goroutine with no recover, and no recover exists anywhere else in `core/services/gateway/**`, an unrecovered panic here crashes the entire Gateway process — not merely the one request.

### Impact Explanation
A single malicious or malfunctioning outbound endpoint (fully controlled by an unprivileged workflow author, exactly analogous to the "malicious Staker/payer" in the source report) can, if any panic-triggering edge case exists in HTTP-response handling, take down the shared Gateway process. This denies service to **all** other workflows and nodes relying on that Gateway for HTTP actions/triggers — a full node-wide DoS rather than a single-transaction revert, making the blast radius broader than the original finding.

### Likelihood Explanation
Likelihood is bounded by whether a genuinely panic-inducing HTTP response can be crafted (this was not verified beyond the test-harness demonstration that a panic in `fetchFn` propagates through the shared singleflight and is never recovered). The architectural gap — no `recover()` anywhere in the outbound-request goroutine or in `responseCache.Fetch`, combined with a singleflight key that is shared across concurrent, potentially unrelated requests — is confirmed and reachable purely from unprivileged, node/workflow-supplied URL and header/body data.

### Recommendation
- Wrap `fetchFn`/the HTTP callback execution (and the `h.wg.Go` goroutine body in `makeOutgoingRequest`/`handleWebAPIOutgoingMessage`) with `recover()` and convert any panic into an `OutboundHTTPResponse` error result, so a single bad outbound target cannot crash the Gateway process.
- Add panic-safety inside `responseCache.Fetch`'s singleflight callback specifically, converting a recovered panic into a normal error result returned only to the actual callers of that key, rather than allowing an unrecovered panic to escape the goroutine.
- Reconsider whether the singleflight cache key should also incorporate `WorkflowID`/request identity to reduce the blast radius of any given key's failure (already flagged by the passing-but-permissive `TestRequestHash` behavior).

### Proof of Concept
Existing repository tests directly demonstrate the propagation mechanics (not full end-to-end panic-trigger from a hostile HTTP endpoint, which was not verified in this codebase):
- `TestFetch_PanicInFetchFn_PropagatedToCaller` [4](#0-3)  shows a panicking `fetchFn` panics `Fetch` itself.
- `TestFetch_PanicInFetchFn_PropagatedToAllWaiters` [3](#0-2)  shows the panic is delivered to every one of the 5 concurrent goroutines sharing the same cache key, not just the flight leader — confirming that a single hostile response can crash every concurrent consumer of that key, and, absent any `recover()` in the calling goroutine (`h.wg.Go` in `makeOutgoingRequest`), the whole Gateway process.

func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}

	// Slow path: singleflight deduplicates concurrent fetches per key.
	// Cache check + store happen inside the flight so the key isn't released
	// until the result is cached, closing the race window between singleflight
	// completion and cache write.
	result, _, _ := rc.flight.Do(cacheKey, func() (any, error) {
		// Re-check cache: a previous flight may have just stored the result.
		rc.cacheMu.RLock()
		cachedResp, exists := rc.cache[cacheKey]
		rc.cacheMu.RUnlock()
		if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
			rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
			return cachedResp.response, nil
		}

		response := fetchFn()

		if storeOnFetch && isCacheableStatusCode(response.StatusCode) {
			rc.cacheMu.Lock()
			rc.cache[cacheKey] = &cachedResponse{
				response: response,
				storedAt: time.Now(),
			}
			rc.cacheMu.Unlock()
		}

		return response, nil
	})

	return result.(gateway.OutboundHTTPResponse)
}

// createHTTPRequestCallback creates a callback function that makes the actual HTTP request
func (h *gatewayHandler) createHTTPRequestCallback(ctx context.Context, requestID string, httpReq network.HTTPRequest, req gateway_common.OutboundHTTPRequest) func() gateway_common.OutboundHTTPResponse {
	return func() gateway_common.OutboundHTTPResponse {
		l := logger.With(h.lggr, "requestID", requestID, "method", req.Method, "timeout", req.TimeoutMs)
		l.Debugw("Sending request to client", "requestBodySize", len(httpReq.Body), "numHeaders", len(httpReq.Headers))
		start := time.Now()
		resp, err := h.send(ctx, httpReq, req)
		externalEndpointLatency := time.Since(start)
		if err != nil {
			isBlockedRequest := errors.Is(err, network.ErrBlockedRequest)
			isHTTPSendError := errors.Is(err, network.ErrHTTPSend)
			isHTTPReadError := errors.Is(err, network.ErrHTTPRead)
			isExternalEndpointError := isHTTPSendError || isHTTPReadError

			switch {
			case isBlockedRequest:
				l.Warnw("HTTP request blocked", "requestID", requestID, "err", err)
				h.metrics.IncrementBlockedRequestCount(ctx, h.lggr)
			case isHTTPSendError:
				l.Warnw("error while sending HTTP request to external endpoint", "requestID", requestID, "err", err)
				h.metrics.IncrementHTTPSendErrorCount(ctx, h.lggr)
			case isHTTPReadError:
				l.Warnw("error while reading HTTP response from external endpoint", "requestID", requestID, "err", err)
				h.metrics.IncrementHTTPReadErrorCount(ctx, h.lggr)
			default:
				l.Errorw("error while sending HTTP request", "requestID", requestID, "err", err)
			}

			return gateway_common.OutboundHTTPResponse{
				ErrorMessage:            err.Error(),
				IsExternalEndpointError: isExternalEndpointError, // error while sending request to or reading response from external endpoint
				IsValidationError:       isBlockedRequest,        // validation error before sending request to external endpoint
				ExternalEndpointLatency: externalEndpointLatency,
			}
		}
		l.Debugw("Received HTTP response", "responseBodySize", len(resp.Body), "statusCode", resp.StatusCode, "numHeaders", len(resp.Headers))
		h.metrics.IncrementCustomerEndpointResponseCount(ctx, strconv.Itoa(resp.StatusCode), h.lggr)
		h.metrics.RecordCustomerEndpointRequestLatency(ctx, time.Since(start).Milliseconds(), h.lggr)
		return gateway_common.OutboundHTTPResponse{
			StatusCode:              resp.StatusCode,
			Headers:                 resp.Headers,
			MultiHeaders:            resp.MultiHeaders,
			Body:                    resp.Body,
			ExternalEndpointLatency: externalEndpointLatency,
		}
	}
}
